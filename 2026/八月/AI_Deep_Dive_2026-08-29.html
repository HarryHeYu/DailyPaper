Paper 1 — WikiSkill: Compiling Agent Experience into Persistent Knowledge for Skill Evolution

Authors: Liyan Tang, Cyrus Rashtchian, Chun-Sung Ferng, Andrew Tomkins, Da-Cheng Juan, Tu Vu · Date: 2026-08-27 · Status: arXiv preprint · Paper

5.2 一句话定位

把Agent经验拆成Raw→Wiki→Skill三层，让失败与成功经验先沉淀成persistent knowledge，再编译成procedural skill。

5.3 人话版

传统self-improving agent往往直接从trajectory改skill，失败原因散落在历史中。WikiSkill加入中间Wiki：Raw层保存原始trajectory；Wiki层保存patterns、proposal diff、accept/reject与skill-impact；Skill层保留最终可执行procedure。Skill proposal失败时只rollback skill，Wiki仍保留失败知识。五benchmark五模型上WikiSkill稳定超过skill-evolution baselines；Qwen-3.6-27B平均39.4→63.3，Gemini-3.5-Flash49.5→68.1。最关键ablation：Proposer无Wiki avg48.7，有Wiki63.7；但Inference Agent也直接看Wiki反而63.7→60.9，说明knowledge accumulation和execution access应该分离。

5.4 Background & Research Gap

Trace2Skill/EvoSkill/SkillOpt能利用execution history，但经验往往仍附着在优化过程上，没有成为独立、可累积、可检索、可审计的知识层。WikiSkill填的是“经验如何变成persistent declarative knowledge，再反向生成procedure”的gap。

5.5 Core Insight

Raw trace保真但冗长；Skill简洁但容易丢失失败原因。Wiki是中间表示，尤其保存rejected proposals，这些negative evidence会影响下一轮skill development。

5.6 Method Deep Dive

Dtrain/Dval/Dtest → Inference Agent with current Skills → immutable Raw trajectories → Wiki Maintainer → pattern pages / logs / skill-impact → Skill Proposer → one atomic edit → validation gate → accept or rollback Skill → Wiki always persists → next iteration

5.7 核心公式

τ_i ~ π(x_i;S_{k-1})
W'_k ← M_WM(W_{k-1},T_sample,k)
P_k ← M_P(W'_k,S_{k-1},T_train,k)
S_k=S'_k if R(T_val,k)>R_best, else S_{k-1}

真正关键不是accept/reject gate，而是Wiki不随rollback消失。

5.8 Toy Example

ALFWorld里Agent反复“拿物品→查看→移动→又放回原位”。第一次proposal失败被rollback，但Wiki记录failure pattern。下一轮Proposer看到失败历史后生成更具体skill。若只删除最终SKILL.md，Wiki与Raw仍可能把它重新编译出来。

Paper 2 — GraphMemix: Query-Aware Evidence Forests for Long-Term Multimodal Agent Memory

Authors: Geng Li, Yuhao Wang, Dong Li, Jianye Hao, Yuxin Peng · Date: 2026-08-27 · Paper

5.2 一句话定位

把长期多模态memory retrieval从独立Top-K改成query-conditioned evidence forest，在固定K条memory预算下联合选node和relation。

5.3 人话版

传统Top-K会拿到相似但重复的memory，漏掉语义不相似却沿session/事件关系才能找到的关键证据。GraphMemix用多view检索24个seed，扩成最多48个candidate；Node Verifier判断direct support，ECV判断相对anchor的new fact/clarification/corroboration，最后在K=10预算下选evidence forest。Qwen3-VL macro Judge Accuracy49.80→61.55，Gemma4也+12.33pp；不同dataset中15.14%–39.70%的gold原本不在top-10，却是relation-recoverable。

5.4 Background & Gap

长期多模态memory常需要跨时间、跨模态组合。提前summary可能压掉未来query才需要的细节，embedding Top-K又看不到relation。本文填的是joint evidence-set construction。

5.5 Core Insight

一条memory有direct utility；另一条memory可能单独不强，但相对anchor提供incremental utility。这两种价值不应压成单一pointwise score。

5.6 Method Deep Dive

archive+query → multi-view seeds L=24 → schema + mutual-kNN expansion → candidates M=48 → Node Verifier → anchors → ECV edge roles → trusted graph → forest optimization under K=10 → ordered evidence → frozen reader

5.7 核心公式

max_(S,F) U_node(S|q) − C_edge(F|q) − C_open(S,F)

奖励有用node，惩罚不可靠edge和过多独立chain。

5.8 Toy Example

用户问“东京旅行最后订了哪家酒店？”Top-K抓到东京照片和酒店页面，但漏掉后续聊天“就订第二家”。GraphMemix从hotel-B anchor沿same-session relation找到聊天并补全证据链。若删除direct booking memory但聊天仍可达，target仍可恢复。

Cross-Paper Synthesis

WikiSkill揭示写入侧重建：experience→wiki→skill；GraphMemix揭示读取侧恢复：query→anchor→relation→evidence chain。完整Agent Unlearning必须同时防止Recompilation和Retrieval Recovery。

Best Migration — Recompilation + Retrieval Closure

MVE：20 target skills/events；删除后继续3轮WikiSkill evolution，同时运行GraphMemix-style relation recovery；比较source-only、lineage delete、relation closure、full closure。Metric：Recompilation Recovery Rate、Relation Recovery Rate、Minimum Recovery Path、Retain Utility。

Collision

Skill lifecycle已有EvoMal/Repo2Skill-Evo/Coalition-Aware；Memory recovery已有InjecMEM/Agentic Unlearning/GraphMemix。真正的新意应放在benign procedural reacquisition + provenance closure + multimodal relation recovery + direct/recoverable/closed三态verification。
