Paper 1 — Control-Plane Placement Shapes Forgetting

Title：Control-Plane Placement Shapes Forgetting: An Architectural Study of Agent Memory Across Thirteen System Configurations
Author：Dongxu Yang
Affiliation：DeepLethe
Date：2026-06-16, arXiv v2
Status：arXiv preprint
Paper：PDF · arXiv

一句话定位

它不是研究“Agent 能不能记住”，而是研究 Agent Memory 系统究竟有没有被命令忘掉的能力，以及 LLM 放在写入、召回还是 mutation control plane 的哪个位置，决定了它能修复哪类 forgetting failure。

人话版

多数 Agent Memory 工作把“记忆好不好”理解成 retrieval 准不准，但真实系统还必须支持 supersede、release、purge。论文将 memory system 分成 recall plane 与 control plane，并用统一六方法 Adapter Protocol 对 13 种系统配置进行测试。标准 template case 上多个系统接近 99%，但进入 adversarial deletion 后，deterministic 系统普遍只有约 63–68%。关键不是有没有 LLM，而是 LLM 放在哪里：inscribe-time LLM 擅长 canonicalization，却帮不了 later intent-aware deletion；mutation-time LLM hook 则能把大量 non-primitive-existence cases 提升到约 93–94%，同时几乎不改变 recall hot path。

Background & Research Gap

长期记忆系统至少有两类操作。第一类是 Recall Plane：inscribe 事实并在 query 时召回。第二类是 Control Plane：旧事实被更新时 supersede、临时信息失效时 release、用户要求彻底删除时 purge。传统 LongMemEval、LOCOMO 等更偏向第一类，因此一个系统可以 Recall 很强，却没有真正 purge 能力。

例如用户原先职位是 Research Assistant，后来改成 Research Scientist。一个 retrieval-first 系统可能只是让新职位排名更高，但旧职位仍在 store 中；这不等价于真正删除。

Core Insight

作者真正观察到的是 intelligence placement 决定 ambiguity coverage。Deterministic primitives 对 substring、temporal qualifier 等规则性删除强，但对 identifier obfuscation、cross-lingual alias 弱。Inscribe-time LLM 可以在写入时做 entity linking 和 canonicalization，却无法理解之后某次 mutation 的精确 intent。Mutation-time LLM planner 位于 supersede / purge / release 决策点，正好解决“该删谁、删多少、哪个 alias 属于同一对象”的问题。

Method Deep Dive

Memory system → reset / inscribe / recall_texts → supersede / release / purge → Template Suite (1000) → Adversarial Layer (385, 10 categories) → mutation through native/composed primitives → deterministic top-k oracle → compare deterministic / vector / inscribe-LLM / mutation-LLM regimes → cross-evaluate recall benchmarks → characterize Recall × Forgetting plane

Adapter Protocol：六方法是行为契约而非固定 API。不同 backend 可以用自己的 primitives 实现。如果某能力根本不存在，就记 N/A，而不是把 API coverage 与 algorithmic failure 混为一谈。

Adversarial Layer：覆盖 substring trap、prefix collision、paraphrase supersession、negation trap、temporal qualifier、shared attribute、compound fact、identifier obfuscation、cross-lingual identifier、recursive supersession 十类。它的价值是把“easy forget”进一步拆成稳定 failure signatures。

核心公式与数学直觉

Adapter = {reset, inscribe, recall, supersede, release, purge}
Pass(case)=1 iff every must_contain survives AND every must_not_contain disappears from top-k

这个评价函数同时惩罚“忘不掉”和“误删 retain”。它比单纯 target disappearance 更合理，因为 deletion 不应以大规模 collateral damage 为代价。论文没有复杂训练 objective；真正的“数学对象”是 operation algebra 与 per-category success geometry。

Toy Example

Memory 中有 Alice-ID-123、Alice-ID-1234 和 Alice 的旧/新邮箱。用户要求 purge Alice-ID-123：substring delete 可能误删 1234；用户改用中文别名“爱丽丝”发起删除，BM25 可能匹配不到；compound fact “Alice 住北京并在 TCS 工作”里用户只删除单位，如果 backend 不支持 partial edit，再强 planner 也无法创造缺失 primitive。这说明 semantic planning 与 primitive existence 是两个独立层次。

Experiment Setup Deep Dive

论文覆盖 13 个配置，包括 LETHE、MEM0、LangGraph、MEMPALACE、Letta、OpenMemory、A-MEM、Graphiti、HippoRAG 及若干 +LLM variants。主 embedding 使用 all-MiniLM-L6-v2 384-d ONNX，并做 multilingual embedder swap。Template Suite 1000 cases，Adversarial Layer 385 cases。人类验证使用 10 位 NLP/CS annotators，100-case stratified sample，Fleiss κ=.958、observed agreement 99.1%；还提供 external-authored subset 与 cross-family judge audit。

Metrics 教学式解释

Pass Rate↑：应保留内容还在、应删除内容消失。N/A：系统没有某 primitive 时单独报告。Recall score↑：独立衡量记忆召回。Latency/Cost↓：评估将 LLM 放到 mutation control plane 后的系统代价。重要的是不要把 Recall 和 Forgetting 合成一个 scalar。

Results Deep Dive

  1. Template Suite：LETHE 99.3%、LangGraph 99.5%、MEM0 88.8%、MEMPALACE 0%，说明 easy benchmark 极易高估 readiness。
  2. Adversarial 上 deterministic 系统聚集于 63–68%：LETHE 63.4、MEM0 68.3、LangGraph 62.9。
  3. prefix_collision：LETHE 32/39，MEM0 12/39，词法精确匹配更稳。
  4. cross_lingual_identifier：MEM0 21/38，LETHE 0/38，向量 matching 反而占优。
  5. LETHE+LLM overall 91.7%，排除 primitive-existence compound_fact 后约 93.3%。
  6. LangGraph+LLM overall 93.2%，说明 placement effect 跨 backend。
  7. 345 个 non-primitive-existence cases 中，deterministic 约 70%→hook 93–94%，提升超过 22pp。
  8. 换 Qwen-2.5-72B 后依然有明显 lift，说明不是单模型特例。
  9. 换 multilingual embedder 并没有自动修复 cross-lingual deletion，证明核心 lever 不是 embedding。
  10. Recall 轴基本不因 mutation hook 改变，支持两个 plane 的独立性。

Strongest result：两个不同 backend 在相同 mutation-hook contract 下都升到约 93%，且 recall hot path 不变。
Weakest/failure：底层缺少 partial edit primitive 时，LLM planner 也无法凭空创造能力。

Ablation / Mechanistic Analysis

Embedder swap 不解决关键问题；cross-backend hook 复现提升；cross-LLM family 方向一致；在不触发 mutation 的 FactConsolidation 任务中，+LLM 版本和 deterministic backbone 基本一样，这个 negative control 很有价值，因为它说明 hook 并不是“加一个大模型所有指标都涨”。

Claim vs Evidence

Authors Claim：Control-plane placement 决定 forgetting failure coverage。
Experiments Actually Show：13 配置、十类 adversarial、backend/model/embedder ablation 与 external subset 都支持这种结构性差异。
Not Yet Proven：真实 agent skill、trajectory、多模态 memory deletion 更复杂，literal oracle 也不能覆盖所有 semantic equivalence。

Contribution

New Benchmark：FORGETEVAL；New Protocol：六方法 Adapter + honest N/A；New Empirical Finding：Recall 与 Forgetting 是两个 plane；New Architectural Finding：mutation-time LLM 对 intent-aware deletion 最有效；New Evaluation Principle：memory system 应同时报告 recall 与 control-plane forgetting。

Limitation & Failure Modes

系统覆盖仍有限；部分 adversarial data 为 LLM-drafted；substring oracle 对抽象语义有局限；compound fact 受 primitive existence 约束。额外还没有 multi-agent shared memory、image/OCR carrier、skill/trajectory forgetting，也没评估删除后 long-horizon reacquisition。

Reproduction View

最小复现建议做三个 backend：exact lexical SQLite、embedding vector store、lexical + LLM mutation hook。选四类 prefix_collision、cross_lingual_identifier、compound_fact、recursive_supersession 各 20 case。严格区分 N/A 与 FAIL，固定 top-k，先复现 architecture fingerprint，再扩大到完整 benchmark。

Paper 2 — Can Scientific Claims Be Removed from Large Language Models?

Title：Can Scientific Claims Be Removed from Large Language Models? A Systematic Evaluation of Claim-Level Unlearning
Authors：Snigdha Paul, Manasi Patwardhan, Arman Cohan
Affiliation：TCS Research；Yale University
Date：2026-08-21
Paper：arXiv HTML
Code：Scientific-Claim-Unlearning

一句话定位

它把 scientific claim 是否真正被删除定义成跨不同 QA 形式、不同 paraphrase view 的 forget transfer，并发现 GD/NPO/SimNPO 等往往只压制训练中看到的 forget subset。

人话版

传统 LLM unlearning 常拿一批 forget QA 做优化，再看这些 QA 的 accuracy 是否下降。但科学知识不是一个字符串，而是一个 underlying claim。SciUnlearn 为每个 claim 生成 8 个 QA，再拆成互不重合的 F1/F2；在 F1 上 unlearn 后，F2 就是 semantic holdout。如果模型只在 F1 上坏掉，却仍能正确回答 F2，就说明它忘的是 surface pattern，而不是 claim。结果显示这种 cross-view asymmetry 非常普遍；而真正把 F1/F2 都压低的强更新，经常伴随 retain/general utility 损失。

Background & Research Gap

科学知识会更新、撤稿、被推翻，而且同一 claim 往往通过多种措辞、多种题型、多条引用和推理路径存在。传统 instance-level forget set 很容易只让见过的问法失效，却保留底层语义。因此 scientific unlearning 的关键不是“这个 QA 会不会了”，而是“同一 claim 的所有可合理访问 surface 是否都闭合”。

Core Insight

论文最关键设计是 paired semantic forget views：F1∩F2=∅，但来自同一 claim set。若 unlearning 真正在 claim representation 层生效，优化 F1 后 F2 也应明显下降；如果只是 surface suppression，就会出现 F1 大跌而 F2 高位保持的方向性不对称。

Method Deep Dive

Dolma scientific papers → choose CS / Medical / Retracted → extract 1–5 claims per paper → quality judge: accuracy / independence / clarity → generate 8 QA per claim: MCQ / True-False / Fill-Blank / Assertion-Reason → validate QA → split into disjoint F1 / F2 semantic views → construct R_ext / R_int → apply GD / NPO / NPO+RT / SimNPO / SimNPO+RT → LoRA and full-parameter variants → evaluate target view + complementary view → evaluate retain + general benchmarks → diagnose claim-level transfer vs surface suppression

核心公式与数学直觉

min_{θ'} E_{(q,a)∈F_i}[ℓ_f(a|q;θ')] + λ E_{(q,a)∈R}[ℓ_r(a|q;θ')]

forget loss 压低 target answer，retain loss 保持非目标知识，λ 控制 forget-retain trade-off。不同算法的具体 objective 不同，但都面临同一个问题：训练 objective 只直接看到 F_i，并不自动保证 semantic closure。

Claim-level transfer = drop on F_j, j≠i, after optimizing only F_i

这不是训练 loss，而是最重要的评价原则：真正 claim-level unlearning 应该让互补 view 也一起下降。

Toy Example

Claim：“药物 X 在高剂量下增加肝损伤风险。”F1 用 MCQ 和 fill-blank；F2 用 T/F 和 assertion-reason。若 GD 让 F1 从 95% 降到 40%，但 F2 仍 92%，模型明显还记得 claim。只有 F1/F2 都显著下降，同时 R_ext/R_int 与 MMLU 等基本保持，才更接近真正 removal。

Experiment Setup Deep Dive

Datasets：Computer Science、Medical、Retracted。规模：CS 76 papers / 170 claims / F1 536 / F2 536 / Rext 1060 / Rint 418；Medical 78 / 127 / 508 / 508 / 908 / 543；Retracted 91 / 141 / 390 / 390 / 884 / 671。Models：OLMo-3-7B-Instruct、Llama-3-8B-Instruct。Training：full-parameter 与 rank-8 LoRA。Baselines：GD、NPO、NPO+RT、SimNPO、SimNPO+RT。Metrics：EM、ROUGE-L F1、R_ext/R_int、MMLU、ARC-Challenge、HellaSwag，以及附录中的 Min-K% MIA / reference-model score。

Metrics 教学式解释

EM↓ on forget：答案完全匹配，越低越好，但对 free-form 很严格。ROUGE-L F1↓ on forget：允许部分表面变化，却仍不是真正 semantic correctness。R_ext↑：保护引用链里的外部科学知识。R_int↑：保护同 paper 的非 target context。MMLU/ARC/HellaSwag↑：防止“整个模型坏掉所以忘得好”。Cross-view transfer：最重要，应看 F1 优化后 F2 降多少以及反向结果。

Results Deep Dive

  1. OLMo CS Base F1 R-F1=97.54；GD(F1)=71.70，但 F2 仍 93.51。
  2. OLMo CS NPO+RT(F1)：F1=88.81，F2=93.67，forget 本身并不强。
  3. LLaMA CS NPO+RT(F1)：F1=73.56，F2=90.91，cross-view gap 明显。
  4. LLaMA CS GD(F2)：F2 降到 59.18，但 F1 仍 93.31，方向性 asymmetry 再次出现。
  5. Medical OLMo GD(F1)：F1 92.16→58.20，F2 仍 75.40，有 spillover 但远非 complete removal。
  6. Retracted LLaMA NPO+RT(F1)：F1 88.63→36.96、F2 也约 35.69，但 MMLU 64.75→51.05，HellaSwag 55.89→50.50。
  7. Retracted LLaMA NPO+RT(F2)：F2 R-F1=24.43、EM=1.79，F1 也 48.25，但 MMLU 仍有明显下降。
  8. Retain-aware methods 整体比无 retain 版本更能保护 utility。
  9. T/F 与 AR 等较简单 question format 更容易被忘。
  10. 更 rooted 于 pretraining/citation structure 的 claims 往往更难删除。

Strongest result：跨模型/domain 出现的 F1/F2 directional asymmetry。
Weakest/failure：个别 setting 的确可以同时压 F1/F2，但经常伴随 utility 损失，不能把所有成功都解释成 clean claim deletion。

Ablation / Mechanistic Analysis

LoRA vs full parameter：LoRA 往往形成更局部、较浅的 suppression。Question format：T/F、AR 更容易忘，暗示 output decision geometry 会影响难度。QA density：一个 claim 对应的 paraphrased QA 越多，forgetting 往往越强。Rootedness：更深嵌入 pretraining/citation structure 的 claim 更难删，与 hard-to-unlearn / difficulty predictor 方向高度一致，但仍主要是相关性证据。

Claim vs Evidence

Authors Claim：当前 unlearning 多数实现 surface suppression，不能可靠删除 scientific claim。
Experiments Actually Show：多数方法/setting 存在显著 F1/F2 asymmetry，强更新还可能损伤 utility。
Not Yet Proven：论文没有直接证明内部 representation 仍保留 claim；模型规模有限；F1/F2 仍来自自动生成 QA；没有 adaptive recovery / reacquisition attack。

Contribution

New Task：Scientific Claim Unlearning；New Benchmark：SciUnlearn；New Protocol：paired semantic forget views；New Empirical Finding：当前方法大多 subset-specific；New Failure Characterization：rootedness、question format、QA density 会影响 forgetting。

Limitation & Failure Modes

只覆盖部分 optimization-based methods；缺少更广泛 mechanistic/representation approaches；retracted set 与模型规模有限；claim extraction 和 QA generation 引入 LLM bias；EM/ROUGE 仍偏 surface；最重要的是未系统测试 retain premises 是否能 multi-hop 重新推导 target claim。

Reproduction View

最小复现可先选 20–30 claims，每个 claim 生成 4 种 QA × 2，均衡拆成 F1/F2；用 7B/8B 模型 LoRA 跑 GD 与 NPO+retain。第一目标是复现“F1 掉、F2 不掉”的 cross-view gap，而不是先追求最强 forget score。然后再加入 paraphrase、cloze、multi-hop reconstruction，就可以自然连接 black-box residual auditor。

Cross-Paper Synthesis

两篇共同击中一个核心：局部成功 ≠ 等价类上的 closure。Control Plane 里，单个 purge query 成功不代表 alias / prefix / cross-lingual / compound 都正确删除；SciUnlearn 里，F1 accuracy 下降不代表 F2 semantic view 一起消失。真正的 unlearning 对象应从“一个输入/一个 API 调用”升级成一组语义或操作等价 surfaces。

Best Migration Direction — Equivalence-Class Unlearning Closure

把 target 定义成 equivalence class 而非单样本：文本 claim 有 paraphrase/cloze/multi-hop；Agent memory 有 alias/prefix/cross-lingual/compound；MLLM 有 image/caption/OCR/text-only；Agent skill 有 direct execution/tool path/memory reconstruction。只有所有 equivalent surfaces 都关闭 target、retain surfaces 不误删，才算 closure。

MVE：30 targets × 6 surfaces × 3 methods。指标：Worst-Surface Leakage、Closure Rate、Retain FPR、Surface Transfer Matrix。这个方向可以把 black-box residual auditor、Agent Memory control plane 和 Multimodal Unlearning 统一到一套语言中。

Collision / Overlap

Strongest Collision：多 view forgetting 与 SciUnlearn、Erasure Illusion、REBEL/Can LLMs Truly Forget 相邻；Agent Memory forgetting 也已有 ForgetEval、FactConsolidation、FAMA。单纯“再加更多 paraphrase probe”或“再做 delete benchmark”不够。真正差异化应放在 统一等价类 closure、cross-modal surfaces、sample-level hardness prediction、logical derivation recovery、black-box surface fingerprinting。
