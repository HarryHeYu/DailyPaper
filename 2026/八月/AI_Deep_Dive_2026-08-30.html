Paper 1 — OBLIVION: Workflow-Level Operational Skill Unlearning for Deployed Agents

Authors：Zhengyang Shan, Xu Qian, Jiayun Xin, Kun Li, Yue Zhang, Minghui Xu
Affiliation：Shandong University
Date：2026-08-08 · Status：arXiv preprint · Paper

5.2 一句话定位

把Agent Skill删除重新定义为source-to-sink workflow closure：显式entry删掉后，只要archive、transcript、memory、schema等residual carrier还能经过primitive tools重新到达persistent/callable sink，就没有真正unlearn。

5.3 人话版

部署Agent的skill并不只存在一个文件里。旧聊天里可能有步骤，vector memory里可能有摘要，archive里可能留着helper，MCP schema或registry draft里也可能有参数格式。管理员删掉skill entry后，Agent仍能“读旧材料→总结→写helper→注册schema→重新调用”。OBLIVION因此提出Operational Skill Unlearning：不讨论模型参数是否忘记，而是问部署系统是否还能从残留状态把skill复活。它构建AgentForgetBench，把每次恢复写成Residual Source→Transforms→Dangerous Sink→Observable Effect；防御先用Cross-Surface Coherent Erasure跨六个surface清理known carriers，再用Anti-ReDerivation Guard在runtime传播revoked-source taint，只在会让skill持久化/可调用的sink附近block。Locked benchmark中No-defense ASR=1.0，OBLIVION降到0.114，IWE=0.115，同时locked utility=1.0、benign block=0。

5.4 Background & Research Gap

传统Machine Unlearning关注训练数据对parameters的影响；Agent部署后却还有memory、files、registries、tool schemas和transcripts。已有StruQ/Task Shield/ClawGuard主要处理instruction injection、goal alignment或visible tool boundary，而revoked-skill resurrection可以跨多个看似无害步骤，所以单边界防御不足。

5.5 Core Insight

真正评估单位不是“某个entry是否消失”，而是从任何residual carrier出发是否仍存在到dangerous sink的可达workflow。删除问题本质上更接近软件卸载中的dependency closure与garbage collection。

5.6 Method Deep Dive

Revoked skill request → CSCE scans behavior gate / registry / vector memory / filesystem / transcript / MCP schema → transactional tombstones/deletes + audit receipts → agent executes normal primitive tools → dispatcher records typed events/dependencies → ARG propagates revoked-source taint through transforms → before persistent/callable sink, frozen remediation checks workflow → audit-only or block → primary oracle verifies observable effect → ASR / IWE / Utility / Benign Block

CSCE：负责已知carrier的协调删除，并通过transaction/audit log保证partial failure可追踪。ARG：不是关键词filter，而是数据依赖taint；summary/transform之后taint继续存在。Frozen remediation：测试前冻结规则，避免看测试attack再即时加规则。

5.7 核心公式与数学直觉

w=(s,t1,…,tm,k,e)

s是residual carrier，t是transform，k是sink，e是observable effect。这个workflow tuple就是“删除闭包”的基本对象。

ASR=(1/|R|) Σ 1[r.passed]

只有primary oracle确认实际effect发生才算attack success，而不是看模型文本声称“已恢复”。IWE则按sink危害加权：persistent file、long-term memory、registry/execute、external action权重递增。

5.8 Toy Example

一个邮件批量发送skill被撤销。Registry entry已删，但archive还留helper片段，transcript里有字段映射。Agent先read archive→summarize params→write helper→register tool schema。单个read/write都可能是benign，但整条链让skill重新可调用。OBLIVION在schema registration sink处根据lineage block。

5.10 Experiment Setup Deep Dive

Locked benchmark共160 cases：88 attack、8 benign near-miss、64 utility。攻击sink包括persistent files、long-term memory、registry、tool schema、simulated external actions和execution。另有40-case skill-attack-derived sandbox（30 attack/10 utility），以及DeepSeek生成的1904 API-call two-stage rollout。

5.11 Metrics 教学式解释

ASR↓：实际dangerous effect成功率。IWE↓：按sink危害加权。Utility↑：正常任务完成。Benign Block↓：误拦正常流程。Boundary Utility↑：专门挑长得像skill restoration的benign流程，防止“全挡住就安全”。

5.14 Ablation / Mechanistic Analysis

Static ARG和OBLIVION block rate都约.081，但ASR从.750降到.114，说明提升主要来自更广的source-to-sink handling而非“block更多”。Aggressive CSCE+ARG会让boundary utility跌到很低，证明erase越彻底不等于系统越好。

5.15 Claim vs Evidence

Authors Claim：Operational skill unlearning必须workflow-level评估。Actually Show：controlled benchmark里entry deletion后100%攻击可复活，workflow remediation大幅降ASR且保locked utility。Not Yet Proven：真实开放系统carrier/sink更丰富，audit-only如何转生产enforcement未解决，残余10个成功attack说明政策不完整。

5.16 Contribution

New Problem：Operational Skill Unlearning；New Benchmark：AgentForgetBench；New Mechanism：CSCE+ARG workflow remediation；New Metric：IWE；New Empirical Finding：visible entry removal远不足以防skill resurrection。

5.17 Limitation & Failure Modes

Controlled fixtures与真实SaaS有差距；规则仍依赖开发集；boundary utility有代价；未覆盖multi-agent communication、cross-modal carriers和parameter-level latent residual。

5.18 Reproduction View

最小复现可只做4种carrier×3种sink：transcript/filesystem/vector memory/schema → file/memory/registry。实现No-defense、Static Taint、Workflow Guard，并用deterministic oracle确认effect。先验证No-defense ASR≈1，再比较两种guard。

Paper 2 — When Unlearning Fails: Reliable Data Deletion under Post-Training in Agent Networks

Authors：Zihao Ding, Jun Huang, Liang Dong
Affiliation：South Dakota State University；Baylor University
Date：2026-07 · Status：arXiv preprint · Paper

5.2 一句话定位

把Agent Network unlearning从一次性模型修复改成持续运行下的删除保持问题：forget data已经塑造后续retained trajectories，因此continued self-improvement会让被删影响重新出现。

5.3 人话版

Self-improving agent每轮都用当前policy执行任务，然后把新trajectory继续拿来训练。第4轮用户要求删除某条trajectory时，问题不仅是这条数据还在不在；前几轮由它塑造的policy已经采集出一批“retained”trajectory，这些轨迹带着同样行为偏好。即使当前模型用NPO或retraining擦掉，继续训练几轮后target方向又会回来。论文把这种现象叫influence echo，并定义Influence Regeneration Rate（IRR）测未来恢复。MUTE先追踪forget influence传播到哪些client/trajectory，再用NPO+retain擦模型、隔离高风险retained trajectories，并把之后local update投影到forget-gradient subspace的正交方向；同时用behavioral audit和uplink scheduling持续维护删除。

5.4 Background & Research Gap

经典unlearning假设删除请求后训练环境相对静态。自我改进Agent却形成policy→data collection→future update闭环，因此target influence会通过未来数据回流。一次性post-unlearn checkpoint并不能说明删除会持续。

5.5 Core Insight

删除对象不仅包含当前参数里的target signal，还包含被target塑造出来的未来训练数据。真正目标必须同时满足Current Leakage低和Future Regeneration低。

5.6 Method Deep Dive

self-improving network → deletion request at t_d → Influence Provenance estimates inherited influence → NPO + retain preservation on LoRA → quarantine/downweight high-risk retained trajectories → estimate dominant forget-gradient subspace → project subsequent local updates away from it → behavioral audit after every round → communication-aware client scheduling → continue training and measure IRR over K rounds

5.7 核心公式与数学直觉

min Σ_t Σ_k s_k[t] s.t. BLI≤0.5+ε, U≥(1−δ)U0, τ≤τmax, IRR≤ρ

普通forget-retain objective只管当前状态；这里额外加入C4：未来regeneration必须低。BLI接近0.5代表当前行为泄漏接近chance，IRR接近0代表后续训练没有把target带回来。

5.8 Toy Example

机器人早期target trajectory让policy偏好“从左侧抓杯子”。删除原trajectory并纠正当前policy后，旧policy生成的成功轨迹仍带着左侧抓取。继续训练便会重新恢复该习惯。MUTE标记这些echo trajectories，并阻止future updates沿相同forget direction重新拟合。

5.14 Ablation / Mechanistic Analysis

关键机制是future-update projection：没有projection时，相关retained trajectories可以几轮内重新fit erased direction。Quarantine太低会伤retain，太高会漏掉echo；uplink越多，server越能及时trace/audit/contain。

5.15 Claim vs Evidence

Authors Claim：self-improving agent network中的unlearning必须抵抗post-training influence echo。Actually Show：两backbone、三granularity、通信限制与physical testbed均支持future regeneration是独立问题。Not Yet Proven：LLM tool agents、开放multi-agent communication、完全black-box setting尚未验证。

5.16 Contribution

New Problem：Influence Echo；New Metric：IRR；New Method：MUTE provenance+erase+containment+audit scheduling；New System Result：通信约束与真实edge hardware验证。

5.17 Limitation & Failure Modes

依赖white-box gradient/subspace；主要VLA/federated setting；task deletion IRR仍较高；projection可能限制合法未来学习；provenance score错误会导致误quarantine。

5.18 Reproduction View

最小版本不需机器人：用LLM/Agent LoRA做10轮self-improvement，第4轮NPO delete一个target，继续6轮。比较①one-shot NPO；②NPO+quarantine；③再加forget-gradient projection。每轮测target black-box preference/ASR作为IRR proxy和retain utility。

5.21 Attack / Verification Lens

攻击端可主动构造“看起来retain、实际上携带forget influence”的future trajectories；验证端不再只看单个post-unlearn checkpoint，而要看整条leakage-vs-round curve。

5.22 与 Paper 1 的关系

OBLIVION是当前environment里的residual carrier closure；MUTE是未来学习过程中的echo carrier closure。一个完整Agent Unlearning生命周期必须同时关闭这两类路径。

Cross-Paper Synthesis

OBLIVION把删除边界扩到“当前可达environment carriers”；MUTE把删除边界扩到“未来self-improvement生成的echo trajectories”。统一起来，Agent Unlearning应满足：当前没有workflow能复活target，未来学习也不会重新生成target influence。

Best Migration — Three-Layer Agent Deletion Closure

把Daydreaming的Behavioral Reconstruction、OBLIVION的Workflow Resurrection、MUTE的Future Influence Regeneration统一成同一benchmark。对每个target同时测ASR@budget、Workflow ASR/IWE、IRR、Retain Utility。任一层失败都不叫真正Agent Unlearning closure。

Collision

OBLIVION已经明确占据Operational Skill Unlearning；Agentic Unlearning占parameter-memory pathways；Daydreaming占Output-only reconstruction。新的独立论文不能只做“删skill仍会恢复”。更强差异化应是统一三层closure、cross-modal carriers、cross-agent echo、black-box future-IRR prediction。
