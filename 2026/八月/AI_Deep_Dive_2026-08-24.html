PAPER 1 · NEWSELF-IMPROVING AGENTS

On the Fragility of Self-Improving Agents: Variance, Task Order, and Underspecification

Qinyuan Ye, Yu Li, Yada Pruksachatkun, Jiaxin Zhang, Chien-Sheng Wu · Salesforce AI Research · arXiv:2608.18066v1 · 2026-08-18 · Code/Data links in paper

Full HTML · Abstract

5.2 一句话定位

重新评估 memory-based self-improving agents，证明 run variance 和 task order 足以把“小幅持续提升”翻转成明显退化，默认 benchmark 顺序甚至暗含 easy→hard curriculum。

5.3 人话版

AWM、ReasoningBank 这类 agent 会把每次任务后的成功/失败总结成 memory，再让后续任务读取。过去多数实验只按 benchmark 默认 task ID 顺序跑一遍，因此看起来“做得越多越聪明”。这篇论文指出，在线 memory 是有历史的：第一次任务偶然成功还是失败，会决定 memory bank 里出现什么；错误memory一旦被写入，会在后续反复被retrieve，最终形成完全不同的状态轨迹。作者在 WebArena、VisualWebArena、SCUBA 上做多次重复和两种随机打乱。结果显示，加入self-improvement后17/24个domain×method case的跨run方差上升，11个相对增加超过50%；RBank在GitLab的best–worst gap从4.44%扩大到7.78%，Map从2.75到8.26，Multisite甚至2.08到10.42。更关键的是，默认task顺序本来就是隐式curriculum：前段成功率高、后段低；RBank默认order平均+1.5%，但shuffle后很多setting不升反降。作者进一步发现“用API”“等待用户确认”“Haversine估计地图距离”等错误memory会自我强化。加rubric、environment feedback和更明确prompt只能追回约31%的退化。对continual unlearning，这几乎就是一个现成警告：同一组forget requests的顺序可能决定最终模型状态，因此所谓easy→hard curriculum不能只在一个固定order上证明有效。

5.4 Background & Research Gap

普通静态模型的evaluation噪声通常被当成测量噪声；而self-improving agent会把早期输出变成未来输入，因此噪声具有因果后果。已有工作很少报告run-level variance，也很少打乱task order。与此同时，benchmark默认task ID往往不是随机生成，而是随着构造过程从简单到复杂。于是“memory帮助学习”与“benchmark给了有利课程”混在一起。

对unlearning而言，完全类似的confound是：forget requests常按数据集ID、identity batch或固定难度顺序执行。若模型在前几次删除中先形成某种参数/拒答/记忆状态，后面的“更难样本”可能被这个状态帮助或拖累。若不换序，很难判断hardness predictor与curriculum到底是真机制还是order artifact。

5.5 Core Insight

1. Stateful variance：memory construction受trajectory和LLM sampling影响，早期随机性会累积。
2. Order as intervention：任务顺序改变state evolution，因此不能假设exchangeable。
3. Hidden curriculum：default task IDs常表现easy→hard。
4. Underspecification：memory constructor不知道环境约束时，会生成“合理但不可执行”的经验。
5. Strong initialization：更强backbone会显著缩小旧memory方法的边际收益。

5.6 Method Deep Dive

Online task stream Q → no-memory baseline → AWM / ReasoningBank → each setting repeated 3 full runs → report mean, std, best–worst gap → run Default / Shuffle-1 / Shuffle-2 → inspect written/retrieved memories → identify underspecification / contagious memories → inject Rubric + Environment Feedback + Prompt Modification → re-run shuffled conditions → measure recovered gap and remaining fragility

5.7 核心公式与数学直觉

Pass@1_r = (1/N) Σ_i 1[task_i success in run r]
Std = sqrt((1/(R-1)) Σ_r (Pass@1_r-Mean)^2)
Best–Worst = max_r Pass@1_r - min_r Pass@1_r

R=3。对stateful agent，best–worst特别重要：10point gap意味着不是“同一个系统小抖动”，而是历史已经把系统带到不同memory states。论文还对RBank WebArena +1.5%的mean gain做t-test，p=0.23，说明这种headline提升并不稳定。

5.8 Toy Example

考虑四个delete requests：A/B容易、C/D困难。默认A→B→C→D时，模型先在A/B上学到稳定forget pattern，后面C/D更容易；换成D→C→A→B，早期D更新过强造成retain损伤，C又在受损state上训练，最后A/B也出现rebound。若agent还有memory，D失败后生成“这类请求一律拒答”的错误策略，后续反复retrieve，就像论文中的API/Haversine contagious memory。于是同一forget set得到完全不同结果。

5.17 Limitation & Failure Modes

5.18 Reproduction View

最小复现可以不跑完整WebArena：选100–200 tasks，no-memory/RBank各3 seeds，default+2 shuffles，记录memory写入/检索。若直接服务unlearning研究，更建议对现有continual pipeline直接跑10种delete order，先看order std和best-worst是否足够大。

5.19 Research Value

5.20 Migration 1 — Adversarial Deletion Order Attack

同一20个forget targets，生成default/random/easy-first/hard-first以及基于pairwise interference/preference geometry的adversarial order。每种3 seeds。指标Final Forget、Retain、Rebound、Order Std、Best–Worst。若最坏顺序显著破坏unlearning，就得到黑盒/continual attack surface。

5.20 Migration 2 — Order-Robust Hardness Curriculum

静态hardness不够，应估计conditional hardness H(target | current deletion state)。训练时随机化邻接并优化worst-order objective。最小实验50 targets，对比easy→hard、hard→easy、random、robust curriculum；看mean和worst-order forgetting。

5.21 Attack / Verification Lens

定义 Order Robustness Envelope：同一forget set在多种request order下的Forget/Retain/Rebound范围。若某method只在一个有利顺序成功，就不能称continual unlearning稳定。攻击者只需控制合法删除请求的提交顺序即可放大残留或collateral。

5.22 与 Paper 2 的关系

Paper1负责“stress”：先制造/发现order-dependent failure；Paper2负责“diagnose”：再定位failure第一次在哪一stage出现。组合为 Stress first, diagnose second。

PAPER 2 · NEWAGENT MEMORY DIAGNOSTICS

D²ACCI: A Dual-Loop Diagnostic Protocol for Evidence-Preserving Agent Memory

Xule Liu, Yijun Liu, Chao Li, Shao Kun · arXiv:2608.17756v2 · revision 2026-08-19 · Status: preprint

Full HTML · Abstract

5.2 一句话定位

用inner memory loop + outer diagnostic loop把memory改动变成可审计决策：不仅看accuracy，还要求paired evidence、protected-slice non-regression和stage-level Diagnostic Coverage Rate。

5.3 人话版

Memory system常见开发方式是“加一个BM25、session memory或forget guard，总分涨了就上线”。D²ACCI认为这样很危险，因为总分可能被少数slice拉高，关键用户场景却退化；更糟的是，最后答错时你不知道问题在store、retrieve、forget filter、context packing还是generation。作者把系统拆成两层。Inner loop执行真实memory pipeline：ingestion、L0原子事实/L1 topic rollup/L2 profile、session memory、retrieval、constraint cache里的forget/update filtering、context assembly、generation；每个stage都必须产生typed trace。Outer loop对每个candidate feature做Full vs Ablated paired evaluation，计算McNemar、bootstrap CI、protected slice delta和DCR，再决定Accept、Reject、Feature-Flag或Accept-with-Monitor。DCR是这篇最关键的metric：它不问“答对了吗”，而问“失败样本至少有几个stage留下了足够ID、score、filter decision、packed context等可行动证据”。MemStack在LoCoMo/LongMemEval/PersonaMem-V2为93.59%/90.93%/57.20%；Supplement、Session、Forget Guard分别+2.71/+3.67/+1.92pp且p≤.003，而BM25/RRF在不同benchmark平均数方向不一致，统计上均被判null feature flag。更强的证据是：某slice trace-adapted与result-only accuracy同为43.33%，但DCR@3=100% vs0%。PersonaMem错误中57.1%来自generation/option scoring、29.8% constraint handling、只有13.0% retrieval miss。这说明“继续优化retriever”可能完全修错地方。

5.4 Background & Research Gap

Agent memory至少有五六个stage，一个final error无法唯一定位。对unlearning尤其明显：目标重新泄漏，可能是旧memory没删、retrieval绕过filter、context重新塞入target，或memory完全干净但parameter仍记得。Aggregate-only evaluation没有root-cause information，也无法安全决定feature是否上线。

5.5 Core Insight

Paired evidence比overall delta强；protected slices防止silent regression；diagnosability与accuracy正交；feature governance允许null组件保留feature flag而非强行promotion。

5.6 Method Deep Dive

INNER conversation/events → ingestion & supplement extraction → L0/L1/L2/session storage → retrieval channels → constraint cache / Forget Guard → context assembly → generation / option scoring → typed trace OUTER Full vs one-feature ablation on same examples → discordant pairs → delta + McNemar p + bootstrap CI → protected slices → DCR threshold → Reject / Feature-Flag / Accept-with-Monitor / Accept → archive evidence

5.7 核心公式与数学直觉

DCR_tau(F;S) = (1/|F|) * Sum_i Indicator[C(d_i) >= tau]

F是failure/discordance集合，C(d_i)是该trace中actionable stages数量。默认DCR@3并要求coverage≥0.90。Actionable由schema验证：retrieval要有top-k IDs/scores，forget guard要有constraint IDs/filter decisions，assembly要有最终packed context，generation要有output/judge metadata。

DCR的价值是accuracy orthogonality：同样43.33% accuracy，一个系统的失败可定位、另一个完全不可定位。它不能保证root cause一定判断正确，但能保证“证据还在”。

5.8 Toy Example

用户要求忘掉“喜欢咖啡”，agent之后仍推荐咖啡。Trace显示delete constraint已创建；L2 profile已删除coffee；但旧session summary仍保留，session retriever把它召回；Forget Guard只过滤L2 facts；assembled context再次含coffee。于是最早泄漏点是session retrieval/filter coverage，而不是generator“参数记忆”。没有trace时两种完全不同的问题会被统称为unlearning失败。

5.20 Migration 1 — Deletion-DCR

给每个delete request一个provenance ID，storage/retrieval/filter/context/generation都记录target lineage。200 scenarios，比较entry deletion、dependency closure、guard-only。指标Leakage、Retain、Deletion-DCR、Earliest Leakage Stage accuracy、False Promotion Rate。

Combined Research Opportunities

1. Order-Robust Continual Unlearning Benchmark

固定同一forget set，只变request order；报告mean/std/best-worst/worst-order，不允许只给一个默认sequence。

2. Deletion-DCR

每次泄漏输出root stage：memory store、retrieval、filter、context、generation/parameter。

3. Adversarial Order Search with Diagnostic Feedback

攻击器根据前几次sequence的discordance和stage traces学习哪些request pairs干扰最强，再组合最坏顺序。

4. Conditional Hardness Predictor

不只预测H(target)，而预测H(target | current deletion state)，把“难忘程度”变成sequence-dependent quantity。
