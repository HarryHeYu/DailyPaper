5.2 一句话定位

这篇工作不是新的 unlearning 算法，而是在审计：当 unlearned checkpoint 与 retrained oracle 的 BatchNorm running statistics 来自不同拟合过程时，公开 forget/retain/test 数字乃至 pass/fail verdict 有多少是“部署状态 convention”造成的，而不是“被删除数据仍存活”。

5.3 人话版

很多vision unlearning论文把unlearned model和“去掉forget set后从头retrain”的oracle比较，根据forget、retain、test accuracy或衍生准则判断是否足够像retrain。作者指出：带BatchNorm的模型不只有可训练权重θ，还携带running mean/variance φ，这些统计量参与inference却不是梯度参数。Retrained oracle只看retain data，所以其φ天然沿retain-only trajectory形成；unlearned checkpoint的φ则取决于具体procedure是否冻结buffer、是否在包含forget records的batch中更新、以及weight变化后buffer是否stale。作者对263个公开checkpoint先anchoring，再保持θ字节级不变，仅用retained data重新拟合φ。221个可做10次replicate census的checkpoint中，47个指标移动超过预先固定的±1.2pp margin；12个公开verdict发生crossing，4个超过实测recalibration budget，2个在10次re-keyed refit上都稳健。关键机制实验显示，把retain fitting records换成removed records几乎不移动metric，真正与shift相关的是shipped state相对retain-only refit的staleness。因此这不是“forget data藏在BN里”的简单恢复故事，而是审计两端的deployed-state convention不一致。论文也明确限定：LayerNorm/RMSNorm LLM没有这一BN通道。

5.4 Background & Research Gap

经典unlearning把omission retrain当gold reference，默认比较两端除了“是否经过unlearning”外其余状态可比。但ResNet类checkpoint的inference state可写成(θ,φ)：θ是trainable tensors，φ是BN running statistics。即使θ相同，换φ也会改变activation normalization。更重要的是，oracle的φ在retain-only训练中自然形成，而unlearned checkpoint的φ可能来自base state、混合batch或unlearning过程。公开release通常不记录φ的index set、transform、accumulation rule。

一个具体checkpoint原criterion |d_f-d_t|=0.0414，小于0.05而通过；θ不变、仅retain-only refit φ后变成0.0573，verdict反转。Research gap不是“BN recalibration会变accuracy”——这早已知道；而是公开unlearning表格和verdict对一个未报告state convention究竟有多敏感、这种敏感是method-level还是artifact-level、是否来自removed-data provenance。

5.5 Core Insight

完整artifact而非weights：删除audit读的是m(θ,φ)。
checkpoint-level：method平均稳定不代表每个artifact稳定。
provenance不是主因：把retain records换成removed records几乎不动。
staleness更匹配：shipped φ与current-θ retain-refit φ̂的距离才跟shift走。
crossing只是sensitivity：retain-only refit是第二个合理convention，不是作者宣布唯一正确答案。

5.6 Method Deep Dive

released checkpoint (θ,φ) → reproduce published cells as shipped (anchoring) → freeze θ byte-identically → sample retained fitting pool → use producer training transform → exact BN-statistics refit → φ_hat → recompute same published metrics → Δm = m(θ,φ_hat)-m(θ,φ) → repeat 10 independently re-keyed pools → exact sign test + FDR control per checkpoint → clustered family equivalence analysis → provenance swap / state-distance / matched-weight controls → re-run original pass/fail criterion → quantify crossings and scope

Anchoring保证不是loader错误；exact refit消除EMA/order影响；10次replicate给per-artifact test足够离散p-value；family层使用cluster-aware interval，允许equivalent/different/unresolved三种结论。然后作者不是停在“数字动了”，而是用provenance swap、omission-reference control、frozen-buffer twin、quantization control逐个排除替代解释。

5.7 核心公式与数学直觉

metric: m = m(θ,φ) state rebuild: φ_hat = Refit(retain_indices, θ, producer_train_transform) displacement: Δm = m(θ,φ_hat)-m(θ,φ) primary practical margin: |Δm| > 1.2 pp family equivalence: 90% interval ⊂ [-1.2,+1.2] → equivalent interval outside margin → different interval spans margin → unresolved

最关键是θ/φ解耦。Δm不是“unlearning变好”，只是同weights在不同合理state convention下读数差。±1.2pp来自预先固定的published seed spread尺度。统计上最值得你借鉴的是equivalence而非普通NHST：无法证明等价时必须报告unresolved，不能把“不显著”写成“相同”。

5.8 Toy Example

  1. base ResNet为θ₀,φ₀。
  2. unlearning后权重变θu，但某procedure冻结BN，φ仍接近φ₀。
  3. oracle retrain只看retain data，得到θr,φr。
  4. 公开audit比较m(θu,φ₀)和m(θr,φr)。
  5. 固定θu，用retain data重建φ̂u。
  6. 若forget accuracy从2%变4.5%，说明metric对state convention敏感。
  7. 再把refit pool全换forget data，若只4.50→4.56%，removed provenance解释不足。
  8. 若||φ₀-φ̂u||与shift相关，则更像stale buffer。
  9. checkpoint靠近criterion时可能发生pass/fail crossing。

5.14 Ablation / Mechanistic Analysis

θ固定只改φ后metric移动，建立state因果影响；retain→removed provenance swap近0，反驳“数据是谁”解释；omission reference refit≈0，说明operation本身不会必然制造movement；matched weight movement仍出现大buffer residual，反驳“只是权重动多”；normalization-free/quantization负control进一步限制scope；cluster sensitivity显示统计设计不足时应报告unresolved。

5.15 Claim vs Evidence

Authors Claim：带BN的公开unlearning数字可能依赖未报告state convention，且movement更像state staleness而非removed-data provenance。
Actually Show：两套第三方release、263 anchored artifacts和多类control支持这一窄claim；12个原verdict确实cross。
Not Proven：并非所有unlearning都受影响；method ranking很少反转；多数crossing未超实测budget；不能直接外推LLM；forgetting-quality证据很窄。

5.2 一句话定位

MAPLE把“每次自然语言优化请求重新生成solver”改成可持续维护的 executable-state Agent：同时记住输入表、可执行优化程序、已接受方案、候选搜索群体与历史更新，并根据revision风险决定复用旧搜索状态还是full restart。

5.3 人话版

现实业务不是一次性prompt：今天排班，明天新增员工，后天要求保留昨天某人的岗位，再后来目标优先级发生变化。若每次从头生成solver会丢历史决定；若盲目复用旧code/population，又可能把已失效结构带进新问题。MAPLE把工作区显式化为S_t=(D_t,W_t,A_t,P_t)：数据、Workbench程序、accepted output、candidate population，并配event history E_t。LPD定位revision改了什么；LSM把“之前提到的客户/分配”绑定回accepted plan；TSS固定decision type及mutation/crossover/repair；最后根据change summary选择Warm reuse或Full restart。更新只有compile、smoke-test、执行与output-contract都通过才commit，否则rollback。新benchmark NLDO包含15条trajectory、180次更新，主run中动态单目标solve rate100%、quality0.951，多目标100%、HV0.875；Persistent ReAct只有51.3%/0.501和11.5%/0.042。论文真正新意不是GA或memory本身，而是把code、accepted decisions和search population都当成persistent executable state。

5.4 Background & Research Gap

现有OR Agent通常在static benchmark中把自然语言转成LP/MILP或solver code，但真实环境更像持续维护Git工作区：旧决策已被业务接受，后续update只改局部约束。系统既要continuity，又要minimal edit，还要在结构变化大时安全restart。Persistent ReAct虽保留code和answer，却没有独立candidate archive、typed binding和search-state policy。MAPLE填的gap是：让LLM optimization agent维护可执行、可验证、可回滚、可复用search state的动态问题。

5.5 Core Insight

Agent memory不只是文本，而是solver code、accepted decision、candidate population、event records；历史自然语言引用必须绑定到accepted state才能真正执行；revision应只改requested surfaces；旧population的reuse必须是条件决策；长期状态必须有commit/rollback semantics，而不是LLM说“修好了”就继续。

5.6 Method Deep Dive

x0,D0 → LLM builds Workbench W0 → compile/smoke test/≤3 repair → fixed solver → validate output contract → commit S0=(D0,W0,A0,P0), E0 for each update u_t: → LPD locates changed data/decision/evaluation/binding → LSM resolves references from events + accepted plans → copy previous committed state → patch only requested tables/functions → compile + smoke-test + repair → compare old/new state Δ_t → assess reuse risk → Warm repaired candidates or Full fresh population → numerical search → validate solution + protocol → pass: commit S_t and append event → fail: rollback to S_{t-1},E_{t-1}

LPD负责localization；LSM负责“语言历史→具体entity→accepted assignment”的typed binding；TSS把decision type与operators绑定，减少LLM自己发明representation导致的不稳定；Warm最多修复100个old candidates再补fresh，Full则200 fresh；fixed checker只接受有结构证据的restart理由；commit机制防止坏update污染后续trajectory。

5.7 核心公式与数学直觉

S_t=(D_t,W_t,A_t,P_t) S_t=Φ(x0,u_1:t,S_{t-1},E_{t-1}) SolveRate = 1/(T+1) Σ r_t v_t OnlineQuality = 1/(T+1) Σ r_t q_t Q_scalar = 1[feasible] * max(0,1-max(0,f_t(x)-f*_t)/max(|f_t(x)|,|f*_t|,1)) failed revision ⇒ no commit

S_t是全文最重要公式：它把长期Agent state从chat history扩展到数据、代码、输出与search population。r_t表达strict accepted prefix，一次failure可使后续suffix失去eligible status；v_t/q_t区分数学validity和quality。多目标用HV↑与IGD↓。与Persistent ReAct根本差异不是“多一段prompt”，而是独立P_t、typed state、binding和commit语义。

5.14 Ablation / Mechanistic Analysis

去TSS使routing quality约0.669→0.336且token更多、方差暴涨；只给events知道“谁”但不知道accepted assignment，只给plan知道assignment但不知道历史语言指谁，二者必须合用；Always Warm略优Always Full，说明reuse有价值；adaptive MAPLE再小幅提升，restart selector不是主体增益；aux-field re-score将Persistent ReAct大幅抬高，证明评测协议应与数学能力分开。
