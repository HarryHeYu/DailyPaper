Executive Summary

今天的核心不是一个新 loss，而是定义边界。 RD-Forget 把“forget”定义为 query-local selective use，明确保留 source archive；这与 Machine/Agent Unlearning 追求的不可恢复删除不是同一问题。最值得建立的新 evaluation taxonomy 是：Storage Accessibility、Behavioral Influence、Recoverability 三轴。

Kernel-Managed Shared Memory 表明 Multi-Agent memory 治理可以下沉到 kernel，因此 delete/tombstone 也能变成系统 invariant；Subagents vs Agent Skills 则说明 skill 的执行 substrate 本身影响恢复面。ContractEval/OpenDiscoveryTrace 进一步提示：final answer 无泄漏并不能证明中间 trace 没有使用 target。

Tier S

1. RD-Forget — What Should an Agent Forget?

基本信息：Yuhang Li / Yuchen Li；arXiv:2609.10263v1；Paper。

人话版

RD-Forget研究的是“旧事实什么时候不应该用于当前答案”，而不是“把事实真正删除”。系统始终保留完整 source archive H；query 到来后，curator 按问题抽取证据、按 subject|relation|scope 分 semantic slot，同 slot 新值把旧值标成 SUPERSEDED；current query 默认禁用旧值，historical query 可 rescue。四模型×三主 benchmark 共12 cell 全部领先；GPT-5.6-Luna 平均86.71%，ACE 67.26%、ReasoningBank 64.46%。但旧source从未删除且可被历史query重新取回，因此它是强 Selective Use Forgetting，不是 Hard Unlearning。

Method Deep Dive

H + query q → query-conditioned curator → semantic slots / supersession → historical-intent gate → eligible evidence → selector → pack under 2048 tokens → frozen answer model
Z*(q) ∈ argmin D_q(Z), subject to Σc(m)≤B D_q(Z)=E[d(Y,gθ(q,Z))|q,H]

目标是在固定 context budget 下最小化 answer distortion，不优化 target 是否从系统不可恢复。

Results

  • Qwen 66.59 vs ACE 48.86 / RB 45.97。
  • Luna 86.71 vs 67.26 / 64.46。
  • MiniMax 77.13 vs 57.77 / 53.36。
  • Kimi 72.83 vs 64.30 / 62.68。
  • Luna -FORGET：91.86/93.59/74 → 68.60/60.26/51。
  • -QC：77.91/82.05/56，说明 query-conditioned curation 是第二关键模块。

Claim vs Evidence

证据支持 storage/use 分离更适合处理更新与历史，但未证明隐私删除、法规删除、archive compromise 或参数级知识删除。

Migration

建议将 memory state 明确拆成 ACTIVE / SUPERSEDED / HARD-DELETED，统一评估 Storage Accessibility、Behavioral Influence 与 Recoverability；在 LME-KU + PersonaMem 上比较 RD-soft、source delete、execution-state replay、agentic unlearning，并加入 historical/tool-action/adaptive recovery probes。

记住5句话

  1. RD-Forget 控制 use，不删 storage。
  2. 12 个主 cell 全部领先。
  3. -FORGET 在 LME-KU 下降 33.33pp。
  4. 旧事实可以被 historical query 重新启用。
  5. 它正好说明 behavioral forgetting ≠ unlearning。
2. Kernel-Managed Shared Memory

基本信息：Ryan Lum, Yongfeng Zhang；Rutgers University；arXiv:2609.10144v1；Paper。

人话版

论文把 Multi-Agent memory 从“每个 Agent 自己搜/过滤”提升成 kernel service。ProfileAgent/TaskAgent 只写结构化 memory，AssistantAgent 不直接 retrieve；kernel 统一做 user identity、write-before-read barrier、sharing visibility、ranking、token budget 和 prompt injection。3 models×4 methods×150 trials=1,800 trials中，kernel_shared 相比同底层 Mem0 但无 orchestration 的 mem0_default 提升约2.4–4.0分；GPT-4o Profile Usage 1.05→4.69。相较 full naive context，GPT-4o/Qwen 基本打平，同时 latency 下降15–61%。

Method

writer agents → standardized metadata → write barrier → retrieval → visibility invariant → rank/dedup/budget → kernel injection → retrieval-free assistant
visible(m,a)=true iff owner(m)=a OR sharing=shared

Results

  • GPT-4o kernel 4.69/4.99/4.61 vs Mem0 1.05/1.03/1.00。
  • Llama 3.87/4.33/3.63 vs 1.07/1.31/1.04。
  • Qwen 3.63/4.40/3.58 vs 1.24/1.60/1.19。
  • Latency GPT 19.2→7.5s，Llama25.5→21.7，Qwen36.3→26.3。
  • Fully private endpoint 0/450 exposure。

Migration

将 Multi-Agent Unlearning 做成 kernel-enforced delete syscall：delete_memory(target,user,scope,epoch)，所有 retrieval/injection 统一检查 tombstone，derived memories 带 parent IDs。重点测 concurrent write、stale replay、cross-agent sharing。

记住5句话

  1. 共享memory应由kernel管理。
  2. 同Mem0 provider，加kernel后质量从近floor升到4分以上。
  3. visibility可成为系统invariant。
  4. latency下降15–61%。
  5. 这为Multi-Agent delete syscall提供了系统入口。
3. Subagents vs Agent Skills

基本信息：Wasu Top Piriyakulkij et al.；arXiv:2609.09233v1；Paper。

人话版

同一个 skill package 可把 SKILL.md 直接塞进主Agent context，也可启动 fresh-context subagent 执行。只有 skill 具有清晰 I/O contract 与 procedural instructions 时，subagent 才稳定更好；若只是松散知识，直接注入 context 并不差。SkillsBench 87 tasks 中成功构造 64 个 procedural+contract skills；context 压力增加时 subagent 更稳，强模型上80%以上任务降低 peak context，但 total tokens 更高。对 Skill Unlearning，subagent 是新的隐藏恢复面。

Method

AgentSkill: skill → instructions into main context Subagent: input contract → fresh worker context → procedure → output contract
ω=(Iω,πω,βω) Subagent(s): X_in → X_out

Results

  • 无I/O contract时AgentSkill与Subagent相当或前者更好。
  • 加入procedural+I/O contract后趋势反转。
  • distracting tools增加时Subagent下降更慢。
  • 强模型上80%以上任务降低peak context。
  • 代价是total token明显增加。

Migration

在20个SkillsBench skills上比较 registry / description / resource / worker-memory 四层删除，分别测试 AgentSkill 与 Subagent execution。指标 Skill Recovery ASR、Registry Leakage、Subagent Behavioral Leakage、Retain SR、tokens。

记住5句话

  1. 同skill内容，执行方式会改变能力。
  2. 没有I/O contract时Subagent不一定好。
  3. 有procedural contract后趋势反转。
  4. Subagent省peak context但更费总tokens。
  5. Skill Unlearning必须把Subagent当独立恢复面。

Tier A

4. ContractEval

把自然语言SOP编成query-active expected graph，再与observed trace匹配，检查omission/branch/order/extra action/invariant/output contract。200 clean+1200 perturbations=1400 cases；普通output judge平均检测0.495，trace judge0.570，gold-graph ContractEval detection/localization均1.000，LLM-backed GPT-5.4为0.982/0.903。迁移到Unlearning：把SOP obligations换成Deletion Obligations，检查target retrieval、tool arg、retain invariants。Worth Deep Reading: YES。

5. OpenDiscoveryTrace

558条AI scientist完整trajectory、124科学任务、每step 9字段。三frontier final success均84–89%，但Claude错误约2.5/trajectory，GPT-5.4仅0.08，约30×差距；final success会掩盖process failure。迁移：构建Trace Residual Leakage benchmark，检查final不泄漏时中间search/tool/memory是否仍使用target。Worth Deep Reading: YES。

6. Black-Box Red Teaming of Agentic AI

仅需系统描述就自动构造多步agent攻击；七risk domains，每domain120 scenarios。核心迁移：将taxonomy替换为direct/paraphrase/multi-hop/tool/memory/cross-agent/reacquisition route，让攻击Agent自适应搜索恢复路径。Worth Deep Reading: YES。

7. Do Agents Know When They Succeed?

利用trajectory residual-stream动态与action representation probe预测最终success，跨Bash/SQL/Python与Qwen/DeepSeek模型优于surface calibration，无需额外rollout。可直接迁RULER：将label替换为post-unlearning residual leakage/hard-to-unlearn。Worth Deep Reading: YES。

Tier B

8. The Menu Is an Execution Prior

Tool menu应覆盖可执行state path而非query top-k。ToolBench online success 0.737→0.898。对Tool-level Unlearning：不能只禁final tool，还要检查producer chain是否仍能间接恢复target capability。Potential Use: Tool-level Deletion Closure / Evaluation。

9. AgentAudit

从完整trace评planner、memory、tool selection/invocation、alignment/security/execution integrity等十维。对Unlearning可用于stage-wise定位memory residue、planning residue、tool-action residue。Potential Use: Evaluation / Failure Attribution。

10. Procedural Memory Under Change

32 formal cells里，在current evidence明确充分时没有观察到预定义interference signature。重要negative control：stored residue不一定有behavioral causal effect。Unlearning应同时报告Stored Residue与Behavioral Causal Effect。Potential Use: Negative Control。

Collision Detection

⚠️ Agent Forgetting terminology HIGH：RD-Forget保留archive并支持historical rescue，不能等同Hard Unlearning。后续研究必须把“不可用”“不影响行为”“不可恢复删除”拆开。

⚠️ Agent Deletion Closure HIGH：Execution-State Unlearning覆盖runtime descendants，CONTINUITY覆盖context continuity，Kernel Shared Memory覆盖kernel governance。剩余空间主要是跨层Hard Delete contract、Multi-Agent concurrency、parameter+memory joint deletion。

⚠️ Skill Unlearning HIGH：Repo-To-Skill、MASkills、Persistent Skills、SCAFFOLD、Subagent Skills已覆盖storage/evolution/composition/invocation；必须突出delete/reacquisition/hidden execution substrate。

⚠️ Black-box Recovery HIGH：UMPeek、Stress Testing、Black-box Agent Red Teaming都走向adaptive search；固定prompt ASR不足。

⚠️ Trace-level Evaluation LOW-MEDIUM：通用trace evaluation已拥挤，但target-specific deletion obligations仍有空间。
