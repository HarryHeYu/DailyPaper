Executive Summary

Machine Unlearning：今日新增高价值材料主要落在 auditing 与 privacy leakage，而不是新的 forget objective。值得重点补读的是 Auditing of Unlearning Algorithms 与 Membership Inference Beyond the Forgotten Set：前者尝试把黑盒攻击结果转换为 unlearning guarantee 的经验下界；后者把隐私面从 forget 扩展到 retain，提示 unlearning 可能让保留训练样本更容易被识别。

Agent / Multi-Agent：今日最明显趋势是 memory/skill evaluation 从“能否检索”升级到“是否仍有效、适用于谁、是否值得验证、错误应归因给谁”。Stale Constraints、SkillFeed、DoCtOR 分别从 verification budget、profile counterfactual、multi-agent credit assignment 三个角度给出可迁移机制。

Inference-time：REINS 的核心不是又一个 refusal vector，而是将 harmful-path inhibition 与 refusal-path enhancement 拆成两路 SAE feature control，再用 Gate 控制 locality。对 representation-level unlearning 很有启发，但必须与 true deletion 明确区分。

Today's Most Important Paper

When Stale Constraints Go Unchecked: Budgeted Verification Failures in Inherited Agent Memory

它最值得关注的不是一个新 Agent architecture，而是一个非常干净的 failure decomposition：source 已经被更新或撤销、provenance link 仍存在、derived memory 仍然保留、Agent 只有有限验证预算，于是关键 provenance path 根本没有被检查。研究上可以直接迁移为 Provenance-Budgeted Agent Unlearning Auditor：删除源信息后，不只问“源还在不在”，而要问 summary、memory、skill、decision 这条 descendant chain 是否会因为 verification allocation 失败继续影响未来行为。

  3. SkillFeed — 最值得学：保持 task 不变、只改变 profile 的 counterfactual routing evaluation。

Tier S

1. REINS: Refusal-Enhanced Inhibitory Steering with Sparse Autoencoder Features

Paper · Code

人话版

REINS 不把安全 steering 简化为“往拒答方向推”。它先根据当前 prompt 的早期 continuation，用 SAE feature attribution 找出正在支持 harmful continuation 的特征并抑制；再用一组拒答校准样本挑出真正与 coherent refusal 有关的 features 并增强。最后用 Gate 决定哪些请求需要 intervention，以减少对正常任务的副作用。

Background & Gap

单一 dense steering vector 往往把内容、格式与安全行为混在一起。复杂 wrapper 下，模型已经进入“继续正常完成任务”的 harmful trajectory，此时只增加 refusal signal 等价于踩刹车但不松油门。SAE 提供稀疏 feature coordinates，使“压危险路径”与“增强安全替代路径”可以分开处理。

Core Insight

安全控制应拆成两个不同目标：Harm-Inhibit 降低当前 unsafe continuation 的 feature support；Refusal-Enhance 提高 coherent refusal trajectory 的可达性。两者都在 SAE feature space 操作，但前者是 prompt-specific，后者是 calibration-derived。

Method Deep Dive

Prompt → unsteered early continuation → SAE feature attribution → Top-K harmful-support features → suppress harmful features → refusal calibration pairs → refusal-specific features → enhance refusal features → optional Gate → final generation

第一步先让模型生成短 early prefix，避免只根据输入文本猜测危险机制。随后用 gradient×activation 找到对该 prefix 有正贡献的 features。拒答分支则比较 refusal、neutral answer 与原始 harmful continuation 中的 feature activation，只保留在 refusal 中特异增强的 features。最终联合 intervention。

Experiment / Results

在 Qwen3.5-4B 上，GUISE harmful response rate 从 90.3% 降到 26.3%；strong baseline CorrSteer-A 为 43.7%。REINS 的 coherent refusal rate 达 63.7%，同时 collapse rate 约 2.7%，说明它并非主要靠输出崩坏制造“安全”。直接 REINS 会带来 utility/locality 损伤，而 Gate 可把 MMLU-Pro、GPQA 基本恢复，并把无关输出变化显著压低，同时 harmful behavior 指标几乎不变。

Contribution / Limitation

New Mechanism：将 harmful inhibition 与 refusal enhancement 解耦。New Evaluation：同时关注 HRR、SRR、collapse、utility 与 collateral effect。限制是它本质仍是 inference-time control，不能证明 underlying knowledge 已删除；如果 early prefix 被攻击者刻意伪装，feature attribution 也可能选错。

Migration

可改成 Bidirectional Feature-Level Unlearning：将 harmful continuation 换成 forget-target continuation，将 refusal calibration 换成 retain-neighbor behavior calibration。最小实验：Qwen/LLaVA 选 20 个 forget targets，direct/paraphrase/cloze 三 views，比较单向 suppression、双路 intervention、GA/NPO；指标包括 worst-view recovery、retain FPR、CE 与 representation residual。

如果只记住 5 句话

  1. 只增强 refusal 不够，因为 harmful path 仍活跃。
  2. REINS 把 suppression 与 replacement 拆成两套 feature controllers。
  3. 安全指标提升不能只看 harmful rate，还要看 collapse 与 utility。
  4. Gate 的主要作用是恢复 locality。
  5. 迁到 unlearning 时必须加入 recovery audit，避免把 steering 误称为 deletion。
2. Beyond Task-Only Matching: Personalized Skill Routing with Counterfactual Evaluation

Paper · Project

人话版

普通 skill router 只问“这个 task 像不像某个 skill”。论文指出，同一个 task 对不同用户 profile 可能应该选择完全不同的 skill，因此构造 profile-counterfactual pairs：task 保持不变，只改 profile，并要求正确 skill 切换。SkillFeed 用 task retrieval、skill body evidence 与 profile-aware reranking 联合解决这个问题。

Core Insight

Skill applicability = task relevance ∩ profile compatibility。真正严格的 routing benchmark 不是平均 Hit@k，而是保持 task 不变、仅改变 profile 后，router 是否能按约束切换到另一 skill。

Method

Task + Profile → dense/BM25 candidate retrieval → skill body chunk retrieval → profile-aware evidence fusion → listwise reranker → selected skill

第一阶段学 task-skill relevance；第二阶段加入 profile-sensitive counterfactual negatives。关键不在 InfoNCE/listwise loss 本身，而在 hard negative 设计：负样本在 task 层高度相似，只在 profile suitability 上冲突。

Experiment / Results

SkillFeed-Bench 包含 profile-sensitive、profile-insensitive 与 profile-counterfactual splits。task-only router 在普通 query 上可以很强，但在 counterfactual split 上显著失效；加入 profile conditioning 后，counterfactual routing 有大幅恢复。Full pipeline 的总体 Hit@1 约 75.1%，而 profile-sensitive setting 是最明显的增益来源。

Contribution / Limitation

New Benchmark / Protocol：profile-counterfactual routing。Engineering：retrieval + rerank 组件较标准。限制是 benchmark 中 profile 明确且结构化，而真实用户约束可能缺失或冲突；论文也没有直接研究 skill revocation/deletion。

Migration

最直接方向是 Counterfactual Revoked-Skill Routing：删除某 skill 后，在相同 task、不同 profile、不同 alias/body paraphrase 下测试它是否被重新召回。指标：Revoked-Skill Hit@1/5、Substitute Recovery、Retain Routing Accuracy、ASR@budget。

如果只记住 5 句话

  1. Skill 是否适用不能只由 task 决定。
  2. Counterfactual profile 是更严格的 evaluation。
  3. 平均 Hit@k 会掩盖 profile-sensitive failure。
  4. 最重要创新是 benchmark/evaluation，而不是 loss。
  5. 它可以直接迁成 Skill Unlearning 的 revoked-skill closure test。
3. When Stale Constraints Go Unchecked: Budgeted Verification Failures in Inherited Agent Memory

Paper

人话版

论文研究一个很实际的问题：Agent 的 inherited memory 有 provenance，但 source 后来已被新记录撤销；Agent 每轮只有两个验证槽位。结果多数模型不会把预算花在“看起来已经确定”的旧约束上，于是继续服从 stale memory。只要在相同预算下强制把一个验证槽位分给关键 lineage，大多数错误马上消失。

Core Insight

失败不是“没有 provenance”，而是 verification allocation failure。可追踪性只保证“理论上能查到”，却不保证有限预算下 Agent 会真的去查。

Method

Inherited memories → target consolidated memory → underlying source becomes superseded → budget=2 verification slots → native allocation → decision vs. → forced-critical same-budget allocation → decision

最关键实验保持验证预算完全相同，只改变哪个 source record 被曝光，因此能较干净地区分“预算不足”与“预算分配错误”。

Experiment / Results

Primary、fresh-wording、held-out/corrected replication 都出现相同趋势：在 superseded world 的 native policy 下，大约四分之三决策仍服从 stale constraint；forced-critical 同预算 intervention 可带来约 60–80pp 的 authoritative-consistent decision 增益。尤其重要的是：native policy 一旦真正拿到 target current record，决策通常就能修正，说明瓶颈主要在 exposure/allocation，而不是 evidence integration。

Contribution / Limitation

New Empirical Finding / Evaluation Protocol：把 provenance failure 从“是否可追踪”推进到“有限预算下会不会检查”。限制是 controlled task 较小，forced-critical 使用 oracle knowledge，不能直接当 deployment scheduler。

Migration

构建 Source→Summary→Memory→Skill lineage；删除 source 后比较 native verification、forced-critical oracle 与 risk-aware scheduler。指标：Deletion-Consistent Decision、Critical-Path Visit Rate、Residual ASR、Budget@95%Closure、Retain Utility。这个方向是今天最强 Research Idea。

如果只记住 5 句话

  1. Provenance link 存在不等于 Agent 会去看。
  2. Stale memory 可以因为验证预算分配而持续影响决策。
  3. 相同预算只改变检查对象，就能修复大部分错误。
  4. 这说明 deletion closure 必须覆盖 derived memory 与 verification policy。
  5. 它非常适合直接改造成 Agent Memory Unlearning benchmark。

Tier A

4. Auditing of Unlearning Algorithms

Paper

人话版：把 membership inference 从“分类准确率”升级为对 unlearning claim 的统计审计，并尝试给出与 certified guarantee 对齐的 ε lower bound。高 ε_LB 表示 unlearned model 与真正 retrained reference 仍然容易区分。

Method：用 balanced sign vector 决定多个 candidate forget batches 是否参与删除，再从 unlearned model 输出中猜 sign vector，通过 hypothesis testing 把猜测能力转换成经验 ε 下界。

Research Value：Evaluation ★★★★★，Attack ★★★★★。迁到 LLM/MLLM 时，可把 candidate batches 换成 identity/claim groups，比较 GA/NPO/RMU/retain oracle。Worth Deep Reading: YES。

5. Membership Inference Beyond the Forgotten Set

Paper

人话版：攻击目标从“forget vs non-member”改成 forget / retain / unseen 三分类。关键发现是 unlearning 也会改变 retain samples 的输出分布，导致本来应该保留的训练样本更容易被识别。

Migration：MLLM 中构造 Forget、Retain-near、Holdout 三类，测 score-side、teacher-forced likelihood、pairwise preference 与 Δscore。指标：macro-AUROC、retain-member AUC、privacy-utility curve。Worth Deep Reading: YES。

6. When Not to Imitate: Boundary-Aware Skill Memory

Paper

人话版：成功 trajectory 蒸馏出的 skill 可能在 near-miss task 上把 Agent 带进错误工具。BASM 为 skill 增加 applicability、risk、avoidance、recovery boundary，使“照着做”变成“满足条件才做”。

Main Finding：论文报告普通 success-distilled memory 会显著增加 risky state 的 wrong-tool preference；boundary-aware memory 在 AppWorld/BFCL/AgentDojo 上同时改善 success、安全与步骤效率。

Migration：删除 skill core 后还要测试 boundary text 是否能恢复 target tool preference，适合作为 Skill Unlearning 的 descendant leakage test。Worth Deep Reading: YES。

7. Finding Where the Buck Stops / DoCtOR

Paper

人话版：Multi-Agent 失败后，不让所有 agent 都反思，而是先找 decisive error agent + step，再生成 counterfactual correction，只让真正负责的 agent 写 reflection。

Migration：把“谁造成 target information propagation”当 causal credit assignment，删除决定性 communication chain，而不是全局清空 shared memory。Worth Deep Reading: YES。

8. What Makes Agent Memory Useful for Reliable Unanswerable Question Handling?

Paper

人话版：同一历史 experience 可被写成 compact trajectory、insight、principle、success trace、workflow，不同 representation 对 Agent 的长期行为影响明显不同；组合更多 memory 也不一定更好。

Migration：做 Representation-Specific Memory Unlearning：同一个 target experience 同时写成 trajectory/principle/workflow，删除一种后测试其他 representation 是否继续保留 target behavior。Worth Deep Reading: YES。

Tier B

9. ITER: Interaction-Aware Retrieval for Agentic Search

Agentic search 的 retriever 不应该只看当前 sub-query，而应结合 main question 与之前 sub-queries。价值在 trajectory-conditioned retrieval：删除一个 trajectory segment 后，未来 retrieval distribution 可能仍因剩余 history 而保留 target influence。Potential Use: Trajectory Unlearning Evaluation。

10. GOD: Govern, Observe, and Direct

多 Agent control room：支持实时观察、提问、干预与 replay。对 unlearning 的核心价值不是 SOTA 算法，而是把 deletion before/after intervention 做成可重复 experiment harness。Potential Use: Multi-Agent Unlearning Benchmark Infrastructure。

11. Bolt-on, Verifiable Provenance for LLM-Powered Data Processing

Paper

BLIP 要求找到一个输入子集，使 LLM 仅看到这部分时仍能复现同一答案，并尽量最小。对 deletion closure 的迁移非常直接：先找 target behavior 的多个 minimal provenances，再执行删除；只有所有可验证 provenance 都失效，才更接近 operational closure。

12. CoCoBench

Paper

把 embodied multi-agent coordination 拆成 task allocation、sequential ordering、mutual exclusion、handoff coordination。对 Multi-Agent Unlearning 可用于判断删除某共享信息后，到底是哪类 coordination mechanism 被误伤，而不是只看最终 success。

Idea Mining

Idea 1 — Provenance-Budgeted Agent Unlearning Auditor

Inspiration：Stale Constraints + provenance verification。Gap：现有 Agent Unlearning 很少区分 source deletion、derived-memory persistence 与 verification allocation failure。

Hypothesis：很多 deletion failure 的主因不是 deleted source 仍可检索，而是 stale summary/skill 在有限验证预算下继续被当作 authoritative。

MVE：Source→Summary→Memory→Skill→Action lineage；6/20/100 memories 三规模；20 deletion targets；Qwen/Llama/DeepSeek；比较 hard-delete source、delete retrieved memory、full reset、provenance-aware invalidation。

Metric：Deletion-Consistent Decision、Critical Path Visit Rate、Residual ASR、Budget@95%Closure、Retain Utility。Novelty ★★★★★ · Feasibility ★★★★★ · Compute ★★☆☆☆ · Collision Risk 中 · Best Venue NeurIPS/ICLR。

Idea 2 — Counterfactual Revoked-Skill Routing

Inspiration：SkillFeed + BASM。删除 target skill 后，在相同 task、不同 profile/constraints 下测试它是否通过 alias、body evidence 或 substitute routing 被重新召回。

Metric：Revoked Hit@1/5、CF-Recovery、Retain Routing、Task Success。Novelty ★★★★★ · Feasibility ★★★★★ · Compute ★★☆☆☆ · Collision Risk 低中。

Idea 3 — Bidirectional Feature-Level Inference-Time Unlearning

Inspiration：REINS。SAE attribution 定位 forget continuation features，同时从 retain-near samples 校准 retain features，联合 suppression + enhancement，再用 adaptive recovery attack 测真实性。

风险：最主要问题是 steering ≠ true unlearning，因此论文必须把 verification/recovery 放到核心，而不是只报告 output suppression。Novelty ★★★★☆ · Feasibility ★★★★☆ · Compute ★★★☆☆ · Collision Risk 中高。

Idea 4 — Causal Multi-Agent Communication Unlearning

Inspiration：DoCtOR。用 counterfactual failure attribution 找 target information 的 first decisive propagation step，再只删除 decisive message/memory lineage，与 all-agent reset 比较。

Metric：cross-agent leakage、retain success、deletion size、reacquisition time。Novelty ★★★★☆ · Feasibility ★★★★☆ · Collision Risk 中。

Collision Detection

⚠️ Agent Memory / Skill Unlearning：Agentic Unlearning、From Recall to Forgetting、OBLIVION、WikiSkill、When Unlearning Fails、MAP-Graph、BASM、SkillFeed 已覆盖多个邻近角度。单纯“删 memory 后测性能”创新不足。更清晰的 gap 是 verification-budgeted deletion closure、profile-counterfactual revoked-skill recovery 与 cross-representation closure。

⚠️ Inference-time / SAE Unlearning：SAE steering、activation editing、representation intervention 已很拥挤。如果只是找到 forget features 并抑制，容易被归类为 steering/editing。必须加入 unlearning-specific threat model、adaptive recovery、retain-neighbor locality、semantic-view closure。

⚠️ Black-box Audit：MIA AUC 或单一 prompt ASR 已不足；更值得做 sample-level residual predictor + query budget + counterfactual views + formal/statistical lower bound。
