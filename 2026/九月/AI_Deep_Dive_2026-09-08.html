为什么选这 2 篇

今天的两篇都直接落在“因果后代 / 派生状态”这一条主线上。第一篇提出 execution-state unlearning：删除一个源 memory 远远不够，summary、plan、tool arguments、KV cache 等所有 downstream state 都可能继续保留其影响；第二篇则从 multi-agent failure trace 中显式构造 causal-inspired dependency graph，寻找真正决定最终失败的早期步骤，而不是停留在表面症状。它们共同提供了一个比“相关性传播”更强的研究框架：先发现依赖，再做 intervention / replay 验证。

共同主题：不要只删除或修正表面节点，而要沿 dependency graph 处理真正的后代状态，并用 counterfactual / replay 检查这些后代是否真的受 source 影响。

5.2 一句话定位

它把 Agent unlearning 的目标从“删掉一个 memory record”升级为：让整个可重构 execution state 与“这个 Agent 从未见过目标 z”时的 counterfactual runtime 一致。

5.3 人话版

Stateful Agent 的知识不只存在于显式 memory。一个目标事实 z 一旦进入 session，后续 summary、pending plan、tool routing argument、generated reply、KV cache 都可能成为它的派生状态。因此，只删 memory row 可能完全不改变真实行为。论文提出更严格的执行态遗忘目标：forget 后得到的 runtime，应该等价于同一个 Agent 从未见过 z 时运行到当前位置的 counterfactual runtime。作者用 Provenance-Guided Selective Replay 实现这一点：记录 artifact-level provenance，找到 z 第一次进入 runtime 的时间 τ，求其 descendant taint closure，恢复 τ 之前的安全 checkpoint，再在去掉 z 的条件下只重放后缀，重新生成所有 summary、plan、tool state 和 KV。理论上任何 exact 方法都至少要重算 T−τ+1 个 transition，Selective Replay刚好达到下界。实验中 Memory-Delete 基本等于 No-Forget；Forget-Instruction 在攻击提示下仍可100%恢复；Selective Replay 与 Full Reset 在泄漏与行为审计上对齐，却显著减少重算成本。

5.4 Background & Research Gap

传统 machine unlearning 主要研究参数 θ 的更新，希望删掉训练样本后模型行为接近 retrain oracle。Agent 系统多了一层持续演化的 non-parametric execution state：memory、summary、plan、tool state、cache。即便模型参数完全不变，这些状态也会继续保存旧信息。

例如用户在第4轮告诉 Agent“以后不要购买 Brand-X”。第5轮 summary 可能改写成“用户避免某大厂”，第6轮 planner 过滤 Brand-X，第7轮 tool router 不再搜索相关商品。到了第10轮用户撤销这条偏好。如果系统只删 memory 里的 Brand-X，后续 summary/plan/cache 仍会影响行为，甚至完全不再出现 Brand-X 字符串。

Memory delete 不传播；source redaction 不重算后代；IFC/taint gate 只能控制未来 flow；full reset 虽正确却昂贵。因此本文真正解决的是：怎样在不完全重启 Agent 的前提下，把源事实的整个派生影响精确撤销。

5.5 Core Insight

第一，删除 source 不等于删除 influence。z 会通过 summary、plan、tool arguments、cache 等多个载体向后传播。

第二，执行态比参数更容易给 exact guarantee，因为 execution 可以被建模为可重放 transition system。

第三，forget 成本由 target 首次进入点 τ 决定，而不是由总 session 长度本身决定。τ 越靠后，需要重演的 suffix 越短。

第四，string-level clean 不等于 behavioral clean。模型可以完全不说出目标，却继续按照被撤销偏好行动。

5.6 Method Deep Dive

Stateful runtime R_T + forget target z + provenance graph G + checkpoints C + observations {o_t} → LocateSource(z) → find first influence boundary τ → compute descendant taint closure → choose safe checkpoint c* < τ → crop KV / restore env snapshot → sanitize z from affected observation → replay suffix: deterministic/read-only tools replayed consequential tools shadow-executed model transition F rerun summaries/plans/tool args/cache regenerated → obtain R'_T → compare to counterfactual R_T^{-z} → leakage + behavior + cost audits

Provenance：RuntimeBlock 存 id、type、parents、source_ids、token span、turn 等字段，让系统知道每个 derived artifact 是由哪些 source 产生。

FirstEntry τ：不是简单找字符串第一次出现，而是找 z 第一次开始影响 runtime 的 transition boundary。

Taint closure：把所有直接或间接依赖 z 的 summary、plan、reply、tool args 标为失效。

Restore：恢复 τ 之前的安全 prefix，包括 KV crop 和环境 snapshot。

Replay：保留不受 z 影响的 observation，只从 suffix 重新执行 transition function F。

Tool safety：read-only/deterministic tool 可直接重放；有真实 side effect 的工具必须 shadow execution，避免二次付款、二次发邮件等。

Regeneration：所有 model-authored downstream artifacts 都重新生成，从而得到真正“无 z 世界”下的状态。

5.7 核心公式与数学直觉

Real runtime: R_t = F(R_{t-1}, o_t; θ) Counterfactual without z: R_t^{-z} = F(R_{t-1}^{-z}, o_t^{-z}; θ) Prefix-sharing: R_t = R_t^{-z}, for t < τ Exact execution-state unlearning: U(R_T, z) = R_T^{-z} Lower bound: Any exact method needs at least T - τ + 1 transitions in worst case. Selective Replay: Cost_SR = T - τ + 1

R_T^{-z} 是核心 reference：不是“把当前 transcript 里的 z 删除”，而是“如果一开始就没见过 z，当前 runtime 本应是什么”。

Prefix-sharing 表示 τ 之前两条世界线完全相同，因此可以复用。

Lower bound 说明如果 z 可能影响 τ 之后的每一步，而没有预先存 counterfactual suffix，那么这些 transition 必须重算。

Strongest baseline：Full Reset。从头重新执行整个无 z session，正确但成本 O(T)。Selective Replay 达到相同 counterfactual target，但只重放 suffix。

5.8 Toy Example

  1. 第5轮写入 z：“avoid Brand-X”。
  2. 第6轮 summary 改写成“避免某大厂”。
  3. 第7轮 planner 排除 Brand-X。
  4. 第8轮 tool router 不搜索 Brand-X。
  5. 第10轮用户撤销该偏好。
  6. 普通 delete 只删 memory row，summary/plan/tool/KV 继续存在。
  7. Selective Replay 定位 τ=5，恢复第4轮 checkpoint。
  8. 第5–12轮重新执行，但去掉 z。
  9. 新 summary 不再含该偏好，新 planner 重新把 Brand-X 纳入候选。
  10. 最终行为与“从未收到 z”的 counterfactual twin 对齐。

5.11 Metrics 教学式解释

Any-leak↓：任何artifact或answer出现目标就失败。

Leak@probes↓：用多个攻击提示测试同一post-unlearning state，检查direct/introspection/cued completion等恢复路径。

Leak@5↓：temperature0.7 连采5次，只要一次泄漏就算失败。

CAD↓：Counterfactual Action Divergence，比较方法的action与Full Reset reference的差异；0最理想。

Behavioral Residue↓：不要求模型说出目标，只看选择/行动是否仍受撤销事实影响。

Recompute↓：重算token或transition成本。

5.12 Results Deep Dive

  1. Memory-Delete 在 headline 结果上接近 No-Forget，说明仅删memory row几乎不改变行为。
  2. Forget-Instruction 在主query可看似不泄漏，但六类攻击 probe 可达100%恢复。
  3. Source-Redaction 随 derivation depth 增加，derived artifact leakage 明显上升。
  4. ToolSandbox 中，泄漏大量通过 routing arguments 传播，说明 target 不必出现在 final answer 也能影响真实 action。
  5. Sanitize-no-Replay 可以把字符串泄漏降到0，但 CAD仍明显非0，说明“安全”是通过破坏状态而不是得到正确counterfactual。
  6. Selective-Replay 与 Full Reset 在 headline、Leak@probes、Leak@5、behavioral audit、CAD 上对齐。
  7. Full Reset平均重算约1235 tokens，Selective-Replay约133，约9.3×更省。
  8. Behavior-only测试中，一些字符串完全clean的方法仍100%保留旧偏好；Selective-Replay与Full Reset floor一致。
  9. 只删target span会留下大量泄漏，甚至让 CAD 比 No-Forget更差。
  10. span+descendants可把leak降到0，但只有+replay后CAD才归0，证明“closure”和“reconstruction”缺一不可。
Strongest result：Selective-Replay 在多种泄漏、stochastic、behavioral、CAD审计上与 Full Reset 对齐，同时重算成本显著下降。
Weakest / boundary：只覆盖 reconstructible runtime，不处理 model parameters、真实世界已提交副作用或 target 的相关概念。
Failure case：若 post-τ 人类输入/外部世界本应因 z 的缺失而变化，那么固定 recorded observations 的 replay 并不是真实 counterfactual 世界。

5.14 Ablation / Mechanistic Analysis

Source-only：无法清理KV与derived state。

Descendant closure：负责安全，能阻止旧derived artifacts继续泄漏。

Replay：负责正确性，让本应存在的良性后续状态重新生成，因此CAD回到0。

IFC only：未来流控无法修 resident state；IFC+Replay才彻底。

Behavioral audit：排除了“只是不输出字符串”的伪遗忘。

5.15 Claim vs Evidence

Authors Claim：stateful Agent unlearning应以counterfactual execution-state equivalence定义，Selective Replay可exact实现。
Actually Show：在可记录provenance、可重放的runtime中，多模型/多suite结果与Full Reset reference一致且成本接近理论下界。
Not Proven：开放Agent框架未必有完整provenance；外部世界和人类后续输入可能不可重放；参数残留和语义相关target未处理。

5.17 Limitation & Failure Modes

Authors' Limitation：只覆盖 reconstructible runtime；不覆盖参数、已提交side effects、related facts；固定后续observations是较强假设。

Additional：真实 serving stack未必支持KV crop；provenance漏边会直接破坏保证；多target连续删除可能频繁重放；跨subagent进程的state closure更复杂；RAG/vector-store embedding影响未被完全定义。

5.22 与另外 Top Paper 的关系

Execution-State Unlearning告诉你“源删除后要处理哪些后代”；DCFA告诉你“如何从trace里估计哪些上游步骤真的造成后续影响”。当真实系统没有完整provenance时，可以用DCFA式graph做 dependency discovery，再用Selective Replay做 intervention verification。

5.23 如果只让我记住这篇论文

  1. 删memory row不等于Agent真的忘记。
  2. summary、plan、tool args、KV cache都可能继续携带目标影响。
  3. 正确目标是和“从未见过z”的counterfactual runtime一致。
  4. z之前的prefix可直接复用。
  5. 任何exact方法最坏至少重放T−τ+1步。
  6. Selective Replay达到这一成本下界。
  7. Forget-Instruction经多probe仍可被恢复。
  8. 字符串完全clean时，行为仍可能100%保留旧偏好。
  9. Selective Replay与Full Reset对齐，但重算显著更省。
  10. 真正关键不是把后代全部删掉，而是对真正受影响的后代做重构。

5.2 一句话定位

DCFA 研究 multi-agent system 失败后“到底哪一步才是决定性错误”，用全局 causal-inspired dependency graph + 局部 counterfactual-inspired search，从表面异常追溯到纠正后最能改变最终结果的步骤。

5.3 人话版

多 Agent 系统出错时，最显眼的往往不是根因。某次检索遗漏、某个orchestrator错误转述、某个assistant晚期答错都可能出现，但真正决定系统失败的通常是更早、影响范围更大的步骤。DCFA把完整trace拆成两个阶段。GCA先找minor deviations，然后对前后步骤判断temporality、necessity、sufficiency，建立causal-inspired dependency graph，并提出一个初始 decisive-error hypothesis。LCE再从这个候选出发，只在局部图里向前/向后搜索，假设修正某个interaction，估计最终outcome alignment能改善多少。Who&When 184条multi-agent failure traces上，DCFA在六个LLM backend上整体超过All-at-Once、Step-by-Step、Binary Search、A2P和ECHO：Algorithm-generated平均44.79% vs ECHO32.28%，Hand-crafted20.69% vs16.67%。不过完整LCE很昂贵：full DCFA约300s/32k tokens，而GCA-only约32s/13k，因此真正最有性价比的部分其实是显式dependency graph本身。

5.4 Background & Research Gap

失败归因不能简单等价于“找到第一个错误”或“找到最明显错误”。一个早期检索遗漏可能让后续所有Agent建立在错误前提上；一个晚期答案错误可能只是前面错误的症状。

All-at-Once依赖长上下文整体判断；Step-by-Step只能局部看；Binary Search假设错误位置有一定局部性；A2P加入causal prompt但仍是隐式reasoning；ECHO用hierarchical context和多视角共识，但仍不显式建因果传播结构。

本文真正填的gap是：把自然语言trace转成dependency graph，再用“纠正某一步后最终结果会改善多少”的counterfactual-inspired信号判断根因。

5.5 Core Insight

第一，minor deviation ≠ decisive error。

第二，长trace中的因果归因会受context degradation，Hand-crafted traces平均约51.6步，比Algorithm-generated约8.7步难得多。

第三，只向后找cause不够，也要向前看effect propagation，因此LCE采用双向局部搜索。

第四，作者明确使用“causal-inspired”而非formal causal inference，因为Nec/Suff与do()都由LLM判断，没有真实系统intervention。

5.6 Method Deep Dive

Failed trace T={τ1,...,τn}, final output Y_hat, ground truth Y → GCA: MDI: find minor deviations CGC: evaluate Temp / Necessity / Sufficiency build dependency graph HG: produce initial decisive-error hypothesis → LCE: construct corrected candidate interactions estimate ΔS on outcome alignment forward greedy search on effects backward greedy search on causes merge local chain DED final decision → output decisive step τ*

MDI：高召回收集retrieval omission、invalid premise、coordination deviation等。

CGC：对p

HG：结合全trace、errors、reasons和graph产生初始root-cause hypothesis。

Corrected trace：构造候选“修正版本”，但这是LLM模拟的counterfactual，不是真实重跑。

ΔS：估计修正候选后最终答案更接近ground truth的程度。

Bidirectional search：向前找传播后果，向后找更早根因，最后只在小局部范围做最终决策。

5.7 核心公式与数学直觉

Trace: T = {τ1,...,τn} Temporality: Temp(τp→τq)=I[p

Necessity：若没有p，q是否还会发生？

Sufficiency：若有p，q是否足以被解释为其后果？

ΔS：是LLM模拟“修正candidate后最终outcome会改善多少”，不是实际do-intervention effect。

Strongest baseline：ECHO。它是现有最好且适合长trace的归因baseline。GCA-only与ECHO成本近似，但准确率更高，说明显式graph而不是更多compute承担主要增益。

  2. τ9 Orchestrator未经验证直接传播。
  3. τ12 Assistant基于错误前提推导错。
  4. τ15最终回答错误。

  6. GCA建立τ8→τ9→τ12→τ15依赖链。

5.10 Experiment Setup Deep Dive

Dataset：Who&When，共184条failure traces；126条Algorithm-generated，58条Hand-crafted。

Trace length：Algorithm-generated平均约8.7步；Hand-crafted约51.6步。

Models：Qwen3-Coder-30B、DeepSeek-R1-32B、Qwen3-235B、DeepSeek-R1-671B、GPT-5、Gemini-2.5-pro。

LCE backend：本地Qwen-Coder-30B，2×A800。

Baselines：All-at-Once、Step-by-Step、Binary Search、A2P、ECHO。

Metric：Step-level Accuracy；另分析 attribution offset、runtime、tokens、graph density。

Research Questions：显式dependency graph是否优于prompt-only？LCE是否主要帮助长trace？性能是否只是靠更多compute？graph质量是否受model capacity影响？

5.11 Metrics 教学式解释

Step-level Accuracy↑：预测的具体interaction index必须和ground-truth decisive error一致。

Attribution Offset↓：|pred−gt|，用于区分“错在附近”和“完全偏离”。

Runtime↓：wall-clock成本，LCE最大代价在此。

Tokens↓：总token消耗，用于检查是否只是靠更多推理。

Graph Density：不是越高越好，过密可能代表LLM把一切都当有因果。

5.12 Results Deep Dive

  1. Algorithm-generated平均：DCFA44.79%，ECHO32.28%，+12.51pp。
  2. Hand-crafted平均：20.69% vs16.67%，+4.02pp；绝对值仍低。
  3. Qwen3-Coder-30B：23.02→37.30，+14.28pp。
  4. DeepSeek-R1-671B：40.48→53.17，+12.69pp。
  5. GPT-5：Algorithm-generated31.75→47.62，+15.87pp。
  6. LCE对Hand-crafted平均+3.45pp，对Algorithm-generated+1.93pp，说明长trace更受益。
  7. DeepSeek-R1-671B短trace上GCA-only与full相同，LCE无额外增益。
  8. DeepSeek-R1-32B某些length level下DCFA略低于ECHO，弱模型执行复杂graph reasoning会引入噪声。
  9. ECHO约31s/12k，GCA-only约32s/13k，却Accuracy 24.48→30.05；这是最有性价比的主结果。
  10. full DCFA约300s/32k，只把30.05进一步推到32.74，边际收益较低。
Strongest result：GCA-only在几乎相同成本下明显超过ECHO，最能排除“只是花更多compute”。
Weakest：full DCFA接近10×runtime，只换来约2.69pp额外提升。
Failure case：Hand-crafted长trace绝对准确率仍只有20%左右，尚不足以用于自动问责。

5.14 Ablation / Mechanistic Analysis

去LCE：长trace损失更明显，说明LCE主要修context degradation。

GCA vs ECHO等成本：显式dependency graph本身承担核心增益。

Graph density：较弱模型会生成过密/过稀graph，说明graph只是LLM推断的latent hypothesis，不是ground truth。

Counterfactual-inspired correction：因为没有实际重跑系统，所以只能算“模型认为修正会有用”，而不是actual causal effect。

5.15 Claim vs Evidence

Authors Claim：显式dependency structure + 局部counterfactual refinement能更准确定位decisive error。
Actually Show：Who&When、六个LLM、短/长trace上均总体改善，且GCA-only有良好性价比。
Not Proven：没有真实do-intervention验证edge；benchmark单一；长trace绝对准确率仍低；不能用于正式责任判断。

5.16 Contribution

  • New Mechanism：Global causal-inspired dependency graph。
  • New Mechanism：Local bidirectional counterfactual-inspired refinement。
  • New Protocol：以decisive error而非surface deviation为目标。
  • New Analysis：trace-length、graph density、offset、cost。
  • Engineering：training-free，可接多种LLM。

5.17 Limitation & Failure Modes

Authors：依赖底层LLM推理能力；极长/高分支trace仍难；intrinsic hallucination难归因。

Additional：ground-truth outcome已知是较强假设；Nec/Suff由LLM判断可能漏真实弱因果；LCE昂贵；Who&When仅184条；没有验证“纠正预测step后真实系统是否真的恢复”。

5.21 Attack / Verification Lens

可形成 Minimal Recovery Intervention Attack：找出最小步骤/载体，纠正或注入它后能最大恢复目标输出。也可定义 Residual Causal Influence (RCI)：对某个已忘target的descendant进行ablation/correction后，final leakage变化量。

5.22 与另外 Top Paper 的关系

DCFA最大的弱点是“counterfactual-inspired而非真实intervention”；Execution-State Unlearning最大的强项正是可从checkpoint真实重放。因此最自然的组合是：DCFA负责找top-k候选，Selective Replay负责真正do-intervention并测最终结果。

5.23 如果只让我记住这篇论文

  1. 多Agent失败里最明显的错误不一定是决定性错误。
  2. decisive error应看“纠正后能否改变最终结果”。
  3. GCA先找minor deviations，再显式构造dependency graph。
  4. 边需要temporality、necessity、sufficiency。
  5. LCE在局部图上做双向搜索。
  6. 向前看后果，向后找更早根因。
  7. Algorithm-generated平均44.79%，明显高于ECHO32.28%。
  8. Hand-crafted长trace仍只有20%左右，问题远未解决。
  9. GCA-only性价比最好，full LCE成本很高。
  10. 对unlearning最重要的迁移是“先发现因果后代，再用真实replay验证”。

Combined Research Opportunities

Best Migration Direction — Intervention-Verified Causal Descendant Unlearning

Forget target z → collect agent/video/multimodal trace → DCFA-style dependency discovery → top-k plausible descendants → replay / intervention verification → measure actual leakage & utility delta → classify true causal descendants → reconstruct only verified descendants → black-box behavioral audit → closure certificate

这个方向直接回答“如果 A 做事件 T 对 B 产生影响，unlearn A/T 后要不要处理 B？”：不是所有B-side信息都删除，而是只对经干预验证、确实由A/T造成的因果后代做重构；与A/T只是共现但不依赖的B知识应保留。

Collision / Overlap

Strongest Collision：Execution-State Unlearning 与 PlanFence、MutMem V2 都涉及 provenance / derived state，但它最独特的是“真正重演 counterfactual suffix，并给出 T−τ+1 最优性”。因此新的工作不应再只做签名、tombstone 或 lineage check，而应向 semantic/causal descendants + replay reconstruction 走。

DCFA 与 A2P、ECHO、LLM causal graph discovery 有重叠。若要真正强调 causal，下一步必须加入真实 intervention/replay，而不能继续只靠 LLM 回答 do() 问题。
