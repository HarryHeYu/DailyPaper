5.2 一句话定位

它把 unlearning 从“把 forget accuracy 降下来”重新定义为非对称泛化：目标知识必须跨多种表达被彻底忘掉，而巨大而隐式的非目标知识空间必须被广泛保留。

5.3 人话版

传统 unlearning 很容易出现两类假成功。第一类是 under-forgetting：训练时那句问题答不出来了，但换成反向问法、paraphrase、间接推理或 jailbreak，又能把目标知识恢复。第二类是 over-forgetting：目标知识确实没了，但与它同实体、同主题、甚至只是词面相似的无关知识也被一起损坏。作者提出 SUITE，把 forget 侧分成 direct、reverse、indirect 等表达，把 retain 侧细分为 16 级 semantic tiers，再补 lexical、syntactic、general probes。然后在此基础上提出 JensUn++，用 refusal target、prefix mixing、动态梯度平衡与 hard pairing，让模型既更彻底忘记，又少误伤。

5.4 Background & Research Gap

以往方法包括 GA/GradDiff、NPO/SimNPO、PDU、RMU、JensUn 等。它们都试图在 forget 与 retain 间平衡，但问题在于：如果 benchmark 只问训练过的那条 direct question，就会把“表面 suppression”错当成真正删除。

例如目标事实是“某航天事故在发射后 73 秒发生”。如果只问“多少秒后发生事故”，模型可能答不出；但换成“哪次事故发生在 73 秒后？”或通过 1986 年、航天器名称等间接线索，知识仍可能恢复。与此同时，与目标词共享同一个实体名但语义无关的问题也可能被误伤。

本文真正填的 gap 是：建立一个能同时测 forget intensive generalization 和 retain extensive generalization 的结构化 benchmark，使“忘得不够”和“忘得太多”可以同时被看见。

5.5 Core Insight

作者的第一个经验发现是：粗 benchmark 会显著高估 unlearning。切换到 SUITE 后，一些方法在 reverse/indirect 查询上暴露出非常高的 residual knowledge，同时最靠近目标的 retain tier 也会显著受损。第二个经验发现是：forget 与 retain 两项 loss 的梯度尺度在训练过程中会变化甚至反转，固定权重并不稳定。

因此 JensUn++ 的设计不是单纯“换一个 loss”，而是把三个失败点分别对齐：prefix mixing 处理旧答案轨迹恢复；dynamic gradient balancing 处理训练阶段的尺度漂移；hard pairing 迫使模型根据语义而不是句式 cue 区分 forget 与 retain。

5.6 Method Deep Dive

Real-world topic → 25 atomic forget facts → Direct / Reverse training queries → Indirect multi-hop queries held out for evaluation → paraphrase + fill-in-the-blank augmentation → retain construction: semantic tiers s0...s15 lexical probes syntactic probes general knowledge → strict train/test separation → JensUn++: refusal target prefix mixing JS-based forget objective retain distribution matching dynamic gradient balancing augmentation-matched hard pairing → evaluate worst-case forget leakage → evaluate nearest-neighbor retain damage → sequential / joint / adversarial stress tests

Atomic facts 与 Query Views

每个 topic 先拆成原子事实，再生成 direct、reverse、indirect 三种信息访问方式。Indirect 不进入训练，因此它是判断模型是否只记住“该拒绝哪种 prompt 模板”的关键。

Retain Boundary

Retain 不再是随便抽一批无关样本，而是 s0 到 s15 的分层语义邻域。s0 与 target 极近但不属于待删事实，是最难的 collateral-damage 区；越往后语义越远。另加 lexical/syntactic probes，用于区分“删知识”与“删词面/句式”。

Prefix Mixing

训练时把原正确答案的一段 prefix 与 refusal target 拼接，使模型学习：即使已经进入旧答案轨迹，也要能切换到 refusal。它本质上是在训练 trajectory-level recovery resistance。

Dynamic Balancing

在 logits 上计算 forget/retain 梯度范数，并按比例动态调整 forget loss，使训练过程中两边不会因尺度漂移而失衡。

5.7 核心公式与数学直觉

g_f = ∇_z L_f
g_r = ∇_z L_r

α = ||g_r||₂ / (||g_f||₂ + ε)

L = λ_f · α · L_f + λ_r · L_r

直觉上，如果某阶段 forget 梯度过强，α 会缩小它；如果 forget 梯度已经很弱，则不会继续使用固定的大权重粗暴推进。相比单纯 NPO/GradDiff，JensUn++ 还明确把输出分布拉向稳定 refusal，而不仅仅是“降低原正确答案概率”。

5.8 Toy Example

目标：忘记“事故发生在发射后 73 秒”。训练只见 direct 与 reverse。测试时加入 indirect：“1986 年那次航天灾难在起飞后多久发生？”以及 lexical probe：“Challenger 这个单词中第二次出现的字母是什么？”如果模型 direct 忘了但 indirect 还能答 73，属于 under-forgetting；如果 lexical 题也坏了，则属于 over-forgetting。

5.11 Metrics 教学式解释

Q_All / Q*All：forget knowledge rate，越低越好；Q*All 还加入 adversarial query，是更严格的 worst-case。
Gibberish：胡言乱语比例，越低越好；错误输出不等于合格的忘记。
s0 accuracy：最靠近 target 的 retain 能力，越高越好，是过度遗忘的敏感指标。
MMLU：一般 utility，但可能掩盖局部 collateral damage，因此只能作为补充。
RGQ：LLM judge 比较通用生成质量，需要警惕 judge bias。

5.12 Results Deep Dive

  1. 粗 benchmark 会显著高估遗忘；SUITE 中 reverse/indirect query 暴露出 massive under-forgetting。
  2. 最靠近 target 的 s0 retain 也会被明显误伤，说明很多方法不是“精确删一个事实”，而是在抹掉周围知识。
  3. Llama sequential：JensUn++ 的 Q_All≈3%、Q*All≈3%、Gibberish=0；JensUn 约 14%/16%，且 gibberish 很高。
  4. Ministral 上 forget rate 的绝对差距较小，但 JensUn++ 主要胜在把高比例 gibberish 压到接近 0。
  5. Retain 总体只小幅下降，说明 strongest result 并非单纯用 utility 换 forgetting。
  6. s0 仍是最明显 failure region，最近邻知识没有被完全保护。
  7. 未见的多语言/role-play/jailbreak 只带来较小 worst-case 增幅，说明其 query-form 泛化有一定韧性。
  8. Sequential 中前几个 topic 不容易被后续 unlearning 重新学回，但个别 topic 仍明显更难。
Strongest result：低 worst-case forget leakage + 0 gibberish + 小幅 retain drop 同时出现。
Weakest / failure：s0 邻近知识仍有明显 collateral damage，且 topic hardness 不均匀。

5.14 Ablation / Mechanistic Analysis

Prefix mixing 负责抵抗从旧答案 prefix 恢复；dynamic balance 负责训练过程 forget/retain 梯度尺度变化；hard pairing 负责防止模型利用 augmentation type 作为 shortcut。需要强调，这些是输出/优化层面的机制证据，并不能证明内部 representation 中目标知识被真正擦除。

5.15 Claim vs Evidence

Experiments Actually Show：更细粒度 benchmark 确实会改变对现有方法的判断，JensUn++ 在多模型、多 setting 下总体 Pareto 更好。
What Is Not Yet Proven：没有 retraining-equivalence，也没有证明 representation-level deletion；没有覆盖超大模型、multimodal、agent memory 与长期 reacquisition。

5.16 Contribution

  • New Benchmark/Protocol：SUITE 的 asymmetric generalization evaluation。
  • New Empirical Finding：训练/评测边界定义的重要性可与算法本身相当。
  • New Mechanism：JensUn++ 的 prefix mixing + dynamic balancing + hard pairing。
  • New Evaluation：sequential/joint/adversarial + nearest-neighbor retain boundary。

5.17 Limitation & Failure Modes

Topic 数量有限；主要是文本事实；semantic tiers 仍需要辅助标注；部分 utility 使用 LLM judge；缺少 adaptive recovery、cross-modal leakage、membership/retraining-equivalence 与表示层审计；完整 protocol 的调参与 compute 成本较高。

5.18 Reproduction View

最小复现不必复制全部 benchmark。可选 1 个 topic、10 个 atomic facts，每个构造 direct/reverse/indirect，再做 s0、s3、lexical、syntactic retain。使用 3B–7B 模型比较 NPO、GradDiff、JensUn-style refusal 与 JensUn++-lite。最先验证的核心现象是：direct 看似成功，但 indirect/lexical 会暴露 residual 与 collateral。

方向 B — Difficulty-Aware Curriculum

用 unlearning 前的 direct preference、paraphrase variance、nearest-retain confusion 等预测 post-unlearning worst-surface leakage，再按 hardness 分配步骤与 probe budget。Minimum Experiment：50 targets，比较 uniform sampling、random curriculum、loss-based curriculum；主指标 Spearman(hardness,residual)、AUROC(hard target)、forget-retain Pareto。

5.21 Attack / Verification Lens

可直接形成 black-box probe：direct→reverse→indirect→paraphrase→lexical collision→multi-hop 自适应查询。Verification 应报告 worst-surface leakage，而不是平均 forget accuracy。可定义 Boundary Closure Rate：目标所有等价查询都无法恢复、而所有 non-target boundary probes 仍正确的 target 比例。

5.23 如果只让我记住这篇论文

  1. Unlearning 不是单纯降低 forget accuracy。
  2. 真正问题是 simultaneously 解决 under-forgetting 与 over-forgetting。
  3. Forget 侧必须跨 direct/reverse/indirect/paraphrase 泛化。
  4. Retain 侧必须在离 target 最近的邻域也保持准确。

  6. 粗 benchmark 会让很多方法看起来比实际更好。

Paper 2 — Governed Shared Memory for Multi-Agent LLM Systems

Authors：Yanki Margalit, Nurit Cohen-Inger, Erni Avram, Ran Taig, Oded Margalit
Affiliation：Caura.ai; Ben-Gurion University of the Negev
Date / Status：2026-06-23 · arXiv preprint
Paper：arXiv · PDF
Code / System：Caura GitHub · Project site

5.2 一句话定位

这篇论文把 multi-agent memory 从“向量检索组件”提升为受治理的分布式状态系统，要求同时满足 scope、temporal consistency、provenance 与 propagation。

5.3 人话版

一个 agent 自己记东西时，memory benchmark 往往只问“能不能找到”；但多 agent 共享记忆时，问题变成：谁能看哪条？旧事实如何被新事实 supersede？一条总结是由哪些 agent 的哪些 observation 推导出来？一条 memory 写入后多久对同 fleet 可见？论文定义 fleet memory F=(A,M,G,P,T)，并用 ArgusFleet 对真实生产系统 MemClaw/Caura 做 live probe。最有价值的不是漂亮的 provenance 数字，而是作者实际发现 GET-by-id 曾绕过更细 scope、dedup gate 会在 contradiction detector 之前拒绝输入等 production failure，并用实验定位与修复。

5.4 Background & Research Gap

LoCoMo、LongMemEval 等更关注长期记忆召回；vector DB/RAG 关注 top-k relevance；很多 single-agent memory framework 默认“读者与写者边界简单”。但在 fleet 中，relevance 只是必要条件，不是充分条件。授权、时间、来源、传播都必须参与“这条 memory 是否应该出现在结果里”的判断。

最具代表性的失败是：semantic search path 可能有 fleet filter，但如果 caller 已知 memory_id，另一个 GET endpoint 曾经只检查 tenant，不检查更细的 fleet/agent/scope/trust。于是“search 没泄漏”并不能证明系统整体没泄漏。

5.5 Core Insight

Shared memory correctness 由多个正交 primitive 决定：scope 是 access control；supersession 是 temporal/state resolution；provenance 是 event sourcing；propagation 是 distributed consistency。任何一个 primitive 没有在所有 path 一致执行，局部正确都会变成系统错误。

第二个关键发现是 pipeline ordering：contradiction detector 在“两个写入都被接受”的条件下可以几乎完美，但 synchronous near-duplicate gate 会先把冲突写入当成重复而拒绝，导致 detector 根本没有机会运行。因此 module accuracy ≠ end-to-end system correctness。

5.6 Method Deep Dive

Agents A → write memory w_i=(agent, content, scope, time, provenance) → governance G checks authorization / trust → storage M → temporal semantics T handle supersession / contradiction → provenance P records derived_from → retrieval r_j=f(query, requester, governance, time) → propagation to authorized peers → ArgusFleet live probes: leakage contradiction provenance propagation → compare observed behavior with invariants → save traces + latency + CIs → localize handler / ordering / policy failure

5.7 核心公式与数学直觉

F = (A, M, G, P, T)
w_i = (a_i, c_i, s_i, t_i, p_i)
r_j = f(q_j, a_j, g_j, t_j)

w_i ∈ r_j ⇒ auth(a_j, s_i, G)

LEAK_RATE = n_leaks / n_expected-deny
MISS_RATE = n_misses / n_expected-allow

这里最关键的是 invariant，而不是复杂 loss。普通 retrieval benchmark 只看召回率；本文把“该看到”和“不该看到”拆开，因此一个系统完全可能 recall 很高却同时泄漏严重。Leak 与 miss 必须成对报告。

5.8 Toy Example

Support fleet 写入客户争议款信息，Finance fleet 不应读取。后来新状态写入“争议已解决”。正确系统必须：Finance 无论 semantic search 还是 direct GET 都看不到 secret；新状态 supersede 旧状态；如果 Manager 生成周报总结，provenance 能追溯到原始 observation。只满足其中任何一个都不能叫“共享记忆正确”。

5.10 Experiment Setup Deep Dive

System：MemClaw/Caura production multi-tenant service；ArgusFleet 是 live REST harness。
Leakage：4 fleets × 6 agents，多类 expected-allow / expected-deny probe，并重点覆盖 search 与 GET-by-id。
Provenance：50 条 depth-4 derivation chains。
Propagation：40 fleet-scoped facts，多 sibling 与 foreign-fleet readers。
Contradiction：100 facts，sequential/concurrent 写入。
Metrics：leak/miss、Wilson CI、chain completeness、writer identity、depth fidelity、visibility rate、cross-fleet leak、detection/stale rate、p50/p95/p99 latency。

5.11 Metrics 教学式解释

Leak rate↓：本应拒绝却返回的比例。
Miss rate↓：本应允许却没返回的比例。
Wilson CI：适合极端二项比例，如 0/80。
Chain completeness↑：来源链每一跳是否完整。
Writer identity↑：来源节点是否对应正确写作者。
Visibility rate↑ / cross-fleet leak↓：传播效率与隔离性必须同时满足。
Conditional detection：在两个 write 都成功 admission 的前提下测 contradiction module，能把 admission failure 与 detector failure 分开。

5.12 Results Deep Dive

  1. GET-by-id 曾存在 sub-tenant enforcement gap；修复后更低 trust 的 cross-fleet read 被阻断。
  2. Semantic search 同时存在 leak 与 miss，说明 relevance ranking 与 auth filter 是两个独立维度。
  3. Provenance 是 strongest result：depth-4 chains 可完整恢复，writer identity 也稳定。
  4. Propagation 对 same-fleet sibling 基本可见，而 foreign-fleet 维持隔离。
  5. Tight polling 把早期看起来很长的 visibility latency 修正为约交互级别，证明 harness 自身也可能产生假结论。
  6. Contradiction detector 在两条冲突 write 都被接受时表现很好。
  7. 但 end-to-end contradiction detection 明显更差，因为 dedup gate 抢先拒绝大量本应进入 contradiction pipeline 的写入。
  8. Strong consistency 的主要成本体现在 write latency，而不是 read visibility。
Strongest result：provenance chain 完整性与 writer identity 的稳定表现。
关键 failure：GET path authorization gap 与 dedup-before-contradiction ordering failure。

5.14 Ablation / Mechanistic Analysis

虽然不是传统 ML ablation，但它做了很强的系统诊断：tenant-key vs agent-scoped credential、synchronous response vs post-settle re-fetch、batched probe vs tight polling、overall vs conditional contradiction detection。通过控制这些条件，作者能把失败定位到具体 handler、pipeline ordering 或测量 artifact，系统层面的因果证据反而很强。

5.15 Claim vs Evidence

Experiments Actually Show：在一个真实 production system 上，scope、provenance、propagation、contradiction 的确可以通过 invariant-driven live probe 被审计，并且能发现设计图上看不到的问题。
What Is Not Yet Proven：没有跨多个 memory systems 的大规模比较；没有 cross-tenant adversarial benchmark；实验规模仍有限；不能证明该架构在任务成功率上优于 Mem0/Letta/Graphiti 等。

5.16 Contribution

  • New Formalization：F=(A,M,G,P,T) 的 governed fleet memory。
  • New Evaluation Harness：ArgusFleet live-service invariant testing。
  • New Empirical Finding：GET scope gap、dedup starvation、write-side consistency cost。
  • System/Engineering：Caura/MemClaw production implementation。

5.17 Limitation & Failure Modes

单 tenant；每类实验规模有限；tight polling sample 较少；缺跨系统 comparand；项目作者自己评估自家系统存在 self-evaluation bias；没有 multi-agent deletion/unlearning primitive；没有恶意/Byzantine agent、policy conflict、cross-region partition 与长期任务成功关联。

5.18 Reproduction View

用 SQLite/Postgres + vector index 搭最小 3-scope memory service：tenant/fleet/agent。实现 write、search、GET-by-id、supersede、derived_from，然后做 4 个测试模块：unauthorized canary、contradictory pair、depth-3 provenance、fleet propagation。最先跑 access-path equivalence test：同一个 unauthorized memory 分别走 search、GET、list、summary/cache path，检查 auth 决策是否一致。

5.20 Migration Analysis

方向 A — Multi-Agent Memory Unlearning Closure

Original Problem →scope/temporal/provenance correctness。
Transferable Mechanism →invariant + multi-path live probes。
New RQ →删除某用户/事实后，search、GET-by-id、summary cache、derived memory、propagated copies 是否全部消失？

通过 cross-fleet canary、near-duplicate contradiction、rapid supersession、derived-chain probes 等行为差分推断内部 architecture regime。Minimum Experiment：5 backends × 40 probes × 5 seeds；指标 Regime AUROC、Probe@95% confidence、Failure Localization Accuracy。

5.21 Attack / Verification Lens

Attack 可利用 search/GET 路径差异、dedup starvation、rapid concurrent write 与 derived memory residual。Verification 应定义 Access-Path Closure、Derived Residual Depth、Scope-Conditional Leakage、Supersession Consistency、Delete-to-Invisible latency。

5.22 与 Paper 1 的关系

Paper 1 的 closure 是语义/查询等价类；Paper 2 的 closure 是系统访问路径与 provenance/propagation。二者组合后，可以得到一个比普通 multi-view unlearning 更强的统一验证框架。

5.23 如果只让我记住这篇论文

  1. Multi-agent shared memory 不是“大一点的 RAG”。
  2. 它本质上是一个受治理的分布式状态系统。
  3. scope、time、provenance、propagation 都是 correctness 的一部分。
  4. search path 安全不代表 GET-by-id 也安全。
  5. 论文实际发现并修复了这类 gap。
  6. Provenance 是最强正结果之一。
  7. Propagation 与 isolation 必须一起评估。
  8. Contradiction module 正确不代表端到端 pipeline 正确。
  9. 评测 harness 自己也可能制造错误结论。
  10. 最值得迁到 unlearning 的思想是：删除必须跨所有访问路径与派生副本形成 closure。
