5.2 一句话定位

MeClear 把有害长期记忆识别从单条 Leave-One-Out 删除升级为 cooperative Shapley attribution，从而找出被冗余冲突掩盖的负效用 memory coalition，并对当前 query 做最小、可验证的 context clearance。

5.3 人话版

长期 Agent 的 memory bank 会不断积累旧事实、矛盾记录和重复表述。单看相似度无法判断这些记录是帮忙还是添乱；更糟的是，如果两条错误记忆互相替代，删任意一条都不会让答案恢复，传统 LOO 就会把它们误判成“没影响”。MeClear 将 active context 中 K 条 memory 当作合作博弈中的 players，用 sampled Shapley value 估计每条 memory 在不同 coalition 中对任务正确性的平均边际贡献。对负贡献记忆排序后，它建立一系列 nested clearance sets，并真正重新运行 Agent 验证“删除到这里是否恢复”，最后选择收益最大的最小清除集合。作者在 LoCoMo 上构造 745 个 causally verified cases、1,115 条 fault memories；MeClear 达到约85.9% target recall、47.0% exact harmful-set match、82.3% task recovery，Recovery 比 LOO 高25.5pp。它并不永久删除 persistent bank，因此更准确地说是 memory influence control，而不是合规意义的 machine unlearning。

5.4 Background & Research Gap

主流 memory system 通常假设 relevance≈utility：与 query 相似的记忆应该被检索。但相关并不意味着帮助正确决策。过时事实、重复错误、版本冲突都可能高相关却有害。

例如 F1=“John 2023年1月在Italy”、F2=“John年初去过Italy”，正确答案其实是12月。只要F1或F2任意存在，模型都可能答January。删F1仍有F2，删F2仍有F1，所以单条LOO effect都接近0，但二者都在共同维持错误。

MeClear真正填的gap是：在固定已检索context内，如何对interacting memories做coalition-aware negative-utility attribution，并通过真实task recovery验证最小干预。

5.5 Core Insight

LOO零效应不代表无害：冗余坏证据可互相遮蔽。
Harmfulness是query-conditioned：历史事实对“当前状态”可能有害，对“去年状态”却有用。
Attribution与intervention分开：识别负贡献只是第一步，必须实际重跑。
最小化collateral damage：先最大化recovery，再选最少删除。

5.6 Method Deep Dive

Persistent memory bank B_t + query q_t → retriever freezes active context M_t={m1,...,mK}, K=5 → baseline value v(M_t) → LOO screening → sample L=16 permutations → estimate Shapley ψ_i → harmful candidates ψ_i < -τ → sort by most-negative ψ → build nested clearance C_0...C_h → rerun agent on M_t \ C_j → require positive gain + recovery predicate → choose best minimal j → query-scoped cleared context → persistent bank unchanged

Freeze retrieval：避免每次ablation后重新检索带来的混淆。
LOO：只做direct harm screening，接近0视为inconclusive。
Shapley：通过不同coalition解除冗余遮蔽。
Nested filtration：将2^h子集缩成h+1候选。
Verification：最终仍看真实任务恢复，不接受纯语言判断。

5.7 核心公式与数学直觉

M_t = ρ(q_t, B_t; K) v_t(S) = E_y[r_t(y)] d_i = v_t(M_t) - v_t(M_t \ {m_i}) ψ_i = Σ_{S⊆M_t\{m_i}} |S|!(K-|S|-1)! / K! * [v_t(S∪{m_i}) - v_t(S)] Redundant harm: d_i = d_j = 0 but ψ_i = ψ_j = -Δ/2 ψ̂_i = (1/L) Σ_l marginal_i(π_l) Ĥ = {m_i | ψ̂_i < -τ}

v(S)测downstream task correctness，不是semantic relevance。d_i只看full-context附近单点干预，所以会被redundancy mask。ψ_i平均不同coalition下的边际贡献，因此能发现“单删看不出来”的harm。

主实验L=16、τ=0.05。τ太小会把evaluator noise当harm，太大则漏弱负贡献。与LOO差异是机制性的，而不是简单多跑几次。

5.8 Toy Example

  1. K=5，其中F1/F2是两条语义冗余错误。
  2. 完整context答错。
  3. 删F1仍有F2，LOO≈0。
  4. 删F2仍有F1，LOO≈0。
  5. 随机permutation中，谁先出现谁第一次引入错误penalty。
  6. 多轮平均后F1/F2都得到负Shapley。
  7. MeClear按负贡献排序逐步清除并实际验证。
  8. 两条都清除后答案恢复。
  9. persistent bank仍不变。

5.2 一句话定位

Procedural Graphs把Agent的“怎么做”从自由文本经验或固定workflow升级成可定位当前节点、局部检索相邻transition、动态生成指导，并通过成功/失败轨迹自演化topology的显式procedural memory。

5.3 人话版

很多Agent在长任务里每一步都要从越来越长的trajectory重新判断“我现在做到哪里、下一步该调用哪个工具、哪些前置条件不能跳”。Procedural Graph（PG）把procedure显式结构化：节点是tool action、skill、reasoning step或task state；边表示admissible transition，并带condition、guidance、pitfall。在线执行时先匹配active node，只取2-hop局部子图，再让LLM把结构转成situational guidance，solver仍自由决定下一步。离线则用成功/失败trajectory让refiner提出graph edit；候选只有在held-out validation不下降时才commit，坏edit rollback并进入rejection memory。六个主benchmark×四模型共24 settings中，PG对各setting strongest baseline为19胜2平3负。最强机制证据是坏expert graph会把MultiChallenge从87.5打到58.93，但iterative validation-gated evolution可恢复到92.86；说明真正关键不是“有graph”，而是graph能被执行反馈修正。

5.4 Background & Research Gap

MemoryBank/ExpeL把经验压成自由文本，procedure dependency隐式；AutoGuide检索局部guideline，但guideline彼此不连接；AWM等workflow更结构化，却可能线性或固定。PG补的是：explicit transition structure + progress-conditioned local retrieval + soft generative guidance + feedback-driven editable topology。

5.5 Core Insight

Procedure需要连接关系：独立tips无法稳定表达先后依赖。
局部结构胜过全图：全图会造成context overload。
Expert prior可能错：人工graph也能伤性能。
长程成功依赖时机：关键不是更多tool calls，而是什么时候做什么。

5.6 Method Deep Dive

Initial Procedural Graph G0 → nodes: tools / skills / reasoning / task states → edges: admissible transitions → attributes: condition / guidance / pitfalls ONLINE: query + trajectory → Match(last action, V) → active node → retrieve h=2 local neighborhood → guidance model Ψ(local graph, q, recent w=3 steps) → situational guidance → ReAct solver chooses next action OFFLINE: retained graph → rollout training trajectories → refiner proposes add/delete/revise graph edits → structural checks → held-out validation → accept if non-degrading → else rollback + rejection memory → next round

5.7 核心公式与数学直觉

G=(V,R,E,Φ), E⊆V×R×V u_t = Match(a_{t-1},V) G_t = N_h(u_t), h=2 g_t = Ψ(G_t,q,T_{t-w:t}), w=3 a_t ~ P_solver(. | q,T_t,g_t) accept G_candidate iff S_val(G_candidate) >= S_val(G_k)

h=2控制procedural lookahead；太大会退化成full graph overload。w=3压缩guidance输入。PG是soft guidance而不是硬FSM。Validation gate是self-evolution的稳定核心：没有可微loss，而是直接用held-out task score决定graph edit是否保留。

5.8 Toy Example

  1. 财务Agent graph含audit_cash、forecast_runway、request_funding等节点。
  2. forecast→funding edge带“runway不足才触发”的condition。
  3. 最近动作定位到audit_cash。
  4. 只提取2-hop子图。
  5. guidance生成“先forecast，再决定是否融资”。
  6. solver执行。
  7. 若失败轨迹显示重复融资，refiner修改pitfall/condition。
  8. validation下降则rollback。
  9. 不下降则commit。

5.21 Attack / Verification Lens

PG天然可作为attack policy representation：每个probe是node，条件决定下一步。可定义 Procedural Residual Reachability：预算B内从Start到成功恢复target的可达概率；再配 Minimum Residual Path Length。

5.22 与另外 Top Paper 的关系

Cross-Paper Synthesis

两篇共同说明：长期 Agent 的关键问题已经从“单条 memory 是否相关”升级成“多个 memory / procedure component 怎样共同构成行为”。MeClear关注 coalition interaction；Procedural Graphs关注 topology与path。

共同趋势：从free-form memory / single probe走向 intervention-aware structured memory。
可组合mechanism：Shapley coalition attribution + local procedural graph。
最可能新论文：Coalition-Aware Procedural Unlearning / Self-Evolving Recovery Graph。
最适合baseline：MeClear用于harmful-memory attribution；PG用于procedural memory。
最适合attack：PG。
最适合benchmark/metric：MeClear，可导出coalitional residual metrics。

Combined Research Opportunities

Best Migration Direction — Coalition-Aware Procedural Unlearning

Target knowledge/capability → enumerate recovery probes/actions → represent as Procedural Graph → execute on unlearned model → collect success/failure trajectories → cooperative attribution over nodes/edges/carriers → identify redundant recovery structures → minimally prune/retrain risky coalition → validate forget + retain + held-out identities → evolve attacker graph again → repeat until no low-cost residual path remains

核心思想：即使单个probe都不强，只要多个probe按正确procedure组合起来还能恢复，遗忘就没有闭环。MeClear负责识别冗余masking，PG负责表示和演化恢复路径。

Collision / Overlap

Strongest Collision：Procedural Graphs 与 JIT-Agent、Harness-of-Harness、MASkills 都属于优化Agent外部结构。低碰撞区域不是再做一个graph optimizer，而是用procedural topology定义unlearning residual reachability，再用coalition attribution处理多路径冗余。
