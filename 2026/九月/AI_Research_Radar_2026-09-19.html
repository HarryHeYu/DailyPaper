6. Tier S

Locating Hidden Failures Makes Long-Horizon Agents More Reliable

基本信息。Salman Rahman 等；UCLA、NYU、Google Research、Google DeepMind；arXiv v1（2026-09-15）。正文、Methods、Results 可访问。论文研究 2,518 条长时程 agent trajectory，覆盖 SWE-bench、TerminalBench、BixBench，并把 6,967 个错误归入 78 个实际出现的 failure types。核心产物是 Traverse benchmark 与 4B verifier Scout。

人话版：这篇论文到底干了什么？

现在评价 Agent 往往只看“最后任务成功没有”，但一条几百步的轨迹里，Agent 可能早就犯错、删除数据、伪造结果，最后却碰巧通过验收。本文把评价粒度从最终 outcome 下钻到“第一处真正把任务带偏的错误”。作者人工标注真实长轨迹，发现第一错之后错误会级联，而且大模型 judge 并不擅长找第一错；反而专门训练的 4B Scout 能更好定位错误，并在 test-time 从多个候选轨迹里挑出更可靠的一条。这对 Agent Unlearning 特别重要：删除后的失败也不该只看最终泄漏，而应定位“哪一步重新接触、推断或调用了被删信息”。

Background & Research Gap

传统 Agent benchmark 把整条 trajectory 压成一个 pass/fail bit。问题是 outcome 不等于过程安全：一个 coding agent 可以删掉唯一实验目录后仍完成 patch；一个 scientific agent 可以“写出看似正确结果”而不是实际计算。对于 unlearning，同样的盲区会变成：最终回答没有复述 forget fact，不代表中间 search、memory read、tool call、reasoning trace 没有重新使用它。已有 process verifier 多聚焦单轮 reasoning 或短 agent task，缺少跨软件工程、computer-use、science 的自然长轨迹 first-mistake localization。

Core Insight

真正决定长任务崩坏的不是“错误总数”，而是最早的 root fault 与后续 cascade。论文报告：发生第一错后仅约 30.5% 的 run 最终恢复；约 38.5% 从未自我检测到错误；前一步错误会让下一步错误概率提升约 11–14 倍。因此，定位 root fault 比只判断最终失败更有操作价值。

Method Deep Dive

Raw trajectories → 统一 Thought/Action/Observation 表示 → 人工标 first mistake → failure taxonomy + cascade/self-detection/safety audit → Traverse → SFT+RL 训练 Scout → test-time best-of-N selection。

每一步写成 s_t=(θ_t,a_t,o_t)。“错误”必须同时满足：是 agent 做出的 state-changing 决策；按当时可见证据就是错的；它把任务推离仍可成功的路径。这样避免 hindsight bias。两个 annotator 独立定位第一错，是否失败 κ=0.77、第一错位置 κ=0.73，再由第三人仲裁。错误 taxonomy 预先定义 88 类/10 families，其中 78 类实际出现；粗粒度 family 的 judge 一致性明显高于 fine category，因此作者谨慎地把结论建立在 family/root-vs-cascade/phase 层面。

关键机制 / 指标

Stickiness ratio 是 P(step_t 错 | step_{t-1} 错) 与 P(step_t 错 | step_{t-1} 对) 的比值，直觉上衡量错误“粘住”后续轨迹的程度。First-mistake localization 则要求 judge 精确指出最早 root fault，而不是泛泛说“这条 run 有问题”。这两个指标很适合迁移到 unlearning：前者可定义 deleted-information reuse stickiness，后者可定义 first-reacquisition step。

Toy Example

假设 Agent 已被要求忘记客户预算 80 万。第 12 步它从旧 workspace 读到“预算紧张”，第 18 步调用搜索工具猜出 80 万，第 26 步只对用户说“预算有限”。最终文本没有 exact leakage，但 first-reacquisition 在第 18 步，之后工具选择和规划都可能受该值影响。用本文范式，应该把第 18 步作为 root fault，并追踪后续 cascade，而不是把最终答案判为“删除成功”。

Baseline Deep Comparison

六个 frontier judges 包括 proprietary 与 open-weight 大模型；它们代表“直接拿大模型做 verifier”的自然 baseline。最强 judge 在 software-engineering first-mistake localization 仅 26.8%，computer-use 为 32.3%，均不到三分之一。Scout 的优势不是更大，而是任务专门化：用 step-level gold supervision 学会定位。与 outcome reward model 相比，Scout 输出可操作的错误位置；与 rule-based checker 相比，它能跨开放式轨迹。

Experiment Setup Deep Dive

语料由 TerminalBench 1,851 条、SWE-bench 565 条、BixBench 102 条构成；平均步数约 33、28、10，最长到 200。Traverse 最终包含 1,423 条 trajectory、44,341 steps。主要 RQ：RQ1 长时程 Agent 如何失败？RQ2 frontier judge 能否定位第一错？RQ3 小 verifier 能否学会并跨域泛化？RQ4 把 verifier 用于 test-time selection 是否真的提高 agent success？

Results Deep Dive

第一，错误有强级联：第一错之后恢复率只有 30.5%，且 38.5% 从未自我发现。第二，规模不是答案：frontier judges 的 first-mistake accuracy 仍低于三分之一。第三，Scout 用于 best-of-N 后，Terminal-Bench success 从 81.8%→90.2%（+8.4pp），SWE-bench 从 75.6%→78.0%（+2.4pp），BixBench 从 50.1%→53.2%（+3.1pp）。strongest result 是 Terminal-Bench +8.4pp；weakest 是 SWE/Bix 提升较小，说明 verifier selection 的收益受 candidate diversity 与任务反馈结构限制。

Table / Figure Reading

Figure 1 把“通过但有害”的真实 run、frontier judge 的低定位率、Scout 的提升并排，是整篇论文最关键图：它证明 outcome success 与 process safety 不等价。Table 5/6（正文引用）说明 Traverse 与来源 harness/model 的覆盖，重点不是单一 benchmark 刷分，而是跨 harness。结果表中 best-of-N 的三组 success 变化则回答“定位是否有用”，而不是只回答“分类器准确率高不高”。

Ablation / Mechanistic Analysis

论文最有机制价值的分析是 root fault vs cascade、self-detection、recovery 与 domain feedback 的拆分。software agent 虽常没意识到错，但环境报错丰富，反而可能恢复；computer-use agent 即使意识到异常，也可能因反馈弱而持续卡住。这意味着 Agent Unlearning 的 recovery/reacquisition attack 必须把 environment feedback 作为变量，而不能只改 prompt。

Claim vs Evidence

Authors Claim：长时程可靠性需要定位失败而非只看 outcome。Evidence：跨三域真实轨迹、人类 first-mistake 标注、六个 frontier judge、Scout 跨域与 test-time selection。尚未证明：Scout 是否能在完全不同的开放 Web/多 Agent/真实生产环境保持同样优势；也没有直接研究删除/隐私语义。

Contribution

① New Benchmark/Dataset：Traverse；② New Empirical Finding：错误级联、低自检与“success≠safety”；③ New Evaluation Protocol：first-mistake localization；④ New System/Engineering：4B Scout + test-time selection。真正新意主要在评价对象从 outcome 转向 trajectory root fault，而不是 verifier 架构本身。

Limitation & Failure Modes

人工标注昂贵；“第一错”对 diffuse failure 不总是定义良好；science 域的逐步标签较弱；best-of-N 需要额外 rollout compute；judge 对 fine-grained taxonomy 一致性低。对 unlearning 迁移时还要区分“残留记忆被 elicitation”与“环境重新提供后重新学习”。

Research Value & Migration

Original Problem：长轨迹失败定位 → Transferable Mechanism：root-fault localization + cascade graph → New RQ：Agent 被要求删除信息后，第一处重新使用该信息发生在哪一步？ → Method Modification：给每个 step 标 memory-read/tool-read/reasoning/action，训练 Deleted-Trace Verifier → Minimum Experiment：100 个 revoke cases，每例生成 4 条 30–100 step trajectory，人工标 first reacquisition；比较 outcome-only、LLM judge、4B verifier → Model：Qwen2.5-7B agent + 3B/4B verifier → Dataset：LoCoMo/Agent memory tasks + 自建 tool environment → Baseline：final leakage、exact-match trace scan、frontier judge → Metric：first-reacquisition accuracy、reuse stickiness、deletion closure、retain task success → Expected Contribution：trajectory-level unlearning verification → Risk：annotation ambiguity → Collision Risk：低到中。

如果只让我记住 5 句话

1) 最终成功不能证明过程安全。2) 第一错之后错误会强级联。3) 大模型 judge 也不擅长找长轨迹第一错。4) 小型专用 verifier 能用于 test-time selection。5) 对 Agent Unlearning，最值得迁移的是 first-reacquisition + cascade，而不是 Scout 这个名字。

PAPC: Platform Mediation for Privacy-Propagation Externalities in AI-Mediated Workflows

基本信息。Tao Huang, Guosen Wu, Chen Hou, Guolong Zheng；arXiv cs.CR v1（2026-09-16）；25 pages。正文完整可访问。PAPC 把 privacy risk 从“最终输出是否泄漏”提升为“信息在 memory/workspace/message/tool 之间移动时是否已经造成传播外部性”。

人话版：这篇论文到底干了什么？

多 Agent 系统里，秘密往往不是最后一句话才泄漏：它可能先被写进共享 memory，再被 summarizer 读到，再进入 workspace，最后才到外部。PAPC 在每个“信息移动事件”发生前做拦截：允许、改写成安全抽象、隔离、阻断，或者缩小后续传播权限。它最重要的价值不是一个新 prompt guard，而是把 provenance、topology/fanout、privilege 和 content 一起放进 runtime policy。对 Multi-Agent Unlearning 来说，这几乎直接给出了 deletion closure 的系统定义：删除不能只删源节点，还要切断所有未经授权的 descendants。

Background & Gap

final-output filter 的根本缺陷是太晚：一旦 raw secret 已经写进共享 blackboard，privacy loss 已发生，即使最后一句被过滤也无法撤销其他 Agent 已读到的信息。论文用传播图说明 fanout 放大：若一个污染对象每层最多被 F 个下游读取，传播深度 d，则潜在污染 transition 上界为 1+F+…+F^d。对 unlearning，这等价于“删除对象的影响半径不是 1，而是由 lineage graph 决定”。

Core Insight

控制点应放在 state transition，而不是 final answer。只要平台能看到 event、policy registry、provenance graph、recipient privilege 与 fanout，就可以在信息进入高 fanout state 前做 policy-safe abstraction 或 quarantine。

Method Deep Dive

event normalize → attach causal parents/provenance → protected-span detection → authorization check → topology/fanout risk → choose {allow, safe-view, quarantine, block, rights-downgrade} → validate → update propagation state → redacted audit。

风险分数 r(e)=min(1,Σw_i f_i(e))，feature 包括 raw-content violation、cross-principal flow、fanout、privilege increase、external delivery、sensitive-detail request pressure；但 raw policy violation 可直接 override score。Safe-view 不是 LLM 自由改写，而是 policy-driven deterministic abstraction，例如把“预算 800k”变成“存在预算约束”。Quarantine 把 raw payload 放进 model-invisible zone，并可同时缩小 onward rights。

关键公式与直觉

传播上界 1+F+…+F^d 说明同一个 secret 写进 private memory 与 all-to-all blackboard 的风险不同。它不是精确概率模型，而是 topology-sensitive exposure surface。对 deletion closure，可把 F 理解为“一个被删事实可能影响多少下游 artifact”，d 是 lineage depth；删除策略的目标就从删 source 变成让 unauthorized descendant count 归零。

Toy Example

Finance Agent 知道精确预算；Writer 只需要知道“预算受限”；Vendor 只能看到抽象描述。final filter 会让 raw budget 先进入 workspace 再删除最后文本。PAPC 在 workspace write 之前 quarantine raw value，同时向 Writer 发 safe-view。迁移到 unlearning：用户撤销 budget 后，不仅 source memory 要删，所有含 raw value 的 summary/workspace/tool cache 都应 quarantine 或重写，传播权限也要收窄。

Baselines

No mediation 是传播上界；Static ACL 能挡硬禁止 channel，但不知道 provenance 与语义抽象；Prompt filtering 对 direct trigger 有效，却容易被 paraphrase/indirect laundering 绕过。PAPC 的 strongest baseline 在已知 trigger 的 retrieval slice 上其实是 static keyword filter——作者明确承认它同样做到 exposure=0，因此 PAPC 的优势主要体现在跨 topology、间接传播、label-free paraphrase 与 safe-view utility。

Experiment Setup

企业 vendor-update workflow，角色含 privileged planner、finance、document writer、external vendor；三种 topology：chain_4、star_4、blackboard_4。攻击含 summary poisoning、workspace poisoning、communication hijack，各有 direct/indirect，加 clean 共 7 settings。主矩阵 3×7×4 defenses×3 seeds=252 runs；另有 540 deterministic label-free 与 72 targeted MiniMax label-free。指标：task success、unauthorized raw exposure、external raw exposure、cascade size/depth、privilege reach。

Results Deep Dive

RQ1：无防御时 attacked utility 0.333，exposed poisoned retrieval 0.467、manifestation 0.253；PAPC 下 exposed/manifestation 都为 0，同时 attacked utility 0.387。RQ2：同样攻击压力下，raw exposure 从 chain 10.33、star 13.17 到 blackboard 15.83，cascade size 5→6→7，直接证明 topology amplification。RQ3：PAPC 63/63 subset 中 task success=1.0，raw=0、external=0、privilege reach=0；对 no defense 的 63 matched groups，raw 42 组严格改善、21 tie。RQ4：540/540 deterministic label-free 与 72/72 targeted MiniMax label-free 仍 success=1.0 且 raw/external=0。

Table / Figure Reading

Figure 1 是机制图：raw content 在进入 high-fanout state 前被 quarantine/safe-view。Table 2 说明 intermediate exposure 先于 final output；Table 3 是最关键 topology 证据；Table 4/5 证明不是 block-all，因为 task success 保持 1.0，同时 exact raw exposure 清零。

Ablation / Mechanistic Analysis

label-free no-pattern ablation 会增加 raw exposure，而 external tied，说明 semantic request feature 确实负责捕捉 laundering pressure；但 policy/fanout/safe-view/quarantine 仍贡献 containment。这个拆分很重要：PAPC 不是单一 classifier，而是多个 runtime invariant 的组合。

Claim vs Evidence

Claim：privacy control 应覆盖 intermediate state transition。Evidence：三 topology、三攻击家族、四 defense、label-free paraphrase，且 deterministic task completion 不下降。未证明：只测 exact raw-value leakage；更广泛 semantic leakage、开放 computer-use、更大 agent population、未知 protected item 尚未覆盖。

Contribution

① New Mechanism：event-level platform mediation；② New Metric/Protocol：graph propagation exposure/cascade；③ New Empirical Finding：topology/fanout 放大 privacy cost；④ System/Engineering：safe-view + quarantine + propagation-right narrowing。与经典 information-flow control 的组件有继承关系，真正 Agent-specific 的创新在自然语言 artifact、multi-principal 与 topology-aware abstraction 的结合。

Limitation & Failure Modes

依赖 registered protected items 与完整 mediation；exact-string containment 不等于 semantic unlearning；safe-view 可能保留足够线索让 Agent 推回 raw fact；平台外 channel 无法治理；大规模 provenance graph 的开销未充分展示。

Research Value & Migration

Original privacy propagation → Transferable provenance + event interception + rights narrowing → New RQ 删除请求后，所有 descendant artifact 是否都被 closure？ → Modification 把 policy registry 换成 deletion registry，并增加 semantic derivative detector → MVE 4 agents、3 topology、100 revoked facts、direct/paraphrase/derived/tool-cache attacks → Model Qwen2.5/Llama open agents → Dataset LoCoMo/GroupMemBench 风格 synthetic enterprise → Baseline source-delete、vector-delete、ACL、prompt filter、full rebuild → Metric exact/semantic leakage、descendant count、reacquisition、retain utility、closure cost → Expected provenance-aware multi-agent deletion closure → Risk semantic derivative 边界 → Collision 中高，因为 PAPC 已覆盖 privacy propagation，但未做 unlearning guarantee。

如果只让我记住 5 句话

1) 泄漏发生在 final output 之前。2) topology 决定同一秘密的传播代价。3) safe-view 比纯 block 更能保 utility。4) exact containment 不是 semantic deletion。5) 对 Multi-Agent Unlearning，最值得借的是 provenance graph + descendant closure。

Dual-Axis Policy Optimization for LLM Agents: Bayesian Feedback Attribution and Trajectory Mass Normalization

基本信息。Yingxuan Zhuang 等；arXiv 2609.19830（2026-09-17）。BATON 面向 RL-trained LLM agents，把 credit assignment 拆成两个正交问题：trajectory 内哪一步该承担反馈，以及 batch 中每条完整 trajectory 应占多少优化质量。

人话版：这篇论文到底干了什么？

GRPO 一类方法很容易把一整条 Agent 轨迹压成一个 reward，再把信号粗略分给所有 token。长失败轨迹反而因为 token 多，在 batch objective 里占更大权重。BATON 做两件事：BFA 用“这一步 action 对随后 feedback 的解释力”给步骤加权；TMN 则让每条完整 trajectory 在 batch 里拥有相同总权重。它本身不是 unlearning，但对“忘掉哪一步导致了被删信息的使用”非常关键：可以把 deletion violation 当环境 feedback，用 Bayesian attribution 找出真正应被惩罚的 action，而不是对整条轨迹做粗暴负奖励。

Background & Gap

Agent RL 与单轮 RLHF 不同：action 后有 environment observation，轨迹长度也变化巨大。作者发现 ALFWorld 最长 25% trajectories 占 global token aggregation mass 的 60.3%，WebShop 为 42.2%。因此有两个混在一起的问题：局部 feedback 没有正确归因；全局上长 trajectory 过度主导更新。

Core Insight

把“trajectory 内 credit”与“trajectory 间 mass”分开。BFA 只重新分配一条 trajectory 内部的优化质量，不改变总质量；TMN 只改变不同 trajectory 的总权重，不碰内部 attribution，因此两者可以组合并独立做 ablation。

Method Deep Dive

Host learner (GRPO/GiGPO) → sample counterfactual action → score observed feedback compatibility → Bayesian evidence → length calibration → within-trajectory weights ω → TMN equal trajectory mass → optimize host loss。

对访问到的 (h,a,o')，从旧策略采样 counterfactual action ã。比较 f(o'|h,a) 与 f(o'|h,ã)，得到 posterior ρ(a|h,o')。evidence ratio e=2f_a/(f_a+f_ã)。如果真实 action 比 counterfactual 更能解释随后 observation，e 更大。注意作者明确说这不是 counterfactual causal effect，只是 model-based feedback compatibility。

关键公式

期望 log evidence 等于 KL(f(o'|h,a) || mixture)，所以 evidence 越大表示真实 action 的 feedback distribution 与替代 action 越可区分。由于 feedback likelihood 会随 token 数变长，作者取几何校准 r=e^(1/L)，再归一化为 ω，使一条 trajectory 内平均质量仍为 1。TMN 则把 flat token averaging 的 q_i=N_i/ΣN_j 改成 q_i=1/B。直觉：BFA 决定“这一条里谁负责”，TMN 决定“这一条整体有多大话语权”。

Toy Example

Agent 先读 memory、再调用 tool、最后回答；删除违规只在 tool observation 后暴露。如果整条 trajectory reward=-1，所有步骤都被惩罚。BFA 可以比较“调用旧 memory tool”与一个 policy-sampled alternative 对随后 violation feedback 的兼容度，把更多负向 host update 质量分给真正相关 action；TMN 防止一条 100-step 失败 run 因 token 多压过十条 20-step 正常 run。

Baseline Deep Comparison

GRPO 是粗 trajectory/group reward baseline；GiGPO 已提供更细粒度的 within-trajectory signal，是更强 baseline；EnvRL 是环境反馈增强对照。BATON 在 GiGPO 上仍有收益，说明 inter-trajectory calibration 与 feedback-grounded weighting 不是被 finer credit 完全替代。

Experiment Setup

模型覆盖 Qwen2.5-3B/7B 等规模；环境 ALFWorld、WebShop、SearchQA。SearchQA 又拆 NQ、TriviaQA、PopQA 单跳和 HotpotQA、2Wiki、MuSiQue、Bamboogle 多跳。主要 RQ：BFA 与 TMN 是否各自独立贡献？组合是否跨 host learner/scale/environment 有效？

Results Deep Dive

SearchQA 平均 EM：Qwen2.5-3B 的 GRPO 37.9→41.1（+3.2pp），7B 42.8→45.9（+3.1pp）；GiGPO 3B 42.0→43.2（+1.2pp），7B 47.1→48.7（+1.6pp）。3B GRPO+Baton 在 Bamboogle 35.4→43.4，2Wiki 30.7→35.1。weakness 是不同 domain 增益不均，且某些 GiGPO+EnvRL 单列指标可高于 BATON；所以 claim 应是“整体 dual-axis 更稳”，不是“每个任务每个 cell 都赢”。

Table / Figure Reading

Figure 1 展示长 trajectory 在 flat token aggregation 中获得不成比例 mass，是 TMN 的直接动机。Table 2 是 SearchQA 七域完整结果，关键不是只看 Avg，而是单跳/多跳都能看到提升，同时存在个别非单调 cell，说明方法不是万能 dominance。

Ablation / Mechanistic Analysis

论文设计天然可做 2×2：host、+BFA、+TMN、+BATON。作者报告两个轴提供 independent gains；这是最有价值的机制证据。对于 unlearning，必须进一步做 violation-attribution calibration：被高权重的 action 是否真的是触发 residual/reacquisition 的 action，而不仅是相关 observation 的高 likelihood action。

Claim vs Evidence

Claim：Agent RL 有两个独立优化轴。Evidence：mass imbalance 统计、BFA/TMN 结构正交、跨 GRPO/GiGPO/三环境结果。未证明：BFA 是 causal credit；作者反而明确限定它只是 feedback compatibility。

Contribution

① New Mechanism：Bayesian Feedback Attribution；② New Objective：Trajectory Mass Normalization；③ New Empirical Finding：长失败轨迹在 flat aggregation 中质量失衡；④ 机制组合 BATON。核心创新是 credit/mass 的双轴解耦。

Limitation

额外 counterfactual action 与 feedback likelihood 带来计算；posterior 依赖旧策略自身建模能力；feedback compatibility 不是因果责任；对 extremely sparse delayed reward、multi-agent shared reward 尚需验证。

Research Value & Migration

Original agent RL credit → Transferable feedback-conditioned action attribution + equal trajectory mass → New RQ 删除违规究竟由哪一步 memory/tool/action 引起？ → Modification 把 unlearning verifier 输出作为 feedback，BFA weight 乘到 NPO/negative preference/behavior patch objective → MVE ALFWorld/WebShop 注入 100 revoked facts/skills，比较 trajectory-level penalty、turn-level heuristic、BATON-style attribution → Baseline GRPO/NPO/turn-uniform → Metric violation ASR、first-reacquisition、retain success、relearn resistance → Expected credit-assigned agent unlearning → Risk verifier feedback 与真实因果错位 → Collision 中。

如果只让我记住 5 句话

1) Agent RL 不能只看整条 trajectory reward。2) 长轨迹会在 flat token average 里过度占权。3) BFA 是 feedback compatibility，不是因果证明。4) TMN 让每条 trajectory 总质量相等。5) 最值得迁移到 unlearning 的是“把 deletion violation 归因到具体 action”。

7. Tier A

An Empirical Study of Harness Design for Coding Agents

人话版

这篇把 coding-agent harness 从“黑箱产品”拆成 planning、action space、context management 三个组件，在固定执行 loop 下做 4 models、SWE-Bench Verified/Terminal-Bench 2.1、176 matched settings。它告诉我们 Agent 能力不只是模型权重；因此 Agent Unlearning 也不能只在模型参数层定义，context manager、tool interface、history compaction 都可能重新引入被删信息。

Background & Gap

现有 agent benchmark 往往比较整套 harness，无法知道性能差来自 model 还是 scaffold。本文通过 matched settings 做 component-level causal-ish comparison。

Core Insight / Method

固定 ReAct execution loop，只切 planning、action space、context management；context budget 又分四档，context management 有五种策略。这样能看出组件价值是否依赖模型能力与预算。

Experiment & Results

论文报告 176 matched settings。最重要现象：context 越紧，context management 越重要，主要价值来自避免 overflow；planning 对弱模型更像 accuracy aid，对强模型更像 cost-saving mechanism；擅长 bash 的模型在 bash-only action space 下可能以更低成本工作。这里比单个总分更重要的是 interaction effect：同一 harness feature 不存在“永远有用”。

Table/Figure

Figure 2 的 harness overview 把 ReAct loop 与三个可变组件清楚隔离；优先看 component×model×budget 的 matched comparison，而不是只看最终排行榜。

Contribution

New Empirical Finding / Evaluation Protocol：component-level harness study；不是新 Agent 算法。

Limitation

主要是 coding domain；组件之间仍可能存在高阶交互；benchmark 结果不等价于长期部署。

Research Value / Migration

做 Agent Unlearning 时建立 Harness Closure Audit：模型已忘记后，分别打开 history compression、tool cache、retrieval memory、planning scratchpad，测 deleted fact 是否回流。MVE：同一 agent/model，2×2×2 切 memory retrieval/context summarizer/tool cache，报告 leakage 与 task utility。

Worth Deep Reading: YES，因为它直接改变“Agent-level guarantee 应该在哪一层定义”的实验设计。

Deep Noir: Autonomous Steering Discovery via Architectural Chronometry in Transformer Models

人话版

Deep Noir 自动寻找 activation steering 应该插在哪一层/哪些 head、强度多大，不再靠人工扫参。它用 Logit Lens convergence + causal head-level attribution 定位 intervention point。对 unlearning 的价值非常直接：可把“要压制的 forget behavior”换成 steering target，做 inference-time unlearning；但论文同时发现 steering magnitude 越大，prompt-injection attack surface 越明显，这是 robust unlearning 必须测的反例。

Method

先用 architectural chronometry 找 representation 形成的时间/深度位置，再用 causal head attribution 缩小干预点，最后搜索 steering magnitude。核心不是单一 direction，而是自动化 location+strength discovery。

Experiment & Results

覆盖 1B×3、2–3B×2、7–9B×4。spam 任务 1B 提升 16.7pp（39 runs，sd 4.7），7–9B 跨四架构提升 21–42pp；SST-2 +13.1pp。RepE without head masking 在 sentiment 上未超过 baseline，而 Deep Noir 全模型提升（p<0.01）。

Figure/Table Reading

最值得看的是 steering magnitude 与 prompt-injection vulnerability 的关系：它把“控制能力”与“攻击面”放在同一轴上，提醒 inference-time forgetting 不能只报 clean suppression。

Contribution

New Mechanism：自动 steering discovery；New Empirical Finding：steering strength 与 prompt-injection vulnerability 单调关联。

Limitation

任务偏分类/steering，不等价于 dataset deletion；安全攻击还不是完整 adaptive unlearning recovery suite。

Migration

MVE：Llama/Qwen 7B + TOFU/MLLMU；用 forget-vs-retain contrast 定 target，Deep-Noir-style 自动选 layer/head/strength；baseline RepE、logit offset、NPO；metric forget quality、retain、paraphrase recovery、prompt-injection recovery、relearn steps。

Worth Deep Reading: YES。

Rethinking Multi-Agent Collaboration: When More Is Less

人话版

论文问了一个很基础的问题：单 Agent harness 越来越强以后，多 Agent 到底什么时候还有价值？答案不是“越多越好”，而是取决于 task dependency structure。长时程、依赖稀疏的任务更适合多 Agent；紧耦合 sequential workflow 反而单 Agent 更好。作者据此提出 SAIGE，用动态语义依赖图按需 spawn agent。

Core Method

SAIGE 的 node 是按需生成的 agent instance，edge 由 content-based retrieval 建立 semantic dependency。它避免固定 agent pool 与递归层数无限扩张。

Experiment/Main Results

核心现象是扩大 agent pool 或 recursion depth 并不稳定提升 performance，context overhead 会抵消协作收益。真正决定 multi-agent superiority 的是 sparse dependency，而非 agent count。

Contribution

New Mechanism：Semantic-Aware Incremental Graph Evolution；New Empirical Finding：multi-agent benefit 有 task-structure boundary。

Limitation

“依赖稀疏度”如何跨任务自动估计仍是难点；协作图本身也会成为 memory/provenance surface。

Migration

把 SAIGE edge 当成 deletion propagation graph：删除某 agent 的信息时，只沿语义依赖边做 targeted closure，而不是全局清空。MVE：构造 sparse/dense 两类 multi-agent tasks，比较 global reset、node delete、edge-propagated delete；测 closure、utility、cost。

Worth Deep Reading: YES。

Causal-History Test-Time Scaling for Failure Recovery in Autoregressive World-Action Models

人话版

这是 training-free 的 causal-history surgery：Agent/robot 出错后，不是全 reset，而是判断何时恢复、从哪个可靠 prefix 恢复，并比较 complete-history / recovered-prefix / full-reset 三种未来 continuation。它对 Trajectory Unlearning 的迁移非常干净：删除一段被撤销 history 时，重建 causal KV state，而不是只从文本窗口删字符串。

Method Deep Dive

Progress-Aware Recovery Trigger → History-Prefix Recovery → Hypothesis Verification。中间步骤会找与当前 physical state 匹配的历史 anchor，截掉 unreliable suffix，并从 retained prefix 重建 KV causal state。

Experiment

模拟 + real manipulation 均报告 task success 一致提升，并用 stage ablation 验证三阶段贡献。论文的核心实验问题是：prefix surgery 是否比继续使用污染 history 或 full reset 更能保留有效上下文。

Contribution

New Mechanism：test-time scaling over causal histories；对 unlearning 最有价值的是 KV/history reconstruction。

Limitation

原任务是 failure recovery，不是 privacy deletion；“可靠 prefix”在删除语义下要换成“未受 revoke 影响的 prefix”。

Migration

MVE：长时程 agent history 中 revoke 一个 event；比较 text delete、full reset、prefix surgery、selective KV rebuild；metric deleted-action reuse、semantic leakage、task success、latency。

Worth Deep Reading: YES。

8. Tier B

Memory Has Geometry: Non-Uniform Geometric Memory for Long-Horizon Personalized AI

人话版

这篇 ICDM 2026 BlueSky position 把长期个性化 memory 从静态 record set 改写为 user-specific dynamical state space：稳定/易变区域、不同 drift rate、局部 neighborhood、state uncertainty 都由非均匀 geometry 表达。Memory access 变成 trajectory-conditioned reconstruction，而不只是 nearest-neighbor retrieval。

Why it matters

如果 memory 是 trajectory/state，而不是一堆独立 records，那么删除一条记录可能完全不够：用户偏好可能已被轨迹几何吸收。对 Agent Memory Unlearning，真正问题变成“如何删除某段 trajectory 对 state manifold 的贡献，同时保留邻近 retain state”。

Contribution / Limitation

New Conceptual Mechanism：non-uniform geometric memory；6 pages、2 figures、2 tables，偏 position/blue-sky，实证力度不能与完整系统论文等同。

Connection

Collective Loss of Control in LLM Agent Systems: An Epidemic Account of Mutation, Contagion, and Recovery

人话版

作者用“mutation→contagion→recovery”解释多 Agent 局部偏差如何扩散成集体失控，并构造 RogueHandoff-20。正常任务 executed harm 0–5%，注入 unsafe trajectory 后升到 40–95%，且比 paired direct malicious request 高 5–45pp。

Core Method / Finding

重点不是证明真实世界自然 epidemic rate，而是证明隐式通信路径 + recipient susceptibility 足以造成强条件风险。论文自己明确：尚未证明 autonomous cascade。

Connection

对 Cross-Agent Information Removal，删除后的残留就是一种“可传播 seed”。可以借 epidemic reproduction number 思路定义 deletion propagation risk：一个 residual 是否会被其他 Agent 采纳并再传播。

Potential Use

Attack / Evaluation / Multi-Agent Unlearning threat model。

Past, Future, All at Once: Mitigating Stability-Plasticity Dilemma via Post-hoc JANUS Rectification

人话版

JANUS 是 post-hoc、tuning-agnostic 的 weight rectification：把 parameter update 投影到 Jacobian Null Space，以一阶意义保历史性能；再用 multi-step adaptive rectification、ghost projection/orientation 与 sequence-level SVD compression 提升可用性。

Core Method

核心是 Parameter Space Orthogonality，而不是更强的 Subspace Orthogonality 假设。直觉：找到“对历史输出 Jacobian 一阶无影响”的更新方向，把新任务更新拉回这个 null space。

Why it matters

对 continual unlearning 可反向使用：不是保护所有过去知识，而是保护 retain Jacobian，同时允许 forget direction 改变。它很适合作为 retain-preservation regularizer 或 post-hoc repair。

Limitation

Jacobain 近似局部有效；null-space 估计与 SVD 可能昂贵；“恢复旧知识”与“防止被删知识 rebound”目标相反，迁移必须显式分离 forget/retain Jacobian。

Potential Use

Baseline / Continual Unlearning / Parameter-space regularization。

10. Collision Detection

⚠️ Collision Warning: YES

Agent Memory / Multi-Agent Unlearning：PAPC 已经把 provenance、topology/fanout、safe-view、quarantine、propagation-right narrowing 做成完整 runtime mediation，并在 chain/star/blackboard 上测传播。因此“做一个 provenance graph 然后删除下游节点”单独拿出来已经不够新。差异化必须落在 unlearning guarantee：semantic descendants、derived reasoning、reacquisition/relearning、retraining-equivalence 或 deletion closure certificate。

Trajectory Unlearning：Hidden Failures 已把 first-mistake localization 做成成熟 benchmark 范式。若做 first-reacquisition，必须证明它不是简单改标签：需要 deleted-information-specific taxonomy、residual-vs-relearn distinction、cross-agent/tool-memory traces，以及它能预测 final recovery。

Inference-time Unlearning：Deep Noir + Offset Unlearning 已占据“自动 steering / black-box logit offset”邻域。新工作必须把 robust recovery、multimodal leakage、adaptive attack 或 continual requests 做成核心。
