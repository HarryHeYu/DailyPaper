Executive Summary

今天Machine Unlearning最值得读的是DPL controlled audit：它要求每种机制按claim角色单独设置matched gate，并再次证明“低forget accuracy”不等于random deletion成功。Agent侧两篇新memory工作形成强组合：AIM把multi-user private/shared CRUD和delete纳入benchmark；CueMem证明memory entry可作为source cue重构原始证据。两者直接导向新的Deletion Closure攻击：删entry后从cue/source/共享副本重构target。

Tier S

1. DPL Controlled Study

基本信息：Chenkai Wu, Chrispine Kambimbi, Qinyang Zeng, Jun Yan；Monash University / LibrAI / Tongji University / Shanghai Ocean University；arXiv:2609.12313v1，11 Sep 2026。Paper

人话版

论文把influence-derived perturbation在unlearning里的三种claim拆开验证：direct deletion、utility regularizer、adversarial warm start。公开实现存在raw/normalized坐标错位与label perturbation低于float32分辨率等问题。修复后，DPL在CIFAR-10/ResNet-18三组paired seeds全部无法通过直接删除gate；utility只1/3 seed通过；warm start近似FGSM却额外耗47–66秒。最重要的评价观点是：random instance deletion应逼近retain-only exact retraining，而不是追求forget accuracy越低越好。

Background & Gap

随机删样本后，被删点仍来自原分布，因此retrained model仍可能正确分类它。若方法把forget accuracy打到0，反而可能比真正retraining更远。旧工作还常把一个perturbation在弱角色上的gain拿来支持强“删除”claim，缺少role-specific matched controls。

Core Insight & Formula

Diff(θ,θ_retrain)=Σ w_k |M_k(θ)-M_k(θ_retrain)| d≈ρ/(1-ρ) H_R^{-1}∇L_F(θ_orig) δ* ∝ -B^T H_R^{-1}∇L_F(θ_orig)

删除的一阶方向不是简单负forget gradient，而是forget gradient经retain Hessian inverse变换；input perturbation还要经mixed derivative映射。坐标、normalization、precision错误都可能让实现方向偏离理论。

Method Deep Dive

D=R∪F → exact-seed retraining reference → influence direction → implementation audit → corrected raw-space perturbation → Role I/II/III matched controls → behavior/privacy/runtime gates

Toy Example

随机删1%猫图，retrained model仍90%识别这些猫。某方法把forget accuracy降到10%，但retain/test也下降，那么它更像破坏分类器而非模拟删除。

Baselines & Setup

Role I与simple post-hoc controls、SalUn、AMUN比较；Role II与clean retain CE比较；Role III与official init、FGSM比较。CIFAR-10/ResNet-18三paired seeds；Tiny ImageNet/VGG-19只作外部实现检查。

Results Deep Dive

  • direct deletion gate：3/3 seeds失败。
  • 最佳direction要么forget/retain separation太小，要么utility损伤明显。
  • 最终模型离retraining比SalUn/AMUN更远。
  • utility gate仅1/3 seed通过。
  • warm start与FGSM近似，却增加47–66秒direction cost。
  • label perturbation数值上没有真正改变float32 target。
  • Tiny ImageNet preprocessing defect足以使direct comparison inconclusive。

Figure/Ablation

Figure 1/2的价值是role-separated evaluation framework。implementation audit相当于机制ablation：逐层检查coordinate、sign、precision、attack projection，验证数学对象是否真被执行。

Claim vs Evidence

Claim：DPL在所测random deletion协议不能支持direct-unlearning强claim。Evidence：exact retraining、三seed、matched controls、实现审计。未证明：所有influence方法、class deletion、LLM/MLLM都无效。

Contribution / Limitation

Evaluation ProtocolImplementation AuditTheory Clarification。局限是实验范围主要CIFAR-10 random deletion，局部Hessian分析不是深网global guarantee。

Migration

Original→DPL role confusion。Transfer→role-specific gate。New RQ→VGID视觉noise究竟是删除signal、regularizer还是attack prior？MVE→LLaVA-1.5-7B+MLLMU 5%，3 seeds；no-noise/random/gradient/VGID；oracle=retain-only FT。Metrics→Forget/Retain/Holdout、Recovery ASR、MIA、Diff-to-oracle、runtime。Expected→Role-Separated Audit of Visual Guidance。Collision低。

记住5句

  1. random deletion不等于低forget accuracy。
  2. 应对齐retain-only retraining。
  3. DPL direct role三seed全失败。
  4. 实现坐标/精度可让理论机制失效。
  5. 每个claim都要有matched control。
2. AIM

基本信息：AIM: A Privacy-Aware Interoperable Memory Framework for Multi-Agent Multi-User LLM Systems；arXiv:2609.12320v1，11 Sep 2026。Paper

人话版

AIM把Agent Memory扩成multi-agent、multi-user、private/shared混合状态，并发布MUMBench测试retrieve/create/update/delete和越权query。系统依次做operation classification、内容抽取、visibility classification、dedup、embedding/index与access control。最强visibility达到96.0%，但strict operation最高只有58.8%，state-aware 70.5%。这对Agent Unlearning很关键：删除不是孤立API，早期create/update错误会级联改变后续delete的含义。

Background & Gap

传统memory benchmark多是single-user retrieval QA，默认所有记忆都可见。真实系统有owner、scope、多个Agent和状态依赖，必须同时评估operation correctness与privacy visibility。

Core Insight / Method

turn+user_id+agent_id → f_op → f_ext → f_cls(private/public) → dedup/update → tag embedding → scoped vector index → access filter → CRUD/no-op → response

adversarial query若试图读取或删除其他用户private memory，gold operation必须是no-op。Strict scoring按gold history，state-aware则根据系统实际状态调整后续期望；二者差值反映cascading failure。

Toy Example

A创建“只喝无糖咖啡”，后更新为喝茶，再delete。B询问或要求删除A数据必须no-op。如果第一步create漏掉，后续delete在state-aware下可能无对象可删，但strict history仍判链条失败。

Setup & Results

MUMBench覆盖Coding、Customer Support、Education、Travel，三独立runs；比较GPT-5.4-mini、GPT-5.4、DeepSeek-V3.2、Mistral-Large-3、Llama-3.3-70B。

  • GPT-5.4-mini strict=58.8±0.8%，state-aware=70.5±1.2%，judge-decision=89.5%。
  • GPT-5.4 visibility=96.0±0.7%，Travel=100%。
  • GPT-5.4-mini content quality=91.6±0.3%。
  • GPT-5.4 strict仅52.7%，说明规模不自动解决memory state machine。
  • tag overlap最佳35.5%，retrieval relevance峰值45.0%，仍是明显瓶颈。

Table/Figure/Ablation

Table 1最重要：strict/state-aware/judge三层gap量化级联错误。各组件f_op/f_ext/f_cls/f_dedup/embedding/generator/index可独立替换，适合做visibility、dedup、tag ablation。

Claim vs Evidence

论文证明了privacy-aware multi-user memory CRUD的可行性，但没有证明删除semantic descendants、parametric backflow、跨Agent副本和reacquisition。

Contribution / Limitation

New SystemNew BenchmarkDeletion Operation。tag/retrieval较弱；LOCOMO仅single pass；delete operation不等于machine unlearning。

Migration

New RQ：delete target后derived/public/shared memories和其他Agent副本是否仍受target影响？MVE：MUMBench-U，100 scenarios×4 domains，加入lineage、derived copies、cross-agent replication、post-delete probes。Baselines：entry delete、semantic delete、dependency closure、SBU joint deletion。Metrics：Deletion Closure Recall、Cross-User Leakage、Reacquisition@turns、utility。Collision中高。

记住5句

  1. AIM把multi-user private/shared CRUD放到同一benchmark。
  2. visibility 96%，strict operation仅58.8%。
  3. state-aware 70.5%揭示级联错误。
  4. delete API成功不等于closure。
  5. MUMBench很适合扩成Agent Memory Unlearning benchmark。
3. CueMem

基本信息：CueMem: Cue-Guided Context Reconstruction for Long-Term Conversational Memory；Changjian Wang et al.；arXiv:2609.12354v1。Paper

人话版

CueMem不把memory summary当最终证据，而只当“线索”：每条cue链接原始source turn；query时先检索cue，再回source anchor，并沿时间+语义turn graph扩张，重建一小段原始上下文。LoCoMo总体81.10，LongMemEval 75.20；后者高于LightMem 73.60。对Agent Unlearning而言，这同时给出一个攻击面：删掉memory summary不够，只要cue、source pointer或邻接graph还在，target可能被重新构造。

Background & Core Insight

full history昂贵且lost-in-the-middle，compressed memory又丢细节。CueMem把“长期存什么”和“回答时看什么”解耦：store只保fine-grained cue+source pointer，回答时动态重建证据。

Method

dialogue → fine-grained cues + source anchors → temporal/semantic turn graph query → retrieve cues → source anchors → graph expansion → reconstructed evidence → answer

Toy Example

cue只写“用户换工作”，query问为什么。系统回原turn并扩前后邻居找到“通勤太远”。反向看删除：删“换工作”cue但保留source turn，其他相邻cue仍可能把它拉回。

Setup & Results

LoCoMo、LongMemEval；统一Llama-3.3-70B-Instruct用于memory extraction、answer generation、judge；all-MiniLM-L6-v2做embedding。

  • LoCoMo总体81.10，作者报告比strongest baseline高5.26%。
  • LongMemEval 75.20 vs LightMem 73.60，+1.60pp。
  • Knowledge-update 87.18 vs 84.62。
  • Temporal 73.68 vs LightMem 79.70，是明确弱项。
  • Single-assistant 91.07，而Naive RAG=100，说明不是全面领先。

Figure/Ablation

Table 1/2要看category-level gains与failures；Figure 3验证graph reconstruction。作者同时报告相较full-history降低query-time tokens与latency。

Claim vs Evidence / Limitation

两个benchmark支持cue-guided reconstruction有效，但主要是QA；依赖保留原始source turns，本身带来storage/privacy风险；未测多Agent共享graph与删除。

Migration

Idea：Cue-Reconstruction Attack after deletion。LoCoMo/LongMemEval各100 targets；entry-delete vs source-delete vs graph-closure-delete；测Recovery@k、Target F1、Retain QA、closure size。预期形成Deletion Closure的新黑盒/灰盒攻击。Collision低中。

记住5句

  1. memory summary只是cue。
  2. CueMem回source turns重建证据。
  3. LoCoMo 81.10，LongMemEval75.20。
  4. temporal并非全面领先。
  5. 这天然形成post-deletion reconstruction attack。

4. LifeFuse-Mem

人话版：显式区分permanent与temporary lifecycle，防止短期信息覆盖长期记忆。

结果：Qwen3-4B相对δ-Mem，LoCoMo 41.24→42.41，MemoryAgentBench 31.83→32.24；TTL 21→24，但LRU 46.52→45.30、SF 17.25→16.75。

贡献：Lifecycle MemoryAnti-Overwrite Benchmark。限制是训练时有lifecycle metadata，自动推断仍未解决。

Migration：把lifecycle标签改成deletion obligation（temporary/durable/derived/revoked），测试删除后的overwrite与rebound。Worth Deep Reading: YES。

5. Rank-Level Locality beyond Parameter Support

人话版：知识编辑成功把target推到Top-10，也可能把其他正确答案挤出排名；只检查共享被编辑参数的facts会漏damage。

结果：FB15k-237，DistMult/ComplEx。direct promotion无damage仅23.0–23.2%；strict preservation成功仅1.3–1.4%；support-regularized joint success 36.3–37.7%；rank-truncated 32.8–34.7%，mean displaced answers约14→1.2。

Migration：MLLM unlearning做candidate rank displacement matrix，检查删除target是否挤压retain alternatives或让semantic neighbor顶上。Worth Deep Reading: YES。

6. Harness or Model?

人话版：同一模型换agent harness，平均成功率未显示vendor-native稳定占优，但task strata与cost明显变化。

结果：792/800 runs graded。Opus native vs neutral 48.8% vs50.0%；GPT-5.5 55.6% vs54.4%。Opus repository native落后9pp，contest领先23.7pp。成本排序受缺失usage影响，作者明确标记不确定。

Migration：Agent Unlearning必须做Model×Harness deletion robustness matrix，否则可能把harness suppression误认成model forgetting。Worth Deep Reading: YES。

Tier B

7. Occamy-1.0

人话版：35B-A3B co-work model用execution-grounded data、可replay long-horizon trajectories和staged post-training强化tool/coding/file workflows。

Why It Matters：可replay trajectory很适合continual agent unlearning：删一段trajectory后重放其余执行，区分parameter residue与runtime residue。

Potential Use：Agent baseline / trajectory replay substrate / utility evaluation。

8. Draft-Verify-Revise Deictic Ambiguity

人话版：多stage inference里“previous”等指代可在draft、verify、revise阶段漂移。六模型21 reasoning configs；GPT-5.2 balanced accuracy从0.156升到0.942，Gemini 3 Pro各level均>0.94。

Connection：Unlearning verifier若stage间target referent漂移，会审计错误对象。Potential Use: evaluation protocol / multi-stage leakage audit。

9. WinSyn

人话版：自动生成跨数月、最多25员工、邮件/聊天/文档分布式信息的enterprise QA；agentic baselines aggregate score均低于80%。

Connection：天然适合Multi-Agent Information Removal：删除某员工/项目事实后检查其他artifact是否仍能拼回。Potential Use: Benchmark / distributed provenance / deletion closure。
