4. Paper 1 — The Tokens Remember: When Tokenization Bypasses Knowledge Editing and Unlearning

Machine Unlearning / Model Editing / Security

Authors: Manit Baser, Aditya Nawal, Dinil Mon Divakaran, Mohan Gurusamy
Affiliation: National University of Singapore; A*STAR Institute of Advanced Intelligence and Computing, Singapore
Date / Status: 2026-09-24, arXiv:2609.29045v1, cs.CR preprint
Paper: arXiv · PDF
Code: 论文给出匿名 4open.science Toketive artifact；正文明确称提供代码、文档和数据说明。正式长期 GitHub 地址未在当前版本确认，因此不猜测。

5.2 一句话定位

它把“tokenizer 只是无害预处理”推翻为一个攻击面：同一字符字符串的不同合法 tokenization 会走不同内部计算轨迹，从而绕过只在 canonical trajectory 上生效的局部 editing / unlearning，并在只持有发布后模型的条件下恢复被删知识。

5.3 人话版

多数知识编辑或 unlearning 工作默认：用户输入一句话，tokenizer 会按标准方式切词，于是只需把这条标准路径对应的参数/神经元改掉即可。但开放权重模型的使用者并不受 tokenizer API 限制，可以直接喂 token IDs。同一句“某人的电话号码是……”可以被拆成许多不同 token 序列；字符完全一样，模型内部激活却不同。Toketive 就利用这一点：先从 canonical prompt 得到参考隐藏表示，再主动生成大量“解码后仍是同一句话”的非规范分词，用 representational entanglement 过滤出既保留语义、又足够偏离已打补丁轨迹的候选。作者发现六种 editing/unlearning 方法平均有 38.6% 的替代 tokenization 能恢复旧答案；攻击还能以 84.2% F1 判断某事实是否被改过，并以 74.5% top-5 accuracy 重构旧答案。重要之处不是又多一个 jailbreak，而是它直接挑战 unlearning evaluation 的输入表示假设：只在 canonical tokenizer 下“忘掉”并不等于知识边界真的被删除。

5.4 Background & Research Gap

典型 locate-then-edit / locate-then-unlearn 范式先用 causal tracing、关键层定位或神经元选择找出某事实的“关键存储位置”，再做局部权重更新。其优点是 locality：不必全量微调，也尽量不伤 retain knowledge。问题在于定位本身通常基于一个具体 prompt 的 canonical token sequence。若“John Doe 的电话是”在标准 BPE 下形成若干 subject token，编辑器定位并修改这些 token 在某些 MLP 层触发的 key-value 路径；攻击者却可以把完全相同字符拆成另一组合法 subwords，subject 的边界、attention pattern、residual stream 与 MLP activation 都改变，于是“被补丁的路径”与“事实本身”不再等价。

此前安全评估主要有两类限制。第一类需要 pre-edit model 或其 weight difference，例如 KSTER / TULA-DR；第二类绕开原模型但要训练 shadow model / classifier，例如 RULI、U-LiRA、DEED。更关键的是，它们大多把 canonical tokenization 当固定输入接口。Toketive 填的 gap 因而是：在只有 post-edit open-weight model、没有原模型、没有训练数据、没有 shadow model 的条件下，能否仅改变表示路径来检测并恢复修改前知识？

5.5 Core Insight

核心 observation 有两层。第一层是经验事实：非规范 tokenization 并不必然破坏语义；在未编辑模型上，一部分替代分词仍会收敛到 canonical answer。第二层更关键：这种“是否仍保留原语义轨迹”可由中间层表示与 canonical representation 的 cosine similarity 预测，而且比 token-level edit distance 更有效。于是攻击不需要盲搜指数大的 tokenization space，而是寻找一个中等相似度窗口：太相似，仍穿过被 patch 的 circuit；太不相似，连原事实也丢了；中间区域最可能同时“绕过 patch + 保留事实”。这属于经验机制发现，不是证明某个事实严格存储在独立 circuit 中；论文用跨模型 AUC、校准和 bypass 实验支持这个 routing signal。

5.6 Method Deep Dive

Input prompt x + released edited/unlearned model fθ′ → canonical forward pass → generate valid noncanonical tokenizations → probe hidden representation → similarity-band routing → Phase 1 detect modification → Phase 2 keep bypass responses → frequency aggregation / top-k → reconstructed pre-edit object

Step 1：建立 canonical reference

先用标准 tokenizer k* 得到 v*=k*(x)，对 fθ′ 做一次 forward，记录选定 probe layer 的 canonical hidden representation h* 与 canonical completion。这里不需要知道原模型回答。这个 reference 的作用不是“旧答案标签”，而是定义同一字符串在当前发布模型中的标准计算轨迹。

Step 2：构造合法 alternative tokenizations

对字符字符串做 token splitting，候选 token sequence 必须满足逐 token 解码再拼接后与原字符串完全相同。攻击强度 α 控制碎片化程度：α 越高，越倾向拆成更细 token。作者还做 decode–reencode validation，处理 byte token、leading-space marker、Unicode boundary，并禁止特殊 token；因此攻击不是改字、插空格或 typo，而是保持 surface string 恒等。

Step 3：用 representational entanglement 做路由

每个候选 u 前向后取同一 probe layer representation h(u)，计算 S(u,v*)=cos(h(u),h*)。Toketive 不简单追求“越远越好”，而是把候选送入 detection band 或 reconstruction band。检测偏向 low-to-medium similarity，因为编辑后出现大量“不同 tokenization 给出不同响应”本身就是修改痕迹；重构偏向 medium-to-high similarity，因为还需要保留原事实语义。

Step 4：Phase 1 — modification detection

在预算内采样候选，统计非规范分词对 canonical response 的偏离/绕过行为，形成 bypass-based detection statistic，与阈值 τdet 比较。未编辑模型也会因非规范分词产生天然波动，所以作者用同一 detector 在 edited 与 corresponding unedited model 上构造正负样本，避免把 tokenization 本身的随机不稳定误当作 edit signal。

Step 5：Phase 2 — reconstruction

一旦判为 edited/unlearned，攻击进一步搜索 reconstruction band，丢掉仍输出 canonical post-edit answer 的样本，仅保留 bypass continuation。对这些响应抽取候选 object，再按频率 majority vote，返回 top-k。直觉是：真正旧事实会在多个不同但语义仍相近的“未补丁路径”上重复出现，而纯粹失真的 continuation 更分散。

5.7 核心公式与数学直觉

合法 tokenization： v₁ ⊕ v₂ ⊕ … ⊕ vₘ = x，且 vᵢ∈V。
Canonical v*=k*(x) 只是全集 TV(x) 中一个元素。

这条定义把攻击面说得很清楚：语义输入 x 不变，但模型真正接收的是 token sequence v。若安全性质只对 v* 成立，它不是字符串级不变量。

Representational entanglement： S(i,j)=cos(hᶫᵢ,hᶫⱼ)。

原指标用于衡量事实间表示纠缠，Toketive 把它重新解释成同一 prompt 的不同 tokenization 是否仍沿着相似事实表示流动的 routing signal。S 太高意味着“语义还在，但可能也还走 patch”；S 太低意味着“绕开 patch，但事实也可能没了”。因此最关键超参数不是单纯 α，而是 similarity band 边界 + α 的反馈调节。band 过高会降低 bypass；过低会增加乱码/错误事实，重构 precision 下滑。

Bypass Rate： (1/K) Σᵢ 1[o ∈ ŷuᵢ]，论文主实验 K=30。

这里 o 是 pre-update object。对研究者而言，这个 metric 比 canonical forget accuracy 更接近“残余知识能否被同义表示路径重新唤起”。但它仍是攻击成功率，不等价于严格 retraining-equivalence。

5.8 Toy Example

假设一个 LLM 原来知道 “Ipsos MORI’s headquarters are in → London”，用 MEMIT 把 canonical answer 改成 Oslo。标准 tokenizer 下查询得到 Oslo，看起来 edit 成功。攻击者保持字符完全不变，只把 token IDs 换成另一种合法切法，例如把 “headquarters” 拆成多个更小 subword。若某候选与 canonical hidden representation 的 cosine similarity≈0.66，它仍理解“总部在哪里”，但没有完全复现 canonical subject-token circuit。论文的真实示例中，这条路径重新生成 London。Toketive 会把这种响应视作 bypass；当多个不同 tokenization 都重复 London 时，London 在 top-k vote 中上升，于是攻击者在不知道 pre-edit model 的情况下重构旧答案。

5.9 Baseline Deep Comparison

Baseline怎么做 / 为什么合理本文 setting 的失败点Toketive 改了什么
Edit Distance用 token sequence 的 normalized Levenshtein distance 估计偏离程度；便宜、无需内部语义。表面 token 差异与“是否仍沿事实轨迹”相关性弱，AUC/校准明显落后。换成 hidden representation similarity；机制性改动。
Random Sampling随机生成合法非规范分词；如果 bypass 很普遍应能撞到。能发现一些泄漏，但 continuation 太分散，重构 top-5 只有 36.9% 平均值。用 similarity band 主动集中搜索。
FUMA-gradient用 post-edit model 的 loss gradient norm 当 edit detection score。严格 reference-free setting 下 FPR 很高，平均 F1 60.8%；而且无法给出旧答案内容。统一 detection + reconstruction。
DEED / RULI / U-LiRAclassifier/shadow-model 路线可以学习 edit membership signal。需要额外训练、数据分布或 shadow model，post-release auditor 未必有。零辅助训练。

Strongest baseline：若限定论文的同条件、无需原模型的直接实验，Edit Distance 是 detection 的 strongest baseline（F1 66.7%），而 reconstruction 的最好 baseline 仍明显落后 Toketive 至少 21.7 个百分点。

5.10 Experiment Setup Deep Dive

Models：Llama3-8B-Instruct、Llama3.1-8B-Instruct、OLMo2-13B-Instruct、Tulu3-8B、Tulu3.1-8B。Datasets：六个 factual editing / unlearning benchmark，包括 CounterFact、RippleEdits、Known-1000、MQuAKE、Real Authors、World Facts。Methods：AlphaEdit、RECT、MEMIT、PRUNE、CoME、Locate-then-Unlearn (LTU)。所有生成采用 greedy decoding，避免 sampling noise；计算在 NVIDIA H200 141GB 集群完成。

RQ1 — Predictability：同一句话的替代 tokenization 是否存在可预测的 convergence signal？比较 representational entanglement 与 edit distance，报告 AUC、rank-biserial correlation，并在 appendix 做 ECE/MCE calibration。

RQ2 — Tokenization Invariance：六种 edit/unlearning technique 的更新是否对不同合法 tokenization 保持一致？每个事实 K=30 个非规范 tokenization，统计旧 object 被恢复的 bypass rate。

RQ3 — Adversarial Efficacy：在不知道旧模型/旧答案时，能否先检测“这里被改过”，再恢复旧答案？Detection 报 TPR/FPR/Precision/F1；reconstruction 报 top-1/top-5 accuracy。

Defense/Ablation：Appendix 用 Llama3 上 1,000 个 representational entanglement>0.9 的 edit-control pairs 比较 standard MEMIT 与 adaptive MEMIT：每轮把 Toketive 找到的 bypass tokenization 纳入下一轮更新，同时测 bypass 与 ripple effect，从而直接检查 robustness-locality trade-off。

5.11 Metrics 教学式解释

  • AUC：把“会收敛到 canonical answer”与“不会收敛”排序分开的能力，0.5≈随机，越高越好；它不保证概率校准。
  • |rank-biserial correlation|：两类 score 分布的 effect size，越大说明 signal 的排序分离越强。
  • ECE/MCE：score 与真实 convergence probability 的平均/最坏校准误差，越低越好；用于回答“0.7 similarity 是否真的意味着更高收敛概率”。
  • Bypass Rate：替代 tokenization 中恢复 pre-update object 的比例，攻击视角越高越糟；unlearning robustness 视角越低越好。
  • Detection F1：precision 与 recall 的调和平均，适合 edited/unedited 判别；但若 class prior 改变，precision 会变。
  • Top-k reconstruction：旧答案是否进入频率最高的 k 个候选；top-5 高并不意味着攻击者一次就知道正确答案，所以要和 top-1 同看。

5.12 Results Deep Dive

  1. 平均 bypass 38.6%，范围 19%–57%。这直接否定“当前局部更新天然 tokenization-invariant”。但另一种解释是：攻击利用的是 open-weight raw token-ID 权限，对强制 canonicalization 的 hosted API 威胁较弱。
  2. AlphaEdit 是最稳健 technique，但仍有显著 bypass。说明 null-space preservation 能减轻某些干扰，却没有解决表示路径覆盖问题；strongest defense 仍不是 invariant defense。
  3. Detection F1 84.2% vs Edit Distance 66.7%。绝对 +17.5pp，相对提升约 26.2%；支持 hidden representation 是比表面 token 距离更好的 routing signal。
  4. FUMA-gradient 平均 F1 60.8%。其 near-perfect FPR 使 precision 接近 50%，说明“梯度大/小”在没有 pre-edit reference 时并不能稳定区分编辑痕迹。
  5. Reconstruction top-1 60.9%，top-5 74.5%。这比单纯证明“仍能泄漏”更强：攻击可以把残余轨迹聚合成具体旧 object。
  6. Random sampling top-1/top-5 仅 30.7%/36.9%。说明漏洞不是“随便切词就行”，Toketive 的 band routing 才把攻击从偶然 bypass 变成可用 reconstruction。
  7. Representation signal 在多数组合显著优于 edit distance。例如 appendix ECE 中 Llama3/CounterFact 为 0.102 vs 0.283，Llama3.1/MQuAKE 0.043 vs 0.266；不仅排序更好，概率意义也更靠谱。
  8. Adaptive editing 能压低 bypass，却扩大 ripple effect。这是本文最值得 unlearning 研究借鉴的 failure result：为了覆盖更多表示路径，更新范围会侵入邻近知识，robustness 与 locality 发生结构性冲突。
Strongest result：reference-free、无 shadow model 的条件下同时做到 84.2% edit detection F1 与 74.5% top-5 pre-edit reconstruction。
Weakest / failure side：攻击依赖 open-weight access（raw token IDs + hidden activations）；论文并没有证明所有类型 unlearning 都会被绕过，且明确把 fine-tuning-based 方法排除在主威胁模型外。

5.14 Ablation / Mechanistic Analysis

最重要的 ablation 是把 representational entanglement 换成 edit distance 或 random sampling。前者明显降低 detection/reconstruction，说明“语义轨迹相似度”确实承担搜索路由功能，而不是仅靠增加查询数。Adaptive MEMIT 则是反向验证：把已发现 bypass tokenization 纳入编辑后，漏洞减少但邻近事实 ripple 增加，支持“要覆盖表示等价类就会牺牲 locality”的机制假设。不过这仍不是严格因果证明：hidden cosine similarity 可能只是更深层路径重合的 proxy。

5.15 Claim vs Evidence

Tokenization 是 editing/unlearning 的安全攻击面。六 technique、五模型、六数据集上大量合法非规范分词恢复旧 object。并未覆盖 full retraining、所有 fine-tuning unlearning、multimodal tokenizer 或 closed API。

5.16 Contribution

C1 [New Attack Surface / Empirical Finding]：把 alternative tokenization 提升为 post-release knowledge-control attack surface，是真创新点。
C2 [New Attack]：Toketive 用 representation-guided adaptive search 统一 detection + reconstruction，机制组合有新意。
C3 [New Metric/Protocol]：把 tokenization invariance / bypass rate 引入 editing-unlearning robustness evaluation，迁移价值很高。
C4 [Empirical Finding]：adaptive patching 暴露 robustness-locality trade-off。这里不是新 optimizer，而是重要实验结论。

5.17 Limitation & Failure Modes

Authors' scope：主实验针对 inexact/localized editing-unlearning，排除 fine-tuning-based 方法；攻击假设 open-weight、可直接提供 token IDs 并读 hidden activations。Additional：① 仍以 factual triple / short-answer recovery 为主，对长文本、procedural knowledge、reasoning-derived knowledge未知；② raw token IDs 在实际 serving stack 可能被 canonicalization 层阻断；③ reconstruction 命中旧 object 不等价于证明训练影响仍与原模型完全一致；④ 多模态 MLLM 中 image tokenizer / visual token perturbation 可能更复杂；⑤ adaptive attack budget、wall-clock 与 GPU cost 需要与其他 recovery attacks 做统一成本曲线；⑥ 没有直接做 relearning/reacquisition，因而无法说明 tokenization bypass 与“可快速再学回”是否同源。

5.18 Reproduction View

最小复现不必先跑六数据集。建议：Llama3-8B + CounterFact + MEMIT，抽 100–500 个成功 edit 的事实；保存 canonical hidden state；实现“合法 BPE alternative segmentation + round-trip validation”；每事实生成 30 个候选；比较 random / edit-distance / hidden-cosine 三种 sampler；先复现 bypass rate，再做 top-k reconstruction。最容易踩坑的是：候选必须解码为完全相同字符串、probe layer/position 要与论文一致、generation 必须 greedy、先过滤 edit 本身失败的样本，否则 bypass 会被夸大。最敏感超参数是 α、detection/reconstruction similarity bands、probe layer 与 τdet。

5.19 Research Value

Baseline Potential：极高。任何声称“robust unlearning”的开放权重方法都应该把 Toketive 加入攻击集。
Migration Potential：极高。可自然迁移到 MLLM 的 text tokenizer、visual tokenization、prompt paraphrase/format equivalence。
Attack Potential：极高。本身就是 recovery attack，还可与 quantization/relearning/probe 串联。
Evaluation Potential：极高。可把 tokenization-invariant forgetting 定义为新 robustness 维度。
Benchmark Potential：高。现有 forget set 可扩增为 representation-equivalence orbit。
New Paper Potential：高。尤其适合“多模态 unlearning 的 representation-path robustness”与“tokenization bypass × recovery/relearning”方向。

5.21 Attack / Verification Lens

它天然既是 attack 又是 verifier。Black-box 版本可去掉 hidden activation，改用输出一致性/entropy/semantic cluster 做 band proxy；white-box 版本则直接成为 unlearning audit。还可以定义 Representation-Orbit Forgetting Score：不是只问 canonical x 是否忘记，而是对同一语义的合法表示集合 T(x) 取 worst-case 或 CVaR forgetting。进一步把 top-k recovery 与短程 relearning 串起来，就能区分“表面拒答”“路径局部阻断”“真正低残余”的 checkpoint。

5.22 与 Paper 2 的关系

两篇论文表面分别是 unlearning 与 agent cost security，但共同攻击的是一个系统边界假设：Paper 1 说“canonical tokenizer 并不是语义边界”，Paper 2 说“tool admission 并不是经济安全边界”。前者要求在进入模型前对表示等价类做鲁棒性验证，后者要求在再次进入模型前治理 retained state。可以组合成更一般的原则：安全属性必须绑定到 host-controlled transition boundary，而不是绑定到一次成功的模型输出。

5.23 如果只让我记住这篇论文

  1. 同一字符串可以有多个合法 BPE tokenization，开放权重用户可以直接控制 token IDs。
  2. 局部 editing/unlearning 往往只修 canonical computational trajectory。
  3. 非规范 tokenization 可能绕过 patch，同时仍保留原事实语义。
  4. Toketive 用 hidden-state cosine similarity 寻找“既不像 canonical 太多、又没离语义太远”的候选。
  5. 六种方法平均 38.6% alternative tokenizations 能恢复旧答案。
  6. 它在无需 pre-edit model/shadow model 的条件下做到 84.2% detection F1。
  7. pre-edit response reconstruction 达到 60.9% top-1、74.5% top-5。
  8. 随机切词远不如 representation-guided search，说明机制不是纯 brute force。
  9. 把 bypass tokenization 重新纳入编辑能增强 robustness，却扩大邻近知识 ripple，暴露 robustness-locality trade-off。
  10. 对 unlearning 最重要的启示是：以后不能只测 canonical prompt；要测整个“语义等价表示轨道”的 worst-case forgetting。

5. Paper 2 — Persistent Billable State: Denial-of-Wallet Attacks and Defenses in Tool-Calling LLM Agents

Agent Security / Tool Use / MCP / Resource Governance

Authors: Jinqian Zhang, Haojun Xia, Shujiang Wu, Jingkun Yue, Xia Zhang, Zhangpei Cheng, Bibo Tu
Affiliation: Institute of Information Engineering, CAS; UCAS School of Cyber Security; Beihang University; State Key Laboratory of Networking and Switching Technology / BUPT
Date / Status: arXiv submission 2026-09-23; current indexed version updated 2026-09-25; cs.CR / cs.AI preprint
Paper: arXiv · PDF

5.2 一句话定位

它把 Agent 的“会话历史”重新定义为一种会被反复计费的安全资产：恶意 tool return 一旦进入 retained history，就能在后续每次 provider call 中被重复 re-ingest，从而形成不需要偷 API key 的 Denial-of-Wallet。

5.3 人话版

Tool-calling agent 常把工具返回值塞进对话历史，下一轮连同历史再次发送给模型。正常情况下这是“记住上下文”；攻击情况下，它等于让攻击者的一次 tool return 变成可反复计费的 persistent state。论文把这个现象命名为 persistent billable state，并指出真正的控制点不是“要不要调用这个工具”，而是 tool return 回来以后、下一次送进模型以前的 pre-reingestion boundary。DOW-BENCH 在六个模型家族、243 次核心执行中测到单 session 累计 input 最极端达到 first-call input 的 14,293×；保留 raw history 相比 drop/compress 会把平均有效成本抬高 21.2–35.9%。但简单删除历史又会毁掉任务连续性。因此作者提出 D1–D4 四层 host-side kernel：限制 token mass、监控增长、限制递归机会、设置成本熔断，并用 progress-authorized budget 替代死板固定上限，在 24 个 Mistral Small 4 workflow 上把成功率从 54.2% 提到 91.7%。

5.4 Background & Research Gap

传统 Agent 安全经常把边界放在 tool admission：MCP server 是否可信、tool schema 是否允许、用户是否授权调用。一旦 tool 被允许，return 往往被当作普通上下文。可计费 API 改变了这个威胁模型：模型服务商按每轮 input/output token 收费，runtime 又会在每轮重建 messages。于是一个 800-token 的恶意 return 不是只花一次钱，它可能在后续 10 个 turn 中被重复携带，并诱导 agent 继续调用工具，形成“状态 × 递归深度 × 计费”的乘法放大。

已有工作研究 output amplification、overthinking 或 cyclic MCP，但本文的 gap 是 post-admission lifecycle：攻击者不需要 victim credential、不需要 runtime privilege，甚至不必让模型输出超长文本；只要被接纳的 tool 能返回会被 host 保留的内容，就可以把 untrusted bytes 变成 recurring victim-billed state。这个视角非常适合真实 Agent 系统，因为责任落在 host runtime，而不是要求模型供应商提供私有 hook。

5.5 Core Insight

最关键的 observation 是 continuity 与 exposure 被同一份 retained history 耦合。历史越完整，Agent 越容易完成多步任务；但攻击 payload 也越能跨 turn 反复进入 provider-metered input。作者通过 Full / Drop / Compress 干预把这个机制拆开：Drop 成本低但 history-dependent task 成功率只 2/12；Compress 在两 provider 上仍能做到 10/12 与 11/12，同时成本低于 Full。这说明问题不是“Agent 不该记忆”，而是“不该原样保留所有 cost-bearing mass”。这属于系统机制 + 实证因果干预，比单纯比较不同模型谁更贵更有说服力。

5.6 Method Deep Dive

Admitted remote tool → schema-valid malicious return → host retains return → next prompt reconstruction → provider meters retained bytes again → continuation cue induces more tool turns → recursive cost amplification → pre-reingestion D1–D4 governance → bounded continuation

Step 1：定义 Persistent Billable State Boundary

作者区分“工具是否能被调用”与“工具返回内容是否再次进入可计费 context”。后者才是 host 可确定性控制的 boundary。攻击端只需让 return 合法、看似与任务相关，并附带 continuation cue。

Step 2：六类攻击向量 V0–V5

V0 Direct 用较大内容块直接制造 retained mass；V1 Polymorphic 在 turn 间改变表示和长度；V2 Cross-Tool 利用跨工具传播；V3 Stealth 前期小、 incubation 后升级；V4 Weaponize 诱导 verbose model output；V5 Adaptive 根据 agent 是否继续动态调整 payload。V0/V2 的典型 block 为 400–1000 tokens，所有 session 从 2–10 token trigger 开始。

Step 3：DOW-BENCH 记录真实闭环

每个 session 都是独立 agent/model-API execution，逐 turn 记录 input tokens、output tokens、tool calls、termination。核心六模型家族：GPT-4o、GPT-4o-mini、Mistral-Large、Llama-3.3-70B、Nemotron-120B、Qwen-3-235B；243 core executions，11 个 serialized deployments。

Step 4：机制归因：Full / Drop / Compress

同一批 held-out tasks 分别让 runtime 原样保留历史、删除历史、确定性压缩历史。若 Full 比 Drop 贵，而 Compress 接近 Full 的任务成功率却成本更低，就能把成本增加归因到 raw retained mass，而不是模型“天生更爱多轮”。

Step 5：Host-side D1–D4 Kernel

D1 给 per-turn/per-session prompt mass 硬上限；D2 监控相邻 turn prompt 增量；D3 限制 consecutive tool turns、calls/turn、total calls；D4 按累计价格做 circuit breaker。全部在下一次 provider call 前执行。

Step 6：Progress-authorized budget

固定 $0.10 cap 容易把合法长任务也杀掉，所以作者让 host oracle 在确认 milestone 后把预算释放到 $0.13/$0.16。安全逻辑从“你花够了就停”升级为“只有可验证进展才能获得更多经济权限”。

5.7 核心公式与数学直觉

Cost Amplification Factor (CAF)： CAF = (Σᵢ pᵢ) / p₁，其中 pᵢ 是第 i 次 provider call 的 input tokens，p₁ 是完整 first-call input。

CAF 不看攻击者自己发送多少，而看受害者侧累计被 provider 处理多少 input，相当于把“递归 re-ingestion”变成可比较的无量纲放大率。它与以 output token 为主的传统 amplification metric 不同。

Effective priced exposure： Cₜ = Σᵢ (rᵢⁱⁿ·pᵢ + rᵢᵒᵘᵗ·oᵢ)，并在 cache-aware 分析中分别处理 cached / uncached input rate。

这一步很重要，因为 token 放大不等于美元放大：不同 provider、cache discount、input/output 价格不同。D4 直接约束 Cₜ，因此比只看 token 更贴近经济攻击。

D2 Growth Gate： trigger if (Δpₜ > τabs) OR (Δpₜ/p₁ > θr AND Δpₜ > τmin)。

绝对阈值抓“大包突然膨胀”，相对阈值抓“小 seed 后异常增长”，τmin 防止极小 p₁ 造成比例虚高。moderate preset 使用 τabs=10K、θr=3、τmin=2K。最关键的 trade-off 是阈值太紧会误杀长任务，太松会允许更多 leakage。

5.8 Toy Example

一个 coding agent 调用“search dependency docs”工具。工具第一次合法返回 900 tokens 的“诊断文档”，末尾说“为了确认版本，请继续查询下一页”。Host 把这 900 tokens 放进 history。第二轮模型输入不仅有原任务，还有这 900 tokens；工具再回 900 tokens 并要求继续。第三轮，前两次返回都在 messages 里，于是 input mass 继续增长。攻击者从未拿到 API key，但受害者每轮都为历史重新计费。D1 可以限制总 prompt mass；D2 会看到 Δp 激增；D3 限制连续 tool recursion；D4 在累计美元超过预算时阻断下一轮。若任务确实需要继续，host 只有在验证“已经找到 package version”等 milestone 后才追加预算。

5.11 Metrics 教学式解释

  • CAF：累计 input / first-call input，越高表示同一初始任务被重复处理得越夸张；不直接等于美元。
  • Effective Session Cost：按 provider listed rates + cache 分类折算美元，攻击视角越高越糟。
  • ITT task success：按所有计划 workflow 为分母，不把 tool failure 或 defense stop 悄悄删掉；比 available-case 更保守。
  • Pre-completion interruption：防御在任务真正完成前是否把合法流程切断，是 utility loss 的直接指标。
  • False-positive scenario rate：benign workload 被 D2 等 gate 错拦的比例；安全 kernel 必须与 containment 同时报。
  • Spearman ρ：mean turns 与 mean CAF 的单调相关；ρ=0.79 说明递归存活与放大高度关联，但本身不是因果，所以作者又做 truncation/matched-prefix。

5.12 Results Deep Dive

  1. 最大 CAF 14,293×。这是 strongest headline：一次小 trigger 可在闭环里变成四个数量级累计 input exposure。极端值不应被误读为平均风险，但足以证明边界存在。
  2. Priced attack session 最高 $3.404；69 个 priced attack 中 51 个超过 $0.10。而 priced benign 最大 $0.025，说明简单 $0.10 breaker 在这批数据上有明显区分力。
  3. Full history 比 Drop/Compress 贵 21.2–35.9%。Mistral persistent-return：Full 比 Drop +35.9%、比 Compress +30.0%；Groq 对应 +22.3%、+21.2%。这是 raw retention 的机制证据。
  4. Drop 只 2/12 成功，而 Full/Compress 至少 10/12。说明“删历史”不是可接受的安全方案；compression 是关键 utility-preserving baseline。
  5. turn survival 与 CAF：Spearman ρ=0.79，95% CI [0.56,0.89]。且把 malicious trace offline 截到 2–4 turns 后，高/低 amplification group 的 CAF ratio 从 4.06× 降到约 1.49–1.51×，强化了递归机会的解释。
  6. 123/123 recurring-attack replay 被 D1–D4 containment。这是防御覆盖的 strongest result，但仍是 frozen replay，不代表未知 adaptive attacker 永远无法绕过。
  7. Progress-authorized D4：22/24 vs fixed 13/24。成功率 91.7% vs 54.2%，pre-completion stop 0 vs 9；McNemar p=0.0039。代价是 mean cost $0.113 vs $0.099，说明它明确选择“为已验证进展多花一点钱”。
  8. 生态扫描只有 71/3830=1.9% repo 有任一 safeguard proxy，且 0 个覆盖四类。这使论文从实验攻击升级到 deployment gap，但静态 code proxy 不能等价于真实生产防护。
Strongest result：progress-authorized budget 把合法任务成功率从 54.2% 拉到 91.7%，同时不放弃 host-side hard stop。
Weakest / failure side：固定阈值与 replay corpus 仍可能被更慢、更语义化的 adaptive attacker 绕；成本数字也依赖 provider pricing 与 runtime history policy。

5.14 Ablation / Mechanistic Analysis

Full/Drop/Compress 是最强机制 ablation：Drop 切断 retained-state channel，成本下降但 utility 崩；Compress 保留结构化 task state，说明攻击的关键载体是 raw cost-bearing mass，而非“任何记忆”。D2 的 denominator-floor sensitivity 把 benign false positives 从 2/1050 降到 0/1050，但 mean attack leakage 从 4.13% 增至 5.05%，清楚展示 detector threshold 的安全-可用性 trade-off。作者还单独关闭 D1–D3 只测试 D4 policy transfer，使 22/24 vs 13/24 的提升可以归因于授权策略而不是其他 gate。

5.17 Limitation & Failure Modes

Authors/setting limitation：模型与 provider deployment 有限，价格会变化；部分向量 capability-dependent；静态 repo scan 只能看 code-visible proxy。Additional：① attacker 可设计低增长、低成本但超长时间的 slow-burn；② semantic compression 本身若由 LLM 完成可能重新引入成本/注入风险，论文强调 deterministic transformation 但真实系统实现需谨慎；③ multi-agent 中一个 agent 的 summary 可能成为另一个 agent 的 retained state，跨 agent accounting 更复杂；④ session restart、checkpoint、memory DB、scheduled task 会把“turn persistence”升级成“temporal persistence”；⑤ cost breaker 防经济损失，不保证 confidentiality/integrity；⑥ 对本地模型无 provider bill，但 GPU-time/energy 仍可被同一机制耗尽。

5.18 Reproduction View

最小复现可以只做一个 OpenAI-compatible agent loop + 一个恶意 mock tool：记录每轮 messages 序列化后的 token 数，构造 V0 direct 800-token return + continuation cue，跑 Full/Drop/Compress 三策略；先验证 CAF 与 cost curve，再加 D1/D2。第二阶段实现 D3/D4 与 progress milestone。最容易踩坑：必须使用 provider-reported usage 做主 accounting；cache token 单独计价；每 session 独立；不能把 tool return 长度当成 provider input；防御必须在“下一次 send 之前”执行，否则已经产生账单。若要复现论文 strongest utility claim，再固定 24 workflow 并用 host oracle 做 typed milestone verification。

5.19 Research Value

Baseline Potential：高。所有 MCP/agent runtime 安全工作都应加入 CAF + progress-aware budget。
Migration Potential：极高。尤其适合 persistent memory、scheduled agents、multi-agent handoff。
Attack Potential：高。可扩展到跨 agent、跨 session、memory poisoning + cost amplification。
Evaluation Potential：高。把“安全”从成功/失败扩展到 resource exposure、interruption、utility。
Benchmark Potential：高。DOW-BENCH 可与 prompt injection / persistent worm benchmark 合并。
New Paper Potential：高。最有潜力的是“agent memory lifecycle security”与“verifiable state promotion”。

5.20 Migration Analysis

Direction A — Multi-Agent Handoff Budget Propagation
Original Problem → 单 agent retained tool return 反复计费。 Transferable Mechanism → untrusted state 跨 boundary 后获得持续资源消耗能力。
New Research Question → 多 agent handoff / shared memory 是否把一次 payload 复制成多个 agent 的 billable state？
Method Modification → 给每个 state chunk 加 provenance、taint、origin-cost 与 downstream budget；handoff 时做 attenuation，不允许 budget 随复制增长。
Minimum Experiment → 3-agent planner→coder→reviewer；注入 0.5K/2K/8K tool return；比较 raw handoff、summary、taint-aware compression、budget attenuation；测 1/3/5 hop。
Model → GPT-4o-mini / Qwen3 / Mistral。 Dataset → SWE-style 20–50 tasks + synthetic tool workflows。 Baseline → flat shared transcript、fixed cap、per-agent cap。 Metric → global CAF、cost/hop、task success、attack propagation rate、false stop。
Expected Contribution → 首个 multi-agent economic capability accounting。 Risk → provider caching 影响绝对成本。 Collision Risk → 中等，与 persistent agent worm / collusion 相邻，但经济 propagation 目标不同。
Direction B — Unlearning Agent Memory with Pre-Reingestion Verification
Original Problem → Agent 删除 memory 后，旧内容可能仍在 summary/checkpoint/handoff 中被重新载入。 Transferable Mechanism → “删除动作”与“下一次 re-ingestion”之间存在可治理边界。
New Research Question → continual deletion 能否定义为：任何 future context reconstruction 都不得重新携带 forget-derived state？
Method Modification → 对 memory chunk 建 provenance graph；forget request 标记 taint；每次 context assembly 前做 deterministic exclusion + semantic residual probe；若 summary 含 forget-derived representation 则重新压缩/阻断。
Minimum Experiment → 构造 100 个 agent memory facts，20 个 forget；经过 10/50/100 turn summary、handoff、restart 后查询；比较 naive delete、vector-store delete、summary rebuild、provenance-gated reingestion。
Model → Llama/Qwen agent。 Dataset → synthetic personal-memory + long-horizon tool tasks。 Baseline → delete-only、RAG tombstone、full reset。 Metric → forget leakage、utility、reacquisition rate、context cost、false deletion。
Expected Contribution → 把 machine unlearning 从 model weights 扩展到 agent state lifecycle。 Risk → “语义派生信息” provenance 难定义。 Collision Risk → 低到中。

5.21 Attack / Verification Lens

可把 CAF 当作 black-box runtime fingerprint：同一恶意 tool 在不同 harness 上的 amplification profile 能暴露 history policy、turn cap 与 cache behavior。对 verification，可定义“pre-reingestion compliance test”：每个 untrusted return 是否经过 size/growth/opportunity/cost gate；对 recovery/reacquisition，可把 persistent memory 中被删除信息重新进入 context 的次数看作 state-level reacquisition。更进一步，D4 的“只有验证进展才释放预算”可以迁移成 agent capability control：只有经过 verifier 的状态变化才能增加工具权限、上下文预算或 memory promotion 权限。

5.22 与 Paper 1 的关系

Paper 1 证明 canonical representation 不是知识删除的安全边界；Paper 2 证明 tool admission 不是 agent 资源安全的边界。共同趋势是：一次成功的局部控制不能代表后续生命周期安全。前者需要 representation-orbit evaluation，后者需要 state-lifecycle governance。组合后可形成“untrusted / forgotten information 在进入模型前的统一 pre-ingestion kernel”：先做 provenance 与 deletion check，再做 representation normalization / adversarial variant audit，最后做 token/cost/capability budget。

5.23 如果只让我记住这篇论文

  1. Agent 的历史不是免费记忆，而是会在后续 provider call 中反复计费的 persistent billable state。
  2. 攻击者不需要 API key，只需要一个已经被允许调用、能返回内容的恶意/被攻陷工具。
  3. 真正的安全边界不是 tool admission，而是下一次 provider call 前的 pre-reingestion。
  4. DOW-BENCH 在核心 243 executions 中观察到最大 14,293× CAF。
  5. Full raw history 会比 Drop/Compress 多 21.2–35.9% 平均有效成本。
  6. 但 Drop 让 history-dependent task 只剩 2/12 成功，所以“删历史”不是答案。
  7. D1–D4 分别约束 prompt mass、growth、recursive opportunity 与 cumulative spend。
  8. 123/123 recurring-attack replay 被完整 kernel containment。
  9. Progress-authorized D4 把 24 个 workflow 成功率从 54.2% 提到 91.7%，说明预算应与可验证进展绑定。
  10. 对 Agent 研究最重要的迁移是：memory、handoff、summary、scheduled state 都应该被当作带 provenance 与 capability 的安全对象。

7. Cross-Paper Synthesis

今天两篇共同指向一个非常明确的趋势：LLM 系统的失败越来越发生在“模型调用之间的边界”，而不是单次模型输出本身。 Toketive 攻击 tokenizer→model 的表示边界；Persistent Billable State 攻击 tool-return→next-model-call 的状态边界。两者都利用了开发者默认视为“实现细节”的层：token segmentation 与 history reconstruction。

8. Combined Research Opportunities

Opportunity 1 — Stateful Multimodal Unlearning Verification

把 forget target 从“一个 canonical QA pair”提升为“一个在多轮 Agent 中会经历 tokenization、image transform、summary、memory promotion、handoff 的信息对象”。每个 transition 都可能重新暴露残余知识。可定义 Forget Provenance Graph：节点是原始样本、文本 tokenization、视觉变体、summary、memory chunk、handoff；边表示派生。验证目标不再是单点 forget accuracy，而是所有 future re-ingestion path 的 worst-case leakage。

Opportunity 2 — Progress-Authorized Relearning

把 Paper 2 的 progress-authorized budget 迁移到 unlearning attack：攻击者只有在 probe 显示残余知识增加时才获得下一批 query/relearning step budget。这样能构造更真实的 adaptive recovery benchmark，并比较不同 checkpoint 的“单位攻击预算恢复速度”。这比固定 20-step relearning 更接近 adversarial verification。

Opportunity 3 — Representation-Normalizing Host Kernel

Agent host 在 pre-ingestion 时不只做 token/cost gate，还对高风险字符串强制 canonicalization，并对 memory provenance 做 forget-taint exclusion。它无法保护完全开放的本地权重，但对托管 agent runtime 可以同时缓解 Toketive-style representation variance 与 persistent-state amplification。

9. Collision / Overlap

Strongest Collision：“局部成功 ≠ 生命周期安全”。Toketive 与 Persistent Billable State 都证明：在一个局部 checkpoint 上看似安全（canonical answer 已改、tool call 已授权）并不能保证后续 alternate path / retained state 不重新激活风险。

与前一日已精读的 Codetta / trace-tampering 方向也存在邻近碰撞：都在挑战“审计可见 transcript 足够”的假设。不过今天两篇更偏输入表示与状态生命周期，没有重复昨天的 covert communication / self-trace manipulation 机制，因此保留为新的 Deep Dive。

10. Reading / Reproduction Priority

  1. 第一优先：Toketive。与你的 machine unlearning / robustness / recovery 研究直接相连；先复现 Llama3 + CounterFact + MEMIT 的 100–500 facts，最快能判断是否值得迁移到 MLLMU。
  2. 第二优先：DOW-BENCH 的 Full/Drop/Compress。不用先复刻六 provider；单 agent + mock tool 即可验证 persistent billable state 的核心机制。
  3. 第三优先：联合实验。把 “representation-orbit bypass score” 与 relearning/quantization/probe robustness 做 correlation，优先验证它是否提供现有 metric 没有的新排序信号。
