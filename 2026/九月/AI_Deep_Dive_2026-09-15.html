4. Paper 1 Full Deep Dive

Published Unlearning Numbers Move Per Checkpoint, and Not Because the Removed Data Survives: An Audit of 263 Released Batch-Normalized Checkpoints

Machine UnlearningVerificationBACKFILL

基本信息：Junlong Shen, Xingyu Li；University of Alberta；arXiv:2609.11490v1；2026-09-10；arXiv preprint。全文 38 页、4 figures、26 tables。
Paper：Abstract · HTML · PDF。论文称 supplementary code archive 含预注册文件；本次未确认独立公开 GitHub，因此不虚构 Code URL。

5.2 一句话定位

它审计的不是一种新 unlearning algorithm，而是一个更基础的假设：unlearning verdict 是否会被“权重之外、但推理时真实存在”的 deployed state 改写。

5.3 人话版

带 BatchNorm 的视觉模型不只有训练权重 θ，还保存 running mean/variance φ。作者把 θ 保持 bit-identical，仅用 retained data 重建 φ，再重算论文原本发布的 forget/retain/test 指标。221 个可重复审计 checkpoint 中，47 个 forget accuracy、39 个 retain accuracy、40 个 test accuracy 的移动超过预先规定的 ±1.2 percentage-point 容忍带；12 个 published pass/fail verdict 会跨阈值，其中 4 个超过测得的 recalibration budget，2 个在所有 replicate 上都成立。但把 removed records 换进固定 fitting pool 时 pooled shift 只有 +0.015 pp，几乎没有证据表明是“被删数据藏在 BN state”。更符合数据的是 shipped normalization state stale。论文因此把 unlearning verification 从“看权重/输出”推进到“定义完整 deployed state + fitting convention”。

5.4 Background & Research Gap

Approximate unlearning 通常以 omission retraining 为理想参照：删除 forget set 后从头训练，再看 unlearned checkpoint 是否足够接近 reference。旧评估重点讨论 forget accuracy、retain utility、membership inference、seed variance、recovery attack，却往往把模型写成 f_θ。对 ResNet 这并不完整，因为 BatchNorm inference 使用 running statistics φ。它们不是普通 gradient-updated weights，却能改变激活与最终 accuracy。

论文给出的直观案例是 MU-Bench 的 2% removal bad-teaching checkpoint：as-shipped 时 |d_f-d_t|=0.0414，小于 0.05 criterion，判为通过；保持 θ 不变、retain-only refit φ 后变成 0.0573，同一个权重对象跨到不通过。Gap 因而不是“有没有更强 unlearning loss”，而是审计对象定义错了一层。

5.5 Core Insight

Observation 1：method/family 平均稳定不代表每个 artifact 稳定；同一 family 内存在明显 checkpoint heterogeneity。Observation 2：removed-data provenance 对 φ 的直接影响不足以解释大幅 metric movement；20 个对象的 removed-vs-retain fitting contrast pooled 仅 +0.015 pp，0 个超过 0.5 pp。Observation 3：shipped state 到 retain-only refit 的距离却显著超过 omission-reference null。故最受支持的解释是 state staleness，不是“BN 重新记住 forget set”。这是有 controls 的经验/机制性发现，但不是对所有架构的理论定理。

5.6 Method Deep Dive

Released checkpoint (θ,φ) → anchor published cells → freeze θ byte-identically → sample retained fitting pool → exact rebuild φ̂ → recompute m(θ,φ̂) → Δ=m(θ,φ̂)-m(θ,φ) → repeated refits / TOST / sign tests → verdict crossing → provenance & alternative-state controls
  1. Anchoring：先复现 release 自己的数字；263 artifacts 成功 anchor。不能复现的对象不进入主结论，避免 loading/eval mismatch 冒充科学结果。
  2. Freeze θ：任何 trainable tensor 不变，把干预变量限制为 normalization state。
  3. Rebuild φ̂：用 retained subset + producer 的 training transform 前向一次，计算 exact statistics，不使用 EMA；这样 φ̂ 由 index set 与 θ 决定。
  4. Re-evaluate：完全沿用 release metric，计算 displacement Δ。
  5. Per-checkpoint repeats：221 checkpoints 各做 10 次 re-keyed refit；只有 10/10 都越过 margin 才算 displaced。边界 null 下 exact sign-test 最小 p=(1/2)^10≈0.00098，再做 BY multiple-testing control。
  6. Identification：固定 fitting pool，仅把等量 retained records 换成 removed records，测试 provenance 是否驱动 shift。
  7. Boundary control：再检查 static 8-bit activation quantization scales 与 LayerNorm/Swin；该第二 fitted-state channel 返回 0 displaced，限制过度泛化。

5.7 核心公式与数学直觉

真实审计对象：m(θ, φ) 重建：φ̂ = Refit(R; θ) 位移：Δ = m(θ, φ̂) − m(θ, φ) Equivalence question: CI(Δ) 是否完整落在 [−ε,+ε]？

θ 是 trainable tensors，φ 是 inference-time BN statistics，R 是 retained fitting set，m 是 release 自己的 forget/retain/test readout。这里没有新训练 objective，核心是 counterfactual state intervention。Strongest baseline 是 as-shipped evaluation，因为它正是 field 默认的 checkpoint 读法。ε=±1.2 pp 与 detection floor 很关键：margin 太宽会把实质 state sensitivity 判稳定，太窄则把 nuisance noise 当问题。作者使用预先设定 margin，而不是看完结果再挑阈值。

5.8 Toy Example

假设 unlearned ResNet 权重 hash 完全固定，原 φ 下 forget=4%、test=74%，criterion 通过。用 retained images 重建 φ̂ 后 forget=7.5%、test=76.2%。这不能自动解释成“知识恢复”，因为 θ 未变；它只证明 readout 对 state convention 敏感。再把 calibration pool 中少量 retained images 换成 forget images，如果结果仍约 7.5%，就进一步排除“forget samples 直接藏在 φ”这一解释。最后若 LayerNorm 模型上同样操作无效，则 claim 应限定为具有相应 fitted state 的架构。

5.10 Experiment Setup Deep Dive

主 population：MU-Bench CIFAR-100 ResNet-50 release，180 checkpoints 中 72 满足其自身 admission criterion，覆盖 Bad Teaching、NegGrad、Random Label 等 families、3 procedure variants、5 removal ratios、5 seeds。第二 population：Unlearning Comparator 的 CIFAR-10 ResNet-18 class-deletion checkpoints，包含 omission reference、SSD 等 arms。总计 263 anchored，221 进入 replicate census。

RQ1：θ 不变时 retain-only rebuild 能否移动 published metric？ RQ2：movement 是 family-level 还是 artifact-level？ RQ3：removed records 是否直接驱动？ RQ4：是否改变 pass/fail？ RQ5：另一 fitted deployed state 是否也有同现象？

5.11 Metrics 教学式解释

Refit displacement：同 checkpoint 重建 state 前后 metric 差，越大表示 state sensitivity 越强，不等价于 privacy leakage。TOST equivalence：不是“没显著差异”，而是置信区间完整落在 ±ε 才能支持足够接近零；跨界应叫 unresolved。Detection floor：在真实 cluster structure 上植入 true-zero，估计实验设计能分辨的最小幅度，防止把 low-power null 当稳定。Verdict crossing：最直观，但依赖 criterion geometry，所以必须结合 recalibration budget。

5.12 Results Deep Dive

  1. 47/221 forget displaced：约五分之一，不是极少数 outlier。
  2. 39 retain、40 test displaced：说明 channel 影响 utility/readout，而非只针对 forgetting。
  3. 12 verdict crossings：把“数字移动”提升到“published decision 改变”；但只有 4 超 measured budget、2 在所有 replicate 成立，作者没有夸大。
  4. removed-pool +0.015 pp：0 个超过 0.5 pp，是最强 mechanistic negative control。
  5. 20/20 state drift：shipped φ 距 retain-only refit 超过 reference null band，支持 stale-state account。
  6. matched weight movement residual +33.80 pp [21.28,46.32]：不能简单归因“权重动得越多，BN 越 stale”。
  7. 0/118 quantization-state displaced：第二 fitted-state channel 不复现，是最重要 generalization boundary。
  8. near-threshold population：45 中 20 displaced，却 0 verdict cross，最近差 0.204 pp；crossing 同时依赖 sensitivity 与 threshold geometry。

Strongest result：bit-identical θ + large artifact displacement + provenance-null control 的组合。
Weakest/failure：quantization 0/118、near-threshold 0 crossing，说明不能泛化成“所有 non-weight state 都会破坏 unlearning”。

5.14 Ablation / Mechanistic Analysis

这篇的“ablation”是 identification controls：freeze θ 去掉 weight-change explanation；removed↔retain swap 去掉 provenance explanation；normalization-free/LayerNorm 检查 channel 依赖；quantization-scale 检查跨 state generalization；order/batch-size/transform controls 检查实现。它支持“stale fitted state can alter audit readout”，但没有证明具体 unlearning 方法为何产生 staleness，也没有证明 state movement 与真实 privacy leakage 因果一致。

5.16 Contribution

C1 New Metric/Protocol：weight-preserving deployed-state rebuild audit。C2 New Empirical Finding：artifact instability 与 family average 解耦。C3 New Mechanistic Finding：staleness 比 removed provenance 更符合数据。C4 Engineering/Scientific Practice：anchoring、pre-registration、detection floor、negative controls；单个统计组件不是新发明，但组合进 unlearning audit 很有价值。

5.17 Limitation & Failure Modes

Authors' limitation：主要针对 batch-normalized vision models；不是所有 release 都能 anchor；crossing 依赖 criterion；第二 deployed-state channel 为 null。Additional：尚未验证 LLM/MLLM LoRA；LayerNorm 没有同类 running state；accuracy movement 不等于 privacy recovery；没有 adaptive attacker 搜索最危险 state；production 还可能有 quantization calibration、adapter routing、cache、summary 等状态。

5.18 Reproduction View

最小复现：一个带 BN 的 unlearned ResNet + retain/forget/test split。anchor.py 先复现 published cells；rebuild_bn.py freeze weights、按 retained training transform 前向、重建 running stats；audit.py 计算 Δ 与 repeated sign test。最易踩坑：误用 eval transform、scored item 混入 fitting pool、不同 batch size/kernel、把 EMA 与 exact refit 混淆。第一优先复现论文 2% bad-teaching crossing，而不是一开始重跑 263 个。

5. Paper 2 Full Deep Dive

AIM: A Privacy-Aware Interoperable Memory Framework for Multi-Agent Multi-User LLM Systems

Agent / Multi-AgentMemoryPrivacy

基本信息：Zachary Johnson 等 11 位作者；Microsoft；arXiv:2609.12320v1；2026-09-11；arXiv preprint。
Paper：Abstract · HTML · PDF。本次正文未确认独立 Project/Code 链接。

5.2 一句话定位

AIM 把 agent memory 从单用户向量库升级成多用户、多 Agent、带 CRUD 生命周期与结构化权限边界的共享 memory service。

5.3 人话版

Agent memory 真正难的不只是“记住什么”，而是“谁拥有、谁能读、谁能改、什么时候删、哪些知识能跨用户共享”。AIM 给每条 memory 加 owner、agent、visibility、tags、timestamp、metadata；先做 multi-label operation detection，再抽取事实、判断 private/public、去重，最后在 index 层用确定性 visibility predicate 阻止越权检索。作者还构建 MUMBench：672 条 chronological interactions、93 users、四领域，覆盖 CREATE/READ/UPDATE/DELETE/NOOP 与 adversarial cross-user queries。最佳 visibility accuracy 96.0%，但 strict operation accuracy 58.8%、state-aware 70.5%、retrieval relevance 最好仅 45.0%。所以它的价值不是“memory 已 solved”，而是把 privacy、deletion、state evolution、sharing 变成一个可系统评估的问题。

5.4 Background & Research Gap

MemGPT、Mem0、A-MEM 等主要优化单用户 memory 的抽取、检索、压缩与更新。多 Agent/企业环境里，共享与隐私冲突：例如“东北暴雪造成物流延迟”适合 public；用户地址、订单号则必须 private。另一个 gap 是操作并非互斥：“我搬到旧金山了，给我推荐晚餐”同时要求 CREATE 新事实与 READ 旧偏好。第三个 gap 是 benchmark：传统 LOCOMO 主要测单用户长期 retrieval，不覆盖 cross-user authorization 与完整 CRUD state evolution。

5.5 Core Insight

核心 insight：语义判断可以 probabilistic，但 authorization 必须 deterministic；memory operation 应是 multi-label 而非单分类。LLM 判断 intent、抽取、visibility；一旦 visibility 被赋值，private memory 在 retrieval candidate 阶段就对非 owner 不可见，而不是先塞进 context 再让 LLM“自觉不泄漏”。这是系统工程机制。它仍有入口风险：visibility classifier 96% 并非 100%，false-public 会成为高危单点。

5.6 Method Deep Dive

Message x + user u + agent a → multi-label C/R/U/D detection → visibility-constrained READ if needed → structured extraction → private/public classification → scope-restricted dedup → ownership-checked CREATE/UPDATE/DELETE → shared index → dense retrieval → tag rescoring → LLM reranking + temporal fusion → R
  1. Operation Detection：f_op(x) 输出 C/R/U/D 子集，允许一条消息多操作。
  2. Structured Extraction：抽 content、tags、temporal/domain metadata。
  3. Visibility：LLM + explicit rules 判断 private/public。
  4. Hard Enforcement：所有 read/write 先过 visibility predicate；private 对非 owner 在候选阶段不可见。
  5. Dedup：只在合法 scope 内比较，避免跨用户 dedup 泄漏 memory existence。
  6. Cascaded Retrieval：visibility-constrained dense search → tag semantic rescoring → LLM rerank + recency/temporal fusion。固定 pre-filter count=5 后来成为明显 bottleneck。
  7. Delete：只删除 user 有权限且 ownership 合法的目标。注意这只是 external-store deletion，不是 model-weight unlearning。

5.7 核心公式与数学直觉

V(u,m_i) = (v_i = public) OR (v_i = private AND owner(m_i)=u) strict(i) = 1[ C(ŷ_i) = C(y_i) ]

第一式是安全核心：public 全局可读；private 只有 owner 可读。相比 prompt-only privacy，它在 LLM reranker 前就过滤 candidate。第二式中 C 是 canonical normalization 后的 operation multiset；strict 要求整个集合精确匹配，因此任何漏 CREATE/UPDATE 都使 turn=0，会放大 cascade。state-aware accuracy 根据系统实际 store state 调整期望，更适合 sequential memory system。二者差距本身就是 error propagation 的量化。

5.8 Toy Example

用户 A：“我下月去巴黎，我花生过敏；卢浮宫周五晚开放吗？”系统输出 CREATE+READ。旅行计划和过敏信息标 private；“卢浮宫开放时间”查询可访问 public memory。用户 B 的酒店订单即使语义相似，也在 index filter 阶段不可见。一个月后 A 说“不去巴黎了，删旅行计划”，DELETE 只能触碰 A 拥有的对应 memory，不能删除公共博物馆知识。若之前从 A 的计划生成了 summary 或跨 Agent derived memory，AIM 当前的简单 DELETE 是否能闭包删除它们，正是最值得继续研究的 gap。

5.11 Metrics 教学式解释

Strict operation accuracy：整个 canonical operation multiset 完全一致才算 1，高更好；严格但会放大 cascade。State-aware：基于实际 store state 判断当前动作，避免早期错误让后续“本来不可能完成”的动作永久扣分。Judge-decision：LLM judge 判断语义合理性，容错更大但有 judge bias。Visibility accuracy：private/public 正确率；对安全来说还应补 false-public rate，因为 4% 错误可能风险不对称。Content Quality：抽取 memory 的质量，不等于最终回答质量。Retrieval Relevance：候选 memory 与 query 的相关性，AIM 最好 45%，明显偏低。

5.12 Results Deep Dive

  1. 96.0% visibility：最佳 privacy classification 强，但 4% error 对安全部署仍不可忽略。
  2. 58.8% strict：最佳 GPT-5.4-mini 仍只有约六成 turn 完整正确，lifecycle orchestration 远未 solved。
  3. 70.5% state-aware：比 strict +11.7 pp，显示 cascade/annotation-state mismatch 很大。
  4. 89.5% judge-decision：语义合理动作远多于 exact gold match，benchmark gold 存在灰区。
  5. 91.6% Content Quality：一旦决定 CREATE，抽取通常不错；瓶颈更像“何时做什么、如何找回来”。
  6. 45.0% Retrieval Relevance：weakest result，固定 top-5 prefilter 很可能是 engineering bottleneck。
  7. Coding state-aware 79.8%（DeepSeek-V3.2） vs Travel 最好 62.7%（GPT-5.4-mini）：长 update chain 更难。
  8. LOCOMO：Mem0 Single-Hop F1 0.387 vs AIM 0.175；Open Domain F1 0.477 vs 0.219；judge 0.729 vs 0.338。AIM 在传统 retrieval 明显落后。

Strongest result：privacy visibility + index-level enforcement + stateful benchmark 的组合。
Weakest/failure：45% retrieval relevance 与 LOCOMO 大幅落后 Mem0；因此优势是 problem formulation/privacy architecture，不是 retrieval SOTA。

5.14 Ablation / Mechanistic Analysis

最清晰的“机制分解”来自 metrics：visibility 高、retrieval relevance 低，说明 privacy classifier/access-control 与 retrieval bottleneck 可分离；strict→state-aware→judge 的阶梯揭示 cascade。论文没有强 causal ablation 证明 tag rescoring 或 temporal fusion 各自贡献，因此机制证据主要是系统归因，而不是 representation-level causal proof。

5.16 Contribution

C1 New System：multi-user shared registry + deterministic visibility。C2 New Mechanism：multi-label memory operation detection。C3 New Benchmark：MUMBench，覆盖 CRUD/NOOP/privacy/adversarial query。C4 New Protocol：strict/state-aware/judge 分层 evaluation。Dense retrieval、LLM classification、reranking 单独看并不新，真正创新是把它们围绕 multi-user lifecycle 组织成新的 evaluation object。

5.17 Limitation & Failure Modes

Authors：tag overlap 最好仅 35.5%；retrieval relevance 45%；LOCOMO AIM 单 pass 而 Mem0 报多 run；用户可写错误 public memory；public scope 过粗；conflict resolution/user audit 尚待验证。Additional：synthetic GPT-4o data 可能低估真实 privacy ambiguity；false-public 是高危入口；public poisoning 可跨用户扩散；DELETE 不保证 summary/backup/log/cache/parametric trace 消失；并发 update/race condition 覆盖不足；LLM judge 可能有偏。

5.18 Reproduction View

最小模块：op_detector、extractor、visibility、store、retriever、evaluator。可用一个中型 instruction model + FAISS/SQLite metadata filter。关键坑：必须在 dense search 前 owner/visibility filter；update/delete 再查 creator ownership；benchmark 必须 sequential replay，不能把 672 条独立 batch 化。第一实验优先复现 60 adversarial queries 的 unauthorized retrieval，而不是先追 Content Quality。

5.19 Research Value

Baseline：高——agent memory deletion/privacy。Migration：极高——跨 Agent handoff/session index。Attack：极高——public poisoning、visibility flip、cross-user inference。Evaluation：极高——CRUD sequential replay。Benchmark：极高——可扩成 revocation/unlearning benchmark。New Paper：高——“memory deletion ≠ model/system unlearning”存在明显空白。

5.20 Migration Analysis

Migration A — Agent Memory Unlearning / Revocation Benchmark

Original：AIM 只保证 store-level DELETE。Mechanism：stateful CRUD + owner/visibility + adversarial query。RQ：DELETE 后能否从 summary、derived memory、cross-agent public memory、context 中恢复？Modification：为 memory 建 provenance DAG，DELETE 级联 revoke；攻击用 paraphrase/multi-hop/other-agent/reacquisition。Minimum Experiment：MUMBench 选 50 private memories，每条生成≥2 derived memories；比较 vanilla AIM、Mem0、provenance-aware cascade delete；5 attack families×5 prompts。Model：一个 closed mini + 一个 Qwen open model。Dataset：MUMBench+derived annotations。Baseline：AIM DELETE、Mem0 DELETE、store-reset oracle。Metric：Deletion Success、Derived Leakage、Reacquisition ASR、Retain Utility、Unauthorized Recall。Contribution：把 agent memory deletion 与 unlearning verification 接起来。Risk：external vs parametric memory 边界。Collision：中。

Migration B — Cross-Agent Memory Poisoning + Trust Retrieval

Original：任一用户可创建错误 public memory。Mechanism：shared public index。RQ：攻击者能否从 Agent A 写入，在 Agent B/其他用户触发错误？Modification：加入 provenance、writer reputation、verification status、conflict set；score=relevance×trust×freshness。Minimum Experiment：四领域各注入 10% conflicting public memories，攻击者控制 1/5/10 users；比较 AIM、source-trust、cross-source consensus。Model：DeepSeek-V3.2/Llama-3.3-70B。Metric：Poison Success、Benign Recall、False Suppression、Attack Cost。Contribution：multi-user memory supply-chain security。Risk：synthetic poison 太简单。Collision：中高，需与 RAG poisoning 区分。

5.21 Attack / Verification Lens

Attack 可做 visibility misclassification、public poisoning、cross-user inference、delete-then-recover。Black-box probe 可用“只有另一个用户 memory 才能回答”的 canary query。Unlearning verification 应在 DELETE 后做 derived/paraphrase/multi-agent reacquisition。可定义 Revocation Closure、Cross-User Leakage@K、Poison Propagation Radius。

5.22 与 Paper 1 的关系

AIM 的 DELETE 是 store-level operation；Paper 1 提醒我们，改掉一个显式 state 不等于整个 artifact 的 deletion verdict 稳健。最自然组合就是 deleted memory 的 state-channel reconstruction/recovery audit。

7. Cross-Paper Synthesis

两篇共同说明一个趋势：删除不能只看主权重或一条表面 readout，而必须先定义完整系统状态及其生命周期。Paper 1 证明 θ 之外的 deployed state 能改变 unlearning audit；Paper 2 把 external memory 显式建模成 owner/visibility/timestamp/CRUD state。组合起来，自然得到一个更强研究对象：删除 root memory 后，derived summary、shared replica、cross-agent cache、retrieval index、parametric trace 是否形成可恢复的 state closure？

最可组合的机制是：AIM 的 lifecycle/provenance/visibility + Paper 1 的 counterfactual state rebuild、per-artifact repeats、TOST、detection floor。前者告诉我们“有哪些状态、谁能访问”，后者告诉我们“如何证明 deletion verdict 对 state convention 稳健”。

8. Combined Research Opportunities

Top Opportunity — Provenance-Closed Agent Unlearning Verification

为 CREATE/UPDATE/summary/share 建 provenance DAG；DELETE 不只删 vector，而是定义 revocation closure。验证阶段冻结主 LLM，逐个恢复 vector store、summary、shared memory、cache 等 channel，测哪条 channel 让 deleted fact 重新可见；统计上用 per-artifact repeated attacks + equivalence margin，而非平均 leakage。这个方向同时吸收两篇核心机制，并与 retrain-equivalence 的 unlearning 思想兼容。

Opportunity 2 — MLLM State Recovery Surface

把 deployed state 扩到 vision tower/projector/LLM LoRA、quantization calibration、generation cache、system memory。对每个 channel 做 frozen-weight perturbation，形成 State Recovery Surface；重点测 image-conditioned residual knowledge 是否比 text-only 更容易在 state perturbation 后恢复。

9. Collision / Overlap

Strongest Collision：两篇都否定“单一表面 accuracy 足以描述 deletion correctness”。Paper 1 中同一 θ 因 φ 改变而 crossing；Paper 2 中 strict/state-aware/judge scores 差距巨大。与 recovery attack 文献存在邻接，因此新论文不能只做“换 state 后恢复”，而应强调 systematic state taxonomy + provenance closure + artifact-level statistical verification。
