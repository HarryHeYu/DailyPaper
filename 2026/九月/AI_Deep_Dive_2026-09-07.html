5.2 一句话定位

ATU 把 LLM unlearning 的安全边界从“模型参数里是否还会直接回答”扩大到“部署为 tool-augmented Agent 后是否仍能通过搜索、数据库、文献检索等外部工具恢复 forget target”。

5.3 人话版

传统 unlearning 往往把模型单独拿出来测试：问一个 forget query，如果回答不出来，就认为“忘了”。ATU 指出这在 Agent 部署中会严重高估安全性。因为模型可以先调用 web search、database、literature retrieval 或 code tool，再从工具 observation 中把已经从参数里压低的知识重新复制到最终答案。论文把这叫 tool-mediated recovery。作者先证明这个现象非常显著：例如 NPO 后 RWKU standalone forget score 为 44.6，但一接 Agent 工具后升到 68.6；MUSE Books 从 9.7 升到 29.8。随后提出两阶段 ATU：Stage 1 仍用 GA/DPO/RT/NPO 做 parametric unlearning；Stage 2 把模型放进模拟工具环境，用 trajectory-level reward 对“主动搜索 forget target”“工具 observation 已出现目标”“最终答案泄漏目标”逐级惩罚，同时在 retain/tool-use tasks 上奖励正常工具使用，再用 GRPO-style RL 更新。最终 NPO+Stage2 在 RWKU 将 Agent forget score 从 68.6 降到 47.5，并在 swapped tools、held-out tool families、forced retrieval、held-out queries 上仍保持一定泛化，但 exact-copy/adaptive retrieval 仍能造成明显恢复。

5.4 Background & Research Gap

目前 LLM unlearning 的典型范式，是在 forget set 上降低 target likelihood，在 retain set 上用 KL、GD、NPO、preference 或 refusal regularization 保护 utility。无论 TOFU、RWKU、MUSE，绝大多数主评测都把模型当 standalone generator：给 prompt，直接看输出。

但实际产品越来越常把 LLM 放到 Agent framework 中。假设“某书段落”已经被 NPO 压到模型不再直接生成；用户却要求 Agent “搜索这本书相关页面并总结原文”。模型不需要从 weights recall，只需调用 search，读取 observation，再复述。此时 parametric unlearning 并没有失效，而是系统层出现了新的信息来源。

旧方案的几个自然应对都不够：一是禁用工具，会直接毁掉 Agent utility；二是只让模型 refusal，会因提示变化/工具 observation 诱导而失效；三是只删 Agent memory，外部 web/database 仍可回流；四是做 ToolDelete，删除的是 tool capability，不是“保留合法工具但避免特定 target recovery”。ATU 真正填的 gap 是：目标知识可以继续存在于世界与工具中，但 unlearned model 在使用这些工具时不应重新泄漏它。

5.5 Core Insight

核心 observation 1：parametric forgetting 与 agentic forgetting 是两个不同变量。 standalone score 下降，并不能预测 tool-augmented score。NPO 在 RWKU standalone 从 base 57.7 降至 44.6，但 Agent deployment 直接回到 68.6；MUSE 更极端，9.7→29.8。

Observation 2：Stage 1 后，模型反而可能更依赖工具。作者在 Figure 6 报告 forget-query ToolUse_F 普遍上升，说明模型“内部想不起来”后会把工具当替代 recovery path。因此单纯压 weights 甚至可能把 leakage 转移到 trajectory。

Observation 3：只在 final answer 上惩罚不够。若 Agent 已经发出了 target-seeking search query，即使最后碰巧没泄漏，这条 trajectory 也暴露了风险策略。于是 reward 必须覆盖 intermediate tool behavior。

这是一种 deployment-level system observation + online RL intervention，不是证明模型内部知识被“真正擦除”的 representation-level结论。

5.6 Method Deep Dive

Base policy π_θ0 + forget target c → construct F(c), R_same(c), R_other → Stage 1 parametric unlearning GA / RT / DPO / NPO → obtain π_θ1 → add target-independent tool retain set R_T → deploy π_θ in simulated agent environment E_train → for each query x: generate trajectory τ=(x,a1,o1,...,aK,oK,y) → trajectory-level judge: forget query: penalize target-seeking tool calls penalize target information in observations/trajectory heavily penalize final answer leakage retain query: reward correct/helpful answer reward appropriate tool use penalize over-refusal / irrelevant tool calls → sample 4 trajectories per prompt → group-normalized advantage → clipped GRPO/PPO-style objective + KL to Stage-1 checkpoint → π_θ2 → evaluate standalone + agent deployment → swapped tools / forced retrieval / held-out tools / held-out queries

Stage 1：目的仍是压制 weights 中的 direct recall。论文并不要求某一种特定 unlearning loss，而是把 GA、RT、DPO、NPO 都作为可替换初始化。

Retain 分层：R_same(c) 保同领域邻近知识；R_other 保一般能力；R_T 专门保 target-independent tool use。R_T 很关键，否则 Stage2 最容易学到的策略就是“看到类似问题就永远不要用工具”。

Trajectory generation：训练时模型真的在 simulated Agent environment 中选 tool、读 observation、给最终答案。优化目标因此覆盖 policy behavior，而不只覆盖 token likelihood。

Forget reward：安全拒答 +1.0；模糊但不泄漏 +0.3；已经有 target-seeking/risky tool use -0.5；trajectory 出现目标信息 -1.0；最终回答直接或改写 reference -2.0。这使 policy 在目标真正进入 final answer 前就受到惩罚。

Retain reward：正确有帮助 +1；部分正确 +0.5；严重错误/无关 tool use/过度拒答为负。它相当于给“不要恢复 target”增加一个 utility counterforce。

RL：每 prompt 采4条 trajectories，用 group-relative advantage 做在线优化，并以 Stage1 checkpoint 为 KL anchor，避免 Stage2 把 parametric forgetting 或一般语言能力推离太远。

5.7 核心公式与数学直觉

Agent trajectory: τ = (x, a1, o1, ..., aK, oK, y) Stage 1: θ1 = argmin_θ L_KU(θ; F(c), R) L_KU = L_forget + λ_ret L_retain Stage 2 reward: R(τ)= R_forget(τ,y*) if (x,y*) ∈ F(c) R_retain(τ,y) if (x,y) ∈ R Policy ratio: ρ_i(θ)=π_θ(τ_i|x) / π_θold(τ_i|x) RL objective: L_RL = -E[min(ρ_i A_i, clip(ρ_i,1-ε,1+ε) A_i)] + β_KL KL(π_θ || π_θ1)

τ：把工具调用与 observation 都纳入 policy object。传统 unlearning 只看 y；ATU 把“怎么得到 y”也变成优化对象。

λ_ret：Stage1 的 forget–utility trade-off。过小会过度忘记邻近知识，过大则 forget 不足。

ε_clip：限制单轮 policy 更新幅度，防止 trajectory reward 很离散时 policy 发生过大跃迁。

β_KL：Stage2 最关键稳定器之一，强制 policy 留在 Stage1 附近。β 太大，tool behavior难改变；太小，模型可能学成广泛拒答或失去原 parametric forgetting结构。

与 strongest baseline NPO 的区别：NPO 只在 token likelihood level 压低 forget response 相对 reference model 的偏好；ATU 直接优化 tool-augmented trajectory，能惩罚“搜索 forget target”的策略，即使 final token 尚未泄漏。

5.8 Toy Example

目标是忘记某公众人物的一个具体事实。Stage1 NPO 后，直接问“他的出生地？”模型回答“不知道”。但把模型放进 Agent：

  1. Agent 思考：“我可以搜索。”
  2. 调用 web_search("X birthplace")。
  3. observation 返回明确出生地。
  4. Agent 最终回答正确——unlearning 在 standalone 看似成功，在 system-level 失败。
  5. ATU Stage2 对第2步 target-seeking search 就给 -0.5，即使最后没说答案。
  6. 若 observation 已带出 target，trajectory reward -1。
  7. 若 final answer 泄漏，-2。
  8. 另一方面，对 retain query “帮我查明天航班”使用 airline tool 并正确回答仍获 +1。
  9. 训练后，Agent 学到“工具仍可正常使用，但当 query 落在 forget target surface 时不要主动重建目标”。

5.10 Experiment Setup Deep Dive

Datasets：RWKU（现实公众人物知识）与 MUSE Books（copyrighted-book knowledge）。使用官方 forget/retain splits；Stage2 额外构造 target-independent general tool-use retain set。

Models：Qwen-3-4B-Instruct、Qwen-2.5-7B-Instruct；Appendix 另做 Qwen-3-8B。

Agent：modified Qwen-Agent framework；tools 包括 web search、database lookup、literature retrieval、code execution 等 recovery channels。

Stage1 RWKU：LoRA；bf16；cutoff512；batch1×grad accumulation16；cosine LR；20 warmup；target modules q_proj,v_proj；10 epochs；训练后 merge LoRA。

Stage2：OpenRLHF，bf16，DeepSpeed ZeRO-3，gradient checkpointing，1个vLLM rollout engine，TP=1，temperature0.7，top-p0.9，max generation128，4 trajectories/prompt；judge=Qwen2.5-7B-Instruct，temperature0。

Compute：单服务器4×RTX4090 24GB，128 AMD EPYC 7543 CPU threads，约512GB RAM。

Baselines：GA/RT/DPO/NPO；Stage2另比 refusal SFT、trajectory DPO。

RQ1：parametric unlearning 在 Agent deployment 会不会被工具恢复？
RQ2：ATU 是否以 utility 为代价？
RQ3：跨 benchmark/backbone 是否成立？
RQ4：ATU 到底改变 final answer，还是改变 tool-use trajectory？
Robustness RQ：swapped tools、forced retrieval、held-out tools/query 是否仍工作？

5.11 Metrics 教学式解释

RWKU FB/QA/AA ROUGE-L Recall↓：分别是 fill-blank、普通 QA、adversarial attack probe 对 forget reference 的恢复程度。越低越忘。

All↓：三类 forget probe 的加权平均，方便总体比较；缺点是会掩盖某类 attack（如AA）特别差。

ΔAll：Agent deployment 相对 standalone 的恢复增量，或 Stage2 相对 Stage1-Agent 的改善量。它是本文最直观的 “tool-mediated recovery gap”。

Neighbor↑：同领域邻近但不该忘的知识，检查局部 collateral damage。

Factuality/Fluency↑：一般输出质量；不能替代 task utility，但能检查全局崩坏。

MUSE knowmem_f↓ / knowmem_r↑：forget 与 retain split 的知识记忆程度。

ToolUse_F↓：forget queries 中至少调用一次工具的比例。它不是越低越绝对好，因为可能靠“全禁工具”作弊，所以必须与 general tool-use retain score 一起看。

Held-out tool contains-match↑：目标无关工具任务是否仍正确执行，补足 ToolUse_F 的作弊风险。

5.12 Results Deep Dive

  1. 核心 recovery gap：RWKU NPO standalone All=44.6，Agent=68.6，+24.0；说明 standalone forgetting 明显高估部署鲁棒性。
  2. MUSE recovery：Qwen3-4B NPO knowmem_f=9.7，Agent后29.8；Qwen2.5-7B 10.0→32.9，跨模型一致。
  3. Stage2 strongest：NPO+ATU 68.6→47.5，降低21.1点，是主设置最强结果。
  4. 跨Stage1：GA 61.1→51.6、DPO67.1→53.9、RT67.5→52.2、NPO68.6→47.5；说明Stage2不是只适配NPO。
  5. MUSE Qwen3-4B：29.8→15.8，同时 retain 56.7→55.1，仅小幅下降；这是较好的forget–retain balance。
  6. Qwen2.5-7B：RWKU NPO Agent61.7→Stage2 41.5，-20.2；Neighbor 77.2→71.1，有明显但非灾难性utility代价。
  7. Qwen3-8B：NPO Agent86.0→Stage2 33.8，改善52.2点，且 Neighbor 80.7→85.7；说明大模型上可能更能学会target-specific trajectory policy。
  8. Swapped tools：NPO Stage2 在原tools 47.5，在同类型替代tools 46.7，说明并非只memorize某个API名字。
  9. Held-out tool families：Stage2 accuracy87.5%，Stage1 92.5%，Base80%；保留未见过的airline/workspace/spreadsheet/mock-shell工具能力，但比Stage1损失5点。
  10. 非RL对比：Refusal SFT仅-8.7、Trajectory DPO -10.5、ATU -21.1；online rollout是明显收益来源。
  11. 效率：ATU训练1.97h，SFT1.10h，DPO1.35h；forget improvement/hour约10.7 vs7.9/7.8。ATU更强但更贵。
  12. Adaptive forced retrieval：“retrieve before answering”将Stage2 47.5推到59.6（+12.1）；exact-copy 也到57.7。说明ATU并未封死强制工具恢复。
  13. Held-out queries：Stephen King 60/40 split 上52.6→36.8，Neighbor49.7→51.1，初步说明不是记训练prompt。
  14. Reward judge：Qwen2.5-7B 与人工 sign agreement83.3%、exact63.9%，并得到最佳 forget47.5；judge更大并不更好。
Strongest result：Qwen3-8B 的 NPO Agent 86.0→ATU33.8，同时 Neighbor80.7→85.7，是“工具恢复被大幅关闭且 utility 没一起崩”的最强现象；主设置则 NPO 68.6→47.5 最可比较。
Weakest / trade-off：Qwen2.5-7B Neighbor77.2→71.1，且 ATU 比SFT/DPO贵1.5–1.8×，说明不是无成本提升。
Failure case：forced retrieval / exact-copy directive 仍明显抬高 leakage；工具 observation 若被用户明确要求逐字复制，policy-level mitigation存在根本困难。

5.14 Ablation / Mechanistic Analysis

Stage1 vs Agent：同一个checkpoint只改 deployment，forget score明显回升，干净证明 recovery 来自 system path，而不是参数更新失败。

Agent w/o Tools：Appendix 将 framework effect 与 tool effect 分开。Stage1 NPO standalone44.6、Agent w/o tools约45.1、Agent w tools68.6，说明主要 recovery 真的是工具，不只是Agent prompt格式。

Swapped Tools：替换同类型API后Stage2仍有效，说明policy学到的是更一般的 target-seeking behavior，而非工具名黑名单。

Reward Judge Ablation：4B/7B/8B judge 结果非单调，7B最贴人工且下游forget最好，说明judge quality是方法敏感点。

Training dynamics：128-step audit mean KL≈0.50，没有出现“超短+1 reward”明显 reward hacking；但这只排除一种特定hack。

这些机制证据说明 ATU 改变 trajectory policy，但并不能证明目标知识从模型内部 representation 中被彻底删除。

5.15 Claim vs Evidence

Authors Claim：parametric unlearning 对 tool-augmented agent deployment 不充分；ATU 能减少 direct + tool-mediated recovery，同时保留正常工具使用。
Experiments Actually Show：RWKU/MUSE、多backbone、多Stage1 method、swapped tools、held-out tools/queries都支持“工具是新恢复通道”和“Stage2能显著缓解”。
What Is Not Yet Proven：没有关闭任意未知工具/多步Agent framework；没有证明强 adversarial prompt 下安全；没有阻止用户直接要求复制 tool output；没有 representation deletion 证据；reward judge依赖较强。

5.16 Contribution

  • New Failure Mode：Tool-mediated Recovery。
  • New Threat Model：provider发布unlearned model，但downstream deployer控制tools/prompts。
  • New Method：Stage1 parametric + Stage2 trajectory RL 的 ATU。
  • New Objective/Protocol：对 intermediate target-seeking tool behavior 也给负reward。
  • New Evaluation：standalone vs agent、tools vs no-tools、swapped tools、forced retrieval、held-out tools/query。
  • New Empirical Finding：parametric unlearning 后工具依赖可能上升。

5.17 Limitation & Failure Modes

Authors' Limitation：agent/tool environment覆盖有限；tool-mediated recovery gap没有完全关闭；未来需 adaptive recovery attacks 和更广 agent benchmarks。

Additional：防御训练显式看到 recovery tools，仍可能对全新tool semantics不泛化；LLM judge存在 reward-model bias；external observation 若必须完整呈现，model-side policy无法保证删除；工具本身可能缓存 target；真实deployment中的memory、browser history、files、plugins、subagents形成更多recovery carriers；用户可能把 target encode 成多步间接检索；Stage2也可能让模型学到“target identity fingerprint”而非真正forget。

5.18 Reproduction View

最关键模块：1) RWKU/MUSE loader；2) Stage1 GA/RT/DPO/NPO LoRA；3) Qwen-Agent tool environment；4) web/database/literature/code tools；5) trajectory serializer；6) forget/retain reward judge prompts；7) general tool-use retain set；8) OpenRLHF GRPO training；9) KL anchor；10) Agent/no-tool/swapped-tool/forced-retrieval evaluator。

最小复现建议先做 RWKU + Qwen3-4B + NPO：复现 standalone44.6附近→Agent68.6附近的 recovery gap，比直接训练Stage2更重要。第二步只做 refusal SFT vs trajectory DPO vs ATU 三组；第三步再做 swapped tools 与“retrieve before answering”攻击。如果第一步没有稳定 recovery gap，后续ATU结果没有意义。

方向 B — Recovery-Carrier Attribution before Agentic Unlearning

Original Problem →ATU统一对整条trajectory训练。

Collision Risk →低到中，与PlanFence/MutMem provenance邻近，但目标是行为credit。

5.21 Attack / Verification Lens

ATU 最自然的攻击是 forced reacquisition：强制 retrieve、指定 target search query、要求逐字复制 observation、换同类tool、让subagent检索后回传、先写入memory再要求回答。可定义 Agentic Recovery Gap (ARG)=Leak_agent-tools − Leak_standalone；以及 Carrier-conditioned Reacquisition Rate，分别测web/RAG/database/memory/subagent恢复能力。

5.22 与另外 Top Paper 的关系

JIT-Agent 说明 harness 可以动态决定 memory、planning、action、capability orchestration；ATU说明这些 capability 尤其是tools会改变 unlearning 的实际边界。组合起来最重要的结论是：固定一个Agent harness评测 unlearning 远远不够。一个JIT harness generator甚至可以主动产生更强检索/分解/工具路由，从而成为新的 adaptive recovery attacker。

5.2 一句话定位

JIT-Agent 把“Agent harness engineering”从人工或 Ahead-of-Time 搜索，重写成一个独立可训练的 meta-agent：它根据具体任务即时生成 memory/planning/action/capability 四模块 harness，并能学习修复错误 harness、在线保留更优设计。

5.3 人话版

同一个 foundation model，套不同 harness，能力可以差很多。Deep research 需要证据图和长期 memory，购物规划需要约束求解，terminal coding 更适合短 ReAct loop，复杂研究任务甚至需要递归 subagent。传统 Agent framework 的问题是这些 harness 通常由工程师提前手写，或者通过大量历史 trajectories 做 Ahead-of-Time 搜索，得到一个“平均适合”的固定 scaffold。JIT-Agent 反过来训练一个专门生成 harness 的模型：输入当前任务、固定四模块 protocol、可用 tools/skills 和少量历史高质量 harness，它即时产出任务专属执行程序。训练分三阶段：Stage I 用强 teacher 生成合法 task-adaptive harness，并做SFT+DPO；Stage II 专门学习如何根据 compiler/runtime diagnostics 在最多2轮内修复坏 harness；Stage III 用 Evo-GDPO 在线比较候选与历史bank，在 reward 不下降的前提下再优化 latency/cost，只把 Pareto frontier 改进设计写入 bank。JIT-Agent 在9个agent benchmark上对 GLM-5.2 平均+7.7、DeepSeek-V4-Flash +8.8，DeepPlanning最高+24.8；固定backbone对比 Claude Code/Codex/OpenCode 等时，6个setting中4个性能第一，并且6/6成本最低。

5.4 Background & Research Gap

Agent capability 不只来自 model weights。memory怎么压缩、planner是DAG还是linear、action是ReAct还是recursive、tools如何搜索/路由，都会改变最终表现。过去有两类路线：第一是固定成熟runtime，如 Claude Code/OpenCode；第二是 AutoHarness/Meta-Harness/AHE/Harness-R1 等，用历史反馈 Ahead-of-Time 搜索或编辑一个可复用 harness。

问题是 deployment tasks 高度异构。例如 deep research 需要多分支证据搜集和事实图，office automation 需要 artifact/workspace state，购物需要constraint satisfaction。一个固定 AOT harness 要么复杂到什么都带，成本很高；要么针对平均任务优化，遇到新结构不匹配。

JIT-Agent 的 gap 是：能否把“设计 harness”本身 amortize 成一个模型能力，像 compiler 一样在看到 task instance 后即时生成最合适的 memory/planning/action/capability program，而不是每次重新搜索。

5.5 Core Insight

Insight 1：正确 harness 是 instance-dependent，不只是 domain-dependent。同是research task，有的需要DAG，有的需要递归delegation，有的只需串行检索。

Insight 2：harness 可以被统一表示成四个模块的 composable protocol：Memory M、Planning P、Action A、Capability orchestration F。这样不同 Agent framework 能落到同一设计空间，而不只是比较几段prompt。

Insight 3：harness generation 的三个 failure 是不同的：不会定制、不会修、不会从执行经验继续改善。因此训练也必须拆成 customization、repair、evolution 三阶段。

Insight 4：reward/latency/cost 不应简单加权，因为模型可能用更长trajectory买准确率。Stage III 只有 reward 不低于 incumbent 时才激活 latency/cost improvement，构成带性能约束的 Pareto evolution。

5.6 Method Deep Dive

Task τ + protocol Π + capability registry C_τ + retrieved prior harness context E_τ → JIT generator p_θ produces harness h h = (Memory M, Planning P, Action A, Capability F) → protocol/static/runtime validation → if invalid: structured diagnostic g bounded repair (≤2 rounds) → frozen executor π_ψ runs h → obtain reward r, latency ℓ, cost κ → static inference: generate N harnesses in parallel select one execute selected only OR streaming inference: retrieve from bank B_n generate h_n execute once evaluate (r,ℓ,κ) update bank only if frontier improves Training: Stage I: teacher-generated valid harnesses → SFT → preference pairs under same executor/seeds → weighted DPO Stage II: invalid harness + diagnostics → bounded patch trajectories → repair supervision Stage III: sample G candidate harnesses → compare to incumbent bank → decoupled reward/latency/cost advantages → Evo-GDPO clipped PPO + KL → conservative frontier update

Unified protocol：把 13 个代表性 scaffolds 重实现到同一个 HarnessFactory：ReAct、Plan-and-Execute、ReSum、Flash-Searcher、GAM、MemoBrain、AggAgent、OAgent、AgentFold、HiAgent、DeepAgent、ROMA、AOrchestra。它们形成初始 bank B0。

Stage I：强teacher接收 task + 3个同类型seed harness + protocol + tools，生成任务专属harness。只有 protocol-valid 且能执行的样本保留。随后 SFT 学“会生成”，DPO 学“同样合法时哪个更好更省”。

Stage II：不是把坏generation丢掉，而是收集 compiler error、interface mismatch、tool-call failure、runtime exception，让 teacher 提结构化 patch，最多2轮修到 executable。它学习的是“局部修复能力”。

Stage III：每轮从bank检索历史强design，生成G个候选。先以任务 reward 为主；只有 candidate reward≥incumbent，latency/cost优势才生效。用 Evo-GDPO 归一化三个reward channel，再做 PPO-style 更新。

Streaming inference：部署时 generator weights 固定；只让 bank 吸收这次任务产生的更优harness，下一任务检索它。即“online evolution”发生在 external harness archive，而不是持续更新模型参数。

5.7 核心公式与数学直觉

Harness: h = (M, P, A, F) Stage-I preference: h+ ≻_τ h- iff r+ > r- and ℓ+ ≤ ℓ- and κ+ ≤ κ- and at least one efficiency gain is strict Δ_val = α_r(r+−r−) + α_ℓ[ℓ−−ℓ+]_+ + α_κ[κ−−κ+]_+ Stage-III channels: R_i^rew = r_i + λ_evo [r_i−b_r]_+ R_i^lat = I[r_i≥b_r][b_ℓ−ℓ_i]_+ R_i^cost= I[r_i≥b_r][b_κ−κ_i]_+ A_i^m = (R_i^m − mean(R^m)) / (std(R^m)+ε) A_i^Σ = w_rew A_i^rew + w_lat A_i^lat + w_cost A_i^cost with w_rew > w_lat + w_cost

Preference relation：非常保守：h+ 必须 reward 更高，而且 latency/cost 不得更差。这避免“更聪明但贵很多”的样本被Stage I偏好学习。

Δ_val：不仅决定chosen/rejected，还作为DPO pair权重；差距越实质，训练信号越大。

Stage III gating：latency/cost只有 r_i≥b_r 时才激活，这是最关键设计。它明确把性能当hard-ish constraint，效率是第二目标。

λ_evo：控制“超过历史最佳”的额外奖励，过大可能让模型只追reward frontier，忽视稳定性；过小则online bank难持续提高。

w_rew：要求大于其它权重之和，防止一个快但明显更差的harness被综合advantage选中。

与固定harness baseline区别：不是简单在ReAct prompt上加技巧，而是 task-conditioned synthesize 整个 memory/planning/action/capability program。

5.8 Toy Example

任务：“从多个网页找到20个联系人，去重、标准化、生成xlsx，并邮件发送。”

  1. 固定ReAct可能把所有网页、联系人、操作都堆进同一context，随着任务变长丢状态。
  2. JIT-Agent识别这是“多阶段artifact pipeline”，生成 GraphPlanPlanning：discover→filter→normalize→workbook→verify→email。
  3. Memory选择 GraphPlanMemory，只保存目标、evidence、normalized records、artifact path，不保留每一步冗长CoT。
  4. Action选择 bounded-width DAG executor，只执行ready nodes。
  5. Capability orchestration 只暴露 search/file/spreadsheet/email 所需 tools。
  6. 若生成的email tool schema写错，validator返回interface mismatch，Stage II repair修改对应patch。
  7. 执行后 reward高于bank中旧harness且cost更低，则写入 bank。
  8. 以后遇到相似“检索→结构化→artifact→delivery”任务，检索到该harness作为参考，但仍可针对新任务重新实例化。

5.11 Metrics 教学式解释

Benchmark score↑：不同benchmark原始metric不同，被统一映射0–100；可看总体能力，但跨benchmark平均需谨慎，因为metric语义不同。

#Tokens↓：每case平均模型token消耗。对Agent特别重要，因为复杂harness可能通过更多planning/反思换性能。

API Cost↓：综合实际模型定价后的case成本；比token更贴现实，但不同provider价格会改变结论。

Pareto frontier：同时考虑performance与cost；某点若存在另一点更便宜且更强，则被dominant。

Cumulative accuracy↑：streaming evaluation随着task序列推进的累计正确率；用于判断bank是否在积累有用经验。

Tool calls↓/适中：不是越少越好，而是辅助解释性能是否靠interaction explosion买来。

5.14 Ablation / Mechanistic Analysis

论文没有传统“去掉一个模块”的大表式 ablation，因此机制分析主要来自结构化对照：

Fixed backbone, change harness：同模型只换harness后显著提升，最直接隔离 harness contribution。

Fixed harness baselines vs JIT：同backbone、相近工具环境下比较多runtime，排除model weights差异。

Cost control：JIT token更少而性能更高的setting，排除“更多test-time compute”解释。

Static vs Streaming：只有bank是否积累经验不同，streaming后期更高，支持online archive evolution。

Generated harness visualization：Palimpsest/Trapdoor等显示不同task确实生成DAG、递归delegation、folded context、gated tools等不同execution semantics。

不足是：没有系统量化 Stage I/II/III 分别去掉后的性能；因此“repair supervision”和“Evo-GDPO各贡献多少”仍缺标准ablation。

5.15 Claim vs Evidence

Authors Claim：harness intelligence 是独立于 model scaling 的可训练、可迁移、可积累能力；JIT generation 比固定AOT harness更适配异构任务。
Experiments Actually Show：固定backbone下大量paired gains、固定runtime对比、cost frontier、跨family 24/24提升、streaming优于static，都支持 harness作为一阶能力来源。
What Is Not Yet Proven：没有完整Stage ablation；没有安全/攻击评估；没有证明生成harness不会放大prompt injection/数据泄漏；streaming bank长期是否会污染/遗忘未知；对闭源强runtime的接口公平性仍可能存在实现差异。

5.16 Contribution

  • New System/Engineering：JIT harness generator / HarnessFactory。
  • New Representation：Memory–Planning–Action–Capability 四模块统一harness protocol。
  • New Training Pipeline：Customization SFT+DPO → bounded repair → Evo-GDPO。
  • New Objective：reward-first、efficiency-gated multi-channel evolution objective。
  • New Inference Protocol：Static JIT 与 Streaming JIT bank evolution。
  • New Empirical Finding：固定backbone下task-conditioned harness可带来大幅跨任务提升并降低成本。

5.17 Limitation & Failure Modes

Authors' limitation / implied：统一四模块 protocol 是人为设计边界；training需要teacher与大量执行评测；streaming经验是否在长期OOD任务上持续有益仍需验证。

Additional：生成harness可能成为新的攻击面：自动决定memory retention、tool exposure、recursive subagents，很可能改变权限边界；bank可能被poisoned trajectory污染；低成本优化可能诱导跳过安全检查；repair模块可能把“安全失败”修成“可执行但危险”；跨provider harness semantics可能不等价；benchmark tool registry相对干净，真实plugin生态更复杂。

5.18 Reproduction View

最关键模块：1) 四模块 protocol schema；2) common execution kernel；3) 13 seed HarnessFactory；4) task-type retriever；5) teacher harness synthesis；6) protocol/runtime validator；7) StageI SFT+DPO；8) structured diagnostic/patch engine；9) StageIII candidate evaluator与Evo-GDPO；10) harness bank + Pareto frontier；11) static/streaming inference；12) benchmark adapters。

最小复现不建议一上来训27B generator。先实现统一protocol+5个seed harness，在2个benchmark上做“oracle selector”：根据task type人工选择harness，验证 harness差异是否显著。第二步用小模型SFT生成合法harness，测Valid rate。第三步再加入repair。只有最后才做Evo-GDPO。这样可以把“生成能力”与“RL evolution”拆开验证。

5.19 Research Value

Baseline Potential ★★★★★：做 Agent research 时，固定ReAct不再是足够baseline；需要考虑强task-adaptive harness。

Migration Potential ★★★★★：可用于自动生成 unlearning verifier/recovery harness。

Attack Potential ★★★★★：JIT harness可以成为自动 adaptive recovery attacker。

Evaluation Potential ★★★★★：可测试模型能力是否对 harness 敏感。

Benchmark Potential ★★★★☆：可做 Harness Robustness / Harness Shift benchmark。

New Paper Potential ★★★★★：与 unlearning closure、Agent security、adaptive verification结合空间巨大。

5.20 Migration Analysis

方向 A — JIT-Adaptive Unlearning Recovery Harness

Original Problem →JIT-Agent根据任务生成最合适的harness。
Transferable Mechanism →task-conditioned memory/planning/action/tool orchestration。
New Research Question →固定direct/paraphrase/cloze attack是否低估了unlearned model在“最适攻击harness”下的recoverability？
Method Modification →把目标改为“恢复forget knowledge”；generator可在候选actions中选择direct query、prefix、candidate verification、search、RAG、memory accumulation、subagent debate；reward=forget recovery − retain false-positive − query/tool cost。
Minimum Experiment →30 forget targets×4 unlearning methods×2 LLM；每target最多50 queries、10 tool calls；生成4个candidate harness并只执行1个。
Model →Qwen3-8B / Llama3.1-8B unlearned；小型Qwen3-4B/8B做harness generator起步。
Dataset →TOFU、DUSK、RWKU。
Baseline →fixed direct、Cloze、TAS、ATU forced-retrieval、manual mixed attack harness。
Metric →Best-Harness ASR、ASR@query budget、Harness Diversity、Retain FPR、Cost-to-Recovery。
Expected Contribution →从“攻击prompt优化”推进到“攻击系统结构优化”。
Risk →搜索空间大、容易把tool access本身当捷径。
Collision Risk →低；与TAS/ATU互补而非重复。

方向 B — Harness-Invariant Unlearning Verification

Original Problem →JIT说明同一模型不同harness表现差异巨大。
Transferable Mechanism →把harness视为deployment distribution的一部分。
New Research Question →一个unlearning checkpoint的forget/retain结论在不同memory/planner/tool orchestration下是否稳定？
Method Modification →固定模型，采样10–20种harness配置；每个harness测forget leakage/retain utility；计算worst-case而非average。

Minimum Experiment →20 targets×5 methods×12 harnesses（ReAct、RAG、DAG、recursive、memory-heavy、tool-heavy等）×3 seeds。

Model →Qwen3-8B、LLaVA-7B（后续扩multimodal）。

Dataset →RWKU + MLLMU-Bench。

Baseline →standalone-only evaluation、single-ReAct Agent、ATU default agent。

Metric →Harness-Worst Leakage、Harness Variance、Utility Min、Tool-Recovery Max、Robust Forgetting Radius。

Expected Contribution →定义 harness-invariant unlearning robustness。

Risk →不同harness能力不等，公平预算必须严格控制。

Collision Risk →低。

5.21 Attack / Verification Lens

JIT-Agent 几乎天然是一种 meta-attack generator。如果把 environment reward 改成“成功恢复被忘知识”，它可以自动选择 memory策略、search breadth、subagent delegation、候选验证与停止条件。可定义 Harness Robustness Envelope：在固定预算的可接受 harness family 内，unlearned model 的最大 leakage；以及 Harness Sensitivity：不同harness下forget score方差。

5.22 与另外 Top Paper 的关系

ATU 训练时假设一个给定 agent framework 与一组 recovery tools；JIT-Agent 说明 downstream deployer完全可能动态生成更强的 harness。于是 ATU 的真实 adversary 应该升级为：不仅控制 prompt 和 tools，还能优化 harness 本身。这形成今天最重要 collision：Agentic Tool Unlearning 的 threat model 仍可能低估 “Adaptive Harness Recovery”。

5.23 如果只让我记住这篇论文

  1. Agent能力不是模型权重单独决定，而是model–harness pair决定。
  2. JIT-Agent不是优化一个harness，而是训练“生成harness的模型”。
  3. harness被统一为Memory、Planning、Action、Capability四模块。
  4. Stage I学task-conditioned生成，Stage II学修坏harness，Stage III学在线Pareto evolution。
  5. 效率只有在reward不下降时才参与优化，避免用性能换成本。
  6. GLM-5.2平均+7.7，DeepSeek-V4-Flash平均+8.8，Planning最高+24.8。
  7. 同backbone比较成熟runtime时，JIT在6个setting里成本全部最低。
  8. 跨6个backbones×4benchmarks的24个paired comparisons全部提升，平均+7.6。
  9. 它并非每个setting性能第一，因此应看Pareto而非leaderboard。
  10. 对unlearning最重要的启发是：未来攻击者可以优化整个recovery harness，而不只是prompt。

Cross-Paper Synthesis

今天两篇共同推动一个很重要的系统观：LLM safety / unlearning 不应再把“模型”当作唯一边界。

共同趋势：从 parameter-centric AI 走向 execution-system-centric AI。

可组合 mechanism：ATU 的 trajectory reward + JIT 的 harness synthesis。前者可做 defender，后者可做 adaptive attacker/verifier。

值得借用的实验范式：ATU 的 standalone→agent→no-tool→swapped-tool 分解；JIT 的 fixed-backbone controlled harness comparison + cost Pareto。

最可能形成新论文的 gap：Harness-Adaptive Unlearning Recovery / Harness-Invariant Unlearning Robustness。

最适合作 baseline：ATU 作为 agentic unlearning baseline。

最适合产生 attack：JIT-Agent。

最适合产生 benchmark/metric：二者组合出的 Harness Robustness Envelope + Agentic Recovery Gap。

Combined Research Opportunities

Best Migration Direction — Adaptive Harness Recovery for Unlearning

Unlearned checkpoint → candidate attack goal / target → JIT recovery-harness generator choose memory strategy choose planner choose tools choose subagent/verification pattern → execute under fixed total query/tool/token budget → observe recovery reward → evolve attack harness bank → find worst-case leakage harness → defender trains ATU-style trajectory policy → re-run adaptive harness search → iterate until: worst-case leakage < threshold AND retain/tool utility > threshold

相比你当前 direct/paraphrase/cloze/candidate/context collision，这个方向把 attack surface 从“query formulation”提升到“整个 agentic recovery system”。它能自然统一 TAS、Cloze-Lens、RULER、ATU 与 Agent harness evolution。

Collision / Overlap

Strongest Collision：ATU 已经占据“参数遗忘在 tool-augmented deployment 中被恢复”这个方向，因此如果做相关新工作，不能只换更多tool或把文本换成多模态就结束。更有区分度的是：adaptive harness search、carrier attribution、worst-case harness robustness、cross-modal tool reacquisition。

JIT-Agent 与 Meta-Harness、AHE、Harness-R1、Harness-of-Harness、MASkills 在自动Agent改进上有明显重叠，但核心差异是“训练一个 task-conditioned harness generator + learned bounded repair + bank evolution”，而不是编辑单个durable harness或skill library。
