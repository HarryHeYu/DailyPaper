5.2 一句话定位

RD-Forget把Agent forgetting从“删掉旧事实”改写成“保留完整历史，但针对当前query动态构造只允许合适证据进入的memory view”。

5.3 人话版

用户去年在Acme工作，今年去了Beryl。问“现在在哪里工作？”时，Acme应该被抑制；问“之前在哪里工作？”时，Acme又必须重新可见。若系统直接删除旧值，历史问题失效；若所有旧值一直active，当前问题会被过时信息污染。RD-Forget的核心是将storage与use分离：原始history H持续保留；每次query到来，用curator抽取与问题有关的事实，为同一subject-relation-scope划分slot，新值将旧值标记为SUPERSEDED而非物理删除；historical intent下旧值通过rescue重新eligible；多跳问题则保留完整relation chain。最终只在2048-token预算下构造answer-time Z(q)。实验中四个模型、三个主benchmark的12个组合全部第一；最关键ablation是去掉forgetting后，Luna在LME-KU从93.59降到60.26，说明让旧版本一直active是最大性能杀手。

5.4 Background & Research Gap

传统memory系统常把“存在于存储”与“有资格被检索”绑在一起，但版本化事实天然需要更细的语义。例如Mira先在Acme工作，后去Beryl；Beryl位于Lyon。当前问题需要Mira→Beryl→Lyon，同时必须压制旧Acme；历史问题又要重新访问Acme。单纯recency会误删旧但必要的中间relation，直接delete则永久破坏历史。

RD-Forget填的gap是：在历史不变的情况下，根据query intent与slot-level replacement关系构造一次性的used-evidence view。

5.5 Core Insight

Stored history与used evidence是两个不同对象；replacement必须发生在relation slot内；SUPERSEDED不等于deleted；historical query需要rescue；forgetting与multi-hop closure必须同时考虑。这些观察既是系统设计，也是对“旧事实应该消失还是暂时不参与”的概念澄清。

5.6 Method Deep Dive

Stored history H + query q → query-conditioned curator → extract active evidence → identify older replaced evidence → assign semantic slots → preserve multi-hop chain → materialize ACTIVE / SUPERSEDED entries → historical-intent eligibility → rank candidates → LLM selector → greedy pack under 2048-token budget → answer model → source history remains intact

Curator不看gold answer，只根据query抽最小完整证据。Slot定义subject|relation|scope，同slot的新值才能替代旧值。旧值进入SUPERSEDED状态并保存superseded_by指针。Eligibility决定当前query是否允许读取旧值。Closure要求保留多跳中间事实。最终只压缩Z(q)，不改变source archive。

5.7 核心公式与数学直觉

H=(e1,...,eT) Z(q) ⊆ C(q) Z*(q) ∈ argmin_Z D_q(Z) subject to Σ c(m) ≤ B D_q(Z)=E[d(Y,gθ(q,Z)) | q,H] c(m)=Tok(m.text)+8 B=2048 E(q)=ACTIVE ∪ DEPRECATED(if rescue) ∪ SUPERSEDED(if rescue and historical-intent)

Rate–distortion直觉是：在固定memory-view预算下，尽量不损失answer utility。旧事实对current query可能是distortion source，对historical query却可能是必要证据，因此最优Z*(q)必须query-dependent。核心超参B决定证据容量，但增大B不能替代forgetting，因为更多context也可能把旧值重新带回来。

5.8 Toy Example

  1. H中有Mira→Acme。
  2. 后来新增Mira→Beryl。
  3. 另有Beryl→Lyon。
  4. 问“当前雇主位于哪里？”
  5. Acme与Beryl同employer slot，因此Acme标SUPERSEDED。
  6. Beryl→Lyon是不同relation，仍ACTIVE。
  7. current intent下Acme不eligible。
  8. Z(q)只包含Mira→Beryl与Beryl→Lyon。
  9. 模型答Lyon。
  10. 若问历史工作，Acme被rescue回来。

5.2 一句话定位

Fortunate Recall把Agent memory管理建模成事实生命周期：不同fact type使用不同decay、slot supersession、event-time validity、retraction mask和category-aware routing。

5.3 人话版

身份、航班、偏好、慢性病、deadline并不应该用同一套时间衰减与更新策略。职业身份可能持续几年，航班信息一旦过期应立刻失活，deadline临近时反而更重要，撤回计划应在current query不可见但在change-history query可被追溯。Fortunate Recall提出10+1 behavioral ontology，并为每个事实维护category c、slot key κ、lifecycle state ξ、event-time anchor h，再用deterministic policy做category-specific decay、supersession、expiry、retraction和routing。FR-Bank在516题LifecycleBench上76.9%，高于MemoryOS 70.5；它还显著降低staleness与confabulation。更有价值的是负结果：去掉10+1 ontology，仅保留generic lifecycle metadata后，retrieval correctness只小降约1–2pp，说明真正承载正确率的是slot/state/event-time等通用lifecycle primitives，ontology本身更像calibration与policy-parameter layer。

5.4 Background & Research Gap

统一memory policy无法同时正确处理相反的时间规律。Identity应慢衰减；Logistics应快速过期；Obligation临近时权重上升；Preference需要same-slot supersession；Retracted计划既不能继续当current truth，也不应完全消失。FR填补的是“事实如何随时间存活、替换、过期、撤回、重新检索”的显式生命周期语义。

5.5 Core Insight

分类单位应是fact edge而非整个utterance/entity；age-only decay表达不了event-time；binary present/absent表达不了retraction；单一global衰减参数无法服务所有类别；高retrieval recall可能反而让stale facts进入context并提高confabulation。

5.6 Method Deep Dive

Conversation/source → LLM extraction: fact edge category c slot κ event-time h confidence/retraction cue → persistent memory → deterministic lifecycle update: duplicate supersession state ξ event validity decay λ_c → query category/intention → cosine + BM25 + category-forced retrieval → merge/deduplicate → top-20 distillation → lifecycle filtering: retraction mask expiry backward-looking bypass supersession handling → blended score → top-10 memory → answer

Ontology定义事实的时间行为族；slot决定同属性版本竞争；event-time处理deadline/logistics；state表示active/retracted/superseded；routing弥补abstract query与具体fact之间的词汇gap。LLM主要用于抽取和一次distillation，真正生命周期逻辑是deterministic。

5.7 核心公式与数学直觉

a(e)=exp(-λ_c · Δt) Lifecycle basis: (c, κ, ξ, h) Retraction target: current query → relevance(z)=0 change query → relevance(z)=1 Binary system can only represent: (0,0) delete or (1,1) retain Uniform two-intent Bayes error = 1/2

λ_c是category-specific decay。核心理论是retraction的表示下界：若只有present/absent，就无法表达“当前不可见、历史可见”的(0,1)模式，因此二元memory语义先天不足。与MemoryOS相比，FR不是只做层次summary，而是显式建lifecycle state machine。

5.8 Toy Example

  1. 用户说“下周五飞上海”。
  2. 系统记录Logistical Context和event-time。
  3. 后来用户说“航班取消了”。
  4. 同slot计划进入retracted/expired。
  5. 问“下周五去哪？”旧上海行程被mask。

  7. “我喜欢跑步”属于Hobby，采用更慢decay。
  8. 不同事实使用不同state transition和时间规则。

  5. binary present/absent表达不了retraction。
  6. 高Hit@k不等于高memory quality。
  7. AV7里FR retrieval pass低但E2E正确率高。
  8. FR-Bank在LifecycleBench比MemoryOS高6.4pp。
  9. ontology本身对correctness贡献不大。
  10. unlearning前应先区分ERASE、RETRACT、SUPERSEDE、EXPIRE。
