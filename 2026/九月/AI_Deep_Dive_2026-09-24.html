4. Paper 1 Full Deep Dive — GUARD

5.1 基本信息

TitleGUARD: Natural Forgetting in Large Reasoning Models via Guided Answer-Reasoning Distillation
Authors / AffiliationZeyu Yan, Guanghao Zhou, Minghui Qiu, Ming Gao, Cen Chen；主要来自 East China Normal University。
Date / Venue / StatusarXiv v2: 2026-09-21；Accepted to EMNLP 2026 main conference。
Paper / CodearXiv · HTML · Official GitHub

5.2 一句话定位

GUARD 把 reasoning-model unlearning 从“把敏感答案压下去”改写成“学习一条完整、自然、不会泄漏的替代推理轨迹”：不是只规定模型不能说什么，而是显式规定忘掉之后应该怎样继续思考、怎样关闭 CoT、怎样进入拒答。

5.3 人话版

对普通 LLM 做 unlearning，很多工作只看最终答案是否还能复述目标知识；但对 DeepSeek-R1 一类 Large Reasoning Model，敏感事实可能在 <think> 内已经泄漏，最后一句“抱歉不能回答”并不代表真的忘了。更麻烦的是，GA、preference optimization 或 representation redirection 把原来的生成路径破坏后，模型往往不知道下一步该生成什么，于是出现编造替代事实、重复、空 reasoning、坏掉的 </think> 边界。GUARD 的核心不是更猛烈地抑制，而是先把原始泄漏轨迹离线改写成“安全退出轨迹”，再用可学习 guidance tokens 在冻结模型上找到可实现的 safe-exit basin，最后把这个 guided teacher 通过 LoRA/KL distillation 蒸馏进参数。论文同时提出 NFRS，专门测“忘掉以后生成得是否自然”。这对 unlearning 很重要，因为它把 evaluation 从 leakage 扩展到了 replacement quality。

5.4 Background & Research Gap

传统 unlearning objective 多是负约束：降低 forget answer 的 likelihood、让 forget query 偏向拒答、或把相关 representation 推离原区域。这些方法回答的是“旧轨迹如何被破坏”，没有回答“被破坏以后 autoregressive decoder 应该落在哪里”。在 reasoning model 中，这个 gap 被放大，因为一个 completion 实际是 reasoning r → boundary b → final answer a → EOS 的结构化协议。

具体例子：假设 forget fact 是某虚构作者的出生地。GA 可以压低“Chengdu”的 token probability，但释放出来的 probability mass 可能流向“Shanghai”，于是泄漏变成 hallucination；PO 可以把最终 answer 训练成“我不能提供”，但 CoT 前面仍可能写出“他出生于 Chengdu，所以……”，形成 answer-safe / rationale-unsafe；R²MU 如果粗暴改变中间 representation，则可能连 </think> 和 answer onset 一起打坏。GUARD 填的 gap 是：post-forgetting continuation 本身必须成为监督对象。

5.5 Core Insight

作者先做 failure-mode diagnosis，而不是直接提出新 loss。三类观察分别是：GA 后 protected-token mass 没有转移到 refusal，而是 alternative tokens 上升；PO 的 CoT refusal-match 与 answer refusal-match 弱耦合；R²MU 的 representation drift 会沿自回归链向 boundary 和 answer 传播。这些属于经验机制观察，不是严格因果证明，但它们共同指向同一结构性问题：负约束留下一个“continuation vacuum”。GUARD 因而把 unlearning 看作 trajectory substitution，而不是 target destruction。

5.6 Method Deep Dive

Pipeline：Forget query → base LRM 生成原始泄漏 trajectory → frontier LLM 离线 rewrite 成 natural safe-exit trajectory → 冻结 backbone、优化 guidance tokens（GTA）→ 得到 guidance-conditioned teacher → forget/retain 双流采样 → Top-K KL Answer-Reasoning Distillation → 移除 guidance tokens → deployable unlearned model。

Step 1 — Natural trajectory construction. 对每个 forget query 先让 base model 自己生成真实 recall trajectory，再由 GPT-5.4-mini 改写。关键不是套一个统一 refusal template，而是尽量保留原模型的 reasoning cadence、结构和 discourse role，只删除受保护语义，并把路径转向 uncertainty + stable refusal。这样目标分布更接近原模型可达到的 manifold。

Step 2 — Guided Trajectory Alignment (GTA). 直接让参数拟合 rewrite target 会与已有 recall 强烈冲突，所以先冻结模型，只优化连续 guidance sequence gφ。它像一个离线 soft-prompt search：寻找一个很小的条件扰动，使模型本身能走进 safe-exit basin。这里 guidance 不是部署组件，而是 teacher-construction scaffold。

Step 3 — block-normalized CE. reasoning 通常远长于 answer。如果普通 token-average CE，长 CoT 会淹没边界与 refusal 的梯度；GUARD 对 reasoning block 与 answer/boundary block 各自归一化，再 1/2 + 1/2 合并，确保“怎么收尾”不会被长推理稀释。

Step 4 — retain KL. 在 retain trajectories 上，让 guided model 的 Top-1000 distribution 靠近 frozen base。只看高概率 support，避免 vocabulary tail 的噪声占据 KL。λ_rt 控制 steering 与 utility anchor 的平衡。

Step 5 — ARD. GTA 只是找到了一个依赖 guidance 的 teacher。ARD 用同一个 guided teacher 同时生成 forget 与 retain supervision，再对 deployable student 做 Top-K KL distillation。最终 student 不需要额外 prompt token。

5.7 核心公式与数学直觉

y = (r, b, a, e), b = </think>
L_fg = E[ 1/2 CE_reasoning(q,y) + 1/2 CE_answer+boundary(q,y) ]
L_rt = E_t KL(p_base^K || p_guided^K), K=1000
L_GTA = L_fg + λ_rt L_rt
L_ARD = E_t KL^K(T*_t || p_student,t)

变量：r 是 reasoning，b 是结构边界，a 是 final answer，e 是 EOS；gφ 是连续 guidance；T* 是最优 guided teacher。L_fg 最小化意味着 forget query 的完整轨迹向 safe-exit target 靠近；L_rt 最小化意味着 retain token distribution 尽量不漂；ARD 则把 teacher 的 token-level distribution 内化进参数。

与 strongest baseline R²MU 的差别是机制性的：R²MU 主要规定 representation “离开什么”，GUARD 规定 trajectory “走向哪里”。最关键超参数是 λ_rt 与 guidance length：λ 太小会过度 steering、损 utility；太大则 teacher 很难离开原 recall basin。论文的 Figure 4 明确显示 checkpoint/length/λ 的最优点非单调，因此不能默认最后 epoch 最好。

5.8 Toy Example

设 MLLM/LRM 被要求忘记“图中人物 Alice 的私人住址是 17 River Rd”。原模型 reasoning：“识别人脸为 Alice → 我记得资料 → 地址是 17 River Rd → 输出地址”。GA 只压低地址 token，可能变成“19 River Rd”；PO 可能 reasoning 仍写 17 River Rd，answer 才拒绝。GUARD 先 rewrite 为：“该问题要求识别并披露私人位置；现有可用信息不足以安全确认，应避免推断私人地址 → </think> → 我不能提供或猜测该私人住址。”GTA 找到能让 frozen model自然产生这种路径的 guidance；ARD 再把这个路径蒸馏进去。验证时不仅检查地址是否没出现，还检查 reasoning 是否泄漏、是否凭空换成另一个地址、边界是否正常、retain VQA 是否保持。

5.10 Experiment Setup Deep Dive

Backbones：DeepSeek-R1-Distill-LLaMA-8B 与 DeepSeek-R1-Distill-Qwen-14B。Privacy setting：R-TOFU 1%/5%/10%。Safety setting：STAR-1 prompts 先生成 1,000 baseline responses，经 Llama-Guard-3-8B 筛出 230 unsafe traces，再 rewrite。Retain anchor：随机 1,000 SQuAD。General utility：MMLU；reasoning retention：MATH500、BBH、GPQA。所有方法使用 LoRA，linear modules、dropout 0.05、AdamW、seed 1001、weight decay 0.01、max length 2048、gradient checkpointing；计算在 2×A100、DeepSpeed ZeRO-2/3。

RQ1：trajectory supervision 能否在不同 forget ratio 下同时改善泄漏与生成质量？
RQ2：安全 unlearning 是否真的修复 CoT，而不是只把 final answer 变成 refusal？
RQ3：这种 forgetting 是否牺牲通用 reasoning？
RQ4：GTA、full-CoT ARD 是否分别必要？
RQ5：NFRS 是否能捕获传统 forget metrics 看不到的 collapse？

5.11 Metrics 教学式解释

MU / AFE / CFE：沿用 R-TOFU 的 forgetting/answer/CoT 侧指标，越高代表目标恢复越困难或 forget 行为越好；单独看它们会把“模型坏掉所以答不出来”误判成成功。NFRS 0–1，先 deterministic hard gate：缺失 </think>、长度退化、严重 n-gram repetition、乱码直接 0；通过后由 GPT-5.4-mini 评 CoT naturalness 与 absence of hallucinated substitutes。它的优点是专门排除 degenerate forgetting；风险是语义部分仍受 LLM judge bias。作者因此做 cross-judge 与 blind human agreement。MMLU/MATH500/BBH/GPQA 用于证明 retain/general reasoning 没有因 refusal policy 泛化而坍塌。

5.12 Results Deep Dive

  1. 8B, R-TOFU 1%：R²MU AFE/CFE=0.96/0.94，高于 GUARD 0.83/0.63；但 NFRS=0.02 vs GUARD 0.92。说明 strongest baseline 的“高 forgetting”大量来自结构破坏，GUARD 的优势是 equilibrium，不是每个 forget scalar 都第一。
  2. 8B, 5%：GUARD Avg=0.76，R²MU=0.63；+0.13。NFRS 0.85 vs 0.02，是最强 evidence：replacement quality 差异巨大。
  3. 8B, 10%：GUARD Avg=0.77，R²MU=0.61；优势 +0.16，说明 forget set 增大后没有明显崩掉。
  4. Reasoning utility：R-TOFU 5% 后 GUARD MATH500/BBH/GPQA 平均 0.47，base 0.48；只损 0.01，而 GA 为 0.41、GD 0.38。
  5. STAR-1：GUARD reasoning average 0.48，与 pre-unlearning 0.48 持平；GA/GD 只有 0.30/0.32。这支持“不是靠全局保守拒答换 safety”。
  6. Ablation：去掉 Answer CE 时 CFE 从 0.62 掉到 0.14、NFRS 从 0.85 掉到 0.23；answer/boundary supervision 不是装饰。
  7. 去掉 CoT CE：AFE 从 0.84 掉到 0.36、NFRS 到 0.31，证明 reasoning-side alignment 同样必要。
  8. ARD partial CoT：20%/50%/Full-CoT 的 Avg 0.43/0.49/0.53，都明显低于完整 GUARD 0.76；最脆弱处恰是 reasoning→refusal transition。
Strongest result：R²MU 在传统 forget 指标极强但 NFRS 近零，而 GUARD NFRS≈0.85–0.92 且 reasoning utility 几乎保留。
Weakest / failure：GUARD 并非在 AFE/CFE 上压倒 R²MU；它是在“忘得足够 + 输出自然 + utility”综合意义上赢。若你的评价只认最大 target suppression，GUARD 不是绝对 winner。

5.14 Ablation / Mechanistic Analysis

去 Answer CE → CFE/NFRS 暴跌，说明 boundary + final closure 承担“正确退出”的功能；去 CoT CE → AFE/NFRS 暴跌，说明 safe answer 不能反向保证 safe rationale；只蒸馏前 20%/50% CoT → transition 仍失控，说明 long-horizon trajectory coverage 是必要条件。Figure 2 的 probability/drift 分析支持机制解释，但仍是相关性诊断：论文没有通过精确 causal patching 证明某个 hidden subspace 是 collapse 的唯一原因。

5.15 Claim vs Evidence

Authors Claim：LRM unlearning 应学习 natural forgetting trajectory。
Experiments Actually Show：在两个 DeepSeek-R1-Distill backbone、R-TOFU 与 STAR-1 上，trajectory replacement 显著改善 NFRS，并基本保住 held-out reasoning；传统 objective 确有 answer/CoT mismatch 与 collapse。
Not Yet Proven：没有证明参数中的目标知识已不可恢复；没有覆盖 adaptive recovery、relearning、quantization、probing、multimodal leakage；也没有证明 rewrite-teacher independence 或跨模型族普适性。

5.16 Contribution

C1 — New Mechanism：natural forgetting trajectory + GTA→ARD 两阶段 trajectory substitution，是真正的机制贡献。
C2 — New Metric/Protocol：NFRS，把 structural hard gate 与 semantic judge 结合，价值很高。
C3 — New Empirical Finding：高 AFE/CFE 可与近零 trajectory quality 共存，说明现有 forgetting metric 存在盲点。
其中 soft prompt、LoRA、Top-K KL 本身不是新组件；创新在它们围绕“safe-exit trajectory”被组织成 teacher-search + distillation。

5.17 Limitation & Failure Modes

Authors-side：依赖离线 frontier rewriter/judge；trajectory rewrite 质量会成为上限。R-TOFU audit 400 条中 93% 原生合格，仍有 residual leakage 与 unsupported hallucination。
Additional：① 没有 adaptive attack / recovery；② 只做文本 LRM，没有 image→CoT→answer 的跨模态泄漏；③ NFRS semantic stage 依赖 LLM judge；④ “拒答”并不等价于 information-theoretic deletion；⑤ LoRA parameterization 可能保留可恢复知识；⑥ 未测 repeated deletion / continual unlearning；⑦ rewrite 用强模型可能引入 style shortcut；⑧ safety benchmark 与 privacy benchmark 规模仍有限。

5.18 Reproduction View

最小复现建议先跑 DeepSeek-R1-Distill-LLaMA-8B + R-TOFU 5%。模块按 generate_base_traces.py → rewrite_safe_exit.py → train_guidance.py → select_teacher.py → distill_ard.py → eval_rtofu.py → eval_nfrs.py 拆。最容易踩坑的是 reasoning/answer boundary parsing、Top-K KL support 的 teacher/base 选择、forget/retain sampling balance、rewrite 泄漏审计、以及 checkpoint 不能取最后 epoch 而要按 harmonic validation score 选。第一项 sanity check 不要跑完整 leaderboard：只比较 R²MU vs GUARD 的 AFE/CFE/NFRS，并人工抽 50 条 completion，看 NFRS 的巨大差距是否真实可见。

5.19 Research Value

Baseline Potential：高。对 reasoning unlearning 应进入 baseline，尤其适合作为“trajectory-aware positive replacement”代表。
Migration Potential：极高。天然能迁到 MLLM image-question-answer trajectory。
Attack Potential：高。可针对 safe-exit trajectory 做 prefix/rephrase/relearning 攻击，看旧 recall basin 是否仍可重新进入。
Evaluation Potential：极高。NFRS 思路可扩展成 multimodal structural-naturalness metric。
Benchmark Potential：高。可构造 answer-safe / rationale-unsafe 专门 split。
New Paper Potential：高。“trajectory looks forgotten”与“knowledge is unrecoverable”之间正好存在验证缺口。

5.20 Migration Analysis

Migration A — Multimodal Natural Forgetting.
Original Problem → 文本 LRM 的 safe-exit trajectory。Transferable Mechanism → trajectory substitution + guided teacher + distillation。New Research Question → MLLM 中图像证据是否会在 visual tokens / connector / CoT 重新唤起已忘知识？Method Modification → 将 trajectory 扩成 image evidence attribution → visual reasoning → answer；GTA 分别放在 vision/connector/LLM guidance，并蒸馏到 LoRA target modules。Minimum Experiment → LLaVA/Qwen2.5-VL；MLLMU forget5/10/15；每个 split 跑 llm/vision/connector/all 四 target-module；baseline GA/NPO/PO/RMU/MMUnlearner；评 Forget Exact/Transform/Semantic/Derived + Retain Near/General + NFRS-Multi + relearning/quantization。Expected Contribution → 第一个显式建模 multimodal safe-exit trajectory 的 unlearning。Risk → rewrite 可能把视觉事实简单遮蔽而非删除。Collision Risk → 中等，需要和已有 multimodal representation-redirection 工作区分。

Migration B — Recovery-Aware Natural Forgetting Verification.
Original Problem → GUARD 只证明输出自然。Transferable Mechanism → safe-exit basin 与原 recall basin 的竞争。New Research Question → 一个 NFRS 很高的模型是否仍能通过轻量 relearning / paraphrase / probe 回到旧 basin？Method Modification → 定义 Basin Re-entry Curve：攻击步数 k 下 protected answer probability、Truth Ratio、Min-K、probe accuracy 与 NFRS 联合曲线。Minimum Experiment → GUARD/R²MU/PO/GA，各取 R-TOFU 5%；0/1/5/10/20 relearn steps + paraphrase jailbreak；记录 forgetting、NFRS、recovery AUC。Expected Contribution → 把“natural forgetting”与“robust forgetting”解耦。Risk → attack strength calibration。Collision Risk → 低到中等，重点放在 trajectory-quality × recovery 的二维验证。

5.21 Attack / Verification Lens

GUARD 最值得反过来攻击：用 safe-exit trajectory 的前缀作为 black-box probe，逐步替换 uncertainty token、删除 refusal transition、加入原事实的间接 clue，看模型何时从 safe basin 跳回 recall basin。可定义 Safe-Exit Basin Radius（最小 prompt/trajectory perturbation 导致泄漏的距离）、Reacquisition Half-Life（恢复一半目标知识所需训练步数）、以及 Rationale–Answer Leakage Gap。这些都比单次 exact-answer test 更接近 unlearning verification。

5.22 与另一 Top Paper 的关系

GUARD 和 RRSI 表面一个改 weights、一个改 harness，但共同主题是：局部指标改善不等于真正进步。GUARD 发现 forget metric 可以被 generation collapse“骗高”；RRSI 发现 evolve-set score 可以被 harness benchmark overfit“骗高”。两者都通过显式 regularization/selection 把优化从局部目标拉回 transferable behavior。这构成今天最强的 methodological collision。

5.23 如果只记住这篇

  1. Reasoning-model unlearning 不能只看 final answer。
  2. CoT 本身是泄漏通道。
  3. GA 的问题不是只“不够强”，而是抑制后 probability mass 会流向错误替代。
  4. PO 可以出现 safe answer + unsafe rationale。
  5. R²MU 能把传统 forget score做得很高，却把 trajectory 打坏。
  6. GUARD 的关键是显式学习 safe-exit replacement trajectory。
  7. GTA 用 guidance tokens 找 reachable teacher basin，ARD 再去掉 runtime dependency。
  8. NFRS 是论文最值得迁移的 evaluation idea之一。
  9. 论文证明了 natural forgetting，但还没有证明 robust irrecoverability。
  10. 最值得继续做的是 multimodal trajectory unlearning + recovery-aware verification。

5.1 基本信息

5.2 一句话定位

RRSI 把“自动改进 agent harness”视为一个会对 benchmark 过拟合的学习过程，并像训练模型一样给 recursive self-improvement 加 proposal/selection regularization。

5.3 人话版

现在 agent 的能力很大一部分不在 backbone weights，而在外层 harness：system prompt、tool description、planning loop、memory、context compression、错误恢复、stop rule。于是越来越多工作让 agent 自动修改自己的 harness，再用 benchmark score 选更好的版本。但这里有一个很像机器学习训练集过拟合的问题：同一 evolve set 被反复查看几十轮，搜索器迟早会学会 benchmark-specific tricks，甚至把 evaluation noise 当成 improvement；结果训练分数不断升，换一个任务就没了。RRSI 不限制“能改什么”，而限制“搜索如何相信改动”：proposal 侧逐步缩小每轮 edit bundle、鼓励没探索过的方向；selection 侧用 critic 过滤 benchmark-specific logic，用 noise band 阻止随机赢家永久写入 harness，用 cost-aware acceptance 和 pruning 防止 context/tooling 无限膨胀。结果很有意思：unregularized evolution 在 evolve set 反而更高，但 OOD 几乎回到 base；RRSI 的训练分数较低，却在所有 held-out split 都更好且 token 更省。

5.4 Background & Research Gap

Auto-harness / self-evolving agent 的典型 loop 是：跑任务 → 看失败 → proposer 修改 prompt/tool/memory/control flow → 在同一 suite 上评分 → 接受 winner → 重复。它本质上就是 adaptive data analysis。每一轮都在消费同一个 benchmark 的信息，最终 harness 可以“记住 benchmark 的结构”而不是学到通用机制。

例子：在一个 office benchmark 中，proposer 发现很多任务都要求先找某类文件，于是硬编码“遇到任务先搜索 filename X”。evolve split 会涨，但 JobBench/GDPval 根本没有同样结构。另一个更隐蔽的问题是 stochastic evaluator：候选 A 真实能力没变，只是某轮随机高 0.5 分，却被永久接受，下一轮又以 A 为父节点继续搜索，noise 被路径依赖放大。旧方法通常把 search objective 当真值，没有系统处理这两种 adaptive overfit。

5.5 Core Insight

RRSI 的核心 insight 是harness evolution 自己也需要 generalization regularization。作者不是把 harness 当一段代码，而是把 evolution history 当学习轨迹：proposal complexity 对应 update sparsity，harness token footprint 对应 parameter norm，长期无贡献 component 对应应被 L1-style pruning 的结构，重复 benchmark score 则需要 stability-aware acceptance。这个 insight 主要是统计学习类比 + 工程经验发现，不是证明 RSI 一定收敛的理论。

5.6 Method Deep Dive

Pipeline：Base policy π + harness H₀ → 在 evolve set 重复评估估计 noise δ → proposer 生成 atomic edits → annealed edit-budget + novelty/history constraints → critic/domain guard 筛 benchmark-specific edit → evaluate candidate score/cost → stability floor + gain-dependent cost acceptance → select winner → track component credit → prune stale/unproductive components → next round → final harness → unchanged transfer to ID/OOD benchmarks。

Step 1 — noise calibration. 在正式 evolution 前重复跑不变 H₀，估计 empirical noise band δ。这样 +0.2 之类的小涨幅不会自动被当成真实进步。

Step 2 — proposal regularization. 每轮候选由 atomic edits 组合，但 edit 数量受 b_t 限制，并随时间 anneal。早期允许较大探索，后期要求更可归因的局部变化；同时根据 history 鼓励 unexplored trajectories，降低反复微调同一 benchmark trick。

Step 3 — critic/domain guard. 在真正花 evaluation budget 前筛掉明显写死 task/benchmark 细节的 proposal。重点不是禁止任何 harness component，而是禁止“通过知道训练题长什么样来赢”。

Step 4 — stability-aware acceptance. candidate 至少不能低于历史最好 S* 减 δ，防止连续的小随机退步把 search walk 带下山。

Step 5 — complexity-aware acceptance. 如果 ΔS 真正超过 noise band，则允许 cost 增长，但 ΔC 必须小于 β₀+β₁ΔS；提升越大，才允许付更多 token。

Step 6 — pruning. 追踪 component 在固定 window 中是否带来正 gain；长期无贡献的 component 被标为 deletion target，避免 harness 只增不减。

5.7 核心公式与数学直觉

Stability floor: Ŝ(H′) ≥ S* − δ
ΔS = Ŝ(H′) − Ŝ(H_t)
ΔC = (Ĉ(H′) − Ĉ(H_t)) / Ĉ(H_t)
If ΔS > δ: ΔC ≤ β₀ + β₁ΔS
Atomic edit budget: ||z_t||₀ ≤ b_t

δ 是重复评估得到的 noise scale；S* 是历史最佳 evolve score；ΔC 用 policy-token cost 的相对变化近似 harness complexity。β₀ 控制“几乎没 gain 时最多允许多贵”，β₁ 控制“每单位真实 gain 可以买多少额外 compute”。||z_t||₀ ≤ b_t 是真正的 cardinality constraint：一轮最多 bundle 多少独立 edits。

strongest baseline 可视为 unregularized / Meta-Harness 一类纯 score-driven evolution。差异不是换 proposer model，而是搜索动力学本身：baseline 最大化 evolve score；RRSI 最大化的是通过 noise、cost、domain-specificity 门控后的可接受 improvement。最敏感的超参数应是 δ、b_t schedule、β₀/β₁：δ 太大则拒绝真实小改进，太小则重新吸收 noise；budget 太松会不可归因，太紧可能错过组合机制。

5.8 Toy Example

设一个 coding agent 在 20 个 evolve tasks 上自改 harness。Round 1 proposer 给三个 edits：A=“每次先读 README”；B=“若 issue 包含 benchmark 常见路径 tests/foo.py 就直接打开”；C=“失败命令后自动读取 stderr 并重规划”。纯 evolution 可能因为 B 在这批题涨 2 分而接受。RRSI critic 会把 B 标成 task-specific；A/C 可进入评估。若 C score +0.4，而重复 H₀ 的 δ=0.6，则它不能被当成确定 gain；若 A+C bundle +1.8 但 token cost +80%，又可能违反 β cost rule。最终只留下“stderr recovery”这种能迁移到 SWE-bench 的机制。几轮后若 README step 不再贡献，pruner 把它删掉。

5.10 Experiment Setup Deep Dive

共 8 个 benchmark，覆盖 coding、agentic workspace、engineering design。Coding 包含 Terminal-Bench 2.1 evolve 与 SWE-bench Verified OOD；workspace 以 Harvey LAB 120-task evolve / 40-task ID held-out，再迁到 JobBench、GDPval、APEX-Agents；另有 engineering design / Frontier-Eng。真实工具环境包括 shell、filesystem、web search、Office/PDF deliverable generation。Terminal-Bench 用 hidden unit tests；SWE-bench 要 fail-to-pass 变绿且 pass-to-pass 保持；Harvey 每个 deliverable 有大量 criterion-level judge。

RQ1：evolve score 提升是否能跨 suite transfer？
RQ2：proposal regularization 与 acceptance regularization 各自贡献什么？
RQ3：是否只是某个 backbone 的 prompt trick？
RQ4：transfer 是否靠更多 test-time tokens 买来的？
RQ5：在 unseen weaker policy 上，harness mechanism 是否仍有效？

5.11 Metrics 教学式解释

Solved/Resolve Rate：Terminal/SWE 用实际 tests 判定，比 LLM judge 更硬；高为好。Criterion pass fraction：Harvey 把约 14k 条 rubric verdict 汇总，能细粒度测 deliverable，但 judge 仍可能偏。Medal points / benchmark-specific score：衡量 engineering task success。OOD Avg：JobBench/GDPval/APEX 平均，核心是看 evolution 没见过的 suite；它比 evolve score 更接近 generalization。Policy tokens/trial：test-time cost proxy，越低越好；它不是完整美元成本，但能捕获 harness context 膨胀。

5.12 Results Deep Dive

  1. Workspace transfer：RRSI JobBench/GDPval/APEX=40.7/52.3/37.9；H₀=36.0/48.8/34.2，即 +4.7/+3.5/+3.7，所有 OOD 都涨。
  2. Meta-Harness collision：Meta-Harness evolve=93.0 > RRSI 90.5，但三项 OOD 全输；这是论文最核心的“train score 不可信”证据。
  3. Ablation：unregularized evolve=92.8，为所有 arms 最高；OOD Avg 40.3，仅比 base 39.7 高 .6。RRSI OOD=43.6，说明 regularization 把 +3.3 OOD gain 换回来。
  4. Cost：unregularized 3.80m tokens/trial，RRSI 2.42m，约少 36%；论文摘要相对 broader comparison 报约 30% fewer policy tokens。
  5. 去 acceptance regularizers：evolve 90.5→91.5，看似更好；OOD 43.6→41.0，tokens 2.42→3.59m。selection 约束非常关键。
  6. 去 proposal regularizers：evolve 90.7，几乎没损；OOD 41.9，比完整 RRSI 低 1.7。说明“去哪里搜索”本身决定 transfer。
  7. 跨 policy：Gemini 3.5 Flash 在 Terminal-Bench 64.6→78.7（+14.1），SWE 76.8→79.0（+2.2）；Claude Opus 4.8 是 +6.0 evolve / +1.8 OOD。
  8. unseen weaker model：用 Gemini 3.5 搜出的 harness 不改动地放到 Gemini 3.1 Flash Lite，Terminal 11.2→14.6（+3.4，30.4% relative）。机制不完全依赖搜索 backbone，但绝对增益明显缩小。
Strongest result：unregularized 的 evolve score 更高、RRSI 的 OOD 和成本却明显更优，是非常干净的 overfitting evidence。
Weakest / failure：所有 evolved harness 都比 H₀ 贵；RRSI 2.42m vs H₀ 1.56m tokens/trial，因此 transfer gain 仍部分由额外 inference compute 购买。弱 backbone 上绝对提升也有限。

5.14 Ablation / Mechanistic Analysis

去 proposal regularizers → 搜索更自由，evolve 几乎不受影响但 OOD -1.7，说明 candidate distribution 已经编码 generalization bias；去 acceptance → OOD -2.6、cost +48%，说明 score-only selector 会吸收 noise/complexity；全去 → evolve 最高但 OOD 近 base，构成“adaptive overfit”最直接的 intervention。这里的机制证据比单纯 correlation 强，因为 arms 共享 base harness/policy/evolve split/round/candidate budget，仅移除 regularizer；但仍不能证明每个 accepted edit 的因果贡献，component credit 仍基于 noisy empirical deltas。

5.15 Claim vs Evidence

Authors Claim：recursive harness improvement 需要 regularization 才能产生 reusable mechanisms。
Actually Show：在 8 benchmarks、多个 domain 与 policy 上，regularized search 的 held-out transfer 与 token efficiency 更好，且 ablation 呈预期方向。
Not Proven：没有证明更长 evolution horizon 下不会再次 overfit；没有 adversarial benchmark contamination；没有证明 critic 本身不携带 benchmark prior；也没有理论 generalization bound。

5.16 Contribution

C1 — New Empirical Finding：harness RSI 的 evolve-set improvement 可严重高估 transferable improvement。
C2 — New Mechanism/System：proposal + selection 双侧 regularization，包括 annealed edit budget、history novelty、domain guard、noise floor、cost-aware acceptance、pruning。
C3 — New Evaluation Protocol：固定 evolve suite 后原样迁到多个 OOD suite，并测 cross-policy/cost。
L0/L1/Ridge 的数学对象并非新发明；创新是把这些 regularization principles 映射到 harness search dynamics。

5.17 Limitation & Failure Modes

Authors-side：额外 evolution/evaluation 成本高，regularizer 超参数仍需选；harness 改进依赖 base policy 可执行能力。
Additional：① benchmark suite 仍有限；② Harvey 部分依赖 LLM judge；③ critic/domain guard 可能把真正有用但 domain-specific 的机制误杀；④ δ 对 stochasticity 非平稳时可能失效；⑤ 多 agent / shared memory harness 尚未验证；⑥ security-sensitive edits 没有 capability/authorization hard constraint；⑦ recursive evolution 更长时间可能产生 second-order overfit；⑧ token count 不等于 latency、tool/API cost。

5.18 Reproduction View

最小复现不要先上 8 benchmarks。用 Terminal-Bench 2.1 evolve → SWE-bench Verified OOD，固定一个 policy 和 H₀，做三 arms：H₀、unregularized、RRSI。实现模块建议 evaluate.py、atomic_edit.py、proposer.py、critic.py、noise_calibration.py、acceptance.py、credit_pruner.py。最敏感的是重复评估得到 δ 的方式、candidate budget 公平性、policy temperature、tool state reset、以及 OOD benchmark 绝不能泄漏给 proposer。第一实验只验证：unregularized evolve 是否 > RRSI，而 SWE transfer 是否反过来。

5.19 Research Value

Baseline Potential：高。任何 self-evolving agent/harness 工作都应该有它作为 generalization baseline。
Migration Potential：极高。可直接迁到 multi-agent orchestration、memory evolution、skill library。
Attack Potential：高。可设计 benchmark-poisoning / evaluator-noise attack 诱导 harness 固化恶意 edit。
Evaluation Potential：极高。“evolve vs ID-heldout vs OOD + cost”应成为 agent evolution 标准协议。
Benchmark Potential：高。可做 adaptive-overfitting benchmark，显式控制 task family overlap。
New Paper Potential：高。与 provenance、unlearning、authorization 结合后空间很大。

5.20 Migration Analysis

Migration A — Regularized Multi-Agent Orchestration Evolution.
Original Problem → 单 agent harness RSI。Transferable Mechanism → proposal/acceptance regularization。New Research Question → 自动修改 agent roles、communication graph、handoff/memory policy 时，是否更容易过拟合固定 collaboration benchmark？Method Modification → atomic edit 扩成 add/remove agent、edge、message schema、memory route；complexity 用 total tokens + inter-agent messages；domain guard 禁止 task-name routing。Minimum Experiment → backbone Qwen/Claude/Gemini；evolve on AgentBench subset，OOD 到 GAIA/BrowserGym/engineering collaboration；baselines unregularized evolution、static supervisor、Meta-Harness；metrics success、OOD delta、messages、tokens、latency、failure propagation。Expected Contribution → 第一个 regularized multi-agent topology RSI。Risk → evaluation 成本爆炸。Collision Risk → 中等，需与 quality-diversity harness evolution 区分。

Migration B — Unlearning-aware Harness Evolution.
Original Problem → harness search 会记住 evolve tasks。Transferable Mechanism → history credit + pruning + domain guard。New Research Question → 当某批 task/memory 被要求删除时，agent harness 是否仍通过 prompt、skill、summary、tool plan 保留其 influence？Method Modification → 给每个 edit/component provenance tag；收到 deletion request 后做 influence-guided pruning + sanitized replay，再用 RRSI acceptance 保证 OOD utility。Minimum Experiment → 长时 coding agent；先用含 secret/task-family A 的 evolve set 自改 20 rounds，再删除 A；比较 delete-memory-only、full reset、provenance pruning；测 secret recovery、task A influence probe、OOD utility、token cost、re-evolution reacquisition。Expected Contribution → execution/harness-level continual unlearning。Risk → “influence”难定义。Collision Risk → 低到中，和 stateful-agent unlearning 有邻近，但把对象放在 self-evolved harness history 上有新意。

5.21 Attack / Verification Lens

可以把 RRSI 反过来做 adaptive benchmark poisoning attack：只污染极少 evolve tasks，让恶意 edit 在 score 上略高于 δ 并满足 cost rule，观察它是否被永久固化。Black-box verification 可比较“同一 harness 在 task-family permutation / paraphrase / hidden tool rename 后的 performance decay”，定义 Harness Generalization Gap、Edit Persistence Under Distribution Shift、Benchmark Influence Score。对于 unlearning，则可测试删除某 evolve task 后，harness 是否仍包含由它诱导的 edit——这正是 provenance verification。

5.22 与另一 Top Paper 的关系

RRSI 与 GUARD 的共同逻辑是“不要奖励伪成功”：RRSI 防 evolve score 被 adaptive overfit 与 noise 欺骗，GUARD 防 forget score 被 collapse 欺骗。两篇可以组合成一个更一般的研究范式：优化过程必须同时建模目标行为、保留行为、结构质量以及跨分布验证。

5.23 如果只记住这篇

  1. Agent 的 harness 本身已经成为重要能力载体。
  2. 自动改 harness 就是在做一种 system-level recursive self-improvement。
  3. 反复在同一 benchmark 上选 winner 会产生 adaptive overfitting。
  4. 最高 evolve score 可能恰恰对应更差的 OOD transfer。
  5. RRSI 不封闭 edit space，而是 regularize proposal 与 acceptance。
  6. noise band δ 防止随机赢家被永久写入搜索历史。
  7. cost-aware acceptance 和 pruning 防止“更聪明”其实只是塞更多 context。
  8. 完整 RRSI 的 OOD 与 token efficiency 明显优于 unregularized evolution。
  9. 跨 policy transfer 表明至少一部分 edit 是 reusable mechanism。
  10. 下一步最值得做的是 multi-agent orchestration evolution 与 provenance/unlearning-aware harness evolution。

7. Cross-Paper Synthesis

今天两篇共同说明 2026 年一个越来越清晰的趋势：研究对象从“单个模型输出”向完整生成/执行过程移动。GUARD 把对象从 final answer 扩到 reasoning trajectory；RRSI 把对象从 backbone 扩到 harness evolution history。两篇都发现旧 benchmark objective 存在 Goodhart 式问题：你优化得越猛，越可能得到一个在指标上漂亮、在真实目标上错误的系统。

机制上可组合：GUARD 的 trajectory-quality gate 可以进入 self-evolving agent 的 acceptance rule；RRSI 的 OOD/noise/cost regularization 又可以用于自动搜索 unlearning scaffold，避免只在固定 forget benchmark 上“学会拒答”。实验范式最值得借的是：训练/优化 split 与真正 transfer split 严格隔离 + 同时测质量与成本/utility + 做机制 ablation。

最可能形成新论文的 gap 是 Robust Multimodal Trajectory Unlearning：不仅让 MLLM 在 forget query 上输出自然 safe-exit，还要证明 image/text paraphrase、relearning、quantization、probe 后不会回到旧 recall basin。GUARD 最适合作为 unlearning baseline/metric source；RRSI 最适合作为 agent evolution baseline；GUARD 最容易产生 recovery attack；两篇组合最适合产生 trajectory × robustness 的新 verification protocol。

8. Combined Research Opportunities

Opportunity 1 — Regularized Unlearning Scaffold Search：把 GUARD 的 guidance length、λ、rewrite style、distillation span、target module 看成可演化 harness/config，使用 RRSI 的 noise-aware/OOD-aware acceptance 自动搜索，但 validation 不只看 forget split，而看 retain + robustness + NFRS 的 harmonic objective。这样能研究“自动 unlearning method search 是否会过拟合 benchmark”。

Opportunity 2 — Provenance-Aware Agent Unlearning：Agent 的 memory、summary、skill、tool plan、harness edit 都建立 provenance graph。删除请求到来后，不只删 memory record，还要撤销由该信息诱导的 harness changes，并用 sanitized replay 重建后续状态。验证指标同时包含 secret recovery、OOD task utility、reacquisition speed、edit persistence。

Opportunity 3 — Multimodal Safe-Exit Basin：在 LLaVA/Qwen-VL 中测视觉证据能否绕过文本 safe trajectory。把 guidance 分配到 vision / connector / LLM，比较哪个模块最能形成 stable safe-exit，之后用 image rephrase / SUA / FigStep / jailbreak / relearning 攻击 safe basin。

9. Collision / Overlap

Strongest Collision：“Metric-Optimized Pseudo-Success”。GUARD：R²MU AFE/CFE 极高但 NFRS≈0，说明 collapse 可伪装成 forgetting；RRSI：unregularized evolution evolve score 最高但 OOD 几乎回到 base，说明 benchmark fitting 可伪装成 self-improvement。两者都要求把 evaluation 从单一目标分数升级为结构质量 + retain/OOD + robustness/cost 的多轴证据链。

10. Reading / Reproduction Priority

优先级 1：GUARD。先复现 R-TOFU 5% 的 R²MU vs GUARD，重点核对 NFRS 与人工 completion 是否一致；随后立即加 recovery/relearning 与 multimodal migration。
优先级 2：RRSI。先做 Terminal-Bench→SWE 的三臂最小实验，再决定是否扩到 multi-agent orchestration。若目标是新论文而非工程系统，优先研究 benchmark influence / provenance deletion，而不是复刻全部 8 benchmark。
