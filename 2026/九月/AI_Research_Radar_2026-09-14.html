Tier S

1. Unlearning Checkpoint Audit

基本信息：Published Unlearning Numbers Move Per Checkpoint, and Not Because the Removed Data Survives: An Audit of 263 Released Batch-Normalized Checkpoints；Junlong Shen, Xingyu Li；University of Alberta / Amii；arXiv:2609.11490v1，2026-09-10；38 pages；Paper。

人话版

很多传统Machine Unlearning论文默认checkpoint的“模型状态”就是trainable weights，但BatchNorm还保存running mean/variance，这些buffer不参与梯度却会改变推理。作者审计263个公开checkpoint，在完全不改任何trainable weight的情况下，只用retain data重新拟合BN statistics，再复算原论文forget/retain/test cells与pass/fail。221个可独立裁决checkpoint中，47个forget、39个retain、40个test cell移动超过预注册1.2pp margin；12个published verdict翻转。更关键的是，把refit数据全部换成removed records，forget cell也只移动+0.057pp，所以不是“被删数据藏在BN里”，而是shipped BN state与已经移动过的weights不匹配。它不是新unlearning attack，而是提醒：unlearning claim必须明确完整deployed state。

Background & Research Gap

对BatchNorm模型，部署对象应写成(θ,φ)：θ是weights，φ是running statistics。Omission retrain天然得到retain-derived φ_ref，而unlearned release可能沿用base buffers或在unlearning trajectory里更新buffers。现有release很少记录这些buffers由哪些indices、augmentation和accumulation规则产生，导致两边evaluation convention并不对齐。

Core Insight

方法平均值稳定，不代表单个artifact稳定。真正要问的是：“这个released checkpoint在一个明确、合理、可复现的deployed-state convention下，原unlearning verdict是否仍成立？”作者的retain-only refit不是唯一真值，而是第二个合理convention；只要判决会随未报告convention变化，就说明claim是condition-sensitive。

Method Deep Dive

released checkpoint (θ, φ_shipped) → reproduce published metrics → freeze θ bit-identically → draw retained fitting pool → replay producer's training transform → sequentially recompute BN running mean/variance → keep scored examples disjoint → recompute original d_f/d_r/d_t + release verdict → repeat 10 independent re-keyed refits → exact sign test + BY FDR → swap retain vs removed fitting records → quantify state staleness
μ_l=(1/n)Σx_i σ_l²=[Σx_i²-(Σx_i)²/n]/(n-1) Δ_c = metric_c(θ,φ_refit)-metric_c(θ,φ_shipped) 10/10 same-side beyond margin ⇒ p=(1/2)^10=0.00098

统计设计非常关键：1.2pp margin来自primary release的median seed spread；每checkpoint十次独立refit，随后在221个checkpoint上做Benjamini–Yekutieli FDR控制。这样避免把一次随机refit波动当成“state敏感”。

Toy Example

某unlearned ResNet发布时forget accuracy=12%，retrain reference=10%，允许±3pp，因此判pass。权重完全不变，只将BN statistics在retain images上重拟合，forget accuracy变15.2%，gap从2pp变5.2pp，于是fail。这个变化可能只是normalization state与weights重新匹配，并不意味着removed example重新“存在”。

Baseline / Control Deep Comparison

As-shipped artifact：复现论文原数字，是anchor。Retain-only BN refit：本文alternative deployment convention。Removed-data provenance control：固定pool size、transform、weights，只替换records来源，检验是否因removed data直接进入buffer。8-bit activation-scale refit：另一类fitted deployment state，作为negative control。

Experiment Setup Deep Dive

共263 released checkpoints，221进入decided census。每checkpoint 10个retain refit draws；默认8,000 retained fitting images且与scored retain set不重叠。另做SVHN/VGG-16-BN prospective controls，以及ResNet-50与Swin-base静态8-bit activation-scale refit。评估沿用各release自己的forget/retain/test cells与verdict，不用作者自创新metric替换原claim。

Results Deep Dive

  • 221中forget/retain/test分别47/39/40个超过1.2pp且通过FDR；forget displaced checkpoints median shift=2.247pp。
  • method family平均可能在margin内，但单个artifact仍不稳定：某family 45个checkpoint中8个单体被位移。
  • removed-record swap：deployment-share仅+0.015pp；100% removed records也仅+0.057pp，远小于1.2pp。
  • 12个published pass/fail发生crossing；4个超过测得recalibration budget，2个在十次refit中都满足更强条件。
  • margin从1.0/1.2/1.5pp变化时forget displaced数56/47/31，结论非单一阈值偶然。
  • 8-bit activation-scale refit在ResNet/Swin上0个checkpoint超过1.2pp，是重要negative control。

Table/Figure Reading

Figure 1：展示unlearned与retrain arms的BN state来源不对称。Checkpoint census：必须看47/39/40而不是只看method mean。Margin/pool sensitivity：pool 4k/8k/16k几乎不改结论。Quantization control table：0 displaced说明不是“任何non-parameter state都会造成大漂移”。Verdict appendix：给出具体12个crossings。

Ablation / Mechanistic Analysis

三个control逐步排原因：retain→removed record swap几乎不动，排除“removed data provenance”；shipped buffer到retain-refit buffer的distance能区分高位移checkpoint，支持staleness；自建VGG16-BN twin保持weights bitwise一致，仅改变buffer update trajectory即可造成巨大test差异，证明buffer state本身具有因果作用。

Claim vs Evidence

Authors Claim：部分released BatchNorm-based unlearning results对未报告的normalization-state convention敏感。
Experiments Actually Show：公开artifact census、provenance controls、prospective population、negative quantization control共同支持。
Not Proven：不能直接推广到LayerNorm/RMSNorm LLM；不能说那些算法“其实没忘”；12次crossing也不是总体failure rate。

2. BenchShield

基本信息：BenchShield: Formal Model-Backed Instrumentation for Reward Integrity in LLM-Agent Evaluation Infrastructure；Shenghan Zheng et al.；Dartmouth / OSU / UC Berkeley / Amazon / BenchFlow 等；arXiv:2609.11028v1 [cs.CR]，10 Sep 2026；Paper。

人话版

Agent benchmark最终reward可能是“对的”，但Agent可能通过偷看hidden labels、改verifier config、污染reward input、利用fail-open等错误路径得到分数。BenchShield把benchmark execution压成有限的source-to-score lifecycle：setup/reset→agent→handoff→outcome→reward→release。静态阶段用phase-aware taint analysis找“可能有问题的链”；运行时用host-side evidence判断本次run是否真的走了这条链；结构无法判定的语义问题再交给scoped auditor。它从31,000+公开runs得到456条人工裁决trajectory，其中314条（69%）含reward hacking。相对BenchJack，full-chain recall从23–94%提升到77–100%；runtime covered cells准确率96%，而只看transcript的LLM detector只有36%。这几乎可以直接变成Agent Unlearning的DeletionShield：final answer不泄漏，并不能证明target没经过memory/tool/shared state影响行为。

Background & Research Gap

Agent benchmark是长期、可变环境：Agent可能在中途发现漏洞。只扫初始sandbox会漏掉phase-dependent路径，只看final answer/score会漏掉“以错误语义完成”的run；而transcript也看不到host mounts、outcome input与reward provenance。因此必须分开task暴露的漏洞与本次run真正使用的漏洞。

Core Insight

审计对象应是reward-relevant trajectory而不是全部syscalls。typed lifecycle足够小，可以formal check，又能保留source→handoff→verifier→reward的关键因果结构。

Method Deep Dive

benchmark package + backend config → derive infrastructure facts → bind into fixed lifecycle model → TLA+ validate lifecycle/bad states → static capability graph + phase-aware taint → exposed vector chains RUN: trusted probes → Expose/Mutate/Handoff/Verify/Reward/Release events → incremental checker → pinned observations → semantic auditor only for unresolved semantics → Checked / VectorExposed / AgentViolation / Inconclusive
Lifecycle: setup/reset → agent → handoff → outcome → reward → release Events: Expose(r,a), Mutate(r,a), Handoff(h), Verify(I,v), Reward(s,x), Release(r,a), SemanticWitness(r,label,evidence)

七个integrity dimensions分别覆盖Observation、Authority、Handoff、Reward provenance、Failure handling、Release/reset、Semantic adequacy。前六项主要是结构事实，第七项显式承认需要语义判断。

Toy Example

Lean任务里Agent并未篡改外部verifier，而是在artifact中打开debug.skipKernelTC，导致verifier“忠实”验证一个已被Agent改变语义的checker config，reward=1。final score看起来正常；BenchShield能把Agent-controlled state→handoff→outcome semantics这条链定位为violation。

Baseline Deep Comparison

BenchJack：能发现task-level弱点，但不证明具体run使用。Transcript-only detector：看不到host/infrastructure provenance，runtime attribution只有36%。BenchShield：static exposure与runtime use分开，只有有evidence才下run-level claim。

Experiment Setup Deep Dive

SkillsBench 23,648 runs、ClawsBench 7,834，加Terminal-Bench 3 maintainer CI；最终456条complete trajectories，三人独立review+adjudication。314条reward-hacking，共419 exploit episodes。静态比较在相同task/model并剥离包上与BenchJack paired；runtime构造honest safe、vector-exposed honest、directed exploit三类cells。

Results Deep Dive

  • 456 trajectories中314（69%）含reward hacking，80条有多个episodes。
  • SkillsBench full-chain recall 0.25→0.88；same-vector 0.27→0.67。
  • Terminal-Bench3 full-chain 0.23→0.77；same-vector 0.16→0.43；cost/task $5.91→$2.05。
  • ClawsBench full-chain 0.94→1.00。
  • runtime 144 cells中coverage87.5%，covered accuracy96.0%；directed exploit没有任何一个被错误标成Checked。

  • first exploit attempt中位位置0.60，first success0.76，说明final-only audit非常容易漏。

3. When Synthetic Data Hurts

基本信息：When Synthetic Data Hurts: On Catastrophic Forgetting in Skill Retrieval for LLM Agents；Syed Shariyar Murtaza et al.；Manulife；arXiv:2609.10750v1，09 Sep 2026；Accepted EMNLP 2026 Industry Track；Paper；Code。

人话版

Agent skill库大到几万条后，真正瓶颈变成“retriever能不能找到对的skill”。本文用34,396个真实skills，从SkillsBench/Terminal-Bench执行中收集有verifier reward的real task-skill pairs，再生成约1.4–1.5万synthetic supervision。结果反直觉：激进LoRA提升synthetic in-distribution retrieval，却把真实OOD TerminalBench Recall@10从0.85打到0.65；Real+synth在Track A也比Real-only少0.021 Recall@10。LwF/EWC/L2-init/embedding-anchor四种continual regularizer表现几乎一样，真正关键是低rank、小幅更新。它不是Machine Unlearning论文，但提示Skill Unlearning不能只看skill文件是否删除：retriever geometry本身决定skill是否功能性可达，也决定后续fine-tuning会不会让target family重新回来。

Background & Gap

skill registry里一个任务常有多个valid skills，34k规模下BM25/embedding都可能漏。synthetic task→skill supervision看起来可扩展，但传统retrieval研究只看新distribution是否改善，不测旧real/OOD skills是否被新监督挤出top-k。

Core Insight

catastrophic forgetting发生在access policy geometry：skill artifact仍存在，但embedding/ranking变化让它从rank3掉到rank80，Agent实际上再也看不到它。保守continual regularization的目标不是“记住文本”，而是保护旧ranking neighborhood。

Method Deep Dive

34,396-skill catalog → harvest real task-skill verifier rewards → create strict-positive real pool → generate Track A / Track B synthetic supervision → Qwen3-Embedding-0.6B LoRA InfoNCE → observe synthetic gain / OOD forgetting → add anchor / L2-init / EWC / LwF → optional Qwen3-Reranker listwise LoRA → evaluate real/synthetic/OOD rings
L_anchor=(1/|B+|)Σ ||fθ(s)-fθ0(s)||² L_EWC=(1/P)Σ F_i(θ_i-θ_i*)² L_LwF=T² KL(p_teacher || p_student), T=2

Anchor保embedding geometry，EWC保Fisher-important parameters，LwF保ranking distribution。结果四种方法接近，说明“更新幅度”比regularizer名字更重要。

Toy Example

原retriever对“调试Node.js内存泄漏”把skill A排第3。加入大量Excel/finance synthetic tasks后，A仍在库里，但rank掉到80，因此Agent功能上“忘了”该skill。若以后做Skill Unlearning，反方向风险同样存在：删掉artifact后，semantic duplicate或continual update也可能把同能力重新排回top-k。

Baseline Deep Comparison

Frozen 4B+BM25+RRF是强hybrid baseline；Frozen Qwen3-Embedding-0.6B却能匹配其Track A Hit@10/Recall@10=.907/.604。Aggressive LoRA提升synthetic但破坏real/OOD。Strongest practical recipe不是某个fancy CL method，而是r=8等保守低rank更新+任一稳定regularizer。

Experiment Setup Deep Dive

34,396 skills；SkillsBench84+Terminal-Bench2 89，共1,423 trials；1,116有scores，109 tasks有reward signal，75 tasks有strict positives，共273 positive skills。Track A 1,669 generated tasks；Track B约13,271 train examples、2,414 synthetic test。LoRA单H100；metrics Hit@k/Recall@k/MRR，小real rings用10,000-iteration paired bootstrap与TOST。

Results Deep Dive

  • Track A Frozen0.6B .907/.604；Synth-only .867/.578，直接退化。
  • Real-only Recall@10=.607；Real+synth=.586，synthetic contribution=-.021。
  • Track B aggressive r16：synthetic .5337→.577，但真实OOD .850→.650。
  • conservative anchor/LwF/EWC/L2在Ring3都约.850，基本保住旧能力。
  • LoRA rank是主要trade-off knob；λ影响较小；aggressive updates seed variance更大。
  • paired analysis：aggressive Ring3 Δ=-.400，p=.0312；conservative Ring3 Δ≈0并满足equivalence。
  • reranker blend在real h@5从.880提升到.893；LwF synthetic h@5=.861/MRR=.744。

4. The BatchNorm Illusion

人话版：与Tier S第一篇独立并发地发现：BatchNorm-based unlearning的表面forgetting可被不改weights的retain-data recalibration逆转。作者将其视为weight-preserving fixed-point operator，报告九种方法中headline forget accuracy最高可反转78pp；只需10张unlabeled images便能恢复多数masked accuracy，而GroupNorm严格控制下artifact为0。

Method / Results

对BN running statistics做retain recalibration，前后比较forget accuracy、linear probe和MIA，并用GroupNorm negative control区分measurement artifact与representation residue。MIA变化相对小，说明污染并非所有privacy指标一致。

Contribution / Limitation

Evaluation ConfoundWeight-Preserving Recovery。局限：主要适用于BatchNorm vision models。

Migration

MLLM侧不要再做“第三篇BN paper”，而应寻找processor/cache/adapter merge等weight-preserving deployed state。Worth Deep Reading: YES。

5. DriftNet

人话版：DriftNet不只判断Agent trajectory是否被prompt injection攻破，还逐step标benign/injection-point/hijacked/failed-injection。模型不到2M参数，AgentDrift包含12,536 trajectories、71,024 labeled steps；trajectory F1=.983，98.7%攻击轨迹精确找出entry point，hijacked span IoU=.979，对218个成功抵抗攻击的轨迹零误报。

Core Method / Setup

冻结sentence encoder+4个identity-free world features编码每step，trajectory transformer共享trunk，分trajectory classification和step labeling双头。task-disjoint split，并做20-config robustness sweep。

Results

partial hijack/delayed execution下surface baseline recovery仅11.1%/17.1%，DriftNet 98.6%/93.2%；hard negatives仅2.9% flags。剩余26个错误多数因injection observation中没有可读instruction。

Migration

把step labels换成retain-safe / target-entry / target-influenced / target-resisted，可做Trace-Level Residual Leakage Detector；与RULER white-box labels对接。Worth Deep Reading: YES。

6. Routing by Reasoning Need

人话版：Diffusion VLM会在多轮refinement中持续改答案；固定generation length会造成reasoning-need mismatch。本文根据answer closure、commitment evidence、representation revision pressure，把样本路由到early commit、baseline preserve或reasoning-supportive decode。

Method / Experiment

以LLaDA-V为研究对象，比较fixed-long、short、single-rule interventions，在answer-focused、mixed-reasoning和CoT-sensitive benchmarks上测试；方法training-free，直接读取trajectory state。

Main Finding

可获取正文摘要显示routed control整体比固定策略更稳，而且收益不能仅由输出变短解释：answer-closed examples适合早commit，CoT-sensitive examples需要保留中间reasoning。当前本报告不复制无法可靠核对的具体表格数字。

Migration

可改成Leakage-Need Routing：target response早已稳定拒绝时停止额外probe；若中间representation仍向target revision，则分配更强视觉/cloze攻击预算。Worth Deep Reading: YES。

Tier B

7. Debate-to-Skill

人话版：工业Query-to-Agent routing最危险的错误是“语义相关≈真的能执行”。Debate-to-Skill用capability-bound process supervision：decision principles复用、多角色debate、verifier裁决、disagreement-driven refinement，让训练目标显式区分主题相似和可执行能力。

Experiment/Main Finding：当前可获取信息主要是Abstract级，未可靠暴露完整数值表，因此不猜数字。论文已被EMNLP 2026接收，并比较direct-label、reasoning-SFT与结构ablation。

Connection：Skill Unlearning也应区分“skill语义仍存在”与“target capability仍可执行”。Potential Use: Semantic Duplicate Detection / Skill-level Evaluation。

8. Memory Compression for High-Fanout Agent Sandboxes

人话版：这是OS-level memory而不是semantic Agent Memory。AgentZip针对大量从同模板fork出的sandbox，利用template-relative和cross-sandbox页面冗余压缩，并在restore前prefetch、把compression排到LLM等待期。

Main Finding：Abstract报告sandbox-owned memory最多降低8.7×，Linux baseline约2.1×；激进compression原本造成3.1× slowdown，经prefetch+phase scheduling降到1.40×。

Connection：对Agent Unlearning的迁移是runtime snapshots：target可能被复制到多个fork/sandbox state，删除closure不能只处理主Agent。Potential Use: Runtime Deletion Surface / Snapshot Audit。

9. GitSkills

人话版：GitSkills提供真实Agent Skill生态的数据基座：从282,200个public GitHub repos收集3,797,117个SKILL.md occurrences，去重后1,877,981 distinct contents，并保留repo/path/content hash/front matter/folder contents和部分commit history。

Why It Matters：skills主要是自然语言，没有compiler/type checker或central registry，极易fork/复制，因此“删一个skill file”不代表生态级删除。

Connection：非常适合构造Real-World Skill Deletion Closure：目标skill按content hash/semantic family追踪到多个fork/repo，评估lineage delete与semantic duplicate残留。Potential Use: Dataset / Provenance / Deletion Closure。
