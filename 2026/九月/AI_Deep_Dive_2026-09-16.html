4. Paper 1 Full Deep Dive

The Router Within: Eliciting Native Skill Routing from a Frozen LLM

Agent · Fresh 14 Sep

5.1 基本信息：Ruishuo Chen, Xun Wang, Yu Chen, Zhuoran Li, Longbo Huang；Tsinghua University IIIS；Submitted 14 Sep 2026；arXiv:2609.15982v1；arXiv preprint。
Paper：arXiv · HTML · PDF。正文未给独立公开 Code/Project URL，本报告不猜测。

5.2 一句话定位

Gavel 把几千到几万 Agent Skills 的选择重新交还给冻结 Agent LLM 自己的 hidden states 与 predictive distribution，而不是把所有 metadata 塞进 context 或另挂大型 retriever。

5.3 人话版

Progressive disclosure 的问题是 skill 越多，metadata 越挤上下文；retrieve-and-rerank 虽能扩展，却让一个外部模型替真正执行任务的 Agent 做选择。Gavel 发现 Agent LLM 在理解当前任务时，中间层已经形成“我需要什么能力”的表示；同一个冻结模型读 skill 时，也形成“它提供什么能力”的表示。作者只训练两个线性投影 Wq/Ws，把两类表示拉到可匹配空间。Glance 用 token-level late interaction 低成本扫完整 skill library；Verdict 再让同一 LLM 对 shortlist 用 full attention、task likelihood 与 yes/no judgment 精排；Product-of-Experts 融合。Qwen3-32B 上新增仅 7.9M 参数，跨三个公开 benchmark 与新 SkillTraj 零样本迁移；live mini-swe-agent 正确触发率 0.909。关键价值不是又一个 retriever，而是证明 forward pass 本身可成为 skill/tool/memory/MCP routing substrate。

5.4 Background & Research Gap

旧范式一是 progressive disclosure：预载每个 skill 的 name/description，让 Agent 自己挑。优点是判断者就是 Agent，缺点是 context cost 随 N 增长，而且 metadata 是 skill body 的有损摘要。旧范式二是 external retrieve-and-rerank：可扩展，却看不到 Agent 自己形成的计划、工具返回与错误 skill 上下文，且存在 domain shift。

例如“修这个 repo”最初并不暴露需要哪个 skill，直到测试返回 CUDA ABI mismatch。只检索最后一条 message 会丢目标，吃整段日志又会被噪声稀释。Gavel 沿 Agent 自己 decoding hidden states 累积 token vote，让 skill need 在 rollout 中何时出现成为动态信号。Gap 因而是：此前没有把 frozen Agent LLM 已存在的 routing signal 做成 scalable、installation-time indexable、mid-rollout router。

5.5 Core Insight

作者发现 routing signal 存在，但不能直接拿 native attention keys 做跨文档匹配：Appendix A 的最佳 native configuration 在 SkillRet validation Hit@1 仅 0.001，而训练 glance head 达 0.918。说明不是“原 attention 本来就是 retriever”，而是需要两个小线性 map 解缠 capability signal。一旦 shortlist 小了，同一 frozen LLM 的 full attention 又比独立 reranker 更能判断细粒度适配。这是 representation readout 的强经验结果，但不是“线性 probe 证明因果理解”。

5.6 Method Deep Dive

Install skill s → frozen LLM encodes full skill → Ws projects mid-layer states → ε-cover key bank Live rollout x → Wq projects task token states → token-wise max matching → Glance g(s|x) → prune by Δ → frozen LLM Verdict → likelihood L + yes/no log-odds V → Product-of-Experts → load skill / abstain
  1. 用 matrix-entropy compression valley 选 readout layer；Qwen3-32B 64 blocks 取 block 45。
  2. skill 安装时只 forward 一次；每个 token 经 Ws 成 unit key，新 skill 不重训。
  3. task token 同层状态经 Wq 成 unit query。
  4. 每个 task token 对每个 skill 找最相似 key，保留局部 capability 证据。
  5. Wq/Ws 用 multi-positive contrastive loss 一次性训练。
  6. token 只给自己的 top-k skills 投票并加 recency weight，减少长 trajectory 噪声。
  7. ε-cover farthest-first 压 key bank；ε=.83 时约 8.5× compression，最多损 1.6 points。
  8. 约 9 个 shortlist candidates 进入 Verdict，读取 query-likelihood 与 yes/no judgment。
  9. g、L、V calibrated 融合；live gate 连续两 token 触发，V<0 可 abstain。

5.7 核心公式与数学直觉

m_i(s)=max_j <q_i,d_j^s> L=-log [Σ_{s∈S+} exp(τ m̄(s)) / Σ_{s∈S+∪S-} exp(τ m̄(s))] g(s|x)=[1/Σw_i] Σ_{i:s∈T_i} w_i m_i(s) ε-cover: max_D<q,d>-ε ≤ max_C<q,c> ≤ max_D<q,d> Ruling ≈ g + αL + γV

max_j 让每个 task token 找 skill body 中最相关局部证据，而不是把数千 token 平均成一个 embedding。ε 是关键 storage/accuracy knob；τ=40 控制 contrastive sharpness。Strongest baseline Qwen3-Embedding-8B+Qwen3-Reranker-8B 学的是外部 retrieval relevance；Gavel 的根本差别是 routing signal 来自执行任务的同一 Agent。

5.8 Toy Example

Agent 安装 6,660 skills。初始任务“跑通 Python 项目”时 pytest-debug、dependency-fix 相近。运行测试后出现 CUDA extension ABI mismatch，新 token 的 Wq 状态与某 PyTorch/CUDA compatibility skill 的局部 keys 强匹配；recency vote 将其推到 top。Verdict 再读完整 skill 与 trajectory，L 判断 skill 是否能解释 task，V 判断是否应该用；PoE 后加载。若 V<0 则 abstain。这是 trajectory-conditioned capability detector，而非静态分类器。

5. Paper 2 Full Deep Dive

Explainable LLM Unlearning through Reasoning

Machine Unlearning · BACKFILL

5.1 基本信息：Junfeng Liao, Qizhou Wang, Shanshan Ye, Xin Yu, Ling Chen, Zhen Fang；UTS / RIKEN AIP / University of Adelaide；Submitted 8 Feb 2026；arXiv:2603.09980v1。
Paper：arXiv · HTML · PDF。正文提到 open-sourced codebase，但可核验页面未给确定 URL，因此不猜测。

5.2 一句话定位

TRU 把 unlearning 从“只压低 forget likelihood”改成“显式定义该忘的 scope 与删后响应，再用 reasoning target 教 scope discrimination，同时用 GA-based loss 压原知识”。

5.3 人话版

GA/NPO 只告诉模型“这批答案别再说”，却没告诉哪些改写也属于同一知识、哪些相邻问题不该忘，更没规定忘后如何回答，因此常见两类假成功：换语言/改写就恢复，或模型直接乱码/到处拒答。TRU 用 DeepSeek-reasoner 为每个 forget sample 生成“为什么属于 unlearning scope”的 reasoning trace + coherent refusal，用 CE 学这个 target，再叠 GradDiff 等 GA loss，避免只学拒答模板。WMDP/MUSE/TOFU 上 behavioral UQ 大幅高于 GA/NPO/RMU，跨语言、固定 jailbreak、少量 relearning 也较稳。但核心争议是：主要指标奖励合理拒答，所以它究竟删除了知识，还是学会更聪明的 scope-aware refusal，仍未彻底证明。这使它非常适合作为 recovery/representation verification baseline。

5.4 Background & Research Gap

标准 data unlearning 的 Du 不能唯一定义知识范围。WMDP 一个英文危险问题被压低，不代表西班牙语改写、间接描述也被删。作者定义 task-specific equivalence x~T x'，equivalence class [x]T 才是 unlearning scope。PO 虽教“I don't know”，却可能只学模板并过度拒答。TOFU 中若把“author profile”误扩成“personal information”，模型会拒绝不应删除的邻近问题，说明 scope 本身是 specification。

5.5 Core Insight

“删除什么”和“删后怎么表现”都是 supervision problem。最关键 ablation：去 reasoning 只留 refusal，WMDP UQ 7.01→8.99，RQ 4.19→2.87，Specificity 2.56→0.15。也就是说看起来“忘得更好”其实是 indiscriminate refusal。Reasoning 的主要价值是 scope discrimination，而不是纯 forgetting strength。这是强 behavioral evidence，但不是 representation erasure 证明。

5.6 Method Deep Dive

Forget xu + task criterion T → DeepSeek reasoning target (r,s) → G_rt → CE target loss learns scope + coherent refusal → GA-based loss suppresses original forget likelihood + retain protection → L_target + αL_GA → reason about scope → refuse in-scope / answer out-of-scope
  1. 先定义 task criterion。
  2. 每个 xu 自动生成 reasoning+refusal triplet。
  3. 非 reasoning backbone 加 <think>/<answer> tokens。
  4. L_target SFT scope reasoning 与 response。
  5. 默认 GradDiff 继续压 forget content。
  6. α 平衡；默认 .1。
  7. 用 UQ/RQ 与 cross-lingual/jailbreak/relearning 验证。

5.7 核心公式与数学直觉

GradDiff: min (1/N)Σ logPθ(xu) -(λ/M)Σ logPθ(xr) L_target=-(1/N)Σ[logPθ(r|xu)+logPθ(s|r,xu)] TRU: min L_target + α L_GA-based

GradDiff 在 minimization 下压 forget likelihood、提 retain likelihood；L_target 是标准 reasoning SFT。α 最关键：太小接近 refusal SFT，太大 GA 主导 collapse。NPO 仍是 reweighted GA；RMU 做 representation misdirection；TRU 新增显式 behavioral target，因此很可能是 unlearning+alignment 混合。

5.8 Toy Example

MLLM 中 forget Alice 图像+“秘密项目=Nova”。普通 GA 可能只压原 image-QA。TRU target 写出“视觉身份是 Alice；问题询问删除范围内私密项目；应拒绝”，再配 GA 压 Nova。若侧脸/语义改写也拒绝，说明 scope generalization；但仍需 probe/recovery 判断是视觉知识真删还是身份→拒答 shortcut。

攻击 TRU 的 scope detector：找 semantic 等价但绕过 detector 的输入。可定义 Scope Boundary Leakage 与 Reasoning-Erasure Gap；白盒在 refusal token 出现前检查 GT evidence 是否仍在中层。

5.22 与 Paper 1

TRU 最大缺口是拒答更聪明不等于真删除；Gavel 提示可从回答前 hidden trajectory 读 residual scope signal。

7. Cross-Paper Synthesis

共同趋势：不要只看最终输出；forward pass 中已经存在可读出的“任务/范围判别信号”。Gavel 从中层读当前需要什么 skill；TRU 用 reasoning supervision 教模型判断 query 是否属于 forget scope。一个是 readout，一个是 targeted training。

最强组合：Residual Scope Router for Unlearning Verification。冻结 unlearned MLLM，把 forget concepts/identities 当“skills”，用 Gavel 式 Wq/Ws 读 query→forget-scope score，再与输出拒答/GT likelihood 对照。若 TRU 已拒答但中层仍强路由到 forget concept，可能直接量化“行为抑制≠表示删除”。

8. Combined Research Opportunities

Top Opportunity — Residual Scope Router for MLLM Unlearning

LLaVA-1.5-7B + MLLMU forget5%，Original/GA_Diff/NPO/PO/TRU/VGID；训练轻量 scope router，预测 recovery difficulty；比较 GPWR/Cloze-Lens/RULER，指标 Spearman、AUROC、ASR@budget、retain FPR。若 routing residual 与 recovery ASR 高相关，可形成新 verification paper。

Opportunity 2 — Revoked Skill/Memory Routing

skill/memory 被撤销后，registry 删除不代表 backbone routing signal 消失。保留审计 key，观察 trajectory 是否仍强 match，并测试相似 skill/reacquisition 能否恢复；连接 Agent revocation 与 unlearning。

9. Collision / Overlap

Strongest Collision：TRU 与 refusal-SFT/alignment 的边界。其 behavioral UQ 很强，但可能是更聪明拒答。Gavel 给出不同验证路径：读回答前的 hidden capability/scope signal。与 representation-probe/recovery 文献邻近，因此新工作需强调 trajectory-conditioned scope routing + multimodal residual + recovery correlation。
