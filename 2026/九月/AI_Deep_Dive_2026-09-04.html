5.2 一句话定位

PURGE 把 LVLM hallucination 中的“虚假 object–background correlation”显式构造成 retain/forget partitions，再用 unlearning objective 定向压制 context-driven prediction，同时保留 object-grounded prediction。

5.3 人话版

很多 LVLM 看起来能识别物体，其实是在偷看背景。例如训练数据里“牛”经常出现在草地，“船”经常出现在水面，于是模型可能在根本没有目标物体时，仅凭背景就回答“Yes”。PURGE 的关键不是再加一个 hallucination loss，而是先把数据重新组织成“应该保留什么、应该忘掉什么”。作者设计三种 partition：PURGE-D 用 object removal / counterfactual 图像做数据级拆分；PURGE-H 用模型在配对样本上的行为一致性/失败类型做拆分；PURGE-M 则显式发现候选背景 cue，并将“object 在、cue 弱”的样本作为 retain，“object 不在、cue 强”的样本作为 forget。然后在 LLaVA-1.6-7B、Qwen3-VL-8B-Instruct、Qwen3.5-9B 上用 GA/KL/NPO 做 partition-aware unlearning。最强 PURGE-M-NPO 在多个 hallucination / spurious-correlation benchmark 上同时提高准确率、降低 CHAIR/CHR，并且在 Waterbirds 上把 CLIP 的 worst-group accuracy 提到 79.6%。它说明 unlearning 可以被用作“去掉错误因果捷径”的工具，而不只是删除隐私或事实。

5.4 Background & Research Gap

LVLM hallucination 的传统修复路线包括更好 instruction tuning、RLHF/DPO、额外视觉 grounding loss、数据过滤、Group DRO/IRM、spurious-correlation mitigation、post-hoc calibration。它们大多把目标写成“整体提高准确率/减少 hallucination”，但没有显式区分：模型是因为真正看到了 object 才预测，还是因为背景 cue 让它猜出来。

例如一个没有 cow 的草地图片，模型看到 grass 就回答“Yes, a cow is present”。如果只用普通 supervised fine-tuning，你可以给更多 negative examples，但模型仍可能学新的 dataset-specific shortcut；如果直接 gradient ascent 所有 cow 样本，又可能把“真正有 cow 的 object evidence”一起抹掉。

PURGE 填的 gap 是：先构造一个可控的 counterfactual / semantic partition，让 retain set 专门代表 object-grounded evidence，让 forget set 专门暴露 context-driven error，再把 unlearning 的“forget vs retain”结构用于 spurious correlation removal。

5.5 Core Insight

核心 insight 是把 spurious correlation 写成两个条件概率：希望 P(c|z)→0，其中 z 是背景/上下文；同时保持 P(c|o) 基本不变，其中 o 是真实 object evidence。普通 hallucination mitigation 常把两者混在一个训练分布中，因此无法精准告诉优化器“到底忘哪种关联”。

PURGE 的 observation 来自反事实样本：当 object absent 但背景 cue 仍强时，模型仍预测 target concept，说明 prediction 在依赖 z；反之 object 存在、cue 弱时仍正确，才更接近 object grounding。PURGE-M 将这一观察显式编码进 semantic partitions，是三种 partition 中最稳定、结果也最强的版本。

5.6 Method Deep Dive

Image/question pool → choose target concept c → construct structured partitions PURGE-D: object-present image → object removal / inpainting counterfactual → retain: object-grounded → forget: object-removed but shortcut-triggering PURGE-H: paired model responses → consistent correct / consistent negative → failure partitions (1,0)/(0,1) → retain vs forget by observed behavior PURGE-M: LLM proposes candidate background cues → open-vocabulary detector scores cue s(v) → define C/C^c (object present/absent) → define S/S^c (cue strong/weak) → retain = C ∩ S^c → forget = C^c ∩ S → keep C∩S and C^c∩S^c for evaluation → train θ' with retain + λ·forget objective → freeze vision encoder → update LLM LoRA (+ multimodal projector when available) → evaluate object grounding / hallucination / worst-group robustness

PURGE-D：数据级 disentanglement，依赖 object removal / inpainting 生成 counterfactual。优点是直观，缺点是图像编辑 artifact 可能成为新 shortcut。

PURGE-H：让模型行为本身参与分组。模型在原图/对照图上的一致或不一致预测决定 retain/forget，属于 behavior-driven hard-example mining。

PURGE-M：最有研究价值。LLM 先提议可能共现的背景 cue，再用 open-vocabulary detector 给每张图计算 cue score s(v)，得到四个语义区域。作者不把全部四组都训练：C∩S^c 是最“干净”的 object-grounded retain；C^c∩S 是最典型的 spurious forget；其余两组留作 evaluation，避免训练信号被 entangled/trivial samples 污染。

训练层面：vision encoder 全冻结；LLaVA/Qwen3-VL 更新 language-model LoRA 与 multimodal projector，Qwen3.5-9B 因设置中无独立 projector，只训练 LoRA。

5.7 核心公式与数学直觉

Goal: P_{θ'}(c | z) → 0 while P_{θ'}(c | o) ≈ P_θ(c | o) General objective: L^(k) = L_retain^(k) + λ L_forget^(k) PURGE-M partitions: retain = C ∩ S^c forget = C^c ∩ S where: C = target object present C^c = target object absent S = strong candidate spurious cue S^c = weak/absent cue

λ：最关键的 forgetting-strength knob。增大 λ 会更强压制 forget partition，但可能把附近的合法预测一起拉低；因此作者还用 β 控制 KL/NPO 偏离 pretrained model 的程度，PURGE-D 另用 γ 给 object-absent sample 提供 negative supervision。

作者将 GA、KL、NPO 都放进同一 partition-aware 框架。最强组合普遍是 NPO，说明核心贡献主要不是“发明新 loss”，而是 给已有 unlearning objective 提供更正确的 forget/retain boundary。这点与你现有研究很契合：boundary 设计可能比优化器本身更重要。

5.8 Toy Example

目标 concept 是“cow”。有四张图：A=有牛+草地，B=有牛+室内，C=无牛+草地，D=无牛+城市。普通模型在 C 上也回答“Yes”。PURGE-M 中 C 表示有牛，S 表示强草地 cue。B 属于 C∩S^c，进入 retain；C 属于 C^c∩S，进入 forget；A 因 object/cue entangled 不用于训练；D 是简单负样本也不用于核心 unlearning。训练后希望模型对 C 从 Yes→No，但对 B 仍保留 Yes。也就是说忘掉“grass→cow”的错误关联，而不是忘掉 cow 本身。

5.10 Experiment Setup Deep Dive

Models：CLIP-RN50；LLaVA-1.6-7B；Qwen3-VL-8B-Instruct；Qwen3.5-9B。

Benchmarks：Waterbirds、MM-SpuBench、Causal-HalBench、POPE Random/Popular/Adversarial、CHAIR on COCO val、AMBER、MMHal。

Training pool：COCO-like candidate pool约4万样本；每个 PURGE method 实际约8k retain +8k forget，总约16k parameter-update samples。

Optimization：5 epochs，bf16，AdamW，LoRA LR=2e-5，projector LR=1e-5，LoRA rank 8，alpha 16，dropout 0.05，λ=1.0，β=0.1，γ=1.0。

Trainable components：vision encoder frozen；LLaVA/Qwen3-VL：LLM LoRA + projector；Qwen3.5：LoRA only。

Research Question 1：partition-aware unlearning 能否提升 worst-group / spurious robustness？
RQ2：D/H/M 三种 partition 哪种最有效？
RQ3：NPO/KL/GA 哪种 objective 最适合这些 partitions？
RQ4：更新 projector 是否比 LLM-only 更能删除跨模态 shortcut？
RQ5：忘记比例增大时性能是否持续增长，还是出现 utility trade-off？

5.11 Metrics 教学式解释

Average Accuracy↑：整体平均正确率，可能掩盖 minority group。

WGA↑：Worst-Group Accuracy，取最差 group 的准确率，是 spurious-correlation 任务最重要指标之一。

POPE Acc/Recall/F1↑：围绕 object existence 的 yes/no hallucination；Yes ratio 还可检查模型是否通过一味回答 No“作弊”。

CHAIR_s / CHAIR_i↓：分别衡量 sentence-level 和 instance-level object hallucination；越低越好。

CAC/AAC/CHR↓：Causal-HalBench 中分别表征 causal/attribute hallucination consistency/rate 类指标；应和总 Accuracy 一起看，避免单纯提高回答拒绝/保守程度。

AMBER CH↓ / Cov↑ / Hal↓ / Cog↓：综合衡量 object hallucination、coverage 和认知性错误，适合检查“降低 hallucination 是否以少说内容换来”。

5.12 Results Deep Dive

  1. Waterbirds：Pretrained CLIP Avg90.8/WGA44.9；Group DRO83.3/73.7；MSC84.7/77.5；PURGE-M-NPO 90.9/79.6。它几乎保持 pretrained 平均准确率，同时把最差群组提高34.7pp，是非常强的“retain utility + robustness”结果。
  2. Causal-HalBench LLaVA：Baseline Acc85.6、CHR12.9；PURGE-M-NPO Acc94.6、CHR3.2。准确率+9.0pp，CHR下降9.7pp，说明不是简单保守回答。
  3. Causal-HalBench Qwen3-VL：Baseline Acc84.7、CHR7.4；PURGE-M-NPO Acc94.1、CHR1.2，+9.4pp / -6.2pp。
  4. MM-SpuBench：LLaVA 59.7→78.3，Qwen3-VL 73.8→88.7，PURGE-M + LLM+Proj 是最强。
  5. CHAIR：LLaVA baseline CHAIR_s41.2/CHAIR_i23.6；PURGE-D-NPO LLM+Proj20.3/12.7，约减半；更完整的 PURGE-M 配置在附录还能到更低水平。
  6. POPE Random：Qwen3-VL baseline Acc79.1/F179.4；PURGE-M-NPO 99.6/99.6，提升约20pp，且 Yes ratio 49.6 接近平衡，不是全答No。
  7. Controlled object-absent：最难 A_ny partition 中，LLaVA32→59、Qwen3-VL46→63、Qwen3.5 47→58，直接证明背景 cue 依赖被削弱。
  8. AMBER Qwen3-VL：CH5.9→2.8，Coverage62.3→85.2，Hallucination26.5→8.3，说明降低幻觉的同时输出覆盖更高。
  9. Forget ratio：25→50→75→100% 一般持续改善，但75–100%开始 plateau，LLaVA 饱和更明显；说明更强 forgetting 有 diminishing returns。
Strongest result：Waterbirds 上 Avg90.9 + WGA79.6，同时接近 pretrained 的总体准确率并大幅提升 worst-group，最能说明“选择性去 shortcut”而不是简单牺牲 utility。
Weakest / model-specific：Qwen3.5-9B 没有独立 projector，因此无法获得 projector-adaptation 的完整增益，很多表中的改善小于 LLaVA/Qwen3-VL。
Failure / trade-off：PURGE-D 的 pixel/inpainting partition 比 PURGE-M 弱，并在高 forget ratio 早早饱和；说明“反事实图像看起来直观”不等于提供最干净的 causal supervision。

5.13 Table / Figure Reading

Table 1 Waterbirds：不要只看 WGA。Group DRO/MSC 虽 WGA≈74–77，但平均准确率降到83–85；PURGE-M-NPO 把 WGA推到79.6的同时 Avg90.9，这才是最强 Pareto 证据。

Table 3 Causal-HalBench：四个 Q 子指标、Acc、CAC、AAC、CHR 同时改善，说明不是通过“拒绝/少回答”换取低 hallucination。

Table 5/6 projector ablation：LLaVA MM-SpuBench PURGE-M-NPO 从 LLM-only72.3→LLM+Proj78.3；CHAIR_s 也从较高水平进一步降到低十几。说明 shortcut 不只存在 language readout，也编码在 vision-language interface。

Figure 8 forget-ratio curve：PURGE-M 始终最强，PURGE-D最早饱和。做 unlearning 时应把“增加 forget data”与“改进 forget boundary quality”区分开。

Table 16 POPE：Popular/Adversarial 的收益比 Random 更突出，说明方法在 bias 更强时价值更大。

5.14 Ablation / Mechanistic Analysis

LLM-only vs LLM+Projector：projector 加入训练后 MM-SpuBench 与 CHAIR 显著继续改善，验证 object-background shortcut 位于跨模态 interface，而不是纯 LLM 末端。

PURGE-D/H/M：M consistently strongest、H second、D weakest，说明 semantic/model-informed partition 比 pixel-level counterfactual 更能隔离“应该忘掉的依赖”。

Forget ratio：性能随 forget samples 增加而改善，但75–100%边际收益变小；机制上支持“足够暴露 shortcut 后，增加数量不如提高 partition informativeness”。

这些 ablation 支持机制假设，但还不能证明网络内部真正删除了某个 shortcut representation；论文测的是行为与 benchmark robustness，没有 activation-level causal verification。

5.15 Claim vs Evidence

Authors Claim：partition-aware unlearning 可以选择性删除 spurious object-background dependencies，同时保持或提升 object-grounded reasoning。
Experiments Actually Show：在 CLIP + 3个 LVLM、多种 objective 和多 benchmark 上，PURGE-M/NPO 广泛提高 spurious robustness，并且 projector adaptation 与 partition quality 的 ablation 都支持机制解释。
What Is Not Yet Proven：没有证明 shortcut representation 从内部彻底删除；没有 adaptive recovery attack；没有真实用户场景的动态 background shift；没有说明这种方法在 identity/knowledge unlearning 上同样有效。

5.16 Contribution

  • New Benchmark/Protocol：三种 structured partition strategy。
  • New Mechanism：把 spurious-correlation mitigation 写成 retain/forget unlearning。
  • New Empirical Finding：semantic partition quality 比单纯 forget data 数量更重要。
  • New Evaluation：跨 Waterbirds、POPE、CHAIR、Causal-HalBench、MM-SpuBench、AMBER、MMHal 的统一验证。
  • 非核心创新：GA/KL/NPO、LoRA、projector tuning 本身是已有组件；真正创新是 partition boundary。

5.17 Limitation & Failure Modes

Authors' limitation：仍依赖构造高质量 structured partitions；不同数据/模型下 cue discovery 可能变化；训练需要额外 counterfactual / detector pipeline。

Additional：PURGE-M 的 LLM cue proposal 可能有遗漏或偏见；open-vocabulary detector score 不是因果真值；对“多个重叠 spurious cues”处理有限；没有 representation residual / recovery 测试；Qwen3.5 projector 不适用；模型规模仍集中7–9B；真实 deployment 的 continual shortcut drift 未覆盖。

5.18 Reproduction View

核心代码模块：1) object/cue annotation；2) PURGE-D inpainting；3) PURGE-H paired prediction miner；4) PURGE-M cue proposal + detector scoring；5) retain/forget sampler；6) GA/KL/NPO trainer；7) LLM LoRA/projector freeze policy；8) multi-benchmark evaluator。

最小复现建议先只做 LLaVA-1.6-7B + MM-SpuBench：约8k retain/8k forget，5 epochs，LoRA r=8、alpha16、dropout0.05，LR2e-5，projector1e-5。先跑 Baseline、PURGE-D-NPO、PURGE-M-NPO；若能复现59.7→约72/78这一量级，再加 projector ablation。

Migration Potential ★★★★★：可以迁到 identity unlearning 的 visual-near / context-near retain boundary。

5.21 Attack / Verification Lens

PURGE-D/H/M 都可以反向变成 attack generator：专门构造 target absent 但 associated context 强的输入，检查模型是否通过 shortcut 恢复目标。对于 unlearning verification，应报告四分区 confusion matrix，而不是只报普通 forget/retain。可以定义 Contextual Residual Leakage：目标实体缺失时，仅靠 context cue 导致目标输出的概率。

5.22 与另外 Top Paper 的关系

PURGE 强调“只改变错误依赖、保留正确结构”；HoH 强调“只修复 gap / 新增小能力、保留 verified behavior”。两者的共同机制是 incremental selective update。组合后可以研究 continual unlearning loop：每轮独立 evaluator 找 residual leakage / collateral damage，下一轮只对 hardest partition 做小步修正，同时 warm-start 保留已验证 utility。

5.23 如果只让我记住这篇论文

  1. PURGE 的真正贡献不是新 loss，而是重新定义 forget/retain boundary。
  2. 目标是压低 P(c|context)，保留 P(c|object)。
  3. PURGE-D 用图像反事实，H 用行为失败，M 用语义 cue。
  4. PURGE-M 通常最强，说明语义 partition quality 很关键。
  5. NPO 是 strongest objective，但不是论文的核心创新。
  6. Waterbirds 上 PURGE-M-NPO 达到 Avg90.9/WGA79.6。
  7. Qwen3-VL 的 POPE/AMBER 和 LLaVA 的 CHAIR 都有大幅改善。
  8. 训练 projector 能进一步减少 hallucination，说明 shortcut 存在于跨模态 interface。
  9. 更大 forget ratio 会改善，但75–100%开始饱和。
  10. 最值得迁移到你的工作的是“visual/context-near partition + residual recovery probe”。

Paper 2 Full Deep Dive — Harness-of-Harness

5.2 一句话定位

HoH 不重新训练 coding model，而是在现有 coding harness 外面再套一层长期 orchestration，把一次性的“写代码 episode”变成 planning→development→independent QA→evidence feedback 的持续改进过程。

5.3 人话版

现在的 Codex、OpenCode、Pi 等 coding agents 很擅长一次性完成 issue，但真正从零开发一个完整软件时，问题不是“这一轮能不能写出代码”，而是几十轮以后还能不能记住需求、保留已验证功能、避免重复修同一个 bug、同时继续增加新能力。Harness-of-Harness 的做法是把一个固定 coding harness 当作执行器，在外层设置三个角色：Planner 根据高层 specification 和上一轮 QA evidence 选出一个小而可验证的增量；Developer 在当前 artifact 上 warm-start 实现，并做本地 shift-left testing；独立 QA Tester 再从黑盒/白盒证据验证新功能与回归，输出 structured evidence bundle 给下一轮。底层模型、harness、role policy 在整个 run 中固定，变化的只有 development document、artifact 和 evidence。三个 harness-model 组合在 GameCraft-Bench、FrontierSWE、ProgramBench 上平均相对增益 52.25%，三轮最大相对增益 82.86%；70-loop 的 Fusepoint 案例还能持续开发出可玩的 FPS。核心不是多 Agent 数量，而是“证据驱动的长期 artifact state management”。

5.4 Background & Research Gap

现有 coding agents 大多在 bounded episode 内工作：给 issue，模型探索 repo、改代码、跑测试、提交答案。多 Agent 软件工作如 MetaGPT/ChatDev 通常有预定义角色流程，EvoDev/AgileCoder 做迭代 sprint，Self-Harness/Meta-Harness 则直接优化 harness 本身。

HoH 针对的是更长 horizon：从空 workspace + 高层 PRD 开始，数十轮持续增加 capability。随着时间推移，会出现三类典型 failure：1) agent 忘记早期 requirement；2) 为修当前 bug 破坏已完成组件；3) 陷入重复 repair，缺少新的 capability growth。单纯“再多调用几次 Vanilla coding agent”不能保证这些问题被系统解决。

5.5 Core Insight

作者的核心 insight 是：长周期软件开发需要显式保留三个不断演化的状态——计划 D_t、软件 artifact A_t、测试证据 E_t。下一轮计划不能只看最初 specification，也不能只看当前 code；它必须同时知道“还有哪些 gap”和“哪些行为已经 verified，绝不能被回归破坏”。

第二个 insight 是不应强行规定 agent 的内部 reasoning/workflow，而应约束 可验证 output contract。Planner/Developer/Tester 各自自由使用底层 harness 工具，但必须交付结构化 artifact；不满足 schema 就重试。

这是 systems / orchestration insight，而不是新的 RL 算法。它的“学习”发生在 persistent project state 和 evidence feedback 上，不修改模型参数。

5.6 Method Deep Dive

High-level specification S + initial artifact A0 → iteration t Planner: input S + previous evidence E_(t-1) → choose bounded priorities → identify verified functionality to preserve → define observable acceptance criteria → output development document D_t Developer: input S + D_t + warm-start artifact A_(t-1) → establish behavioral baseline → implement bounded increment → shift-left local tests → output candidate artifact A_t Independent QA Tester: input S + D_t + A_t + public execution records → derive checkable claims → black-box / white-box / runtime testing → split evidence: E_t^ver = verified behavior E_t^gap = failures / insufficient evidence Runtime: freeze role inputs enforce single-writer artifact boundary bind evidence to exact tested candidate persist version history → next iteration with A_t and E_t

Planner：每轮只选小而相关的任务，既要处理 outstanding failures，也必须推进至少一个 concrete capability，避免陷入 endless repair。

Developer：唯一允许修改 artifact 的 role，warm-start 自 A_(t-1)，使 lineage 清晰。实现前先建立 baseline，每个 meaningful change 后立刻 retest。

QA Tester：与 Developer 自测严格分离。Developer 的“我完成了”只是 claim，只有独立 QA 的 observable evidence 才能进入 verified set。

Runtime：固定 role inputs / permissions，把 evidence 绑定到确切 candidate，并保留版本化 history。长期 coherence 很大一部分来自这个 deterministic outer runtime。

5.7 核心公式与数学直觉

Planner: D_t = Plan(S, E_(t-1)) Developer: A_t = Develop(S, D_t, A_(t-1)) QA: E_t = Test(S, D_t, A_t) Evidence split: E_t^ver = {(c_i,r_i,s_i) in E_t | s_i = verified} E_t^gap = {(c_i,r_i,s_i) in E_t | s_i = gap} Next loop: (S, A_t, E_t) → D_(t+1) → A_(t+1) → E_(t+1)

这里没有 loss function；数学对象是 persistent state transition。S 是固定 public specification；D_t 是当前增量计划；A_t 是软件状态；E_t 是 claim-evidence bundle。

与 Vanilla Continuation 的最关键区别不是“多跑几轮”，而是 Vanilla 只有 artifact continuation；HoH 额外保留独立 QA evidence，并基于它更新 D_t。Table 2 的 matched-pass 实验正是为了排除“只是 token 更多”的解释。

5.8 Toy Example

目标是从零做一个任务管理 Web App。S 要求登录、项目、任务、搜索、导出。第一轮 Planner 只安排“登录+最小项目列表”，Developer 实现并本地测试，QA 验证登录成功但发现 session timeout 没处理，于是 E_1^ver 记录登录/项目列表已通过，E_1^gap 记录 timeout。第二轮 Planner 不会重新重写登录，而是计划“修 timeout + 新增任务 CRUD”，明确要求 preserve 已验证登录流程。这样十轮之后，系统不是不断“重新生成一个 app”，而是在一条可追踪 artifact lineage 上持续增加 verified capability。

5.10 Experiment Setup Deep Dive

Harness–Model pairs：Codex CLI 0.142.5 + GPT-5.5 high；OpenCode 1.14.30 + DeepSeek-V4-Pro；Pi Coding Agent 0.80.10 + MiniMax-M3。

Benchmarks：GameCraft-Bench 45 tasks；FrontierSWE 15 tasks；ProgramBench 使用 hidden behavioral tests。

Main protocol：Vanilla=1 pass；HoH@T=T planning-coding-testing loops，主实验 T=3；benchmark evaluator 输出不回流开发 loop。

Metrics：GameCraft Overall 0–100；FrontierSWE task reward + Dominance；ProgramBench Avg Test Pass Rate；另记录 provider token usage。

Long-run case：Fusepoint，Godot 4.7，70 loops；初始 workspace 只有 PRD；人类只处理网络/API availability，不参与 planning/coding/debug/testing/acceptance。

Research Question 1：HoH 是否跨 harness/model/benchmark 有稳定提升？
RQ2：提升是否只是因为更多 passes/tokens？
RQ3：plan update、evidence feedback、warm-start 各承担什么？
RQ4：10轮乃至70轮后是否仍持续改进，而不是回归/循环？

5.11 Metrics 教学式解释

GameCraft Overall↑：编译/运行失败直接0分；可运行后综合 Core Mechanics、Content Depth、Functional Visuals、Art & Presentation。比单元测试更适合完整游戏 artifact。

FrontierSWE Reward↑：任务自带 verifier 输出的 official reward。

Dominance↑：相对 12 个 harness-condition configuration 的 task-level win rate，更接近“跨配置竞争力”。

ProgramBench Pass Rate↑：每个任务 hidden behavioral tests 通过比例再取均值，避免只看最终 binary pass/fail。

Token usage：只适合同一 provider/config 内比较，因为不同 provider cache accounting 不一致。

5.12 Results Deep Dive

  1. Codex GameCraft：49.58→71.52，+21.94pp；三轮持续单调增长。
  2. OpenCode GameCraft：26.90→48.98，+22.08pp，说明弱 baseline 也能靠 protocol 显著提升。
  3. Pi GameCraft：42.16→58.78，+16.62pp。
  4. FrontierSWE：Codex 0.31→0.54；OpenCode0.23→0.31；Pi0.26→0.55，其中 Pi +0.29 最强。
  5. ProgramBench：Codex60.41→66.50；OpenCode45.27→57.56；Pi35.83→52.68，Pi +16.85pp。
  6. Matched-pass：HoH@1/2/3=59.71/64.84/71.52；Vanilla continuation1/2/3=49.58/54.99/58.24。HoH@2 用5.67M tokens 已超过 Vanilla 3-pass 6.33M 的58.24，排除“仅仅更多 token”。
  7. Ablation：w/o Plan Update 63.39（-8.13）；w/o Evidence Feedback65.23（-6.28）；w/o Warm-Start63.67（-7.85）。三个信息通道都关键。
  8. Warm-start 还省 token：Full HoH@3=8.41M；w/o Warm-Start=11.12M，重复从空 workspace 重建反而更贵。
  9. FrontierSWE 10 loops：Dominance 从 HoH@3 的39.33%继续到 HoH@10 72.67%，Vanilla27.33%，说明改进不是只发生前三轮。
  10. Fusepoint 70 loops：系统持续经历 initial construction→功能增长/issue accumulation→后期修复收敛，说明长期开发轨迹中会显式 reopen/close issue，而不是只累计代码。
Strongest result：Matched-pass Table 2。HoH@2 5.67M tokens 得64.84，超过 Vanilla 3-pass 6.33M tokens 的58.24，最有力证明结构化 evidence loop 的贡献。
Weakest / dataset-specific：ProgramBench 的增益明显小于 GameCraft/FrontierSWE，尤其 Codex只+6.09pp；说明当任务主要由 hidden tests 定义、increment planning空间较小时，HoH收益更有限。
Failure / cost：HoH 不是免费提升。它增加 planner/tester 调用和 token；70-loop case 还是单个复杂项目，不能据此证明所有长期开发都会稳定收敛。

5.14 Ablation / Mechanistic Analysis

去 Plan Update：D_t 固定为 D_1，分数-8.13，说明长期 plan 必须根据新证据重写。

去 Evidence Feedback：Planner 只看 S，不看上一轮 QA，-6.28，证明 testing 的价值不只是最后打分，而是影响下一轮工作选择。

去 Warm-Start：每轮从 A_0 重新开发，-7.85，token 8.41M→11.12M；说明 artifact continuity 同时提高质量与效率。

这些是清楚的系统机制 ablation，但并不证明三模块之间完全独立；它们可能存在强交互，例如 evidence 没有 warm-start artifact 时可操作性本身就下降。

5.15 Claim vs Evidence

Authors Claim：HoH 能让固定 coding harness 在长周期自主开发中持续改进，避免 bounded-episode agent 的长期 coherence 问题。
Experiments Actually Show：3种 harness-model、3个 benchmark、matched-pass control、三项 ablation 以及70-loop case 都支持“结构化长期 loop 比简单 repeated execution 更好”。
What Is Not Yet Proven：没有大规模多项目 multi-day benchmark；70-loop 只有一个 FPS case；没有对长期安全 drift、malicious evidence、错误 QA feedback 做 stress test；没有证明多 Agent 比一个统一 agent 更优。

5.16 Contribution

  • New System/Engineering：Harness-of-Harness outer orchestration。
  • New Protocol：Planner→Developer→independent QA 的 persistent state loop。
  • New Evidence Mechanism：verified/gap claim-evidence bundle。
  • New Empirical Finding：长期 improvement 需要 plan update、evidence feedback、artifact warm-start 三者共同存在。
  • New Demonstration：70-loop multi-day FPS autonomous development。

5.17 Limitation & Failure Modes

Authors' limitation：multi-day case 规模有限；更多软件领域/真实项目需验证。

Additional：QA 本身可能 hallucinate 或漏测，错误 evidence 会被下一轮放大；长期 token/storage cost 高；重复 loop 可能形成 overfitting to evaluator；role prompt / schema 设计仍人工；没有 adversarial planner/tester；70-loop autonomy 仍依赖网络/API uptime 人工恢复；底层模型快速更新后效果可能改变。

5.18 Reproduction View

最小实现模块：1) role prompt templates；2) D_t document schema；3) single-writer workspace manager；4) developer self-test hook；5) independent QA runner；6) E_t normalized evidence bundle；7) Git/version state；8) outer loop scheduler。

最值得先跑不是70-loop游戏，而是 GameCraft-Bench 10个任务、Codex/GPT-5.5 或可替代 coding agent：Vanilla 1/2/3 continuation vs HoH1/2/3，记录 score 和 tokens。然后做三项 ablation，能最快验证机制 claim。

5.19 Research Value

Baseline Potential ★★★★★：任何“长期 Agent 自我改进/continual agent”工作都应对比简单 continuation。

Migration Potential ★★★★★：可以迁到 continual unlearning、Agent memory cleanup、long-horizon red-teaming。

Attack Potential ★★★★☆：evidence poisoning / stale evidence / false closure 很自然。

Evaluation Potential ★★★★★：verified vs gap 的结构特别适合 unlearning closure。

Benchmark Potential ★★★★☆：可做 multi-round unlearning regression benchmark。

New Paper Potential ★★★★★：把 QA evidence 换成 residual/attack evidence，就是新的 continual unlearning framework。

5.20 Migration Analysis

方向 A — Evidence-Grounded Continual Unlearning

Original Problem →HoH 对软件做多轮修复/增长。
Transferable Mechanism →每轮依据 verified/gap evidence 更新小范围计划并 warm-start。
New RQ →unlearning 能否从“一次优化”变成持续 audit→targeted update→re-audit？
Method Modification →Planner 读取 forget leakage、retain regression、attack residual；生成本轮最小 unlearning target/partition；Trainer 只更新指定 LoRA/module；Verifier 独立跑 direct/paraphrase/cloze/representation/retain tests，输出 E_t^ver/E_t^gap。
Minimum Experiment →20 targets，最多5轮；每轮只处理 top-k hardest target；与 one-shot NPO/GA_Diff、固定5轮重复 NPO 对比。
Model →LLaVA-1.5-7B/Qwen2.5-VL-7B。
Dataset →MLLMU-Bench forget5%。
Baseline →one-shot NPO、fixed repeated NPO、random curriculum、loss-based curriculum。
Metric →Worst-Surface Leakage、Retain Utility、ASR@budget、Rounds-to-Closure、cumulative tokens/GPU hours。
Expected Contribution →证据驱动、可停止的 continual unlearning protocol。
Risk →对 verifier overfit。
Collision Risk →中；需突出 evidence-driven control loop 而非普通 curriculum。

方向 B — QA Evidence Poisoning as Unlearning Attack

Original Problem →HoH 假设 QA evidence 可靠。
Transferable Mechanism →下一轮 plan 强依赖 E_t。
New RQ →若 unlearning verifier 被少量 false evidence 污染，会不会提前宣布 closure 或把训练预算导向错误 target？
Method Modification →注入 stale/pass-flipped/missing attack results，比较 planner 的 target selection 变化。
Minimum Experiment →30 targets×3 evidence corruption rates(5/10/20%)×3 policies。
Baseline →uncorrupted verifier、majority-vote verifier、cryptographically bound trace。
Metric →False Closure Rate、Missed Residual Rate、Retain Damage、Attack Success after Stop。
Expected Contribution →首次把 verifier trustworthiness 纳入 continual unlearning。
Risk →需要合理的 adversarial evidence model。
Collision Risk →低。

5.21 Attack / Verification Lens

HoH 最自然的 attack surface 是 evidence：如果 QA 把未验证 capability 标成 verified，下一轮 Planner 会主动“保留”错误状态。迁到 unlearning 时，这对应 false closure attack。可定义 Closure Evidence Integrity：每个“已忘记/已保留”的 claim 必须绑定可复现 probe trace，而不是单个 judge label。

5.22 与另外 Top Paper 的关系

PURGE 给出高质量的 structured forget/retain partitions；HoH 给出持续的 evidence-driven control loop。最自然组合不是“让 Agent 帮 PURGE 调参”，而是把 PURGE-M partitions 当作每轮 verifier 的 hardest residual groups：发现哪类 context shortcut 仍泄漏，下一轮只针对该 partition unlearn，直到 closure 或 utility boundary 到达。

5.23 如果只让我记住这篇论文

  1. HoH 不改底层模型，而是改长期 orchestration。
  2. 持续状态只有三个核心：计划 D_t、artifact A_t、证据 E_t。
  3. Planner 不能只看原始需求，必须消费上一轮 QA evidence。
  4. Developer 是 single writer，并从 A_(t-1) warm-start。
  5. Developer 自测不算 acceptance，独立 QA 才能产生 verified evidence。
  6. 三种 harness-model、三 benchmark 都有提升。
  7. Matched-pass 证明收益不是简单“多跑几次”。
  8. 去 Plan Update/Evidence/Warm-Start 都会掉6–8分。
  9. 70-loop Fusepoint 说明 protocol 能维持多日 artifact evolution，但仍只是一个 case。
  10. 最值得迁移到 unlearning 的是 audit→targeted update→independent verification 的持续闭环。

Cross-Paper Synthesis

今天两篇表面上一个做 multimodal unlearning、一个做 coding agent，但共同机制高度一致：不要做无差别全局更新，而要根据结构化 evidence 进行小范围、有边界、可验证的增量变化。

Combined Research Opportunities

Best Migration Direction — Evidence-Grounded Partition-Adaptive Continual Unlearning

Initial unlearning → independent verifier direct / paraphrase / cloze context-only / visual-near partitions retain-near tests → E_t = verified + gaps → Planner selects only hardest residual partition → Trainer updates minimal LoRA/module → warm-start next checkpoint → re-run independent verifier → stop when: worst-surface leakage < threshold AND retain utility > threshold OR marginal improvement plateaus

这个方向同时吸收 PURGE 的 boundary quality 与 HoH 的 evidence loop。真正的论文问题不是“多训练几轮”，而是：能否在固定 compute budget 下，把 unlearning budget 自适应分配给仍然失败的 target/partition，同时显式保护已经 verified 的 retain behavior？

Collision / Overlap

Strongest Collision：PURGE 与已有 spurious-correlation mitigation / multimodal hallucination mitigation 存在较强任务级重叠；它的差异在“用 unlearning 的 retain/forget structure 做 targeted shortcut removal”。如果迁到 MLLM identity unlearning，不能只把 PURGE-M 原样换数据，必须增加 recovery/closure 或 representation residual。

HoH 与 MetaGPT/ChatDev/AgileCoder/EvoDev/Self-Harness 在“多角色/迭代开发”有 overlap，但 matched-pass、independent evidence feedback、artifact warm-start 三件套构成较清晰机制差异。
