SALMONN-duo: Adaptive Dual-System Coordination for Full-Duplex Voice Agents

5.2 一句话定位

把“低延迟、不断线的语音交互”和“慢但强的工具/推理 Agent”拆成异步双系统，并让前端学会什么时候值得把请求委托给后端。

5.3 人话版

传统全双工语音模型擅长一边听一边说，但真正的 Agent 还要查知识、调用工具、执行多步任务；如果把这些能力都塞进实时模型，每个简单问候也要付出大模型成本和延迟。SALMONN-duo 的解法不是继续把 System 1 做大，而是让一个 8B 的全双工前端持续负责对话节奏，再异步调用更强的 System 2。关键不只是“路由”，而是前端必须在后端仍运行时继续回应用户、处理插话，并在结果异步返回后按当前上下文重新排序和表达。作者用 knowledge-boundary-aware SFT 教它识别自己的知识边界，再用 cost-aware GRPO 把正确性、安全和调用成本放进同一个后训练目标。结果显示：它不像 MoshiRAG 那样几乎 100% 委托，也不像 VoiceChat 那样几乎不委托，而是随问题难度改变调用率；在定制 τ-Voice 上，加入安全与成本奖励后 Overall Pass@1 从 SFT 的 57% 提到 64%，同时有效委托率达到 85.4%。

5.4 Background & Research Gap

全双工语音 Agent 的核心矛盾是两个时间尺度：对话层要求几十到几百毫秒级持续反应，任务层的检索、推理和工具执行却可能持续数秒且耗费昂贵模型调用。已有方案常见两条路：一是让同一模型额外生成 JSON/tool-call channel；二是把知识问题几乎全部转交后端。前者把实时模型和任务求解模型绑死，后者又把“能不能自己回答”退化成固定规则。论文指出，真正缺的不是工具本身，而是delegation utility：一次委托带来的正确性/安全收益，是否值得它的延迟和成本。

具体例子：用户正在办理换货，System 2 已开始查询账户；此时用户插问“Diary of a Wimpy Kid 的作者是谁？”如果前端暂停等待后端，交互断裂；如果把所有问题都丢给后端，又浪费调用。SALMONN-duo 要做到：前端直接回答自己会的问题，同时保持换货任务状态；后端结果回来时，还要根据用户是否要求“先处理换货”决定输出顺序。这是普通静态 router benchmark 没覆盖的异步状态一致性问题。

5.5 Core Insight

核心观察有三层。第一，知识边界可以通过模型自身多次 rollout 的正确性近似监督，而不是把问题类型当作“是否检索”的代理；这是经验观察。第二，委托是一个序列决策：SFT 只学习离线标签，会遇到 exposure bias，尤其在多轮对话里当前状态由自己过去的回答塑造，因此需要 RL 直接优化 episode outcome；这是训练机制判断。第三，任务成功奖励太稀疏，单独做 GRPO 会留下 hallucination 与 policy violation，所以必须显式加入 safety reward，并惩罚“不产生工具使用”的无效后端调用；这是工程与经验共同发现。

5.6 Method Deep Dive

Streaming user audio → System 1: streaming encoder + Llama-3.1-8B + streaming synthesizer → at a speaking boundary: DIRECT or emit DELEGATE → snapshot current conversation context → asynchronous System 2 infers intent / reasons / calls tools → System 1 keeps listening, speaking, backchanneling and handling new requests → backend result returns asynchronously → inject backend tokens into System 1 stream → System 1 reconciles result with latest context and response-order constraints → spoken response / continued task execution

Step 1 — 实时前端

System 1 基于 SALMONN-omni：SPEAR streaming speech encoder、Llama-3.1-8B-Instruct backbone、改造后的 CosyVoice2-0.5B streaming synthesizer。输入流按 80 ms time block 处理；作者移除原 SALMONN-omni 的 echo stream 来降低序列长度。System 2 返回文本后，每个 time block 插入 N=100 个 token。设计目的不是让前端“解决所有任务”，而是把它限定为实时交互与委托控制器。

Step 2 — DELEGATE 作为语言动作

作者比较额外 delegation head 与把 DELEGATE 当作模型输出 token。后者直接进入生成分布，不需要从中间 hidden state 另训分类头，且对原始回答能力破坏更小。模型在准备开始说话的 time block 做决定：输出 DELEGATE 就启动异步后端，否则直接回答。这个设计解决“router 与 generator 表征不一致”的 failure mode。

Step 3 — Knowledge-boundary-aware SFT

对训练问题先让 System 1 backbone 产生多次 rollout，再根据回答正确性决定是否应该委托；需要委托时还生成自然 filler，保证后端工作期间前端能立即确认用户请求。这里的监督标签不是“知识问题→检索”，而是“这个模型在这个问题上是否可靠”。因此同一问题对不同 checkpoint 可以产生不同路由标签。

Step 4 — 异步 System 2

System 2 可以是单一强 LLM，也可以是协调 specialist agents/tools 的 orchestration layer。调用时使用 snapshot context；在 QA 实验中后端是 GPT-4o-2024-11-20，在 τ-Voice 中是 GPT-5.2-2025-12-11 + domain tools。前端不阻塞等待：用户可以继续插话，后端返回顺序也允许与调用顺序不同。

Step 5 — cost-aware GRPO

QA 场景的偏好顺序是：direct 且正确 > delegate 且正确 > 任意错误。任务型对话则用 episode pass、turn-level hallucination/policy safety，以及无效委托成本组成奖励。作者特别把“委托但后端没有调用任何工具”视为可疑冗余调用，每发生一次就降低成本分，最低到 0。

5.7 核心公式与数学直觉

QA reward ordering: r_direct,correct > r_delegate,correct > r_direct,incorrect = r_delegate,incorrect τ-Voice composite reward (conceptual): R = 1·R_pass + 1·R_safety + 0.5·R_cost Unnecessary-delegation score: starts at 1, minus 0.2 for each backend reference that uses no tool, clipped at 0.

最关键的不是复杂新公式，而是 reward ordering。若 direct-correct 与 delegate-correct 同奖，最安全策略会退化成“全部委托”；若成本惩罚过强，router 又会变成过度自信。QA 表 4 中把 r_delegate,correct 从 0.65/0.80/0.90 扫描，0.80 在 TriviaQA、HaluEval、MultiTurn 的 AUROC/ARA 上整体最均衡。τ-Voice 的 reward 权重为 pass:safety:cost = 1:1:0.5，说明作者把成本当约束而不是首要目标。与 strongest baseline MoshiRAG 的机制差异在于：后者几乎每个知识问题都调用后端；SALMONN-duo 直接学习“何时不需要后端”。

5.8 Toy Example

假设用户说：“帮我把订单 A 换成蓝色；对了，《小屁孩日记》作者是谁？”System 1 首先识别换货需要环境工具，输出 DELEGATE，把当时的订单上下文 snapshot 给 System 2；同时说“我来查一下换货选项”。System 2 查询订单期间，用户提出作者问题。System 1 的知识边界认为自己能可靠回答，于是不二次委托，直接回答 Jeff Kinney。随后 System 2 返回“蓝色有库存，但需确认地址”。前端读取最新上下文，知道作者问题已经完成，于是回到换货流程询问确认地址。如果用户明确说“先把换货办完再回答别的”，response-order policy 会反过来优先呈现后端结果。这个例子体现论文真正解决的是异步任务结果与动态会话状态的合并，而不只是 tool calling。

5.10 Experiment Setup Deep Dive

  • System 1：SPEAR + Llama-3.1-8B-Instruct + CosyVoice2-0.5B；LoRA rank 32、scaling 0.1；还训练 encoder→LLM、LLM→synth connector 与 CosyVoice LM。
  • SFT：309k 单轮 QA、36k 个 10–15 turn 日常对话、32k τ-Voice episodes；QA 来源 TriviaQA、Natural Questions、HotpotQA。
  • RL：GRPO group size=4；SFT LR=2e-4，RL LR=1e-6，AdamW weight decay=0.1；64×A100-80G。20k warm-up（最大 240s，batch 128）后再 1.5k steps（最大 1200s，batch 64）。56 GPU 做 GRPO，8 GPU 在线 CosyVoice 合成；GRPO:SFT loss=2:1。
  • Evaluation：OpenAudioBench 的 Llama Questions/Web Questions/TriviaQA，HaluEval，1000 个 HotpotQA fullwiki 样本；MultiTurn 923 个 3–5 turn 对话；定制 τ-Voice test split。
  • Judge：QA 用 GPT-4o-2024-11-20；τ-Voice hallucination/policy 用 GPT-5.2-2025-12-11。作者在主要评测中默认后端拿 ground-truth dialogue history，因此 ASR error propagation 并未完整纳入。

Research Question A：DELEGATE token 是否比额外 routing head 更少损伤原能力？
RQ B：自适应委托能否在准确率接近强后端时显著降低调用率？
RQ C：cost-aware GRPO 是否改善整个 accuracy–delegation Pareto frontier？
RQ D：在长时、多轮、带政策的任务里，reward shaping 是否同时改善 task success 与 safety？

5.11 Metrics 教学式解释

  • Accuracy：最终回答正确率，高好；但若不同时看 Delegation Rate，会奖励“全部调用强后端”。
  • Delegation Rate：触发 System 2 的比例，单独越低不一定越好；必须与准确率一起看。
  • AUROC：把“该问题是否需要委托”当二分类，衡量路由分数排序能力，1 最好、0.5 近随机；不直接反映某个实际成本阈值。
  • ARA (Answer–Reference Agreement)：强制给 reference 后，最终回答与 reference 在正确性上的一致率；高值说明前端能消费异步后端信息，但若 reference 自身错会误导。
  • Pass@1：τ-Voice 单次 episode 是否成功，高好；它稀疏，所以作者额外加 safety reward。
  • Hal.：幻觉率，低好；Pol.：政策遵循，高好；Effective Del.：委托后确实发生工具使用的比例，高说明后端调用更“值”。

5.12 Results Deep Dive

  • Strongest result：TriviaQA 上 SALMONN-duo 80.2% accuracy、仅 25.0% delegation；MoshiRAG 为 75.8%/99.9%。不是只省调用，还高 4.4pp；支持“知识边界路由”而非全检索。
  • HotpotQA：46.1% accuracy、61.3% delegation，几乎追平 MoshiRAG 46.8% 但调用少约 38.6pp。说明难题上 router 会主动提高调用率。
  • Llama Questions：79.7%/16.3%；说明简单题主要由 System 1 自己处理。相比 GPT-4o reference 88.0% 仍有明显上限。
  • MultiTurn：56.2% accuracy、61.9% delegation，优于 MoshiRAG 54.3% accuracy 且后者委托 95.6%；多轮优势存在但只有 +1.9pp，属于较弱的 accuracy margin。
  • Routing ablation：TriviaQA 使用 delegation token 时无后端 accuracy 68.5%，而 hidden-head ℓ=16/24/32 为 56.9/55.5/54.5；说明外挂 router 会显著扰动基础能力，token 化决策更稳。
  • GRPO：MultiTurn AUROC 从 SFT 0.730 提到 r_del,correct=0.80 时 0.754，ARA 93.6→95.3；提升不巨大但跨多个数据集的 trade-off curve 更优。
  • τ-Voice：SFT Overall Pass@1=57%；只优化 pass 到 59%；加 safety 到 63%；再加 cost 到 64%。同时 delegation 从 48.1%→57.6%→71.8%→62.7%，说明安全奖励会诱导更多求助，成本项再把无效调用压回。
  • Weakest/failure：加入 cost-aware GRPO 后 interruption order correctness 81.9→87.8%，但 interrupt-question accuracy 77.2→74.7，出现约 −2.5pp；优化流程控制并非无代价。另一个弱点是 τ-Voice 的 SFT-always-S2 仍达到 65% overall，略高于最终 64%，说明最终方法主要赢在效率/安全折中，不是纯成功率绝对最优。

5.13 Table / Figure Reading

  • Table 1：比较 routing head 层 16/24/32 与 delegation token。最重要的不是 AUROC，而是 token 方案保住了 System 1 自身准确率：HotpotQA 23.6 vs 13.6–17.7。说明“把路由器接在哪层”不是小工程细节，它会改变 backbone 行为。
  • Table 2：五个 spoken QA 同时列 Accuracy 与 Delegation Rate，是论文最核心证据。MoshiRAG 的高 accuracy 与约 100% 调用绑定；VoiceChat 的低调用与低知识准确率绑定；SALMONN-duo 落在两者之间形成 Pareto 点。Hotpot/HaluEval 委托率约 60%，LlamaQ 仅 16.3%，难度自适应很明显。
  • Table 4 + Figure 3：GRPO 并非简单抬高某一个固定阈值下准确率，而是多数 delegation budget 下都改善曲线；这比只报一个阈值更能支持“delegation utility 改善”。不过 AUROC 增幅只有数个百分点，应避免夸成路由范式突破。
  • Table 5：最值得研究迁移。SFT-always-S2 的 65% pass 是成功率上界式对照；最终模型 64% 几乎追平，同时 62.7% 调用、85.4% effective delegation。真正贡献是把 success、安全、成本三者同时放到 episode-level protocol。
  • Table 6：异步结果顺序的验证很少见。order correctness 87.8% 说明模型学到事件排序，但 accuracy 小降暴露了控制与内容能力的 trade-off。

5.14 Ablation / Mechanistic Analysis

三个关键 ablation 能回答“模块到底做了什么”。把 DELEGATE 从生成 token 换成 hidden-state head，基础 QA 明显下降，支持“语言动作式路由更兼容原模型”的机制解释；从 SFT 到 cost-aware GRPO，AUROC/ARA 与 Pareto curve 改善，支持 RL 在 exposure bias 下重新校准边界；τ-Voice 从 pass-only reward → +safety → +cost，分别显示 safety 项负责压 hallucination/policy violation，cost 项负责把 71.8% 的高调用拉回 62.7% 并把 effective delegation 提到 85.4%。但这些是干预式模块证据，不等于内部表征因果证明：论文没有对“knowledge boundary representation”做 causal probing。

5.16 Contribution

  • Contribution 1 — New System/Engineering + Mechanism：全双工 System 1 + 异步可插拔 System 2，重点是持续会话中的异步结果融合。
  • Contribution 2 — New Objective/Protocol：knowledge-boundary-aware SFT + cost-aware GRPO，把 direct/delegate 正确性、safety 与无效调用成本联合优化。
  • Contribution 3 — New Empirical Finding：voice agent 的“调用率”必须与 accuracy/safety/effective delegation 联合评估；近乎全委托不是理想 baseline。

5.17 Limitation & Failure Modes

Authors' / protocol-visible limitations：定制 τ-Voice 禁用了原 benchmark 每两秒的 interruption/backchannel checks，并移除了 background noise、speaker variation；主要评测还默认 backend 可见 ground-truth dialogue history。因此语音链路最脆弱的 ASR/噪声传播被弱化。
Additional：System 2 用 GPT-4o/GPT-5.2，性能与成本依赖闭源服务；LLM-as-judge 与 user simulator 也来自同类闭源模型，存在 correlated judge bias。训练需 64×A100-80G，复现成本高。后端错误被论文默认“更强”，没有系统研究前端是否应该拒绝/纠正错误 reference。异步多请求 race、backend timeout、stale snapshot、工具副作用回滚等生产 failure mode 仍未充分覆盖。

5.18 Reproduction View

最小复现不必先做语音。先用 Llama-3.1-8B-Instruct 做 text-only System 1，加入 DELEGATE token；从 TriviaQA/HotpotQA 各抽 2k train + 500 test，用 backbone 多 rollout 正确率生成 direct/delegate label；System 2 用固定强模型或 oracle answer。先复现 Table 1/2 的核心：token router 是否比 hidden-head 更保 utility，以及 accuracy–delegation curve 是否优于 always-delegate/never-delegate。第二阶段再加 GRPO group=4，reward 设 direct-correct=1、delegate-correct=0.8、incorrect=0，画不同阈值 Pareto。只有这两步成立后才值得接 streaming speech。最敏感超参预计是 r_delegate,correct、LoRA 学习率、rollout 数量与 boundary label threshold。

5.19 Research Value

  • Baseline Potential：高。任何异步 agent routing / fast-slow architecture 都可把它作为 utility-aware router baseline。
  • Migration Potential：很高。“前端保持响应 + 后端异步执行 + 结果按最新状态重绑定”可直接迁移 coding agent、GUI agent、multi-agent orchestration。
  • Attack Potential：高。可攻击 knowledge boundary：诱导过度自信造成 under-delegation，或构造高不确定输入造成 denial-of-wallet 式 over-delegation。
  • Evaluation Potential：很高。Effective Delegation 与 response-order correctness 比单纯 tool success 更接近真实 agent lifecycle。
  • Benchmark Potential：高。可做 stale-result / reordered-result / interrupt / cancellation / backend-error 的异步 Agent benchmark。
  • New Paper Potential：高。尤其适合与 unlearning verification 结合：被删除知识是否会通过 System 2、memory、tool 或旧 snapshot 回流。

5.21 Attack / Verification Lens

可直接构造两类 probe：一是 under-delegation attack，把模型不知道的长尾知识包装成它熟悉的表达，测试 boundary 是否过度自信；二是 over-delegation / denial-of-wallet，通过不确定性诱导大量昂贵后端调用。作为 verification，可把 forced-delegate 与 forced-direct 的差异定义为“external dependency gap”；把旧 snapshot 返回后是否覆盖新用户指令定义为 stale-result violation；把 unlearning 后经 System 2 恢复忘记内容定义为 delegation-mediated reacquisition。

5.22 与 Paper 2 的关系

SALMONN-duo 的思想是“不要把所有请求都交给同样昂贵的协作机制”；Paper 2 则从理论与大规模实验说明“更多同质 agent 往往并不会继续带来信息”。两者高度互补：前者学习何时调用，后者告诉你为什么调用更多 peer 可能无效。组合后最自然的新方法是 correlation-aware delegation：System 1 不只预测任务难度，还预测新增 agent 是否提供独立信息。

5.23 如果只让我记住这篇论文

  • 它真正研究的是 delegation utility，不只是 voice tool calling。
  • System 1 小而实时，System 2 强而异步，二者分离不同时间尺度。
  • DELEGATE 作为生成 token 比额外 hidden-state routing head 更少伤害原能力。
  • knowledge-boundary label 来自模型自身 rollout 正确性，而不是问题类型规则。
  • MoshiRAG 的高分伴随近 100% 委托；SALMONN-duo 在多个数据集用更少调用获得相当或更高准确率。
  • GRPO 的价值主要是重新优化多轮 exposure bias 下的 accuracy–cost frontier。
  • τ-Voice 证明 pass-only reward 太稀疏，必须显式加 hallucination/policy safety。
  • 最终模型并非纯成功率最高：always-S2 仍略高，因此贡献是 Pareto trade-off。
  • 评测弱化了 ASR、噪声和部分 interruption 条件，部署结论不能外推过度。
  • 最值得迁移的是异步 snapshot→result→latest-context reconciliation，可用于 coding agent 与 unlearning lifecycle verification。

5.2 一句话定位

它不是再造一种 multi-agent debate，而是回答更基础的问题：什么时候“多几个 Agent”在数学上就不该指望有用？

5.3 人话版

很多 multi-agent 工作默认 team size 越大越强，但这篇论文把问题拆成任务结构与聚合机制。对“析取型”任务（数学题、选择题），只要团队里有人找到正确解，理论潜力 pass@N 会随 N 快速上升；可现实里的 plurality vote 只会收敛到同一模型最常给的答案，因此大量少数派正确解根本没被选出来。对“补偿型”任务（Fermi 数值估计），平均本应消掉独立噪声，但同一 LLM 在同一题上的不同采样共享系统偏差，平均只会更稳定地收敛到同一个错值。作者用 13 个 3B–20B open-weight 模型、最多 30 agents、约 6.8×10^7 次 generation 验证：disjunctive pass@30 能涨 5–20pp，但直接投票几乎不涨；多轮 revision 的大收益几乎一位 peer 就拿到了；Fermi 中 87% 平方误差来自 item-level bias。结论很强：team scaling 的瓶颈不是“人数不够”，而是独立信息与选择机制不够。

5.4 Background & Research Gap

传统 Condorcet jury theorem 告诉我们：若每个成员独立且正确率 p>0.5，多数投票的错误会随人数指数下降；wisdom-of-crowds 又告诉我们：独立、无偏的数值估计做平均，方差按 1/N 下降。Multi-agent LLM 很自然地借用了这两个直觉，但 LLM 的多个“agent”往往只是同一个 checkpoint 的不同 sample：它们在某一道难题上共享难度、训练偏见和知识缺口，因此并不等价于真正独立的人。已有工作观察到更多 calls 会饱和、debate 会 conformity、错误相关性会限制 ensemble，但缺一个把这些现象统一到“任务组合规则”的理论框架。本文用 Steiner taxonomy 把 benchmark 的聚合机制分类，并给出 large-team limit。

具体例子：一道 MATH 题，30 个 sample 中可能 8 个算对、22 个因为同一诱导错误给出同一个错答案。pass@30 已经是 1，因为有人会；但 plurality 必然选 22 票的错误。再看“纽约一天喝多少杯咖啡”的 Fermi 题：30 个 sample 可能围绕同一个错误人口假设波动，平均会降低随机波动，却不会修复共同的人口偏差。

5.5 Core Insight

核心 insight 是把“相关性”从 agent 交互层下沉到 item-conditioned distribution。给定题目 k，同模型 sample 可以近似独立地从 P_k 采样；但跨题看，容易题的 p_k 都高、难题都低，于是 correctness 呈现很高的 intra-class correlation。对 voting，N→∞ 时不是趋向真值，而是趋向 P_k 的 modal answer；只有正确答案本身是 mode 的题最终会被做对。对 continuous estimate，N→∞ 时 sample noise 消失，留下 item-level bias b_k。这个观察既有理论推导，也有大规模经验验证，是本文最有迁移价值的部分。

5.6 Method Deep Dive

Choose task combination rule → map benchmark to Steiner type → sample N independent agents from same open-weight model → Round 1: independent direct answers → aggregate: plurality (disjunctive) / geometric mean (compensatory) → compute pass@N and realized team score → Rounds 2–3: expose peers' previous answers, allow revision → estimate item-level answer distributions / error correlation / bias → compare observed scaling to theoretical large-N limits → repeat with heterogeneous model pools

Step 1 — Task typing

Steiner taxonomy 不是把 benchmark 永久贴标签，而是按“团队怎样组合成员贡献”分类。同一数学题如果用 verifier 选候选，是 disjunctive；如果严格串成每个 agent 必须成功的 pipeline，则会更像 conjunctive。论文重点研究 disjunctive 与 compensatory，同时列出 additive、conjunctive、discretionary 作为未来扩展。

Step 2 — Homogeneous sampling

13 个 open-weight model 从 3B 到 20B，team size N∈{1,2,3,5,7,10,15,20,25,30}，三次运行，temperature=0.4。Round 1 独立回答；Round 2/3 每个 agent 看自己和 teammates 上一轮回答后可 revision。这个设置把“人数”与“交互轮数”分开。

Step 3 — Disjunctive aggregation

离散题报告两个量：pass@N 表示至少一个 agent 正确，是团队潜在生产力；plurality accuracy 是真正被选出的答案，是实际生产力。两者差距就是 selection/coordination loss。

Step 4 — Compensatory aggregation

Fermi estimate 跨多个数量级，所以先转 log10 error，再做 geometric mean。这样 multiplicative error（差 10 倍、100 倍）变成可加误差。关键分解是：总误差 = item-level shared bias + within-item sample variance；只有后者能被更多同质 samples 平均掉。

Step 5 — Heterogeneous teams

作者再混合不同模型 family，检验“多样性是否真的增加有效 team capacity”。结果是：Fermi 上跨模型组合能明显超过成员；disjunctive 上虽然大幅超过平均成员，却仍输给最强单模型，暴露 equal-weight voting 在 competence 不同成员间的结构性问题。

5.7 核心公式与数学直觉

Ideal disjunctive potential: P_disj(N) = 1 - (1-p)^N Majority error bound (binary, independent p>0.5): P(error) ≤ exp[-2N(p-1/2)^2] Fermi signed log-error: e_i = log10(x_i / g) ē_N = (1/N) Σ e_i Effective team capacity under equicorrelation ρ: N_eff(N) = N / [1 + (N-1)ρ] lim_{N→∞} N_eff = 1/ρ Compensatory MSE: MSE(N) = b² + σ²/N_eff item-wise: E[b_k²] + E[σ_k²]/N

最重要的变量是 ρ 与 b_k。ρ 高意味着新增 sample 不是新增独立信息；例如 ρ=0.9 时无限加人 N_eff 也只趋近 1.11。b_k 更致命：平均只能压 σ²/N，却不能压 b_k²。论文测到 Fermi 的 β≈0.87，即约 87% MSE 是 shared item bias，所以无限 homogeneous team 理论上最多消掉约 13%。与“More Agents Is All You Need”式经验 baseline 的根本差异是：本文不把 N 当单调有效的 compute scaling axis，而先问新增 agent 的独立信息量。

5.8 Toy Example

知识删除验证可以直接套这个框架。假设对一个被 unlearn 的人物有 10 种 paraphrase probe，每次对同一模型采样 30 个回答。若只看 majority refusal，可能 25 个拒答、5 个泄漏，于是“验证通过”；但从 disjunctive attack 角度，攻击者只需一个泄漏样本，pass@N(leak) 会随 N 增长。反过来，如果 30 个 probe 都因为同一视觉线索错误而泄漏相同事实，简单平均多个 metric 也不会消掉 shared bias。于是验证协议应该同时报告 majority behavior、leak-pass@N、item-level correlation 与 heterogeneous probe family 的 N_eff，而不是把重复采样当作独立证据。

5.11 Metrics 教学式解释

  • pass@N：N 个 agent 至少一个正确的比例，高好。它测“候选生成潜力”，不是最终系统 accuracy；没有 verifier 时可能完全兑现不了。
  • Plurality Accuracy：票数最多答案的正确率。适合离散答案，但多个语义等价答案若规范化不好会被拆票。
  • ALE：|log10(x/g)|；0 是精确，1 表示差一个数量级，越低越好。clip 可稳健化但会隐藏极端灾难。
  • Within-one-order accuracy：估计落在真值 10 倍范围内的比例，高好；直观但阈值粗。
  • ρ / intra-class correlation：同一模型不同 sample 的 error correlation，高表示新增 agent 信息重复。
  • N_eff：把相关团队换算成等效独立成员数。N=30 但 N_eff≈1.2 时，“30 agents”本质上只有约一个独立判断。
  • β：item-level bias 占总 squared error 的比例；越高，靠重复采样平均越无效。

5.12 Results Deep Dive

  • Strongest phenomenon：GSM8K single-agent 34.3%→pass@30 54.4%，潜力 +20.1pp；但 Round-1 plurality 从 N=2 到 30 只 +0.3pp。说明生成多样性存在，selector 才是瓶颈。
  • MATH-500：29.7%→pass@30 47.1%（+17.4pp）；MMLU-Hard 52.4→67.7（+15.3pp）；GSM-Hard 18.0→28.9（+10.9pp）；ARC 83.1→88.4（+5.3pp）。任务越接近 ceiling，新增候选潜力越小。
  • Revision 很强但不是“大团队”强：GSM8K N=5 Round1 34.1→Round3 61.9；可是 N=2 gain 26.5pp、N=30 gain 26.6pp，差 −0.1pp，95% CI [−0.6,0.3]。一个 peer 基本吃完收益。
  • 单 agent 给 5× token budget，GSM8K 也 +12.4pp，说明 revision gain 的一部分其实是“先想后答”的 test-time compute，不应全归因于 collaboration。
  • Fermi：within-one-order 31.6%→N=30 33.4%，仅 +1.8pp；ALE 1.84→1.71。可与此同时 pass@30 达 57.3%，说明同样存在好候选但 geometric mean 无法识别。
  • 清理 144 个可疑 RealFP label 后，single 40.9→N30 43.6，仍只 +2.7pp，而 pass@30=70.8%；因此失败不能简单归因于坏标签。
  • Fermi β=0.87；理论 Eq.4 对所有 team size 的预测平均误差仅 0.6%，Pearson r=0.997。这个拟合是本文最强机制证据。
  • Heterogeneous exception：五个 7B–8B family 的 Fermi team 把平均成员 ALE 降 25.8%，team ALE=1.45，优于最佳成员 1.80；说明真正的 architectural diversity 能打破部分 shared bias。
  • Failure case：disjunctive heterogeneous best pool 83.2%，虽比成员均值 +22.1pp，却低于 strongest member gpt-oss-20b 的 86.8%，所有 10 splits 都输 3.4–4.3pp；equal-weight voting 仍不够。

5.14 Ablation / Mechanistic Analysis

本文的 mechanistic analysis 不是神经元 probing，而是统计机制干预。第一，固定模型改变 N，验证 modal-answer / bias limit；第二，固定 N 引入 revision rounds，发现 peer count 不重要而 revision opportunity 重要；第三，提高 temperature，within-item dispersion 增加 30–70%，但 Fermi ρ 仍 0.83–0.98，说明“多采样更随机”不等于“获得独立偏差”；第四，换成跨模型 heterogeneous pool，Fermi 明显改善，支持 shared architecture/model bias 是关键来源。它们提供较强因果方向证据，但仍无法把 correlation 精确归因到预训练数据、架构或 alignment 的哪一层。

5.16 Contribution

  • Contribution 1 — New Framework：把 Steiner task taxonomy 引入 LLM multi-agent scaling。

5.17 Limitation & Failure Modes

Authors-visible：正文重点只覆盖 Steiner 的 disjunctive 与 compensatory 两类；结论不能直接外推到长链 conjunctive agent task、并行 additive exploration 或动态 discretionary orchestration。
Additional：模型仅 3B–20B open-weight，未覆盖最新闭源 frontier agent；Round 1 的 answer-first prompt 对 reasoning model 并不完全成立；debate protocol 相对简单，没有 role specialization、private memory、tools、learned verifier。Fermi 只有 RealFP 一类，且 27.2% label 被判可疑。约 6.8e7 generation 虽大，但“agent”主要是同模型 sample，不等价于自治软件 agent。最重要的 deployment caveat：真正生产 MAS 的价值可能来自工具权限、异构 memory 与分工，而不是重复语言采样。

5.18 Reproduction View

最小复现只需 2 个模型 × 2 个任务。选 Qwen3-8B 与 Llama-3.1-8B；GSM8K 500 题、RealFP 200 题；T=0.4，每题预生成 30 samples。离散侧从同一 30 samples 离线重采 N={1,2,5,10,30}，算 pass@N、plurality、item modal correctness 与 ρ；连续侧算 e_i=log10(x_i/g)、geometric mean、ALE、b_k、σ_k、β、N_eff。核心 claim 若成立，应看到 pass@N 上升远快于 plurality，且 Fermi 的 β 高、MSE(N) 接近 E[b_k²]+E[σ_k²]/N。随后只需混合两个模型各 15 sample，看 cross-model bias 是否下降。这样不用 6.8e7 generation 就能验证机制。

5.19 Research Value

  • Baseline Potential：高。任何声称“multi-agent scaling”的工作都应至少与 single、pass@N、plurality、N_eff 对照。
  • Migration Potential：极高。尤其适合 unlearning robustness：重复 probe 是否只是高度相关证据？
  • Attack Potential：高。攻击者可利用 pass@N：只要少数 sample 泄漏，增加 queries 就放大成功率。
  • Evaluation Potential：极高。建议把 correlation-adjusted effective probes 引入 robustness / verification。
  • Benchmark Potential：高。可构造 task-type-controlled agent benchmark，明确 aggregation operator。
  • New Paper Potential：高。“effective verification capacity”与“heterogeneous attack families”几乎可直接形成 unlearning meta-evaluation 论文。

5.21 Attack / Verification Lens

这篇论文几乎天然是 verification 论文的母体。对 black-box probe，最危险的统计错误就是把同一 prompt 的 30 次 sample 当 30 个独立验证；N_eff 可以直接纠正。对 recovery，pass@N 的视角更适合攻击者：防守方 majority refusal 可能很好，但攻击者只需要一次恢复。可以定义 Leakage Amplification Curve L(N)=P(至少一次泄漏)，以及 Verification Efficiency=N_eff/N。若跨模态 probe family 显著提高 N_eff，就能定量证明“多模态攻击不是简单重复”。

5.22 与 Paper 1 的关系

Paper 1 学习“什么时候值得调用 System 2”；Paper 2 解释“新增 peer 到底增加多少独立信息”。两者组合后，router 的成本项不该只惩罚调用次数，而应奖励 marginal information gain。也就是说，第二个后端如果和第一个高度相关，即使便宜也可能不值得调用；反之，一个异构 specialist 虽贵，却可能显著增加 N_eff。这形成今天最强的新研究方向：Correlation-Aware Delegation / Effective-Agent Routing。

5.23 如果只让我记住这篇论文

  • 不要把 team size 当成有效 compute；先看 N_eff。
  • disjunctive 任务的 pass@N 可以明显增长，但 plurality 可能几乎不动。
  • 原因是无限投票只会收敛到模型在该 item 上的 modal answer。
  • GSM8K 从单体到 pass@30 有约 20pp 潜力，但 Round-1 voting 基本兑现不了。
  • 多轮 revision 很有效，但一位 peer 与 29 位 peers 的增益几乎相同。
  • Fermi averaging 失败不是因为 sample 不够，而是约 87% squared error 是 item-level shared bias。
  • 提高 temperature 增加随机性，却不一定降低 shared correlation。
  • 真正的跨模型 diversity 在 Fermi 上有效，说明 diversity 比人数重要。
  • heterogeneous voting 在离散任务仍输给最强成员，说明还需要 competence-aware selector。
  • 对 unlearning，最直接迁移是 N_eff + leak-pass@N：把‘多少个 probe’改成‘多少个独立证据’。

7. Cross-Paper Synthesis

共同趋势：Agent 研究正在从“能力堆叠”转向“资源是否带来边际信息”。SALMONN-duo 把强后端调用视为有成本的动作；Scaling 论文进一步说明，即使成本允许，多加同质 agent 也可能只复制同一 bias。下一阶段的 orchestrator 不应只学 difficulty routing，而应学 marginal independent information。

可组合机制：把 SALMONN-duo 的 DELEGATE policy 从二元动作扩成 DIRECT / backend-A / backend-B / multi-agent，状态里加入历史 agent 的 error-correlation / uncertainty embedding，reward 用 task success − monetary cost + λ·ΔN_eff。这样“调用谁”不再只由模型大小决定，而由新增信息的正交性决定。

值得借用的实验范式：Paper 1 的 accuracy–delegation Pareto curve、effective delegation、异步 response ordering；Paper 2 的 pass@N vs realized score、N_eff、bias decomposition、heterogeneous pool。把两组指标合并，能形成比“success rate + token cost”更强的 Agent evaluation protocol。

最可能形成新论文的 gap：异步多 Agent 的“有效独立能力”目前缺少 online routing；unlearning robustness 也普遍把多个 attacks/probes 当平行指标，却很少校正 probe correlation。这两个 gap 可以合并成 correlation-aware verification。

8. Combined Research Opportunities

Best Migration Direction — Correlation-Adjusted Multimodal Unlearning Verification
把 Paper 2 的 N_eff / pass@N / bias decomposition 迁移到现有 Faithfulness–Robustness 框架，再用 Paper 1 的 delegation pathway 增加“外部 memory/tool/agent 是否把忘记知识重新引入”的系统侧验证。最小版本无需发明新 unlearning 方法，就可以成为 evaluation / attack paper：同样 30 个 probes，比较 raw count 与 effective probe count；再测 heterogeneous multimodal probes 是否显著提升 N_eff 与 recovery success。

机会 2 — Effective-Agent Router：训练 router 预测“下一 agent 的 ΔN_eff”，不是只预测 task difficulty。最小实验用 3–5 个开源模型，GSM8K/HotpotQA，固定总 token budget；比较 cheapest-first、strongest-first、uncertainty router 与 ΔN_eff router。

机会 3 — Async Reacquisition Benchmark：unlearned System 1 + retain/original/RAG System 2，注入 delayed return、stale snapshot、user correction、tool result conflict，测忘记知识是否经异步路径回流。它把 model-side unlearning 提升到 system lifecycle guarantee。

9. Collision / Overlap

Strongest Collision：More Agents ≠ More Independent Evidence. 这直接碰撞“增加 agent 数/增加 attack 数就等于更强验证”的隐含假设。Paper 1 的 always-S2 对照又说明“更多外部能力”可以抬成功率，却牺牲成本；Paper 2 则说明“更多同质 peer”甚至未必抬成功率。二者共同要求把 quantity 改成 marginal utility × independence。

与 Machine Unlearning 的 collision 更具体：若 robustness 汇总把 FigStep、Jailbreak、Image Rephrase、SUA 或多个 paraphrase 当等权独立证据，可能高估评测覆盖度；反过来，攻击者关心的是至少一次恢复，因此 average leakage 又可能低估风险。建议同时报告 mean、worst/pass@N 与 correlation-adjusted N_eff。
