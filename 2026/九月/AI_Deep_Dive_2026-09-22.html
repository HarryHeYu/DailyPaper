4. Paper 1 Full Deep Dive — LU-500

5.1 基本信息

LU-500: A Logo Benchmark for Concept Unlearning
Authors: Keyu Li, Jin Gao, Jialing Zhang, Dequan Wang；Affiliation: Shanghai Jiao Tong University。arXiv v1: 2026-07-27；v2: 2026-07-29；cs.CV / cs.AI；当前为 arXiv preprint。
Paper · Full HTML · Official GitHub · Dataset entry

5.2 一句话定位

LU-500 把 concept unlearning 从“整幅图里的大概念消失了吗”推进到一个更苛刻的局部问题：只删除占图像很小、但语义高度可识别的 logo，同时尽可能不动周围合法内容。

5.3 人话版

过去扩散模型 unlearning 常删 style、celebrity、object 等全局概念，评测也常只问目标还在不在。Logo 不一样：Apple 标记可能只占 MacBook 图像几个百分点，但哪怕残留一点轮廓仍能泄露品牌；同时如果为了删 logo 把电脑、桌面、广告牌一起改掉，也不能算高质量 unlearning。LU-500 用 Fortune Global 500 构造 9,584 个经过验证的 explicit / implicit prompt，后者甚至不直接说“logo”，而是通过产品、店铺、包装等上下文诱发品牌。作者用 local CLIP/SSIM + global CLIP/SSIM 同时测“删干净”和“别误伤”，发现 NP、SLD、SEGA、ESD、Forget-Me-Not 都存在明显 local–global trade-off。ProLU 多 Agent prompt rewriting 能删得更狠，但本质是改输入语义，不等于模型真的忘了。这篇最值得借用的不是某个新 unlearning algorithm，而是局部泄漏 + 全局效用的双区域评测范式。

5.4 Background & Research Gap

旧范式通常把 unlearning 看成全局分布移动：让生成结果不再像 Van Gogh、某位 celebrity 或某个 object。于是一个全图 CLIP score、分类器命中率或 unsafe rate 就能大致工作。但 logo 是 localized concept：目标区域可能很小，且与产品语义纠缠。比如“a silver MacBook on a wooden desk”没有出现 Apple logo 字样，却可能自然生成苹果标志。若安全 guidance 把整台 laptop 的材质、位置、背景都改了，target detector 也许不再命中，但 utility 已被牺牲。LU-500 填的 gap 正是：现有 benchmark 缺少一个同时要求 implicit triggering、localized erasure 与 non-target preservation 的大规模测试床。

5.5 Core Insight

核心观察有两层。第一，concept 是否被忘记与 image 是否被保留是两个不同轴，不能压成一个成功率。第二，logo leakage 既有 prompt-semantic 成分，也有 model-representation 成分：ProLU 通过删除 prompt 中品牌诱因可显著降低 local score，却会改变场景，这说明“把触发词绕开”不等于“权重层面 disentangle”。作者进一步做视觉属性相关分析，发现多数属性与 semantic leakage 相关较弱，但 LogoSSIM 对区域大小/结构属性出现更明显关系，支持 spatially controlled unlearning 的方向。它主要是经验发现与 benchmark diagnosis，而不是理论定理。

5.6 Method Deep Dive

Fortune Global 500 → explicit/implicit prompt synthesis → human validation → SD3 baseline generation → verify logo exists → apply unlearning/intervention → OWLv2 localize residual logo → local metrics + global metrics → failure correlation / ablation

Step 1 — Prompt construction：每家公司生成 LUex（直接点名 logo）和 LUim（产品/商店/网站/广告/包装等隐式语境）。初始约 10k prompts，经人工筛选后 9,584 条：4,748 explicit、4,836 implicit。

Step 2 — Pre-unlearning validity：用 Stable Diffusion 3 Medium 生成，并剔除无法稳定生成可验证 logo 的 prompt。这个步骤很关键：若 base model 本来就不会生成目标，所谓“unlearning 成功”是伪成功。

Step 3 — Intervention：主实验跑 inference-time NP、SLD、SEGA，并把 SLD/SEGA 设成多档强度；另在 legacy compatible backbone 上测 ESD、Forget-Me-Not。固定 paired generation seed，降低随机采样噪声。

Step 4 — Localize：OWLv2 用“company name + logo”查询候选区域；作者人工核验自动框，报告 98% detection accuracy。

Step 5 — Two-region evaluation：logo crop 上测 CLIPScore / LogoScore / LogoSSIM；全图测 ImageScore / ImageSSIM。局部指标希望低，全局指标希望高。

Step 6 — ProLU diagnostic：Remover 删除品牌诱因 → Reflector 检查过删/漏删并迭代 → Checker 做最终文本 guard → P2 prompt 再生成。它故意作为“prompt-space upper diagnostic”，而非声称模型已 weight-level unlearn。

5.7 核心公式与数学直觉

CLIPScore_logo = cos(E_img(crop_after), E_text(company)) LogoScore = cos(E_img(crop_before), E_img(crop_after)) LogoSSIM = SSIM(crop_before, crop_after) ImageScore = cos(E_img(I_before), E_img(I_after)) ImageSSIM = SSIM(I_before, I_after) Ideal direction: CLIPScore_logo ↓, LogoScore ↓, LogoSSIM ↓ while ImageScore ↑, ImageSSIM ↑

这不是单一 objective，而是一个隐含的 Pareto 问题：局部要“不同”，全局要“相同”。SLD/SEGA strongest settings 通过增大 safety/editing guidance 让 target region 变化更多，但同一 guidance 也扩散到全局 latent，导致 ImageSSIM 下滑。最关键超参数因此不是某个固定数，而是 intervention strength；它越大，通常 local erasure 越强、global preservation 越差。与只优化 target suppression 的 baseline 相比，LU-500 的评价明确惩罚“把整幅图毁掉来实现遗忘”。

5.8 Toy Example

假设 prompt 是“a courier holding a FedEx package in front of a warehouse”。Before 图中盒子角落有清晰 FedEx 标。方法 A 把 logo 模糊掉，但盒子、人物、仓库完全保持：CLIPScore/LogoSSIM 大幅下降，ImageSSIM 仍高，这是理想局部 unlearning。方法 B 把整个包裹换成空白袋、仓库颜色也变：logo 的确没了，但 ImageSSIM/Score 暴跌，这是 utility sacrifice。方法 C 仅把 prompt 改成“generic package”再生成：局部最干净，却改变了用户本来的“FedEx package”语义——这正是 ProLU 展示的“input filtering ≠ model unlearning”。

Strongest baseline：若按 local erasure，ProLU strongest；若按 preservation，SEGA_v1 strongest。正因为没有单一 winner，这篇论文的价值就是把 Pareto trade-off 暴露出来。

5.10 Experiment Setup Deep Dive

Model：主 backbone Stable Diffusion 3 Medium；fine-tuning compatibility 实验用 SD-v1-4（ESD）与 SD-v2-1-base（Forget-Me-Not）。Dataset：9,584 prompts，500 companies，explicit 4,748 / implicit 4,836。Generation：主设置 28 inference steps、guidance scale 7.0、1024×1024，paired seed 固定。Evaluation：OWLv2 local detection + 5 metrics。RQ1：inference-time methods 能否同时 erase+preserve？RQ2：weight-level legacy methods 是否摆脱 trade-off？RQ3：logo intrinsic attributes 能否解释失败？RQ4：ProLU 三个 agent 各承担什么？

5.11 Metrics 教学式解释

CLIPScore↓：crop 与 company text 的语义相似度，低表示品牌语义弱；缺点是 detector miss 时被置 0，可能把 detection failure 当 unlearning success。LogoScore↓：before/after crop 的 CLIP image similarity，测语义层变化。LogoSSIM↓：像素结构相似，特别敏感于局部几何/纹理。ImageScore↑：全图 CLIP similarity，测大语义是否保留。ImageSSIM↑：全图结构/像素保真。两组指标互补：只看 local 会奖励毁图，只看 global 会奖励什么都不删。

5.12 Results Deep Dive

  1. ProLU explicit CLIPScore 0.26，优于 NP 0.30、SLD_v3 0.28；说明 semantic rewriting 能强力压低品牌语义，但不能据此宣称 weight-level forgetting。
  2. ProLU implicit LogoSSIM 0.05，是表中最强 local structural disruption；同时 ImageScore 只有 0.77、ImageSSIM 0.53，说明代价是场景变化。
  3. SEGA_v1 global preservation strongest：explicit/implicit ImageScore 都 0.98，ImageSSIM 都 0.97；但 CLIPScore 0.32/0.31，几乎仍是原始 logo semantic strength。
  4. SLD 从 v1→v3，explicit LogoSSIM 0.29→0.08，但 ImageSSIM 0.86→0.50：局部删除增强伴随全局结构保真大幅下降。
  5. SEGA v1→v3，explicit LogoSSIM 0.42→0.19，同时 ImageSSIM 0.97→0.83；trade-off 同方向复现。
  6. fine-tuning：ESD CLIPScore 0.24、ImageSSIM 0.38；ProLU 同 backbone 0.23、0.45。这里不能得出“prompt rewriting 普遍优于 ESD”，因为比较局限于 legacy checkpoint。
  7. Forget-Me-Not ImageScore 0.80 高于同 backbone ProLU 0.75，但 CLIPScore 0.28 弱于 0.25；再次出现 preservation vs erasure 交换。
  8. ProLU ablation：完整 reduction 16.76%；去 Remover 只剩 3.07%，即 Remover 承担约 83.2% 的增益；去 Reflector reduction 15.15%，Reflector 贡献约 16.8%；去 Checker aggregate delta 为 0。
  9. Weakest evidence：Checker 被称为“architecturally essential”，但 aggregate CLIPScore 完全不变，因此目前更多是设计直觉/guard rationale，而不是实证性能贡献。
  10. 视觉属性相关性多数较弱；LogoSSIM 上较明显的结构相关只支持“spatial control 值得探索”，并不构成 causal mechanism。

Strongest result：Table 1 中 intervention strength 的 local–global Pareto trade-off 极稳定。Failure case：文字型 logo 会变成乱码伪文字，多实例场景可能只删最显著一个。Utility trade-off：明确存在，而且是论文核心，不应把更低 target score 单独视为更好 unlearning。

5.14 Ablation / Mechanistic Analysis

ProLU ablation 是最直接机制证据：去 Remover，CLIPScore reduction 从 16.76% 掉到 3.07%，证明核心机制就是 semantic cue ablation；去 Reflector 仍有 15.15%，说明它只是边际 stabilizer；Checker 对 aggregate score 0 贡献。Correlation analysis 不是因果分析：它只能说明某些 visual attributes 与 LogoSSIM 共变，不能证明“区域更大导致 unlearning 失败”。真正需要的下一步是 mask-controlled intervention 或 matched-pair causal test。

5.15 Claim vs Evidence

Authors Claim：logo 是 localized + semantically entangled 的 unlearning target，现有代表方法难以兼顾 erase/preserve。Experiments Actually Show：在 SD3 inference-time baselines 与两个 legacy fine-tuning implementations 上，这个 trade-off 很明显，explicit/implicit 都出现。What Is Not Yet Proven：没有覆盖所有现代 weight-editing method；没有 adaptive prompt attack；没有 long-tail/multilingual brands；也没有证明 ProLU 的失败意味着所有 prompt-space mitigation 都无法做到语义保持。

5.16 Contribution

New Benchmark/Dataset LU-500；New Metric/Protocol local/global × pixel/latent multi-grained evaluation；New Empirical Finding local–global trade-off；New System/Engineering ProLU diagnostic；Mechanistic Analysis visual correlation。真正新意主要在 benchmark framing 与 evaluation protocol，ProLU 是已有 prompt rewriting + multi-agent 组件的组合。

5.17 Limitation & Failure Modes

作者承认覆盖范围限于 Fortune Global 500、当前兼容 methods/backbones，缺 long-tail、multilingual、adaptive attack 与更广 variance。额外限制包括：OWLv2 miss 会让 local metric 人为归零；paired seed 不能完全解决 diffusion stochasticity；全图 SSIM 对局部小变化天然不敏感；品牌 prompt 可能包含合法语义，删除它会改变用户 intent；没有 recovery/relearning；没有测试 quantization、model merge、LoRA reload 后 logo 是否恢复；也没有把 logo detector 本身作为 adaptive attack target。

5.18 Reproduction View

最小复现不必跑 500 brands：先取 Apple/Tesla/Coca-Cola/FedEx/Disney 各 10 explicit+10 implicit，SD3 Medium 固定 seed，跑 before、SLD 三档、SEGA 三档、ProLU；OWLv2 检框后计算 5 metrics。仓库已给 generate_prompts.py、generate_prolu_prompts.py、run_baselines.py、detect_logos.py、calculate_metrics.py，以及 SD3 pipeline patch。第一张必须复现的图是 intervention strength vs LogoSSIM/ImageSSIM Pareto curve；若曲线不存在，论文核心 claim 就被削弱。最容易踩坑的是 diffusers patch 版本、OWLv2 crop 对齐、无检测时 local=0 的处理、paired seed 与 prompt rewrite 后构图差异。

Migration A — Localized MLLM Unlearning：Original Problem=diffusion logo removal → Transferable Mechanism=target region 与 non-target region 分开评估 → New RQ=MLLM 删除某实体视觉证据时，是否只破坏与该实体相关的 visual tokens，而保持其他对象问答能力 → Method Modification=用 detector/segmentation 产生 target mask，对 vision tower/projector 的 attribution 或 representation 加 masked projection/orthogonality constraint → Minimum Experiment=LLaVA-1.5-7B，100 个带目标实体图像，每图构造 target-QA、same-image non-target-QA、image-rephrase；LoRA 只训 vision/projector/all 三组；Baselines=GA/NPO/MMUnlearner/MANU；Metrics=target AP/TR/ROUGE-L、same-image non-target accuracy、GQA/VQAv2、mask-region feature similarity、relearning/quantization recovery → Expected Contribution=把 forget/retain 从 dataset-level 推到 same-image spatial disentanglement → Risk=mask quality → Collision Risk=中。

5.21 Attack / Verification Lens

LUim 本身就是一种非 adaptive black-box probe：不说 target 名称，只给关联产品/场景，看模型是否重新生成或识别目标。对 unlearning verification，可定义 Local Leakage / Same-Image Utility 双指标；对 recovery，可在 unlearning 后重新注入少量 logo crop 或 contextual prompts，看 target representation 是否快速回来；对 black-box，可只依赖生成图 + detector，不需模型内部权重。新 metric 可用 Local–Global Harmonic Score，但应同时保留原始两个轴，避免再次隐藏 trade-off。

5.22 与 Paper 2 的关系

LU-500 强调“删除时不能误伤周围合法内容”；Agent Zero Memory 强调“记忆时不能丢掉来源、时间和被替代历史”。二者共同指向一个更一般的原则：forget 与 remember 都不是二值操作，而是需要 provenance / scope / locality 的结构化状态变更。

5.23 如果只让我记住这篇论文

  1. Logo 是小区域、高语义密度的特殊 unlearning target。
  2. LU-500 有 9,584 个 validated prompts，explicit 与 implicit 各约一半。
  3. base model 必须先能生成 logo，否则 unlearning 评测无意义。
  4. 局部 erasure 与全局 preservation 必须分开测。
  5. SEGA 弱档保图最好，但删得不够。
  6. 强 guidance 删得更狠，却明显毁全图。
  7. ProLU local 最强，但本质是改 prompt，不是模型忘记。
  8. Remover 承担 ProLU 约 83% 的效果，multi-agent 包装不能替代核心机制。
  9. 现有结果支持 spatially controlled unlearning，但 correlation 不是因果。
  10. 对 MLLM unlearning，最值得迁的是 same-image target-region forgetting vs non-target utility。

5. Paper 2 Full Deep Dive — Agent Zero Memory

5.1 基本信息

Agent Zero Memory: Provenance-Aware Long-Term Memory for LLM Agents
Authors: Pengyuan Zhu, Ming Wu；Affiliation: Zero Labs。Submitted 2026-08-30；arXiv:2608.29606v1 [cs.CL]；10 pages, 3 figures；当前为 arXiv preprint。
Paper · Full HTML

5.2 一句话定位

Agent Zero Memory 不把长期记忆当成一个 vector DB，而是把“什么时候发生”“实体之间如何关联”“哪些事实必须可审计”拆成 timeline + entity graph + citation-locked documentary memory 三套并行表示，再由 agentic retrieval 按 query 动态读取。

5.3 人话版

很多 Agent memory 的问题不是完全搜不到，而是“搜到了错误版本、无法解释来源、或把后来修正与旧事实混在一起”。Agent Zero Memory 的解法是承认没有一种 memory representation 能同时做好 temporal、multi-hop、stable facts：事件时间线保存事实如何变化，entity-event graph 负责跨 session 关系跳转，HDM 保存用户明确写下且必须可追溯的稳定事实。查询时先 intent gate 判断是否需要 memory，再 route source，随后三个 reader 并发做 dense+lexical agentic search，只能引用自己真正打开过的 evidence；证据不够就 abstain。LongMemEval 95.60%、LoCoMo 93.60%，分别比最强公开结果高 0.73、1.10 点。更有意思的是 8 个 backbone 的 LongMemEval accuracy 只差 3.4 点、成本却约差 30×，说明系统质量更多来自 memory substrate，而不是一味换更强模型。

5.4 Background & Research Gap

单一 vector memory 擅长语义近邻，却可能错过 rare identifier；知识图谱擅长 relation traversal，但 extraction/link 错误会固化；context log 保留原文，却随着历史增长越来越贵。更麻烦的是 update semantics：用户先说“deadline Oct 1”，后说“改成 Oct 15”。如果 memory 直接 overwrite，就无法回答“什么时候改的”；如果简单 append，又可能返回旧日期。Agent Zero 的 gap 是把 memory 当成一个需要 provenance、版本历史、query-dependent read cost 的知识系统，而不只是 retrieval cache。

5.5 Core Insight

作者的核心 insight 是representation specialization + provenance discipline。时间问题应读 timeline，多跳问题应走 graph，稳定 profile/preferences 应读 curated HDM；raw source 与 inferred memory 必须分层，不能让推断污染 ground truth。Citation lock 则把“请不要幻觉”从 prompt policy 变成接口约束：answer 只能引用 reader 实际 open 的 item，无法组出 supporting citation set 就 abstain。这属于系统机制设计与形式化约束，不是新神经 objective。

5.6 Method Deep Dive

Chats / files / connectors → preprocess & classify → dense+lexical index → LLM extract events + HDM → agentic connect entity-event graph → query intent gate → source router → 3 concurrent agentic searches → open evidence → citation-locked partial answers → integrate answer + citations + confidence

Build-1：把 chat/file/agent trace 标类型，保留 raw artifacts。

Build-2：所有 item 同时建 embedding 与 lexical index，避免“语义召回”与“精确词召回”互相替代。

Build-3：抽取 Memory Events 与 HDM。Events 是时间主轴；HDM 用 L0/L1/L2 三层文档表示，让 reader 先看便宜摘要再决定是否打开全文。

Build-4：Connect stage 建 entity–event graph，把 people/projects 与 events 连起来，支持跨 session multi-hop。

Read-1：IntentGate 先判断当前 turn 是否需要 memory；不需要就零额外 memory latency。

Read-2：Router 限定 connector / agent histories / HDM 等 source bucket。

Read-3：Events、Graph、HDM 三个 agentic search 并发，各自用 embedding+lexical，agent 自己控制 time/source/speaker filters，并按需 open raw chunks。

Read-4：每个 reader 产出 (answer, citations, confidence)，最后 integrate。时间查询会跳过普通 relevance rerank，避免把“最新”排序打乱。

5.7 核心公式与数学直觉

Memory substrate: M = (T, G_E, D) Provenance: π(x) = < origin(x), timestamp(x), evidence_pointer(x) > Query: q → (a, C, κ), κ ∈ [0,1] Citation lock: C ⊆ O and every atomic claim in a is supported by some c ∈ C otherwise a = ⊥ Hybrid retrieval: RRF(d) = Σ_r 1 / (k + rank_r(d)), k = 60

T/G_E/D 分别是 timeline、entity-event graph、documentary memory。O 是本次 reader 真正打开过的 items；C 必须是 O 的子集，因此不能引用“系统里存在但本轮没看”的证据。RRF 把 dense 与 lexical ranking 合并：rare names/IDs 靠 lexical，paraphrase 靠 embedding。与 Mem0 类“extract→overwrite”最大的机制差异不是 retriever，而是 non-destructive update + provenance。关键超参数包括 top-K、RRF k、open cap、intent/router threshold；过小会 recall loss，过大会增加 cost/context noise。

5.8 Toy Example

科研 Agent 记住“forget10 对应 retain90”。一周后你修正某实验其实用了 retain_shared90 与 retain_celebrity90 两套 split。Timeline 保留旧说法与修正时间；Graph 把 MLLMU、forget10、两套 retain split、对应 run 连起来；HDM 只把经过你明确确认的长期 protocol 写成 curated rule。下次问“什么时候从单 retain 改成双 retain？”时，reader 应走 timeline；问“哪些实验受这次 split 变更影响？”走 graph；问“当前标准 protocol 是什么？”走 HDM，并给原始证据引用。

5.10 Experiment Setup Deep Dive

LongMemEval：500 questions，六类：single-session-user/assistant/preference、multi-session、temporal reasoning、knowledge update，并含 abstention。LoCoMo：1,540 questions，single-hop/multi-hop/temporal/open-domain。Metrics：official LLM-judged answer accuracy；另外报告 median latency、平均 USD/query、prompt/cached/completion tokens。Backbones：论文列出 gpt-5.5、gpt-5.6-sol、gpt-5.6-terra、gpt-5.4-mini、opus4.8、sonnet5、glm5.2、glm5.2fast、deepseek-v4-pro 等配置；LongMemEval 表中 8 个 operating points。Infrastructure：PostgreSQL + pgvector 3072-d embeddings + BM25/fuzzy lexical + RRF k=60。RQ1：能否 SOTA？RQ2：质量来自 substrate 还是 backbone？RQ3：accuracy-cost-latency frontier？RQ4：hybrid retrieval 两通道是否互补？

5.11 Metrics 教学式解释

Judged Accuracy↑：最终回答是否正确，直接但依赖 LLM judge，尤其 near-saturated benchmark 0.x 点差可能受 judge/harness 影响。Median Latency↓：对少数 slow tail 更稳健，但不反映 p95。USD/query↓：结合 provider list price 与真实 token counts；cached token discount 会改变“token 多=贵”的直觉。Accuracy per cent↑：经济效率指标，但把 90→91 与 94→95 当同等价值，部署时需谨慎。Ablation ΔAcc：衡量 retriever channel 的边际贡献。

5.12 Results Deep Dive

  1. LongMemEval 95.60%，Mastra 94.87%，+0.73 pp。强，但 benchmark 已接近饱和，差距需结合 harness caveat。
  2. LoCoMo 93.60%，Mem0 92.50%，+1.10 pp；ByteRover 2.0 为 92.20%。
  3. LongMemEval backbone spread 92.20–95.60，仅 3.4 pp，支持“memory substrate 比 model 更决定质量”的 claim。
  4. gpt-5.5 95.60%，$0.034788/query；deepseek-v4-pro 92.20%，$0.001768/query，约 20× cheaper，只损失 3.4 pp。
  5. glm5.2fast 93.00%，median 6.158s；gpt-5.5 16.311s。低延迟 operating point 很有部署价值。
  6. opus4.8 成本 $0.052221/query，却只有 93.80%，说明更贵 backbone 不自动带来更高 memory QA accuracy。
  7. Hybrid retrieval ablation：gpt-5.6-sol full 95.20；embedding-only 94.00（-1.20），grep-only 93.60（-1.60），lexical-only 93.40（-1.80）。两个通道确实互补。
  8. 即便 restricted retrieval 93.40–94.00，也仍高于很多外部 baseline，说明结构/provenance 贡献可能大于 hybrid 的最后 1–2 点。
  9. Weakest result：论文没有逐一 ablate timeline、graph、HDM、citation lock，因此“每个 store 各自承担多少 SOTA 增益”仍未被定量拆开。
  10. Failure/validity：competitor numbers 来自不同公开 harness，不是统一复跑；这削弱 0.73/1.10 pp SOTA margin 的因果解释。

5.13 Table / Figure Reading

Figure 1：最重要的是 build/read 分离和三 store 并行，不是“画了三个数据库”。它把 write-time structure 与 query-time agentic search 解耦。

Table 1：系统比较真正值得看的是 update semantics、provenance、read cost vs history。Agent Zero 的卖点不是某个 retriever，而是同时选 non-destructive、citation-locked、gated top-k。

Table 3/4：SOTA margin 小，但两 benchmark 同方向。由于 baseline 非统一 harness，应该把它理解为“位于最强公开水平之上”，而不是严格显著优胜。

Table 5 + Figure 2：accuracy 3.4pp spread 对应约 30× cost spread；这是全文最有工程意义的结果。模型选择变成 operating-point policy，而不是默认最贵模型。

Figure 3：accuracy-latency frontier 与 cost frontier 不重合；glm5.2fast 最快但不是最便宜，说明部署要三维 Pareto。

Table 7：hybrid 95.20，单通道掉 1.2–1.8pp；embedding 与 lexical 是互补，而不是“向量检索已经足够”。

5.14 Ablation / Mechanistic Analysis

论文真正的 quantitative ablation 只有 retrieval channel：full→embedding/grep/lexical 单通道，证明 hybrid 的最后 1–2pp。它没有分别移除 timeline、graph、HDM、citation lock、intent gate，因此 representation specialization 的机制证据更多来自设计对应 benchmark question types 与整体结果，而非 factorial causal ablation。这个缺口反而是最值得后续验证的：按 question category 做 store knock-out，才能证明 temporal gain 真由 timeline、multi-hop gain 真由 graph 贡献。

5.15 Claim vs Evidence

Authors Claim：provenance-aware multi-store memory 可结构性减少 fabrication，并达到 SOTA；质量主要 memory-driven。Actually Show：两个 benchmark headline 很强；backbone accuracy 相对稳定；hybrid retrieval 有小而稳定的增益。Not Yet Proven：“fabrication structurally excluded”只对 citation channel 成立，不代表 cited source 本身正确或 answer interpretation 无错；三 store 的独立贡献没完整 ablate；跨系统不是统一 harness；真实组织级 years-long memory、privacy deletion、poisoning、conflicting sources 尚未系统评估。

5.16 Contribution

New System timeline+graph+HDM；New Mechanism citation lock / non-destructive provenance；New Retrieval intent-gated routed concurrent agentic search；New Empirical Finding backbone quality spread 小、cost spread 大；Engineering PostgreSQL/pgvector/BM25/RRF implementation。创新主要是系统组合与 epistemic discipline，不是新的 embedding model 或训练 objective。

5.17 Limitation & Failure Modes

作者明确承认跨系统公开数字 harness 不统一。额外风险：memory poisoning 会被 provenance 忠实地保存，却不代表内容可信；citation lock 防“无来源引用”，不防 source-level misinformation；entity linking 错误会污染 graph；HDM curated notes 可能过时；组织共享 memory 带权限/隐私边界；没有 deletion/unlearning semantics——这对 GDPR/用户忘记请求尤其关键；没有 memory deletion 后 derived event/graph/summary 是否同步消失的验证；没有 adaptive retrieval attack、prompt injection、malicious connector、conflicting-source calibration；成本研究主要是 read side，background build cost 没同等细拆。

5.18 Reproduction View

最小复现建议先只做 LongMemEval：Postgres 建 raw artifacts、events、entity edges、HDM tables；pgvector + BM25/fuzzy；实现 intent gate、router、三个并发 reader 与 citation-open whitelist。先复现 Table 7，因为最容易 controlled：固定 gpt-5.6-sol，full/embedding/grep/lexical 四组。第二步做 category-wise store knockout：timeline-off 看 temporal/update，graph-off 看 multi-hop，HDM-off 看 preference/profile。若 category specificity 不出现，三 store 的机制解释就需要重估。

5.19 Research Value

Baseline Potential：高，尤其 agent memory/provenance。Migration Potential：极高，与你的 Voyager 这类跨 Agent session continuity 很接近。Attack Potential：高，poisoned memory、stale correction、permission leak 都可攻。Evaluation Potential：极高，可把 provenance completeness、stale-memory rate、citation-open discipline 变成 protocol。Benchmark Potential：高，现有 LongMemEval 缺 deletion request。New Paper Potential：极高：memory provenance 与 machine unlearning 的冲突几乎是现成新问题。

5.20 Migration Analysis

Migration A — Provenance-Aware Agent Memory Unlearning：Original Problem=long-term memory faithful recall → Transferable Mechanism=每个 derived item 带 evidence pointer → New RQ=用户删除一个 source 后，能否证明所有 timeline/graph/HDM derivative 都被撤销，而 unrelated memory 不受损 → Method Modification=构建 provenance DAG，deletion 从 raw artifact 向所有 descendants 传播 invalidation；保留 tombstone audit 但禁止内容可恢复 → Minimum Experiment=LongMemEval/LoCoMo 各注入 100 deletion requests，删除后测 target recall、derived multi-hop leakage、unrelated QA、re-add/reacquisition → Baseline=naive vector delete、Mem0 delete、full rebuild → Metric=Deletion Completeness、Residual Derived Leakage、Utility、Deletion Latency、Reacquisition → Expected Contribution=Agent Memory Unlearning benchmark/protocol → Risk=“审计 tombstone”本身泄露被删内容 → Collision Risk=低。

Migration B — Voyager Provenance Memory Layer：Original Problem=单用户聊天 memory → Transferable Mechanism=timeline+entity graph+documentary summary + citation lock → New RQ=跨 Claude/Codex/Grok 的 session continuity 如何避免 stale handoff 与错误 merge → Modification=thread lease/continuity bundle 作为 raw provenance；events 保存 switch/continue；graph 连 repo/branch/thread/agent；HDM 只放稳定 project decisions → Minimum Experiment=20 repos×30 handoff trajectories，制造 5 类冲突：stale bundle、branch divergence、duplicate thread、failed attach、later correction；比较 flat summary、vector memory、tri-store provenance → Metric=resume accuracy、stale-state error、wrong-thread attach、citation coverage、latency → Expected Contribution=provenance-aware multi-agent continuity → Risk=工程量较大 → Collision Risk=中。

5.21 Attack / Verification Lens

可反向形成四类攻击：poison raw source、制造同名 entity 误链接、用时间措辞诱导 router/rerank 返回旧事实、让恶意 connector 内容成为高置信 evidence。Black-box verification 可设计“先陈述 A→后纠正 B→删除 A→问历史/当前/来源”四联测试。对 unlearning verification，provenance DAG 天然能检查 derived memory 是否仍指向已删除 source。新 metric：Provenance Closure（删除后所有 descendants 是否失效）、Stale Recall Rate、Unsupported Citation Rate、Deletion Reacquisition Curve。

5.22 与 Paper 1 的关系

LU-500 的“局部删除不能毁掉全局”可以直接迁成 memory deletion 的“删一条 source 不能毁掉 unrelated memories”；Agent Zero 的 provenance pointer 又能解决 LU-500/MLLM unlearning 很难回答的“target information 到底从哪里流入 derived state”。二者组合成一个非常自然的新方向：provenance-aware localized unlearning。

5.23 如果只让我记住这篇论文

  1. 长期 memory 不该只有一个 vector store。
  2. timeline、graph、HDM 分别服务 temporal、multi-hop、durable facts。
  3. 更新不应 destructive overwrite，旧事实与修正都要有 provenance。
  4. Citation lock 要求只能引用本轮真正打开过的 evidence。
  5. LongMemEval 95.60%、LoCoMo 93.60%，但跨系统 harness 不统一。
  6. 8 个 backbone accuracy 只差 3.4pp，成本却约差 30×。
  7. 因此 memory substrate 可能比盲目升级 backbone 更值得投资。
  8. Dense+lexical hybrid 比任一单通道高 1.2–1.8pp。
  9. 论文最大缺口是没有把 timeline/graph/HDM/citation lock 分别 ablate。
  10. 对 unlearning 最关键的迁移是：用 provenance DAG 做可验证的 agent-memory deletion。

7. Cross-Paper Synthesis

今天两篇共同说明一个趋势：AI 系统里的“删除/记忆”正在从二值状态转向有 scope、有 provenance、有局部性的结构化状态管理。LU-500 告诉我们“目标没了”远远不够，还要问周围合法内容是否被破坏；Agent Zero 告诉我们“记住了”也不够，还要问这个 belief 来自哪里、什么时候成立、后来是否被替代。

可以组合的 mechanism 是：用 Agent Zero 式 evidence pointer / provenance DAG 描述 target information 的来源与 derived states，再用 LU-500 式 local-vs-global evaluation 判断删除传播是否过度。值得借用的实验范式包括 paired before/after、implicit trigger、non-target preservation、store/module ablation、reacquisition test 与 provenance closure。

最可能形成新论文的 gap：Agent Memory Unlearning——用户删除一条聊天、文件或 connector source 后，不仅 raw chunk 要消失，event summary、entity edge、documentary note、cross-agent learned experience 等 derived memory 也必须可验证地失效，同时 unrelated memory 保持。

8. Combined Research Opportunities

Best Migration Direction — Provenance-Aware Multimodal / Agent Unlearning Verification

把“forget set”扩成 provenance graph：raw image/text/source → visual/text representation → derived answer/memory/skill。删除请求沿 graph 传播 invalidation；评测同时包含 target leakage、same-context non-target utility、derived-memory leakage、relearning/reacquisition 与 robustness。这样 LU-500 的 locality 和 Agent Zero 的 provenance 可以统一成一套 verification protocol。

Opportunity 2：Same-image utility：MLLM 删除某个 logo/person/object 后，仍应回答同一图中其它对象、OCR、关系问题。

Opportunity 3：Memory deletion robustness：删除 source 后做 paraphrase、multi-hop、cross-agent handoff、re-add partial evidence，测试 derived knowledge 是否恢复。

Opportunity 4：Spatial provenance：把 detector mask / attribution region 当作视觉 evidence pointer，研究视觉信息从 image tokens → projector → LLM layers 的传播与删除。

9. Collision / Overlap

Strongest Collision：Agent Zero Memory 的目标是“尽量不丢信息、保留历史与 provenance”，而 Machine Unlearning 的目标是“在删除请求后让特定信息不可恢复”。如果系统为了审计保留 superseded facts、events、graph edges、HDM summaries，那么它可能恰好制造了 unlearning 的 derived-data leakage。真正的问题不是 vector DB 里删没删，而是provenance graph 上所有 descendants 是否都被安全撤销。
