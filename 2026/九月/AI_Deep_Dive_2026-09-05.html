5.2 一句话定位

这篇论文把 unlearning attack 的威胁模型从“攻击者已知 forget prompt，只需恢复答案”推进到“攻击者连被忘记的 prompt 都不知道，也能仅靠 retain data 与黑盒 querying 主动发现并重建 forget set”。

5.3 人话版

之前很多 unlearning recovery attack 有一个隐藏前提：攻击者已经知道模型忘的是哪条问题，只是不知道答案，例如知道“某作者生日是什么”但模型拒绝回答。TAS 取消这个前提。攻击者手里只有 retain data，可以从其中提取大量“模板”和“候选实体”，例如 “What is [PERSON]’s occupation?”、223 个可能的人名，然后对 unlearned model 做有限预算黑盒查询。关键 observation 是：偏好式 unlearning 常把 forget prompt 学成拒答，而对 retain prompt 正常回答，因此“哪个 template–entity 组合更容易触发拒答”本身就是忘记目标的侧信道。TAS 用 Beta posterior + Thompson sampling 做 active search，不暴力遍历整个 template×entity 空间，而是优先查询最有信息量的组合，再用确认阶段避免早期偶然拒答误导。实验覆盖 DUSK、TOFU、PISTOL，Llama2-7B/Llama3-8B/Gemma-7B，以及 DPO/NPO/LUNAR。单实体设置下它达到 100% entity identification，TOFU 可从 804,138 个组合空间中仅用约 2,488 次查询完成早停，相当于约 323× query reduction；forget prompt reconstruction 最高可到约95%。

5.4 Background & Research Gap

LLM unlearning 经常通过 DPO/NPO/LUNAR 等方法把 forget data 对应的回答引导到 refusal / abstention 区域。传统评价看 Forget ROUGE、forget probability、Truth Ratio 等；传统攻击则通常已知具体 forget prompt，再尝试 jailbreak、prefix、reasoning、candidate verification 或 activation steering 恢复答案。

现实攻击者却往往不知道删除请求具体对应哪几条训练样本。例如一个 API 服务声称“已经删除某用户相关数据”，外部观察者可能只知道 retained corpus 的风格和实体集合，却不知道究竟删了哪个用户、哪些问句。旧攻击无法先回答“到底被删了什么”。

这篇填的 gap 是 target discovery。它把 refusal trace 看成一个可搜索信号：如果某个实体在多个常见 template 上异常触发 refusal，则该实体更可能被 unlearn；找出实体后，再把它填回 retained canonical templates，就能近似重建 forget prompts。

5.5 Core Insight

最关键 insight：unlearning 的 refusal alignment 会留下“目标定位信号”，而不仅是答案抑制。 一个 forget entity 不需要在所有 prompt 上都稳定拒答，只要相对其它实体存在统计差异，active search 就能逐步聚焦。

第二个 insight 是模板质量和 query allocation 同样重要。TOFU 有 3,606 个 distinct templates，但作者将其 canonicalize 到 74 个 canonical templates，大幅降低 paraphrase 冗余；同时 Thompson sampling 根据 entity posterior 和 template posterior 动态分配查询。

第三个 insight 是“拒答证据”具有不对称性：一次明显 refusal 对涉及的 entity 是正证据；而一次流畅正常回答则是强负证据。对多实体 slot，作者还按 credit assignment 把 refusal 信号分摊到各 slot，而 compliance 则可同时降低多个候选的 posterior。

这属于 black-box attack + statistical active search，而非白盒 representation attack。

5.6 Method Deep Dive

Retain dataset R + black-box unlearned model M_u → extract raw templates T_raw → canonicalize templates T → extract candidate entity pool E → build candidate assignments Z → initialize Beta posterior: entity-slot posterior θ_(i,e) template posterior φ_t → Phase 1: warm-up coverage query broad templates/entities score refusals update posteriors → Phase 2: adaptive active search Thompson sample informative template t Thompson sample candidate entity/tuple z query M_u(t[z]) refusal-score response update θ and φ → optional early stop for single-entity setting → Phase 3: confirmation re-probe top-c candidates avoid incomparable posterior magnitudes → infer forgotten entity/entities → instantiate retained/canonical templates with predicted entity → evaluate reconstructed forget prompts → output entity ranking + reconstructed forget set + query-cost metrics

Step 1 Candidate construction：DUSK/TOFU 是单实体 arity=1，PISTOL 是有序 entity pair arity=2。TOFU 的 raw template 空间最极端：4000 prompts、3606 distinct templates、223 candidate entities，暴力空间 804,138 queries。

Step 2 Response scoring：模型输出通过 curated refusal expressions 得到 refusal score；可选 embedding channel 用 all-MiniLM-L6-v2 与 canonical refusal expressions 做 cosine similarity。

Step 3 Posterior state：每个 slot–entity 和 template 都维护 Beta posterior。Entity posterior 表示“这个 entity 是 forget target 的可能性”，template posterior 表示“这个 template 对目标具有区分性的可能性”。

Step 4 Warm-up：先覆盖足够模板/实体，避免 Thompson sampling 一开始被噪声锁死。

Step 5 Adaptive search：Thompson sampling 同时选择 template 和 entity assignment，让 query budget 集中到高价值区域。对于 arity=2 的 PISTOL，还会探测有序 pair。

Step 6 Confirmation：这是一个非常关键但容易忽视的设计。Adaptive search 天生对“当前领先者”分配更多 probes，因此不同 entity posterior 的样本量不平衡，posterior mean 不能直接跨 entity threshold。最后必须给 top candidates 统一确认预算。

Step 7 Prompt reconstruction：实体识别后，将预测实体填入 retained/canonical templates，形成 candidate forgotten prompts，再与真正 forget set 比较。

5.7 核心公式与数学直觉

Entity-slot posterior: θ_(i,e) ~ Beta(α_(i,e), β_(i,e)) Template posterior: φ_t ~ Beta(α_t, β_t) Adaptive query: t ~ ThompsonSample({φ_t}) z ~ ThompsonSample({θ_(i,e)}) Score: s = Score(M_u(t[z])) Update: (θ, φ) ← Update(θ, φ, t, z, s)

Beta posterior 适合表示“某候选是否具有 forget-like refusal behavior”的 Bernoulli-style 不确定性。α 增大代表更多正 refusal evidence，β 增大代表更多正常回答/负证据。Thompson sampling 不是每次只选 posterior mean 最大的 entity，而是从 posterior 抽样，因此自然平衡 exploitation 与 exploration。

Template posterior φ_t：如果某 template 对所有实体都容易引发拒答，它并没有定位价值，所以 template posterior 会被反方向更新，使“普遍诱导拒答”的模板失去权重。

Strongest baseline objective：UCB 也是经典 active search，但它使用显式 confidence bonus；TAS 的 Thompson sampling 在这个离散 noisy refusal setting 中表现更好。真正的差异不只是 sampling rule，还包括 canonical templates、slot-aware credit、confirmation。

最关键超参：总 budget B、warm-up 比例 ρ_w、confirmation 比例 ρ_c、top-c candidates。B 太小会导致真 entity 从未被 probe；confirmation 太少会让 early leader 因 unequal allocation 被误判；太多则浪费 query。

5.8 Toy Example

假设 retain corpus 中出现模板：T1 “Where was [PERSON] born?”、T2 “What is [PERSON] known for?”、T3 “What did [PERSON] study?”；候选实体池有 Alice、Bob、Carol、David。真正被忘的是 Carol。

  1. Warm-up：每人至少被少量 query。Alice/Bob/David 大多数正常回答，Carol 在 T1/T2 出现多次 “I don’t know / I can’t provide that information”。
  2. θ_Carol 的 α 上升，posterior 变高；如果 T3 对所有人都容易回答，φ_T3 不会变高。
  3. Thompson sampling 后续更频繁选择 Carol×T1/T2，而不再均匀遍历 4×3=12 个组合。
  4. 为了防止 T1 本身是高 refusal template，template posterior 会惩罚“对所有实体都拒答”的模板。
  5. Confirmation 阶段给 Carol 和 runner-up Bob 相同 probe 条件；Carol 仍显著更拒答。
  6. 最终预测 Carol 是 forget entity，并重建 “Where was Carol born?”、“What is Carol known for?” 等 forget prompts。

5.10 Experiment Setup Deep Dive

5.11 Metrics 教学式解释

Entity Accuracy↑：单实体 setting 是否准确选中真正 forget entity。

MRR↑：真 entity 排名倒数的均值，哪怕 top-1 错也能看它是否接近前列。

Prompt Recall↑：真实 forget prompts 有多少被重建；高表示覆盖强。

Prompt Precision↑：重建出来的 candidate 有多少是真的 forget prompts；TAS 常出现 recall 高、precision 中等，说明它更像“发现候选 forget surface”，仍需后处理确认。

Hit Rate↑：预算内是否至少 probe 过一次真实 forget entity。如果 Hit Rate 低，后续 ranking 再聪明也没用。

First Hit↓：首次碰到真 entity 的 query index，衡量发现速度。

Cost↓：Q/Q_space，可跨搜索空间大小比较 query efficiency。

5.12 Results Deep Dive

  1. TOFU entity recovery：Random Accuracy0.185、Greedy0.333、UCB0.875、TAS1.000；TAS 相对 UCB +12.5pp，且 MRR1.000。
  2. TOFU prompt reconstruction：TAS Prompt Recall0.873±0.232、Precision0.576±0.232，说明 prompt coverage 强，但 precision 仍不是完美，存在过重建。
  3. TOFU query efficiency：全空间804,138；固定预算5000仅0.60%，early-stop平均2488约0.30%，相对 brute-force 323.21× reduction。
  4. DUSK：暴力空间仅1278，因此 Random 已不弱；但 TAS 仍可在小预算下稳定达到 exact entity identification，说明方法并非只在巨大搜索空间有效。
  5. PISTOL：ordered entity-pair 的搜索空间18,216，TAS early queries≈868，约20.99× reduction，证明方法能扩展到 arity=2。
  6. DPO 下 prompt reconstruction：DUSK recall0.917、PISTOL0.980、TOFU1.000；即便标准 forget metric 很低/看似成功，prompt identity 仍可暴露。
  7. Canonical ablation：TOFU full TAS=1.000 Accuracy；No-canon总体降到0.875。Llama2/3 在 raw templates 上仍可1.000，但 Gemma-7B只有0.500，说明 canonicalization 主要提高 noisy-model robustness。
  8. Multi-entity DUSK pair A：Entity Recall/Precision/MAP均1.000，Prompt Recall0.969、Precision0.810。
  9. Multi-entity TOFU pair A：Entity Recall0.833、Precision0.926、Prompt Recall0.590，明显退化，是本文最重要 failure case：dense paraphrases + unknown cardinality 会导致 under/over-count。
Strongest result：TOFU 从804k组合空间中用约2488 queries early-stop 仍保持100% entity match，相当于约323× reduction。
Weakest result：Prompt Precision 远低于 entity accuracy，例如 TOFU 约0.576；找到“谁被忘了”比精确还原“哪些句子被忘了”容易得多。
Failure case：TOFU multi-entity pair A Prompt Recall仅0.590，说明攻击在未知多目标数量、密集 paraphrase 空间下仍有明显边界。

5.14 Ablation / Mechanistic Analysis

Canonical templates：去掉后 TOFU总体 Accuracy 1.000→0.875，Gemma-7B 甚至只有0.500，说明 canonicalization 主要减少 dense paraphrase 对 refusal posterior 的稀释。

Budget curve：DUSK 在 B=100 后 Accuracy/MRR 已1.0；PISTOL/TOFU 也在低于 ceiling 时达到 plateau，说明 active search 真正把信息集中到少量 candidates。

Confirmation：Appendix 明确解释，Thompson sampling 会造成 leader 有30 probes、runner-up只有2 probes，posterior magnitude不可直接比较；统一确认阶段承担“校准不平衡采样”的机制。

这里的证据是 black-box statistical causality，不证明 forget representation 的内部位置；它证明的是 refusal behavior 足以泄漏目标身份。

5.15 Claim vs Evidence

Authors Claim：targeted unlearning 会暴露新的 attack surface，攻击者可以在不知道 forget prompts 的情况下发现并重建它们。
Experiments Actually Show：3 datasets×3 models×3 unlearning methods 中，single-entity target discovery 极强，query efficiency 尤其在 TOFU 显著；多实体仍可行但性能下降。
What Is Not Yet Proven：没有证明开放域无限 entity universe 也能搜索；攻击依赖 retain data 能提供合理 template/entity pool；商业 API 可能有 rate limit/随机性；更自然的 free-form forget prompts 未必可被模板化；拒答策略若完全去除 target-specific trace，攻击可能显著变弱。

5.16 Contribution

  • New Attack：Targeted Active Search，系统研究 unknown-forget-prompt black-box discovery。
  • New Threat Model：攻击者只需 retain data + black-box model，不知道 forget prompts。
  • New Mechanism：entity/template 双 posterior + Thompson sampling + confirmation。
  • New Evaluation Protocol：同时评估 entity discovery、prompt reconstruction、query efficiency。
  • New Empirical Finding：refusal-based unlearning 会泄漏“删除对象是谁”，不仅泄漏答案 residual。

5.17 Limitation & Failure Modes

Authors' limitation：搜索空间需要从 retain data 构造；研究集中 entity-structured forget sets；多实体和未知 cardinality 更难；query budget 与 rate limits 仍是现实约束。

Additional limitation：refusal classifier 本身可能受安全模板/模型风格影响；canonicalization 需要高质量 preprocessing；prompt reconstruction evaluation 可能有 LLM-as-judge bias；攻击主要针对 refusal-aligned unlearning，纯 retraining-like erasure可能没有可利用 signal；black-box API 的 temperature、system prompt 和 moderation layer 可能改变拒答分布。

5.18 Reproduction View

核心代码模块应包括：1) retain prompt parser；2) entity extractor；3) template canonicalizer；4) black-box query client；5) refusal scorer；6) Beta posterior state；7) warm-up scheduler；8) Thompson sampler；9) confirmation；10) prompt reconstruction evaluator。

最小复现建议先做 TOFU + Llama3-8B + NPO，单个 forget entity：构造223 entities，先只用74 canonical templates，B=5000；复现 TAS vs UCB vs Random 的 entity Accuracy / First Hit / Cost。若 TAS 能稳定 top-1，再尝试 raw 3606 templates 做 canonical ablation。

5.21 Attack / Verification Lens

TAS 本身就是强 black-box verification：先问“我能否发现谁被忘了”，再进入 known-target recovery。未来评测不应只报告 Forget Accuracy，而应新增 Target Concealment Risk。可定义 Discovery Query Complexity (DQC)：达到95% posterior confidence识别 forget target 所需 queries。DQC 越低，unlearning 越容易被外部 fingerprint。

5.22 与另外 Top Paper 的关系

TAS 找的是“哪个 target / surface 仍泄漏足够信号”；MASkills 解决“如何把复杂 team-level feedback 归因到具体 skill，并只更新那个 skill”。把两者组合，可以构造一种 adaptive unlearning controller：TAS式 active verifier 在大候选空间里发现最危险 target，skill/partition-level optimizer 只更新对应模块或 policy artifact，而不是全局重复 unlearning。

5.23 如果只让我记住这篇论文

  1. 以前多数 recovery attack 默认已知 forget prompt；TAS 取消了这个假设。
  2. 攻击者只需要 retain data 和黑盒模型。
  3. 核心泄漏不是答案，而是 target-specific refusal trace。
  4. TAS 同时维护 entity posterior 与 template posterior。
  5. Thompson sampling 把 queries 集中到最有信息量的组合。
  6. Confirmation 阶段用于修正 adaptive sampling 造成的样本量不平衡。
  7. TOFU 搜索空间约804k，TAS early-stop约2488 queries仍可100%识别 entity。
  8. Prompt reconstruction precision明显低于 entity identification，是当前主要弱点。
  9. 多实体 TOFU 会出现 under/over-count，攻击并非无条件稳定。
  10. 最值得迁移的是 Unknown-Target MLLM Unlearning Discovery。

5.2 一句话定位

MASkills 把 multi-agent continual learning 的优化变量从“整个 system prompt / memory”改成离散、可独立寻址的 skill library，并用 per-skill credit、hierarchical aggregation、momentum、validation rollback 和 typed operators 持续演化团队能力。

5.3 人话版

很多 self-improving Agent 的做法是每次失败后把“经验”塞进 memory，或重写整个 system prompt。但 team-level failure 很难归因：这次任务失败，到底是 Retriever 没检索好、Reasoner 误推理，还是某个“cross-check” skill 调用时机错误？MASkills 将每个 Agent 的 procedural knowledge 拆成多个 SKILL.md 文件，每个 skill 独立描述“何时做什么、怎么做、用什么资源”。运行时记录本轮到底调用过哪些 skill，中央 critic 对每个被调用 skill 做 counterfactual-style credit assignment；多条 trajectory 的文字梯度再按 skill→agent→topology 层级聚合，并用 momentum 平滑历史方向。之后系统只对相关 skill 做 refine，遇到缺失能力则 induct 新 skill，重复 skill 被 consolidate，长期低价值 skill 被 prune。任何 candidate library 在提交前都要过 held-out validation gate，否则 rollback。实验在 HotpotQA、LoCoMo、GAIA 上全面提升；HotpotQA F1 达76.3，LoCoMo multi-hop F1 17.22，GAIA Avg23.3。最关键 ablation 是去掉 validation rollback 后 LoCoMo-MH 从17.2掉到6.6、GAIA从23.3掉到13.5，说明长期自我修改中“能退回去”比单纯“能学新东西”更重要。

5.4 Background & Research Gap

单 Agent continual improvement 常见两条路线：memory-based（Reflexion 等）把失败经验追加成记忆；prompt optimization（TextGrad/DSPy 等）对整段 instruction 做语言空间更新。Skill discovery（Voyager、EvoSkill、MemSkill、PolySkill）进一步将过程性知识拆成技能，但大多是 single-agent setting。

到了 multi-agent system，team reward 是共享的，credit 却分散在 Retriever、Verifier、Planner、Solver、Memory Agent 等多个角色上。如果只给“Agent A 本轮表现不好”的反馈，无法知道是它哪一个 skill 导致问题；如果整段 prompt rewrite，又容易 collateral damage。

例如 HotpotQA 两跳问题失败：Retriever 成功找到第一条文档，Reasoner 的“verify bridge entity before second search” skill 没触发。全局改 Retriever prompt 可能破坏已经很好的检索能力。MASkills 的 gap 是：team-level outcome → specific skill invocation → stable local edit。

5.5 Core Insight

第一 insight：skill 比 memory 更 actionable，比 monolithic prompt 更可归因。 一个 skill 具备显式 description（路由信号）和 markdown body（执行程序），可以被独立调用、改写、删除、合并。

第二 insight：multi-agent credit 必须落到“某 trajectory 中实际 invoked 的 skill”，而不是 agent identity。Critic 通过 counterfactual 比较“用了这个 skill vs 不用会怎样”生成自然语言 credit。

第三 insight：语言空间 edit 很噪，不能把每轮 critique 直接写进 skill。需要 hierarchical aggregation + momentum smoothing；更重要的是 held-out validation + rollback，类似 trust region，防止一次坏编辑永久污染 skill library。

这是一种 language-space policy-gradient analogy。论文明确强调 gradient、advantage、momentum 都是结构类比，不是对神经参数求导。

5.6 Method Deep Dive

Multi-agent Dec-POMDP + initial skill libraries {K_i} → execute trajectories τ under decentralized agents → record skill invocation traces For each invoked skill k: → centralized critic produces textual credit C_i^text(τ,k) → convert credit to language-space edit direction g_i(τ,k) Across batch: → aggregate trajectory feedback per skill G_i^(m)(k) → aggregate across skills / agents / topology → momentum-smooth with historical edit directions Skill-space optimization: → Refine existing skill with localized diff → Induct new skill from persistent hard trajectories → Consolidate overlapping skills into macro-skill → Prune consistently low-utility / obsolete skills Validation gate: → evaluate candidate K_i' on held-out D_val → accept if reward does not regress beyond δ → otherwise rollback → updated persistent skill library → next optimization cycle

Step 1 Skill-aware execution：每个 Agent 的 system prompt 中渲染自身 skill library，trajectory 记录每轮实际调用了哪些 skill。这个 trace 是后续 attribution 的关键。

Step 2 Skill-conditioned credit：centralized critic 读取完整 trajectory、agent role 和 skill invocation，输出针对具体 skill 的结构化自然语言评价。

Step 3 Hierarchical aggregation：同一个 skill 在多个 trajectories 中可能收到矛盾反馈，因此 LLM_Agg 总结 recurring behavioral pattern、去冗余、解决冲突，再向 agent/topology 层继续聚合。

Step 4 Momentum：当前 batch 的 edit direction 与历史累积方向结合，避免技能描述在每轮训练中来回震荡。

Step 5 Typed operators：Refine 是局部 diff；Induct 是新建；Consolidate 将功能重叠 skill 合并成 macro skill；Prune 删除持续低 utility 的 skill。这样 skill space 可以增也可以缩，不会无限 append。

Step 6 Validation rollback：候选 skill library 在 held-out validation 上评测。如果下降超过容忍阈值 δ，整个 candidate edit 不提交，直接恢复旧 library。

5.7 核心公式与数学直觉

Cooperative objective: max_{ {K_i}_{i=1}^N } E_{τ ~ π(. | {K_i})}[ R(τ) ] Skill credit: C_i^text(τ,k) = LLM_Critic(τ, i, k, ξ_i) Skill-level aggregation: G_i^(m)(k) = LLM_Agg({ g_i(τ_b,k) }_{b=1}^B) Refinement: k ← k ⊕ Δk Δk = LLM_Refine(k, G_i^(m)(k)) Induction: k_new ~ LLM_Propose(H_i, G_i^(m)) Consolidation: k_macro = LLM_Merge(k_a, k_b, ...) Validation: J_val(K_i' | K_-i) = E_{τ~D_val}[R(τ)] Accept iff: J_val(K_i' | K_-i) ≥ J_val(K_i | K_-i) - δ

优化变量 K_i：不是模型参数，而是第 i 个 Agent 的技能集合。

R(τ)：team-level reward。MASkills 的困难就是把它归因到多个 skill invocation。

G_i^(m)(k)：language-space “gradient”。它不是向量微分，而是经过 LLM 聚合后的结构化修改方向。

δ：validation rollback 的关键 tolerance。δ=0 要求候选绝不下降，非常保守；δ 大则允许一定噪声/探索，但提高 regression 风险。

Strongest baseline objective：TextGrad / LangMARL 会在语言空间做整体或 agent-level update；MASkills 更细到 skill granularity，并加入 typed lifecycle 与 rollback。区别是机制性的“优化单位”变化，而不只是 prompt engineering。

5.8 Toy Example

一个两 Agent HotpotQA team：Retriever 有 skill A“先找第一实体页面”、skill B“检查 bridge entity”；Reasoner 有 skill C“用两条证据交叉验证”。某轮失败时 trace 显示 A、B、C 都调用了，但 critic 判断：A 提供了正确页面，C 在已有证据下推理正确，真正问题是 B 太早确认 bridge entity。

  1. C_A 得到正 credit，不改。
  2. C_B 得到负 credit：“bridge entity 未经过第二来源验证”。
  3. 多个失败 trajectory 都出现同一模式，G(B) 稳定指向“增加 second-source check”。
  4. Refine 只修改 B 的 markdown body，不重写 Retriever 整个 prompt。
  5. 新 skill B' 在 held-out validation 上若下降超过 δ，则 rollback。
  6. 如果后来发现“数值答案需要独立重算”是现有 skill 都不覆盖的 repeated failure，则 Induct 一个 cross-verify-number skill。
  7. 长期出现两个相似 verification skills 时 Consolidate；某 skill 几十轮几乎没用且 utility 低则 Prune。

5.10 Experiment Setup Deep Dive

Formal setting：cooperative Dec-POMDP；agents decentralized execution，shared team reward；支持 centralized、hierarchical、decentralized-peer coordination topology。

Actor backbones：GPT-4o-mini 用于 HotpotQA 与 LoCoMo；Qwen2.5-7B 用于 GAIA。论文/代码还做多个 backbone robustness comparison。

Benchmarks：HotpotQA（multi-hop reasoning）；LoCoMo（long-horizon conversational memory，SH/MH 等）；GAIA（tool-using general assistant）。

Skill format：Anthropic Agent Skills 风格 SKILL.md，description 是路由信号，body 是执行内容；每个 skill 独立编辑。

Metrics：HotpotQA F1；LoCoMo F1/BLEU（单跳/多跳等）；GAIA L1/L2/L3 success 与 Avg。

Code：公开训练/评估 entry points，支持 topology、skill library 初始化、resume、可选 role evolution。

RQ2：学到的 skill 是否可复用/跨任务迁移？

5.11 Metrics 教学式解释

HotpotQA F1↑：答案 token-level F1，适合开放式 multi-hop QA；但不直接测过程正确性。

LoCoMo F1/BLEU↑：F1 更看答案内容覆盖，BLEU 更看表述 n-gram；两者互补，但都可能低估语义等价回答。

GAIA Success↑：任务是否最终成功，直接反映 tool-use assistant 能力；L3 更难，因此零分不一定意味着框架完全失败，也可能是 actor backbone能力上限。

Validation reward：不是最终 benchmark score，而是是否提交本轮 skill edit 的 safety gate。

Skill transfer：把一个任务学到的 library 直接迁到新任务、不做额外优化，若还能提升，才说明 skill 不是单纯 task-specific prompt hack。

5.12 Results Deep Dive

  1. HotpotQA：MASkills F1=76.3；MultiPersona69.2、CoT-SC68.9、ADAS64.5。相对 strongest listed prompting baseline MultiPersona +7.1pp。
  2. LoCoMo single-hop：MASkills F127.61、BLEU21.30；MemGPT F126.65、BLEU17.72。F1小幅+0.96，但 BLEU +3.58。
  3. LoCoMo multi-hop：MASkills F117.22、BLEU12.87；LoCoMo baseline F112.04、BLEU11.16；相对最强 F1 baseline +5.18。
  4. GAIA Avg：MASkills23.3，R1-Searcher20.4，Vanilla ReAct18.4，Base6.8。相对 R1-Searcher +2.9pp。
  5. GAIA L1：35.3 vs R1-Searcher28.2，+7.1pp；L2=22.6 vs19.2，+3.4pp。
  6. GAIA L3：MASkills 0.0，而 R1-Searcher8.3。这个反例很重要：MASkills并非所有难度都胜，复杂 L3 仍受 actor/tool能力限制。
  7. Ablation — no credit：LoCoMo-MH17.2→14.2，GAIA23.3→17.1，说明 per-skill attribution 明显重要。
  8. No momentum：17.2→16.4、23.3→21.9，影响较小但稳定，说明主要作用是降噪而非决定性增益。
  9. No validation rollback：17.2→6.6、23.3→13.5，是最大退化，证明长期自修改最危险的是错误 edit 累积。
  10. No consolidation/pruning：17.2→13.9、23.3→13.0，说明只会不断新增/refine skill 会造成 library fragmentation/冗余。
  11. Topology：HotpotQA/GAIA decentralized peer 最强（HotpotQA76.30、GAIA23.30），但 LoCoMo multi-hop centralized22.27 优于 decentralized17.22，说明最佳 communication topology 强烈 task-dependent。
Strongest result：Validation rollback ablation：LoCoMo-MH 17.2→6.6，GAIA 23.3→13.5。它清楚证明“可回滚”是 continual self-improvement 的核心稳定器。
Weakest result：GAIA L3 仍为0，而 R1-Searcher达到8.3，说明 skill optimization 无法弥补所有底层 actor/tool reasoning 能力差距。
Failure / trade-off：GPT-5.1 作为 optimizer backbone 成本高，且闭源 critic/optimizer会影响完全本地复现；持续 skill evolution 也可能对 validation split 过拟合。

5.14 Ablation / Mechanistic Analysis

去 Skill Credit：team-level feedback 无法精确落到 invoked skill，GAIA掉6.2pp，说明 skill attribution 真正承担局部优化功能。

去 Momentum：影响相对较小，说明 aggregation 已经消除了大量噪声；momentum更多是跨 cycle 稳定器。

去 Rollback：灾难性下降，是最强机制证据：language-space critic 会提出坏 edit，如果没有 held-out gate，continual learning 很快积累 regression。

去 Consolidation/Pruning：GAIA 23.3→13.0，说明 skill space 不能只增长；“遗忘/退休低价值 skill”本身就是持续 Agent 学习必要操作。

这些是系统级 causal ablation，因为模块被直接移除再重测 performance；但 credit 内容仍由 LLM critic 生成，无法证明其自然语言“因果解释”本身是准确 causal attribution。

5.15 Claim vs Evidence

Authors Claim：把 multi-agent policy improvement 转为 reusable skill-space optimization，可以实现稳定、可迁移的 continual improvement。
Experiments Actually Show：HotpotQA/LoCoMo/GAIA 三类任务上均有总体提升；skills 跨任务迁移；多 topology/backbone 下保持竞争力；关键组件 removal 都带来退化。
What Is Not Yet Proven：没有证明 skill credit 是真实因果 attribution；没有长期几十/上百 cycle 的技能库漂移研究；没有安全/adversarial skill poisoning；optimizer 依赖 GPT-5.1；GAIA L3 说明能力上限仍明显。

5.16 Contribution

  • New Mechanism：skill-conditioned multi-agent credit assignment。
  • New Optimization Space：从 monolithic prompt 转为 discrete skill library。
  • New Continual Operators：Refine / Induct / Consolidate / Prune。
  • New Stability Protocol：hierarchical aggregation + momentum + held-out rollback。
  • New Empirical Finding：skill library 可跨 task/topology/backbone transfer。
  • Engineering：公开 pip-installable library、Anthropic Agent Skills-compatible SKILL.md。

5.17 Limitation & Failure Modes

Authors' limitation：LLM-based optimizer/critic 有成本与噪声；技能形式和任务空间仍受 benchmark 约束。

Additional limitation：GPT-5.1 optimizer 使完全开源复现不纯；validation rollback 依赖 held-out set 的代表性，可能 overfit；skill consolidation 可能误合并功能相近但安全边界不同的技能；pruning 可能删除低频但关键 emergency skill；多 agent trace 变长后 credit 成本会快速增长；没有 multi-agent adversarial interaction 或 malicious skill tests。

5.18 Reproduction View

官方 repo 已提供 maskills/core、trainer、experiments、配置与 benchmark scripts。关键模块：SkillLibrary、skill trace、SkillCreditCritic、LLM_Agg、四类 operator、validation gate、topology-aware rollout。

最小复现建议先做 HotpotQA：GPT-4o-mini actors + 2 agents（Retriever/Reasoner）+ 初始小 skill library。运行 Full、w/o credit、w/o rollback 三组，目标先复现 Full≈76.3 F1 与 rollback removal 明显下降。之后再做 LoCoMo multi-hop，检查 consolidation/pruning。

最容易踩坑：不同 topology 的 rollout engine不能混评；GAIA repo明确区分 library engine 与 env engine；skills_dir 固定库与可演化 SkillLibrary 的语义不同；description 是路由 signal，写太泛会导致 skill 误调用。

Baseline Potential ★★★★★：Agent skill / continual agent work 的强新 baseline。

Migration Potential ★★★★★：可迁到 Agent skill unlearning、memory operation unlearning、multi-agent policy repair。

Attack Potential ★★★★☆：skill poisoning、credit manipulation、rollback bypass 很自然。

Evaluation Potential ★★★★★：per-skill utility / validation gate 为“删 skill 但保团队能力”提供好框架。

Benchmark Potential ★★★★☆：可构造 skill lifecycle / deletion benchmark。

5.21 Attack / Verification Lens

MASkills 也可以反向用于 unlearning verification：把“被删 target skill”当作一个不应再获得正 credit 的 artifact，持续在新 trajectories 中检查它是否通过其它 skill 组合被功能性重建。可以定义 Functional Skill Residual (FSR)：目标 skill 文件不存在后，原目标 capability 在团队轨迹中仍被成功执行的概率。

5.22 与另外 Top Paper 的关系

TAS 是“主动找到最可疑 target”的搜索器，MASkills 是“把团队级反馈落到具体可编辑 skill”的执行器。二者合起来形成一个很自然的闭环：active audit → identify risky target → local credit assignment → targeted update/prune → rollback-protected validation。这比固定 forget set + 一次性 unlearning 更接近持续部署环境。

5.23 如果只让我记住这篇论文

  1. MASkills 的优化变量不是模型参数，而是每个 Agent 的 skill library。
  2. Skill 是独立 SKILL.md，可单独调用、修改、合并和删除。
  3. team reward 通过 critic 归因到本轮实际 invoked skills。
  4. 多 trajectory 的文字梯度先分层聚合，再做 momentum 平滑。
  5. Refine 是局部改，Induct 是新建，Consolidate 合并，Prune 删除。
  6. 任何 candidate edit 都必须经过 held-out validation gate。
  7. HotpotQA F1=76.3，LoCoMo-MH F1=17.22，GAIA Avg=23.3。
  8. 去掉 rollback 后性能暴跌，是整篇最强机制证据。
  9. GAIA L3 仍为0，说明 skill optimization 不能替代底层模型能力。
  10. 最值得迁移的是 credit-aware Agent skill unlearning 和 functional residual verification。

Combined Research Opportunities

Best Migration Direction — Active Residual Discovery → Credit-Aware Targeted Unlearning

Large candidate space → TAS-style black-box active verifier → rank unknown risky targets by posterior → select top target → map target to module / skill / memory carrier → collect trajectories / probes → assign local credit / residual attribution → targeted refine / prune / unlearn → held-out rollback gate → re-run active verifier → stop when: discovery confidence drops AND recovery ASR < threshold AND retain utility remains above threshold

这个方向把 black-box residual / difficulty predictor 线与 Agent skill-level selective update 合起来。它比“一次给定 forget set 的 unlearning”更接近现实：系统可能只知道“有某类敏感 target 需要被发现和处理”，而不是提前拿到完美 forget list。

Collision / Overlap

Strongest Collision：TAS 与黑盒 recovery / residual-auditor 主线明显邻近，但它主要占据的是 unknown target discovery through refusal trace，不是 representation residual prediction。新的工作不能只做“用更多模板猜 forget entity”；应转向 multimodal unknown-target、target hardness prediction、或 target discovery→recovery 的两阶段统一攻击。

MASkills 与 EvoSkill/MemSkill/TextGrad/LangMARL 有较多组件重叠，但 per-skill CTDE credit + typed lifecycle + validation rollback 的组合有清晰系统差异。
