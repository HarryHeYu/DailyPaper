5.2 一句话定位

它用 controlled swap test 证明：长期合作后的 LLM Agents 在最终任务得分上仍大体可替换，但在协调效率上并不可替换，因为 private notebook 中形成了 partner-specific conventions / transactive memory。

5.3 人话版

生产系统往往把 Agent 当可替换进程：某个角色挂掉，就换一个同模型、同role实例，默认只要能力相同就能无缝接手。作者把这一假设做成严格实验。每个setting先建立8个独立团队，所有Agent都来自同一个 frozen base model、相同role prompt，只允许在10个formation episodes后重写一个≤200 token的私有notebook。notebook分 task notes κ 和 partner notes π。随后把两个团队中同role的Agent对调，并在相同held-out tasks上测task score和coordination cost；同时设置placebo——走一遍“成员变更”流程但实际把原Agent放回去，从而控制纯粹的roster disruption。结论是swap对最终score影响较小，却让每单位进展的通信成本上升16%–63%。Hanabi里，换入“有经验但来自另一队”的Agent甚至比没经验新手更费沟通，说明旧团队形成的约定会发生interference。formation从5→10→20轮时partner-specific ratio ρ从0.17→0.27→0.41，表明团队越磨合，成员越不是fungible slot。

5.4 Background & Research Gap

Multi-agent框架一方面强调role modularity，另一方面又强调long-term memory和team learning。两者存在张力：如果长期经验只是generic task knowledge，换人应该免费；如果经验包含“这个具体队友习惯怎么做”，换人就会有隐性成本。

例如Team A长期约定“R2”表示立即执行第二阶段；Team B同样的模型却把“R2”理解为先汇报状态。交换一个Agent后，双方能力没变，但会先按各自旧convention行动，失败后才通过额外message修复。过去cross-play研究常混入model/policy差异，而本文固定model、role、prompt和经验量，只改变partner identity，真正隔离team-specific residue。

5.5 Core Insight

第一，长期memory可拆成generic task knowledge κ 与partner-specific knowledge π。第二，partner mismatch最先表现为coordination cost，而非最终score，因为多数失败还能靠额外沟通修回来。第三，任务coupling越高，partner-specific residue越大：ρ约0.18、0.26、0.44。第四，team age会加剧不可替换性：E=5/10/20时ρ=0.17/0.27/0.41，真正增长的是swap penalty Π而不是generic experience V。

5.6 Method Deep Dive

Frozen base model → K independent teams → fixed role slots/prompts → private notebook μ=(κ,π) → E formation episodes → held-out evaluation → conditions: Intact Placebo Swap Swap-cleared Amnesia Naive → measure task score + coordination cost → derive V, Π, ρ → extract protocol signatures → Jensen-Shannon divergence d → ablate model / temperature / formation length → recovery after swap

Formation：没有weight update，适应全部存在notebook文本里。κ记录环境事实/recipes/failure modes；π记录队友会主动做什么、哪些handoff措辞有效、什么必须说清楚。

Placebo：最关键control。它复制“发生了一次人员变更”的通知和流程，但不换人，因此Swap−Placebo才更接近partner identity effect。

Swap-cleared：换入Agent后清partner notes，测试π是否携带主要旧团队residue。

Protocol signature：自动抽取handoff模板、字段顺序、alias、Hanabi hint→action映射，避免人工主观编码。

5.7 核心公式与数学直觉

μ=(κ,π) Generic experience value: V = benefit(formed team vs naive) Swap penalty: Π = cost/performance gap(Swap vs Placebo) Partner-specific ratio: ρ = Π / V Protocol divergence: d = JSD(S_i,S_j)

ρ回答“长期经验收益中有多少绑定具体partner”；越大越不fungible。d用Jensen-Shannon divergence量化不同团队形成的protocol差异。这里最关键结构变量不是learning rate，而是coupling、formation length和decoding temperature，它们决定独立团队有多少机会形成任意约定。

5.8 Toy Example

  1. Team1与Team2都用同一个模型和相同role。
  2. Team1形成“R2=直接执行”的约定，Team2形成“R2=先确认”的约定。
  3. 交换Team2的Initiator到Team1。
  4. 能力没变，任务仍能完成。
  5. 但新Initiator发R2后，旧Responder按Team1约定直接行动。
  6. 双方发现不一致，再发clarification和correction。
  7. task score只小降，messages/progress明显增加。
  8. 清掉partner notes后部分成本下降，说明旧π是载体之一。

5.21 Attack / Verification Lens

定义 Team Memory Residual (TMR)：成员删除/替换后，剩余Agent的protocol signature与旧团队convention的相似度，以及旧convention trigger成功率。真正的member unlearning应同时检查被删Agent自己的状态和其它成员“关于它”的memory。

5.2 一句话定位

Agent Zero Memory把长期Agent memory从单一vector store升级成“事件时间线 + 实体事件图 + citation-locked documentary memory”的三视图、全provenance底座，并证明高质量memory结构可显著降低对超强backbone的依赖。

5.3 人话版

长期Agent memory常在三个目标之间取舍：时间更新、跨实体关联、稳定事实整理。单一vector index擅长语义召回但不擅长“什么时候变了”；knowledge graph擅长关系却未必保留完整原始证据；summary/profile可读但容易丢source。Agent Zero Memory并行维护三套memory：Memory Events记录每次发生什么、何时更新；entity-event graph连接跨session人物与项目；Hierarchical Documentary Memory保存durable facts。每个item都有origin、timestamp、evidence pointer。查询时先做intent gate和source router，再让三个agentic readers并发搜索各自store；每个reader内部同时使用dense与lexical retrieval，并受citation lock约束——只能引用自己实际打开过的evidence，证据不足就abstain。LongMemEval达到95.60%，LoCoMo93.60%。更重要的是，固定memory/retrieval逻辑只换backbone时LongMemEval accuracy仅差3.4分，但单query成本约差30倍，说明长期memory质量很大程度由substrate而不是最大模型驱动。

5.4 Background & Research Gap

单一memory表示总有blind spot。例如用户去年住北京、今年搬上海：profile overwrite得到当前值但丢历史；vector store可能同时检索两个冲突事实；graph能表示关系却不一定让final answer可审计。

另一个关键是provenance。经过reflection/summary后的memory若失去source pointer，系统很难回答“这条事实是谁说的、什么时候说的”，也难在用户请求纠错/删除时知道该撤销哪些derived facts。本文把provenance从answer附属品提升为memory schema与reading protocol的一等约束。

5.5 Core Insight

第一，没有单一memory structure能同时最好支持temporal update、multi-hop relation和durable profile，因此使用多视图并行存储。第二，provenance要在memory build时绑定，而不是生成答案后补citation。第三，retrieval/representation比backbone能力更决定长期memory QA，controlled sweep只差3.4pp。第四，dense和lexical互补：embedding负责paraphrase，lexical负责rare identifier/exact term。

5.6 Method Deep Dive

Conversations + files + connected sources → Memory Build Memory Events timeline Entity–Event Graph Hierarchical Documentary Memory every item = content + provenance + timestamp + evidence pointer → Query → intent gate → source router → 3 concurrent agentic readers → each reader: dense retrieval BM25/fuzzy lexical retrieval reciprocal rank fusion k=60 agent-controlled filters open raw evidence on demand → citation lock → integrate grounded answers → final answer + confidence + citations

Events：专门保留什么时候发生、何时更新、什么值被supersede。
Graph：连接people/projects/events，支撑跨session multi-hop。
HDM：保存整理后的durable facts/profile。
Hybrid search：pgvector 3072维cosine + BM25/fuzzy，RRF k=60融合。
Citation lock：reader没有open的evidence不能被引用，防止模型用参数知识伪装成memory evidence。

5.7 核心公式与数学直觉

Provenanced item: m=(content, origin, timestamp, evidence_pointer) RRF(d)=Σ_c 1/(k+rank_c(d)), k=60 Citation lock: cite(d) ⇒ d ∈ OpenedEvidence(reader) Final: A=Integrate(A_event,A_graph,A_doc)

RRF的好处是不同retriever分数不必同尺度。k=60使rank差异平滑。Citation lock本质是information-flow constraint：没有被reader实际读取的source不能进入grounding链。与strongest baselines相比，核心区别不是“多一个vector index”，而是三种structured memory + provenance discipline。

5.20 Migration Analysis

方向A — Provenance-Guided Agent Memory Unlearning

Original Problem →每个memory item有origin/evidence。
Transferable Mechanism →用support set定义删除范围。
New RQ →删一个source后，哪些events/edges/HDM facts应删除，哪些因多source支持应保留？
Method Modification →给每个m维护S(m)；删s时若S(m)={s}则删除/重建，否则只重算confidence。

5.21 Attack / Verification Lens

可做 Provenance Poisoning：恶意source重复注入错误事实，让support count看似很强；或把partner-specific convention写入κ逃避member-exit cleanup。可定义 Citation-Closed Forgetting：删除source后，任何final answer的citation chain都不能到达该source，同时behavior也不再依赖它。

5.22 与另外 Top Paper 的关系

Interchangeability告诉我们“关于特定partner的经验会形成关系性耦合”，Agent Zero告诉我们“memory必须有source/时间/evidence provenance”。组合后自然得到organizational unlearning：成员退出时清理其它Agent对它形成的π，但保护被其它来源独立支持的task knowledge。

5.23 如果只让我记住这篇论文

  1. 长期Agent memory不应只是vector store。
  2. 三种视图分别负责时间、关系和durable facts。
  3. 每条memory都带origin/timestamp/evidence。
  4. 三个agentic readers并发搜索。
  5. citation lock禁止引用没实际打开的证据。
  6. LongMemEval95.60、LoCoMo93.60。
  7. 固定memory只换backbone时accuracy仅差3.4分。
  8. 但成本可相差约30倍。
  9. hybrid retrieval比任一单通道高1.2–1.8分。
  10. 对unlearning最重要的是provenance能定义哪些memory后代应被撤销。

Cross-Paper Synthesis

两篇共同说明：长期Agent系统积累的不只是task knowledge，而是带有来源、时间与关系身份的组织知识。Interchangeability证明关于具体partner的经验会形成coordination residue；Agent Zero Memory说明如果memory没有结构化provenance，后续审计、更新、删除就很难知道该动哪里。

共同趋势：Agent memory从检索准确率问题走向组织状态治理问题。

最佳baseline：Agent Zero Memory + swap-test protocol。
最佳attack：partner-convention poisoning。
