人话版：这篇论文到底干了什么？

GRPO 和 GSPO 这类用可验证结果奖励训练推理模型的方法，通常只知道一整条答案对还是错，却把同一个分数广播到这条轨迹里的每一个 token。于是关键推导步骤和“我们可以看出”这样的套话拿到一样的学分。SAEPO 的做法是：先用在通用语料上预训练并冻结的稀疏自编码器，把每个生成 token 的隐状态变成稀疏语义特征；再在同一道题的正确轨迹和错误轨迹之间做不要求位置对齐的软对齐，得到一个“这个 token 更像成功解答还是更像失败解答”的语义分数；最后把它标准化后加到原来的结果优势上。验证器、重要性比率、裁剪和 KL 都不变，推理时也不需要 SAE。作者把它插进 GRPO 和 GSPO，在 Qwen3-1.7B-Base、Qwen3-4B-Base 和 OLMo-3-7B-Base 上评了六个数学基准和两个代码基准，数学平均最多提高 6.63 个百分点，代码平均最多提高 5.57 个百分点，并且在匹配墙钟预算下训练准确率爬升更快。它重要，是因为它把可解释的稀疏特征直接写成了可插拔的 token 级学分，而不是再训练一个过程奖励模型。

Background & Research Gap

结果可验证的强化学习（RLVR）已经成为提升大语言模型数学与代码推理的主流配方。对每一道题，策略采样一组完整解答，由规则验证器给出对错，再像 GRPO（Shao et al., 2024）或序列比率版本的 GSPO（Zheng et al., 2025）那样，用组内归一化后的标量优势去更新策略。这条路的吸引力在于不必标注逐步推理，但代价也很清楚：监督只在轨迹末端出现，却必须被广播进每一个 token 的策略梯度。KTAE（Sun et al., 2025）已经指出，GRPO/DAPO 风格的方法把同一条轨迹里的所有 token 看成贡献相同；OAR 和 GTPO/GRPO-S 也把这个问题表述为长链推理上的粗粒度学分。

一个具体反例足够说明失败模式。假设一道几何题采样了八条轨迹，其中三条最终答案正确。正确轨迹里既有“圆的内接四边形对角互补”这样的关键步骤，也有“接下来我们考虑”这类话语标记；错误轨迹里也可能写对了“内接”和“对角”，却在最后把公式用错。结果优势会给整条正确轨迹的每一个 token 同样的正分，给整条错误轨迹同样的负分。于是正确轨迹里的套话被强化，错误轨迹里其实有用的中间概念被一并惩罚。现有 token 级改进并没有真正解决“语义对齐”：有的依赖位置或启发式重加权，有的需要额外的过程标注或可学习奖励头。SAEPO 想回答的缺口是：能不能只用当前策略在同一道题上的对错轨迹，以及一个冻结的、非任务特异的稀疏特征空间，就构造出问题局部、且不必按位置对齐的 token 级学分，并作为插件接到现有目标上。

Core Insight

同一道题的正确轨迹和错误轨迹，会在不同位置表达相近的中间概念。如果先把 token 隐状态映射到稀疏、近乎单语义的 SAE 特征，再用温度软对齐比较“这个 token 更像正确组还是更像错误组”，就能得到一个只依赖问题内部对比、而不依赖逐步标注的局部信号。把该信号加到原来的结果优势上，广播式学分就变成了有方向的 token 级塑造；全对或全错的题目则自动退回纯结果更新。反直觉之处在于：SAE 是在 FineWeb-Edu 上针对基座模型预训练的，并不是数学专用特征器，却能在数学和代码 RL 中稳定复用。

Method Deep Dive：从 Input 到 Output

输入。对每个问题 q，当前策略 πθold 采样 G 条完整轨迹 {oqg}g=1G。每条轨迹有生成 token 下标集合 𝒥qg，以及目标层隐状态 Hqg,t∈ℝd。验证器给出标量结果奖励 rqg（数学为正确性加格式奖励，代码为全部单测通过）。同时备有一个在 RL 之前训好、全程冻结的 BatchTopK SAE 编码器 fenc。

步骤 1：按对错切分。用最终答案对错把组拆成正确集 𝒞q 和错误集 ℐq。数学里只有格式分、答案仍错的轨迹算错误。若某一侧为空，这道题在本轮没有对比，不产生 SAE 信号，只保留原来的结果优势。这一设计避免了在全对或全错组里硬造对比。

步骤 2：编码为稀疏特征。对每个生成位置 t，计算 ϕqg,t=fenc(Hqg,t)∈ℝn。Qwen3-1.7B 使用第 21 层、隐维 2048、32 倍扩展得到 65536 个潜在特征，目标平均稀疏度 k=8；4B 用第 27 层、k=16、81920 维；OLMo-3-7B 用第 21 层、k=16。SAE 在对应基座模型的 FineWeb-Edu 激活上用 EleutherAI sparsify 与 Adam（学习率 10−4）训练，之后冻结。

步骤 3.1：跨轨迹语义对齐。作者不按位置对齐，因为同一中间结论可能出现在不同步。对轨迹 g 的 token t，以及同题另一条轨迹 h≠g 中的每个 token u，用余弦相似度除以温度 τ 做 softmax，得到对齐权重 ωqg,t,u(h)，再对 h 上的余弦加权求和，得到该 token 与整条 h 的匹配分 mqg,t(h)。然后分别对正确组（去掉自身）和错误组求平均，得到 sqg,t+ 与 sqg,t−。默认 τ=0.05。

步骤 3.2：语义分数。Sqg,t=ρq[sqg,t+−sqg,t−]，其中平衡系数 ρq=2min(|𝒞q|,|ℐq|)/(|𝒞q|+|ℐq|) 会压低极不均衡的对错比。正分表示该 token 更像正确轨迹里的概念，负分则相反。

步骤 4：优势塑造。原始 S 的尺度随 batch 变化，因此在一个更新批次里对所有已定义分数做标准化，得到 S^qg,t；未打分 token 置零。最终优势为 Aqg,t=Aqgout+αS^qg,t，默认 α=2。把这个 token 级优势代回 GRPO 的 token 比率目标或 GSPO 的序列比率目标即可。验证器、比率构造、裁剪和相对参考策略的 KL（系数 β=0.02）一律不动。推理时不跑 SAE。

一个反直觉设计。人们容易以为必须用数学语料训练 SAE，或在 RL 中微调它。作者反而用通用语料预训练并冻结。附录显示，RL 结束后数学轨迹上的重建余弦只从 0.957 降到 0.932–0.940，top-1000 活跃特征仍保留 94.3%–97.1%。另一个反直觉点是：软对齐允许一个 token 同时和多条轨迹的不同位置匹配，而硬对齐（表 10）会把六基准平均从 38.68 降到 37.41，且 AIME25 掉到 0.0。方法因此承认“同一概念不必出现在同一时间步”。

RL 形式化。状态是问题加已生成前缀；动作是下一个 token；策略是 πθ；轨迹是完整解答；奖励是稀疏、规则型的结果奖励（数学 Racc+Rfmt，格式分为 0 或 0.1；代码为 0/1）。优势是组内归一化的 Aout 加上标准化语义项。学分分配发生在 token 级，但语义项本身来自问题组内的对错对比，而不是逐步真值。KL 对着冻结参考策略。该信号仍可能被黑客利用——如果模型学会在错误轨迹里避免激活“正确组常见概念”，或在正确轨迹里堆砌这些概念——但受控最小编辑实验表明，引入局部错误会降低语义分，修复错误会提高语义分。计算上，对齐要对每个 token 扫描同题其他轨迹的全部位置，复杂度随 G 和生成长度上升；作者把这项放在策略更新之前，用已经算好的隐状态做一次冻结编码，不必反传 SAE。GSPO 版本只是把塑造后的 Aqg,t 在序列比率目标里按轨迹使用：因为 GSPO 的比率是整句几何平均，token 级优势并不会变成逐步比率，而是改变这条轨迹被加权的方向与幅度。换言之，同一套语义分既能改写 GRPO 的逐步更新，也能改写 GSPO 的整句更新，真正被替换的只有广播式 Aout。

关键公式 / Objective

结果优势沿用 GRPO 风格的组内标准化：

Aqgout=rqg−μqrσqr+ϵstd

当组内奖励标准差过小时置零。语义分数与塑造后的优势为

Sqg,t=ρq[sqg,t+−sqg,t−],Aqg,t=Aqgout+αS^qg,t.

直觉是：ρq 避免“七对一错”时错误轨迹主宰对比，s+−s− 给出方向，α 控制语义项相对结果项的权重。与 baseline 的关键区别不是换了一个新的策略目标，而是只改优势：GRPO 仍用 token 级重要性比率，GSPO 仍用序列级几何平均比率。关键超参数是 α=2、τ=0.05、钩子层（1.7B 为第 21 层）和稀疏度 k。当 α=0 时退化为原算法。

可手工推演的 Toy Example

设 G=4，某几何题采到两条正确、两条错误轨迹。正确轨迹 A 在某步写出 token“interior”，错误轨迹 C 在另一位置也写了相近的“内角”概念，错误轨迹 D 则充满套话。对 A 中的“interior”，它与 C 的匹配分可能中等、与 D 较低，但与另一条正确轨迹 B 中的“内接”很高，于是 s+ 大于 s−，S>0。同一条正确轨迹里的“we”与对错轨迹的套话都相似，s+ 与 s− 接近，S 接近 0；标准化后还可能为负。若把四条轨迹全部改为正确，则 ℐq 为空，本步不产生 SAE 项，更新退回纯 Aout。这个例子说明：SAEPO 奖励的是“在成功解法中更常见的概念”，而不是“处于正确轨迹中的任意 token”。

Baseline Comparison

对照包括：Vanilla GRPO / GSPO（最直接的结果广播基线）；KTAE（token 级学分）；THR（2026 年的 token 级方法）；GTPO。作者强调在每个骨干和每个优化器块内比较。最强可比较基线并不固定：Qwen3-1.7B 数学平均上，GRPO 块是 THR 的 36.72，GSPO 块是 THR 的 37.12；OLMo-3-7B 的 GRPO 块则是 KTAE 的 38.75。GTPO 在多组设置中大幅落后（例如 1.7B 上 GRPO+GTPO 数学平均仅 27.50），更像失败对照而不是最强对手。SAEPO 在所有骨干、两种优化器和两类任务的平均指标上超过上述学分方法。

Experiment Setup

模型为 Qwen3-1.7B-Base、Qwen3-4B-Base 与 OLMo-3-7B-Base，全参数微调，不用 LoRA。数学训练数据是 DeepScaleR-Preview-Dataset 的 40315 道竞赛题，与六个评测基准及 AIME25 无交叉（训练池中的 AIME 限于 2024 年前）。代码训练用 DeepCoder-Preview-Dataset 中 TACO、SYNTHETIC-1 和 LiveCodeBench-v5 的训练划分。采样 G=8、温度 1.0；评测为贪心解码。最大生成长度数学 8192、代码 4096。优化器用 AdamW，学习率 10−5 恒定，KL 系数 0.02，种子 42。1.7B 每步 32 题（256 条轨迹）共 250 步，4B/7B 每步 8 题共 1000 步，因而都消耗 64000 条轨迹。主结果报告最后一个检查点，不按方法挑最好点。数学奖励 Rout=Racc+Rfmt，用 math_verify 核对 boxed 答案。单卡 NVIDIA RTX PRO 6000 Blackwell（约 97 GB）：7B 约 80 小时，4B 约 36 小时，1.7B 约 14 小时（含 8.1 GPU-hour 的 SAE 预训练）。

评测基准：MATH-500、GSM8K、AIME25、AMC、Minerva Math、OlympiadBench，以及 LiveCodeBench-v5 与 LeetCode Dataset v0.3.1（228 道留出题，需全部单测通过）。报告未加权平均。

Results：按研究问题看证据

RQ1：把 SAEPO 插入 GRPO/GSPO，能否在匹配采样预算下提高数学和代码平均，并超过现有 token 级学分方法？ Setup 即上节的三骨干、两优化器、六加二基准。Observation（表 1）：Qwen3-1.7B 上，GRPO 数学平均从 35.56 升到 38.68，GSPO 从 36.63 升到 39.55；相对最强学分基线 THR（36.72 / 37.12）仍高出约 2 个百分点。Qwen3-4B 上，GRPO 从 48.43 到 49.97，GSPO 从 47.73 到 50.15。OLMo-3-7B 上提升最大：GRPO 从 35.29 到 41.92（+6.63），并超过最强基线 KTAE 的 38.75；GSPO 从 41.71 到 43.07。代码侧，4B 的 GRPO 平均从 12.11 到 17.68（+5.57），主要来自 LeetCode 的 10.96 到 22.81。Interpretation：平均收益在三骨干上同向，而且不是只打赢“裸”GRPO。绝对值上 1.7B 的 AIME25 仍是 3.3 或 6.7，说明难题样本很少、单次评测噪声大；相对提升应和绝对水平分开看。最弱结果也很清楚：1.7B 上 GSPO+SAEPO 的 LCB-v5 为 5.02，低于 vanilla GSPO 的 5.73；4B 上 GRPO+SAEPO 的 LCB-v5 为 12.54，略低于 vanilla 的 13.26。代码收益集中在 LeetCode，并不均匀。把最强结果（OLMo-7B 数学 +6.63，4B 代码平均 +5.57）和这些局部回退放在一起，更能看清交易：平均分提高并不等于每个子集都提高。

RQ2：语义分数是否对局部步骤对错敏感，还是只是结果标签的另一种写法？ Setup：从 976 道训练题中筛出可编辑轨迹，由 Qwen3-32B 做最小编辑（在正确步骤中引入一处可验证错误，或修好一处错误），盲评确认后得到 304 次引入错误和 120 次修复；编辑跨度外的 token 保持不变。然后重算语义分，并用编辑点后的前缀各采样 32 条续写估计成功率。Observation（表 3–4）：引入错误使编辑处语义分平均下降 0.58（95% CI [−0.70,−0.47]），续写成功率从 0.74 降到 0.17（95% 的编辑会下降）；修复错误使语义分上升 0.16（CI [0.06,0.25]），成功率从 0.15 升到 0.32（62% 的编辑会上升）。Interpretation：语义分平均上顺着局部对错移动，而且这些编辑确实改变了最终做对的概率。它不是简单复制整条轨迹的对错——图 5 也显示，正确轨迹里的停用词仍可拿负分，错误轨迹里的“面积”“棱锥”等概念仍可拿正分。但修复侧样本量更小、成功率提升也不对称，说明“改对一步”并不保证能救回整道题。

Ablation

表 2 是最关键的机制消融（1.7B + GRPO）。用原始隐状态对比替代 SAE 特征，六基准平均只有 36.53，略高于 vanilla 的 35.56，但远低于 SAEPO 的 38.68，且 AIME25 掉到 0.0：稀疏特征空间不是可有可无的包装。把语义分符号反转，平均暴跌到 25.48，低于不做塑造：方向错了比没有信号更糟。表 7 换钩子层：第 21 层最好（38.68），第 15 层只有 35.92，甚至略低于 vanilla，说明不是越浅或越深越好。表 8 扫稀疏度 k：k=8 为 38.68，k=4 为 36.54，k=32 为 38.50 但 GSM8K 和 AIME25 波动大。表 9 用同一批数学 rollout 比较编码器：SAE 40.12，普通自编码器 38.50，MLP 只有 35.40，支持稀疏性本身有贡献。表 11–13：α=4 降到 35.77，过强会伤害；τ=0.02 平均 39.32 反而略高于默认 0.05 的 38.68，说明默认超参并非处处最优；去掉平衡系数 γ=0 降到 36.90。

Claim vs Evidence

Authors Claim：SAEPO 是可插拔的 token 级学分模块，能在多种骨干和两种目标上提升数学与代码平均，并提供可解释、对局部对错敏感的语义信号，同时额外计算很小。

Experiments Actually Show：在三个基座模型和匹配的 64000 条轨迹预算下，数学未加权平均确实全面提高，最大绝对提升出现在 OLMo-3-7B 的 GRPO（+6.63）。代码平均也提高，但 LCB-v5 上有两次小幅回退。受控编辑实验支持语义分平均上随局部对错变化。墙钟开销主要不是 SAE 前向，而是更长的生成。三种子重复只覆盖 1.7B+GRPO 的数学平均。

What Is Not Yet Proven：没有工具调用、长视界智能体或多轮环境中的证据；没有证明 FineWeb-Edu SAE 对任意领域都够用（4B 的重建余弦只有 0.799，明显弱于 1.7B 的 0.960）；没有与训练好的过程奖励模型做直接比较；也没有在指令微调模型或更大稠密模型上验证。AIME25 的离散分数（0.0/3.3/6.7/10.0）不宜单独解读为能力跃迁。

Contribution

类型：New Mechanism（冻结 SAE 特征上的问题内软对齐学分）+ Empirical Finding（通用语料 SAE 可在数学/代码 RL 中复用，反转信号会显著变差）。它不是新的验证器，也不是新基准。

Limitation

作者在结论中把扩展到其他可验证领域、其他 SAE 架构和其他优化算法列为未来工作，正文没有独立的 Limitations 节。额外限制包括：依赖组内同时出现对错轨迹，简单题或过难的组会频繁退回广播优势；语义分是相关而非因果，受控编辑由另一个模型提出，可能偏向“容易改写的算术步”；代码未发布，复现成本不低；单卡、单一数据顺序、评测多为贪心解码，可能高估稳定性。

Research Value

对当前 RL for LLM 的价值在于：它给出一种不训练 PRM、不改目标函数的学分插件，并且用最小编辑和反转信号证明方向是机制的一部分。对智能体和长视界任务，更有迁移价值的是“在同一任务的成功/失败轨迹之间做稀疏特征对比”，而不是数学基准上的两三个点。

Migration / Research Transfer

Original Problem → Transferable Mechanism。原问题是结果奖励过于稀疏，无法区分轨迹内部哪些 token 该强化。可迁移机制是：冻结一个通用稀疏特征器，在同一任务实例的成功与失败轨迹之间做不对齐的语义对比，并用该对比去塑造优势。

New Research Question。在延迟后果的智能体环境里（例如今日的 SMB Bench：今天的缺货会在数周后表现为客户流失），能否用状态或动作片段的 SAE/稀疏特征对比，把季度利润这样的稀疏回报写回数天前的下单动作，而不是只在轨迹末端做 RLOO/GRPO？

Method Modification。把“token”换成“一天的工具调用或状态摘要”，把正确/错误改成“同起始状态下高回报续写 vs 低回报续写”，保留软对齐与 α 塑造，验证器改为环境回报或规则化的经营指标。

Minimum Experiment。模型用 Qwen3.8 或同等 7B–27B 工具智能体；数据集用 SMB Bench 的共享状态续写（论文已有 Day-60 panel 与 MaxRL 设定）；基线为原文的 CISPO/MaxRL 与连续美元 RLOO；指标为验证店与密封测试店的季度利润、缺货千克数、以及保护承诺是否中途撤销。先在固定起始状态下做 4 次更新、每步 16 条续写，比较加入特征学分前后的密封店利润差。可证伪假设：若特征学分不能在密封店上相对纯结果 RL 提高利润，或只减少“看起来像成功轨迹的措辞”而不减少缺货，则机制没有迁过去。估计计算成本中等（原文学共享状态 MaxRL 花费 605.82 美元量级），撞题风险来自 AnchorCredit、Attention PRM 和一批过程奖励工作，应用场景需强调延迟经营后果而非数学逐步分。

Risk。经营轨迹比数学解更长、更异构，SAE 可能对齐到文风而不是决策；环境非平稳时“成功组”会漂移。

五句话总结

SAEPO 用冻结 SAE 在同一道题的对错轨迹之间做软对齐，把结果优势改写成 token 级语义学分。它不改验证器和策略目标，推理也不需要 SAE。三骨干、两优化器上的数学平均都提高，OLMo-7B 的 GRPO 最大提升 6.63 个百分点；代码平均提高但 LCB 有回退。反转信号会明显变差，受控编辑支持局部对错与语义分同向变化。最值得借的不是数学涨点，而是把问题内稀疏特征对比当成一种可插拔的学分模块。

人话版：这篇论文到底干了什么？

语言模型智能体越来越多地被要求管理持续多日的运营，而不是做完一道单轮题。今天少订货，货架空了会藏住流失的进店需求；今天短交，几周后客户订单会悄悄变小；紧急补货又会抽干现金流。作者推出 SMB Bench：一个校准过的 90 天批发模拟器，包含 18 个成对因果任务和 859 次前沿模型轨迹，用来问一个更窄的问题——什么样的经验和学习信号，能让智能体在没见过的店铺里，注意到、归因并作用于自己决策的延迟后果。16 个模型的排行显示，多数前沿系统在“环境已改变”的季度里跑不赢一条固定采购规则；只有 GPT-6 Astra 和 Gemini 4 Carbon 在改变季度上显著超过该规则。随后他们对 Qwen3.8 做共享状态的短程 MaxRL：验证店利润从 +1216 美元升到 +2419 美元，密封测试店仍整体亏损（−4495 对未训练的 −5984），但缺货和中途撤销保护承诺明显减少。这篇工作的价值不在于又一个代理排行榜，而在于把“延迟后果”做成可审计、可训练、并且会在密封店上暴露协调失败的问题。

Background & Research Gap

现有智能体基准多半奖励短期正确或工具调用成功。经营环境的麻烦是：关键后果在时间上错位，观测还会被自己的行为审查——空货架让你看不见本该发生的需求。若只用单步代理奖励（例如当天有货），模型很容易 Goodhart。作者用 42 个候选机制在 168 个审计世界里筛选，只接纳能在至少 4/6 家店造成不低于 0.25% 基准营收损伤、且通过捷径检查的任务。最终留下供应商冲击、反应型客户账户和稳态对照。缺口因此很具体：不是“智能体能不能下单”，而是它能不能在 90 天视界里，把数周后的客户流失归因到今天的覆盖决策。

Core Insight 与方法流水线

核心判断是：延迟后果必须先被环境因果地实现，再被写成可对比的学习信号。流水线是：校准 90 天批发世界 → 智能体每天用 SQL 和订单工具行动并写备忘 → 用相对固定采购规则的季度利润评分 → 在共享的 Day-60 状态上做短程续写 RL，而不是从零开局刷完整季度。Agent 结构可写成：输入（当日库存、订单、账户与工具结果）→ 规划（模型在 <think> 中做预测与解释）→ 记忆（受限制的笔记）→ 工具（SQL、下单）→ 环境推进一天 → 反馈（库存、缺货、现金流）→ 更新（评测时冻结，训练时对共享前缀做 MaxRL）。状态是店铺日历状态加笔记；长视界问题在 10 步也许只是订货平滑，在 100 步后客户可能已经流失，在 90 天约等于 90 个决策日之后，错误会沿库存和账户复合。失败传播的典型例子是密封店里未训练模型最差的一季：一次对缺货的错误解释触发 31 次撤销覆盖，造成 441 kg 缺货和 3913 美元量级的单季亏损。

训练方面，商店 1–4 用于转录与起始状态，商店 5 做验证和提示词打磨，商店 6 只在战役结束时评一次。共享状态二元 MaxRL 为 4 次更新、每次 16 条续写，学习率 3×10−5，温度 1.0，优化器为 CISPO（cmax=4.0），花费 605.82 美元；对照的连续美元 RLOO 更贵（1229.56 美元）且附录指出存在幸存者偏差。奖励来自季度经营结果，稀疏、环境给出、可被代理指标黑客化；作者因此把评测提示与训练提示分开，并在附录讨论单步代理奖励的 Goodhart。

Experiment Setup 与主要结果

RQ1：前沿模型是否已经能在改变的世界里超过固定规则？ 16 个模型、18 个任务、共 859 次计分运行。表 5：固定采购规则全任务平均 +6412 美元；GPT-6 Astra +7749、Gemini 4 Carbon +7703，改变季度相对固定规则分别为 +1337 和 +1291 美元，95% 区间下限大于 0。Claude Fable 5.2 全任务 +7275，但改变季度区间穿过 0。Grok 4.7 为 −4722，DeepSeek V4.1 Flash 为 −3036，许多更小或更便宜的模型在改变季度上落后固定规则超过 1 万美元。Inference 成本也很高：Astra 每次运行 213 美元。结论是：领先模型能在部分改变季度里创造价值，但“整体强”并不等于“会处理延迟后果”；固定规则仍是必须超过的强基线。

人话版：这篇论文到底干了什么？

少步视频蒸馏里，DMD 一类目标常常很快把单帧外观和布局学好，运动却滞后，还容易在潜在块的四帧里出现周期性卡顿。HorizonFlow 认为问题出在 DMD 梯度没有把外观、布局和运动分开：静态部分信噪比高，运动部分又缺两种信号。它在普通 DMD 上加了两个修正。Chunk Evenness 在像素空间测量四帧相位上的运动是否均匀，并且只纠正“比训练视频更不均匀”的多余卡顿，同时拒绝靠冻结或模糊取巧。Semantic Commitment 则用来稳住语义和时间承诺，避免少步学生在外观收敛后仍然改布局或丢运动。整个学生只训练 600 次迭代、8.4k 样本、约 51 A100 小时，在 Wan2.1-T2V-1.3B 的 VBench 上得到 85.64 的总分，超过 50 步教师的 82.81，也超过 FastWan、CoDMD、rCM 和 Self-Forcing；严重卡顿比例从数个百分点降到 0.3%。推理 4 步、832×480、81 帧在一块 A100 上约 10.6 秒，与其他少步方法同一量级，真正省下的是训练计算。

Background & Research Gap 与 Core Insight

少步蒸馏希望把 50 步教师压到 3–4 步。已有方法要么堆百万级样本（rCM 报告 2.56M 样本、约 16k A100 小时），要么仍留下可见的块状卡顿。作者把 DMD 梯度拆开看，发现布局和外观的信噪比远高于运动，于是每帧质量会在几百次迭代内先收敛，运动还在噪声里。缺口是：如何在极小训练预算下，专门把“运动是否均匀、语义是否守住”补进更新，而不是再砸数据。核心洞察是把校正写成对伪目标的位移：x~+ΔCE+ΔSC，并且 CE 只惩罚超过训练集的不均匀，避免把视频冻住。

Method 流水线

输入是教师与噪声；学生按 k=1,2,3,4 步从纯噪声滚动。先算标准 DMD 更新，再在随机时间窗上解码灰度帧，用相邻帧 RMS 差构造四个相位均值，定义均匀度 E(z)=∑p=03(ap/a¯−1)2。相对训练视频滑动平均 E¯data 计算多余不均匀 e，仅当 e>0 时沿 ∇zE 走几步，且只有降低 E、同时保持运动量和高频能量的步骤被接受，形成 ΔCE。Semantic Commitment 在此基础上加入对语义/时间承诺的校正 ΔSC。两者与 DMD 一起更新学生和 critic，1:1 交替，共 600 次迭代，学生与 critic 都从教师初始化，不用单独的初始化阶段。7 卡 A100、batch 14，AdamW，学生学习率 2×10−5。这个设计还有一层工程上的取舍：作者没有再上 rCM 那种 4:1 的 critic/学生更新比，表 S5 显示那种配方每次学生更新要 180–225 秒，而他们的 1:1 配方约为 87 秒，这才使 600 次迭代在 51 A100 小时内跑完。Semantic Commitment 针对的是 DMD 梯度里运动分量信噪比低、布局却先被改写的问题；消融里单独加 SC 总分 84.07，甚至略低于 plain DMD 的 84.62，必须和 CE 一起才能把总分推到 85.57，并让严重卡顿降到 0.3%。也就是说，两个修正不是可互换的加分项，而是分别管“块内运动是否均匀”和“语义是否还守着”。

GRPO 一类政策梯度（PG）主导了 LLM 微调，但最近有工作显示演化策略（ES）也能微调十亿参数模型。这篇论文问的不是“谁总分更高”，而是：两种方法作为同一梯度的不同估计器，在什么任务上更省样本。作者把关键量写成有效维度 Deff 和有效视界 Teff。结论很硬：参数个数本身几乎不构成诅咒，真正让 PG 变贵的是视界——当终端学分落到与奖励相关方向重叠的填充 token 上时，PG 的相关方差按 (k+γβF)/k 膨胀。ES 对填充长度不敏感。因此短视界、低 Teff 的任务上 PG 通常更省；长思维链且只有结果奖励时，ES 开始有竞争力，甚至可能反过来。

Background 与 Core Method

常见直觉是“参数越多 ES 越没希望，序列越长 PG 越差”，但两者常被混在一起。作者用多技能密码锁测试床把填充长度 F、学分方案 β（逐步 vs 终端）和权重重叠 γ 拆开。表 2 显示：终端学分加局部填充时，F=4096 的方差相对值测到 612.9，预测 580.2；若改为逐步学分，该比值保持 1.0。表 4 的中位 rollout 数同样：逐步学分下 PG 几乎不随 F 变，终端学分下则会从几十涨到数千。

Experiment 与 Main Finding

在 Qwen2.5-7B-Instruct 的真实任务上，他们估计 Teff 与 Deff。MATH-500 平均 1104 个生成 token，Teff 约 434；TriviaQA 只有约 16 个 token，Teff 约 5.5。表 7：短文本任务上全参数或 LoRA 的 PG 远强于 ES，例如 SQuAD 上 PG 约 0.82，ES 只有 0.378±0.097；TriviaQA 上 PG 约 0.55，ES 几乎停在基线附近。这与“视界短则 PG 更划算”一致。论文的对比按测得视界排序，而不是按任务名排序。失败边界也很清楚：MATH 上 Deff 估计极不稳定（表 5 区间 63–1011，信号份额只有 0.15），不宜过度解释；ES 在许多语言任务上仍然明显更弱，作者并没有宣称 ES 可以替换 GRPO。

Contribution、Limitation 与 Why It Matters

贡献是 Empirical Finding + 一个可测量的分析框架（Deff vs Teff）。限制：测试床是合成组合锁；真实任务的 ES 实现与超参搜索未必对称；没有把 SAEPO 这类 token 级学分直接代入他们的 β 理论。它之所以重要，是因为它给“要不要上过程奖励/token 学分”提供了方差视角：把 β 从终端改到逐步，等价于阻止填充拉长有效视界。Potential Use：在长链 RLVR 里，先测 Teff，再决定加过程学分、缩短填充，还是认真考虑 ES。把这个结论接到今日的 SAEPO 上很自然：SAEPO 并没有把结果奖励变成逐步真值，但语义分改变了终端优势被广播到哪些 token，相当于部分降低那些与任务无关的填充所占用的有效视界。若测量发现某个数学任务的 Teff 仍接近生成长度，就说明广播还在付钱；若 Teff 明显下降，则 token 级学分至少在方差意义上做对了。作者也提醒，名义参数量 D 不是 ES 的账单，有效维度 Deff 往往小得多，所以“模型太大不能用 ES”这句话需要先测量再下。

Idea Mining · 三项可证伪实验

以下是研究设想，不是已有实验结果。

Idea 1 · 最佳设想：把问题内稀疏特征对比写成延迟后果的动作学分

Inspiration：SAEPO 用冻结 SAE 在同一道题的成功/失败轨迹之间做软对齐；SMB Bench 则证明，智能体的关键错误发生在数天前的下单，而回报要到季度末才出现。

Research Gap：现有 Agent RL（含原文 MaxRL/CISPO）仍主要使用轨迹末端或短程续写的结果奖励，很难指出哪一次撤销覆盖或哪一次短交应该被惩罚。

Hypothesis：在同一起始状态下，用成功续写与失败续写的状态/动作摘要做稀疏特征对比，再塑造逐步优势，密封店的利润和“中途撤销保护”次数会优于纯结果 MaxRL。

Proposed Method：把 SAEPO 的 token 换成“一日工具调用或状态摘要”，正确/错误改成同前缀下的高回报/低回报续写，保留软对齐、平衡系数和 α 塑造。

Minimum Viable Experiment：沿用 SMB Bench 的 Day-60 共享状态，4 次更新、每步 16 条续写。Model：Qwen3.8-27B 或同级工具智能体。Dataset：SMB Bench 商店 5 验证、商店 6 密封。Baseline：原文 MaxRL/CISPO 与连续美元 RLOO。Metric：季度利润、缺货千克、Day-0 覆盖、撤销次数。Expected Contribution：一种面向延迟经营后果的可插拔学分，而不是又一个提示词。Novelty ★★★★☆ / Feasibility ★★★☆☆ / Compute Cost ★★★☆☆。Risk：特征可能对齐到文风而非决策；环境非平稳时成功组会漂移。Collision Risk：与 AnchorCredit、Attention PRM、过程奖励工作部分重叠，需强调延迟环境后果和动作片段对齐。Best Venue：ICML / NeurIPS / ICLR 的 Agent RL 或 LLM 智能体轨道。

Idea 2 · 把 Chunk Evenness 接到大模型规划后的小模型涂色块

Inspiration：HorizonFlow 用 CE 只纠正超过训练集的块内卡顿；Plan Big 用 14B 规划、1.3B 涂色换 3 倍加速。

Research Gap：BigSmall 的动态维度仍可能低于全程 14B（表 1 中 74.2 对 74.7，差异不大但消融里去掉规划块会掉到 65.3）。少步或小模型渲染块仍可能把运动挤进少数帧。

Hypothesis：在 1.3B 渲染块上加训练免费或轻量的 CE 约束（或对已有 Self-Forcing 学生补一轮 CE），3× 加速下的 Dynamic / 卡顿指标会接近全程 14B，且语义差仍覆盖 0。

Minimum Viable Experiment：同一对 Krea-14B / Self-Forcing-1.3B，VBench 946 提示、报告 DiT 时间和动态维度。Baseline：BigSmall 与 plain 1.3B。Metric：FPS、ΔSem、Dynamic、以及 HorizonFlow 的 E>0.1 比例。Compute Cost ★★☆☆☆。Collision Risk：与 Draft Forcing、Mass Forcing 同时出现，差异化应放在“规划分配 + 块均匀度”而不是再做一个少步蒸馏。Best Venue：CVPR / ICCV / NeurIPS 的高效视频生成轨道。

Idea 3 · 先预测评委漏洞，再禁止学分流向这些模式

Inspiration：候选论文 Which Loopholes Get Found?（2611.29651）表明，GRPO 中最先被利用的漏洞，可由训练前的曝光度（策略倾向 × 评委假阳性率）预测；SAEPO 又会把优势写到与“正确轨迹”相似的 token 上。

Hypothesis：若在优势塑造时对已知高曝光漏洞模式施加负学分或屏蔽，评委被 hack 的首个模式会推迟出现，且任务准确率下降有限。

Minimum Viable Experiment：复用该文的 14 个漏洞家族与七个评委设定，在同一 GRPO 运行中比较“只报告曝光度”与“用曝光度约束 SAEPO/标准优势”。Metric：首次被利用的漏洞是否仍是最高曝光者、任务分、漏洞出现步数。这是防御性设想，Compute Cost ★★★☆☆。Collision Risk：与 reward hacking 文献高度重叠，必须把“训练前预测”和“token 级屏蔽”绑在一起才有增量。Best Venue：ACL / ICLR 安全与对齐轨道。

Collision Detection · ⚠️ Collision Warning: YES

Collision 1：Token / 过程学分。SAEPO 与 KTAE、THR、GTPO 直接比较过，也与近日报告中的 Evidence-Based Credit Assignment、Budget Internalization、Breaking the Long Horizon、以及今日的 AnchorCredit、Attention PRM 撞在“不要把结果奖励广播到所有 token”这一方向上。已解决的是：在数学/代码 RLVR 里，用冻结 SAE 的问题内软对齐可以提高平均分，并且反转信号会变差。尚未解决的是：该方法能否迁到工具轨迹和延迟环境后果，以及它与可学习 PRM 谁更稳。差异化建议见 Idea 1，不要再做一道 MATH-500 上的新加权。

Collision 2：少步 / 投机视频生成。同一天至少还有 Mass Forcing、Draft Forcing、On-Policy Codec Distillation、FlowMap Distillation 与 HorizonFlow 并列；Plan Big 又与投机解码、SDVG、Speculative Forcing 比较。HorizonFlow 已占据“600 次迭代 + 卡顿可测”的位置，Plan Big 已占据“14B 规划 / 1.3B 涂色、3.02× DiT 加速”的位置。剩余缺口是把卡顿正则接到分配规则上（Idea 2），而不是再报一个接近的 VBench 总分。

Collision 3：长视频记忆与交接。VideoJSON 与今日 VTree、近日 BATON / VMSA / ESSENCE 都在讨论记什么、何时升级记忆。VideoJSON 的差异是最小 JSON + 程序查询在多个基准上赢了专用记忆，但 EgoLifeQA 上并未全面胜出。若继续做记忆图，需要先对这个弱基线认输或赢回来。
