1. Sol Video Inference Engine Video AccelerationAgent

基本信息。Yitong Li, Junsong Chen, Haopeng Li 等；NVIDIA Research / Efficient AI Team & Singapore Lab；arXiv:2606.23743，2026-06-24（v2）。状态：预印本。Paper · Project · Code。

一句话定位与人话版

Sol 把视频扩散推理加速从“挑一个算法”改成“对特定模型 × 硬件 × 服务配置，搜索一套可组合的加速栈”。它不是训练一个更快的视频模型，而是让五类已有优化——跨步缓存、稀疏注意力、token pruning、低比特量化、kernel fusion——各由专门 skill agent 调参，再由 integrator 组合，并让人类以质量反馈做最终把关。核心价值在于承认这些优化并不独立：缓存可能改变数值误差的累积方式，量化会改变 attention 稀疏化的安全阈值，pruning 又会影响 kernel 的实际形状。于是“理论上各有收益”不等于“叠起来仍快且不坏”。官方页显示，在其选定设置中，Cosmos3-Super、LTX-2.3、SANA-Video 相对 SGLang 分别达到 2.27×、2.38×、2.77×；这是端到端倍率，而不是只报 FLOPs，因此对部署更有意义。

Background & Research Gap

视频生成的每一步去噪都要处理时空 token；模型放大、帧数增加和分辨率提升会把 attention、激活访存与 kernel launch 一起推高。常见论文往往固定一种假设：相邻 diffusion step 的特征相近，所以 cache；少数 attention score 重要，所以稀疏；部分 token 不重要，所以裁剪；数值冗余可量化。每条命题在一个模型、一个分辨率、一个 GPU 上都可能成立，但部署时面对的是组合选择：LTX 的时空结构与 Cosmos 不同，B200 的吞吐/显存带宽比也不同于消费卡。旧范式把“算法适用性”和“组合次序”交给工程师手动试；Sol 的 gap 是没有一个面向具体实例、同时衡量速度和感知质量的编排层。

可核验事实：作者公开说明系统是 training-free，使用 cache、sparse attention、token pruning、quantization、kernel fusion 五类技术；对三个不同规模/架构视频模型报告超过 2× 的端到端加速并保持 near-lossless VBench 质量。具体 GPU、prompt、分辨率、绝对 latency 与每项技术贡献：本期 Not Verified。

Core insight：配置空间本身是优化对象

最重要的观察不是“某种近似有效”，而是加速策略的最优解依赖实例。把部署实例记为 x = (模型、硬件、分辨率、帧数、batch、采样步数)，把可组合的实现方案记为 c。一个诚实的系统目标不是只最大化 token 吞吐，而是从候选集合中选出速度高、质量仍合格、运行稳定的 c。下面公式是对系统目标的解释性抽象，不是作者声称的原始目标函数：

c*=argmaxcSpeed(x,c) subject to Q(x,c)≥τ

Q 是质量评分，τ 是可接受下限。它解释了为什么必须有人类 validator：VBench 或自动指标可以约束一部分质量，但不必然覆盖主体一致性、物理违和或提示词服从。最危险 failure mode 是 agent 把指标当奖励：它找到了更快的组合，却在未被指标覆盖的 prompt 上出现闪烁或身份漂移。这是典型 reward hacking，只不过 reward 是“速度 + 自动质量代理”。

Method Deep Dive：从输入到输出

Input → instance profiling → 五个并行 skill agents → candidate stack → integrator → quality validation → deployment recipe。

  1. 实例定义。固定模型、权重、硬件和服务配置；不固定这些条件就没有可比较的 latency。
  2. 技能层搜索。cache agent 寻找可复用跨步特征；稀疏 attention agent 决定少算哪些注意力连接；pruning agent 决定少传哪些 token；quantization agent 控制表示精度；fusion agent 减少中间张量和 launch 开销。这里输出不是“最好算法”的口号，而应是带配置、误差和时间的候选。
  3. 组合层。integrator 不应把五个局部最优直接相乘，因为一项近似可能破坏另一项的输入分布。正确动作是测候选 stack 的端到端时间与质量，并淘汰不兼容组合。
  4. 验证与交付。人类 validator 对生成结果给反馈；最终产物是针对该 x 的 recipe，而非宣称一套默认开关通吃所有模型。

Toy example

假设你要部署一个 49 帧视频模型。cache agent 发现后半段采样步的中间特征变化小，提出每两步复用一次；pruning agent 发现背景 token 对文本条件响应弱，提出保留主体周围 token；quantization agent 把某些矩阵换成低精度。单独测试时，三者均省时。组合后却可能出现问题：被量化的 attention score 已很接近阈值，pruning 又删除了少量边缘 token，cache 将偏差延续数步，导致人物边缘闪烁。integrator 因此要把“2×加速的三个独立证据”改成“组合后的实测质量约束”。若 VBench 合格而人工仍看出闪烁，应收紧阈值或回退一种近似。

限制、攻击视角与迁移

作者可见限制：依赖实例化调优和人工质量反馈；recipe 未必可迁移。附加限制：如果搜索只在少量 prompt/seed 上进行，得到的栈可能对评测集过拟合；把调优时间忽略后，短期任务的总成本可能反而更高。可做的 efficiency stress test 是构造长视频、快速镜头、细粒度文本绑定和不同 batch 的矩阵，检查加速倍率和质量是否同时坍塌。

迁移 1（推断加速）。视频的“实例条件化组合” → LLM serving 的 KV eviction、speculative decoding、quantization → 问题：不同上下文长度/并发下如何选安全 stack？最小实验：Llama 级模型，LongBench + ShareGPT trace，baseline 为 vLLM 默认与各单技术，指标 TTFT、TPOT、throughput、pass@1、峰值 KV memory；风险是 controller 本身开销吞噬收益，Collision 是已有 autotuner/serving scheduler。

迁移 2（Agent）。skill agent + integrator + validator → 自动给研究 agent 的 tool-chain 配置做资源-质量编排 → 最小实验：BrowserGym 或 coding benchmark，候选为小/大模型路由、缓存、上下文压缩、并行工具调用；指标成功率、wall-clock、token、恢复率。风险：用 LLM judge 做质量 validator 会偏向自身文风；应保留可执行任务成功作为硬约束。

记住它的八句话。Sol 的单位不是一项优化，而是一条部署 recipe。它把模型、硬件和服务配置共同当作条件。五类加速技术在局部有效不代表可直接叠加。并行 skill agent 降低了搜索的人力成本。integrator 的责任是检测组合冲突。validator 使质量约束不只依赖速度指标。官方可核验结果是三模型端到端超过 2×。它最值得借鉴的是“以具体实例为单位的可复现实验协议”。

2. Towards Efficient Agents: A Co-Design of Inference Architecture and System AgentInference

基本信息。Weizhe Lin, Hui-Ling Zhen, Shuai Yang 等；arXiv:2512.18337，2025-12-20。状态：预印本，BACKFILL。Paper。代码状态：Not Verified。

一句话定位与人话版

AgentInfer 的问题意识是：Agent 的慢，不是单次 LLM decode 慢，而是多轮 reasoning、上下文持续膨胀、工具等待和异质请求相互放大。它把加速切为四个互补模块：AgentCollab 用层级双模型分工，AgentSched 做 cache-aware hybrid scheduling，AgentSAM 用 suffix automaton 从多会话语义记忆中做 speculative decoding，AgentCompress 在不打断推理的条件下异步压缩/重组记忆。作者称在 BrowseComp-zh 与 DeepDiver 上，无效 token 消耗减少超过 50%，总体加速 1.8–2.5×且准确率保持。值得关注的地方是评价对象从 tokens/s 改成 agent task completion：真正有价值的是在任务成功不下降时少走回合、少带上下文、少等工具。

从“模型推理”转向“闭环工作流”

传统 LLM serving 关注 prefill、decode、batch；但 Agent 每一次工具调用都会生成新 observation，旧 memory 又会进入下一次 prefill。即使 token decoder 加速两倍，若 agent 因为计划差多调用三次工具，总 wall-clock 仍可能变慢。AgentInfer 的核心缺口就是此处：单点 kernel 优化不控制系统层 token 流和角色分工。其四模块对应四种浪费：大模型处理所有子任务、相似会话不复用、排程不感知 cache、历史上下文不压缩。

下面是理解其端到端目标的抽象，而非论文逐字公式。令任务完成时间为 L，令成功率为 A、成本为 C；系统不应只优化单 token latency，而应在 A 不降的约束下优化整个 trajectory：

minimizeπE[L(τ,π)+λC(τ,π)] subject to A(π)≥Abase

这里 τ 是一条 agent trajectory，π 是路由、调度、缓存复用和压缩策略。λ 决定你把 token/算力看得多重。这个视角也揭示 failure mode：若压缩提高速度却抹掉关键证据，A 会下降；若小模型被路由到难子任务，错误又会写回 memory，造成后续多轮返工。故“减少无效 token”只能算中间指标，不能替代任务成功率和恢复率。

Method Deep Dive

Input/任务状态 → AgentCollab 路由 → AgentSched 排程 → AgentSAM 复用/推测 → AgentCompress 异步整理 → tool/environment feedback → 下一轮状态。

  1. AgentCollab。层级双模型把不同难度/角色的推理交给不同能力与成本的模型。合理之处是多数步骤可能只是检索、格式化或局部判断；危险在于路由器的错误会把关键步骤下放。
  2. AgentSched。调度器不应只看队列长度，还应偏好 cache 可复用或相近上下文的请求，以降低 prefill 的重复劳动。它解决的是服务层等待，不是语义质量。
  3. AgentSAM。suffix automaton 对跨会话语义记忆的复用为 speculative decoding 提供候选延续。其机制直觉是相似轨迹常有相似 action/文字片段；但验证模型拒绝候选时，收益会显著下降。
  4. AgentCompress。异步蒸馏和重组 memory，避免每轮把原始工具日志全部塞回上下文。关键不是压缩率而是 preservation：哪些实体、约束、证据来源和未完成子目标不能丢。

Toy trajectory 与 baseline

一个网页研究 agent 要比较三篇论文。第一次检索后，普通系统把三段长网页原文都留在 prompt；第二轮又把它们连同工具日志重新 prefill。AgentInfer 式系统可让小模型提取结构化证据，大模型只处理冲突与结论；调度器把相似任务排到有 prefix cache 的 worker；memory compressor 保存“结论—证据 URL—置信度—待验证问题”，而非全文。若用户随后问“第二篇的硬件条件”，系统必须能回到证据，而不能只依赖压缩摘要。这个反例说明压缩必须带 provenance。

实验协议、指标与复现

若复现，最先要定义“无效 token”：是被截断、被重复 prefill、被低价值 reasoning 消耗，还是最终不改变 action 的 token？定义不同会直接改变超过 50% 这个数字的含义。任务指标至少需要 success rate、平均 tool calls、总输入/输出 token、端到端 P50/P95、TTFT、TPOT、GPU memory、cost/task 和 recovery success。只报 tokens/s 会把工具等待与重复回合藏起来；只报成功率则看不到用昂贵大模型换来的改善。

最小版本：选 BrowseComp-zh 类检索任务或你自己的浏览器/代码 agent trace；固定模型、工具、超时与 prompt；先实现 memory schema（事实、来源、置信度、待办），再比较“完整日志 / 截断 / 摘要 / provenance-aware compression”。之后加 cache-aware scheduling，最后才加 dual-model 和 speculative module。最敏感超参是路由阈值、压缩触发长度、memory token budget、candidate acceptance rate、并发度和 cache TTL。最能验证核心 claim 的实验是：在任务成功率等同的前提下报告任务级 P95 时间与 token，而非只测离线 decode。

风险、迁移与研究价值

Long-horizon failure propagation：小模型漏掉一个约束 → 压缩后的 memory 把错误当事实 → 后续 planner 基于错误调用工具 → 多轮成本增加，形成“加速模块反而降低成功率”的闭环。对此需要 provenance、可回溯原 observation 与不确定性标记，而非只做短摘要。Attack lens：恶意页面可制造重复的高频后缀或污染 memory，使 SAM 错误复用、压缩器保留错误摘要；可用带注入提示的 web trajectory 衡量 attack success、错误持久轮数和恢复成本。

迁移 1（Video Agent）。AgentInfer 的任务级优化 → 视频理解 agent 的 frame budget + memory compression → 用长视频 QA，模型 Qwen-VL 类，baseline 为固定帧采样/滑窗，指标 QA accuracy、frames、visual tokens、端到端时间和证据可定位率。预期贡献是把“帧少”改为“任务成功且可追溯”；风险是关键短事件被压缩遗漏；Collision 是已有 token/frame pruning。

迁移 2（Unlearning evaluation）。provenance-aware agent memory → 自动构造 profile-level 多跳 probe → 用你的 MLLMU Profile 证据包，让 agent 生成与追溯攻击轨迹；baseline 为静态 QA，指标可触达事实覆盖、黑盒泄露率、证据链长度和生成成本。风险是 agent 自身先验泄漏混淆模型泄漏；要用未知对照 profile 和 source-attribution 限制。

记住它的八句话。Agent 的瓶颈是整条任务轨迹，不是单次 decode。双模型路由消减不必要的大模型调用。cache-aware scheduling 瞄准重复 prefill。语义 memory 可以成为 speculative decoding 的候选来源。异步压缩要保存证据和未完成约束。>50% 无效 token 减少是中间指标。1.8–2.5×端到端加速需要以同等成功率解释。它最值得迁移的是 task-level、provenance-aware 的评价口径。

3. Cross-Paper Synthesis

两篇的共同趋势是：加速的对象从“一个算子/一个模型”上升到“带条件的工作流”。Sol 的条件是模型 × 硬件 × 视频配置；AgentInfer 的条件是任务阶段 × memory × cache × 工具状态。二者的可组合方向很直接：用 Sol 的 instance-specific recipe 作为视频生成/理解工具的执行层，用 AgentInfer 的任务级 scheduler 决定何时调用、调用什么规模的模型、怎样保存结果。真正的研究 gap 是统一的质量约束：视频端要防止 VBench 之外的视觉退化，Agent 端要防止压缩/路由导致的长期事实漂移。最适合作系统 baseline 的是 Sol；最适合作 agent benchmark/metric 出发点的是 AgentInfer；最强 Collision 是“自动调优是否只是搜索已有技巧”，答案取决于是否给出跨配置、端到端且含调优成本的严格证据。

阅读与复现优先级

  1. Sol：先找其配置和端到端 benchmark 脚本，复现实测 1× 对照、warm-up 协议与单技术开关。
  2. AgentInfer：先验证 task-level P95 与成功率，再拆四模块；不要直接把 token reduction 当成功。
  3. 你的可落地小题：做“provenance-preserving adaptive memory budget for multimodal agents”：以信息可定位率和任务成功为硬约束，动态选择帧/token/memory 压缩。它连接 Video、Agent、Inference，并可自然延伸到多模态 unlearning 的黑盒 probe。
