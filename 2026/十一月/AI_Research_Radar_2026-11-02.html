RL Highlights

核心趋势：RL 正在从“选一个更好的 PPO/GRPO 变体”转向三类可控对象：训练数据分布（Unified Training）、reward distribution 与 token credit（TACE）、reward generator/rubric 的自适应更新（RACE）。这三者分别回答“学什么、把成功归因给谁、谁来判定成功”。真正有价值的交叉点是把这三个控制变量放进长轨迹 Agent 的同一闭环。

审计重点：Unified Training 的 verifier 是可验证 outcome；TACE 的 rank normalization 在稀疏奖励上出现明确失败；RACE 的 learned rubric 可能与 policy 共同漂移。不要把 task success 的提升直接解释为更好的因果 credit；需要独立测 reward hacking、探索覆盖率和 sample efficiency。

Agent / Multi-Agent Highlights

核心趋势：从静态工作流走向可验证的过程状态。SPLICE 把消息传播视作可干预图结构；Prefix Executability 把执行合法性拆到每个前缀；CORAL 把工作记忆重启视作策略动作；EpiAgent 进一步把他人隐含信念显式建模。这些机制可组合成 Observation → Message/Memory → Tool Action → Outcome → Attribution → Update。

审计重点：在 10、100、1000 步的长期交互中，错误可能通过共享记忆与下游工具链持续放大。SPLICE 的回滚不撤销外部副作用，CORAL 的 checkpoint 可能保存错误事实，EpiAgent 的 belief reward 不一定对应团队成功；这些都应该在下一轮研究中作为独立 failure cases。

Video Acceleration Highlights

核心趋势：视频生成加速从单纯删 token 转向“估计误差可控的 attention 计算预算”：AB-Attention 校正稀疏抽样偏差，Triage 对每个 tile 分配 skip/FP4/refine 三档；流式理解的 Video-MemComp 则把 KV budget 按层级敏感性和在线 entropy 分配。AB 在 H20 上报告 1.84–2.23× 端到端速度，Triage 在 Blackwell 上最高 2.32×；Video-MemComp 的 90% KV 节省并不代表整机显存或吞吐同步改善。

未来方向：Video LLM 的 query-aware event selection、Video Agent 的跨轮 memory credit、生成模型的 kernel-aware 误差预算。每次实验都应同时记录 Frames / Tokens / FLOPs / wall-clock / peak memory / FPS / QA 或生成质量；没有报告的项必须保留为 Not Reported。

人话版：这篇论文到底干了什么？

传统大模型训练把预训练、中期训练、SFT 和强化学习当作彼此分离的阶段。本文提出：对于特定 RL 目标，成功轨迹的分布本身就能成为最大似然学习的目标，因此不同训练阶段可以由同一个 token 加权似然损失处理。真正改变的是数据来源、混合比例和更新时机，而不是训练算法。作者不仅给出形式化推导，还实现静态语料与在线 RL 生成混合、异步采样的统一训练器。实验揭示一个很重要的现象：早期某阶段的即时指标更好，不一定让后续 RL 更好；持续混入少量旧数据可能改善能力保持与后续可塑性，但也会损害部分当前任务准确率。

Background & Research Gap

现在的标准训练流水线在阶段边界切换目标函数：预训练拟合语料，SFT 拟合示范，RL 则优化奖励。这样做便于工程组织，却使一个基础问题难以回答：若给定相同的总计算预算，究竟应该何时使用哪类数据？例如，一个模型先把数学推理轨迹学到很熟，再进行数学 RL，可能比从预训练后期开始就持续接触推理数据的模型更差；仅比较阶段末的 loss 不能解释这种差异。本文把“训练阶段”重写为随时间变化的数据分布问题，允许同时研究保留旧知识、学习新技能和数据复用。

Core Insight 与理论推导

作者从 MaxRL 出发。令模型为 πθ(y|x)，验证器给二值奖励 r∈{0,1}，成功概率 pθ(x)=E[r]，成功条件分布 πθ⁺(y|x)=πθ(y|x,r=1)。关键恒等式是 ∇log pθ(x)=E_{y~πθ⁺}[∇log πθ(y|x)]。这意味着 MaxRL 可以理解为：先从当前模型生成正确回答，再对这些成功回答做最大似然拟合。推广到多数据源后，定义 qₜ=Σₛ λₛ,ₜ(ρₛ,ₜ∘μₛ,ₜ)，统一损失 L(θ;qₜ)=−E_{(x,y)~qₜ}log πθ(y|x)。其中 λ 是混合权重，ρ 是 prompt 分布，μ 是目标回答分布。阶段式训练只是某时刻把全部权重分给单一数据源的特例。

必须注意理论边界：当生成器不是当前策略时，拟合外部成功分布仍是似然训练，但不再等价于当前策略的 MaxRL 梯度；这不是对所有 PPO/GRPO 目标的无条件等价。论文还区分 MaxRL 与 REINFORCE：后者的有效 prompt 分布按成功概率加权，容易更重视已经能做对的题；MaxRL 保持原始 prompt 分布。对于连续奖励，作者讨论 TailRL 等扩展，而不是把所有奖励直接二值化。

Method Deep Dive：Input → Output

输入是预训练语料、中期推理轨迹、示范数据、在线 prompt 和 verifier。第一步把各数据源统一成 (token 序列 z, 非负 token 权重 w)；普通文本每个 token 权重为 1，SFT 的 prompt 为 0、回答为 1，RL 的失败回答权重为 0。第二步对每个 RL prompt 采样 N 个候选，估计成功率 p̂，成功回答赋权 1/p̂，令每个 prompt 的成功轨迹贡献相对均衡；若全失败，则本轮没有正向更新。第三步从共享缓冲区按设定的 token 比例抽取静态样本与在线生成样本，用统一加权 NLL 更新模型。第四步生成器与训练器异步工作，定期同步权重。输出是不断更新的策略及其下一轮训练分布。

举例：一个工具 Agent 有历史成功轨迹 100 条、当前环境生成轨迹 20 条。如果把两者完全分成先 SFT 再 RL，后期可能忘记工具格式；统一训练可持续保留少量历史轨迹，并将成功的新动作混入同一梯度。这个例子是迁移设想，不是论文已验证的 Agent 结果。

Baseline / Experiment Setup / Research Questions

对照组是阶段式 pretrain→midtrain→MaxRL、统一训练的不同混合比例、无 midtraining 混合、额外加入 pretraining 文本以及不同损失归一化。受控实验从头训练约 124M 参数模型：20B 预训练 tokens，约 510M 推理轨迹语料，Base RL 6,000 updates，Extended RL 12,000 updates；以 pass@1、pass@16、训练总 FLOPs、保留的通用能力为指标。作者构造 8–9 人与 10–11 人的逻辑谜题，并用未在训练出现的 12 人题测尺寸泛化。真实数据实验用 0.76B 模型、Math12K、240M token 混合语料以及 MATH-500、GSM8K、HumanEval+、MBPP+、SciQ 等。

RQ1：混合训练是否优于阶段式训练的最终推理能力？RQ2：在相同累计 compute 下谁更优？RQ3：是否能减轻预训练能力遗忘？RQ4：数据混合比例与时间表如何影响 coding 与 math 的权衡？RQ5：经过数学 RL 后再进行代码 RL，谁的起点更好？这些问题的顺序很重要，因为单一 benchmark 的提升不足以证明统一训练的价值。

Results / Figure Reading

结果一：Figure 4 显示在受控任务中，更多预训练后期的 midtraining 混合通常改善最终 RL 推理表现；但 RL 期的混合比例不是越大越好，Base 的最佳点出现在中间比例。结果二：Figure 5 在累计计算预算上比较 pass@1 与 pass@16：统一训练在高预算和最低预算的某些设置中更优，阶段式训练在部分中间预算、尤其 coverage 上仍有优势，不能简化成“全程统一必胜”。结果三：Figure 6 显示五种预训练混合初始化保持接近纯预训练的通用能力，而最能保留能力的阶段式基线仍出现明显退化。结果四：真实数据 Figure 7 将 midtraining token 比例从 0 调至 5%，Math accuracy 变化较小、coverage 往往增加、held-out midtraining loss 下降，但 Coding accuracy 会随比例增加而下降。结果五：Figure 9 的 4,000 次 coding RL 表明，先前统一训练的模型最终在 HumanEval+、MBPP+ 的准确率均高于阶段式起点，5% 混合配置在所列四项 coding 指标最好。

可核实规模数字：124M / 0.76B 两种模型规模；受控语料 20B + 510M tokens；Base/Extended 为 6,000/12,000 RL updates；真实数据混合为 0–5%；后续 coding RL 4,000 updates。论文主要曲线在网页文本中没有给出所有精确点值，故不虚构 pass@1 的具体提升百分比。实验表格应与曲线一起读，不能把“计算更优”误当成同一 checkpoint 的绝对准确率更高。

Ablation / Claim vs Evidence

去掉 RL 期旧数据混合，有些设置的泛化与保持能力下降；增加 pretraining 文本能改善 held-out loss，却往往牺牲 reasoning accuracy；把统一 token loss 换成分别归一化的 RL+midtraining loss，在 Extended 中某些配置更好，但需要额外调系数。作者声称训练阶段可被统一理解，推导支持的是特定似然形式的 RL；实验真正显示混合策略有竞争力，并非证明所有模型规模、所有奖励机制、所有数据混合都能获益。尤其异步生成的数据陈旧度与 reward distribution shift 仍可能影响大规模训练。

Contribution / Limitation / Research Value

New Objective/Training Framework：统一似然视角与共享训练器；New Empirical Finding：阶段中途数据暴露可改变后续 RL 可塑性；System Value：静态与在线样本使用同一数据格式、训练调度与异步缓冲。最强 baseline 应按具体 RQ 分开判断：阶段式 MaxRL 在部分 coverage/中预算区间仍强，不能仅拿统一训练最优点与单一弱配置比较。局限是模型最大仅 0.76B、主要验证可检验奖励与文本任务、没有真实多工具 Agent 轨迹、不同混合策略可能隐含不同数据复用率。

Migration：RL × Agent Experience

Original Problem：预训练与 RL 目标分离。Transferable Mechanism：成功轨迹的加权似然与持续数据混合。New Research Question：Agent 的失败恢复、工具技能与新环境探索是否能共用一个自适应 replay mixer？Method Modification：按轨迹来源、工具种类、执行前缀可靠性和成功率调整 λₛ,ₜ，加入旧技能保持约束。Minimum Experiment：小型工具任务训练 3 组——阶段式 SFT→RL、固定混合、状态驱动混合。Model：Qwen3-4B 或更小开源模型；Dataset：可复现的工具环境与历史轨迹；Baseline：常规 GRPO、固定比例 replay；Metric：任务成功率、可执行前缀、旧技能保持、GPU-hours、rollout 数；Expected Contribution：可解释的跨阶段 Agent 数据调度；Risk：成功轨迹筛选带来模式坍缩与环境过拟合。

五句话总结

① 本文最重要的变化是把训练生命周期转成数据分布设计。② MaxRL 的成功条件分布提供与 MLE 相接的数学桥梁。③ 数据混合对最终 RL 的作用不能从某个中间阶段的 loss 推断。④ 实验同时发现保持能力收益与当前 coding accuracy 代价。⑤ 值得迁移到 Agent 的不是“所有数据都混在一起”，而是有预算、有验证器、有反馈的混合调度。

人话版：这篇论文到底干了什么？

多 Agent 失败不一定是每个 Agent 都没找到答案，也可能是证据找到了，却没有通过通信图传到真正需要它的 Agent。SPLICE 先运行原始工作流，诊断哪条缺失边阻断信息，再插入一条定向连接并重跑受影响节点。关键创新是它不盲目接受新结果，而是追踪新证据进入接收者后如何改变中间输出、是否传播到最终答案，再由训练过的 selector 决定采用还是回滚。论文在 Web 工具调用和推理规划任务上同时评估分数与额外成本。它把 Agent 的信息流由“静态拓扑设计”推进到“可诊断、可干预、可验证”的执行时过程。

Background & Gap

固定 DAG 工作流里，每个 Agent 只看前驱节点。例如旅行规划系统中，航班 Agent 找到跨国转机，签证 Agent 却只收到直飞航线摘要，最终答案漏掉过境签要求。这里不是检索失败，而是证据路由失败。粗暴增加所有边也不行：错误的上游结论可能覆盖正确答案，还增加 token 与调用成本。已有图重连与 best-of-N 方法常看最终答案质量，却没有把“新边究竟造成了什么过程变化”作为采用证据。

Core Insight

把一次候选通信边当作可控干预：保留原执行轨迹 τ，增加边 e 与消息 m 后得到试验轨迹 τ(e,m)，比较接收者的变化、变化来源以及下游传播范围。这样可以区分三种情况：消息根本没被用；消息被用但没有影响终局；消息被用且导致可验证的正/负变化。作者以“先形成连接、再根据局部活动选择保留”解释方法，但核心科学价值仍是过程证据与反事实试验，不是生物类比。

Method Deep Dive：Input → Diagnose → Intervene → Verify → Output

Input：query、静态 Agent DAG、各节点输出与原始最终答案。步骤一 Query-level：预测原答案质量，低质量或不确定问题优先试验，控制调用预算。步骤二 Edge-level：找出可能缺失证据的接收者，并选出掌握该证据的源节点。步骤三 Message-level：提取接收者子任务中提及、但其现有父节点未覆盖的实体/数值集合 M；让源节点按 M 重组织证据，而非复制整段回答。步骤四 Trial：只插入候选有向边，重新执行接收者及下游依赖节点，保留 base 与 trial 两份输出。步骤五 Process-conditioned selector：从内容新增/删除、信息来源、向终点传播距离构造特征 φ；Qwen2.5-7B-Instruct selector 经 SFT 和 DPO 学习三分类：改进、无影响、变坏。步骤六：依据收益概率、原答案质量和风险选择采用或回滚。注意这里的回滚是输出选择，不意味着撤销真实外部 API 副作用。

Objective 与 Toy Example

作者的选择器训练使用 DPO：以 reference policy 为锚，使正确的“采用/拒绝”判断相对于错误判断更有概率。部署时的采用边际值 Δ=p(改善)·(1−r̂)−p(损害)·r̂：原答案质量越高，越需要更强证据才值得覆盖。例子：Agent A 已查到“API 需要参数 currency”，Agent B 生成调用却缺少它。新增 A→B 后 B 的 payload 补齐，且最终执行成功，过程特征支持采用；若 B 只是把 A 的错误解释复制进最终答案，则应拒绝。此例对应论文中信息缺口的结构，不代表作者逐字给出的案例。

Authors: Bin Xu, Mo Zhang, Zhengfeiyang Zhang, Xinfeng Yang, Yixing Ma, Wei Wang, HeXin Wang, Pengfei Zhou, Wangbo Zhao · 2026-10-29 arXiv v1 · Venue: 未核实正式发表 / preprint · Affiliation: CUHK Shenzhen; Shandong University; University of Tokyo; Fudan University; UC Berkeley; HKUST; National University of Singapore · Code: Official GitHub linked · Project: Not Verified

人话版：这篇论文到底干了什么？

视频扩散 Transformer 的 3D 全注意力开销随视频 token 数量平方增长。传统稀疏注意力往往把低分块直接扔掉，导致 softmax 的分母和输出都被系统性改变；即使选块更准，极端稀疏时质量仍会下降。AB-Attention 采用三层设计：局部 query 聚类更准确估计重要性；按重要性概率抽样并用逆纳入概率校正；把比执行 tile 更细的小 K/V 块重新打包成高效 GPU tile。它无需重新训练，在 Wan2.1 和 HunyuanVideo 上跳过约 89–92% 注意力计算，端到端加速 1.84–2.23 倍，同时比最强稀疏 baseline 的 PSNR 更高。这是一篇同时有算法机制和真实 wall-clock 证据的系统型工作。

Background & Research Gap

高分辨率长视频会产生数万视觉 token，视频 DiT 每个去噪步骤都做空间-时间全注意力，计算与显存访问代价很大。现有 RadialAttention 用静态 mask，DFSAttn 用动态评分，SVG2 通过聚类重排 token。它们的共同问题是把没有选中的块视作零贡献，并且以 GPU 执行 tile 为最小保留单位。想象一个 128-key tile 只有 4 个 token 对当前 query 至关重要：整 tile 保留浪费算力，整 tile 丢弃则破坏输出。本文要同时解决估计不准、直接截断和粒度太粗三个问题。

Core Insight

注意力近似的目标不是尽量精确地找 top-k 块，而是以固定预算尽可能估计完整 dense attention 的分子与归一化分母。作者用按重要性概率抽样、再按 inclusion probability 重加权的思想，使被抽中的块代表未抽中块的期望贡献。与此同时，query 的语义多样性可以通过块内聚类描述，而不必全序列聚类/重排。最终把 4-token 小块装进 128-token tensor-core tile，实现“细粒度选择、粗粒度高效执行”的分离。

Method Deep Dive

Input：当前去噪步的 Q、K、V 与预算 s。Step 1 IBCS：对每个 128-query 块内部做 8 类轻量聚类，取 query 代表及权重；对 4-key 块做均值池化，用代表 query 与 pooled key 估计注意力重要性。只在 query 块内部聚类，不改变全局 token 顺序。Step 2 SIP：把评分转为 key 块被纳入的概率 π，系统抽样选出 s 个不同小块；在 attention logits 上加 −log π，相当于按纳入概率校正被抽中块的贡献。Step 3 Tiled Execution：gather 选中的细粒度 K/V 块，打包为 GPU 适配的大 tile，用在线 softmax 完成注意力。Step 4 Reuse：采样计划每 4 个去噪步更新一次，但每一步都用当前激活重新计算注意力。Output：近似 dense 的 attention 输出，不需要更新原视频模型权重。

关键公式直觉：若某块被抽中的概率为 π，其对分子/分母的期望贡献需乘以 1/π；在 softmax 的 logit 形式中实现为 −log π。它不是简单把 top-k 的概率重新归一化，而是尝试修正未观察块造成的系统偏差。理论上分子与分母的单独估计可无偏，但两者之比一般不严格无偏，这点需要区别于论文对估计器的表述。采样预算、聚类数、计划更新间隔决定质量与开销。

Toy Example / Baselines

假设某 query 面对 1,000 个小块，其中 20 个关键块承担大部分注意力。top-k 固定选 20 块，会完全抹去其他 980 块的尾部质量；AB-Attention 给所有块非零纳入机会，让高分块更常出现，抽中低分块时用权重代表其总体贡献。与 Radial、DFSAttn、SVG2 相比，本文的优势不只是稀疏率更高，而是在更稀疏时仍保留 softmax 统计量的校正。strongest baseline 在 Wan2.1 1.3B 的 PSNR 是 SVG2，在 HunyuanVideo 上是 DFSAttn。

人话版：这篇论文到底干了什么？

工具 Agent 的最终任务成功率无法反映中间执行路径是否真正可运行。一个规划器可能生成了错误工具调用，却通过偶然恢复拿到正确答案；也可能最终失败，但前十步全部合法。本文提出 Prefix Executability，把整条轨迹的每个前缀放进工具 schema、环境前置条件与数据依赖中检查，用 PEC、FED、TER、AUC-PEC、Recovery Rate 五类指标描述可靠性。它的价值不是又造一个成功率，而是给长轨迹 RL、工具规划和 Agent 可靠性提供可以定位第一处错误的过程监督。

Background / Core Insight

传统工具 benchmark 把 trajectory 压缩成最终成功/失败，无法分辨“早早犯错、后面救回来”和“每一步都合法但最终没达到目标”。作者把可执行性看作前缀生存过程：对每个 k，检查从第 1 到第 k 个工具调用能否在真实状态中执行。关键是环境状态与数据依赖，而不只是函数名和参数格式。

Method / Agent Architecture

单一 episodic retrieval 擅长还原某次对话的原话，却可能难以回答跨时间的关系变化；单一关系图擅长结构查询，但可能丢失事件时间、语气与来源。方法从对话历史抽取两类记忆，利用 consolidation 合并重复信息，再由检索器选择相关记忆回答新问题。真正要问的是“什么时候关系图覆盖了事件细节，什么时候事件证据能纠正陈旧关系”。

Experiment / Contribution / Limitation

两个 benchmark：LoCoMo 与 LongMemEval-S；论文摘要明确报告准确率 90.2% 和 85.5%，但没有给出各类 baseline 的具体值，因此不猜测相对提升。贡献属于 Memory Architecture 与 empirical complementarity。局限是 consolidation 可能把暂时关系误写成长期事实，或者在合并时删除 provenance；长期更新 100/1000 轮后的稳定性需单独测试。

Connection / Potential Use

与 CORAL 的 checkpoint 不同，这篇研究跨对话的长期知识层；与 SPLICE 相连的研究机会是把每条关系记忆标记来源 Agent 和原始事件，再通过删除/替换单条记忆做反事实 utility attribution。最小实验：LoCoMo 上比较 episodic-only、graph-only、hybrid、hybrid+provenance，指标为 accuracy、stale memory rate、检索 tokens 和写入成本。

Tier BVideoVideoMemBench: How Well Do MLLMs Remember in Video Conversations?
Authors: Zhengdong Hu, Chao Wang, Kaituo Feng, Huanjin Yao, Mingfei Lu, Hehe Fan, Yi Yang · 2026-10-29 arXiv v1 · Venue: 未核实正式发表 / preprint
Paper · Full text HTML

人话版：这篇论文到底干了什么？

传统 VideoQA benchmark 往往让每道题独立地从视频回答，而真实用户会围绕同一视频连续提问：第二个问题可能引用第一次看到的事件，也可能引用模型自己前面给出的答案。VideoMemBench 专门测这种 in-context video memory，把跨轮依赖拆成 Episodic Dependency 和 Answer Dependency，并用必要性、非泄漏性约束构造问题。它不是直接加速算法，但为评估 Video cache/streaming memory 的“删掉历史是否影响后续回答”提供了更贴近 Agent 使用场景的任务。

Background / Method / Findings

如果每道题都能单独从视频答对，模型可能根本没利用跨轮记忆。本文让 planner、generator、judger 三类角色构造依赖链，再经人工审查，确保后续题不能仅凭当前问题作答。样本包含 326 个视频、2,476 个对话轮次，其中 1,387 轮依赖之前轮次；有多父节点依赖和远距离回指。评测超过 20 个开闭源 MLLM，论文报告最好的 Claude Opus 5 总分也仅 45.7%。

Contribution / Limitation

New Benchmark 的重点是 typed dependency 与必要性验证，而非更长的视频本身。局限是自动生成与人工复核可能仍带语言模式偏差；benchmark 规模 326 视频，能否覆盖连续数小时的实时场景、反复修正先前错误的对话，尚需进一步验证。若模型第一次答错，Answer Dependency 会产生错误传播；这既是挑战，也要求评分区分记忆失败与原始感知失败。

Connection / Potential Use

把 Video-MemComp 的压缩预算从“单次 QA 准确率”改成“跨轮依赖正确率”，可检验其缓存是否保留真正会被未来问题引用的事件。最小实验：同一视频多轮 QA，对比 full cache、均匀压缩、Video-MemComp、query-aware episodic cache；测 accuracy、dependency-conditioned accuracy、KV tokens、TTFT 与显存。若只优化单轮 benchmark，可能在此任务上暴露新的退化。

Tier BUnlearningPreserving Utility in Continual LLM Unlearning via Orthogonal Projections
Authors: Juan Belieni, Ana Carolina Erthal, Eliezer de Souza da Silva, Diego Mesquita · 2026-10-29 arXiv v1 · Venue: 未核实正式发表 / preprint
Paper · Full text HTML

人话版：这篇论文到底干了什么？

连续机器遗忘与一次性遗忘不同：模型先忘 A，再忘 B 时，第二次梯度更新可能让 A 的知识重新出现，或者沿同一敏感方向持续损伤通用能力。COP（Continual Orthogonal Projection）缓存先前 forget set 的低秩激活子空间，限制新的遗忘梯度在其正交补空间中更新，从而减少对既有删除效果的一阶干扰。它不是简单换一个 loss，而是针对“多次请求之间的干扰”提出结构性约束，因此虽属第二优先级，仍有持续追踪价值。

Method / Experiment / Finding

输入为当前 forget request、模型和过去请求的激活子空间基。先根据旧请求保存的低秩基定义投影，再把当前梯度投影到旧子空间的正交补，最后按原遗忘 objective 更新参数。作者强调无需保存旧 forget 样本或旧梯度，可插入不同可微 unlearning loss。实验覆盖 TOFU 和 RWKU，摘要称相较常规与 continual-specific baselines 能保持 utility、减少旧遗忘回退，但没有在摘要给出明确数值；此处不猜测。

Contribution / Limitation

贡献是 New Mechanism（跨请求低秩正交保护）与 first-order non-interference 理论保证。关键限制：一阶不干扰不等于多步优化或非线性行为完全不干扰；不断增加保护子空间可能让可更新空间变小；旧请求激活子空间不一定覆盖可通过新 prompt 重新激活的知识。与普通 loss 改进相比，它值得关注的是“删除历史”成为训练状态的一部分。

Connection / Potential Use

可迁移到 Agent Memory 编辑：为已验证的旧删除请求保存低秩行为方向，观察新删除后是否发生 re-learning；或者反过来用于保护长期技能不被新 RL 更新破坏。最小实验比较单次 vs 10 次序列遗忘、COP vs replay/regularization，测 forget retention、utility、relearning attack 与保护子空间秩增长。仅根据 Abstract / 可获取信息总结，正式深读需先核 Table 1–3。

Tier BRLCheap Retrieval and Observation Credit Assignment from One Quantity: The Value of Information
Authors: Daniel Strauss, Nikolaos Sotirakis, Zhenshan Bing, Alois Knoll · 2026-10-29 arXiv v1；CoRL 2026 Workshop on Memory for Robot Foundation Models · Venue: 未核实正式发表 / preprint
Paper · Full text HTML

人话版：这篇论文到底干了什么？

强化学习 Agent 的长期记忆有两个相互关联的问题：在有限延迟与能耗下怎么找到真正有用的历史观察，以及当某次记忆后来帮助任务成功时，如何把 credit 追溯到最初采集它的动作。本文提出用同一个 Value of Information（VoI）量同时处理 retrieval 与 observation credit。作者用已归档 rollout 和学习到的 world model 估计 VoI，在观察时把其作为采集动作最优价值的下界，在决策时用它确定最优检索集合。这提供了一个连接“该存什么”和“为什么存它有用”的理论入口。

Background / Core Method

普通 attention 要每次扫描整个 memory store，recurrent compression 又必须过早决定保留内容。作者将某条观察的价值定义为它能让未来决策改善多少，而不是 embedding 相似度。Pipeline：归档 trajectories → world model 估计有无该观察的价值差 → observation 时给采集动作 TD target 设置下界 → decision 时按 VoI 选择检索集合。理论关注最优动作价值与检索集，但训练的 world model 误差会直接污染 VoI。

Experiment / Limitation

论文为 11 页的 CoRL 2026 Memory for Robot Foundation Models Workshop 工作，摘要只报告一个使用较少上下文完成 memory task 的 pilot retrieval 系统，没有足以支持大规模 Agent 优势的数值。作者也明确将检索系统描述为仍需训练和改进的原型。因而应把它看作高潜力理论机制、低成熟度实证，不应仅因标题吻合 credit assignment 就升为 Tier S。

Connection / Potential Use

可与 SPLICE 的边干预结合：一条来自 Agent A 的观察是否对 Agent B 的后续回报有价值？最小实验在 MiniGrid Memory 或可回放工具环境比较相似度检索、全量检索、VoI 估计与 oracle 反事实检索；指标为 return、检索 tokens、world-model error、credit attribution precision。最大的风险是 world model 对未见轨迹的反事实预测不可靠。
