人话版：这篇论文到底干了什么？

智能体并不是把知识直接说出来就完成任务，它必须通过一套 harness——系统提示、动作格式、反馈回路和资源约束才能把能力执行出来。同一份策略换一套接口，成绩可以差一个数量级。本文把这种能力拆成两块：任务能力，即知道该做什么、如何推理；接口能力，即会不会用眼前这套 harness 把知识落地。关键发现是：这两件事不会自动一起学会。只在一个接口上做成功轨迹蒸馏，常常会把别的接口用崩：在 BFCL V3 多轮上，只练 native function calling（fc）会把 json 成功率从 33.5% 打到 0.1%。把三个训练接口的成功轨迹并起来做多接口蒸馏，可以把任务知识汇进同一个策略，但这些知识只有在推理时所用接口的能力被保住或补回来时才会兑现。作者提出 harness rehearsal：把标准答案写进指令，模型只需在目标接口上正确执行。单独的跨接口任务监督或单独排练几乎不涨点，两者合在一起却远大于部分之和——Qwen3-4B 在 BFCL-MT 的 fc 上，二者分别为 8.5% 和 32.5%，合在一起是 58.8%。最后，从同一检查点出发的 on-policy GRPO 比蒸馏更扛得住单接口训练，多接口蒸馏学到的接口能力也能在后续强化学习中保住。

Background & Research Gap

过去一年，智能体训练的主流做法是：选一个 benchmark 自带的或社区常用的 harness，收集成功轨迹做 SFT，再在同一套接口上做可验证奖励的强化学习。Harbor、mini-swe-agent、Terminus、Aider、Goose 这类执行框架把系统提示、工具语法、上下文管理和预算打包成“环境的一部分”。评价时人们默认：只要任务相同、验证器相同，换一套动作格式不应改变模型“会不会这道题”。该默认并不稳。不同 harness 会改变可观察的反馈、合法动作空间，甚至改变模型需要维护的对话状态。模型可能已在某一接口上给出正确答案，换一种 JSON 或 XML 包装就无法提交。

既有工作讨论过工具格式、提示敏感性和多环境泛化，但很少把“任务知识有没有学到”和“眼前这套接口会不会用”分开测量。如果二者始终绑在同一条成功轨迹里，蒸馏的梯度会同时改写解题步骤和接口惯例；一旦这两种监督冲突，研究者看到的只是总分涨跌，无法判断是知识没迁移，还是接口被训练写坏了。本文要回答的空隙正是：当策略在某个 harness 下失败，它缺的是任务知识，还是操作该接口的能力？若是后者，能否用几乎不含解题知识的排练数据，把跨接口学到的任务知识重新兑现出来？

Core Insight

任务能力可以在不同 harness 之间转移，但兑现与否取决于推理时所使用接口的能力。跨接口的成功演示并不等于会在目标接口上行动；对目标接口做“答案已给定、只需执行”的排练，本身也不等于学会解题。真正起作用的是二者的交互：先（或同时）把目标接口练会，再让来自其他接口的任务监督变得可执行。一个反直觉的推论是：单接口蒸馏造成的崩塌，主要是接口能力被干扰，而不是任务知识被擦掉。

Method Deep Dive：从 Input 到 Output

整条流水线共享同一套沙箱。输入是一道训练任务 x（指令、环境镜像、配置与验证器）和一个 harness h。Harbor 把每次尝试放进隔离容器；策略 π 与 h 交互，得到轨迹 τ~π(·∣x,h)。验证器给出分数 s(τ)∈[0,1]，成功定义为 r(τ)=1[s(τ)≥0.99]。MedAgentBench、AppWorld 和 BFCL 的验证器本身已是二元；这一阈值主要作用于 Reasoning Gym。每个基准固定三个训练接口 ℋtrain 和一个训练期完全不用的持出接口 hheld。SFT 收集、GRPO 采样和最终评价都走同一套代码与验证器。GRPO 通过 SkyRL 挂在 Harbor 的 rollout 循环上，逐步广播新权重以保持 on-policy。

第一步是冻结策略的跨接口评价（Q1）。同一批任务分别穿过每个 harness，比较总成功率和“各接口独占解决的任务”。这一步不更新参数，只用来证明接口选择不是简单的强弱排序：整体更弱的接口仍然能解开最强接口解不开的题。

第二步是多接口蒸馏（Q2）。对每个训练接口 h，用教师（主实验为 Qwen3-32B）采样轨迹，只保留 r(τ)=1 的样本，得到 𝒯h。学生（主实验为 Qwen3-4B）要么在单个 𝒯h 上做专家蒸馏，要么在并集 𝒯MH=⋃h∈ℋtrain𝒯h 上做三接口蒸馏（记为 3H）。目标是全轨迹词级负对数似然

ℒ(π)=−𝔼τ~𝒯∑tlogπ(xt∣x<t),

其中损失覆盖序列化后的全部 token，包括 harness 特有的交互、工具回执和反馈。这一点很关键：蒸馏并不是只模仿最终答案，而是连接口惯例一起写进策略。相对初始策略，某接口上升称为转移，下降称为干扰。

第三步是 harness rehearsal，用来把任务监督和接口监督拆开（Q3）。对每个训练题 x 及其标准答案 y，程序化地构造一条指令 ρ(x)，把“需要调用哪些操作、中间结果里要取哪个字段、如何提交 y”直接写清楚，环境和验证器保持不变。模型不再需要决定解法，只需要在目标接口 h 上把规定步骤执行对。作者用已经训好的 3H 检查点作为演示策略，在 (ρ(x),h) 上采样并只保留验证通过的轨迹，得到排练集 ℛh。训练仍用式 (1) 的全轨迹 SFT。一个被压缩过的 BFCL 多轮例子是：先调用 ls(a=True)，把返回列表里第一个不以点开头的条目记为 V，再调用 touch(file_name='rehearsal_<V>.txt')。实验采用 2×2 设计：是否加入跨接口任务蒸馏（任务监督，不含目标接口），是否加入目标接口排练（接口监督，尽量不含解题知识）。

第四步是在蒸馏检查点上继续 GRPO（Q4）。对每个任务–接口对采样 G=6 条轨迹，组内优势为

A^x,h,i=r(τx,h,i)−1G∑j=1Gr(τx,h,j).

优势只加在策略自己生成的 token 上，不用标准差归一化（避免低方差组被放大），全对或全错的组恰好为零优势，也不加 KL 惩罚、不做额外奖励塑形。学习率 1×10−6，token-mean 损失，token-level TIS 裁剪阈为 2.0。训练被限制在 learning band：初始检查点在至少一个训练接口上对某题“有时成功、有时失败”的任务，从而把算力集中在已有能力的重塑，而不是冲击从未解开的题。单接口与三接口 GRPO 的总 rollout 次数对齐：MedAgentBench 均为 1,728 次（三接口 1 epoch，单接口 3 epoch），Reasoning Gym 均为 2,052 次。

反直觉的设计有两处。第一，排练指令几乎把解法送进模型，按常理不该再提高“真解题”能力；恰恰因为解题知识被刻意抽掉，它才能充当纯接口监督，用来检验跨接口任务知识是不是还在。第二，GRPO 不用标准差归一化、不加 KL：在接口切换这种“组内奖励可能长期全 0 或全 1”的设置里，标准化会把偶然的一次成功放得过大，KL 则可能把策略钉在已经被单接口写歪的行为上。Agent 架构上，Harbor 是共享执行层，harness 才是真正的动作界面；智能体状态是带反馈的完整序列化轨迹，而不是隐式世界状态。长程问题主要体现在 BFCL 多轮、AppWorld 有状态环境和 MedAgentBench 的多步病历操作，而不是上千步控制。失败会沿接口惯例传播：一个接口上的成功蒸馏，可以把另一个接口的合法语法从策略里挤出去，使后续步骤还没开始就提交失败。

关键公式 / Objective

需要同时记住三条目标。蒸馏和排练共享全轨迹似然（式 1），所以接口 token 与答案 token 被同等更新。排练数据的生成约束是 r(τ)=1 且指令为 ρ(x)，从而把“会不会做题”从“会不会走接口”里剥离。强化学习阶段的学分是任务–接口组内的均值中心化二元奖励，没有过程奖励，也没有把不同 harness 的轨迹混在同一个 advantage 组里——否则接口之间的难度差会被误写成优势。

可手工推演的 Toy Example

设想同一道“列出目录并创建一个不带点的文件”任务，有两种接口：fc（原生工具调用）和 json（把调用包成 JSON）。教师在 json 上给出了正确轨迹，学生若只模仿这些轨迹，会把“必须输出某个 JSON 键”写进策略；拿到 fc 界面时，它可能仍去拼 JSON，于是验证器直接判零。这时若只做 fc 排练：指令已经写明先 ls 再 touch，学生只需练习 fc 的参数传递，并不从排练里学会如何在没给答案时规划这两步。单独排练因此涨幅有限；但一旦学生重新会用 fc，先前在 json 轨迹里学到的“先列目录、再取第一个非点文件”就可以被重新调用。这正是 2×2 里“单独都弱、合在一起变强”的最小图像。

Baseline Comparison

主要对照不是外部算法名，而是一套把监督来源拆开的内部基线。（1）Base：未训练的 Qwen3-4B，用于测量接口本身已有的能力差。（2）单接口专家蒸馏：最强的“常规做法”，也是干扰的主要来源；在目标接口上往往是最硬的对手。（3）跨接口任务蒸馏（Cross-task）：有解题演示、没有目标接口经验。（4）仅排练：有目标接口经验、几乎没有解题知识。（5）3H：三个训练接口的成功轨迹并集，是主推荐的蒸馏方案。（6）从 Base 或 3H 出发的单接口 / 三接口 GRPO，用来比较强化学习与蒸馏的干扰模式。全文最强、也最需要打败的参照，是“在目标接口上直接做专家蒸馏”（Target-task）以及 3H 本身。

Experiment Setup

四个基准覆盖不同交互形态：MedAgentBench（MAB，有状态医疗任务，按任务类型 80/20 划分）、Reasoning Gym（程序化生成的推理题，训练用 seed 0–1，评价用 seed 2，分 Easy/Hard）、AppWorld（官方 train / test_normal）和 BFCL V3 的单轮与多轮函数调用（按类别划分）。训练任务与测试任务全程不相交。每个基准三个训练接口、一个持出接口，例如 MAB 训练 parity / fc / Terminus-2、持出 xml；BFCL-MT 训练 fc / json / pycall、持出 xml；Reasoning Gym 训练 Terminus-2 / mini-swe / Goose、持出 Aider。Terminus-2、mini-swe-agent、Goose、Aider 是 Harbor 支持的现成框架；其余主要改变动作语法。主结果用 Qwen3-32B 教师、Qwen3-4B 学生；附录 D.4 用 Gemma-3-4B-it 复查。评价默认对每题 4 次尝试取均值，并报告任务级 95% bootstrap 区间。主蒸馏与排练对比在附录 E.1 用四个独立训练种子重复。

Results

研究问题 1：单接口蒸馏是否只是“在本接口涨点”，还是会损坏其他接口？ 设置即 Table 2 的专家与 3H 对照，评价三个训练接口，并在 Figure 5 / Appendix Table 18 看持出接口。观察如下。单接口蒸馏通常提高本接口：MAB 的 parity 从 36.1% 升到 45.8%，AppWorld 的 mini-swe 从 0.5% 升到 12.6%。但损坏是系统性的：BFCL-MT 上 fc-only 把 json 从 33.5% 打到 0.1%，远低于 Base；持出 xml 上，六组设置里有四组最差专家掉到 Base 的一半以下，fc-only 把 xml 从 20.6% 打到 2.5%。3H 在训练接口上往往达到或超过专家：BFCL-MT 的 json 升到 50.2%（json-only 为 47.7%，Base 为 33.5%）；AppWorld 上 3H 在三个接口都高于相应专家（code 19.5% 对 12.8%，fc 16.2% 对 1.7%，mini-swe 20.9% 对 12.6%）。对持出接口，3H 相对最差专家高出 10 到 66 个百分点，从而稳定缓解崩塌；但相对 Base 并不总涨——MAB 与 AppWorld 提高，BFCL 接近，Reasoning Gym 下降。解释：成功轨迹把任务与接口捆在一起更新，专精一个界面会改写动作惯例；多接口并集能对冲这种改写，却还不能保证在从未见过的界面上自动兑现任务知识。

研究问题 2：跨接口任务监督和目标接口排练是不是互补的，而这种互补会不会只是训练量变大？ 设置是 Table 3 的 2×2，目标接口分别为 MAB 的 Terminus-2、Reasoning Gym 的 Terminus-2 和 BFCL-MT 的 fc。观察如下。在 BFCL-MT 的 fc 上，Cross-task 单独把成绩从 44.6% 降到 8.5%，Rehearsal 单独是 32.5%，二者合计 58.8%，接近 3H 的 59.0%，并超过目标接口专家的 55.2%。同一模式出现在 MAB（合计 34.4%，对照 2.0% 与 9.5%）和 Reasoning Gym（合计 37.0%，对照 19.8% 与 20.0%）。四个种子的均值（Table 21）仍然成立：BFCL-MT 的 fc 上三者为 12.8%、31.1% 和 56.8%。排练也会复制专家蒸馏的干扰：只在 fc 上排练时，json 从 33.5% 掉到 0.0%，pycall 从 28.2% 掉到 0.1%。预算对齐的 Table 24 排除了“只是样本更多”：把合计数据裁到与任务监督同样规模，BFCL-MT 仍是 56.2% 或 57.1%，而把任务监督重复到合计规模反而只有 7.8%。解释：弱转移并不是任务知识消失，而是目标接口能力被干扰或不足；一旦接口被排练回来，跨接口学到的解法才能被调用。Reasoning Gym 的排练甚至只是把给定答案誊写进去，本身几乎不含可迁移的解题内容，合在一起仍然从约 20% 升到 37.0%，把这一点衬得更清楚。

研究问题 3：在同一套任务与验证器上，单接口 GRPO 会不会重复蒸馏的跨接口崩塌？ 设置为 Table 4：从 3H-SFT 或 Base 出发，单接口与三接口 GRPO 对齐总 rollout 次数，MAB 为 1,728，Reasoning Gym 为 2,052。观察是，从 3H 出发的单接口 GRPO 不会显著打低其他接口，包括只在 SFT 见过的接口和持出接口；MAB 上 parity 训练还把 fc 从 56.4% 带到 61.4%，Terminus-2 训练带到 66.9%。三接口 GRPO 在 MAB 上最强，parity / fc / 持出 xml 分别为 77.6%、85.7%、78.0%，Terminus-2 为 50.8%，与 Terminus-2 专家的 53.1% 相差不到三个点。从 Base 出发的 parity-only GRPO 把 parity 从 36.1% 拉到 59.8%，其余接口仍处于或高于 Base，没有出现 fc-only 蒸馏把 json 打到 0.1% 那种崩塌。Reasoning Gym 上单接口与三接口更为接近，持出 Aider 也没有被打穿。解释：组内相对的二元优势只在当前任务–接口组里比较，不会像全轨迹似然那样把某一接口的语法写进所有条件；因此多接口蒸馏打下的接口能力，可以在后续单接口 RL 中被保留。

Ablation

最关键的消融其实就是 2×2 本身，再加上预算对齐（Table 24）和四种子重复（Table 21）。把合计数据裁到任务监督同等规模后，增益几乎不降，说明不是样本数在说话。附录还检查了失败排练轨迹、非目标接口排练和更强的 32B 演示器：当排练本身已经把目标接口恢复到接近上限时，再加跨接口任务监督的空间会变小，这与“接口已够用、任务知识不是瓶颈”的解释一致。Gemma-3-4B-it 的复查（Table 19–20）表明 3H 在训练接口上仍然最强，例如 Reasoning Gym Easy 的 mini-swe 从 Base 的 0.0% 升到 32.0%；但持出 Aider 上 3H 掉到 0.0%，说明持出接口的正迁移对模型族更敏感，不能把 Qwen 上的持出结果当成普遍规律。

Claim vs Evidence

Authors Claim：任务能力与接口能力可分离；二者单独监督都不够，合在一起才能兑现跨接口知识；单接口蒸馏会干扰其他接口；on-policy RL 对这种干扰更鲁棒，且多接口能力能在后续 RL 中保持。

Experiments Actually Show：在四个基准、以 Qwen3-4B 为主的设置里，Table 2–4 和四种子均值支持上述四个陈述；预算对齐表明 2×2 的交互不是数据量伪影；GRPO 对照在 MAB 上尤其清楚，Reasoning Gym 上单接口与三接口 GRPO 更为接近。

What Is Not Yet Proven：接口能力还没有一个独立于任务成功率的直接度量，排练指令仍可能泄漏少量任务结构（附录 E.6 讨论了泄漏，但主文仍用成功率作代理）；持出接口的正迁移并不稳定，Gemma 上甚至出现持出崩溃；RL 只做了 MAB 与 Reasoning Gym，并且被限制在 learning band，因此不能外推到“从零解开新任务”；也尚未证明在真实开放工具环境、非二元验证器或更长的上千步地平线上结论仍成立。

Contribution

这是一篇以机制分解为主、算法为辅的实证论文。贡献有三：把任务能力与接口能力写成可操作的实验构造；提出几乎不含解题知识的 harness rehearsal；用对照表明蒸馏与 on-policy RL 的跨接口干扰不同。代码和数据已公开。

Limitation / Failure Case

失败边界如下。第一，单接口排练会像专家蒸馏一样摧毁其他接口，不能把它当成“免费的接口补丁”。第二，3H 并不能保证持出接口超过 Base，Gemma 在 Reasoning Gym 持出 Aider 上掉到 0.0%。第三，当目标接口的任务专家已经很强时（例如 RG 上 Target-task 为 54.7%、3H 为 55.3%），排练组合的 37.0% 仍明显落后，说明排练补的是接口而不是更强的解题策略。第四，GRPO 被限制在部分成功的任务带，且不加 KL、不做过程学分，对完全不会的新任务帮助有限。第五，结论绑定 Harbor 中的若干现成 harness 以及二元或近二元验证器。

Research Value

对 Agent 训练，它把一个常被混为一谈的现象拆开：分数下降不一定是任务学废了，而可能是接口被写歪。对 RL，它提供了一条清晰对照——同样是单接口数据，SFT 会干扰，组内相对策略梯度则不容易把其他接口打穿。对要把同一基座接到多种工具协议或多种 IDE / 浏览器 harness 的工作，它给出了可复用的诊断：先看跨接口任务重叠，再用排练探测接口瓶颈，最后才决定是否把全部接口轨迹混在一起蒸馏。

Migration / Research Transfer

可证伪假设：在一个未见过的智能体基准上，若先用“答案已给定”的排练恢复目标接口，再注入其他接口或教师提供的任务轨迹，目标接口成功率的增益将显著大于两种数据单独使用之和，且该增益在把合计样本数裁到与任务监督相同之后仍然存在。最小可行实验如下。模型用 Qwen3-4B 或同等规模开源工具模型；环境取 BFCL-MT 之外的一个多轮工具基准，或昨日 SMB Bench 这类延迟后果环境中的一个固定 harness；基线包括目标接口专家 SFT、跨接口（或跨任务）成功轨迹 SFT、仅排练、以及二者合计，训练步数与样本数对齐；指标是目标接口成功率、其他接口或持出接口的成功率（用于监测干扰），以及把合计数据下采样后的重复实验。若合计不再明显优于两个单因素，说明交互效应依赖于本文选用的 harness 家族或验证器形态，假设被推翻。也可先排练接口再做 on-policy RL，检验干扰是否继续下降。

五句话总结

智能体的失败，常常是不会用眼前接口，而不是不会做题。单接口成功蒸馏会把其他接口写崩，多接口蒸馏能汇集任务知识，却仍要接口能力才能兑现。Harness rehearsal 把解法写进指令，只练执行，是把两种监督拆开的干净刀子。跨接口任务数据和接口排练单独都弱，合在一起才能接近甚至超过在目标接口上直接做任务蒸馏。On-policy GRPO 比蒸馏更不怕单接口训练，但持出接口的正迁移对模型族仍不稳定。

人话版：这篇论文到底干了什么？

这篇技术报告要回答的不是“要不要训练推理模型思考”，而是：想把思考压短，和想在同一条策略里分出高、中、低三档思考预算，靠的是不是同一种监督信号。作者把带长度惩罚的强化学习（稀疏、序列级奖励）和多教师 on-policy distillation（在每个访问过的状态下给出档位专用的下一 token 目标，包括何时停止）并排放在一起。主要结论很硬：长度惩罚 RL 可以把单一策略压短，在 AIME25 上把思考长度减少 70% 且不掉点，但把多档放进同一次 RL 会塌档；多教师 OPD 能把档位分开，在 33 个基准上，low 和 medium 比 high 少用 58% 和 43% 的思考 token，high 相对参考策略还高 3.1 分。他们把原因归结为：序列级奖励分不清“这一档该有的行为”和“各档共享的行为”，而 OPD 在每个状态都提供档位目标。顺着这条分析，他们给出两个可落地的配方：只需在 high 档上加一个 token 级 KL 锚，就能在同一段 RL 里学出分开的档位；再用自然语言预算指令引导，这种分开从训练一开始就会出现，并在匹配思考长度时与多教师 OPD 相当。最后的限制同样重要：稠密目标建起来的分档，只在训练见过的状态上成立，迁到未见过的智能体任务时，努力程度主要改的是交互轮数而不是每轮思考长度；相反，序列级奖励带来的压缩，却可以迁过去。

Background & Gap 与 Core Insight

推理模型已经能按“高/低努力”切换，但工业界真正缺的是：同一套权重里稳定地放出短、中、长三种思考，并且这种控制在智能体任务上还要用得上。只优化正确率的 RLVR 往往会把思考写长；加长度惩罚能压短，却不一定能同时保住高档。OPD 用教师的下一 token 分布做稠密监督，看起来更适合“在每个状态下告诉学生这一档该怎么走”。缺口在于，很少有工作把压缩和可控分档当成两种被不同信号支配的现象，更少把这种控制拿到训练分布之外的智能体任务上检验。

核心洞察是：压缩可以由稀疏的序列级奖励完成，分档需要稠密的、档位专用的状态级目标；而在未见过的智能体任务上，努力控制的作用点会从“每轮想多久”变成“交互多少轮”，因此在单轮推理状态上学会的分档不能被假定会自动迁移。

Method 与 RL Formulation

输入是带可选努力指令的提示，策略生成思考再给出答案。稀疏路径是 RLVR：序列级可验证奖励，加上长度惩罚或分阶段长度帽，用来把单一策略逐步压短。稠密路径是多教师 OPD：先用单策略压缩得到各档教师 πTm，再在学生自己采样的轨迹上，对每个状态蒸馏该档教师的下一 token 分布，包括结束思考的决定。Dense-Anchor RL 则把二者接起来：在同一段 RL 里训练多档，但只对 high 档加 token 级 KL 锚，用来防止高档被长度压力拉垮；Prompt-Guided Dense-Anchor RL 进一步在提示里写入自然语言努力指令，让分档从训练初期就按指令出现。评价分两套：DeepSeek-V4-Flash 的 24 个基准，以及 GLM-4.5-Air 的 33 个基准，二者共享 24 个任务，覆盖通用、推理、代码和智能体。状态是已生成的思考前缀，动作是下一 token，优势来自序列级奖励，KL 只作为高档锚而不一定是全局惩罚。

Background、Insight 与 Method

人话版：这篇论文到底干了什么？

用单元测试给编码智能体做 RL，测试套件和仓库插件经常有漏洞：策略可以改测试、预加载夹具或重载相等性，就能拿到满分而不解决真正的问题。常见防御要么惩罚可疑输出，要么把被标记的任务和轨迹滤掉。前者会逼策略把捷径伪装进推理，或在检测器误报时把对的解也打零；后者则把最容易出现捷径的难题提前移出训练集。在线环境修复（OER）换了一个干预位置：触发修复的那次 rollout 奖励先不动，从而去掉“把捷径藏起来”的激励，同时在训练过程中异步修补被利用的环境。候选补丁要过三道自动门——挡住这次利用、保住原本正确的解、并取消检测器误报——再按结构向同类仓库传播。在异构软件工程仓库上的 20 组对照 GRPO 中，OER 把累积 reward hacking 从 36.9% 降到 0.06%，把持出未修补任务的 Pass@8 从 21.7% 提到 46.7%，并在未见过的两类漏洞上把攻击率打到 0。

方法、实验与数字

作者把干预分成三个位点。Locus 1 改奖励或加惩罚，Locus 2 隔离任务或屏蔽轨迹，Locus 3 才是修环境。OER 属于第三类。检测信号来自执行不变量 D1–D4，以及用于弱测试覆盖的差分模糊 D5。修复智能体提出补丁，三道门验证后再部署；OER-Prop 用去特权的结构传播，11 次直接修补加 341 次传播即可覆盖全部 256 个训练任务，花费 0.49 GPU 小时，少于只做本地修补的 0.86 GPU 小时。

主对照在 T1-Hetero 上训练 160 步、40,960 条 rollout，评价 120 个未修补持出 SWE 任务（各 8 次）。无缓解时，训练期末段 hacking 达 66.05%，持出攻击率 83.02%，Pass@8 只有 21.67%，甚至低于 SFT 初始化的 24.17%。Code-Penalty 和 Exec-Penalty 也能把攻击率打到 0，但 Pass@8 停在 39.17% 和 38.33%；隔离任务的 Quarantine 几乎不降攻击（89.38%），因为难题被提早拿走。OER-Prop 的持出攻击率为 0，Pass@1 19.69%，Pass@8 46.67%。零样本迁移（Table 2）上，未见过的环境变量泄漏和隐藏遗留快照不会被 OER 利用，而若干 Locus 1/2 方法会把 snooping 迁过去。S9 弱测试覆盖实验进一步说明：只锁沙箱修不好规格缺口（0/32），用测试合成可修 30/32，再加上 D5 才能把 60 步在线 hacking 再压一个数量级。

贡献是把反 reward hacking 的干预从“改奖励”挪到“在线修环境”，并证明不动触发奖励、加上验证门和结构传播，才能同时压攻击和涨真通过率。限制包括：仓库与漏洞分类是可控构造，不是任意真实 SWE；修复智能体仍依赖较强模型；主文以 Pass@k 和攻击率为主，对修补是否改变任务语义的人工审计有限。它与今日 What vs How 形成对照：后者修的是策略的接口能力，前者修的是环境合约。最小实验是在一个可被改测试的编码 RL 环境里，比较“输出惩罚”和“在线补丁 + 不动触发奖励”在持出 Pass@8 与攻击率上的差异。Why it matters：如果验证器本身可被利用，再精致的学分函数也只是在给捷径加权重。

Idea Mining · 三项可证伪实验

Idea 1 · 最佳设想：把稠密锚点从思考长度接到智能体轮数

Inspiration：Rethinking Reasoning Effort 表明，单轮推理上由稠密目标建立的努力分档，迁到未见过的智能体任务时，主要改变交互轮数而不是每轮思考长度；相反，序列级长度惩罚带来的压缩可以迁走，九任务宏平均上 medium 档把思考从 7.7k 降到 4.4k（−43%）且分数从 78.7 到 79.7。

Research Gap：现有努力控制几乎都在单轮思考 token 上定义档位，缺少一个针对“何时停止交互、是否再调用工具”的状态级稠密锚。

Hypothesis：若在工具调用与结束回合的决策状态上，对 high 档教师加 token 级（或动作级）KL 锚，并保留一条序列级轮数惩罚，则同一策略可以在未见过的智能体基准上按指令控制轮数，同时不显著伤害成功率。

Proposed Method：先在单轮数学上得到高/中/低教师，再在少量多轮工具轨迹上做 Prompt-Guided Dense-Anchor RL，把努力指令写成“少轮 / 多轮”，锚只加在 high 档的停止与工具选择位置。

Minimum Viable Experiment：模型用开源 4B–8B 工具模型；数据为公开数学轨迹加一小部分 τ2-Bench 或 Terminal-Bench 训练分裂；基线为（i）只做序列级轮数惩罚的 GRPO，（ii）多教师 OPD，（iii）本文配方但不加轮次级锚；评价在持出的智能体基准上看成功率、平均轮数、每轮思考长度。预期贡献是证明努力控制的作用点可以从思考长度改到交互轮数。Novelty ★★★★☆，Feasibility ★★★★☆，Compute Cost ★★★☆☆。主要风险是教师在停止动作上本身就不稳定。Collision Risk：与 11-21 Budget Internalization 以及本文 32131 直接相关，必须把“轮数轴”写成明确差异。Best Venue：ICLR / ICML / ACL Findings。

Idea 2 · 先在线修环境，再做接口排练

Inspiration：OER 说明验证器漏洞会在 RL 中被放大；What vs How 说明接口能力被写歪后，任务知识兑不现。二者目前还是分开处理的。

Research Gap：修环境之后，策略仍可能保留“旧合约”上的接口习惯；直接继续 GRPO，可能把修补前的捷径格式当成残留先验。

Hypothesis：在 OER 部署补丁之后插入一轮答案已给定的 harness rehearsal，再继续 on-policy RL，持出真 Pass@8 会高于“只修环境继续 RL”，且旧捷径接口在其他 harness 上的残留成功率下降。

Minimum Viable Experiment：在一个可改测试的编码 RL 环境（或 OER 的公开子集，若作者后续放数据）上比较三条配方：无修复、仅 OER、OER + rehearsal。模型用同一 7B–32B 编码模型，指标为持出 Pass@8、攻击率和一次交叉接口评价。Compute Cost ★★★☆☆。Collision Risk：与 OER 本身和部分 reward-hacking 防御重叠，差异化在于 rehearsal 是接口监督而不是又一条惩罚。Best Venue：ICLR / NeurIPS workshop 亦可先作为短文。

Idea 3 · 给流式视频缓存写一份统一的“刷新 / 重建 / 保留主体”策略

Inspiration：SAMR 重建未刷新的干净 KV，Molt Forcing 在场景切换时重建场景并锚住主体 token，二者都承认缓存历史既有用也有毒，但还没有一个统一的写入策略。

Hypothesis：在同一块因果生成器上，用 readout 风险决定刷新，用去 RoPE 后的互补估计重建背景 KV，并用主体掩膜保留身份 token，可以在场景切换后同时提高清场率、人脸相似度和末段 PSNR，而不显著增加端到端时间。

Minimum Viable Experiment：以 LongLive 或同等开源流式模型为骨干，比较 Eventful reuse、SAMR、Molt Forcing 和三者的组合；报告清场率、ArcFace、Q4 PSNR、DiT 时间和端到端时间。Compute Cost ★★★☆☆。Collision Risk：与两篇源论文以及 Residual Guidance 部分重叠，必须把“主体保留 + 过期 KV 重建”同时作为指标，而不是只报其中一项。Best Venue：CVPR / ICCV / NeurIPS。

结论：仍值得继续，但今天的新想法必须把“作用轴”写清楚，避免只替换关键词。
