人话版：这篇论文到底干了什么？

决策模型不生成长文本，而是对带类型的问题给出选项及概率，因此既可用来选下一步，也可在事后给已执行动作打分，或在强化学习里提供步骤监督。以往几乎只按“它自己当演员能不能做完任务”来评价，结论往往很难看：它们会被更容易的子目标吸引，跳过必须先做的步骤。本文要问：一个自己演不好的决策模型，能不能当好老师？

作者在 ALFWorld 上比较了三款专用决策模型（JEV、Decider v1.2、GPT Decisions）和三个用同样问题接口改装的通用 LLM，并只用 JEV 当老师，去训练 Qwen2.5-1.5B 与 7B 策略。关键发现非常干净：JEV 自己当演员只完成 42.9% 的 ALFWorld 任务，有顺序依赖的任务上更只有 14.7%；但若让它在看到整条轨迹后回答“这一步是否帮助达成了目标”，再把中心化后的分数加进 GRPO 的结局优势，1.5B 策略成功率从只有结局奖励的 72.8% 升到 82.9%，WebShop 从 56.8% 升到 71.4%。换成“这一步之后任务会不会成功”这个问题，同样的模型和同样的后见上下文，ALFWorld 反而掉到 69.3%。也就是说，差演员可以是好老师，但前提是问对问题、并给它看完整后果。

背景与研究缺口

长程智能体的强化学习长期被一个结构问题卡住：任务往往到最后才给出对错，GRPO 一类结局奖励会把同一条轨迹里的所有动作写成同一个优势。想把信用拆到步骤，要么为每个环境手工标注过程奖励，要么每一步都问一个昂贵的 LLM 评判。决策模型看起来能填这个空缺：它们预训了带概率的选择，查询便宜，同一套接口可以切换成演员、法官或教师。

缺口在于，公开评价几乎只看演员角色。已有工作反复报告它们会被提到任务物体的命令吸引、跳过前置子目标。若只根据这些失败就否定它们，会漏掉一个可能性：演员必须在后果出现前预见到“先放杯子会让任务做不完”；法官却是在整段回放之后打分，能看到后来有没有加热、有没有把杯子放到桌上。本文把这个差别做成实验：先量演员的失败形态，再改问题与上下文看法官是否仍把分数摊平，最后把最能分开动作贡献的打分接到 GRPO，看策略能否超过纯结局基线，甚至超过老师自己当演员的水平。若这一假设成立，决策模型就可以从控制器改写成过程奖励源。

核心洞察

核心判断可以压成一句话：角色不是模型的属性，而是问题与可见上下文的属性。同一模型在只看见前缀时，会像演员一样被更容易的子目标吸走；一旦看见整条轨迹，并被问“这一步帮没帮上忙”而不是“任务最终会不会成功”，就能把里程碑动作和空操作分开。这才是值得加进 GRPO 的过程信号。若问题仍盯着最终成败，后见分数会在一条轨迹里变得差不多，几乎只是把结局奖励再说一遍。要迁移的不是更强的在线演员，而是用后见加贡献问题，把一个不必自己能做对的模型变成步骤级教师。

方法深挖

输入与角色定义。决策模型 D 接收一个目标 g、一段可见上下文，以及一个关于某个动作 t 的是非问题，输出 [0,1] 上的分数。专用决策模型通过各自的决策 API 查询；通用 LLM 则用两种方式接到同一接口：提示词归一化 Yes/No 概率（Qwen prompted、GPT Luna），或约束式读出（Qwen constrained）。所有通用模型在实验中关闭推理。六个模型分成两组：JEV（TypeSafe AI，闭源，基座与适配方式未披露）、Decider v1.2（Perplexity，由 Qwen3.8-27B 全参数微调，开源权重）、GPT Decisions（OpenAI，基于 GPT-6 Luna，适配方式未披露）；以及三个对照：Qwen prompted、Qwen constrained（皆基于 Qwen3.8-27B）和 GPT Luna。

三个角色共用同一套查询，只改可见范围和问题。演员角色：在当前观察与候选动作上选择下一步，相当于在线决策。法官角色：对已经执行的动作打分，上下文可以是动作之前的前缀（Prefix），也可以是整条轨迹（Hindsight），并且隐去环境奖励、成功标签与隐藏状态，避免直接泄漏结局。教师角色：法官的同一套查询被应用到正在训练的策略所采样的轨迹上，模型在训练期保持冻结，测试期不再调用。

两个正交的设计轴。问题轴上，Value 问“该动作之后任务会不会成功”，Progress 问“该动作是否帮助达成了目标”。上下文轴上，Prefix 只给到当前步，Hindsight 给出整段回放。默认教师是 Hindsight + Progress。这四个组合后来会在 1.5B 策略上被完整交叉，用来证明不是“加了任何稠密分数都有用”，而是特定组合才有用。

接到 GRPO 的方式。对每个任务 u，策略 πθ 采样一组轨迹 𝒢u。轨迹完成后，教师给每条轨迹 τi 中的每个已执行动作打分 si,t=D(g,τi,t)∈[0,1]。这些分数在组内做中心化，再加到 GRPO 的结局优势 Ai,tout 上，得到步骤优势。作者明确不除以分数的标准差：若一个组里教师给的分差不多，调整就应该很小，避免把近乎常数的分数放大成虚假的步骤差异。每个动作的优势再赋给该动作生成的全部 token。教师分数的权重取 λ=0.5。也就是说，步骤监督是加性的、组内相对的，而且幅度被故意压住：它修正结局优势的分配，而不是改写奖励的定义。训练设置在两个环境上对齐：150 步、每步 16 个任务、每任务 8 条 rollout；ALFWorld 每条最多 30 个动作，WebShop 最多 15 个；策略提示/回复 token 上限分别为 2048/512 与 4096/512。

一个反直觉的设计。最容易想到的用法是让决策模型在线当演员，或至少用“任务会不会成功”这种和演员目标一致的问题来打分。论文却把默认教师选成了演员最不擅长的设定：先让它把整段后果看完，再问贡献而不是成败。后面的实验表明，这个选择不是口味问题：Hindsight + Value 在 ALFWorld 上反而低于纯结局 GRPO。换言之，后见本身不够，问错问题会把步骤信号稀释成结局奖励的回声。

诊断实验如何接到训练。演员诊断在 116 个“已经站在目的地、手里拿着还没被清洁/加热/冷却的物体”的状态上，对比完整目标与去掉容易子目标后的目标，历史、观察、候选动作和剩余步数完全相同，从而把“会不会做正确步骤”和“会不会被更容易的步骤吸走”分开。法官诊断则在 462 条至少含一个里程碑动作和一个空操作的轨迹上，把动作标成里程碑、空操作与其他三类，比较两种问题的分数间隔和 Recall@R。教师实验不再改环境，只把上述打分接到 GRPO，并在三个推理种子上报告成功率。整条链因此是：先在受控状态上定位失败机制，再在同一机制上选择监督问题，最后用策略学习检验这个选择是否可训练。

关键公式与 Objective

教师打分与组内中心化优势是贯穿全文的两条式子。打分不使用环境奖励：

si,t=D(g,τi,t)∈[0,1]

组内中心化后与结局优势相加（λ=0.5，Su 为该组中所有被打分的动作）：

Ai,t=Ai,tout+λ(si,t−s¯u),s¯u=1|Su|∑(j,k)∈Susj,k

作者故意不做组内标准差归一化，使教师分数几乎相同的组只产生很小的步骤修正。每个 Ai,t 再广播到该动作的全部生成 token。训练目标仍是带裁剪的策略梯度，只是优势从纯结局变成了结局加上加权的教师贡献。

Toy Example

以“把加热过的杯子放到侧桌”为例。正确顺序是：走到微波炉、打开它、加热杯子、再放回侧桌。错误但更诱人的顺序是：手里已经拿着杯子，直接放到侧桌上。JEV 当演员时，在这类有依赖的任务上成功率只有 14.7% 到至多 18.8%；在 116 个“站在桌边、杯子还没加热”的状态上，完整目标下它把 63.8% 的概率分给“先放杯子”，只有 14.6% 分给必须先做的加热方向。如果把“放到侧桌”从目标里拿掉，这两项变成 2.5% 和 77.6%。模型并不是不知道该加热，而是更容易的子目标把概率吸走了。

改当法官并看到后续加热成功后，情况会翻过来。只看前缀时，JEV 给过早放置打 0.79，给走向和打开微波炉只打 0.23 和 0.20；后见出现加热后，打开微波炉的分数升到 0.66，看完全程达到 0.76。教师用的正是这种后见贡献分：不要求 JEV 自己线上选对，只要求它在回放里承认哪些步骤后来有用。

Baseline Comparison

演员与法官实验以六模型互比，最强演员是 Decider v1.2（ALFWorld 63.6%），但其 Heat 仍只有 18.8%。教师实验的主基线是只用结局奖励的 GRPO，数字引自 GiGPO（Feng 等，2025），并非作者同栈重跑，后文比较时必须记住这一点。更干净的对照是四组教师消融：Prefix 或 Hindsight，交叉 Value 或 Progress，它们共享同一策略、同一采样预算和同一个冻结的 JEV。最强是 Hindsight + Progress；最说明问题的阴性对照是 Hindsight + Value，它在 ALFWorld 上弱于纯结局 GRPO。1.5B 与 7B 对照表明该信号并不只在小模型上成立。

实验设置与研究问题

设置。环境是 ALFWorld 与 WebShop。ALFWorld 被拆成无依赖（Pick、Look、Pick2）和有依赖（Clean、Heat、Cool）两类，后者必须先完成清洁/加热/冷却再放置。演员与教师评估使用同一批任务；演员每个任务评估一次，教师训练出的策略用三个推理种子取平均。WebShop 同时报告分数与成功率。JEV 教师通过 OpenRouter 查询，标价为每百万输入 token 0.042 美元、输出免费；四次 Hindsight + Progress 训练的教师 API 费用在 22.21 至 30.07 美元之间。

RQ1：演员失败是不是因为不知道正确步骤？Setup：在 116 个诊断状态上，比较完整目标与去掉容易子目标的目标。Observation：完整目标下 JEV 把 63.8% 概率给容易子目标、14.6% 给必须先做的步骤；去掉容易子目标后变为 2.5% 与 77.6%，六个演员方向一致。在完整任务成功率上，JEV 的 Pick2 为 70.8%，有依赖的三类分别只有 11.1%、18.8%、16.0%，总计 42.9%。Interpretation：失败主要是目标结构造成的注意劫持，而不是缺失程序性知识。进一步的提示实验支持这一点：只加一句“考虑依赖关系”，六个演员的成功率变化仅在 −2.8 到 +5.2 个百分点；即使加上排序范例，JEV 也只从 19.0% 升到 24.1%，Decider 甚至从 89.7% 降到 85.3%。改提示补不好演员，更说明需要换角色而不是换话术。

RQ2：怎样的法官分数才能真正分开动作贡献，并且这些分数能不能教出更好的策略？Setup：先在 462 条轨迹上比较 Value 与 Progress（皆用 Hindsight），再把四种问题–上下文组合接到 Qwen2.5-1.5B 的 GRPO，并在 7B 上验证默认组合。Observation：作为法官，JEV 在 Value 下给里程碑/其他/空操作的均分是 0.632、0.604、0.577，几乎摊平；Progress 下变成 0.659、0.440、0.298，轨迹内里程碑比空操作高 0.36，Value 只有 0.05；Progress 的里程碑 Recall@R 在每个 R 上都高 8.0 到 16.0 个百分点。作为教师，Hindsight + Progress 把 1.5B 的 ALFWorld 成功率从 72.8% ± 3.6 升到 82.9% ± 2.9，WebShop 成功率从 56.8% ± 3.8 升到 71.4% ± 0.7；7B 上从 77.6% 升到 83.8%、从 66.1% 升到 73.6%。1.5B 教师策略已经超过 7B 的纯结局 GRPO（77.6% 与 66.1%）。Hindsight + Value 则把 ALFWorld 降到 69.3% ± 0.7。有依赖任务上，Hindsight + Progress 达到 86.8%，比其他三种设置高 6.9 到 16.2 个百分点，而 JEV 自己当演员只完成其中 14.7%。Interpretation：能教的是“后见下的贡献判断”，不是“后见下的成败预测”，也不是演员本人的成功率。最强结果出现在演员最弱的任务类型上，这正是本文想证明的机制，而不是平均分上的轻微波动。

最强与最弱结果，以及权衡。最强的是 1.5B 在 WebShop 上的绝对提升（成功率 +14.6 个百分点）以及有依赖 ALFWorld 任务上教师策略与演员老师之间的巨大反差（86.8% 对 14.7%）。最弱的是 Hindsight + Value 在 ALFWorld 上的回退，以及 Prefix 两种问题之间差别不大——没有后见时，贡献问题也帮不上太多忙。权衡则是：教师信号要在训练期为每个动作付一次 API 调用，四次默认训练各约 22–30 美元；测试期不再调用，所以推理成本回到策略本身。另一个权衡是对闭源 JEV 的依赖：开源的 Decider 是更强的演员（63.6%），但论文没有用它当老师做同等训练，因此“差演员才是好老师”这一命题目前主要建立在 JEV 上，还不能推广到所有决策模型。

消融、论断与证据

消融。问题与上下文的 2×2 已经是最关键的消融：只有 Hindsight + Progress 在两个环境上都显著优于 GRPO；Prefix 下两个问题接近；Hindsight + Value 在 ALFWorld 上有害。目标结构消融表明，去掉容易子目标就能把 JEV 对正确步骤的概率从 14.6% 拉到 77.6%。提示消融表明，一般性提醒几乎无效，排序范例只对部分模型部分有效。规模消融表明 7B 上方向相同但幅度更小。

Authors Claim / Experiments Actually Show / What Is Not Yet Proven。作者声称：演不好的决策模型仍然可以教得好，因为事后评价能看到行动时必须预见到的后果。实验实际表明的是：在 ALFWorld 与 WebShop 上，用冻结的 JEV、Hindsight + Progress、λ=0.5 的加性优势，可以稳定提高 Qwen2.5 1.5B/7B 的成功率，并且增益集中在有依赖任务与更短的完成步数上；同时，Value 问题与纯提示干预都不能替代这一选择。尚未被证明的是：换开源决策模型当老师是否再现同一模式，GRPO 若在作者自己的训练栈中重跑数字会不会变化，以及这套监督在更长的工具轨迹或缺少清晰子目标标注的环境中是否仍然有效。

Contribution

（发现）拆开演员、法官、教师三角色，证明演员失败不蕴含教师失败。（机制）可训练信号来自“后见 + 贡献问题”，而不是后见本身或成败预测。（证据）两个环境上的 2×2 教师消融、动作类型分数间隔、完成步数，以及 1.5B 教师策略超过 7B 结局 GRPO。

Limitation

作者承认：教师实验主要使用闭源 JEV，基座未知；通用 LLM 关闭了推理；环境只有 ALFWorld 与 WebShop；GRPO 数字引自 GiGPO 而非同栈复现；训练期按动作查询，费用随轨迹变长。此外，里程碑标注依赖可检查的状态变化，迁移到不可完全观测的工具环境会变难；λ 固定为 0.5；论文未把更强的演员 Decider 也训成教师，因此“差演员、好老师”还不能写成对所有决策模型成立的定律。

Research Value

对 RL for Agents 而言，这是把信用分配从“再设计奖励模型”转向“复用已有决策模型，但改问题与上下文”的实证工作。它与把交接文本也纳入训练的路线互补：一个提供步骤级事后信用，一个提供跨回合的经验书写。Hindsight + Value 的失败也提醒做推理 RL 的人：把过程奖励问成“最终会不会对”，可能只是换一种方式广播结局优势。产品上的建议同样明确：别急着让决策模型在线控权，先让它在训练期看完整回放并回答贡献问题。

Migration / Research Transfer

Original Problem：长程智能体的结局奖励无法区分轨迹中哪些动作真正推动了有顺序的子目标。

Transferable Mechanism：冻结一个不必自己能做对的评判模型，在整段轨迹可见的条件下询问“该动作是否有助于目标”，将组内中心化分数加到 GRPO 结局优势上，并且故意不做标准差放大。

New Research Question：在工具使用或软件工程智能体中，若把“是否有助于目标”改成“是否缩小了与最终补丁/最终状态的距离”，同一套加性优势能否在 SWE-bench 类任务上超过纯结局 GRPO，尤其是在教师模型自己解决率很低的实例上？

Method Modification：用开源评判器替换 JEV；用测试或状态差分自动标记里程碑式工具调用；先在不超过 20 步的短轨迹上验证问题形式，再扩展到长轨迹。

Minimum Experiment：在 MiniSWEBench 或 WebShop 风格的工具环境上，训练 Qwen2.5-1.5B 或 Qwen3-4B，对比纯 GRPO、Hindsight + Value、Hindsight + Progress 三组，每组三个种子，报告成功率、平均步数，以及教师模型自身 pass@1。

Model / Dataset / Baseline / Metric：Qwen3-4B-Instruct；MiniSWEBench 或 AppWorld；基线为同栈 GRPO 与 PPO；指标为成功率、到达成功所需步数、以及教师分数与自动里程碑标签的一致性。

Expected Contribution / 可证伪假设：若机制成立，Hindsight + Progress 应在教师自身解决率低于 30% 的任务子集上仍优于 GRPO，而 Hindsight + Value 不应显著优于 GRPO。若三组难分胜负，则说明该机制依赖家庭环境中干净的状态变化，不能直接迁移到工具轨迹。

Compute Cost / Risk / Collision Risk：★★★☆☆。主要成本是采样与教师推理，1.5B/4B 级别可在数张 GPU 上复现；风险是开源评判器质量明显低于 JEV，或自动里程碑标签过噪。撞题风险中等：过程奖励与 LLM-as-judge 文献很多，但“差演员、好老师”这一受控命题仍较新，需避开只换奖励模型、不改问题形式的重复。

五句话总结

一，决策模型演不好有顺序依赖的任务，主要是因为容易的子目标在行动当时吸走了概率，不是因为不知道正确步骤。二，同一模型在看到整条轨迹并被问“是否有帮助”时，能把里程碑动作和空操作分开。三，把这种分数加进 GRPO，1.5B 策略在 ALFWorld 与 WebShop 上分别达到 82.9% 与 71.4%，超过纯结局 GRPO 和 7B GRPO。四，只问最终成败或只给前缀，都得不到同等增益，Hindsight + Value 甚至有害。五，最值得迁移的不是更强的在线控制器，而是后见贡献这种信用分配。

人话版：这篇论文到底干了什么？

智能体做强化学习时，通常只拿最终对错更新策略，环境在试错过程中暴露的错误日志、测试失败和工具报错都被压成一个标量。另一条路线给模型套上反思与压缩的脚手架，把上一轮经验写成 playbook 交给下一轮，但这些交接文本怎么写，本身并没有被学习。本文把两件事放到同一个目标里：既用可验证的标量奖励做梯度更新，也把“写给未来自己的经验”当作训练对象。

具体做法是固定 ACE 脚手架，让同一个 Qwen3 模型同时扮演行动者、反思者和 playbook 编辑者。候选 playbook 的价值不靠语言看起来是否合理，而靠再跑一条新轨迹，看下游行动者能不能因此得分。为了在与 GRPO 相同的 8 条行动 rollout 预算里给三个角色都造出对比组，作者设计了 ACE-RL 的采样树。在 Mastermind、MBPP、AppWorld 和 MiniSWEBench 上，同等训练计算下 ACE-RL 的 RSI@3 分别为 0.775、0.987、0.667、0.340，高于把 GRPO 演员直接放进同一脚手架的结果，也高于用评论家把下一轮奖励回传给整条链的 Delayed-joint PPO。增益不只来自更好的演员：丢掉 playbook 编辑后，AppWorld 与 MiniSWEBench 会掉一截。

背景与研究缺口

当前智能体训练大致分成两派。一派是结局型 RL：GRPO 或 PPO 只优化当前回合的行动，环境反馈再丰富，最后也只剩一个标量。另一派是递归自我改进脚手架，例如 ACE：同一模型先行动，再反思，再编辑一份任务局部的 playbook，下一轮从这份文本接着干。脚手架保留了细粒度经验，但权重通常冻结，交接文本的写法靠提示工程，模型并没有因为“下一次真的更好了”而学会怎么写。

把两者简单拼接并不解决问题。一种常见做法是先用结局 RL 训演员，再把它丢进手写脚手架；论文后面表明，这在部分基准上能缩小差距，但并不等于模型学会了利用自己写下的经验。另一种做法是把整条“行动–反思–编辑–再行动”链用同一条下一轮奖励和评论家一起训，这正是 Delayed-joint PPO / CompactionRL 一类方法的信用结构。风险在于，四个环节共享同一个延迟奖励，谁真正帮到了下一次尝试并不清楚，训练还可能崩溃。缺口因此很具体：需要一个目标，明确优化的是脚手架执行后的下游结果；还需要一种信用规则，让反思和编辑得到的是可验证的、执行过的 playbook 价值，而不是“看起来像总结”的语言奖励；并且这一切必须装进与普通 GRPO 相当的行动采样预算里。ACE-RL 就是对这个缺口的一个具体回答。

核心洞察

核心洞察是：交接文本的奖励必须来自它被执行之后的下游任务结果，而不是来自同一条链上延迟回传的总奖励，也不是来自对文本本身的偏好。一个编辑值多少钱，要看拿着这份新 playbook 再跑一次，行动者能得多少分；一条反思值多少钱，要看从它长出的那些可执行编辑平均能得多少分。有了这种可验证的交接价值，三个角色就可以各自在“同一输入的多个输出”上做组相对优势，从而在不增加行动 rollout 预算的前提下一起更新共享模型。换句话说，要学的不是“把经验写进权重”，而是“写出对未来尝试确实有用的经验”。

方法深挖

固定的任务局部脚手架。作者采用 ACE 的任务局部变体。同一个策略 πθ 在三套固定角色指令下工作：行动指令 ιact、反思指令 ιref、编辑指令 ιcur。对任务 q 与当前 playbook P，一次交接迭代是：先采样行动轨迹 τ~πθ(·∣ιact(q,P))，由任务验证器给出 Rq(τ)∈[0,1]；再让反思者阅读轨迹、奖励以及环境暴露的测试失败和工具错误，写出洞见 z；最后由编辑者阅读 P 与 z，发出结构化操作 u（增加、更新或删除一条提示），经 Apply 得到候选 P′。Playbook 只对当前任务局部有效：每次行动都开启新的环境回合，跨尝试保留的唯一状态就是 P。

学习问题。普通结局 RL 优化的是空 playbook 或固定 P0 下的 Jact(θ)=𝔼[Rq(τ)]。作者改成优化脚手架执行的结果 JH(θ)=𝔼[Rq(ω)]，其中 ω 是一次完整脚手架轨迹。落到 ACE 上，就是最大化新 playbook 之下一次新鲜尝试 τ~ 的奖励：JACE(θ)=𝔼[Rq(τ~)]。这个标量同时依赖于种子轨迹、反思、编辑和再尝试，因此必须把信用拆开，而不能只给 τ~ 打一个分。

可验证的交接奖励。对候选 P′=Apply(P,u)，用旧策略再采样一条行动 τ~~πθold(·∣ιact(q,P′))，定义 V^(P′)=Rq(τ~)。这是对目标 JACE 里下游条件价值的一次无偏但高方差的估计。信用按产物而不是按整条链来给：编辑得到自己这份 playbook 的执行分，反思得到从它长出的可接受编辑的平均分，行动者无论跑在旧 playbook 还是候选 playbook 上，都拿自己的任务奖励 ract(τ)=Rq(τ)。写成式子就是 rcur(u)=V^(Apply(P,u))，以及 rref(z) 对集合 C(z) 里的编辑取平均；C(z) 为空时反思奖励为 0。

不可接受的编辑，包括对 playbook 毫无改动的编辑，奖励记为 0。这样，语言上漂亮但执行后无增益的编辑不会被强化；反过来，即使种子轨迹失败，只要从它写出的反思能长出提高下游分数的编辑，反思仍可得到正奖励。把评估用的再尝试同时放进行动者组，还有第二层用意：演员不仅要在原来的 P 上学会做事，也要学会阅读刚被选中的新 playbook，否则测试期的顺序自我改进会读到一份训练时从未见过的上下文。作者没有用额外的语言质量奖励或长度惩罚来约束 z 和 u，一切对错都以验证器在下一轮给出的 Rq 为准。

每个角色自己的对比组。GRPO 式优势要求同一输入有多个输出。算法 1 的采样树在每条任务上这样构造：先在当前 (q,P) 上采 N 条种子行动；从中均匀挑一条，写 M 条反思；再均匀挑一条可用反思，写 C 条编辑，其余可用反思各写一条；每个可接受编辑执行一次，这些再尝试并入行动者组。默认 N=4,M=2,C=3，行动组最多 8 条，与 GRPO 的组大小对齐，从而比较时不能把增益解释成“多采了几条轨迹”。角色 i 的优势为 Ai=(ri−μG)/(σG+ϵ)，均值和标准差只在本角色的组内计算。常值奖励的组被丢掉，三个角色的输出在一次带裁剪的 token 级替代目标里一起更新共享参数。

Playbook 如何进入下一轮，以及一个反直觉选择。记种子奖励为 s=Rq(τj⋆)，下一轮 playbook 取所有候选中 V^(P′) 最大且不差于 s 的那份，否则保留原 P。每 F=3 次遭遇把 P 重置为空，以避免过长文本失控，也使测试时超过三轮的编辑成为对训练分布的外推。反直觉之处在于：作者没有把下一轮奖励广播给整条链，而是为每个交接产物单独“跑一次账”。这比 Delayed-joint PPO 更费一次评估 rollout，但换来的是按角色可比较的、执行过的价值。行动预算仍然是 8，因为评估 rollout 本身就计入行动者组，演员也因此学会阅读新的和旧的 playbook。

关键公式与 Objective

脚手架目标与交接价值是主线。ACE 目标只为新 playbook 下的再尝试付酬：

JACE(θ)=𝔼(q,P)~μ𝔼τ,z,u,τ~~πθ[Rq(τ~)]

候选 playbook 的价值用一次新鲜行动估计，再赋给编辑与反思：

V^(P′)=Rq(τ~),rcur(u)=V^(Apply(P,u)),rref(z)=1|C(z)|∑u∈C(z)V^(Apply(P,u))

组相对优势为 Ai=(ri−μG)/(σG+ϵ)。下一轮 playbook 仅在候选价值不低于种子奖励时才替换。

Toy Example

想象一个 AppWorld 式任务：演员第一次没有找到所需数据接口，轨迹失败。反思者读到工具错误，写出“应先查询某张表的主键”。编辑者把这条提示写进 playbook。ACE-RL 不会因为这句话像经验就给奖励，而是用新 playbook 再跑一次：如果第二次拿到了数据并完成任务，这份编辑和那条反思才得到高分；如果再跑仍然失败，漂亮的总结也是 0。若同时还有另一条编辑只是改写了语气、没有改变行为，它会因为 V^ 不高甚至因“未改动”被判不可接受而拿 0，从而在编辑组内被相对压低。测试时不再为候选打分，只按顺序执行“行动–反思–编辑–再行动”，RSI@K 表示前 K 次尝试中最好的一次奖励。这就是“把经验写给未来自己，并用未来自己的成绩给这笔经验打分”。

Baseline Comparison

所有方法共用同一任务验证器，每步 8 个任务、每任务 8 条行动轨迹，并在同等累积更新 FLOPs 下比较。PPO 只训演员，用 GAE 评论家，测试看 pass@3。GRPO 同样只训演员，用组相对优势，测试既看独立 pass@3，也把它放进脚手架看 RSI@3。ERL 让模型改写提示并把改进内化到权重，测试不使用脚手架。Delayed-joint PPO 训三个角色，但整条链共享下一轮奖励与评论家，是最接近的“也训交接”的基线。ACE-RL 也训三个角色，但奖励来自执行过的 playbook，优势在角色组内归一化。最强的非本方法基线通常是 GRPO（独立或进脚手架后）；最能说明机制的对照是 Delayed-joint PPO 与“丢掉编辑再评估”的控制实验。

实验设置与研究问题

设置。Mastermind 与 MBPP 用 Qwen3-0.6B（非思考模式），AppWorld 与 MiniSWEBench 用 Qwen3-4B-Instruct-2507。每条行动回合训练和测试都是 20 步（MBPP 为 6 步）。测试时权重冻结、温度 0.7。独立评估从八条互不交接的行动中取 pass@K；脚手架评估跑八次顺序访问，RSI@K 是前 K 次中的最好奖励，正文主数字取 K=3。每条方法只训练一次，误差杠是任务上的标准误。计算量按累积更新 FLOPs 对齐，PPO 类方法包含评论家。

RQ1：在相同行动预算和相同计算量下，为交接文本单独记账，是否优于只训演员、以及把下一轮奖励广播给整条链？Setup：Table 2 在四基准上比较 pass@3 与 RSI@3。Observation：ACE-RL 的 RSI@3 为 0.775 ± 0.014、0.987 ± 0.011、0.667 ± 0.063、0.340 ± 0.048。同脚手架里的 GRPO 是 0.739、0.820、0.597、0.260；独立 GRPO 的 pass@3 是 0.686、0.867、0.624、0.245。配对差值分别为 0.089、0.120、0.042、0.095（对独立 GRPO，标准误见正文）。Delayed-joint PPO 全面落后，并在训练中崩溃：Mastermind 上它在 0.54 EFLOPs 时冲到 0.66，随后训练奖励在 0.73 EFLOPs 前掉到 0.05 以下；MBPP 峰值 0.53，对 ACE-RL 的 0.99；AppWorld 与 MiniSWEBench 从 0.21 与 0.08 掉到接近 0。评论家后期解释方差仍高于 0.95，因此不能把崩溃简单归因于拟合失败。ERL 与 PPO 亦全部低于 GRPO，PPO 在 Mastermind 与 MiniSWEBench 上测试奖励甚至为 0。Interpretation：训练交接是有用的，但信用不能靠一条延迟奖励匀给整条链；按执行价值给角色分组，才能在小模型上稳定学到“写对经验”。

RQ2：增益是更好的演员，还是 playbook 真的在跨尝试起作用？这个作用在训练地平线 F=3 之外还在吗？Setup：先把同等计算的 GRPO 检查点放进同一脚手架；再把 ACE-RL 的编辑全部丢弃，使每次访问都读空 playbook；最后把 RSI@K 与 pass@K 画到 K=8。Observation：GRPO 进脚手架后仍落后，同等计算下为 0.74 对 0.78（Mastermind）、0.82 对 0.99（MBPP）、0.60 对 0.67（AppWorld）、0.26 对 0.34（MiniSWEBench）。丢掉编辑的控制中，playbook 在 K=2,3 上四基准都有帮助，AppWorld 在 K=2 为 0.105±0.041，MiniSWEBench 在 K=3 为 0.090±0.040；MBPP 因接近天花板，0.987 对 0.977，差异很小。K=8 时 ACE-RL 的 RSI 为 0.81、0.99、0.81、0.40，仍高于 GRPO 的 pass@8（0.78、0.91、0.68、0.30）。从 K=3 到 K=8，AppWorld 的差距还在扩大。例外是 Mastermind：过了训练地平线后，丢掉编辑的曲线从 K=5 起略微领先，K=8 时差 0.016±0.016。Interpretation：MBPP 上的高分不能全部记在 playbook 上，因为演员已经接近满分；AppWorld 与 MiniSWEBench 上，写出并保留经验确实贡献了可测的增益，而且在未见过的更长编辑链上没有整体崩掉。Mastermind 的后期回退则是真实的失败边界：任务局部提示在过多轮次后可能变负，说明交接价值需要过期或再选择，而不能假定“越写越有用”。

最强、最弱与权衡。最强是 MBPP 上 0.987 对 GRPO 进脚手架的 0.82，以及 AppWorld 在更长 K 上持续拉开。最弱是 Mastermind 超过三轮后 playbook 帮助消失，以及 AppWorld 上对独立 GRPO 的配对增益只有 0.042±0.041，统计上更不稳。权衡是：ACE-RL 把部分行动预算用在“为候选 playbook 记账”，种子行动更少；它换来了三个角色的可训练信号，但也依赖 playbook 定期重置，并且每套方法只跑了一个训练种子。

消融、论断与证据

消融与控制。真正起机制验证作用的不是换一套超参，而是三类对照：只训演员（GRPO/PPO）、训交接但信用不按执行价值拆开（Delayed-joint PPO、把改进内化到权重的 ERL）、以及 ACE-RL 自己丢掉编辑。前两类都无法同时在四基准上又高又稳；第三类表明增益不能全部解释为演员变强。

Authors Claim / Experiments Actually Show / What Is Not Yet Proven。作者声称，智能体训练不仅应优化当前回合的行动，还应优化未来回合将继承的、由模型写成的经验。实验实际表明：在四个基准、两种模型尺度、与 GRPO 对齐的 8 条行动预算和同等更新 FLOPs 下，按执行价值训练 ACE 的三个角色，可以得到更高的 RSI@3，并且在 K=8 时整体仍高于独立 pass@8；playbook 在部分基准上有可分离的贡献。尚未被证明的是：同一套记账能否迁移到别的脚手架（不只是 ACE）；多随机种子下领先是否仍然显著；Mastermind 式的后期衰减如何被系统性避免；以及在更大模型和更长工具链上，一次评估 rollout 对 V^ 的估计是否太噪。

Contribution

（问题表述）把经验交接强化学习写成对脚手架结果而非仅对当前行动的优化。（机制）用执行后的 playbook 价值给反思和编辑付酬，并用角色内对比组把它装进 GRPO 预算。（证据）四基准上对只训演员、内化式改写和延迟联合 PPO 的同等计算比较，以及丢掉编辑与超地平线 K 的控制实验。

Limitation

作者在附录讨论了局限。从正文已能看到的限制包括：每个方法只训练一次；V^ 只用一条评估 rollout，方差会进到反思和编辑的奖励里；playbook 每三轮强制重置，既是正则也是对长记忆的回避；MiniSWEBench 绝对成功仍然不高；Mastermind 在超过训练地平线后出现编辑变负。还可以补充：没有开源实现可供核对；计算对齐看的是更新 FLOPs 而非墙钟；脚手架提示与验证器都被固定，因此还不能声称“任何交接格式都可以这样训”。

Research Value

这篇论文把“记忆/技能/playbook 该不该学”从提示工程问题，变成了一个有可验证奖励的强化学习问题。它与“用后见贡献分数给当前轨迹分配步骤信用”刚好咬合：一个管回合内的步骤，一个管回合间的经验书写。对 Agent RL 的启发是，脚手架不该只是测试期的包装，而应进入训练目标；对只做推理 RL 的启发是，若要把反思或总结当作未来上下文，最好按其下游效果而不是按文本相似度来付酬。

Migration / Research Transfer

Original Problem：智能体脚手架会写下经验，但这些文本的写法本身没有被下游任务结果监督，模型因此可能学会“写得像总结”，而不是“写出下一次真能用的提示”。

Transferable Mechanism：为每个候选交接产物跑一次下游尝试，用其任务奖励作为可验证价值，再在同一输入的多个产物之间做组相对更新；演员的评估轨迹同时进入行动组。

New Research Question：若把 ACE 的 playbook 换成工具智能体的技能条目或记忆卡片，用同样的“执行一次再记账”能否提高 AppWorld 或 MiniSWEBench 上超过三轮的成功，并避免 Mastermind 式的后期衰减？

Method Modification：把重置规则改成按 V^ 下降触发的过期，而不是固定 F=3；对 V^ 用两条评估 rollout 降噪；在编辑组中加入一条“空编辑”作为明确的负对照。

Minimum Experiment：在 Qwen3-4B 与 AppWorld 上比较 GRPO 进脚手架、Delayed-joint PPO、ACE-RL 原版、以及带过期规则的 ACE-RL，报告 RSI@3 与 RSI@8，并重复丢掉编辑的控制，必要时再加一个训练种子以检查单次运行是否偶然领先。

Model / Dataset / Baseline / Metric：Qwen3-4B-Instruct；AppWorld 与 MiniSWEBench；基线为同栈 GRPO 与 Delayed-joint PPO；指标为 RSI@K、丢掉编辑后的差值、以及训练奖励是否崩溃。

Expected Contribution / 可证伪假设：若机制成立，带过期的版本应在 K=8 时保持 playbook 差值为正，且不损失 K=3 的成绩。若所有交接方法都与 GRPO 进脚手架难分，则说明该基准上的增益主要来自演员，而不是经验书写。

Compute Cost / Risk / Collision Risk：★★★★☆。4B 级智能体 RL 成本明显高于 1.5B 的纯文本打分实验；风险是单次 V^ 过噪，以及单种子结论不稳。撞题风险中等偏高：CompactionRL、ACE 和各类记忆 RL 同期很多，差异化必须坚持“按执行价值给交接文本付酬”，而不是再做一个新脚手架。

五句话总结

一，ACE-RL 把递归自我改进脚手架里的经验书写，变成可以用下游任务奖励验证的学习对象。二，反思和编辑的分数来自再跑一次行动，而不是来自同一条链上广播的延迟奖励。三，在四个基准、与 GRPO 对齐的行动预算和计算量下，它的 RSI@3 全面最高，Delayed-joint PPO 则出现训练崩溃。四，丢掉编辑的控制表明，AppWorld 与 MiniSWEBench 的一部分增益确实来自 playbook，但 Mastermind 在超过三轮后会失效。五，最值得迁移的是“给交接文本按执行价值记账”，而不是 ACE 这个特定格式。

人话版

长上下文多模态模型常常把一张图早早放进对话，中间隔了很长文本后才被问到图上的细节。图其实还在上下文窗口里，但模型已经读不准。作者把这种失败称为视觉证据漂移：例如 Qwen2.5-VL-7B 的 DocVQA 从短上下文的 93.5 ANLS 掉到插入 32K 文本后的 52.6。他们用三种控制说明，真正起作用的是图像和问题之间的位置关系，而不只是上下文有多长。提出的 Visual Position Re-Anchoring（VPR）是训练免费方法：在问题开始前，把已缓存的视觉 key 的旋转相位，朝一个短上下文参考位置搬回去，注意力计算本身不变，也不额外做前向。默认用一次性的静态补偿。十个检查点、十个视觉任务上，静态 VPR 改进了 100 个模型–任务分数中的 97 个；在固定频率的 Qwen / LLaVA 上，32K 输入加 128 个生成 token 的额外时延只有 0.06%–0.14%。

背景与缺口

多模态应用越来越需要“先看图、再谈很久、最后再问图”。保留图像 token 并不等于还能用到它的细节。作者还做了位置-only 控制：在不增加文本的前提下挪动图像与问题的相对位置，表现就会变，说明这不全是“上下文太长所以难”，而是位置关系本身可操作。已有训练免费干预往往去改注意力权重或反复重算映射，开销可以很大，有的甚至达到数倍墙钟。缺口是：能否只改缓存里视觉 key 的位置相位，就让问题在长上下文里重新“看见”图像，并且把墙钟开销压到可以忽略。

核心洞察

图像还在，并不等于位置编码仍把图像放在问题能够到的相对位置上。把视觉 key 的旋转相位搬回短上下文参考，等于在不删文本、不重训、不改注意力核的前提下，恢复图像与问题的相对距离。补偿过了头（rho>1）会掉点，说明这不是简单的“越靠近问题越好”，而是要回到短上下文那种分离，而不是把图像相位推到问题之后。

方法 Pipeline

输入是已经预填充好的多模态 KV 缓存。在问题段开始前，VPR 只更新视觉 key 的旋转相位，value 与文本 key 不动，随后按标准注意力解码。静态日程把位移一次加满到短上下文参考，连续日程则随当前查询位置跟踪；默认用静态。强度用 rho 控制，主文取 rho=1。方法不提取注意力图，也不增加模型前向，只做缓存上的相位改写。对使用动态 NTK 的 InternVL3-2B，输入超过训练长度会改变频率，静态与连续都会反复再相位，开销明显上升，这是实现上必须分开报告的一点。

A TRACE: Trajectory Synchronization for Training-Free Resolution Extension in Video Generation

  • 作者: Libo Zhu, Fan Li, Zhixin Wang, Binglu Wang, Weisheng Dong, Yulun Zhang（上海交通大学、华为、西北工业大学、西安电子科技大学）

人话版

很多视频生成骨干仍锁在较低分辨率，把它们重新训练到 1080p 或 4K 很贵。训练免费的做法通常是：先在低分辨率走完去噪，再把结果上采样后继续，或者直接在高分辨率上硬跑。前者对不齐对应噪声水平的轨迹，后者又慢又容易结构漂。TRACE 的想法是在早期去噪阶段同步低、高分辨率两条轨迹：高分辨率的更新由低分辨率预测和当前高分辨率状态算出来，这一阶段甚至不必做高分辨率模型推理；随后再用局部窗口注意力补细节，并用低分辨率布局去检查、修正多出来的主体。在冻结的 Wan2.1-1.3B、Wan2.2-A14B 与 Bernini-R-1.3B 上，相对最强训练免费基线 FreeSwim，端到端分别快 2.74×、2.92×、2.02×，Q-Align 等质量指标同时更高。

背景与缺口

FreeSwim 等滑动窗口方法已经能做训练免费的分辨率扩展，但仍把低分辨率终点上采样再加噪，得到的高分辨率状态并不对应低分辨率轨迹的同一噪声阶段，细结构和语义容易漂，而且高分辨率全程推理很慢。缺口是：怎样在不微调骨干的前提下，既借用低分辨率已经走对的布局，又保留高分辨率自己长出新细节的自由，并且真正减少墙钟，而不是只谈理论 FLOPs。

核心洞察

高分辨率生成不需要从头自己走完一条轨迹。早期可以让低分辨率当“布局老师”，把对应噪声水平的预测搬到高分辨率状态上；后期再把自由度交还给高分辨率局部注意力。多出来的主体则用低分辨率布局做局部校正，并同步改写求解器缓存，以免 UniPC 一类多步求解器带着旧状态继续走。

方法 Pipeline

先在低分辨率（例如 Wan2.1 的 832×480）按共享噪声日程采样，缓存轨迹。高分辨率早期步用跨尺度轨迹同步（CSTS）：用校准过的上采样与噪声匹配参考，由低分辨率预测构造高分辨率更新，此阶段不做高分辨率骨干推理。进入模型步之后，在共享的高分辨率潜空间上用局部窗口注意力补细节。局部细化可能造出额外主体，于是轨迹引导的结构校正（TGSC）用交叉注意力定位提示中的实体，对照低分辨率布局生成修正掩膜，只改被怀疑重复的区域及其求解器历史。对更高分辨率，再把已经完成的 High 当作中间层，复用 Low 的缓存轨迹继续扩展。全程骨干冻结，无需按视频调参。

  • 作者: Xiaoliang Fu, Jiaye Lin, Yangyi Fang, Cong Qin, Binbin Zheng, Chaowen Hu, Zekai Shao（复旦、美团、清华、北大、中科大；通讯 Jiaye Lin）

人话版

RLVR 里人们常用 token 熵或序列熵来维持探索，但这些指标分不清“多种做对的方法”和“多种做错的胡话”。高熵看上去很多样，实际上可能只是在无效轨迹上发散，作者称之为多样性幻觉。他们定义有效熵：只在验证器判定正确的轨迹上计算 −pilogpi，错误轨迹贡献为 0。VEPO 把这项以系数 beta 加进 GRPO，并不另建价值网络。梯度分析表明，对正确且序列概率小于 e−1 的轨迹，最小化有效熵损失会提高这条轨迹的概率，从而把质量推向“还没被充分探索的正确解”；错误轨迹的权重为零，不会因为“写得更乱”而获得探索奖励。在 DeepSeek-R1-Distill-Qwen 的 1.5B 与 7B 上，六个数学基准的平均 Avg@32 分别从 GRPO 的 48.4 和 58.9 升到 50.6 和 61.1；在两边都至少写出八条正确轨迹的 441 道 MATH500 题上，VEPO 的每题不同策略簇从 2.31 增加到 2.68。

背景、缺口与洞察

GRPO 已经能用组内统计在没有评论家的情况下做 RLVR，但探索信号仍然沿用旧的熵。Token 熵只看下一步的局部不确定，序列熵又对全部轨迹一视同仁，而正确轨迹在组合上远比错误轨迹稀疏。继续最大化这些熵，等于把预算花在无效区域。有效熵把测量域改成“被验证器承认的子空间”：正确且概率偏低的轨迹会被吸引，错误轨迹得不到熵带来的额外推力。对自回归 LLM，序列概率几乎总是远小于 e−1，因此理论上的符号翻转在实践中可以忽略，VEPO 在常用体制下表现为对“尚未被充分探索的正确解”做吸引。

有效熵定义为 Hmathrmeff(pitheta)=−sumor(omidq)pitheta(omidq)logpitheta(omidq)，或等价的期望形式 mathbbEosimpitheta[−r(omidq)logpitheta(omidq)]。总目标为

JmathrmVEPO(theta)=JmathrmGRPO(theta)+beta,Hmathrmeff(pitheta)

序列级权重 Wi=r(oimidq)bigl(1+logpitheta(oimidq)bigr) 从计算图断开后，乘到各 token 的对数概率梯度上。默认 beta=10−4。训练用 DAPO-Math-17K，组大小 G=8，全局 batch 512，裁剪 epsilon=0.2。在线奖励用 math_verify，最终评估改用更严的 prime_math，以降低奖励黑客带来的虚高。这个实现故意保持最小：没有过程奖励模型，也没有额外的熵目标网络。作者提醒，序列对数概率按原始求和、不做长度归一化，换一种归一化就不再是同一个泛函；把 Wi 广播到所有 token，也不能识别哪些推理步骤真正重要。若复用旧策略的 rollout，得到的是局部替代而非无偏的当前策略估计。

设置。骨干为 DeepSeek-R1-Distill-Qwen 1.5B 与 7B。基准为 AIME24/25、AMC23、MATH500、Minerva、OlympiadBench，报告 Avg@32 与 Pass@32。基线包括 GRPO、Entropy-Reg、AEPO、Entropy-Adv、GTPO、Adv-Reweighting。

RQ1：有效熵能否在不牺牲准确率的前提下提高探索质量？Table 1 中，1.5B 的平均 Avg@32 / Pass@32 为 50.6 / 71.6，超过 GRPO 的 48.4 / 70.1 和 AEPO 的 48.5 / 70.7；7B 为 61.1 / 78.5，超过 GRPO 的 58.9 / 77.2 和 AEPO 的 59.3 / 78.1。单点并非全赢：1.5B 的 AIME25 Avg@32 为 27.8，略低于 Entropy-Reg 的 28.4 和 AEPO 的 28.1，但聚合与多数主基准仍更高。三个训练种子上，六基准 Avg@32 增益在 1.5B 为 +2.1、+2.4、+2.1 个百分点，在 7B 为 +2.3、+2.4、+1.9，方向一致。

RQ2：更高的 Avg@32 是不是只因为更常做对，而不是真的更多策略？Table 2 把比较限制在 441 道两边都能拿出至少八条正确轨迹的 MATH500-7B 题，每题各取恰好八条正确轨迹再聚类。VEPO 的每题不同簇为 2.68，对 GRPO 的 2.31（+0.37，16.0%，自助区间 [0.24, 0.50]）；Hill-1 有效众数为 2.24 对 1.97；最大簇占比从 0.68 降到 0.61。因为正确条数被对齐，这些差异不能用“做得对所以看起来更散”来解释。作者也写明：这只覆盖常被解出且答案被验证的题，并不证明每一步推理都正确。超参上，β∈{3×10−5,10−4,10−3,3×10−3,10−2} 的扫描显示，过大的 β 会把熵维持得很高、收敛变慢，默认 10−4 是在有效子空间探索与收敛之间的折中。这些结果合在一起说明：VEPO 的贡献主要是改了探索发生的区域，而不是堆了一个更复杂的优化器。

B HyperSkill：冻结骨干，用超图技能库演化替代参数空间里的 GRPO（Agent · Skill）

B HyperSkill: Training-Free Omnimodal GRPO via Hypergraph-Indexed Skill-Library Evolution

  • 作者: Haoran Luo, Shangkai Lin, Jinyang Wu, Xinliang Zhou, Luu Anh Tuan（NTU、清华、Stanford、VinUniversity）
  • ID: arXiv:2611.15178 · PDF（v1，cs.AI，提交 2026-11-11；论文写 Accepted by NeurIPS 2026）
  • 全文来源: 已读 PDF 第 3–4 节与主结果叙述（Table 2 在正文中被引用，11 数据集平均 42.0 对最强基线 29.0）

人话版

强化学习能打磨推理，但更新参数昂贵、会遗忘，也不容易审计。训练免费的技能库避开了梯度，却常常按整段轨迹的相关性收入条目，结构也是扁平的。HyperSkill 把骨干冻结，把“优势”记在超图技能库的节点与超边上：训练阶段用反事实检查决定一条技能该不该进库，并从失败里学一条协议技能；测试时由门控检索按优势排序注入技能；执行协议再迫使冻结模型给出答案。作者在 11 个文本、视觉和全模态基准上报告，HyperSkill 全部取得最高或并列，平均 token 级 F1 从最强基线 XSkill 的 29.0 升到 42.0（+13.0），相对零样本 27.4 为 +14.6。

背景与方法

评测集合名为 HyperSkill-Bench，含 AIME2024/2025、WebWalkerQA、FVQA、InfoSeek、DocBench、MMLongBench-Doc、OmniVideoBench、WorldSense 等 11 个数据集，共 636 道测试题，指标是带答案形状与 CJK 分词的 token 级 F1。所有方法共享冻结的 gemini-2.5-flash-lite 与同一工具栈，每个数据集用 128 道训练题构建库。三个组件分别是：C1 训练时蒸馏并做反事实准入，C2 超图演化与带阈值的门控检索，C3 执行协议（工具轮次、投票与输出约束）。基线包括 TrainingFreeGRPO、EvoSkill、SkillCraft、AutoSkill、Memento-Skills 与 XSkill，都按各自论文流程在同一 128 题上重建库。

主要发现与数字

六个训练免费基线的 11 数据集平均只在 23.4–29.0 之间，而且每个都会在至少三个数据集上低于零样本；HyperSkill 则在每一行都不低于零样本。相对次优列的优势在 AIME2024（+26.7）、AIME2025（+20.0）和 OmniVideoBench（+14.3）上最大，另有五个数据集的配对自助区间包含 0，作者把这五个保守计为平局。消融把平均从 42.0 降到 39.5（去掉 C1）、37.8（去掉 C2）和 31.6（去掉 C3），说明执行协议的贡献最大，但三个组件都有效。需要记住：骨干是闭源 API，库的超参按数据集在留出训练题上选定后再全量重训，因此比较的是“带配置选择的训练免费系统”，不是完全零调整的即插即用。

贡献、局限与用途

贡献是把 GRPO 的优势想法搬到可审计的技能库，并用反事实准入和超图组合来替代扁平记忆。局限包括：单次评估、测试集对 AIME 只有 30 题、F1 不是 Exact Match、依赖专有模型，以及部分数据集优势在统计上并不显著。它与当天的 ACE-RL、决策模型教师可以对照着读：一个把经验写进冻结库，一个把经验写进可训练 playbook，一个把经验写成步骤分数。潜在用途是在不能微调骨干的多模态代理里，先用小规模题目蒸馏可检查的技能，再看门控是否比相关度检索更稳。Why It Matters：它提醒我们，“训练免费 GRPO”如果没有反事实检查，可能只是换了一个会写笔记的零样本。

B 重新审视“RL 会泛化、SFT 只会记”：关键其实是 SFT 数据从哪来、有多少（RL）

B Rethinking “RL Generalizes, SFT Memorizes”: The Role of SFT Data

  • 作者: Yunlong Hou, Fengzhuo Zhang, Yuan Cheng, Jiachun Pan, Xingyao Li, Zhuoran Yang（NUS、Yale、Cisco Foundation AI）
  • ID: arXiv:2611.14912 · PDF（v1，cs.LG，提交 2026-11-11；论文写 Accepted to NeurIPS 2026）
  • 全文来源: 已读 PDF Table 1、第 3 节与附录 Table 5–6

人话版

许多论文把“RL 更会泛化、SFT 只会记忆”写成近乎定律。本文用 Qwen2.5 / Qwen3 系列追问：这个结论是不是在 SFT 没有被给予与 RL 相当的数据资源时得出的。他们发现数据来源很关键：完全用更强模型生成的正确答案，并不总比用已经 RL 调过的同系列模型做拒绝采样更好；把两种来源按 70% / 30% 混合（Mix-2）时，SFT 在数学和更广的推理任务上都更稳。进一步把 SFT 的正确 rollout 数、乃至总 rollout 预算（含错误轨迹）与 RL 对齐后，SFT 可以达到与 RL 相当甚至更好的泛化。作者把原因部分归于更大的数据覆盖了长尾解题方法。

背景与方法

RL 在 DAPO 上训练，每题 8 条 rollout；对照 SFT 若只保留每题一条正确轨迹，看到的数据量天然少 8 倍。数据来源有两支：Qwen3-14B 拒绝采样得到 15,607 条，RL 调优模型拒绝采样得到 14,512 条，并按比例做成 Mix-k。规模实验再依次匹配“可解题目数”（约 1 万对）、“每题正确 rollout 数”（约 3.9 万）和“总 rollout 数”（约 13.8 万，含约 9.8 万条最终错误的轨迹）。方法标注由 Qwen3-32B 完成，共整理出 138 种解题方法。

主要发现

Table 1 在 Qwen2.5-7B 上给出具体分数：基座平均数学 42.7、一般推理 33.8；RL 后为 50.9 与 43.8。SFT 用纯 RL-tuned 或纯 Qwen3-14B 数据，数学已经接近甚至个别超过 RL（例如 SFT w/ Mix-2 的 MATH500 为 76.2，对 RL 的 74.8；AIME24 Avg@32 为 13.4，对 RL 的 14.2），但一般推理仍落后，直到 Mix-2（70% RL-tuned + 30% 强模型数据）把一般推理平均做到这组 SFT 里最好。附录 Table 5 里一般推理总平均：基座 33.8±0.41，RL 43.8±0.43，SFT w/ RL-tuned 在更大设置下可以到 43.7±0.41，部分混合超过 RL（正文 Figure 9 的 90%/10% 混合在 rollout 对齐后优于 RL）。更关键的观察是：匹配正确 rollout 已能大幅抬升 SFT 泛化，再把错误轨迹也纳入、对齐总预算，SFT 可以不再明显弱于 RL。尾部方法覆盖随 k 增加而上升，并且在 MMLU-Pro 等评测里被更频繁地用到。

贡献、局限与意义

贡献是把一句流行对比，改写成可检验的数据来源与数据规模问题，并提供理论侧的浅层 Transformer 分析作为支持。局限是：主表仍以 Qwen 家族为主；部分一般推理集（如 MMLU-Pro）波动很大，Mix-3 之后甚至崩到个位数；“方法”依赖另一个 LLM 标注；对齐的是 rollout 条数与梯度计算量，并不自动等于墙钟或采样开销完全相同。它提醒做 RL for LLM 的人：在宣称 RL 的泛化优势前，先问 SFT 是否已经看到了同样多、同样多样的正确与近正确轨迹。潜在用途是用 RL 模型当数据发生器，再以更便宜的 SFT 把长尾方法蒸馏回去。Why It Matters：若这一观察站得住，很多“必须上 RL 才能泛化”的实验结论需要重做对照，先把 SFT 的 rollout 预算补齐。

B 当世界里错误还在，把智能体历史“清理干净”反而更糟（Agent Memory）

B Cleaning an Agent's History Hurts When the World Still Holds the Error

  • 作者: Egor Pakhomov, Anurag Koul, Hongjun Liu, Bo Pang, Shafiq Joty, Erik Nijkamp（Salesforce AI Research）
  • ID: arXiv:2611.14654 · PDF（v1，cs.AI，提交 2026-11-10，周五 11-13 公告）
  • 全文来源: 已读 PDF 摘要、引言与第 5 节主要结果

人话版

工具智能体会在历史上留下自己的错误，而压缩、修复或交接历史的系统，往往在世界状态并未被撤销的情况下，把记录改得看起来已经做对。先前工作很难分清：是“让模型看见正确答案”在起作用，还是“告诉它这一步已经完成”在起作用。本文把智能体冻在真实的中途状态上，只改历史或只改世界，再让接收模型接着做。结论很尖锐：同样是正确的值，写成一条诚实的旁注会帮助恢复，写成“自己已经成功完成的动作”却会伤害恢复；在世界里效果还不在时，一张成功回执更会把整任务成功率打下去。

背景与方法

两条受控设计。第一条在 AgentCE-Bench 的 319 个冻结状态上，智能体已经把一个错误值写入持久状态；世界保持不变，把同一经过核验的正确值用两种自然编辑写进历史：一条是保留原错误、在旁边附加真实说明；另一条是改写成智能体自己已完成的动作。第二条在 AppWorld 上，冻结一次数据库写入之后，独立变换回执（成功或失败）与世界（写入前或写入后），使两种回执在各自世界里恰好一种为真。接收模型包括 gpt-5.5 与 claude-sonnet-5。

主要发现

在 AgentCE-Bench 上，相对于匹配过角色、位置、轮次和长度的中性旁注，真实旁注把剩余目标的恢复率从 51% 提高到 66%；把同一正确值写成已完成动作，则把恢复率从无编辑历史的 50% 降到 44%。两种编辑披露的值相同，但效果相差 22 个点，并且在两个接收模型上都为正。这说明“答案出现在历史上”本身不能预测后果，复制可见值的简单假说不成立。在 AppWorld 上，当写入效果还不在世界里时，成功回执把整任务成功从 45% 降到 28%；一旦效果已经在，同一张成功回执又把成功从 38% 升到 49%。两种效应合计相差 27 个点，在多数接收模型与显著性阈值下保持同向。历史编辑的效果因此取决于它描述的世界是否仍然成立。

贡献、局限与用途

贡献是一次把“记录怎么写”和“世界里还剩什么”拆开的因果式评测，直接打到记忆压缩、错误修复和经验交接的设计假设。局限是：状态冻结与编辑都依赖可重置环境；接收模型是专有 API；恢复率与整任务成功是不同度量，不宜直接横比。它与 ACE-RL 形成对照：交接文本若把未完成的步骤写成已经完成，下游尝试可能比不写更糟；也与“清理历史”类记忆编辑形成碰撞。潜在用途是给 playbook 或记忆写入加一条约束：当世界尚未改变时，只允许旁注式的正确信息，不允许伪造成功。

Idea Mining

Idea 1：查询到达时再锚定历史视频 KV

Inspiration：VPR 证明单图+长文本里，视觉证据失败在很大程度上是位置关系问题；流式与长视频智能体则会不断累积历史帧，查询往往更晚才到。

Gap：VPR 没有视频基准，现有视频 token 剪枝（如昨日 DiFiT）走的是删 token 而不是改位置。流式场景里历史帧的 RoPE 会随着后续帧和时间文本越来越远，即使缓存还在，查询也可能“看不见”早先的证据。

Hypothesis：当新查询到达时，把历史帧的视觉 key 静态再锚定到一个短上下文参考，可以在不剪帧的情况下恢复证据访问，墙钟开销接近 VPR 在固定频率模型上的 0.1% 量级，准确率不低于轻量均匀抽帧。

Proposed Method：在 Qwen2.5-VL 或同类 M-RoPE 模型上，维护按帧分段的视觉 KV；查询到来时对历史视觉 key 做 ρ=1 的静态相位搬移，文本 key 与 value 不动；对比 Vanilla、均匀丢帧、以及训练免费剪枝。

Idea 2：带“禁止伪造成功”约束的后见教师交接

Inspiration：ACE-RL 按下游执行给 playbook 记账；17167 说明问对问题才有步骤信号；14654 说明成功回执在世界未改变时会伤害恢复。

Hypothesis：在 ACE-RL 的编辑奖励上增加一项可检查约束——若环境状态未变，包含“已完成/已成功”表述的编辑强制为 0 或负，同时用 Progress 问题给再尝试的步骤打分——可以减轻 Mastermind 在 K>3 后的 playbook 负贡献，并保持 AppWorld 上的 RSI@3。

Idea 3：工具轨迹上的有效熵探索

Inspiration：VEPO 只在数学 RLVR 上验证了有效熵；智能体同样有可验证结局（测试、任务成功），但常用熵仍然鼓励无效的工具呼叫序列。

Gap：工具轨迹比数学解更长、也更容易出现“看起来多样但全部失败”的探索。

Hypothesis：把 Heff 加到工具使用 GRPO 上，在通过验证器的轨迹子空间里吸引小概率成功计划，将提高不同成功计划数，并在同等 rollout 预算下提高 pass@3。
