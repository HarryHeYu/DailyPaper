人话版：这篇论文到底干了什么？

多智能体 LLM 系统（这里是 Solver 与 Verifier 轮流发言解数学题）做强化学习时，主流做法只拿最终对错当奖励，再按智能体拆成 agent-wise 的 GRPO 优势。这样每个 token 拿到的信号都是同一个标量，Verifier 在第二轮指出“你第三步的系数算错了”这种最有价值的话，只被压缩成一个分数甚至被丢掉。OPSD4MAS 的做法是：把某一轮回答之后若干轮里出现的“更正、警告、被验证的结论、策略”抽成原子事实，用两道过滤挑出真正有用的事实，把它们当作只在训练时可见的特权上下文喂给同一个策略，得到一个“知道未来的老师”；老师与普通上下文下的学生在学生自己生成的每个 token 上的对数概率差，就是逐 token 的信用。再把这一项与 GRPO 的结局信号线性退火地合在一起训练。在 Qwen3-4B、六个数学基准上，FW4 版本相对 GRPO 把平均 pass@1 提高 8.87 个百分点、平均 pass@4 提高 9.54 个百分点；AIME24 与 AIME25 的 pass@4 最多提高 20.00 个百分点。它最值得记住的发现不是“有增益”，而是：未经处理的未来对话当特权上下文，训练结果反而比纯 GRPO 差得多（平均 pass@1 33.24 对 49.63）。

背景与缺口

LLM 多智能体系统通常由预先定义的工作流、图或自主决策驱动，多个角色通过对话协作。把 RL 搬到这种系统上，MAGRPO、M-GRPO、MARTI 一类方法把任务结局、阶段性评价或对智能体互动的判断都变成标量奖励；DrMAS 进一步按“查询加智能体”分组，对每个智能体的响应奖励做各自的均值方差归一化，得到 agent-wise 优势。MAPoRL 与 CoMAS 则引入了讨论中的信号，比如答案正确性的变化或基于互动的评判，但最终仍然落到一个标量上。

这类做法有两个具体的毛病。第一，粒度太粗：一轮回答里有四百个 token，其中一个公式写错了，后面的 Verifier 明确指出了错误并给出修正，但标量优势只能告诉优化器“整段响应要加强还是要削弱”，无法区分哪些 token 被这条修正支持、哪些被它反驳。第二，沟通内容被浪费：未来的发言是解释错误、验证论断、给出修复的天然监督，却被压成一个分数。论文的反例很具体：在图 5(c) 的矩形题里，Solver 在第五轮把 13×163=2119 纠正为 2123=11×193，这条修正能让第四轮 Verifier 的推导直接受益，但标量奖励完全看不到它。

反过来，直接把未来对话原样塞进老师上下文也不行，因为对话里混着错误、无关闲聊和过程性描述。这正是本文真正要解决的缺口：沟通里有信号，但需要被抽取、被筛选，才能当作可靠的特权信息。

核心洞察

作者的核心判断可以压成一句话：未来沟通是特权上下文，而不是奖励。把它放进老师侧，老师与学生是同一个策略的两种视图，二者在学生采样 token 上的对数概率差天然就是 token 级的信用，既不需要额外的老师 logits，也不需要把沟通压成分数；推理时学生用的是普通上下文，既没有未来信息也不调用外部模型。真正的难点转移到了“给老师看什么”。论文用两层过滤回答它：先看事实与同一问题其它轨迹的结局是否关联（粗过滤），再看去掉这条事实后目标 token 的概率是否朝着该响应的 GRPO 优势所指的方向移动（细过滤）。一个反直觉的结论由此而来：事实影响很强不等于事实有用，只有“影响方向与结局一致”的事实才该保留；不加筛选时，拥有更多信息的老师反而把学生带坏。

方法深挖

设定与变量。每个角色 r 有参数 θr，全体参数为 Θ。对问题 q 采样第 j 条轨迹 τj=(yj,1,…,yj,Tj)，其中第 i 个响应由角色 r(i) 生成，token t 的上下文是 (q,yj,<i,yj,i,<t)。MAS 的 RL 要更新所有参与的智能体，而不只是最终回答的那个。结局奖励 R(τ) 只在轨迹结束时给出，目标是 maxΘ𝔼q,τ~MASΘ(q)[R(τ)]。基线 DrMAS 把同一问题下同一智能体的所有响应放在一起做归一化，得到响应级优势，并广播到该响应的每个有效 token。

第一步：事实抽取。对目标响应 yi，外部模型读取其后窗口 yi+1,…,ymin(i+W,T) 里的发言，抽取原子事实，类型分为更正、警告、被验证的论断、策略四类，每条事实保留来源与目标身份。最后一个响应没有未来，因此只能当来源、不能当目标。抽取提示要求把评语当作“可能出错的证据”，让模型自己重新验证被评价的响应，并拒绝“答案是对的”或“要严谨”这类空话。附录给出的抽取与关系标注提示是逐字模板，两者都只输出严格的 JSON。

第二步：关联过滤（粗）。另一个外部调用把每条事实相对同一问题的每条轨迹标记为 rj(f)∈{+1,−1,0}，分别是被遵循、被违反、无关。同时，每条轨迹的整体优势 A(τj)=(R(τj)−μq)/(σq+ϵ) 在问题组内只计一次，不按重复回合加权。关联分为 assoc(f)=∑jA(τj)rj(f)/(∑j|A(τj)||rj(f)|+ϵ)：在高优势轨迹里被遵循、或在低优势轨迹里被违反，都加分。这一步只给事实排序，取前若干条作为候选集 Ci，没有正分阈值。

第三步：留一过滤（细）。对每条候选事实 f，比较带上完整候选集与去掉 f 之后目标响应各 token 的对数概率：δf,i,tLOO=gi,t(Ci)−gi,t(Ci⧵{f})，再乘上该目标响应的 DrMAS 优势 Ari 得到 zf,i,t。令 m+=𝔼t[max(z,0)]、m−=𝔼t[max(−z,0)]，定义影响量 E(f)=𝔼t[δ2]、方向精度 P(f)=m+/(m++m−+ϵ)、净对齐 N(f)=m+−λcm−。事实要同时满足 E≥Emin、P≥Pmin、N>Nmin 才保留，再按净对齐、精度、影响量排序截断到 top-K。这一步使用的是更新前缓存的策略得分，不需要梯度。

第四步：事实条件化的 OPSD 信用。对保留下来的集合 Fi，把它们以 “[Privileged Future Lessons]” 加编号列表的形式追加到最后一条用户消息，套用聊天模板，得到老师视图。对学生采样的每个 token 计算 δi,t=logπθr(yi,t∣q,y<i,yi,<t,Fi)−logπθr(yi,t∣q,y<i,yi,<t)，系数取 Ai,tOPSD=sg(λOδi,t)，其中 sg 表示停止梯度；没有保留事实时系数为零。角色内的 OPSD 损失是 ℒOPSD(r)=−1Zr∑i∈Ir∑tmi,tAi,tOPSDlogπθr(yi,t∣·)，梯度只流经普通上下文那一路对数概率；它既不使用重要性比率也不裁剪，按有效 token 求平均。

第五步：线性退火的联合目标。角色 r 的总损失是 ℒ(r)(s)=ℒGRPO(r)+wO(s)ℒOPSD(r)，其中 wO(s)=max(w0−sρ,wmin) 随训练步数 s 线性下降。GRPO 部分沿用 DrMAS 的裁剪替代目标，按每个响应的掩码均值再对非空响应取平均；OPSD 部分按角色同质的小批次对有效 token 平均。两者的归约方式刻意保持不同。为满足上下文预算，序列化器先从末尾开始删去事实，必要时再删较早的未保护历史消息，但始终保留首条消息、首条用户消息与最新消息；完整候选集与留一提示分别序列化，只有保留的历史与其它事实一致时，二者之差才隔离出单条事实。

反直觉的设计。其一，留一过滤用的是 GRPO 实际使用的 agent-wise 优势而不是关联过滤里的轨迹优势，二者的归一化口径不同；论文强调这是为了让“事实是否有用”与“优化器此刻要把该响应往哪推”同向。其二，OPSD 系数不与优势相乘，而是完全由对数概率差给出，因此退火后期只由 GRPO 控制，避免沟通里未经验证的信息长期支配更新。其三，教师没有独立的外部 logits，而是同一个参数、不同上下文，这意味着老师的“聪明”完全来自事实，没有来自更大模型的分布泄漏，但也意味着事实的质量全部依赖外部抽取器。

论文共 9 种设置：基座模型、三种冻结权重的 MAS（Solver–Verifier 循环、AFlow、GPTSwarm）、三种标量奖励 RL（DrMAS-GRPO、DrMAS-DAPO、CoMAS），以及 OPSD4MAS 的 FW2 与 FW4。按六个数据集等权平均 pass@1，最强基线是 DrMAS-DAPO（约 58.19%），我用 Table 1 逐列重算；GRPO 约 55.45%，CoMAS 约 55.86%。FW4 约 64.33%，所以对 DAPO 的差距是 6.14 个百分点，对 GRPO 是 8.87 个百分点，与论文正文一致。需要强调的是，所有基线分数都是作者在本研究里重新评测的，而不是从原论文照抄；AFlow 的搜索优化器用的是 Qwen3-235B-A22B 系列服务，执行器仍是 Qwen3-4B，因此“冻结权重”一组在优化器侧拿到了更大的模型。

实验设置与研究问题

设置。所有可训练智能体从 Qwen3-4B 初始化，全部使用非思考模式，在 DAPO-MATH-17k 上训练；测试集为 AMC23、AIME24、AIME25、MATH-500、OlympiadBench 英文纯文本数学子集与 Minerva，基座评测题量分别是 83、30、30、500、675、272。项目可用 24 张 80GB A100（附录说明这描述的是可用资源，而非每次运行的分配）。四个研究问题分别是：RQ1 相对标量奖励 RL 与冻结 MAS 是否更好；RQ2 未来窗口从 2 到 4 是否有益；RQ3 事实抽取、关联过滤、留一过滤各自是否必要；RQ4 被选中的事实到底有没有下游效用。

RQ1：Setup → Observation → Interpretation。Table 1 中 FW4 在六个数据集上全部排名第一（pass@1 与 pass@4 的均值口径）。AIME24 pass@4 达到 83.33%，对 DrMAS-GRPO 的 63.33% 提高 20.00 个百分点；AIME25 pass@4 是 73.33% 对 53.33%，同样 +20.00。解释上要小心：这两个数据集各只有 30 道题，一道题等于 3.33 个百分点，所以 +20.00 对应的是多解出 6 道题，而不是平滑的分布移动。相对 CoMAS，FW4 的均值 pass@1 与 pass@4 差距分别是 8.46 与 11.13 个百分点。绝对增益最稳的是 AMC23：pass@1 82.23% 对 DAPO 78.01%（+4.22）与 GRPO 68.07%（+14.16）。增益最薄的是 MATH-500：pass@1 91.50% 对 GRPO 90.95%，只多 0.55 个百分点，说明在基座已经很强的简单题上，沟通信用几乎没有可挖的空间。FW2 则是一个诚实的反例：它在 MATH-500 pass@1 上是 89.00%，低于 GRPO 的 90.95%，在 AMC23 pass@1 上是 74.10%，也低于 DAPO 的 78.01%。

RQ2：窗口大小。FW2 的均值 pass@1 与 DAPO 接近，但均值 pass@4 比 DAPO 高 4.83 个百分点；窗口加到四个响应后，均值 pass@1 与 pass@4 再分别提高 6.06 与 3.65 个百分点。解释是：更长的未来窗口能让更多“后来才暴露”的错误回溯到更早的响应上，这与“沟通里有延迟纠错”的动机一致，但论文没有给出更大窗口（如 6 或 8）的曲线，因此不能说收益会继续线性增长。

RQ3：训练消融（见下表）。以 AMC23、AIME24、AIME25 等权均值计，无 OPSD 即纯 GRPO 是 49.63 / 66.60，未处理的原始未来沟通是 33.24 / 50.46，只抽事实不过滤是 42.57 / 63.97，加关联过滤是 42.99 / 65.18，完整两层过滤是 64.91 / 82.74。每一个不完整变体都低于纯 GRPO，只有完整版超过它，分别高 15.28 与 16.15 个百分点。解释：特权上下文不是“多多益善”，质量不足时会把学生拉向未经验证的内容；留一过滤贡献最大（pass@1 +21.92），关联过滤只加 0.42。

RQ4：事实注入诊断。固定四个 FW4 检查点（100/110/120/130）的历史，只重新生成最终的 Solver 回答。放松阈值的 Relaxed 档相对不注入分别提高 6.13、4.27、1.98、2.10 个百分点；在每个检查点上，Relaxed 都优于更严的 Strict 与完全不设留一门的 All。配对的“打乱事实”对照（用其它问题的事实、保持可见数量与大致长度）显示匹配事实比打乱事实高 2.86 至 8.12 个百分点。解释是：收益来自内容匹配，而不是多放了文字，并且中等过滤强度最好。需要注意，这个诊断只验证事实在固定权重下对最终 Solver 回答有帮助，并不等同于训练收益本身，二者之间还隔着一次完整的 OPSD 训练。

消融、论断与证据

消融：三步依次加入的收益是：抽取相对原始沟通 +9.33（pass@1），关联过滤 +0.42，留一过滤 +21.92，三步里留一过滤是主角。关联过滤几乎不贡献，意味着“与结局相关的事实”和“真正改变目标 token 概率的事实”几乎是两回事，论文没有消融去掉关联过滤只留留一过滤的情形，所以关联过滤是否必要其实没有被直接检验。论断 vs 证据：作者称“把沟通转成 token 级信用优于标量奖励”。证据显示在 Qwen3-4B、数学、非思考模式下 FW4 确实超过三个训练基线，且消融与注入诊断相互印证。尚未证明的是：（一）提升来自“沟通”本身，还是来自外部强模型在抽取阶段重新验证并写出了正确修正，因为抽取提示明确要求外部模型自己核对解法，这相当于把一个更强的验证器的知识注入训练；论文缺少“用同一外部模型直接给出提示而不经过未来沟通”的对照。（二）跨任务与跨模型规模的泛化，作者自己在局限中承认只测了数学与 4B。（三）统计可靠性：四个注入检查点来自同一次训练而非独立种子，作者明确说明比较是描述性的，没有显著性检验，AIME 又只有 30 道题。（四）论文伦理一节也承认，过滤能否降低多智能体间错误反馈的放大并未被证明。

Contribution

（机制）把“未来沟通”重新定位为特权上下文，用同一策略的两种视图产生 token 级信用，并与 GRPO 的结局信号线性退火联合。（方法）FEHF 管线：原子事实抽取、基于结局关联的粗过滤、基于留一与方向精度的细过滤，提供了一个可复用的“特权信息质量闸门”。（经验发现）未处理的特权信息低于纯 GRPO 基线；中等强度过滤最好；匹配事实优于打乱事实。（资源）论文给出代码链接，并在附录公开了抽取与关系标注的完整提示模板，便于复现与替换抽取器。

Limitation

作者承认：只评测数学与 Qwen3-4B；抽取与关系标注依赖外部模型，特权上下文的质量受该模型、阈值、上下文预算与退火设置影响；注入诊断使用固定权重与冻结历史，且四个检查点同属一次训练。额外的局限：第一，没有给出外部抽取调用的成本与延迟，每个目标响应都要经历抽取、关系标注和多次带事实的前向打分，这对训练吞吐的影响论文没有量化；第二，AIME24 与 AIME25 的样本量使 pass@4 的 +20.00 对应约 6 道题，缺少置信区间；第三，Solver–Verifier 只有两个角色，是否能推广到角色更多、通信受限的拓扑未知；第四，冻结权重基线里 AFlow 的搜索优化器规模远大于执行器，比较并不对称。

Research Value

对 RL、Agent 与多智能体三条主线，这篇论文处在“轨迹 → 奖励 → 信用分配 → 记忆或技能更新”链条上一个少有人动的环节：不是改优势估计，而是改信用的来源，把“别的智能体说过的话”变成监督。它与昨天 OMA 讨论的外层记账互补：OMA 管每条轨迹的总权重，这里管轨迹内部每个 token 的方向。更有价值的是它对“特权信息需要质检”的实证——原始沟通反而负收益，这个结论可以直接迁移到 Agent 记忆（哪些经验该写入）、技能库准入（哪些轨迹片段该固化）与多智能体信息流审计。它也和今天另一篇 OPSD 审计论文形成张力，见 Collision 一节。

Migration / Research Transfer

Original Problem：多智能体对话里的纠错信息被标量奖励压缩。Transferable Mechanism：“方向一致的留一影响”——一条上下文信息是否有用，看它让目标 token 概率移动的方向是否与该样本的结局优势同号。New Research Question：把这一闸门从多智能体对话搬到单智能体的长程记忆写入：一条被写入记忆的经验，是否应该按“有它与没有它时后续动作 token 概率的变化”乘以最终结局优势来准入或淘汰？Method Modification：把未来窗口换成“后续 H 步轨迹中的失败信号与修复信号”，事实换成记忆条目，留一换成“检索时移除该条目”，信用写回为记忆的效用分数，同时仍保留结局 RL。Minimum Experiment：Model 用 Qwen3-4B 或同尺度开源模型；Dataset 用 ALFWorld 与 WebShop 的多轮任务；Baseline 取不带闸门的记忆写入、只用关联过滤、以及标量奖励 GRPO；Metric 取任务成功率、记忆命中后的动作改变率、写入条目数与有效条目占比。可证伪假设：若方向精度 P 低的条目被保留，成功率应下降；若去掉留一闸门而不降成功率，则该机制在记忆场景里不成立。Expected Contribution：给出“记忆条目的因果效用”这一可训练信号。计算成本：每条候选条目需要一次额外前向，约为训练前向成本的一至数倍，可通过只对被检索到的条目打分来压缩。撞题风险：中到高，MemCredit、CoReMem 等工作已经在谈记忆效用与信用，差异化在于把方向一致性作为准入判据；Risk：留一在条目相互冗余时会低估单条价值，需要成组留一；最终还必须报告匹配算力下的对照，否则收益可能只是多花了前向。

五句话总结

一，OPSD4MAS 把多智能体的未来对话当作特权上下文而不是标量奖励。二，两层过滤——结局关联与方向一致的留一影响——决定哪些事实能当老师。三，在 Qwen3-4B 与六个数学基准上，FW4 相对 GRPO 平均 pass@1 提高 8.87 个百分点，相对 DAPO 提高 6.14 个百分点。四，未过滤的原始沟通比纯 GRPO 低 16.39 个百分点，证明特权信息必须质检。五，增益是否来自沟通本身而非外部强模型的验证，以及能否离开数学与单一模型规模，目前都没有被证明。

人话版：这篇论文到底干了什么？

RLVR 默认验证器能分辨对错，但现实里的验证器常常只能“证伪”：代码的公开单测没过，说明一定错；全部通过，却不代表正确，因为公开测试只有一两个。作者把这种情形叫做单侧可验证（one-sided verifiability，OSV）：验证器判负的样本几乎可信，判正的样本只是“暂未被证伪”，里面混着不少假阳性。在这种设定下，GRPO 把通过检查的样本当正例强化，等于直接奖励了能蒙混过关的捷径。NOPO 的做法是：完全不强化“通过”的样本，只对被证伪的样本做带参考模型的负偏好抑制（NPO 损失，原本是遗忘学习里的工具），并按同一组 rollout 里“未被证伪样本所占比例”给每个提示的负向更新加权，整组都被证伪时权重为零、整组丢弃。在 Qwen3-4B 与 8B、五个代码与推理基准上，平均 pass@16 为 52.86 与 52.13，对 GRPO 分别高 3.93 与 3.86 个百分点；CodeContests 上 pass@512 为 66.95，而 GRPO 只有 48.54，甚至低于基座的 51.05。

背景与缺口

RLVR 的标准叙事是：有一个可靠的验证器，对每个采样给 0 或 1，再用 GRPO 一类算法做策略梯度。可是在真实场景里，完整验证器往往是瓶颈。写代码任务里，用户给得出需求，却给不出完整测试集；科学问题上，验证一个答案可能和生成它一样难；用 LLM 当验证器时，它更擅长挑出一个具体错误，而不是证明全局正确。已有的无监督 RLVR 路线（多数投票、熵最小化、自信度一类的内在奖励）不依赖外部判定，但被已有研究证明受限于基座分布的锐化；噪声奖励路线则需要先用真值标签标定假阳性假阴性率，而这恰恰是无标签设定下拿不到的，并且假阳性率会随策略学会钻空子而上升。

具体反例来自论文表 1 的验证器噪声：以 Qwen3-4B 在 CodeContests 上为例，公开测试只有约 1.9 个，通过公开测试的响应里有 20.7% 实际是错的（qpos=20.7）；在 TACO 上这个比例高达 64.5%，ZebraLogic 的约束检查器通过的响应里 73.0% 是错的。这时把“通过”当成奖励 1，每一个只绕过了少数测试的捷径解都会拿到直接的正梯度，策略学到的是“让验证器通过”而不是“解对题”。缺口因此很清楚：当验证信号只在负面可信时，该怎样做 RL，既不依赖真值，也不去强化可疑的正例。

核心洞察

核心洞察是把验证器信息的可信方向拆开用：只信负的，正的当作无标签。这看起来像把一半信号扔掉，作者的论证是，负样本是确定的反例，抑制它们的方向不会奖励任何捷径；真正的难点在于“只知道往哪里别去，不知道往哪里去”，在线抑制会把概率质量重新分布到未知的地方，可能产生新的错误再被抑制，形成无约束的“逃离式”更新。因此第二个洞察是：只有当同一组 rollout 里出现了未被证伪的样本，才说明这个提示处于模型当前可达的范围内，质量的转移才有“落脚处”；此时才应当放心地做抑制。这个设计反直觉的地方在于，被用作权重的未证伪样本并不参与梯度，也不被当作正例，只是用它们的个数当作支持度。

方法深挖

设定。问题 x，候选解 y，潜在真值正确性 r*(x,y)∈{0,1} 训练时不可见，观测到的是验证器输出 r(x,y)=V(x,y)∈{0,1}。论文给出三类验证器：公开单测 Vpub=𝕀[∀(Ij,Oj)∈Tpub(x), Exec(y,Ij)=Oj]，只检查必要条件的约束检查 Vcon，以及让 LLM 只找错误的 Vllm=𝕀[Jϕ(x,y)=NotFind]。单侧性用两个条件概率度量：qneg=Pr(r*=0∣r=0) 与 qpos=Pr(r*=0∣r=1)，后者越大说明假阳性越多；它们只用来分析，训练中不可见。

负偏好抑制（样本级）。对一个被判负的响应，定义相对参考策略的对数比 Δθ(x,y)=logπθ(y∣x)−logπref(y∣x)，NPO 损失为 ℒNPO,β=2βlog(1+exp(βΔθ))。它对 logπθ 的导数是 2σ(βΔθ)：当策略仍给这个负例不低于参考的概率时惩罚大，一旦已经压到参考以下，惩罚自动衰减，因此不会像朴素梯度上升那样无限发散。参考策略是冻结的基座，β=0.1。

未证伪支持度（组级）。对同一提示采样 G=16 个响应，验证标签 ri∈{0,1}，支持度 c(𝐫)=∑iri。权重 ωγ(𝐫)=1（当 γ=0，即退化为普通 NPO），否则 ωγ(𝐫)=(c(𝐫)/G)γ。默认 γ=1。整组都被证伪时 c=0，权重为零，该组直接从更新里丢掉；这在难题上很常见，其概率等于一减去验证器 pass@G。

总目标。ℒNOPO(θ)=𝔼[ωγ(𝐫)·1G∑i=1G𝕀[ri=0]ℒNPO(θ;x,yi)]。验证标签与支持度被当作固定反馈，梯度只经过被判负响应上的 NPO 项。Algorithm 1 的流程是：采样提示、固定旧策略并生成 G 个 rollout、算验证标签、算 c 与 ωγ、对 ℒNOPO 做一步梯度。Algorithm 1 先固定旧策略再采样，因此每一步的负例都来自当前策略在线生成，而不是固定的负例数据集。没有重要性比率，没有优势归一化，没有 KL 项（kl\_loss\_coef=0），所以实现上比 GRPO 更简单。

与 GRPO 的逐项对照。GRPO 把验证标签转成组内归一化优势，同时强化高分样本、削弱低分样本，并带重要性比率与裁剪；NOPO 删去了其中全部“强化”的一半，只保留“削弱”，并把优势归一化换成与组内通过比例成正比的标量权重。后果是更新方向只由负例决定，更新幅度只由支持度和参考相对的对数比决定，二者都不依赖对正例的任何判断。选择 NPO 而不是朴素的负对数似然梯度上升，是因为后者在在线设定下没有上界：被抑制样本的概率越低，梯度反而越大，容易引起熵爆炸；NPO 的 sigmoid 门让惩罚在对数比为负时趋于零。三类验证器的覆盖密度相差悬殊：代码公开测试能识别 82% 至 91% 的真错误，ZebraLogic 约束检查为 35% 至 56%，OlympiadBench 的 LLM 自验证器只有 9% 至 13%，所以同一个 NOPO 在三类任务里每组可用的负例数量完全不同，这也解释了为什么组级权重必须显式存在。

工程配置。全部 RL 在 verl 框架加 vLLM 上做：AdamW、恒定学习率 5×10−7（20 步线性预热）、每步 16 个提示各 16 个 rollout 共 256 条、PPO 迷你批含 4 个提示、每步只跑一个内层轮次、最多 150 个全局步，每批 rollout 只被使用一次；采样温度 0.8、top_p 0.8、top_k 20；代码任务最长响应 8192，逻辑与数学 16384。因为以负向优化为主的方法会出现熵发散，作者监控策略熵，并取熵发散之前保存的最近检查点做评测，这是一个影响所有负向方法比较公平性的细节。

三个反直觉点。一，被丢弃的是“通过验证”的样本的梯度，保留的只是它们的数量。二，整组全败的提示被完全丢弃，意味着训练永远只在“模型能解出至少一次”的提示上发生，这是一种隐式课程，也是对难题没有学习信号的代价。三，参考策略固定在基座上，使得抑制具有“相对基座”的自衰减，而不是相对当前策略，这样即使策略漂移也能限制过度惩罚。附录 C.1 还说明主结果里训练与评测使用同一个基准的测试题，评测则用包含隐藏测试的完整测试集作为 oracle：训练期验证器平均只有 1.7 至 2.6 个公开测试，而评测 oracle 有 12 至 204 个。

Toy Example

取 G=16、γ=1。提示 A：16 个 rollout 里 6 个通过公开测试，c=6、ω=6/16=0.375，10 个被判负的响应各自按 NPO 抑制，总强度乘 0.375。提示 B：2 个通过，ω=0.125，同样的负例只得到约三分之一的力度。提示 C：全部 16 个失败，ω=0，整组被丢弃，没有任何梯度。若 γ=2，A 的权重降为 0.3752≈0.141，更保守。再看负例本身：设某被判负响应相对参考的对数比 Δ=+2，β=0.1，则梯度系数 2σ(0.2)≈1.10；当它已被压到 Δ=−20，系数为 2σ(−2)≈0.24，惩罚自动变小。这两个乘子（样本级自衰减、组级支持度）合起来，使得“抑制强度只在模型还会犯这个错、且别的采样已经能走通”时才大（以上数值为我按公式演算，非论文报告值）。

Baseline Comparison

四个对照：GRPO（直接把验证器当二值奖励，kl 系数 10−3）；EM-RL（无验证器、token 级熵最小化）；w-Reinforce（验证器正样本权重 0.1、负样本权重 1，同样偏向负样本）；以及 NOPO。最强基线是 w-Reinforce：在 Qwen3-4B 上平均 pass@16 为 50.69，8B 上 48.84，仅次于 NOPO 的 52.86 与 52.13；在大 k 的推理预算下也一直是亚军。GRPO 在 pass@1 上最强，但这恰好是它的弱点所在，见下文。EM-RL 几乎与基座持平，印证内在奖励方法受限于锐化。

实验设置与研究问题

设置。基座 Qwen3-4B 与 Qwen3-8B（非思考模式）。代码：LiveCodeBench（release_v6 代码生成）、TACO 测试集（排除 64 道解析不出公开测试的题）、CodeContests，使用公开测试二值奖励，CodeForces 保留为未见迁移目标；逻辑：ZebraLogic 的 Medium-Large 子集（4×4、4×5、5×3、6×2），用只检查格式与域约束的确定性检查器；数学：OlympiadBench 英文纯文本子集，用 LLM 自验证器。每提示 G=16。RQ1 单侧信号下 NOPO 是否优于 GRPO 等；RQ2 收益是否在大推理预算下依然存在（能力边界是否被扩展）；RQ3 收益能否迁移到未见基准；RQ4 支持度权重与指数 γ 是否必要。

口径说明。训练期验证器与评测 oracle 是两套东西：评测使用包含隐藏测试的完整测试集（TACO 平均 204 个测试、LiveCodeBench 40 个、CodeContests 12 个），训练期却只有平均 1.7、2.6、1.9 个公开测试；ZebraLogic 与 OlympiadBench 以真值答案评测。

RQ1：主结果。Table 2 中 Qwen3-4B 平均 pass@16：基座 46.85、GRPO 48.93、EM-RL 47.17、w-Reinforce 50.69、NOPO 52.86；8B 是 44.94、48.27、44.91、48.84、52.13。10 个“基准×骨干”格子中 NOPO 拿到 9 个第一，例外是 Qwen3-8B 的 OlympiadBench（76.52 低于 GRPO 的 76.97）。论文自己的解释是，OlympiadBench 的 LLM 自验证器负类召回只有 8.8% 至 12.5%（表 1），被抑制的负样本太少，信号弱。8B 上的提升更突出：平均对基座 +7.19、对 GRPO +3.86；ZebraLogic 上 NOPO 为 66.25，对 GRPO 的 60.62 与基座的 56.25 分别高 5.63 与 10.00 个百分点；LiveCodeBench 上 42.86 对 GRPO 的 37.14。最大的单格提升在 CodeContests：4B 由 41.18 到 50.47，8B 由 43.10 到 55.04；最小的在 OlympiadBench，4B 由 73.78 到 75.33。

RQ2：推理预算扩展。Table 3，Qwen3-4B 在 CodeContests 上，k=512 时 NOPO 66.95、w-Reinforce 63.60、基座 51.05、EM-RL 51.46、GRPO 48.54；LiveCodeBench 上 NOPO 50.86、基座 42.29、GRPO 41.71。观察：NOPO 与基座的差距随 k 增大而拉开，GRPO 则在 k=512 低于基座，呈现“锐化换小 k”的典型失败。但同表也暴露了 NOPO 的短板：CodeContests 的 pass@1 只有 26.87（GRPO 37.23），LiveCodeBench 的 pass@1 是 25.33，低于基座的 26.03。换句话说，NOPO 用单次命中率换覆盖：CodeContests 从 k=1 到 k=512，NOPO 由 26.87 升到 66.95，涨幅 40.08 个百分点，GRPO 由 37.23 升到 48.54，只涨 11.31。LiveCodeBench 上趋势一致：k=512 时 NOPO 50.86、w-Reinforce 48.57、基座 42.29，而 k=1 时 NOPO 的 25.33 低于 GRPO 的 29.40，也低于基座。解释：NOPO 不强化任何正例，所以并不提高单次命中率，它保留并拓宽了可达解集；若部署只采样一次，GRPO 反而更好。

RQ3：迁移。Table 4（Qwen3-4B，pass@16）：以 CodeContests 训练，迁移到 TACO、LiveCodeBench、CodeForces，NOPO 为 15.78、40.57、32.12，平均未见 29.49；基座 23.66，GRPO 23.30，w-Reinforce 27.68。以 LiveCodeBench 训练时，未见平均 NOPO 31.93，基座 25.90，GRPO 24.91。最大的单项在 CodeForces：NOPO 为 32.12，基座 22.91（+9.21），GRPO 只有 24.63（+1.72）。第二组迁移里，NOPO 对 CodeContests 为 49.37，基座 41.18，GRPO 39.75，比基座还低 1.43。GRPO 的收益甚至不能迁移到同域，在 TACO 与 LiveCodeBench 上低于基座。附录 Table 7 给出验证器噪声如何被训练改变：GRPO 使 CodeContests 上的 qpos 从 20.7 升到 25.2，同时负类召回 rneg 从 91.3 降到 79.8，说明策略学会了逃过测试；NOPO 则把 qpos 降到 16.6，召回保持 92.4。

RQ4：消融。Table 6，Qwen3-4B 在 TACO 上训练、在三个未见代码基准评测，Unseen-Avg：NSR 38.67、NPO 38.53、NOPO(γ=0.5) 39.55、NOPO(γ=1) 41.44、NOPO(γ=2) 39.55。线性支持度最好，纯 NPO 与 NSR 都不如加了支持度的变体；γ=1 相对纯 NPO 的未见平均提升 2.91 个百分点，训练域内 pass@16 为 19.52 对 17.82。也就是说，门控的价值更多体现在迁移而非域内：域内差距只有 1.70 个点，未见平均差距是 2.91 个点。

消融、论断与证据

消融：NPO 与 NSR（无正样本的 w-Reinforce）在未见平均上低于任何带支持度权重的变体，γ=1 最好，γ=0.5 与 $2$ 并列次之，说明权重必要且对指数不敏感；但只有一个训练源（TACO）、一个骨干，γ=1 对 NSR 的 2.77 个点优势（41.44 对 38.67）也缺少种子方差来判断是否稳健，同时说明“只抑制”还不够，必须有组级门控。论断 vs 证据：作者称 NOPO “扩展能力边界”。证据是大 k 下的 pass@k 差距与迁移结果，两者较有说服力，Table 7 又从验证器噪声角度给出机制性佐证。尚未证明的有：（一）主结果里训练与评测使用同一基准的测试题，属于测试集上的无标签训练，与“泛化”不是一回事，只有 Table 4 的未见基准才是干净的迁移；（二）训练期取熵发散前最近的检查点，对负向方法的选择偏向没有量化；（三）没有多种子方差，各格差距有时只有零点几个点；（四）NOPO 的 pass@1 退步（LiveCodeBench 25.33 对 26.03）说明它不是 GRPO 的无条件替代。

Contribution

（问题形式化）提出并度量单侧可验证性，用 qneg、qpos、rneg 把“验证器哪一侧可信”变成可测量的量。（方法）NOPO：参考相对的 NPO 抑制加组级未证伪支持度权重，不强化任何正样本。（经验发现）GRPO 在 OSV 下会提高假阳性率、降低负类召回；负向方法在大推理预算下扩展而不是锐化能力；负样本聚焦的方法迁移更好。（跨界）把遗忘学习的 NPO 搬进在线 RLVR，是一次干净的方法迁移。

Limitation

作者承认：负向学习只知道避开什么、不知道转向哪里，设计因而保守；不同 OSV 场景里，验证正样本可能含有可利用的结构（成对比较、不确定度过滤），尚未纳入。额外的局限：主结果与测试题同源；单一训练配方（150 步、恒定学习率 5×10−7）；全组失败的难题被完全丢弃，意味着对真正难的题没有学习信号；低负类召回的验证器（OlympiadBench）上收益有限甚至为负；pass@1 退步；没有成本对比，每个运行约 12 小时、8 张 A100，推理预算扫描需要最多 512 次采样。

Research Value

对 RL for LLM 主线，这篇工作把“奖励可信度的不对称”放到中心：Agent 场景里常见的信号——工具调用报错、环境断言失败、静态检查警告——同样是单侧的，只能证伪。它给出一条不依赖人工奖励、也不强化捷径的训练路线，并提供了可审计的诊断量 qpos 与 rneg，可以直接用来判断一个 Agent 环境的奖励是否适合做正向强化。它与 Reward Hacking 研究天然接壤：GRPO 把 qpos 从 20.7 推到 25.2 正是一种可量化的“验证器逃逸”。同时对 Unlearning 方向有反哺意义：NPO 在在线 RL 中的行为（自衰减、需要门控）是遗忘文献里少见的在线设定实证。

Original Problem：验证器只能证伪时的 RLVR。Transferable Mechanism：组级未证伪支持度门控的负向抑制。New Research Question：在多轮 Agent RL 中，轨迹结局常常也只有单侧可信信号（环境报错必为失败、任务“完成”不代表正确），能否对失败轨迹中的具体步骤做抑制、并以同组成功轨迹数门控，避免把“看似完成”的轨迹当正例？Method Modification：把 𝕀[ri=0] 换成“出现硬错误的步骤”的 token 掩码，c(𝐫) 换成同一任务组内无硬错误轨迹的数量，参考策略取 SFT 初始化；对比加入轻度正向项（w-Reinforce 式）。Minimum Experiment：Model 用 Qwen3-4B；Dataset 用 ALFWorld 或 WebShop，仅启用“动作非法/页面报错”作为单侧信号，用环境真实成功作为 oracle 评测；Baseline 为步骤级 GRPO、w-Reinforce、纯 NPO；Metric 为成功率随 k 的曲线、qpos（被判通过却失败的比例）、pass@1 与 pass@16 的差。可证伪假设：若 Agent 环境的未证伪样本里假阳性率很高，则 GRPO 的 qpos 应上升而 NOPO 式方法下降；反之假设不成立。计算成本：与 GRPO 同级，少了优势计算，增加参考策略前向。实验细节：建议先在 Qwen3-4B 与 ALFWorld 的三个任务类型上跑三个种子，沿用论文的每步 256 条 rollout 与 150 步；论文没有给出 Agent 场景成本，需自测。成败判据：相同 rollout 预算下，NOPO 式方法的成功率 pass@8 比步骤级 GRPO 至少高 3 个百分点，且 qpos 不上升。撞题风险：中，负样本强化与 NPO 类文献都在涨，但“单侧性诊断加门控”的组合在 Agent 上尚少；Risk：Agent 轨迹很长，步骤级负样本归因本身就不可靠，可能需要先用 OSV 的思路做轨迹级筛选。

五句话总结

一，作者形式化单侧可验证性：验证器判负可信，判正只是未被证伪。二，NOPO 只对判负样本做参考相对的 NPO 抑制，并按组内未证伪样本比例加权，整组全败则丢弃。三，两个骨干上平均 pass@16 为 52.86 与 52.13，比 GRPO 高 3.93 与 3.86 个百分点，CodeContests 的 pass@512 为 66.95 对 GRPO 的 48.54。四，GRPO 在 OSV 下把假阳性率从 20.7 推到 25.2，NOPO 压到 16.6，但 NOPO 的 pass@1 不提升甚至略降。五，主结果与测试题同源、没有多种子，真正干净的证据是未见基准迁移与大 k 曲线。

A TraceKV：为推理型视觉语言模型做“保持策略”的低秩 KV 压缩（Video/Multimodal Efficiency · KV Cache）

A TraceKV: Policy-Preserving Low-Rank KV Cache Compression for Reasoning Vision-Language Models

  • ID: arXiv:2611.15569 · PDF（v1，cs.CV，2026-11-11）
  • 作者: Ke Li, Zishan Shao, Yiran Chen（Duke University ECE；一作为实习期间工作）
  • Venue: 未核实 · 代码: 摘要写 “Code will be available at github.com/AK-DREAM/TraceKV”，属于“将发布”，未核实
  • 全文来源: arXiv PDF 全文，含 Table 1–6、Figure 1–5
  • 范围提示: 评测集为 ScienceQA、MathVista、MMMU 等图像推理基准，没有视频基准；它与视频的关系是“多模态长上下文加长推理轨迹的 KV 成本”，请按此理解其视频相关性。

人话版

推理型 VLM 要写很长的思维链，KV cache 同时被大量视觉 token 和不断增长的推理 token 撑大。低秩压缩（把 K、V 投影矩阵分解，只缓存低维 latent）是一条省显存的路，但已有方法按“重建误差最小”用静态的输入上下文做校准，实测一到推理阶段，压缩模型与稠密模型的下一 token 分布之间的 KL 会随生成步数快速增大，出现逻辑错误甚至死循环。TraceKV 不改模型、不重训，只在校准阶段做三件事：让稠密模型自己生成推理轨迹来校准（on-policy），用 Fisher 信息估计每个 KV 状态对策略 KL 的敏感度并加权做 SVD，再按“对策略 KL 的重要度”在所有层与 K/V 投影之间全局分配秩。在 Qwen2.5-VL-7B、InternVL3-8B、Qwen3-VL-8B 的三个推理基准上，70% 秩加 4-bit 量化即 5.64 倍 KV 压缩，平均准确率 73.41%，稠密为 73.58%；解码端到端最高 1.83 倍加速。

Background & Gap

KV 压缩有三条路：丢 token（SnapKV 等）、降精度（KIVI、KVQuant）、低秩（Palu、WSVD）。针对 VLM 的低秩方法通常把投影矩阵的近似写成 min‖X(W−W^)‖F2，其中 X 是静态多模态校准序列的激活，评测也多在短答案任务上。缺口在两点：其一，静态校准没有覆盖模型自己生成的推理 KV 状态。论文 Table 1 显示，在 50% 秩下用输入上下文校准，MMMU 上输入部分重建误差 8.02，进入推理阶段升到 10.27；加入真值解答轨迹只降到 9.67，加入稠密模型自己的 on-policy 轨迹降到 8.88。其二，等量的重建误差对策略的影响并不等价：许多视觉 token 的状态敏感度低，而某些文本与推理状态非常敏感，均匀重建把有限的秩浪费在不敏感处。

Core Insight 与 Pipeline

核心洞察是把压缩目标从“重建”换成“保持策略”：minrank(W^)≤r𝔼s~dpDKL(p(·∣s)‖pW^(·∣s))。该目标没有闭式解，作者用二阶展开 DKL≈12δ⊤Fδ（F 为 Fisher 信息）得到可用 SVD 求解的替代目标。流水线：（1）让稠密模型对校准集（256 个 ScienceQA 训练样本）自回归生成推理轨迹，收集输入与推理状态的激活 Xon；（2）对每个 KV 状态 yt，用蒙特卡洛估计其敏感度 s^t=12Kdout∑k‖gt(k)‖22，其中梯度来自从稠密策略采样的下一 token 的负对数似然；构造加权协方差 C=Xon⊤DXon（D=diag(s^t)/∑s^），做白化 SVD，解 min‖D1/2Xon(W−W^)‖F2；（3）用 Im,i=12K∑k⟨Gm(k),ΔWm,i⟩F2 估计每个奇异分量对策略 KL 的重要度，在全局秩预算下跨层、跨 K/V 选取分量；（4）对低秩 latent 做 Hadamard 旋转后用逐 token 非对称量化；（5）Triton 内核把 key 重建、RoPE 与注意力 logit 计算融合，value 先按注意力权重在 latent 上聚合再重建，避免显式物化完整 KV。

Research Value、Migration、Worth Deep Reading

A DiFiT：学习“保留哪些视觉 token”，并让剪枝后的输出分布贴近全 token 模型（Video/Multimodal Efficiency · Token Pruning）

A DiFiT: Distribution-Fidelity-guided Visual Token Pruning for Multimodal Large Language Models

  • ID: arXiv:2611.15069 · PDF（v1，cs.CV，2026-11-11；备注 8 figures, 13 tables）
  • 作者: Jingyuan Zhang, Nihao Niu, Xinyang Lv, Beibei Han, Xiaoyun Wang（通讯）, Yanning Hou, Ke Xu；单位含安徽大学、国防科技大学（IEEE 格式稿件）
  • Venue: 未核实 · 代码: 论文文本中未见链接（未核实）
  • 全文来源: arXiv PDF 全文，含 Table I–XI、Figure 1–7

人话版

视觉 token 剪枝通常只看“剪完之后答案还对不对”。作者指出这不够：即使贪心解码的答案完全不变，剪枝仍可能改变其他候选 token 的概率，使置信度策略做出不同的接受或拒绝，使采样解码出现不同续写。DiFiT 先量化这种“预测漂移”，再提出一个学习式剪枝器：冻结视觉编码器、投影器与语言模型，只训练一个打分器（DPS）加可微 Top-K，目标同时包含答案监督（交叉熵）和“与全 token 模型输出分布匹配”的双视图蒸馏（DVD），再用多预算掩码损失（MBL）让同一个排序服务 30%、20%、10% 等多种保留率。在 Qwen2.5-VL-7B 上，10% 保留率时平均性能保留 89.36%，比 VisionSelector 的 86.55% 高 2.81 个百分点；MVBench 20% 保留率下准确率 66.38%（全 token 68.10%），预填充时间从 1413.34 ms 降到 603.90 ms。

Background & Gap、Core Insight

已有剪枝方法按重要性（注意力）、覆盖与多样性、或学习式选择来决定保留谁，评价口径是任务得分保留率。缺口是“同一个贪心答案背后分布可以很不同”：全 token 与剪枝模型对同一 token 都取最高概率，一个把概率集中在它上面，另一个把更多概率分给替代项。论文在共享参考前缀下比较分布，发现在固定的、全都答对的样本上，每种被评测的剪枝方法的平均漂移都随压缩率增大；更大的漂移与更多的“接受/拒绝”决策不一致和采样失败相关，这种关联在控制全模型置信度、首 token 预测间隔、任务与预算之后仍然存在。核心洞察：保留集合应当保住“模型输出分布”，而不只是答案；参考答案告诉你该奖励哪些 token，全 token 分布告诉你概率在竞争项之间怎样分配，二者互补。

Pipeline

输入是图像（或视频帧）视觉特征 X∈ℝB×N×D 与文本问题。DPS 双感知打分器为每个视觉 token 打分，可选地融合文本相关性（门控融合）；可微 Top-K 在训练时产生软掩码、推理时产生硬掩码，推理只做一次剪枝后的前向，兼容高效注意力内核。训练损失三项：交叉熵监督参考答案；DVD 在共享参考前缀下，用温度 τ=2 对教师（全 token）与学生（软掩码视图）logits 做 softmax，再取 ℒKL=τ2∑imi∑imiDKL(Pifull‖Pisoft)；MBL 把软掩码与硬选择在 30%、20%、10% 三个预算上对齐，用更大预算的排序指导更小预算。交叉熵与 DVD 只监督 30% 学生路径，MBL 监督三个预算。每个骨干单独训练一个打分器。

A HeMeR：把异构记忆更新“对账”到可复用的 KV 状态（Agent Memory × Efficient Inference）

  • ID: arXiv:2611.16487 · PDF（v1，cs.AI，2026-11-12）
  • 作者: Saehun Chun, Wonje Choi, Jinwoo Jang, Taeyoon Kwack, Honguk Woo（通讯）；成均馆大学

人话版

具身 Agent 每一步决策前，要把陈述性记忆（环境事实）、程序性记忆（学到的例程，以 LoRA 适配器形式存在）、工作记忆（当前观察与子目标）拼成一个记忆上下文喂给基础模型。现有做法每步都把更新后的上下文当新输入，整个 KV cache 重算，哪怕大部分内容没变。HeMeR 把记忆上下文表示为带类型的“记忆块”，每块对应一段 KV 范围；记忆更新时只重算受影响的范围，没变但位置移动的块用 RoPE 重映射复用，程序性记忆切换适配器时把适配器 ID 作为 KV 兼容性条件。在 ALFWorld 上任务成功率 71.43%、每步 0.18 秒，对最强成功率基线 MemRL 的 52.86% 与 0.90 秒；真实机械臂（UR7e）上成功率 83.20%，每步 1.87 秒对 MemRL 的 2.94 秒。

Background & Gap、Core Insight

记忆增强 Agent 的文献主要研究“存什么、取什么、怎么更新”，而不关心记忆被合成上下文之后在推理侧怎么复用 KV。通用 KV 复用（前缀缓存、CacheBlend 的非前缀片段、KEEP 的失效区域）与多适配器服务（LRAgent）各管一部分，没人同时处理“内容更新”与“适配器切换”。举例：冰块融化这样的环境变化只改一条陈述性事实，却让前缀缓存整段失效；更隐蔽的是，适配器切换后即使文字没变，旧 KV 也不再兼容。核心洞察：三类记忆最终都落到同一件事上，就是 KV 状态，所以应该在 KV 层面用统一的“记忆块加 KV 范围”索引来对账，而不是在三个记忆接口上各自缓存。

Pipeline（Agent Architecture）

Agent 流程：观察 ot 与目标 g → 从三类记忆模块组装记忆上下文 Xt → 与上一步 Xt−1 做对账 → 生成动作 → 环境反馈 → 更新记忆。对账的数据结构是记忆模式（schema）：每个块记录持久 ID、模块类型、语义角色、规范化内容、依赖标注、位置、token 跨度、KV 范围，程序性块还记录适配器 ID。相邻两步按持久 ID 匹配块，类型、角色、依赖、内容与适配器全部一致才允许复用，否则局部重算；得到计划 Δt=DiffS(Xt−1,Xt)，把块分为插入、驱逐、重排（RoPE 重映射）、重算、复用。适配器稳定性：把适配器配置纳入兼容条件，切换时只重算受影响范围。实现上 ALFWorld 用 Llama-3.2-3B-Instruct、Habitat 用 Qwen3-VL-4B-Instruct，程序性记忆为 rank-8 LoRA，贪心解码，2×RTX A6000，随机种子 0/7/42/99/123。

人话版。OPSD 让一个冻结的“老师”（学生的拷贝，额外看到标准解答这类特权信息）在学生自己的轨迹上逐 token 打分。作者问：学生的进步是不是真的来自那份解答。Background。Standard OPSD 的损失是在学生采样的每个前缀上，用裁剪过的前向 KL 把学生分布拉向老师分布；而老师既要解题、又要识别学生错误、还要产生有用的 token 目标，这三件事互不蕴含。Core Method。在 Qwen3-1.7B、4B、8B 与五个竞赛数学基准（AIME 2024、2025、2026，HMMT Nov 2025、Feb 2026）上，作者把审计拆成四段：Source（老师能否用解答）、Encoding（token 目标是否区分正确与错误轨迹）、Transmission（学生是否学到）、Expression（不看解答时能否表达）；并把老师、学生展开与评测的思考模式独立切换。Experiment / Main Finding。老师有解答时能解难题、能从学生错误后恢复，但不可靠地识别错误，token 目标也不偏向正确轨迹；重复训练让学生“够得着的成功”更频繁，而不是解锁新的；图 1 显示最大持续增益出现在“思考模式老师监督、不思考的学生训练并评测”的组合，在思考型老师、非思考展开与非思考评测的设置下，Step 100 时只给题目（无解答）的老师训练出的学生，其平均 Avg@12 在 1.7B、4B、8B 上反而分别高 1.36、15.21、8.60 个百分点（1.7B 的区间含零）。作者称之为 reasoning arbitrage：增益跟踪老师的思考模式而不是解答。补充细节。Source 阶段的结论是，老师带解答时解难题与错误后恢复的能力确实提高了。Thinking-ON 评测下各组差异很小且混杂；训练曲线是三个训练种子的平均，Base 是三个解码种子的平均，阴影为描述性的 95% bootstrap 区间。作者还在 4B 与 8B 上做了“经验证的修正”试点：个别变体从原题开始生成时略高于 Standard OPSD，但没有一个改善错误前缀恢复，更高的修正剂量还会降低更广泛的准确率；Purified OPSD 在更长训练里改善了保留。Contribution。分阶段审计框架，以及“准确率提升不能证明特权信息被迁移”的实证。Limitation。仍是进行中的工作；只在 Qwen3 数学上，OLMo 与代码仅做保留性检查。Why It Matters。它直接挑战所有“特权上下文蒸馏”类论文的归因，包括今日 Tier S 的 OPSD4MAS：后者在非思考模式下训练，没有思考模式套利，但同样缺一个“只给题目的老师”对照。Connection。与 OPSD4MAS 的留一过滤形成互补：作者的 Encoding 阶段缺陷正是后者用过滤来补的。Potential Use。在任何 OPSD 或事实条件化蒸馏实验里，加入“老师无特权、仅切换思考模式”的消融。

Idea Mining

以下 4 个想法是基于今日论文的推演，尚未做实验，也未做穷尽式查新；Collision Detection 只覆盖已读材料与摘要。

Idea 1：Agent RL 中的“单侧硬证据”负向步骤抑制（Falsification-Gated Step Suppression）

  • Motivation：Agent 环境里“工具报错、状态未变化、测试未过”是可信负信号，而“看起来完成了”只是未被证伪。NOPO 在单轮答案上证明了只抑制被证伪样本的价值。
  • Core Hypothesis：在长程 Agent 轨迹中，仅对带硬证伪证据的步骤做负向更新、并按同组未证伪比例加权，比对整条轨迹强化成功样本更不容易奖励“蒙混过关”的捷径。
  • Method Sketch：把步级硬错误（非零退出码、状态断言失败）作为 r=0 的可信负；负向项取 NOPO 的参考相对 NPO 形式；组级权重取组内未被证伪的比例。
  • Required Experiment：在 ALFWorld 或 SWE 类环境上对比 GRPO、仅正向 RFT 与该方法，比较 pass@k 随 k 的变化、假完成率（声称完成但被后验断言推翻）；对 Honesty Is a Race 的 pr/b 量做预测检验。
  • Possible Baselines：GRPO、NOPO（单轮）、负样本强化类方法。
  • Expected Gain：未验证；预期主要表现为 pass@k 大 k 端与假完成率，pass@1 可能与 NOPO 一样不涨。
  • Risk：轨迹长时负信号稀疏；步级归因本身就是难题；NOPO 的 pass@1 不提升可能限制 Agent 场景的实用性。
  • Novelty Level：中（NOPO 的直接外推，已有“失败归因”文献可能覆盖部分）。
  • Feasibility：中；需要可程序化判定的步级证伪。

Idea 2：用“方向一致的留一影响”筛选 Agent 记忆写入

  • Motivation：OPSD4MAS 发现未过滤的事实会让训练比纯 GRPO 差 16.39 个百分点，说明特权信息必须质检；Agent 记忆写入同样面临“写什么”的问题，现有工作多按语义相关度或摘要质量选择。
  • Core Hypothesis：记忆写入前，用“留一条后对决策的影响方向是否与最终结局一致”过滤，能减少错误记忆的放大。
  • Method Sketch：对候选记忆条目做反事实留一，量化其对下一动作概率的方向性影响，只写入方向与结局一致的条目；与 HeMeR 的块级对账结合，使写入决策有成本模型。
  • Required Experiment：LoCoMo 或 ALFWorld 类长程记忆任务；对比相关度检索、MemCredit 式效用估计与本方法；消融留一粒度与方向条件。
  • Possible Baselines：MemCredit、MAPE、DISCERN、Folio。
  • Expected Gain：未验证。
  • Risk：留一代价高；结局相关≠因果。
  • Novelty Level：低到中（⚠️ 与 MemCredit 的反事实干预思路高度重叠，见 Collision）。
  • Feasibility：中。

Idea 3：流式视频 KV 的“策略敏感度”分配，并用 MemInStream 式证据区间做探针

  • Motivation：TraceKV 在图像推理上证明了按策略 KL 敏感度分配压缩预算优于按重建误差；流式视频的记忆题恰好提供“证据区间”，可以检查被压缩掉的是不是证据。
  • Core Hypothesis：在流式视频上把压缩预算向“证据区间内的 KV”倾斜，同样的压缩率下记忆类题的准确率更高。
  • Method Sketch：用小批量带证据标注的数据估计 Fisher 敏感度，得到帧或 token 级的预算分配；推理时无标注，采用学到的轻量预测器。
  • Required Experiment：MemInStream 的状态跟踪与情节检索类；同压缩率下比较均匀低秩、TraceKV 式分配与本方法；报告 TTFT、显存与准确率。
  • Possible Baselines：TraceKV、DiFiT 式剪枝、StreamForest 等在线模型。
  • Expected Gain：未验证。
  • Risk：TraceKV 本身没有视频评测，迁移的假设尚未得到支持；证据区间需要标注。
  • Novelty Level：中。
  • Feasibility：中；需要先在视频上复现 TraceKV。

Idea 4：把 DiFiT 的“预测漂移”当作视频 Agent 的回看触发信号

  • Motivation：DiFiT 表明答案不变时分布仍可漂移，漂移与接受/拒绝决策不一致相关。视频 Agent 若在剪枝视图下不确定，可触发用更多 token 回看。
  • Core Hypothesis：剪枝视图与少量全 token 探针之间的分布差，可作为“是否追加算力”的低成本信号，优于仅用输出置信度。
  • Method Sketch：周期性用全 token 对少数位置做探针，估计漂移；超过阈值时扩大保留率，类似 Branch-and-Commit 的“何时何处花算力”。
  • Required Experiment：MVBench 与长视频基准；与固定保留率、置信度触发比较平均 token 数与准确率。
  • Possible Baselines：DiFiT 固定预算、VisionSelector、置信度自适应方法。
  • Expected Gain：未验证。
  • Risk：探针本身有成本，可能抵消节省；DiFiT 的视频证据仅 MVBench 一项。
  • Novelty Level：中到低。
  • Feasibility：中。
