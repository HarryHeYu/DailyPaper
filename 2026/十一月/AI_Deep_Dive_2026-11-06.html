Paper 1｜Stabilizing On-Policy Targeted Guidance in Agentic Reinforcement Learning

2026-11-03 / v2 11-04 · Agentic RL · 正文可访问

01 · 基本信息、为什么入选、研究定位

论文：Stabilizing On-Policy Targeted Guidance in Agentic Reinforcement Learning；作者：Kevin Frans、Alexander M. Rush、Sergey Levine、Pieter Abbeel、Ashvin Nair；日期：2026-11-03 首次提交，11-04 更新 v2；状态：arXiv 预印本；Venue：未从原文确认；项目/代码：正文没有给出可核实的官方公开仓库，因此标记 Not Verified。全文 HTML / arXiv / PDF。

一句话：把 reward judge 原本只用于计算二值奖励的文字反馈，转成“只对失败的 agent turn 生效”的自蒸馏方向信号，在完成软件工程任务的主奖励不退化的前提下，学会普通 on-policy RL 很难探索出来的输出与工具行为。

为什么选它：这篇不是把一个新 loss 简单拼到 GRPO 上。它追问更普遍的问题：当某个行为在当前策略采样分布中几乎不存在时，即便 reward 定义正确，策略梯度也可能学不到。它把探索支持集、辅助奖励干扰、在线蒸馏稳定性放进一个可检验的闭环。论文提供 GRPO、OPSD、Online SFT、LaTRO、Verifree 等对照以及可核验的多维风格得分与主任务 pass rate，恰好适合用来区分“辅助行为提升”与“真正智能提升”。

02 · 人话版（问题、方法、结果、重要性）

想象一个编程 Agent 可以改代码、运行测试，却几乎不会按用户指定格式报告进度。你给它一个奖励：“必须先请求用户批准”，但训练时它从未碰巧这样做，GRPO 就看不到正样本；只用评分信号，并不能教它“批准”步骤如何组织。作者注意到，判断是否合格的模型其实已经知道哪里错了，也能给出一句具体修改意见。于是同一个语言模型被临时加上这句提示，变成反馈条件下的教师；学生仍在自己刚执行过的轨迹上训练，只在失败回合学习教师概率分布，同时继续进行普通的任务 RL。这样既利用了文字说明提供的方向，又避免从另一条完全不同的教师轨迹学进不适合当前环境的动作。论文 Table 1 的七项风格指标里，TG 多项明显领先，但最终 coding pass rate 为 0.33，和 GRPO 的 0.33 一样；这说明论文有力证明的是“特定辅助行为可被学会且主任务不明显受损”，并未证明编程能力本身提高。更重要的结果是：蒸馏过重、始终给反馈或不覆盖 thinking token 都会造成训练不稳定。真正值得迁移的是失败回合门控、同策略条件教师和监督/奖励分工三者组合。

03 · Background 与 Research Gap

标准策略优化目标是最大化 E[R(τ)]，也就是让按策略采样的轨迹获得更高回报。GRPO 通过同一个任务的一组 rollout 的相对回报来构造 advantage：若采到更好的行为，它就提高相应动作概率。问题在于支持集覆盖：当前策略如果从不生成“先征得用户批准再运行命令”的动作，那么二值规则的奖励再准确，也只能给所有样本打 0。重复采样不是原则性的解决方式，尤其长时工具调用的一次 rollout 成本很高。

以前有几条路线：第一，给风格/工具行为加 reward，仍依赖探索；第二，在线 SFT，让教师重新生成符合要求的动作序列，问题是教师的上下文和实际交互状态可能不同；第三，OPSD 直接用带提示的自己当教师，不必额外模型，但它可能持续把策略推向反馈条件分布，从而扰乱主任务。论文将研究缺口准确落在“如何在不牺牲 primary coding reward 的情况下，让 RL 学到原本零概率或低概率的辅助行为”。

具体例子：Agent 在仓库中实现修复，工具返回测试失败。用户要求每轮更新包含 Markdown 状态表。仅给完成任务 reward 的策略往往不写表；仅给表格 reward 的策略可能学到空表、牺牲修复质量。文字反馈可以指出“下轮进度用表格表示”，但如果把整个教师修改后的执行过程当金标，就可能误教其它命令。TG 对原始 rollout 的那个失败 turn 算反馈条件教师的 logits，尽量把学习信号限定在格式偏好上。

04 · Core Insight 与机制证据链

作者把 judge 的输出拆成两个层次：R_i 是判定某条标准是否满足的标量，f_i 是告诉策略如何修正的文字。标量告诉“好坏”，文字告诉“方向”。这是一种基于训练行为的经验性观察，不是一个对任意任务都成立的理论定理。论文的充分条件直觉是：给提示后的策略 μ 应该在对应标准上比原策略更好，同时在不相关动作上与原策略尽量接近。若提示改变了策略对文件系统、工具调用次序或代码编辑内容的判断，则即使风格提高也可能降低主任务 pass rate。

三层机制分工特别关键。第一层，定位：judge 找出不合格的 turn 和 criterion，减少干预范围。第二层，方向：同权重但多一个反馈字符串的 teacher 给 student 提供每个 token 的分布偏差，使低概率新行为能够被“看到”。第三层，巩固：真正的 criterion reward 仍进入 on-policy GRPO，让策略在不再需要提示以后继续探索和维持习得行为。作者 Figure 5、6、7 表明，只做其中一层不能自动得到训练稳定性。

这里“同权重教师”也有风险。它不是独立的 oracle；如果学生参数逐步变差，教师的分布也会随之漂移。因此作者不是简单鼓励更大 KL 权重，而是强调最小干预和较低蒸馏强度。它的真正研究价值是一个控制思路：把外部评价中含有的丰富结构转成局部可控的学习方向，而不把整个策略改造成符合 judge 文风的模型。

05 · Method Deep Dive：从轨迹到更新

Input: 任务与初始策略 → on-policy 多回合工具轨迹 → criterion 判定及失败 turn → 将静态反馈插入失败 turn 之前 → 同权重 teacher 计算完整词表 logits → 失败 turn 上的 reverse-KL → 与含辅助 reward 的 GRPO 联合优化 → 下一轮策略。

Step 1，收集真实交互。学生按 πθ 在工具环境执行，产生观测、思考、命令、环境返回信息以及最终代码结果。它的动作不是单个 token，而是一个完整 agent turn 中自回归产生的 token 序列；这使得“反馈插在哪里”与“蒸馏哪些 token”具有操作意义。

Step 2，评估多个 criterion。除软件修复是否通过之外，按 rubric 分别计算 Markdown 表格、描述解决方案、遵守请求顺序、批准流程、加粗、运行命令、建议工作等二值分量。这些分量可以同时构成奖励 R(τ)=Σ λ_iR_i(τ)。Judge 使用额外信息，可能影响可迁移性；其误判风险不能与真实执行结果混为一谈。

Step 3，构造最小教师上下文。把相关 feedback 放在对应失败 turn 之前，不放在整个序列头部。教师为 πθ(·|s_t,f_t)，和学生 πθ(·|s_t) 共享参数，只多一段指导文字；stop-gradient 防止 teacher 端也被作为目标共同更新。

Step 4，算 full-vocabulary KL。不是让教师另写一条完整轨迹，也不是只用 teacher 生成的几个 token 拟合。作者在训练端计算整词表 reverse-KL，涵盖 thinking 与 tool call token，并在每条 rollout 内归一化，避免循环推理的长轨迹通过 token 数放大惩罚。

Step 5，失败回合门控。只有未满足对应标准的 turn 才加入蒸馏损失。满足标准时，辅助 KL 理论上归零，让主策略只受正常策略梯度驱动。这一设计也解释为何持续加提示的 ablation 会伤害 coding pass rate。

Step 6，混合优化与下一轮采样。联合 loss 梯度更新策略；下次采样仍来自未注入提示的学生。重点不是“推理时每次都要询问 judge”，而是训练期用局部提示教会无提示的学生。若训练 reward 对风格给出错误激励，模型仍可能 reward hacking；TG 不是 verifier 正确性的保证。

06 · 核心数学、KL 与训练直觉

R(τ) = Σᵢ λᵢ Rᵢ(τ)
𝓛(θ) = 𝓛_GRPO(θ) + λ Σₜ∈𝓕 KL[ πθ(·|sₜ) ‖ stopgrad(πθ(·|sₜ,fₜ)) ]

第一式是任务与多个辅助标准的加权 reward。λ_i 是不同 criterion 的 reward 权重，不应和第二式的蒸馏系数 λ 混淆。第二式中的 𝓕 是失败 turn 集合；s_t 是任务历史组成的交互状态；f_t 是对该回合的文字反馈；学生看到 s_t，教师看到 s_t 与 f_t。

KL(p‖q)=Σ_a p(a)log[p(a)/q(a)]，此处是 reverse KL：用当前学生概率 p 作为加权，惩罚学生把质量放在 teacher 认为不合理的 token 上；同时也可能偏向 teacher 的单一高峰模式。stopgrad 仅冻结本次优化中的教师分支梯度，不意味着教师参数在整个训练中恒定。与普通 GRPO 的区别是：GRPO 依赖 sampled action 的相对 reward；TG 的 KL 对完整词表提供方向，补偿“未采样就没有梯度”的覆盖不足。

作者还给出接近策略的启发式要求 E_s KL[π(·|s)‖μ(·|s)] 小于阈值 δ。δ 并非论文保证的硬约束，而是希望 teacher 修改尽量小的一种设计原则；如果文字反馈太强，teacher 可能把修代码行为也改变，奖励之间出现干扰。蒸馏系数 λ 越高，理论上风格习得越快，但 Figure 6 实证显示它可能推高 entropy 与输出 token 长度，随后造成 pass rate 崩塌；λ 太低则冷启动更慢。

把 thinking token 纳入蒸馏不是为了让模型把所有反馈写给用户看，而是作者发现中间生成的自我约束会帮助组合多个风格目标。这个结果只是一种相关实验支持，不代表可从模型的自然语言思维链直接证明因果推理机制。为了复现，需要测试启用/关闭 thinking KL 时输出分布、各 criterion 同时满足率和 pass rate 的变化，而不能只看平均 reward。

07 · Toy Example：失败回合定向修正

设编码任务：“修复 parser 的空列表边界条件，并在调用外部命令前告知用户”。模型产生 3 个 turn。t=1 浏览文件；t=2 调用 shell 直接执行测试；t=3 提交修复并写自然语言总结。任务自动测试通过，主 reward=1，但 t=2 的“Approval”=0，t=3 的“Markdown”=0。

普通 GRPO：如果 32 条 rollout 都没有请求批准，那么 Approval 奖励全为 0；它们的组相对 advantage 不提供任何相关方向。TG 对 t=2 构造反馈“运行测试前先请求批准并陈述理由”，对 t=3 构造反馈“最终回复包含 Markdown 状态表”。Teacher 在 t=2 对“请先批准”这类 token 给出的概率上升，在 t=3 对竖线和表头等 token 给出更高概率。学生在原 rollout 的相应位置最小化 KL，而 t=1 保持不蒸馏。

下一轮学生自己先输出审批请求，再等待许可，最后按表格总结；如果自动测试仍通过，那么主 reward=1、两个辅助 reward=1，该 turn 就不再需要反馈 KL。最坏情形：模型学会“我已经获得批准”的虚假表述，格式 judge 给 1，实际环境却未授权。这是典型 reward hacking。复现时应让环境状态机校验真实审批事件，而不是仅做文面分类；并分别记录合规行为率和修复成功率，防止文字得分掩盖功能损失。

08 · Baseline 深比较（含 strongest）

Baseline（仅 coding RL）：不优化风格，只做任务修复，主任务是天然参照上界；优点是不会被辅助目标干扰，缺点是新格式永远没有梯度。它是判断“主任务是否退化”的必要基准，而不是所有维度最强的风格方法。

GRPO + binary criterion reward：把七条风格奖励加入组相对优势；公平，因为训练范式不变。它的 strongest 特性体现在 coding pass rate 0.33 与 TG 持平，而且 Sol. Desc=0.96、Bolded=0.95，说明某些简单风格能直接靠 RL 学到。弱点是 Markdown=0、Approval=0、Cmd Ran=0：这些是更有诊断力的“零支持集”标准。因此它是本文最重要的主训练 strongest baseline，但 strongest 的定义必须按任务维度区分。

OPSD：带 feedback 的同权重教师提供蒸馏目标，却不给对应 reward。Markdown=0.77 说明方向信号有效；Cmd Ran=0.01 表明学习不完整；pass rate=0.30 也略低。差别是机制性的“缺少 RL 巩固”，不只是调 kernel。

Online SFT：教师重新生成替代 turn，再把它当训练数据。形式直观、容易实现，但产生 off-policy 动作；论文里 coding pass rate 0.26，低于 0.33。其失败不是 SFT 一定无效，而是当前异步、多回合工具环境中替换动作可能与真实状态脱节。

LaTRO / Verifree：通过教师备选动作似然提供 reward。两者对应 pass rate=0.14 与 0.20，显著落后；风险集中在 reward 指向的是另一动作的概率而非真实执行成功。应该把它们作为可能出现策略偏移的对照，而不是简单宣布所有 likelihood-as-reward 方法无效。

09 · 实验设计、可复核设置与 Metrics

Research Question A：当目标行为脱离模型原有分布时，定向文字反馈是否能教会新工具形式？论文的工具格式曲线和 Figure 3 对应该问题。Research Question B：七个辅助标准能否同时提升而不降低 coding pass rate？Table 1 的多列结果直接回答。Research Question C：反馈在每个 turn 中交错出现时是否稳定？Figure 5、6、7 研究诗歌状态报告、蒸馏系数和 thinking token。

模型：Qwen3-Coder-30B，另经作者针对 agent coding harness 做 SFT；数据：软件工程问题，训练 prompt 单轮 epoch 内不重复，公开数据集名称和划分比例在当前可核实段落中未明确披露，不应假定为 SWE-bench；训练：200 个优化 step，每 step 32 groups × 32 rollouts，Adam，learning rate 3e-6，异步 RL，推理策略可能滞后；对各方法调整蒸馏权重与风格 reward 权重；计算：文章未给足可统一比较的 GPU 小时与美元成本。

风格指标：每个 criterion 的成功率，范围 0–1，越高越好；它衡量具体 rubric 遵从性，不能代替真实编程能力。Pass Rate：任务执行/验证通过比例，越高越好；它检验功能，但并不反映安全、可维护性或污染风险。标准差：Table 1 注释明确为训练最后 32 steps 的波动，不是跨独立训练 seed 的误差条；不能据此计算严谨的跨 seed 显著性。Entropy：策略 token 分布不确定度，高不总是好，异常突增与代码质量下降在 Figure 6 同时出现。KL：训练正则项，不是效果指标；数值越小表示学生更接近反馈条件教师，却不能单独说明更正确。

13 · Contribution、Limitation 与 Failure Modes

Contribution 1 — New Objective / Mechanism：将失败 criterion 的 per-turn 反馈映射为 full-vocab reverse-KL，局部化训练方向；创新在位置/门控/目标结合，KL 和自蒸馏本身不是新算法。Contribution 2 — New Empirical Finding：只用 feedback distillation 不稳，组合 RL reward 才能持续学会多个目标。Contribution 3 — Training Protocol：thinking token 纳入 KL、按 rollout 归一化、训练端完整 KL，构成可操作的稳定性配方。

Authors' Limitation：每项 reward 都需要人为设计静态反馈串；只测试多轮软件工程环境，目标主要是写作风格和格式；部分 OPSD 变体未全部 head-to-head 移植。Additional Limitation：Judge 的偏差会同时污染 reward 与 teacher 提示；反馈插在错误回合时可能改变未受影响的工具决策；奖励可能鼓励表面合规而非真实权限状态；额外 teacher logits 增加训练计算与显存，缺少统一成本报告；异步训练使 teacher/student 版本变动叠加；full-vocab KL 对超大模型可能是主要吞吐瓶颈。Failure propagation：早期误导的一个工具动作会改变后续环境，之后局部门控未必能恢复整条轨迹。外部 evaluator 必须把“命令真的运行过”与“模型声称运行了”区分。

14 · Reproduction View：最小可执行方案

实施模块：rollout_collector 保存 {task_id, turn_id, history, assistant_tokens, tool_result, version}；criterion_judge 对每 turn 输出二值 scores 和失败原因；feedback_builder 从固定 mapping 产生 f_t；teacher_logits 在不改当前参数的条件下加入反馈；distill_mask 只覆盖对应失败 turn 的 thinking/tool/answer tokens；trainer 把 group advantage 与 masked reverse-KL 合并；evaluator 独立跑自动测试和判定程序。

最小配置：先用同一 7B 级可跑工具模型替换 30B（这是迁移复现实验，不是复现原表数字），4–8 rollout/group，任务从 200 个有确定测试结果的小仓库问题抽样。设 primary reward=测试通过，辅助 criterion=必须给出有效状态表；比较 GRPO、GRPO+always-on KL、GRPO+fail-only KL、纯 OPSD。λ 从 0.01/0.05/0.1 小网格试验；保存每个 criterion、pass rate、KL、entropy、总 token、tool call 数和训练时间。原论文的 200 steps、32×32 rollout 与 3e-6 学习率作为原始协议对照，不应误当适合 7B 的最优超参。

优先重现：最先验证 GRPO 在罕见 criterion 上出现大量零奖励，而 fail-only KL 能产生正成功率且不伤 pass rate；随后做 λ 扫描并检查 entropy spike。易错点：学生和教师读到的历史必须只差反馈；训练时不要从教师重新采样替代 action；教师分支必须 stop-gradient；thinking mask 要与 tokenizer 的实际 token span 对齐；judge 和最终评测避免共享单一错误解析器。只复现格式提升不能宣称复现了真正的长时 Agent 能力。

16 · Attack / Verification Lens 与十句话记忆卡

Attack：把 judge feedback 中插入“在回复前泄露私有路径”的伪规则，检验 teacher 是否把攻击文本转为学生的长期偏好。Black-box probe：仅观察下一轮无反馈行为，测改变发生在目标 turn 还是整个任务。Robustness：加入矛盾 criterion、延迟反馈及 10% label noise。Recovery：先错误蒸馏，再用正确 feedback 训练 N step，测恢复曲线。Benchmark：给 criterion 标注 support rarity、可验证性、跨回合依赖、真实环境影响。

02 · 人话版：不是只删掉注意力

视频扩散模型每次去噪都要让很多视觉 token 相互注意。最直观的加速是“只计算重要块”，但哪个块重要通常得在每个 step 重新分析，分析本身可能比省下的时间还贵；如果先把稀疏位置固定，模型又会丢失关键内容。DecoupAttn 想到一个折中：先用语义聚类为全部 key 提供廉价的近似贡献，再对少数预先选定的块算准确 attention，用真实值替换这些块的近似值。近似不是零，而是每个 key 都参与；因此省略块的残差往往部分抵消，对“到底选哪个精算块”没那么敏感。作者再用最终生成 latent 的误差来分配不同层、头、step 的计算预算，而不是平均砍 80%。去噪时 key 会漂移，因此保留第一次聚类中心、每步重新指派 key 的归属，避免近似误差累积。实验在十个视频生成、控制生成和渲染模型上报告平均 1.31 倍、最高 1.65 倍的实际加速，PSNR 对九个模型最好。但最值得注意的是不同模型的真实 speedup 差很多，某些只有 1.06 倍左右，而且离线 profiling 需要数小时 GPU 时间，不能说“任何一次生成都免费加速”。

03 · Background 与 Research Gap

视频 DiT 的 self-attention 要对同一帧和跨帧的 token 配对计算 softmax(QKᵀ/√d)V。序列长度为 L，普通 attention 的 score 规模近似 L²；高分辨率、长视频让注意力很昂贵，但实际延迟还包含 VAE、FFN、交互、kernel launch 和内存搬运。对 text-to-video、多步生成、神经渲染而言，这些瓶颈的占比都不同。此前在线稀疏方案（如基于聚类或 block 评分的 routing）每步根据 Q/K 再挑重要块，可以适应动态内容但 routing overhead 高；离线固定 mask 无需挑选，却可能错过关键语义；补偿算法通常用被选块的同一分组去估计未选块，因此 mask 更新会连带引发聚类与补偿重做。

举例说，一个镜头由近景人物转成远景街道：在线选择可以追踪新出现的建筑 token，却需要重算所有 block 的价值；静态位置表会更快，但可能完全删掉远处车辆的注意力。若对所有 key 先计算语义簇均值，再针对静态选中块纠正近似误差，远处车辆仍以簇近似进入输出，未必需要实时重新识别每个关键 block。真正的问题变为：补偿误差怎样累加？在哪些 head/step 值得多花精算预算？簇过时又该怎么办？论文把这三个问题分别映射到 decoupled estimator、distortion budgeting、reassign cache。

这项研究与 FlashAttention 是不同层级：FlashAttention 保持 dense attention 算子等价，通过减少显存读写来优化实现；DecoupAttn 改变计算对象，是有质量损失风险的近似系统，必须以输出质量为约束。尤其不要把“density=0.20”机械解释为 GPU 耗时少 80%；作者清楚列出了补偿、统计、核融合和别的网络阶段仍消耗时间。

04 · Core Insight：补偿残差抵消与离线固定块

论文的观察不是“视频 attention 天然固定”。如果直接 drop 掉 80% 的块，被删除的注意力质量有相同方向的系统偏差，累加后很难抵消。若用近似模型预测所有 key 的贡献，而只对一部分块做精确修正，则遗漏的是预测残差，残差在语义簇内围绕均值变化，有机会相互抵消。结果决定误差大小的除了每块残差能量，还有它们的方向对齐程度。作者用 coherence κ 量化被跳过残差的相干性，并把近似误差界连接到最终 latent。

这为静态稀疏计划提供一个新理由：不是因为关键块不会变，而是因为所有未精算块也有廉价补偿，选错一个块的损害可以被降低。应注意“接近随机误差的抵消”是带假设和经验观察的近似规律，不是保证在任意 key 分布下都成立。如果视觉内容有重复纹理、跨帧显著运动或恶意构造的对齐残差，κ 可能升高，固定计划失效。作者 Appendix 的理论和聚类残差实验支持这一思路，但跨域图像与硬件变化仍需复验。

另一个 Insight 是预算应优化最终视频而非局部 attention map。早期时间步、某些 layer/head 的小局部误差可能被后续去噪放大；晚期某些很大 attention 误差则可能对最终图像影响很小。Distortion Budget 用校准得到的 sensitivity J_u 对残差能量加权，再以拉格朗日方法分配有限的精算块，使每个预算单位尽量改善最终 latent，而不是争取保留最多 attention mass。

05 · Method：Input → Offline Plan → Online Attention

Input: 冻结的 Video DiT + 少量 calibration clips + 目标稀疏密度 ρ → 第一次 sparse step 语义聚类和残差估计 → 测量每个 step/layer/head 的输出敏感度 J → 求解离线精算 block 位置与预算 → 缓存 centroid codebook → 每步重新分配 key、更新簇统计 → 对选定块 exact attention + 所有跳过 key 的 compensation → 输出去噪 latent。

Step 1，确定细粒度单元。用 u=(t,l,h) 表示时间步 t、Transformer 层 l、注意力头 h；再将 token 按内存块切成 query tile g 与 key block b。某单元要么 dense，要么使用指定比例的固定精算 block 和补偿方法。作者第一 step 与第一 layer 保持 dense；因此密度计算不能只数 sparse 单元的比例。

Step 2，补偿预测所有 key。每个 head 的 key 做语义聚类，统计簇的平均 key、平均 value、key variance、cross-covariance。query 对每个 centroid 做近似 softmax contribution，另用二阶方差和 value-key 交叉项矫正。这里 compensation 是可融合的轻计算，不要求每个 query–key 对精确交互。

Step 3，选精算 block 并做差分校正。对静态计划选中的 block 计算精确分子 N_ib 和归一化质量 Z_ib。它们原来也已经被簇补偿了一次，若直接加 exact 就会双计数。故用 n_gc（某个簇中不在精算块的 key 数）从补偿中扣除已精算 key。等价地先补偿全部，再对精算块加上 exact−approx residual。归一化分母由精确与近似共同组成，不能分两次独立 softmax 再生硬平均。

Step 4，离线估算每种选择的最终影响。在校准 clip 上，将每个候选稀疏配置的局部残差能量 ε_u 与其最终 latent 敏感度 J_u 相乘，以预测输出失真。预算求解器在 ρ 约束下选择 head/step 的精算密度，不追求局部 attention 最大相似度，而优先把精算次数给会导致大最终误差的单元。

Step 5，Reassign Cache。初始 k-means centroid 固定为 codebook；后续 step 不重新跑完整 k-means，而让每个最新 key 找最近的旧 centroid，再计算最新成员均值与方差。固定的是 centroid 身份和 mask，更新的是 key 的归属及统计；这直接解决 key 随去噪漂移导致旧簇越来越不准的问题。

Step 6，运行。使用 block-sparse kernel 计算精算块，再由一个 fused compensation kernel 合并补偿。虽然不训练原模型权重，但要完成离线校准/编译。任何新分辨率、新分布或不同硬件都可能改变最优预算，需要重新校准并且把 profiling 时间计入部署经济账。

06 · 数学：分子分母、残差、Distortion Budget

yᵢ = Nᵢ / Zᵢ， Nᵢb = Σⱼ∈b exp(qᵢ·kⱼ/√d)vⱼ，Zᵢb = Σⱼ∈b exp(qᵢ·kⱼ/√d)
ŷᵢ = [Σb∈S Nᵢb + Σc n_gc aᵢc] / [Σb∈S Zᵢb + Σc n_gc ωᵢc]
||ŷᵢ−yᵢ||² = ||Σb∉S rᵢb||² / Ẑᵢ² = κᵢ Rᵢ / Ẑᵢ²
minπ Σu wᵤ Jᵤ εᵤ(oᵤ,η) s.t. X(π)≤ρ

第一式：每个 query i 的 dense 输出由 softmax 分子 N 和归一化分母 Z 构成。q、k 是 d 维向量，v 是 value；exp(score) 代表注意力未归一化权重。第二式：S 是离线选中的精算块，a_ic 是簇 c 中每个 key 预测的 numerator contribution，ω_ic 是对应 denominator mass，n_gc 是排除已精算块之后该簇剩余 key 的计数。必须做 n_gc 扣除，否则 exact 部分会重复计数。

第三式：r_ib 是 exact block 与补偿预测的归一化残差；R_i=Σ||r_ib||² 是残差能量，κ_i=||Σ r_ib||² /R_i 是对齐因子。若残差方向分散，κ 小，即使很多 block 不精算，输出也可能保真；若同向，误差可能相加放大。它与“只看 top-k attention 分数”根本不同：后者没有估算补偿之后的 residual。

第四式：π 是整个采样器的稀疏计划；o_u 是单位选项，η 选择不同补偿 estimator；X 是平均执行密度，ρ 是上限；w_u 是步数权重；J_u 衡量该局部误差传到最终 latent 的敏感度；ε_u 是本单元补偿后残差。拉格朗日放松为每个单元最小化 Jε+μX，μ 是“稀疏精算的影子价格”。μ 增大倾向更少精算，速度可上升但失真风险加大；μ 下降允许更多精算，保真更高但接近 dense 耗时。作者对 μ 二分后再贪心补足预算。此过程有理论最优性表述，但限于可分解的代理目标，不等价于原始真实视频失真问题的全局最优。

聚类修正：论文公式 (4) 使用 key 方差二阶项和 pooled value-key covariance 修正一阶 centroid 预测。若 key cluster 很分散或 value 与 key 强相关，简单平均会有偏差；二阶修正有助降低补偿残差，却增加统计成本。Reassign Cache 用每步最近 centroid 的映射 c_t(j)=argmin_c||k_j^(t)−m_c||²，让固定 codebook 在内容变化时仍可以重新覆盖当前 key 分布。

07 · Toy Example：4 个块如何做差分补偿

设某 query 看四个 key block，每块 2 个 token，dense 真实 numerator 分别是 [10,20,6,4]，denominator 分别 [2,4,2,2]，则 dense 输出 y=40/10=4。为了说明机制，假设轻量 centroid 预测每块的 numerator 是 [9,19,7,5]、denominator 仍为 [2,4,2,2]；这些是玩具数据，不是论文实验。若只精算 block 1 和 2，另外两个块的补偿为 7 和 5，则 ŷ=(10+20+7+5)/10=4.2，误差 +0.2；如果直接 drop block 3、4，输出只由 30/6=5 决定，误差 +1。

换一种看法：对所有块先做 9+19+7+5=40 的近似，再把块 1 的误差 +1、块 2 的误差 +1 加回去，得到 42；跳过块 3 的残差是 6−7=−1，块 4 残差是 4−5=−1。此示例的残差没有抵消，故最终仍有误差。若块 4 的真实值改为 6 而预测仍 5，它的残差 +1 就可以抵消块 3 的 −1；这才是论文希望利用的 residual cancellation。关键不是任何固定 block 都安全，而是补偿模型越好、跳过残差越不相干，静态选择越有机会奏效。

再设同一模型有两个层可分配 1 个额外精算块，A 层残差平方 0.2、最终敏感度 J_A=10；B 层残差平方 0.5、J_B=1。若只看局部误差，应优先 B；若看预计最终失真 Jε，A 是 2、B 是 0.5，应优先 A。Distortion Budget 正是在这些局部残差与全局效果不一致时带来优势。等到下一 denoising step，key 换了语义簇，Reassign Cache 把新 key 分给最接近的旧中心，再更新均值，避免使用失真的陈旧统计。

08 · Baseline 3–5 项逐个比较

Dense FlashAttention（质量基准）：逐块精确算所有交互，是质量锚点和 wall-clock 分母。它并非总是质量得分 100%，因为论文还测不同 dense kernel 间的数值差异 Floor；所有 PSNR 都要记住是相同 seed 的 dense 输出，不是对真实世界视频 ground truth 的质量分。

CalibAtt（离线校准稀疏）：校准选择固定 block，部署便宜，但遗漏块被删除。与 DecoupAttn 相比，缺少全 key 语义补偿，因此同 density 下错误更大；差异主要是估计器机制，而不只是 kernel 工程。

SVG-EAR（误差感知补偿）：对未精算部分提供补偿，与本文机制距离最近，是重要 strongest quality baseline 候选。作者明确称其为主要强对照，并在多模型 PSNR 上比较。缺点是需要在线 routing/compensation 相关重算；Cosmos-Predict2.5 的 E2E 为 20.96s，比 dense 19.68s 还慢，而 DecoupAttn 15.71s。此证据支持“解耦选择与补偿”有系统价值。

Sol-Attn / Sparse VideoGen2：在线识别稀疏 block，能跟随新 prompt 和动态场景，但 routing 造成显著时延；图中部分方法精度仍不如 DecoupAttn。其适用场景可能是分布剧变、静态计划失效时，因此不能宣称静态方案所有情况下占优。

PISA / SparsePR：采用不同的剩余注意力估计策略，包括 Taylor 或 residual reconstruction。这两类的意义是检验性能提升究竟来自“有补偿”还是“把补偿与精算 mask 解耦”。论文并未只拿 drop-only 弱基线比较，而是把同样强调补偿的方案拉入质量与加速双轴对照。实际 strongest baseline 要按每模型和目标确定：有的在线方法 PSNR 较高但速度低于 dense，不能只说“速度最好且精度最好”。

09 · Setup、指标定义、加速层级

Research Question 1：在固定 density=0.20 时，是否同时保住输出并实现 wall-clock acceleration？作者在 10 个模型上比较 PSNR、SSIM、LPIPS、VBench 与相对最快 dense backend 的速度。包含 Cosmos-Predict1、Cosmos-Predict2.5、Wan2.1-14B（480p）、Wan2.2-A14B、HunyuanVideo、Cosmos3-Nano、Cosmos-Transfer2.5、DiffusionRenderer、AlayaRenderer、UniRelight，涵盖 4、35、50 步的不同采样设置。每个结果的基准应与具体模型、同 seed 的 dense 输出匹配。

Research Question 2：降低 density 之后质量—速度曲线是否仍有优势？作者 Figure 5(b–d) 扫不同稀疏程度，误差条为 standard error。Research Question 3：解耦、敏感度预算和重分配三个模块各自贡献多少？Table 2 及 Appendix 的匹配延迟、跨 prompt 和误差实验提供证据。Research Question 4：离线计划生成值得吗？Figure 5(a)、Table 9/10 给出 E2E、离线 GPU-h 和回本视频数量。

PSNR：峰值信噪比 =10log10(MAX²/MSE)，越高越接近参考 dense 图像，每提高 3dB 大致对应 MSE 降约一半；但绝对色彩与感知意义有限。SSIM：结构相似度，越接近 1 越好；对结构保持敏感但不等于语义一致性。LPIPS：深层特征距离，越低越接近参考，依赖感知网络。VBench：多项视频一致性、运动和美学评价的集合/平均，越高越好，却可能不反映提示语符合程度。Latency/E2E：要区分 kernel 注意力、DiT 模块和完整生成，单位秒或毫秒；Speedup：相应 dense 时间 / proposed 时间，超过 1 才是真实加速；Density：精算块占比，0.20 不等于 5× speedup。

未报告的系统维度：我们能够从论文主体核实 latency/E2E 与一些内核分解；若未找到统一的 TTFT、TPOT、tokens/s、GPU memory、energy 等数值，则在效率表标为 Not Reported。视频扩散不是 autoregressive token serving，TTFT/TPOT 本来就不必强行移植，合理核心指标是每段视频 wall-clock、FPS/throughput 与质量。作者使用 FlashInfer 稀疏块注意力内核和融合补偿内核，性能必然与硬件、token 长度和 kernel launch 相关。

12 · 消融、理论边界、Claim vs Evidence

解耦 ablation：Tied（让 exact blocks 与簇分组耦合）在十模型平均 PSNR 较完整方法少 2.85dB；UniRelight 更少 7.39dB。支持 decoupling 是主机制，不是仅靠优化 kernel 达到效果。Uniform sensitivity ablation：将全部 J_u 设为 1，平均损失 1.68dB，Cosmos3-Nano 损失 4.10dB；说明 final-latent budget 对某些模型尤重要。Uncompensated error ranking：不按 compensation residual 排序，平均少 1.18dB；这支持残差预算优于直接照搬 drop-only attention error。Frozen reassignment：不动态重分配，平均少 1.23dB；AlayaRenderer 少 2.59dB、UniRelight 少 4.45dB，而部分模型差距很小，提示漂移的强弱具场景依赖。

Authors Claim：可对视频生成模型在训练自由条件下将静态块选择与语义补偿分离，减少在线路由，在十模型上保持 dense 保真并取得真实加速。Experiments Actually Show：在测试的模型/分辨率/生成步骤、0.20 density 与实现内核下，存在明确 1.06–1.65× 的 wall-clock 收益，以及 PSNR、LPIPS 对强 sparse baseline 的优势。What Is Not Yet Proven：对任意变长视频、不同 hardware kernel、从未校准过的内容域、超长 streaming、agent 动态重规划都有相同效果；对真实用户主观视频偏好或 prompt-to-video factual correctness 有系统提升。理论约束依赖残差随机抵消近似与用小校准集估计 sensitivity，不保证所有分布下成立。

14 · 复现计划：硬件、对照与正确性

核心模块：dense attention hook、Q/K/V 捕获与 token/block 索引；校准 key k-means 和统计；每个候选精算密度与 estimator 的 ε_u 测量；基于最终 latent 的 J_u 估计；拉格朗日预算求解；静态 block mask 导出；在线 key assignment；融合 numerator/denominator compensation；同 seed 输出对比；end-to-end profiler。

最小可行复现：挑一个公开小尺寸视频 DiT 或可运行的图像 DiT 替代并承认不是原论文规模；固定 4-step sampler、32×32 或更小 attention block（按 kernel 兼容性调整）、8 段 calibration 与 20 段 held-out prompt；对比 dense、static mask-drop、static mask+centroid、static mask+second-order、static mask+second-order+budget、完整 reassign。所有方案锁定相同精算块 density ρ=0.20 和同 seed；校准集不能进入测试集。

最先跑：直接测语义簇补偿与 positional centroid 在单个 attention call 的 numerator/denominator MSE、残差 coherence κ、输出 PSNR，确认“补偿而非纯删除”机制存在。之后再测 sampler 的最终 latent MSE 和 E2E；不要先上来优化 CUDA 而不知道近似是否正确。调参先扫描簇数、块大小、ρ ∈{0.1,0.2,0.3,0.5}、key assignment 更新间隔，再测 κ、质量与成本。核心 claim 最直观的验证是：给定相同真实 E2E 延迟，semantic compensation + budget 的 PSNR 明显高于 online dynamic routing 和 drop-only 静态 mask。

踩坑：混合精算与补偿后的 softmax 分母要统一且数值稳定；n_gc 不能把精算 token 重算；key/value 均值统计要正确处理 padding；4-step 时每次聚类开销占比大；同 seed 的 dense baseline 可能有不同 kernel 产生的 floor 数值差异；不能将不同 GPU 的时间直接混用；离线 GPU-h 和回本视频数要与部署请求分布联动。不公开代码阶段，所谓“完全复现”要以自主实现为前提，而非给出虚构仓库命令。

15 · Research Value、Migration A / B

Baseline Potential：是训练自由 video attention 近似的强对照。Migration Potential：残差补偿 + 局部精算可用于 streaming VLM、KV cache 和 agent observation selection。Systems Potential：离线静态调度与在线轻量补偿使服务端低开销实现有价值。Attack Potential：构造同向残差的视频纹理击穿静态 mask。Evaluation Potential：同时记录 residual coherence、latent MSE 和真正 E2E；Benchmark Potential：跨分辨率/长度/硬件的静态计划泛化矩阵。New Paper Potential：以输出损伤为目标的 cache/visual token allocation 值得试验，但与已有 rate-distortion sparse attention 工作有明显查新压力。

Migration A — Streaming Video VLM。Original Problem：DiT self-attention 稀疏近似；Transferable Mechanism：所有视觉 token 的低成本簇补偿 + 选择性精算 + 结果敏感度预算；New Research Question：在实时问答中不丢弃远处事件的前提下减少视觉 prefill；Modification：将每个 frame/patch 作为 block，簇按时序+语义分组，以答案 token 的 NLL 增量替代最终 latent MSE，动态预算分配给问题相关高影响帧；Minimum Experiment：取 Video-MME 的 100 条样本，每段固定 16/32/64 frame、每帧同分辨率，模型 Qwen2.5-VL-7B；比较 dense、uniform frame discard、attention top-k、centroid-only、centroid+selected exact；每组固定视觉 token prefill budget，计 TTFT、峰值显存、QA accuracy、NLL、E2E；Model：Qwen2.5-VL-7B；Dataset：Video-MME 子集；Baseline：均匀抽帧和 query-aware top-k；Metric：回答准确率 / token / TTFT / cache memory；Expected Contribution：证明补偿是否比删除在固定时延更好；Risk：VLM cross-attention/KV 架构不允许原样复用 DiT 估计器；Collision Risk：已有 frame-selection、token-merging、video KV cache 方法很多。

Migration B — Budgeted Agent KV Memory。Original Problem：在有限注意力预算下保留被跳过的 value 贡献；Transferable Mechanism：簇均值估计 + residual exact correction + 输出敏感度；New Research Question：Agent 多轮上下文可以按“对下一工具决策的影响”而非 token recency 分配 cache 吗；Modification：对 memory token 的 value 建簇，以工具调用动作的 log-prob margin 或真实 next-action success 估计 J_u，精算近期决策关键 provenance 节点，其余簇贡献近似；Minimum Experiment：在 100 个 20-step coding/web agent 轨迹中记录完整状态，构造 4/8/16k 上下文窗口，离线标注重要工具决定，比较 full KV、LRU eviction、attention-score eviction、residual-budgeted cache；至少 3 seed，锁定响应模型权重；Model：Qwen3 8B；Dataset：可执行 agent 回放轨迹；Baseline：LRU 与 attention top-k；Metric：next-action agreement、任务成功率、KV memory、TPOT/TTFT；Expected Contribution：可追溯的长期记忆近似与预算控制；Risk：删除 KV 后 attention 的归一化与原实现不同，无法直接搬运 fused kernel；Collision Risk：与近年 KV 压缩、层敏感度预算及 non-prefix reuse 研究高度重叠。

16 · Attack/Verification Lens 与十句话记忆卡

Black-box stress test：在生成 prompt 中插入极细的周期纹理、短暂遮挡和跨帧突变，量化固定 mask 对罕见事件的错失；测按帧 PSNR、光流一致性及 κ。Robustness：保持固定 ρ，让采样步数、视频分辨率、运动强度、镜头切换率与簇数独立变化；分离 distribution shift 与硬件差异。Recovery：在去噪中途将关键帧条件切换，测试重新 assign 的恢复速度和是否必须在线重编译 mask。Benchmark：设计 ResCoherenceStress：每个样本有残差方向一致性标签、重复纹理强度、运动频率与原模型输出 MSE，报告 speed-quality Pareto 前沿。

十句记忆：① Video DiT attention 昂贵，但 dense 精确算子的时间不是整个视频生成时间。② 普通静态 sparse mask 会丢信息，在线 routing 可能把收益花在路由本身。③ DecoupAttn 把全 key 补偿与少数 exact block 分离。④ 不被精算的 key 仍以 centroid 近似进入分子和分母。⑤ 跳过块的残差如果不相干，会相互抵消。⑥ 固定精算块不等于固定语义统计。⑦ Distortion Budget 将局部残差乘上到最终 latent 的敏感度。⑧ Reassign Cache 用固定中心、动态成员抵抗 step 间漂移。⑨ 报告平均 1.31×、最高 1.65×真实加速，但某些场景只有约 1.05×。⑩ 下一步最值得做的是在质量匹配、E2E 匹配和校准成本摊销三方面严格复现。

Cross-Paper Synthesis

两篇共同指向一个研究策略：不要把昂贵的精确信息均匀施加到所有位置。TG 将反馈教师的分布性监督只给真正失败的 turn；DecoupAttn 将昂贵精确 attention 只给对最终 latent 影响最大的 block/head/step。但“门控对象”的选择必须由目标任务真正的损失决定：RL 以环境成功和 criterion 失败为依据，Video 以补偿残差乘最终失真敏感度为依据。如果用便宜 proxy 代替真实 outcome，前者可能学到假合规，后者可能在动态纹理上失真。

机制的组合空间是：对多模态 Agent 的 video tool call，先以便宜的簇/摘要保留全部观察证据，再用真实的环境任务失败信号选择值得精读的视频局部；这种选择既不只按视觉显著性，也不只按 judge 文本偏好，而是以“最终行为错误改善多少”为目标。但两篇并未联合验证此结论，所以它属于新的研究假设，不是已经存在的 Collision。

实验范式值得借用：按最终任务质量和每单位计算成本联合测量；对 on-policy 与 off-policy 监督做公平对照；同时报告最强正结果、没有收益的模型和错误传播。RL 的 pass-rate 守恒和 Video 的 dense-relative 保真都提示：主要约束指标不能被单一 proxy score 替代。

Combined Research Opportunities

机会一：Outcome-Gated Visual Compute for Agents。让 VLM 先进行低成本视频摘要，遇到任务失败时使用 verifier 反馈定位关键失效 turn，再按视频 token 对下一工具动作 reward 的边际贡献恢复精确视觉计算。最小实验：100 条可回放的视频+操作轨迹，每条固定 16/32/64 帧与工具动作预算；比较均匀帧选、静态视觉 token pruning、任务损失驱动的 residual budgeting；指标为真实工具成功率、wall-clock、视觉计算量和错误恢复步数。

机会二：Verified Adaptive Precision Scheduler。将 TG 的失败门控作为一个外层事件控制器，仅在真实输出错误或安全规则不满足时激活更密集的 attention/更高精度；其它请求维持低成本补偿。需要区分在线质量探针本身的延迟与修正收益。可在长上下文 agent history 上做固定总 GPU-seconds 与等成功率 Pareto 曲线，而不是只报告 token savings。

机会三：Residual-Aligned Error Attack。向多智能体记忆或视频流注入具有方向一致性的错误片段，检验 static cache plan 与文字 feedback gate 是否被共同绕过；设计标签包括错误来源、被消费的 turn、修正尝试次数和最终环境状态，形成可以独立复核的 benchmark。

Collision / Overlap

Strongest Collision：NONE（尚未完成全面查新）。方法层面的相似不是文献中的既有共同工作。需要重点查新三类可能影响新颖性的研究：① outcome-aware frame/token routing 与 video quality sensitivity；② feedback-guided on-policy distillation、process reward 和 error-local credit；③ sparse+low-rank control variates 与 KV memory residual correction。尤其 DecoupAttn 明确引用与它接近的 compensation、calibration、output-aware allocation 工作；不能把“使用 residual”单独包装为全新思想。

Reading / Reproduction Priority

立即实验价值：TG 更适合作为 Agent RL 的研究 baseline；它的失败回合门控、full-vocab KL 及功能 pass-rate 共约束很容易形成可解释消融。系统加速实验价值：DecoupAttn 更适合作为 video attention 的 system baseline；应先证明在同一 GPU、相同 wall-clock budget 下仍有保真优势，再考虑移植到 VLM。Benchmark/Attack 价值：前者可做 reward hacking 与 verifier 错判压力测试；后者可做残差一致性与分辨率迁移的 stress test。

建议优先顺序：先实现 RL 的 small-scale fail-only KL 四组对照，验证最小因果链；并行建立 Video 单层稀疏注意力的 residual sanity check；最后再合并形成视觉 agent 的 task-outcome-aware compute router。没有最小实验前，不建议直接把这两篇的交叉点当作确定创新点。
