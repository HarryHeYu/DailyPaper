论文 1｜CoT-Proxy：只蒸馏教师动作与短摘要，推理时仍用学生自己的思考 NEW Agent / Multi-Agent

1. 基本信息

标题：CoT-Proxy: Cross-Format Transfer for Distilling Long-Horizon Policies
作者：Dawid J. Kopiczko，Tijmen Blankevoort，Yuki M. Asano（University of Technology Nuremberg；NVIDIA。邮箱 dj.kopiczko@gmail.com）
arXiv：来源：abs · pdf · html · 21 页 · 提交 2026-11-24 · cs.CL
代码：Not Reported
方向：Agent / Multi-Agent（长程策略蒸馏，交叉 continual learning）

2. 一句话定位

封闭教师的思维链往往不可见，于是这篇论文证明：把每一步的 think 块留空、只监督教师动作（再可选地在空块之后放一段短摘要），再加域外 replay 上的 KL，就能把长程策略蒸馏进已经会单轮推理的学生；推理时学生仍用自己的思考风格去执行教师的行动，作者称为 cross-format transfer。

3. 人话版

可以把学生想成一位已经会解奥数题、但还不会连续操作一堆日常 App 或修补真实仓库的助手。老师更强，可是老师若是封闭模型，你看不到他的草稿纸，最多拿到一句 API 返回的推理摘要和最终要执行的命令。常规做法是让学生模仿老师的整段思考，这里换成另一种教法：训练时把「思考栏」先盖住，只让学生抄老师按了哪个按钮；有时再在按钮前贴一张两句话的便利贴，说明老师当时的判断，但便利贴不许写进思考栏。为了不把学生原来的解题能力冲掉，每个更新里还混进几条学生自己在数学或聊天题上的旧答卷，用 KL 把它拉回初始模型。考试时把思考栏打开。出人意料的是，学生并不会在测试时再写那张便利贴，却仍然会用自己的口吻思考，并更像老师那样行动。

4. 背景与缺口

语言模型作为智能体时，通常跑在一个提供工具、执行动作并管理历史的 harness 里。得到长程策略的主流路线是环境内强化学习；对更小的模型，更便宜的替代是在更强教师的轨迹上做监督微调。标准配方会同时模仿思维链、可见评论和动作。作者关注的学生已经是后训练过的推理模型：单轮推理不弱，但长程任务很弱。这时蒸馏变成持续学习问题——既要加上新能力，又不能丢掉旧能力。

缺口有两边。第一，最强教师常常是 API 后的封闭模型，推理项被加密，至多返回摘要，加密的目的之一正是阻止这类蒸馏。第二，即便开放教师给出完整 CoT，小模型也未必适合模仿强推理者的痕迹。另一方面，已有安全文献观察到：在关闭思考的条件下微调狭窄的不良行为，重新打开思考后不良对齐仍会泛化。作者问的是同一机制能否用来迁移有用的长程策略；其经验动机是，长任务失败有时被归为执行而非推理，因此真正需要教的可能只是动作。

5. 核心 insight

关键不是「不要推理」，而是「不要监督教师的推理」。空 think 块在训练时被预填且不计入损失，它只是给后面的动作提供条件，并不会教学生去写空块。同一套表示会套到轨迹里每一个历史回合上，避免教师思考从上下文泄漏。推理时只预填开口 token，学生自己填思考，并把它保留到后续回合。若再把教师推理的短摘要放在空块之后、动作之前，学生得到的是关于「为何这样行动」的信号，而不是对 CoT 本身的模仿。作者强调：摘要必须待在 think 块外面；一旦放进去当短 CoT 用，收益会明显下降。

6. 方法逐步拆解

一步，把教师轨迹写成三种训练目标（图 1）。Full-CoT 是常规目标：think 块里放教师思考，开口之后的思考、结束符和动作全部监督。Action-only 预填空的 <think></think>，只监督随后的动作。CoT-proxy 保留这个空块，再在空块与动作之间插入 <summary>…</summary>。开放教师的摘要离线生成：教师只看到当步完整思考，看不到任务、动作、观察和后续结果，并被要求用至多两句概括「最终看法与下一步」。封闭教师则直接使用 Responses API 在 reasoning effort xhigh、summary=detailed 下返回的摘要，按返回顺序拼接，不做缩短或过滤。

二步，所有目标都把可见回复剥到解析出的单个代码块动作。教师常会在动作外写一句预告或解释，作者认为那是另一种形式的推理，留下会模糊「只学动作」与「也学 CoT」的对比；第 5 节显示留下这些文字会降低任务成功率。

三步，用固定的域外 replay 做持续学习正则。微调前，初始学生在 OpenR1-Math 与 OpenAssistant 的提示上生成 1,000 条回复（另持出 100 条测漂移）。每次更新混入 17 条教师轨迹和 3 条 replay（15%）。教师样本走交叉熵，replay 样本走把学生拉向初始模型的 KL。LoRA 下初始分布来自关掉 adapter 的同一基座，多一次前向，不必复制权重。作者特别强调 replay 必须来自目标环境之外：若用学生自己在 AppWorld 训练任务上的轨迹做正则，等于把要改的策略按在原地。

7. 核心公式

记一次更新里教师样本与 replay 样本的被监督位置集合为 𝒯 与 ℛ，Nt=|𝒯|，Nr=|ℛ|；位置 i 的上下文与目标 token 为 hi、yi。最小化

ℒ(θ)=−1Nt∑i∈𝒯logpθ(yi∣hi)+1Nr∑i∈ℛKL(pinit(·∣hi)‖pθ(·∣hi))

第一项是教师目标上的平均 token 交叉熵；第二项是 replay 上、对完整词表的 KL，把当前学生拉向初始学生。两项各自按自己的 token 数归一化，避免一边样本更长就主导梯度。直觉上，动作（和摘要）负责写入新的长程策略，KL 负责把单轮能力钉在初始模型附近。该惩罚只需要初始学生的 logits，不需要教师，因此对封闭教师同样可用。

8. Toy example

假设某一步教师的思考是「测试证实了问题；Number.serialize 在传入 None 时失败，因为它没有被当成 colander.null。计划修改该方法，使 None 与 null 同等处理。」动作则是一段补丁命令。Full-CoT 会让学生在 think 块里逐字学这段思考。Action-only 看到的是空 think 块加那条命令。CoT-proxy 在空块之后放两句摘要，例如「Number.serialize 只检查 colander.null，因此在 None 上失败。计划两者都接受。」（这是附录 A 提示中的示例，不是某次测试轨迹的逐字摘录。）推理时学生仍先写自己的「Okay / Wait / Let me」，再发出命令，而不会把 <summary> 标签写出来——因为训练里摘要总是条件在空 think 块上，测试时这个上下文不会出现。

9. Baselines

  • Initial：未经环境蒸馏的 Qwen3-4B-Thinking-2507 与 Qwen3-32B，思考默认打开。这是能力保留和增益的参照。
  • Full-CoT：标准轨迹模仿，监督教师思考与动作。封闭教师没有这一项，因为完整 CoT 不可见。
  • Action-only：本文的最小配方，证明「只学动作」也能迁移策略。
  • CoT-proxy：在 Action-only 上增加块外摘要；开放教师用自摘要，封闭教师用 API 摘要。
  • 对照变体（消融，不是主基线）：0% replay、域内 replay、把摘要放进 think 块（summary as CoT）、打乱摘要、保留可见文本、关闭思考评测。

教师本身也列出：开放教师 Qwen3.6-27B，封闭教师 GPT-5.6 Luna。它们是数据来源，不是被对比的学生方法。

10. 实验设置

两个环境分开实验。AppWorld 用官方 test-normal：168 个任务、56 个场景；训练是官方 90 个训练任务，每位教师各滚三次，得到 270 条轨迹（开放教师 3,704 回合，封闭教师 4,218 回合）。SWE-bench Verified 报 500 题的解决率；训练从 SWE-rebench 抽取，并去掉 SWE-bench 所用的 12 个仓库。开放教师各跑一次，250 条轨迹、8,993 回合。封闭教师在 SWE-bench 上扩大收集：500 个训练任务各跑八次，4,000 条中只保留成功的 2,970 条，训练五遍，因成本只跑一个种子。Harness 对教师、初始学生和训练后学生相同：AppWorld 跟官方 ReAct 并采用 LOOP 的 one-shot 演示，SWE 改编自 mini-swe-agent。

训练配方对所有配置固定（表 10）：LoRA rank 16、alpha 32，覆盖全部线性层、无 dropout；bf16 基座、fp32 adapter；AdamW，学习率 3e-5，两次 warmup 后恒定，梯度裁剪 1.0；上下文 32,768（32B 为 20,480），按完整回合前缀截断，保证三种目标监督同一组回合；教师样本默认 8 遍（AppWorld 128 次更新，SWE-bench 118 次）。评测（表 11）思考开启，温度 0.6、top-p 0.95、top-k 20；AppWorld 最多 50 回合，SWE-bench 75 步；每步至多 8,192 输出 token；模型上下文 65,536（32B 为 40,960）；累计 transcript 预算 40,960，观察截到 3,000 token，墙钟 2,400 秒/题。单轮保留测 AIME 2025（每题 4 个样本，共 120 个答案）、IFEval，以及 MMLU-Pro 的 1,000 题分层子集。除封闭教师的 SWE-bench 外，均报三种子均值与标准差。

11. 指标教学

TGC是 AppWorld 的任务目标完成率，文中也直接称为 task success。SGC要求一个场景里的全部任务都成功，更严。Verified (%)是 SWE-bench Verified 的解决率。Turns是每题平均模型回复数，不是越长越好：Full-CoT 往往步数最多，却不是最成功。In budget是轨迹在用尽累计上下文 token 预算前结束的比例；在预算内结束不等于成功，初始模型常有 80%–99% 的 In budget，但解决得最少。KL是持出 replay 上、相对初始模型的平均每 token 散度，表 3 以 10−3 nats 为单位。配对检验（表 16）在相同任务与匹配种子上比较目标：差值对三种子平均，95% 置信区间来自对任务（AppWorld 上重采样整个场景）的 10,000 次配对 bootstrap，p 值来自配对置换并在开放/封闭教师比较内做 Holm 校正。

16. 贡献

  • 给出一套不监督教师 CoT 的长程策略蒸馏配方：空 think 块、动作监督、域外 replay 上的 KL，并在 4B 与 32B 推理学生上观察到 cross-format transfer。
  • 提出 CoT-proxy：把教师推理的短摘要放在思考块外，作为额外监督信号；在所报设置中相对 Action-only 均有提升。
  • 同一配方适用于封闭教师，只使用可见输出和 API 摘要，并在 GPT-5.6 Luna 上给出 AppWorld 与 SWE-bench 结果。
  • 系统消融了 replay 比例与来源、摘要位置与来源、可见文本，以及训练目标如何改写学生在推理时的思考长度与措辞。

17. 局限

证据集中在 AppWorld 与 SWE-bench Verified 两个长程环境，学生也只覆盖 Qwen3 家族的 4B / 32B。封闭教师的 SWE-bench 是扩大数据后的单次运行。Full-CoT 与 CoT-proxy 的差距多数不显著，不能把「代理摘要优于完整 CoT」写成通例。CoT-proxy 会把思考中位数压得很短，是否伤害需要更长探索的任务，本文没有另做基准。训练墙钟、学生侧 GPU 类型与代码均为 Not Reported。伦理声明提醒：提供商条款可能限制用输出训练其他模型，作者自称只使用任何用户都能从 API 拿到的可见回复与摘要，并未试图恢复被加密的推理。

18. 复现要点

先固定 harness、提示、预算和评分器，再只改变训练目标。轨迹要以完整历史为一件样本，三种目标截断到同一组完整回合。空 think 块必须预填且无损失；摘要若使用开放教师，标注器不能看见动作和结果，并执行附录 A 的两句、字数和特殊标记过滤（最多重试三次，否则写空摘要）。封闭教师需回传先前回合的加密 reasoning items，summary 设为 detailed。Replay 必须来自域外，建议 15%、每更新 17+3。评测一律开思考；若要核实 cross-format transfer，不要在测试时再预填空块。能力保留至少应看 AIME / IFEval / MMLU-Pro 与持出 KL。没有官方代码，复现成本主要在教师滚轨迹、摘要标注（表 9：开放教师 AppWorld 7.5、SWE-bench 17.6 个 H100 GPU-小时）以及 4B / 32B 的 LoRA 训练，后者开销 Not Reported。

19. 研究价值

对把推理模型改造成长程智能体的路线，它提供了一个很实际的切口：当教师 CoT 不可见或不宜模仿时，仍然可以做监督式策略蒸馏，而不必先上环境内 RL。它把安全文献里的 cross-format transfer 翻成能力迁移工具，并给出可操作的放置规则——摘要在块外有用，在块内是差的短 CoT。对提供商来说，结果也说明「隐藏 CoT、只给摘要」并不能完全阻止策略层的蒸馏。

20. 可执行迁移

  • 蒸馏封闭编码 / 办公智能体时：不要强行恢复隐藏 CoT。先把可见回复解析成纯动作，空 think 块加动作做 SFT，再用 API 摘要做成块外 <summary>；务必加域外 replay KL，避免把数学和遵指令能力冲掉。
  • 不要用学生在目标环境里的失败轨迹做 replay。表 4 显示那会把策略钉死。Replay 应来自希望保留的能力域（数学、聊天、指令遵循）。若没有教师思考，也可用事后解释，但只预期收回大约三分之二的摘要增益，且仍须把可见套话剥掉。

21. 方向专用分析

昨日的 Harnesses 论文问的是：神经符号编排能否把短任务上的训练组合成更长、跨域的行为。今日这篇问的是另一个 Agent 问题：在已经存在的 ReAct / mini-swe-agent 套件里，如何把更强教师的长程策略写进小推理模型，尤其是教师不肯给出 CoT 的时候。它几乎不做多真多智能体协议，核心是「教师—学生」的策略转移，以及思考格式在训练与推理之间的错位。和深度优先 / Evolving Harnesses 那些改搜索或改工具层的工作相比，这里改的是监督信号的格式。

22. Attack / Verification

可核查点包括：表 1–2 是否三种子（SWE 封闭教师除外）、TGC 与 SGC 是否被拆开、In budget 是否被误读成成功率、表 16 的显著性是否被摘要忽略、关闭思考后增益是否还在（表 13）、打乱摘要是否仍有同等增益（表 14）。攻击或误用角度上，同一机制也可以迁移不良策略：安全文献已经表明，关思考微调狭窄不良行为会在开思考后泛化；本文等于展示了正向迁移，也就暗示摘要与动作日志足以泄漏教师策略。验证封闭教师实验时，还应核对其是否只使用了 API 摘要而非任何隐藏 token 还原。

论文 2｜U-Statistics-Powered LLM Reasoning：把 GRPO 的 group size 做成可估计的方差比，并用悲观规则稳住小分母 NEW Reinforcement Learning

1. 基本信息

标题：U-Statistics-Powered LLM Reasoning
作者：Shijin Gong（中国科学技术大学），Kai Ye（伦敦政治经济学院），Victor Chernozhukov（麻省理工学院），Xinyu Zhang（中国科学技术大学 / 中国科学院），Chengchun Shi（伦敦政治经济学院）

2. 一句话定位

这篇论文把 GRPO 的策略梯度写成二阶 U-统计量，从而把「在固定采样预算下如何选 group size」变成估计方差比 c3/c1 的经典统计问题，并在分母偏小时用带标准误惩罚的悲观估计，避免去偏后的比值爆炸。

3. 人话版

想象每次更新你只能批改固定数量的答卷。你可以少出几道题、每道题让模型连写很多份（组大），也可以多出几道题、每道题只写几份（组小）。组大时，同一道题内部的奖励基线更稳；组小则能看到更多不同的题，题与题之间的差异不会被「题目太少」放大。作者证明，最优的组大小几乎只取决于两类波动的比值：题与题之间差多少，以及同一道题里答卷还抖多少。麻烦在于，前一种波动往往很小，直接相除时分母一被估低，你就会误以为该用特别大的组。去偏看似更「正确」，但在分母接近零时反而更不稳。于是他们改成悲观原则：选组大小时，不只看估计出的梯度误差，还要加上这份误差的标准误，专门惩罚「分母看起来太小、组会被选得过大」的情况。

4. 背景与缺口

GRPO 由 DeepSeekMath 提出，并随 DeepSeek-R1 成为训练大推理模型的主流策略梯度算法，后续还有 Dr. GRPO、GSPO、GPG 等变体，也被用到智能体设置。它的核心是随机梯度上升：每步抽一批提示，再为每个提示抽一组回复，用组内相对表现构造梯度。计算成本主要在生成长推理轨迹。固定每步总回复数后，组变大意味着提示变少，组变小则提示更多、每题回复更少，这是真实的权衡。尽管算法很成功，组大小这个超参大多仍靠试错。

缺口因此很具体：缺少对组大小的原则性选择规则，尤其是最优值会随数据集和训练阶段变化（图 3）。作者把该问题接到 U-统计量与 Hoeffding 分解上，并指出朴素的方差比估计在分母较小时会不稳定。这与 11-24 的 CreditFilter（按熵排序做信用校准）和 11-19 的 ASH（activation steering 加 hint 增强的 GRPO）都不同：本文不改优势怎么分配给 token，而改每步预算如何在「更多提示」与「每题更多回复」之间切开。

5. 核心 insight

第一，单个提示上的 leave-one-out 梯度是二阶 U-统计量，因而整步梯度的 MSE 可以精确拆成三项：c1/B（提示间）、c2/(BG)（一阶投影）和 c3/(BG(G−1))（二阶退化项）。固定总预算 N=BG 时，中间项与 G 无关，最优组大小有闭式 G*=1+c3/c1。第二，c1 往往远小于 c3（表 1 中 GSM8K 的比值已达 290.93），去偏虽然能去掉有限组偏差，却也可能让分母非正，从而把组大小推到上限。第三，把每个候选 G 看成多臂赌博机里的臂，最小化带标准误的损失上界，可以在正则体制下保持与去偏相同的多项式速率，并在弱信号体制下避免最坏的超额 MSE。

6. 方法逐步拆解

一步，先写清简化版 GRPO。提示 X 来自训练集经验分布，补全 Y~πθ(·|X)，奖励 Z=r(X,Y)。目标是最大化期望奖励。策略梯度为得分函数乘奖励的期望；REINFORCE 用单条补全做蒙特卡洛，方差大。PPO 一类方法会另训价值网络，成本高。GRPO 改为对每个提示抽 G 条补全，用组平均近似价值。正文采用 leave-one-out：第 j 条的基线是其余 G−1 条的平均奖励，以保持无偏。若把自身奖励也算进组平均，期望会变成真梯度的 (G−1)/G。

二步，做试点估计（算法 1）。试点用小写 b,g,n=bg，真正的梯度估计用大写 B,G,N=BG。只在更新集合 𝒯 上重估组大小，其余迭代沿用上次的 G。实现里在 t=0,25 以及此后每 50 步估计一次；t=25 的额外一次是因为作者观察到第 0 步常选出对后期偏大的组。试点样本不复用到随后的梯度估计，以避免组大小与梯度之间的依赖。

三步，比较三种规则。有偏规则把有限组估计直接代入缩放律，并截断到 Gmax。去偏规则先用线性关系 𝔼(𝐜^)=A𝐜 求 𝐜~=A−1𝐜^；若 c~1≤0 则直接取 Gmax，否则把比值下截到 1、上截到 Gmax。悲观规则在去偏损失上加 kσ(G)，并用 (c~1)+ 强制分母项非负；实现里协方差用分组 jackknife，k 取 90% 标准正态分位数。还可以给 τ^1 加地板，防止小样本把不确定度估成接近零。

7. 核心公式

期望奖励与策略梯度（式 (1)(2)）是标准形式。GRPO 的 leave-one-out 梯度（式 (4)）为

𝐠^B,G(θ)=1B∑i=1B[1G∑j=1G∇θlogπθ(Yi,j|Xi)(Zi,j−Z¯i,−j)]

引理 1（GRPO 缩放律）给出 MSE 的三项分解，以及固定预算下的最优组大小：

MSE{𝐠^B,G(θ)}=c1B+c2BG+c3BG(G−1),G*=1+c3/c1

其中 c1=𝔼‖𝐠(X;θ)−𝐠(θ)‖2 是提示间变异；c2、c3 来自组内的一阶与二阶项，三者都不依赖 B,G。有偏估计 c^1 的偏差为 c2/g+c3/(g(g−1))（式 (7)），是正的、阶为 O(g−1)。悲观选择规则（式 (16)）最小化

Qk(G)=G(c~1)++c~3G−1+kσ(G),2≤G≤Gmax

其中 σ2(G) 是去偏损失 ℓ^(G)=c~1G+c~3/(G−1) 的方差（式 (15)）。用 Cauchy–Schwarz 把 σ(G) 换成上界后，可看到闭式直觉（式 (17)）：分子分母都加上 k 倍标准误，分母被抬离零，过大的 G 会被劝退。超额梯度 MSE 定义为相对最优组的归一化增量（式 (13)），并可写成 ℛ(G^)=𝔼{c1(G^−G*)2/(G^−1)}，因此高估组大小比低估更便宜。

来源：abs · pdf · html · 式 (4)–(7)、(15)–(17)；引理 1

8. Toy example

假设某一步测得 c3/c1=6.97（表 1 里 Reasoning Gym 的进制转换），则 G*=1+6.97≈3.6，固定组 4 已经接近最优。若换成 GSM8K 的 290.93，最优大约是 1+290.93≈18；DAPO-Math-17k 的 507.31 则大约是 24。现在想象试点里 c~1 被估成接近 0 甚至为负：去偏规则会直接跳到 Gmax，提示数被压到极少，提示间方差项 c1G/N 被放大。悲观规则会在分母上加 ksd(c~1)，相当于拒绝「分母可能只是估低了」这种过于乐观的大组。图 3 也显示，同一数据集在不同 checkpoint 上的 MSE–G 曲线最低点会移动，所以组大小不该在整段训练里锁死。

9. Baselines

  • 固定组大小：策略优化实验比较 G∈{2,4,8,16,32,64}（DAPO 与代码实验从 4 起）。这是最直接的试错基线。
  • 有偏方差比：忽略有限组偏差，分母天然带一层正的缓冲，弱信号时反而更稳，但 g 不够大时会系统性偏离 G*。
  • 去偏方差比：纠正式 (7)(8) 中的偏差，正则体制下更快，弱信号时可能选出 Gmax。
  • 截断 / 带地板的悲观估计：主方法。梯度 MSE 实验里比较 ϵ0=0 与 ϵ0=1000/(gb)；策略优化主结果采用截断悲观（ϵ0=0）。

没有把 PPO 价值网络或完整 Dr. GRPO / GPG 当作下游对照；正文明确理论针对简化 GRPO。

10. 实验设置

两部分。梯度估计（第 5.1 节、附录 B.1）：先用标准 GRPO 后训练 Qwen2.5-1.5B-Instruct，再在 19 个 checkpoint 上评测（Reasoning Gym 的进制转换 / 质因数分解 / 小数运算取第 0/50/100/150 步，GSM8K 取 0/150/300/450，方程、分数、骑士与无赖取第 50 步）。真梯度用 1024 个提示、每提示 256 条补全的蒙特卡洛近似。试点 b∈{8,16,32,64,128}、g∈{4,8,16,32,64,128}，梯度预算 N=512，每个选中的 G 再独立抽 256 次梯度、用样本协方差的迹估 MSE，整个过程重复 25 次。奖励为任务二元校验器，温度 1。相对超额 MSE 的「oracle」用六个固定组以及各方法平均 MSE 的最小值近似，因为对每个整数 G 做精确 oracle 成本过高。

策略优化：Reasoning Gym 与 GSM8K 上仍用 Qwen2.5-1.5B-Instruct，N=512，最长短度 512，学习率 10−6，前者 200 次更新（每任务 2,000 道测试题），后者 500 次（1,319 道测试题），五种子，贪心解码。数学推理把 Qwen3-8B 先在 496 条数学解上做一轮 SFT 以缩短轨迹，再在 DAPO-Math-17k 的 800 题子集上训 300 次，长度 4,096，N=256，试点 (b,g)=(32,32)，单次运行。代码用 DeepSeek-Coder-1.3B-Base 在 AceCode 上训 500 次，长度 1,024；按原文 hard-example 手续得到 21,880 题，随机 5,000 作测试、16,880 作训练，各方法共用划分，单次运行。全部实验在 NVIDIA GH200 集群上。

11. 指标教学

梯度 MSE是 𝔼‖𝐠^−𝐠‖2；因 leave-one-out 估计无偏，它等于协方差的迹。相对超额 MSE是相对近似 oracle MSE 的增量再除以该 oracle，用于在不同 checkpoint 间比较。测试准确率在 Reasoning Gym / GSM8K 上是贪心正确率；表 2 对 MATH500（500 题）、Minerva（272）、OlympiadBench（675）报贪心，对 AIME 2024/2025（各 30）、AMC 2023（40）、HMMT Feb 2024/2025（各 30）、BRUMO 2025（30）、CMIMC 2025（40）报 Average@16（温度 0.6）。表 5 同时给 greedy、Average@8 与 Pass@8（八个样本，温度 0.6）。Time share是试点估计占该次运行墙钟的比例，不是固定组方法变慢的倍数；加权按 GPU 数后，组大小选择约占全部 GPU-小时的 8.1%。

14. Ablation

主消融是估计器本身，而不是网络结构。图 5 已表明：两边样本都小时去偏最差（弱信号）；样本足够大时去偏与悲观接近，有偏仍需要够大的 g。附录把地板与 k 再扫一遍：完成尺度地板主要在 b,g 都小时介入；扩大地板在 b 小而 g 大时提供额外保护。策略优化主文选择截断悲观而非带地板版本，因此表 2、4、5 不应被读成「已经用上最优地板」。另一个隐含消融是更新日程：如果每步都做试点，成本会高得多，所以他们只在稀疏的 𝒯 上估计。

15. Claim vs Evidence

「自适应组大小改进优化」在表 4 的四列与均分上最干净（五种子）。表 2、5 支持「总体更好」，但不支持「每个子基准都最好」：数学十项里赢六项，代码贪心均分甚至略低于 G=32。摘要只说降低梯度 MSE 并改进优化、额外开销有限，这与 27/30、表 6 的 7.03%–10.33% 相符，但不要把 8.1% 说成对固定组墙钟的 8% 减速——它是估计时间占自适应运行总时间的份额。理论保证依赖有界奖励、有界得分范数和固定维度（假设 1）；实现里表 1 只在最后四块上算方差，主训练是否全程如此，正文没有另给一张实现表，超出部分记 Not Verified。DAPO 与 AceCode 为单次运行，缺少种子误差。代码未发布。

16. 贡献

  • 把 GRPO 梯度的 MSE 写成与 group size 相关的三条方差项，并给出最优组大小的闭式缩放律。
  • 系统比较有偏与去偏方差比，指出去偏在弱信号下可能让分母非正、把组推到上限。
  • 提出悲观估计，并在三种样本量体制下刻画超额 MSE 的速率（定理 2–3，细节见附录重述）。
  • 在合成推理、数学与代码后训练中显示，自适应组可以降低梯度 MSE 并提升总体测试表现，试点开销约在百分之几到百分之十。

17. 局限

讨论写得很清楚：分析针对简化 GRPO，省略了奖励方差归一化、回复长度归一化、PPO 式小批次和 KL 正则，优化器是经典 SGA 而不是 Adam。预算分配只发生在一步之内，没有联合优化「每步采多少」与「训多少步」。每个提示共用同一个 G，而不同题目的奖励波动可以差很多。试点的 g 本身也有最优尺度（约 c1−1/2），文中只作为未来工作提出。评测模型最大到 8B，DAPO 只用 800 题子集，且大实验多为单次运行。附录 B.3 还写明十个数学基准的题量与解码协议，引用表 2 时必须把前三列的贪心与后七列的 Average@16 分开，不能写成统一的 pass 指标。

18. 复现要点

先实现 leave-one-out 的式 (4)，不要把自身奖励算进基线。试点与梯度样本要分开。方差估计若按表 1 的成本控制，需记录所用参数子空间。悲观规则要同时实现 (c~1)+、jackknife 标准误和 Gmax 截断；k=z0.90 可作为起点。更新日程可先复用 t=0,25 而后每 50 步。下游对照必须固定每步总补全数 N，只改 G（因而也改 B=N/G）。数学实验还需复现那一轮 496 条解的 SFT 热启动。没有代码与随机种子文件，表 2、5 应视为单次点估计。

19. 研究价值

它把一个每天都在调、却很少被认真建模的超参，变成可以估计、可以给出速率的统计量。对做 LLM-RL 的人，最大的启发不是又一个奖励整形，而是：当优势估计的某些分量本身很弱时，「更无偏」未必「更好用」，把不确定度写进目标往往更安全。U-统计量视角也解释了为什么 leave-one-out 既保持无偏，又会引出与 G(G−1) 相关的第二项。对想复现理论图的读者，附录把定理 2 和定理 3 的超额 MSE 按正则、弱信号、弱识别三块写全；正文图 4 只给出领先项，证明细节不必写入精读。

20. 可执行迁移

  • 在现有 GRPO / Dr. GRPO 训练环里加一条稀疏试点：每隔几十步用独立的 (b,g) 估计 c1,c3，用悲观规则更新 G，并保持 N 不变。先从截断悲观、90% 分位数做起，不要一上来就把地板加得很大。
  • 不要只扫 {8,16,32} 并在单一 checkpoint 上做结论。图 3 与表 1 说明最优组会随任务和训练阶段移动；至少在早期再估一次（他们放在第 25 步），并同时盯梯度 MSE 和下游准确率，避免把单次 DAPO 跑分当成稳定排序。

21. 方向专用分析

用户最高优先的 RL-for-LLMs 方向里，近日已读工作更多在改信用分配、预算内化或 hint steering。本文回到更古典、也更常被忽略的采样设计：同样 512 或 256 条补全，组大小会改变梯度的 MSE 形状。它与多智能体关系不大，但对任何用组相对奖励做更新的智能体 RL 都可能迁移——只要仍存在「提示多样性 vs. 组内基线质量」的权衡。理论目前还没覆盖工具使用、多轮环境与过程奖励，把缩放律直接搬到长程智能体上需要另做验证。

22. Attack / Verification

核对应先核对式 (4) 是否真是 leave-one-out，再核对表 1 是否只用了最后四块——用全参数重算比值，数字可能不同。表 2 的 greedy 与 Average@16 不要混用；表 5 不要只摘最高的 Average@8 而隐藏 HumanEval+ 贪心的第二名。试点如果与梯度样本重用，组大小会依赖同一批噪声，理论里的期望超额 MSE 不再直接适用。恶意角度看，悲观规则本身不易被「投毒一条奖励」直接掀翻，但若攻击者能污染试点批次、把 c~1 长期压到非正，去偏规则会持续选 Gmax；这正是作者引入惩罚项的原因，也是实现时必须给分母加地板或截断的理由。

23. 记忆总结

  • GRPO 的 leave-one-out 梯度是二阶 U-统计量，MSE 分成 c1,c2,c3 三项。
  • 固定 N=BG 时，最优组大小是 G*=1+c3/c1。
  • 表 1：c3/c1 可从约 7 到 500+，c3/c2 却都靠近 1，所以难处在小分母。
  • 去偏在正则体制更好，但弱信号下可能让 c~1≤0 并跳到 Gmax。
  • 悲观规则最小化 G(c~1)++c~3/(G−1)+kσ(G)，用不确定度惩罚过大的组。
  • 图 5：截断悲观在 27/30 个样本量组合上平均超额 MSE 更低。
  • 表 4 五种子均分 64.38，高于最佳固定组 63.73；大组 64 会掉到 57.95。
  • 表 2 均分 45.14 为最高，但十项里只赢六项，引用时不要说全面领先。
  • 表 6 试点占墙钟 7.03%–10.33%，加权约 8.1% GPU-小时。
  • 理论尚未覆盖完整 GRPO 配件与 Adam；大基准多为单次运行，代码 Not Reported。

2. 一句话定位

LoomKV 在不改服务引擎的前提下，用按头校准的两级 3-bit 编码无损压缩 KV，并把省下的字节真正变成容量：在分层缓存（tier mode）里写成定长精确记录，在 GPU 池（pool mode）里把变长记录打进更小的共享预算页，从而在前缀复用和长请求并发两个瓶颈上同时加宽缓存。

3. 人话版

多轮智能体或 IDE 助手会反复提交几乎相同的长前缀。引擎把 KV 留在 GPU，再溢出到主机内存和 SSD，下次就能跳过预填充。可是容量会在两个地方先见底：外层缓存不够，前缀还没被再次用到就被丢掉，只好重算；GPU 池不够，即使前缀就在 SSD 里，新的长请求也只能在门口排队。有损量化或丢 token 能腾出更多空间，但会改输出，每个模型和任务都得重新验收。LoomKV 的想法更保守：BF16 的高字节（符号加指数高 7 位）其实非常集中，最常见的 7 个值大约能盖住 94% 的出现次数，于是用短符号编码常见值，罕见值再逃逸。因为每一个 KV 数值都被精确恢复，省下的空间可以直接当成「同样硬件上的更大一层缓存」或「同一个 GPU 预算里的更多 token」。关键工程不是再抠零点几个点的压缩比，而是让变长记录不要把分配、换出和注意力内核卡住。

4. 背景与缺口

以 Qwen3-30B-A3B 为例，每个 token 的 BF16 KV 为 96 KB，一块预留 32 GB 的 GPU 大约只装得下五个 64K 会话。vLLM、SGLang 等引擎因此通过 LMCache、Mooncake、HiCache、CachedAttention、Strata 把 KV 下放到 DRAM / SSD。图 1 把两个瓶颈分开：在两块 H800、64 个会话、400 GB DRAM 的 AgentX 上，把 DRAM+SSD 从 1200 GB 减到 1040 GB，goodput 从 9.4 降到 4.6 请求/分钟，命中率从 0.84 降到 0.55，是典型的容量悬崖；而把 SSD 固定在 2 TB、把准入从 12 提到 16 时，平均运行中请求只多 0.8，等待却多 2.9，goodput 从 10.6 掉到 3.7，这是 GPU 池瓶颈，加外层缓存解决不了。

现成压缩对不上这个场景。nvCOMP 一类通用 GPU 压缩既不够瘦，也不够快；DFloat11 / ZipNN / ZipServ 面向离线权重；SplitZip 更适合同机传输，解压进连续缓冲后再散射到分页缓存。有损方法（KIVI、FP8 KV、CacheGen、H2O、SnapKV）会改 KV。和 11-23 的 Aggron（利用队头阻塞空档压缩智能体 KV）、11-19 的 Spool，以及 TraceKV 相比，LoomKV 的主张是无损、同时覆盖外层与 GPU 池，并且不改引擎。

5. 核心 insight

可压缩的位几乎都在高字节：图 1c 对 48 层、96 个 K/V 张量平均后，高字节 top-7 约占 94%，top-14 占 99.81%，剩下 0.19%；低字节 top-7 / top-14 只有 4.21% 与 8.21%，熵约 7.97 bit，所以低字节原样保存。编码必须是定宽的，因为 GPU warp 需要在固定偏移上做相同的查表；Huffman / ANS 会让位偏移依赖前面所有符号。更细的洞察是「省下的字节不一定等于容量」：如果仍按原始大小分配，或用过大的固定槽位，压缩比再好看也扩不出对象数。于是 tier mode 按精确长度分配对象，pool mode 用共享的变长预算把物理页缩小，并让注意力在寄存器里解压后直接做 MMA。

6. 方法逐步拆解

编码。每个高字节先拿 3-bit 主符号：0–6 指向码本第一行最常见的 7 个值，7 是逃逸。逃逸后再发 3-bit 次符号指向第二行的 7 个值；只有落在 14 个入口之外才写回 8-bit 原文（约 0.19%）。选 3 bit 是因为 4 bit 会给每个标量多花 1 bit，而 8 个 1 字节入口正好喂给一条 PRMT。每个层的每个 K 或 V、每个 KV 头各有一份静态码本，启动时可用通用后备，也可用一次 1024 token 的前向离线校准；记录头写入码本摘要以防不匹配。FP8（E4M3）则原样保留 3 bit 尾数，只编高 5 位，并在头内减掉静态的每通道指数偏移；K 还要在模型 256K 上下文上做 RoPE 再旋转后再拟合偏移。Pool mode 把第二级加宽到 4 bit（15 个次入口），让融合解压可以无循环。

Tier mode：一份 TileStream 记录覆盖 128 token 的一整块、所有层的 K 与 V。以 Qwen3-30B-A3B 为例，原始整模块 12 MB（TP 2 时每 rank 6 MB），记录 4 KB 对齐并加 4 KB 填充以便 O_DIRECT。字节按类型分成低字节、主符号、次符号、原文四条流；张量再切成 256 标量的 tile（32 车道 × 每车道 8 个标量）。分组 tile 索引让各个 warp 不必扫描更早的 tile。存储路径上三个核直接从分页块计数、布局、紧凑写出；不可压缩块回退到原文，最坏不超过原始大小。为了不让长度读回堵住加载，handler 线程启动压缩后立刻去服务排队的 load，由后台 worker 等 CUDA event、一次性读回长度、按精确长度分配 L1 并写穿到 L2。加载路径用四个旋转的 GPU 缓冲，把 PCIe 拷贝与解压叠起来。

Pool mode：每个 FragPack 记录是某一层、某一头、K 或 V 的 128×128 标量（原始 32 KB），并在压缩时就排成 MMA 片段顺序。页面容纳 2H 条记录（H=4 时 8 条），变长部分共享每条 1280 B 的预算；装不下或超过压缩上限的记录进 32 KB 原文溢出区。服务中只有 0.03% 记录回退（其中 0.009% 因页面已满）。融合 decode 核用 TMA 把精确长度拷进共享内存，线程解压进寄存器后直接做 m16n8k16 MMA 与在线 softmax，不再把还原后的 KV 写回全局内存。未完成的 open block 仍以原文放在每请求暂存区；prefill 不融合，先解到临时工作区再跑原装注意力，最多增加 3% 预填充时间。

7. 核心公式

若一层或一池分配了 B 字节、存储比为 r，则原始等价容量为 B/r。作者把「表现像同等大小的原始层」称为容量等价。对单个 BF16 标量，低字节加主符号固定花费 8+3 bit，次符号、原文和索引再加 3pe+8pr+0.14 bit。代入 Qwen3-30B-A3B 测得的逃逸率 pe=0.061、pr=0.0019，逃逸与索引只再加 0.34 bit，合计 11.34 / 16，比值为 0.709，大约节省 4.66 bit，元数据与对齐开销不到 1%。若主逃逸直接写 8-bit 原文，代价将是 0.06×8=0.48 bit/标量，这正是引入第二级的原因。Sizing 规则把写穿 LRU 的原始需求估计为约 1.8W（W 是在线会话的平均 KV），DRAM-only 约为 1.2W 到 1.3W，再乘以存储比：BF16 用 0.71，FP8 用 0.85–0.87。

8. Toy example

图 3 用 8 个 BF16 标量走一遍编码：低字节原样放下；常见高字节如 3C、3B 直接映到主符号 0 与 3；39 逃逸一次后走次符号 0；罕见的 41 两次逃逸，写成原文。解压时一条车道一次处理 8 个标量：先把 8 个 3-bit 主符号解开，用无分支 PRMT 查前 7 项，逃逸位置再用 warp scan 去次流和原文流里取数，最后与低字节交错写回引擎的分散页，不必经过临时连续缓冲。这解释了为什么 Table II 里 LoomKV 的分页解压能到 1182 GB/s，而 SplitZip 在连续缓冲上 1215 GB/s、散射进页后只剩 671 GB/s。

9. Baselines

  • Raw BF16 + 未修改的 LMCache：主服务对照，分层与 GPU 池都不压缩。
  • 有损 FP8 KV：把 KV 体积减半，作为「可以牺牲数值精度」时的上界对照；LoomKV 也可叠在 FP8 之上。
  • 内核对照（Table II）：SplitZip、ExANS、nvCOMP ANS / Bitcomp / LZ4；离线体积对照 ZipServ、ZipFusion。
  • 注意力对照：vLLM 配置下的 FlashAttention-3 与 FlashInfer。
  • 系统消融：精确长度改为 0.90 固定槽；28 GB GPU 预算下与「同等 token 数的更大原始池」对比；缓存模拟器里替换 LRU / 独占 LRU / Belady。

10. 实验设置

服务器为 1 TB DRAM、15 TB SSD、两块 H800（80 GB，700 W）。主模型是 Qwen3-30B-A3B-Instruct，TP 2，每 token 96 KB BF16 KV；对照模型 GLM-4-9B-Chat-1M（80 KB/token）。引擎是未修改的 vLLM 0.30，128 token 块，默认注意力为 FA3；缓存是 LMCache 0.5.6，128 token chunk，写穿 LRU。主工作负载 AgentX 回放 cc-traces 的 393 个 Claude Code 会话（带子智能体与记录的思考时间），指标只统计预热后的剖析窗。会话之间不共享前缀，提示最长达 254K，中位数 89K。每 GPU 预留 54 GB 给 KV（原始 1.18M token）；pool mode 的暂存、溢出区和记录表从同一 54 GB 里扣。默认准入 S=8，以免引擎内排队掩盖缓存效应；Q4 再扫到 16。多数实验 P=64 个在线会话（工作集约 641 GB 原始；P=32 时约 306 GB），400 GB DRAM，SSD 从 400 GB 扫到 2 TB，剖析窗 1800 秒（约 600 个请求）。每组实验跑三次，表中报告中位数 goodput 的那一次。AI IDE 轨迹是内部服务三小时开环回放：5,098 个请求，0.47 请求/秒，平均提示 68K、p99 192K，平均输出 505 token，没有 FIFO 准入代理。

11. 指标教学

存储比是压缩后字节除以原始字节，越小越好；0.709 表示大约 71% 体积，等价于约 1/0.709≈1.41 倍容量。Goodput是满足引擎 TTFT ≤ 2 s 且 ITL ≤ 40 ms 的请求/分钟，不是原始吞吐。引擎 TTFT已扣除代理等待。命中率是由缓存服务的提示 token 比例；Table V 还拆成 GPU 池 + 分层。Wait是 vLLM 内平均等待请求数。原始等价 GB/s把压缩吞吐折算回等价的原始字节速率，便于和 raw copy 比。重复实验在工作集已被层接住时，吞吐大约差 1%、goodput 大约差 4%；靠近悬崖时作者另报范围。

14. Ablation

编码消融（图 8）：两级 3+3 平均每个高字节 3.20 bit，相对 ZipServ 少约 6%，相对单级 3+raw 少约 8%，相对 ALP-RD 少约 20%，相对 SplitZip 的 4-bit 指数方案少约 25%；pool 的 3+4 只比 3+3 多 1.2% 高字节（记录体积 +0.1%）。粒度上，从全局码本走到每层 K/V 已经拿到几乎全部 BF16 熵收益，再走到每头基本持平，每通道没有额外好处。系统消融里，精确长度改为 0.90 固定槽会把 L1 增益从 1.41 倍砍到 1.11 倍；共享预算页是 1.38 倍块数，若按每条最坏 2 KB 预留则只有 1.33 倍，理想零空隙为 1.42 倍，扣掉后端缓冲后净 token 为 1.34 倍（54 GB）或 1.31 倍（28 GB）。缓存模拟显示压缩与替换策略正交：独占 LRU 会把悬崖挪到更少字节，但压缩仍按 0.71 把悬崖同比左移。DRAM-only 扫描（图 11）把可支撑的会话数大约平移 1.2–1.5 倍（中心在 1.4 倍）；悬崖带内 Qwen3-30B-A3B 的 goodput 为 3.5–4.3 倍，GLM-4-9B 最高到 7.6 倍（Table III 中 14.4 对 1.9）。

15. Claim vs Evidence

「九模型约 0.71」与 Table I 的 0.705–0.709 一致；摘要 0.85–0.87 对应表内 0.853–0.873，引用最好带三位小数。「2.7–3.6 倍 goodput、1.9–3.1 倍更低平均 TTFT」来自悬崖附近的重复范围，中位数行是 640 GB 约 2.9 倍、480 GB 约 2.7 倍与 1.9 倍，不要把范围当成单次点估计。2 TB 行上 goodput 同为 15.1，TTFT 1.73 对 1.69，说明容量足够时几乎没有服务收益，这与最多 2.2% 吞吐代价的声明一致，并不矛盾。Pool 不是与 FA3 比特级一致，只在误差上对齐，且求和顺序不同；FP8 融合核在功耗封顶下并不更快。S=16 的 14.0 对 11.1 并发来自正文/图 12，表中只给了等待队列。评估限于单机 TP 1/2 与 PCIe，MLA、流水线或专家并行、FP4 均为未测。

16. 贡献

  • 给出面向 KV 的按头校准两级 3-bit 无损编码，并在九个模型上把 BF16 存到约 0.71、FP8 存到约 0.85–0.87。
  • Tier mode 的 TileStream 与直写分散页的并行解压，以及把长度读回移出加载关键路径的异步传输。
  • Pool mode 的 FragPack 共享预算页，以及快于 FA3 的 BF16 融合 decode 注意力（多数形状）。
  • 在未修改的 vLLM + LMCache 上分别验证外层悬崖、GPU 并发和两层同时紧张的生产派生轨迹，并给出按系统状态选择模式的建议。

17. 局限

单节点、TP 1/2、PCIe；流水线并行、专家并行、多引擎共享缓存服务器、MLA 与 FP4 未测试。MLA 上 TileStream 或可直接压潜向量，但 pool 的 GQA 核需要改。混合结构里它只压注意力 KV。Pool 后端目前支持 BF16/FP8、128 维头、GQA 组大小至 8、128 token 块。FP8 pool 的端到端收益有限：共享页必须按最难压的层来定（0.906 对均值 0.838），且封顶下内核更慢。代码未发布。AI IDE 轨迹来自内部服务，外部无法直接复现该工作负载本身。公开可复核的主路径仍是 AgentX 与 cc-traces：会话不共享前缀、提示中位数 89K、最长 254K，这与「前缀复用」设定并不矛盾，因为复用发生在同一会话的后续回合，而不是跨会话共享。

18. 复现要点

需要未修改的 vLLM 0.30 与 LMCache 0.5.6，块与 chunk 都设为 128。先离线用 1024 token 前向校准每头码本，并把摘要写入记录头。Tier mode 必须按精确长度分配，且把长度读回放到后台线程；加载至少要用多缓冲，否则 GPU 争用会让 PCIe 空等。Pool mode 要扣暂存区、溢出区和记录表后再比 token 容量，并保持 CUDA graph 所需的固定网格。评测应分开报告「外层悬崖」「GPU 池排队」和「两层都紧」，不要用单一加速比概括。AgentX / cc-traces 可用于公开复现；goodput 阈值是 2 s TTFT 与 40 ms ITL。三次重复取中位数 goodput 的那一次，靠近悬崖时要报范围。

19. 研究价值

它把「无损压缩能否变成服务容量」从微基准问到了分层缓存和 GPU 分页注意力的系统层，并且明确反对两种常见短路：只报压缩比却仍按原大小分配，以及用有损量化换容量后再假装输出不变。对推理加速方向，这篇的价值是一份可操作的模式选择：外层见底用 tier，GPU 见底用 pool，两头都紧也用 pool（因为它把同样的记录写到 L1/L2），两边都宽裕就关掉压缩。

20. 可执行迁移

  • 先观察瓶颈再开模式：命中率明显低于无界缓存、或 SSD 命中很多，就先开 tier mode，按 0.71（BF16）或 0.85–0.87（FP8）去缩 DRAM/SSD 规划。若命中已经很高但引擎内部持续排队，再开 pool mode，并按 1.31–1.34 倍 token 重新设准入。
  • 不要用固定槽「差不多」地接下压缩记录。Table III 里 0.90 固定槽把 13.5 降到 8.4。实现上优先精确长度对象或共享变长预算；同时把长度读回移出 handler，并用至少四个加载缓冲避开 MPS/时间片造成的 PCIe 停滞。

21. 方向专用分析

Inference Acceleration 近日已读的是草稿侧（G-MTP、GaaD、ALD）或调度侧（Aggron、Spool、NarrowSpec）。LoomKV 回到 KV 层次结构本身：它不改生成算法，只让同样的硬件多装一些可以精确还原的 KV。它与推测解码正交，也可以叠在 FP8 KV 上（DRAM-only、P=64 时，FP8 raw 的 goodput 6.6–10.6，加上 tier 后命中 0.92、goodput 19.4）。对视频加速没有直接关系；对智能体服务则很实际，因为 AgentX 和 IDE 轨迹的前缀既长又会被反复提交。

22. Attack / Verification

核对应区分三种声明：分层输出与 raw 的 SHA-1 一致；pool 在压缩与原文 FragPack 上逐比特一致；pool 对 FA3 只在误差上对齐（BF16 均为 3.1×10−5，McNemar p≥0.42）。不要把后一项说成 bit-exact。校验解压正确性时，写地址必须只来自宿主校验过的元数据，记录内偏移要被夹紧——作者把这写成对损坏记录的防护。安全意义上，无损压缩不会引入量化常见的对齐退化，但实现若在逃逸流或溢出区上出错，可能造成静默坏 KV；因此「单位测试覆盖 raw fallback、部分 tile 与损坏头」应被视为复现的一部分，而不仅是性能表。

23. 记忆总结

  • 容量会在外层缓存和 GPU 池两处分别见底，加其中一层解决不了另一层。
  • 可压缩性主要在 BF16 高字节：top-7 约 94%，top-14 约 99.81%。
  • Table I：校准后九模型 BF16 存储比 0.705–0.709，FP8 为 0.853–0.873。
  • TileStream 按精确长度写层；FragPack 用共享变长预算把页缩小。
  • Table II：分页解压 1182 GB/s，约 raw copy 的 81%，并直写分散页。
  • 悬崖上中位数约 2.7–2.9 倍 goodput；2.7–3.6 倍是 480 GB 的重复范围。
  • 工作集已在层内时，pool 可多装 1.31–1.34 倍 GPU token，12 路大约相当于 raw 的 8 路。
  • AI IDE 上 tier / pool 的 goodput 为 11.6 与 15.0，对 raw 9.4 即 1.24 倍与 1.59 倍。
  • 容量足够时最多慢 2.2%；分层与 raw 比特级一致，pool 只在舍入上对齐 FA3。
  • 外层紧用 tier，GPU 紧或两头都紧用 pool，两边都宽裕就关掉压缩。
