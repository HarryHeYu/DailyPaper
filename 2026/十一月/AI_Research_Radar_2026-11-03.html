DiscernMem · Remembering Is Not Enough: Refining Memories and Learning When to Use Them in Multi-Agent Systems

Agent · Tier S · 2026-10-27 · BACKFILL · arXiv 2610.36652 · HTML 正文（如可用）

人话版：这篇论文到底干了什么？

多智能体团队保存的经验不一定能直接复用：一条规则可能写错，也可能本身正确、但被错误角色或错误情境调用。DiscernMem 不把团队失败粗暴归咎于某条记忆，而是用“只注入这条记忆”与“完全不注入”两种配对回放估计其局部影响；再通过轨迹证据决定修正规则内容还是修正使用边界。对开发 Agent memory/skill attribution 的研究尤其重要，因为它把记忆本身的质量和记忆使用策略拆开。

Background & Research Gap

团队成功掩盖个体错误：比如某测试 Agent 给出“失败就重跑所有测试”的经验，后来构建 Agent 代替它修复环境，团队仍然成功。由最终成功率推断该经验有用，就会产生虚假归因。反过来，真正有用的经验在错误任务上被调用，也可能变成有害因素。

相关工作常按语义相似度、整体 utility 或任务家族检索经验；其不足是“什么内容需要改”与“什么时候不该用”混成一个问题。论文明确把这两类故障分离。

Core Insight / Method Deep Dive

Input：当前任务、角色拥有的记忆、上游代理消息与历史任务流 → 匹配同身份记忆 → 真实运行一次团队任务 → 使用相同配置与 seed 分别进行单记忆/无记忆回放 → 计算配对效果 → 分析轨迹中的具体失配证据 → 若规则有缺陷则提出内容修复并跨任务回放验证；若仅使用场景不对则更新适用边界 → 将内容与 Meta-memory 分开保存 → 后续按角色与边界检索。

DMR（Defect-Aware Memory Refinement）是真正的修复引擎。其“反事实”不是完整因果识别，而是受控配对执行；共享配置和种子减少随机波动，但多智能体交互仍可能导致非线性联动。修复最多三轮，每轮三个候选，并在触发任务、至多两个保留任务和一个相关任务上验证，以减小新任务修好、旧任务退化的风险。

BLM（Boundary-Learning Meta-Memory）不是把失败反馈压成一个分数，而是记录每次复用上下文、测得效果、成功的修订，学习角色专属 use/avoid 条件。一个经验的 body 可以不改，但边界持续更新。匹配所需条件在 Agent 行动前可观察，因此部署时不应依赖未来结果。

Objective / Toy Example

论文更像具有接受门槛的有限回放优化，而不是一次全参数 RL 更新。以 Δ(m)=Score(只有角色持有m)-Score(零记忆) 为核心归因信号，结合容差 ε=0.01 和校验集决定修订；这不是标准 Shapley 值，无法直接分摊所有交互效应。

Toy Example：在代码仓库中有一条“编译失败时清除缓存”的经验。因缓存污染导致失败时，这条规则有益；因 import 错误导致失败时，清缓存无效。系统应该先把后者标记为“不要调用”，而不是立即删除整条经验。若轨迹表明命令写错了，才调整规则内容并在两个历史故障重放。

Experiment Setup / Baselines / RQs

共享冻结骨干 Qwen3-4B-Instruct-2507；检索 Qwen3-Embedding-0.6B；AutoGen、CAMEL、MacNet 三种多智能体架构，TriviaQA、PopQA、KodCode、PDDL 四类任务。评估是 prequential：先用旧记忆处理当前任务并计分，之后才纳入经验，避免同题泄漏。

RQ1：跨多智能体架构/任务类型是否有效？RQ2：边界记忆和修复验证分别贡献多少？RQ3：复用、修订集中度和超参数敏感性如何？比较对象包括 No-memory、ChatDev、MetaGPT、Generative Agents、Voyager、G-Memory、ConMem 等；最强基线随架构与任务不同，不能宣称一个统一强基线。

论文报告主结果、消融、调参约使用 900 GPU-hours，所有报告分数均来自每个设置的一次运行，这限制了统计置信度。

Results / Tables / Figures

Table 1：三个架构平均分分别为 AutoGen 59.03、CAMEL 56.93、MacNet 59.67，领先各自最强对照 0.70、0.51、4.32 分。最大且更稳的优势在 KodCode/PDDL 等程序性任务，不能据此说 TriviaQA 等 QA 全胜。

CAMEL 的 PDDL 37.71 对 28.48，多出 9.23 分；三个架构 KodCode 为 81.35–81.60，PDDL 分别为 29.15/37.71/36.99。读表时要区分绝对 score 和相对 point gain。

Table 2 的 AutoGen/PDDL：完整 29.15；关闭 BLM reuse 27.40（-1.75）；关闭 DMR validation 26.31（-2.84）；两者都关 25.36（-3.79）。CAMEL/KodCode：81.35 → 80.20/79.50/78.80，证明受测的两个功能都有贡献，却不能证明所有模块都必要。

Figure 2：79.9%–94.2% 的记忆 body 未修订，但修订体的注入次数份额高出其库存份额 1.2–4.3 倍。MacNet/PopQA 中修订体只占 5.8% 库存，却占 25.3% 注入；这是关联，不能误写成“修订导致更多使用”。

Authors Claim vs Evidence vs Unknown

作者主张：通过缺陷修复和适用边界两条分离路径实现更可靠的多智能体记忆演化。实验确实在三架构平均分与程序任务上支持该结论，并在两个任务/架构组合的消融里分离了模块效用。

尚未证明：1000-step 长时任务的稳定性；反事实估计在多记忆相互作用下的可辨识性；跨不同骨干/真实部署分布移位的泛化；多次随机种子的稳定性。评价时尤其要注意其高 GPU 回放成本。

Contribution / Limitation / Research Value

New Mechanism：把规则正确性与使用场景学习分离。New Evaluation：配对回放结合历史任务回归测试。New Empirical Finding：高频记忆更容易成为修订/重用焦点，程序性任务收益强于部分 QA。

价值：很适合作为 memory attribution 和 memory repair 的强基线；但若只改写“反事实评分”而无多记忆协同因果机制、成本缩减或新的 stress test，研究创新性不足。

Migration — 可操作的最小实验

Original：多智能体记忆损坏/误用 → Mechanism：受控回放与适用边界 → New Question：是否能在相互依赖的两条记忆之间区分协同效应和误用？→ Method：从单记忆对照升级为随机小规模 coalition 回放、估算交互项并学习低成本代理评估器。

Model：Qwen3-4B-Instruct 级别冻结骨干；Dataset：KodCode + PDDL 的可复现子集；Baseline：No-memory / ConMem / DiscernMem / naive leave-one-out；Metric：任务成功率、错误归因 AUROC（需人为构造 ground truth）、修复后回归率、每次归因 token/GPU 成本。预期贡献：在回放预算固定条件下，提高相互作用记忆的归因有效性；风险：组合数指数增长和多智能体轨迹随机性。

五句话总结

该论文讲的是正确的记忆被错误地用，与错误记忆被正确地用，是两种不同故障。

方法通过配对回放进行局部影响估计，并以历史任务防回归。

三个架构平均分均领先，但部分 QA 结果并不占优。

没有解决多记忆交互的严格因果归因，且回放代价很高。

最值得迁移的是内容修复与应用边界的解耦。

AgentMemRec · Agent Memory as Recommendation: Recommender-System Design for Long-Term Memory of LLM Agents

Agent · Tier S · 2026-10-26 · BACKFILL · arXiv 2610.34673 · HTML 正文（如可用）

人话版：这篇论文到底干了什么？

长期 Agent 在回答跨会话问题时，最怕的不是没找到一条看似相关的记忆，而是有限上下文预算里没凑齐解决问题需要的所有证据。AgentMemRec 把记忆选取改写成推荐系统的预算化 slate 选择：先低成本召回候选，再训练排序器，再把 token 预算尽量填满。实验重点解释“为什么一次召回准确并不等于最终回答正确”，比堆叠更多 LLM 记忆总结调用更有机制价值。

Background & Core Insight

请求相当于推荐系统中的 user，历史轮次是 items，上下文是 token-budget slate。一个问题可能必须同时拿到用户前后三次更改的约束；拿到其中两条也会回答错误。把这些证据逐条排序并考虑覆盖率，比纯语义相似度最近邻更符合真实目标。

论文将完整证据在候选池中的覆盖率 r_pool 与排序后被最终 slate 保留的覆盖率 r_rank 分解，目标近似为最大化两者乘积，同时约束服务所需 LLM 调用数。这个乘积依赖论文列出的独立性和完整 slate reward 等假设，不是任意复杂检索场景的普适定理。

Method Deep Dive / Formula

Input：query 与多 session 对话历史 → BM25 稀疏检索 + bge-m3 dense 检索 → RRF（k=60）融合 → top-128 turn pool → LightGBM LambdaRank 以 10 个低成本特征重排 → 计算每条记忆的增量渲染 token 代价 → 依排序顺序跳过超预算的条目、填满上下文 → 交给回答模型。

具体的排序特征包括 dense cosine、全局 dense/BM25 rank 对数、RRF 池位置、cross-encoder 分数，以及 user role、session 内位置、age、length 与实体/词键共享。使用 152 个开发问题产生的 19,456 个 question-turn 训练样本；该数字是训练 pair 数，不是用户数量。

关键式是 max_{φ,g,f} r_pool(φ,g)×r_rank(f|φ,g)，subject to LLMcost(d)≤L。φ 是候选提取，g 是融合，f 是排序器；在 L=0 下仍能使用预训练嵌入器、BM25 与 LightGBM，因为这里的 0 只指选择时额外 LLM 调用，不是零计算。

Toy Example：一份旅行历史先说 12 月去东京，后改为大阪，再后来取消酒店但保留航班。只取“东京”和“航班”会错；可行 slate 必须同时保留改目的地和酒店状态的信息。

Experiment Setup / Baseline / RQ

LongMemEval-S/M、LoCoMo；比较 A-Mem、HippoRAG 2、DynamicRAG、T-Mem、Adaptive-k 与有 64 次 LLM rerank 调用的 Ref。RQ1：候选池能否覆盖跨 session 全套证据？RQ2：不用 LLM 的学习排序能否逼近昂贵 reranker？RQ3：成本与检索质量是否形成 Pareto 改善？

需小心部分表格混合重现与引用结果，不可将不同 answer model/judge 协议的得分直接等价比较。真正稳的判断应优先看共享评测协议和作者的配对差值。

Results / Figure Reading

摘要汇总 LongMemEval 跨会话问题相对多种方法提升 10–31 个点，且相较 64-call Ref 有约 3.2× 更低 serving cost。这里是多任务/模型的范围值，不是单独一个通用提升。

Table 5：当证据跨至少三个 sessions 时，AgentMemRec 在 Qwen/DeepSeek 的分数为 68.4/77.6；Ref 是 67.9/76.0；Adaptive-k 38.8/49.0，T-Mem 57.1/57.1。复杂证据组合越需要完整 slate。

两 session 的 160 个问题上，AgentMemRec 为 84.5/93.0；Ref 83.4/93.1，显示优势未必在所有条件都优于 expensive rerank。

特征消融：删去 turn-context features，跨至少三 session 的 slate completeness 下降 31.1 点；单删 role、position、age、length 中任一项不超过 2.9 点。说明协同特征比孤立启发式更重要。

Figure/Equation：核心不是复杂网络图，而是 r_pool×r_rank 的链式瓶颈分析；任一阶段损失的证据无法在后续恢复。

Claim vs Evidence / Weakness

作者说 memory selection 可以无 LLM calls 高效完成，证据支持其固定 benchmark 上的强性能。尚未证明多种记忆互相矛盾、政策更新、故意注毒或对话强时序依赖时，填满 slate 一定优于 cutoff。

独立证据概率、完整 slate 下答案质量近似恒定、加更多证据不降低质量，均是有条件假设；在冲突记忆和 distractor 密集的真实数据里可能不成立。

Contribution / Research Value

New Formulation：预算化 slate 推荐；New System：candidate-retrieval + LambdaRank + cost-aware fill；New Empirical Finding：跨 session 证据完整性是实际痛点。

可复用价值：作为 Agent memory retrieval 的强性能/成本基线；还可将概念迁移到 Video event retrieval 的 query-aware 帧/事件选择。

Migration — 最小实验

Original：跨会话证据选取 → Transferable：完整证据 slate 的成本约束 → New Question：流式 video Agent 能否按事件依赖而非逐帧 saliency 选择视觉证据？→ Method：把视频 events 做成 retrieval items，用原来的语义相关性与新增的时序先决关系建图，在固定视觉 token budget 下最大化答案证据覆盖率。

Model：现成视频 VLM；Dataset：LongVideoBench/Video-MME 的可用长视频 QA 任务，须按官方视频/帧协议复现；Baseline：均匀采样、query-aware top-k、VETO 类 token 压缩；Metric：QA 准确率、关键事件 recall、latency、显存、tokens、证据完整率。风险：事件标注缺失，压缩后定位成本可能抵消收益。

五句话总结

长期记忆问题不只是找相关片段，更是凑齐证据集合。

排序器无需在选择时额外调用 LLM，仍要计算 embeddings 与 reranker 分数。

跨三个以上会话证据的困难问题尤其受益。

依赖独立性和单调性假设，遇到冲突记忆需验证。

可迁移到视频事件选择和多模态上下文预算分配。

DTCA · DTCA: Denoising Token Credit Assignment for Reinforcement Learning in Diffusion Language Models

RL · Tier S · 2026-10-26 · BACKFILL · arXiv 2610.35201 · HTML 正文（如可用）

人话版：这篇论文到底干了什么？

扩散语言模型不是传统从左到右依次吐 token，而是反复去噪并提交多个位置；最终答案对错的 reward，很难告诉训练器究竟哪一步、哪个 token 起到了决定作用。DTCA 在去噪轨迹中根据提交一个 token 后其他 mask 位置的预测置信度变化估计贡献，再用词性聚类形成先验，挑选高信息去噪步骤，并用策略更新导致的熵变化校正 token credit。其价值在“credit 不等于每个 token 分同一分”，但贡献代理指标是否真因果仍待检验。

Gap / Core Insight / Formulation

State：当前 partially masked 序列与去噪步；Action：提交/修正一个 token；Policy：LLaDA 的条件分布；Trajectory：多阶段去噪；Reward：数学题 final-answer correctness；Advantage：group-relative；Objective：带 frozen reference 的 KL 正则化 policy optimization。

旧做法把最终 reward 在 token 或去噪阶段粗分。DTCA 的观察是某个 token 提交后，其他掩码位置变得更确定可能说明该 token 带来了全局信息。于是构造 POS 贡献表以平滑样本稀疏性，并优先选择高贡献、具有高不确定性质量的 timestep。

关键超参数：按 POS-weighted uncertainty 累积覆盖 70% score mass，最少 2 最多 32 个去噪状态；用于平衡熵变化的 λ 按公式从正负 entropy delta 比例求得并 clip 至 [-0.95,0.95]。λ>0 时放大使熵增加的学习信号，λ<0 时反过来。

这不是人类标注的 process reward model：token-level credit 是基于置信度和 entropy 的辅助估计，终局 correctness 仍是核心 reward；潜在风险是过分奖励模型本来就高置信但实际错误的线索。

Method / Toy Example

Input：MATH 训练题及 offline MATH/GSM8K denoising traces → 对 token commitment 计算其他 mask 位置置信度提升 → 聚合到 POS 表 → 按贡献与不确定性筛选去噪 states → 执行 group-relative policy update → 从熵变化估算 λ 并调整 token credit → 加 k3 KL 限制偏离参考策略 → 输出改进模型。

Toy：模型在“已知 x+3=5，求 2x”中先提交 x=2，后续位置“4”的置信度提高。DTCA 会把 x=2 的贡献看得较大；但如果早期错算 x=3、其余位置也自洽，置信度提升会误导。需要和真值/反事实扰动区分。

Experiment Setup / Baselines

LLaDA-8B-Instruct，不经过中间 SFT；在 MATH 训练集做 RL；MATH500 和 GSM8K 评测 final-answer accuracy；生成预算 128/256/512。Baseline：Base、Uniform SFT、LLaDA-1.5、d1、ESPO、TraceRL、Coupled-GRPO、RLDF；其中 RLDF 在部分列更接近 DTCA，为重要强对照。

RQ1：不同预算下是否改善？RQ2：Contribution Credit 与 Entropy Calibration 是否必要？RQ3：是否降低梯度范数与缓解不稳定更新？训练 token、完整 wall-clock 等若未明确可比不应补猜。

Results / Tables / Ablation

Table 1 的 MATH500 基线为 30.8/36.4/39.2，DTCA 是 39.8/43.2/44.0；分别增加 9.0/6.8/4.8 点。GSM8K 从 75.3/83.2/82.9 变为 80.6/85.3/85.4，增加 5.3/2.1/2.5 点。

与 RLDF 的 MATH500 36.2/41.2/42.6 相比，DTCA 领先 3.6/2.0/1.4 点；说明表中提升不能全部理解为“对最强 RL baseline 增加 9 点”。

256 budget：去 Contribution Credit 后 MATH500 39.4 vs 43.2（-3.8），GSM8K 82.9 vs 85.3（-2.4）；去 Entropy Calibration 后 MATH500 41.8（-1.4），GSM8K 83.9（-1.4）。512 budget 删除熵校正分别损失 4.2/3.5 点。

Figure 3：统一 credit 的消融仍可能获得近似 response reward，但梯度范数更大。它提醒我们训练 reward 曲线趋同并不意味着优化步骤同样稳定。看图时需分辨 gradient norm 下降是否伴随 reward 真实收益。

Claim vs Evidence / Limitation

作者认为去噪阶段分配细粒度信用能改善 RL，六个预算/数据集对照和组件消融支持；但只在一个扩散 LM 主干、数学任务上验证，不能直接外推到 Agent 长时 trajectory 或自回归 LLM。

confidence improvement 是 attribution proxy，非反事实因果证据。POS 先验可能对代码、中文、视觉 token 或跨语言上下文失效。没有原文逐项证明 reward hacking 已被完全解决。

Contribution / Migration

New Mechanism：POS-conditioned token contribution；New Objective Adjustment：entropy-balanced credit；New Empirical Finding：小预算下收益更明显。

Original：去噪 token-level credit → Transferable：未来状态预测不确定性的改善 → Question：工具 Agent 哪条工具调用真正提高后续决策质量？→ Method：把状态预测 uncertainty reduction 与少量反事实 tool ablation 混合作为 credit estimator；Model：4B 级工具调用模型；Dataset：可复现的工具 QA/模拟交互任务；Baseline：sparse outcome、uniform credit、PRM、SCA 启发式；Metric：sample efficiency、任务成功率、归因一致性、rollout 训练成本；Risk：降低熵不代表更接近正确答案。

五句话总结

扩散文本 RL 的 credit 需要沿去噪过程分配。

DTCA 使用置信度贡献代理和熵变化修正。

数学 benchmark 六列都优于原始基线。

强 RL 基线差距小于相对原始模型的 9 点表述。

可迁移到 Agent credit，但必须加入真实环境反事实验证。

VETO — VETO: Video Efficient Token Optimization for Vision Language Models

VETO · VETO: Video Efficient Token Optimization for Vision Language Models

Video · Tier A · 2026-10-01 · BACKFILL · arXiv 2610.01785 · HTML 正文（如可用）

人话版

长视频 token 堆积使视觉编码和 LLM 推理昂贵，VETO 首先对每帧合并语义相近 token，再跨帧合并重复信息。这比只压缩空间或只压缩时间更可能真正降低端到端时延，因为跨帧匹配时序列已缩短。论文声称 training-optional 插件，可直接装进已有 VLM；最值得读的是压缩顺序如何改变额外开销，而不是单纯“剪掉多少 token”。

Mechanism / Setup / Results

Pipeline：视频帧 → intra-frame optimal-transport-inspired token matching/merge → inter-frame redundancy matching/merge → 压缩后视觉 token → VLM；加速对象为视频理解阶段的视觉 token 处理。

LLaVA-OneVision-7B 推理最高可快 45%；10% token budget 时 VETO accuracy 55.7%，VFlowOpt 54.9%、VisionZip 52.6%、FastV 47.9%。在 LLaVA-OneVision、InternVL-2.5、LongVA 上测试；“最高快 45%”不是所有配置稳定收益。

理论论文讨论 O(TN²/k + T²C) 代替完整 O((TN)²) 关联成本，但不能将理论式直接换算成实测 FLOPs 降幅。需要按官方硬件环境、预处理开销、batch、FlashAttention 核分别复现实测延迟。

Limitations / Research Value / Migration

最可能失效：低冗余快速镜头切换、小目标瞬时事件、字幕/数字细节。双轴压缩仍可能损失时间顺序证据；是否完全 training-free 取决于论文的具体部署路径。

最小实验：与只做空间合并、只做时间采样、均匀采样三种策略同预算比较，在 Video-MME/LongVideoBench 计完整 pipeline wall-clock、GPU memory、token、QA accuracy、事件召回，不只比较 FLOPs。Worth Deep Reading: YES。

ProactMem — Proactive Memory for Event-Driven LLM Agents

ProactMem · Proactive Memory for Event-Driven LLM Agents

Agent · Tier A · 2026-10-27 · BACKFILL · arXiv 2610.36967 · HTML 正文（如可用）

人话版

普通 Agent 记忆大多等查询来到时才检索。ProactMem 把主动服务所需的历史信息分成 recent events、temporal trajectories 和 behavioral regularities；轨迹结论要能回到原始事件验证，行为规律先经历史 replay 评估，再检查当前触发条件。这给 proactive agent 提供了更严格的“何时行动”判据。

Method / Experiment / Results

Input：时间有序事件流 → 构建近期事件与时间轨迹 → 提取可复用规律 → 对来源事件校验 → 历史 replay 检查规律 → 当前事件适用性匹配 → 产生主动行动机会。

ProactiveStream 是三个应用范围的纵向 benchmark，按时间顺序输入隔离事件流并用 episode-aware label 评估。报告总体 F1 52.6%，较五种外部 baseline 中最强者相对提升 21.4%；注意这是相对百分比不是增加 21.4 percentage points。

Limitations / Migration

真实用户环境中的偏差累积与假规律、反事实安全性并未由单一 F1 完全证明。尝试以“规则覆盖证据 + 触发精度 + 过期时间”构造 memory reliability，给 memory retrieval policy 增加 abstention；baseline 用纯最近事件和向量检索，指标 precision/recall/F1 与误触发成本。Worth Deep Reading: YES。

SCA — SCA: Spatial Credit Assignment for Reinforcement Learning of GUI Agents

SCA · SCA: Spatial Credit Assignment for Reinforcement Learning of GUI Agents

RL · Tier A · 2026-09-29 · BACKFILL · arXiv 2609.36939 · HTML 正文（如可用）

人话版

GUI Agent 的一组点击尝试如果全失败，普通 group-relative RL 得不到区分信号；但坐标距离目标按钮有远近差别。SCA 使用空间几何残差修正 group-relative credit：有成功/失败混合组时从其它样本预测某样本 reward 并利用残差，全失败时按与目标坐标的距离排序，从而修复失败样本没有梯度方向的问题。

Method / Experiment / Limits

RL state 是 GUI screenshot + 指令，action 是目标点击坐标；reward 以成功/失败及训练期几何信息形成；credit 从二值 group reward 调整为对空间误差敏感。部署策略没有增加额外视觉检测模块。

原文报告 GUI grounding 与离线 action prediction 多 benchmark 的表现、并做合成环境中与精确 return gradient 的误差和方向比较。当前报告未从全文核实可逐列复算的 benchmark 数字，故不写“提升 X%”。

标注目标坐标是辅助训练信号，并不总能在在线多步任务获得；“离按钮近”可能不是“离任务成功近”。迁移方向：把环境可计算的距离反馈扩展到 web agent 的动作误差归因，并与最终任务成功联合评估。Worth Deep Reading: YES。
