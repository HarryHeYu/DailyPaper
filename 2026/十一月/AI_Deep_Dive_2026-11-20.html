论文 1｜Depth Before Breadth：先深度后广度的反向–正向课程与成对优势分解 NEWAgent / Multi-Agent

本文把稀疏终局奖励下的长程 LLM Agent 学习，写成扩张策略诱导的能力区：用成对优势分别给「走到更可解的终点」和「从该终点完成任务」记功，并先沿成功参考轨迹反向推进、再从原起点正向探索。Table 1 报告 Qwen2.5-1.5B/7B-Instruct 的 ALFWorld 总成功率 90.1%/96.1%、WebShop 成功率 80.2%/82.6%，总体高于同表 GRPO / GiGPO / CRPS，但并非所有子任务领先，且基线数字取自既有论文。

1. 基本信息

2. 一句话定位

Depth Before Breadth 针对只用终局 0/1 奖励训练长程 LLM Agent 时「早期动作难记功、反向课程又被参考轨迹绑死」的问题：把目标改成扩张策略的能力区，用左优势比较前缀终点是否更好解、用右优势比较同一终点上的后缀是否完成任务，并先沿成功参考把原起点纳入能力区，再从原起点做在线探索，覆盖参考轨迹之外的状态。

3. 人话版

把当前策略看成一张「会做的地盘」。地盘内的状态，模型已较有把握把任务做完；地盘外还差一口气。长程任务的起点往往在很外面，整条轨迹只在最后给出成功或失败。若把这一分摊到几十步，早期搜错商品、走错房间很难被单独揪出。反向课程先从靠近终点处开局（例如已进入商品页，只差选规格和下单），学会后再把开局往前挪，从而沿着一条成功示范把地盘拉向起点。但它有两个漏洞：开局一前移，同一笔终局分数又被摊到更长的动作串上；训练几乎只在示范路上进行，策略走偏后碰到的路外状态未必被覆盖。

本文的拆法是：在边界附近，真正难的常常不是「从这里一直走到终点」，而是「先花很少几步走进已经会做的区域」。于是 rollout 被切成前缀和后缀。前缀只回答「局面被带到了哪类终点」，后缀只回答「从这类终点能不能做完」。同一终点至少采两条后缀，用完成率估计该终点有多好解，再比较不同前缀——走对的拿正左优势，走错的拿负的。右优势只在同一终点内部比较后缀，避免把「走到好位置」和「在好位置上收尾做对」混成一个轨迹级分数。课程上先沿示范把地盘拉回原起点（深度），再让策略从原起点自己走、加长前缀（广度）。

4. 背景与缺口

引言指出，LLM Agent 已从单轮生成走向多步交互，GRPO 一类组内相对策略梯度是常见范式，但长程任务仍受奖励稀疏制约：失败轨迹逐步没有信号，成功轨迹也只有一个终局奖励要分摊到整段交互（§1）。课程学习是应对手段之一。经典反向课程从近目标状态起步再把起点推远（Florensa et al., 2017）；近期工作采用锚定在成功参考轨迹上的变体，先掌握近目标局部执行再回到原起点（文中举 Zhang & Yang, 2026 等）。

作者认为仍有两个结构问题。起点后移后，终局反馈又被拉长，早期动作依然难分离；训练起点绑在参考轨迹上，策略探索中的 off-reference 状态暴露不足（Ross et al., 2011）。缺口因而不是再引入过程奖励或额外标注，而是在仍然只用终局奖励的前提下，把「进入已可解区域」和「在区域内完成任务」分开记功，并在原起点练稳后继续向策略自己的状态分布扩张。

5. 核心 insight

关键观察在 §1 与 Figure 1：把训练起点沿成功参考往回移，不只是「题目变短」，同时会把能力区朝原起点扩张。该图将轨迹上 Pass@1 超过 80% 的起点定义为能力区，画出 checkpoint 20 / 40 / 60 三条曲线；到 ckp60，新边界大约位于「剩余步数约占轨迹 60%」处。紧贴边界的新起点可以距真正目标仍远，但往往只差很少几步就能走进已会做的区域。长程问题于是分成两个耦合子问题：（i）从刚出界的状态进入能力区——短视野；（ii）从进入后的状态完成任务——更长视野，但已被前期训练部分覆盖。同一分解也可用于策略自己 rollout 到达的近边界状态，从而不把训练锁在参考轨迹上。

两个阈值必须分开：Figure 1 的 80% 只是该图的可视化定义；训练用的 η 在 Table 3 中为 ALFWorld 的 0.6 与 WebShop 的 0.78。§3.2 还写明，实践中并不显式计算近边界集合，也不给出数值 δ，只把反向课程的当前起点当作近似近边界上下文。

8. Toy example（本文自造算例，非论文数字）

以下为本文自造的教学算例，任务设定、前缀分配和奖励都不是论文表格或图中的实测值，只用来把式 (5)–(7) 的计算方向走一遍。

设想六步网购：「买一只中号红色马克杯」，参考轨迹为搜索 → 打开商品 A → 选红色 → 选中号 → 确认 → 下单。当前已把「商品页之后」练稳，开局放在搜索结果页，前缀长度为两步。采 n=8 条前缀，去重得三个终点，各采 NR=2 条后缀：e1 为正确商品页，m=4，两条后缀都买对，V̂=1；e2 为错误商品页，m=3，两条都失败，V̂=0；e3 仍停在筛选页，m=1，一条成功一条失败，V̂=0.5。前缀加权基线为 (4×1+3×0+1×0.5)/8=0.5625，故 AL(e1)=0.4375，AL(e2)=−0.5625，AL(e3)=−0.0625。e1、e2 上后缀结果相同，AR=0；e3 上成功后缀得 1，失败后缀得 −1。于是走到正确商品页的前缀获得正左优势，即使全对的后缀不再提供右信号；走进错误页的前缀被左优势惩罚；单例终点的 0.5 略低于组均，但成功与失败仍被右优势分开。若按普通 GRPO 把整条 0/1 广播到每一步，e1 上「点对商品」和「选对规格」会分享同一个正分，e3 也写不出 0.5 的中间估计——这正是 Figure 3b 要对比的情形。

15. Claim vs Evidence

对齐较好的部分：摘要与 Table 1 在两个尺度、两个基准的总体成功率上一致。§4.2 对 GRPO、GiGPO 的差值计算正确，并主动报告 Clean（1.5B）与 Cool（7B）两处例外。Table 2 支持「课程阶段和成对优势都有贡献」。Figure 3–4 为「PA 维持更宽、且部分可解终点能被右优势利用」提供了过程证据。

需要收紧的部分。第一，「优于有竞争力的智能体 RL 方法」成立在总体列上，但不覆盖每一子任务；WebShop 1.5B 相对 GiGPO 的成功率差距达 15.2 个百分点，明显大于 ALFWorld 总体的 3.4 个点。第二，表注写基线取自既有论文，同时正文写「相同骨干与训练设置」「匹配的评估协议」；若数字是引用而非复跑，匹配程度取决于原始设定，本文无复现表。第三，Ours 的 ± 是评估种子方差，CRPS 无标准差，不能直接比较训练稳定性，也未见显著性检验。第四，Figure 5 的效率结论只有曲线、没有数值表，终端值 Not Verified。第五，「大多数训练任务」达标才切换正向，缺少比例；参考来源未报告。不可把 Figure 1 的 80% 与训练 η 混用。

16. 贡献

按作者三条贡献并按其证据强度转述。第一，用策略诱导的能力区看待反向课程，并指出长程任务中嵌着「进入能力区」的短视野问题；Figure 1 是示意证据。第二，给出只用终局奖励的成对优势与反向再到正向的课程；Algorithm 1 与式 (5)–(8) 构成可实施的更新。第三，在 ALFWorld、WebShop 与两个 Qwen2.5 尺度上，总体指标超过同表强基线，并用终点覆盖与阶段 |E| 说明能力区在匹配交互预算下更宽。边界是：实验限于两个文本基准和单一模型族，方法依赖成功参考与中间状态重置。

17. 局限

论文自行指出（第 9 页）：反向训练需要成功参考，后缀采样需要从中间上下文重启；二者不可用时方法受限。若后缀全部失败，左右优势都会消失。从已知解附近起步可降低该风险，但若可解上下文始终落在已采前缀够不到处，扩张可能停滞。

还可补充：参考生成协议未给出，能力区可能部分记住的是示范支持集。终点只按动作序列去重，在随机环境或「同一动作、不同观测」时可能误合并。消融只覆盖 WebShop 1.5B，主表又有子任务逆转，外推到软件工程、GUI 或多代理缺少直接证据。文档中 16 与 32 的批次陈述、140/500 与「每 run 128 题」的评估陈述，以及公式中奖励为 {0,1}、训练时又乘 10，都会增加复现歧义。代码未发布。

18. 复现要点

已写明的旋钮：骨干 Qwen2.5-1.5B/7B-Instruct；4×H100；n=8、NR=2；d=Δℓ=3；η=0.6 / 0.78；奖励二元、训练乘 10；clip 0.2 / dual-clip 3.0；无 KL、无熵奖励；Adam 10−6、constant、grad clip 1.0、1 epoch；迭代 100 / 150；最大轮数 50 / 15；长度以 Table 3 为准（max model len 12288 / 15360）。评估应同时记录 140 seen / 500 test 的官方划分，以及「128 题×3 个评估种子、固定 checkpoint」这一表注协议，并写清实际采用哪一种。

实现上必须能把环境重置到参考或前缀终点，否则后缀采样不成立。终点键先按论文做：同一任务下的动作序列。后缀按终点复用，更新时再给每条前缀随机绑定一条。课程切换用表中的 η，而不是 Figure 1 的 80%；「大多数任务达标」需自行规定可记录的比例。批次上同时记录「16 tasks per update」与 batch size 32。没有官方代码，参考轨迹来源必须单独记入日志。

19. 研究价值

主要价值在问题重构：把稀疏终局奖励下的长程智能体，写成扩张策略自己的可解区域，并在边界附近把长程拆成短视野进入与区内完成，从而不必先引入过程奖励模型。反向之后必须再正向，是对「只沿示范做课程会被分布偏移伤害」的一次可测回应，Figure 4 用 |E| 的先降后升把「先深度、后广度」画了出来。对实践者，它提供了一套不改奖励、只改 rollout 结构与优势计算的组件，可挂在现有 GRPO 栈上对照。另一面也很清楚：没有代码、两个基准、依赖示范与重置，更像一份强的方法原型，而不是可直接上生产的配方。

20. 可执行迁移

迁移一：若已在用 GRPO 训练多步工具或购物/家居类 Agent，不必先换奖励模型。保持组大小，把轨迹在当前视野 ℓ 处切开；按动作序列归并前缀终点，对每个不同终点再滚 NR=2 条后缀（预算按 |E|NR 计）；用式 (6)(7) 分别写前缀与后缀优势，再套原有 clip 更新。先在已有验证集上对比「轨迹级 GRPO」与「只改优势、先不改课程」，看单例终点是否出现 0.5 的中间估计。前提是环境能重置到前缀终点；若不能，不要用「从日志里续写」冒充同策略后缀。

迁移二：若已在用示范做反向课程，把「原起点成功率越过 η」当作切换开关，进入正向阶段：从原起点采样，当前缀终点种类数连续若干更新不再增加时，把 ℓ 加一个固定步长。用 |E| 直方图做课程仪表盘：反向后期若 |E|=1 比例很高，说明能力区已沿示范塌缩，这时才适合放开广度；若反向阶段 |E| 一直散且原起点成功率上不去，应先检查参考质量或 η，而不是急着加长前缀。两个环境不要盲目共用同一 η：论文自己就用了 0.6 与 0.78。

21. 方向专用分析（Agent × RL：capability region / reverse-to-forward curriculum / paired advantages / 稀疏终局奖励）

这是单智能体、语言界面上的长程 RL，不是多智能体博弈；方向标签中的 Multi-Agent 只表示它落在 Agent 训练谱系，论文没有多代理实验。它面对的结构是稀疏终局 0/1、部分可观测、开放文本动作、视野可达数十轮。GRPO 把组内相对优势广播到整段轨迹，整组全败时优势为零；PA 并不直接解决整组全败（若所有终点的后缀都是 0，左优势同样全零），它解决的是更细的一件事：即使组内已有成败差别，也不要把「进入可解终点」和「在终点上做对」写成同一个标量。这与 GiGPO 依赖跨轨迹重复状态对齐、CRPS 沿示范重放是近邻但不同构：PA 显式构造「共享终点上的多条后缀」，同时估计终点价值与后缀优势。

能力区 Cη(π) 随策略移动，不是环境里预先画好的子目标图。课程因此不是按任务难度排序，而是按「当前策略已经可靠的上下文」往外推。反向阶段用成功参考给出有序的近边界序列，代价是宽度被压到示范邻域（Figure 4 中反向晚期均值 |E|=2.21，近半数组塌到单终点）。正向阶段把锚点改回原起点并加长前缀，代价是 |E| 回升、后缀采样点变多；作者用反向已形成的短后缀能力来主张这不一定增加总环境步（Figure 5 的定性结论）。实践含义是：示范课程可以把终局奖励拉近到可学的短视野，但若不接正向阶段，部署时一旦偏离示范仍会走出能力区。尚未回答的问题包括：多代理中「终点」应如何定义，以及在不可重置的真实网站或工具环境里，后缀估计还能不能做无偏。

2. 一句话定位

PQRS 是一种无需训练的视频扩散 Transformer 稀疏注意力：只对 Key 做聚类，让每个 Query 按自己的质心分数选择 Key 簇，对未选簇做质心补偿，再用按簇为主序的核把不规则选择打包成稠密任务，从而在四款 720p 视频 DiT 上同时做到更接近稠密输出、也更快。

3. 人话版

720p、约五秒的视频扩散，token 数可以到几万。Wan2.1 在 81 帧、720p 时 N = 75,600，引言写明在单枚 H100 上一条五秒片段大约要 28 分钟，而自注意力占其中大部分。稀疏注意力的想法很直接：只精确计算那些真正扛住大部分注意力质量的 token 对。问题是，哪些对值得算？

一类流行做法先把内容相近的 Query 和 Key 各自聚成簇，再让「同一个 Query 簇里的所有 Query 共用一份 Key 簇清单」。这样清单整整齐齐，正好喂给按块稀疏的 GPU 核。但共用也有代价：簇里那个和均值不太一样的 Query，会被塞一份并不适合它的 Key 列表。PQRS 的判断是：这份共用本身才是精度损失的来源，而不是「分了簇」这件事。于是它不再聚 Query，让每个 Query 自己点单；没点到的 Key 簇，用该簇的 Key/Value 均值做廉价补偿。点单结果因 Query 而异，不能再指望「一整块 Query 对同一串 Key」。作者把遍历顺序反过来：按 Key 簇走，把选了同一组簇的 Query 装进同一个稠密任务，并用上一步去噪留下的 log-sum-exp 当作固定的 softmax 偏置，一次过完，避免在线 softmax 反复缩放。

4. 背景与缺口

相关工作把视频 DiT 稀疏注意力分成几路。静态方法利用时空局部性，使用按头的空间/时间掩码、滑动窗或能量衰减掩码；动态方法在线估计块重要性，或只在少数步搜索掩码再复用。聚类方法（SVG2、SVOO、AdaCluster、HyperVAttention、SCOPE 等）按内容把相似 token 排成连续块，在免训练方法里目前保真最好。SVG-EAR、PISA、Sol-Attn 则对未选块做近似而非直接丢掉。可训练路由也存在，但不是本文比较对象。

这些免训练聚类方法几乎都把「一份 Key 选择」共享给一个 Query 块或 Query 簇，以便映射到块稀疏核。TRA 可以给每个 Query 不同预算，执行时仍是块稀疏掩码；SparsePR 按 Query 对 Key 簇的响应重新分组。本文认为缺口在于：共享选择会限制精度，而把 Query 簇切细又会抬高 k-means 成本、打乱核的 tile 效率。PQRS 要同时拿掉 Query 侧聚类、保住精度，并用新的执行顺序把不规则选择跑快。

5. 核心 insight

第一，精度瓶颈在「共享」而不在「聚类」。固定 Key 簇与密度，把 Query 簇从粗切到每个 Query 单独一簇，召回上升、补偿后的输出误差下降；即便用 Oracle（簇内真实注意力质量的平均）来选簇，共享选择仍然比不上「用质心分数做逐 Query 路由」。第二，逐 Query 路由并不更贵：它省掉 Query 侧 k-means，只需每个 Query 对 Key 质心打一次分。对 Wan2.1-T2V-14B、720p（N = 75,600）、Ck = 592、ρ = 0.22，该路由成本只相当于稀疏注意力计算的 1.8%。相对双边聚类，只要 Iq Cq > Ck（SVG2 常用 Iq = 2，即 Cq > 296），逐 Query 路由更便宜。第三，硬件要的是「同一 tile 里的 Query 看同一组 Key」，不必事先把 Query 绑在一起再选择；可以先让每个 Query 自己选，再把选择相同的 Query 桶在一起。

6. 方法逐步拆解

一次注意力、一个头，PQRS 按 Algorithm 1 走三步，再由第 4.2 节的按簇为主序核执行精确项。

只对 Key 聚类。每次稀疏注意力调用，在 QK 归一化与 RoPE 之后，对每个头的 Key 做 k-means，得到 Ck = 592 个簇及其均值 k̄c、Value 均值 v̄c 和规模 |Kc|。首次稀疏调用跑 50 次迭代，后续同一层（任一 CFG 分支）从上一轮质心暖启动，只跑 2 次。按 Key 均值的余弦相似度贪心把簇打成宽度 G = 4 的组，并把 K、V 重排成组内连续。

逐 Query 路由。用一次矩阵乘 Z = Q K̄⊤ / √D 得到每个 Query 对每个 Key 簇的 logit zic，再按式 (1) 的形式（把簇级均值换成该 Query 自己的 logit）得到估计质量 P̂ic。Query i 按分数从高到低加入簇，直到累计质量至少为 p = 0.848，并且所选 Key 数至少为 f N（f = 0.10，沿用 SVG2 官方实现的 floor）。阈值用二分而不是排序。选择记成每组一个 G 位编码。

质心补偿加精确计算。未选簇用已算好的 zic 与 v̄c 写入 FP32 累加器 (ui, li) 作为初值；被选簇则对真实 Key/Value 做稠密计算。最后 ôi = ui / li。

按簇为主序的执行。核按 Key 簇（实际是组）遍历，按（组，编码）把 Query 分桶，同一桶共享完全相同的成员选择，作为最多 128 个 Query 的稠密任务，避免「取并集」或「掩掉未选项」。偏置 mi 在开核前固定为同一层、同一 CFG 分支上一步的 LSE（第一步稀疏调用沿用最后一次稠密 FlashAttention 返回的 LSE）。各任务计算 P = exp(sij − mi)，用原子加把 (PV, P1) 写入累加器。若 li 落在 (10−30, 1030) 之外，该行用单行在线 softmax 重算；主机不同步。HunyuanVideo 只稀疏「视频 Query 对视频 Key」，有效文本 Key 另走一次 FlashAttention，再用 LSE 精确合并。

8. Toy example（本文自造算例，非论文数字）

以下为自造算例，用来说明「共享选择」如何漏掉离群 Query、以及质心补偿与按编码分桶在做什么。簇分数、召回与延迟都不是论文表格或图中的测量值。

设 6 个 Query、8 个等规模 Key 簇，目标累计质量 p = 0.80。若按双边聚类，q1–q3 被分进同一 Query 簇，簇均值选出 {K1, K2, K3}，估计质量 0.40 + 0.25 + 0.20 = 0.85，看起来达标。但 q3 自己的质量其实是 K5 = 0.35、K1 = 0.30、K2 = 0.15、K3 = 0.10。共享清单只覆盖 0.30 + 0.15 + 0.10 = 0.55，把 q3 最重要的 K5 留给了补偿。逐 Query 路由会为 q3 依次收入 K5、K1，再收入 K2，累计 0.80，召回对齐该行自己的分布。未选的 K3–K4、K6–K8 仍用 |Kc| exp(zic) v̄c 进入分子分母，不把尾巴直接清零。

11. 指标教学

PSNR、SSIM、LPIPS 都是「同一提示、同一随机种子下，稀疏视频相对稠密视频」的帧级相似性：先对每帧比较，再对帧平均，再对视频平均。SSIM 用 11×11 均匀窗，LPIPS 用 VGG 骨干。它们度量的是贴近稠密输出的程度，不是「更好看」。VBench 0.1.5 以 custom-input、默认预处理运行，不参照稠密视频；正文把它在五个维度上取平均后写入 Table 1：subject consistency、background consistency、motion smoothness、aesthetic quality、imaging quality，分维度见 Table 4。密度是稀疏注意力调用里被精确计算的 Query–Key 对比例，不含补偿项。端到端延迟是整段生成墙钟，加速比相对同一管线的稠密注意力。注意 Figure 1 的 27.61 dB / 33.58 dB 是图中展示样本的 PSNR，附录 D.4 说明 Figure 8–11 的时延采用 Table 1 均值；主结论应读 Table 1 的 50 条平均，而不是单张宣传图。

15. Claim vs Evidence

摘要与结论称：PQRS 是所评稀疏方法中最快、也最接近稠密输出的，Wan2.1-T2V 达到 28.9 dB、HunyuanVideo 达到 35.4 dB，端到端加速 1.66×–2.10×；在 VBench 上相对稠密「未检测到退化」。Table 1 支持前半句：四模型上 PQRS 的 PSNR、SSIM、LPIPS 与端到端加速均为稀疏方法最优，圆整与表中 28.86、35.44 一致，加速极值正好来自 Wan2.2 的 1.66× 与 HunyuanVideo 的 2.10×。

需要收窄的是 VBench。「未检测到退化」说的是相对稠密，不是「在五项平均上压过所有稀疏基线」。PISA 在 Wan2.1-T2V 上为 83.78%（PQRS 83.70%），在 Wan2.2 上为 84.32%（PQRS 84.26%）。这些差异幅度很小，且 VBench 不对照稠密视频，不能单独用来宣称生成质量提升。50 条提示的 Table 1 未给置信区间；预算曲线上的 bootstrap 只出现在 Figure 7 的文字说明里。Figure 1 的样本 PSNR 低于表平均，若直接当数据集结论会偏悲观。基线密度超参经过调整（SVG-EAR 降 top-p 以对齐密度，SVG 与 PISA 为了对齐约 1.5×），比较更公平，但也不是各方法官方默认预算下的原样复制。PISA 在 HunyuanVideo 上的文本块处理被作者承认为略不利。速度数字建立在「双方都用融合核」之上，作者明确提醒：SVG 家族官方加速有时把稠密管线留在原始 Diffusers 算子上，会把融合收益也算进去。

16. 贡献

作者在引言列出三点：（1）把聚类稀疏注意力的精度代价定位在共享选择，而不是聚类本身；（2）提出免训练的 PQRS：每个 Query 独立路由 Key 簇，其余用质心补偿，并配上能在单次遍历里以 tile 效率执行不规则选择的按簇为主序核；（3）在四款 720p 视频 DiT 上，相对五个免训练基线取得最好的 PSNR、SSIM 与 LPIPS，同时也最快，端到端加速 1.66× 到 2.10×，VBench 上未检出相对稠密的退化。贡献陈述与 Table 1 的「相对稠密的保真 + 加速」一致，但对 VBench 的解读应保持第 15 节的限定。

17. 局限

论文没有独立的 Limitations 小节，以下为正文与附录中可见的约束，以及阅读后的补充。评测只覆盖两个家族的四款 720p 模型、各 50 条提示、单枚 H100、约五秒长度（81 或 129 帧）；Wan2.2 还包含专家 CPU 卸载这一共享开销。前 20% 步与每栈第一块始终走稠密注意力，因此「稀疏」不是全流程稀疏。核与 TMA / wgmma 路径面向 H100，跨设备可移植性未验证。显存、多卡、更长视频与非 720p 的主结果 Not Reported。没有代码或项目页，第三方无法直接复核分桶核与原子加实现。VBench 只用了五个维度的平均，不是完整套件。PSNR 系列只说明贴近稠密教师，不保证在人类偏好上更好。相关工作中的若干聚类或逐 Query 方法未进入主表。这些都限制了把 1.66×–2.10× 直接外推到生产管线的把握。

18. 复现要点

若复现主表，应固定：单枚 H100；官方采样（Table 5 的步数、采样器、shift、guidance）；720p；前 20% 步与第一块稠密；非注意力侧使用同一套融合核；PQRS 使用 Ck = 592、p = 0.848、f = 0.10、G = 4，四模型不改。k-means 首次 50 次迭代、其后 2 次暖启动，须在 QK 归一化与 RoPE 之后对每个头单独做。LSE 缓存必须按「同一层、同一 CFG 分支」对齐；Wan2.2 里只有在最后一次稠密步活跃的专家拿得到稠密 LSE，另一专家的首次稀疏调用要用选中 Key 的预计算精确偏置，并把该次 k-means 跑满 50 次。HunyuanVideo 只稀疏视频对视频，密度也只统计这一块；文本侧保持稠密，并用 LSE 合并。指标按帧对齐稠密视频再两级平均，VBench 0.1.5、custom-input。基线超参不要偷偷改回官方默认后再和 Table 1 对打。行修复应在设备侧判断列表是否为空，避免主机同步。没有官方代码是目前最大的复现风险。

19. 研究价值

它把「为了迁就块稀疏核而先绑定 Query」这一习以为常的工程选择，重新写成一个可测量的精度成本，并用动机实验表明：切细 Query 簇会涨点，但真正的上限是每个 Query 自己选；这条路在 FLOPs 上甚至更便宜。真正难的是执行，而不是再加一个模块。把 KV-outer 遍历、按选择编码分桶、以及跨步 LSE 固定偏置组合在一起，让不规则掩码不必退回在线 softmax 的多次缩放或额外预计算。对视频加速方向，这提供了一条「免训练、一套超参打四模型、在更低密度上同时赢质量和墙钟」的对照点，尤其适合已经在用 SVG2 / SVG-EAR 一类聚类稀疏注意力的 720p DiT 推理栈。

20. 可执行迁移

迁移一：若现有栈已经是双边聚类（SVG2 风格），先不要急着把 Cq 加到更大。用与 Figure 3 相同的协议——固定 Key 簇与目标密度，把 Query 簇一直细化到 Cq = N——只看召回的低分位（尤其 P1）和补偿后的相对输出误差。若 P1 仍明显低于中位数，说明共享清单在欠覆盖离群 Query。这时应改成逐 Query 路由，而不是继续为 Query 侧 k-means 付钱。可用式 (7) 先算一笔账：当 Iq Cq > Ck 时，逐 Query 打分已经更便宜。

迁移二：一旦选择变成逐行不规则，不要把「取并集再掩码」或「在线 softmax 多次缩放」当作默认执行。按 Key 组遍历，用 G 位编码把相同子集的 Query 分桶（先扫 G，本文在 H100、40 头的 Wan2.1-T2V 上是 4 最快），并把上一步同一层、同一 CFG 分支的 LSE 当作固定偏置；同时保留 li 越界则单行重算的修理路径。Table 8 说明，若改回精确偏置预计算，单次调用加速会从 3.52× 掉到 2.14×。配套上保留 token floor 与前 20% 稠密热身，先在「相对稠密的 PSNR / SSIM / LPIPS + 端到端墙钟」上验收，不要只报 VBench 五项平均的微小波动。

21. 方向专用分析（Video Acceleration：聚类稀疏注意力、per-query routing、centroid compensation、720p DiT）

静态掩码假设「光栅顺序上邻近的 token 更该互相看」，但视频潜在空间里，响应同一组 Key 的 token 常常并不相邻。聚类稀疏注意力用内容相似性重排，这是它相对滑动窗或能量衰减掩码的关键优势，也是本文选择在这条线上改进、而不是另开静态掩码的原因。现有聚类方法为了迁就块稀疏核，几乎都做两件事：Query 与 Key 都聚类，以及一个 Query 簇共享一份 Key 清单。PQRS 证明第二件才是精度税，于是取消 Query 聚类，只保留 Key 簇作为「选择粒度」。

逐 Query 路由的分数仍是对 Key 质心的 softmax 质量估计，不是对全部真实 Key 扫一遍；它和 SVG2 的式 (1) 同构，只是把 q̄n 换成 qi。质心补偿则负责没被选中的质量尾巴：SVG-EAR 已经表明补偿有效，但 Table 2 进一步说明，补偿在「选择已经按行对准」时多赚 3.1 dB，在共享选择下只赚 1.7 dB。直觉是，共享清单会把某些 Query 的高分簇错推给估计器，而质心近似最适合「质量本来就轻」的尾巴。

720p DiT 的 token 规模让这些设计不再是微优化：Wan 系 75,600、HunyuanVideo 118,800，自注意力接近二次。端到端仍然只有 1.66×–2.10×，是因为热身、首块稠密和 VAE 等部件还在；真正注意力核上，Table 8 给出 3.52×。评价上，训练免校准的加速必须同时看「相对稠密教师」的 PSNR/SSIM/LPIPS 和「无参照」的 VBench：前者敏感、能排方法，后者防止只是在复制稠密瑕疵时看起来很像。PQRS 的主叙事建立在前者的大幅度领先，以及后者与稠密持平。

22. Attack / Verification lens

验证时应把 Figure 1 样本 PSNR 与 Table 1 平均拆开，并核对时延是否只是把 1682 / 960 / 1701 / 809 秒写成了分钟。检查密度定义是否只计入精确对、是否把补偿当成「也算计算了」。核对基线是否使用 Table 6 的调整超参，以及 HunyuanVideo 上 PISA 的 sink/padding 处理。LSE 跨步复用是数值风险点：作者给出 69 nats 阈值、行修复比例和 Figure 5 的稳定性描述，复现时至少要记录被修复行数是否同阶。没有开源核对，原子加与分桶核的正确性只能靠「相对稠密 PSNR」间接约束。评测规模是 50 条提示，Table 1 无区间，小样本波动可能吞掉 VBench 上零点几个百分点的差异。最后，PSNR 对教师的贴近可以被「更强的补偿把误差抹平」部分解释，所以 Table 2 的 2×2 拆分是必要的健全性检查，而不能只看主表一行。

  • PQRS 是免训练的视频 DiT 稀疏注意力：只聚类 Key，每个 Query 按自己的质心分数选簇，未选簇用质心补偿。

论文 3｜NarrowSpec：推测解码的草稿隐宽度不必对齐目标模型 NEWInference Acceleration

相对自训全宽草稿，NarrowSpec 把 DFlash / EAGLE-3 残差隐宽度收到一半或四分之一后，在温度 0、batch 1、SPEED-Bench 880 条上，B200 端到端 1.06–1.12 倍、GB10 为 1.13–1.44 倍（Table 3、25）。半宽 AL 代价至多 3.0%，四分之一宽 2.1–5.4%；batch 扫描最高 1.21 倍。

1. 基本信息

2. 一句话定位

对读取目标隐状态的特征条件草稿，残差流不必做成与目标相同的宽度：把它收到一半或四分之一、在边界加适配器，并在 DFlash 借用词表头时于加载时折叠，可以在接受长度基本保住的前提下压低每次投机迭代里的草稿开销，从而降低每输出 token 时间（TPOT）。

3. 人话版

推测解码像「助理先打草稿、主编一次批改」：小模型提出若干候选 token，目标模型一次前向成批核对，只收下最长正确前缀。批改（verify）通常更贵，助理又快又准，摊到每个落地 token 上的时间才会下降。

DFlash、EAGLE-3 这类「看着主编隐状态写稿」的助理，习惯把笔记本（残差隐宽度）做成和主编一样宽。本文的回答是：本子可以改成一半甚至四分之一宽，读写这条残差流的投影会一起变窄；只在接入目标隐状态、对目标词表打分的接口上加线性适配器。DFlash 借用冻结词表头，训练时先把窄状态抬回全宽再打分，上线时把两段线性映射合成一个更窄的头，logits 只在浮点舍入上有差别。头数、头维和 MLP 中间维不动，因此注意力核和草稿 KV 体积不随宽度缩小。

4. 背景与缺口

式 (1) 把解码延迟拆成两条路：提高接受长度 AL，或降低一次投机迭代的代价 Titer。提高 AL 的路线（EAGLE 类隐状态条件化、Medusa / MTP 额外头、候选树等）往往会在草稿或验证侧加活。直接降 Titer 的路线则缩短草稿上下文（MagicDec、LongSpec、SpecExtend、windowed drafting）、用更少层做自投机、裁剪词表投影（FR-Spec、VocabTrim、NanoSpec），或稀疏化验证、更早停草稿（§8）。这些方法多半只动一个部件，残差隐宽度通常仍直接做成目标宽度。

最接近的先行工作只覆盖一部分：SlimSpec 用低秩瓶颈压缩词表投影，层内残差仍是全宽（§5.3、§8）；Gemma 4 的 MTP 草稿把 Transformer 做成 256 或 1,024 宽，但没有比较备选宽度，也未测量代价与收益。缺口是：在冻结目标上训练的特征条件草稿里，宽度能去掉多少、AL 会掉多少、端到端能换回多少，需要在并行草稿（DFlash）与自回归草稿（EAGLE-3）、稠密与 MoE 目标上一起量清楚。

5. 核心 insight

第一，草稿的每个块都读写同一条残差流，把这条流收窄，等于同时缩小注意力投影、MLP、接入目标特征的投影、写草稿 KV 的投影，以及通向词表的投影（附录 Figure 6）。宽度是「整网一起瘦」的轴，不是只砍一个头或只砍 MLP。

第二，在固定提案长度 k 时，一次迭代里草稿要跑的位置数目由宽度和 k 决定，而不是由本轮实际接受了多少 token 决定（DFlash 每轮都草拟满块；EAGLE-3 在 SGLang 里用 CUDA graph 把第一步 pad 到 8，并且七步都会跑）。于是式 (1) 可以比较干净地拆开：Titer 主要由宽度决定，AL 主要由训练决定。

第三，借用的词表头不必永远停在目标宽度。训练时的输出适配器与冻结头都是线性的，中间没有非线性（最终 norm 在适配器之前），加载时折叠成 V×dd 的单一 GEMM，代数上精确，有限精度下只差舍入（附录 B）。折叠让借来的头也能按 2 倍或 4 倍变窄，并在 DFlash 上贡献草稿体节省的 38–44%（§5、App. F）。

6. 方法逐步拆解

记目标与草稿隐宽度为 dt、dd，词表大小为 V。中间残差流不必是 dt 维，本文取

dd∈{dt/2, dt/4}

两家族都不改头数、头维和 MLP 中间大小，故注意力与草稿 KV 条目尺寸不变（§2）。

DFlash 是块并行草稿（Figure 1、Table 1）。k 取发布块大小：Qwen3-8B 为 16，GPT-OSS-20B 为 8。每轮对 k 个位置做一次前向（上一轮留下的 bonus token 加 k−1 个 mask），经 5 层（Qwen）或 8 层（GPT-OSS）提出 k−1 个 token。它从目标 5 层取隐状态，由每轮一次的 context pre-pass 写入草稿 KV，并借用目标的 embedding 与词表投影。

EAGLE-3 是单层解码器按步自回归（Figure 3），k=7，共提出 7 个 token。第一步读刚接受的 token（含 bonus），把 3 层目标隐状态从 3dt 经 fc 压到 dd，只有 bonus 位置继续链式生成；第 2–7 步用草稿自己的上一 token 与隐状态，每步把 embedding 与隐状态拼成 2dd。它借用目标 embedding，但在修剪词表上自训词表头（32,000 / 151,936 与 64,000 / 201,088），再经查找表映回目标 id。

窄草稿按自身宽度从零训练，与目标宽度张量相遇处加适配器。两家族的 fc 都先把抽取的目标隐状态（5dt 或 3dt）映到 dd。Token embedding 来自目标 V×dt 表，再经 dt→dd 输入适配器。DFlash 打分用冻结的 Wlm，训练时加输出适配器 Wout，先抬维再算 logits；EAGLE-3 的词表头本身在 dd 上训练，不需要输出适配器。

DFlash 若按训练图直接跑，每轮都要先走 Wout 再走全宽 Wlm。最终 norm 在 Wout 之前，两段之间没有非线性，加载时一次合成

Wlm(Wouthd)=Wfoldhd
Wfold=WlmWout∈ℝV×dd

上线只跑一次从 dd 到 V 的 GEMM。两目标词表投影都保持 BF16；折叠改变浮点运算顺序，logits 不必按位相同，但在半宽 Qwen3-8B 与 3,405 个真实状态上，折叠路径相对 FP64 甚至略近（Table 10）。EAGLE-3 可在导出时把输入适配器乘进 embedding，得到自己的 V×dd 表（半宽 BF16 约 0.6 GB）；显存紧时可改为七步各跑一次适配器。DFlash 的输入适配器每轮只跑一次，作者保留目标 embedding，付出 4.2–7.2 µs（相对别处节省的 212–351 µs，Table 23）。

DFlash 上宽度进入四条路径：唯一新增的输入适配器、把 5dt 映到 dd 的 fc、被折叠掉因而上线不跑的输出适配器，以及读取 fc 输出、写入固定尺寸 KV 的 context K/V 投影（§2.4）。EAGLE-3 则主要在 fc 与折叠后的 embedding 表上体现宽度，自有头和解码投影都在 dd 上跑。

7. 核心公式：变量、目标与直觉

解码（不含 prefill）的每输出 token 时间写成

TPOT=TiterAL,Titer≈tverify+tdraft

AL 是接受长度。主面板用整个集合的「完成 token 总数 / 验证步总数」做池化，长回复权更大。Titer 是一次投机迭代的代价，近似为 tverify 与 tdraft 之和。降低 TPOT 只有两条：提高 AL，或降低 Titer。本文把宽度当作降低 Titer 的旋钮，并同时报告 AL 代价，避免「草稿更快但老被拒」的虚快。

折叠的训练路径是

hup=Wouthd
logits=Wlmhup

两段都是线性映射，加载时合成 Wfold。直觉是：与其每步把激活抬回 dt 再读 V×dt 的大头，不如把抬维一次性吸进更窄的 V×dd 权重。附录 B 用归一化 RMS 与 top-1 对 FP64 的一致率检查舍入；折叠可能改变近平局处的 argmax，但验证仍只用目标自己的概率，输出分布不会因折叠而系统性偏移。操作目标是：在匹配数据预算下选一个 dd，使 TPOT 相对自训全宽草稿下降，并把 AL 损失控制在可接受范围。宽度是训练前的架构选择，文中没有另写可微的「宽度损失」。

8. Toy example（本文自造算例，非论文数字）

以下算例是为讲清「Titer 下降 vs AL 下降」和折叠合成而构造的，数值不是论文表中的测量结果，不能当作实验证据。

假设验证完全不随草稿宽度变化，tv=3.00 ms。全宽草稿 td=1.20 ms，接受长度 A=4.00，则 Titer=4.20 ms，

TPOTfull=tv+tdA

得到 TPOTfull=4.20/4.00=1.050 ms。半宽把草稿降到 t′d=0.80 ms，若 AL 只掉 2% 到 A′=3.92，则 Titer=3.80 ms，TPOTnarrow=3.80/3.92≈0.969 ms，相对全宽约 1.08 倍。若同一套更快的迭代碰上 15% 的 AL 跌幅（A′=3.40），TPOT 变成 3.80/3.40≈1.118 ms，反而不如全宽（约 0.94 倍）。这个对比用来理解后文 Table 16 里「四分之一宽 DFlash-Qwen 在 RAG 类上迭代更快、但 AL 掉得太多，TPOT 变成 0.95 倍」的机制，并非复述该表数字。

11. 指标教学

AL（acceptance length）：每次验证提交的 token 数。面板上的池化 AL 是「完成 token 总数 ÷ 验证步总数」，长样本权更大。∆AL 相对本文全宽草稿，正值表示接受更长。

Titer 是一次投机迭代时间。Table 3 去掉每轮第一次 decode（日志含 prefill，App. G），且该轮至少 8 步。Batch 扫描则取「整批 B 个请求都在跑」的步骤均值，并丢掉每块头尾各两步及超过中位数两倍的步骤（至多 0.9%，几乎只在 B=1）。两种估计器不可直接混比绝对值。

TPOT = Titer / AL，是不含 prefill 的每输出 token 时间。TPOT 加速比包含 AL 变化，Titer 加速比只看迭代。草稿份额是全宽设定下 tdraft / (tdraft+tverify)，用来解释收窄最多能省多少。

Table 29 的带宽占用是 GEMM 的 BF16 权重字节除以核时间、再除以峰值带宽（B200 8 TB/s，GB10 273 GB/s）。没有核能真正打满峰值，重要的是随宽度变化的趋势。注意力核几乎不随宽度变快，这可解释长上下文下收益变薄。

14. Ablation 与缺失的 ablation

已做对照包括：四 cell × 三宽度；温度 0/1（Table 14、26，温度 1 的 TPOT 加速相对温度 0 移动不超过 0.03 倍）；11 个类别与八基准；B200 / GB10 /（仅 DFlash-Qwen）H100；batch 与上下文扫描；算子时延剖析（Table 7、23、28）；折叠核对（Table 10）；MLP-only 未训练切片（Table 8）；DFlash-Qwen 的 NVFP4 量化（Table 33）；以及 EAGLE-3-Qwen 在扫描提示上对 k∈{1,3,5,7} 的扫参。

Table 8：要在 B=1 追上半宽，MLP-only 需比全宽高出 2.1–10.6% 的 AL；追上四分之一宽则需 0.7–7.5%。切片能省下与收窄几乎相同的 MLP 时间（DFlash-Qwen 半宽为 120 对 122 µs），但不碰词表头和注意力投影，只抓住草稿体节省的 41–55%。EAGLE-3-GPT-OSS 上 MLP 已接近小 GEMM 地板，切片相对全宽不更快（约 2% 噪声内）。固定核形状不保证训练后的小 MLP 看到同一运行时成本，这些时延是估计。

k 扫参：在那些提示上，全宽最优 k=3，两个窄宽是 5；若按事后最优 k 比较，收窄收益降到半宽 1.03 倍、四分之一宽 1.05 倍，对照同一运行里 k=7 的 1.08 与 1.11 倍。最优 k 依赖事先并不知道的接受情况，这不是服务器可预知的设置。未在 GPT-OSS 或更大 batch 上扫 k。

未完成的消融包括：训练过的 MLP-only / head-only 对照；对已经量化的目标头做折叠（Q(Wlm Wout) 一般不等于 Q(Wlm)Wout，App. B.1）；更多种子与训到收敛；真正训练并评测窄 MTP 草稿；其他 pair、大 batch、量化感知训练，以及远超 32k 的上下文。

15. Claim vs Evidence

摘要称：温度 0、batch 1 下，半宽或四分之一宽使端到端解码在 B200 加快 1.06–1.12 倍、在 GB10 加快 1.13–1.44 倍。Table 3 与 Table 25 的端点与此相符：B200 为 1.06 倍（DFlash-Qwen 四分之一宽与 DFlash-GPT-OSS 半宽）到 1.12 倍（EAGLE-3-Qwen 四分之一宽）；GB10 为 1.13 倍（DFlash-GPT-OSS 半宽）到 1.44 倍（EAGLE-3-Qwen 四分之一宽）。

「从 batch 32 到各 GPU 能放下的最大 batch，收窄最高达 1.21 倍，且没有比全宽更慢的窄草稿」：B200 的 1.21 倍出现在 Table 9 的 DFlash-Qwen 四分之一宽、B=128；GB10 的 1.21 倍出现在 Table 30 的 EAGLE-3-Qwen 四分之一宽、B=32。该判断只覆盖这两张扫描表的 cell 级 TPOT，不是每一个提示类别。Table 16 里 DFlash-Qwen 四分之一宽在 RAG 上为 0.95 倍，是容易被读过头的反例，附录已写出。

「减半代价至多 3.0% 接受，四对里有两对不降；四分之一宽代价 2.1–5.4%」与 Table 3 的面板池化 ∆AL 相符。这是单次训练、单一种子、匹配预算而非收敛；正的 ∆AL 被作者明确读成持平。类别层面可以更差（RAG −14.8%，训练长度外的长样本被池化放大）。八基准上 EAGLE-3-Qwen 半宽的 4.3–6.2% 也重于面板上的 3.0%。

H100 的 1.11 倍不宜当成纯硬件定律：服务配置同时从 NVFP4+TRT-LLM MHA+FP8 KV 改成了 FP8+FA3+BF16 KV，绝对 AL 还低了 8.6–9.7%，论文无法拆开这些因素（App. I）。发布草稿行只说明本文全宽有竞争力（DFlash 的 z-lab 在温度 0 上 AL 差距在 1.6% 以内），不能解释宽度效应；RedHatAI 的 Qwen EAGLE-3 落后 20.6%，来自数据与配方。

16. 贡献

把草稿残差隐宽度立成可测量的设计轴，而不是继承目标宽度的默认值，并在 DFlash 与 EAGLE-3、稠密与 MoE、两档收窄上用匹配数据预算完成对照。

给出借用词表头的折叠做法：加载时把输出适配器与冻结头合成 V×dd 投影，代数精确，有限精度下与未折叠路径在面板温度 0 的成对运行中 token 一致，AL 差在 0.03% 以内（App. B）。

用阶段与算子剖析、以及 B200 / GB10 / H100 的带宽对照，说明收益取决于草稿占迭代的份额、以及变窄后 GEMM 还能多接近峰值带宽；并补充 batch、上下文、类别、量化和 k 的边界条件。

17. 局限

论文自述：每个变体一次训练、一种子、匹配数据预算而非收敛，换预算可能改变 AL 代价；只测了两家族、两目标，草稿占迭代份额很小的目标收益会更小；上下文扫描止于 32k，收窄不缩小 KV 注意力，更长上下文下收益预期会变薄；MLP-only 消融用未训练切片且只比延迟。

补充：主加速相对的是作者自训全宽草稿，不是任意已发布草稿；折叠增加一份常驻 V×dd 头（半宽 DFlash-Qwen 约多 0.61 GB，约一张 B200 显存的 0.3%），EAGLE-3 半宽若折叠 embedding，净服务权重甚至大于全宽（Table 11 为 1.28× 与 1.55×）；GB10 与 B200 的目标注意力后端不同，H100 配置不齐；未发布本文代码与窄草稿权重（Not Reported）；温度 1 下各变体采样不同文本，分项 AL 含采样噪声（App. D）；GPT-OSS 聊天模板会写入当天日期，同一权重跨日 AL 最多可差 0.8%，作者要求同日比较。

18. 复现要点

必须按自身宽度从零训练，不能把全宽权重直接截断当窄草稿。同一 cell 要共用数据、顺序、epoch 数与调度形状；EAGLE-3 必须按宽度重选学习率与 initializer_range（Table 13），DFlash 则可以用同一 6e-4。报告的 checkpoint 要与论文一致：DFlash-Qwen 用第 5/6 个 epoch，其余用最后一个。

服务侧需要引擎支持窄 hidden_size、边界适配器，以及 DFlash 的加载期折叠（SGLang 用 torch.mm 一次合成并存成 BF16）。不要对已经量化的目标头做折叠后指望与「先量化再乘适配器」一致。评测应同时报 AL、Titer 与 TPOT，并写明 Titer 是否去掉 prefill 步。GPT-OSS 比较必须在同一天进行。Batch 扫描不要直接套用 880 条面板的 AL。量化若要叠加，先折叠再把 Wfold 量化一次（App. J）。

硬件需按表写清：B200 上目标注意力为 TRT-LLM MHA，草稿注意力 FA4；GB10 换后端且 memory fraction 为 0.5；H100 用 FP8 目标。训练用 4×B200。代码仓库未提供，复现需自行在 SpecForge 与 SGLang 0.5.18 nightly 上补齐窄宽度路径。

19. 研究价值

它把一个长期被默认掉的超参数——特征条件草稿的残差宽度——变成可以和上下文、层数、词表维并列讨论的轴，并用端到端 TPOT 而不是只报 AL 来结算。折叠给所有借用目标词表头的草稿（含尚未评测的内置 MTP 层）提供了一条不必改验证器的实现路径。跨 B200 与 GB10 的对比说明：同一套窄草稿在带宽更低、核更长的设备上更接近按字节比例加速，这对边缘或工作站部署更有经济意义。

20. 可执行迁移

迁移一：新训特征条件草稿时，不要默认 hidden_size=dt。在 B200 这类高带宽数据中心 GPU 上，先把半宽当作默认尝试——面板上是 1.06–1.09 倍，四格里两格 AL 不降，另外两格为 1.5% 与 3.0%。在 GB10 这类低带宽 GPU 上，四分之一宽在本文四格、两个温度下都是最快档（1.20–1.44 倍）。选定后必须在新宽度上重扫学习率与初始化，并一次改好引擎里的窄残差与适配器路径。

迁移二：只要草稿借用目标词表头（DFlash 或内置 MTP），就在加载时折叠，让词表投影与躯干一起变窄。先在 BF16 头上合成，再决定是否量化 Wfold；不要对已经 4-bit 的目标头直接折叠。EAGLE-3 一类自训头本来就在 dd 上，无需折叠，但半宽若再折叠 embedding 表会增加常驻显存，显存紧时应改为运行时适配器（同一份 dt×dd 权重，DFlash 上单次 4.2–7.2 µs）。量化可以与半宽叠加（DFlash-Qwen 上 1.11 倍），到四分之一宽时收益接近消失甚至略亏，不要假设「越窄越该再量化」。

21. 方向专用分析（Inference Acceleration：推测解码、草稿宽度、接受率 vs TPOT、B200 vs GB10）

推测解码的结算式就是 TPOT=Titer/AL。只追 AL 往往会给草稿或验证加活；只追 Titer 若伤害 AL，端到端也可能更慢。本文在 k 固定时让 Titer 随宽度下降，再看 AL 会不会把这笔账吃回去。Table 3 里 DFlash-Qwen 是现成例子：四分之一宽 Titer 1.12 倍，AL −5.44% 后 TPOT 只剩 1.06 倍，反而输给半宽 1.09 倍。Table 16 的 RAG 是反例：迭代 1.11 倍不够补偿 14.8% 的 AL，TPOT 落到 0.95 倍。服务上应同时监控这两项。

与目标宽度脱钩之后，头数和头维仍固定，注意力与草稿 KV 不瘦。因此长上下文只能慢慢变薄（8k 到 32k，Titer 加速最多动 1.6%），不能靠宽度去打 KV-bound 场景。这与 MagicDec、windowed drafting 等轴正交，论文认为可以组合，但没有做窗口化实验；已做的组合只有 EAGLE-3 自带的修剪词表，修剪后再收窄仍能继续缩小那张头（Table 6）。

DFlash 与 EAGLE-3 的 batch 行为不同。DFlash 每请求处理 k 个位置，草稿 GEMM 看到 kB 个 token，与验证侧同量级；DFlash-Qwen 的草稿份额从 B=1 的 25.4% 升到 B=512 的 31.4%，收益随 batch 升高或维持。EAGLE-3 第一步也覆盖约 8 个位置，但其余六步每请求只草 1 个 token，多数 GEMM 只看到 B，验证 MLP 更早进入计算受限，草稿份额从 34.2% 降到 B=256 的 23.8%，收益随之回落（Table 9）。迁到 MoE 目标时还要加上「小 batch 只点亮部分专家」的折点（GPT-OSS 在 B=32 附近）。

B200 与 GB10 的差别，核心是变窄后还能保持多少峰值带宽。Table 29 在 DFlash-Qwen、batch 1：1,245 MB 的词表投影在两张卡、三个宽度都还在峰值的 73–85%；B200 上较小的 FC2、QKV、输出投影在四分之一宽时核只有 5–11 µs，占用分别掉到 33%、30%、19%，五类核合计从 69% 降到 47%。GB10 上同样的核在四分之一宽仍跑 46–226 µs，占用维持 79–84%（最小输出投影为 67%），合计 83% 到 81%。于是四分之一宽草稿在 B200 只比全宽快 1.43–1.75 倍，在 GB10 是 3.44–3.87 倍。SGLang 是共同底座，但 GB10 换了目标注意力后端并降低了显存份额，比较应落在宽度比和草稿份额上。

22. Attack / Verification lens

验证协议仍是标准推测解码：温度 0 只接受目标 argmax，各变体在数值非确定性之内应吐出目标贪心输出；温度 1 用拒绝采样保持目标分布，但各草稿提议不同，接受差异含采样噪声。折叠不能改变输出分布，只能改变提议。附录 B 在 3,405 个状态上，折叠与未折叠相对 FP64 的 top-1 一致率为 97.2% 与 97.0%，两者互相一致 99.1%，所有失误都是近平局（折叠路径失误的最大 margin 为 0.10 logit，全体中位 margin 为 0.51）。同一对半宽与四分之一宽 DFlash-Qwen 检查点在 880 条、温度 0 的成对运行中输出 token 完全一致，AL 差在 0.03% 以内。

测量陷阱包括：GPT-OSS 模板写入日期，跨日比较最多可移动 0.8% AL；贪心输出会随 batch 因核数值而变，只能在同一 B 下比宽度；分析器与未分析运行的宽度比一致到 0.2–0.9%，但 Nsight 可能漏掉 GPU 外时间，大 batch 阶段和可比未分析 Titer 低至 13%，加速比必须来自未分析运行；池化 AL 会被超长样本主导；按测试提示事后选 k 会高估可部署收益；单一种子使 AL 上升不能当稳定增益。本文保证的是目标分布的无损解码，前提是验证器未被改掉，且折叠后的头没有用错已经量化的权重。

23. 记忆总结

  • 特征条件草稿的残差隐宽度不必等于目标宽度；半宽或四分之一宽是训练前的架构选择，不是部署时的临时裁剪。
  • B200、温度 0、batch 1、880 条 SPEED-Bench 上，相对自训全宽草稿的 TPOT 为 1.06–1.12 倍；GB10 为 1.13–1.44 倍（Table 3、25）。
  • 半宽 AL 代价至多 3.0%，四格中两格不降；四分之一宽为 2.1–5.4%。单次种子的小幅上升应读成持平。
  • Batch 扫描中最高 1.21 倍，cell 级没有更慢的窄草稿；但 DFlash-Qwen 四分之一宽在 RAG 类上是 0.95 倍，池化被 7 条超长样本放大。
  • 结算式是 TPOT=Titer/AL：验证几乎不随宽度动；AL 掉太多时，更快的迭代也会输。
  • DFlash 借用词表头时，加载折叠 Wfold=Wlm Wout，logits 只差舍入，该头贡献草稿体节省的 38–44%。
  • 注意力头几何不变，KV 与注意力核不瘦；8k 到 32k 的 Titer 加速变化不超过 1.6%。
  • 低带宽 GPU 上收益更大：变窄后的 GEMM 在 GB10 仍接近峰值带宽，在 B200 上许多短核会掉占用。
  • 数据中心卡先试半宽并重扫学习率；低带宽卡再试四分之一宽。量化与半宽可叠加，与四分之一宽则可能不划算。
  • 本文未给出 NarrowSpec 代码或窄草稿权重（Not Reported）；复现需在 SpecForge 与 SGLang 中自行接好窄宽度与折叠。
