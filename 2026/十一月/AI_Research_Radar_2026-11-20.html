S Depth Before Breadth: Reverse-to-Forward Curriculum with Advantage Decomposition for LLM Agent

人话版：这篇论文到底干了什么？

这篇论文要解决的是：用稀疏终局奖励训练长程 LLM 智能体时，失败轨迹几乎没有学习信号，成功轨迹又要把同一个对错分数广播到整条多轮交互上，信用分配和探索都很难。作者把问题改写成“扩大策略自己的能力区域”——即当前策略已经能较可靠完成任务的那一批决策上下文。他们发现，能力边界附近往往只需再走几步就能进入更可解的状态，于是把长程学习拆成两件耦合的事：先走到更可解的上下文，再从那里把任务做完。

对应的方法叫 Paired Advantage（成对优势）加上先反向、后前向的课程。前缀动作按“所到达终点的经验完成率相对组内平均是否更高”来计分，后缀动作只在同一终点内部比较成败。反向阶段顺着成功参考轨迹从靠近终点处往起点退，先把可解区域钉住；前向阶段再从原始起点做策略自己的滚动，把区域扩到参考轨迹之外。在 ALFWorld 与 WebShop 上，用 Qwen2.5-1.5B/7B-Instruct，整体成功率分别达到 90.1%/96.1% 与 80.2%/82.6%，超过同设定下的 GRPO 与 GiGPO。

背景与研究缺口

LLM 智能体已经从单轮生成走到多轮、带状态的环境交互，GRPO 一类的组相对策略梯度也成了智能体强化学习的常见默认选项。难点在于奖励几乎只在回合结束时给出一个二元结果。所有失败 rollout 在每一步都是零信号；即便成功，也只有一个终局奖励要分给整条轨迹里的每一次思考与动作。动作空间是开放文本，观察又是部分可观测的网页或房间描述，这种稀疏反馈会让策略既不知道早期搜索或导航错在哪，也不敢离开已经走过的成功路径。

现有补救大致有两条。一条仍在轨迹级做相对优势，如 PPO、RLOO、GRPO，把同一个 A(k) 广播到该轨迹的所有动作，早期“走到可解状态”的动作和后期“把任务做完”的动作被绑在一起。另一条尝试更细的信用，例如 GiGPO 做步级分组，CRPS 用反向回放。它们能缓解一部分长程归因，但没有显式回答一个更结构的问题：当前策略到底已经能从哪些上下文可靠收官？若能力区域已经覆盖某条参考轨迹的后半段，却还没有覆盖起点，继续从起点做完整 rollout，会反复在前半段交学费。反过来，若只沿着参考轨迹做反向课程，策略又可能挤在参考路径上，离线状态一出现就不会走。缺的是一个同时处理“进入可解区域”和“在区域内收官”、并能从参考轨迹扩到策略自身分布的机制。

核心洞察

关键不是再发明一种更密的过程奖励，而是承认：策略自己诱导出一个能力区域 Cη(π)={c:pπ(c)≥η}，真正有信息的训练上下文往往就在这条可靠阈值附近。长程任务因此可以拆成“前缀把智能体送到更好的终点上下文”和“后缀从该上下文完成任务”。用终点处的经验完成率比较前缀、用同一终点内的后缀成败比较收官动作，再用先沿着成功参考往后再向前探索的课程去扩大这个区域，稀疏终局奖励就够用了。

方法深读：从输入到输出

输入是任务 x~𝒟，智能体在每一步收到观察 ot、输出文本动作 at，轨迹 τ={(ot,at)} 只有终局奖励 R(τ)∈{0,1}。决策上下文 ct=(o≤t,a<t,x)，策略为 πθ(at∣ct)，目标是最大化 J(θ)=𝔼[R(τ)]。行为策略 πθold 在能力边界附近的起点采样 n 条轨迹，每条被切成前缀与后缀：前缀决定到达哪个终点上下文 e，后缀决定能否从 e 完成任务。

前缀按终点上下文去重。作者特意只用可执行的 <action> 序列判断两个前缀是否落到同一 e，忽略 <think> 里的措辞差异，避免把同一环境状态拆成许多表面不同的终点。记 I(e) 为到达 e 的前缀下标，m(e)=|I(e)|，ℰ 为独特终点集合。对每个 e，再从该上下文采样 NR≥2 条后缀，用经验完成率 V^(e)=1NR∑jRe,j 估计 e 处的可解程度。左优势把终点和“按前缀计数加权的组内平均完成率”比较：

AL(e)=V^(e)−1n∑e′∈ℰm(e′)V^(e′)

它奖励那些把智能体送到更高完成率终点的前缀，即使这些前缀自己还没有看到最终成功。右优势只在同一终点的后缀之间比较：AR(e,j)=Re,j−1NR−1∑j′≠jRe,j′。若同一终点的所有后缀结果相同，右信号为零，但该终点仍可通过左信号对前缀产生梯度。这是一个反直觉却关键的设计：全部失败的终点并不是“没有信息”，只要组里还有完成率更高的终点，到达低价值终点的前缀就会被惩罚。

更新时，为每条前缀从其终点均匀抽一条后缀拼成完整轨迹，前缀段用 AL、后缀段用 AR，各自做 PPO 风格的重要性比裁剪（见公式一节）。两个阶段共用同一目标，差别只在前缀从哪来、有多长。反向阶段假定任务有一条成功参考 τ*，从靠近末端的上下文 cT−1* 出发，以固定步长 d 沿参考往回走；在当前位置 ci 采样长度为 ℓi=d+2 的前缀，做成分对优势更新，直到该点的估计成功概率达到可靠性阈值 η，再退到更早的参考上下文。当大多数训练任务的原始起点已进入 Cη(π) 时，反向阶段结束。此时策略往往已能从起点可靠求解训练任务，但能力区域仍可能集中在参考轨迹周围。

前向阶段改以原始起点 c0=(o0,x) 为锚，前缀长度从与最终反向阶段对齐的 ℓ0=d+2 起，按 ℓi=d+2+iΔℓ 递增。这些前缀可能到达参考之外的上下文，再用同一套成对优势把它们纳入扩大中的能力区域。课程何时往前加长，并不靠手工指定 δ，而是监视每组独特终点数 |ℰ| 的均值：当它在连续更新中稳定，说明当前前缀长度下的终点多样性已经平台化，再把前缀加长 Δℓ，让策略去找可能跨过能力边界的新终点。实现上 n=8、NR=2，ALFWorld 的 η=0.6，WebShop 的 η=0.78，两阶段步长都是 3。训练关闭 KL 损失与熵奖励，使用双裁剪（clip ratio 0.2，dual-clip c=3.0），终局二元奖励再乘以 10 作为训练尺度。

从输入到输出的依赖可以按一次更新来走：先确定当前课程阶段与起点（反向是参考上的 ci*，前向是 c0 加当前前缀长度），采样 n 条前缀并按动作序列归并终点，再对每个非终止终点重启环境、采两条后缀、得到 V^(e) 与成对优势，最后把随机配对的后缀接回前缀、用式 (8) 更新策略参数，并按 pπ(ci)≥η 或 |ℰ| 是否稳定来决定课程是否迈步。状态是文本决策上下文，动作是带思考标签的文本，策略是同一套 LLM，轨迹是多轮交互，优势是终点级与后缀级的相对量而不是学习到的 critic。信用分配因此是结构上的分解，而不是额外标注。一个容易忽略的实现细节是：终点去重只用可执行动作，这会把“想得不一样但点了同一个按钮”的前缀合并，从而让 V^(e) 估计的是环境状态价值，而不是语言表层价值。若不去重，左优势会把措辞差异误当成不同能力边界，课程也就失去“区域”的含义。

关键公式与目标

组相对基线（用于对照）把轨迹级优势广播到所有动作：

A(k)=R(k)−mean(R)std(R)+ϵ

本文的目标把同一条拼好的轨迹拆成两段裁剪目标。记 ρt,k(θ)=πθ(at,k∣ct,k)/πθold(at,k∣ct,k)，前缀步 t=0,…,ℓ−1 使用 AL(ek)，后缀步 t=ℓ,…,Tk−1 使用 AR(ek,jk)：

J(θ)=𝔼[1n∑k=1n1ℓ∑t=0ℓ−1min(ρt,kAL,clip(ρt,k,1−ϵ,1+ϵ)AL)+1Tk−ℓ∑t=ℓTk−1min(ρt,kAR,clip(ρt,k,1−ϵ,1+ϵ)AR)]

与 GRPO 的差别在于：优势不再是整条轨迹共享的一个标量，而是按“到达了哪个终点”和“从该终点如何收官”分开估计。关键超参是终点采样数 NR、反向步长 d、前向增量 Δℓ 与可靠性阈值 η。

手造 Toy Example

设某任务采 n=2 条前缀，分别到达不同终点 e1,e2，故 m(e1)=m(e2)=1。每个终点采 NR=2 条后缀：e1 两次都成功，V^(e1)=1；e2 一成一败，V^(e2)=0.5。前缀加权基线是 (1·1+1·0.5)/2=0.75，于是 AL(e1)=0.25、AL(e2)=−0.25。对 e1，两条后缀结果相同，右优势为 0，但仍有左优势推高通向 e1 的前缀。对 e2，成功后缀的 AR=1−0=1，失败后缀为 0−1=−1。GRPO 若把整条轨迹当作一个样本，一旦两条完整轨迹一成一败，优势只是“整条成功对整条失败”，无法说出“前缀走错了终点”还是“终点对了但收官失败”。成对优势把这两件事拆开，这正是后文单例终点分析里 PA 能给出 V^(e)=0.5、而 GRPO 只能看到 0 或 1 的原因。

基线对照

对照分三族。闭源提示：GPT-4o、Gemini-2.5-Pro。无参数更新的提示智能体：Qwen2.5-Instruct、ReAct、Reflexion。强化学习：轨迹级的 PPO、RLOO、GRPO，以及针对长程信用的 GiGPO（步级分组）与 CRPS（反向回放）。同骨干、同设定下最强的可比较基线是 GiGPO；CRPS 的数字引自原论文、未给标准差。闭源模型只作提示参照，不参与同尺度训练对比。

实验设置

RQ1（主结果）：在相同骨干与训练协议下，成对优势加反向-前向课程能否超过轨迹级 RL 与现有长程信用方法？RQ2（机制）：PA 是否真的扩大了前缀终点覆盖、并在单例终点上给出中间价值？RQ3（消融）：反向、前向与两个阶段的 PA 各自贡献多少？RQ4（代价）：额外的后缀采样会不会把环境交互预算用爆？

模型为 Qwen2.5-1.5B-Instruct 与 Qwen2.5-7B-Instruct。环境是 ALFWorld（3827 个家务任务，六类：Pick、Look、Clean、Heat、Cool、Pick2；评测用 seen 类别与实例变体共 140 题）和 WebShop（超 110 万商品、12000 条用户指令，评测测试集 500 题）。回合上限分别为 50 和 15 轮，输出格式为 <think> 再 <action>。所有 RL 方法：每步 16 个任务、每任务 8 条 rollout；本文再从中采 n=8 条前缀、每个独特终点 2 条后缀。优化器 Adam，学习率 10−6，常数调度，梯度裁剪 1.0，温度 1.0、top-p 0.95。训练在 4 张 NVIDIA H100 上进行，ALFWorld 100 次迭代，WebShop 150 次迭代；每次运行随机采样 128 个任务，三个匹配随机种子平均。本文方法的标准差来自固定检查点上的三次评测种子；部分基线数字引自 GiGPO 与 CRPS 论文。

结果与实验分析

RQ1 主表。在 1.5B 尺度，提示基线整体很弱：Qwen2.5 在 ALFWorld All 仅 4.1%、WebShop 成功 5.2%；Reflexion 也只有 21.8% 与 21.9%。GRPO 把 ALFWorld All 提到 72.8±3.6、WebShop 成功 56.8±3.8；GiGPO 再升到 86.7±1.7 与 65.0±3.2。本文方法达到 90.1±2.0 与 80.2±3.9，相对 GRPO 分别高 17.3 与 23.4 个百分点，相对 GiGPO 高 3.4 与 15.2 个百分点。WebShop 分数为 88.6±1.5，同样高于 GiGPO 的 83.1±1.6。7B 尺度上，本文 ALFWorld All 为 96.1±1.4、WebShop 成功 82.6±1.2、分数 92.5±1.1，相对 GRPO（77.6±5.2 / 66.1±3.7）高 18.5 与 16.5 个百分点，相对 GiGPO（90.8±1.3 / 72.8±3.2）高 5.3 与 9.8 个百分点。最强结果出现在 7B 的 Pick/Look/Clean/Heat：四类均达到 100.0±0.0。最弱的是 1.5B 的 Clean（84.2±4.23，低于 GiGPO 的 94.8±3.8）以及 7B 的 Cool（85.9±6.0，低于 GiGPO 的 89.3±8.2）。作者据此认为方法在不同交互结构的任务上总体有效，但并没有在每一个子类上都压过最强步级分组基线。闭源提示中 Gemini-2.5-Pro 的 ALFWorld All 为 60.3%、WebShop 成功 35.9%，仍明显低于经过 RL 的 1.5B 模型，说明这两项基准的难点主要在多轮交互策略而不是纯语言能力。

RQ2 机制。图 3 在 ALFWorld、Qwen2.5-7B 上比较 PA 与 GRPO 的前缀终点覆盖。两者从同一检查点、同一数据初始化，PA 对每个非终止终点采恰好两条后缀。随着训练进行，PA 保持更宽的终点集合；在只被一条前缀到达的单例终点上，GRPO 只能看到一个二元结果、无法给出中间价值，而 PA 的两条后缀在一成一败时给出 V^(e)=0.5。文中还报告：从最早到最晚的分组，PA 的单例覆盖从约 70 降到 48.7，但价值为 1 的单例从约 25 升到 32.2，价值 0.5 的从约 13 降到 8.1；GRPO 则同时失去覆盖（约 72 到 24.6）和高价值终点（约 34 到 17.9）。这支持“先比较终点、再比较收官”确实在扩大可解区域，而不是只是把成功集中到更少的路径上。图 4 把 WebShop 的 |ℰ| 分成四个阶段：反向阶段把均值从 4.08 压到 2.21，|ℰ|=1 的比例在后期反向达到 46%，说明策略先把 rollout 收束到参考附近的可靠终点；前向早期均值回到 6.68，66% 的组达到 |ℰ|≥7，后期稳定在 4.92。能力区域是先锚定、再向外扩，而不是一开始就广撒网。

RQ3 与 RQ4。表 2 在 WebShop、1.5B 上做组件消融：仅反向且不用 PA 为 68.8%；加上前向升到 74.7%；再只在反向启用 PA 到 76.6%；两阶段都用 PA 达到 80.2%，比仅反向基线高 11.4 个百分点。前向扩张和成对优势都不是装饰。图 5 则表明，尽管前向阶段每组大约 5.9 个独特终点、每个非终止终点还要采两条后缀，PA 在匹配的累计环境步数下验证成功率仍更高；后期反向时 8 条前缀平均只到 2.21 个终点，需要采后缀的终点并不多，而反向已经练出的短收官又限制了前向阶段的无效长轨迹。因此额外分支并不必然推高每步环境交互。作者只定性写道 PA 每步环境步数通常少于基线，没有在正文给出逐步的绝对步数表，这一点应记为证据强度一般。

把这些数字放回研究问题里：主结果支持“整体成功率可以超过最强同设定基线”，但不支持“每一类家务任务都更强”。WebShop 上的相对增益明显大于 ALFWorld（1.5B 上对 GiGPO 的成功率为 +15.2 对 +3.4），这与购物任务更依赖早期搜索是否走进可购买的商品页、因而更吃前缀信用的直觉相符，但论文没有做“把同一批失败案例按前缀错误还是后缀错误分类”的误差分析，这个解释仍是推测。CRPS 在 1.5B / 7B 的 ALFWorld All 为 83.0 / 86.0、WebShop 成功 61.0 / 74.0，低于本文，但其数字无标准差、且是转引，只能作弱对照。训练协议里奖励缩放为 10、关闭 KL 与熵，意味着优化几乎完全依赖成对优势本身；若优势在全后缀失败时消失，更新就会停，这与作者承认的失败模式一致。评测方面，ALFWorld 用的是 140 个 seen 变体而非完全 held-out 的 unseen 官方划分说明中的全部细节，推广边界需要读者自行收窄。

消融、主张与证据、局限

去掉前向课程会损失 5.5 个百分点（80.2 对 74.7 的反向+前向但无 PA 之后，再对照 68.8 的仅反向），说明“先钉住再扩展”不是可有可无的训练顺序。去掉 PA、只保留课程，最高停在 74.7，说明课程提供的是更合适的起点分布，真正把“走到哪”和“如何收官”分开的是成对优势。作者主张：稀疏终局奖励加上能力区域扩张，足以在 ALFWorld 与 WebShop 上超过轨迹级 RL 和强长程基线。实验实际表明的是：在这两个基准、两个 Qwen2.5 尺度、匹配的 8-rollout 协议下，方法的整体成功率与 WebShop 分数全面领先，且消融与终点统计与机制叙述一致。尚未被证明的是：在没有成功参考或不能从中间上下文重置的环境（例如许多真实工具调用与软件工程任务）中，反向阶段是否还能启动；以及 Clean/Cool 上相对 GiGPO 的落后，究竟是任务结构不匹配、参考质量问题，还是超参（如 η）未调。作者自己列出的局限很坦率：反向依赖成功参考，后缀采样要能从中间上下文重启；若所有采样后缀都失败，左右优势都会消失；靠近已知解起步能降低这种风险，但若可解上下文落在已采样前缀够不到的地方，扩张可能停滞。此外，主表部分基线数字来自先前论文而非完全复现，CRPS 没有标准差；训练效率一节缺少逐步环境步的绝对表。奖励是缩放后的二元终局奖励，没有过程奖励或学习型奖励模型，hackability 相对较低，但对“差一点就成功”的轨迹仍然不敏感。

贡献

贡献类型：New Mechanism（能力区域 + 成对优势）与 Objective（前缀/后缀分开的裁剪目标）以及 Empirical Finding（反向锚定后再前向扩张、终点覆盖与代价并不必然恶化）。不是新基准或新数据集。

研究价值与迁移

对 RL/Agent 主线的价值很直接：它给“稀疏终局奖励下的长程 LLM 智能体”提供了一个可操作的信用结构，而不必先训练过程奖励模型。可迁移的机制是“按到达终点的经验价值给前缀打分、按终点内相对成败给后缀打分，并用参考轨迹把训练起点放在能力边界附近”。

原问题是家务与购物这类可重置、有成功示范的交互。迁移问题可以是：在搜索增强或软件工程智能体上，若把“检索到的证据集合 / 测试是否变绿”看作终点上下文，能否用同样的成对优势减少全零组？最小实验是：在 Search-R1 或 SWE-bench 的子集上，用同一骨干比较 GRPO、GiGPO 与“以证据状态或测试结果为终点”的 PA；若环境不能任意重置，可用保存的前缀状态或 teacher-forced 前缀近似重启。模型可用 Qwen2.5-7B 或同级指令模型，基线至少包括 GRPO 与 GiGPO，指标用严格 EM 或 Pass@1，并记录独特终点数与全零组比例。可证伪假设：若终点定义对最终成功没有预测力，则 AL 会退化成噪声，PA 不应显著超过 GRPO。计算成本主要是每终点两条后缀，反向阶段通常更短；风险是参考轨迹质量以及与今日 ECA、既往 Outcome-Mass Alignment / Gaze-RL 的机制重叠。更合适的发表去向是强调智能体 RL 信用分配的会议轨道，而不是再做一个 ALFWorld 刷分短文。计算上，反向阶段 rollout 更短，前向阶段虽然终点变多，但已有的收官策略会截断无效长轨迹；主要额外成本是每终点两条后缀和中间状态重启，在可保存模拟器里通常可接受，在不能重置的真实网站上会显著更贵。碰撞风险来自同日的 ECA（用证据似然做搜索步信用）以及近日的 Outcome-Mass Alignment、Gaze-RL：都在拆长程信用，但终点集合与证据集合不是同一个对象，仍有组合空间。

五句总结

这篇论文把长程智能体 RL 改写为扩张策略诱导的能力区域，而不是再堆更密的过程奖励。成对优势把“走到更可解的上下文”和“从那里收官”分成两个相对信号。课程先沿成功参考向后钉住可解区域，再向前扩到策略自己到达的离线状态。ALFWorld 与 WebShop 上两个尺度都超过 GRPO 与 GiGPO，但 Clean/Cool 并非全胜，且方法依赖参考与可重置。最值得带走的，是用终点经验价值做前缀信用、并用 |ℰ| 稳定与否来推进课程这一套可检验的设计。

S Replay, Don't Resample: Off-Policy Consolidation of Long-Horizon RL Experts

人话版：这篇论文到底干了什么？

前沿模型的后期训练常常是：先在每个领域用强化学习训一个专家，再把这些专家并成一个学生。现在流行的做法是 multi-teacher on-policy distillation（MOPD）：学生必须在每个环境里重新采样，教师再给每个 token 打分。这很贵，而且学生会继承最终专家已经漂掉的行为。作者指出，专家自己的 RL 日志里其实已经有合并所需的东西——按学习顺序排好的轨迹、采样概率和奖励。

他们提出 MRPD：按专家原来的训练顺序回放这些日志，在记录轨迹上重算策略梯度，并在记录前缀上把学生拉向最终专家的下一 token 分布。回放虽然来源是离策略的，但因为学生始终跟着当时的记录策略走，重要性比大多落在裁剪区间内，所以过程是准在策略的。合并时既不采样、也不调用环境或奖励模型，在三个长程智能体域（推理、搜索、SQL）上得到最好的学生，整体平均 58.6，超过在线 RL 与同一批专家上的 MOPD，而合并成本大约只有训这些专家的七分之一。

背景与研究缺口

用可验证奖励做强化学习，已经是把语言模型变成会用工具的长程智能体的标准路径。一旦领域变多，实验室往往先训单域专家，再合并。参数合并（uniform soup、TIES）几乎免费，但常常在某些域塌掉。在策略蒸馏则更强：学生在环境里采样，教师在这些新前缀上提供 token 级 KL 或奖励，Kimi K3、DeepSeek-V4 一类系统都走这条路。代价是明确的：每一步都要等最长的那条轨迹，工具调用和教师前向叠在一起；并且教师是最终专家，学生会把最终专家已经学歪的行为（例如搜索把回合用满）一起学过来。

日志通常在训练结束就被扔掉。并发的 REGEN 开始回收单域 GRPO 的 rollout，但把它池化成一个数据集，用离线的优势加权似然来训。这就把“专家是怎么学会的”变成了“专家最后留下了哪些样本”。缺的是把日志当成课程：早期批次来自接近初始化的策略，晚期批次才接近最终专家。若学生按这个顺序走，它面对的记录策略始终跟自己很近，离策略数据也可以用在策略的裁剪更新来消化。若不按顺序、把 300 步洗成一锅，学生会同时遇到所有阶段的轨迹，训练-推理间隙会一直很大。MRPD 要检验的正是：顺序本身是不是比数据量或奖励形式更重要。

核心洞察

专家强化学习已经为合并付过一次环境交互的账。真正该再利用的不是最终检查点里的静态样本，而是按时间排好的训练日志。顺着这条课程回放，重要性比可以对着记录策略来算，学生会保持准在策略；再在同样的前缀上蒸馏最终专家的分布，就能同时保留“当时是怎么学会的”和“最后学会了什么”。日志是课程，不是数据混合。

方法深读：从输入到输出

设定有 D 个域，每个域有环境、工具和二元奖励 R∈{−1,+1}。所有模型从同一个监督检查点 πref 出发。域 d 的专家用强化学习训 K 步，最终教师记为 πTd。专家在第 k 步用记录策略 πk,oldd 采样一批轨迹，执行工具、打分，再更新得到 πkd。每条样本存下 token (x,y)、只覆盖模型生成 token 的损失掩码 M（工具输出不进损失）、奖励 R，以及采样对数概率 logπk,oldd(yt∣x,y<t)。全部专家日志组成学生的回放缓冲。

MRPD 同样走 K 步。第 k 步取各专家第 k 个训练步的批次并起来，做一次优化。学生因此按时间顺序消费专家经验：先靠近 πref，再靠近最终专家。凡是涉及重要性比的目标，都对着当时的记录策略计算 rt=πθ(yt∣x,y<t)/πk,oldd(yt∣x,y<t)。这正是专家自己那次裁剪更新里的比，只是把专家换成了学生。因为回放保持时间顺序，学生与 πk,oldd 的间隙大部分时间落在裁剪范围内，所以数据虽是离策略采来的，更新过程仍是准在策略的。这是反直觉处：通常离策略数据最怕的是比率炸裂，这里用“跟着专家的学习轨迹走”把炸裂压住，而不是再引入保守的行为克隆约束。

目标由两项组成。策略梯度项与 GRPO 相同，优势是同一 prompt 的 g 个样本组标准化后的 A^=(R−R¯)/(σR+ϵ)，再对 rt 做双侧裁剪；全对或全错的 prompt 没有梯度，也没有额外 KL 惩罚。蒸馏项在每个被掩码覆盖的记录前缀 st=(x,y<t) 上，把学生拉向该域最终专家：ℓKL(st)=βKL(πθ(·∣st)‖πTd(·∣st))。KL 可以只在记录 token 上做有偏估计并走进优势与裁剪（sampled-token），也可以在词表上闭式计算、直接最小化且不经过裁剪（dense）。默认是 dense 反向 KL，用 top-k 个 token 加一个尾质量原子，k=256，β=1。完整目标在记录批次而不是 πθ 自己的样本上取期望，第一项把专家当时的训练目标接到学生身上，第二项在每个位置把学生拉向最终专家。

变体用来分离机制：只用 sampled-token 蒸馏；去掉蒸馏只留 PG（离线 GRPO）；去掉 PG 只留蒸馏；两项都去掉则退化为对全部记录做 NLL（SFT）或只对 R=1 的样本做 NLL（offline RAFT）；以及把 dense 项改成前向 KL。代价上，MRPD 每一步只有学生更新和各专家在本域记录批次上的一次前向，没有学生生成和工具调用。状态是带工具观察的多轮前缀，动作是模型 token，策略是共享的学生 πθ，轨迹来自专家日志，奖励是可验证的二元结果，信用来自组相对优势，蒸馏则提供稠密的 token 级教师信号。

一次更新的数据流是：读出第 k 步三个域的日志批次并拼接，对学生做前向得到 πθ 在记录 token 上的概率以及（若用 dense KL）在 top-k 原子上的分布，对各专家只在本域记录前缀上做一次前向以提供教师分布，然后用记录的旧对数概率计算比率与组相对优势，反向传播式 (3)。没有环境步进，也没有学生自己的解码循环。掩码 M 把检索到的文档、SQL 结果或代码输出排除在损失之外，避免学生去模仿环境文本。默认选择 dense 反向 KL 而不是 MOPD 常用的 sampled-token 估计，是因为后者要穿过重要性比和裁剪：一旦学生暂时走出记录策略的邻域，最需要纠正的 token 反而得不到梯度；闭式 KL 不经过裁剪，能把学生拉回教师邻域。这也解释了后文打乱顺序时，没有 KL 的设定掉点更狠。超参上 β 默认取 1，表 4 显示 0.1 到 3 的变化只带来不到一个 Overall 点的摆动，说明方法对蒸馏强度并不脆弱；真正敏感的是批次顺序，而不是这一系数。工具输出被掩码还带来一个实现上的好处：学生不会在 SQL 结果或检索段落上浪费梯度，PG 与 KL 都集中在模型自己该负责的 token 上。

手造 Toy Example

设想两个域、各两步日志。第 1 步专家还接近 πref，记录概率高，学生从同一初始化出发，重要性比接近 1，PG 项几乎就是专家当时的更新。第 2 步专家已经变强，若学生也按顺序走完了第 1 步，它仍靠近第 2 步的记录策略，裁剪很少触发，同时 dense KL 开始把剩余质量拉向最终专家。若把两步洗乱，学生在第 1 次更新就可能碰到第 2 步的“已经很强的专家轨迹”，比率大量出界，PG 被裁掉，只剩（或甚至没有）蒸馏项可学，这正是后文“打乱顺序损失更大、尤其在去掉 KL 时”的微型版本。奖励在全对或全错的组内不提供梯度，这些组要靠蒸馏项才能动。

基线对照

无训练：πref、均匀 soup、TIES（density 0.2，λ=1）。在线 RL（三域同时，每域每步 24 prompt × 8 样本，共 576 条，300 步）：RAFT、GRPO、PPO。在策略蒸馏：MOPD，以及加任务奖励的 MOPD+GRPO。单域 GRPO / PPO 专家作为上限参考，不参与学生排名。最强需击败的训练学生基线是 MOPD 与 MOPD+GRPO；最强训练免费基线是 TIES。

实验设置

RQ1：同一批专家日志上，MRPD 能否在更低成本下超过在线 RL 与 MOPD？RQ2：增益主要来自轨迹本身，还是来自 PG 与蒸馏两项？RQ3：日志的顺序、数量与 β 谁更重要？RQ4：回放是否真的保持准在策略（训练-推理间隙与裁剪比例）？

三个智能体域：推理是 ReTool 设定的竞赛数学加 Python 沙箱，最多 16 次代码、16k token；搜索是 Search-R1 设定，E5 检索 Wikipedia，最多 8 次搜索；SQL 是 Spider 与 BIRD，只读 SQLite，最多 8 轮，按执行对错计分。训练提示分别为 DAPO-Math-17k、NQ+HotpotQA、Spider 训练集。所有模型从 Qwen3-4B 经 ReTool SFT 冷启动后的 πref 出发。专家是单域 GRPO：每步 64 prompt × 8 样本，学习率 10−6，clip (0.2,0.28)，无 KL，异步训练 K=300 步。默认回放批次为 3×64×8=1536 条/步，学生也走 300 步并沿用专家超参。评测在 300 步后、十六个 held-out 集上进行：AIME 2024/2025 与 AMC 2023 用 32 样本平均准确率，Minerva、OlympiadBench、MATH-500 用 4 样本；七个搜索集用 exact match；Spider dev/test 与 BIRD dev 用 4 样本执行准确率。Overall 是三个域平均的再平均。训练与计时均在 8 张 H100 上。

结果与实验分析

RQ1 主结果与成本。表 1 中 πref 的 Overall 仅 28.2，均匀 soup 到 46.1，TIES 已经到 56.8，说明免费合并并不弱。在线 RAFT / GRPO / PPO 为 51.5 / 52.5 / 52.6，反而低于 TIES，也远低于单域 GRPO 专家的 59.3 与 PPO 专家的 57.4。MOPD 与 MOPD+GRPO 达到 58.1 与 58.2。MRPD 以 58.6 成为最好的训练学生，并且是唯一在三个域都进入前两名的学生：推理 63.7（MOPD 略高，为 63.8）、搜索 42.0（TIES 最好，为 42.6）、SQL 70.1（甚至略高于该域 GRPO 专家的 69.6）。相对三个在线 RL，MRPD 至少高出约 6 个点；相对同一批专家上的 MOPD，它略强，但成本差距很大。8 张 H100 上，MOPD+GRPO 300 步要 29.4 小时，在线 GRPO 22.1、PPO 24.1，MRPD 为 9.2 小时。三个专家自己分别用了 30、32 与 4.5 小时，合并只占其训练算力的 14%，约七分之一。MRPD 单步平均 110 秒（更新 79、专家前向 24、读下一批日志 6），最长不超过 173 秒；MOPD+GRPO 单步平均 350 秒，其中 340 秒是生成，最长一步 878 秒（文中另一处写到 1887 秒属于 PPO 的极端慢 rollout）。若把回放改成与在线方法等量的 576 条/步，全程只需 3.7 小时，单步 44 秒，约为 MOPD+GRPO 的八分之一、在线 GRPO/PPO 的六分之一。表 4 显示这个数据匹配设定只让 Overall 下降 0.2，仍有 63.6 / 41.6 / 70.1 的域平均。

RQ2 轨迹与两项损失。最干净的对照是：同样按顺序回放、把两项都去掉。表 3 中，对全部记录做 SFT 得到 57.5，只对正确样本做 RAFT 得到 57.6，只留 PG 的离线 GRPO 为 57.7。它们已经超过所有在线 RL，离线 RAFT 相对在线 RAFT 的 51.5 高出 6.1 个点。作者的解释是：每一步日志都来自在该域走得更远的专家，而不是来自同时打三个域、更慢爬升的学生。蒸馏项贡献最大：单独用 sampled-token KL 到 57.7，dense 反向 KL 到 58.2；再加 PG 分别升到 58.2 与 58.6。因此默认 MRPD 比日志 SFT 高 1.1–1.2 个点，大约走完了通往专家上限的三分之二。时间动态也不同：dense KL 单独学得最快，100/200/300 步为 57.9 / 58.4 / 58.2，后期停滞；加上 PG 后起得慢一些，但 300 步时更高。前向与反向 KL 单独几乎打平（58.3 与 58.2），加上 PG 后反向升到 58.6、前向降到 57.8，差距出现在最后 100 步。作者猜想这时学生已靠近专家，剩余误差落在自己的高概率 token 上，寻求众数的反向 KL 更能容纳 PG 的更新。

RQ3 与 RQ4，以及一个失败继承现象。表 4 是关键证据：把 β 从 1 改到 3、0.3、0.1，Overall 只掉 0.5 到 0.7；把每步样本从 1536 减到 576，只掉 0.2；把 300 步打乱，dense KL 掉 0.6，sampled-token 掉 1.0。去掉 KL 后打乱的惩罚更大，表 3 中 SFT / RAFT / PG-only 分别掉 3.8 / 2.6 / 3.1。打乱并不会让学生一开始更慢：200 步时打乱甚至与顺序持平或略高（dense 为 58.1 对 57.8），但随后 100 步几乎停滞，顺序回放却还能再涨 0.8 到 1.4。于是“顺序比数量或奖励更重要”不是口号，而是同日志上的可重复差值。MOPD 在搜索上最弱（40.6），图 5 显示最终搜索专家约 60% 的轨迹打满回合上限，MOPD 的学生从第 50 步起就有约 80% 打满；回放在记录前缀上蒸馏，不重新采样那些已经漂掉的长轨迹，因而没有继承这条曲线。训练-推理对数概率差在顺序回放中大多落在裁剪区间，最多约 4% 的 token 被裁剪，并随日志靠近最终专家而缩小；打乱回放则一直维持高间隙。熵方面，MRPD 从 0.38 走到 0.36，没有崩也没有被蒸馏抬飞。第二次独立的 MRPD 跑到 58.5，与主结果 58.6 接近。最弱的地方也很清楚：搜索上 TIES 仍然略高；方法依赖学生与专家共享同一 πref，换初始化尚未做；规模停在 4B 稠密模型、三域、单次主运行。训练奖励曲线（图 3）不能用来给方法排名：回放看到的是专家日志的平均奖励，在线方法看到的是自己 rollout 的奖励；两者都从约 −0.4 起步，MOPD 因最终专家从第一步就给 token 级信号而升得最快，约 30 步过 0.2，回放日志约 75 步才过 0.2，最后 50 步三者都在约 0.34，在线 GRPO/PPO 则只到 0.14 与 0.19。真正用来比较的是 held-out 表。

消融、主张与证据、局限

去掉顺序（打乱）比去掉三分之二的样本更伤，尤其在没有 dense KL 的时候，这是全文最强的机制证据。去掉蒸馏项后只剩 57.5–57.7，去掉 PG 则停在 58.2 左右，两项都有贡献但蒸馏更大。作者主张三句：回放轨迹本身已经贡献了大部分增益；PG 与蒸馏都有用；顺序比数量或奖励更重要。实验实际表明的是：在共享 πref、Qwen3-4B、三个可验证奖励域、300 步这一设定下，这些主张都被同日志对照支持，而且第二次运行的 58.5 与主结果接近。尚未被证明的是：若学生与专家不是同一初始化，准在策略性质是否还在；若换成更大模型或 MoE，成本优势与顺序效应是否仍在；以及搜索上 TIES 略优是否意味着合并在检索任务上另有结构。作者的局限写得很清楚：所有实验都从同一 SFT 检查点出发，没有试过“学生来自别的检查点”或“专家来自别的检查点”；规模限于 4B、三域、多数配置单次运行。额外还应记下：在线方法用 576 条/步、MRPD 默认 1536，主成本对比虽也给了数据匹配的 3.7 小时，但主精度表对应的是 1536 设定；奖励是可验证二元，hackability 低，但搜索打满回合这一漂移说明可验证奖励仍可能学到不良回合结构，只是 MRPD 因为不重新采样而没有把它放大。若有人只看 Overall 的 0.4–0.5 点优势，可能觉得相对 MOPD 几乎打平；真正改变决策的是成本与机制：同样接近专家上限，却不必再付一轮环境交互，并且不会把最终搜索专家的回合膨胀继承过来。

贡献

贡献类型：New Mechanism / Objective（按专家训练顺序回放并组合 PG 与最终专家 dense KL）与 Empirical Finding（日志是课程；顺序大于数量；合并成本约七分之一）。同时提供系统路径：合并阶段不再调用环境。代码已给出。

研究价值与迁移

对 RL 与智能体主线，这篇论文改变的是“多专家如何变成一个通才”的默认流程。可迁移机制是：把已有 RL 运行的日志当作有序课程，在记录策略上重算裁剪策略梯度，并在同一前缀上蒸馏最终专家。原问题是推理、搜索与 SQL 三个可验证域的合并。新问题可以是：把近日的单域智能体 RL 专家（例如用 Depth Before Breadth、FlashREINFORCE 或异步协议训出的工具使用专家）的日志按序回放，看在不能共享同一冷启动、或域数更多时，顺序效应是否还在。最小实验是两到三个域的 7B 级专家，比较“按序 MRPD、打乱、池化后的离线 GRPO、以及 MOPD”，主指标用各域 held-out 平均与总体平均，辅以裁剪比例、训练-推理对数概率差和墙钟。可证伪假设：若学生初始化与记录策略差到大多数比率被裁掉，而 dense KL 又不足以把学生拉回邻域，则按序回放不应再明显好于打乱。计算上，回放没有生成与工具调用，成本优势在更长视野下理应放大，但专家前向（尤其是 dense 词表 KL）会随模型变大而上升。碰撞来自 MOPD、并发的 REGEN，以及同日的 COPD / 在策略蒸馏理论分析；差异在于 MRPD 强调时间顺序与准在策略，而不是再采学生轨迹。一个更具体的下一实验是：把 FlashREINFORCE 一类异步单轨迹协议里本来就会写下的日志直接交给 MRPD，检验“没有组内兄弟样本时，按序回放加 dense KL 是否仍能合并多域专家”。若异步日志的记录策略跳动更大，裁剪比例会成为关键中间指标。

五句总结

MRPD 不让学生重新进环境，而是按专家学习过的顺序回放训练日志。策略梯度在记录轨迹上重算，最终专家的分布在记录前缀上蒸馏，过程保持准在策略。三个长程智能体域上它得到最好的学生，合并大约只需专家训练算力的七分之一。同日志消融表明：轨迹本身贡献大部分增益，顺序比样本数量更重要。最需要警惕的前提是学生与专家共享同一初始化，以及目前规模仍停在 4B。

人话版：这篇论文到底干了什么？

流式视频问答有严格的内存和延迟限制。只看最近几帧，当前感知清楚，但历史会丢；把过去帧也塞进上下文，又会稀释对当前场景的注意并引发幻觉。现有级联系统往往在不确定时再去检索历史，却处理不好当前帧模糊、或关键线索还没出现这两种情况。ActiveForager 做一个流式视频智能体：默认只维持干净的短工作窗，需要时才在四种动作里选——直接回答、放大最近高分辨率帧、从记忆中召回并让共享权重的子智能体隔离验证、或者等待后续帧。

为防止历史证据干扰当前视觉 token，作者加上 Stream-Decoupled Attention Mask（SDAM）。策略用 TUPO 训练：只有当工具带来的证据真的提高了正确答案的似然、并且最终答对时，才给工具奖励，从而避免工具崩塌。在 OVO-Bench 上，方法在更少的主上下文视觉 token 下同时提升实时感知、历史回溯和前瞻响应；在 Video-Holmes 上还把 Qwen3-VL-8B 的零样本多跳准确率从 23.57% 提到 47.14%，约为一倍。

背景、洞察与管道

流式设定里，主上下文若持续堆积历史帧，注意力会被拉走。作者的洞察是：工作窗应当保持短而干净，额外证据只按需采集，并且历史视觉与当前视觉在注意力上要隔开。管道是：对每个查询，策略先写简短诊断再选 a1∈{Answer,ZoomIn,Recall,Wait}。ZoomIn 读 CPU 环形缓冲里的高分辨率裁剪或密帧；Recall 按时间重叠与变化分数排序历史片段，子智能体在干净 KV 缓存中隔离验证，只在状态为 Found 时返回短事实卡加一帧锚点；Wait 有界地推迟决策。SDAM 在所有层阻断最近帧与额外证据之间的直接注意；当 Recall 成功时，答案 token 不再直接看最近窗，而是看验证过的历史锚点，避免把两段视觉混在一起。

TUPO 先用 SFT 初始化交互格式，再用反事实工具效用做强化学习。冻结参考模型比较加证据前后正确答案 y* 的对数似然，按答案长度归一化得到 ΔIi；正的工具奖励还要求最终答对、且诊断文本与所选动作匹配。总奖励为 Ri=Racc+λigRIG+λfmtRfmt−λcostCi，优势是组中心化但不做方差标准化，并按轮次而不是按 token 数均衡路由轮与合成轮，避免长答案吞掉路由更新。这与“只要最终对了就奖励所有工具调用”相反，正是为了阻止工具崩塌。

人话版：这篇论文到底干了什么？

搜索增强语言模型用终局答案奖励做强化学习时，一条轨迹里每一次检索都拿到同一个对错分数。更糟的是，若一组 rollout 全部答错，组中心化优势会变成零，即使有的轨迹已经检索到了有用文档。ECA 在训练时额外引入一个只服务于信用分配的信号：用冻结的当前策略，在“只含问题与去重后已检索文档、不含思考和查询文本”的证据提示上，看参考答案的似然提高了多少，从而把检索的信息增益从措辞变化里隔离出来。

作者比较了两种回报：ECA-Step 累加逐步裁剪后的势函数增量，ECA-Horizon 保留望远镜式的全程势差，并配上交叉折组标准化、新颖性门控和搜索局部的 token 赋值。在七个 Search QA 基准上，ECA-Horizon 相对纯结果 GRPO 的严格宏平均 EM 在 Qwen2.5-3B/7B-Instruct 上分别提高 1.03 与 4.80 个百分点，并在 MultiHop-RAG 的 816 道多跳推理题上零样本迁移。

背景、洞察与方法管道

Search-R1 一类方法让模型在推理中穿插检索，只用最终答案是否匹配来做 GRPO / RLOO，从而不必标注每一步检索。问题是结果奖励没有分辨“这次搜索是否带来了新证据”。全失败组尤其致命：相对优势塌缩，那些其实已经搜到桥接实体的轨迹也无法学习。GiGPO 用状态分组缓解一部分方差，但仍缺少对检索内容的中间监督。

核心洞察是：文档对参考答案的似然贡献，可以在一个去掉思维链和查询措辞的证据专用提示上单独测量。设 Φi(D) 为冻结策略在只含问题与文档集合 D 的提示下，对规范别名 y* 的对数似然。一次新检索把 Dk−1 变成 Dk，势差就估计这次搜索的信息增量。ECA-Step 把逐步增量裁剪后累加，ECA-Horizon 保留从当前证据到回合结束的望远镜差，避免逐步裁剪切断远程贡献。新颖性门控在 Dk=Dk−1 时不给正信用，以抑制重复查询。该信号只在训练期计算，推理成本不变。

A Keep the Reasoning, Read the Image: On-Demand Visual KV for Multi-Turn Reasoning VLMs

人话版：这篇论文到底干了什么？

会长时间思考的视觉语言模型，常靠 KV 保留策略在推理变长时把缓存控制在可承受范围。作者发现，这种修剪在多轮对话里牺牲的是图像：图像和推理共享一个预算，推理一变长，视觉条目就被挤出。一道 CharXiv 图问题，若先问，相对完整缓存只掉 8 分左右；若放在一轮推理之后再问，会掉约 24 分。问题不是容量不够，而是图像没有被保护：同样多的名额若只是加进共享预算，恢复远不如留出一个不可驱逐的视觉储备。

据此他们提出训练无关的 ShelfKV：所有视觉 KV 放在 CPU“架子”上永不删除，每步解码只把当前查询得分最高的视觉条目换进 GPU“书桌”上那些文本条目得分最低的注意力槽。图像不会被驱逐，却只在被读取时占用注意力槽。在对话设定里，它把最强宿主策略 DBTrimKV 在匹配 GPU 内存下最多提高 20.3 个点，并且在 DBTrimKV 使用约两倍内存时仍领先 8.7 个点。

背景、洞察与方法

多轮推理 VLM 的 KV 保留原本是为了让很长的思维链塞进有限 GPU 缓存。已有策略按注意力、近因或冗余来删历史 token，并没有把“图像区域”和“正在增长的推理”区分开。核心洞察是：图像需要被保护，但不需要每一步都占着注意力槽。ShelfKV 叠在现有宿主策略之上：宿主继续决定哪些文本 KV 留在 GPU；全部视觉条目另存一份在 CPU，并用低维草图（默认 r=32、4 bit）按当前查询打分，把高分视觉条目与书桌上最低分的文本条目交换。这样 GPU 条目数保持与对照设置匹配，但注意力读到的是当前问题真正需要的那一块图像。反直觉之处在于：把同样的槽位永远留给一块固定视觉储备，不如按需把槽位让给当前查询所要的区域；而推理文本却不应该也放到架子上按需读，因为后续步骤会反复用到它。

实验与结果

主实验用 Qwen3-VL-8B-Thinking 与 4B-Thinking，宿主策略为 R-KV 与 DBTrimKV，评测包括 CharXiv 追问、自由多轮 CharXiv 对话（计第 2–4 轮）、MMMU-Pro 与 MMDU。表 1 在 DBTrimKV、8B 上：宿主 B=256 时 CharXiv 追问 61.3%，B=512 为 73.0%，B=1024 为 78.0%；ShelfKV 在 386 个 GPU 条目/头时达到 84.0%，在 259 条目时为 81.7%。81.7 相对 B=256 的 61.3 大约高 20.4 点，与摘要“最多 20.3 点”一致；81.7 相对 B=512 的 73.0 恰为 +8.7，对应“宿主用两倍内存时仍领先 8.7 点”。自由对话上 ShelfKV 为 85.0，对照 DBTrimKV 在 1024 条目的 79.4；MMDU 分为 4.9 对 4.5。与匹配 GPU 内存的固定视觉储备相比，追问从 79.0 到 84.0，对话从 81.9 到 85.0。单轮 MMMU-Pro 的优势最小（56.7 对 55.3），符合“只有后轮问题需要推理没用过的区域时，保护图像才划算”。R-KV 宿主上增益同样存在，但绝对精度仍明显低于完整缓存，因为弱宿主会把推理文本也删掉。

人话版：这篇论文到底干了什么？

视频扩散变换器的推理成本主要来自超长 token 序列上的自注意力。Wan2.1 在 720p、81 帧时要处理 75,600 个 token，一段五秒视频在单张 H100 上稠密注意力要约 28 分钟。现有基于聚类的稀疏注意力往往把查询和键都聚类，并让同一查询簇共享一份键簇选择。作者证明：在键簇和密度固定时，把查询簇分得越细越准，最准时其实是每个查询自己选，根本不必对查询聚类。

PQRS 因此只聚类键，让每个查询独立选择键簇，并用簇质心补偿未选中的部分。为了在没有共享键列表的情况下仍然跑得快，它按键簇遍历、把选择相同的查询收成稠密任务，并用上一去噪步留下的 softmax 偏移一次性合并。在 Wan 与 HunyuanVideo 家族的四个 T2V/I2V 模型上，它是所比较稀疏方法里最快、也最接近稠密输出的一个。

核心方法与主要结果

方法是训练无关的。实现上四个模型共用 Ck=592 个键簇、路由阈值 p=0.848、地板 f=0.10，并在前 20% 去噪步和每个 Transformer 堆叠的第一块保持稠密注意力。评测用 50 条 VBench 增强提示（T2V）和 50 对 VBench++ 图像-提示（I2V），在单张 H100 上按各模型官方采样配置计端到端延迟。表 1 的关键数字：Wan2.1-T2V-14B 上 PQRS 的 PSNR 28.86 dB、SSIM 0.909、LPIPS 0.094，密度 22.0%，延迟 960 秒、加速 1.75×（稠密 1682 秒）；同密度附近的 SVG-EAR 为 27.19 dB / 1032 秒 / 1.63×。HunyuanVideo-T2V-13B（129 帧）上 PQRS 为 35.44 dB、809 秒、2.10×（稠密 1701 秒）。Wan2.1-I2V 为 29.97 dB、1.74×；Wan2.2-T2V-A14B 为 23.47 dB、1.66×。VBench 与稠密几乎持平。消融写明：即使不做质心补偿，逐查询选择也比共享选择高 0.9 dB；补偿加在逐查询上再涨 3.1 dB，高于加在共享选择上的 1.7 dB。单次稀疏注意力调用在 Wan2.1-T2V 上为 97.8 ms，相对稠密 329.1 ms 加速 3.52×，密度 23.2%。图 1 里单条样本的 16.0 分钟 / 1.75× 与主表一致，但样本 PSNR 27.61 低于 50 条平均的 28.86，比较时应看表 1。
