When Every Rollout Fails: Splicing Learner-Conditioned Options into Long-Horizon Agent RL

Haowen Hou, Yicheng Liu, Zhen Huang, Jiaqi Wang · 作者单位未核实（arXiv HTML 的 affiliation 字段为空） · arXiv:2611.34777 · 2026-11-26 新提交（Thursday, 26 November 2026 公告） · 状态：预印本，cs.LG / cs.AI / cs.CL · 全文：已读 arXiv HTML 方法、实验与表格 · 代码：未核实 · abs · PDF · HTML

人话版：这篇论文到底干了什么？

长程智能体若用可验证的二元奖励做组相对策略优化，一组 rollout 经常全部失败。组内奖励全是零，组相对优势也变成零，这一步就不再有基于奖励的策略梯度。常见补救是向更强模型要一整条成功轨迹再做监督，但这既贵，又让学生长时间暴露在教师的离策略历史上。SPLICE 只处理全失败组：提议模型在当前失败轨迹里选一个可恢复的拼接点，从那里生成若干有界 option；若 option 本身没有做完，就用当前策略把任务续写到结束，用这些续写的平均回报估计“这个 option 对学生是否用得上”。只保留正回报 option，按回报加权得到局部目标，并且损失只打在 option 内部的动作 token 上，不监督教师续写的后缀。主实验在软件工程（SWE-bench Verified）和深度检索（BrowseComp-Plus）、Qwen3-8B 冷启动与 Qwen3.5-9B 两套策略上都超过直接 GRPO 和完整教师轨迹指导。更关键的是，它对当初失败训练任务的毕业率高于提议命中率更高的 ReLIFT，同时提议模型回合更少。增益主要来自中等和困难任务，简单任务已经饱和。

Background & Research Gap

组相对策略优化把同一任务的一组轨迹拿来标准化终局奖励，从而避免学习价值网络。这个设计在数学题这类“一组里总能采到对和错”的设置里很有效，但换到上百轮的软件工程或深度检索，问题就变了。环境反馈稀疏，成功轨迹本身就少；若一组 G 条轨迹全部失败，组均值和组标准差都退化，优势估计对每条轨迹都是零，奖励相关的梯度随之消失。全成功组至少还保留了可强化的行为，全失败组则什么都不提供。论文把后者单独称为 all-fail group，并把它当作长程智能体强化学习的结构性瓶颈，而不是调一调学习率就能消失的噪声。

已有补救大致有两条。一条是先做拒绝采样监督微调，让策略先见过成功轨迹，再跑强化学习；另一条是在训练过程中向更强模型要完整轨迹，只在验证通过后写入缓冲区，再触发一轮监督，ReLIFT 是这一路线的代表。两条路都依赖“教师把整件任务做完”。完整教师轨迹有三个不便：提议模型要跑完全程，成本高；学生要拟合一条很长的离策略历史，协变量偏移会沿轨迹累积；教师觉得好的后缀，当前学生未必接得住。长程智能体真正缺的，往往不是整份标准答案，而是在某个失败前缀之后、学生自己还能接着做完的一段局部修正。这个差距正是 SPLICE 要填的：把外部指导限制在有界 option，并且用当前策略的续写，而不是教师自己的续写，来决定这段 option 有没有训练价值。

Core Insight

全失败组不是没有信息，而是终局奖励无法在组内对比。若在失败轨迹的中途插入一段教师生成的有界 option，再用学生自己把任务做完，这段 option 的价值就可以用学生续写的通过率来定义。训练目标应当相对这些被保留的 option 加权，并且只更新 option 内部的 token；把教师续写的成功后缀也写进损失，反而会加重离策略暴露，效果更差。反直觉之处在于：提议命中率更低、教师回合更少的方法，毕业率可以更高，因为“教师能做完”并不等于“学生接得住”。

Baseline Comparison

对照在同一份 3,200 任务子集和同一初始策略上展开，控制的是任务数据而不是计算量。直接 RL 即对初始策略做 GRPO，是最弱但最干净的强化学习基线。SFT 用提议模型为每道题生成完整轨迹并拒绝采样，只保留成功样本。SFT+RL 从该监督检查点再跑与 SPLICE 相同步数的 GRPO，是计算更重、也是主表上最强的非 SPLICE 基线。ReLIFT 被改成在线版本：每个全失败组请求一条完整教师轨迹，验证成功后入缓冲，缓冲满 64 条再微调，是最直接的完整轨迹指导对照。后文以 SFT+RL 为最强总体基线，以 ReLIFT 为最强在线指导基线。

Contribution

方法贡献是把全失败组改写成“拼接点上的学生条件 option 监督”，而不是再要一条完整教师轨迹。目标贡献是用组内标准化后的续写回报构造回报加权分布，并证明它在经验上不低于均匀监督。实验贡献是在两个任务、两套策略上同时报告解出率、毕业率、提议命中率和教师回合，并把增益定位到中等与困难任务。工程贡献是把强化学习与 splice 更新分成不同小批量交替进行，提议模型和分支重建只在训练时使用。

Claim vs Evidence

作者声称 SPLICE 能从全失败组恢复学习信号，并在四个设置上超过 GRPO 与完整轨迹指导，同时降低提议模型开销。实验实际表明：在 SWE-bench Verified 与 BrowseComp-Plus 上，它对 Qwen3-8B-CS 和 Qwen3.5-9B 的均值都最高；毕业率 18.9% 高于 ReLIFT 的 15.9% 与 RL 的 8.1%，教师回合从 113.4k 降到 93.5k。尚未被证明的是：该优势是否能推广到提议模型弱于学生、或环境无法快照恢复的设定；三次续写的价值估计误差有多大；以及墙钟优势在执行非常昂贵的环境里是否还成立。消融支持软分布优于单 option 和硬选最大 Q^，但这些比较都固定在同一套 K=M=3 与 α=0.3 上。

Limitation

作者承认两点。第一，每个 option 要用当前策略做多次续写，异步流水线在他们的实验里只增加有限墙钟，但环境执行很贵时，这个代价可能被放大。第二，默认只用三次续写估计 Q^k，存在采样误差；提高精度就要更多续写或更强模型，质量和成本需要权衡。还可以补充：作者单位与代码均未在可获取页面中核实；主分析集中在 Qwen3-8B-CS，Qwen3.5-9B 只有主表；Deep Research 环境只存交互历史、不能像 SWE 那样恢复容器快照，方法对状态恢复质量的敏感性没有单独成表；训练墙钟只有“少于 ReLIFT 和 SFT”的定性结论，正文没有给出精确 GPU 小时。简单任务已经接近 99%，SPLICE 并不创造新的简单题收益，它解决的是中等和困难任务的探索失败。

Research Value

对强化学习，这篇工作把“全失败组没有梯度”从调参问题改写成可操作的数据构造问题。对智能体，它表明外部指导应该以学生能否续写为准，而不是以教师能否做完为准。这一机制可以直接迁到工具调用、可视化检查和多轮检索：当整段轨迹没有终局奖励时，只拼接一段有界修正，并用当前策略评估这段修正。

Migration / Research Transfer

原问题是长程智能体的全失败组。可迁移机制是：在失败前缀上插入有界 option，用当前策略续写估计学生条件价值，再对保留 option 做长度归一的加权监督。新问题可以是：在视觉工具智能体里，当所有观察动作都没能改变最终对错时，能否只拼接有界的观察 option，而不是重放整条教师看图轨迹。方法改动是把拼接点从容器快照改成图像检查历史中的可恢复观察边界，用通过率或即时答题置信度作为 R(τ)。最小实验建议在一个带局部观察工具的视觉问答或 GUI 智能体上，比较直接 GRPO、完整教师轨迹指导，以及学生条件 option 拼接。模型可用 7B–8B 视觉语言或工具智能体，数据集可用公开的多跳视觉问答或短程 GUI 任务，基线至少包括 GRPO 与完整轨迹 SFT，指标为任务成功率、毕业率和教师回合。可证伪假设是：在教师命中率更低的情况下，学生条件 option 仍能提高毕业率；若学生续写与教师续写一样好或更差，且教师回合没有下降，则假设失败。计算成本中等偏高，因为要为每个 option 做多次续写。撞题风险来自同日的 Collect for Coverage、近一周的 SAEPO、FReDraft 以及 Replay, Don't Resample，差异化应坚持“有界 option + 学生续写，而不是模块级优势或完整轨迹回放”。较合适的投稿方向是强化学习或智能体顶会。

五句话总结

全失败组让组相对优势归零，长程智能体的 GRPO 会在最需要探索的任务上停学。SPLICE 不向教师要完整答案，而是在失败前缀上拼接有界 option，并用学生自己的续写来估价。主表上它超过最强的 SFT+RL 和在线完整轨迹指导 ReLIFT，且教师回合更少。增益集中在中等和困难任务，毕业率的提高比提议命中率更说明问题。下一步最值得做的，是把“学生接得住的局部修正”迁到视觉观察和工具调用，而不是再堆更长的教师轨迹。

Method Deep Dive：从 Input 到 Output

输入是当前策略快照 πold 在任务 x 上采到的一组轨迹 𝒢(x)={τi,Ri}i=1G，以及冻结的提议模型 πρ。每条轨迹是多轮交互 τ=(x,o1,a1,…,oT,aT,oT+1)，终局奖励 R(τ)∈{0,1}。智能体在回合 t 的状态是完整历史 ht，动作是策略在该历史上采样的工具或代码调用。输出是一次参数更新：若组内既有成功也有失败，走标准 GRPO；若全部成功则跳过；若全部失败，则走 splice 更新。强化学习与 splice 样本放在不同小批量里交替训练，提议模型和分支重建只在训练阶段启用。

拼接点不是任意 token 边界。系统每隔 C=4 个智能体回合记录一个可分支点；所谓可分支，是指环境可以从那里恢复交互。SWE 默认恢复容器快照，Deep Research 则重置后重放已记录的历史并重新发出后续请求。对每个被路由到 Splice 的组，先随机抽一条失败轨迹 τ−，再由提议模型根据任务、完整交互历史和终局验证器反馈，在这些可分支点中选择 bt*。随后在同一拼接点上生成 K=3 个候选 option，每个 option 至多 Hb 个连续回合。Hb 随当前 GRPO 批次的平均轨迹长度自适应调整，比例系数默认 α=0.3。这段设计的含义是：教师只被允许改写局部，而不是从第一步起接管整条轨迹。

估价必须对学生条件化。若某个 option 在提议阶段就完成任务，立刻用任务验证器赋值 Q^k∈{0,1}。若仍未完成，就从 option 结束处让 πold 独立续写 M=3 次直到终止，用平均奖励做价值估计。零回报 option 被丢弃；若一个都不剩，这次 splice 更新直接跳过。保留集合 ℐ 上的回报先做组内标准化，再经 softmax 得到目标分布 q*。损失函数不是整条拼接轨迹的似然，而是按 q* 加权、并在 option 内部做长度归一的平均 token 损失。这一步是刻意的：序列级 KL 投射会让更长的 option 占更大损失份额，长度归一可以保住 option 级权重。监督范围覆盖且仅覆盖提议模型在保留 option 里生成的动作 token，当前策略续写的后缀不进入梯度。这与“教师把后面都做对了，顺便也学后缀”的直觉相反，但消融显示，把成功后缀写进损失会同时降低解出率和毕业率，并把教师回合推高到约四倍。

强化学习表述如下。状态是交互历史 ht，动作是每回合的策略输出，策略是 πθ，轨迹是完整多轮交互，奖励是稀疏、规则化、由验证器给出的二元结果，不能学习奖励模型。优势在 GRPO 路径上是轨迹级组相对优势，在 splice 路径上是保留 option 之间的候选相对优势，二者都不需要价值网络。信用分配是本文的核心：GRPO 把终局奖励广播到一条轨迹的全部动作 token；splice 则把监督限制在被验证为对学生有用的局部 option。没有额外的 KL 或熵项在正文主公式中出现。奖励本身很难在验证器被绕过的意义上“被黑”，但仍然很稀疏，而且与“中间步骤是否真正推进任务”并不自动一致。训练效率方面，正文报告了提议模型回合和相对墙钟顺序：SFT 最高，RL 最快但最终解出率最低，SPLICE 的教师回合和墙钟都低于 ReLIFT 与 SFT；精确 GPU 小时正文未给出。异步流水线使用 staleness =2，作者称与同步训练的解出率相当。智能体结构是：输入任务与观察，经脚手架（SWE 用 OpenHands 默认提示和工具，Deep Research 在 Uni-Agent 上提供 search、open、find）调用环境，验证器给出终局反馈，再决定走 GRPO 还是 splice。智能体状态即交互历史加可恢复环境快照。长程问题是明确的：训练与评估的回合上限为 150，上下文上限为 128k，属于百步级而不是千步级。失败会沿前缀传播，正因为如此，方法选择在中途拼接，而不是在终点才给建议。

Experiment Setup 与研究问题

软件工程训练数据来自 SWE-Gym 与 R2E-Gym 的子集，并排除与 SWE-bench 仓库重叠的任务，评估指标是 SWE-bench Verified 的 resolve rate。深度检索训练数据来自开源数据加质检流程，评估指标是 BrowseComp-Plus 的答案准确率，检索器用 Qwen3-Embedding-8B，裁判是 gpt-oss-20b。两个领域都固定抽样 3,200 条训练任务。策略有两套：Qwen3-8B 先做脚手架与工具格式的冷启动得到 Qwen3-8B-CS，并关闭 thinking；Qwen3.5-9B 直接从发布检查点出发并开启 thinking。提议模型统一为 Qwen3.5-122B-A10B。默认 K=3、M=3、α=0.3、C=4，回合上限 150，上下文 128k。主结果报告三次运行的均值与样本标准差，评估每个训练运行的最终检查点。后续机制分析默认用 Qwen3-8B-CS 和 SWE。下面用两组实验回答两个研究问题。

Results：数字、对照与解释

研究问题一：在相同任务数据下，学生条件的局部 option 是否比直接 GRPO 和完整教师轨迹指导更强？实验设置即 Table 1 的四个格子。观察如下。Qwen3-8B-CS 上，初始策略在 SWE-bench Verified 和 BrowseComp-Plus 上分别为 11.2 和 16.4；直接 RL 只提到 15.9 和 20.2，绝对增益 4.7 和 3.8 个点，与正文概括的 3.7–5.2 个点一致。SFT 单独已经到 21.5 和 24.2，SFT+RL 再升到 24.4 和 26.7，说明先让策略见过成功轨迹再做强化学习，明显强于从零探索。ReLIFT 为 19.7 和 23.5，强于直接 RL，但弱于 SFT+RL。SPLICE 达到 25.7 和 29.3，分别超过最强基线 SFT+RL 1.3 和 2.6 个点，超过 ReLIFT 6.0 和 5.8 个点。Qwen3.5-9B 起点高得多（53.2 和 42.5），直接 RL 在检索上甚至略低于 SFT（46.2 对 48.2），但 SPLICE 仍以 61.2 和 50.7 取得四个格子中的最高值，相对 SFT+RL 的 59.9 和 49.4 仍有 1.3 和 1.3 个点。解释是：完整教师轨迹能提供成功行为，但真正进入学生更新的，应当是学生接得住的局部修正；否则高计算的 SFT+RL 会把预算花在过长的离策略历史上，在线完整轨迹指导也会把大量教师回合用在学生用不上的成功样本上。

研究问题二：更低的提议命中率，为什么反而对应更强的失败任务恢复？Table 2 在 SWE 训练任务上比较提议命中率、毕业率和教师回合。ReLIFT 的命中率为 55.1，SPLICE 只有 30.7，少 24.4 个点；教师回合从 113.4k 降到 93.5k，约少 17.5%。可是毕业率（初始失败任务被训练后策略解出的比例）却从 ReLIFT 的 15.9 和 RL 的 8.1 升到 18.9。也就是说，教师更常做对，并不等于学生毕业更多。Table 3 把同一训练集约 3,200 题按难度切开：简单 342 题、中等 1,087 题、困难 1,771 题。简单题初始已达 99.4，RL 与 SPLICE 都是 99.3，没有新收益。中等题从初始 0.5 到 RL 的 10.9，再被 SPLICE 提到 24.8，比 RL 多 13.9 个点。困难题从 0.2 到 RL 的 6.4，再到 SPLICE 的 15.4，比 RL 多 9.0 个点。解释是：局部拼接最有用的区间，是标准强化学习已经开始碰到成功、但还远远不够的中等难度，以及仍然接近全失败的困难题；简单题不需要教师，最难的题也不是靠更长的教师轨迹就能全部救回来。

PURA: Video Token Pruning via Unified Spatiotemporal Redundancy Assessment

人话版：这篇论文到底干了什么？

视频大模型的预填充成本几乎随视觉 token 数线性上升，于是训练无关的 token 剪枝成了常用加速手段。既有方法常常预先规定先剪时间还是先剪空间，或给时空两边分配固定配额，也有方法在全局范围内做无结构匹配。PURA 的做法是：为每个视觉 token 同时构造同帧空间候选和沿时间链回溯的时间候选，用视觉编码器注意力得到的重要性去加权它与最近邻参照的特征误差，形成统一的删除代价，让空间冗余和时间冗余在同一个分数上竞争。为了避免逐个删除带来的排序开销，它每次预选一批低代价 token，但只同时删除互不依赖的那些，并把被删 token 的重要性累加到被保留的参照上，最后按相似度把相近特征融合回去。主实验在 Qwen3-VL-8B、InternVL3.5-8B 和 LLaVA-Video-7B、五个视频理解基准上比较多种保留率。极端压缩时优势最大：在 5% 保留率下，平均相对分已经超过所有基线在 10% 保留率下的成绩。效率表在一块 RTX 5090 上给出了真实端到端时延：10% 保留时预填充加速约 10.8 倍，端到端只有 2.53 倍，理论浮点与墙钟并不一致。

Background & Research Gap

视频理解要把几十到上百帧编码进语言模型，视觉 token 数很容易压过文本。训练无关剪枝希望在尽量不掉点的前提下减少进入语言模型的 token。一个典型反例是：只在空间上合并相似块，会把相邻帧里反复出现的同一物体各留一份；只在时间上抽关键帧，又可能把同一帧里真正不同的区域剪掉。另一类方法先做时间剪枝再做空间剪枝，或反过来，等于提前规定了冗余的主方向。还有方法允许任意 token 互相当参照，结构上更灵活，但在长序列上会变成昂贵的全局匹配，论文里 Unified 的压缩阶段就到了 509 毫秒，几乎把预填充省下的时间吃回去。

用户真正关心的不只是少算了多少浮点，而是端到端时延、显存和准确率是否一起改善。预填充可能加速十倍，若视觉编码、剪枝本身和自回归解码没有同比下降，墙钟就只能到两到三倍。PURA 试图同时处理两个缺口：用统一代价避免预先规定时空配额，用成批且互不干扰的删除控制剪枝开销。它没有把查询文本写进删除代价，因此仍然是查询无关的训练无关方法。这一点与此前“查询感知还是查询无关”的讨论直接相关，后文会作为迁移和碰撞条件来写。

Core Insight

一个 token 该不该删，不取决于它属于空间还是时间，而取决于：删掉它之后，用哪一个仍被保留的参照来代表它，代价更低。把重要性加权的特征误差放在同一个尺度上，时空候选就会自动竞争。第二个洞察是计算性的：真正不能并行删除的，是互为参照或共享参照更新的那些 token；只要一批里没有这种依赖，就可以一起删，而不必逐步贪心。重要性转移则防止“一群彼此相似、单个都不突出的 token”被集体删光。

Baseline Comparison

主对照是 HoliTom、FlashVID、Unified、UniComp 和 V-CAST，均在相同帧数和保留率下比较。最强准确率基线随保留率变化：64 帧 Qwen3-VL-8B 上，20% 时是 HoliTom（相对分 96.9%），10% 时是 FlashVID（93.5%），5% 时仍是 FlashVID（88.7%），1% 时是 V-CAST（78.6%）。效率表上，端到端最快的竞争基线是 V-CAST（1362 毫秒，2.59 倍），但它的 VideoMME 分最低。Unified 预填充很快，压缩阶段却要 509 毫秒，端到端只剩 1.88 倍。后文同时用最强准确率基线和最快端到端基线来读表，避免只看一项。

Contribution

方法贡献是统一的时空冗余代价，加上保证参照关系不被破坏的成批删除，以及把被删重要性转移并按相似度融合的后处理。实验贡献是在三个模型家族和 20%、10%、5%、1% 四档保留率上给出完整准确率，并在 RTX 5090 上报告压缩、预填充、语言模型总计和端到端时延。经验贡献是指出：5% 保留的 PURA 可以超过 10% 保留的既有方法，同时端到端加速明显小于预填充加速。

Claim vs Evidence

作者声称 PURA 在低 token 预算下持续优于既有方法，并取得更好的性能与推理效率折中。实验实际表明：在 Qwen3-VL-8B、64 帧上，相对最强基线的保留性能优势随压缩变强，分别为 1.5、2.9、5.2、6.3 个点；在 InternVL3.5-8B 与 LLaVA-Video-7B 的 20% 和 10% 上也保持最高平均分。效率表证实 10% 时端到端 1393 毫秒、相对分 97.8%，快于多数基线且明显准于 V-CAST。尚未证明的是：查询感知能否进一步减少被误删的证据 token；峰值显存从未报告；融合阈值 0.8 与分段相似度阈值的敏感性只有部分消融；结论节没有单独的失败案例分析。作者也没有把端到端 2.53 倍和浮点约 3.8 倍、预填充 10.79 倍之间的差距写成理论错误，但这个差距必须被明确指出。

Limitation

结论写得很短，没有独立的局限节。可以补充如下。方法完全训练无关，删除代价来自视觉编码器注意力，不看问题文本，对“只与当前问题相关的小区域”可能不友好。效率表没有报告 GPU 显存和吞吐量。1% 保留时相对分仍有 84.9%，绝对下降不可忽略。更高帧数实验把 256 帧保留 25%、512 帧保留 12.5% 与 64 帧全量比较，token 预算大致可比，但帧采样协议与压缩协议是缠在一起的。代码未核实，因此无法复现压缩阶段的常数开销是否对实现敏感。成批删除会偏离逐步贪心，消融只扫了批大小，没有给出最坏情况下的精度损失上界。

Research Value

对视频加速，这篇工作把“统一时空代价”和“剪枝过程本身不能太慢”放在同一张效率表里，避免只报告理论浮点。对智能体和长视频，它提示：若要把剪枝接到带查询的代理循环里，应先搞清楚查询无关的代价已经能保住多少，再决定是否值得加入查询感知。

Migration / Research Transfer

原问题是视频大模型的训练无关视觉 token 削减。可迁移机制是：在统一代价上让不同来源的参照竞争，并用依赖约束做批量删除和重要性转移。新问题是：在视频智能体或流式视频问答里，删除代价能否乘上与当前问题相关的注意力，而不把压缩阶段重新做成数百毫秒的全局选择。方法改动是把初始重要性 Ii(0) 从纯视觉编码器注意力，改成视觉注意力与问题到 token 注意力的组合，并在流式设置下只更新新到达的时间链。最小实验建议在 Qwen3-VL-8B、VideoMME 与 EgoSchema 上比较查询无关 PURA、查询感知变体，以及既有查询感知剪枝。指标为保留率、端到端时延、压缩阶段时延和准确率，特别要看长视频与问题只依赖局部片段时的掉点。可证伪假设是：查询感知在 5%–10% 保留率下能再挽回至少一部分 VideoMME 长视频分，且压缩时延不超过 V-CAST 与 PURA 之间的差距。计算成本低，因为是训练无关。撞题风险高，近一周已有 Query-Aware vs. Query-Agnostic Training-Free Video Token Pruning，必须把差异放在统一时空代价和成批删除上，而不是再发明一个查询门控。

五句话总结

PURA 用重要性加权的特征误差，让空间参照和时间参照在同一分数上竞争，而不是预先规定剪枝顺序。成批删除和重要性转移解决的是速度和“相似但集体重要”的内容被误伤。准确率优势在低保留率下最明显，5% 的 PURA 已超过 10% 的既有基线。端到端加速只有 2.5–2.7 倍，远小于预填充的 10–18 倍，这是必须记住的墙钟事实。下一步最值得做的，不是再降一个百分点的保留率，而是在不显著增加压缩时延的前提下加入查询条件。

Method Deep Dive：从 Input 到 Output

输入是已经编码好的 N 个视觉 token 及其归一化特征 zi、所属帧号 fi，以及视觉编码器的注意力。目标是留下 K 个精炼后的视觉 token，送给语言模型。算法不更新模型权重。首先把全部 token 放入保留集 𝒜。空间候选是同一帧内的其他保留 token。时间候选的构造分两步：用每帧 token 特征的平均作为帧嵌入，在相邻帧余弦相似度低于阈值的地方切开时间段；在段内，后一帧的每个 token 在前一帧对应空间位置的局部邻域里找最相似者，形成时间链接。从 token i 沿链接回溯，得到时间链 𝒯(i)。初始参照集合因此是

ℛ(i)={j∈𝒜∣fj=fi, j≠i}∪(𝒯(i)∩𝒜).

时间链接只建一次，之后即使中间 token 被删，仍可访问更早的保留候选。每个 token 在 ℛ(i) 里选最相似者作为参照 j，用平方特征距离 ‖zi−zj‖22 衡量表示误差。初始重要性 Ii(0) 来自视觉编码器注意力：有 CLS 时对 CLS 到 token 的注意力跨头平均，否则对其他视觉 token 作为查询时赋给 i 的权重跨位置和头平均。统一删除代价为

C(0)(i,j)=Ii(0)‖zi−zj‖22.

没有候选的 token 代价为无穷，必须保留。这一步的反直觉之处是：算法并不先判断“这是空间冗余还是时间冗余”，而是让两类参照直接竞争，谁更能代表它谁就赢。

若每次只删代价最低的一个再更新状态，要做 N−K 步，长序列上不可接受。Coordinated Pruning 每次先取出当前代价最低的 M 个候选，再按代价升序扫描，构造一个可同时删除的批次 ℬ。一个 token 被加入批次，当且仅当：它选中的参照不在批次里，并且它也不是批次中已有成员的参照。这样，删除其中任何一个都不会立刻改变同一批次里其他人的参照或重要性，这批代价在同时执行时仍然有效。批次大小还受 Bmax 和剩余额度 |A|−K 限制。删除后，把被删 token 的重要性加到各自仍被保留的参照上：

Ij(t+1)=Ij(t)+∑i∈ℬjIi(t).

只要旧参照还在，它仍是最相似的可用候选，因此只在参照被删时才重新选择，并且只重算重要性或参照发生变化的那些代价。循环直到留下 K 个 token。最后，沿删除链接把被删 token i 归到最终参照 j 的融合集，但仅当特征余弦相似度超过 0.8 时才融合，

x~j=xj+∑i∈ℱ(j)xi1+|ℱ(j)|.

若融合集为空，则保留原特征。这 K 个精炼 token 进入语言模型。没有强化学习，也没有查询文本进入代价，因此这是视觉侧、训练无关、查询无关的剪枝。

还可以把几个容易被忽略的实现细节补全。时间链接一旦建成就不再随剪枝改写，这是为了避免“中间帧被删后，后面的 token 失去通往更早证据的路径”。参照选择只在旧参照被删时才重做，因为相似度在剪枝过程中不变，只要参照还在，它仍是最近邻。批大小 Bmax 越大，迭代越少，但与逐步贪心的偏离也可能越大；作者在消融里扫过这一项，正文把默认选择写成在速度和精度之间可接受的折中，而不是理论上的最优批。融合阈值 0.8 是硬切断：相似度不够的被删 token 只把重要性留给参照，并不把特征平均进去，以免把语义不同的内容混在同一个表征里。整个流程发生在视觉 token 进入语言模型之前，因此它加速的是预填充和随后的解码上下文长度，并不改变视觉编码器本身的计算图。也正因为代价来自编码器注意力而不是问题文本，同一段视频在不同问题上会留下同一组 token。这是方法简洁的来源，也是它在查询依赖型任务上可能留下的空隙。

Background & Gap 与 Core Insight

少步蒸馏已经能把视频扩散从几十步降到三四步，稀疏注意力和低比特核则继续打每一步里的注意力与线性层。直接把这三者加在一起会有量化缺口和稀疏初始化不稳定的问题。论文的核心判断是：压缩带来的分布偏移，应当在蒸馏开始前用重建把它钉在稠密教师上；量化感知蒸馏或直接在 NVFP4 上做 DMD，都不是他们实验里最好的选择。VSQA 负责把 90% 稀疏与 NVFP4 注意力做成可用的核，分阶段配方负责让学生在压缩后仍然对准教师。

Pipeline

输入是文本提示与噪声，骨干是 Wan2.1 的 1.3B 与 14B 文生视频模型。训练时先做稀疏加 NVFP4 的分层重建预热和 ODE 初始化，再在三个学生时间步上做分布匹配，并保留重建正则。推理时用三步生成，注意力走 VSQA，线性层走 NVFP4；端到端计时里 14B 基线用优化过的 Wan VAE，JetDiffusion 使用 TAEHV 解码器。输出是视频，质量用 VBench 在多个种子上汇总。
