论文 1｜ViRA：用 Cross-Input Relative Policy Optimization 训练超高分辨率视觉智能体

1. 基本信息

标题：ViRA: Toward Ultra-High-Resolution Visual Agents via Cross-Input Relative Policy Optimization。作者（PDF 署名，未改拼写）：Huawei Lin1,†、Jinting Liu1、Tongyan Wang2、Xuyang Chen1、Ruihua Shi1、Zhichao Xu3、Jiaxin Qin1、Guoshenghui Zhao1、Baijian Yang2、Yingjie Victor Chen2、Tan Yu4、Weijie Zhao1,‡。†为 Project Lead，‡为通讯作者（wjz@cs.rit.edu）。单位：1 Rochester Institute of Technology；2 Purdue University；3 University of Utah；4 NVIDIA。来源：arXiv:2611.21605v1 [cs.CV]，PDF 页眉标注 16 Nov 2026。更精确的 arXiv 上传时钟（时分秒）Not Reported。公告批次：按本次深读规格，属 2026-11-17 左右 arXiv 新投稿列表，不标 BACKFILL。摘要页 · PDF。本地核验文件：/workspace/papers_2026-11-18/2611.21605.pdf（pdfinfo 计 74 页）、2611.21605.txt（pdftotext -layout）、2611.21605_tables.txt、2611.21605_key.txt。方向标签：Agent × RL（视觉 agent + 强化学习 / CrossRPO）。代码与资源（论文页眉）：github.com/huawei-lin/ViRA；数据 ViRA-Train、ViRA-Bench；模型 ViRA-9B、ViRA-27B。本次未独立核验这些仓库是否已公开上线。

2. 一句话定位

ViRA 把「同一问题、多张只在证据区域不同且答案不同的图」做成 contrast set，用 CrossRPO 在组内做相对策略优化、并显式奖励「整组都做对」，从训练信号上切断「靠常识猜对也拿分」的捷径；在约 3,500 条 ViRA-Train 上训练出的 ViRA-9B / ViRA-27B，于 ViRA-Bench 最大分辨率上把 set accuracy 做到 63.3%，对照逐版本 GRPO 的 59.3%（摘要；Table 3 / Table 17）。

3. 人话版

超高分辨率照片里，真正回答问题的那一小块常常只有几十个像素——比如街对面行人手里拿的是什么。模型吃不下整张 45 MP 的图，只能先看缩略图再决定放大哪里。麻烦在于：缩略图里那个小物件糊成一团时，常识已经给出了高频答案。一个人把小设备举到眼前，十有八九是手机。于是智能体不必看清也能把「手机」答对；强化学习如果只看最终对错，这次「蒙对」和真正读到证据是同一笔奖励。猜对往往还更便宜，因为不必调用 zoom。

作者的办法像出「改错对照练习」。同一条问题、同一张街景，只把那只手里的物件改成计算器或遥控器，正确答案随之改变。只靠常识、始终回答「手机」的策略，整组里最多对一版。CrossRPO 先在同一版本的多次尝试之间比较（避免「这个版本上永远猜对」也能拿到正优势），再用其他版本是否也做对来加权：只有当你开始把三版都读对，当前这版的正确轨迹才拿到最大信用。

4. 背景与缺口

引言指出，现代相机动辄数十兆像素，但关键细节可能只有几十像素宽。以 Qwen3.5 把 32×32 像素编成一个视觉 token 计，45 MP 照片大约需要 44,000 个 token，模型因此截断输入并把大图缩小。Claude Haiku 5.5 的上限是 3.8 MP，45 MP 里宽 50 像素的细节会缩到约 15 像素。现有视觉智能体先看低分辨率全图再多次 zoom：一类走固定搜索，一类用监督或对最终答案的 RL（多为 GRPO）学习「往哪看」。

缺口有两层。第一，答对不等于读过证据。图 1a 把 45 MP 街景里的手持设备分别做成手机、计算器和遥控器（约在 110 像素见方内）：无 zoom 时 Haiku 与 GPT-6-Luna 三版都答「smartphone」；DeepEyes、ZoomEye 能 zoom 仍给同一答案；给 Haiku 配上 zoom 并开到最高 thinking，它仍把遥控器认成手机。第二，单图上对最终答案做 RL，猜对和读对同一笔奖励。后来有工作奖励工具调用、裁剪覆盖或调用改善了答案，表扬的是「看过」而不是「读过」。DeepEyes 可放大到整个遥控器，却写确认那是手机；把同一裁剪单独再问，又能答出「TV remote」。这些方法都还是一次只评判一张图。

5. 核心 insight

单张图上，读和猜可以给出同一个答案，任何只定义在该图上的奖励都分不开二者。Contrast set 把这个问题变成可训练的联合事件：同一问题、K 个版本只在证据小区域不同且正确答案两两不同。若策略对证据区域「盲视」，则各版本上的答案分布相同；因为正确答案互异，各版本正确率之和不超过 1；若始终输出同一答案且 K≥2，则 set accuracy 为 0。真正读证据的策略可以让每个版本的正确率都接近 1。

由此得到两条原则。其一，优势必须在同一版本的多次 rollout 内比较，否则「只在原图上永远猜对」会在 pooled GRPO 中得到正优势（文中为 K−1）。其二，要显式优化「整组全对」，但不能只用 set accuracy：其梯度在「有一个版本从未做对」时会消失。CrossRPO 因此最大化「各版本正确率之和 + 加权联合项」，并用与当前版本独立的交叉输入权重来估计联合项，保证「整组都靠常识给出同一答案」时优势全为零（Proposition A.27）。

6. 方法逐步拆解

交互与奖励。智能体收到问题与被降到像素预算 x MP 的图像。每一轮要么作答，要么在当前视图上给框调用 zoom。工具始终从全分辨率原图裁切，再缩放到同一预算（附录 C.1）：裁剪偏大则缩小，偏小则每边最多放大 4 倍；框用 0–1000 坐标，边长至少扩到 32 像素。最多 6 次 zoom。一次 rollout 是完整多轮轨迹，奖励等于最终答案正确性，没有过程奖励。

目标与优势。Contrast set 为同一问题下 K 个只在证据处不同、答案两两不同的版本；智能体一次只看见一版。版本正确率为 pv，set accuracy 为 ∏vpv。对 K≤3，目标是各版本正确率之和加上加权联合项（式 (2)）。K=1 时权重为 0，退化为该图上的 RLOO；K>3 时联合项改为三元组正确率的平均（文本实验做到 K=16）。每个版本采 n 条 rollout。逐版本套 GRPO 不含联合项；把全部版本放进一组（pooled GRPO）则会让「只在一版上猜对」高于组均值。CrossRPO 保留一组一版本，组内用留一均值 c¯v,−i，再乘与当前版本独立的 wv（其他版本经验正确率之积），得到式 (5)。仅当该版本内部有对有错时优势非零；因子 1+λwv 介于 1 与 1+λ 之间，在其他版本全部做对时最大。永远回答「smartphone」的策略正确性恒为 1、0、0，全部优势为 0。

批尺度、保证与数据。按组用标准差缩放会消掉 1+λwv，因此改为对整个 batch 做均方根缩放（式 (7)），只改变步长。理论保证包括：梯度估计无偏（Theorem A.19）；不给常识捷径计信用；K=1 回收 GRPO/RLOO，K≥3 时联合项不能由成对奖励表达；随机搭配则联合项不再分离捷径（Proposition A.27、A.34、A.38）。数据上，原图来自 Wikimedia Commons，只编辑证据小区域并写出带四个选项的问题（先给位置、不点名被改属性）。ViRA-Bench：762 组、466 张 24–108 MP 照片，每组 K=3；入选物件在缩到 1 MP 时长边至多 13 像素，全分辨率短边至少 28 像素，面积中位数为照片的 0.0075%；458 题问可见属性、209 需一步推理、95 涉及多个物件，全部经人工审核。第一跳覆盖率在变体与原图之间各预算相差至多 2.4 个百分点（附录 B.2），该检验不覆盖「读」。ViRA-Bench-Real：78 组、234 张，Nikon Z8 拍摄（8256×5504，45.4 MP），三张之间只换物件，面积中位数 0.0017%。ViRA-Train：6,457 个 contrast set（4,110 组三版本、2,347 组两版本）加 2,804 张单图，共 9,261 项，照片 21–120 MP，与 Bench 无近重复；其中 5,329 题关于文字、1,128 题关于物体。

7. 核心公式：变量、目标与直觉

对 K≤3，目标（式 (2)）把各版本正确率与整组全对加在一起：

J(θ)=∑v=1Kpv+λ∏v=1Kpv,λ≥0

按乘法法则，版本 v 的梯度被「其他版本也做对的概率」放大（式 (3)）：

∇θJ=∑v=1K(1+λ∏u≠vpu)∇θpv

该概率用与当前版本独立的交叉输入权重估计，组内再用 RLOO 的留一均值，得到式 (4)(5)：

wv=∏u≠vp^u
Av,i=(1+λwv)(cv,i−c¯v,−i)

集合上的梯度估计与批内统一尺度为

g^=∑v=1K∑i=1nAv,i∇θlogPθ(ov,i∣sv)
A~m=Amsℬ,sℬ=(1M∑m=1MAm2)1/2

变量表。sv,yv：第 v 个图像版本及其正确答案，且 yu≠yv。
ov,i：在 sv 上第 i 条完整多轮 rollout。
cv,i：最终答案是否等于 yv，取值 0 或 1；奖励 r=c。
pv：版本 v 上答对的概率；p^v 为其 n 条 rollout 的均值。
c¯v,−i：同一版本除去第 i 条后的留一平均正确率。
wv：其他版本经验正确率的乘积。
λ：联合项系数，主实验取 0.5。
Av,i：CrossRPO 优势；A~m 是对 batch 内 M 条优势做均方根缩放后的值。
Pθ(o∣s)：当前策略下整条轨迹的概率。

直觉可以记成一句：组内比较负责「不要奖励永远猜对的版本」，组间权重负责「把最多的信用留给能把整组解开的读证据轨迹」。λ=0 时式 (5) 就是逐版本 RLOO。

8. Toy example（本文自造算例，非论文数字）

以下为自造算例，数字不是论文里的准确率或优势值，只用来把式 (5) 算清楚。

问题：「街尽头那个行人手里拿的是什么？」三个版本：s1 手机、s2 咖啡杯、s3 遥控器，正确答案两两不同。取 n=4 条 rollout，λ=0.5。

状态 A：纯常识捷径。十二条轨迹全部回答「手机」，于是正确性为 4/4、0/4、0/4。各版本内部完全相同，CrossRPO 的 Av,i=0，参数不更新。若改用把 12 条放进同一组的 pooled GRPO，组均值 μ=1/3，标准差 σ=2/3，原图上每条猜对轨迹的优势为 (1−1/3)/(2/3)=2≈1.41，捷径被强化——这正是 Proposition A.27 所禁止的。

状态 B：第二版偶尔读对。版本 1 仍 4/4 对，版本 2 有 1 条读对、3 条仍猜「手机」，版本 3 仍全错。此时 w2=p^1p^3=1·0=0，那条唯一读对的轨迹得到 A2,i=(1+0)(1−0)=1；同版本三条错的轨迹优势为 0−1/3=−1/3。其余两版本优势为 0。「在咖啡杯这一版上读对」已得到正信用，而原图上继续猜对不再得分。

状态 C：前两版已稳定读对，第三版刚出现 1/4 正确。此时 w3=1，第三版那条正确轨迹得到 A3,i=(1+0.5·1)(1−0)=1.5，同版本错的轨迹为 1.5×(0−1/3)=−0.5。1.5 是这个自造组里出现过的最大优势：信用留给解开整组的读证据轨迹。

10. 实验设置

模型与数据。由 Qwen3.5-9B、Qwen3.8-27B 直接 RL 得到 ViRA-9B、ViRA-27B，训练时 thinking 关闭（Table 14）。先去掉基座在 12.8 MP、不 zoom 就能整组做对的 contrast set，以及八次尝试中至少七次全对或全错的单图，因为式 (5) 在一版上全对或全错时优势为零。ViRA-9B 训练 3,642 项（1,664 个 contrast set + 1,978 张单图），ViRA-27B 训练 3,401 项（1,338 + 2,063），分项见 Table 13。一个 contrast set 计一项：每版本 n=12/K 条，整组共 12 条，与 GRPO 单输入组大小相同。单图用于保持普通问答能力，并演示 K=1 可与集合同批训练。

超参（Table 14，附录 C.4）。verl 0.10、vLLM 0.32 做 rollout；每步 16 项、每项 12 条；预算在 0.5–16.8 MP 对数均匀抽样，最多 6 次 zoom；clipped ratio，ϵ=0.2，按 token 取均值；旧对数概率来自 vLLM；每步更新一次；AdamW，β=(0.9,0.999)，weight decay 0.01，学习率 1×10−6 恒定、无 warmup，全局梯度裁剪 1.0；bf16、fp32 梯度规约；无 KL、无熵奖励；温度 1.0、top-p=1.0；λ=0.5。开放答案由 GPT-4o（gpt-4o-2024-11-20）按 Mini-o3 的 judge 提示打 0/1 分。各做一整遍：227 步（9B）与 212 步（27B），取最后 checkpoint。硬件 8 张 H200，12.7 与 29.6 小时（约 100 与 240 GPU-hours）；27B 使用 tensor parallel 2 与 sequence parallel 2。三次视觉运行的标准差在 Table 1/3 中 Not Reported。

评测。十个基准。ViRA-Bench（762 组）与 Real（78 组）在 0.5/1/2/4 MP 及各模型最大分辨率上报告 set accuracy 与每组 token（三版本、多轮提示加生成之和）。最大输入：Qwen3 族 16.8 MP，Qwen2.5-VL 系 12.8 MP，Haiku 3.8 MP，GPT-6-Luna 30.7 MP。另外八个单图基准在 1 MP 与最大分辨率报准确率：V∗（191）、HR-Bench 4K/8K（各 800）、MME-RealWorld-Lite（1,919）、TreeBench（405）、O3-Bench（照片中位数 19 MP）、MMStar 与 HallusionBench（中位数 0.18 与 0.53 MP，只报最大分辨率）。开源 + tool 基线的工具采用 DeepEyes 格式、裁剪不放大、每轮最多 2,048 token，与 ViRA「最多 4× 放大、每轮 4,096 token」并不完全相同。

11. 指标教学

  • Set accuracy（越高越好）。一个 contrast set 只有三个版本全部答对才计成功。它直接对应「不能靠单一常识答案过关」：在 K=3、答案互异时，始终输出同一答案的策略得 0。这是主指标，也是联合项要最大化的对象。
  • Per-image accuracy（越高越好，Table 16 / Table 17 括号内）。把每个版本当独立题目计分。它可以远高于 set accuracy：已发布 7–9B agent 在 Bench 上单图可达 30%–51%，整组最多只解开 21.1%（§5.2，Table 16 与 Table 1）。二者并读才能看出「单张看着还行、一换证据就垮」。
  • Tokens per set（需与准确率一起看）。一组三个版本、多轮提示加生成的总 token。高分辨率或反复 zoom 会把它推高。CrossRPO 相对逐版本 GRPO 的一个实际优点是更少 zoom、更少 token。
  • O / A / B、Zoomed、On obj.、Zooms（Table 19 / Table 23）。O 常接近常识答案，A/B 才检验是否读了被替换的证据。Zoomed 是至少 zoom 一次的比例；On obj. 是最后一跳裁剪至少覆盖物件框一半面积的比例；Zooms 是每图平均 zoom 次数。作者用「On obj. 不降、但 A/B 准确率降得更明显」来论证联合项改善的是阅读而非寻找。
  • 通用基准准确率（越高越好）。检查 contrast set 训练有没有伤害普通视觉问答，以及增益是否只存在于编辑图上。

14. Ablation 与缺失的 ablation

已做消融共享数据、奖励、工具与步数，隔离的是优势定义（附录 G.1）。λ=0.5 从 2 MP 起是 Bench 上最准的变体；λ=1 在 Bench 每个预算都更低，Max 仅 56.6；λ=2 低预算更好，但 Max 与全部通用基准更差，且每图 zoom 2.7 次、每组 34K–346K token。随机搭档证明必须对照同一问题的其他证据版本；「只留一版」证明额外图像本身几乎不够。把交叉输入因子乘到逐版本 GRPO 上，并不能超过原版逐版本 GRPO（Table 17）。ConsistRoll 在两套 contrast set 上全面落后，与「成对奖励表达不了 K=3 联合项」一致。

文本迁移（Table 4 / Table 5）在 ConFiQA 上用同一套优势、无图像无工具，训练 2,856 道「基座不看段落就能答对」的题，测试 1,660 题。整组三版本全对：CrossRPO 81.9±3.1，λ=0 为 81.0±1.3，pooled GRPO 79.6±1.8，pooled RLOO 80.2±1.7，基座 58.6。NQ-Swap 替换段与 FaithEval 上四种方法相差不超过 2.0 个百分点。K=4/8/16 时 CrossRPO 的整组全对均值最高，逐版本准确率为 91.5% / 93.4% / 94.6%。作者称这些实验只说明联合项能迁到文本。

缺失或不充分之处。只训练了 Qwen3.5 / Qwen3.8 一族，没有与覆盖率或框面积奖励做正交实验。图像集合 K 最大为 3。题干含物件位置，没有去掉位置提示的对照。Real 只有 78 组，1/78≈1.3 个百分点，排序对小样本敏感。三次视觉运行未报告标准差。开放答案的 GPT-4o judge 没有人工一致性抽样（Not Reported）。

15. Claim vs Evidence

对齐较好的声明。「最大分辨率 63.3%，对照 GRPO 的 59.3%」可在 Table 3/17 核对，引言还补了 pooled GRPO 52.6% 与 λ=0 的 58.7%，只需记住摘要中的 GRPO 是逐版本而非 pooled。「联合项不会强化整组靠常识给出同一答案」有证明，随机搭档给出实证对应。ViRA-9B 为同尺寸开源模型在十个基准上最准，与 Table 1、Table 2 的组内排序一致。「约 3,500 条」与 3,642 / 3,401 相符，且少于 Table 15 已报告训练量的已发布 agent（DeepEyes 47K、Thyme 至少 500K、ZwZ2 20.4K）。编辑痕迹「不指引第一跳搜索」有 Table 12 支持（覆盖率差在 −2.4 到 +1.2 个百分点；ViRA-9B 五个预算平均差为 0.0）。

需要收窄的声明。「多数基准上超过最高 thinking 的 Haiku 与 GPT-6-Luna」为真，但 Real 0.5 MP、O3-Bench 以及部分 HR-Bench 分辨率上并不超过 Haiku。把 63.3 vs 59.3 写成「全面优于 GRPO」不合适：逐版本 GRPO 在低分辨率和几乎整张 Real 表上领先，CrossRPO 的优势更集中在高分辨率编辑图、token 效率与通用基准。用编辑图训练再评测，仍有「认编辑痕迹」的剩余风险；Real 与第一跳检验作了缓解，但 Real 规模小，且第一跳检验不覆盖阅读。题干自带位置描述，会让搜索任务偏轻。总体不是过宣称，但摘要比表格更「顺」。

16. 贡献

按论文 Contributions 并对照实验，可概括为三条。第一，提出适用于任意集合大小（含单图）的 CrossRPO，证明更新无偏、不会强化整组靠常识作答的集合，并把 GRPO 与近年双输入方法收为其目标的特例。第二，构建超高分辨率 contrast set：ViRA-Train（9,261 项，含 6,457 个 contrast set 与 2,804 张单图）、ViRA-Bench（762 组编辑图）与实地拍摄的 ViRA-Bench-Real（78 组）。第三，用约 3,500 条数据训练 ViRA-9B / ViRA-27B，在同尺寸开源模型中取得领先，并展示联合项对阅读（而非仅仅找到物件）的作用；作者声明将公开数据、代码与模型。

17. 局限

论文自述。编辑图可能留下影响「阅读」的痕迹；Real 只有 78 组，且为同一相机、室内、以海报标牌为主，缺少与 Bench 同规模的室外实地基准。题干描述了物件位置，搜索比无位置提示更容易。图像集合最多三版本，更大 K 只在文本上测过。构造 contrast set 的成本高于单图；相对 λ=0 的增益主要出现在 contrast set 上，单图权重为零，行为与 RLOO 相同。奖励只有准确率，不鼓励更紧的框或继续放大，ViRA-9B 通常只 zoom 一次且框偏大。只训练了一个基座家族。基线沿用各自工具与提示，专有模型走 API。文本实验规模很小。

阅读时还可看到的局限。三次主实验未给标准差；78 组 Real 上 1–2 个百分点的方法排序不稳定；开放题依赖 GPT-4o；ViRA 与部分 + tool 基线的 zoom 实现不完全相同。GPT-6-Luna 在最大分辨率上的崩塌被报告但未给出因果结论，记为 Not Verified。错误分析表明，即便覆盖了物件，变体上仍大量退回原图答案，「看见」之后的读与说仍是瓶颈，而当前奖励给不了这一步更细的信用。

18. 复现要点

要复现主结果，至少需要对齐：基座 Qwen3.5-9B / Qwen3.8-27B；按 Table 13 的来源与「12.8 MP 无工具未整组做对 / 单图八次尝试中对 1–6 次」筛选；λ=0.5，每项 12 条 rollout 且 n=12/K，每步 16 项，一整遍（227 / 212 步），学习率 1×10−6，clip ϵ=0.2，无 KL 与熵奖励，thinking 关闭，batch 级 RMS 缩放而不是按组标准差；zoom 必须从全分辨率原图裁切、每边最多 4×、预算对数均匀 0.5–16.8 MP、最多六次调用；开放答案用同一 GPT-4o 与 Mini-o3 提示。评测要报告 set accuracy 而不是只报单图准确率，并固定 0.5/1/2/4/Max 网格、贪心解码、三次种子。消融若改用逐版本 GRPO 的组内 σ，就不再是 CrossRPO，结果也会回到「低分辨率更强、更费 token」的另一条曲线。数据管线依赖多种闭源编辑与审核模型（Table 10），更可行的路径是使用作者声称将发布的数据集，再重跑训练与 Table 3 的优势替换。

19. 研究价值

这篇工作的价值不在「又一个会 zoom 的 27B 模型」，而在于把视觉智能体 RL 里长期被单图准确率掩盖的捷径，变成一个可证明、可消融、可用 set accuracy 直接测量的对象。对比组训练在 NLP 里并不新鲜，但把它做成任意 K 的相对策略优化、并处理 zoom 轨迹的信用分配，对 Agent × RL 是可迁移的。约 3,500 条、八卡一天量级就能拉开与同尺寸开源系统的差距，说明在正确的负例结构下，视觉 agent 后训练不必堆到十万级轨迹。Real 上逐版本 GRPO 的反超、以及「覆盖后仍答原图答案」的高比例，也说明联合项不是万用增益，阅读与框策略仍需更细的奖励。

20. 可执行迁移

迁移一：在现有 GRPO/RLOO 视觉 agent 训练里加 contrast set 通道。数据侧为同一问题构造 K=2 或 3 个「只改证据、答案不同」的版本；实现侧保持「一组一个版本」的 RLOO 优势，乘上交叉输入因子，并把标准差缩放改成 batch RMS，否则权重会被消掉。建议默认 λ=0.5，并始终并排跑 λ=0 与「随机搭档」两个对照：若后两者贴近而 CrossRPO 拉不开，说明对照集没有共享那条捷径。度量上同时报 set accuracy、O/A/B、On obj. 与每组 token，不要只看单图准确率。

迁移二：先给 zoom 补过程度量，而不是立刻改奖励。ViRA-9B 的局限是一次大框。可在验证集上跟踪「最后一跳中物件长边的像素数」和「是否在裁剪上二次放大」（文中 1 MP 时 94% 只 zoom 一次）。若要改奖励，先把它当作分析指标跑完 λ 网格，再考虑对过框面积加很弱的惩罚，并检查 A/B 准确率与 On obj. 是否一升一降。接口上保持「框画在当前视图、裁切始终回全分辨率原图」；把题干里的位置提示做成可开关字段，单独测搜索难度。

21. 方向专用分析（Agent × RL：CrossRPO 与 GRPO/RLOO、contrast set 奖励与 zoom 信用分配）

从同策略 RL 看，CrossRPO 并没有改成离策略：rollout 仍来自当前 πθ，损失仍是截断比为 0.2 的 clipped ratio，旧对数概率来自生成这些轨迹的 vLLM。它改的是优势的对照范围。GRPO/RLOO 的「相对」发生在同一输入的一组轨迹之间，正确猜测与正确阅读不可辨。Pooled GRPO 把范围扩到整组版本，却让原图上的常识答案相对变体上的错误答案「显得更好」。CrossRPO 把相对比较锁回同一版本（全对或全错则优势为零），再用独立于该版本的 wv 把联合成功注入尺度。

Contrast set 奖励能切断常识捷径，关键不在多给了一点 set bonus，而在于捷径在联合事件上的测度为零：始终同一答案时 ∏vpv=0，式 (5) 给出全零优势。随机搭档进一步说明，没有共享捷径的输入被捆在一起时，联合项只是平均正确率的再缩放。因此必须用同一问题下证据的最小替换来造负例。

Zoom 的信用分配本文只解决了一半。最终奖励不含「框是否盖住证据」。CrossRPO 的约束是间接的：变体上最终答案必须随裁剪内容改变，否则整组奖励为 0。Table 19 显示联合项几乎不增加覆盖率，却提高 A/B 准确率，信用更多落在「读」而不是「找」。另一半尚未解决：没有对框尺度与二次放大的信用，ViRA-9B 学会一次宽松的 zoom；逐版本 GRPO 反而 zoom 更勤（2.52 次）但 On obj. 只有 52.1%。过程奖励与联合项正交（附录 G.3）。

22. Attack / Verification lens

如何攻击结论。可以训练或提示一个专门检测编辑痕迹的头，只在 A/B 上改变行为、在 Real 上失效，以测试「阅读增益」有多少其实是「认编辑」。可以把题干中的位置描述去掉或换成误导性位置，看 set accuracy 与第一跳覆盖率是否同时垮掉。可以只比较 Real 的 0.5–4 MP，并强调逐版本 GRPO 在该区域全面领先，从而把「CrossRPO 优于 GRPO」收窄到「高分辨率编辑图 + 通用基准 + 更少 token」。还可以质疑 78 组 Real 的统计力度，以及 GPT-4o judge、贪心解码与单一模型族。专有模型对比须固定 thinking 级别与工具桥接方式。

如何独立核验。按「三版本全对」重算 Table 1 的 set accuracy，并平行计算 Table 16 的单图准确率。复现 Table 12 的第一跳覆盖率差，看是否仍落在约 −2.4 到 +1.2 个百分点。用同一批 3,642 项重跑 CrossRPO 与 λ=0、逐版本 GRPO、pooled GRPO，核验 63.3 / 58.7 / 59.3 / 52.6 是否同向。文本侧用 ConFiQA 的强先验协议核对 Table 4 的 81.9±3.1。若权重如约开放，再在 V∗ 与 HR-Bench 上核对三次运行均值是否落在 Table 2。图上比例若无法在文本中定位，应标 Not Verified。

23. 记忆总结

ViRA 要解决的不是「会不会调用 zoom」，而是「对了并不等于读过」：单图最终答案 RL 会强化常识捷径。CrossRPO 在 contrast set 上做组内 RLOO，再用其他版本的正确率乘积加权，显式优化整组全对，并证明「整组靠同一常识答案」时优势为零。主结果要记四个数：ViRA-Bench Max 上 CrossRPO 63.3%，逐版本 GRPO 59.3%，pooled GRPO 52.6%，无联合项 58.7%（Table 3/17）。ViRA-9B / ViRA-27B 各用 3,642 与 3,401 项、八张 H200 上 12.7 与 29.6 小时训完；9B 领跑同尺寸开源，27B 在 Bench 全程超过最高 thinking 的 Haiku 与 GPT-6-Luna，但 Real 0.5 MP 与部分通用基准并非如此。联合项提高的是变体上的阅读，不是找到物件的频率；随机搭档会取消增益。逐版本 GRPO 在低分辨率和 Real 上往往更准，但更费 zoom 与 token，不能被摘要里的 59.3% 一笔带过。编辑图加实地小基准是必要的双重保险，78 组 Real 仍偏小；一次大框、题干含位置、只训 Qwen 家族，是复现和迁移时最先该碰的边界。

2. 一句话定位

MiSTiQ 把网格编码存储和微缩放（MX）计算格式接到一起：用束搜索在 bitshift 网格上编码 KV cache，再用 MX-Hash 把重建值直接生成到目标 MX 元素网格上，从而在约 1.25 有效比特/元素的预算下，既少占显存，又不必先反量化到高精浮点再算注意力。

3. 人话版

可以把 KV cache 想成一本越写越厚的草稿纸。上下文一长、并发一批，它既占显存，解码时还要反复搬运；在投机解码、MLA 或共享前缀等场景里，解码甚至可能变成算力瓶颈。量化就是少用比特记每一个数。更狠的矢量量化一次给一组通道挑一个「允许的向量」，可是这本清单（codebook）随向量长度指数膨胀，硬件很快装不下；多数方法即便把码存瘦了，算注意力前仍要先解回高精浮点，低精度矩阵单元用不上。

MiSTiQ 换了两套办法。存储不再靠大词典，而靠在有限状态的网格里选一条路：只记下每一步怎么拐，解码按规则恢复整段向量。这是 QTIP 一类思路，作者把它从权重搬到 KV，并用束搜索代替全量 Viterbi，以控制在线编码开销。计算则用 MX：若干低精度元素共用一个块尺度，可以先在元素网格上累加点积，再乘块尺度。关键不是「先随便量化再硬转成 MX」，而是先按块缩放，让网格哈希直接吐出已落在 MX 元素网格上的值。缓存里存路径比特与块尺度，读出已是可计算的 MX 张量。

4. 背景与缺口

长上下文与大 batch 同时推高 KV 的容量和内存流量。应对大致两条路：改结构（MQA、GQA、滑动窗口或混合注意力），或做训练后压缩。本文走量化，因为它不必重训即可接到已有模型上。

KV 量化很早就利用键值分布不同：KIVI 对键按通道、对值按 token 量化；更低比特时，NSNQuant 用双归一化、通道中心化和 Hadamard，配可复用高斯码本且无需数据相关校准；VecInfer 用平滑和 Hadamard 改善码本利用率，并融合反量化与注意力。这些方法通常把缓存存成整数码，计算仍走高精通路。显式码本在每元素 k 比特、向量长 V 时有 2kV 项，硬件很难装下。QTIP 用 bitshift 网格把有效量化维数和码本大小解耦，但原作面向权重、编码用 Viterbi。MX 格式用共享块尺度扩展低精度动态范围；先前 MX 用于 KV 的工作多在四比特及以上。作者认为，把「低于 2 有效比特的存储」和「直接重建到 MX 兼容格式」合在一起仍是缺口，并称就其所知 MiSTiQ 是首个专门针对 KV、同时满足这两点的量化器——此为论文声明，本文未做独立普查。

5. 核心 insight

第一，缩放和网格量化的顺序会影响重建误差。应先做 MX 块缩放，再对归一化值走网格；若先网格再转 MX，搜索就看不见最终的元素量化。

第二，编码对象不是标准高斯，而是块归一化后的「MX-Gaussian」。若网格状态近似均匀，就可用逆变换抽样：把状态混洗成均匀分位数，经尺度条件的逆 CDF，再用 QE 打到目标网格。这就是 MX-Hash：重建值从一开始就长在 MX 元素格式里。

第三，KV 必须在线编码，全量 Viterbi 要保留 2L 个状态。作者改用束搜索，只留 B 条假设；解码端仍是确定性的状态恢复，不必再搜索。

第四，当块尺度从粗的 UE8M0（2 的幂）换成更细的 UE5M3 或 NVFP4 的 E4M3 时，把尺度钉死再搜索会吃亏。他们在束内把尺度放松成连续变量，用闭式最小二乘逐步重拟合，再量化回尺度格式。

第五，键比值更怕量化。固定总载荷下应给键更多转移比特；V 越大，转移预算改 1 比特，每元素载荷只变 c/V，分配可以更细。

6. 方法逐步拆解

接到已有预处理。主实验把 MiSTiQ 当作 NSNQuant 工作流里码本量化器的即插替换，保留归一化与 Hadamard：归一化在 RoPE 前，量化在 RoPE 后。附录另给出与 VecInfer 预处理的结合。键通道先减去冻结的逐通道均值、再除以冻结标准差（按层、KV 头、键通道校准，标准差下限 10−6），Hadamard 后再量化；重建并逆变换后还原均值和尺度。

先按块求尺度，再进网格。长度 d=T 的向量切成大小 dmx 的块。参考尺度取块内最大绝对值除以元素格式最大值（附录写明 E2M1 为 6），再量化到所选尺度格式。UE8M0 用初始尺度并在搜索中固定；UE5M3 与 NVFP4 做联合尺度搜索。块之间尺度独立，网格状态和累积代价跨块延续。假定 V 整除块长，使每一步发射落在同一 MX 块内。

在 bitshift 网格上束搜索编码。沿用 QTIP 的 (L,k,V) 网格。后继由旧状态左移 kV 位再写入新比特得到。束搜索用 bstart 比特选起始状态（主实现为 8），每步至多保留 B 条，按局部平方误差累加排序。紧凑存储是各步转移标签加上起始状态。解码只做状态恢复、重建映射和拼接，不再搜索。

用 MX-Hash 代替大码本。状态经 32 位线性同余发生器和混合器打散后，取出符号位与 31 位幅度秩，变成开区间概率，经尺度条件逆 CDF，再用就近、偶舍入并饱和的 QE 打到元素网格。混合器按格式、V 和搜索策略离线校准（标准设置为 48 个候选、32 条长 128 的训练向量和 256 条留出向量）。重建直接落在 E2M1 网格；附录 E 给出查找表逼近。

联合搜索路径和块尺度。把块尺度放松为连续变量，每步用「目标与发射的内积、发射的平方范数」做带正则的最小二乘，正则拉向搜索前的参考尺度，避免短前缀把更好路径挤出束。一块结束时去掉正则再拟合。为改尺度而不改已发出的量化元素，这里使用附录 D 的尺度无关 Clipped MX-Hash。

键值混合精度。键和值分开编码，转移预算可以不同，但共用 V 和重建格式。高于约 2 比特的 UE8M0/UE5M3 用 V=4、块长 32、键/值预算 8/6；同档 NVFP4 用块长 16、预算 7/5；低于 2 比特用 V=8、块长 128、预算 9/6。分配对所有层固定。脚注指出，小块长硬件可通过复制尺度容纳更大的逻辑块。

7. 核心公式：变量、目标与直觉

8. Toy example（本文自造算例，非论文数字）

以下为讲解用的自造算例，数字不是论文实验或图表读数。

设只有 4 维的一段向量 y=[1.2,−0.4,0.8,−1.6]，块长等于 4，整段共用同一尺度。为便于观察，自造一个比真实 E2M1 更粗的元素集合 {0,±0.5,±1,±1.5,±2}，并取 CS=2。参考尺度 s⋆=1.6/2=0.8，假定尺度格式恰好能表示 0.8，则归一化向量是 x=[1.50,−0.50,1.00,−2.00]。

再自造一个极小网格：每步发射 V=2 个数，共两步；只展示两个状态。假设已经含元素量化的「玩具 MX-Hash」给出：状态 0 发射 (1.5,−0.5)，状态 1 发射 (1.0,−2.0)。第一步的目标恰是 (1.50,−0.50)，状态 0 的平方误差为 0，状态 1 为 0.52+1.52=2.5。若束宽为 2，两条都留下。第二步目标是 (1.00,−2.00)。路径 0→1 的第二段误差为 0，总误差为 0；路径 0→0 的第二段误差仍是 2.5。编码器于是记下起始状态和两次转移比特，而不是存一张完整码本。解码端用块尺度 0.8 乘回元素，得到 y^=[1.2,−0.4,0.8,−1.6]，本玩具恰好零误差。

真实系统里，哈希受 E2M1 网格和 MX-Gaussian 分位数约束，几乎不会这么巧；束搜索也只是近似，不保证全局最优。这个例子只想说明三件事：先缩放再编码、哈希直接吐出元素网格上的值、存储的是路径而不是词典。

9. Baselines

主表对比的是同一套 MX 计算格式约束下的 KV 矢量量化方法，另列 BF16 作为未量化参照（题注称其为 historical，不参与「最佳量化结果」着色）。

  • BF16（16.00 有效比特）：未量化 KV，提供三项指标的上限参照。
  • NSNQuant（Son 等，2026）：双归一化 + 通道中心化 + Hadamard，共享 256 项有符号高斯码本（30 次 Lloyd 迭代），64-token 窗口。作者把它的重建载荷再转到目标 MX 格式；码本拟合仍在 FP32 中完成，MX 转换不进入其训练目标。
  • VecInfer（Yao 等，2026）：RoPE 后的倒数平滑、全头 query/key Hadamard、值不旋转；向量长 4 时键/值码本为 1024/256 项，向量长 8 时为 4096/256 项。解码时转到 MX 的输出尺度不计入缓存比特。

  • Table 5：保留 VecInfer 预处理，只换量化器，用来分离「换编码」和「换预处理」。

10. 实验设置

模型：Llama-3.1-8B-Instruct、Qwen3-8B。任务：WikiText-2 困惑度（不做自由生成）；LongBench 七项的未加权平均，任务为 Qasper、TriviaQA、GovReport、QMSum、MultiNews、SAMSum、TREC，覆盖问答、摘要和分类，分项见附录 Table 6/7；GSM8K 准确率，设定为偏解码的思维链生成。硬件：NVIDIA H100；除 GSM8K 用 4 卡外，其余每跑 1 卡。主量化设置：高于 2 有效比特时块长 32（NVFP4 为 16），低于 2 比特时块长 128；UE5M3 与 NVFP4 启用放松的联合尺度搜索。网格默认 L=16、T=1024，高比特档 V=4、低比特档 V=8，束宽 B=128。实现用 Triton 核，搜索期算术为 FP32。UE8M0 向上取整；UE5M3 就近、平局朝零；NVFP4 用 E4M3FN 块尺度、就近偶数舍入，并另有一个张量级全局尺度。低比特、块长 128 的 NVFP4 配置复用块长 16 校准得到的映射，正文称之为 NVFP-style。

Not Reported：主实验使用的具体 λ；WikiText-2 的上下文长度与 stride；GSM8K 的 shot 数、最大生成长度和采样温度；端到端时延、吞吐或注意力核加速比；大于 8B 的模型。

11. 指标教学

WikiText-2 困惑度（越低越好）。衡量固定文本上的平均不确定度，不涉及自由生成，适合先看 KV 被量化后下一词分布是否仍准。

LongBench 七项未加权平均（越高越好）。覆盖问答、摘要和分类，用来看长上下文理解是否塌掉。不是 LongBench 全套；单项可能与均值不同向，须回 Table 6/7。

GSM8K 准确率（越高越好，表中为百分数）。思维链解题是很长的解码负荷，量化误差会逐步累积，用来补只看前向困惑度的盲区。

有效比特 beff。它不是元素格式的名义位宽，而是把转移载荷、块尺度和起始状态等元数据摊到每个元素上的存储预算，便于在不同块尺度格式之间比较。

高斯分析中的 RMSE·2beff（越低越好，已按位宽校正）。用于在不同有效比特下比较量化器本身；只出现在 Figure 2，主模型表不用它。

15. Claim vs Evidence

对得上的部分：在约 1.25 有效比特、三种块尺度和两个 8B 模型上，WikiText-2 与 GSM8K 的优势有 Table 1 全程支撑；NVFP4 组内的 LongBench 均值最高同样有表为证；设计选择的逐步改进有 Table 2；低于 1 比特仍优于同设定基线有 Table 4。把它写成「码本量化器的即插替换」也有 NSNQuant 主实验和 VecInfer 的 Table 5 双重印证。

措辞需对齐。摘要说 NVFP4 取得两个模型上最高的 LongBench 平均：若读成「在所评基线、NVFP4 格式内」，证据充分；若读成「所有格式里绝对最高」，则 Qwen3 上 UE5M3 的 33.42 高于 NVFP4 的 33.06，应以后者为准并以后文为准。摘要把困惑度和 GSM8K 的优势限制在约 1.25 比特，这是负责的；外推到 2.25 比特会被 Table 1 的反超打脸。UE8M0、1.25 比特下 Llama 的 LongBench 落后，说明平均分不能代替分项和格式条件。「首个把亚 2 比特存储与直接 MX 重建结合的专用 KV 量化器」是作者所知范围内的声明，本文无法独立核验该优先性声明。

过宣称风险主要不在准确率数字，而在系统含义。论文强调低精度计算的好处，但实验评估的是量化后的语言质量，没有把「在 MX 上直接算注意力」翻译成可核对的速度或能效。质量结论站得住，服务层结论待补测。

17. 局限

论文自述。结论段希望把「网格存储 + MX 计算」延伸到权重，因为离线编码允许更重的搜索；同时也承认哈希建立在高斯假设上，未来应针对经验和权重/KV 的更广分布放松这一假设，例如改用适应经验分布的重建映射。

从实验看得更清楚的限制。只有两个 8B 指令模型，任务是困惑度、七项 LongBench 和 GSM8K，没有多模态、代码或超长上下文基准。约 1.25 比特时 GSM8K 相对 BF16 仍有巨大缺口（Llama 上 37.23 对 76.95，Qwen3 上 50.11 对 88.63），所谓「最高」是相对所评量化基线，不是接近无损。编码用束搜索，写入路径的计算量未测；解码虽轻，但服务系统还要把网格状态、块尺度和分页缓存对齐，这些工程成本未出现在表中。低比特 NVFP4 是 style 迁移而非对该块长的单独校准。代码尚未随预印本发布。

18. 复现要点

应严格按附录 A 对齐，而不是只抄主文默认值。主实现：L=16，bstart=8，T=1024，B=128，搜索用 FP32 Triton 核；重建直接落在 E2M1 网格。高比特 UE8M0/UE5M3：V=4，块长 32，键/值转移 8/6，UE8M0 用初始尺度、UE5M3 用联合尺度。高比特 NVFP4：V=4，块长 16，预算 7/5，E4M3FN 加每张量全局尺度。低比特：V=8，块长 128，预算 9/6；其中 NVFP4 复用块长 16 的校准映射。哈希资源按元素格式、尺度格式、V 和搜索策略分别准备，运行时更大块直接复用已校准映射。基线必须「先按原方法拟合 FP32 码本，再在输出侧转 MX」，不要把 MX 约束喂回他们的码本目标，否则对比不公。校准细节（48 个混合器候选、训练/留出向量条数、NVFP4 高比特用 8/32 条长 1024 的向量等）也应照抄。尚缺的 λ、WikiText 切分和 GSM8K 解码配置需要实现者自行声明，否则难以逐点对齐 Table 1。

19. 研究价值

在推理加速谱系里，这篇工作卡在一个夹缝：一边是已经能把 KV 压到极低比特、但计算仍回高精的码本方法；另一边是硬件开始原生支持的 MX/NVFP4，却多在四比特以上讨论。它给出的不是又一张「再低 0.1 困惑度」的表，而是一条可复用的接口——用网格解决码本装不下的问题，用哈希让搜索目标与计算格式一致。对推理系统而言，1.25 比特仍能在 LongBench 上保住大部分均值（Llama NVFP4 上 41.02 对 BF16 的 48.50）这件事，意味着长上下文的显存墙还可以往下推；对做格式与内核的人，这说明「兼容某种元素格式」必须进入量化目标，而不能只做事后转换。价值主要在这条设计路线，而不在尚未提供的速度数字。

20. 可执行迁移

建议一：若已有 NSNQuant 或同类「归一化 + Hadamard + 矢量量化」流水线，把码本替换做成可开关后端，先在 1.25 有效比特、UE5M3 或 NVFP4 上复现 Table 1 的三项指标。设置对齐附录：V=8，块长 128，键/值转移 9/6，束宽 128，开启联合尺度搜索。度量不要只报均值：同时记 WikiText-2、LongBench 七项分项和 GSM8K，并单列 TriviaQA/TREC。若只能改量化器、不能改预处理，先看 Table 5 的落差，再决定要不要把标准化和 Hadamard 一并迁过来。

建议二：部署前补一组论文没做的「存储—计算」对照。同一有效比特下比较：（a）网格解码后升到 BF16 再做注意力；（b）把 MX-Hash 输出留在 MX/NVFP4 上用对应张量核计算；（c）基线码本方法的「整数码 + 高精反量化」。度量至少包括每 token 的 KV 字节、解码阶段 HBM 流量、注意力核耗时，以及与质量表同一套的困惑度/LongBench。编码侧要单独报出束搜索写入开销，避免只优化了缓存体积、却把预填充或流式写入拖慢。

21. 方向专用分析（Inference Acceleration：KV 存储与低精度注意力计算）

KV 量化有两笔账。一笔是存储：每元素少几比特，长上下文和大 batch 就能多塞请求。另一笔是计算：若读出 K/V 仍要反量化到高精，省下的主要是容量和部分带宽，不是张量核上的低精度吞吐。MiSTiQ 同时碰这两笔账。存储上，网格用状态转移代替 2kV 级码本，使 V=8、亚 2 比特、键值不等比特可实现。计算上，输出已在 E2M1 一类元素网格上，块尺度也是 UE8M0、UE5M3 或 NVFP4 的原生格式，理论上可以走「读缓存—在 MX 上做点积—乘块尺度」。

硬件会反过来约束算法。码本受 SRAM 和查表限制，这是网格的动机；但束搜索要在写入路径上扩后继并做 top-B，复杂度为 O((2bstart+(T/V−1)B)2kV)。很长的预填充或步步写 cache 时，这笔开销可能抵消部分带宽收益，论文却没有测量。共享前缀、分页 KV 和投机回滚也会打乱一段连续 T=1024 的网格，前缀命中时必须能从已有转移比特继续走状态。这些是搬进推理引擎时要设计的接口，不是格式选对就自动成立。

有效比特与质量更像一条服务曲线。1.25 比特是主文最有说服力的工作点；0.93 比特仍能在困惑度上赢，但绝对值已经很高；2.25 比特则与强码本方法拉锯。部署应按目标 SLA 选点：要保长解码质量就不要只看 LongBench 均值；要冲容量，则可接受 1.25 比特的质量损失，并优先用可做联合尺度的 UE5M3/NVFP4。

22. Attack / Verification lens

独立核验应先复现 Table 1 在 1.25 比特、三种格式上的困惑度与 GSM8K，以及 Table 2 的四级阶梯；这是论文最硬的锚。若主结果只能在 NSNQuant 预处理下出现、换成 Table 5 的 VecInfer 预处理就大幅恶化，则贡献应写成「预处理 + 网格量化」，而不是网格单独万能。其次应核对 LongBench 均值是否由七项未加权平均得到：用 Table 6/7 逐项相加再除以 7，应能回到 Table 1（例如 Llama NVFP4 1.25 的 MiSTiQ：30.06+32.66+22.79+39.68+26.02+82.43+53.50=287.14，除以 7 为 41.02）。若只报告均值而隐藏 TREC 或 TriviaQA 的回退，应视为选择性汇报。

攻击其结论的角度包括：换一个未出现的 70B 或 MoE 模型，看高斯哈希是否失配；把上下文拉到数万 token，看动态有效比特和网格分段是否变质；在真实注意力核上比较「MX 直接计算」与「先回 BF16」，检验计算收益是否存在；测量束搜索编码是否成为预填充瓶颈；检查低比特 NVFP-style 映射迁移有没有被当成该块长上的正式 NVFP4。凡是图 4–6 上没有印出的点，都不应被二次引用成精确数字。

23. 记忆总结

MiSTiQ 来自 Arm AI Research 与 Graphcore Research，通讯作者为 Hai Victor Habi 与 Douglas Orr，目标是同时解决「码本太大」和「量化后仍要回高精再算注意力」。

存储单元是 bitshift 网格上的一条路径：束搜索编码，解码只做状态恢复；主设置为 16 比特状态、束宽 128、起始状态 8 比特。

计算单元是 MX 块：先缩放再编码，MX-Hash 按 MX-Gaussian 逆 CDF 直接生成已量化元素；UE5M3/NVFP4 还在搜索中联合拟合块尺度。

键比值敏感。低比特用 V=8、键/值转移 9/6，高比特用 V=4 和 8/6 或 7/5；有效比特约 1.25 或 2.25，包含载荷与元数据。

Table 1 显示，约 1.25 比特时两个 8B 模型的困惑度和 GSM8K 全面优于所评基线；NVFP4 下 LongBench 均值也是该格式内最高（Llama 41.02，Qwen3 33.06）。

不要推到所有格子：UE8M0 的 Llama LongBench 会输给 NSNQuant，2.25 比特上亦有反超；Qwen3 的 LongBench 跨格式最高点在 UE5M3 的 33.42。

消融表明改用网格是最大增益，MX 感知哈希和联合尺度继续加分；同一量化器塞进 VecInfer 预处理能改善，但远达不到主表水平。

低于 1 比特时优势仍在，但绝对困惑度已经很高；论文没有提供时延或 MX 注意力加速数字，系统收益待验证。

迁移时应做可开关的量化后端，对齐附录的 V、块长和键值预算，并补测「MX 上直接算注意力」相对「先反量化」的流量与核时。

设计口令：少存靠网格路径，能算靠哈希直接打到 MX 网格上；先缩放、再搜索，而且搜索必须看见最终的元素格式。

2. 一句话定位

QASK-Edit 把生成式视频编辑看成多源条件生成，在不更新权重的前提下，为每个 query tile 与每个 key source（源视频、参考图、音频、文本、生成中视频等）单独选择稀疏阈值：用注意力质量与子块分数离散度估计近似风险，在该源的风险预算内决定整块近似、热子块精确或全 token 精确，再把所有来源并进同一次 softmax。Table 1 上相对各编辑器发布的稠密流水线，端到端加速为 StreamEdit 1.46×、UniEdit-Flow 1.26×、MiniMax-H3 1.33×（摘要所称最高 1.46×即前者）；Table 4 推广到 Reference-to-Video 时为 Wan2.1-VACE-1.3B 1.36×、Phantom 1.32×。

3. 人话版

一次视频编辑像在装配线上改纪录片：每个 query 都要同时看原片、修改指令、参考图，以及正在生成的新片子。这些材料必须看清楚的程度差很多：改和服的那几帧要对上原片衣纹，远处的海浪往往只需一个摘要。同一个来源里，不同 query、头、层和去噪步要看的块数也在变。现有训练免费稀疏方法却常发一张统一工时卡：全体共享一个保留比例，或所有来源用同一个标准化门槛。

QASK-Edit 把工时卡按来源拆开。先做廉价的块均值摘要，再估计「若只用摘要会错得多离谱」：既看这块大概占多少注意力质量，也看块内子块分数吵不吵。每个来源自带一笔风险预算，系统在候选门槛里挑尽量省算力、但残差风险仍不超过预算的方案。内部一致的块可以整块近似，暗藏局部热点的块则下钻到子块甚至原始 token。精确路径与近似路径按 token 个数加权，倒进同一次 softmax。预训练编辑器的权重完全不动。

4. 背景与缺口

扩散变换器把生成式视频编辑做强了，也把注意力的二次代价一起继承下来：条件输入与正在编辑的视频拼在一起，序列更长。已有路线包括按局部时空图案限制计算、用轻量分数选块、语义聚类成块，以及稀疏精确计算与低成本近似的混合方法。Sol-Attn 允许 query 相关的精确计算量，但仍用共享 β 标定；ISA 则先按固定比例预选上下文。

缺口在于：这些方法通常默认一条稀疏规则可以同时服务不同条件来源和不同 query。第 3.1 节在 StreamEdit 与 MiniMax-H3 上做了预备分析：对每个 query tile、头、层、去噪步，在各来源内部按稠密注意力权重给块排序，记录覆盖该来源 90% 注意力质量所需的最少块数及其百分比，并报告均值和任务内标准差。结论是跨来源的均值需求在块数和百分比上都不一样，而且同一来源内部的任务内标准差常常与均值相当。固定比例或共享门槛会在某些 query–来源对上算得过多，在另一些对上又砍掉不该砍的条件信息。

5. 核心 insight

判断有两层。第一，生成式视频编辑是参考条件生成：每个 query 面对的是不同的 key source。源视频、生成中视频、文本、音频、参考图像的长度与被需要的程度都不一样，编辑前后期的关注点也可能切换。第二，即便限定在同一个来源，需求仍会随 tile、头、层和去噪步波动，因此给每个来源贴一个固定 β 仍然不够。

于是稀疏阈值必须按 query tile × key source 独立标定；用来做决定的不是名义保留率，而是近似之后还剩多少风险。风险代理把块的估计注意力质量与子块分数离散度相乘：又重要又内部很吵的块才值得付精确计算，内部一致的块可以用均值代表，分数不起眼却藏着局部高峰的块则按子块找回热点。附录 B 写明这只是近似难度的代理，不是输出误差的可证明上界。预算 εg 同时充当整块摘要是否可信的筛选阈值和该源残差风险总和的上限，避免再引入一套独立超参。

6. 方法逐步拆解

（1）分块与代表。沿用 SPADE 的 SICS，对 query 与每个视频 key source 独立选择空间、时间或时空混合布局；value 跟随对应 key，其他模态用适合自身结构的划分（具体规则 Not Reported）。Table S1 中完整块、子块、二层子块分别含 128、32、16 个 token，三种父布局为 Spatial 1×8×16、Temporal 8×1×16、Mixed 4×2×16。query 使用 64 token 的 tile。对块与子块计算均值代表；二层子块均值只用于评估可靠性，不新增精确计算决策。

（2）打分与选门槛。由块与子块代表得到 sij、aic 和二层分数 bif，再在全体有效来源上用 token 数加权 softmax 估计 p̂ij，并以子块分数相对块分数的加权方差定义 uij；整块近似风险是二者乘积。候选集 B={−1, 0, 0.5, 1, 1.5, 2, 3, 4}。对每个 query tile 与每个来源，先算 token 数加权的 μi、σi（视频来源可用全部视频块的统计），再令 ti(β)=μi+βσi。候选按降序检查，接受第一个满足 Ri,g(β)≤εg 的门槛。作者强调 R 对 β 不必单调，并称在可行候选里改挑残差最低者对质量没有明显提升、却略增延迟，故采用早停；具体差值 Not Reported。

（3）分层路由与统一注意力。若某子块被指定为受保护，则其所在整块全部按 token 分辨率计算（指定策略 Not Reported）。对其余块：uij≤εg(j) 则整块近似；否则若 sij>ti(β)，所有有效子块都走精确；再否则只把 aic>ti(β) 的热子块精确。若所有候选都不可行，则对 uij>εg 的块以及含受保护子块的块做全 token 计算，其余整块近似。预算为零或被指定必须全算的来源始终使用原始 token。贡献只有三种：整块均值 KV、部分细化、全 token。所有来源的条目进入 Ti，每条带键、值与重数 mb（原始 token 为 1，块代表为 nj，子块代表为 nc）。同一 tile 内的 query 共享路由图案，但每个原始 query 单独算经过 log mb 校正的 logit，并在同一 softmax 下聚合，再接回原去噪流水线。附录 A.3 称在 Triton 中融合了 KV 打包与各层均值、风险估计与掩码下标、以及写入 softmax 的重数校正；比较实验还共用 RoPE 与 query/key RMS 归一化融合。

8. Toy example（本文自造算例，非论文数字）

自造算例，数字不是论文里的。用来说明同一 query 对源视频 token 与文本 token 的需求不同。

设某个 query tile 只面对两个来源：源视频 4 个块、每块 128 个 token；文本 2 个块、每块 16 个 token。已算好块相关性分数：源视频 s=1.20、0.20、0.10、0.00，文本 s=1.10、0.90。按公式 (2) 做跨来源的 token 数加权质量估计。es 约为 3.3201、1.2214、1.1052、1.0000（源）与 3.0042、2.4596（文）；乘上块长后得到 424.97、156.34、141.46、128.00 与 48.07、39.35，总和 Z≈938.19。于是 p̂ 约为源 0.45297、0.16664、0.15078、0.13643，文 0.05123、0.04195。文本两块分数并不低，但因为短，联合注意力质量一共只占约 0.09318。若全体共享一个保留比例，文本很容易被源视频的中低分块稀释或误伤。

再设子块离散度（自造）为：源 u=0.02、0.40、0.08、0.05，文 u=0.01、0.01。源视频第 2 块分数中等但内部很散；文本块短且内部一致。整块风险 r=p̂u 约为源 0.00906、0.06666、0.01206、0.00682（合计 0.09460），文 0.00051、0.00042（合计 0.00093）。若取 ε源=0.10、ε文=0（对应论文「零预算则始终用原始 token」），则文本直接全精确。源视频若把第 2 块也整块近似，单块就贡献 0.06666 的风险，容易逼近预算，于是只对热子块做精确计算，残差改走二层离散度。原则是：同一 query 必须按来源独立分配计算，分数不高但很吵的块往往更需要精确计算。

9. Baselines

主实验比较稠密注意力与五种训练免费稀疏方法，超参跟随各方法官方仓库；Table 4 的集合更窄。

  • Dense：各 backbone 发布的稠密流水线，是速度比的分母（1.00×）。它是「不稀疏」的参照，但不是所有指标上的最优，例如 MiniMax-H3 的 IVE 分数低于若干稀疏方法。
  • SpargeAttention / SpargeAttn（两种拼法并存）：三个编辑器上速度为 1.31×、1.21×、1.31×；在 R2V 上比 QASK-Edit 更快（1.44× 与 1.45×），但 OpenS2V 的 Open 分数明显低于稠密。
  • SVG2：以语义聚类与重排来构造块。编辑器上加速有限（1.12×、1.10×、1.08×），代表成块策略而非按源自适应门槛。
  • SVOO：论文引用为经离线稀疏剖析与在线 QK 共聚类的方法，只出现在编辑比较（1.29×、1.14×、1.19×）。MiniMax-H3 上其 IVE-long 为 0.6241，略高于 QASK-Edit 的 0.6236。
  • Sol-Attn：允许 query 相关的精确计算量，但用共享标准化截止 β 标定，是与「按源独立选 β」最直接的对照。编辑器上为 1.31×、1.11×、1.09×；R2V 上为 1.32× 与 1.29×。
  • ISA（LIVEditor）：先按固定比例预选上下文再按锐度分组，只出现在 Table 1。StreamEdit 与 UniEdit-Flow 上 FiVE-Acc 最高（0.5987、0.2689），但未编辑区域保真明显下降（如 StreamEdit 的 PSNR 21.00 对 Dense 的 23.42），加速也有限（1.03×、1.07×）；MiniMax-H3 上加速 1.29×，仍低于 QASK-Edit 的 1.33×。

相关工作还提到 SPADE、SVG-EAR 等，但它们不是主表比较对象。R2V 比较未包含 ISA 与 SVOO，不能把 Table 4 的排序直接外推到这两名缺席者。

10. 实验设置

模型与数据。三个视频编辑器为 StreamEdit（Self Forcing 变体）、UniEdit-Flow（官方基于 Wan2.1 的实现）与 MiniMax-H3。推广实验用 Wan2.1-VACE-1.3B 与 Phantom，编辑任务用 FiVE-Bench 与 IVE-Bench（Short / Long）。附录给出任务池 1,019 条：FiVE-Bench 419、IVE Short 400、IVE Long 200。源固定 β 的校准使用 24 个样本（采样种子 2026，FiVE 按类别 1–6 分层），并全部排除出评测。Table 1 未另行列出最终评测条数，精确 N 记为 Not Reported。风险预算敏感性在分层抽取的 200 条上做（Table S3：82+79+39）。R2V：每个模型–方法对评 330 条 OpenS2V 与 40 条 VACE-R2V 视频。

分辨率、硬件与种子。同一 backbone 内设置对所有方法一致。StreamEdit：832×480、16 fps，帧数随基准视频调整、最多 81 帧。UniEdit-Flow：最大像素面积 832×480，超出则等比例缩放后再把宽高向下取整为 16 的倍数。MiniMax-H3：256×256、固定 124 帧，官方 BF16 检查点经 torchao 量化到 INT8；参考变换器独占一枚 GPU，Qwen 编码器独占另一枚，视频与音频 VAE 再共享一枚。R2V 统一为 832×480、81 帧。硬件为 NVIDIA RTX 5880 Ada（48 GB）。编辑比较的生成种子为 2026，推广实验与风险预算消融为 42，采样种子 2026 与之分开。

超参与评测改动。64-token query tile、128-token KV 块、四份 32-token 子块；候选集 B 如上。默认风险预算见 Table S2：StreamEdit 为 0.10 / 0.10（参考 / 生成视频，无音频预算），UniEdit-Flow 为 0.02 / 0.02，MiniMax-H3 为 0.30 / 0.10，另加音频 0.10。消融时按 εg=c·εdefaultg 对同一编辑器的全部默认预算乘同一因子 c。OpenS2V-Eval 的 API 部分用 DeepSeek-V4.1-Flash 替换 GPT-4o，FiVE-Bench 的 VLM 用 Qwen3-VL 替换 Qwen2.5-VL，替换对所有方法一致。FiVE 第六类 10 个物体删除任务采用 StreamEdit 的 better-remove 标注：修改 10 条目标提示、8 条源物体标注、10 条目标物体标注，其余 409 条任务不变。速度按视频测量端到端时延，排除加载、编译与量化；绝对秒数、峰值显存和实际精确计算比例的主表 Not Reported。

11. 指标教学

  • Speedup↑：相对 Dense 端到端流水线的加速。因为排除了加载 / 编译 / 量化，且 MiniMax-H3 还叠加 INT8 与降分辨率，跨编辑器比较加速比没有意义。
  • FiVE-Acc↑：FiVE-Bench 上基于 VLM 的编辑成功率，回答「改没改对」。它会受评测 VLM 替换和 10 条标注修订影响，也不测量未编辑区域是否被误伤。Table 1 用 0–1，Table 2 用百分数尺度，不要混读。
  • PSNR↑ / SSIM↑ / LPIPS↓：未编辑区域保真。PSNR、SSIM 越高越好，LPIPS 越低越好。ISA 在前两个编辑器上 FiVE-Acc 更高、但这三项更差，说明改成功和没改坏可以分家。
  • IVE-short↑ / IVE-long↑：IVE-Bench 官方 Total Score，分短、长子集报告。Table 1 用 0–1，Table 2 与敏感性图用分数点。IVE-Long 的预算权衡更清楚，其他分数可以非单调，不能只用一个总分下结论。
  • OpenS2V-Eval 的 Open / Single / Human↑：参考条件生成的聚合质量，0–100 分。Table 4 报 Open；Single 与 Human 的完整数字在 Table S4。因 GPT-4o 被替换，不宜直接对官方排行榜。
  • VACE-R2V Normalized Average↑：按 VACE 的做法对 VBench 指标归一化再平均。Table S5、S6 给出归一化前的原始维。动态程度衡量运动量，不是保真指标。
  • CLIP-I / DINO-I / CLIP-T：Table S7 的辅助参考一致性，与基准聚合分分开列表，不能当成总分替代。
  • 注意力输出误差与精确块比例（Table 3）：相对源固定 β 基线，报误差下降 / 精确块比例下降。负的比例下降表示精确计算反而增加，用来检验在线标定是否按 query 需求加减预算。

14. Ablation 与缺失的 ablation

论文做了三类直接消融。第一，Source-specific routing（Table 2(a)）：共享 β 对独立 β，速度三项全升，质量随编辑器而异。第二，Online vs. calibrated source-fixed β（Table 2(b)）：IVE 在三个编辑器上均有小幅上升，FiVE-Acc 有升有降。第三，按需求分组的机制验证（Table 3）：在线标定降低输出误差，并在低需求组少算、高需求组多算。风险预算乘数扫描（Figure 4）更像敏感性分析，具体曲线点不从折线目测。

缺失或只给定性句的部分包括：分层路由有没有单独关掉某一层、SICS 对固定布局、候选集 B 的疏密、风险代理是否必须同时用质量与离散度、融合与 log mb 各自的时延、早停对最小残差规则的数值表，以及受保护子块是否必要。Figure 3 因双栏条形图不宜逐格引用。也没有把 ISA 的固定比例预选接到 QASK 路由上做组合消融，因此很难把 1.46× 精确分解到各组件上。

15. Claim vs Evidence

对齐得比较好的声明有：「最高 1.46×」在 Table 1 的 StreamEdit 上成立，且三个编辑器上它确为所报方法中最快；「R2V 最高 1.36×」对应 VACE-1.3B，Phantom 为 1.32×，写法是 up to；「按源、按 query 分配有好处」有 Table 2 与 Table 3 支撑。附录 B 把风险称作代理而非证书，没有假装成理论保证。

容易过宣称的是摘要中「在保持编辑质量与未编辑区域保真的同时」这一句。证据其实是「有竞争性、且随模型与基准而变」：UniEdit-Flow 的 PSNR 下降 1.10 dB、LPIPS 相对变差 4.72%；MiniMax-H3 的 FiVE-Acc 下降 6.28%；StreamEdit 的 IVE-short 下降 1.90%。正文第 4.2 节的措辞（competitive、model- and benchmark-dependent trade-offs）比摘要更老实。R2V 上若把「维持质量」读成全面领先也不成立：SpargeAttn 更快，VACE-R2V 甚至略高，只是 OpenS2V 各轨道掉得明显。MiniMax-H3 的设置是 256×256 + INT8 + 多 GPU 放置，把 1.33× 说成完整分辨率下的通用加速，超出了表格覆盖范围。评测器替换与 10 条 FiVE 标注修订在方法间是公平的，但绝对分数不宜与外部论文直接对比。加速排序的证据够硬，质量「保持」需要加条件，不宜当无损加速来引用。

16. 贡献

对照证据可收成三点。其一，把视频编辑重新表述为参考条件生成，并指出跨 key source、以及同一来源内跨 query 的注意力需求并不均匀，从而解释为何固定块数或固定比例选择有局限。其二，给出训练免费框架 QASK-Edit：用注意力质量与子块离散度估计近似风险，在源级预算下为每个 query tile 独立选门槛，并在块–子块层级上做整块近似、局部细化或全 token 计算，最后用带重数校正的共享 softmax 聚合。其三，在三个编辑器上给出可核验的加速与质量权衡，并在两个图像条件生成模型上展示同一套路由可以迁移。贡献的重心是分配策略而不是新的可训练模块。

17. 局限

论文没有单独的 Limitations 节。可以从正文与附录读出的限制如下。风险 R 只是代理，不是输出误差上界，早停策略在风险非单调时也不保证选到「同预算下误差最小」的路由。MiniMax-H3 为迁就算力降到 256×256 并做 INT8，另外两个编辑器也有最大面积或最大帧数限制，全分辨率与全精度下加速比会不会缩小，Not Reported。主结果不报绝对时延、显存和实际稀疏度，因而无法判断 1.46× 里有多少来自融合内核。FiVE 与 OpenS2V 的评测器被替换，10 条删除标注被改写，走官方评测脚本可能对不上表。缺代码与缺若干组件消融，使分层路由与风险代理的独立价值不易核实；受保护子块的指定规则和非视频模态的具体划分也没有操作级说明。方法并未在所有编辑器、所有指标上同时不降。

18. 复现要点

若要对齐 Table 1 / Table 4，同一 backbone 内必须让所有方法共用分辨率、帧数、量化、GPU 放置和生成种子（编辑 2026，推广 42）；速度只计每条视频的端到端生成，去掉加载、编译、量化。QASK-Edit 侧应对齐 64 / 128 / 32 / 16 的层级、Table S1 布局与 SICS 选布局、候选集 B 的降序早停、Table S2 的默认 εg，以及公式 (7) 里带 log mb 的统一 softmax。源固定 β 的对照要在 24 个校准样本上匹配平均精确计算比例，且这些样本不得进入评测。风险预算扫描应使用同一份 200 条分层名单（Table S3 的 82 / 79 / 39 配额，最大余数法，采样种子 2026，生成种子 42），不要重抽。评测阶段必须复现两处替换（DeepSeek-V4.1-Flash、Qwen3-VL）以及 FiVE 第六类 10 条 better-remove 修订，否则分数会与表错位。没有开源实现时，融合内核只能以附录 A.3 为准，算子级等价性 Not Verified。

19. 研究价值

在视频 DiT 编辑里，条件来源天然比纯生成更多、也更不能互相替代：源视频管保真，文本和音频管编辑意图，生成中视频管时间一致。把稀疏注意力的决策单元从「一条序列、一个比例」改成「query×来源、一笔风险预算」，是可以迁移到其他参考条件生成任务上的问题定义，而不只是又一个内核技巧：关键不是要不要近似，而是近似预算如何在来源与 query 之间拆开。经验上，它给出了三编辑器加两生成器的可核验权衡，并提醒编辑加速必须同时报「改对了没有」和「没改坏没有」。用质量加权的离散度做可加的源级预算，是一个干净的工程启发式，尽管还不是误差证书。

20. 可执行迁移

建议一：给每个条件来源单独暴露风险预算，而不是一个全局保留率。在已有编辑或参考条件生成流水线里，把注意力输入按 source 打标签，并给每个 g 提供 εg。起步可借用 Table S2 的数量级（0.02 或 0.10），再在不超过 200 条分层子集上扫乘数 c，分别盯长视频综合分、未编辑区域保真和指令成功率。接受标准应预先写明指令分允许下降的百分点，并要求保真不低于选定基线；比较时延前先固定分辨率、量化和种子。

建议二：把统一 softmax、重数校正和按需求分组的误差审计做成必测项。路由模块应返回精确 token、子块代表、块代表三类条目，并在同一 softmax 里加 log mb，禁止把近似分支单独归一化后再硬加。除加速比外，至少再报相对稠密注意力的输出误差和精确块比例，并按 query 需求分低 / 中 / 高三组（对应 Table 3 的 25% / 50% / 25% 分位）。若低需求组没有少算、高需求组没有多算，说明在线标定没有工作。若短文本或音频频繁打到零预算或全精确，就应把它从共享统计里拆出。

21. 方向专用分析（Video Acceleration：训练免费稀疏注意力、query×key-source 自适应与质量–速度权衡）

训练免费是这条线的硬约束：编辑器往往已经训好甚至量化好，能换的是注意力实现而不是权重。QASK-Edit 把计算分配放在推理期的路由上，因此必须把路由和摘要的开销打进融合内核。相对 SVG2，它不只做语义成块；相对 SpargeAttn，它更不愿意用速度换 Open 分；相对 Sol-Attn，差别就是共享 β 对按源独立 β（Table 2(a)）；相对 ISA，它不做固定比例预选，也更顾及保真与速度。

视频编辑作为条件生成，质量–速度权衡必须是二维的。加速最高的 StreamEdit 并不是质量改善最大的模型；IVE-short 改善最显眼的 MiniMax-H3（+18.86%）却在 FiVE-Acc 上付出 −6.28%，且运行在降分辨率和 INT8 上。R2V 上 1.36× 低于部分稀疏基线的速度，但换来 Open 分不跌。评测上要同时报端到端速度、稠密对齐误差、编辑成功和未编辑保真，不要用一个「最高 1.46× 且保持质量」的句子覆盖三套权衡。同一路由能迁到 VACE 与 Phantom，说明该方法并不绑定某一种编辑器结构，但仍依赖需人工设定的源级预算。

22. Attack / Verification lens

若要攻击其结论，优先打四处。第一，换回官方评测器（Qwen2.5-VL、GPT-4o）并去掉 10 条 better-remove 修订，看 FiVE-Acc 与 OpenS2V 的排序是否还在。第二，把 MiniMax-H3 拉回更高分辨率与 BF16，检查 1.33× 与 IVE 增益是否还在；若加速明显收缩，则当前数字更像低分辨率下的注意力占比结果。第三，补报绝对秒数、注意力耗时占比和实际精确 token 比例，防止 1.46× 被融合实现或非注意力部分的差异解释。第四，把 SpargeAttn 放进同一 Pareto 图：它在 R2V 上更快，若在编辑器上再扫一档更保守的超参，未必不能逼近 QASK 的前沿。

独立核验建议：重实现公式 (2)–(7)，核对降序早停选出的 β 是否等于满足预算的最大候选，并记录 R(β) 是否真的非单调；按 Table 3 的分组重测输出误差，看低 / 高需求组的精确块比例符号是否再现；在文本或音频源上统计被整块近似的比例，验证短条件源没有被长视频源误伤。Figure 3、Figure 4 只作定性印证，不把条形图目测值写进对照表。没有官方代码前，若绝对分数与 Table 1 对不上，应先查评测器、标注修订和分辨率。

23. 记忆总结

  • QASK-Edit 是中山大学计算机学院四人组的训练免费稀疏注意力，面向视频 DiT 编辑，不更新权重。
  • 关键洞察：注意力需求随 key source 与 query 同时变化，固定保留率或共享 β 会错配条件信息。
  • 做法是为每个 query tile × 来源，用质量乘离散度估计近似风险，在 εg 预算内选最大可行 β，再在整块近似、热子块与全 token 之间选择，最后带 log mb 并进同一次 softmax。
  • Table 1：相对 Dense 的端到端加速为 1.46× / 1.26× / 1.33×（StreamEdit / UniEdit-Flow / MiniMax-H3），是所报方法里各模型最快的。
  • 质量并非无损：UniEdit-Flow 的 PSNR 降 1.10 dB，MiniMax-H3 的 FiVE-Acc 降 6.28%，StreamEdit 的 IVE-short 降 1.90%；ISA 有时更会改但更伤保真、也几乎不加速。
  • Table 2 显示按源独立选 β 普遍更快；Table 3 显示在线标定把精确计算转到高需求 query，误差下降 3.2%–17.3%。
  • Table 4：同一框架迁到 VACE-1.3B 与 Phantom，加速 1.36× 与 1.32×，Open 分上升 1.01 与 1.22；SpargeAttn 更快但 Open 分更低。
  • 复现必须对齐 Table S2 默认预算、MiniMax 的 256×256+INT8、评测器替换和 10 条 FiVE 标注修订；主表没有绝对时延，代码 Not Reported。
  • 摘要「保持质量」需要加条件：它在三个编辑器上取得所比较方法中最高的端到端加速，但权衡随模型与指标而变。
  • 评测应在同一 backbone 内比端到端，并分开看编辑成功与未编辑保真，不要只用一个总分或最高加速倍数下结论。
