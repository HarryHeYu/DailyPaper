论文 1｜TIDE：在保持同策略语义的前提下收回 on-policy RL 的空转算力

NEWReinforcement LearningLLM post-training systems

1. 基本信息

标题：TIDE: Reclaiming Lost Performance In On-Policy Reinforcement Learning。作者（PDF 署名）：Mathew Jacob*、Morgan Borjigin-Wang*、Kan Zhu、Po Hao Chen、Yi Pan、Andy Ruan、Nayani Modugula、Ethan Lavi、Luis Ceze、Malte Schwarzkopf、Akshay Narayan、Deepti Raghavan、Stephanie Wang。星号为共同一作。单位：1 University of Washington（Seattle）；2 Brown University（Providence）；3 UC Berkeley；4 New York University。通讯：Mathew Jacob（mjacob2@cs.washington.edu）、Morgan Borjigin-Wang（mbwang@brown.edu）。来源：arXiv:2611.17924v1 [cs.LG]，兼 cross-list cs.DC、cs.PF。标注 Preprint, Under review。提交时间：2026-11-13 09:03:23 UTC（北京时间 2026-11-13 17:03:23，Asia/Shanghai）。公告批次：Monday, 16 November 2026 的 cs.LG new listings（周五提交、周一公告）。不标 BACKFILL。 摘要页 · PDF。本地核验文件：/tmp/deepdive_2026-11-17/pdfs/2611.17924.pdf（15 页），pdftotext -layout 抽文。代码链接：Not Reported。

2. 一句话定位

TIDE 是一套面向大模型同策略（on-policy）强化学习后训练的调度系统：在不改权重更新语义的前提下，把长尾 rollout 造成的空转 GPU 和低 batch 解码浪费收回来，端到端最多比同步共置基线快 1.36 倍，并达到利用率上界的最多 97%（Table 2、Figure 7）。

3. 人话版

今天很多 LLM 的 RL 后训练（尤其是 GRPO 一类批评器无关的方法）采用「共置（colocated）」部署：同一批 GPU 先跑推理引擎做 rollout，全部做完后再切到训练引擎更新权重。这样最容易保证训练样本来自当前策略，也就是同策略。麻烦在于 rollout 长度差极大。DAPO-Math 上中位长度约 6,000 token、最长观察到 28,000（§6.1）；Text2SQL 还要穿插 1–5 轮 SQL 工具调用。只要有一个引擎在啃长尾，其他已经做完的 GPU 就只能空等；就算还在跑，batch 也会越跑越小，解码从「摊销权重加载」变成「几乎在单条上走」，吞吐直线下降。作者在 Table 1 里把这两种浪费分别叫 idle loss 和 inefficiency loss，再加上切引擎的杂项空闲，共置系统有时只剩利用率上界的 56.6%。

有人用异步、离策略来填满 GPU，但这改了训练语义。TIDE 的主张更窄：真正需要的屏障只在优化器步进和权重复制之前，而不必挡在「第一条 rollout 完成」之前。于是它可以一边继续生成长尾，一边把已经完成的 GRPO 组送到训练引擎开始累加梯度；再通过把剩余请求迁到少数引擎上，把解码 batch 重新做大，腾出来的 GPU 继续去训练。迁移阈值 B 不用为每个任务手调，而是用一个类似拥塞控制的线性控制器，按「训练侧有没有饿死」逐步加减。

4. 背景与缺口

同策略 RL 要求本步训练数据来自当前权重，所以业界常用同步屏障。作者指出，这个屏障放得太早，会同时制造两类损失（§3.1）。第一，引擎完成时间严重倾斜（Figure 3，DAPO-Math、DeepSeek-R1-Distill-8B、8×H200、20 步）：多数引擎远早于最后一个结束，空等最多占到总 GPU 时间的 30.0%（Text2SQL、8×H200，Table 1）。第二，即便 GPU 没闲着，batch 收缩也会让解码远离峰值：同一 DAPO×H200 配置下，共置只达到最优解码吞吐的 84%，折合整步浪费 8.4% GPU-hours。切相位卸载/加载的杂项空闲为 0.2–3.6%。合在一起，共置只达到利用率最优的 57–83%（正文对 Table 1 的归纳）。

相关工作里，RollPacker（Gao et al., 2026）用一次性把大约一半 GPU 切去训练，并可用「先完成的样本先进训练」的 tail batching，后者会 skew 样本分布、不再保持原语义；RLHFuse 重叠的是奖励计算而非训练，且面向带批评器的 PPO，不直接适用于 TIDE 瞄准的无批评器 GRPO（§2）。TLT（Hu et al., 2026）用投机解码加速长尾，但作者认为其收益高度依赖接受长度，并且在开关投机、draft 预填充和显存开销上会被对冲。缺口因此是：在保持同策略语义、且不靠任务专用调参的前提下，把空转和低效解码一起收回。

5. 核心 insight

同策略并不要求「所有 rollout 完成才能开始训练」，只要求「权重更新发生在本步全部梯度齐备之后」。把屏障后移到优化器步进之前，就可以在一步之内重叠推理与训练。进一步，迁移阈值存在一个中间最优：B 太小则引擎在低利用率上磨蹭，太大则推理过早被抽干、训练挨饿（Figure 6）。作者观察到「加大 B 通常能提高总利用率，直到训练开始挨饿」，于是把训练空闲当作二进制反馈，用线性控制器在线搜 B，并加一条 KV cache 否决，避免把请求迁进已经饱和的引擎。

6. 方法逐步拆解

系统中每张 GPU 同时挂一个推理引擎和一个训练引擎，同一时刻只有一个活着（Figure 5）。主机上有两个路由器。

步骤 1：分发与亲和。每步开始，Rollout Router 把 prompt 分到各推理引擎，并保证同一个 GRPO 组的样本落在同一引擎，以提高前缀缓存命中，这对多轮轨迹尤其重要（§5）。

步骤 2：负载上报与阈值迁移。引擎持续上报剩余 rollout 数。当某引擎剩余条数不超过阈值 B，Router 抢占其上在飞请求、记下已生成 token，迁到当前负载最低的引擎，然后把腾空的 GPU 交给 Train Router。作者试过按 KV 占用把请求拆到多个目的地，最终发现「迁到最空的一台」同样好且更简单；他们迁的是 token 而不是 KV 内容，因为两者性能相近（§5）。

步骤 3：训练感知的粒度。不是任意腾出一张卡都能立刻训练。Megatron 若 TP=2，少一张卡组不成完整副本；FSDP 则要先凑够能装下分片状态的卡，之后才能一张张加入，但每次加入都要重新分片。因此 Router 只在「迁出后能立刻形成可训练单元」时才动手，并会把短时间内的多次迁移捆成一次重配置（§4.1.3）。

步骤 4：流式派训练活。完成的 GRPO 组不断到达，长样本往往更晚完成。若副本贪心拉大 batch，尾部会堆在少数副本上。Train Router 一开始每次派 64 条；剩余变少后，每次最多派剩余的四分之一，只在步末缩小 batch，以避免全程小 batch 的固定开销（§4.2）。

步骤 5：保持同策略。梯度可以提前累加，但优化器步进、梯度裁剪等整批非线性操作必须等全部梯度到齐。然后才做权重复制，进入下一步。

实现分叉。TIDE-Megatron 基于 Slime，推理用 SGLang、训练用 Megatron；TIDE-FSDP 面向显存紧张场景，基于 SkyRL，推理用 vLLM、训练用 FSDP2，并把优化器完全卸载到 CPU（类似 ZeRO-Offload），还做变长序列 packing。两者都用 Ray actor 封装 GPU 工人，工具调用走 SkyRL-Gym，优化器为 Adam（§5）。

7. 核心公式：变量、目标与直觉

TIDE 的核心不是新的策略梯度，而是一步之内的资源控制律。迁移在「该引擎剩余 rollout 数 N(e) 落到阈值以下」时触发，并先做 KV 容量检查（Algorithm 1）：

N(e)≤B⇒dest=LeastLoaded
if KV(e)+KV(dest)>1: B←B−ΔB; else migrate and repurpose

整步结束后，用训练侧是否出现空闲来更新阈值：

B←B−ΔBif starvation detected;B←B+ΔBotherwise

初始值取保守的 B0=ΔB，因为过早迁移（B 过大）会让训练挨饿、完全不前进，代价高于过晚迁移（推理至少还在低 batch 下推进）。步末的 KV 否决会把 B 往「不会撑爆最紧 KV」的方向压，作为本步内的安全阀，因为饥饿信号要等到训练真正开始才能读到，来不及纠正已经过早的迁移。

变量表。N(e)：引擎 e 上尚未完成的 rollout 条数。B：迁移阈值（条）。ΔB：每步固定步长（可配置）。KV(·)：该引擎 KV cache 占用比例。starvation：任一训练 GPU 出现可测空闲。利用率最优：假设训练已是计算瓶颈、取其实测 GPU 时间，再加上「把本步全部 token 用尽量大的 batch 解码」的最优推理 GPU 时间，以及权重同步时间（§3.1）。目标是在不提前做优化器步进的约束下，最大化相对这一上界的吞吐份额。

直觉。这很像延迟型拥塞控制：把「训练空闲」当成丢包或排队信号，用加减窗口去追推理与训练的速率匹配点。它不试图解析每个任务的长度分布，而是让分布自己通过饥饿表现出来。

8. Toy example（本文自造算例，非论文数字）

假设 4 张 GPU 同步做 32 条 rollout，一开始每卡 8 条。其中 3 张卡 100 秒内完成，第 4 张卡因为一条超长样本要再跑 200 秒。共置方案里，前 3 张卡空等 200 秒，训练完全不能起步。若 B=2，当某卡剩 2 条时就把它们迁走并立刻改去训练：前 3 张卡的空等变成「先训练已完成的组」，第 4 张卡继续消化长尾；迁入的目的地因为 batch 变大，解码吞吐也会回升。若一上来就把 B 设成 8，四张卡几乎同时被抽空，训练侧可能还没拿到足够的完整 GRPO 组就开始挨饿——这正是 Figure 6 里「B 过大」的那一侧。控制器会在下一步把 B 调小。此段数字是为讲清楚机制而编，不来自论文。

9. Baselines

  • Synchronous colocated：完全同步的共置，先全部 rollout 再训练。这是公平的主对照，因为 TIDE 明确对标「保持同策略语义」的这一族。
  • RollPacker 的 GPU 重用算法（移植到 TIDE 上以公平比较，§6.2）：一次性把恰好一半 GPU 切去训练。粒度粗，容易让训练或 rollout 一侧欠载。需注意：原文 RollPacker 还有会改变样本分布的 tail batching；作者在评价里强调的是其一次性切换策略，并指出 tail batching 本身不保持原 RL 语义。
  • TLT：用投机解码加速长尾的同步系统。作者为了给它「最好可能的速度」，离线训练了 EAGLE-2 draft、去掉在线训 draft 的开销，并且把加速比报成「相对关闭投机的 TLT 自己」，因为 TLT 基于 verl，框架开销与 Slime/SkyRL 不可比（Figure 7 注）。即便如此，TLT 在全部评测里仍慢于其共置对照。

作者没有把异步离策略系统当作主对比，这是合理的，因为语义已经不同；但这也意味着「若可以接受离策略，利用率还能再高多少」不在本文范围内。

10. 实验设置

两个应用（§6.1）。Text2SQL：跟 SkyRL-SQL 配方，微调 Qwen2.5-Coder-7B-Instruct，35 步；一条 rollout 是 1–5 段、每段最多 3,000 token 的 LLM 生成，中间夹对 SQLite 的 SQL，呈 ReAct 风格。DAPO-Math：微调 DeepSeek-R1-Distill-Llama-8B，20 步；单段生成，上限 32,000 token，实测最长 28,000、中位 6,000。硬件三套单节点：8×H200（每卡 141 GB HBM3e，NVLink，2×Xeon Platinum 8480C、2 TB DDR5）；4×H100 SXM（80 GB HBM3，DGX，四代 NVLink/NVSwitch，900 GB/s 每卡）；4×L40S（48 GB GDDR6，PCIe Gen4、无 NVLink，2×EPYC 9954、1.5 TB 内存）。H200 上用 Megatron，TP=2 加 DP；L40S 与 H100 上的相应任务用 TIDE-FSDP。优化器为 Adam。全部为单节点，多节点结果 Not Reported。

11. 指标教学

  • 端到端加速比（Figure 7）：共置基线的步时间除以该系统步时间。大于 1 表示更快。
  • 利用率最优份额（Table 2）：最优步时间 / 系统步时间。作者把训练视为已达计算峰值，最优推理时间来自「单 GPU 尽量保持大 batch 跑完本步全部 token」的测量，再加权重同步。
  • Idle / Inefficiency / Misc. idle（Table 1）：分别是等长尾的空转、低 batch 解码相对最优解码的浪费、以及相位切换时卸载加载的时间，四项（含 of optimal）加总为 100%。
  • 每步秒数（Table 3）：消融用的墙钟步时间。脚注说明消融另采了一批长度不同的 rollout，故加速比与端到端主实验不完全相同。
  • Draft 平均接受长度（对 TLT）：最多 9；用于解释投机何时划算。作者还给出 4×L40S 上盈亏平衡长度 2.48、4×H100 上 2.25。

14. Ablation 与缺失的 ablation

Table 3 是主消融，机制按 repurposing → 负载均衡 → 迁移 → KV 否决递进，覆盖两种后端。§6.4 与 Figure 9 用 ServingStudio 回放轨迹，比较固定 B（取初始每 GPU batch 的某个分数）与 TIDE 自适应策略，对照是「每一步都选最好 B」的 oracle：至少一个固定策略能接近 oracle，但最优固定值随任务变；TIDE 不调参也能贴近最佳固定策略。文中没有给出 Figure 9 的精确纵轴读数，那些点值标为 Not Verified。缺失或不完整之处：没有多节点 / 跨机 Rack 实验；没有把准确率、奖励或 AIME 一类任务指标随系统变体列出（本文只报系统吞吐）；ΔB 的具体默认数值 Not Reported；与投机解码叠加的端到端数字只在展望里定性讨论。

15. Claim vs Evidence

「最多 1.36×、最多 97% 最优」有 Table 2 与 Figure 7 支撑：97.4% 出现在 DAPO × 4×H100，1.36× 出现在 Text2SQL × 8×H200，表述与证据对齐。「超过所有被评估的同策略基线」在四个配置上成立，但 TLT 的对照经过改框架与离线训 draft 的调整，比较是作者自己定义的「尽可能有利」版本，不是原论文默认配方的直接复现。「自适应策略无需手工配置也能泛化」有三个硬件、两个任务、两种后端，以及 Figure 9 的仿真支持，但全部是单节点，泛化到 NVL72 或晶圆级系统只是展望。「保持同策略语义」由「优化器步进前设屏障」的设计保证，论文没有另做「关闭屏障后策略漂移」的对照实验，这一点是论证而非测量。

16. 贡献

作者归纳为：系统量化共置同策略 RL 的两类浪费并指出可重叠的机会（§3）；设计按训练饥饿调节的迁移策略，并做成可接 Megatron 与 FSDP 的系统 TIDE（§4–5）；在多种任务与硬件上证明相对共置的加速，并收回大部分利用率上界（§6）。对读者而言，更实在的贡献是把「屏障应该放在权重更新前」说清楚，以及用一条极便宜的反馈（训练是否空闲）避免为每个任务调 B。

17. 局限

评测限于单节点（§7 自己承认），多节点长尾会更重，但通信与重配置开销如何放大并未测量。TIDE-FSDP 在 Text2SQL × L40S 上，步长短、重配置贵、straggler 少时会出现中性甚至负加速，只在总体上仍为正。系统不报告对最终准确率或奖励的影响——若实现有 bug，同策略语义只能停留在设计层面。ΔB、初始每 GPU batch、GRPO 组大小等关键超参数在正文中未给出数值。没有开源链接。与投机解码、解聚式训练池的结合只是设想。利用率上界假设「训练已经打满」，若训练本身也有气泡，上界会被高估。

18. 复现要点

代码：Not Reported。要复现，需要：Slime + SGLang + Megatron，以及 SkyRL + vLLM + FSDP2 两套栈；SkyRL-Gym、Ray、Adam；Text2SQL 与 DAPO-Math 的原配方与步数；8×H200 / 4×H100 / 4×L40S 或等价互连与显存；实现 group affinity、token 级迁移、KV 否决、FSDP 重分片与「64 条再降至剩余 1/4」的派活规则。消融必须固定同一批 rollout，否则会像 Table 3 脚注那样与主实验对不上。ServingStudio 仿真用于扫 B，不是端到端训练的替代。

19. 研究价值

在算法侧 GRPO / RLVR 论文已经很多的时候，这篇把「同策略」从口号落成一条可执行的系统约束，并给出可核验的浪费分解。它说明：很多「RL 很慢」首先是调度问题，不一定要改目标函数。对做后训练平台的人，迁移阈值的反馈设计比再堆一个启发式切换点更有迁移价值。

20. 可执行迁移

  1. 若你已在共置同步 GRPO 上跑起来，先不要上异步。把「训练开始」从「全部 rollout 完成」改到「有完整组就累加梯度，优化器仍等到齐」，并统计每步 idle 与 batch 收缩曲线；这是 Table 1 那套分解，一天内就能知道有没有 10–30% 的空转可挖。
  2. 迁请求时加上 KV 容量否决，尤其是在 80 GB 或更小显存、多轮工具调用的任务上。Table 3 显示，没有否决时迁移可能比不迁更慢。阈值用「本步训练是否挨饿」做 ±ΔB，从很小的 B0 长上去，避免一上来切掉一半推理卡。

21. 方向专用分析（RL：同策略语义、长尾 rollout 与后训练吞吐）

这篇是 RL 系统论文，不是新的优势估计。它针对的恰是当前 LLM-RL 的主流设定：批评器无关的 GRPO、变长推理链、工具调用，以及推理引擎（vLLM/SGLang）与训练引擎（Megatron/FSDP）必须共置切换。算法论文常默认「rollout 成本是固定的 G 条样本」，这里则说明 G 条样本的墙钟时间被长度分布支配。Text2SQL 的多轮结构把空转推到 30%，提醒做 agentic RL 的人：环境时延和多次预填充会放大 straggler，系统收益可能大于再改一层奖励。作者也警告，投机解码在小 batch、计算已饱和时可能减速，TIDE 的迁移是先把 batch 做大，二者应是互补而不是互替（§7）。对策略优化本身，TIDE 不改变优势计算，只要求组内样本尽量留在同一引擎以利前缀缓存——这是实现细节，却可能影响多轮 RL 的实际吞吐。

22. Attack / Verification lens

可核验性强的是步时间、加速比和 Table 1 的百分比，来源是作者自己的测试床与轨迹，外部复现需要同样硬件拓扑。风险在于：若梯度累加或组切分有误，表面上的同策略会被破坏，而论文没有用奖励曲线或 KL 到旧策略的诊断来交叉验证。RollPacker 基线是「移植算法」而非原仓库原配，TLT 又改了框架与 draft 训练方式，基线强弱需要读者自己打折。利用率最优依赖「训练已打满」和「最优解码」的测量方法，换一种计时（是否含切换、是否含奖励计算）数字会动。没有代码则无法检查抢占后 token 拼接、优势是否在组齐后才算等实现细节。建议复核时至少对齐：同一批 prompt、同一随机种子下的长度直方图、以及优化器步进是否确实发生在最后一条 rollout 之后。

23. 记忆总结

  • 共置同步 RL 的浪费来自等长尾（idle）和 batch 萎缩（inefficiency），不是单纯「GPU 不够」。
  • 同策略只需挡住优化器步进，不必挡住训练开始。
  • TIDE 用「做完就改去训练」加「把剩余请求合成更大 batch」两招回收算力。
  • 迁移阈值 B 用训练饥饿做加减，不必为每个任务手调。
  • KV 否决在显存紧张时是必要的，H200 上几乎无感，H100 上能把 1.09× 拉回 1.14×。
  • 端到端最大 1.36×（Text2SQL、8×H200），最优份额最高 97.4%（DAPO、4×H100）。
  • 多轮任务空转更大，加速也更大；这是对 agentic RL 的直接含义。
  • 评测全是单节点、只报系统指标不报准确率，代码未给出。
  • 一次性切一半 GPU（RollPacker）和尾部投机（TLT）在本文设定下都打不过细粒度自适应重用。
  • 若你在跑同步 GRPO，先画每步空转曲线，再决定要不要上异步。

2. 一句话定位

MMFlash 把块扩散草稿（DFlash 一类）接到视觉语言模型上：用「图像到底改了多少下一 token 分布」来给难学的视觉依赖 token 加损失权重，长视频再用稀疏注意力压草稿上下文，在保持无损投机解码的前提下，Qwen3.5 图像基准平均加速可达 3.00–3.05×（贪婪），单点最高 3.58×（Table 1）。

3. 人话版

投机解码的故事很简单：小模型先猜一段 token，大模型一次并行核对，猜对了就白嫖多个 token，猜错了从第一个分歧切开。输出分布与原模型一致，所以叫无损加速。EAGLE 这类自回归草稿每个位置仍要跑一次前向，草稿越长越贵。DFlash 改用块扩散：一个前向就填满整块（本文默认 16 个位置：1 个锚点加 15 个掩码），于是可以把原来花在逐步草稿上的算力拿去把草稿模型做深一点。

把这套搬到 VLM 上会撞墙。有的 token 只是在续写「所以答案是」，有的 token 必须读图上的百分比或坐标。作者用目标模型自己定义「视觉依赖」：同一段文本前缀，把图像拿掉再跑一次，两个下一 token 分布的 KL 越大，这个位置就越靠图。他们发现，依赖最低的四分位接受率约 46%，最高的只有 22%；块里第一次拒掉的位置，44% 落在最高四分位，最低四分位只占 7%（摘要与 Figure 3）。更麻烦的是，按官方配方在约 90 万多模态样本上重训，这个缺口几乎填不上。MMFlash 的办法不是让草稿模型再看一遍像素——目标模型的隐状态里已经融进视觉——而是在训练损失里给「图既改变了预测、目标又比较有把握、草稿却还没学会」的位置加分。长视频里草稿注意力原本就挤在近处，远处帧又高度冗余，于是用「4 个 sink + 步长 32 的视觉 token + 全部文本 + 局部窗 256」把 4 万多上下文收到大约 1.6K（Figure 2b）。

4. 背景与缺口

VLM 的自回归解码本来就慢，推理模型把输出拉得更长，瓶颈更明显。现有 VLM 投机大致三种：草稿看全部视觉、只看蒸馏过的视觉、完全不看视觉 token。MMFlash 走第三条，因为目标在 prefill 时已经把视觉写进隐状态，草稿再编码一遍只会让费用随视觉 token 数膨胀（§2 与附录 A）。DFlash 在纯文本上已验证，其块内损失权重只按位置衰减：越靠后的位置被前面拒掉的风险越高，所以权重 wk=exp(−(k−1)/γ)。这个权重看不见「这个位置到底靠不靠图」。动态位置权重（D-PACE 等）也仍是位置或置信度的函数，不会显式对准视觉依赖。缺口就是：多模态草稿的接受率损失集中在视觉依赖 token 上，而仅换多模态数据并不足以把能力搬过去。

5. 核心 insight

草稿的唯一任务是模仿目标模型的选择，一个 token 被接受当且仅当它与目标预测一致。因此「图像贡献了多少必须被模仿的预测」应当用目标模型自己的分布来量，而不是用注意力图或草稿模型。这个分数可以离线算一次，训练不再付出额外前向。额外努力只值得花在「图既改变了分布、目标又比较自信」的位置：若带图分布仍然很平，目标只是在近并列的候选里随便挑一个，再加权也学不像。同时，验证只接受块的前缀，后面的位置要以「前面都活下来」为条件；草稿已经学会的位置则应把加权退回去，免得牺牲纯文本 token。这三件事乘在一起，就是 MMFlash 的权重。

6. 方法逐步拆解

步骤 1：视觉依赖分数。对训练回复中的每个位置 t，目标模型对同一前缀分别在「有图 I」和「去图」下各跑一次，得到 dt（式 1）。离线存入训练集，训练时不再算。

步骤 2：分位数 × 置信。在整个训练集 D 上把 dt 变成分位数 g~t∈[0,1]，再乘以带图分布熵的衰减 exp(−Ht)，得到 gt（式 2）。高分出现在「图既改预测、目标又定得住」的地方。

步骤 3：三因子块损失。仍对目标选中的 token 做交叉熵，但把 DFlash 的位置权重换成式 3：验证感知的前缀存活权重 bk（式 4，平滑 λ=0.5）、视觉加分 α⋅gk（默认 α=1），以及停梯度后的「当前还不会」项 (1−sg(qk))。后者大时加分大，学会后回到基线权重。

步骤 4：推理时的块扩散草稿。每步以验证留下的 bonus token 为锚，一次前向填 16 个位置，目标一次核对，保持标准投机解码的无损性。草稿只读目标隐状态，不重编码图像或视频。

步骤 5：视频稀疏注意力。七个图像基准平均输入 477 token，三个视频基准平均 41,218。分析显示最近 256 个位置只占上下文 0.8%，却吃掉 50.1% 的草稿注意力；远处帧占 96% 以上，却只吃 46% 且每 token 很淡（Figure 4）。模式固定为：前 4 个 sink、视觉 token 步长 32、全部文本、局部窗 256，训练与推理一致。可先不加训练地套到已有草稿上，再在 LLaVA-Video-178K 的 2K 样本上微调 3 个 epoch（Table 2）。

7. 核心公式：变量、目标与直觉

视觉依赖（式 1）与加权重（式 2）：

d=KL(p(·∣prefix,I)‖p(·∣prefix))
gt=g~t·exp(−Ht)

DFlash 的位置衰减（对照）与 MMFlash 损失（式 3–4）：

LDFlash=∑k=1B−1wk(−logqk),wk=exp(−(k−1)/γ)
wk=bk(1+α⋅gk(1−sg(qk))),LMMFlash=∑k=1B−1wk(−logqk)
bk=∏i=1kq¯i,q¯i=(1−λ)sg(qi)+λ

变量表。p：目标模型下一 token 分布。I：图像（或视频视觉输入）。dt / g~t / gt：原始 KL、其训练集分位数、再经熵缩放的分数。Ht：带图分布的熵。qk：草稿在块内第 k 个掩码位置上对目标所选 token 的概率。sg：停梯度。bk：由草稿自信度连乘得到的前缀存活代理，λ 防止某一位置把后面全部清零。B=16：块长。α=1：视觉加分强度。γ：DFlash 原衰减超参，本文沿用其官方设定，具体数值正文未再列出（Not Reported in the MMFlash 正文）。目标：在仍拟合目标自身选择的前提下，把梯度重新分配到「验证可能到达、视觉上决定预测、草稿还不会」的位置。

直觉。d 回答「图重不重要」，exp(−Ht) 回答「目标有没有一个稳定答案」，bk 回答「核对时能不能走到这儿」，1−qk 回答「现在还要不要加把劲」。四问同时为真，才值得把权重抬上去。

8. Toy example（本文自造算例，非论文数字）

假设块长为 4，位置 1 是「The」，几乎不靠图，g1=0，草稿已经很准 q1=0.9；位置 2 要读出图上的「31%」，g2=0.8，草稿还在胡猜 q2=0.2。取 λ=0.5，q¯1=0.5×0.9+0.5=0.95，b1=0.95，b2=0.95×(0.5×0.2+0.5)≈0.57。则 w1=0.95×(1+0)=0.95，w2=0.57×(1+0.8×0.8)≈0.94，几乎把本会被位置衰减压下去的视觉位置拉回到与前缀相当的学习强度。若位置 2 后来学会了 q2=0.9，加分项收缩，权重重新让路给还没学会的别处。数字是为解释公式而编，不是论文测量。

9. Baselines

  • MTP：Qwen3.5 自带的多 token 预测头，报告 3 / 7 / 15 个草稿步。这是厂商内置基线，公平且很强；15 步时加速比常掉到 1 附近甚至小于 1（Table 1），说明「更长草稿」不等于更快。
  • EAGLE-3：树验证的特征级 SOTA，与 MMFlash 共用同一套由目标模型重写的训练数据。视频实验把树大小收到 4，因为长上下文更贵。
  • DFlash-z：官方发布的文本预训练草稿（6 层、抽 8 层隐状态）。训练配方未公开（Table 附近脚注）。
  • DFlash：作者按官方设定在同一多模态数据上重训（5 层、抽 5 层）。这是最干净的方法对照：数据与超参对齐，差别主要在视觉感知重加权（以及视频上的稀疏注意力与微调）。

不公平之处需要记一笔：主表在并发 1、单卡 H200、SGLang、思考模式关闭下测；评价只抽每基准 200 条，不是全量；DFlash-z 的数据与层数和「同数据 DFlash」并不齐。

10. 实验设置

训练数据取自 LLaVA-OV-1.5-Instruct-Data 约 100 万条，用目标模型按官方生成设置重写回复（温度 0.0，top-p 0.95，top-k 20，最大 4,096），丢掉总长超过 4,096 的样本后约 90 万条；部分 prompt 被改写以引出更长回复（Appendix D.1）。目标模型主实验为 Qwen3.5-4B 与 9B；泛化实验为 Gemma4-E4B-it 与 Qwen3.8-27B。块长 16，每样本 512 个锚点，batch 2，6 个 epoch，学习率 6.0×10−4、余弦退火到 0，前 4% 线性 warmup，8×H100 训练。推理跟各目标官方设置，思考模式关，最多 4,096 生成 token，top-p 0.95、top-k 20，温度 0 与 1，并发 1（主表），单卡 NVIDIA H200 + SGLang。基准：ChartQA、CharXiv、MMStar、MMBench、DynaMath、MathVista、MathVerse，以及 LongVideoBench、MVBench、Video-MME（平均上下文约 41.6K / 42.3K / 39.8K）。各 200 条随机样本，LMMs-Eval，零样本。视频微调：LLaVA-Video-178K 的 2K 样本、3 个 epoch。

11. 指标教学

  • 平均接受长度 τ：每次成功核对平均接受多少 token（含被验证过的前缀）。越大，目标前向被摊得越薄。
  • 解码加速比 Speedup：相对「无投机的自回归基线」的墙钟加速，不是相对某个弱实现。
  • 吞吐 tok/s（Table 3）：服务并发下的生成速度。加速比随并发升高而收窄，因为解码逐渐变成计算瓶颈。
  • 块接受率（附录 Figure 5）：整块按首个预测 token 的视觉依赖四分位分组后的接受比例。
  • 无损：标准投机验证不改变目标分布；本文没有另报任务准确率对照，默认由算法保证。

14. Ablation 与缺失的 ablation

已有：测时块长 8 vs 16（Table 4）；草稿 3/5/8 层（Table 6、附录 Table 9 为 T=1）；tap 5 vs 8 层（Table 7、Table 10）；视频上稀疏单独与再微调（Table 2）；并发与 vLLM（Table 3、附录 Table 8）。最关键的方法对照其实是 Table 1 里同数据 DFlash vs MMFlash，它隔离了视觉感知重加权。缺失：没有把式 3 的三个因子（bk、gk、1−qk）拆开做成一张表，因此不能从数字上断言「熵缩放」或「停梯度加分」各自贡献多少；α、λ 没有扫描；没有全量基准（只有 200 条子集）；没有把任务准确率与基线并排（无损是算法声明）。抽隐状态的离线存储「常达数十 TB」（附录 D），主实验改用在线训练，这一成本只定性给出。

15. Claim vs Evidence

「无损加速最高 3.58×」与 Table 1 的 9B ChartQA、T=0、并发 1 一致；「平均 3.00–3.05×」是七个图像基准在两个模型、贪婪解码下的平均，不能理解成任意视频或高并发的保证。视频「2.33–2.71×、比 DFlash 高 11.2–23.2%」需要算上稀疏与 2K 微调，不是训练重加权单独的结果。相对 EAGLE-3「最多 195.4%」是加速比的相对提升，且发生在 EAGLE-3 本身已经偏弱的 MMBench 上，容易被读成绝对倍数。泛化到 Gemma 与 27B 只在三个基准、T=0 上展示，27B 甚至没有 EAGLE-3 对照（Table 5）。「高并发仍然有效」有 Table 3 支持，但加速比从 3.58× 降到约 1.1–1.9×，正文自己也写明会收窄。

16. 贡献

提出用目标模型 KL 定义 token 级视觉依赖，并给出接受率随该分数单调下降的证据；把该分数变成不增加训练前向的损失重加权；为长视频草稿设计训练推理一致的简单稀疏模式；在两个 Qwen3.5 尺度、七个图像与三个视频基准、两个温度、SGLang/vLLM 以及另外两个模型家族上给出可核对的加速数字，并发布代码与草稿权重。

17. 局限

附录 F 写得很清楚：系统设计与评测针对「图像或视频进、文本出」的 VLM；视频仍靠简单稀疏加轻量微调，而不是为视频单独做的草稿，长视频草稿难于图像。评价只有每基准 200 条。没有报告任务准确率对照。重加权三因子缺少拆分消融。离线隐状态存储可达数十 TB，在线训练则每步要跑目标模型。尚未推广到带音频、流式语音的 omni 模型。注释为 Work in process，结果仍可能更新。

19. 研究价值

它把「多模态投机为什么难」从印象推进到一个可计算的 token 级诊断，并且证明这个诊断可以直接变成训练信号。对做 VLM 服务的人，更有用的也许是工程结论：草稿不必再看一遍像素；长视频上先做与训练一致的稀疏，再谈更花哨的路由；默认 5 层草稿已经接近加速比的甜点。

20. 可执行迁移

  1. 若已在 VLM 上用 DFlash 或类似块扩散草稿，先不要改结构。用目标模型对训练语料算 KL(p(·∣x,I)‖p(·∣x))，按分位数看接受率是否也从高到低掉一截；若是，把式 3 的加权插进现有交叉熵，α=1、λ=0.5 可作起点。这只改损失，不改服务栈。
  2. 服务长视频时，让草稿与训练使用同一套「sink + 步长采样视觉 + 全文本 + 近窗」，不要训练用全文、推理再截断。Table 2 显示，即便不微调，稀疏也能先抬一段 τ。并发升高后加速比会掉，需要按 Table 3 的形态重新选并发与块长（必要时用 Table 4 的块长 8 换吞吐）。

21. 方向专用分析（Inference Acceleration：无损投机、草稿费用与服务形态）

投机解码的速度由「接受长度 / 每次草稿+核对的墙钟」决定。MMFlash 用扩散把草稿前向次数从 O(τ) 降到每块一次，于是可以养更深的草稿；视觉重加权则专攻接受长度里最容易断的那些位置。它还演示了两个服务现实：并发升高后，系统从显存带宽受限走向计算受限，投机空间变窄，但仍可能在中等并发上打败「把并发加倍的基线」；测时块长可以小于训练块长，加速比只降约 5%，这为动态块长调度留下余地。与昨天精读过的 LazyWeights（端侧量化）不同，这里是服务端、无损、面向 VLM 的解码加速，二者不互相替代。对视频 token 极长的请求，稀疏注意力属于草稿侧的 KV/上下文控制，和目标模型自己的 KV 优化是正交的。

22. Attack / Verification lens

无损性依赖于标准核对实现；若服务栈在采样、temperature、或停用词上与训练不一致，表面上的加速可能伴随着分布偏离。评价子集只有 200 条，换种子可能改排名，尤其是分项基准上的「最高 3.58×」。相对 EAGLE-3 的百分比提升对弱对照敏感，复核时应同时看绝对加速比和 τ。视频数字把稀疏与微调叠在重加权之上，不能直接当「同一方法的零成本推广」。代码已声明但本次未运行，权重是否与 Table 1 完全对应需要下载后才能确认。建议复核协议：固定样本 ID、同一 SGLang 版本、同一生成上限，并抽查若干 prompt 的输出是否与无投机贪婪解码逐 token 一致。

  • VLM 投机的失败点集中在高视觉依赖 token，多模态数据本身补不齐。
  • 用目标模型有图/无图的 KL 定义依赖，分数可离线计算。
  • 再乘上目标自信度、前缀存活和「现在还不会」，就得到 MMFlash 的损失权重。
  • 草稿只读目标隐状态，不重编码像素，费用不随视觉 token 膨胀。
  • 图像上贪婪平均约 3.0×，9B ChartQA 单点 3.58×；同数据 DFlash 大约 2.7×。
  • 长视频要先靠稀疏注意力（40K→约 1.6K），微调是加成不是前提。
  • 5 层草稿是加速甜点，再加深主要涨 τ 不涨速度。
  • 测时块长收到 8，加速只掉约 5%，适合做动态调度。
  • 高并发时加速比会收窄，但仍可能在更低并发上胜过「翻倍并发的基线」。

2. 一句话定位

Token2Tile 是视频扩散变换器里的训练免费稀疏注意力算子：在一个保护注意力 logit 的在线低秩空间里按每个 query 挑选 key 簇，再把同一 query 簇的选择并成可在 GPU tile 上执行的并集，并用 per-query 残差补上未选中的质量。相对稠密 FlashAttention-3，端到端 1.48–1.54×，VBench 各维与稠密相差不超过 0.5 分；在相近速度下，H3 上 PSNR 比 SOL / SubBlock 高 5.5–6.8 dB（Table 1）。

3. 人话版

视频 DiT 的注意力随隐空间 token 数二次增长。作者写，MiniMax-H3 上它大约吃掉稠密去噪一步的 64%。FlashAttention-3 把实现打满了，但仍然算完每一对 query–key。预训练好的生成器若能在推理时丢掉不重要的对、又尽量接近稠密输出，就可以直接加速，不必再训练。

难处在粒度打架。每个 query 真正想看的 key 并不一样，可 GPU 内核只有在连续的 query 块对连续的 key 块（tile）上才快。若按 tile 或按簇用一个代表去打分，代表会把成员差异抹平，选中的集合往往抓不住每个 query 自己的注意质量。就算选得很准，没选中的尾巴里仍有质量，直接砍掉会放大输出误差，所以还需要残差分支。Token2Tile 的折中是：打分和残差都保持「每个 query 一份」，执行时则把相近 query 的选择并起来，再把选中的 key 打包装进跨簇边界的连续 tile。簇和选择每 R=4 次调用刷新一次，中间复用结构、只代入当前的 Q,K,V，结构开销大约只占一次注意力调用的十分之一（Figure 4）。

4. 背景与缺口

稠密注意力是标准 softmax（式 1）。稀疏视频注意力已有静态模式、按块路由、低分辨率草稿、反对角线打分、池化阈值（SOL）、子块打分（SubBlock），以及把 query/key 聚类的 SVG2 / SVG-EAR 等（§5）。残差方面，SLA、PISA、SOL、SVG-EAR、SparsePR 各用不同方式补被跳过的交互。作者用捕获的注意力做了一个对照（Figure 2，每 query 预算 1%）：按 query 选 key 簇能抓住最多质量；换成连续 64-key 块或共享一个选择，质量明显下降；把 per-query 选择在 query 簇上取并，执行对数显著少于同样大小的连续 query tile；尾巴里仍留 32–68% 的质量，若不用残差而直接丢掉，输出误差会再放大一截（H3 / Wan / Hunyuan / LTX-2.3 上的倍数见原图红字，精确柱高未列表，不从像素读取）。缺口是：同时保住 per-query 的选择与残差，又把执行组织成高效 tile，并且用同一个、由当前 Q,K 闭式算出来的低秩空间完成聚类、打分和残差。

5. 核心 insight

聚类、打分、残差全部依赖 query–key 交互，因此低秩空间应当保护 QK⊤，而不是分别重构 Q 和 K。该目标有闭式解（定理 1）：对二阶矩做一次 d×d 分解即可，在线、无需训练。相近的 query 在这个空间里打分类似，它们的选择并集不会膨胀失控；并集比单 query 预算更密，这种「多出来的精确计算」被当成自适应分配——成员意见分歧大的簇自动获得更多精确对。残差打在「并集之外」的簇上，避免把别的成员并进来的 key 算两遍。刷新间隔 R=4 把结构成本摊薄，精确注意力仍占调用时间的大约 80%。

6. 方法逐步拆解

步骤 1：logit 保护的低秩空间（§3.1）。求匹配投影 Pq,Pk∈Rd×r，使 Q~=QPq、K~=KPk 最小化式 3 的 logit 误差。定理 1 给出式 4。原空间 d=128，取 r=32。每个头对当前请求的 Q,K 做一次 128×128 分解，不用预训练投影。

步骤 2：聚类。在该空间做 k-means：CK=2048 个 key 簇作为选择与残差单位；大约 CQ≈N/128 个 query 簇，每簇约 128 个 query，对齐内核 tile 高度。首次稀疏调用跑四轮 k-means，之后刷新从上一轮质心热启动（key 簇更新一次，query 簇两次）。

步骤 3：按 query 选择，再取并集（§3.2）。query i 用质心分数 gic 给每个 key 簇排序，取能覆盖预算 bN 的最短整簇前缀 Si。同一 query 簇的选择取并得到 Ua，再加被钉住的上下文（文本或音频 token）保持精确。执行密度 ρ 由式 6 定义，通常高于名义预算 b：H3 T2V 的 2.5% 日程在整条去噪轨迹上平均执行约 16.5%。方法比较都在相同 ρ 下进行。

步骤 4：Per-query 残差（§3.3）。输出是 Ei 上的精确注意力，加上并集外各簇的质心贡献（式 7）。权重写成「近似权重 + 掩码修正」（式 8），从不物化 N×N 矩阵。两支用 log-sum-exp 合成一次 softmax。

步骤 5：打包与时间复用（§3.4）。把 key/value 排成连续簇段，稀疏内核沿选中段遍历，并在簇边界之间打包 tile，而不是把每个簇对上取整到固定块。每 R=4 次刷新标签、质心与并集；复用调用只把缓存结构套到当前 Q,K,V。CFG 的无条件分支复用有条件分支建好的结构。调用复杂度见式 9，长序列下精确项主导。

步骤 6：去噪时间的预算分配（§3.5）。稠密前缀之后，把剩余步分成四个窗口，用一次离线误差注入标定：在每个窗口的探测步上扫预算网格，测量相对稠密输出能量的 SSE，再用动态规划按窗口长度分配。日程归一化到总预算 B，跨 prompt 复用，不改模型权重。较早窗口更敏感，会分到更多预算（Figure 7）。

9. Baselines

  • Dense FA3：速度与保真的参照。加速比是成对请求时间之比；PSNR/SSIM/LPIPS 相对「同一生成器的稠密视频」。

11. 指标教学

  • PSNR / SSIM / LPIPS：相对配对稠密视频的保真。PSNR 高、LPIPS 低更好。它们量的是「像不像稠密输出」，不是审美绝对分。
  • VBench 维（Subject、Background、Motion、Aesthetic）：生成质量的常用自动指标，单位为 %。正文要求与稠密相差不超过 0.5 分。
  • Time / Speedup：八卡请求时间（秒）及相对稠密 FA3 的倍数。
  • Attention SNR（dB）：算子输出对 FP32 稠密注意力的保真，在相同 ρ 下比较选择规则。
  • 盲测 score（Table A1）：score = 胜 + ½ 平；区间由对评分者的 bootstrap 得到。
  • DiT / E2E 加速（Table 2）：只含去噪器 vs 含 VAE 等全请求。步数变少时，E2E 会明显小于 DiT。

14. Ablation 与缺失的 ablation

Table 4 与附录 C 把残差、共享选择、预算分配、低秩维、簇大小、刷新间隔拆得很细。Table 5：query 簇加倍时并集体积膨胀的实测/预测比为 H3 1.33/1.32、Wan 1.25/1.26、Hunyuan 1.26/1.28、LTX 1.27/1.25。32 维相对 16 维在 3.5% 最多差 2.6 dB，再加维则落入 k-means 波动。R=4 相对 R=2 或每次刷新的质量/时间权衡有定量描述（约 0.34/0.16 dB vs 0.42/0.27 dB，调用变慢 1.24–1.43×）。标定日程相对均匀日程在 H3 T2V 与 Wan I2V 上高 0.55–0.80 dB，且不增加执行对数（16.5% vs 16.8%）。缺失：没有在 DiT 上微调或蒸馏该算子的对照（它宣称训练免费，这可接受）；没有非 Hopper、非 d=128 的内核数字；代码未发布，附录里部分 SNR 表（A2–A18）本次只抽检了与主文交叉引用的条目，未把 23 张表全部搬进本页。

15. Claim vs Evidence

「1.48–1.54×、VBench 在 0.5 分内、H3 上 5.5–6.8 dB、Wan 上 4.6–4.8 dB 且更快」都能在 Table 1 相应行直接加出来，证据扎实。内核「最多 7.9×」（附录，1% 预算）不可与端到端 1.5× 混用，正文也把二者分开。「最准确的选择规则」在四个生成器、匹配 ρ 的 SNR 上成立（Table 3），但生成质量只在 H3 与 Wan 上测；Hunyuan 与 LTX 没有 Table 1 那样的端到端视频。盲测对 SVG 系列只是略胜（56%），置信区间下限 52%，不能宣传成「观感全面压过语义聚类方法」。SubBlock 未对 Wan 调参，该对照偏弱。实现限定非因果注意力、Hopper、d=128，结论外推需要另证。

16. 贡献

一套把 per-query 打分、per-query 残差与并集自适应分配结合到 tile 执行里的训练免费算子；一个由 Q,K 闭式计算、同时服务聚类/打分/残差的 logit 保护低秩空间；以及把 query 簇内分歧与并集体积联系起来的统计模型，并用受控实验把打分、决策和预算分配拆开。附录表多，便于复核。

17. 局限

结论段自己写下：实现针对 Hopper 上的非因果注意力且 d=128，簇 logit 工作空间随 N×CK 增长。长视频、高分辨率时这块显存会成为新的瓶颈，正文未给出峰值显存的完整对外配方（附录 Table A5 有每 rank 的分配注意力显存，本次未把全部单元格写入本页，细节见原表）。仅单机八卡（及部分四卡、单卡）评测。没有开源。八步蒸馏模型上端到端加速缩到 1.03–1.11×，说明「步数已经很少」时稀疏的全请求收益有限。VBench 对质量差不敏感，主要证据其实是相对稠密的 PSNR 与盲测。

代码：Not Reported。需要：SGLang-Diffusion 与 FA3 / FlashInfer 可变块注意力，八张 H200 与 Ulysses-8；MiniMax-H3、Wan2.1-14B 及可选的 HunyuanVideo、LTX-2.3；VBench / VBench-I2V；实现在线 128×128 SVD、k-means（CK=2048、每 query 簇约 128）、并集打包、LSE 合并、R=4 结构缓存、CFG 结构共享，以及四窗口误差注入标定。比较必须匹配执行密度 ρ 而不是名义 b，并沿用各基线自己的稠密前缀与稠密层策略。内核时间须用 CUPTI 且与 FA3 交替测量。

19. 研究价值

它把「token 级准确」和「tile 级速度」之间多年的张力写成一套可执行的算法，并且用同一个闭式空间把三件事情绑在一起，避免再叠三个异构模块。对视频生成推理，1.5× 端到端在几乎不伤 VBench、PSNR 明显更接近稠密的情况下，是比再做一轮蒸馏更便宜的插头式加速。统计模型与并集膨胀的预测（相关 0.95–0.99）也给后续调簇大小提供了工具。

20. 可执行迁移

  1. 在已有块稀疏服务里，先不要改内核。对捕获的 Q,K 做式 4 的投影，检查 32 维空间里每 query 的 top 簇与 128 维是否一致（论文用 Spearman 与 logit 误差，见表 A8 的设定）。若一致，就可以把打分搬到 32 维，这是最便宜的一步。
  2. 把「每 query 自己选、再在约 128 个 query 的簇上取并、并集外用质心残差」接到现有可变块内核；刷新间隔先用 R=4。用一次标定输入给四个去噪窗口做误差注入，早期窗口多分预算——Table 4 和 Figure 7 显示，残差与非均匀日程都是整 dB 级的，而不是小数点后的装饰。

21. 方向专用分析（Video Acceleration：训练免费、质量–速度权衡与内核）

视频加速常见三条路：蒸馏少步、训练免费稀疏/缓存、以及系统侧并行。Token2Tile 走第二条，强调相对稠密生成器的保真，而不是另训一个学生。端到端 1.5× 看起来不如少步蒸馏的 2–4× 起跳，但它不改采样步数，可与 LightX2V / HyperFlow 叠加（Table 2，尽管此时 E2E 收益变薄）。与昨日 TRACE（分辨率扩展）也正交：一个管注意力对数，一个管空间分辨率。比较时务必把「内核加速」（可到 4–8×）和「全请求加速」（约 1.5×）分开写，否则会夸大用户能感知的延迟改善。预算 b 与执行密度 ρ 的分离是实践要点：口头上的 2.5% 其实在跑 16% 的精确对，和「只算 2.5%」的方法不可比。

22. Attack / Verification lens

数字大多可在 Table 1、3、4 与 Figure 4 逐格核对，附录还提供盲测区间，这是高质量的证据链。风险在于：实现未开源，打包内核、热启动 k-means、CFG 结构共享都可能影响 ρ 与时间；SubBlock 在 Wan 上未调参；盲测对 SVG 接近随机优势；工作空间随 N×CK 增长，在更长视频上可能被迫降 CK，从而改变 Table 3 的 SNR。建议复核：固定同一随机种子的稠密视频作参照、报告实际 ρ、公布每窗口预算，并在未调参声明清楚的基线上同时给出「按作者默认」和「简单网格搜索后」两组对照。

23. 记忆总结

  • 视频 DiT 注意力又贵又稀疏，但「按 token 准」和「按 tile 快」不是同一粒度。
  • 用保护 QK⊤ 的在线低秩空间同时做聚类、打分和残差，d=128→r=32 通常够用。
  • 每 query 选自己的 key 簇，再在 query 簇上取并，并集既是执行 tile，也是自适应预算。
  • 残差打在并集之外，避免重复计算，去掉后 I2V PSNR 可掉 3.25 dB。
  • 结构每 4 次调用刷新，约占一次注意力的十分之一；精确部分仍是时间主体。
  • 端到端相对 FA3 为 1.48–1.54×，VBench 差距不超过 0.5 分。
  • 相近速度下 H3 的 PSNR 比 SOL/SubBlock 高 5.5–6.8 dB，Wan 比 SOL 高 4.6–4.8 dB 且更快。
  • 内核加速远高于端到端，八步蒸馏后全请求收益会进一步变薄。
  • 实现绑在 Hopper、非因果、d=128，工作空间随 N×CK 增长；代码未给出。
  • 比较一定要对齐执行密度 ρ，不要只看名义 1–5% 预算。
