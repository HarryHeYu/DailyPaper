Paper 1 · SCOPE — Agentic RL（BACKFILL）

基本信息与一句话定位

SCOPE: Selective Critical-Step On-Policy Self-Distillation for Agentic Reinforcement Learning，Qirui Liu、Wei Cao、Yu Mi、Yichen Sun、Xuekun Zhang、Lei Liu、Yue Shen、Zhixuan Chu；浙江大学 / 蚂蚁集团；arXiv:2610.38391 v1，2026-10-28，预印本（未核实正式 venue）。全文 HTML · arXiv · 项目页。论文中未核实官方代码仓库，故不把项目页等同于开源代码。

定位：让长轨迹 Agent 的训练同时拥有任务级完成奖励、步骤级纠错监督，以及仅在成功轨迹之间比较的效率奖励。

人话版：为什么不能只给整局打分

假设购物 Agent 需要找到指定颜色、尺寸和价位的商品。一次搜索后，它错误地打开了不符条件的商品，却在后面意外修正了错误并成功下单。终局 reward=1 会把之前错误行动也作为成功轨迹的一部分强化。另一条失败轨迹可能前面所有筛选都正确，只在最终结算按钮上犯错；简单 GRPO 则倾向于压低整条轨迹。SCOPE 先让模型学会阅读自己的执行记录、定位错误步骤并生成针对性的纠错 skill；随后在在线训练中，只对这些被标记步骤进行自蒸馏。它引入有符号且幅度有界的蒸馏系数，解决 teacher/student log-probability 大幅偏离时的梯度爆炸问题；对于成功轨迹，再用同组成功者的相对交互长度分配效率奖励。作者在 ALFWorld 和 WebShop 的多个 Qwen 模型上报告优于 GRPO 和技能引导基线的任务完成率，但额外的离线 SFT 和在线分析计算必须纳入成本比较。

Background、研究缺口与核心观察

普通 REINFORCE / PPO / GRPO 用 trajectory 最终回报指导策略学习。对短数学答案，最终正确与中间选择常常相近；对会搜索、点击、移动的 Agent，中途的无效动作和最终成功并不等价。论文 Figure 1(a) 的标注诊断显示：WebShop 成功轨迹中 29.8% 的步骤仍有错误；失败轨迹中 42.4% 的步骤正确。这是作者的经验统计，不是普适概率。单独增加 outcome reward 的采样次数并不能直接消除这种 credit ambiguity。

与使用整段 hindsight skill 的 SEED 相比，SCOPE 指出“纠错文本只针对个别步骤，却被应用到整段轨迹”会使不相关动作得到 off-target 梯度。另一方面，若直接使用教师与学生的原始 log-prob gap 做蒸馏权重，训练中学生 log probability 极端下降时，固定 teacher cache 会造成系数爆炸。Figure 3 的一次异常更新中，原本 gap 为 0.284 nats，训练阶段 gap 变为 2715.5 nats，梯度范数非有限。作者据此提出：选择性定位与梯度有界必须同时存在。

方法全流程：Input → Step → Output

Task q → snapshot actor rollout N 条 trajectory → 分别检查成功/失败历史 → 为错误 step 生成 skill 与 evidence → 只选择错误 step → skill-conditioned frozen teacher 对同一 token 打分 → bounded signed self-distillation → 成功组内比较交互长度 → GRPO + auxiliary loss → 新 policy

第 1 步，快照与采样。在外层轮次 u 令快照参数 θ̄ᵤ=θᵤ，从同一任务采 N 条轨迹。快照冻结不变：既用来执行任务，又充当 hindsight analyzer 和技能条件 teacher。更新中的 student 参数 θ 则在 microbatch 间持续变化。该结构避免“同一次训练中 teacher 也随梯度乱跑”，但仍受到 teacher 定位错误的影响。

第 2 步，分析器预训练。用一个小规模、由 GLM-5.2 帮助标注的轨迹分析 SFT 数据集训练策略模型识别出错位置、生成证据说明和修正技能。这里并非“全流程没有外部模型”，外部模型介入离线 warm-up；在线阶段才是自举分析。

第 3 步，针对轨迹结局的不同分析。成功轨迹结合自身 observation、action-validity feedback 寻找可避免的失误；失败轨迹额外参考同一任务组内成功轨迹的 action sequences。参考成功者是提供可行路径，而不是保证只有一条正确策略。分析器可以返回空集合；若没有可证明的错误，不对该轨迹启用 auxiliary loss。

第 4 步，明确 step mask。对每条轨迹给出若干 (target-step set, skill, evidence) 元组。mask mᵢ,ₜ=1 才计算蒸馏梯度，未被选中的动作不承担该信号。设计上同时降低 off-target 更新和无效 teacher scoring，但仅当定位 precision 足够高才有效。

第 5 步，条件教师与普通学生对齐。teacher 在原始历史之外插入与步骤对应的 corrective skill，student 仅看原始交互历史；两者计算同一已采样 token 的 log probability。teacher 不是直接执行技能，而是用“知道本步该怎么修正”的条件概率来影响未显式得到技能的 student。

第 6 步，稳定性约束。使用 tanh 将教师-学生差异约束到 [-c,c]，并 stop-gradient 阻止权重本身反向传播；否则少数低概率 token 可能支配全部梯度。差异为负的 token 仍能收到压制信号，区别于只保留正向引导的 gate。

第 7 步，相对长度奖励。只有成功 trajectory 参与“谁用更少动作完成”的对比；失败者不因短而获奖。使用 log 长度差使奖励基于相对比例而非固定长度阈值。

第 8 步，联合优化。把每条轨迹的最终 reward 和成功相对长度 bonus 组成组内 advantage，同时在选中 token 上额外优化蒸馏。推理阶段无需调用 analyzer 或提供技能文本。

核心数学与优化直觉

Δ = stopgrad(log p_teacher(y | h, skill) − log p_student(y | h))

A_dist = c · tanh(α Δ / c), |A_dist| < c

L_OPSD = − mean_selected[ A_dist · log p_student(y | h) ]

当 teacher 更相信真实采样 token，Δ 为正，梯度增强 student 对其概率；teacher 更不相信时，Δ 为负，压低 student 概率。这里的 teacher 信号仍然是概率差而非真实因果 advantage；选择错误会把错误引导变成训练更新。α 控制原点附近斜率，c 控制最大单 token 推动力；α 大会把小差异放大，c 过小会提前饱和。

p_ij = sigmoid((log T_j − log T_i)/τ_len)

R_pair(i) = R_i + λ_len · mean_{j≠i, successful} p_ij

Tᵢ 是交互步数，τ_len 决定偏好锐度，λ_len 决定长度奖励权重；只有成功轨迹加 bonus。两条成功轨迹长度 8 与 16 步，当 τ=0.1，log(16/8)/0.1≈6.93，短者 p≈0.999；当 τ=1，p≈0.667。前者几乎硬偏好，可能掩盖必要探索。

L_total = L_GRPO + λ L_OPSD

GRPO 把同 task 组内 reward 标准化得到 advantage，以 PPO-style clipping 限制 ratio 更新，另有 reference KL 和 entropy 项。KL 是当前策略相对参考策略的分布差异，系数 β_ref 大则偏离受限；entropy bonus 鼓励保留探索，不是“越乱越好”。与纯 GRPO 的根本区别不是替换 RL objective，而是增加“只在经过定位的步骤生效”的局部蒸馏 objective。

Toy Example：购物 Agent 的反事实纠错

任务：买“黑色 M 号、预算 100 元以内”的运动衫。一次 rollout：① 搜索“运动衫”正确；② 点开红色 L 号商品错误；③ 返回搜索正确；④ 筛选黑色 M 号正确；⑤ 下单成功。终局 GRPO reward=1；若完整轨迹分配相同 advantage，步骤②也可能被正向强化。分析器从商品页面观察与目标属性的冲突，生成针对步骤②的 skill：“进入详情前核对颜色和尺寸”，target-step={2}。teacher 在看到该技能的条件下，会降低原已采样错误点击 token 的概率：若 teacher log p=-2.1、student log p=-0.7，Δ=-1.4；c=1、α=2.5 得 A_dist≈-0.998，OPSD 梯度将压低错误点击概率。其他步骤 mask=0，不受此辅助信号改变。再假设两次成功分别用 5 与 9 次交互，相对长度奖励偏向前者，但不会给只交互 2 次就失败的策略任何长度 bonus。此为教学构造数值，不是论文实验数据。

实验配置、研究问题与指标教学

主训练与评估 backbone：Qwen2.5-3B-Instruct、Qwen2.5-7B-Instruct、Qwen3-1.7B；另测 Qwen3-32B。ALFWorld 为文字互动家务环境，六类 Pick/Look/Clean/Heat/Cool/Pick2；seen 验证每轮 128 episodes。WebShop 为根据约束搜索并购买商品，固定 128 tasks。主表 150 step checkpoint，32B 的 seen 也在 step 150，unseen 32B 测 134 episodes。不同模型规模采用同模型内比较。

Success rate（越高越好）：完全完成任务的比例；会忽视接近成功的细节。WebShop normalized score（越高越好）：购得物品对需求的归一化匹配分数；高分不一定严格完成。Mean steps（越低通常越好）：每 episode 环境交互次数；必须和成功率一起解释，不能把“少做动作而失败”当高效。Localization Precision/Recall/F1（越高越好）：错误步骤定位与人工真值的一致程度，Precision 低时错杀正确步骤，Recall 低时遗漏修正机会。Parsing accuracy：解析器能否读出合法的错误位置/skill 结构，不代表修正真的有效。

RQ1：比 GRPO 和技能型 baselines 强吗？RQ2：错误定位可靠、是否降低 off-target 更新？RQ3：离线 SFT、步骤选择、长度奖励分别贡献多少？RQ4：数值稳定性及训练更新效率是否更好？RQ5：是否迁移到未见任务？RQ6：32B 是否仍有效？作者还在附录展示标注数据制作、训练设置和 prompt；复现应先固定这些数据构造与 checkpoint 时刻。

消融、机制解释与证据边界

离线监督初始化用于让小模型形成有效错误定位能力，论文报告 SFT 后的 3B 错误定位 micro-F1 甚至超过 7B base。定位能力提升是中间证据，不自动等同成功率的因果解释。步骤选择组件主要避免 teacher 信息干扰无关 action；签名 bounded 系数主要避免训练期间 log-prob gap 变得极端；长度 reward 的消融把 ALFWorld 总成功从 98.4% 降到 93.0%，改为绝对长度 bonus 则为 97.7%。这说明长度 shaping 不只是额外速度偏好，可能间接改善任务策略。

Authors Claim：细粒度自蒸馏与相对长度奖励能兼顾成功率和效率。Evidence：同 backbone 的 ALFWorld/WebShop 主表、训练稳定性、unseen 以及 32B 对 GRPO 支持该点。Not Proven：跨开放网页/现实 GUI 的鲁棒性；真实总 GPU 成本、在线 analyzer 单位成本；模型是否只在标注风格相似轨迹中有效；step attribution 是否具有干预因果意义。

Contribution、限制与复现视角

Contribution 1 [New Mechanism]：结构化的目标步骤与纠错技能绑定，mask 掉未选步骤。Contribution 2 [New Objective]：有符号 tanh 有界 OPSD，保留正负更新。Contribution 3 [New Reward]：成功者之间依据 log 步长的 Bradley–Terry 比较。SFT、自蒸馏、GRPO 都是已有组件，创新主要在精确作用范围与共同约束。

作者侧限制与补充风险：初始 SFT 依赖外部标注；失败组无成功参照时分析信息不足；性能可能受任务环境结构与解析规范影响；强成功率接近天花板之后需要更难的 benchmark；局部教师引导可能过拟合某类 corrective skill；多组 rollout 引入延迟；高质量 judge/定位数据仍需人工验证。

最小复现路线：从 Qwen2.5-3B、ALFWorld、固定 128 seen eval 开始，先做 GRPO；然后用相同 SFT 数据训练分析器，并记录 target-step precision/recall；第三步保存 rollout snapshots、按 step mask 计算 cached teacher log-probs；第四步加入 bounded A_dist 与长度奖励。日志必须分别记录有 mask/无 mask 的梯度范数、selected-token ratio、loss、互动数、成功率及 GPU-hour。先重现 Table 1 的同模型胜负与 Figure 3 稳定性，最后跑 SEED/SDAR 而不是只对 GRPO。

Research Value、迁移实验与 Attack Lens

Baseline Potential：强，在 agentic RL 算法论文可作为 localized distillation baseline。Migration：高，错误定位可以接入 tool-use safety、memory write、multi-agent message。Systems：中，mask 减少 teacher scoring 范围但 analyzer 可能额外耗时。Attack：高，可通过污染 evidence 诱发错误 step selection。Evaluation：高，应度量反事实步骤损害。Benchmark：高，设计“成功轨迹含局部错误”的评价。New Paper：中高，但需证明定位与 reward 的独立贡献。

迁移 A — Agent memory 写入审计。Original：action-level 错误被 outcome 掩盖 → Mechanism：目标步骤 selective guidance → Question：是否能仅纠错造成未来失败的 memory write？→ Modification：把 memory write 视为独立 action、记录 provenance 与未来 read 依赖 → Minimum Experiment：Qwen2.5-3B + ALFWorld 扩展 200 条可回放轨迹，在随机 20% memory write 注入事实性噪声，比较全轨迹 reward、step-only correction、因果 read-attribution correction，测 downstream success、write F1、对正确记忆误删率及 token-cost → Baseline：GRPO、SEED、no-memory → Contribution：有可定位错误归因的 persistent-memory RL → Risk：oracle write 标签不可靠，碰撞风险：已有 memory provenance / critical-step learning。

Paper 2 · GAAC — Efficient Inference（BACKFILL）

基本信息 / 一句话定位 / 人话版

GAAC: Lossless KV Compression for Bandwidth-Efficient LLM Inference on Personal Devices；Yipin Guo、Arun M George、Siddharth Joshi；University of Notre Dame；arXiv:2610.38210 v1，2026-10-28，预印本，venue 未核实；全文 HTML · arXiv。未见论文明确的官方开源代码链接，不推断 code 状态。

定位：为带宽受限端侧 LLM 服务提供无损 BF16 KV 缓存编码，将更少 KV 读取字节直接转化为 decode-attention 与服务吞吐收益。

长期对话时 KV cache 随 token 长度累积，每生成一个新 token 都可能读取大量此前 key/value。模型权重量化到 4-bit 以后，KV 仍保持 BF16，反而成为明显的内存与带宽负担。一般 KV quantization 直接截断数值，存在模型输出质量风险；传统压缩虽然减少容量，但如果每次还得先把整个 cache 解压再做 attention，带宽成本并未消失。GAAC 观察 BF16 指数在每个 layer/head/channel 上聚集于很短的连续窗口，因此不修改任何浮点 bit：保留 sign 和 mantissa，指数用校准过的 base + 小 offset 存储。每 8 个数共享 3-bit/4-bit/raw 模式标签，并把解码融合到 attention tile 读取时。论文报告约 1.405× 无损 KV 压缩、端到端 decode step 最高约 1.15×、相同 KV 内存预算下 serving 吞吐最高约 +29%。关键不是“压缩率很高”，而是证明压缩、省字节与真实速度在特定端侧带宽瓶颈下能够闭环。

Background / Gap / Core Insight

W4A16 指权重 4 bit、activation 16 bit；权重占用下降以后，模型上下文从 4K 扩到 64K，历史 KV 的容量和每 token 读取成本继续随长度上升。以一个查询 token 需要查询 64K 历史状态为例，若每个历史键值仍为 BF16，访问时必须从慢速内存读取全部值。传统量化降低位宽，但少量数值误差可能被长上下文 attention 放大；传统 lossless codec 可能压得更小，却有随机访问、复杂 codebook 查表以及完整解压成本。

作者的核心观察来自对 KV BF16 exponent 分布的经验统计：跨若干 Qwen/Llama 模型，大多数指数落在通道特有的连续 8 值窗口，少量落在 16 值窗口。Table 1 的经验 exponent entropy 约 2.69–2.78 bits。由此可以用定长短 offset + fallback 表示，既保证所有 bit 可恢复，又能在 GPU tile 内用整数加法完成指数解码。

重要区分：这是模型表示的统计性质和 kernel 工程发现，不是关于全部 Transformer 必然成立的数学定理。其收益取决于计算与带宽谁是瓶颈；decode 读 KV 越多、带宽越紧张越可能收益，prefill 和少 full-attention layer 的体系则未必。

方法全流程与编码数学

Calibration KV exponent histogram → channel-wise contiguous base windows → 8-element group mode selection → bit packing → fill-then-finalize KV block → compressed slots/paged table → fused decode attention tile read + reconstruct → exact attention output

步骤 1：离线校准。从 WikiText 训练集子集取 KV，按 layer、K/V、head、channel 统计指数，选择覆盖数目最多的长度 8 与 16 的连续窗口，确定 b₃ 与 b₄。这里使用两种 base 而非共享 one-size-fits-all 指数中心。

步骤 2：八元组模式。按照 attention 访问顺序把八个指数打成组；若所有 eᵢ-b₃,ᵢ ∈ [0,7]，使用 3-bit；否则若全部落在 b₄ 对应 16 值窗口，使用 4-bit；否则回退 8-bit raw exponent。一个 outlier 使整个组变宽，这是 SIMD 友好与压缩率之间的权衡。

步骤 3：精确恢复。每个数的符号与 7 bit mantissa 不动，指数按 cᵢ=eᵢ-b_w,ᵢ 编码，恢复指数 êᵢ=b_w,ᵢ+cᵢ；因为 raw mode 保底、差分用整数精确计算，所以不会产生 KV 的量化误差。核心 3-bit 情况每元素占 8（sign+mantissa）+3（指数）+2/8（mode tag）=11.25 bit，对 16 bit BF16 的理想压缩为 16/11.25≈1.422×。

步骤 4：填满才压缩。当前追加 token 先存未压缩 BF16 tail；一个 paged KV block 完成后再编码一次。这样无需每追加一个 token 都重新打包整个不完整块，也避免自变量长度分配造成的碎片化。

步骤 5：固定容量 slot + fallback。实际压缩块大小可变，作者给压缩块分配固定上限 C；若压缩后 S≤C 则存压缩槽，否则保留 raw block。block table 记录每块编码类型与物理地址，和 paged serving 集成。

步骤 6：边读边解码。decode attention 加载压缩 KV tile 和 tags，局部恢复 BF16，再立即做 QK score/softmax/V 聚合，不在全局内存生成完整解压副本。未压缩 tail 和压缩块共享 softmax 归一化，因此维持普通 attention 的语义。

核心公式、Toy Example 与理论上限

w_g = 3 if every 0 ≤ e_i − b3_i < 8; else 4 if every 0 ≤ e_i − b4_i < 16; else 8

c_i = e_i − b_w,i ; e_recon_i = b_w,i + c_i

一个人工构造的 8 元组指数是 [126,127,128,129,126,128,127,129]，假设该通道 b₃=124，则 offset 分别为 [2,3,4,5,2,4,3,5]，均能用 3 bit 表达。原始 8 个 BF16 需要 128 bit；这里 8×8=64 bit 原样 sign+mantissa、8×3=24 bit exponent offsets、2 bit tag，共 90 bit，即 1.422×。若其中一个指数为 138，整个组不满足 3-bit 窗口；若 b₄=124，则 138-124=14 可进入 4-bit 模式，需要 64+32+2=98 bit，约 1.306×。如果有指数 200，则该组回退 raw，128+2 bit 略大于原始，不是压缩失败导致错误，而是表示自适应时增加了 metadata。上述值为教学构造。

值得注意：lossless KV 意味着相同输入的 reconstructed BF16 内容逐 bit 一致，不意味着不同 GPU kernel 的浮点归约顺序、数值舍入和最终 token 输出在所有环境完全一致；系统仍需 end-to-end deterministic consistency test。

主要瓶颈是 decode 阶段重复读取长上下文 KV 的 memory bandwidth，不是减少 attention 的数学 FLOPs；相反，重构还增加计算量。是否需要训练：无需改动模型权重，仅离线统计 channel windows；hardware：针对 bandwidth-bound 的 DGX Spark/M4，其他平台需要重写融合 kernel。batch 变大后带宽和计算占比变动，应重新测量；context 越长通常越有利，但 RoPE position drift 可能改变 exponent distribution，使 raw 退化增加。

Ablation、Claim vs Evidence、Limitation

Ablation 1：固定 3+4+raw 三模式优于加入 2-bit 模式的设计，虽略损 ratio 却显著降低解码时间。Ablation 2：跨域校准较稳定，最差 ratio 只降 0.004×，但不保证更长上下文的 RoPE rotated keys 不漂移。Ablation 3：Table 5 明确了 IO savings 294.3µs 抵掉额外 49.2µs computation；这是 kernel 级机制证据。

Authors Claim：无损 KV codec 和 fused attention 能缓解端侧带宽瓶颈。Experiments Actually Show：所测 BF16 模型的 compressor bitwise restore 与 DGX Spark/M4 的 decode acceleration、同内存预算服务吞吐增加。Not Yet Proven：所有 GPU 的可移植性、所有长上下文位置、任何任务下的端到端 bitwise output 恒等、能耗改善、prefill 加速。

作者限制：依赖指数分布冗余；在 FP8 E4M3 上收益弱；RoPE rotated key 随更长 position 漂移可能降低 ratio；固定 slots 放弃少量空间上限；只直接优化 decode；未测 energy。补充：复杂 block table 与 fused kernel 的维护风险；KV spill/restore、多租户隔离、batch scheduling 与 speculative decoding 组合未全面评测；CPU/GPU 共享内存争用可能改变性价比。

复现路径、研究价值与迁移

最小复现：先在 Qwen3-4B 采样 BF16 K/V exponent 直方图，按 layer/head/channel 统计 8/16 contiguous coverage；写 Python reference codec 及 roundtrip bit-exact unit tests（随机 exponent、异常值、Inf/NaN、跨 block 边界、raw fallback）；再实现 8-element tag packing；最后在 Triton/CUDA 或 Metal kernel 实现 fused tile decompression，和标准 attention 对齐；优先重现 Table 1 compression ratio、Table 5 timing breakdown，之后连接 vLLM 0.17.1 的 paged KV 管理与 W4A16 serving benchmark。需 sweep context 4K/16K/64K、batch 1/4/16、slot capacity 与模型 KV head 数。

Research Value：Baseline Potential 高：无损 codec 作为所有 lossy KV 压缩工作的 quality ceiling；Migration 高：迁移至 VLM、Video、tool-history KV；Systems 高：实际 kernel/serving co-design 已经验证；Attack Potential 中：生成 adversarial exponent tails 造成原始块比例上升；Evaluation Potential 高：定义 memory traffic 与 decode latency 的可解释分解；Benchmark Potential 高：长位置分布漂移 + bursty agent workloads；New Paper Potential 中高，但必须超过简单组宽微调。

Attack / Verification Lens + 九句记忆

构造 exponent distribution shift 的 stress test：长 RoPE 位置、代码/视频输入、随机噪声视觉 token、模型层切换，测 raw group rate 和 latency regression；伪造极端 input 长度诱发 block fragmentation，测 p99 serving slowdown；将 roundtrip losslessness 与 end-to-end numerical agreement 分开报告；用 entropy-shift-to-slowdown 曲线作为新指标。

① KV cache 是长上下文 decode 的真实内存瓶颈。② GAAC 只压指数，不改 sign/mantissa。③ 每个通道有单独的指数窗口。④ 八元组共享 mode tag，少量异常会退回更宽模式。⑤ bitwise BF16 重建是 lossless 的核心。⑥ 固定槽和 fill-then-finalize 让它可用于 paged serving。⑦ 性能关键是 fused decode，不是“把 cache 先整体解压”。⑧ 64K attention 1.19–1.27×，完整 decode 只有 1.04–1.15×，要区分层次。⑨ 最值得研究的扩展是 Video/Agent 的动态 KV 分布和系统吞吐，而不只是多压一点 bit。

Cross-Paper Synthesis 与 Collision

共同趋势：把昂贵操作只放到有边际价值的对象上

SCOPE 控制梯度在哪些步骤生效；GAAC 控制 decode 时从内存搬运多少字节。一个面向 training signal，另一个面向 memory traffic；二者都不是简单增加模型容量，而是在细粒度对象上做选择性分配。二者都指出原始 proxy 会误导：trajectory outcome 不足以代表每一步正确性，compression ratio 也不足以代表 wall-clock speedup。

可能的组合框架：Utility-Aware Agent Training & Serving

把 agent trajectory 拆为 step/message/tool-return/cache-block；训练侧用 SCOPE 的 step-error evidence 估计未来失败风险；服务侧用 GAAC 为所有历史 KV 提供无损基础压缩，再基于风险决定何时值得额外预算（例如解码/重算）。其中 GAAC 的无损压缩不需要学习到的错误风险，而“风险影响缓存保留”的部分是新的有损决策，需要严格与 lossless codec 分开。

Collision 与 Prior Work 风险

不是已证实的直接论文冲突，而是潜在研发碰撞：Cache Engineering for Agents（arXiv:2610.28577）已提出对 agent KV 的主动 drop/repos；VisMemo（arXiv:2610.25136）已探索视觉近似缓存复用；SEED/SDAR 已探索技能型 RL。任何新工作必须说明自己在“因果 credit/是否保留”“压缩是否无损”“内存读写与模型质量”三维中有何不同，不能仅拼接既有模块宣称全新机制。
