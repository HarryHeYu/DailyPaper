一句话定位、人话版与 Background

AttnSR 想解决长轨迹强化学习最熟悉的问题：终点成功/失败会给整段 trajectory 一个 outcome reward，却不告诉我们哪个历史决策真正促进了成功。它不使用额外训练的 Process Reward Model，也不引入反事实环境 rollout，而是从 actor replay 时已经产生的自注意力矩阵中抽取“后续动作看过哪些早期步骤”，构造 step dependency graph；从终止步骤反向传播相关性、校正近因偏差，并用多层共识降低伪相关，再把相对近期平均 outcome 好坏转化为前面步骤的正负奖励。实验中最强的 ALFWorld 结果是 Qwen2.5-7B-Instruct 的 PPO 91.24%→PPO+AttnSR 97.08%，但 WebShop 官方 score 70.74→69.71，不能说全任务无条件提高。更重要的是它把 attention 明确当作 relevance prior 而非 causal attribution，这种诚实的机制定位对研究者尤其重要。旧范式 PPO 通过整轨迹终局奖励与价值函数的 GAE 反向传播好坏，随着交互变长，很容易让某个偶然正确的晚期动作背锅或抢功；PRM/stepwise reward 需要昂贵标注、额外判别器或环境重放。这里的研究 gap 是：是否能复用训练中已有的结构信号给 sparse reward 加形状，且不能对外宣称“注意力就是因果”。

完整 RL Formulation 和 Method 流

一条交互 episode i 含 K_i 个 step，S_i,k=(assistant action A_i,k, environment observation O_i,k)，最后一轮可以没有观察；训练损失只覆盖 assistant token，环境 observation token 作为上下文不直接反传 actor loss。Input 完整交互轨迹与任务终点得分 R_i → actor 对轨迹 replay、获取每层注意力 Q/K → 按 assistant-to-assistant 和 assistant-to-observation 分块聚合 → 得到严格只由后续指向历史的 step graph G → 从终点 backward propagation 生成 a_k → 减轻距离/近因偏置 → 跨层几何平均得到 p_k → 用 confidence gate 和中心化 outcome 确定签名 → 将 s_k 插入每个助手 step 最后训练 token 的 reward 数组 → 标准 PPO critic/GAE 更新模型。State 可以理解为含历史动作和环境反馈的文本上下文 h_t；Action 是模型实际输出指令或自然语言消息；Policy πθ 按上下文生成 token；Reward 是环境给定 terminal outcome + attention-shaped intermediate shaping，PPO 目标仍是限制策略更新幅度的 clipped policy objective，并由 critic 估值。Credit Assignment 不是直接把高 attention 权重当 advantage：p_k 首先只是候选分摊比例，最终更新方向由 R_i 相对 running mean 的 signed factor 控制，这一点避免将失败轨迹中高相关步骤错误奖励。

核心公式、变量及 intuition

论文式（1） r^PPO_{i,u}=R_i·1[u=e_{i,K_i}]，只在最后 assistant endpoint 给终点奖励；式（2） r^AttnSR_{i,u}=r^PPO_{i,u}+Σ_{k<K_i}s_{i,k}1[u=e_{i,k}]，允许前面 step 出现额外 reward。式（3） a^l_{i,K_i}=1，a^l_{i,k}=ρΣ_{j>k}a^l_{i,j}G^l_i[j,k]，其中 G 的边是后续步骤 j 的 Q 对先前步骤 k 的注意力质量，ρ=0.85 为每跳衰减，越多跳间接路径贡献越小；这不是因果路径概率，而是遍历加权图的启发式评分。式（4）对 log relevance 标准化，叠加 proximity d=exp(-(K_i-k-1)/κ) 的规范化值，系数 η=-0.25、κ=4，来抑制近期 token 常被自然更多关注的问题；softmax 温度 T=1 控制分配尖锐度。式（5）以跨层 geometric mean 合成 p_k：只有多个层都相对支持的历史步骤，最终权重才较高。与 PPO strongest baseline 的核心区别不是 actor clipping、KL 或 critic 结构，而是 rewards 的时间位置。若 ρ 过小，早期关键决策传播衰减；若 η 过负则压制真实临近因果步骤；若 p_k 过尖锐容易 reward hacking 地固定奖励少数 high-attention action；若校正太弱，奖励变相只是 position bias。论文没有声称 SVD/QR 类矩阵分解，也不应该把图权重误写成 learned verifier。

Toy Example：失败轨迹如何得到负反馈

假设一个 ALFWorld Agent 需要先找到杯子，再清洗，再放入柜子：step1 打开抽屉找到物品，step2 调用清洗工具，step3 把杯子放错容器，step4 终止。终点 reward=0。如果之前 100 条轨迹平均 reward=0.7，那么 centered outcome 是负的；Replay 时后续 Q 可能较多关注 step2 的清洗状态，也可能高关注 step3 的目标判断。AttnSR 会把 attention 聚合到 step-level graph，后退计算相关性，经 recency correction 与层间 consensus 得到例如 (0.2,0.3,0.5) 的比例，再按负的 gate 强度给 step1、2、3 分别负 shaping，而非仅在终点判零。数值是教学示意，不是论文给出的具体系数；该方案不能保证真正应该责备的只有 step3，因为高关注可能只意味着模型试图引用一个有误的环境 observation。引入 step 对照最重要：把某步替换为正确动作并重新执行环境，如果 outcome 发生变化，才逐步接近因果验证。对容易被误导的任务，应将这种高风险 attribution 作为调试预警，而不是定论。

Baseline、Setup、研究问题及评价指标

模型：主实验 Qwen2.5-7B-Instruct，另有 Qwen3-4B-Instruct-2507、Qwen2.5-3B-Instruct 测试和 GRPO 扩展；主 PPO 与 AttnSR 对齐 actor、critic、训练设置，在 ALFWorld、WebShop、ScienceWorld 上比较。基线包括 raw instruction model、PPO（same setting strongest controlled baseline）、GRPO、TARL、AgentPRM、FlowTracer、Linear Step Reward 位置消融，以及异步 PPO；GRPO 表中部分使用 epoch1 n=4，不可与 PPO epoch4 n=1 视为 compute-matched。Research Question A：注意力分配优于只在终点更新吗？B：收益是否只是给每步等比例 reward 的结果？C：是否能跨 backbone 和优化器复用？D：是否缩短环境交互，还是单靠提前终止造成 success-rate 抬高？E：某个 benchmark 的 score 和 success 是否同向？ALFWorld 的 success 是任务成功比例，越高越好；WebShop 与 ScienceWorld 的 official score 是连续任务质量，success 是阈值化比例，两者必须一起报；environment steps 是平均实际交互次数，低并不自动更好（可能过早放弃）；output chars 衡量轨迹长度与成本，不等于 GPU tokens/s。配对显著性分析使用 274 个 ALFWorld、500 个 WebShop，以及 ScienceWorld 1,819 中的 1,488 个精确对齐任务；McNemar 用于配对二值成功，bootstrap 10,000 次估计 95% 区间。

至少八条定量结果及真实弱项

Table 1：ALFWorld PPO 成功 91.24%，AttnSR 97.08%，增加 +5.84 percentage points，而不是相对 5.84% 增长；失败数量从 24/274 降至 8/274。Unseen 89.55→97.76（+8.21pp），高于 Seen 92.86→96.43（+3.57pp），更支持对未见任务的泛化，但是否跨分布仍需外部数据。TARL 96.72%、FlowTracer 95.62%、AgentPRM 91.97%，AttnSR 相比最强 TARL 仅高 0.36pp，即 274 个任务中多 1 个成功，不应过度放大排名。ScienceWorld official score 44.53→46.35（+1.82pp），success 28.59→30.90（+2.31pp）；属于方向一致但数值有限的改善。WebShop success 40.20→41.00（+0.80pp），official score 却 70.74→69.71（-1.03pp），这是论文中明确的 trade-off，也是最应报告的弱项。Table 2 的 Linear Step Reward 仅 92.34%，比 PPO 高 +1.10pp，真正 AttnSR 达 97.08%，证明不是随便塞一点过程奖就能得到同样改善；但仍无法隔离 attention graph 与 outcome centering 的全部贡献。跨 backbone Qwen3-4B PPO 87.96→AttnSR 91.24（+3.28pp），Qwen2.5-3B PPO 79.56→87.23（+7.66pp），表明有一定迁移性但大小不一致。异步 PPO 59.32→63.99（+4.67pp），与 canonical 主设置的 91.24% 不可合并比较。GRPO 12.41→20.07（+7.66pp），不能仅凭绝对增益否认其较低基准存在的训练差异。Table 3 的 ALFWorld 平均环境交互步数 PPO 19.28→15.51，约减少 19.6%；WebShop 却 5.93→8.03，约增加 35.4%，再一次反对“统一效率改善”的说法。

Claim vs Evidence、Failure Propagation、局限及贡献

Authors Claim 是利用 actor attention 在不额外 rollout/PRM 的情况下分配 intermediate rewards。Experiments Actually Show：在匹配 PPO 上 ALFWorld 最强，ScienceWorld 小幅正向，WebShop 分数有降；在小模型、异步及 GRPO 扩展中有一定改善。What Is Not Yet Proven：注意力分配是最优 credit 或真因果、在不可逆工具操作和超长多模态 agent 中稳定、推理部署成本没有隐性增长、不同 sampling regime 保持相同趋势。Contribution 1 New Objective/Reward Shaping：用 graph relevance 重新安放奖励；Contribution 2 New Empirical Finding：注意力多层共识和中心化 outcome 提供可用启发式；Contribution 3 New Engineering：无需训练单独 reward model 的 PPO 集成。方法的风险恰是 attention correlates with importance 但可能同时偏好冗长、多次提到的错误观察。一个错误观测若被后续多步反复引用，会放大 attention path，奖励可能误导 planner 把错误 skill 编入 memory；接下来工具调用越多，错误可能被叠加放大。对真实 Agent，输入污染或 prompt-injection 还可能蓄意让敏感 token 获得高 attention，形成 reward manipulation。作者限定 attention 是 heuristic prior 是必要的安全前提，不应该在综述中删掉。

Reproduction、Research Value 与两条可执行迁移

最小复现实验优先使用 Qwen2.5-3B（计算便宜），但核验论文核心数字必须在原 7B 设置完成。实现时在 PPO old-logprob replay 的 Q/K after RoPE 捕获 attention，按 assistant/token mask 正确聚合 AA/AO；记录 step graph matrix 和每层 p_k；在每轮保存 centered terminal score、shaping norm、GAE advantage、KL、reward entropy。最先跑 274 个 ALFWorld held-out task，PPO vs linear shaping vs AttnSR，固定 env seed、actor update 与训练 token budget；同时保存任一 episode 的完整 step-level reward 以检查有没有 observation token 被误更新。Research Value：可直接作为 credit baseline；Attack potential 是对 attention 打伪相关攻击；Evaluation potential 是 step 替换下成功率的反事实一致性；New Paper potential 在于把 attention prior 和环境实际干预结合。迁移 A：Original Problem 长时视频 Agent 只有终点 reward → Mechanism backward graph credit → Question 视觉关键帧选择的 RL 能否用 cross-modal attention 作为辅助 credit？Modification 将视频 frame/token cluster 视为 step，AA/AO 改为 action→frame dependency，依视觉答案的 verifier score 给 shaped reward → Minimum Experiment Qwen2.5-VL-7B + Video-MME 小规模 200 段、每段固定 8/16/32 帧预算，比较 terminal-only、uniform shaping、attention shaping、oracle-frame，记录 answer accuracy、frame tokens、GPU milliseconds、embedding attention entropy、随机种子 3 次。风险为 attention 与真实证据不一致，collision 需查 frame-attribution 和 video-RL 论文。迁移 B：Original Problem Multi-Agent message 的最终 reward 难以分摊 → Mechanism message-level dependency graph + signed allocation → Question 是否能辨识可靠协作消息？Modification 把 AA/AO 转成 agent-to-agent/agent-to-tool 图，并加入 counterfactual masking audit → Minimum Experiment 在 100 个 AutoGen/τ³-Banking 风格多代理任务上，模型 Qwen3-4B，baseline terminal-only、equal message reward、Shapley 近似（高成本）、attention routing，报告 task success、replay counterfactual agreement、messages/任务、每项 GPU seconds；风险是工具状态不可逆导致 counterfactual 不可复现。

方向矩阵、Attack/Verification 与十句话记住

RL 状态：历史任务/观察；动作：工具调用或回答；策略：actor；终点奖励：ALFWorld binary、WebShop/ScienceWorld normalized official score；额外奖励：基于 step attention 与 outcome sign 的 shaped signals；优势函数：GAE 依修改后的 reward；KL/entropy：仍按 PPO 训练配置控制，没有提出新的全局 KL 理论。训练效率：作者称无额外环境 rollout、无独立 PRM，但逐层抓取 Q/K 与 attention 聚合并非完全无计算/显存开销；需要 profiler 检测。Verification Lens：把“提到错误观察多次”作为 red-team data，测试 reward 是否错误偏向恶意步骤；对每个 step 进行替换/遮盖并重新执行，在 outcome 改变与 p_k 相关程度上设 causal alignment metric；观察长 horizon 和不同 agent topology 下的偏差。十句记忆：一，终点奖励不能直接告诉哪个动作有贡献。二，AttnSR 借助 actor replay 的注意力。三，先建 step graph 再从终点回溯。四，用 ρ=0.85 降低长路径贡献。五，负的 recency correction 对冲近因偏差。六，多层几何平均降低单层噪声。七，最终奖励正负由相对 outcome 决定。八，ALFWorld 获益明确，WebShop 分数是反例。九，attention 不是因果证据。十，最值得研究的是用环境干预校准 attention credit。

进一步审计注意力信号的可靠性

Transformer attention 的数值大小依赖 Query、Key 表征、softmax 温度、位置编码以及文本 tokenization。一个后续动作高度关注早期观察，可能因为它确实利用了关键事实，也可能只是因为错误信息被重复引用，或某个指令恰好包含固定格式的关键 token。AttnSR 将 token attention 聚合到步级图，避免用单个 token 的峰值定义重要性，但聚合后的图仍是“模型内部读了什么”的证据，不是“若没有此步结果会改变多少”的证据。跨层几何平均可以抑制偶然单层高权重，代价是如果某条真正关键的信息只在一两个层显著出现，它可能被过度削弱。负的 recency 修正也有同样的张力：一般模型更关注近期历史值得校正，但真实任务常常由最后一两步决定成败。以 ALFWorld 为例，最关键的一步可能是最后放置物体的动作；若模型过度扣除临近奖励，最终的归因也未必更准。可复现时应对 recency weight、hop decay 和 layer subset 做有交叉项的网格，而不是每次只动一个参数就宣称机制可靠。更高强度的评估还需随机打乱无关 observation 文本并保持真正环境状态不变，观察 attribution 是否受到文本长度影响。这类 probe 能检验伪相关，但若没有可控环境状态重放，仍不能被称为严格因果识别。

针对 WebShop 负结果的具体研究路线

WebShop 最有启发性的异常是 success 从 40.20% 轻微增到 41.00%，而连续官方 score 从 70.74% 降到 69.71%。这两个指标不矛盾：Agent 可能更常满足成功阈值，却在商品特征、预算、偏好匹配的细节上失分；也可能由于任务随机性与训练不一致造成差异。应该首先从 task-level paired score difference 看每一任务的增减，而不是仅看两个总体均值。建议在 500 个匹配任务上输出一个矩阵：基础 PPO score、AttnSR score、是否成功、实际点击步数、是否触发 tool error、每步 shaping reward；再把任务按 short/long trajectory 和属性检索难度划分。若损失集中在短轨迹，可能说明过程 credit 不适合强阈值任务；若损失集中在高复杂度属性匹配，可能是跨轮 attention 长路径把无关商品属性奖励放大。下一步使用 outcome reward 的连续差值代替单纯 success 标志验证此问题。对于攻击者，还可以在网页描述中大量重复与目标商品无关的字段，诱导 attention-based graph 更关注错误网页消息。这会把 reward shaping 变成可以被外部文本主动操控的训练过程。该测试比只看 ALFWorld 成功率更能判断新算法适合真实浏览器 Agent 的程度。

为什么更强 baseline 不一定是最高数字的那一行

论文中 strongest baseline 可以有两个含义。一是最公平的受控 baseline：相同 Qwen2.5-7B 主干、同一 PPO 训练预算、只改 reward shaping，这应当是 PPO。二是最难超过的历史基线：TARL 的 96.72% 成功率距离 AttnSR 的 97.08% 仅一个任务。把两者混用会产生两个误判：将 AttnSR 对 PPO 的 +5.84pp 归结为整个领域的领先优势，或者因为仅领先 TARL 一题就否认它在 reward credit allocation 的机制价值。研究报告应先说明“机制归因比较”与“性能榜单比较”分别要回答什么问题；在前者固定训练成本，在后者充分列出计算预算差异和数据条件。若复现只做 274 题一次运行，应避免宣称普适最优；建议至少重复 3 个训练种子，并分析该多出的一个成功是否稳定出现。对模型内部图结构，最好增加 step-level 消融替换的反事实代理，以避免 attention 对中间步骤给出的 high credit 只是对 token 共现的偏好。

进一步的统计审计与下一步实验

一个论文把成功数量从 250/274 提升到 266/274，直观很重要，但如果要研究其在真实在线 Agent 上的价值，还需要查看“哪些任务由失败变成功、哪些原成功变失败”。可以要求输出完全配对的任务清单和 per-task reward shaping heatmap，然后根据步骤长度与观察文本长度分组，检验 attention graph 的优势是不是集中于长步骤与高 token 数的任务。对于 WebShop 的连续官方分数下降，应优先检查失败任务是否存在错误商品属性、无效终止或重复工具调用；如果 score 下降集中于成功阈值附近，仅汇报 success 可能夸大奖励设计的好处。这样做能把结果从一张 aggregate table 转成真正可以证伪的机制诊断，也为 Agent 安全研究提供更有价值的攻击目标。另需逐项统计少数异常长轨迹，避免总体均值遮盖单次失败后的高额恢复成本与重复调用风险。

如何阅读负面证据：与实际部署的距离

对 RL / Agent 论文的严肃判断，应把“作者的局部证明”“论文评估的运行环境”“实际希望部署的工作负载”分成三层。第一层可以按原文复核：公式对象是否与源码一致？对照组是否只改变一个设计因素？指标是否由同一测试集产生？第二层要看成本口径：一次成功对应多少推理 token、工具调用、设备显存和平均服务时间；任务越长，长尾波动和异常轨迹越不能被一个均值藏起来。第三层要看可迁移性：如果软件版本、模型架构、输入长度、采样温度、缓存命中率或任务难度发生变化，哪些机制假设首先失效？这不是对作者工作的否定，而是把研究结果变成可以预测、被证伪的工程假说。阅读时应主动寻找最不支持作者标题的一组设置，将其和最佳设置放在同一页，而不是只汇总 headline number。尤其要区分百分比提升、百分点提升、相对速度比和每项任务实际新增的成功数；小样本上仅一个任务的差距不应被包装成普适最优。

实验目录建议拆成 configs/base.yaml、configs/proposed.yaml、configs/ablation_*.yaml、datasets/task_ids.json、scripts/run_eval.py、scripts/aggregate.py、artifacts/trajectories 与 artifacts/profiles。每次运行保存 paper id、commit SHA、模型 checkpoint hash、tokenizer、硬件、精度、显存预算、随机种子、dataset split、原始模型输出以及工具日志。run_eval 负责不修改结果地完成任务，aggregate 才负责计算 mean/std、pass@k、耗时分位数以及 success/cost 的 Pareto 曲线。需要为不可逆调用准备 mock 环境和回滚机制，避免复现实验影响真实资源。对缓存和推理实验，另存 kernel event trace、host-device bytes、miss ratio、batch size、TTFT、TPOT、end-to-end wall-clock；对 RL/Agent 实验，另存 step reward、优势函数、KL、trajectory 成败、每步状态和动作。不要只保存论文中的最终表格，因为只留下最终表格很难在发现异常后重建成败任务的具体来源。对照组应使用相同 wall-clock/token budget 或明确报告预算不一致，避免以更高训练成本购买更高分。

跨研究方向思考：何处可能发生 Collision

最有潜力的组合研究不是简单把两篇方法堆在一个模型上，而是重新定义“边际收益”的可检验含义。对 RL，边际收益可能指一次动作把最终成功率提高多少；对 Agent memory，边际收益是某条历史信息让之后多少真实任务摆脱错误；对 Video acceleration，边际收益是额外保留一帧/一组 token 对答案或视频质量的改善；对 Inference systems，边际收益则是一个 KV 缓存块减少了多少昂贵设备传输与等待。四种收益的共同点是它们依赖使用场景和预算，因此最值得尝试的泛化框架是“预算约束下的后验价值估计 + 可验证的回退机制”。但这些价值不是相同量纲，不能因为都叫 utility 就直接使用一条 loss；需要分别建立任务成功率、服务时延、成本和回归风险的校准曲线。若要主张新的 benchmark，必须先证明原有指标在任务换位、预算改变或分布偏移时会给出错误的排序；若要主张新方法，必须给出在相同预算下的稳定收益和至少一个明确失败案例。

一句话定位与核心观察

这篇工作不急着提出一个更复杂的 RL loss，而是先问一个研究领域长期回避的基本问题：多轮 Agent RL 到底提升了“每一步做得更好”，还是提升了“允许多次尝试时能够纠错和坚持”？论文把测试预算拆成采样宽度 K（独立尝试多少条 trajectory）与交互深度 T（每条轨迹允许多少轮工具交互），用 Pass@(K,T) 画出能力曲面；发现 RL 在充足交互预算下往往明显更强，约束 T 时优势缩小，在部分任务甚至反转。并且，固定状态下检查一步动作好坏时，RL 模型不稳定地优于 base，真正收益更多来自错误恢复、后期轨迹稳定性。针对这个错位，作者提出 BudgetMix RL，在训练阶段给出不同交互上限，使策略不把冗长重试当作唯一成功模式。核心价值在于替代“一个 Pass@1 的数就是 Agent 变强”这种单轴评价，为 Agent RL 部署提供预算鲁棒性指标。与重新训练一套模型相比，这篇特别值得作为 benchmark/verification 思路精读。

Background：为何 trajectory success 会误导

传统 RLVR/GRPO/PPO 工作常以任务完成率展示改进：给 Agent 足够多轮，它能反复查看文件、执行测试、修复错误，最后通过 verifier，就算最终成功。现实工具环境却可能对每次浏览器动作收费、对 API 请求限流、对数据库操作不可逆。在严格 T=2 的任务中，首次动作选错就失去机会；在 T=20 的任务中，Agent 可能先走十个弯路再找到正确路径。两个 Agent 即使在 T=20 的成功率分别是 70% 和 80%，在 T=2 也可能是 60% 和 50%。如果只看宽松设置，研究会把“更会重试”误认为“每步决策更准”。单轮推理的 Pass@K 是不同 sampling 宽度的成功概率，在交互环境里还必须显式给 T。论文因此同时测 action-quality 与 trajectory-level 的两种能力；这对 Agent curriculum、reward/credit 设计与评估特别关键。代表 baseline 包含未训练的 Base、全预算 GRPO/PPO/GiGPO、过程监督对照、以及作者 BudgetMix 方案。

数学对象：Pass@(K,T) 和局部动作解释

令任务 x~D，历史 h_t=(x,o_1,a_1,…,o_{t-1},a_{t-1})，策略 πθ(a_t|h_t)，环境反馈 o_{t+1}~P(·|h_t,a_t)，轨迹 τ_≤T 最长 T 轮，终局 verifier 给 R(τ_≤T)。固定 T 后多次独立采样 K 条 trajectory，Pass@(K,T) 表示 K 条里至少有一条成功的任务比例；当单次成功概率为 p 且多条独立同分布时，可直觉化为 1−(1−p)^K，但实际系统因环境和采样依赖未必完全满足这个近似。K 只增加采样尝试的数量，T 改变单个尝试内部深度，两者带来完全不同的推理成本与安全风险。作者进一步记录 ActionNLL_B(a_t|h_t)=−Σ_j log p_B(w_t,j|h_t,w_t,<j)，观察某条 RL action 是否在 Base 眼中离谱；又用累计 LLR_1:t=Σ_i[logπ_RL(r_i|h_i)−logπ_B(r_i|h_i)]，分析从整个多轮轨迹看两个 policy 的偏好如何变化。局部动作在 base 下不惊奇而全路径在 RL 下更可能，说明 RL 可能学会更稳定地组合已有能力而非生成全新单步动作。这里只能给出机制一致的解释，不能直接证明优化动力学唯一因果。

BudgetMix Method：从训练输入到策略

输入同样的任务与交互式环境 → 按训练迭代/episode 分配不同 max-turn budget → rollout 在分配的 T 上限内终止 → verifier 对完成任务给二值/数值 reward → 沿原 GRPO/PPO/GiGPO 等策略更新 → 在多种 T 的混合经验上学习 → 评估阶段固定同一组 K、T 网格。关键不是对每条轨迹无限延长，而是允许模型同时体验紧约束和宽松约束，减少依赖“先错后修”的路径。全预算训练只针对 T_max 优化，模型可能将成功概率寄托在允许较多动作的后期；混合预算引入对短轨迹决策的隐性约束。BudgetMix 的奖励仍依靠任务终点 verifier，论文没有声称它完全解决 credit assignment；它解决的是训练与部署预算分布不匹配。算法作为外层 sampling/curriculum 可以叠加在不同 policy optimizer 上，这是工程上容易落地、理论上还需检验最优混合分布的设计。一个关键可控超参就是 T 集合与采样概率：短预算过多会使真正需要多阶段交互的难任务得不到成功信号，宽预算过多则重新出现原来的预算依赖。

Toy Example：同一 Agent 在两种预算下排名反转

考虑文件修复 Agent：第 1 步读栈错误、第 2 步定位模块、第 3 步修改并测试、第 4 步失败后修正、第 5 步最终通过。Base 模型可能第 3 步就做出较高质量 patch，代价是遇到困难时不会恢复；RL 模型可能第 2 步选错模块，但第 4、5 步通过 verifier 提供的反馈纠正。若生产环境允许 5 步，RL 的高最终成功值得肯定；若受 token、时间或外部 API 限制最多 3 步，Base 反倒可能更实用。让每条训练 rollout 的预算有时为 3、有时为 5，BudgetMix 迫使 RL 学习更节制的早期动作，同时保留必要的回退能力。这是为了讲清预算混合机制的教学例子，不是论文给出的源码轨迹。更严格的验证要把同一初态的两个策略 action 排名和错误后恢复轨迹分开记录，不能从终点总分直接归因于动作质量。

Experimental Setup、Baseline 与 Research Question

论文的实证涵盖 FrozenLake、DeepCoder-MT、BFCL-v3、InterCode-SQL，报告了 Qwen3-4B 与 Qwen3-8B 的任务格；训练对照 GRPO Full/BudgetMix、GiGPO Full/BudgetMix、PPO Full/BudgetMix 和 Base，不同任务 T_max 分别可能是 70、10、24、10，具体见 Table 1；请勿跨任务将 25% T_max 当成同样的绝对步数。RQ1：给 K 更多样本后 RL 能否扩大经验成功边界？RQ2：在固定 K 下缩减 T 时成功率是否仍保持领先？RQ3：在同样状态下 RL 下一步动作更好吗？RQ4：如果局部 action quality 不变，RL 轨迹为何更强？RQ5：混合训练 T 是否缓解缺点？指标 Pass@K 是 best-of-K；Pass@T 描述不同交互深度；Pass@(K,T) 是二维成功概率；原始 action NLL 是概率模型给出的惊奇度而非正确性；LLR 是两个 policy 相对偏好而非真实行为效用。每个指标要与任务终点 verifier、步数、成本一起读，不能以 log-likelihood 差大就宣称更好。

Claim vs Evidence、限制与 failure propagation

Authors Claim：Agentic RL 的许多增益源于长程纠错而非每步更优，BudgetMix 缓解跨预算部署风险。Evidence：四任务×两 backbone、不同 policy optimizer 的 Pass@T 结果与 action likelihood/trajectory 分析，支持“预算敏感性”在所测范围普遍存在。Not Proven：长程纠错是所有模型改进的唯一来源，或者 BudgetMix 在无 verifier、部分可观察、不可逆真实世界操作中必然更安全。贡献类型：New Metric/Protocol Pass@(K,T)；New Empirical Finding 轨迹与单步能力不等价；New Engineering/Training Strategy BudgetMix；不是首创 PPO 或一种新 critic。Failure modes：严格预算训练可能过早终止长期规划；训练和测试环境轮次数定义不一致；Pass@K 可能因高采样成本不可部署；Action NLL 受 tokenization 和动作长短影响；LLR 受 policy temperature、response encoding 等影响。长期任务中的失败会传播到工具环境状态及随后 Agent memory：错误首次修改在 T 大时能被撤销，在不可逆数据库操作里却是永久污染。评估必须包括 unsafe action 次数、状态恢复率和修复成本，而不只最终 verifier 成功。

Reproduction、Research Value、迁移与十句话记住

最小复现用 Qwen3-4B 的四任务里先选 DeepCoder-MT 与 BFCL-v3，使用固定 Base checkpoint 和环境随机种子，分训练预算 Full Tmax 与 BudgetMix {0.25,0.5,0.75,1}Tmax（混合方式按原文/实现设置），使用相同优化器、rollout token budget 与 optimizer step 数。测试对每个任务进行 K∈{1,2,4,8} 和 T∈{25%,50%,75%,100%} 的矩阵，记录 Pass@(K,T)、实际交互次数、wall-clock、token cost、action exact-match、失败后恢复比例。把训练中每个预算组的样本数与 reward 分布画成图，防止 BudgetMix 因总训练 tokens 更多而出现公平性缺陷。Research Value：极强的 Evaluation/Benchmark Potential；Baseline Potential 适合任何 agent training；Attack Potential 可通过 budget shock 测策略脆弱性；New Paper Potential 体现在按任务风险、可逆性定义自适应训练预算。迁移 A：Original Problem 工具 Agent 只被宽松 T 评价 → Mechanism Pass@(K,T) → Question Video Agent 帧访问次数/视频 token 预算的受限正确性是否相似？Modification T 视为 frame retrieval 或 video tool-call budget → Minimum Experiment 在 200 条 Video-MME/LongVideoBench 题上，模型 Qwen2.5-VL-7B，每任务允许 2/4/8/16 次检索，K=1/2/4，比较 fixed frame、adaptive sampling、RL-trained retrieval，记录 accuracy、latency、GPU tokens、failure-recovery；风险是“多轮次数”与“视觉信息量”并非严格同构。迁移 B：Original Problem 终点成功掩盖危险早期动作 → Mechanism budget-conditioned policy evaluation → Question 能否训练拒绝不必要危险工具调用的 policy？Modification 在 reward 附加 irreversible action penalty，并在任务 rollout 中随机施加 T 与 api-cost 限制 → Minimum Experiment：用 BFCL-v3 + 100 个构造的可回滚 SQL 任务，在 Qwen3-4B 中比较 Full PPO、BudgetMix、RiskMix；报告 Pass@(1,T)、unsafe write frequency、rollback success、cost-per-success；风险在 reward hacking 和模拟环境与真实风险鸿沟；Collision Risk 与 safe agent RL、cost-aware curriculum 需查新。十句记忆：一，轨迹通过率不等于单步能力。二，交互预算 T 是 Agent 特有的重要维度。三，采样宽度 K 也是成本。四，Pass@(K,T) 将两个轴分开。五，多轮 RL 的收益经常需要更大的 T。六，紧预算可能让排名反转。七，RL 可能主要改善错误恢复。八，局部 action NLL 并不等同正确性。九，BudgetMix 可降低训练/部署预算错位。十，部署前必须报告成功率—预算—危险动作三者的联合曲线。

BudgetMix 评估的公平性：什么叫同样成本

一个常见陷阱是把 BudgetMix 与 Full RL 对比时只固定“episode 数”，没有固定真实模型 token、工具调用和环境执行成本。短预算 rollout 可能更快结束，允许同样 wall-clock 内执行更多轨迹；也可能更难获得正奖励，使有效样本更少。若研究目标是提升 sample efficiency，必须同时报告每个设置的总 rollout 数、有效训练 token、成功 verifier 数、优化步数和设备时间；否则即使表 1 有明确成功率优势，也还不能宣称在完全等量资源下的学习效率提升。另一个问题是 T 的语义：FrozenLake 的一次交互与 DeepCoder-MT 的一次代码工具调用在 wall-clock 和潜在副作用方面差异巨大，因此 25% T_max 更像一种“任务内部预算归一化”，不是跨任务真实能耗归一化。部署时应该进一步将 T 改造为多维预算：环境动作数、API 价格、累计输入输出 token、端到端时间、不可逆修改次数分别计约束。这样可能出现两条成功率相同的轨迹，一条工具调用更多但更便宜，另一条调用少却消耗巨额 prefill，简单 step count 无法排序。这个缺口可能形成比单纯改 GRPO objective 更有迁移价值的系统与评测工作。

错误恢复能力的因果验证：不只看轨迹 likelihood

论文提到 RL 的优势在较晚的交互阶段和出错状态中更显著。要把它转化为能发表的新证据，应设计两个控制实验：一是 fixed-state action evaluation，选一批由 Base 与 RL 都遇到的相同历史状态，比较两个模型的下一动作是否使环境朝更好的状态发展；二是 controlled intervention recovery，给两个模型同样一个事先注入的错误状态，例如错误仓库文件、缺失的 browser element 或错误 SQL 查询结果，测它们在给定 T 内纠错的速度、成功率和额外风险。这样就能减少“RL 模型只是经历了不同状态分布”的混淆。若 RL 在固定正确状态并不比 Base 强，在错误状态恢复明显更强，可以更坚实地支持“恢复能力主导”解释。对于长程工具使用，还要区分失败后的正确回退与盲目重复：两者都会增加 step 数，但前者可能降低成本，后者可能进一步污染环境。建议将 recovery 分成 DetectError、FormRepairPlan、ExecuteRollback、VerifyOutcome 四个阶段，分别计算成功率和危险动作率。结合轨迹 likelihood，还可观察低 NLL 动作在失败后是否更容易组成高成功概率的恢复链，而不只是高频率“多试几次”。

复现实验的四种常见混淆与排除方法

第一种混淆是多轮环境的状态依赖：在同一初态下两个模型第一步不同，随后遭遇的状态分布也不同，所以简单平均每步 reward 不是对等比较。应将固定历史状态的 next-action 测试与自由 rollout 分开。第二种混淆是预算定义：不同任务一次工具调用的耗时和 token 量不同，必须同时报告步骤数和真实计算成本。第三种混淆是验证器质量：如果终局 reward 容易被无效终止或投机式工具调用骗取，BudgetMix 的成功率提高不一定意味着用户目标更好满足；至少对一部分轨迹做独立检查。第四种混淆是测试尝试次数：高 K 可以放大一个很低的 p，离线 Pass@K 因此不是单次部署通过率。建议把最终主图固定为横轴 T/Tmax、不同 K 曲线、纵轴 pass rate，并在右侧同时显示每个点的实际成本与 failure-recovery rate。这样即使两个方法在 full budget 打平，也可能清晰看出谁在严格的现实约束下更值得投入。

补充：部署判断与能力曲面的决策意义

Pass@(K,T) 是一个离线评估曲面，不是生产系统的单一最优运行策略。真正上线时应指定预算和成本约束，先判断每种策略在该可行域的成功率；随后比较谁在相同成本下完成得更快、谁更容易安全退出，不能只选择最大 T 的最高分。尤其对于需要付费外部工具和不可逆写入的 Agent，扩大 K 或 T 均可能引入更多风险。BudgetMix 的贡献是训练模型对这种预算变化不那么敏感，但它没有替部署者决定最恰当的预算。未来可以把任务难度估计、预算选择和风险门控联成一个新的决策器，前提是使用独立任务分布测试，防止优化曲面本身被训练数据泄漏污染。

如何阅读负面证据：与实际部署的距离

对 RL / Agent Evaluation 论文的严肃判断，应把“作者的局部证明”“论文评估的运行环境”“实际希望部署的工作负载”分成三层。第一层可以按原文复核：公式对象是否与源码一致？对照组是否只改变一个设计因素？指标是否由同一测试集产生？第二层要看成本口径：一次成功对应多少推理 token、工具调用、设备显存和平均服务时间；任务越长，长尾波动和异常轨迹越不能被一个均值藏起来。第三层要看可迁移性：如果软件版本、模型架构、输入长度、采样温度、缓存命中率或任务难度发生变化，哪些机制假设首先失效？这不是对作者工作的否定，而是把研究结果变成可以预测、被证伪的工程假说。阅读时应主动寻找最不支持作者标题的一组设置，将其和最佳设置放在同一页，而不是只汇总 headline number。尤其要区分百分比提升、百分点提升、相对速度比和每项任务实际新增的成功数；小样本上仅一个任务的差距不应被包装成普适最优。

可复现实验脚本的最小组织结构

实验目录建议拆成 configs/base.yaml、configs/proposed.yaml、configs/ablation_*.yaml、datasets/task_ids.json、scripts/run_eval.py、scripts/aggregate.py、artifacts/trajectories 与 artifacts/profiles。每次运行保存 paper id、commit SHA、模型 checkpoint hash、tokenizer、硬件、精度、显存预算、随机种子、dataset split、原始模型输出以及工具日志。run_eval 负责不修改结果地完成任务，aggregate 才负责计算 mean/std、pass@k、耗时分位数以及 success/cost 的 Pareto 曲线。需要为不可逆调用准备 mock 环境和回滚机制，避免复现实验影响真实资源。对缓存和推理实验，另存 kernel event trace、host-device bytes、miss ratio、batch size、TTFT、TPOT、end-to-end wall-clock；对 RL/Agent 实验，另存 step reward、优势函数、KL、trajectory 成败、每步状态和动作。不要只保存论文中的最终表格，因为只留下最终表格很难在发现异常后重建成败任务的具体来源。对照组应使用相同 wall-clock/token budget 或明确报告预算不一致，避免以更高训练成本购买更高分。

跨研究方向思考：何处可能发生 Collision

最有潜力的组合研究不是简单把两篇方法堆在一个模型上，而是重新定义“边际收益”的可检验含义。对 RL，边际收益可能指一次动作把最终成功率提高多少；对 Agent memory，边际收益是某条历史信息让之后多少真实任务摆脱错误；对 Video acceleration，边际收益是额外保留一帧/一组 token 对答案或视频质量的改善；对 Inference systems，边际收益则是一个 KV 缓存块减少了多少昂贵设备传输与等待。四种收益的共同点是它们依赖使用场景和预算，因此最值得尝试的泛化框架是“预算约束下的后验价值估计 + 可验证的回退机制”。但这些价值不是相同量纲，不能因为都叫 utility 就直接使用一条 loss；需要分别建立任务成功率、服务时延、成本和回归风险的校准曲线。若要主张新的 benchmark，必须先证明原有指标在任务换位、预算改变或分布偏移时会给出错误的排序；若要主张新方法，必须给出在相同预算下的稳定收益和至少一个明确失败案例。

Cross-Paper Synthesis / Research Opportunities

共同趋势：AttnSR 与 Rethinking Agentic RL 分别从“训练的信用怎样发给步骤”和“最后成功到底由哪些能力驱动”指出终点分数不够。AttnSR 观察到步骤注意力可提供训练先验，但并非因果；预算研究发现长期纠错会掩盖早期动作欠佳。组合机会：用 Pass@(K,T) 的 tight-budget 曲面检验 attention-shaped reward 是否真的提高 first-step decision quality，而不仅仅是拉长或更熟练修复轨迹。最小组合设置是对齐同一 Agent 主干、同一 ALFWorld/BFCL 评估版本和相同 rollout 总预算，分别运行 terminal PPO、AttnSR、BudgetMix、AttnSR+BudgetMix，观察紧预算与全预算两端成功率、单步匹配、恢复率和错误工具调用。Collision 风险：现有 process reward/credit assignment 与 budget curriculum 已覆盖近似设计，真正的创新必须建立反事实步骤正确性与预算鲁棒性间的新证据。
