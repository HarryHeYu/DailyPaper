Paper 1 · What Drives the Zero-to-One Jump?

Rui Zhu, Yumou Liu, Zhenzhe Zheng, Fan Wu · Shanghai Jiao Tong University · arXiv:2611.02747v1, 2026-11-02 · EMNLP 2026 proceedings 41504–41520（arXiv 记录） · 17 页 · Code: Z2O

一句话定位与人话版

这篇工作把数学推理 RL 中“所有答案都错”的困难题从没有训练信号的死区，变成可以根据错误轨迹内部不确定性施加差异化更新的区域。

想象一个模型对某道 AIME 题每次都算错。传统 GRPO 在同题的八条 rollout 全错时，组内奖励都相同，标准化优势接近零；模型几乎无法从这道题学到东西。作者观察到，不同错误解法的开头仍有不同程度的选择空间：一些早期 token 分布更不确定，随后反而更可能出现首次正确解。于是 NAPO 先算每条错误轨迹前 20% token 的局部困惑度相对整条轨迹的比例，再把高分轨迹赋予更强负优势，抑制错误路径而促使策略改变。与 GRPO 相比，AIME24 的 Pass@256 从 70.00% 到 80.00%，AIME2025 从 46.67% 到 53.33%。这不是“奖励模型变聪明”，而是重新利用本来没有梯度的错误样本；是否能推广到工具调用、非二值 reward 仍是开放问题。

Background & Research Gap：为什么全负组难学

RLVR 让模型对一个可验证的问题生成 G 条候选推理，用最终答案的正确性赋予二值 reward，再做 policy gradient。GRPO 用组内平均值和标准差计算 advantage，避免额外 value model。对于“有一条正确、七条错误”的组，正确样本有正优势，错误样本有负优势；但对于“八条都错误”的组，reward 的方差为零，优势无法区分不同错误。

这形成一个很特殊的优化盲点：越难的题越容易被完全跳过，而模型需要恰恰在这些题上探索。仅仅增加 rollout 数量可以偶然采到正解，但开销昂贵；简单地把所有错误统一惩罚，会同时压制有希望的探索与无效的死胡同。

具体例子：题目要求组合计数。八条解法都错，其中 A 在第一步尝试两种合理的划分方式，B 从第一步就固定错误的计数公式。二者最终 reward 同为 0，但作为下一次训练的素材并不等价。本文的 gap 是用模型自身可观测的 token 分布，给全负组构造有区别、无需新增 verifier 的学习信号。

Core Insight：时间位置比绝对熵更重要

作者先固定训练 batch，观察相同 prompt 在若干步内由全负变为至少一正的 N→P 事件，并定义 TTFP（Time To First Positive）衡量首次成功时间。然后对后来发生 N→P 的题与始终 N→N 的题回看此前的错误 rollout，发现前者在生成开头保留更高的不确定性，后段差异收敛。

这不是“高熵必然更好”的因果定理，而是两种训练 continuation 与同批负样本上的经验相关性。绝对平均熵还会被回答长度、后段重复文字影响，因此作者采用早段相对全段的比值；在候选 α=0.1、0.2、0.5 中，0.2 的区分与训练效果更稳。

作者用 token Fisher trace 提供可塑性解释：概率分布越不集中，局部梯度通常越有调整空间。但 Fisher trace 与 Shannon entropy 不相等，而且“可调整”不等于“更接近正确”，所以该机制应理解为可检验的启发式 credit assignment，而非证明错误解法具备正确性潜能。

Method Deep Dive

Input: prompt x + G rollout yᵢ + binary reward rᵢ + token logits → compute early branching driver dᵢ → check whether group has a positive → normalize dᵢ → assign Aᵢ → GRPO clipped policy update → next policy

Step 1–2：rollout、token entropy 与早段 driver

对每个 prompt 采样 G=8 条 rollout，verifier 给每条最终答案二值奖励。记录 old policy 生成时的 next-token 概率，不另跑一个 reward model。对每个有效位置，先截取 top-k（论文 k=20）概率并重新归一化，计算 H_t = −Σ_v p_t(v) log p_t(v)，再取 exp(H_t) 得到有效分支数。

令 T 为回答长度、Tα=ceil(αT)，定义 d = mean_{t≤Tα} exp(H_t) / mean_{t≤T} exp(H_t)。当 d>1，说明回答开头相对整条回答有更多选择分支。它不是正确概率，也不是“推理步重要性”标签，而是 token 分布的形状统计。

注意两类实现坑：top-k 之后必须重新归一化，否则熵尺度不对；EOS 与 padding 必须掩码，否则短输出的分母被污染。α 按有效生成 token 数计算，不应按固定最大长度。

Step 3–5：按组切换优势、裁剪更新

若一个 group 至少有一条正确 rollout，保持原始 GRPO 组内优势，不改变已经可学习的样本。若全负，先做 d̃ᵢ=(dᵢ−minⱼdⱼ)/(maxⱼdⱼ−minⱼdⱼ+ε)，然后设置 Aᵢ=−d̃ᵢ。此时 driver 最大的失败轨迹得到最强的负优势，driver 最小者几乎不更新。

训练仍最大化 clipped surrogate：min(ρᵢ,t Aᵢ, clip(ρᵢ,t,1−ε,1+ε) Aᵢ)，ρ 为当前与 old policy 的 token likelihood ratio。负优势意味着降低这条错误轨迹的概率，而不是把它当成正样本鼓励。它通过抑制有弹性的错误分支改变局部策略，期待下一轮探索转向更有用的解法。

KL 项 β·KL(πθ||πref) 在论文一般形式中约束远离参考策略；诊断固定批次实验报告 zero KL/entropy penalty。不要把这个设置误读为所有 RL 实验都强制同一 β。若一组 driver 完全相同，归一化后的优势趋近零；这是可预期的退化，而不是数值 bug。

核心公式与数学直觉

Hₜ = −Σᵥ pₜ(v) log pₜ(v)
d(y)=mean(exp(Hₜ), first αT tokens) / mean(exp(Hₜ), all T tokens)
Ãᵢ = (dᵢ−min d)/(max d−min d+ε)
Aᵢ = I[any success]·Aᵢᴳᴿᴾᴼ − I[all fail]·Ãᵢ
Tr(Fₜ)=1−Σᵥ pₜ(v)²

公式解释：objective、KL、Fisher 与超参数

熵 H 越大，概率越分散；exp(H) 可以直观理解为“等效有多少种候选 token”。比值 d 消除了部分整体不确定性的尺度差异，却无法消除回答风格和 tokenization 差异。α 决定“早期”窗口：太小会过分依赖格式性开头，太大会混入结论阶段。top-k 决定计算的分布支持集；太小压扁差异，太大增加统计噪声和实现开销。

GRPO 的目标是利用同题 reward 对比提高相对更好的答案概率；NAPO 在全负组时改变 advantage 的定义，实际上优化一种 driver-weighted negative sample suppression。它不是直接优化 Pass@k，也没有直接最大化 TTFP；二者只是外部评估。Fisher trace 的 1−Σp² 衡量分类分布对 logit 的局部敏感程度，高熵时往往更高，但并非单调等价，因此不能把 Fisher 解释当作对 NAPO 效果的充分证明。

Toy Example：八条全错时的实际计算

假设一个数学 prompt 生成四条错误轨迹（为便于手算用 G=4），其早段有效分支数平均值分别为 8、6、3、2，全段平均值分别为 4、4、3、2。于是 d 分别为 2.0、1.5、1.0、1.0。min=1、max=2，归一化 d̃ 为 1、0.5、0、0；最终 advantage 为 −1、−0.5、0、0。

传统 GRPO 因四条 reward 都为零，全部 advantage 约为零；NAPO 则对第一条错误轨迹的采样 token 施加更强负梯度，对第二条施加较弱负梯度，对其余两条基本不动。下一次采样如果策略转向另一条解题路线，可能产生首个正确答案；但也可能仅仅换成另一种错误。这正是要用 TTFP 与 Pass@k 检验的地方。

上述数字为教学构造，绝非论文实测。尤其要注意：所谓“高 driver 的错误轨迹更值得学习”并不表示正向模仿它；实际优化方向是降低其概率，释放策略分布的其他路径。

Baseline Deep Comparison：谁最强、差异在哪里

GRPO：同题分组标准化 reward，优势是无额外 critic、稳定且广泛使用；全负组无法提供差异梯度。本文最重要、最强的机制性 baseline 是 GRPO，因为它是 NAPO 的直接母算法，且在多个低 k 指标领先。

W-REINFORCE：对正负样本设置不同权重，避免完全依赖组内标准化；在难题中有时因强负更新损害正确概率。论文给正优势权重 0.5；它的弱点不是没有负反馈，而是缺少同组内部可塑性区分。

Uniform(−0.1)：全负组所有 rollout 给相同的小负优势，是最关键的消融对照。若它与 NAPO 相当，则新 driver 不必要；论文显示 NAPO 在 AIME24 Pass@8 高 27.28 个百分点，证明差异化优于这个特定常数控制。

Uniform(−1)：更强的统一负优势对照，能测试“仅仅负梯度强度不够”这一解释。论文单次评估报告 NAPO 在多个 benchmark 的 Pass@256 有较大优势，但不能把单次结果当成跨训练种子显著性。

NAPO05：不是外部 baseline，而是 α=0.5 的方法变体。它在 AMC23 和某些低 k 结果优于 NAPO02，说明最优窗口随难度与指标变化，不能只展示 AIME24 的优势。

Experiment Setup 与每组 Research Question

模型 Qwen2.5-Math-7B；训练集 DAPO-17k，训练一轮；每题每步 8 rollout；采样温度 1.0，最大上下文 4096，learning rate 1e−6（固定批次诊断设置）；使用 verl。评测 AMC23、AIME2025、AIME24、Math-Beyond，分别覆盖不同难度。Pass@k 从 1 到 256；训练过程用首次成功时间 TTFP 和累计解决题数衡量探索效率。

RQ1：全负组中的错误轨迹是否存在预测未来成功的可观测差异？作者固定 1024 道 DAPO-17k 题训练 10 步、每步 8 条，并在临界 checkpoint 上控制优化器和数据顺序，只改变采样随机性做 replay。

RQ2：driver 能否改善同预算下的探索？比较 NAPO 与 GRPO/W-REINFORCE 的 Pass@k、TTFP、累计 solved prompts。

RQ3：提升是否仅来自“给负样本一点梯度”？比较 Uniform(−0.1)、Uniform(−1)。RQ4：早段窗口是否重要？比较 α=0.1、0.2、0.5。RQ5：是否有系统开销？比较 advantage 计算时间与总训练步时。

Metrics 教学：Pass@k、TTFP、N→P 与时间开销

Pass@k 指一个问题采样 k 次至少一次正确的概率，越高越好。它反映候选覆盖能力，不等于单次答案可靠性；k 越大越可能掩盖单次输出质量。Pass@1 更接近一次性使用场景，Pass@256 更接近大预算搜索。

TTFP 是某题训练过程中首次采到正解的 checkpoint 序号，越小越好；永远未成功应作为右删失数据处理，不能随意丢掉。N→P 统计从上一轮全负到下一轮至少一正的题数，越多可能意味着突破更多，但也受 rollout 随机性影响。

训练额外开销需要分别看 advantage 计算子过程和端到端 wall-clock：一个子模块相对变慢 78% 不代表训练整体慢 78%。应同时报告 rollout、验证、反向传播耗时，避免只看 FLOPs。

① 最强结果：AIME24 Pass@256 80.00% 对 GRPO 70.00%，提高 10.00 点；与机制主张一致，说明大采样预算下覆盖更多困难题，但不能直接证明单次推理更可靠。

Ablation、Claim vs Evidence、Failure Modes

消融 α：0.2 对早期解题发现最有效，但 0.5 在 AMC23 某些指标更强；这表明早段比例不是普适常数。消融 Uniform：同等负梯度存在时 driver 排序仍有优势；但还需要随机排序、长度匹配排序、token-level entropy 直接排序和多训练种子才能证明早段 entropy 是唯一关键因素。

Authors Claim：早段不确定性可以诊断接近零到一跃迁的错误，并指导负样本更新。Experiments Actually Show：在数学二值验证、Qwen2.5-Math-7B、所测数据和固定预算下，driver 与后续成功关联，NAPO 在若干 Pass@k 和 TTFP 上优于基线。What Is Not Yet Proven：跨模型尺度、非数学领域、工具使用 reward、分布外攻击、独立训练种子稳定性。

作者局限：数学任务和 binary verifier 为主，部分反馈、主观奖励、长 horizon 未覆盖。额外局限：高熵可能来自困惑而非有效探索；min–max 对离群值敏感；回答前缀中的固定格式会污染 driver；负更新会损伤原本正确的高概率 token；Pass@256 高不等于部署中的单样本可靠性。

Contribution、Reproduction View 与 Research Value

Contribution 1 [New Empirical Finding]：定义并追踪 N→P、TTFP，展示零到一事件的训练动力学。Contribution 2 [New Metric / Protocol]：用 early mean-perplexity ratio 衡量错误轨迹开头的分支空间。Contribution 3 [New Objective]：把分级负优势插入 GRPO 全负组。新意在于信号与优势路由的组合；entropy、GRPO、min–max 本身均非新组件。

最小复现：固定 Qwen2.5-Math-7B、DAPO-17k 的一小批困难题；每题 G=8、T=1.0、max length=4096，使用 verl 的 GRPO trainer；在 rollout logits 处保存 top-20 entropy 的 token 标量；实现 group_all_negative、driver、minmax、advantage 四个函数；验证混合正负组与原 GRPO 完全一致。先跑 α=0.2 对 Uniform(−0.1)，记录 TTFP、Pass@1/8/256、训练 seed、GPU 小时。

最容易踩坑的是把负 advantage 当成正奖励、忘记 mask、误把 top-k 未归一化概率计算熵，以及每步保存全词表 logits 导致显存爆炸。Baseline Potential 高：可以作为 RLVR hard prompt 研究的标准对照。Migration Potential 高：同一信号可在 Agent rollout 或 verifier 失败的代码生成中测试。Systems Potential 中：几乎不增加 forward，但采集 token entropy 有实现成本。Attack Potential 中：可设计高熵无效前缀诱导训练。Evaluation Potential 高：TTFP 是训练过程诊断指标。Benchmark Potential 高：构建按零到一事件分层的题集。New Paper Potential 取决于跨域、因果干预和稳定性证明，不能只换一个 α。

Migration A：工具 Agent 的零成功轨迹学习

Original Problem：数学题全负组没有优势。Transferable Mechanism：按轨迹早段可塑性给失败样本分级负优势。New Research Question：工具调用失败的 trajectory 是否也存在可预测的 early branching signal？Method Modification：将 token 熵窗口限制在前两个工具决策前的 action tokens，并增加 tool-call validity mask；成功任务仍用 GRPO，失败组按 driver 负更新。

Minimum Experiment：在 WebShop 或 ALFWorld 选 300–500 个初始成功率低于 10% 的任务，固定一个可用的 3B/7B instruction policy 与环境版本；每任务 G=8，采集 2 个 seed × 500 更新步；保存 action-level logits、最终任务 success、tool error 类型。对照 GRPO、Uniform(−0.1)、随机 driver、NAPO 原始 token driver、action-only driver。

Model：Qwen2.5-7B-Instruct（建议实验模型，不是原论文配置）。Dataset：WebShop/ALFWorld（建议）。Baseline：GRPO + Uniform + shuffled driver。Metric：success@1/8、TTFP、invalid tool calls、rollout tokens、训练 wall-clock。Expected Contribution：识别 Agent 零成功阶段的可迁移 credit assignment。Risk：tool action 的 entropy 受 schema 约束，文本 entropy 可能不反映决策。Collision Risk：需检索 tool-use RL 的 hard-trajectory weighting 与 advantage shaping 先行工作。

Migration B：高熵诱导攻击与 reward hacking 审计

Original Problem：把高 driver 负轨迹作为更强的更新目标。Transferable Mechanism：训练依赖一个可由生成分布操纵的统计量。New Research Question：攻击者能否在不提高真实可解性的前提下，通过无意义高熵前缀改变 advantage 分配？Method Modification：在失败 rollout 的开头插入语义无关但分布高熵的等价表达或随机格式，并比较 driver 与最终正确率的变化。

Minimum Experiment：从 DAPO-17k 抽 500 题，固定原模型、G=8 和 3 个训练种子；构造 clean、格式扰动、随机同义开头三组，保持答案 verifier 与题意不变。先做离线 driver rank correlation，再训练 GRPO、NAPO 与 entropy-clipped NAPO；逐题记录 N→P、Pass@8、错误轨迹长度、无效 token 比例。

Model：Qwen2.5-Math-7B。Dataset：DAPO-17k 子集 + AIME24。Baseline：原 NAPO、GRPO、Uniform、random rank。Metric：driver inflation、rank flip、Pass@k、TTFP、clean-to-perturbed gap。Expected Contribution：为 entropy-driven RL 设计可重复的 robustness benchmark。Risk：文本前缀修改会改变模型真实推理分布，需保持控制条件。Collision Risk：与 entropy regularization、reward hacking 和 prompt perturbation 文献可能重叠。

方向专用 RL Formulation 与十句记忆

State：prompt 与已生成 prefix；Action：下一 token；Policy：πθ；Trajectory：完整推理序列；Reward：最终答案的规则验证，主要是稀疏二值；Advantage：有正例时组相对优势、全负时 −driver；Objective：clipped GRPO；KL/Entropy：论文分析一般形式给 KL，但诊断设置为零惩罚；Credit Assignment：将最终全负奖励拆成 rollout 级差异权重。Reward hacking 风险是模型可能学会改变输出熵形状而非推理能力。训练效率核心是相同 rollout budget 下更快出现首个正确答案，不能把这一点误写成 GPU FLOPs 大幅下降。

记住① 难题不是没有训练价值，而是组相对奖励没有对比。② TTFP 比最终准确率更直接观察第一次突破。③ N→P 之前的失败常保留前段不确定性。④ driver 是早段困惑度与全段困惑度之比。⑤ 全负组赋负优势，不是模仿失败。⑥ 混合组继续使用 GRPO。⑦ AIME24 Pass@256 增加 10 点。⑧ 低 k 在某些数据上会退化。⑨ Uniform 对照支持差异化权重的作用，但因果解释仍有限。⑩ 迁移 Agent 时应把 action entropy 与文本熵分开。

Paper 2 · Agent Memory as Rate-Limited Filtering

Tianhao Guo, Chongyao Guo · arXiv:2611.02361v1 · 2026-11-02 · 67 页 · Venue 未在 arXiv 记录中确认 · 官方代码链接未从已核查来源确认

一句话定位与人话版

这篇论文提出：对长期 Agent 来说，真正重要的记忆未必是保留尽可能多的历史文字，而是维护一个能回答未来决策问题的最小状态。

假设服务权限日志里先授予、后撤销、再重新授予，且不同管理员有不同优先级，授权还有到期时间。把几百条日志全部交给 LLM，它可能忘记哪个事件真正生效；仅检索包含“授权”的相关段落，也可能把过期许可当成当前状态。作者构建可执行的权限状态机，以一对只在关键事件顺序或字段上不同的历史检验读者，发现普通 7B–32B 模型读 256 条日志时接近随机水平，而给 reasoning 模型明确当前状态可达到 96%–98%。模型负责逐条解析、规则程序负责状态更新的混合 filter，在 256 事件下达到 80%–89%。关键贡献不是新的向量数据库，而是把 memory 视为递归状态估计，并把存储容量、状态大小、错误传播和读者能力放到可量化框架里。

Background & Research Gap：长上下文不等于长期状态

常见 Agent Memory 有三类：把历史截断或摘要成文本；将片段向量化后按相似度检索；维护一份模型自己反复重写的 ledger。它们都把问题描述为“保留哪些文本”，却未必回答“未来决策到底依赖哪些状态变量”。

例子：管理员 A（高优先级）撤销用户 U 对数据库 D 的写权限，随后管理员 B（低优先级）重新授予。如果只检索最近一句，模型会批准；如果执行明确的优先级 supersession rule，B 的授予应被忽略。再加入授权过期、组成员关系、维护窗口开关，当前状态取决于事件的时序与合法更新，而不是某句文字的语义相似度。

作者的研究 gap 是：何时一个有限状态足以替代全部历史？什么存储预算可以保持它？解析错误与更新错误分别如何传播？LLM 读者在多长历史之后会落后于显式状态？这使记忆研究从经验性摘要质量转向可执行、可证伪的系统问题。

Core Insight：write-time dependency selection

作者用递归过滤形式化 Agent Memory：给定当前状态 S_{t−1} 与新事件 O_t，通过更新规则 Φ 得到 S_t；未来 query 的答案仅依赖 S_t。对同一状态分量的旧事件，一旦被合法新事件覆盖，原始文字不必再保存。记忆空间因此与 tracked keys 数量有关，而不是线性依赖总历史长度。

关键在于“合法覆盖”。不是简单 last-write-wins：高优先级撤销可能阻止低优先级授予；某个事件可能因过期而失效；组权限与维护窗口会交叉作用。纯粹按 recency、embedding 相似度选择日志无法保证这些关系。

作者还把能力拆成两部分：LLM 从自然语言提取结构化事件，确定性规则负责更新状态。这样的分工不是让 LLM 完全退出系统，而是把最容易累积错误的跨时序逻辑移到可测试的程序中。

Method Deep Dive

Input: ordered log O₁...Oₜ → LLM parse each event → structured event eₜ → deterministic update Φ(Sₜ₋₁,eₜ) → compact state Sₜ → query q → reader / executable decision f(q,Sₜ)

Step 1：构造带 oracle 的可执行事件流

定义 principal 集 P、resource 集 R、group 集 G、来源优先级集合 [L]。一个 key κ=(p,r) 表示某主体对某资源的直接权限。事件包括 grant、withdraw、reconfirm、租期、加入/移出组、组对资源授权、维护窗口开关与无效事件。

作者的 ground truth 不是由另一个 LLM 打分，而是由 replay() 状态机逐事件计算。测试样本成对生成：背景和表面文字尽量保持一致，只交换决定性事件的顺序或一个关键字段，正确答案随之反转。这样可以压制“只看资源名字猜答案”的捷径，也可以把真实因果依赖限定在少数事件上。

实验核心是 balanced accuracy 而非普通准确率，因为 paired contrast 确保正负决策都被检查。若模型只凭关键词一律批准，在平衡数据上最多约 50%，不会因为类别比例获利。

Step 2：显式状态与优先级 supersession

论文的状态包含直接授权记录 d、组成员关系 μ、组对资源授权 γ、窗口要求 ν、窗口是否开放 ω。直接记录包含 grant/withdraw、来源 rank、有效截止时间。新直接事件仅在其 rank 不低于当前有效记录时覆盖，否则被忽略；已过期记录不再以原 rank 阻止后续事件。

最终批准的逻辑是：(当前直接 grant 有效，或者存在一个组成员关系与组授权链) 并且 (资源不要求窗口，或者窗口当前开放)。这是逻辑组合，不是把所有文本交给模型自由解释。

这里最容易混淆的细节是“被拒绝更新的事件”与“撤销权限的事件”：前者根本不应改变状态，后者如果来源 rank 足够高则必须写入一个阻止低 rank 覆盖的状态记录。只保存布尔是否批准，会丢失下一次更新所需的 rank 与截止时间。

Step 3：读者与写者分离

混合过滤器每条日志调用一次 parser，得到事件类型、key、rank、deadline 等结构化字段；确定性 updater 维护状态，最后将与 query 有关的状态以文本或紧凑格式交给 reader。这个架构允许分别测量 parse accuracy、update accuracy、read accuracy。

论文发现“让模型解析每条事件”比“让模型自己持续应用更新规则”可靠。后者把局部语言理解与长时序状态维护捆绑，错误会累积；前者至少使规则逻辑可测试、可复现。

这并不意味着解析错误完全无害：若关键 key 的 grant 被错解析，状态会错；但后续合法事件可能覆盖它。相反，错误解析 rank 可能把一个本应被拒绝的更新写入，影响后续多个事件。写路径必须有 schema validation、事件 ID、版本与审计记录。

Step 4：有限容量与不可逆遗忘

如果显式状态本身超过容量 C，filter 必须驱逐部分状态分量。作者区别“read-time projection”与“bounded recursive store”：前者背后仍有完整真状态，只让读者看一部分；后者真的删掉记录，后续更新只能基于剩余状态执行。两者容量数字相同，长期行为却不同。

例如删除了高 rank 的撤销记录，下一次低 rank 授予会被错误接受；这种错误不是下一次检索能轻易恢复的，因为信息已经在写时丢失。作者因此提出 retention time 由容量 C 与新状态分量插入率 λ 共同决定，量级约 C/λ。

这对实际 Agent 尤其重要：一个只缓存最近 50 条事件的系统和一个维护 50 个有效状态分量的系统，不是同一种 memory。前者按时间裁剪历史，后者按因果依赖压缩历史；但如果状态分量数超过 50，后者仍会出现可预测的不可逆遗忘。

核心公式与数学直觉

Sₜ = Φ(Sₜ₋₁, Oₜ)
f₍p,r₎(Sₜ) = [valid_direct_grant OR ∃g(member(p,g) AND group_grant(g,r))] AND [not_window_required OR window_open]
BA = (TPR + TNR) / 2
BA(f) ≈ 1/2 + [BA(1) − 1/2] · [1 − 2P̄ₑ(f)]
retention time ≈ C / λ

公式解释：状态充分性、最小状态与预测误差

递归式 S_t=Φ(S_{t−1},O_t) 是过滤器的定义：过去的所有信息都被归纳进当前状态。若对任意未来事件 continuation 和任意 query，两段历史给出相同答案，它们可以视为等价历史；论文将此与 Myhill–Nerode 等价类、causal state 联系起来，讨论最小可判别状态的大小。

BA 是 balanced accuracy，越高越好；它对正负类别各占一半的配对测试更合适，但无法单独反映模型置信度校准。AUC 用评分排序而非固定阈值，补充观察模型是否仍能区分批准与拒绝。

预测式中 f 表示保留的状态分量比例，P̄_e(f) 表示状态缺失导致的平均翻转概率，BA(1) 是读者看到完整状态时的准确率。其直觉是：当保留的信息与答案无关时，性能退到 0.5；随着正确依赖分量被保存，准确率从随机基线向完整状态读者靠近。它依赖读者在缺失状态下的行为假设，是被实验检验的模型，不是对所有 LLM 的无条件定理。

C/λ 是容量与新分量写入速率给出的时间尺度，不是精确适用于所有 eviction policy 的统一寿命公式；热点 key、LRU、随机驱逐、默认值压缩都会改变实际分布。

Toy Example：从六条日志更新到当前权限

设用户 Alice 要写数据库 DB，来源 A 的 rank=3，来源 B 的 rank=1。初始状态无授权。事件 1：A grant Alice→DB，有效到事件 10；状态 direct=(grant,3,10)，当前批准。事件 2：B withdraw，rank=1 小于 3，忽略；仍批准。事件 3：A withdraw，rank=3，覆盖为 (deny,3,∞)，当前拒绝。

事件 4：B grant，rank=1，被 rank=3 的撤销阻止，仍拒绝。事件 5：Alice 加入组 ops；事件 6：ops 获得 DB 组授权；此时即使 direct 是 deny，按照本文所定义的 OR 组合，组链可使权限成立（注意这是论文 benchmark 的规则，不是所有真实 ACL 的通用规则）。

事件 7：DB 设置需要 change window；事件 8：close(DB)，最终拒绝。假设 query 是“此刻 Alice 能否写 DB”，只需 direct、组成员、组授权、窗口要求与开关状态，不必再把八条原文交给读者。

反事实对：只把事件 8 改成 open(DB)，其他七条不变，最终答案翻转为批准。一个只凭“出现 grant 就批准”的模型会在两条历史上给同一答案，paired evaluation 能识别这种 shortcut。以上是根据论文状态规则构造的教学案例，非论文原始样本。

Baseline Deep Comparison：真正的 strongest baseline

Full-log reader：直接给 LLM 全部事件；优势是没有写路径解析错误、实现简单；缺点是长上下文中的顺序、覆盖和时效关系难追踪。它是检验“context window 能否替代 memory”的核心 baseline。

Relevance retrieval：按 query 相似度找相关日志；合理且部署方便，但相似性不等于因果依赖，尤其容易漏掉旧的高优先级撤销或维护窗口事件。

Model-kept ledger：让模型持续重写状态摘要；理论上可以压缩历史，但每步的逻辑错误会被后续摘要继承，尤其 rank 与过期条件难保证。

StateMem reimplementation 与 Mem0：属于已有 Agent memory 方案；论文报告混合 filter 在对应测试中领先，但必须按论文指定实现与 reader 判断，不应推广成对所有版本全面领先。

Dependency-selecting retriever：在 query 时检索真正决定当前状态的事件。它在第一领域 256 事件的测试中匹配 filter，是最强机制对照：说明优势关键是因果依赖选择，而不只是写时压缩。它可能需要 query-time 计算和对依赖关系的先验知识，不能把其结果与通用 embedding 检索混为一谈。

Experiment Setup：读者、事件、协议与 Research Questions

Benchmark 是程序生成的权限事件流，包含 grant/withdraw/reinstate/expiry/group/window，ground truth 由状态机 replay。配对样本只改决定性事件的顺序或字段；测试不同历史长度 8、16、64、256、512、1024 等，模型覆盖 7B–32B 的开源 instruction/reasoning 模型以及 120B reasoning 模型。已核实的具体读者包括 Qwen2.5-7B、Qwen2.5-14B-Instruct、phi-4 等；其余型号与具体配置请以论文实验表为准。

RQ1：完整历史是否随着事件数增加而失去决策状态？比较 full log 与 explicit state，报告 BA、AUC。RQ2：正确写时状态能否抵抗长度增加？比较 oracle state、model parse + rule update、model-applied update。RQ3：状态容量不够时能否预测性能下降？比较 read-time projection 与真正 bounded store，在不同 K、T、C 和 eviction policy 下测 BA。RQ4：改写领域措辞后结果是否仍成立？论文有冻结协议的第二领域复制。RQ5：性能提升来自压缩还是 dependency selection？用 query-time oracle dependency retriever 做强对照。

实验不是常规真实世界在线 Agent 成功率测试，而是可执行合成决策环境；其优势是因果变量明确、可控且可预注册，局限是外部任务多样性有限。

Metrics 教学与统计陷阱

Balanced Accuracy = (敏感度 + 特异度)/2，0.5 在平衡二分类里近似随机，1.0 完美；它能避免总是预测多数类的假高分，但不能代替概率校准。AUC 是随机抽取一正一负时，模型给正例更高分的概率；越高越好，衡量排序，不能说明某个固定阈值可部署。

Horizon 是事件数，不是 token 数；不同事件措辞长度会改变总上下文，因此需要同时报告 token count。Reader-dependent horizon 是 full log 读者开始明显落后于显式状态的长度，随模型能力变化；不能说所有模型都有统一的 256 事件阈值。

State capacity 应以可解码的 component records 或 token 数报告；若只报 token budget，可能把“每个状态记录编码更短”误认为“推理更好”。Retention time 表示被保留状态分量在持续新事件下存活的时间尺度，越长通常越好，但可能以更多存储为代价。

Results Deep Dive：强项、弱项与替代解释

① 普通 7B–32B 模型读 8/16 个事件时 BA 在 72%–86%，到 256 事件跌到 48%–55%，意味着上下文窗口“装得下”不代表能正确维护状态。替代解释包括长输入位置偏置、指令遵循和模型读入格式，不全是纯记忆容量。

② Qwen2.5-14B-Instruct 的 BA 从 0.83 到 0.48，下降 0.35；AUC 从 0.85 到 0.53，说明不仅分类阈值漂移，排序能力也接近随机。

③ Reasoning 32B 读显式当前状态达到 96% 和 98%；说明当决策变量已经被正确整理，reader 能相对容易完成最终判断。仍不能证明同样模型能准确从原文自己更新状态。

④ 120B reasoning model 在 256、512、1024 事件时分别比状态读者低约 4、7、10 个百分点；大模型推迟失效 horizon，却不自动消除失效。

⑤ Model parse + deterministic update 在 256 事件达到 80%–89%；优于多种通用记忆 baseline，支持把解析与规则维护分离。弱项是需要每个事件一次解析调用，写路径成本随历史长度线性增长。

⑥ 让模型自行应用解析后的更新时，结果仅 58% 和 59%；相对 80%–89% 有明显落差，说明失败不仅发生在读日志，还发生在逻辑更新。

⑦ 在一个领域，query-time dependency retriever 于 256 事件与 filter 接近；这限制了“写时处理是唯一可行机制”的主张。真正关键是依赖选择，写时与读时是两种计算位置。

⑧ K=15、保留一半状态分量、随机驱逐时，bounded store 的信息因子从 T=64 的 0.36 降到 T=256 的 0.11，再到 1024 的 0.05；而读时投影约保持 0.39–0.45。两者的差距证明不可逆存储遗忘不是一次性少读几条信息那么简单。

⑨ 预测模型在 147 个内部容量单元上的平均绝对 BA 误差为 0.013 与 0.018，支持容量-读者误差分解；但这是针对已知合成状态机和经过校准的读者，不能外推到任意 Agent。

Table / Figure Reading：至少四处关键证据

Figure 1（论文前部的 horizon 实验）：比较不同长度下 full-log 与 state 的读者表现。横轴事件数、纵轴 BA；需要同时看 8/16 与 256/512/1024，不能把某个模型的转折点宣称为所有模型的固定上限。

Table 1（容量模型）：列出不同 K、T、eviction 与保留比例 f 下的预测信息因子。随机驱逐在若干设置下接近 f，而 recency 驱逐可能明显更差，因为关键旧事件可能长期不被触碰。这里不是简单“最近越重要”。

Table 2（bounded recursive store）：比较相同容量下的真实递归驱逐与 read-time projection；在 K=15、f=0.5、长 T 下两者差异扩大，证明写时丢失的状态会影响后续更新。

Figure 4（第 44 页附近）：横轴保留状态比例，纵轴 balanced accuracy；预测曲线与实测点对照，分别画随机与 recency 驱逐。它支持一个有前提的读者模型，而非任何语言模型的普遍定律。

论文的第二领域冻结复制还很重要：不同措辞仍观察到 horizon，减少了“只针对第一组固定模板过拟合”的担忧，但并不能替代真实生产日志。

Ablation / Mechanistic Analysis 与 Claim vs Evidence

核心消融一：full log vs oracle state，隔离读者的时序追踪能力。核心消融二：model parser + deterministic updater vs model applies updates，隔离解析和状态转移逻辑。核心消融三：read-time projection vs bounded recursive store，隔离读时可见性与写时不可逆遗忘。核心消融四：random vs recency/LRU eviction，检验状态重要性是否可以由时间近似。

Authors Claim：Agent Memory 应被视为在线状态过滤；长上下文的可靠性存在读者依赖 horizon；有限容量的错误可被预测。Experiments Actually Show：在带确定性权限规则的合成事件流上，这些现象被配对对照、多个 reader、容量模型与冻结复制支持。What Is Not Yet Proven：开放世界 Agent 的状态是否能被低维且完整地表示、动态 schema 变更时是否仍可在线更新、自然语言歧义能否以规则覆盖、长期真实工作流中的成本收益。

需要区分“理论上充分状态存在”与“实际系统知道该存哪些状态”。论文的规则是预先明确的，真实 Agent 的未来 query 与环境变量可能未知；若状态 schema 不完整，精确 updater 也会精确地丢掉关键证据。

Contribution、Limitation 与 Failure Modes

Contribution 1 [New Theoretical Framing]：将 Agent Memory 作为递归过滤与状态等价类问题。Contribution 2 [New Benchmark / Protocol]：可执行事件生成器、成对反事实历史、冻结复制和预注册假设。Contribution 3 [New Empirical Finding]：不同 reader 的 full-log horizon、显式状态优势和模型自更新失效。Contribution 4 [New System / Engineering]：LLM parser + exact rule updater 的混合过滤器。Contribution 5 [New Metric / Protocol]：以 component capacity 与读者误差预测 bounded memory 表现。

Authors Limitation（由实验范围可确认）：权限决策任务的规则是明确可执行的，状态变量相对结构化；结果并不直接覆盖开放域对话、视觉记忆、不可观测环境或主观目标。Additional Limitation：schema drift、parser 误抽取、事件乱序到达、并发写冲突、时间戳与 rank 不可信、隐私删除请求、状态审计链过长、每事件一次模型调用的成本，以及过度依赖已知 query family。

最危险的 failure mode 是“状态很紧凑但遗漏未来所需的变量”：一旦被不可逆压缩，读者无法通过更强的 reasoning 恢复。另一个是模型解析 rank 错误，让本应被拒绝的更新被执行；这会把一次局部错误扩散成长期错误。

Reproduction View 与 Research Value

最小复现无需训练 LLM：先实现一个 Python 状态机，支持 grant、withdraw、rank、expiry、group、window 六类事件；写 generate_pair() 产生只改关键顺序/字段的正负对；用 replay() 生成 oracle；测试 full-log reader、oracle-state reader、LLM parse + rule update、LLM self-ledger 四种协议。

第一阶段固定 K=3/7/15、T=16/64/256、每格 40 对；报告 BA、AUC、parser event exact match、update state exact match、平均 prompt tokens、每事件解析费用。第二阶段做 capacity C∈{3,7,15} 的随机与 LRU 驱逐，记录信息因子与预测误差。最重要的复现断言是：对每一条合成历史，oracle replay 与增量 exact updater 的最终状态必须一致。

Baseline Potential 高：可以作为 Agent Memory 状态更新任务的严格基线。Migration Potential 高：从权限状态迁移到工具环境、长期项目状态、视频事件。Systems Potential 高：状态存储与读者推理分离，有利于缓存和审计。Attack Potential 高：可攻击解析与优先级边界。Evaluation Potential 极高：paired counterfactual 测试能暴露 shortcut。Benchmark Potential 极高：可扩展到动态依赖图。New Paper Potential 取决于未知 schema、部分可观测、跨 Agent 同步和可恢复性机制，而非仅把日志换成另一个领域。

Migration A：Multi-Agent 共享状态与因果血缘

Original Problem：单 Agent 的权限日志需要保持正确状态。Transferable Mechanism：在线递归过滤 + 反事实依赖对照。New Research Question：多 Agent 的共享 memory 在乱序消息、重复消息、不同权限来源下是否能保持决策一致？Method Modification：把事件状态扩展为带 actor ID、Lamport clock、source rank、dependency ID 的有向状态更新；对同一 key 的冲突定义 deterministic merge，并记录 lineage。

Minimum Experiment：模拟 4 个 Agent 处理 200–1000 条任务/工具消息，生成 1000 对只改变一条消息顺序、来源 rank 或失效标志的历史；固定随机种子、同一 LLM reader；比较 full transcript、RAG、summary ledger、exact filter、filter+lineage。每组测 BA、state exact match、causal flip consistency、storage bytes、update latency、repair latency。

Model：Qwen2.5-7B-Instruct 或同级开源模型（建议）。Dataset：由本文权限生成器扩展的 Multi-Agent EventBench（拟建，不是现有论文数据集）。Baseline：full log、RAG、Mem0、exact single-agent filter。Metric：paired BA、consistency、lineage recall、latency、token cost。Expected Contribution：多 Agent 状态一致性与可追溯性 benchmark。Risk：分布式事件偏序不一定能由单一 rank 解决。Collision Risk：需检索 CRDT、event sourcing、multi-agent shared memory 研究。

Migration B：Streaming Video Agent 的事件状态过滤

Original Problem：大量历史事件不应全部回读。Transferable Mechanism：以任务充分状态代替原始长序列；保留导致当前判断的关键更新。New Research Question：Streaming Video QA 能否在线维护 query-independent 的事件状态，同时保持对未来未知问题的回答能力？Method Modification：把视频帧解析为 object-state events（进入、离开、拿起、放下、遮挡），按对象与关系维护显式状态；为不可观测区间保留不确定性和 provenance，而非强行 last-write-wins。

Minimum Experiment：选 100 段长视频或从视频基准抽取可标注片段；每段按 1 FPS 与 2 FPS 两种采样运行视觉编码器，生成 object event stream；在 10/30/60 分钟窗口测试“当前物体在哪”“谁最后拿过”“何时离开”等反事实问题。比较全帧 VLM、uniform keyframes、文本摘要、事件 filter、filter+uncertainty；同一 GPU 上同步测 TTFT、总 latency、GPU memory、视觉 token、QA accuracy 与 evidence recall。

Model：Qwen2.5-VL-7B（建议）。Dataset：可选 EgoSchema / LongVideoBench 的适用子集，需先确认每题是否有可定位证据。Baseline：uniform frames、query-aware frame selection、text summary、oracle event state。Metric：QA accuracy、causal pair accuracy、event recall、tokens、wall-clock latency、VRAM。Expected Contribution：有可验证状态依赖的流视频 Agent 加速。Risk：视觉解析噪声会持续污染状态，未知未来问题可能需要原始帧细节。Collision Risk：与 video event memory、streaming VLM token compression、object-centric state tracking 高度相关，必须做先行工作对照。

方向专用 Agent Architecture、Attack Lens 与十句记忆

Agent Architecture：Input events → Parser → Explicit Memory State → Planner/Reader → Tool/Decision → Environment → New Events → Update。Agent State 包含 direct record、group、window 与来源优先级，trajectory 是带顺序的事件流；skill library 不是论文直接对象。Long-horizon 关键是状态大小随 key 数增长而非随历史条数无限增长，但 parser 成本仍随新事件数增长。Failure Propagation：解析错 key/rank → 状态错 → 后续决策错 → 工具调用错 → 新事件继续写入错误状态。

Attack / Verification：可以构造顺序翻转、低 rank 覆盖、高 rank 撤销、过期边界、组关系变化、窗口关闭、乱序消息和无效日志注入，形成 black-box paired probes；进一步测被错误事件覆盖后系统是否恢复，以及丢失旧状态后能否从审计日志重新构建。

记住① 长上下文不是可靠状态机。② 当前决策依赖的是可更新状态，不一定是原始日志。③ 状态必须包含 rank、expiry 和关系，而不只是最终布尔值。④ 成对反事实历史能识别捷径。⑤ 读 256 事件的部分模型已接近随机。⑥ 显式状态让强 reader 达到很高准确率。⑦ LLM 解析加规则更新优于 LLM 自己持续更新。⑧ 按相似度检索不等于因果依赖检索。⑨ 真正删除状态与仅少展示状态的长期后果不同。⑩ 最有价值的迁移是动态、可追溯、可恢复的 Agent 状态管理。

Cross-Paper Synthesis

两篇表面上分别讨论 RL 与 Memory，实际上都在研究“信息进入决策之前，哪些局部信号值得保留与赋权”。NAPO 在训练时从失败 trajectory 中提取一个前段可塑性信号，决定哪些错误样本获得更大负梯度；Agent Memory 在运行时从事件流提取足以回答 query 的状态，决定哪些历史可以被合法覆盖。前者是 learning signal routing，后者是 state dependency routing。

互补机制：把 Agent Memory 的可执行状态 oracle 作为 RL for Agents 的 verifier，再使用 NAPO 的全负组优势机制训练长 horizon 工具 Agent。具体做法是以状态机生成任务、定义最终状态是否正确作为 reward，比较 token entropy driver、action entropy driver、state-difference driver。这样可以同时检验模型是否学会正确操作环境，而非仅在语言上输出看似合理的解释。

潜在冲突：NAPO 假定高早段熵对应更有可塑性的失败；状态过滤研究提醒，若缺失关键依赖或误解析事件，生成模型的高熵可能只是状态错误的后果。把 entropy 当成训练权重前应先确认它与真实状态误差有条件相关性。两篇目前不存在已确认的直接重复贡献，因此 Strongest Collision: NONE；但“state-aware negative credit assignment”是值得检索先行工作的交叉点。

Combined Research Opportunities

首选：State-Verified Zero-to-One Agent RL。 使用可执行事件环境生成长时序决策任务，只有最终状态与 oracle 一致才给正 reward；当一组工具轨迹全错时，根据 action-level uncertainty、state distance、dependency coverage 分配负优势。首轮实验用 3B/7B policy、300 训练任务、100 held-out 任务、每题 G=8、2 个 seed，报告 success@1/8、TTFP、state error rate、invalid tool calls、训练 token 与 wall-clock。若 action driver 比文本 driver 稳定，并能在扰动顺序的 paired tests 上保持收益，才有形成新论文的价值。

次选：可验证的 Streaming Video State Cache。 把视频观测变成可更新状态，允许 query-time 回溯关键帧，按状态依赖而非单纯相似度决定保留的视觉 token；必须同时证明 accuracy、causal pair consistency、latency、VRAM 的 Pareto 改善。它最适合 system / acceleration idea，但视觉事件解析错误是首要风险。

Reading / Reproduction Priority

先复现 Paper 2 的状态机与 paired benchmark：无需训练、成本低、容易发现真实 failure mode。随后复现 Paper 1 的全负组 advantage：需要 GPU 训练，但可以从固定 batch 的 offline driver 诊断开始。作为 baseline：Paper 1 适合 RL 算法对照；Paper 2 适合 Agent Memory 与 evaluation。作为 attack/metric：Paper 2 的反事实状态测试最直接；Paper 1 的 TTFP 与 entropy manipulation 是训练诊断候选。
