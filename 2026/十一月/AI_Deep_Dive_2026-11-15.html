一句话定位

TraceKV 把低秩 KV 压缩的优化目标从“把 KV 重建得像”换成“让压缩后模型的下一词分布不偏离原模型”，具体做法是三件事：用模型自己生成的推理轨迹做校准；按 Fisher 信息给每个 KV 状态加权后再做 SVD；按“删掉这个奇异分量会让策略 KL 增加多少”在全局分配秩。在三个 7–8B 推理型 VLM 上，70% 秩加 4-bit 量化时 KV 缓存缩小 5.64 倍，九格平均准确率 73.41%，稠密模型是 73.58%。

人话版

先说清楚问题。会“想一想再答”的视觉语言模型，KV 缓存里装两类东西：一类是图片切成的几百上千个视觉 token 加上问题文本；另一类是模型自己边想边写出来的推理 token，后者越写越长。KV 缓存就是把每个 token 在每层算出的 key 和 value 存起来，下一步解码时直接读，不用重算。缓存越大，显存越紧，带宽越吃紧，解码就越慢。

低秩压缩的思路是：key/value 是输入向量乘一个投影矩阵 W 得到的，如果把 W 拆成两个瘦矩阵 A 和 B 的乘积，就可以只存中间那个短向量（latent），用到时再乘 B 还原。问题在于怎么拆。以前的做法拿一批“静态”的图文输入当校准数据，让还原出来的 KV 和原来的越像越好。

作者发现这在推理模型上会出事：模型越往后写，压缩版和原版的下一词分布差得越来越大（图 1 右），最后表现为逻辑错误或者无限循环。原因有两个。第一，校准数据里没有“模型自己写的推理过程”，所以压缩矩阵对推理阶段的 KV 拟合得差，表 1 里推理段的重建误差是 10.27，输入段只有 8.02。第二，不是所有 KV 都同样重要：大片背景图像块被压坏了几乎没影响，某个关键数字或者推理里的“Since”被压坏了，后面就跑偏。

TraceKV 的回答很直接：让原模型先自己把校准题做一遍，把它写出来的推理也纳入校准；再用“这个 KV 被扰动后，后续所有位置的预测分布会变多少”作为权重，重要的 KV 优先保真；最后在所有层、所有 K/V 投影之间统一按“删掉哪个分量最不伤策略”来分预算。整个过程不训练，只在离线校准时多花大约 30 分钟（单张 L40S，7–8B 模型）。

背景与缺口

KV 缓存压缩大致有三条路：丢 token（SnapKV、R-KV 这类驱逐法）、降精度（KIVI、KVQuant 这类量化法）、降维度（Palu、SVD-LLM、WSVD 这类低秩法）。第三条路的好处是缓存结构规整，还能和量化叠加：低秩 latent 经过 Hadamard 旋转后更好量化，Palu 已经展示过这种组合。

但已有的 VLM 低秩方法（QSVD、WSVD）主要在短答或直接回答任务上评测，用的校准数据也是静态的图文输入，目标是 Eq.1 那种重建误差 ‖X(W−W^)‖F2。这里有三个缺口：（1）推理型 VLM 要压缩的不只是输入，还有不断增长的生成段，而校准数据完全没覆盖生成段；（2）重建误差对所有 token 一视同仁，与“模型最后会不会答错”没有直接关系；（3）秩怎么在层和 K/V 之间分配，过去多用均匀分配或基于重建误差的启发式。

论文把这三个缺口统一到一个原则下：压缩的目标应该是“保住稠密模型的预测策略”，用策略 KL 衡量。这一点受到知识蒸馏的启发——蒸馏也是让学生的输出分布贴近老师。相关工作里，自生成校准（Self-calibration、RAC）和基于损失的敏感度（FWSVD、MBQ）都已有先例。TraceKV 的区别在于把“在线策略校准 + Fisher 加权 SVD + 分量级全局秩分配”放在同一个策略 KL 框架下推出来，并且专门针对 VLM 的推理段。

核心 insight

核心 insight 有两层。

第一层是“状态分布要对”：KV 投影矩阵的低秩子空间是从校准激活里学出来的，用什么激活学，就对什么激活拟合得好。推理型模型推理时真正读写的是它自己写出来的推理 token，所以校准数据必须包含 on-policy 轨迹，而不是题目自带的参考解答。表 1 量化了这一点：只用输入校准时推理段误差 10.27，加参考解答降到 9.67，加模型自己的轨迹降到 8.88，输入段误差几乎不变（8.02→7.96）。

第二层是“误差的代价不均匀”：二阶展开下，KV 状态上一个扰动造成的后续累计策略 KL 约等于 12δ⊤Fδ。把 Fisher 矩阵的迹平均到每一维，就得到每个 KV 状态的敏感度 st，把它当作逐行权重塞进重建目标，仍然可以用一次 Cholesky 白化加 SVD 得到闭式最优解。也就是说，作者没有放弃 SVD 的可解性，只是换了“度量”。附录 A.3 进一步说明这个加权重建目标是理想策略 KL 目标的近似，忽略了跨状态交互项和各向异性项。

把这两层合起来：分布对了、度量对了，剩下的就是预算怎么分。作者再用同一套 Fisher 二阶近似去估每个奇异分量被删掉的 KL 代价，全局排序取前若干个，决定每个投影的秩。三步共享同一批采样梯度，所以额外成本只是 K=8 次反向传播。

方法逐步拆解

  1. 在线策略校准（§4.1）：从 ScienceQA 训练集取 256 道题，让稠密 VLM 用贪心解码自己生成推理轨迹（每题最多 512 个新 token），把系统提示、多模态输入、生成 token 在每个 KV 投影上的输入激活全部收集起来，组成 Xon。生成的前缀同时保留下来，供下一步估计敏感度。按附录 C.1，256 题只用输入时共 171.7K token，加参考解答 190.9K，加在线轨迹 200.3K。
  2. 估计 KV 状态敏感度（§4.2 前半）：在每个已固定的在线前缀位置 cj，从稠密模型的预测分布里独立采样一个 token aj(k)，组成负对数似然 ℒ(k)=−∑jlogpj(aj(k))，对每个 KV 状态 yt 求梯度 gt(k)。重复 K=8 次，用梯度平方范数的平均估计 Tr(Ft)，再除以 2dout 得到 s^t。附录 A.1 证明这个估计无偏：不同位置独立采样，得分函数期望为零，交叉项消失。
  3. 敏感度加权 SVD（§4.2 后半）：令 D=diag(s^1,…,s^N)/∑s^，构造加权协方差 C=Xon⊤DXon，Cholesky 分解得 S⊤S=C（附录 A.4 提到加阻尼保证可逆），对 SW 做 SVD，得到一组奇异分量 ΔWi=S−1uiσivi⊤。
  4. 全局秩分配（§4.3）：复用第 2 步的同一批采样 NLL，对每个投影矩阵 Wm 求梯度 Gm(k)，计算每个奇异分量的重要度 Im,i（梯度与分量的 Frobenius 内积的平方的平均的一半），在所有层、所有 K/V 投影上全局排序，按总秩预算取最重要的若干个，于是每个投影的秩 rm 由数据决定。附录 C.5 的图 8 显示：多数层 value 投影分到的秩比 key 多，中后层（约 16–21 层）分得更多。
  5. 量化整合（§4.4、附录 D.1）：秩对齐到 16 的倍数，在 latent 维上做正交 Hadamard 变换（可吸收进 A、B，推理不增加开销），并把奇异值按 Σα、Σ1−α 分给两个因子，固定 α=0.7；作者报告 α=0.7 比 0.5 让量化后重建 KV 的 NMSE 降低 4–8%。量化是逐 token-latent 的非对称量化，不再分组。
  6. 系统实现（§4.5、附录 D.2）：value 侧先用注意力权重在 latent 空间聚合，再做一次上投影，避免重建整条 value 序列；key 侧因为要先重建再加 RoPE（Qwen2.5-VL 是 MRoPE），用 Triton 核把“重建 key 分块 + 加 RoPE + 算注意力 logit”融合在片上完成，不把完整 key 缓存写回显存；4-bit 时反量化也融合进核。预填充阶段仍用标准注意力。

核心公式：变量、目标与直觉

（1）传统重建目标（Eq.1）：

minrank(W^)≤r‖X(W−W^)‖F2

变量：X∈ℝN×din 是 N 个校准 token 的输入激活，W 是 K 或 V 投影矩阵，W^=AB 是秩不超过 r 的近似。直觉：让所有校准 token 的 KV 都重建得像，每个 token 权重相同。

（2）理想目标：策略 KL（Eq.4）：

minrank(W^)≤r𝔼s~dp[DKL(p(·∣s)‖pW^(·∣s))]

dp 是稠密模型自己推理轨迹上的前缀分布，pW^ 是把 W 换成 W^ 后的模型。直觉：不在乎 KV 本身像不像，只在乎“下一个词怎么选”有没有变。它没有闭式解，所以需要下面的代理。

（3）二阶近似（Eq.2–3）：

DKL(p‖pδ)=12δ⊤Fθδ+o(‖δ‖2)

在原模型处 KL 为零、一阶导为零，所以主项是 Fisher 矩阵定义的二次型。Fisher 越大的方向，扰动越伤策略。

（4）KV 状态敏感度（Eq.6–7）：

ht,j(a) 是位置 j 的对数概率对 KV 状态 yt 的梯度，𝒥(t) 是 yt 之后所有预测位置。st 等于“对 yt 施加一个随机方向、单位能量的扰动时，后续累计策略 KL 的期望二阶增量”。注意它是对后面所有位置求和的，所以早期的关键 token（例如 attention sink）天然会得到很大的敏感度。

（5）TraceKV 的代理目标（Eq.8）：

minrank(W^)≤r‖D1/2Xon(W−W^)‖F2,D=diag(s^1,…,s^N)/∑s^

与 Eq.1 只差两处：X 换成在线校准的 Xon，每一行乘上敏感度权重。最优解：C=Xon⊤DXon=S⊤S，对 SW=UΣV⊤ 取前 r 个分量，W^⋆=S−1UrΣrVr⊤（Eckart–Young–Mirsky）。

（6）分量重要度（Eq.9）：

Im,i=12K∑k=1K⟨Gm(k),ΔWm,i⟩F2

它估计“删掉第 m 个投影的第 i 个奇异分量”带来的二阶策略 KL 增量。作者明确承认：同时删多个分量会有交叉项，这里把单个分量的重要度当作可加的近似。

（7）近似误差分解（附录 A.3, Eq.19）：

𝒟(W+ΔW^)−ℛ(W^)=12∑t≠uδyt⊤Ftuδyu⏟Ecross+12∑tδyt⊤(Ftt−2stI)δyt⏟Eanis+o(‖ΔW^‖F2)

这是全文最诚实的一个式子：代理目标和真实策略 KL 之间差了跨状态交互项、各向异性项和高阶项。论文没有给出这些误差项的数值大小（Not Reported），只用图 4 的策略 KL 曲线间接说明代理有效。

Toy example（本文自造算例，非论文数字）

用一个 2×2 的小例子说明“加权”为什么会改变保留哪个分量。设两个 KV 状态的输入激活 x1=(1,0)、x2=(0,1)，投影 W=diag(3,2)，秩预算 r=1。

均匀重建：X⊤X=I，白化矩阵 S=I，SW 的奇异值是 3 和 2，保留第一个分量。被丢掉的是第二个方向，x2 的 KV 误差为 ‖x2·diag(0,2)‖2=4，x1 无误差。

敏感度加权：假设 Fisher 估计显示 x2 是关键推理 token，归一化后 s1=0.1、s2=0.9。则 C=diag(0.1,0.9)，S=diag(0.316,0.949)，SW=diag(0.949,1.897)。现在第二个分量的奇异值更大，秩 1 解保留它，丢掉第一个方向。

比较加权代价：均匀解的加权误差是 0.9×4=3.6；加权解丢掉 x1 方向，加权误差是 0.1×9=0.9。按未加权的重建误差看，均匀解更好（4 对 9）；按策略敏感度看，加权解好 4 倍。这正是论文图 4(d) 描述的现象：全方法下不敏感的视觉状态误差反而升高（颜色变浅），关键状态误差降低。

再核一下压缩倍数（按论文配置推算，非论文给出的推导）：BF16 每维 16 bit，70% 秩加 4-bit 时理论倍数为 16/(0.7×4)≈5.71，论文报告 5.64×，并说明这个数“包括量化元数据”，差额与逐 token 缩放因子和零点的开销方向一致。同理 50% 秩 4-bit 理论 8.0×、报告 7.76×；50% 秩 3-bit 理论 10.67×、报告 10.24×。三个数都略低于理论值，内部一致。

Baselines

论文实际比较了六个基线，分两组：

  • SVD-LLM（ICLR 2025）：激活白化 SVD，按重建误差截断，是“重建式 SVD”的代表，也是表 5 消融的起点。
  • ZS-SVD（ICML 2026）：Zero-Sum SVD，用损失敏感度平衡秩分配；在 Qwen3-VL-8B 50% 秩时崩得最厉害（MMMU 21.89%）。
  • Palu（ICLR 2025）：KV 缓存低秩投影 + 分组分解 + 量化，最直接的竞品；TraceKV 沿用其 head-group size=4。
  • WSVD（ICLR 2026）：面向低精度 VLM 的加权低秩近似；校准协议照搬其官方实现（256 道 ScienceQA、仅输入、用参考解答估计损失/Fisher）。
  • RTN-KV4（gs32）：逐 token 4-bit 就近取整量化。
  • KIVI-2（gs32, r32）：2-bit 非对称 KV 量化，key 逐通道、value 逐 token，5.33× 压缩。

应有但缺失的对比：（1）token 驱逐类方法（SnapKV、R-KV），作者以“基本正交”为由排除，但在推理型模型上它们是部署时最常见的替代方案，至少应给出同显存下的对比或叠加实验；（2）在线低秩方法（ShadowKV、XKV、IS-KV），只在附录 E 文字讨论；（3）同期的 LASER 与 BELT 只在相关工作中提到；（4）KVQuant 等更强的量化基线。所有基线都只压 K/V 投影，这一点作者明确说明是为公平。

指标教学

  • Rank ratio（秩比）：所有头、所有层保留的 KV 维度占原维度的比例。70% 意味着每个 token 只存 70% 的维度；注意 TraceKV 的全局分配会让不同投影的秩不同，70% 是总量。
  • Comp.（压缩倍数）：相对 BF16 原始 KV 缓存的大小倍数，包含量化元数据。低秩-only 时 50% 秩就是 2.00×。
  • 准确率与 Overall Avg.：三个基准 × 三个模型共九格的简单平均。它掩盖了单格的大起伏，读表时要同时看最差格。
  • 策略 KL（policy-KL）：在稠密模型生成的固定前缀上，比较稠密与压缩模型下一词分布的 KL。它衡量“走同一条路时，会不会想换方向”，但不衡量压缩模型自己走下去会怎样——作者在附录 E 承认这一点。
  • 重建误差 et=‖xt(W−W^)‖22：某个 token 的 KV 被压缩还原后的平方误差，在所有层所有投影上平均。
  • 截断率：生成达到 4096 token 上限而没有给出答案的比例。在 Thinking 模型上，这几乎就是“陷入循环”的代理指标（表 8）。
  • 加速比：注意力模块加速与端到端解码加速分开报告；32K 时稠密模型 OOM，图 5 用虚线外推，这部分不是实测。

贡献

  • 把推理型 VLM 上低秩 KV 压缩的退化定位到两个可测量的原因——校准状态失配与误差敏感度不均——并给出了定量证据（表 1、图 2、图 7）。
  • 在同一个策略 KL 二阶近似下推出三件工具：在线校准、Fisher 加权 SVD（保留闭式解）、分量级全局秩分配；三者共享同一批采样梯度。
  • 把低秩压缩、Hadamard 量化与融合 Triton 核串起来，给出了从显存节省到真实解码加速的完整链路，而不仅仅是“理论压缩倍数”。
  • 附录 A.3 明确写出代理目标与真实策略 KL 之间的误差项，方便后续工作针对性改进。

局限

  • 目标函数在稠密模型轨迹上定义，压缩模型推理时走的是自己的轨迹，存在暴露偏差；表 8 显示截断率仍从 17.56% 升到 23.22%。作者在附录 E 自己承认。
  • 评测只有三个选择/短答型视觉推理基准，没有视频、多图、长文档或开放式生成；“视觉 token 不敏感”的结论在视频场景下是否成立未验证。
  • 校准依赖任务相关样本（ScienceQA 训练集），换到更远的领域时的效果只有 MathVista 一个迁移点。
  • 效率只在 Qwen2.5-VL-7B 上测；预填充仍用标准注意力并需要重建 KV，长输入、短输出场景的收益 Not Reported。
  • 主结果单次贪心运行，无方差；零点几个点的差异不能当作显著差异。

复现要点

  1. 按附录 B 准备：ScienceQA 训练集固定 256 题（论文沿用 WSVD 官方实现的随机采样，但具体题号 Not Reported），系统提示照抄附录 B 的原文。
  2. 稠密模型贪心生成，每题最多 512 个新 token；收集每个 K/V 投影的全部输入激活（含系统提示、视觉 token、生成 token）。
  3. 在每个生成位置从稠密分布采样 token，K=8，种子 0；对 KV 状态和投影权重分别求梯度。显存上要注意：需要保留 KV 状态梯度，7–8B 模型单卡 L40S（48GB）可行，32B 的配置 Not Reported。
  4. Cholesky 前给加权协方差加阻尼（阻尼值 Not Reported）；head-group size 4；秩对齐 16。
  5. 量化用逐 token-latent 非对称、α=0.7、Hadamard。
  6. 评测用 lmms-eval，最多 4096 token，答案从 <answer> 标签抽取，抽不到时走基准默认回退规则。
  7. 代码仓库已在摘要中给出地址，但截至写作未核验是否公开（Not Verified）；复现时最可能踩坑的是 MRoPE 与融合核的对齐。

研究价值

这篇论文的研究价值主要不在某个具体数字，而在于它给 KV 压缩提供了一个可迁移的“度量替换”范式：凡是现在用重建误差做目标的压缩（权重低秩、KV 量化、token 合并），都可以问一句“我的校准分布是不是推理时的真实分布”和“我的误差度量是不是和输出分布挂钩”。论文证明了在 SVD 这种需要闭式解的场景里，也可以通过逐行加权把 Fisher 信息塞进去而不失可解性。

对推理加速方向，它还提醒了一个容易被忽略的成本：压缩造成的“想得更久、更容易循环”。表 8 说明评估 KV 压缩不能只看每步延迟，还必须看生成长度和截断率，否则加速比会被高估。对视频加速，附录 C.4 中“多数视觉 token 不敏感”的观察值得在视频基准上重新验证。

可执行迁移（至少两条）

  1. 迁移到视频 LLM 的 KV 压缩：用视频问答模型自己生成的回答做在线校准，按 Fisher 敏感度给视频帧 token 和文本 token 分别加权，预期大量冗余帧 token 权重极低，可以把秩预算让给问题文本和关键帧。验证方法：在 VideoMME 或 MVBench 上画“策略 KL 随生成长度”的曲线，复制图 1 的现象再比较。
  2. 把“截断率 + 平均长度”加入任何推理加速方法的评测清单：对投机解码、KV 量化、token 驱逐，同时报告每题墙钟时间 = 每步延迟 × 生成长度。可以直接用表 8 的格式。
  3. 用同一批采样梯度做混合策略：TraceKV 的敏感度 s^t 本身就是一个逐 token 重要度，可直接作为 token 驱逐或混合精度（敏感 token 用 8-bit，不敏感用 3-bit）的打分，无需额外前向。

方向专用分析（Inference Acceleration：显存、带宽、端到端收益）

瓶颈定位：解码阶段是带宽受限，KV 缓存读取量随上下文线性增长。TraceKV 节省的是“每步要读多少字节”，同时引入“每步要做的重建计算”。附录 D.2 的设计（value 先聚合后上投影、key 片上重建加 RoPE）就是为了不让重建计算吃掉带宽节省。附录图 9 显示 50% 秩时单步从 96.2 ms 降到 69.7 ms，说明这一权衡在 16K、batch 16 下是划算的。

收益的适用边界：（1）短上下文时 KV 读取不是瓶颈，收益会变小，图 5 从 4K 起测，但 4K/8K 的具体倍数我没有从图中可靠读出，正文只给了 16K 的数字；（2）预填充没有加速；（3）batch 越大、上下文越长越有利，32K 时稠密模型直接 OOM，这本身就是显存压缩的价值，但 32K 的加速比是外推的。

与其他加速手段的组合性：低秩与量化已经证明可叠加；与 token 驱逐理论上正交（一个减少 token 数，一个减少每 token 维度），但没有实验；与投机解码组合时，草稿模型的接受率会不会因为策略偏移下降，是一个值得测的问题——策略 KL 正好是接受率的上游指标。

部署成本：一次性离线校准约 30 分钟；每个模型、每个任务域需要重新校准；需要自定义核（Triton），对 vLLM/SGLang 的分页 KV 布局是否兼容 Not Reported。

Attack / Verification lens

  • 数字一致性：我核对了正文与表格的对应关系：73.33/73.58、70.28 与 Palu 63.19 之差 7.09、73.41 与 5.64×、78.98 与 80.29 之差 1.31、消融 58.41→66.57 之差 8.16、表 7 中 Palu 50% 的三格平均 57.68，均与表格一致。
  • 压缩倍数的口径：TraceKV 与 Palu 在同档压缩下倍数完全相同（5.64× / 7.76×），说明两者用同样的秩比与位宽计算；但 TraceKV 的全局秩分配让各投影秩不同，若某些层秩更高、某些层更低，元数据开销是否完全一致，论文没有拆开说明。
  • 基线校准是否公平：基线按 WSVD 官方协议用参考解答估计损失/Fisher，TraceKV 用在线轨迹；表 7 已补了“token 数对齐”和“加参考解答”的基线，这是一个加分的公平性检查。
  • 可能的漏洞：评测与校准使用同一套推理提示，且校准集来自 ScienceQA 训练集、评测含 ScienceQA 测试集，ScienceQA 上的优势可能部分来自域内校准；表 6 显示换成 MathVista 校准后 ScienceQA 从 87.40 降到 85.07，印证了这一点。
  • 应该追问的问题：在开放式长生成（如图表描述、多轮对话）上策略 KL 的累计行为是否同样可控？当视觉 token 占比更高（视频）时，均匀分配与敏感度分配的差距会更大还是更小？32B 模型校准的时间与显存成本是多少？
  • 如何独立验证：在公开代码出来后，最便宜的验证是复现表 1（三种校准下推理段重建误差）和表 5 的前三行，这只需要 SVD 和一次贪心生成，不需要定制核。

记忆总结

  1. TraceKV 是一个不训练的低秩 KV 压缩方法，对象是推理型视觉语言模型。
  2. 它把目标从“KV 重建得像”换成“下一词分布不变”，用策略 KL 的二阶近似（Fisher）落地。
  3. 第一件工具是在线策略校准：让稠密模型自己生成推理轨迹做校准数据，推理段重建误差从 10.27 降到 8.88。
  4. 第二件工具是敏感度加权 SVD：每个 KV 状态按 Fisher 迹加权，仍有闭式最优解。
  5. 第三件工具是全局秩分配：按删除每个奇异分量的 KL 代价全局排序，value 投影和中后层分到更多秩。
  6. 结果：70% 秩 + 4-bit 压缩 5.64×，九格平均 73.41% 对稠密 73.58%；50% 秩时比 Palu 高 7.09 个点。
  7. 效率：16K 上下文、batch 16 下端到端解码最高 1.83×，峰值显存 32.13 GB 降到 18.57 GB。
  8. 消融中最大单步增益来自全局秩分配（+2.89），不是在线轨迹本身。
  9. 压缩模型更容易“想太久”：Thinking 模型在 MMMU 上截断率仍从 17.56% 升到 23.22%，评测加速必须看生成长度。
  10. 主要局限：只在三个图像推理基准上测，无视频、无多种子；目标定义在稠密轨迹上，存在暴露偏差；属于 BACKFILL（约 82 小时前提交）。

一句话定位

HeMeR 是一个“记忆服务层”：它把具身智能体每一步拼进提示词的陈述性记忆、程序性记忆（LoRA 适配器）和工作记忆切成带类型和 ID 的块，记住每块对应哪段 KV 缓存，下一步只重算真正变了的块，没变但挪了位置的块用 RoPE 旋转修正位置后直接复用，适配器切换也纳入兼容性检查。在 ALFWorld 上，它报告成功率 71.43%、每步 0.18 秒，最强基线 MemRL 为 52.86%、0.90 秒。

人话版

想象一个做家务的机器人，每一步决策前，它要把三类“记忆”拼成一大段提示词交给语言模型：一是“厨房里冰箱在哪、苹果在桌上”这类事实（陈述性记忆）；二是“加热东西要先打开微波炉”这类套路，在这篇论文里实现为按房间类型训练的 LoRA 小插件（程序性记忆）；三是“我刚才拿起了苹果、现在在走向微波炉”这类当前进度（工作记忆）。

问题是：每走一步，这段提示词只变了一小部分，但现有做法常常把整段当新输入，从头算一遍 KV 缓存。前缀缓存（prefix caching）只能复用“开头完全一样”的部分，只要中间插了一条新记忆，后面全部失效。

HeMeR 的做法像做“版本对比”：给每条记忆一个身份证（持久 ID）和档案（类型、语义角色、内容、依赖关系、位置、对应的 KV 区间、所用适配器）。下一步来了，先按 ID 对比新旧两版提示词：新增的块算一遍；删掉的块把 KV 丢掉；内容没变只是挪了位置的块，把缓存的 key 用 RoPE 旋转一下修正位置；内容、依赖或适配器变了的块，连同依赖它的块一起重算。

这样每步要重算的 token 大幅减少。论文表 3 回放 ALFWorld 的记忆更新序列：完全重建要重算 74,784 个 token，HeMeR 只重算 4,219 个，缓存处理总时间从 199.4 秒降到 25.8 秒。

背景与缺口

具身智能体越来越多地使用记忆模块：Voyager 的技能库、Reflexion 的反思、MemGPT 的分层记忆、A-Mem 等。认知架构（CoALA）把记忆分成陈述性、程序性、工作记忆，这篇论文沿用这一划分。已有记忆研究的重点是“存什么、取什么、怎么更新”，几乎不讨论“取出来拼进上下文以后，模型推理要付出多少重算代价”。

另一边，推理系统领域已有很多 KV 复用工作：vLLM/SGLang 的前缀缓存、Prompt Cache 的模块化缓存、CacheBlend 的非前缀片段复用加边界重算、KVLink、CacheSlide 的位置无关复用；具身场景里 KEEP 通过失效受影响区域来复用；多 LoRA 服务里 LRAgent 研究了适配器切换时的 KV 共享。

缺口在于两边没有接上：（1）记忆系统不知道自己的更新对应缓存的哪一段；（2）缓存系统不知道上下文由哪些“语义单元”组成，只能按前缀或固定片段边界复用；（3）程序性记忆通过切换适配器改变的是模型本身，此时即使文本没变，旧 KV 也可能不再兼容。HeMeR 把这三点统一成一个“KV 对账”（reconciliation）问题，形式化为 Eq.5：在任务分布上最大化成功率减去 λ 倍的累计推理代价。

核心 insight

核心 insight：记忆的结构本身就是最好的缓存索引。智能体的记忆系统天然知道“哪条记忆是新的、哪条被删了、哪条只是换了顺序”，这些信息比服务层从 token 序列里猜要准确得多。只要在拼接上下文时保留“记忆块 → KV 区间”的映射，缓存复用就可以从“前缀匹配”升级为“按语义块对账”。

第二个 insight 是把适配器身份放进兼容条件。程序性记忆以 LoRA 形式存在时，切换程序等于切换模型参数。HeMeR 借用 LRAgent 的共享注意力 LoRA 设计（rank 8，只作用于 query 与 value 投影，下投影跨适配器共享、上投影各自独立，key、输出和 MLP 路径共享），让大部分 KV 在切换后近似可用，再对受影响的程序记忆块及其依赖块强制重算。作者原话是这种设计“限制但不消除”跨适配器漂移。

需要强调：块级复用本质上是一种近似。被复用的 KV 仍然带着它当初前文的影响，前文变了它不会跟着变。HeMeR 并没有消除这个近似，而是把它限制在“schema 字段完全一致”的块上，并用附录表 18 的漂移测试说明近似误差不大。

方法逐步拆解

  1. 记忆分层与表示：每步从三个模块检索 Dt、Pt、Wt，用组合函数 Γ 拼成记忆上下文 Xt。陈述性记忆存物体位置、容器关系、任务条件；程序性记忆是按任务类型或房间类型微调的 rank-8 LoRA（ALFWorld 中是浴室、卧室、客厅三个房间专用适配器加一个共享适配器）；工作记忆存最近观测、中间决策、子目标与动作历史。
  2. 记忆 schema：Xt 被组织为一串记忆块，每块记录持久 ID、记忆类型、语义角色、规范化内容、依赖注释、位置、token 跨度、KV 区间，以及（适用时）适配器 ID。初始上下文按普通因果序列一次性预填充。
  3. schema 引导的对账计划：Δt=Diff𝒮(Xt−1,Xt)。先按持久 ID 匹配新旧块（不看位置），只有类型、角色、依赖、内容、适配器全部一致的匹配块才有资格复用；位置变了的匹配块记为“重排”，只在新版出现的记为“插入”，只在旧版出现的记为“驱逐”，其余不一致的记为“重算”。
  4. KV 操作：插入块做预填充；驱逐块删除 KV；重排块把 KV 搬到新位置，并对 key 做 RoPE 重映射（Eq.7）；值向量不做位置修正（RoPE 本来就只作用于 query/key）。多模态骨干上，只对文本侧记忆块做 RoPE 重映射，当前步的视觉 token 每步正常编码。
  5. 适配器稳定的对账：适配器 ID 写入 schema；活跃适配器改变时，重算程序记忆块的 KV 区间及其直接、传递依赖块；其他未变块在共享注意力 LoRA 设计下近似复用。注意活跃适配器作用于整个前向序列，而不只是程序记忆 token。
  6. 组装与生成：把复用、搬移、新算的 KV 片段组装成当前步的缓存 Kt，对新增的“尾部”（当前观测、提示等）做预填充，然后解码动作。附录 C.2 报告规划开销 37–310 微秒、组装 0.7–5.7 毫秒，随记忆规模增长。

核心公式：变量、目标与直觉

（1）记忆检索与上下文组合（Eq.2–4）：

ℛtm=Rm(ot,g,ht),Xt=Γ(Dt,Pt,Wt),at~Fθ(·∣Xt,ot,g)

ot 是观测，g 是任务目标，ht 是交互历史，m∈{dec,proc,work}。直觉：三类记忆各自检索，再拼成一段上下文，模型据此选动作。

（2）服务策略目标（Eq.5）：

Π⋆=\argmaxΠ𝔼τ~𝒟[Succ(τ;Π)−λ∑t=1TCost(Π,Xt−1,Xt)]

Π 决定每步哪些 KV 复用、哪些重算，Succ 是任务是否成功，Cost 是从 Xt−1 到 Xt 的推理计算量，λ 是权衡系数。这是问题定义而非被优化的损失：HeMeR 并不学习 Π，而是给出一个基于规则的 Π。论文也没有报告 λ 的取值或扫描（Not Reported）。

（3）对账计划（Eq.6）：Δt=Diff𝒮(Xt−1,Xt)。它把每个块分到复用、重排、插入、驱逐、重算五类之一。

（4）RoPE 重映射（Eq.7）：

k~j=Rθ(pj′)Rθ(pj)−1kj

kj 是在旧位置 pj 缓存的 key，Rθ(p) 是位置 p 的 RoPE 旋转。先“转回去”再“转到新位置”。因为 RoPE 是按维度对的二维旋转，旋转矩阵可交换，这等价于直接转 θ(pj′)−θ(pj) 的角度差，计算很便宜。它只修正位置相位，不修正“前文改变”带来的内容偏差。

（5）漂移度量（附录 Eq.8）：

Driftℓ,i=‖hℓ,imethod−hℓ,ifull‖2

第 ℓ 层、第 i 个位置上，用某种复用策略得到的隐藏状态与完全重建的差。它是检验“近似复用到底近似得多好”的直接指标。

Toy example（RoPE 算例为本文自造；表 3 算术按论文数字复算）

算例 A：RoPE 重映射。取一对二维分量，频率 θ=0.1 弧度/位置，原始未旋转 key 为 (1,0)。它在位置 10 被缓存，角度 1.0，缓存值为 (cos1.0,sin1.0)=(0.540,0.841)。现在前面删掉了 3 个 token，它挪到位置 7。按 Eq.7 先转回 −1.0 再转 +0.7，等于转 −0.3，得到 (cos0.7,sin0.7)=(0.765,0.644)，与在位置 7 重新计算这个 key 的位置相位完全一致。但如果被删掉的 3 个 token 曾经影响了这个 key 的内容（注意力会把前文信息混进去），这部分偏差 RoPE 修不掉——这就是表 18 中“驱逐在被复用区间之前”的 KL 最高（0.078）的原因。

算例 B：按表 3 复算 ALFWorld 回放。HeMeR 处理的 token 总数 64,128（复用）+6,437（重排）+4,219（重算）+5,358（插入）+1,742（驱逐）=81,884，与完全重建的总数一致。复用占 64,128/81,884=78.3%，重排占 6,437/81,884=7.9%，重算 4,219/74,784=5.6%，三个比例均与正文一致。时间上 HeMeR 为 12.9（重算）+12.4（插入）+0.5（组装）=25.8 秒；完全重建为 186.5+12.4+0.5=199.4 秒；比值约 7.7 倍。插入与驱逐的成本两者相同，所以全部节省来自“不用重算”的 70,565 个 token（74,784−4,219）。

算例 C：事件数。HeMeR 的事件为 5,167 次复用、528 次重排、418 次重算、408 次插入、113 次驱逐，共 6,634；完全重建把 6,113 次全部记为重算。可见绝大多数更新步骤里，大部分块都是原样不动的——这是整个方法能成立的数据前提。

  • ReAct：推理-行动交替提示，无外部记忆。
  • Reflexion：用失败后的语言反思指导后续回合。
  • MemRL（2601.03192）：检索过去轨迹的情景记忆，但把检索结果当作普通输入，每步不复用 KV。它是成功率最强的基线。
  • CacheBlend（EuroSys 2025）：非前缀片段复用 + 边界区域选择性重算，原为 RAG 设计。
  • KEEP（2602.23592）：面向具身规划的 KV 中心记忆管理，通过失效受影响区域复用。
  • LRAgent（2602.01053）：多 LoRA 智能体的 KV 共享，支持程序技能切换，但不追踪陈述/工作记忆更新。

应有但缺失的对比：（1）“同记忆架构 + 完全重建”的成功率。这是判断“成功率提升从何而来”的关键对照：如果 HeMeR 的成功率高于完全重建，说明近似复用意外地有益；如果相当，那么相对 MemRL 的 18.57 个点提升应归功于异构记忆与 LoRA 程序记忆本身，而非 KV 对账。正文表 1 没有这一行，完全重建只出现在效率分析里。（2）vLLM/SGLang 的前缀缓存作为最朴素的工程基线。（3）EPIC、CacheSlide 等位置无关缓存方法只在相关工作中提及。

指标教学

  • SR（成功率）：ALFWorld 与 Habitat 为二值任务完成率；真机为“目标条件成功率”（按子目标计分），所以 10 次试验也能得到 83.20% 这样的非整十数。
  • Latency（s/step）：每个决策步的平均墙钟时间。附录 B.3 说 TTFT 不含记忆检索、提示构建和 schema 对比规划；Latency 的确切口径（是否含环境执行）正文未完全说明。
  • TTFT：到第一个生成 token 的时间，包括 KV 更新、必要的预填充和局部重算，是衡量“缓存处理代价”的直接指标。
  • Reuse ratio（复用率）：记忆更新后保留下来的 KV 状态比例，按每步平均；完全重建为 0。注意它只说明“省了多少”，不说明“复用得对不对”。
  • Active action ratio：生成动作中属于预定义“推进任务”类别的比例；Diversity ratio：每回合中不重复动作的比例。这两项是行为层指标，论文用来说明智能体没有陷入原地打转，但它们与成功率并非单调关系（多样性高也可能是乱试）。
  • K cos / Hidden cos / KL / Top-1 agreement / Top-5 overlap（表 18）：分别比较复用后的 key、最后一层隐藏状态、下一词分布与完全重建的接近程度。Top-1 agreement 是“最可能的下一个 token 是否相同”的比例。

Ablation 与缺失的 ablation

表 4 / 表 22 的消融（ALFWorld）：完整 HeMeR 为 SR 71.43%、0.18 s、复用 75.30%、TTFT 21.59 ms；去掉记忆 schema 为 62.67%、0.38 s、51.39%、30.39 ms；去掉块级对账为 59.40%、0.47 s、42.75%、45.10 ms；去掉适配器稳定对账为 64.85%、0.28 s、66.40%、39.75 ms。

作者的解读是：schema 决定能否识别可复用内容，块级对账是减少预填充的主要来源，适配器稳定对账保证复用状态与当前程序配置兼容。“去掉适配器稳定对账后复用率仍有 66.40% 但成功率下降”这一条最有说服力：它说明复用越多不等于越好，跨适配器的陈旧 KV 会伤害决策。附录还补了一个强制每步切换适配器的测试：HeMeR 复用率 77.9%，去掉该组件后复用率降为零，延迟接近完全重建。

但这组消融有两个解释上的疑点。第一，“去掉块级对账”按作者说法会导致“更广泛的重算或更不稳定的复用”——如果是前者，结果应更接近完全重建、决策质量应更好而非更差，成功率却从 71.43% 降到 59.40%；论文没有说清楚这个变体具体退化为哪种策略。第二，去掉 schema 后延迟翻倍（0.18→0.38 s），而 TTFT 只增加约 9 ms，延迟增加的大部分同样无法用预填充解释。

缺失的消融：（1）同记忆架构下“完全重建”的成功率与延迟；（2）去掉 LoRA 程序记忆（只用陈述 + 工作记忆）时的成功率，用以分离“记忆设计”与“缓存设计”的贡献；（3）依赖注释的来源与质量（人工规则还是自动生成）对结果的影响，附录表 20 只扫了依赖密度（0%→100% 时复用率 85.4%→61.3%）。

贡献

  • 提出“异构记忆 → KV 对账”的问题表述，把智能体记忆系统和推理服务系统接在一起，这是一个明确且实用的系统视角。
  • 设计了带持久 ID、类型、依赖、适配器 ID 的记忆 schema，使非前缀 KV 复用可以按语义块进行，并把适配器切换纳入同一套兼容性检查。
  • 在文本、视觉和真机三类环境中给出效率与行为指标，并在附录提供了相当详尽的成本分解、漂移、规模化、依赖密度、干扰项鲁棒性分析（表 14–21）。

局限

  • 成功率提升的来源没有被干净地分离（见上），这是本文最主要的证据缺口。
  • 延迟口径不统一：主表 0.18 s/step 与插桩分解的约 1.04 s/step 相差数倍；主表各方法 TTFT 接近却延迟悬殊，未解释。
  • 近似复用的正确性检验只用 5 个上下文；没有给出“复用导致动作错误”的回合级统计。
  • 只做单智能体；作者自己指出多智能体并发更新共享记忆时的一致性问题未处理。
  • 模型规模小（3B/4B），上下文较短（主实验中 TTFT 约 22 ms，与表 14 中 5–10 个记忆块的量级相当），在长上下文大模型上收益可能更大，但也可能遇到更多近似误差，均 Not Reported。
  • 依赖注释如何获得、是否需要人工设计，正文描述不足。

研究价值

对 Agent 研究，这篇论文的价值在于把“记忆设计”的成本显性化：记忆检索越灵活、更新越频繁，前缀缓存就越失效，推理成本就越高。HeMeR 提供了一个可以落地的接口约定——记忆系统输出带 ID 和依赖的块，服务层据此复用缓存。这对任何每步都要重新拼接上下文的智能体（网页代理、代码代理、多轮工具调用）都适用。

对推理加速研究，它是“应用层语义指导缓存复用”的一个实例：服务层不必再从 token 序列里猜复用边界，由上层给出结构化提示。这与 SGLang 的 RadixAttention、CacheBlend 的选择性重算是互补关系。

可执行迁移（至少两条）

  1. 迁移到代码/网页智能体的上下文管理：把系统提示、工具说明、检索文档、近期观测分别作为带 ID 的块，记录依赖（如“工具输出依赖于对应调用”），在每轮只重算变化块。验证：在 SWE-bench 风格的多轮轨迹上回放，统计重算 token 比例（复制表 3 的格式），并对比 vLLM 前缀缓存命中率。
  2. 补做归因实验：在同一记忆架构下跑“完全重建”与“HeMeR 复用”，比较成功率差异及 Top-1 动作一致率（回合级），这能直接回答“KV 近似复用是否改变决策”。成本低，复用论文的种子与环境即可。
  3. 把漂移检测当作在线保护：利用表 18 的观察——驱逐与重排带来的 KL 最高——设定策略：当一步中驱逐/重排的 token 比例超过阈值，或距离上次全量刷新超过若干步，就触发一次完全重建，类似表 16 中的周期性刷新。

方向专用分析（Agent × Inference：记忆一致性与服务成本）

记忆一致性：HeMeR 的安全边界是“schema 一致才复用”。这把正确性问题转嫁给了 schema 的质量：如果依赖注释漏掉一条（例如“苹果在冰箱里”这条记忆其实依赖“冰箱已打开”），被复用的 KV 就会携带过期的上下文影响。论文的依赖密度实验（表 20）只研究了“依赖越多复用越少”，没有研究“依赖标错”的后果。

多智能体扩展：作者明确把多智能体并发更新列为未来工作。若扩展，需要类似数据库的版本控制：每个智能体持有一个记忆快照版本，块级 KV 带版本号，写冲突时失效。

服务成本：在作者的设置里，每步上下文较短，预填充只占单步时间的小部分（表 21 中局部重算 + 尾部预填充约 171 ms，而解码约 869 ms）。因此在小模型短上下文的具身场景下，KV 对账带来的端到端收益上限约为 20%（表 21：1,287.5→1,043.3 ms）。真正的大收益出现在记忆块很多的时候（表 19：128 块时相对成本 0.206、显存 22.0 对 46.8 GB）。

行为指标的解读：活跃动作比例和动作多样性在干扰项实验（表 17）中呈现非单调变化（30% 干扰时多样性反而升到 82.29%），说明这两项更适合做诊断，而不适合作为方法优劣的主证据。

Attack / Verification lens

  • 算术核对：71.43−52.86=18.57、76.27−61.80=14.47、76.27−59.40=16.87、83.20−64.28=18.92，与正文一致；表 3 各列加总一致（见算例 B）。
  • 口径冲突：主表 TTFT 相近而延迟悬殊；主表 0.18 s 与表 21 的 1.04 s 不可比。审稿式追问应是：Latency 的定义是否包含解码？各方法每步生成多少 token？
  • 归因漏洞：没有同架构完全重建的成功率；“近似复用让成功率提高”在逻辑上难以成立，提升更可能来自记忆设计。阅读时应把“效率贡献”和“成功率贡献”分开看待。
  • 统计强度：模拟器 5 个种子、真机每方法 10 次试验，标准差 2–5 个点；表 18 只有 5 个上下文。主要差距（十几个点）大于标准差，相对排名大体可信；小差距（如 KEEP 与 MemRL 在真机上 63.40 对 64.28）不应解读。
  • 如何独立验证：最便宜的是用开源模型 + 自建块级 KV 管理器回放一条 ALFWorld 轨迹，复现表 3 的 token 比例与表 18 的 KL；最有价值的是补上“完全重建”的成功率。

记忆总结

  1. HeMeR 是具身智能体的记忆服务层，目标是让异构记忆更新时尽量复用 KV 缓存。
  2. 三类记忆：陈述性（事实）、程序性（rank-8 LoRA 适配器）、工作记忆（当前进度）。
  3. 核心是记忆 schema：每个记忆块有持久 ID、类型、依赖、位置、KV 区间和适配器 ID。
  4. 每步按 ID 对比新旧上下文，分成复用、重排、插入、驱逐、重算五类，只重算受影响的块。
  5. 重排块用 RoPE 重映射修正 key 的位置相位；适配器切换时重算程序块及其依赖块。
  6. ALFWorld 回放：重算 token 从 74,784 降到 4,219，缓存处理时间 199.4 s 降到 25.8 s。

  9. 成功率提升缺少“同架构完全重建”对照，更可能来自记忆设计本身而非 KV 复用。
  10. 可迁移的思想：让上层记忆结构告诉服务层“哪些块变了”，用语义块代替前缀做缓存复用。

一句话定位

OPSD4MAS 把多智能体对话里“后面的人指出前面的人哪里错了”这类信息，提炼成原子事实、经两层过滤后作为特权上下文喂给同一个策略，形成一个“看得到未来的老师”，用老师与学生在学生自己生成的每个 token 上的对数概率差作为 token 级信用，再与 GRPO 的结局信号线性退火地合并训练。在 Qwen3-4B 的 Solver–Verifier 系统上，六个数学基准的平均 pass@1 比 GRPO 高 8.87 个百分点。

人话版

设想两个智能体合作解数学题：Solver 写解答，Verifier 检查，轮流发言直到模型自己决定结束。用强化学习训练它们时，常见做法是看最后答案对不对，给整段回答一个分数（标量奖励），再把这个分数平均摊到每个 token 上。

这里有一个浪费：对话本身包含大量“免费的批改意见”。比如 Verifier 在第二轮说“你第三步的系数算错了，应该是 2123=11×193”，这句话精确指向了 Solver 某个 token 的错误，但标量奖励只能说“整段回答要加强或削弱”，没法说“这几个 token 错了，那几个 token 是对的”。

OPSD4MAS 的做法分三步。第一步，请一个外部模型把某条回答之后若干轮（FW2 是两条、FW4 是四条）里出现的更正、警告、被验证的结论和策略，抽成一条条独立的“事实卡片”。第二步，过滤：先看这条事实跟同一道题其他轨迹的成败是否相关（粗过滤），再逐条拿掉这条事实，看它是否把目标回答的 token 概率往“该回答的 GRPO 优势所指的方向”推（细过滤）。第三步，把留下的事实贴到提示词末尾，让同一个模型在“知道这些事实”的情况下重新给学生已经生成的 token 打分；老师打分减学生打分，就是每个 token 的信用。

推理时完全不用这些东西：没有未来信息，也不调用外部模型，模型就是普通的 Qwen3-4B。

背景与缺口

LLM 多智能体系统（MAS）的强化学习方法大致两类。一类用结局奖励：MAGRPO 用共享奖励优化合作策略；DrMAS 把同一题、同一智能体的所有回答放在一起做均值方差归一化，得到“按智能体”的优势（Eq.3）。另一类用对话信号塑形奖励：MAPoRL 根据讨论中答案正确性的变化塑形验证器奖励，CoMAS 用基于互动的评判得到标量动作奖励。两类最后都落到一个标量。

在线策略蒸馏（OPD）与在线策略自蒸馏（OPSD）是另一条线：让老师在学生自己采样的轨迹上给出逐 token 的信号。OPSD 的老师就是学生自己（或其拷贝），只是额外看到学生看不到的特权信息。已有工作用过参考答案、同题的成功/失败轨迹、外部老师等作为特权信息；MAS-OPD 用冻结外部老师加验证器对过去冲突的归因，π-Play 让 EMA 自老师看出题人的构造路径。

缺口在于：没有人把“MAS 内部未来的对话内容”系统地变成特权信息。难点是对话质量参差不齐：有正确的更正，也有错误的论断和无关的过程描述。论文的消融（表 2）说明，直接把原始未来对话塞给老师，结果比纯 GRPO 差 16.39 个点。所以真正的问题不是“要不要用对话”，而是“怎么从对话里挑出可靠、对当前回答有用的信息”。

核心 insight

核心 insight 一句话：未来的沟通应该作为特权上下文，而不是压成奖励。放在老师侧，老师和学生是同一个策略的两种视图，它们在学生采样 token 上的对数概率差天然就是 token 级信用，不需要额外的老师模型 logits，也不需要把沟通打分。

难点随之转移到“给老师看什么”。论文的第二个 insight 是：一条事实影响大不等于有用，只有影响方向与结局一致的事实才该保留。图 5(b) 的例子：一条由 Solver 提供给 Verifier 的递推公式在 n=1 时给出 −7/13，与初始条件 a1=1 矛盾；它的关联分数为 1、影响幅度 E=0.295 很大，但净对齐 N=−0.141、方向精度 P=0.320，被 LOO 拒绝。反之图 5(c) 的更正 13×163=2119 应为 2123=11×193，E=0.522、N=0.246、P=0.795，被保留。

第三点是稳定性设计：沟通内容没有经过真值验证，所以 OPSD 项只作为辅助，用线性退火的权重与 GRPO 合并，训练后期主要由可验证的结局奖励主导。

方法逐步拆解

  1. 采样多智能体轨迹：Solver 与 Verifier 由 Qwen3-4B 初始化（非思考模式），按 DrMAS 与本文共享的自主交互循环轮流发言，由模型决定何时结束。每条轨迹 τj=(yj,1,…,yj,Tj)，结局奖励 R(τ) 只在结束时给出。训练数据为 DAPO-MATH-17k。
  2. 计算两种优势：GRPO 用 DrMAS 的按智能体优势 Aj,ir（同题同智能体的所有回答归一化，重复轮次分别计数）；关联过滤用按轨迹的优势 A(τj)（每条轨迹只计一次）。
  3. 事实抽取：对第 i 条回答，外部模型读取其后 W 条回答（FW2: W=2；FW4: W=4），抽取原子化的更正、警告、已验证结论和策略，保留来源与目标身份。提取器提示词要求它“自己验证被评回答，评语只是可错的证据”，并按优先级输出（附录 C 给出全文）。外部模型的具体型号 Not Reported。
  4. 关联过滤（粗）：外部模型给每条事实与同题每条轨迹标注关系：遵循 +1、违反 −1、无关 0。按 Eq.4 计算关联分数并排序，保留有限数量形成候选集 Ci（没有正分阈值）。排序依次看关联分数、关系覆盖、类型优先级（更正 > 警告 > 已验证结论 > 策略）、未来距离、事实 ID。来自“整组全失败”的已验证结论被排除。
  5. LOO 过滤（细）：用缓存的更新前策略打分，比较“含全部候选”与“去掉某一条”时目标回答每个 token 的对数概率差 δLOO，乘以目标回答的 GRPO 优势得到 z，算影响幅度 E、方向精度 P、净对齐 N。三者同时过阈值的事实，按 N、P、E 排序取前 K 条，得到最终集合 Fi。
  6. 老师打分与 OPSD 信用：把 Fi 以“[Privileged Future Lessons]”加编号的形式追加到最后一条用户消息，重新做一次 teacher-forced 打分；老师与学生的对数概率差乘以 λO=1 并停止梯度，得到每个 token 的系数。没有选中事实时该系数为零。
  7. 联合训练：每个角色的损失为 GRPO 截断代理损失加上退火权重乘以 OPSD 损失；OPSD 不用重要性比率、不截断，只有普通上下文下的对数概率带梯度。超出上下文预算时，先从末尾删事实，再删较早的非保护历史消息。

（1）DrMAS 按智能体优势（Eq.3）：

assoc(f)=∑jA(τj)rj(f)∑j|A(τj)||rj(f)|+ϵ

rj(f)∈{+1,−1,0} 表示轨迹 j 遵循、违反、无关于事实 f。分数在 [−1,1] 之间：“好轨迹遵循、坏轨迹违反”的事实得分接近 1。它是跨轨迹的、题目层面的相关性，不是因果。

Toy example（本文按论文公式自造的算例）

关联分数：同一道题有 4 条轨迹，按轨迹优势 A(τ)=(+1.5,+0.5,−0.5,−1.5)。某条事实与它们的关系为 (+1,0,−1,+1)（第 1 条遵循、第 2 条无关、第 3 条违反、第 4 条遵循）。分子 =1.5×1+0+(−0.5)(−1)+(−1.5)(1)=0.5，分母 =1.5+0+0.5+1.5=3.5，关联分数 ≈0.143，为正但不高——因为最差的那条轨迹也“遵循”了它。

LOO 三指标：设该事实进入候选集，目标回答有 3 个 token，拿掉它后对数概率差 δ=(0.4,−0.1,0.2)，目标回答的 GRPO 优势 Air=+1。则 z=δ，m+=(0.4+0+0.2)/3=0.200，m−=0.1/3≈0.033，P=0.200/0.233≈0.857，N=0.200−0.033=0.167，E=(0.16+0.01+0.04)/3≈0.265。按附录 B.3 的阈值，Strict（E≥0.10,P≥0.65,N>0.001）与 Relaxed（E≥0.005,P≥0.50,N>−0.001）都通过。

同一事实、相反优势：如果目标回答其实是失败轨迹里的（Air=−1），z=−δ，m+≈0.033、m−=0.200，P≈0.143、N≈−0.167，被拒绝。这说明 LOO 过滤是“针对目标”的：同一条事实，对一个回答是好老师，对另一个可能是坏老师。

对照论文案例：图 5(b) 被拒事实的记录分数 (A,E,N,P)≈(1,0.2946,−0.1409,0.3202)，与本例第二种情形同型：关联满分、影响不小，但方向错。

研究价值

对多智能体 RL，这篇论文提供了一个把“过程信息”转成“稠密信号”的通用模板：任何多轮交互里后来出现的信息（验证器反馈、工具报错、用户更正）都可以作为特权上下文，让同一个模型在“事后诸葛亮”视角下给前面的 token 打分。与训练一个过程奖励模型相比，它不需要标注，也不需要额外的价值网络。

更普遍的价值在于“特权信息需要方向性筛选”这一结论。最近大量 OPSD 工作默认“给老师更多信息总是好的”，表 2 给出了明确的反例与修复手段。这一判据（拿掉某条信息后，老师对学生 token 的评价是否与结局优势同向）可以直接迁移到用参考答案、检索文档、工具输出做特权信息的场景。

可执行迁移（至少两条）

  1. 迁移到工具调用智能体：把工具返回的报错与后续成功调用抽成事实，作为前面那次失败调用的特权上下文，用 OPSD 给出 token 级信用。验证：在多轮工具调用基准上比较纯 GRPO 与“GRPO + 原始工具日志 OPSD”与“GRPO + LOO 过滤 OPSD”三者，预期复现表 2 的模式。
  2. 把 LOO 方向判据用作特权信息的通用守门员：在任何以参考答案为特权信息的 OPSD 训练里，逐条（或逐段）做 LOO，只保留 P 与 N 过阈值的部分。成本是每条一次额外前向，可以只对优势绝对值大的样本做。
  3. 补做归因实验：用同一外部模型直接生成“参考解”作为特权信息（不经过 MAS 对话），比较与 OPSD4MAS 的差距，以分离“对话信息”与“外部模型知识”的贡献。

方向专用分析（Multi-Agent × RL：信用分配、协作与评测可信度）

信用分配：标量奖励在多智能体里有两层模糊——哪个智能体的功劳、哪个 token 的功劳。DrMAS 解决第一层（按智能体归一化），OPSD4MAS 在此基础上解决第二层。值得注意的是 LOO 用的正是 DrMAS 的按智能体优势，所以两层信用在方向上是一致的；而关联过滤用的是按轨迹优势，两者口径不同，作者特意区分。

协作是否真的被学到：论文的证据都是最终答案正确率，没有分析训练后 Solver 与 Verifier 的交互模式（例如 Verifier 指出错误的频率、Solver 采纳更正的比例、对话轮数）。未训练的 Solver–Verifier MAS 在 AMC23/AIME 上不如单模型，说明“协作”本身需要被训练出来；OPSD4MAS 是否改善了协作行为，还是只是让每个智能体单独更强，目前无法区分。

评测可信度：AIME 只有 30 题，pass@4 的一题就是 3.33 个点；所有方法单次训练；按验证集选检查点但验证集构成未说明。主结论（平均 +8.87）方向可信，但具体幅度应打折理解。另外，与 CoMAS 的比较中，CoMAS 的参数索引的是“可扮演不同角色的智能体”，与本文的“固定角色策略”不同，作者在附录 A 已注明。

Attack / Verification lens

  • 算术核对：我按表 1 复算了六基准等权均值：FW4 pass@1 64.33、GRPO 55.45（差 8.87）；FW2 58.27 对 DAPO 58.19（“接近”）；FW4−FW2 pass@1 6.06、pass@4 3.65；表 2 各行与表 3 的三数据集平均一致（如 No OPSD (68.07+48.33+32.50)/3=49.63）。
  • 潜在信息泄露：关联与 LOO 两层过滤都使用了基于真值的结局优势，老师上下文中的事实由“知道结局的过程”挑选。这在训练期是允许的（特权信息的本义），但意味着 OPSD 信号与 GRPO 信号并不独立，二者可能在“强化已经正确的轨迹”上重复计数。
  • 外部模型混杂：提取器提示词要求外部模型“自己验证被评回答”，等于让外部模型做一次批改。如果外部模型远强于 Qwen3-4B，方法的增益可能主要来自批改质量。论文未披露型号，这是最大的可验证性缺口。
  • 小样本与单运行：主表与消融均无方差；注入诊断明确“无显著性检验”。复核时应优先关注大幅差异（表 2 中 ±15–30 个点）而非小幅差异。
  • 如何独立验证：用公开代码与一个已知型号的外部模型，复跑“GRPO / 原始对话 OPSD / 完整 OPSD”三组，每组至少 3 个种子，在 AMC23 + AIME 上报告均值与标准差。

记忆总结

  1. OPSD4MAS 解决的是多智能体 LLM 强化学习里“信用太粗、对话被浪费”的问题。
  2. 它把后续对话里的更正、警告、验证结论、策略抽成原子事实，作为特权上下文。
  3. 老师和学生是同一个策略，老师多看到这些事实；两者在学生 token 上的对数概率差就是 token 级信用。
  4. 事实要经过两层过滤：跨轨迹的关联过滤，和逐目标的 LOO 方向过滤。
  5. LOO 的判据是：拿掉这条事实后，老师对学生 token 的评价变化是否与该回答的 GRPO 优势同向。
  6. OPSD 损失与 GRPO 线性退火合并，推理时不需要未来信息或外部模型。
  7. Qwen3-4B Solver–Verifier 上，FW4 六基准平均 pass@1 比 GRPO 高 8.87 个点，AIME 的 pass@4 最多高 20 个点（6 道题）。
  8. 最重要的发现：原始未来对话做特权信息会让训练变差（33.24 对 49.63），LOO 一步就带来 +21.92。
  9. 主要缺口：外部模型型号未披露、单次训练无方差、只测数学、计算开销未量化。
  10. 可迁移的判据：特权信息不是越多越好，必须按“影响方向是否与结局一致”筛选。
