S Budget Internalization: Fixed-Budget RLVR Trades Test-Time Scaling for In-Budget Accuracy

人话版：这篇论文到底干了什么？

做 RLVR 时，大家几乎都会给 rollout 设一个固定长度上限，例如 4k 或 8k token，理由通常只是省训练成本。这篇论文要问的是：这个上限会不会变成模型学到的行为，而不只是训练时的计算约束。作者在 Qwen3.5-4B、Gemma4-E2B 和 Nemotron-3-Nano-4B 上用固定预算 GRPO 训练数学与程序化推理任务，然后在从 512 到 64k 的多档评价预算上画准确率与输出长度曲线。结果非常尖锐：训练后的模型在接近训练预算处大幅超过基座，但一旦评价预算再加大，准确率几乎不再上升，甚至落到基座以下；同时它们几乎不再使用多出来的 token。作者把这种现象叫做 budget internalization，并通过对截断轨迹的不同计分、KL 锚定、以及在自然短轨迹与人为截断轨迹上做 SFT 的对照，说明它主要来自“被强化的成功轨迹有多长”，而不是某一个 GRPO 公式项。对 LLM 强化学习来说，这意味着只在训练预算附近报一个数字，可能同时掩盖能力提升和 test-time scaling 的损失。

背景与研究缺口

推理模型的一个核心卖点是 test-time scaling：给更长的生成预算，往往能解更难的题。DeepSeek-R1 一类工作把这条轴变成了可部署的能力。可是 RLVR 的训练惯例与这条轴并不对齐。为了避免序列长度带来的二次代价，训练几乎总是在一个固定 rollout cap 处截断，而且很多论文只在该 cap 附近做评价。如果模型只是“在训练预算内变得更会答题”，这种评价看起来完全合理；如果模型同时学会了“不要再想得更长”，只看一个预算就会给出相反的排序。

旧方法的缺口可以分成三类。第一，长度偏置文献（例如 Dr.GRPO）关心的是 1/|oi| 这类归一化会不会奖励短答案，但它们通常仍在单一预算下比较，不追问模型在更高预算上是否还能继续涨分。第二，s1 等工作提出的 budget forcing 证明：基座模型在低预算上常常是想得太长、没来得及给答案，强迫收束可以提高低预算准确率；这解释了基座在 cap 处的失败，却不能自动解释“训练后的模型在高预算上为何补不回来”。第三，过长惩罚、loss masking、KL 正则都是常见工程旋钮，但很少有人把它们放在同一套多预算曲线上，看谁真正保住了弹性。本文的贡献正是把评价协议改成“同一模型、多档预算、同时看准确率和输出长度”，并证明固定预算训练会把 cap 写进行为里。

核心洞察

观察来自一条交叉曲线，而不是某一个损失项。以 Qwen3.5-4B、4k 训练为例：在匹配的 4k 评价预算上相对基座是 +34.8 个百分点，到 64k 则变成 −30.2 个百分点；三个模型家族、两种训练任务上，十八条主实验都出现同样的交叉。更关键的是长度：64k 预算下，Qwen 基座平均输出 27.32k token，4k 训练后只剩 4.97k。这说明模型并不是“有能力写长但被解码器截断”，而是响应分布整体被压短了。消融进一步把原因从“GRPO 特有公式”挪到“哪些长度的成功轨迹被强化”：强迫截断轨迹给答案几乎消掉高预算落差，但也消掉预算内增益；在自然结束的短轨迹上做 rejection fine-tuning 不会内化预算，在人为截断的短轨迹上则会。因此，rollout cap 不是中性的成本开关，它在选择训练信号。

方法深读：从输入到输出

这篇工作的“方法”不是提出一个新优化器，而是把固定预算 GRPO 写成一个可以逐项改动的生成—计分—更新流程，从而定位 budget internalization 从哪一步进入训练。输入是一道可验证问题 q 和当前策略 πθold。输出是一组带奖励的完整或截断轨迹，以及一次策略更新。生成被一个预算 B 和一个终止协议 Π 约束：模型最多写 B 个 token；若在 B 处仍未结束，协议决定是直接截断、掩盖损失，还是补上结束思考标记并强迫给出答案。

标准设定里，奖励 RΠ(oi;B) 只给“完整且最终答案正确”的轨迹记 1，错误或截断记 0。优势 A^i 在大小为 G=8 的组内标准化。作者把完整目标写成

J(θ)=𝔼q~D,{oi}~πθold(·∣q;B,Π)[wB(q,{oi})∑icB(|oi|)ℓi−βDKL(πθ‖πref)].

预算从四个地方进来。第一，采样分布本身被 B 截断，长推理根本走不到结束符。第二，奖励 RΠ 把截断轨迹打成失败，等于对“还在想”施加负梯度。第三，长度归一化 cB(|oi|) 在标准 GRPO 中取 1/(G|oi|)，可能放大短正确轨迹。第四，KL 系数 β 决定更新还要不要锚在仍会写长的基座上。主实验取 wB=1（所有组都保留）、PPO clip ϵ=0.2、β=0。每一步用 32 个 prompt、每题 8 条 rollout，全局 batch 256，最多 300 次更新；Qwen 的峰值学习率为 5×10−7，Gemma 为 3×10−6，Nemotron 为 2×10−6。主对比在 DeepScaleR 上训练，Qwen 用 4k/8k cap，Gemma 与 Nemotron 用 1k/2k cap；另外在 Nemotron-RL-ReasoningGym-v1（15,000 条、来自 104 个可验证环境）上用相同超参复现。

一个反直觉但不容忽视的设计，是作者把“训练时如何对待截断”和“评价时如何对待截断”分成两套协议。训练默认给截断零奖励；评价时用 Inspect AI 报告 avg@k，截断答卷不得分。为了排除“基座只是低预算上没写完答案”这种解释，他们引入 Muennighoff 等人的 budget forcing：若到达预算 B 仍无解析答案，就保留推理前缀、插入模型特定的结束思考标记和答疑提示，再给一小段答题窗口。反向操作则针对已训练模型：拆掉结束思考与最终答案，追加 Wait，让它在 64k 上限内最多续写四次。若只是早停，往上逼应该能找回基座的高预算成绩；若训练已经压缩了推理内容，多写也救不回来。后文实验表明是后者。

消融协议也很干净：在 Qwen3.5-4B、8k cap、DeepScaleR 这一条标准跑上，每次只改上述因素中的一个，评价改为 AIME avg@16，并相对同一预算的基座报差值。改动包括：把数据换成更简单的 GSM8K 或更难的 Nemotron-RL-Math-v2；把截断处理换成 loss masking、DAPO 末 512 token 的软过长惩罚、或最多再给 120 token 的 forced-answer；把归一化换成 Dr.GRPO 的固定预算归一化；把 β 从 0 提到 0.001 或 0.01；最后完全离开 RL，用 rejection fine-tuning 分别拟合“自然在 4k 内结束的成功轨迹”和“把本来更长的轨迹在 4096 处截断再强迫给出正确答案”的轨迹。这样，方法部分给出的不是流程图，而是一条可复现的因果链：从 B 进入采样，到 RΠ 塑造被强化的长度分布，再到评价曲线是否交叉。

实现层面还有几处需要写清，否则别人很难复现这条因果链。主实验的 cap 被有意选在基座模型通常写完 AIME 所需长度之下，因此在每个被选 cap 上，基座生成都会频繁撞线；附录表 12 给出了精确截断率。每个生成预算还会额外预留 2,048 个输入 token，评价预算则只统计生成长度。验证每 10 步做一次，按验证准确率选 checkpoint。Forced-answer 训练并不是简单“允许再写一会儿”：它会先关闭被截断轨迹的思考段，再写入答案前缀，最多追加 120 个 token。RFT 的两条数据管道共享优化步数与超参，差别只有推理是否自然结束。反向 budget forcing 则最多续写四次，并在 64k 总预算下比较；附录记录它平均多消耗 2.58–2.74k token，却几乎带不回 AIME 的高预算分数。这些细节决定了“改的是终止协议”还是“改的是目标函数项”。

关键公式与目标

上面的 J(θ) 是分析用的总目标，不是新损失函数。逐条更新写作 ℓi=∑tmϵ−,ϵ+(ri,t)A^i(RΠ(oi;B))，其中 ri,t 是 token 级似然比，m 是双边 clip。与普通 GRPO 的差别不在advantage公式，而在 RΠ：标准设定把截断视为失败。Forced-answer 改变的是 Π 和因此产生的奖励支持，而不是把 B 写进网络输入。超参上，主实验 β=0，因此模型没有被明确要求留在基座的长推理模式附近；这为后续 KL 消融留下了对照。

手造 Toy Example

设想同一道 AIME 题，基座在 4k 处还在写推导、没有 boxed answer，得 0；放到 64k 才能写完并答对。用 4k cap 做 GRPO 时，所有写到 4k 仍未结束的轨迹都得零奖励，只有碰巧在 cap 内收束且答对的短轨迹得 1。几轮之后，策略学会尽早收束。再在 4k 评价，它比基座强，因为基座还在“想太长”；再在 64k 评价，它仍然写出大约 5k token 的短答案，而基座继续用 27k token 把更难的题做对。于是出现交叉。如果训练时对截断轨迹强迫给答案，短轨迹不再被系统性地标记为失败，交叉会消失，但 4k 上的增益也会一起消失。这个玩具例子就是全文的因果故事。

基线对照

主对照始终是同一家族的基座模型，在完全相同的评价预算与采样参数下比较。算法对照包括标准 GRPO、Dr.GRPO、DAPO 过长惩罚、loss masking、forced-answer、以及不同 β 的 KL 锚定。数据对照是 GSM8K、DeepScaleR 与 Nemotron-RL-Math-v2。监督对照是两种 rejection fine-tuning。最强的“看起来很好”的基线，其实是只在训练预算附近评价的标准 GRPO：它在 8k 上相对基座可到 +41.3 个百分点，但如果同时看 64k，它反而是损伤最大的设定之一。

实验设置

模型为 Qwen3.5-4B、Gemma4-E2B、Nemotron-3-Nano-4B。训练任务是 DeepScaleR 数学，以及 Reasoning Gym 的程序化可验证题。评价主基准是 AIME 2024/2025 的 avg@3（主曲线）和 avg@16（消融）；迁移基准是 GPQA-Diamond 与 LiveCodeBench v6。DeepScaleR/AIME 主对比使用种子 42/43/44，并同时报告验证集选出的 checkpoint 与最终第 300 步；其他实验多为单种子。评价开启 thinking，按各模型卡推荐设置温度与 top-k（Qwen 温度为 1.0、top-k=20）。预算只计生成 token，不含 prompt。训练框架为 NeMo RL，Qwen 用 Megatron，另外两个家族用 FSDP2。

结果与实验分析

研究问题一：固定预算 RLVR 是否只在训练预算附近变好，而在更大预算上失去 test-time scaling？ 设置是三个模型家族、DeepScaleR 上的两档 cap，AIME avg@3 多预算曲线，三条种子的均值与区间。观察非常一致。Qwen 的 4k 训练模型从 4K 的 +34.8 个百分点走到 64K 的 −30.2 个百分点；8k 训练模型从 8K 的 +42.4 走到 64K 的 −24.6。Gemma 的 1k/2k 模型在 16k 上分别落后基座 24.8 与 20.6 个百分点；Nemotron 对应为 25.4 与 13.1 个百分点。作者汇总：六个主要 checkpoint 在训练 cap 处的增益介于 +11.7 到 +46.7 个百分点，在各自最大评价预算上的亏损介于 −17.2 到 −35.0 个百分点。表 1 说明这不是分数平台，而是长度收缩：最大预算下，基座输出 6.11k–27.32k token，训练后只剩 1.01k–6.22k。Reasoning Gym 训练重复了同一交叉，例如 Qwen 4k 从 +31.1 落到 −25.0 个百分点。解释是：只要训练数据相对于 cap 足够难，截断零奖励就会把“写长”变成失败模式，策略于是把 cap 内化成自己的停止规则。

研究问题二：改变截断计分、归一化或数据难度，能否同时保住预算内增益和高预算弹性？ 设置固定为 Qwen3.5-4B、8k cap，只改一个因素，看 AIME avg@16。表 3 是核心证据。基座在 8k/64k 为 9.2% / 78.8%。标准 DeepScaleR GRPO 为 50.4% / 56.5%，即 +41.3 与 −22.3 个百分点。换到更简单的 GSM8K，8k 增益缩小到 +11.6，64k 亏损也缩小到 −6.8；更难的 Nemotron-RL-Math-v2 则仍是 +34.2 / −24.2。附录表 6 解释了数据效应：GSM8K 在 8k 处截断率只有 24%、中位长度 3,744，DeepScaleR 截断率 79%、中位 19,056，Nemotron-RL-Math-v2 截断率 99%、中位 60,879。截断处理上，DAPO 让权衡更差（44.2% / 50.0%），loss masking 不够（38.3% / 59.7%），forced-answer 几乎抹平高预算落差（7.0% / 77.2%），但也抹掉了预算内增益。Dr.GRPO 与标准 GRPO 几乎重合，说明 1/|oi| 不是主因。β=0.01 的 KL 把 64k 成绩拉回 70.1%，但 8k 从 50.4% 降到 32.4%。RFT 对照最能说明问题：自然短轨迹在 64k 上甚至略超基座（83.0% vs 78.8%），人为截断轨迹则掉到 40.4%。结论是：没有任何一种改动同时保住完整的预算内增益和基座的高预算成绩。

迁移实验补充了第三种面孔。在 GPQA 与 LiveCodeBench 上，高预算损伤明显小于 AIME，例如 Qwen 8k 训练模型在 64k 上只差 −2.2 与 −1.0 个百分点，同时平均长度从 11.15k 降到 4.56k、从 38.32k 降到 8.31k。这里的内化更像“改掉过思考”，而不只是丢失能力。Budget forcing 进一步显示：基座在 4k 上被强迫给答案后，AIME / GPQA / LCB 分别提升 8.9、56.2、14.5 个百分点；反之，把 4k 训练模型往上逼，AIME 在 4k 上反而掉 36.1 个百分点，64k 上几乎不涨。因此，训练后的损失不是“还想继续但被提前打断”，而是推理本身被压短了。

若把表 3 再和训练动态放在一起读，还会看到一个容易被忽略的失败边界。标准 GRPO 在 16k、32k、64k 三档上锁死在 56.5%，说明模型并不是“还在缓慢变好，只是没给够步数”，而是评价曲线在略高于训练预算处就冻结了。DAPO 的 8k 成绩（44.2%）低于标准 GRPO，64k 也更差（50.0%），说明单纯在末段加过长惩罚并不能把弹性买回来，反而可能强化“不要靠近 cap”。Loss masking 把 64k 从 56.5% 抬到 59.7%，但仍远低于基座的 78.8%，因为它只是不更新截断轨迹，并没有给模型一条“写长也可以成功”的正样本。最弱的结果其实是预算强迫的 RFT：18.5% / 40.4%，64k 相对基座跌了 38.4 个百分点，比标准 GRPO 的高预算损伤更大。它提醒我们：如果监督数据本身是被截断后再补答的，即使完全不做 RL，也会把 cap 写进模型。相对地，最强的“保弹性”结果是自然短轨迹 RFT 的 83.0%（64k）和 forced-answer GRPO 的 77.2%（64k），但它们都以放弃 8k 增益为代价。对部署而言，权衡并不总是负面：当任务更像 GPQA 或代码、基座存在过思考时，接受一定的长度收缩可能是有用的压缩；当任务更像 AIME、确实需要长链推理时，只看训练预算会选出一个更差的模型。

消融、主张与证据、局限

消融已经表明：改归一化几乎无效，改截断计分和数据难度最有效，KL 只是在两端之间滑动。作者主张可以概括为三句。主张一：固定预算训练会损害 test-time scaling，且在三个模型家族上可复现。实验确实展示了稳定交叉和长度收缩，主对比还有三种子。主张二：该效应可迁移，有时还能提高效率。GPQA 与代码上的高预算落差更小、长度明显变短，这一点成立，但“更小落差”不等于“没有损伤”，LiveCodeBench 上若干 checkpoint 仍落后数个百分点。主张三：预算内化来自被强化的长度分布，而不是某一个 GRPO 项，且不限于 RL。RFT 对照是这里最干净的证据。尚未被证明的是：更大规模模型、非 GRPO 算法、以及真正的多预算或预算条件训练，能否同时保住两端。局限也很明确：活跃参数只有四到五亿量级；多数实验围绕数学；除主对比外多为单种子；行为测量还不能区分“模型内部显式表示了 cap”还是“成功轨迹的长度分布被平移”。在 prompt 里写明预算也不可靠，未经这类 cue 训练的模型大体上会忽略它。

研究价值与迁移

原问题是：固定 rollout cap 会不会在不知不觉中卖掉模型的 test-time scaling。可迁移机制是“把评价协议改成多预算曲线，并把截断轨迹的计分当作一等公民”，而不是再调一个长度惩罚系数。新的研究问题是：能否把可用推理预算写成条件变量，让同一策略在低预算上保持紧凑、在高预算上仍能展开，而不把某一个 cap 内化成停止规则。方法修改上，最小可行实验不必从零设计新算法：在 Qwen3.5-4B 与 DeepScaleR 上，并列训练 B∈{4k,8k,16k} 的混合 cap，或在 prompt 中显式给出当期预算并在该预算内正常结束的轨迹上给正奖励，避免把截断一律记零。对照就是本文的标准 8k GRPO 与 β=0.01 的 KL 跑。指标必须同时包括 AIME 在 8k 与 64k 的 avg@16，以及 64k 下的平均输出长度；成功标准是 8k 增益接近标准 GRPO，同时 64k 不低于基座。预期贡献是一条可部署的预算条件 RLVR 配方。风险在于混合预算可能两边都学不彻底，或者模型学会在 cue 上投机。碰撞风险主要来自 Outcome-Mass Alignment、长度偏置 GRPO 与正则化分数中心化等已有工作，但它们很少以多预算交叉作为主指标，仍有差异化空间。计算成本大约是一篇中等规模 GRPO 论文的数倍，因为要画完整曲线并至少保留三种子。

五句总结

固定预算 RLVR 会把 cap 写成模型行为，而不只是训练成本。三个模型家族在预算内大涨、在更高预算上落后基座，并且几乎不再使用额外 token。截断计分和数据难度决定了这种内化，Dr.GRPO 式归一化几乎解释不了它。在自然短轨迹上做 SFT 不会内化，在人为截断轨迹上会，说明这不是 RL 独有现象。以后报告 RLVR，至少应同时给出训练预算和高预算上的准确率与长度。

S RL Post-Training in Diffusion Transformers Is Activation Steering

人话版：这篇论文到底干了什么？

扩散变换器经过 Flow-GRPO、DanceGRPO 或 GenRL 这类策略梯度后训练后，文字渲染、构图和偏好分数都会明显变好。一个很自然的想法是：这些能力是 prompt 相关的，所以权重更新必须学会输入相关的新变换。作者做了一个故意极简的探针：把基座所有权重冻住，只在每个 block 的输出上加一组与 prompt、token、随机种子都无关的常向量，然后用速度匹配去拟合公开的 RL 模型，目标里完全没有奖励。在 SD3.5-M 上，这组向量只有 0.29M 参数，约为 rank-32 LoRA 的 1.5%（18.8M 的约六十五分之一）。结果是：六个图像 RL 模型的奖励增益被恢复了 90.0%–96.3%，两个视频模型分别恢复 89.8% 与 111.9%。若从零开始、只用这些向量做 Flow-GRPO，它们在 OCR 与 PickScore 上甚至超过原来的权重 RL。作者据此提出一个强硬假设：当前政策梯度后训练，主要是把预训练生成器“推向它本来就算得出来的东西”，而不是教它全新的输入相关技能。

背景与研究缺口

扩散与流匹配模型的 RL 后训练已经从图像走到视频。Flow-GRPO 用组相对策略梯度更新 LoRA，DanceGRPO 可以全量微调，GenRL 与 VBVR-Pro 则把类似配方接到 Wan 系列视频模型上。这些工作通常把成功解释为“策略在奖励方向上学会了新的生成行为”。与此同时，语言模型里的 activation steering 表明：很多行为可以用加在隐状态上的常向量来开关。RaTE 已经尝试过给扩散模型的某个 prompt token 加可学习偏移，但那仍然是跟文本位置绑定的干预，恢复的增益有限。

缺口在于，几乎没有人测量过：RL 带来的奖励增益里，有多少其实可以被一个与输入无关的常移位解释。如果答案是“大部分”，那么把 RL 理解成低秩权重更新或新技能学习，都会过于乐观；如果答案是“很少”，才真正支持“必须做输入相关变换”的假设。更细的缺口还有三个。第一，平均激活差（steering 文献里最常用的构造）是不是已经足够，还是必须对输出速度做回归。第二，同样参数量的输入相关 LoRA 会不会明显更好，从而证明常向量只是粗糙近似。第三，这套现象会不会只存在于图像 LoRA，而不能推广到全量微调与视频模型。本文用八个公开 RL checkpoint 把这三问一次测完。

核心洞察

洞察不是“steering 有用”，而是“RL 后训练的有效更新，在输出空间里看起来像 steering”。权重更新 ΔW 作用在 token 输入 zi 上，得到输入相关的 ΔWzi；常向量 s 却对一个 block、一个引导通道、一个时间分段里的所有 token 加同一偏移。若这种与输入无关的偏移已经能恢复九成以上的奖励增益，而且从零训练这些向量也能得到全部增益，那么策略梯度多半是在选择基座已经具备的计算路径，而不是安装新的 prompt 专用模块。作者还发现，平均激活差 smean 远不够，必须做速度匹配；OCR 上 sfit 正交于 smean 的分量仍保留约 96% 的增益。增益随后主要沿着“图像 token 去读文本 key/value”这条联合注意力通路到达像素。于是，prompt 特异的表面变化，可以由共享移位加上冻结的注意力路由共同产生。

方法深读：从输入到输出

输入是一个冻结的基座扩散变换器 vθ、一个已公开的 RL 模型 vθRL，以及该 RL 模型在训练 prompt 上采样得到的干净隐变量 x0。输出是一组可在推理时直接相加的 steering 向量 s，或一组由 Flow-GRPO 直接训练出来的 sRL。采样遵循流匹配：噪声隐变量为 xt=(1−t)x0+tϵ，模型预测速度 v。SD3.5-M 使用 N=40 步，与 Flow-GRPO 一致，并用分类器自由引导把条件速度 vc 与空条件速度 v∅ 合成 v∅+w(vc−v∅)。FLUX.1-dev 是引导蒸馏模型，每步只有一次前向。

对宽度为 d、共 L 层的模型，记 hℓ,istr 为第 ℓ 层、流 str∈{img,txt} 上第 i 个 token 的 block 输出。Steering 定义为

h~ℓ,istr=hℓ,istr+αsℓ,p,kstr(t),对所有 token i.

向量由引导通道 p∈{c,∅} 和时间分段 k(t) 选择，与 prompt、种子和 token 都无关。主结果取 α=1，并把 N 个噪声水平均分成 K=2 段；SD3.5-M 的分界为 τ=0.75。这一设计有两个不显然的理由。引导尺度 w>1 时，条件通道的变化被乘 w，无条件通道被乘 1−w，符号相反，共享同一个向量无法独立控制两路；把通道拆开是为了让常移位也能改变引导后的净速度。早期步决定布局、晚期步修细节，RL 引起的平均激活变化也随时间改变，所以要分段。附录显示两段已保留八段能量的 83%–94%，一段与两段的奖励增益几乎相同。在 SD3.5-M 上，整组向量有 288,768 个参数。

拟合不用奖励。均值差基线 smean 把 RL 模型与基座在同一条 RL 采样轨迹上的 block 输出相减，并按 token、prompt 和时段平均；测量按层依次进行，避免同一变化被算两次。主方法改为速度匹配：

ℒ(s)=𝔼\|vθ,s(xt,t,yp)−vθRL(xt,t,yp)\|2.

期望遍历 prompt、RL 模型的终样 x0、噪声水平 t 和引导通道 p。两个网络始终冻结，损失按通道和时段拆成独立项。缓存样本、计算 smean 并完成拟合，图像模型最多约 17 个 H100 小时，视频模型约 70 小时。推理代价只是每个 block 输出一次向量加法。一个反直觉点是：拟合目标匹配的是速度，不是奖励，所以 sfit 既可能少恢复一些增益，也可能像 Wan2.1 那样超过 RL 模型。

为了检验“常向量只是容量不够的近似”，作者用同样的损失、同样的缓存样本和同样的更新次数，训练一个参数量相同的 LoRA。若输入相关性必要，这个 LoRA 应当明显更好。他们还把干预限制在条件通道、早期时段或文本流，以及做注意力路径置换：把图像 query 读到的文本 key/value 换回未转向的基座，看增益还剩多少。最后，他们冻住 SD3.5-M，从零开始只训练 sRL，跑 Flow-GRPO，让训练看见奖励但看不见那个已经调好的权重模型。这条路径用来回答：策略梯度自己会不会找到同样的常移位。

拟合与评价还有几条容易被忽略的实现约束。向量不依赖 token 数，因此在一个分辨率上拟合的 s 可以直接用到另一个分辨率，文中展示了从 512 到 768 与 1024 像素，以及不同采样步数和 CFG 尺度的迁移。单通道模型（FLUX.1-dev、Wan2.2-5B）丢掉通道下标 p。smean 必须沿 RL 模型自己的采样轨迹、在相同噪声状态上测量，而不能在基座轨迹上测量，否则比较的不是“同一点上的激活差”。式 (2) 的训练循环不需要奖励模型，这使它能作为事后诊断：只要有公开 checkpoint 和一组 prompt，就可以问“这个 RL 更新有多少是常移位”。在线 RL 路径则完全相反：它不看 vhetaRL，只看奖励，用来排除“我们只是在蒸馏教师”的解释。这两条路径必须分开读，不能把 sfit 的成功直接说成“RL 只优化了这些向量”。

超参上，主拟合与所有主结果都固定 α=1，避免把“加大转向强度”和“学会新方向”混为一谈；限制集合实验则使用与全组相同的配方和训练长度，以保证 12% 参数的结果可比较。

关键公式与目标

式 (1) 与权重更新的差别在于 ΔWzi 随 token 变化，而 s 在给定 (p,k) 下不变。Rank-1 LoRA ΔW=ba⊤ 可看成带输入相关权重 a⊤zi 的 steering，因此“同尺寸 LoRA”是检验输入相关性的正确对照。式 (2) 没有奖励模型，也没有在线采样，只是对缓存的 RL 轨迹做回归。第 5 节的注意力恒等式则解释共享移位如何变成 prompt 特异变化：若文本 key 与 value 发生共享偏移，图像 token i 的注意力份额 mi 与输出变化会依赖它自己的 query，从而把同一个 s 路由成不同像素效果。

手造 Toy Example

假设基座常把标牌文字写乱，Flow-GRPO 的 OCR 模型则能写出正确短语。不必认为网络新学了一个“认字模块”。速度匹配找到一组对所有 prompt 都相同的 sOCR，把它加到冻结基座的 block 输出上，图像 token 通过联合注意力去读被平移过的文本表征，于是在“需要写字”的 prompt 上走出另一条已有计算路径，在风景 prompt 上则几乎只表现为风格或对比度变化。若再把图像读文本这条路换回基座，正确文字会重新变回乱码。这个故事与文中图 8 和路径置换实验一致。

基线对照

主基线是各公开 RL 模型自身的奖励增益，以及训练免费的 smean。还比较了 prompt token 拟合、门控缩放、条件偏移、固定 prompt 后缀和更大 CFG，这些替代干预的增益都不到 steering 向量的 30%。同尺寸 LoRA 用来检验输入相关性。DreamBooth 的监督微调是对照性失败案例：那时 steering 只能恢复部分身份增益，同尺寸 LoRA 更好。最强的对照始终是原来的权重 RL 模型；steering 的主张并不是全面超过它，而是用少两个数量级的常参数恢复其绝大部分增益。

结果与实验分析

研究问题一：一个与输入无关的常移位，能在多大程度上解释已有 RL 模型的奖励增益？ 表 1 给出完整数字。六个图像模型上，sfit 恢复 90.0%–96.3% 的增益，例如 SD3.5-M PickScore 为 +1.416 / +1.560（90.8%），无 KL 的 PickScore 为 95.2%，OCR 为 94.4%，GenEval 为 95.9%，FLUX PickScore 为 90.0%，DanceGRPO HPSv2.1 为 96.3%。smean 明显更弱，OCR 仅 21.5%，GenEval 仅 12.2%。即使只看基座几乎不会的难题：在三个种子上失败、在第四个种子上测试的 146 道 GenEval 题中，基座只对 14.9%，sfit 仍恢复该模型 +0.641 增益的 97.7%。视频上，Wan2.1 的 HPSv3 恢复 111.9%，VBVR-Pro 规则分恢复 89.8%；域外任务族上，steering 增益 +0.0397，RL 模型为 +0.0474。解释是：RL 改变的有效方向，可以用与输入无关的速度回归捕捉；均值差之所以失败，是因为它平均掉了真正起作用、却不在平均方向上的分量。

研究问题二：如果策略梯度只能更新这些常向量，还能否得到全部增益？增益又从哪条通路到达图像？ 表 3 显示，从零训练的 sRL 达到 PickScore 增益的 103.6%、OCR 的 104.6%，用户研究中对基座胜率为 62%–65%，对原 RL 模型为 50%–52%，统计上打平。同尺寸 LoRA 在 SD3.5-M、FLUX 与 VBVR-Pro 上与 steering 的差异区间包含零；只在 Wan2.1 上 LoRA 更差（69.7% vs 111.9%）。相比之下，DreamBooth 监督设定中 steering 只恢复身份增益的 68%–83%，同尺寸 LoRA 更好，说明“常移位够用”并不是任何后训练都成立，而更像政策梯度这类奖励微调的结构。路径实验进一步显示：只干预条件通道、早期步和文本流的 35,328 个参数（全组的 12%）仍能恢复 OCR 增益的 89.5% 和 PickScore 的 73.7%。把图像读文本的 key/value 换回基座后，steering 的 OCR / PickScore 增益分别只剩 20.5% 与 10.5%；RL 模型自己也只剩 26.4% 与 24.5%。反向替换“文本读图像”则至少保留 84.4%。因此，共享移位是通过文本表征被图像 token 读到，才变成看起来像 prompt 技能的像素变化。

表 2 还表明，转向不仅复制训练奖励，也复制副作用：PickScore 模型的 HPSv2.1 与 ImageReward 增益、色彩能量下降（0.550 vs 0.542）以及多样性收缩，都被 sfit 复现。一个全局颜色变换只能解释约 8% 的 PickScore 增益，所以不是“只是把图调得更艳”。最弱的边界在视频推广与方法种类：主张覆盖的是两个确认有正增益的视频模型，而不是全部视频 RL；八个模型都是策略梯度，偏好优化与奖励反传尚未测试。作者也明确不声称 RL 更新本身低秩，也不声称 RL 模型“必须”内部使用这些向量。

把数字换成绝对增益后，还可以更清楚地看到“大部分”到底有多大。PickScore 上基座到 RL 模型是 +1.560 分，sfit 已经拿到 +1.416；OCR 上是 +0.344 对 +0.325。也就是说，剩下没被常向量解释的部分只有大约十分之一，而且 sRL 能把这十分之一也拿回来甚至更多，说明瓶颈在拟合，不在参数化。另一方面，Wan2.1 上 sfit 的 +1.465 超过 RL 模型的 +1.309，提醒我们速度匹配不是奖励最优：多出来的那截可能来自拟合残差对 HPSv3 恰好更友好。这也是为什么作者要报告百分位 HPSv3 与 VideoAlign overall 等额外分数，而不是只盯一个训练奖励。同尺寸 LoRA 在多数图像模型上“没有检测出优势”，不能被读成“LoRA 更差”，只能读成：在当前容量和拟合协议下，输入相关性没有带来可分辨的额外奖励。真正更弱的结果出现在监督身份学习，以及那四个在奖励上没有显著正增益、因而被排除出主表的视频 RL 模型——如果把它们强行算进“视频 RL 都是 steering”，主张就会过满。

消融、主张与证据、局限

作者主张可以分成三层，强度并不相同。主张一：常移位足以恢复大部分已有 RL 增益。表 1 的八个 checkpoint 给出了很强的支持，且对 LoRA 与全量微调、图像与两个视频模型都成立。主张二：策略梯度可以直接学会这些常向量，因此“拟合没拟合到的那部分增益”来自拟合过程，而不是来自向量形式本身。表 3 支持这一点，但实验仍限于 SD3.5-M 的 OCR 与 PickScore。主张三，也是最强的那句：政策梯度后训练主要是把基座推向它已能计算的内容，当前 RL 方法可能根本学不会新的输入相关变换。这是解释，不是已被证明的事实——DreamBooth 已经说明监督目标下输入相关性更重要，而且偏好优化与奖励反传还未测。局限包括：不声称必要性，不声称低秩；视频结论目前只有两个正增益模型；分辨率与步数迁移虽然在附录中显示可以从 512 转到 768/1024，但不等于任意视频长度与任意奖励都成立。

贡献

New Mechanism：用速度匹配的常向量作为 RL 后训练的诊断与替代参数化。Empirical Finding：八个公开图像/视频 RL 模型的大部分增益可被输入无关移位恢复，且直接对向量做 RL 可以超过原权重更新。Empirical Finding：增益主要通过联合注意力中“图像读文本”的通路起作用。

研究价值与迁移

原问题是扩散变换器的 RL 增益从何而来。可迁移机制是：先用一个故意没有输入相关性的探针去拟合或重新训练，再看还剩下多少必须归因于 ΔWzi。新的研究问题对用户更重要：语言模型的 GRPO / RLVR 是否同样接近 activation steering？最小实验可以是：取一个公开的数学 GRPO checkpoint，冻结基座，在若干 transformer 层输出上学习与 token 无关、但可按生成阶段分段的常向量，用对数概率或隐藏态匹配去拟合，再比较 AIME 或 MATH 上的 pass@1 恢复比例。模型可用 Qwen3.5-4B；基线是原 LoRA/全量 RL 与均值差向量；指标是恢复比例、以及只训练这些向量时的 RL 成绩。若恢复也在九成以上，将强烈暗示当前 LLM RL 同样主要是在选择已有计算路径。风险是语言生成的自回归结构与扩散不同，常向量可能不够。碰撞风险来自已有 activation steering 与表示工程文献，但它们很少用“恢复多少 RL 增益”作为主指标。计算成本低于再跑一遍完整 GRPO，更接近若干次教师强制的回归拟合。

五句总结

扩散变换器上的策略梯度后训练，看起来很像在学 prompt 技能，但大部分奖励增益可以被一组与输入无关的常向量恢复。速度匹配远优于平均激活差，同尺寸 LoRA 在 RL 设定下并不明显更好。从零只训练这些向量，就能达到甚至超过原 OCR 与 PickScore 模型。增益主要通过图像 token 读取被平移的文本表征到达像素。这并不证明所有后训练都是 steering，但它要求我们重新检验：当前 RL 方法到底有没有学会新的输入相关变换。

A Streaming-AAA: Streaming AAA Game Video Generation at High Resolution, High Frame Rate, and Low Latency

人话版：这篇论文到底干了什么？

把可玩的 AAA 游戏画面做成可交互的无限视频流，通常会在清晰度、帧率和操作延迟里三缺二。Streaming-AAA 的目标是在 NVIDIA A800 上同时做到 1080p、约 43 FPS、以及约 198 ms 的端到端操作到像素延迟，并且能连续玩很久而不崩。系统由三块组成：为高分辨率解码重设计的视频 VAE，带统一多模态条件的因子化 3D UNet 扩散模型，以及扩散强制预训练、分布匹配蒸馏和短长期混合 KV 缓存。实验在《原神》域内数据上完成，并与 HY-World1.5、Lingbot、Matrix Game 3.0、YUME 比较质量和效率。

背景与研究缺口

游戏世界模型与可交互视频生成最近进展很快，但现有系统往往在 480p–720p、每秒数帧、数秒级延迟上运行，长 rollout 还容易在大约 30 秒内出现重复纹理或风格漂移。扩散强制和自强制蒸馏提供了长时程和少步采样的工具，却很少被同时推进到 1080p 实时可玩。缺口因而是系统级的：既要保高分辨率细节，又要把历史记忆压缩到可缓存的 KV 里，还要把教师强制推理并行化，使动作到来时不必等待整段窗口重算。

与 FastFrames、ScoutCache、Condition Shifting 等近日视频加速工作相比，本文更强调可交互游戏闭环：控制信号必须在两步去噪内生效，记忆必须支撑镜头转回，而不能只优化离线少步采样。

核心洞察

实时可玩不是把离线视频生成器的步数减一减就行，而要把“干净历史条件 + 混合记忆 + 少步蒸馏 + 编解码流水线”当成同一套训练—推理协议。尤其是：短期连续 KV 与每隔 5 帧采样的长期 KV 在蒸馏和推理中必须共用同一布局，否则模型会在训练时依赖推理时并不存在的稠密历史。

方法流水线

任务被写成无限流式预测：pθ(xt+1:t+k∣x1:t,a1:t+k,mt)，要求因果生成、服从控制，并在分辨率、帧率、延迟约束下保持长程稳定。VAE 采用 4×16×16 的时空压缩，解码末端加 Pixel Shuffle，并用三阶段课程从 256×256 静态图走到高分辨率视频。扩散主干从 Stable Diffusion v1.5 初始化，去掉最大分辨率上的两个自注意力，时间模块从 2 块减到 1 块，总参数约 1.2B。条件（动作、天气、时间、帧率）先分别嵌入，再经因果交叉注意力注入。时间模块把已完成帧的 KV 写入混合缓存：长期记忆每隔 5 帧取一次，短期记忆保留最近 8 个 token，号称用有限缓存覆盖约 16 秒。训练分三阶段：64 帧（约 2 秒）扩散强制、640 帧（约 21 秒）长上下文预训练、以及 512 帧（约 17 秒）的自强制风格蒸馏。推理只用 2 步（时间步 999 与 666），把写 KV 与第一步去噪融合成 batch-2 前向，扩散与 VAE 分卡流水线，并分别使用 torch.compile 与 TensorRT。

人话版：这篇论文到底干了什么？

长程智能体一超出上下文窗口，就得决定丢什么。摘要、掩蔽或结构化记忆都要求在未来需求出现之前先做压缩，因而可能把稍后要用的精确值扔掉。GrepMem 的做法几乎故意原始：把全部交互追加进一份纯文本日志，需要时用正则搜索（grep）按需召回；工作上下文仍然可以总结或压缩，但历史本身是无损的。作者用同一套强化学习配方，在五种上下文管理策略下训练 Qwen3.5-9B，并在多问题调研、长流召回和智能体轨迹问答上比较。

背景与研究缺口

长程智能体的默认危机是窗口不够用。现有策略大致分成三条：把旧观察换成临时标记，把历史折叠成摘要，或维护一份有结构的记忆库。它们的共同前提是，系统必须在未来问题出现之前就决定保留什么。一旦任务是“在很长的键值流或日志里查找一个事后才知道的精确值”，这个前提就会失败。GrepMem 要检验的是一个更保守的假设：如果历史可以完整留下，而模型只被教会何时去搜、搜什么，那么许多看起来像记忆架构的问题，其实只是检索接口太弱。

核心洞察与方法

相关工作里的 SUPO、ReSum、观察掩蔽、MemGPT、Context Folding 等，都在“写入工作上下文之前”做取舍。GrepMem 把取舍推迟到查询时：算法维护有界工作上下文与一份只增不减的日志；每次消息、工具调用、工具输出和摘要都会追加。Grep 工具做不区分大小写的正则匹配，结果分页返回，也可以先只返回匹配行号。因为检索不是向量相似，智能体必须自己写出能对上原文的模式，而这一点正是 RL 要学的。

训练不单独监督摘要或 grep 查询，而是把任务动作、上下文管理与检索策略放在同一套强化学习里优化。对照策略有五类：ReAct（直到窗口耗尽都保留全文）、观察掩蔽、SUPO 摘要、MemGPT 风格记忆，以及 GrepMem。评价任务覆盖两类时间结构。BCP-Multi 把问题预先给出，智能体要在同一会话里跨问题复用发现；AMA-Bench 的 file/stream 与 ContextBench 的 KV Store / Log Triage 则在输入之后才揭示问题，更接近“先看见长流、后知道要问什么”。ContextBench 随着流长度远超窗口，专门考验精确值与计数。

人话版：这篇论文到底干了什么？

SFT 加 RLVR 很容易把策略坍缩到少数几乎相同的解法上，于是 pass@k 不再随 k 上升。ROAM-GRPO 给 GRPO 加一条旁路：当一道题在一组 G 条完成里已经有至少 k 条答对，就把它转到 off-mode 轨道，让模型在教师解法旁边再写“一种真正不同的方法”，用 LLM 裁判检查逻辑与差异性，再把通过的新方法自蒸馏回策略。

背景与方法

路由规则很硬：作者取 k=G=8，也就是一组全对才离开标准 GRPO。教师解法选组内中位长度，避免太短或太啰嗦；然后采样 H=16 条候选。合法性 τ 先核对最终答案，再用裁判检查推理漏洞；多样性 φ 同样由裁判判断是否与 Method 1 实质不同。实验在 Qwen3.5-2B 上用 LoRA（r=8,α=16）训练 MATH Level-5 的 1,000 题子集，裁判是 Qwen3.5-9B。对照包括从头 ROAM、标准 GRPO，以及在第 5,000 步才打开 ROAM 的 delayed 变体。评价集是 400 道 MATH-L5 和 400 道 Omni-MATH（难度 5–6），指标为 pass@k 以及正确解答嵌入的平均成对余弦距离（Qwen3-Embedding-0.6B）。

实验与意义

多样性确实被拉起来：MATH 上 ROAM 的 dispersion 约 0.09–0.14，GRPO 约 0.05–0.07，接近摘要中的 1.5–2 倍。代价是 pass@1 明显下降，例如第 6,000 步 MATH 上 55.5% 对 69.7%，Omni-MATH 上 14.4% 对 20.5%。pass@16 则大致打平：GRPO 峰值 MATH 91.0%、Omni-MATH 41.3%（均在第 5,000 步），ROAM 为 89.8% 与 43.2%。Delayed ROAM 在 Omni-MATH 上达到 46.0%，比 GRPO 峰值高 4.7 个百分点，但这条曲线随后波动，作者也承认不稳定。所以这篇工作更像是在展示一条“用 pass@1 换 pass@k 与方法多样性”的机制，而不是在标准单次准确率上刷新 GRPO。它与 Nov 16 的 Illusion of Diversity / Effective Entropy 直接碰撞：都在对抗 RLVR 的模式坍缩，但 ROAM 用的是可路由的离模采矿而不是熵或有效多样性正则。规模仍小（2B、1k 题、workshop），适合作为思想实验与可复现基线，而不是立即当作通用配方。

贡献、局限与关联

贡献是给 GRPO 补上一条可切换的离模采矿轨道，并用 pass@16 与嵌入离散度同时刻画多样性。局限也很明显：2B 模型和 1,000 道题的规模有限；delayed 变体虽然贡献了摘要里那个 +4.7 个百分点，但随后不稳定；降低 pass@1 在多数在线服务里很难被接受；LLM 裁判本身可能把“文风不同”判成“方法不同”。它更适合作为探索多样性的机制原型，尤其适合与预算内化、有效熵这类工作对照阅读：前者问模型还敢不敢写长，后者问模型还敢不敢写不一样。若要把它用到更大模型上，更稳妥的做法可能是 delayed 启动，并始终同时监控 pass@1 与 pass@16，而不是仅仅只去报告离散度这一项关键性指标。

B Query-Aware vs. Query-Agnostic Training-Free Video Token Pruning in Multimodal LLMs

人话版：这篇论文到底干了什么？

视频大模型的视觉 token 太多，训练免费的剪枝方法在“要不要用用户问题、怎么用”上一直说不清。这篇工作用同一套 Qwen3-VL 主干、同一 token 预算和同一解码设置，比较 21 条剪枝原则，覆盖查询无关、浅层查询条件、结构化查询条件和整体式选择。为后两类，作者提出 Structured Query Pruning（把问题分解成语义锚点）及其与视觉多样性结合的 Pareto 变体。

核心方法与发现

最重要的对照不是“用不用 query”，而是 query 如何进入选择。直接拿整句问题嵌入做相关性，在 Video-MME、MVBench 和 LongVideoBench 上会比最好方法低 8–16 分；把问题分解成词级锚点后，这一失败被避免。但查询条件并不自动更优：强的查询无关覆盖方法在全场比较中仍然有竞争力，甚至更好。相对只去冗余的基线，结构化选择在证据特定、长上下文、且预算很紧时帮助最大；在更宽泛的任务上，整体式选择比单用相关性或单用多样性更稳。

实验、效率与意义

在 InternVL3-8B 的 LongVideoBench 上，10% 预算时 Structured / Pareto 为 48.7%，PruneVid 为 46.9%（+1.8）。在 Qwen3-VL 的全场表中，10%/20% 保留下，查询无关的 GAP、VisionZip 等仍很强（例如 VisionZip 在 LongVideoBench 20% 上为 57.1%），而 raw-query 的 FastV 只有 48.8%。效率表 7（Video-MME，20% 预算，N=100）显示：不剪枝端到端 21.40 秒、显存 40.72 GB、TFLOPs 1207.8；PruneVid / VisionZip 等到约 14.3 秒、27.03 GB、264.6 TFLOPs；结构化与 Pareto 因为要付共享的 3.06 秒分解开销，端到端约 17.3–17.4 秒，生成时间却几乎相同（约 0.90 秒）。也就是说，剪枝真正省下的是预填与显存，查询分解是额外的固定税。设计规则因此很清楚：默认先保住视觉覆盖，只有当任务和预算确实需要选择性取证时，再加入结构化相关性。值得作为视频加速的对照实验来读，而不是作为又一个“新剪枝 SOTA”来追。

贡献、局限与效率表

贡献是一次控制良好的原则对比，而不是又一个不可复现的新方法声明。表 7 特别有用：在相同保留 token 数下，各剪枝方法的生成时间与 TFLOPs 几乎一样，真正拉开墙钟的是查询分解。把分解模型从 8B VLM 换成 Qwen3-0.6B，分解时间可从 5.44 秒降到约 3.2 秒，批处理还能再压到 0.69 秒每问，但主文默认仍把 3.06 秒计入端到端。局限是：没有公开代码；主结论依赖 Qwen3-VL 与 InternVL3 的特定实现；“覆盖优先”在极端紧预算、证据高度局部的任务上可能被推翻。与 DRAMA、FrameRouter 等近日视觉 token 工作相关，但本文的价值是把 query 的用法分层讲清楚。

12. Idea Mining

Idea 1. 预算条件 / 多预算 RLVR

Inspiration: Budget Internalization 证明单一 cap 会被写成停止规则，且没有一种单点消融能同时保住预算内增益和高预算弹性。

Research Gap: 现有 RLVR 几乎总是在一个固定 B 下训练，评价却常常假设模型仍能 test-time scaling。

Hypothesis: 若把可用预算当作条件变量，或在多种 cap 的混合分布上训练，并只对“在该预算内自然结束”的成功轨迹给正奖励，模型可以学会按预算展开，而不是内化某一个停止长度。

Proposed Method: 在 DeepScaleR 上对 Qwen3.5-4B 做混合 B∈{4k,8k,16k} 的 GRPO，或在思考段写入显式预算 cue，并把截断零奖励改成“预算条件成功”。

Minimum Viable Experiment: 复用本文标准 8k GRPO 与 β=0.01 KL 作为对照，训练一种多预算配方。

Model / Dataset / Baseline / Metric: Qwen3.5-4B；DeepScaleR 训练，AIME 2024/2025 评价；标准 8k GRPO、forced-answer、KL 0.01；AIME avg@16 在 8k 与 64k，以及 64k 平均输出长度。

Expected Contribution: 一条可同时保住两端的预算条件 RLVR 配方，或一份说明该目标目前不可兼得的失败报告。

Novelty / Feasibility / Compute: ★★★★☆ / ★★★★☆ / ★★★★☆（需要完整多预算曲线，最好保留多种子）。

Risk / Collision / Venue: 混合预算可能两边都学不彻底；与 OMA、长度偏置 GRPO、s1 budget forcing 相关但主指标不同。适合 ICLR / ICML / NeurIPS。

Idea 2. 用常向量探针诊断 LLM 的 GRPO 更新

Inspiration: Activation Steering 表明扩散 RL 的大部分增益是输入无关移位；这一探针尚未被系统用到语言模型 RLVR。

Research Gap: 我们仍不清楚数学或智能体 GRPO 学到的是新的输入相关算法，还是对已有计算路径的常方向选择。

Hypothesis: 冻结基座、在若干层输出上拟合与 token 无关但可按生成阶段分段的常向量，就能恢复公开 GRPO checkpoint 的大部分 pass@1 增益。

Proposed Method / Minimum Experiment: 对 Qwen3.5-4B 的公开数学 GRPO 模型做对数概率或隐藏态匹配，再从零只训练这些向量做 GRPO。

Model / Dataset / Baseline / Metric: Qwen3.5-4B；AIME / MATH；原 LoRA 或全量 RL、均值差向量；恢复比例与只训向量时的准确率。

Expected Contribution: 若恢复也接近九成，将强烈限制“LLM RL 在教新技能”的叙事。

Novelty / Feasibility / Compute: ★★★★★ / ★★★☆☆ / ★★★☆☆。风险是自回归结构与扩散不同。碰撞来自 activation steering 与表示工程，但很少以“恢复多少 RL 增益”为主指标。适合 ICLR / ICML。

Idea 3. 无损日志记忆与可进化 harness 的组合

Inspiration: GrepMem 在精确召回上极强、在因果推理上几乎不涨；Harness 进化能在不改权重的情况下改工具说明与技能。

Hypothesis: 把“追加日志 + grep 工具”当作 harness 的一部分，用 GEPA 进化搜索模式、分页策略和何时调用，而不是先上 RL 改权重，就能在 BCP-Multi 一类复用任务上接近甚至超过 GrepMem 的 RL 后成绩。

Minimum Experiment: 在同一 Qwen3.5-9B 与 BCP-Multi / ContextBench 上比较：冻结策略的 GrepMem、GEPA 进化后的 grep 技能、以及原论文的 RL GrepMem。

Metric: 五任务准确率、grep 调用次数、token 成本。Novelty ★★★☆☆，Feasibility ★★★★☆，Compute ★★☆☆☆。碰撞对象是 MemGPT、CarryOn、SCH 与 ModHarness-RL。适合 ACL / ICLR workshop 或 Agent 专项。

Idea 4. 用 steering 向量替代流式视频生成器上的权重 RL

Inspiration: Streaming-AAA 的后训练是分布匹配蒸馏，Activation Steering 显示视频 RL 增益也可被常向量吸收。

Hypothesis: 对已有游戏或世界模型 RL/蒸馏 checkpoint 做速度匹配，再用少量可训练向量代替全量后训练，可以在更低成本下保住大部分感知奖励，但可能保不住一小时不塌缩所需要的时序记忆。

Minimum Experiment: 在可公开的视频 RL 模型（如文中 Wan2.1 GenRL）上复现拟合，并把同一组向量接到更长 clip；主指标是奖励恢复比例、以及 30 秒 / 60 秒塌缩时间。Compute ★★★☆☆。碰撞来自 Flow-GRPO、GenRL 与各类视频蒸馏。适合 CVPR / ICCV / NeurIPS。

13. Collision Detection

⚠️ Collision Warning：YES。今日正式论文与近一周工作有多处重叠，但都还留有可区分的剩余问题。

  • Budget Internalization vs Outcome-Mass Alignment（Nov 14）、Dense Rewards in GRPO（Nov 13）、s1 式 budget forcing、以及长度偏置 / Dr.GRPO 文献。已解决的是“长度与预算会影响 RL 更新”；本文新提出的是多预算交叉与“截断计分塑造长度分布”。剩余问题是如何同时保住两端。
  • Activation Steering vs Flow-GRPO、DanceGRPO、GenRL、RaTE 以及激活转向文献。已解决的是“可以用向量改变生成”；本文新提出的是对已有 RL 增益的恢复比例，以及视频模型上的同样现象。剩余问题是偏好优化与 LLM RL 是否同样成立。
  • ROAM-GRPO vs Illusion of Diversity / Effective Entropy（Nov 16）、Restoring Diversity in distilled generators（Nov 17）。都在对抗坍缩；ROAM 走的是可路由离模采矿，规模较小。
  • GrepMem vs CarryOn、Falsification-Gated Memory、SCH（Nov 20）、Experience-Handoff、MemGPT、AgentFold。本文把无损检索做成强基线，而不是又一个复杂记忆模块。
  • Evolving Agent Harnesses vs ModHarness-RL（Nov 17）。都把 harness 当作优化对象；本文冻结策略并用 GEPA 进化文本态 adapter，强调可装卸与组合。
  • Streaming-AAA vs FastFrames（Nov 19）、ScoutCache（Nov 18）、Condition Shifting（Nov 13）、PQRS（Nov 20）。都在加速视频生成；本文的差异是 1080p 可交互游戏闭环与墙钟延迟。
  • Query-Aware Pruning vs DRAMA（Nov 14）、FrameRouter（Nov 19）及其他视觉 token 剪枝。本文的差异是控制对照，而不是单一新模块。
