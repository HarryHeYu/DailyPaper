Tier S（默认展开）

S · BACKFILL · Efficient Inference SubTernary：CPU speculative decoding 的统一图与事务KV

补充机制审查。接受率与事务正确性不是同一件事：标准speculative sampling以min(1,p(x)/q(x))接受候选，拒绝后从残差分布采样，才保证最终序列服从target分布。SubTernary的统一图只应改变arena、线程与KV地址，不得改变这条概率链。复现必须分别构造全接受、首token拒绝、中间第m个拒绝、连续两轮拒绝，逐元素对比KV和logit与完全重算reference；只测吞吐会漏掉rollback路径的污染。scratchpad复用时还要检查position id、mask shape、variable K和pointer偏移，确保旧轮次的KV既不被读到也不越界。

统一arena的代价。独立context以更多分配和同步换来清晰的所有权；统一arena改为“地址范围加事务状态”，使指针复位常数时间，却要求不变量：commit区域只能append、scratchpad仅当前轮可写、验证只读历史和因果前缀、reject后旧槽位不可见。应加入assert/fuzz：随机改变K、提高拒绝率、交替长短prompt，并与完整KV重算输出一致性比较。4/4分核输给8/0不等于顺序永远更优，只说明在此系统中draft→verify严格串行且都争带宽；多用户、NUMA、独立设备或Saguaro式branch预计算都可能改变结论。复制论文时应扫线程数、核绑定、上下文、K、acceptance、batch，并区分cold-start与steady-state。

成本与迁移。4.24×是吞吐相对AR，不能自动等于交互延迟缩短4.24×。主文未给p95、首token、RSS、能耗或并发公平性，故全部Not Reported。视频Agent真正可迁移的是事务语义：低成本视觉模型暂存“事件+证据帧+置信度”，全上下文verifier确认后再commit到检索库；reject仅使该版本不可见，保留日志供审计。若错误事件被commit并在10步内导致工具失败，就把负credit归给该memory write；被接受且未来成功复用才得正credit。这比只用最终success训练记忆写入更能隔离长期污染。

评测设计的进一步拆解。Table 1 是累积式消融，不能把各行倍率相乘：2.95×、3.64×、3.99×、4.24×都相对于同一AR基线，而1.23×、1.09×、1.06×才是相邻增量。以吞吐计算，统一图增加1.513 t/s，事务KV再增加0.752 t/s，ternary再增加0.552 t/s；这比一句“系统35%、kernel6%”更能指导下一步。还应补三个问题：context从2K升到8K/32K时copy和mask是否放大；acceptance降低时rollback仍否有优势；多并发是否因统一arena导致尾延迟。每个问题都需比较native SD、只统一graph、只事务KV、组合方案，且同时报tokens/s、time-to-first-token、p50/p95、RSS和正确性hash。没有这套矩阵，不能把单点吞吐外推成普适结论。

RL/Agent映射。SubTernary不是RL论文：它没有显式reward、advantage或credit assignment。若迁移到Agent，必须自己定义state为任务观察、memory版本、tool history；action为暂存、验证、commit、rollback；reward为任务成功减验证成本与污染惩罚；credit可由remove-one-commit的反事实对未来success影响给一次write。reward hacking是agent为避罚而不写memory，故还需检索覆盖和长期success约束。长轨迹证据不能用单episode替代，应报告10/100步的retrieval-harm曲线与错误版本隔离率。

与Video加速的对照。视频剪枝压的是视觉prefill上下文，SubTernary压的是CPU runtime动态管理；前者可能损失证据，后者目标是保持target分布。若两者串联，应先用full-video target建质量上界，再测draft视觉预算影响的acceptance，最后加事务runtime；不能在视觉剪枝已改准确率后仍把tokens/s称lossless。VideoLLM需要分别列Frames、visual tokens、target/draft是否压缩、prefill/decode latency、memory、accuracy和rejection率。今日论文未给这些video指标，因此这里只迁移运行时思想，不错误归类为视频论文。

复现实验的最小清单

功能层：固定greedy decoding，逐token比较AR和speculative；再用固定随机数流比较采样分布，确认rejection/residual不因统一graph而改变。事务层：分别让accept全部、首token拒绝、末token拒绝、连续rollback、K动态变化，导出KV指针和mask，检查下一轮logit等于reference。性能层：单独关闭graph cache、transactional isolation、ternary kernel，各五次以上，记录均值、标准差、CPU利用率、上下文切换、分配次数。稳健层：短prompt、2K/8K/32K、不同acceptance、单请求/并发。若不做这四层，收益可能只是warm cache或不公平配置；尤其不能让target/draft量化精度、线程数、上下文长度不同，再把模型差异误报成runtime贡献。

最小研究原型不必先重写引擎：把每次Agent memory write带版本号，verifier通过后才可检索，失败则保留审计日志而从索引移除。在100条固定轨迹上比较direct write、固定验证和事务写入，量化写错率、错误取回率、最终success、额外p95延迟。若验证太慢致success下降，假设被证伪；若success相近而错误取回明显降低，才值得扩展到多Agent共享memory和RL credit。这能把事务启发变成明确的可失败研究问题。

人话版

在CPU上跑大模型，普通speculative decoding看起来已经很合理：小draft先猜K个词，大target一次性验证；若猜对多个，就少读几次大模型权重。但真实运行时经常卡在“猜词算法之外”：draft与target在两个独立context来回切换，线程池重绑、计算图重建、KV回滚时复制缓冲区。就像仓库拣货员每拿一次货都要换仓库、重开工单；即使路线规划更聪明，切换成本也会吞掉收益。SubTernary 不把重点放在训练一个更强draft，而是让两张静态计算图共用一个内存arena和常驻线程池；把尚未确认的KV写入一块静态scratchpad，验证拒绝时仅移动写指针，像数据库事务rollback而不搬运数据。论文在8核Xeon、Llama-3.2-3B target/1B draft上报告：从autoregressive的2.190 t/s到普通llama.cpp speculative的6.468 t/s，再到系统runtime后的8.733 t/s，最终配ternary draft/AVX2为9.285 t/s。它的重要性是把“生成算法的速度”拆成模型、内存布局、同步和回滚四个可测部分。

可证伪预测

该机制至少给出两个可证伪预测。第一，若瓶颈确为context切换和KV复制，那么随着拒绝更频繁、rollback更多，事务版本相对双context基线的优势应扩大；若优势不变或消失，说明主要收益只是静态graph预热。第二，若统一thread pool的解释正确，改变K时最优线程策略应随阶段持续时间变化，而非总是八核顺序；若K很小或验证很快，调度收益可能收缩。论文主表只给一个context点，因此这是后续应补而非已被证明的结论。研究报告中把“已测吞吐”与“机制预测”拆开，才能避免让漂亮倍率掩盖适用边界。

Background & Gap

CPU解码通常受DRAM带宽限制：每生成一个token，都要把大量权重从主存送入计算单元。speculative decoding 把K个候选合成一次target批量验证，本可提高算术强度；但draft阶段仍按因果链逐token生成，target又必须等待K个候选到齐。更现实的是许多实现将draft、target分别置于独立runtime context：每个轮次切换graph、线程和KV地址。若某候选被拒绝，传统做法会分配临时buffer、复制cache或改映射；对CPU而言，这正是额外的memory traffic。反例很直接：把8个核固定切成4/4，理论上可并行，却在draft时让4个target核闲置，在verify时又让4个draft核闲置，并增加跨核同步。论文实测该分核只有4.17 t/s，而让所有线程顺序服务当前活动图达到8.73 t/s，说明这里的关键不是“同时跑两个模型”，而是尊重draft→verify的因果依赖并避免无谓上下文切换。

Method Deep Dive

状态与流水。给定已确认前缀 x₁…x_t，draft函数D按因果顺序产生候选 x̂₁…x̂_K：每一个x̂_i依赖前一候选，所以它无法与自身后续token并行。target函数T随后对整段候选做一次batched forward，得到每个位置的target概率。接受后commit前缀；首次拒绝则用target分布纠正并开始下一轮。SubTernary 不改变这条概率正确性链，改的是运行时如何承载它。

Unified Graph Caching。方法预先编译目标图 G_target 与草稿图 G_draft，并让二者都置于一个统一context C_unified：G_cached={G_target,G_draft}⊂C_unified。轮次中只把输入指针路由到相应graph offset，不重新分配arena、不重建计算图、不换线程池。一个容易误解的设计是它选择“顺序地把100%线程交给当前活跃模型”，而非把核永久切分给draft/target。原因并非两模型不重要，而是这两个阶段由候选依赖串起来，硬切分的空闲核没有可做的有用工作。可手算小例：K=3，draft先输出a,b,c；此时target才能同时计算a,b,c。若4核只留给draft，前半段有4核在空等；验证时反过来。统一pool让8核在每一段都被用满，消除的是串行链旁边的调度浪费，而不是宣称消除因果链本身。

Transactional KV Isolation。已验证历史KV放在前缀区域，候选K步的KV写到静态SpecScratchpad。验证attention mask允许当前候选看到历史和其因果前缀，却屏蔽未来与上轮残留scratchpad。若接受m≤K个候选，KV_ptr从t推进到t+m；若拒绝，KV_ptr直接回到t。由于数据并未复制到另一块临时区，rollback 是O(1)指针复位而非O(K)复制。这里的反直觉处在于“留下旧scratchpad字节”并不等于模型会读到它：mask显式把stale activations置为不可见。这个设计像数据库的write-ahead暂存区：未commit写入可以被遗忘，但其物理字节不必立即清零。风险是mask/指针任何实现错误都会泄漏旧候选，因此它需要强负向测试，而论文当前只报告系统吞吐证据。

低比特补充。系统还加入权重W∈{-1,0,1}的256-bit AVX2 ternary kernel，借符号/稀疏mask将乘法转为SIMD加法；draft用QAT+STE蒸馏，作者设定token acceptance至少70%。但论文自己的ablation显示，这是次要项：runtime构件贡献35.0%吞吐收益，kernel额外贡献6.0%。因此正确的核心机制是统一图+事务KV，不应把标题理解成又一篇主要靠ternary量化的论文。

Experiment & Results

设置。原文使用固定到8个物理核的8-vCPU虚拟环境，host为Intel Xeon Gold 5218；target为Meta Llama-3.2-3B-Instruct（Q8_0/FP16），draft为Llama-3.2-1B（Q4_0/TQ1_0），每个指标5次独立trial并报告均值±标准差，主对照是llama.cpp。这个设置回答的是单机commodity CPU throughput，不是GPU、在线视频或多租户服务。

RQ1：runtime修复比低比特kernel重要吗？Table 1在context=2048给出累积消融。AR为2.190±0.041 t/s；llama.cpp双context speculative变为6.468±0.112 t/s，即2.95×。加入Unified Graph Caching后为7.981±0.098 t/s，相对上一步1.23×、相对AR 3.64×；再加入Transactional KV Isolation为8.733±0.085 t/s，额外1.09×、总3.99×。这两段共同构成作者所说的35.0%系统收益。最后ternary draft+AVX2为9.285±0.076 t/s，额外1.06×、总4.24×。因此最强baseline（llama.cpp SD）到纯系统方案是6.468→8.733 t/s，绝对+2.265 t/s、约+35%；而低比特仅+0.552 t/s。这清楚回答“瓶颈在哪里”。

RQ2：为何不能把核一分为二？作者对4/4固定分核测得4.17 t/s，而顺序全线程分配为8.73 t/s，约2.09×。该结果支持阶段性全核策略，但它是一个特定CPU、模型和K/上下文配置下的证据，不能自动推断所有NUMA、多socket或高并发场景。文中还声明O(1) rollback latency，但本轮可访问主文没有给逐次rollback微秒分布、p95或内存占用表，所以这些指标应写Not Reported。

Ablation、证据边界与局限

消融的强处是将每一组件递增地测量，不把系统收益归功于kernel；也用4/4分核对照解释调度选择。作者的“3.99× from systems contributions”应理解为在该实施、该模型和2048上下文的吞吐结果。实验实际尚未证明：长上下文增长时scratchpad的空间上界、并发请求/多用户隔离、不同CPU ISA、提示长度与温度变化下的acceptance、生成质量和能耗。更重要的潜在失败是事务KV的正确性：一旦pointer或mask有off-by-one，旧候选可能跨轮泄漏；吞吐平均值无法证明这一安全性质。另一个工程风险是把两图塞入同arena可能增大常驻内存，主文未给RSS峰值，故不能宣称它降低内存。论文也没有Agent或Video实验，任何这类迁移都只能是研究设想。

Research Transfer：可执行的下一步

Original problem→可迁移机制→新问题。原问题是CPU speculative token的安全commit/rollback；可迁移机制是“暂存状态、显式验证、零拷贝撤销”。新问题是Agent在调用工具或写memory前，能否将低成本planner提议的动作写入事务轨迹，只在verifier检查通过后commit，从而阻止错误步骤污染长期memory？最小实验：以Qwen2.5-7B或Llama-3.2-3B为planner/validator，在ALFWorld或WebShop离线轨迹上比较：直接写memory、固定延迟验证、事务memory；记录task success、错误memory写入率、被后续retrieve的有害率、commit/rollback耗时与token。奖励可设为最终success减去错误commit和验证延迟，credit assignment给每次commit而非只给最后答案。可证伪假设：事务策略应降低错误持久化且不显著拉高p95；若工具环境的状态不可逆或verifier过慢，rollback只会增加延迟而无收益。成本与风险：两张24GB GPU或一张CPU+GPU即可做500条轨迹；最大的撞题风险来自已有agent sandbox/plan verification，差异化需落在“memory write transaction + causal blame”，并报告长期污染而非只报单轮成功率。适合 ICLR/NeurIPS systems+agents 交叉方向。

五句话总结

  1. SubTernary 证明CPU SD的运行时上下文与rollback常比新kernel更值得优化。
  2. 统一graph把重建/线程切换移出关键路径。
  3. 事务KV用scratchpad+mask+指针复位实现O(1)撤销。
  4. 主表从6.468到8.733 t/s的收益来自系统设计；9.285 t/s才含ternary。
  5. 它对Agent最有价值的迁移是“未验证状态不得污染长期memory”。

Tier A（折叠）

Saguaro / Speculative Speculative Decoding Inference · BACKFILL

原文。普通SD在验证完前无法开始下一次draft；Saguaro把验证结果表示为“接受前缀长度+bonus token”，并为多个可能结果预生成下一段草稿。命中时直接返回候选，未命中按batch大小选择fallback。原文报告bonus token预测最高90%准确、平均比强SD baseline快30%、最大相对AR 5×，在大batch仍优于SD约20%。其代价是分支计算可能爆炸，且需独立硬件；读者应重点比较cache hit、acceptance与fallback三者，而不是只看最大speedup。

SparseSpec-L Long-context KV · BACKFILL

原文。该方法以同一target模型的稀疏可召回KV做draft、完整KV做verify，用前一轮full verification的per-head attention作为无额外forward的索引，并用entropy与实测成本选动态speculation length。原文报告最高2.79×端到端加速；但搜索摘要未显示完整显存/各任务数字，故不夸大。机制价值在于“稀疏不是删除，而是可回忆的临时视图”，可迁移到视频/Agent memory cache。

Transactional Memory Commit for Tool Agents

Inspiration：SubTernary的SpecScratchpad与O(1)rollback。Gap：Agent通常把reflection/工具结果立即写进长记忆，错误会跨episode扩大。Hypothesis：将写入分为staged/verified/committed三态，并用未来retrieval harm作为credit，可降低错误持久化。MVE：Qwen2.5-7B、ALFWorld/WebShop，baseline为direct write、fixed verifier、AgeMem；指标success、false-write、harm-after-10-step、p95 latency。贡献：把系统事务语义转为可测Agent safety。新颖性★★★★☆，可行性★★★★☆，算力★★☆☆☆；风险是sandbox工作重叠，需突出跨轨迹污染。最佳venue：ICLR/NeurIPS。

Adaptive Branch Budget for Video Agent Verification

Inspiration：Saguaro分支cache与ParallelVLM视觉验证。Hypothesis：根据事件不确定度而不是固定γ选择“预验证多少可能动作/帧解释”，低不确定时保留单分支，高不确定时扩大branch。MVE：LLaVA-OV-7B、LongVideoBench/Ego4D；baseline uniform sampling、ParallelVLM、固定branch；指标video QA、latency、token、rollback率。新颖性★★★☆☆，可行性★★★☆☆，算力★★★★☆；风险是分支成本抵消收益。最佳venue：CVPR/ICCV。
