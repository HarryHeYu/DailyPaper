RL Highlights

今日 RL 线被两个互补问题切开。训练栈问题是：异步智能体给不了整齐的组相对基线，FlashREINFORCE 选择丢掉 sibling，改用批次中心化和序列门，并在 7B 工具实验里保住了 GRPO 已经丢掉的工具调用。适应问题是：测试时到底该改上下文还是改权重，Where Should LLM Agents Adapt 给出跨四个环境的配对证据，ICL 单独最强，GRPO 是稳定的加法，SDPO 不是。ECOD 则提醒我们，OPD 里真正缺的常常不是新损失，而是按任务完成经验来分配教师监督；它能把弱配方放大很多，但不保证在已经很强的 OPD 上继续涨。ViRA 把相对策略优化的分组对象从“同一输入的多次采样”换成“答案会被局部编辑翻转的对比集合”，这是奖励设计层面的贡献。BlockAlign 虽是视频论文，却把偏好优化的接口一致性写得很清楚：监督必须打在推理时真正查询的块平均速度上。

Agent / Multi-Agent Highlights

智能体线今天几乎都在问同一件事：长程交互里，信号应该打在哪一层。FlashREINFORCE 打在异步单轨迹更新能否稳定；ECOD 打在教师监督如何按失败轨迹和成功时长分配；Adapt 打在经验应该进上下文还是进权重；ViRA 打在视觉智能体是否真的读了证据而不是靠常识；ALIVE 打在流式视频里何时开口、何时沉默、何时追问。一个贯穿现象是：只优化最终成功，很容易学到偷懒或乱说话的策略——Adapt 里 ICL 会跳过检查，ViRA 里普通答案奖励分不出猜对和读对，ALIVE 则必须把沉默算进动作空间。今日没有新的大规模多智能体通信论文进入正式集，多代理更多出现在候选池的蒸馏与协作驾驶工作里。

人话版：这篇论文到底干了什么？

智能体强化学习里，工具调用和环境步进让每条轨迹耗时很不一样。GRPO 这类方法还要等同一题的一组 sibling rollout 到齐才能算优势，既压缩题目覆盖，又在异步系统里制造同步屏障。FlashREINFORCE 的做法是：每道题只采一条轨迹，用同一批互不相关题目的奖励均值当基线，得到可正可负的优势；再用序列级 KL 代理决定整条轨迹要不要进更新，并在轨迹内部先对 token 损失取平均，避免长失败轨迹在 token-mean 归约里被放大。这样可以在没有 critic、也不等 sibling 的前提下做一次过的异步更新。实验里，它在政策滞后约 4 步时把 DeepSeek-R1-Distill-Qwen-1.5B 稳定练到 6000 次更新；在 Qwen2.5-Math-1.5B 上用一半 rollout（256k 对 512k）把五基准均值做到 38.0，比报道的 GRPO 高 1.7 个百分点；在 ALFWorld 上 seen/unseen 成功率达到 98.3%/96.5%。

背景与研究缺口

长程智能体的 rollout 时长天然不规则：一次 Python 工具调用、一步 ALFWorld 交互，或一段长短不一的思维链，完成时间可以差出一个数量级。异步 worker 本可以把刚完成的轨迹立刻交给学习器，但以 GRPO 为代表的组相对方法，必须为同一 prompt 重复采样 G 条 sibling，才能构造组内基线。固定 rollout 预算下，这直接减少被覆盖的题目数；在线交互若只能得到一条轨迹，组统计甚至无法定义。把预算改成每题一条，覆盖面立刻上去，但代价也很清楚：没有 sibling 均值，二元奖励下未中心化的 REINFORCE 会让失败轨迹的学习信号变成零；若强行引入负优势，整条轨迹的每个 token 都会被惩罚，其中本来有用的中间步骤也被牵连。若再按 token 数做全局平均，更长的失败轨迹会获得更大的权重，负反馈被长度放大。

异步还带来第二层错配。学习器拿到的批次可能来自多个行为策略快照，token 级重要性采样只能纠正存储历史上的条件动作分布，历史本身仍服从行为策略。作者把剩余的替代误差与累积策略漂移联系起来，认为只做 token 校正不够，还需要一条轨迹级的准入控制。相关工作里，SAO 为异步单轨迹训练学习 value 基线，SPO 维护逐题统计，Seq-MIS 与 Trust Region Masking 讨论序列准入，DPPO 则用散度而不是比率裁剪来做近端更新。缺口在于：能否在无 critic、无参考模型前向、也没有 PPO 式比率裁剪的前提下，把批次中心化、序列信任和轨迹归一化拼成一次过的更新，并在长思维链、多轮工具和交互决策上证明它站得住。

核心洞察

单轨迹并不等于没有基线，只是基线不该再绑在同一题的重复采样上。把同一新鲜批次里互不相关题目的终端奖励取平均，就能得到有符号的优势，失败轨迹因此也有学习信号。真正要防的是两件事：一是行为策略已经走出信任区，还把整条过时轨迹写进梯度；二是长失败轨迹在 token-mean 里被不成比例地放大。前者用一条与奖励无关的伯努利 KL 代理做整段准入（而不是逐 token 掩码），后者先在轨迹内平均再在批次上平均。三者合在一起，异步单次更新才变得可训练，而不是把 GRPO 的组同步换成另一种不稳。

方法深挖

RL Formulation。状态是策略可见的历史 hi,t（含 prompt、已生成 token，以及工具或环境返回的观察）；动作 ai,t 是第 t 个生成 token；策略为 πθ(·∣h)，行为策略为 μi，其采样概率与轨迹一起保存，因为事后重算的“旧概率”未必等于当时真正的采样概率。奖励 Ri 是整条轨迹的标量终端奖励，轨迹 τi=(hi,1:Ti,ai,1:Ti,Ri)。没有 critic，因此也没有学习到的 value 或 GAE；优势来自批次中心化 Ai=Ri−R¯。重要性采样在 token 级进行，信任区在序列级用掩码 mi 处理，熵或 KL 惩罚不作为主损失项，信用分配默认把同一 Ai 赋给轨迹中每个 token，再靠样本均值抑制长度放大。

输入到输出可以写成一次过的循环。Rollout worker 定期领取策略快照，对每个 prompt 只采样一条轨迹并独立提交。学习器取出接下来完成的 B 条轨迹组成新鲜批次 ℬ（可以跨越多个行为快照），计算

Ai=Ri−R¯,R¯=B−1∑j=1BRj.

对二元奖励，若批次里两种结果都在，Ai<0 就是失败；对一般标量奖励，它表示低于批次均值。随后用已存储的行为概率计算 token 比率 ρi,t(θ)=exp(logπθ(ai,t∣hi,t)−logμi(ai,t∣hi,t))，并把行为分布与学习器分布都塌缩成“采到的动作 vs 其余词表质量”，得到伯努利 KL 代理

di,t=pi,tlogpi,tqi,t+(1−pi,t)log1−pi,t1−qi,t,

其中 pi,t=μi(ai,t∣hi,t)，qi,t=πθ(ai,t∣hi,t)。该代理与奖励无关，且是完整分类 KL 的下界，不必存储整份行为分布。再对轨迹取均值 D¯i=Ti−1∑tdi,t，定义 stop-gradient 掩码 mi=1[D¯i≤δ]。超过阈值的轨迹整段丢弃，而不是删掉若干 token 却留下同一条存储历史给其余项使用。

更新本身采用分离比率的样本均值损失

ℒ(θ)=−1B∑i=1BmiAiTi∑t=1Tistopgrad(ρi,t)logπθ(ai,t∣hi,t).

每个轨迹先在内部对 token 取平均，再在批次上以 1/B 加权；对比之下，token-mean 把轨迹 i 的权重写成 Ti/∑jTj，同样的平均 token 损失下，更长的失败会占更大份额。作者强调：token 级信号没有被改写，被改的只是轨迹之间的归约。一次优化步进之后，该批次即被丢弃，避免在同一批数据上做多次顺序 minibatch 而引入额外漂移。整个过程不使用 PPO 式比率裁剪、critic，也不需要参考模型前向。局部替代目标把历史分布固定在行为策略上，因此 token 比率只纠正动作项；序列门的作用是在累积漂移过大时，把整段不匹配的历史贡献一起拿掉。

一个最小的玩具例子能把三个部件分开。设 B=2，两条轨迹奖励为 1 和 0，则 R¯=0.5，优势为 +0.5 与 −0.5。若失败轨迹特别长，token-mean 会让负项主导一步更新；样本均值则让两条轨迹的权重同为 1/2。若失败轨迹的平均代理 D¯i 已越过 δ，掩码直接把它整段拿掉，正样本仍按自己的比率更新。输入是带行为概率的完成轨迹，输出是对 πθ 的一次梯度步。

Reward Analysis。主实验使用可验证的终端奖励：数学题看最终答案是否正确，工具实验看提交答案，ALFWorld 看任务成功。奖励是规则型、稀疏、轨迹级的，不是过程奖励模型。批次中心化让失败轨迹得到负优势，从而避免“只强化成功、失败无信号”；作者也承认这仍是粗粒度惩罚，失败轨迹里有用的中间步会被一并压低，附录讨论了可选的负 token 过滤，但主方法并不依赖它。与最终任务的一致性取决于这些可验证规则本身，论文没有单独分析奖励黑客，但工具实验里 GRPO 停止调用工具、本方法仍保持调用，说明学习信号会影响工具使用是否被保留。

Training Efficiency。推理基线比较中，FlashREINFORCE 在 step 2000 使用 256k 条轨迹，对照的 GRPO 与 C-RF+NTF 使用 512k；也就是用一半 rollout 得到更高的五基准均值。工具实验里每次更新固定 128 条 rollout：本方法覆盖 128 个 prompt 各一次，GRPO 则是 32 个 prompt 各采四次。ALFWorld 每次更新 64 条轨迹，在 step 200、共计 12.8k 条训练轨迹后评估。长思维链实验的政策滞后约为 4 次更新，30B MoE 工具实验把滞后放到约 8，并与滞后约为 1 的 GRPO 对比。论文没有在主文统一报告 wall-clock 或 GPU 小时，重点放在 rollout 预算、更新次数和滞后下的稳定性。

主张与证据、贡献与局限

主主张是：批次中心化的有符号反馈、序列级信任和样本均值归约，足以支撑无 critic 的单轨迹异步更新，并在推理、工具和 ALFWorld 上匹配或超过需要组同步的基线。证据方面，稳定性有 6000 步滞后 4 的曲线和 30B MoE 滞后 8 的续训；样本效率有 256k 对 512k 的五基准均值；工具保留和 ALFWorld 的大幅度领先有表格直接支撑；三个部件都有对位消融。需要收窄的地方是：部分数学子任务并未超过报道的 GRPO，对照数字来自另一组同步训练，训练栈与随机种子并不完全同构；符号优势仍然是轨迹级粗惩罚；交互环境还不够宽。贡献主要是把已有的 IS、信任区和中心化基线，收成一套可在异步生产约束下运行的一次过算法，并提供到 30B MoE 的证据。研究价值在于：很多智能体 RL 系统真正的瓶颈不是再写一个更复杂的 critic，而是如何在不规则、单次、过时的轨迹上仍能稳定更新。

最小可执行迁移

若已有异步 rollout 与可验证终端奖励，不必先上 critic。最小路径是：worker 每题只采一条轨迹，把当时的行为 log-prob 一并存下；学习器按完成顺序凑满一个批次，用批次均值中心化得到优势，用存储概率算 token 比率，再用伯努利 KL 代理的轨迹均值做一次硬门控，然后对分离比率损失做一次优化步进并丢掉该批次。建议先在一个小模型和数学或单工具环境上跑通，把批次大小设成与现有 GRPO 的组大小乘组数相当，例如 128，政策滞后先控制在 2 到 4 次更新。

对照协议要写清楚。同一 rollout 预算下，把 GRPO 的若干 sibling 改成同样数量的不同题目，记录平均准确率、工具调用次数、响应长度、截断率和训练—推理 KL 代理。不要只看最终准确率，因为 token-mean 的崩溃首先出现在长度和截断率上。若训练后期熵升高或 KL 代理持续上扬，优先收紧准入阈值，而不是急着加回 PPO 裁剪。一个很便宜的健全性检查，是复现正样本-only 对照：若拿掉负优势后工具调用消失，说明当前任务确实依赖有符号反馈。风险在于批次过小会使批次均值噪声变大，以及该代理漏掉未采样动作上的漂移；这两点都适合作为第一轮诊断。若目标环境更接近 OSWorld 或多工具仓库，应先确认终端奖励能在轨迹结束时自动给出，再放大模型和滞后，否则中心化基线会变成噪声源。若只需验证算法能否在现有训练栈里跑通，一天内可以先在 1.5B 模型和百级批次上复现“新鲜批次优于顺序 minibatch”这一条，再决定是否上 7B 工具环境。

五句总结

GRPO 的组相对基线与异步智能体的单轨迹到达方式是冲突的。FlashREINFORCE 用跨题目的批次均值代替 sibling 基线，用序列 KL 代理筛掉漂移过大的整段轨迹，并用样本均值阻止长失败主导更新。它在滞后约 4 的条件下把 R1-Distill-1.5B 稳定练到 6000 步，并用一半 rollout 在五基准上达到 38.0 的均值。更关键的现象是：在 7B 工具实验里 GRPO 停止调用工具，本方法仍保持调用，并在 ALFWorld 上把 unseen 成功率做到 96.5%。迁移时先保存真实行为概率、先上批次中心化与序列门，再决定要不要引入更细的过程奖励。

人话版：这篇论文到底干了什么？

少步自回归视频扩散已经能把长视频一块一块接着生成，但每一块仍要跑完若干次去噪，并且反复阅读历史 KV、再为后面的块建缓存。现有加速方法往往只打其中一段，后两项仍然贵。ScoutCache 是一套训练无关的框架：Conditional Denoising Readout（CDR）用浅层特征变化和已知噪声差，估计中间去噪更新，从而在第三个去噪步跳过大部分 Transformer；Output Risk Guided Historical KV Reading（ORHR）按注意力输出扰动，把有限的历史阅读预算分到不同层和头；Content and Coverage Guided Sparse Cache Construction（CCSC）则在进入 Transformer 之前按内容变化和空间覆盖挑选 token，降低建缓存成本。三个模块都在视频前几块上在线校准，不改预训练权重。在 Self-Forcing 上最长做到 2.28 倍加速，在 LongLive 上做到 1.86 倍，并且 VBench-Long 的 Total Score 不降反升。

背景与研究缺口

少步自回归视频扩散把长视频切成潜在块，每块条件于已经生成的内容。典型设置里，一块包含三帧潜在、四个去噪步，前三步之后还要再加噪；去噪网络 Dθ 读取文本条件与历史 KV 缓存，最后还要在零噪声时刻额外前向一次，才能为后续块写出 KV。于是推理成本至少分成三截：去噪本身、历史 KV 阅读，以及缓存构建。TeaCache、FlowCache、MotionCache、SVG2、Dummy Forcing、Forcing-KV 等训练无关方法，以及需要额外 2000 次后训练迭代的 Light Forcing，分别从步间缓存或 KV 共享切入，但很少同时处理这三截，也很少解释为什么历史依赖在层和头之间差得很大、在块与块之间却相对稳定。

近期与“少步、流式、缓存”相关的工作很多，包括用条件平移做少步流式生成，或用特征缓存跳过层。它们解决的是相邻步或相邻块之间能否复用计算，但并不直接回答两个更细的问题：第三个去噪步的干净潜在更新，能否由浅层特征差和已知噪声差读出；以及在固定的历史阅读预算下，应该把预算分给哪些层、哪些头、哪些空间位置。若这两个结构可以被前缀块校准出来，就不必为加速再去改预训练权重，也不必在每一步都做完整的 Transformer。

核心洞察

作者给出两条可观察的结构。第一，浅层特征的空间变化与干净潜在估计的变化相对应，打乱空间位置会破坏这种对应，说明中间去噪更新可以被一个廉价的条件读出头近似。第二，历史 KV 的重要性随 Transformer 层和注意力头变化，但在后续视频块上相对稳定，因此阅读策略可以在前几块校准，再沿时间复用。ScoutCache 把这两条观察分别写成 CDR 与 ORHR，再用 CCSC 在构建缓存时兼顾内容变化和空间覆盖。关键不是再蒸馏一个更小的视频模型，而是把“这一段计算值不值得”的判断，变成可以在单次推理前缀里估计的量。

方法深挖

问题设定针对已经训练好的少步自回归视频扩散，参数 θ 保持固定。记 xb(s)、zb(s) 为第 b 块在去噪步 s 的带噪输入与预测干净潜在，文本条件为 c，历史缓存为 ℳb−1。一块三帧、四步，前三步之后按噪声系数 σs=ts/1000 再加噪：

zb(s)=Dθ(xb(s),ts,c,ℳb−1),
xb(s+1)=(1−σs+1)zb(s)+σs+1εb(s+1).

其中 εb(s)~𝒩(0,I)，且 xb(1)=εb(1)。第四步得到的 zb(4) 被解码成视频帧，并在零噪声时刻再做一次前向以写入后续 KV。ScoutCache 对前三块做完整计算并完成校准，从第四块起启用加速。

CDR 的输入是当前块在第二步的完整预测，以及第三步只跑完第一层 Transformer 后的浅层特征。记 Hb(2),Hb(3)∈ℝN×d 为这两步的第一层输出，N 是每块 token 数。条件特征把已知噪声差和浅层差拼在一起：

Φb=[𝒫(σ3εb(3)−σ2εb(2)),(Hb(3)−Hb(2))Ps,1N],

其中 𝒫 把潜在排成 N 个维度为 p 的补丁，Ps 是固定高斯投影，投影维 rs=128，并加一列截距。校准发生在第 2、3 块：目标更新是 Yb=𝒫(zb(3)−zb(2))，把两块的特征堆成 X，先做 RMS 列归一化，再解带正则的最小二乘得到映射 B。正则排除截距，强度取 λ=m=193。得到的 B 每个视频只算一次，之后共享。对 b≥4，第三步不再跑完网络，而是

z^b(3)=𝒫−1(𝒫(zb(2))+ΦbB),

再用式 (1) 构造下一步带噪输入，第四步仍走完整网络做最终修整。输出是被加速后的干净潜在，而不是一个新的生成器。

ORHR 处理历史阅读。历史缓存被分成四个区域 ℛ={0,1,2,3}：视频第一帧作为固定锚点，再加上前一块的三帧；当前块始终参与注意力。对每一层 ℓ 和每一头 h，方法选择一个非空子集 Sℓh⊆ℛ。为避免为每个候选子集重算注意力，它把区域统计（区域内归一化输出与对数配分）做成可复用的量，再用注意力输出扰动定义风险，在全局预算 ℬ=720=2LH 下做分配。校准使用第三块上的 120 个查询、随机投影维 ro=32，之后的块复用这套阅读策略。直觉很直接：有的头几乎不读历史，有的头高度依赖锚点帧或最近一块，若对所有头统一读四段历史，预算会被不敏感的头浪费，敏感的头反而读不够。ORHR 用“拿掉某段历史后注意力输出会偏多少”来定义风险，因此分配的是输出误差，而不是注意力权重的表面大小。一旦子集在前缀上选好，后续块不再重新搜索，这是它能保持稳定加速的原因，也是它对镜头突变更敏感的原因。

CCSC 把缓存构建从“先稠密再压缩”改成“进 Transformer 之前就选空间位置”。它用内容变化 δf(i) 和覆盖/陈旧性指示构造优先级：从未被覆盖或超过陈旧阈值 A=18 的位置获得额外优先级，再在每个 2×2 空间组里选一个最高优先级位置。这样每块处理 3510 个 token，而不是稠密构建的 4680 个，并且与 ORHR 的历史阅读策略兼容。优先级里的覆盖项很关键：如果只按内容变化选位置，空间上容易扎堆在运动物体周围，背景和尚未变化的区域会被长期跳过，历史缓存就会留下空洞。把“从未覆盖或已经过时”提升成硬优先，再在组内做局部选择，是为了让稀疏缓存仍然覆盖整个空间格子，而不是变成又一种运动区域裁剪。

一个最小例子是 120 秒长视频。前三块完整计算，同时拟合 CDR 的 B 和 ORHR 的阅读子集；从第四块起，第三去噪步只跑第一层并用读出头补更新，历史 KV 只读被选中的区域，建缓存时只处理被选中的空间组。输入是预训练少步模型和一条文本提示，输出是加速后的视频帧序列，模型权重始终不动。把三步连起来看，输入输出边界非常清楚：CDR 的输入是浅层特征和已知噪声，输出是第三步干净潜在的估计；ORHR 的输入是校准查询上的区域注意力统计，输出是每层每头的历史子集；CCSC 的输入是各空间位置的内容差与覆盖状态，输出是本块要写入缓存的 token 集合。

主张与证据、贡献与局限

主主张是：利用浅层特征与历史依赖的可校准结构，可以在不改预训练权重的情况下，同时降低少步自回归视频扩散的去噪、历史阅读和缓存构建成本，并且长视频质量不降。证据来自两个主干、四个时长的墙钟加速与 Total Score，以及配对检验和部件消融。最强基线应视为 Dummy Forcing 与 Forcing-KV 这一档，而不是已经掉点的 MotionCache。局限包括：没有报告理论 FLOPs 与显存；短视频上质量并非处处第一；校准依赖前缀块；尚未看到在更大主干或更高分辨率上的重复。贡献是把三条推理瓶颈放进同一个训练无关框架，并给出可复现的分解数字。

最小可执行迁移

若已经在用 Self-Forcing 或 LongLive 一类少步自回归视频模型做长视频推理，不必先重新蒸馏。最小路径是：保持官方 1.3B 检查点和采样日程不变，对前三块做完整前向；用第 2、3 块的浅层差与噪声差拟合一个正则最小二乘读出头，只在第三去噪步替换完整网络；同时在第三块上收集注意力区域统计，按输出风险为每层每头选出历史区域子集；建缓存时按 2×2 组做内容和覆盖选择。先在 30 秒 MovieGen 子集上对比官方主干、Forcing-KV 和自己的实现，主指标用墙钟时延、FPS 和六个 VBench-Long 维度的 Total Score，并固定提示与种子。

如果只想验证一个部件，优先复现 CDR：它单独就能带来约 2× 的加速，也最容易在现有推理循环里插入。ORHR 需要改注意力阅读路径，适合作为第二步。评估时必须把校准时间计入时延，否则短视频上的加速会被高估。风险是前缀校准在镜头切换或提示控制发生变化时失效，因此要额外准备一组“中途改指令”或硬切镜头的提示，作为失败边界测试。计算成本方面，单卡 A100 40GB、batch 1 即可复现论文设定，不需要重新训练 1.3B 主干。若对照方法复现困难，至少保留官方主干和 Forcing-KV 两个锚点，因为它们是论文中质量和速度都较强的参照；不要只用已经掉点的 MotionCache 来证明自己“又快又好”。记录时把去噪、建缓存和校准三部分分开，这样才能判断加速到底来自读出头还是来自稀疏缓存，也便于和附录 Table 4 对齐。

五句总结

少步自回归视频扩散的推理成本不只在去噪步数，历史 KV 阅读和缓存构建同样昂贵。ScoutCache 用前缀块校准三个训练无关模块：用浅层差读出中间去噪更新，按输出风险分配历史阅读，并在进网络前稀疏地建缓存。它在 Self-Forcing 上把 120 秒生成从 264.32 秒降到 115.78 秒（2.28×），Total Score 从 75.03 升到 79.11。LongLive 上加速到 1.86×，质量同样上升。迁移时先插入 CDR 并计入口径完整的墙钟时延，再决定是否改注意力阅读路径。

人话版：这篇论文到底干了什么？

多轮语言智能体的环境奖励又稀又晚，On-Policy Distillation（OPD）于是在学生自己生成的上下文上，用教师的稠密反馈来补信号。问题是：标准 OPD 并不问“这个任务上教师到底比学生强多少”“这条学生轨迹是不是已经成功了”，也不按教师成功轨迹的长度来分配回合权重。ECOD 把监督分配写成三层：用匹配任务条件下教师和学生的成功率后验做能力校准，只在学生失败的轨迹上直接施加教师监督，再用教师成功执行的长度给出回合级时间先验。得到的权重既可以乘在教师损失上，也可以乘在教师派生的优势上，因此能接到 SOD、TCOD、ATOD 以及 GRPO/GiGPO 式的 OPD 上。在 Qwen2.5-1.5B/7B 的 ALFWorld 与 WebShop 上，配对相对增益平均为未见成功率 6.20%、WebShop 7.05%。

方法与实验

RL Formulation 仍然是多轮语言智能体：状态是到当前回合为止的对话与观察，动作是思考加工具调用，策略是学生 π，奖励是任务成功或归一化的 WebShop 分数，轨迹是完整的多轮交互。OPD 的额外信号来自教师在学生上下文上的 log-prob 或优势，而不是再训练一个 critic。ECOD 不改这个骨架，只改监督怎么分配。任务层比较教师与学生在匹配条件下的成功后验，教师相对更强时才加大系数；轨迹层把直接监督限制在学生失败的轨迹，避免已经成功的 rollout 被教师再拉一遍；回合层用教师成功轨迹的长度做时间先验，让监督更集中在任务真正被推进的区段。作者强调，这与只按散度加权或只做时间退火的变体不同，因为它显式用“会不会做完任务”的经验来校准。

实验用 Qwen2.5-1.5B-Instruct 与 Qwen2.5-7B-Instruct，环境是 ALFWorld（seen/unseen 成功率）和 WebShop（成功率与任务分）。每个方法都有不带 ECOD 的配对基线，教师与基础教师系数保持一致。未见与 WebShop 指标是固定权重下八次解码的均值和样本标准差，箭头是未四舍五入均值的相对变化。

1.5B 上，最刺眼的提升出现在纯 RL 和部分蒸馏配方：GRPO 的未见成功率从 57.56% 到 74.16%（相对 +28.85%），seen 从 61.43% 到 75.00%；WebShop 成功率从 54.49% 到 68.46%（+25.63%）。SOD+ECOD 的未见从 66.98% 到 81.34%（+21.45%），WebShop 从 62.40% 到 75.88%（+21.60%）。在已经很强的 GiGPO-OPD 上，ECOD 仍然把未见从 87.31% 推到 89.55%（+2.56%），但 WebShop 成功率持平。也有反向结果：1.5B 的 ATOD+ECOD 未见从 78.64% 降到 73.51%（-6.52%），尽管 WebShop 仍从 71.88% 升到 77.83%。7B 上增益更不均匀：GiGPO+ECOD 达到未见 91.32%、WebShop 82.71%，相对 GiGPO 分别 +4.37% 与 +11.01%；但 GRPO+ECOD 的未见与基线同为 72.39%，对 GRPO-OPD 的 WebShop 甚至从 77.05% 降到 75.39%。作者汇总 SOD、TCOD-F2B、ATOD 在两套模型上的配对相对变化，得到 ALFWorld unseen 平均 6.20%、WebShop 平均 7.05%，WebShop 单对增益介于 2.29% 与 21.60%。

人话版：这篇论文到底干了什么？

反复进入同一类环境的智能体，比如同一个代码仓库、同一套应用或同一个数据库，会碰到共享潜在结构的任务。经验既可以留在上下文里（ICL），也可以写进权重（GRPO 或自蒸馏 SDPO），但这两条通道通常被分开研究。这篇论文用同一套在线协议把它们放在一起比较：智能体遇到匹配的任务流，先在适应当前任务之前接受评估，并且只能从自己的尝试和环境反馈中学习。一共比较 14 种适应机制加一个无状态基线，模型是 Qwen3.5-9B，任务是 SWE-bench Verified、AppWorld、ScienceWorld 与 BIRD-Critic-SQLite 上的 109 个任务，每个环境 5 种任务顺序。单独看，最强 ICL 把跨环境平均成功率从 28.8% 抬到 49.4%；再加上 GRPO 得到最高的 51.6%。轨迹分析表明，ICL 会少做查找、缩短尝试，但也常跳过对当前任务的检查与验证；把 GRPO 接上去，能在保留“少查找”的同时，把这些核查行为补回来。

方法与实验

协议把每个任务的一轮拆成：准备上下文、在未针对该任务做适应之前评估、再根据自身尝试更新状态。ICL 的策略由保留方式（FIFO 或 Prefix）和准入方式（All 或只保留 Successful）组合而成，得到四种冻结权重策略。权重更新有两条：用可验证奖励做 GRPO，以及用自蒸馏做 SDPO；它们既可以单独使用，也可以接到任一 ICL 策略上。无适应的 Frozen、No ICL 是基线。评估只计每题第一轮、适应之前的结果，先在环境内对任务平均，再对四个环境等权平均，并在 20 个环境—种子流上做配对比较。

Agent 架构是带工具的多轮交互：输入为任务与可选的历史上下文，经策略产生尝试，再写回环境反馈。智能体状态要么是上下文中的经验文本，要么是被 GRPO/SDPO 更新的权重，或二者并存。长程问题在这里体现为跨任务的流，而不是单任务内的一千步；失败会沿流传播，表现为后续任务复用了错误经验，或 ICL 过早跳过检查。

人话版：这篇论文到底干了什么？

轨迹蒸馏已经能把视频生成器收成少步模型，例如 Parallel Decoding Distillation（PDD）和 Parametric Trajectory Distillation（PTD）。如果还想用偏好优化去对齐这些已经部署的少步模型，直接套用常规流匹配目标会错位：那些目标假设的是单头、局部速度监督，而 PDD/PTD 实际执行的是有限区间上的块平均速度，并且只在合法的块边界上起步。作者把只监督起始子区间、却在推理时用融合块平均速度的做法称为 DirectAlign，并指出它会引入训练—推理不一致，质量甚至掉到未对齐的蒸馏基线以下。BlockAlign 的修复是：状态只构造在合法块边界，查询融合后的块级速度预测器，并用跨度归一化的转移残差做监督；同一套接口可以接 DPO、NFT 和 rollout 式目标。再配上离线对、半在线续写和在线 rollout 的统一后训练管道，以及按目标感知的块调度。在 MiniMax-H3 Ref2VA 和内部模型 RefVid-V4 上，相对 PDD 基线的人工偏好为 54.0% vs 33.3%（非平局胜率 61.8%）和 51.3% vs 34.7%（59.7%），对 DirectAlign 的胜率最高到 82.7%。因为直接优化少步模型，PDD 的 5 倍少步 rollout 加速被转换成约 3 倍的端到端在线训练加速。

方法与实验

标准流匹配在任意时间戳预测瞬时速度；PDD 则在块 [sb,eb] 上做一次宏观跳跃，并用多个子区间速度头在块边界融合成块平均速度。PTD 更直接保留平均速度头。因此，后训练若仍对任意时刻的瞬时速度做偏好更新，梯度会推到推理时根本不会走的接口上。BlockAlign 把被监督的状态限制在块起点，让损失对准融合后的块平均速度，并用跨度归一化残差来匹配有限区间转移。目标函数本身不新，新的是接口一致：DPO、NFT 或 rollout 式偏好都可以接到同一个块级预测器上。Objective-aware block scheduler 再按噪声区间把结构、主体交互和纹理细化分到不同块，避免所有偏好信号都打在最后的纹理步上。训练数据与反馈同时覆盖离线偏好对、无奖励的半在线续写，以及在线 rollout 上的分层偏好选择。

效率上，论文强调的是训练侧而不是推理侧再加速：少步模型已经提供约 5× 的 rollout 加速，对齐又不必再回到教师模型上微调和重新蒸馏，端到端在线训练大约快 3×。推理分辨率、FPS、显存和理论 FLOPs 没有作为主指标系统报告，故在效率表中记为 Not Reported；它解决的是“少步模型怎么直接对齐”，而不是“再砍一步推理”。

主证据是人工偏好，而不是自动指标独占。在 RefVid-V4 上，BlockAlign 对 PDD 基线的胜/负为 54.0% vs 33.3%，非平局胜率 61.8%；在 MiniMax-H3 上为 51.3% vs 34.7%，非平局胜率 59.7%。作者称这些差异具有统计显著性。对 DirectAlign 的胜率最高到 82.7%，这与方法叙事一致：接口错位的对齐不仅无助，还会明显劣于不做对齐。质量描述集中在结构合理性、参考一致性和视觉质量，实验是多参考视频生成，而不是开放的纯文本生成排行榜。

需要谨慎的地方是：偏好数字来自特定的 Ref2VA 设定和内部模型，外部无法直接复现内部 RefVid-V4；5× 与 3× 是相对 PDD 少步 rollout 与端到端训练时间的陈述，正文没有提供可独立核对的完整 wall-clock 分解表。它与近日的 ReDiverse、eDMD 都讨论少步蒸馏后的质量，但问题从“蒸馏本身”转到了“蒸馏之后如何做接口一致的偏好优化”。失败边界是清楚的：若忽略块融合接口，对齐会伤害质量；若没有合法块边界，这套目标甚至无法定义。

BlockAlign 的可迁移观点很具体：对任何把瞬时速度换成区间平均速度的蒸馏生成器，偏好优化必须打在推理时真正查询的那个接口上。最小实验是在一个已有 PDD 或类似块蒸馏的视频模型上，并列跑 DirectAlign 与 BlockAlign，用同一组参考视频做偏好或一致性评估。若 DirectAlign 明显掉点而 BlockAlign 上升，就重复了本文的核心现象。计算成本相对从头训练要小，因为优化的是已经蒸馏好的少步模型，但仍需要偏好数据或在线奖励模型。局限是公开可复现性不完整，且缺少系统的推理效率表。

人话版：这篇论文到底干了什么？

超高分辨率视觉智能体通过缩放到相关区域来回答问题，但现有智能体常常靠常识猜，而不是去读那一小块证据。只对最终答案做 RL 纠正不了这件事，因为猜对和读对拿到的是同一份奖励。CrossRPO 的做法是在对比集合上训练：同一个问题配上若干只在证据区域做了微小修改、因而答案不同的图像版本，只有真正读到证据才能做对整个集合。方法奖励“做对整个集合”，并证明它不会强化靠常识答完的集合。作者构造了 21 到 120 百万像素编辑对比集 ViRA-Train / ViRA-Bench，以及用真实拍摄变化排除编辑痕迹的 ViRA-Bench-Real，再用大约 3500 条数据把 ViRA-9B 与 ViRA-27B 各训一遍。CrossRPO 在 ViRA-Bench 最大分辨率上达到 63.3% 的集合准确率，高于逐版本 GRPO 的 59.3% 和 pooled GRPO 的 52.6%；去掉跨输入权重后是 58.7%。ViRA-27B 在该基准的每个分辨率上都超过论文测试的专有模型，两个模型也在多数公开基准上成为同尺寸开源智能体里最准的一档。

对智能体研究，这一点很硬：相对策略优化的分组对象不该默认是同一张图的多次采样，而可以是“答案被局部编辑所翻转”的一组输入。失败边界同样清楚——如果跨输入权重来自其他问题的照片，优势就消失，说明增益依赖对比集本身，而不是某种泛泛的正则。局限是训练和主基准仍大量依赖编辑痕迹，尽管 Real 子集被用来做排除；计算与工具调用开销也需要对照专有模型的 token 数来看，论文提到 Claude Haiku 5.5 在最大思考设置下要用掉 ViRA-9B 约 2 到 6 倍的 token。它适合作为视觉智能体 RL 的机制补充，而不是今日的深度主文。

消融从同一份 Qwen3.5-9B、同一数据、奖励、协议和步数出发，只改优势估计。集合准确率在最大分辨率上按 CrossRPO、逐版本 GRPO、无跨输入权重、pooled GRPO 递减；把跨输入权重换成其他问题的照片后，收益接近消失。论文还观察到 ViRA-9B 缩放到目标物体的频率与逐版本训练相当，但读对物体的比例更高，说明提升主要来自“读什么”，而不是“更勤快地放大”。对 Agent 线，这是一个可执行的奖励设计：先构造能翻转答案的对比输入，再把相对优势定义在集合而不是单次采样上。计算成本方面，约 3500 条数据就能训起 9B/27B，但评估必须走多分辨率预算，不能只报单点准确率。

人话版：这篇论文到底干了什么？

流式视频语言模型已经能持续观察世界，但往往把用户请求当成彼此孤立的问题来答。ALIVE 把交互式流视频理解写成三类能力：主动监测、流式任务协调，以及会寻求反馈的交互。它构造了 ALIVE-SFT-288K 与 ALIVE-RL-3K，分两阶段训练：对比监督微调教模型何时以及如何回应，随后用 Behavior-Aligned Credit Assignment（BACA）把轨迹级优势和局部优势结合起来，在多轮交互里同时调整决策、回复和保持沉默。作者还提出 FSI-Bench，专门评估寻求反馈以及随后的任务完成。在公开基准上，ALIVE 的总体分数在对比模型中最高：OVO-Bench 全部分数为 68.9，超过 AURA 的 65.3 和 Qwen3-VL-8B 的 54.2；StreamingBench 为 76.0，超过 AURA 的 73.1 和 VideoChat3 的 68.7。论文称在另外两个公开基准和 FSI-Bench 上也保持最高总体分。局限是它仍是视觉语言模型，口语交互还要外接 ASR/TTS；与 ScoutCache 那样的生成加速也不是同一问题，它优化的是交互策略，而不是去噪或 KV 缓存。对今日视频线的意义是：流式模型的下一步不只是更快地看完视频，还要在时间轴上决定说不说、何时问。

方法上，对比 SFT 使用动作策略和回应门控的成对样本，明确训练“现在该说话还是该沉默”；BACA 则避免把整段多轮轨迹当成一个不可分的奖励包，从而让局部错误（例如不该打断时开口，或该追问时保持沉默）也能被信用分配捕捉。这与普通视频 QA 微调的差别在于：输出空间包含延迟和沉默，而不只是答案文本。公开表上的领先也不是均匀的，例如 OVO-Bench 某些细项上 AURA 仍然更高，ALIVE 的优势更明显地出现在需要跨时段追踪的项目，如 HLD 的 87.1 对 AURA 的 58.6。迁移时，若已有流式视频骨干，最小步骤是先加回应门控的对比 SFT，再用一个小规模 RL 集（论文是 3K）微调何时开口；评估必须包含“不该说话”的片段，否则总准确率会掩盖过度主动。它与近日 StreamEmbed、CarryOn 等记忆/流式工作相邻，但场景是视频时间轴上的交互策略，而不是文本或视觉 token 的缓存压缩。若要接到今日的视频加速线上，更自然的组合是：用 ScoutCache 一类方法降低生成或回放成本，用 ALIVE 决定在已加速的流上何时介入，二者不要混成同一篇贡献声明。

  • Inspiration: ScoutCache 证明前几块可以校准出去噪读出和历史阅读策略；ALIVE 需要在持续视频流上决定是否开口。
  • Gap: 前者针对少步视频生成，后者针对流式理解与交互，二者都在“时间块 + 历史 KV”上花钱，却还没有被接在同一条推理管线上。
  • Hypothesis: 若理解模型同样存在“浅层变化预示后续计算必要性”的结构，前缀校准可以降低交互式流视频的墙钟时延，同时不明显伤害 FSI-Bench 类的时机决策。
  • Method: 先在冻结的流式视频骨干上探测浅层特征与后层输出的对应，再只对高风险块跑完整计算。
  • Minimum Viable Experiment: 在一个公开流式理解骨干和 ALIVE 的评测协议上，报告时延、FPS 和开口时机准确率。
  • Model: Qwen3-VL-8B 或 ALIVE 发布的检查点。
  • Dataset: OVO-Bench / StreamingBench 子集 + 若干长视频。
  • Baseline: 全计算流式推理；若可得，再加 TeaCache 一类步间缓存。
  • Metric: 墙钟时延、FPS、总体分、不该开口时的误触发率。
  • Expected Contribution: 检验生成侧的训练无关加速，能否迁移到交互式理解且不破坏沉默/追问策略。

  • Risk: 理解模型可能没有生成模型那样稳定的块结构和噪声调度，读出头会失配。
  • Collision Risk: 中。与 ScoutCache、ForeSpark、Condition Shifting 相邻，但任务从生成改到交互理解。
