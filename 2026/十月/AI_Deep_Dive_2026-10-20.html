01 / AGENT × REINFORCEMENT LEARNING

Paper 1 · Tev: Scaling Long-Horizon Agentic Environments with Dense Progress Rewards

BACKFILL｜Agent × RL｜2026-10-13（arXiv v1）。作者：Wenbo Hu、Shraman Pramanick、Krishna Kumar Singh、Nanyun Peng、Kai-Wei Chang、Yong Jae Lee；单位：Adobe Research、UCLA。状态：arXiv 预印本，未核实正式会议录用。论文：arXiv 摘要 · 全文 HTML · 项目 · Tev-27B 权重。代码和 Tev-Gym 数据：项目页仍标记 Code soon / Data soon，不可写成已开源。

一句话定位

把长时程 Agent 任务从“最终成功才有奖励”的稀疏 RL，改造成“由同一真实世界生成任务、过程评分与最终验证”的可验证渐进训练环境，并证明这套数据—奖励联合设计能改善长链工具执行。

人话版（先理解全貌）

想象一个 Agent 要把六个月混乱的零售数据修成可信的 SQLite 仓库。它可能已经找到了重复交易、修正了字段、完成了 80% 的表，但因为最后一个文件没提交，传统 RL 只给零分；另一条轨迹什么都没做，也给零分。若一组 24 条轨迹全失败，GRPO 连“哪条比较有希望”都分不出来。Tev 先在后台生成完整正确的世界，再由它故意制造错误输入，同时保存一张可检查的工作流程图。Agent 每执行一次 bash，就用隐藏的正确世界检查工作区，形成 0 到 1 的进度势函数；训练奖励来自进度变化，最终真正提交成功另加一分。作者生成 1,170 个环境，在 9B、27B、320B 模型上实验。27B 在 ALE-CM 的 P@5 从 0.17 到 0.28；但更难的 TB 4.0-CM 上 P@1 仅从 0.04 到 0.10。重要之处不是一个新 loss，而是把“任务能否客观验证”变成训练环境的设计原则。

Background & Research Gap：为什么不是普通 GRPO 就够了

长时程任务包含大量状态依赖：先分析数据模式，才能修复主键；修复主键，才能构建事实表；事实表可信，才能输出统计报告。普通终局奖励 R∈{0,1} 只关心最后是否提交正确，不能区分“已修好 90%”与“第一步就乱删文件”。对于成功概率 p、每组 G 条 rollout 的 group-relative RL，整组全失败概率是 (1−p)^G；例如 p=0.05、G=8 时约 66%，p=0.01 时约 92%。这不是 reward 数值小，而是组内方差为零，优势函数直接消失。

旧方案包括：反复采样直到有成功轨迹、筛选模型能做对的简单任务、使用专家示范前缀、以单元测试通过比例代替过程质量、或训练 LLM judge。它们各有用处，但在专业工作流中存在成本、难度天花板、测试覆盖不足或评分噪声。比如某个数据仓库任务，单元测试只测文件存在，Agent 可以输出格式正确但内容错误的 CSV。Tev 填的 gap 是生成任务时就拥有可计算的隐藏真值与每阶段正确状态，而不是生成完任务再补一个不可靠的评分器。

Core Insight：先造正确世界，再造问题

作者的核心观察是：如果输入、标准答案、分阶段进度、最终验证器来自同一个潜在世界 W，它们天然共享语义约束。生成器先构造完整正确的数据结构，再将其渲染为 CSV、JSON、SQLite、模型分片或配置文件，最后注入可逆缺陷。工作流 DAG 给出依赖顺序，进度检查器用隐藏 W 比较当前工作区。这个观察主要是环境工程与可验证性设计，不是“所有真实任务都能被分解”的数学定理。它还解决了 separately-generated prompt / checker / artifact 的不一致：提示说需要 100 个订单，checker 却期待 101 个订单，会把正确执行错判为失败。

关键边界是“正确世界可由初始公开文件恢复”，而非“训练时偷偷告诉 Agent 标准答案”。作者要求渲染可 round-trip、破坏操作可逆，并设置隐藏反作弊探针。只有这样，任务才是可解而非被隐藏信息决定的谜题。潜在世界提供监督信号，Agent 在执行时仍看不到 W。

Method Deep Dive：逐阶段走通

Input → seeded latent world W → workflow DAG → clean artifacts → invertible corruption → public task + hidden graders → agent bash trajectory → progress potential Φ → DPPO/PPRS 更新 → trained agent

Step 0：任务规格与 seed。为软件、数据、AI/CS、数学运筹、安全、基础设施、量子计算七个领域设计生成器；seed 固定实体规模、缺陷类型和正确结果。危险点是生成器模板太少，模型记住格式而非学会长时程推理。作者用 19 个覆盖维度和难度层级控制变化。

Step 1：世界 W。生成一套内部一致的正确记录，例如顾客、产品、交易与外键关系，并验证唯一性、连接合法性和数值范围。W 是标准答案的源头，后续所有中间状态都可由 W 确定。若 W 自身有错，后面再精确的 verifier 也只是在验证错误真值。

Step 2：工作流 DAG。将“读源→修复维表→修复事实表→聚合→导出”写成有先后约束的节点，记录每个节点的预期结果与权重。DAG 的关键路径控制依赖深度；节点数量不等于真正的推理难度，作者通过难度层级和实际 rollout 时间补充衡量。

Step 3：渲染和污染。从 W 输出干净文件并检查 round-trip，再注入重复、缺失、字段漂移、分片错序等已知可逆错误。公开给 Agent 的只有任务说明与被污染的文件；正确 W、严格 verifier 和进度 scorer 留在隐藏侧。污染不可逆会制造不公平任务，是首要测试门禁。

Step 4：分离验证。最终 verifier 只对正式提交的完整工作区给 pass/fail；progress scorer 对每一回合的 workspace 评估阶段正确性。二者与参考求解器应有独立代码闭包，避免复制同一个 bug。论文设置八项资格门禁，包含 14 种 gaming probe 必须得零分；这降低了简单作弊，却不构成形式化的安全证明。

Step 5：RL 训练。同任务采样 G=24 条轨迹，每步八个任务共 192 条 rollout。每回合结束后算 Φ(s_t)，将相邻势能差作为 reward，并在最终正式提交成功时给终局项。DPPO 采用 group-centered advantage、total-variation 约束，按相同 turn index 比较回报。最常见失败是所有轨迹仍停留在同一进度节点，组内依然无方差，必须靠任务分层与 active sampling 解决。

核心公式与数学直觉

Aᵢ = (Rᵢ − mean(R₁…R_G)) / (std(R₁…R_G) + ε)　　[论文 Eq.2]

Aᵢ 是第 i 条轨迹相对同组平均回报的优势。全组 Rᵢ=0 时 Aᵢ=0；把 G 从 8 提到 24 能降低全失败概率，却不能解决 p 极小的难任务。分母 ε 只保证数值稳定，不会凭空产生训练信号。

Φ(s) = Σ_{v∈V} wᵥ · c̃ᵥ(s),　Σwᵥ=1,　c̃ᵥ(s)=min{cᵤ(s):u∈ancestors(v)∪{v}}　　[论文 Eq.3 的门控解释]

V 是 DAG 节点集合，wᵥ 是阶段权重，cᵥ 是当前工作区相对 W 的局部正确度；取所有先决节点和本节点的最小值，让“后续漂亮报表”不能掩盖“前置交易表仍然错”。这是先决条件门控，不同于直接把所有局部 test-pass 相加。wᵥ 过大将诱导模型优先刷容易拿分的阶段；门控过严又可能让一个早期小错误压制后续所有进度。

r_t = Φ(s_t) − Φ(s_{t−1});　R(τ)=𝟙[submitted & passed]+λΣ_t r_t=𝟙[pass]+λΦ(s_T),　λ=0.25　　[论文 Eq.4]

相邻差分允许奖励“修好了什么”并惩罚“毁掉了什么”，求和望远镜消去中间项。重要细节：作者并没有采用严格保持最优策略不变的 PBRS 终止势能归零做法；保留 λΦ(s_T)，有意改变目标。单条成功轨迹回报为 1.25，失败轨迹至多 0.25，因此单条轨迹的成功优先级仍最高；但随机策略的期望偏好与轨迹长度仍需单独分析。

训练把 λr_t 分配到各 turn、最后一 turn 再加终局奖励，使用 γ=1 的 return-to-go，并按 turn index 做组内中心化。对照 Direct additive Φ(s_t) 且 γ=0：它会反复奖励停在高势能状态的行为，可能鼓励不提交而耗尽上下文。DPPO 的 TV 约束 0.1 控制 policy ratio 的变化，论文设 β=0，无 KL anchor；这意味着稳定性依赖 TV 约束与训练配置，不能把它误说成“KL regularization 贡献”。

Toy Example：从输入到输出算一遍

假设正确世界有 10 笔交易、2 个产品；公开 CSV 被插入两条重复交易，并把一个产品类别拼错。工作流四节点权重分别为：清洗原始记录 0.2、恢复维表 0.2、重建事实表 0.4、输出报告 0.2。Agent 第 1 回合识别重复但没修改文件，Φ=0；第 2 回合去重后第一节点正确，Φ=0.2；第 3 回合修好类别，Φ=0.4；第 4 回合事实表正确，Φ=0.8；第 5 回合导出报告，Φ=1。对应增量奖励乘 λ 为 0、0.05、0.05、0.10、0.05。若忘了执行 submit，R=0.25；如果正确提交，R=1.25。另一条轨迹只修原始记录便停止，R=0.05；即使两条都没有最终成功，训练仍能分出优劣。若 Agent 先伪造报告而维表未修，DAG 门控会压低该报告节点的有效得分。这是解释性自造小例子，不是论文原始样本。

Experiment Setup 与每组研究问题

9B：Qwen3.5-9B，用 264 个 unit-tier 环境；27B：Qwen3.8-27B，用全部 1,170 环境；扩展：GLM-5.3-Flash → Tev-320B。每步 8 个任务 × 24 rollout；单条最长 65,536 response tokens、每回合 16,384、最多 64 次 bash 工具调用。DPPO、AdamW 学习率 1e−6、温度 1、seed 42、bf16、部分 fp32 LM head；27B 训练约四天，使用四节点 B200 或八节点 A100 的配置。32 GPU 运行采用 16 learner + 16 inference，64 GPU 运行 16 + 48。这不是低算力论文：复现完整训练成本显著。

RQ1：ALE-CM（18 个专家任务：数学科学 8、ML 5、编码系统 5）能否提升？同底座前后对比，5 条独立 rollout。RQ2：TB 3.0-CM（22）和 TB 4.0-CM（18）能否零样本迁移？注意是作者筛选的 CM 子集，且 CPU-only harness 限制了覆盖。RQ3：TB 2.1（89）是否保留中时程能力？RQ4：同数据消融能否隔离 reward、归一化与 world-first 的作用？RQ5：换到更强底座后是否仍有增益？前沿模型使用原生 Codex/Claude Code/Gemini CLI harness，Tev 使用 Vanillux2，跨 harness 结果只宜做生态参照。

Metrics 教学式解释

S@1 是一次 rollout 的平均分阶段 graded score（0–1，高好），能体现部分工作，但可能被 scorer 偏好误导；P@1 是一次 rollout 完整通过严格 verifier 的比例（高好），更贴近真正交付。S@5/P@5 是同任务五次独立尝试取最优再汇总；它衡量可达到的最好结果，不等于“一次执行的可靠性”。P@1 上升而 P@5 不动，通常表示同样的任务更稳定，并非解锁了更多新任务。GPU-h/step 是每个训练 step 的墙钟时间乘 GPU 数，不能直接推出总训练 token 数或最终总成本。Agent time 是固定模型与 harness 的 rollout 时间，不等于人类专家完成任务所需时间。Pearson r 衡量 CM 子集与完整榜单模型排名/得分变化的线性一致性，r 高并不能排除子集本身选择偏差。

Results Deep Dive：逐项核算，不只看 headline

  1. ALE-CM 27B：P@5 0.17→0.28，+0.11 绝对百分点、约 +65% 相对提升。这是相同底座下最醒目的成功率提升，支持训练 recipe 有效；但只有 18 个任务，最好五次尝试仍仅 28% 完整成功。
  2. 同一组 S@1 0.33→0.40、P@1 0.12→0.16。平均过程分改善 0.07、一次成功率仅改善 0.04；部分任务的进度进步没有等比例变成完成交付，说明 submit/收尾仍是短板。
  3. ALE-CM Math & Science P@5 0.25→0.50。翻倍是最强分项；反例是 ML 类别 P@5 仍为 0.00，且 S@5 由 0.32 降到 0.29，不能概括为“所有能力一致增强”。
  4. 9B 的 S@1 0.25→0.29、P@5 0.06→0.11。小模型有增益，但 P@1 仅 0.06→0.07，提示主要是增加多次尝试的可达性，而非单次稳健性。
  5. TB 4.0-CM：27B P@1 0.04→0.10（2.5 倍），但 Claude Opus 5 为 0.52。相对提升很大，绝对差距仍有 0.42；这是重要弱项，不能用“2.5 倍”掩盖低基数。
  6. TB 3.0-CM：27B P@1 0.09→0.14，+0.05；P@5 0.24→0.27。跨数据有增益，但幅度小于部分 in-domain 结果，可能是工作流分布与环境复杂度差异。
  7. Tev-320B 在 TB 4.0-CM：P@1 0.29→0.37，P@5 没有改善。更强模型使已有可解任务更稳定，却没有在五次预算下解锁新的难题；这一现象限制了“突破能力边界”的解释。
  8. TB 2.1：27B P@1 0.764→0.794，+0.030；9B 0.178→0.227，+0.049。说明长任务训练未必破坏中任务能力，但对大模型增益较小；是否在一般编程能力上同样成立尚未验证。
  9. Ablation：Sparse S@1=0.25、P@5=0.06；PPRS 0.29、0.11；Direct additive 0.29、0.06。S@1 一样不代表目标等价：只有 PPRS 的完整提交率同步提升。
  10. 训练成本：Sparse 16.7 GPU-h/step，PPRS 9.0；public-view verifier 22.3。说明信息性轨迹与评分质量会改变每步耗时；但未给出完全等预算下“总 GPU-h 到目标准确率”的对照，不能宣称总成本精确下降 46%。

02 / VIDEO ACCELERATION × INFERENCE

Paper 2 · Speculative Forcing for Efficient Autoregressive Video Generation

BACKFILL｜Video Acceleration × Inference｜2026-10-15（arXiv v1）。作者：Hyunwook Choi、Seungryong Kim、Dongyoon Han、Sangdoo Yun；单位：KAIST AI、NAVER AI Lab。状态：arXiv 预印本，未核实正式会议录用。论文：arXiv 摘要 · 全文 HTML · 项目与视频 · GitHub 仓库。仓库当前只有说明，README 写明代码仍在内部审核，尚未发布实现；不能把“有 GitHub 链接”当作可复现代码已开源。

一句话定位

把视频扩散模型固定 K 步、所有 token 都反复去噪的统一预算，改成“每个时空 token 独立预测何时已接近最终输出、提前冻结并跳过后续计算”的动态推理机制，并在真实 H100 上测量速度与画质权衡。

人话版（先理解全貌）

一段视频的背景墙可能在第一步去噪时就已经接近最终画面，但快速运动的手、刚从镜头外进入的物体还要三四步才能稳定。传统四步视频生成器不管区域难度，一律把每个 latent token 计算四遍，造成大量重复工作。Speculative Forcing 把每一步得到的“干净 latent 估计”当成草稿，让 verifier 判断某个 token 是否已经足够接近它本来四步后的结果。被接受的 token 立刻冻结，不再进入后续去噪计算，但保留 KV 给尚未完成的 token 参考。作者做了无需训练的历史相似度/逐步稳定性检测，以及一个 4.11M 参数的小型 learned verifier。LongLive 的 5 秒视频从 26.4 到 41.7 FPS，30 秒视频从 24.5 到 37.8 FPS；更难的 Lingbot 世界模型从 18.1 到 24.5 FPS。它证明“少算 token”确实可以变成 wall-clock 加速，但这种接受是近似质量判定，绝非 LLM speculative decoding 那种分布严格无损的接受规则。

Background & Research Gap：从扩散步骤到 token 预算

自回归视频生成不是一次生成整段视频，而是逐 chunk 产生未来几帧。每个 chunk 的 latent 以高斯噪声开始，使用视频 DiT/Transformer 进行 K 次 denoising；历史 chunk 的 KV 被缓存以保持上下文。为了实时生成，Self Forcing / LongLive 等模型把几十步蒸馏到四步，但每一步仍计算整张时空 token 网格。对于一堵不动的墙与突然出现的人脸，这相当于给两个难度完全不同的区域相同的算力。

旧范式有三类：减少所有 token 的全局步数（快但画质下降）；feature/cache reuse（仍走完整步序、复用部分特征）；按帧或 chunk 选择步数（整块都被最难 token 拖累）。例如镜头横移时，旧画面左侧墙体已经稳定，右侧新露出的物体仍模糊；chunk-wise 只能全块跑四步，或者全块提前停止并损害新区域。本文的 gap 是：以 token 为粒度做不可逆的 early commitment，已经完成的 token 不再参加后续 forward，而未完成 token 继续细化。

与经典 speculative decoding 的相似点是“草稿→验证→接受”，不同点是：经典 LLM draft token 通过 target distribution 的拒绝采样校正以保证输出分布；这里 verifier 估计与原四步生成结果的接近程度，没有严格分布等价证明。用“lossless speculative video decoding”描述它会误导读者。

Core Insight：视频不同区域收敛速度不同

作者在 Figure 2 对比同一初始噪声、同一条件下第 k 步 clean estimate 与原始四步输出的差距，观察到背景和历史可复用内容较早收敛，运动、遮挡、新视野区域需要更多步骤。这是可视化和统计支持的经验发现，不是“背景总能一步完成”的定理。关键假设是：中间 clean estimate 对最终输出的剩余误差可以在不执行未来步骤的情况下预测。训练自由版依赖“像历史内容”或“相邻草稿变化很小”；学习版从 backbone hidden state 直接预测剩余误差。

真正的系统价值来自把 verifier 输出变成减少后续模型计算的 mask，而不只是显示热力图。token 被冻结后仍作为 KV 上下文供其他 token 使用；chunk 完成后执行一次 clean pass 刷新全部 KV，避免下一 chunk 读到不一致的噪声状态。这一步保证后续生成的上下文语义一致，但也解释了为什么理论 token 减少 58% 不会得到同样比例的端到端时间收益。

Method Deep Dive：一轮视频 chunk 具体发生什么

Input: history KV + prompt/camera + noisy chunk → denoise k=1 → clean draft → verifier score → commit stable tokens → compact active tokens → denoise k=2…K → merge accepted drafts → clean KV refresh → output chunk / next chunk

Step 1：生成第一个草稿。K=4，chunk 内 N 个时空 latent token；第一次 denoising 所有 token 都参与，输出每个 token 的 x̂₀^(1)(i)。这个量不是最终 RGB 像素，而是 latent 空间的 clean estimate。每个 token 包含多个输出像素/帧的信息，单 token 的错误可能影响时空一致性。

Step 2：判定第一次是否可提交。第一次没有前一版草稿，因此 training-free verifier 把草稿与历史 clean latent token bank 比较，取最相似历史 token 的 L2 距离。若与历史高度相似，则倾向于提前接受；这种跨空间位置的最近邻检索能容忍镜头/物体移动，但相似不代表正确，例如重复纹理会造成错误匹配。学习版则读取当前 backbone 特征预测该 token 与四步输出的剩余距离。

Step 3：冻结并保留上下文。接受的 token 固定为当前草稿值 c_t(i)=x̂₀^(k*)(i)，不再 re-noise、不再走后续 denoising forward。它在各层的 key/value 保留，活动 token 仍可 attend 到它。缓存内不同 token 可能来自不同去噪步；因此必须仔细维护 position、timestep、mask 与 KV 写入顺序，否则虽然 FLOPs 降了，结果会因上下文错配而崩溃。

Step 4：继续 refinement。未接受的 token 进入下一噪声层级继续预测。在 k≥2 时，training-free verifier 改用相邻 clean estimates 的差值判断稳定性；学习版仍预测剩余 gap。每步先对分数做时空平滑再阈值化，避免棋盘状的零散冻结边界。若 token 到 k=4 仍不满足阈值，就按原始生成器完成全四步。

Step 5：拼接并刷新。把来自 k=1、2、3、4 的 token 拼成最终 chunk；执行一次 timestep=0 的 clean forward 刷新所有 token 的 KV，再进入下一个 chunk。论文还把当前 chunk 的 clean pass 与下一 chunk 第一次 denoising pass 合并调度，以降低实际执行开销；比较基线也采用适用的相同优化。不能简单删掉这次 clean pass，除非另外证明跨 chunk KV 的正确性。

Step 6：两种 verifier 的取舍。Training-free 不需要额外训练数据，但需为每个模型/场景校准 redundancy 和 stability 两个阈值；learned head 需要完整四步 rollout 作 oracle 标签，增加离线成本，但面对强视角变化更稳。两者都不修改视频生成主干参数；后者属于轻量监督训练，不应称整个系统完全 training-free。

核心公式与数学直觉

p(c₁,…,c_T) = ∏ₜ p(c_t | c_<t)；　rel_k(i) = || x̂₀^(k)(i) − x̂₀^(K)(i) ||₂ / σ_t　　[论文 Eq.1]

c_t 是第 t 个视频 chunk，x̂₀^(k)(i) 是第 k 次去噪的第 i 个 token 的 clean estimate，x̂₀^(K) 是同一初始噪声与条件下原始完整 K 步输出，σ_t 是该完整输出各 token norm 的中位数，防止不同 chunk 尺度影响阈值。rel_k(i)≤ε 表示这个 token 已接近原生成器的最终结果；在实际推理时 x̂₀^(K) 尚不存在，所以 rel 是训练标签/Oracle 分析量，不是可直接部署的判断条件。

s_red(i)=min_{h∈H} ||x̂₀^(1)(i)−h||₂；　s_stab^(k)(i)=||x̂₀^(k)(i)−x̂₀^(k−1)(i)||₂

第一式问“当前草稿像不像已有 clean 历史”，第二式问“它这一步变化大不大”。两者分别用 τ_red、τ_stab 判断，并对分数先做时空平滑 S[·]。历史冗余只提供相关性，稳定性也可能是“连续两步都错”；因此二者都是 gap 的 proxy，最容易出现的 false accept 是视觉纹理稳定但语义仍未收敛。

L(φ) = [N(K−1)]⁻¹ Σᵢ Σ_{k=1}^{K−1} smoothL1( r̂_k(i), rel_k(i) )　　[论文 Eq.2]

φ 是 3D 卷积 head 参数；r̂_k(i) 由冻结 backbone 的 hidden states 预测，Huber/smooth-L1 在小误差区像平方损失、异常大误差区像绝对值损失，避免少数高 gap token 主导训练。推理时 S[r̂_k](i)≤ε 即接受；增大 ε → 更早接受 → 更快但质量更差，减小 ε → 接近原四步成本与质量。模型没有显式最大化 FPS，而是通过阈值控制 accuracy–latency Pareto。

C_denoise = Σᵢ k*(i)；　k̄ = (1/N)Σᵢ k*(i)；　ideal speedup ≈ (K+1)/(k̄+1) = 5/(k̄+1)

k*(i) 是 token 实际提交的步数。相对固定四步的 denoising token 计算，减少比例约 1−k̄/4；但还要加 clean pass，所以理论理想速度比不是 4/k̄ 而近似 5/(k̄+1)。实际还受到每步 kernel launch、索引压缩、KV 操作、仍存活 token 数和最长存活步数影响；论文明确指出每 chunk 的最后活跃 token 会拖住整块调度。

Toy Example：一个 8-token 的四步视频

设某个 chunk 只有 8 个 token：4 个静止背景在 k=1 即满足阈值，2 个缓慢移动物体在 k=2 满足，2 个新出现的手部 token 要到 k=4 才稳定。固定四步需要 8×4=32 次 denoising token 评估；本文只需 4×1+2×2+2×4=16 次，平均 k̄=2，理论 denoising token 计算减半。再加每个 token 一次 clean KV refresh，原方案成本近似 32+8=40，本文 16+8=24，理想速度比 40/24≈1.67×。若执行时间主要由四次完整 kernel launch 决定，实际可能远小于 1.67×；如果 2 个最难 token 可以用高效 sparse kernel 单独计算，则更接近理想。假设 verifier 错把一个手部 token 在 k=1 接受，节省三次评估，却可能在后续 30 秒里积累手部扭曲；因此速度与长期质量必须联合评估。此例仅用于解释算术，不是论文实验。

Baseline Deep Comparison：公平的对照到底是什么

Baseline 机制 合理性与失效处 本文差异
Uniform 4-step 所有 token 跑四次 质量参照最可靠，但浪费易区域算力 token-wise early commit，最重要质量锚点
Uniform 2-step / 3-step 所有 token 提前停止 速度可比，但复杂区域无法补救 只给困难 token 额外步数，机制性
Surprise Forcing 以 chunk 难度分配去噪深度、带长期记忆机制 简单易实现，但 chunk 内异质性大 单 token 判定，strongest adaptive baseline（机制上）
Motion-based / Temporal Difference 根据相邻帧变化分配预算 运动不等于未收敛，镜头变化易误判 对齐与 full-step 的 gap 而非运动量
Channel Variance / Chunk-wise Acceptance 用噪声方差或整块均值决定 混合难易 token 时早停错误传播 保留 token 级空间差异

strongest baseline 要分实验：衡量质量是否保持时是 Uniform 4-step；衡量同算力预算下 adaptive 方法时是 Surprise Forcing 或 matched-steps 的 Chunk-wise Acceptance；衡量 learned verifier 本身时是 Oracle 与 MLP/on-policy head 消融。论文不是直接比较所有视频生成架构的绝对 SOTA，而是在冻结 LongLive/Lingbot 底座下改推理策略。

Experiment Setup：模型、数据、硬件、协议

Models：LongLive 1.3B 与 Lingbot-World 2.0 Causal-Fast 1.3B，均四步生成，主干冻结。Training：LongLive learned verifier 用 1,000 个 VidProM prompt 的完整 rollout；Lingbot 用 1,000 个与测试场景分离的初始图像。head 结构 LayerNorm → Conv3D(1536→96, 3³) → GELU → Conv3D(96→48, 3³) → GELU → Conv3D(48→1,1³)，约 4.11M 参数；Adam lr=1e−3、batch=4；输出做 2×2×2 平均池化后还原网格。Hardware：单张 NVIDIA H100 报告 FPS。

RQ1：5 秒短视频：81 帧、VBench prompt 经 Self Forcing 改写，每个 prompt 五个 seed；VBench 16 个维度。RQ2：30 秒长视频：477 帧、VBench-Long + Drift，检验自回归错误累积。RQ3：交互世界模型：200 个独立导航场景、每段 253 帧，五个相机控制区间（50/50/50/50/52 次转移），测试平移/旋转的 RPE 与画质。RQ4：阈值、选择信号、chunk vs token 粒度是否关键？全部使用相同条件输入与随机 seed；不同场景选择不同阈值（短视频 learned ε=0.28；长视频和世界模型 ε=0.24），所以跨场景速度不能看成同一 operating point。

LongLive 使用 3 latent-frame attention sink、12-frame local window、3 latent-frame chunk；Lingbot 使用 6 sink、18 window、4-frame chunk，额外输入相机轨迹的 Plücker embedding。training-free 的两个阈值也按场景校准。重要复现细节：token mask、clean pass 与下一 chunk 第一次 denoise 的融合、CUDA kernel 和 KV 更新是速度结果的重要组成部分；只在 PyTorch 中给 token 乘 0 不等于减少实际计算。

Metrics 教学式解释

Mean Steps：每 token 平均执行多少次 denoising（低好），衡量理论工作量，但忽略额外 clean pass 与不规则计算开销。FPS/Throughput：实际每秒生成帧数（高好），是论文真正系统加速证据；需同时注明 GPU、帧数、batch 和计时边界。VBench / VBench-Long Total、Quality、Semantic：视频生成质量、视觉与语义的聚合得分（高好），分数差 0.1 不必然具有人类可感知显著性。Drift：非重叠时间段 imaging-quality 分数的标准差（低好），反映质量随时间波动，不等于物体身份漂移或物理一致性。RPE Trans / Rot：相机轨迹相对位姿误差（低好），衡量是否按控制命令运动；它与画面美观互补。AUROC：把“仍需 refinement”的 token 排在“可提前接受”的 token 前面的能力，0.5 接近随机、1 完美；AUROC 高不代表某个实际 ε 下的 false accept 率一定低。FLOPs / 显存 / 能耗：论文没有在主表给出完整 FLOPs、peak GPU memory、Joule 的量化对照，必须写 Not Reported，不得拿 token reduction 当实测 FLOPs。

Results Deep Dive：至少八个带反例的数字

  1. 5 秒 LongLive：4-step 26.40 FPS、VBench 83.08；learned 1.68 steps、41.74 FPS、83.21。实际加速 41.74/26.40≈1.58×，总分 +0.13；这是最强系统证据，但不是无损分布保证。
  2. 5 秒 training-free：1.65 steps、43.61 FPS、83.12，比四步约 1.65×；同质量水平下比 learned 略快，说明训练 head 不是每个场景必需。不能忽视阈值是校准出来的。
  3. 5 秒 uniform 2-step：44.54 FPS、82.46；比 learned 还快一点，却比 83.21 低 0.75 分。说明“固定两步”在同速区间损失更多质量，但该质量差是否显著还需置信区间。
  4. 30 秒 LongLive：4-step 24.45 FPS、VBench-Long 82.69、Drift 1.722；learned 37.78 FPS、82.81、Drift 1.707，约 1.55×。表明收益在长视频保留，Drift 略降；0.015 的 Drift 差不能当作大幅改善。
  5. 30 秒 training-free：38.78 FPS、82.75、Drift 1.685；比 learned 更快且 Drift 更低，但某些一致性子维度更弱。不存在“learned 必然全指标胜出”的结论。
  6. 世界模型 Lingbot：4-step 18.1 FPS、Quality 82.62、Drift 3.094；learned 24.5 FPS、82.65、2.839，约 1.35×。相比 LongLive 加速更小，说明新视野 token 更难早停。
  7. 世界模型相机误差：4-step Trans RPE=0.328、Rot RPE=0.253；learned 0.328、0.260。平移保持、旋转略变差 0.007；支持基本控制精度，但不能说所有控制指标无损。
  8. ε sweep：世界模型 ε=0.24 时 2.55 steps、24.5 FPS、Quality 82.65；ε=0.32 时 1.97 steps、28.3 FPS、Quality 82.07、Drift 3.398。加速更快却明显牺牲画质和稳定性，清楚显示 failure threshold。
  9. token-wise vs chunk-wise：相近步数 2.55 vs 2.61，learned token-wise Quality 82.65、Drift 2.839；chunk-wise 82.54、3.214。改善并非只因为“用了一个 head”，还因为预算粒度变细。
  10. 验证器分类能力：LongLive ε=0.24、k=1 时 learned AUROC 0.934，redundancy 0.828，motion-based 0.701；k=3 时 learned 0.906，stability 0.854。学习特征更能判断剩余 gap，但额外训练是否值得由场景决定。

Ablation / Mechanistic Analysis：谁承担了什么

去掉时空平滑：世界模型 learned Drift 2.839→2.882、Quality 82.65→82.58，说明邻域一致的接受决策有帮助；幅度有限，尚不能证明每次边界错误都被平滑纠正。换成 per-token MLP：2.52 steps、24.8 FPS、Quality 82.67、Drift 2.899，画质甚至略高，说明 backbone 已编码收敛线索，复杂 3D 卷积并非唯一贡献。改 on-policy head 训练：2.57 steps、24.5 FPS、Quality 82.67、Drift 2.940，没有明显胜出；训练数据更贴近当前 policy 不一定更好。

换成 motion / channel variance：Quality 降到 80.97/78.23，说明“是否运动”和“是否需要更多去噪”不是同一问题。改 chunk-wise acceptance：Drift 从 2.839 到 3.214，证实 token 粒度在异质区域有价值。ε 从 0.24 提到 0.32：更快但画质变差，是方法的典型 failure case。以上主要是机制关联与干预消融，尚不是对模型内部表示的严格因果定位；未来可以对单 token 接受决策做反事实强制继续计算实验。

Claim vs Evidence / Contribution

Authors Claim：不改 backbone 就能在不同视频域里以 token-wise convergence 提前接受，保持原四步画质并加速。Experiments Actually Show：两类 1.3B backbone、固定 H100 和给定阈值下 FPS 1.35–1.65×、VBench aggregate 近似持平、世界模型 RPE 大体接近。What Is Not Yet Proven：输出分布严格不变；对 7B/14B 视频模型、不同 GPU、batch>1、极长滚动历史、复杂物理交互同样有效；相同平均质量意味着每个视频都无失真。

Contribution 1 [New Mechanism]：token-wise early commitment + mixed-step KV retention；Contribution 2 [New Metric / Protocol]：以 full-step latent gap 作 oracle，评价 verifier 的 AUROC 与阈值 Pareto（并非首次提出 AUROC）；Contribution 3 [New System / Engineering]：active-token 计算、KV refresh、跨 chunk pass 合并；Contribution 4 [New Empirical Finding]：低运动区域通常更早收敛、动态世界模型更难提前接受。潜在重复点在于 adaptive denoising / caching / chunk-wise scheduling 已有大量先例，真正的新颖性应聚焦提前冻结 token 的承诺语义与其跨 chunk 系统实现，而不是泛称“首次动态计算”。

Limitation & Failure Modes

Authors' Limitation：加速取决于原模型对减少去噪步数的容忍度和任务难度；大幅相机运动使更多 token 必须继续精炼；每 chunk 仍受最后活跃 token 的 forward 开销制约，clean pass 也有固定成本。Additional Limitation：verifier 用同模型四步输出作 teacher，只能逼近原模型而非真实世界真值；容易在“原模型本来就错”时提前锁定错误；阈值对域转移和视频长度敏感；latent L2 与人类感知不完全一致；极小运动的语义突变可能被 redundancy/stability 误判；不同 timestep KV 混存需要严谨实现；额外 4.11M head 与 score smoothing 会占用显存和带宽；缺少真实峰值显存、能耗、batch 扩展、显著性区间；代码尚未公开，独立复现实验仍受限。

Reproduction View：先复现验证机制，再谈 H100 性能

最小实现可在一个公开四步 AR 视频生成器上插入三个模块：collect_fullstep.py（同噪声保存 k=1..4 clean estimate 与 hidden state）、verifier.py（redundancy / stability / learned gap）、masked_denoise.py（active-token gather/scatter + layer KV）、refresh_kv.py（chunk 结束 clean pass）、bench.py（CUDA event FPS、显存、画质）。第一阶段不训练 head：固定 20 个 prompt × 3 seed，用 full-step oracle 算每 token rel_k 分布，画 ε 与可接受比例曲线；第二阶段用训练自由版跑 end-to-end，验证 mask 真的减少执行 FLOPs/时间；第三阶段才训练小 head。最容易踩坑：把 masked token 置零仍执行完整矩阵乘法，理论 token 数减少而 GPU 时间不变；忘记刷新 KV；只比较不同随机 seed；错误地把 decode VAE 时间算入某一方法；未统一 attention sink/window。

建议先扫 ε∈{0.16,0.20,0.24,0.28,0.32}，每个 operating point 记录 k̄、false accept rate（以 full-step oracle 为准）、FPS、VBench Total/Drift、max memory；然后做 force_continue 反事实：随机选 10% 已接受 token 强制跑完整四步，观察后续 chunk 的质量变化。最能验证核心 claim 的结果是在同一生成器、同一 H100、同一 seeds 下，比 uniform 2-step 质量更好、比 uniform 4-step 速度更快。完整 LongLive 训练脚本与自定义 CUDA 实现目前无法直接从仓库获取，须将其标注为待补齐部分。

Baseline Potential：高，token-wise early commit 是 adaptive denoising 的明确对照。Migration Potential：高，可迁移到视觉 token、KV eviction、动态 test-time compute。Systems Potential：高，真实 FPS 已验证，但还缺高并发与跨硬件测试。Attack Potential：高，可构造误导 verifier 的稳定但错误区域。Evaluation Potential：高，可以定义 gap calibration / false accept / future drift 三轴。Benchmark Potential：中高，运动速度、遮挡、视角变化可参数化形成 stress suite。New Paper Potential：中高，重点是 verifier 校准、长期误差传播、系统调度，而非简单再调一个 ε。

Migration A：Video VLM 的“可提前接受视觉证据”机制

Original Problem → 视频生成中不同 token 收敛速度不同。Transferable Mechanism → 以最终输出的近似 gap 决定 token 何时停止计算。New Research Question → 在长视频理解中，哪些 frame/token 已经对当前 query 的答案贡献稳定，能提前退出视觉编码或跨层 attention？Method Modification → 用 frozen Video VLM 在完整 32 帧下的最终答案 logit / hidden representation 作为 teacher，训练一个轻量 per-frame gap predictor；对低 gap 帧跳过后续视觉层或减少进入 LLM 的视觉 token，而不是简单删掉所有背景帧。Minimum Experiment → 从 NExT-QA 取 300 道题、每题统一解码 32 帧；比较 uniform 8/16/32、随机 8、query-aware top-k、gap-aware 8/16/32；离线用完整输入记录各帧贡献差与最终答题正确性，按 7:1:2 划分校准/验证/测试；测 TTFT、视觉 encoder ms、总 latency、tokens、GPU peak、Accuracy；在“新物体突然出现”和“背景静止但语义变化”两个子集专门做 false-accept stress。Model → 开放 7B Video VLM。Dataset → NExT-QA；Baseline → uniform / adaptive frame sampling。Metric → Accuracy、TTFT、wall-clock、token count、false-exit rate。Expected Contribution → 将视觉 token 裁剪变成可校准的质量阈值决策。Risk → teacher logits 不是真值，答案本身可能错；动态索引 overhead 抵消收益。Collision Risk → 与 VETO、VisionZip、query-aware token pruning 接近，需明确“分层 early commit + uncertainty calibration”区别。

Migration B：长时程 Agent / World Model 的风险敏感预算控制

Original Problem → 视频生成固定步数浪费算力，但提前接受错误会累积。Transferable Mechanism → token-wise verifier + 局部接受 + 保留上下文 + 风险阈值。New Research Question → 能否在交互世界模型中按未来动作风险而不是只按 latent gap 分配去噪预算？Method Modification → 让 verifier 输入当前相机动作幅度、可见性变化、历史遮挡与 gap，预测“若现在 commit，未来 H 个 chunk 的质量/位姿误差增长”；以风险上限决定 ε，避免高风险新视野过早冻结。Minimum Experiment → 在 Lingbot 风格的 200 个相机轨迹中构造静止、平移、旋转、突然反向四组，每组相同 seed；训练一个小风险 head，标签由强制继续四步与提前 commit 的 paired rollouts 产生；对照固定四步、固定 ε=0.24、按运动量调 ε、预测未来误差调 ε；报告 5/10/20 chunk 的 Quality、RPE、Drift、FPS、P95 latency 与显存；绘制 FPS–future-error Pareto。Model → Lingbot-World 2.0 Causal-Fast 1.3B（代码/权重可得时）。Dataset → 论文 200-scene 设计的独立重建集。Baseline → uniform / motion / original verifier。Metric → FPS、future Drift、RPE、false-commit rate。Expected Contribution → 从即时 latent gap 转为风险敏感长期控制。Risk → 成本高、动作分布外泛化、teacher error。Collision Risk → 与 adaptive diffusion / world-model uncertainty 研究接近，必须以长期误差的反事实实验证明新增价值。

Video / Inference 专用 Lens

Bottleneck：少步视频扩散的反复 denoising Transformer forward，而不是 LLM decode 的 token-by-token sampling；KV 维护是重要次级成本。究竟少算什么：对已接受 latent token 不再执行后续去噪的 attention/MLP 投影；没有删除输出帧，也没有宣称 KV memory 按同一比例下降。是否 retraining：training-free verifier 不需要；learned head 要离线训练，但 backbone 冻结。是否硬件相关：机制通用，速度证据只来自单 H100；动态 gather/scatter 在不同 GPU 可能表现不同。batch-size scaling：Not Reported。long-context/streaming：30 秒有证据，分钟级/多小时未验证。理论 vs wall-clock：5 秒平均步数从 4 到 1.68，但 FPS 只 1.58×，不能写成 2.38× 的真实加速。迁移到 VLM/Agent/Reasoning：可迁移的是“预测继续计算的边际价值并提前承诺”，不是照搬扩散的 timestep 公式。

Attack / Verification Lens

可设计四类 stress test：① stable-but-wrong：重复纹理或稳定错误物体，检测“变化小就接受”的错误；② occlusion reveal：遮挡解除、突然露出关键物体，检查历史相似度误判；③ camera distribution shift：超出训练的高速旋转/平移，检查 gap head 校准漂移；④ long-run amplification：前 5 秒局部误差很小，但 30/60 秒后是否被自回归历史放大。建议新指标 Early-Commit False Positive Rate、Error Amplification@H、Verified FPS at Quality≥q。这些属于研究建议，不能写成论文已有攻击结果。

如果只记住这篇（9 句）

  1. 四步视频生成器并非所有 latent token 都需要四步。2. 作者把中间 clean estimate 视为草稿。3. verifier 判断与原四步输出是否足够接近。4. 接受的 token 不再计算，但仍保留 KV 供其他 token 使用。5. chunk 结束还需 clean pass 刷新历史 KV。6. 训练自由版用历史冗余和相邻稳定性，学习版用 4.11M head。7. 5 秒 LongLive 的真实速度是 26.4→41.7 FPS，而不是理论 token 比值。8. 大视角变化的世界模型只有约 1.35× 加速，揭示场景依赖。9. 最值得做的是“可校准的 early commit + 长期错误传播 + 真实系统性能”研究。

Cross-Paper Synthesis｜共同趋势与机制分野

这两篇看似不相干：Tev 优化 Agent 的训练信用分配，Speculative Forcing 优化视频生成的推理算力分配。但二者共享一个结构：系统先定义一个不可直接在当前时刻完整观察的“最终正确/充分结果”，再构造可在中途获得的 proxy，利用 proxy 决定接下来的资源。Tev 的隐藏世界 W 能直接检查工作区，因此阶段进度近乎程序可验证；视频论文的四步最终输出在提前停止时尚不存在，只能用 learned gap 或冗余/稳定性 proxy 估计。前者重点是reward fidelity，后者重点是verifier calibration。

共同的失败模式也清楚：如果代理指标与真实目标不一致，优化器就会沿错误方向前进。Agent 可以刷高 Φ 却不提交；视频 token 可以“看起来稳定”却被错误冻结。两篇都使用显式的保护：Tev 的先决条件门控、独立严格 verifier 和 gaming probes；视频的 full-step oracle 标签、阈值扫描、时空平滑和长期 Drift。两者的实验都提醒我们：平均指标变好，不代表所有困难子场景得到解决。Tev 的 ML 子任务没有同步进步，视频的高视角变化场景加速显著缩水。

Combined Research Opportunities｜优先做什么

机会 A：Verifier-Calibrated Compute Allocation（优先级最高）

设计一个统一的“继续计算是否值得”的决策框架：Agent 选择再检索记忆/再调用工具/再执行 verifier，Video VLM 选择再读帧/再跑视觉层，Video DiT 选择再精炼 token。控制器预测 expected Δverified utility / GPU-ms，并在错误接受风险上设约束。最小可行论文不应从通用多任务大框架开始，而应先在一个可验证任务（如 NExT-QA 的帧预算）上证明：在相同准确率下显著降低真实延迟，并通过 error calibration / OOD stress 排除 proxy hacking。若不能拿出强 baseline 和硬件实测，创新会退化为普通 dynamic computation。

机会 B：Long-Horizon Recovery after Early Commitment

把视频的“提前冻结”映射到 Agent 的“计划、记忆或工具结果被当成既定事实”。一旦提前 commit 错误，后续执行是否会级联放大？构造可回滚状态与不能回滚状态两组实验，比较：永不复查、固定周期复查、风险感知复查。报告 final pass、recovery latency、token/GPU cost 和 false-commit amplification。这个方向比“Agent 多加一个反思模块”更具体，因为它把错误传播和资源预算量化。

机会 C：Progress Reward × Realized Latency 的双目标基准

Tev 的每步 GPU-h 与视频的 FPS 提醒我们：理论上少做动作不等于墙钟时间变短。可以构建 Progress per GPU-second、Verified Success under Cost Budget 和 Risk-adjusted Early-Exit Utility 三个指标，在同一 GPU、同一数据、相同预算下比较终局奖励、过程奖励、静态预算、动态预算。要求报告 median / P95 latency、峰值显存、成功率和 seed 方差，避免把“少生成 tokens”误写成“服务吞吐提升”。

Collision / Overlap｜哪些已经有人做过

本期两篇彼此没有直接撞题（Strongest Collision: NONE）。但各自与既有研究有明确重合边界：Tev 与 Verifiable Process Rewards for Agentic Reasoning（VPR） 同样强调中间过程可验证奖励；Tev 的区分点是先造完整世界、长工作流 DAG 与程序化生成任务，必须在论文写作时正面比较 VPR。Speculative Forcing 与 Surprise Forcing、其他 adaptive denoising / feature caching 同样分配视频计算预算；它的区分点是 token-wise commit、mixed-step KV 与真实 FPS。二者均不能把“动态计算”或“密集奖励”本身当成原创概念。
