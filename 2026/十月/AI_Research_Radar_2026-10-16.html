CASI: Credit Assignment via Set Intervention for Agentic Retrieval

Xinyi Cheng, Tianfu Zhang, Jiwen Li 等 · 2026-10-14 v1 · Venue: arXiv preprint · HTML正文 · arXiv/版本记录 · Project/Code: 未核实

人话版：这篇论文到底干了什么？

多条检索 query 一起执行，最终只有一份广告价值反馈，直接把总 reward 广播给所有 query 会把冗余动作也当功臣。CASI 在同一批检索结果快照上重新组合不同 query 子集，估算每条 query 在不同搭档下的边际贡献，再用 Shapley 聚合并修正 RL 的动作级 advantage。它的价值不在发明 Shapley，而在构造可比的反事实集合与不破坏组内均值的信用分配。离线多种对照和线上随机实验均提供证据，但其训练评估器的局部符号一致性只有 59.25%，提醒我们反事实质量决定方法上限。

Background & Research Gap（含具体例子）

假设一个 Agent 同时发出五条广告检索改写：两条找到相同商品，第三条独立补足小众意图，第四条和第五条竞争有限展示位。最后成交价值是整个集合共同产生的；把相同的成功分数分给每条 query，无法辨别互补、冗余甚至负贡献。Singleton 只看单条效果，Leave-One-Out 只看从全集删一条，二者在有高阶交互时可能给出错误排序。论文证明 m≥4 时这些端点值一般不足以恢复 Shapley。

Core Insight：证据与直觉

先固定可重放环境快照，再做“只变组合、不变检索输出”的集合干预；这样可以比较相同条件下的不同联盟，避免每次重新生成和检索引入随机噪声。作者在 1200 条请求上观察到明显联盟依赖；但观察到交互并不自动意味着训练代理评估器可信。

Method Deep Dive：Input → Steps → Output

输入 x → LLM 一次生成 m=5 条检索动作 → 每条只检索一次并缓存候选池 → 构造非空子集 S → 在固定 evaluator 下重新合并候选并计算 R̂(S) → 对所有 S 的边际 R̂(S∪{i})−R̂(S) 做 Shapley 加权 → 组内去均值、标准化、零和有界投影 → 每个动作的 token 使用 A_i=A_rollout+β z_i，公共格式 token 保留原 advantage → RL 更新。重点：31 次是缓存后 evaluator 打分，不是 31 次昂贵的线上拍卖或 LLM 生成。

关键公式 / Objective / Hyperparameters

φ_i=Σ_{S⊆A\{i}} |S|!(m−|S|−1)!/m! · [R̂(S∪{i})−R̂(S)]；Ã_i=A+βz_i，其中 Σz_i=0 且 |z_i|≤κ。前式平均不同前驱联盟下的增量，后式只重分配相对 credit；零和不代表梯度完全等价，因为各动作 token 的 score function 不同。β 控制信用偏移幅度，κ 限制极端偏移。

Toy Example

三条 query A/B/C：A 与 B 找到几乎同一批商品，C 找到另一类有价值商品。单独执行 A、B 都能得分，但一起执行时重复候选占据有限展示位，A/B 的新增边际可能变小；C 的边际却可能更稳定。若只用最终 10 分给三条都记 10，就会不断强化重复查询。联盟干预在固定候选上评估 A、B、C 的各种组合，得到相对贡献。

Baseline Comparison / Strongest Baseline

Broadcast：仅 1 次 evaluator score，所有动作共享回报；Singleton：m+1=6 次，忽略搭档；LOO：6 次，仅从全集移除；Banzhaf：全联盟平均但不同权重；CASI：2^m−1=31 次并用 Shapley 权重。最强对照需分维度：离线 policy replay 中 SFT=60.32，高于 Singleton=55.00；credit alignment 中 Singleton 是 CASI 之外较强者。

Experiment Setup / Research Questions

五条并行 query；离线审计 1200 requests；对 1171 条可定义比较的请求评价信用向量；RL 三个策略各 500 steps、五个独立种子，1000 held-out requests 进行 auction replay；线上 7 天、10% 流量随机 A/B，约 10^8 observations。主要指标为 replay set value、Shapley 参照 cosine、广告主价值 Advv；线上对照是 production control 而非 Singleton 在线消融。

Results：数字 → Baseline → 差异 → 解释

RQ1 联盟信息是否真实存在：1200 条中 330 条全集 replay=0 的请求，仍有 103 条至少一个非零真子集，说明只筛成功全集会遗漏结构。RQ2 信用分配：median cosine CASI 0.4237、Singleton 0.3877、Banzhaf 0.3800、LOO 0.2269；CASI−Singleton +0.0360（95% CI [0.0036,0.0677]）。RQ3 训练是否有效：held-out replay CASI 66.70±3.40、SFT 60.32、Singleton 55.00±4.00、Broadcast 43.30±4.70。RQ4 线上效果：Advv +3.51%，ad spend +5.08%，但无法将收益完全归因于 credit 而非其他部署差异。

Ablation / Sensitivity

替换 coalition-rerun evaluator 后，CASI cosine=0.6011、Singleton=0.6029，CASI 不再胜出；这是强烈的后端依赖证据。additive null 下多联盟评分本就冗余；精确 31 分需要测试近似采样在 m=10/20 时的成本与方差。

Authors Claim

作者主张集合反事实可改进多动作信用分配并提升训练效果。

Experiments Actually Show

固定快照离线训练、五种子 held-out replay 和随机线上部署都提供了有价值的证据；CASI 优于 Broadcast/Singleton 的固定评估结果可核对。

What Is Not Yet Proven

不能证明代理 evaluator 给出的每条动作 credit 等于真实线上因果贡献；不同 evaluator 上优势并不稳定；线上没有 CASI-vs-Singleton 的独立随机比较。

Hindsight-Privileged RLVR: Single-Rollout Token Credit Without Group Sampling

Wei Chen, Yubing Wu, Zhou Xu 等 · 2026-10-14 v1 · Venue: arXiv preprint · HTML正文 · arXiv/版本记录 · Project/Code: 未核实

人话版：这篇论文到底干了什么？

GRPO 为每个问题生成多条轨迹做组内比较；当全部正确或全部错误时 advantage 可能归零，生成成本却照付。HP-RLVR 每个问题只生成一条轨迹，完成后让生成该轨迹的冻结 policy snapshot 分别在原因果上下文与“看到未来和 verifier 反馈”的上下文给相同 token 打分，利用两种分布的 JSD 作为 token 权重，并用历史 reward baseline 决定正负方向。8B 在数学、代码和 ALFWorld 的 100-step 对照中分别快 1.21/1.46/2.30 倍，但并非三类任务准确率全面领先。

Background & Research Gap（含具体例子）

长推理和工具交互 RL 的主要开销往往是 rollout。GRPO G=8 意味着一个 prompt 生成八个答案，且组内奖励全相同时，归一化优势为零。广播 trajectory 级 reward 又不能分清真正关键的推理转折。PRM 需要额外标签，VinePPO 一类方法要从中间状态补采样；HP-RLVR 想用已经发生的未来而不是额外 rollout 构造局部权重。

Core Insight：证据与直觉

同一模型看到真实后续事件时，对先前 token 的分布如果明显改变，该位置可能与最终结果相关。JSD 衡量两个视图差异，不直接判定正确与否；正负方向由 (R−历史 baseline) 决定。这样单次失败轨迹也能产生非零更新，但“预测分布改变”不等于严格的因果贡献。

Method Deep Dive：Input → Steps → Output

输入 prompt → π_old 采样唯一完整轨迹 y → verifier 得到 R∈[0,1] → 历史已完成轨迹构造 b_k → 在每个可训练 token 的原前缀计算 p_causal → 将实现后的未来及反馈作为训练期 privileged context 计算 p_hindsight → 计算归一化 Jensen–Shannon divergence w_t → 使用 (R−b_k)·w_t 构造 token credit → policy 更新；推理时完全不使用 hindsight。

关键公式 / Objective / Hyperparameters

基础目标 J=E[R(x,y)]。历史基线 b_k=mean(R_history)，s=R−b_k。局部权重 w_t=normalized JSD(p_causal,t || p_hindsight,t)，再用 s·w_t 参与 token 更新。JSD 有界、非负，只调整强度；它并不能确定哪种 token 是“错误原因”。历史基线必须在当前 batch 之前固定，否则不满足论文所述单 rollout 基线条件。

Toy Example

Agent 连续查询两次同一网页，随后修正关键词终于找到答案。成功后重放该完整轨迹，早期“重复搜索”的分布在看到最终成功路径时可能改变很大；这种改变会获得较高权重。但若整个任务成功，单凭 JSD 可能也强化重复动作，所以必须用行为级失败探测或反事实回放进一步验证。

Baseline Comparison / Strongest Baseline

GRPO G=8：多采样组内比较，容易出现同分零梯度；HP-RLVR G=1：单轨迹加两次视图评分。相关工作：PRM、VinePPO、GiGPO、HCAPO，分别依赖过程监督、额外续采样或状态比较；本文并未对所有这些方法进行同配置全面比较。

Experiment Setup / Research Questions

Qwen3 1.7B/4B/8B；数学 AIME24/AIME25/HMMT25，代码 LiveCodeBench，交互 ALFWorld ID/OOD；主要 8B 对照在 100 RL steps、每步四个 prompts，HP 一 prompt 一 rollout，GRPO 一 prompt 八 rollouts。训练时间、NPU-hours、任务指标及 gradient-norm zero 比例；论文特别指出不同大小部分预算不完全一致。

Results：数字 → Baseline → 差异 → 解释

人话版：这篇论文到底干了什么？

交互视频生成需要用户改变动作或视角后尽快看到响应，常见做法是把视频切成很短的 chunk，但短 chunk 牺牲联合建模质量和 GPU 并行。本文允许模型用较大的双向窗口预生成未来 latent，将还没播放的部分视为可撤销缓存；新条件到来时只保护已提交前缀，重新生成受影响后缀。关键指标不是离线 FLOPs 减少，而是从指令到显示的 L50/L95 响应延迟。Sol-H3 长窗口高频更新 L50 从 4.45 秒降到 1.41 秒；但高频修改可能大量废弃预计算。

Background & Research Gap（含具体例子）

交互式生成的性能瓶颈不只是采样吞吐，还包含“等 chunk 边界才能应用新条件”的等待。小 chunk 响应快，却不利于运动连贯性和 GPU 大批并行。大 chunk 质量更好，但若把整个 chunk 一次性提交，用户中途改变指令时要等边界。过去的优化常把 chunk 长度当成响应粒度，本文把“生成窗口”与“不可撤销播放窗口”分离。

Core Insight：证据与直觉

未来视频可以提前计算，但尚未展示的未来不应被视为已经承诺的事实。通过 padding 噪声 latent、缓存预测、增量播放和条件变化时后缀重算，能够保留大窗口双向建模的质量而减少边界等待。此方法改变的是 serving schedule 与缓存提交语义，不是让每一次 DiT forward 的 FLOPs 必然变小。

Method Deep Dive：Input → Steps → Output

输入当前播放位置、条件与历史 KV → 在较大 K-latent 双向窗口追加 padding → 运行采样得到多个未来 latent → 缓存预测并逐步提交播放帧 → 若条件不变则复用缓存 → 若条件更新，有限状态 controller 确定安全保留前缀和最早可更新位置 → 丢弃可撤销后缀并重算 → 继续低延迟播放。作者还讨论 retained-prefix KV 可能受到被废弃双向后缀影响的问题。

关键公式 / Objective / Hyperparameters

端到端响应 L = 条件到达至受新条件影响画面展示的时间；论文比较 L50/L95 而非仅 forward latency。理论分析把原先等待 chunk 边界的项移除，剩余延迟受重算、播放缓冲、网络与 DiT 采样影响。K 是双向窗口大小，USP 是 GPU 并行度，更新频率决定缓存命中与废弃比例。

Toy Example

假设每 4 秒才提交一次完整视频 chunk。用户在第 1 秒要求角色转身，旧方案可能等到第 4 秒边界；新方案已缓存未来但只播出了第 1 秒，能保留已播放画面、废弃第 1 秒后的旧条件 latent，立即启动新条件的后缀采样。用户得到更快反馈，代价是废弃的 latent 计算可能白费。

Your Transformer Is Secretly Elastic

Walter Simoncini 等（arXiv 列表）；HTML 作者字段异常，需核验 PDF · 2026-10-14 v1 · Venue: arXiv preprint；未核实会议接收 · HTML正文 · arXiv/版本记录 · Project/Code: 未核实

人话版：这篇论文到底干了什么？

Your Transformer Is Secretly Elastic 通过联合排序每个 attention head 和 MLP neuron，使同一预训练 Transformer 可以按不同计算预算做连续裁剪。不是给每种设备重新训练独立模型，而是学习跨多个 sparsity target 的统一软掩码排名。论文报告覆盖 27 个视觉/文本 encoder、22M–8B 参数；DINOv3 ViT-H+/16 50% 稀疏只损失 0.8% ImageNet-1k linear-probe accuracy，AugReg ViT-B/16 60% 稀疏在 A100 最高 1.80× throughput、1.26× 单查询 latency 改善。

Background & Gap

固定模型规格不能应对负载变化；传统 one-shot importance score 在高稀疏下不可靠。

Core Method

预训练模型→估计 head/neuron 初始重要度→可微 soft pruning 排序→对多个 sparsity budgets 联合优化→运行时按预算裁剪。

Experiment / Main Finding

27 个 encoder；50% sparsity 的 DINOv3 线性探测 accuracy 下降 0.8%；60% sparsity 的 ViT-B/16 throughput 最高 1.80×，单查询 latency 1.26×。这些不是 Video VLM 直接结果。

Contribution

统一弹性排名和真实 A100 throughput/latency 对照。

Limitation

目前验证主要是 encoder，不可直接外推到视频解码器；arXiv HTML 中作者字段出现异常占位文本，本报告以 arXiv 列表作者为准并标注核验风险。

Connection / Potential Use

可迁移到 video encoder 的动态 token/计算预算。MVE：按视频帧动态选择 encoder budget，测 long-video QA 与 wall-clock。

Why It Matters

值得作为下一轮实验的机制对照，但不能只凭摘要或单项分数断言跨场景成立。进一步复现应固定模型、数据划分、硬件与推理预算，并记录负面结果。

Additional Mechanism Audit / Next Experiment

本工作提供一个很好的“理论剪枝与实际速度”对照范例：50% sparsity 并不意味着 wall-clock 自动快两倍，论文实际测到的是特定 ViT-B/16 在 A100 上最多 1.80× throughput、1.26× 单查询 latency 改善。部署时还要考虑不同 batch size、kernel 对不规则 head/neuron 裁剪的支持，以及 GPU 内存带宽瓶颈。其联合排名适合动态负载，但如果用于视频模型，时间维度上的重要性会随帧内容变化，静态排序可能丢失突发事件。另须注意论文 HTML 的作者字段异常，不能据此生成虚假的机构信息，后续引用前应核对 PDF 元数据。

Research Protocol / Failure Audit

把统一排序用于动态视频时，最好让预算控制器感知 query 类型与视频事件密度，而不是固定剪枝比例。对照可选 static sparsity、per-frame adaptive sparsity、per-query adaptive sparsity，并记录稀疏切换导致的 kernel recompilation 开销。如果理论 FLOPs 下降却真实 latency 不变，应明确标记为工程失败而非“高效”。

Implementation / Generalization Check

可将事件密度作为预算控制变量：静态镜头高剪枝、快速动作低剪枝，再用相同平均 FLOPs 的静态剪枝作对照，验证是否真的存在动态分配价值。
