Paper 1 — T2SPO: Trajectory-to-Step Policy Optimization for Agentic Reinforcement Learning

Authors：Bo-Wen Zhang, Junwei He, Maoqi Liu, Feiran Li, Song-Lin Lv, Wentao Ma, Rongyi Lin, Shuhan Zhong, Lan-Zhe Guo
Affiliation：Nanjing University；ByteDance
Date / Status：2026-09-30，arXiv v1，cs.LG；正文未声明正式 venue。
Links：Paper · HTML

一句话定位

把“成功 trajectory 还剩几步到终点”变成可复用的 progress supervision，从而在不训练额外 critic 的情况下给 Agent RL 的每一步分配细粒度 credit。

人话版

GRPO 很适合 LLM Agent，因为不需要 critic，但它有个硬伤：一个 trajectory 最后成功了，里面每一步往往拿到同一个 outcome advantage。于是“无意义地多搜一次”和“真正完成购买的关键点击”可能被同样强化。T2SPO 不直接训练 value model，而是把过去成功轨迹里的每个 state 标上“从这里到成功还剩多少 turn”，再用冻结的 Qwen3-Embedding + TabPFN，根据历史 state 样本预测当前 state 的 remaining distance。若一步动作让预测距离显著下降，就给正的 auxiliary credit；若没有推进，则不给或给较弱信号。这个 credit 加到 GRPO advantage 上。它在 WebShop 上尤其强：1.5B 的成功率从 GRPO 56.8% 到 73.7%，7B 从 66.1% 到 75.8%。但 ALFWorld 上 GiGPO 仍明显更强，且 T2SPO 自己的 state estimation 占训练 step 时间约 21%，所以它不是“免费 critic”。

Background & Research Gap

长程 Agent 的 reward 常常只有 terminal success。PPO 可以训练 critic，用 V(s) 给中间状态估值，但 critic 本身难训、耗显存，还会带来额外偏差。GRPO 用同 prompt 多条 rollout 的相对 outcome 取代 critic，训练更简单，却把 trajectory 内部差异抹平。具体例子：WebShop 中 Agent 先搜“red waterproof hiking shoes”，随后误点无关商品、返回、重新过滤、最后购买正确商品。最终 reward=1，普通 outcome-only GRPO 会把绕路动作也当作成功轨迹的一部分强化。T2SPO 填的 gap 是：能不能不训练 critic，却从历史经验中恢复“这一步有没有靠近成功”的局部信号？

Core Insight

核心 observation 是成功轨迹天然包含一个弱监督的 progress coordinate：对轨迹 s₀→s₁→…→s_L=success，s_t 的 observed remaining length 可以写成 d_t=L−t。它当然不是真实最短距离——成功轨迹可能绕路——但跨许多历史成功轨迹后，相似 state 的 remaining-length 分布仍可作为“离成功还有多远”的经验 proxy。作者用 PFN 的 in-context regression 特性来避免在线训练新的 scorer：TabPFN 参数固定，只改变 labeled context。这个 insight 属于经验监督重解释 + 工程机制设计，不是“remaining length 等于 optimal value”的理论证明。

Method Deep Dive

Input → 当前 batch 多条 agent rollouts → 从历史成功 trajectory 取 state/remaining-length pairs → state embedding + step/round features → 标准化 + SVD → frozen TabPFN 预测相邻 state 的 remaining distance → potential difference → gate / asinh / RMS normalize / clip → step credit pi,t → 加到 GRPO advantage → policy update → 成功轨迹写回 memory。

Step 1：历史轨迹变监督数据

对成功 trajectory 的每个 state，label 是沿该条成功 continuation 的剩余 turn 数。重点是 label 来自已经发生的经验，不需要人工 step reward。默认 success-only memory；附加实验也把 failure state 用 horizon label 塞进 context，但效果不稳定。

Step 2：state representation

状态文本先经过冻结的 Qwen3-Embedding-0.6B。ALFWorld 用 structured summary，WebShop 用 raw observation；再附加 step index 与 collection round。之后在 support 上拟合标准化与 SVD，并对 support/query 使用同一变换。主配置 context budget=256，ALFWorld SVD64，WebShop SVD32。

Step 3：TabPFN in-context regression

TabPFN V2 不更新参数。它接收历史 labeled context C={(x_j,d_j)}，对当前 state 和 successor state 分别预测 d̂_t、d̂_{t+1}。这样“适应新 policy 的经验”通过更新 context 完成，而不是 gradient update scorer。

Step 4：距离差变 step credit

作者构造 F_t=d̂_t−γd̂_{t+1}。若动作后 remaining distance 降低，则 F_t>0。随后经过 gating、asinh 压缩、RMS normalization、clip，最后乘 process weight w。主配置 γ=1、clip c=5、最终 process weight=0.10，并有 1 round burn-in + 4 round linear ramp。

Step 5：注入 policy optimization

Â_T2SPO(i,t) = Â_base(i,t) + p(i,t)

GRPO 的 outcome advantage 保留，p 只提供 trajectory 内的局部差异。作者还给出 PPO extension：r⁺=r_env+p，再通过 GAE 传播。当前 batch 在完成 scoring 后才写回 memory，避免 target 泄漏。

核心公式与数学直觉

PFN: d̂ = fφ(x ; C), φ frozen

C 是历史 state→remaining-length 的 labeled context。与 learned critic Vψ(s) 最大区别是：T2SPO 不通过当前 RL loss 更新 φ，而通过“换 context”适应训练过程。

F(i,t)=d̂(i,t) − γ d̂(i,t+1)

这是 potential-difference 风格信号。γ=1 时最直观：从预计 5 步到成功变成 3 步，则 F=+2；如果变成 6 步，则 F=-1。它把“进展”定义为 predicted remaining distance 的下降。

p = w · g · clip(asinh(F)/RMS(asinh(F)), -c, c)

asinh 对大值近似 log 压缩、对小值近似线性；RMS 让不同 batch 尺度可比；clip 防止 noisy distance prediction 主导 outcome reward。最敏感超参数之一是 w=0.10：过大时 proxy error 会盖过真实 terminal objective，过小则退化回 GRPO。

Toy Example

设 WebShop 历史成功轨迹里有三类 state：A“已搜到正确类别，剩 5 步”、B“已过滤到正确品牌，剩 3 步”、C“正确商品页，剩 1 步”。新 rollout 当前 state q_t 与 A/B 相似，TabPFN 预测 d̂_t=4.2；Agent 点击正确品牌过滤器后 q_{t+1} 更像 B/C，预测 2.7，则 F=1.5。经过归一化得到 p=+0.08；若本条 trajectory 最终 reward 相对 group 得到 base advantage +0.4，则该 turn 用 +0.48 更新。另一个 turn 点错类目，d̂ 从 4.2 变 5.1，p 为负，即使最终靠后续操作救回来，这一步也不会和关键成功动作得到完全相同的强化。

Experiment Setup & Metrics

Models：Qwen2.5-1.5B-Instruct、Qwen2.5-7B-Instruct。Benchmarks：ALFWorld（六类 household embodied-text tasks，报告 success %）与 WebShop（score 0–100 + success %）。RL 结果三 seeds。Estimator：Qwen3-Embedding-0.6B + TabPFN V2；context/pool budget 256。

Research Question 1：step credit 是否优于 outcome-only GRPO？看 Table 1。
RQ2：distance estimator 是否真的学到 useful progress？看 offline MAE 与 context size/SVD。
RQ3：failure examples 是否帮助？看 success-only vs failure-augmented。
RQ4：这套机制的系统代价多大？看 Figure 3 stage timing。

Metric 教学：ALFWorld success 是任务是否完成，越高越好，但不能反映路径长度；WebShop score 是匹配目标属性的连续质量，success 更严格，二者一起看可区分“接近正确”和“完全完成”。Distance MAE 衡量 d̂ 与 observed remaining length 的平均绝对误差，越低越好，但注意 observed length 不是 shortest-path ground truth。

Results Deep Dive

  1. WebShop 1.5B：GRPO success 56.8→T2SPO 73.7，+16.9pp；score 75.8→88.5，+12.7。这是 strongest result。它支持 step progress 对 web agent 有明显价值，但也可能受 WebShop 状态空间较平滑、remaining distance 更可预测影响。
  2. WebShop 7B：66.1→75.8，+9.7pp；score +6.1。模型更强后增益仍在，但绝对提升变小。
  3. ALFWorld 7B：GRPO overall 77.6→83.6，+6.0pp；说明不是只对 WebShop 有效。
  4. ALFWorld 1.5B：72.8→74.7，仅 +1.9pp，且 std=10.0，证据明显弱于 WebShop。
  5. 类别 failure：1.5B Heat 从 GRPO 78.2 降到 65.9（−12.3pp），Pick2 53.5→43.7（−9.8pp）。说明 proxy progress 并非稳定改善所有行为。
  6. 与 GiGPO：T2SPO 在 WebShop 两个规模均胜，但 ALFWorld 被 GiGPO 明显压制。这是最重要的“不要只看 vs GRPO”的反例。
  7. failure-augmented：7B ALFWorld 83.6→89.3，但 WebShop 两规模 success 反而下降，说明“失败=最大距离”这种粗标签不是通用改进。
  8. 系统代价：WebShop 1.5B mean step 380.21s；state estimation 自身约占 full-step 21.06%。它省掉 learned critic，不等于低开销。

Ablation / Mechanistic Analysis

作者主要通过 context size、SVD dimension、TabPFN vs kNN、failure examples 验证机制。更大 context 会降低 offline distance prediction error；SVD32 下 TabPFN 在三个 context budget 都比最佳 tested kNN 更低 MAE。这个证据说明“PFN 能从历史 states 回归 remaining length”，但还没有严格证明“预测更准 → policy 一定更好”的因果链。failure augmentation 的混合结果反而说明 label semantics 是核心脆弱点。

RL / Agent 专用分析

State：环境 observation + interaction history 的 embedding。Action：LLM 每 turn 生成的 agent action。Policy：Qwen2.5-Instruct。Reward：环境 terminal/task reward + T2SPO auxiliary credit。Trajectory：多 turn state-action sequence。Advantage：GRPO group-relative outcome advantage + p_t。KL：沿用 base GRPO regularization。Credit Assignment：核心创新，用 predicted remaining-distance difference。

Reward hacking 风险：Agent 可能学会进入“看起来像历史成功近端状态”的 observation，而不是真正推进任务；尤其当 embedding 忽略隐藏环境变量时。Long-horizon：理论上越长越需要 step credit，但历史 context 只有 256 rows，且 dead-end state 无法用单一距离表达。Failure propagation：错误 state representation → 错误 d̂ → 错误 p_t → 错误强化 → 新轨迹污染后续 memory，是一个闭环风险。

Claim vs Evidence

Authors Claim：历史 trajectory 可在无额外 learned critic 下提供 step-level feedback。
Experiments Actually Show：在 ALFWorld/WebShop、Qwen2.5 1.5B/7B 上，相对 GRPO overall 提升，尤其 WebShop 强；distance predictor 有可测 MAE 优势。
Not Yet Proven：remaining length 是否普遍等价于 task progress；更复杂 web/computer-use agent、不可逆 dead-end、稀疏成功场景是否稳定；wall-clock 是否优于训练小 critic。

Contribution / Limitation / Reproduction

C1 [New Mechanism]：trajectory→remaining-distance→step credit，是真机制创新。
C2 [New Objective integration]：p_t 直接加 GRPO advantage，较简单但实用。
C3 [New Engineering]：frozen TabPFN + online context refresh，把 adaptation 从 gradient 转为 context。

Authors' limitation：failure supervision mixed；dead-end state 需区分 recoverable detour；成功轨迹少时 context coverage 差。
Additional：estimator 21% step-time；历史成功路径长度不是 optimal distance；embedding/PFN 可能 domain shift；只测两个经典 agent benchmark。

最小复现：先复现 WebShop 1.5B。固定 GRPO recipe，加入 state logger；每个成功 trajectory 生成 (state_text, L−t)；Qwen3-Embedding-0.6B→standardize→SVD32→TabPFN；budget 256、w=0.10、c=5、γ=1。先只跑 success-only，对照 GRPO success/score。最先验证的不是最终分数，而是 d̂ MAE 随 context size 是否下降，再看 +p 是否带来 +success。

Research Value & Migration

Baseline Potential：高，适合任何 outcome-only Agent RL。Migration：很高，尤其 tool-use/computer-use。Systems：中，estimator overhead 是机会点。Attack：高，可攻击 progress estimator。Evaluation：高，可把“step progress calibration”变 metric。Benchmark：可做 dead-end/recoverability benchmark。New Paper：高。

Migration A — Multi-Agent causal credit

Original Problem：单 agent trajectory step credit → Transferable Mechanism：历史成功路径的 distance potential → New RQ：一条 message 对团队 success 的边际推进是多少？ → Modification：state 改成 shared blackboard + sender/receiver embedding，预测 team remaining turns；对每条 message 前后做 Δdistance。
Minimum Experiment：2–4 agent collaborative WebShop/ALFWorld variant；Qwen2.5-3B agents；每轮记录 shared state；256 support rows；GRPO vs trajectory-level reward vs T2SPO-message；metric=team success、turns、message count、credit calibration。Expected：得到 message-level credit assignment。Risk：non-stationarity；Collision：中，需检索 multi-agent credit literature。

Migration B — Recovery-aware progress verifier

Original：remaining length 无法区分 detour/dead-end → Mechanism：historical state-conditioned prediction → RQ：能否同时预测 distance 与 recoverability？ → Modification：双头 context target：(remaining steps, success-after-state probability)，credit 只在 recoverable state 使用 distance，dead-end 给强负信号。
Minimum Experiment：ALFWorld + Sokoban-like irreversible tasks；构造 counterfactual recovery rollouts；baseline GRPO/T2SPO/PPO；metric success、dead-end entry rate、recovery rate、estimator AUROC/MAE。Expected：把 progress credit 扩展到 recovery-aware agent RL。Risk：额外 rollout 成本；Collision：低-中。

Attack / Verification Lens

可做 progress spoofing attack：保持 observation 语义接近成功 state，但隐藏关键 inventory/tool state，测试 estimator 是否给虚假正 credit；可做 black-box probe：仅观察 action distribution 在注入“伪进展文本”前后的变化；可定义 Credit Faithfulness：p_t 与 counterfactual action removal 对最终 success 的真实影响相关性。

Paper 2 — VETO: Video Efficient Token Optimization for Vision-Language Models

Authors：Gueter Josmy Faure, Hao Ping Wang, Min-Hung Chen, Winston H. Hsu
Affiliation：National Taiwan University；NVIDIA
Date / Status：2026-10-01，arXiv v1，cs.CV；正式 venue 未声明。
Links：Paper · HTML

一句话定位

把视频冗余拆成“帧内空间冗余”和“帧间时间冗余”，并严格采用 intra-first→inter 的顺序，使 temporal matching 自己也变便宜，而不是只让最终 LLM 少吃 token。

人话版

很多 Video VLM 加速方法只做一条轴：要么每帧删 token，要么删/并帧。VETO 的关键不是“两个都做”这么简单，而是先空间、后时间。先在每帧里把相似 visual tokens 合并，令 N→N/k；再对已经变瘦的 frame representation 做全局 temporal similarity 和 frame merging。这样不仅最终序列短，连“决定哪些帧该合并”的计算也更便宜。零训练即可插在 visual encoder 和 LLM 之间。LLaVA-OneVision-7B 在 VideoMME 上保持 58.9% accuracy，H100+FlashAttention-2 latency 降到 0.85×；EgoSchema 保持 60.2% accuracy，V100 latency 0.60×。10% token budget 时 55.7%，胜 VFlowOpt 54.9、VisionZip 52.6、FastV 47.9。弱点也清楚：InternVL-2.5 VideoMME 从 49.2 降到 48.1；最大模型仅 7B；compression 不 query-aware。

Gap & Core Insight

Vanilla 视频有 T 帧、每帧 N token，LLM attention 面对总长度 TN，朴素复杂度 O((TN)²)。只做 temporal compression 的方法在决定哪些帧冗余时，仍可能对高维未压缩 frame features 做 expensive matching；只做 spatial compression 又不能去掉跨帧重复。VETO 的 insight 是compression operator 的顺序本身是系统变量：先把 N 降下来，再做 T×T temporal comparison，能同时减少 preprocessing overhead 与 downstream attention。作者还指出 fused attention 会“吃掉”部分 intra-only 的理论收益，但总序列长度减少仍能转化成 wall-clock，因此双轴收益在现代 kernel 下反而更重要。

Method Deep Dive

Video → frozen visual encoder M[B,T,N,C] → Intra-frame uniform anchors + cosine assignment + weighted merge → M'[B,T,N',C] → frame mean pool → T×T cosine similarity → greedy non-overlap frame pair merge → M''[B,T',N',C] → frozen LLM。

Intra-frame

每 k 个位置中固定一个 destination anchor，其余为 source。source 对所有 destination 算 cosine similarity，分配给最相似 anchor，再做 size-weighted average。uniform anchor 看似朴素，却避免 saliency-based anchor 全挤在局部区域，也避免额外 O(N²) anchor scoring。

Inter-frame

空间压缩后，对每帧 N' token mean pool 得 F_t∈R^C；算 G_ij=cos(F_i,F_j)，每轮挑 top-m non-overlapping similar frame pairs，按各自代表的 compression size 做 weighted merge，直到 T'。这一步的关键不是新颖的 cosine，而是它运行在已经压缩的空间。

核心公式

M ∈ R^(B×T×N×C) → M' ∈ R^(B×T×N'×C) → M'' ∈ R^(B×T'×N'×C)
S = cosine(X_src, X_dst), idx_i = argmax_j S_ij
F_t = (1/N') Σ_n M'_(t,n); G_ij = cosine(F_i,F_j)

作者给出的有效复杂度表达为 O(T·N²/k + T²·C)，其中 C≪N 的表述强调 temporal matching 不再直接依赖完整 spatial token grid。最关键超参数：k（每帧保留 1/k）与 G（frame retention fraction）。实验显示 spatial 压缩很耐打：k=2→5，VideoMME 只在 58.4–59.0 波动；temporal 压缩更敏感，G=0.75→0.125 时 58.9→52.1。

Toy Example

64 帧视频，每帧假设 576 visual tokens。k=2 后每帧约 288 token；再保留 75% frame，64→48。最终 token 约从 36,864 降到 13,824，即 37.5% 原始量。更关键的是 frame similarity 不再基于完整 576-token frame bank，而是在 288-token压缩后生成 frame representation。若问题是“杯子什么时候被拿起”，VETO 不看 query；它只是根据视觉相似性把重复静止帧合并。因此大多数重复段可安全压缩，但如果拿杯动作只持续极短、且 frame-level mean 表征不敏感，就存在误合并风险。

一句话定位

并行 draft 的后半段即使在首个错误后仍可能包含正确 token；DEdit 让这些“未来正确 token”作为双向上下文，迭代修复更早的错误，从而延长 speculative verification 的 accepted prefix。

人话版

传统 speculative decoding 的 verifier 只接受最长正确前缀：第 4 个 draft token 错了，即使第 5–12 个里很多其实对，也全丢。Diffusion drafter 更容易出现这种现象，因为各位置可并行预测、彼此依赖弱。DEdit 不急着送 target 验证，而是让同一个轻量 drafter 再跑 1–2 次“编辑”：所有 candidate token 同时更新，并允许位置 i 看见左右两边 proposal token，因此后面的正确猜测能帮助修前面的错误。训练时 ProposalMix 按 first-pass confidence 混合 draft prediction 与 ground truth，教模型“该改的改、正确的别破坏”。在单张 H100、batch1、greedy 下，Qwen3-4B 七套件平均 5.72×，Qwen3-8B 5.97×；强 baseline Domino 分别 5.30×/5.56×。它的机制证据也漂亮：遮掉 future context 后 acceptance 全面下降，copy-heavy 场景收益最大。

Gap & Core Insight

Speculative decoding 的速度取决于每次 target verification 能推进多少 token。Parallel diffusion drafter 一次猜整块，draft 很快，但位置间缺少 causal dependence：早期 token 错并不代表后面全错。标准 prefix verifier 却把首错之后全部浪费。DEdit 的 insight 是：suffix 不只是待验证 candidate，也是纠错上下文。这和 Domino 等 causal corrector 的区别是，causal correction 只能用前缀修后面；DEdit 允许“未来→过去”的 proposal-level 信息流。

Method Deep Dive

Decoded context x + target features h(x) → masked W-token block → P1 parallel proposal → bidirectional editor P2/P3… → final proposal → target single-pass verification → accept longest valid prefix + target token → next round。

P1：parallel diffusion draft

给定 anchor y₀ 和 W−1 个 mask，drafter 同时预测每个位置的 token。此时各位置没有通过生成顺序建立依赖。

P2/P3：iterative edit

同一个 drafter 参数读取完整上一版 proposal z^(k−1)，候选区使用 bidirectional attention；每个位置都可改，没有 confidence gate。多一 pass 就多一次 drafter forward，但不多 target query、不加参数。

ProposalMix

训练 editor 时不能只喂 ground-truth，也不能只喂糟糕 first draft。ProposalMix 根据 first-pass confidence，把一部分位置替换成 ground truth、其余保留 draft prediction，构造“部分正确、部分错误”的现实 proposal。目的有两个：学会 repair，也学会 preserve。

核心公式与指标

qθ,i^(k)(v)=qθ(Y_i=v | x, h(x), z^(k−1)); ŷ_i^(k)=argmax_v qθ,i^(k)(v)

区别在条件 z^(k−1)：P2 以后它包含完整左右 candidate context。

τ = E[a + 1]

a 是 verifier 接受的 draft candidate 数；+1 是 target 自己附加的 token。τ 越高，单轮 target forward 推进越多。它比“draft token accuracy”更贴近 speculative decoding 真正吞吐，但仍必须与 wall-clock speedup 一起看，因为编辑 pass 本身有成本。

Toy Example

Target 正确 continuation 是 [A,B,C,D,E,F]。P1 猜 [A,B,X,D,E,F]。标准 verifier 到 X 就停，后面的 D/E/F 全浪费。DEdit P2 同时看到 [A,B,X,D,E,F]；因为 D/E/F 与上下文形成强模式，它可能把 X 修成 C，最终 target 一次验证接受 6 个。反例：若后半段本身也随机、低可预测，future context 没信息，编辑只增加 latency，所以 DEdit 的收益天然依赖 proposal predictability。

Cross-Paper Synthesis

三篇共同趋势非常清楚：2026 的效率/学习方法越来越不满足于“统一处理所有 token / step / frame”，而是在寻找结构化的局部可利用信号。 T2SPO 找 trajectory 内的 progress gradient；VETO 找 spatial/temporal redundancy 的层级结构；DEdit 找 rejected-prefix 后仍有用的 future draft。它们都把原本会被粗粒度算法丢掉的信息重新变成 signal。

Combined Research Opportunities

Opportunity 1：Budgeted Agent Perception RL

把 VETO 的“先空间压缩、再时间选择”当作 Agent 的 perception action，再用 T2SPO 的 step credit 学习什么时候该保留更多视频信息。状态包含当前 compressed video memory、agent plan、uncertainty；动作是调 k/G 或请求 dense frames；terminal reward 是 task success，step credit 用历史成功 trajectory 的 remaining distance。最小实验可用 video QA agent 或 embodied navigation：比较 static VETO、uniform frames、RL budget controller；同时报告 success、frames、tokens、latency、GPU memory。新意在于“效率动作本身也接受 long-horizon credit assignment”。

Opportunity 2：Structured Agent Decoding Stack

Agent 的 tool call/JSON 往往高度可预测，正是 DEdit future-context 最有利的场景。可先把 DEdit 用于 tool-call generation，再将 T2SPO 的 progress estimator 用作“是否值得继续 edit”的 task-level signal：若当前 agent state 已接近成功且 tool schema predictable，允许更宽 W/更多 edit；探索性阶段则保守。目标不是只提 tokens/s，而是 end-to-end task-success-per-second。

Collision / Overlap

Strongest Collision：T2SPO vs GiGPO。 T2SPO 的 headline 是“比 GRPO 更好的 step credit”，但 Table 1 自己显示 GiGPO 在 ALFWorld overall 明显更强，而 T2SPO 在 WebShop 更强。这意味着真正的新问题不是“有没有 step credit”，而是什么环境结构适合什么 credit estimator。这可以直接转成下一篇论文：environment-conditioned credit assignment / credit router。

VETO 与 DEdit 不构成直接方法 collision，但有共同 systems lesson：理论减少的 token/候选并不自动等于 wall-clock；必须把 preprocessing/editing overhead 计入。两者都值得用“quality × latency × memory”的 Pareto frontier，而不是单一 FLOPs。
