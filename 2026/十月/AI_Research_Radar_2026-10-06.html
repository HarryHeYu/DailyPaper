2. Executive Summary

3–5. Today's Most Important Paper / Top 3 / Top 5

Today's Most Important Paper — CompactionRL

它把两个长期分开的研究问题真正接起来：Agent context management 与 RL credit assignment。不是“先训练 agent，再在推理时随便摘要”，而是让摘要 token 和后续动作共同承担最终任务 reward，并显式修正跨 segment 的 advantage。对 long-horizon coding / web / computer-use agent，这比单纯扩 context window 更像一个可扩展训练范式。

6–9. Four-Track Highlights

RL Highlights

核心变化：信用分配开始从“完整 rollout + terminal reward”向 segment/chunk 级学习移动。CompactionRL 解决跨摘要段 GAE；AC2 用 learned critic 给 10k-token action chunk 估值并允许提前停止。Finetuning with Sampling 又从另一侧挑战“新能力必须靠 RL”这一默认前提：先把 off-policy expert traces 用 MCMC 变得更 on-policy，再做普通 SFT。

Agent / Multi-Agent Highlights

PoS 强调显式 belief state；CompactionRL 学习摘要；Trained Agentic Context Management 学会 self-call + range-read；EdgeAgent 则从系统层处理多个 agent 的并发与工具等待。共同趋势是：agent state 不再等于聊天记录，而是需要可更新、可压缩、可调度、可验证的执行状态。

Video Acceleration Highlights

OneStreamer 的价值在于用 query-independent caption memory 保存过去证据，使历史视觉 feature 不必反复回放；PSTL 只监督 27.5% state tokens 仍优于 dense state supervision。MosaiChunk 则面向 autoregressive video generation，在固定 active-memory budget 下路由历史 chunk。这里真正值得追的是“视觉历史如何变成可检索的低成本 memory”，而不仅是 frame dropping。

Inference Acceleration Highlights

EdgeAgent 给出 Apple M4 上从 UMA-aware 1.29× 到完整系统 1.77× 的真实 speedup；最新 speculative decoding 工作则专门审计 consumer system 的 realized cost，提醒 acceptance rate / theoretical speedup 不能直接等价于 wall-clock。另有 offloaded-weight decoding 工作利用 activation sparsity + weight approximation，方向上直指 memory traffic，而非只减少算术 FLOPs。

Tier S CompactionRL: Reinforcement Learning with Context Compaction for Long-Horizon Agents

Yujiang Li, Zhenyu Hou, Yi Jing, Jie Tang, Yuxiao Dong · submitted 2026-10-01 (current surfaced version) · Paper

人话版：这篇论文到底干了什么？

长时间 coding agent 会把 context 塞满。传统做法是在快满时做摘要，但摘要通常只是推理时的“外挂”：训练模型并没有学过什么信息该留下、什么错误必须带到下一段。CompactionRL 把摘要也当成 policy action，让摘要 token 与执行 token 一起由最终任务成功与否来训练；同时用 token-level normalization 和跨 segment 的 GAE 修正信用分配。结果在 SWE-bench Verified 与 Terminal-Bench 2.0 上稳定提高，而且减少了无效 compaction 和 tool call。

Background & Gap

长 context 的根本问题不只是“装不下”，而是历史里包含大量已经失效的 observation、工具输出和中间尝试。推理时 summarization 可以腾空间，却可能删掉真正决定后续成功的细节，例如失败测试名、修改过的文件路径、尚未完成的 TODO。若 summary 不参与训练，最终成功 reward 无法反向告诉模型“这个摘要丢错东西了”。论文的 gap 正是：如何把 context compaction 变成 agent policy 的一部分，并让跨多个压缩段的 reward 正确归因。

Core Insight & Method Deep Dive

Environment rollout → context threshold → policy generates summary → summary + recent tail → continue acting → final task reward → PPO over execution+summary tokens。关键不是摘要器本身，而是训练结构。每个 action-observation 对保持原子性；空间不足时生成 summary，并保留最近两轮 verbatim tail。策略损失按所有生成 token 归一化，避免“segment 多的 trajectory 获得不合理权重”。

跨段信用用 Â(s,i)=(γλ)^(N>s) A_local(s,i) 近似 full-trajectory GAE。直觉是：早期摘要离最终 reward 更远，因此 discount 应跨越后续所有优化 token，而不是每次切 segment 就把距离重置。若不做这个修正，早期摘要会被错误地当成离 terminal reward 很近。

Toy Example

假设 agent 修 bug：第一段发现 parser.py 的边界条件失败；context 将满时摘要。如果 summary 只写“正在修 parser”，第二段可能重复定位。CompactionRL 的 summary token 也吃最终 reward，因此训练会偏向保留“失败测试 test_empty_token、已修改 parser.py:88、下一步跑 regression suite”这类对未来动作有因果价值的信息。

RL Formulation / Reward / Credit

State 是当前 compacted context + environment observation；Action 包含普通 assistant/tool action 与 summary generation；Policy 为同一 LLM；Reward 主要来自最终任务成功，属于稀疏 outcome reward；Trajectory 跨多个 execution/summary segments；Advantage 用 critic + cross-segment GAE；论文选择 PPO 而非 GRPO，理由之一是不同 rollout 因 compaction 次数不同而长度差异大。reward hacking 风险主要表现为 summary 迎合 judge/任务而丢失泛化信息，但这里任务成功是环境型指标，风险小于纯 LLM-judge reward。

Experiment Setup

模型：GLM-4.7-Flash 30B-A3B 与 GLM-4.5-Air-SFT 106B-A12B。SWE-bench Verified 用随机 200 tasks，Terminal-Bench 2.0 用全量；Pass@1。训练使用 64×H800；context budget 分别 64k/80k，剩余不足 10,240 tokens 触发 compaction，每 rollout 最多三次。

Results / Table & Figure Reading

  • GLM-4.7-Flash：SWE-bench 50.5→56.0（+5.5pp）；Terminal-Bench 13.5→20.2（+6.7pp）。
  • GLM-4.5-Air：59.8→66.4（+6.6pp）；21.3→26.2（+4.9pp）。这是最稳定的主结果：两模型×两 benchmark 全正增益。
  • 普通 PPO + inference compaction 反而只有 48.2 / 12.4，低于 base+compaction，说明“会做任务”不等于“会在压缩后的状态里继续做任务”。
  • 去掉 token-level normalization：GLM-4.5-Air 降至 60.0 / 21.3；去掉 cross-segment GAE：63.0 / 22.5。两个组件都不是装饰，尤其 Terminal-Bench 对训练细节敏感。
  • 在真正触发 compaction 的 SWE 子集，完整方法 47.7%，mask summary loss 的变体 42.4%。同时完整方法平均 0.36 次 compaction、60.7 tool calls；mask-summary 变体 0.58 次、90.8 tool calls——说明收益不是靠“做更多动作”。

Figure 2 是方法核心：执行段和摘要段共享最终 reward；Figure 3 给四组 benchmark 主结果；Figure 4/5 显示更少 compaction/tool calls；Figure 6 只看必须 compaction 的任务，排除“多数任务根本没压缩”的混淆。

Baseline Comparison

Inference-only compaction 合理但摘要未被 outcome 优化；standard PPO + compaction at test 证明普通 RL 不自动获得压缩鲁棒性；SUPO/GRPO-style 是最接近的训练 baseline，但 group synchronization 与 segment variability 不匹配。论文报告 CompactionRL 对 SUPO 在 SWE/Terminal 分别 +4.6/+4.9pp。

Claim vs Evidence

Claim：把 compaction 纳入 RL 能训练更强 long-horizon agent。Evidence：两种模型、两个 coding benchmark、一致增益与组件 ablation 支持。未证明：web/embodied/research agent 是否同样有效；SWE 仅 200-task subset；cross-segment GAE 是近似；summary quality 还有 LLM judge 依赖。

Contribution / Limitation / Research Value

Contribution 1【New Mechanism】：summary 作为 policy action；2【New Objective/Optimization】：token-normalized PPO + cross-segment GAE；3【New Empirical Finding】：普通 RL 不会自然适配 inference compaction。局限是训练成本高、需要训练和推理都支持 compaction、跨域泛化未知。科研价值很高：它把 memory/context engineering 转化为可训练的 credit-assignment 问题。

Migration

Original Problem long-horizon coding → Transferable Mechanism summary action +跨段 credit → New Question 能否学习“保留哪些 agent memory 才最有长期回报” → Modification 将 summary action 改为 memory write/delete/merge action → MVE 在 WebArena/ALFWorld 做固定 memory budget，比较 heuristic summarizer、ReSum、PPO-memory、cross-segment GAE-memory → Model Qwen3-8B/GLM-4.7-Flash → Metric success、tokens、tool calls、memory bytes、recovery after misleading memory → Expected 首个 outcome-trained memory compaction credit benchmark → Risk sparse reward 导致 memory action 学不稳。

五句话

  1. 摘要不是预处理，而可以是 policy action。
  2. 跨 segment 的 reward 距离必须正确计算。
  3. 普通 PPO + test-time compaction 不够。
  4. 完整方法同时提高成功率并减少工具调用。
  5. 最值得迁移到 Agent Memory RL。
Tier S Trust the Critic More — Actor-Critic with Action Chunking (AC2)

Kaiyue Wen, Luke Bailey, Arvind Mahankali, Tengyu Ma · submitted 2026-10-01 surfaced revision · Paper

人话版

GRPO 在长推理里很“浪费”：为了拿到 terminal reward，每条证明都要写到底，而且整条轨迹 token 基本共享同一个 advantage。AC2 的做法是从旧轨迹 prefix 继续生成一个较短 action chunk，然后让 learned critic 估计这个未完成状态最终能拿多少分；只在 critic 对该题足够可靠时才相信它。这样可以不把每条 rollout 都跑到终点。Qwen3-4B 在 IMO-ProofBench 上超过 GRPO 18.5% 峰值时只用约 1/2.5 的 decoding FLOPs，并达到 20.57% 峰值。

Background & Gap

terminal-reward RL 的信用过粗：一篇 50k-token proof 最后一步算错，前面大量正确结构也被一起惩罚。actor-critic 理论上能做更细 credit，但 LLM critic 容易不准，因此主流方法往往只拿 critic 做 baseline，不敢让它替代真实终局。AC2 的关键 gap 是“不是 critic 永远不可信，而是应该按 problem 动态判断何时可信”。

Method / RL Formulation

saved prefix → generate ≤10k-token chunk → critic evaluates endpoint → group-relative chunk advantage → actor update。完整 response budget 50k。critic 与 actor 共享模型参数；可提供历史成功 proof 作为 reference。Local readiness 需要：过去五步 global error 过阈值、该题 local error 过更严格阈值、至少已有一条 policy-generated correct trajectory。ready 后仍抽 1/4 做完整 rollout audit，防 critic 漂移。

State=proof prefix；Action=10k-token continuation chunk；Reward/Value=critic 对最终 rubric score 的期望；Credit=chunk endpoint value 的组内相对优势。真正 terminal reward 仍用于 unready/audit samples。这里最大的 reward-hacking 风险是 actor 学会 exploit critic，因此 readiness + periodic terminal audit 正是防线。

Experiment / Results

  • Qwen3-4B-Thinking-2507，FineProofs-RL 训练，IMO-ProofBench 60 道证明题，0–7 rubric，16 responses/problem。
  • AC2 首次超过 GRPO 峰值 18.50% 时消耗 0.79×10²⁰ decoding FLOPs；GRPO 达峰需要 1.99×10²⁰，约 2.5× 差距。
  • AC2 峰值 20.57%，高于 GRPO 18.50%。
  • ready problem 比例在训练后期约升至 70%，说明 critic 不是从第一步就被盲信。
  • Prefix-GRPO 控制同样复用 prefix、但仍 rollout 到 terminal，落后于 AC2，排除了“只是 replay prefix 带来的收益”。

Figure / Ablation / Evidence

最重要图是 score-vs-decoding-FLOPs：它证明的是decoding compute efficiency，不是完整 wall-clock。论文明确 2.5× 不包含 prefill、critic/judge、validation、训练 forward/backward 等成本，因此不能写成“训练快 2.5×”。readiness/error 曲线则说明 critic 信任是逐题建立的。

Contribution / Limitation

【New Mechanism】action-chunk actor-critic；【New Credit Assignment】critic endpoint value 替代部分 terminal rollout；【New Empirical Finding】guarded critic 在长 proof RL 中可以可靠到足以节省 rollout。弱点：目前只证明 repeated-data proof training；readiness 依赖完整轨迹形成 ground truth，single-epoch 场景未解决；真实 wall-clock 未完整报告。

Migration

Agent RL 的工具轨迹天然比 proof 更适合 chunk：以“一个工具调用+反馈”作为 chunk，critic 预测任务最终成功率；先在 WebArena mini-set 比 GRPO/PPO/AC2-tool，测 task success、environment steps、LLM tokens、critic calibration、wall-clock。若能在 tool latency 高时提前淘汰低价值分支，可能同时改善 credit assignment 与系统吞吐。

五句话

  1. 不要给整条长轨迹一个粗 advantage。
  2. critic 可以信，但要按题目建立 readiness。
  3. chunk endpoint value 可替代部分 terminal rollout。
  4. 2.5× 是 decoding FLOPs，不是端到端速度。
  5. 最值得迁移到 tool-use agent 的 step/chunk credit。
Tier S EdgeAgent — On-Device Multi-Agent Inference Orchestration

Yuhai Long et al. · arXiv:2610.03394 · submitted 2026-10-02 · Paper

人话版

多 Agent 在端侧运行时，瓶颈并不只是模型算得慢：多个 agent 共享 CPU/GPU unified memory，而且 tool call 会产生不可预测的等待。EdgeAgent 把这两个系统事实一起处理：一方面针对 UMA 调度模型执行与内存，另一方面 agent 在等工具时主动 suspend/yield，让硬件去服务其他可运行 agent。Apple M4 上，UMA-aware execution 单独带来 1.29×，加上 agent-aware scheduling 后在极端 tool latency 下达到 1.77×。这是今天最值得关注的“Agent × Inference Systems”论文。

Bottleneck / Acceleration Mechanism

Bottleneck 是统一内存上的模型执行资源竞争 + tool-induced bubbles，而不是单纯 attention FLOPs。减少的是 idle time、重复/低效的数据移动与调度空洞。关键系统思想是：agent workload 的“等待外部世界”阶段应被当作 scheduler 可利用的结构，而非普通 batch inference 的异常。

Agent Architecture / State / Failure Propagation

Multiple agents → LLM inference → tool request → async wait → suspend/yield → schedule another ready agent → resume。agent state 必须能跨暂停保存；tool history 与未完成请求属于执行状态。若调度器把 blocked agent 当 ready，会造成硬件空转；若恢复状态/内存映射错误，错误会直接传播到后续工具决策。因此它是“agent orchestration correctness + performance”共同问题。

Baseline / Evidence / Limitation

strongest conceptual baseline 是 batched speculative decoding。EdgeAgent 的 1.29×→1.77× 分解提供了模块贡献证据，但当前报告仍需进一步核对不同 batch size、工具等待分布、模型大小、内存压力下的曲线。最大外推风险是 Apple UMA 的硬件特性：离散 GPU + PCIe、数据中心多 GPU 的收益结构可能不同。

Contribution

【New System/Engineering】面向 UMA 的多 agent 推理编排；【New Scheduling Mechanism】tool wait suspend-and-yield；【New Empirical Finding】agent-aware scheduler 能把外部工具等待转化为可利用并发。

Migration

直接可做：把 coding-agent harness 的 trace 分成 LLM compute / tool CPU / network wait / filesystem wait，构建 agent-aware continuous batching。MVE：4–16 个并发 SWE/terminal agents，对比普通 vLLM continuous batching、naive process concurrency、EdgeAgent-style yield；指标 TTFT、TPOT、task wall-clock、GPU utilization、memory peak、success。若“工具等待越大→调度收益越大”形成稳定 scaling law，会是很强 systems paper。

五句话

  1. Agent inference 不是普通 chat batching。
  2. 工具等待本身是一种可调度资源。
  3. UMA-aware 部分 1.29×，完整系统最高 1.77×。
  4. 真实 wall-clock 比 FLOPs 更有意义。
  5. 值得迁移到 coding-agent / browser-agent serving。
Tier A Beyond Memory: Harnessing Long-Horizon Agents with Explicit Belief States

Paper

人话版

PoS 认为 long-horizon agent 的核心不是“记住更多历史”，而是持续维护一个可行动的当前世界 belief：什么已经确定、什么仍未解决、任务还差什么。它还检测 Belief Trapping——agent 看似一直行动但其实没有推进——并按陷阱类型恢复。一个 ALFWorld 例子中 raw trajectory agent 50 步失败，而 PoS 跟踪“mug 还没加热”后 17 步完成。

Method / Agent State

trajectory → belief construction → consistency validation → unresolved requirements → progress monitor → trap-specific recovery → next action。state 从原始 transcript 升级为 world-state + unresolved requirements。这个设计特别适合动态环境，因为旧 observation 可能已经被 agent 自己的动作作废。

Experiments / Results

论文在四个 execution/diagnosis benchmark、三个 LLM backbone 上总体均取得最高表现；ablation 显示 consistency validation 与 recovery 都重要，context scaling 也显示对增长历史更稳。当前最值得读的是 belief trapping 分类与 recovery 部分，而不是只看最终成功率。

Contribution / Limitation / Migration

【New Mechanism】显式 belief-state context management；【New Empirical Finding】“历史保存”不等于“当前状态理解”。局限是 belief 生成本身可能错，错误会被压缩成高置信 state 并持续传播。MVE：在 WebArena 加入环境状态突变，比较 raw history/RAG memory/PoS，测 stale-belief rate、recovery latency、success。Worth Deep Reading: YES。

Tier A OneStreamer: Unifying Perception, Memory, and Proactive Response in Streaming Video Interaction

Paper

人话版

流式视频 agent 不知道未来会问什么，因此必须在“相关性未知”时就保存证据。OneStreamer 用 Proactive Hierarchical Caption Memory 把过去视觉片段写成带时间定位的局部 caption 与事件 summary，推理时只保留近期视觉窗口 + 历史文本记忆，不必反复读取所有旧视觉 feature；同时 PSTL 只挑关键状态变化/保持 token 监督，减少大量重复“等待”状态。

Method / Efficiency

stream frames → recent visual window → proactive caption generation → hierarchical textual memory → task evidence sufficient? → response/wait。PSTL 让 state supervision 只覆盖 27.5% annotated state tokens，却优于 dense supervision。4B model 在论文比较的 8 个 streaming video benchmark 上均取得最佳结果；保留生成 caption 提升 historical QA 且不损害 realtime perception。

Tier A Trained Agentic Context Management

Paper

人话版

它不直接把 context window 做到百万 token，而是只给模型 8k context，再提供两个极简工具：调用自己、读取原输入某个 token range。模型通过训练学会像操作外部存储一样管理长文档。Qwen3.6-35B-A3B 在 OOLONG-synth 文档超过 40k token 时，用 8k context 达到与 GPT-5.4 1M-context 相当的表现（按论文报告）。

Core Insight / Method

长上下文能力可以被重新表述为 agent skill：模型不需要把全部信息同时塞进 attention，而需要学会“何时读取哪一段、如何递归调用自己”。这把 O(n²) attention 方向的问题部分转化为 tool-selection / information retrieval 问题。

Experiment / Contribution / Limitation

17 页、6 figures、4 tables，代码链接已在 arXiv 条目公开，状态为 under review。最重要结果是 8k-vs-1M 的对比，但需注意 benchmark 为 OOLONG-synth，不能直接外推真实 agent traces。系统成本还应把 self-call 次数、range-read 次数、额外 decode tokens 算进去，否则“context 小”不等于 wall-clock 更快。【New Mechanism】trained context harness；【Systems Value】极高。MVE：把工具换成 agent trajectory range-read，在 SWE/BrowserGym 比 128k raw context 与 8k trained retrieval harness，测成功率、TTFT、总 tokens、KV memory、wall-clock。Worth Deep Reading: YES。

Tier A Finetuning with Sampling: SFT Learns Better Than You Think

Paper

人话版

这篇挑战“RL 才能 on-policy 泛化，SFT 天生 off-policy”的二分法。作者不改 SFT loss，而是先用 MCMC 把 expert trace 改写成更像 base model 自己会生成、但仍保持专家信息的样本，再 SFT。化学案例中 Ours 在 Chemistry 66.0、MMLU 69.2、AMC 37.4，对比普通 SFT 61.8/58.6/27.7；也优于 OPSD 的 61.8/65.1/34.9。

Method

目标分布可理解为“base-model distribution 在语义等价集合上的条件分布”。用 Metropolis–Hastings 接受/拒绝 base model proposal，长序列按 block 渐进重写。KL 的直觉是尽量留在模型熟悉的生成流形上，同时保留 expert correctness。

Why it matters for RL

它不是 RL paper，却直接触碰 sample efficiency：如果成功轨迹稀缺，先把 off-policy expert data 投影到 model-native distribution，可能比让 policy 从零 rollout 找成功更省样本。局限是“语义等价”依赖 task-specific checker/LLM grader，MCMC 本身也有额外采样成本。MVE：Agent RL 前先 MCMC-adapt expert trajectories，再 SFT→RL，测 warm-start success、rollouts-to-threshold、forgetting。Worth Deep Reading: YES。

Tier A Execution-Path Qualification and Realized Costs in Speculative Decoding on Consumer Systems

Paper

人话版

这篇把 speculative decoding 从“理论每次验证多个 token”拉回真实系统：消费者硬件上，真正速度取决于 draft/verify 的执行路径、接受长度、kernel/同步开销和内存行为。它的科研价值不在发明一个新 decoder，而在于建立“哪些路径真的省时间”的资格判断。

Bottleneck / System Lens

Speculative decoding 同时影响 decode compute 与 memory traffic；如果 draft 太贵、acceptance 太低、verification batch 不能高效映射到硬件，理论 token-step 减少可能不转化为 TPOT 改善。论文 23 页、4 figures 并含 appendix，属于今天 inference acceleration 必须读的测量型工作。

Research Value / Migration

对 Agent 特别重要：tool-use workload 有大量短 generation、频繁 prefill 和中断，传统长连续 decode 上测出的 speculative gain 可能消失。建议复现时按 TTFT、TPOT、accepted tokens/step、draft overhead、energy、batch size 分层。MVE：在 consumer GPU/Apple Silicon 上分别跑 chat、long-CoT、coding-agent short bursts，找 speculative decoding 的 workload phase diagram。Worth Deep Reading: YES。

13. Idea Mining

Idea 1 — Outcome-Trained Agent Memory Compaction

Inspiration：CompactionRL + PoS。Gap：现有 agent memory 多优化 retrieval quality，不优化“这次写入/删除是否提高未来任务成功”。Hypothesis：把 memory write/merge/delete 当 policy action，并用跨 segment advantage 训练，可比 heuristic summarization 更好保留因果关键状态。

Proposed：Memory-Action PPO：每 N tool steps 允许 WRITE/MERGE/DELETE，critic 估计 memory state value；对跨段 reward 用 token/step-distance GAE。MVE：Qwen3-8B + ALFWorld/WebArena-mini；固定 4k memory budget；baseline raw-history、RAG、summary、PoS、CompactionRL-style summary；metric success、memory bytes、tool calls、stale-memory rate、recovery。Expected Contribution：从 memory retrieval 转向 outcome-trained memory policy。Novelty ★★★★★ · Feasibility ★★★★☆ · Compute ★★★☆☆ · Risk：sparse reward / critic exploit · Collision Risk：中 · Best Venue：ICLR/NeurIPS。

14. Collision Detection

⚠️ Collision Warning: YES

最明显碰撞：“Agent context compression + RL” 已被 CompactionRL、SUPO、ReSum 等推进；若新项目只是“让 agent 用 RL 学摘要”，创新空间已经很窄。剩余 gap 应转向 memory operation 的更细粒度 action（write/merge/delete）、跨 agent shared memory、belief consistency、或者真实 systems cost。

第二处：“critic 做细粒度 LLM RL credit” 已有 AC2、VinePPO、DGPO、TRIAGE 等脉络。差异化应落到 tool-use / multi-agent / video-memory 这种新结构，而不是再做一个 token-level advantage 变体。

Inference：speculative decoding 已非常拥挤；今天更值得做的是 agent workload 下的 realized-cost / scheduling interaction，而不是再发一个 acceptance heuristic。
