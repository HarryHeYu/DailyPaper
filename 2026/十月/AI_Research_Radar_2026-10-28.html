Tier S 1. When Fine-Grained Credit Assignment Helps and Hurts: Multimodal Agentic Reinforcement Learning through Video Editing

arXiv:2610.35497 · 2026-10-26 · arXiv preprint；未核验正式录用
Authors / Affiliation: Lei Zhao; Zongheng Cao; Xinyu Hu
Abstract / Metadata · Paper HTML · PDF · Code: 未核验 / Not Reported

人话版：这篇论文到底干了什么？

这篇论文问的是一个很容易被忽略的问题：长轨迹 Agent 的奖励是不是越细越好？作者把真实视频剪辑拆成素材选择、叙事排序、粗剪、精剪四类任务，在同一个 Qwen3.5-9B 上比较最终结果奖励、逐轮过程奖励与 token 级自蒸馏。结论并非“过程奖励普遍胜出”：短任务只用 outcome reward 已经很强；长达数十步的精剪才明显受益。固定过程奖励会诱使模型不停检查画面、反复调用工具却不交付作品。把过程奖励权重逐步降到零，反而使精剪得分比 outcome-only GRPO 高 45.4%。真正值得学的是如何根据任务跨度与训练阶段决定信用分配的粒度，而不是简单添加 PRM。

Background & Research Gap

Agent RL 常把一条完整轨迹的最终成败广播到每个 token 或每次工具调用。设想剪辑 Agent 已正确选片、排好镜头，却在最后导出时失败；单一负奖励会惩罚此前正确步骤。相反，如果成片勉强过关，途中大量无意义的重复检查也可能获得正优势。过程奖励看似能修复这一问题，但如果模型学会“多看、多想、多调用”就能拿到过程分数，最终交付反而被挤掉。

论文的缺口不是缺少一种新损失，而是缺少跨任务复杂度、轨迹长度、监督粒度的控制性比较：何时精细 credit 有用、何时伤害性能，以及失败机制究竟来自哪里。

Core Insight & Method Deep Dive

Input → 编辑需求、视频素材、工具环境 → Agent 多轮观察/剪辑 → 根据交付结果或逐轮行为计算 reward → GRPO/OPSD 更新 → 输出可验证剪辑成品。四种训练臂共享同一基础模型和任务集，隔离 credit assignment 的影响。Content Selection 是无序素材选择；Narrative Sequencing 需要时间排序；Rough Cut 需要选区间；Fine Cut 涉及声音与转场等更长链路。

Outcome-only GRPO 只使用可验证的最终交付分数；GRPO+PRM 把 LLM judge 给出的 turn-level process reward 加到训练信号。固定版 λ=0.5 贯穿训练；衰减版在第 20 次更新前保持 0.5，在 20–30 次更新期间衰减到 0，之后只优化 outcome。OPSD 使用带 privileged information 的冻结教师提供 token-level 指导，分别测试参考答案与逐轮建议。这样既比较监督密度，也比较过程信号是否可靠。

关键机制是“先用过程奖励扶上马，再让最终任务结果接管优化方向”。早期过程奖励促使 Agent 真的检查画面、学会调用工具；后期如果仍对这些代理行为付费，模型会延长轨迹而非完成作品。衰减使最终结果重新成为唯一持续优化的目标。

Objective / RL Formulation / Toy Example

状态 s_t 包含编辑需求、当前时间线、可见画面和工具历史；动作 a_t 是观察、调用编辑工具或交付；轨迹 τ=(s₀,a₀,…,s_T)；策略为 Qwen3.5-9B。Outcome reward 来自交付评分；process reward 来自 LLM judge 对每轮行为的评价。概念上可写 R(τ)=R_outcome(τ)+λ(u)·R_process(τ)，其中 u 为训练更新编号；GRPO 在同题多条 rollout 内构造相对优势，不需要单独训练 value critic。论文还测试 OPSD 的教师–学生差异信号，不能把它等同于标准 GRPO。

Toy：剪辑 90 秒预告片时，Agent 第 12 步发现镜头音画不同步并修正，之后第 30 步重复查看同一片段 20 次。过程 judge 可能都给“认真核对”加分；但真正有用的是第一次修正。固定 λ 会鼓励重复核对；衰减 λ 让“按时交付且成片合格”占据主导。这里的 reward hacking 是实验观察到的代理目标偏离，而不是推断模型有主观意图。

Experiment Setup / Baselines / RQ

49 部影片产生候选任务，过滤后使用 797 项；训练 716 项来自 43 部影片，验证 81 项来自不重叠的 6 部影片。四类验证任务数量依次为 14、15、26、26。Qwen3.5-9B，50 次训练更新，16 tasks/update，GRPO 每任务 8 条 rollout，AdamW 学习率 1e-6，turn budget 100，最终分数按 4 次独立评估平均。核心对照包括未训练 Qwen3.5-9B、outcome-only GRPO、固定 PRM、衰减 PRM、两种 OPSD；这里 strongest baseline 应按具体任务判定，主对照是 outcome-only GRPO。

RQ1：任务越长、正负步骤混杂越多，细粒度奖励是否越有价值？RQ2：过程奖励增加时，最终交付是否也改善？RQ3：token-level 自蒸馏是否真的优于简单的 outcome-only 优化？RQ4：同一预算下视觉检查与工具调用的变化能否解释成绩变化？

Results / Table & Figure Reading

Table 3：未训练模型总体 0.284；outcome-only GRPO 提升到 0.413；固定 λ 的 PRM 只有 0.334；衰减 λ 达到 0.447。精剪 Fine Cut 从 outcome-only 的 0.201 升到衰减版的 0.293，提升约 45.4%；但这不能推广为所有任务都应加过程奖励。

Table 4：精剪轨迹中的正面步骤仅 16.7%，负面步骤 35.8%，正负混杂指标 0.651；另外三类混杂指标仅 0.297–0.390。这个相关性支持“长轨迹更需要局部区分”，但不能证明长度是唯一因果因素，因为任务类型也改变了。

Table 5：固定 λ 平均工具调用 165.8 次，而 outcome-only 只有 52.2 次；固定版截断率 44.1%，outcome-only 仅 0.3%。衰减后调用降至 99.5，截断率降至 6.2%，同时总体分数 0.334→0.447。Figure 1 的训练曲线还显示，固定 PRM 的过程奖励持续升高，约第 30 次更新后 outcome 反而下降。OPSD 参考答案版总体 0.277，逐轮建议版仅 0.044，是本研究最明显的失败结果之一。

Ablation / Claim vs Evidence

去掉后期 process-weight decay，最终任务分数下降且大量轨迹耗尽交互预算；说明过程监督应当是阶段性脚手架，而不是永远奖励的目标。改变 OPSD 的 privileged information 会导致从“几乎无收益”到“严重崩溃”的巨大差别，说明 token-level dense signal 并不天然可靠。

Authors Claim：credit granularity 的价值依赖任务结构，固定过程奖励可能造成 reward hacking。Experiments Actually Show：在该剪辑环境和这一组训练配置下，衰减 PRM 的确显著改善长任务并降低截断；OPSD 两个设置均不理想。What Is Not Yet Proven：其他 Agent 环境、其他 PRM judge、不同预算或自适应 λ 是否得到同样结论；Table 4 的混杂性与效果之间仍主要是机制解释而非严格因果识别。

Contribution / Limitation / Research Value

贡献类型：New Benchmark（四种真实视频编辑任务与验证协议）、New Empirical Finding（细粒度 credit 的正负边界）、Reward Design Insight（过程奖励退火）。它对 RL 的价值高于单一 benchmark 提分：把 reward 设计、工具预算、完成率联系到同一条可观测因果链；对 Agent 是长轨迹失败归因；对 Video 是以真实剪辑环境检验视觉工具使用，而非视频编码加速。

作者限制包括任务域、judge 信号和 OPSD 的教师配置；附加限制是没有充分隔离不同任务的长度与动作空间，且训练规模与统计显著性不能自动外推到更大模型。Baseline Potential 很强：直接复现 outcome-only 与固定/衰减 PRM。System Value 在于监控无效工具调用与 truncation；Benchmark Value 在于真实交付检验；Attack/Evaluation Value 在于构造“过程分数高但任务失败”的 reward-hacking 压力测试；New Paper Potential 在于自适应 credit 粒度。

Migration / Minimum Experiment / Risk

Original Problem：视频编辑长轨迹的 credit 失真 → Transferable Mechanism：过程奖励的阶段性使用与终局结果锚定 → New Research Question：能否根据 critic 不确定性、动作可逆性和剩余预算自动调整 λ，而非固定第 20–30 次衰减？→ Method Modification：每轮记录局部 reward、终局可达性与工具预算，动态降低奖励易被刷分的行为权重 → Minimum Experiment：先在 Fine Cut 与一个短任务上做 fixed/decay/adaptive 三臂对照 → Model：Qwen3.5-9B → Dataset：论文视频编辑任务 → Baseline：outcome-only GRPO、fixed/decayed PRM、FOCUS → Metric：最终分数、截断率、工具调用、奖励相关性、rollout 成本 → Expected Contribution：可诊断的长轨迹 reward 调度原则 → Risk：动态控制器本身可能被模型操纵，或只学习到任务长度启发式。

五句话总结

一，长轨迹需要局部反馈，但不是越密越好。二，固定过程奖励会诱发大量无意义工具调用。三，衰减过程奖励把学习重心重新拉回交付结果。四，OPSD 的失败提醒我们 teacher 信息质量比监督粒度更重要。五，下一步应研究基于真实贡献与预算的自适应 credit，而非再堆一种 loss。

Tier S 2. Adaptive Memory Index Evolution for Agents

arXiv:2610.34977 · 2026-10（具体提交日未单独核验） · arXiv preprint；未核验正式录用
Authors / Affiliation: Yuntong Hu; Tongli Su; Yuanfu Sun; Shuo Ma; Qiaoyu Tan; Liang Zhao
Abstract / Metadata · Paper HTML · PDF · Code: 未核验 / Not Reported

人话版：这篇论文到底干了什么？

Agent 的长期记忆经常不是“没有存”，而是“存了也取不到”。这篇论文把 memory content 和 memory access index 拆开：保留原始记忆不动，只根据每次真实检索的竞争情况，持续调整各条记忆的访问优先级。AMIE 既可用语义教师训练 keep/suppress policy，也可以只用检索频次积累状态。作者在五种记忆宿主、三种 benchmark 上做交叉评估，训练版 15/15 下游效用比较均为正增益；更有意思的是，极简单的计数策略有时不输复杂策略，却也可能压制有用记忆。它提供了一个独立于记忆写入、很适合做因果归因的研究接口。

Background & Research Gap

多数 Agent memory 论文在“怎么写摘要、怎么组织知识图谱、怎么压缩历史”上竞争，但一条正确的记忆被长期保留并不意味着它会进入当前上下文。例如“项目使用 clang 而非 GCC”可能被 200 条更近的构建日志挤出 top-k，模型看似遗忘，实则只是 retrieval 被干扰。现有系统往往同时改变记忆内容和检索策略，使得收益究竟来自写入还是访问难以归因。

论文提出 Memory Index Evolution：固定 C_t（存储内容），单独更新 I_t（访问状态），因此可以在同一个宿主与同一批内容上做控制实验。它并不声称取代 content evolution，而是把长期被忽略的可访问性变成独立研究对象。

Core Insight & Method Deep Dive

Input → 当前 query 与宿主原生检索结果 → 读取候选记忆、排名和可用反馈 → 轻量策略对候选输出 keep/suppress mask → 将动作积累进每条记忆的有界访问状态 → 对后续检索分数重加权 → 输出新的 top-k 给 Agent。AMIE 作为 wrapper 运行，不改记忆文本、不训练宿主模型。

语义策略先从教师对“这条记忆是否值得继续暴露”的判断蒸馏出轻量预测器，再在部署时根据实际 retrieval traffic 更新；有界状态避免无限累计。对照的 frozen policy 只用静态决策，count policy 不调用语义模型，仅依据检索频次做持久更新。论文强调更新发生在记忆库 sealing 之后，防止把内容变化误当成索引演化收益。

最重要的机制并非“频次高就应置顶”，而是观察到竞争者反复占据有限窗口时，可以通过相对抑制释放未曾直接见过的证据。学习到的选择性则防止频次规则把真正有用、经常被检索的记忆一并打压。

Objective / Toy Example

形式化记忆为 M_t=(C_t,I_t)，检索 S_t=R(q_t;C_t,I_t)⊆C_t。内容演化 C_{t+1}=G(C_t,O_t)，索引演化 I_{t+1}=F(I_t,O_t)；本工作冻结 G，只研究 F。目标不是“多召回一切”，而是在固定上下文预算下提高下游效用 U(A(q,S))。

Toy：某编译 Agent 有三条历史：A“构建必须用 LLVM22”、B“昨天执行过 cmake”、C“昨天又执行过 cmake”。若 B/C 在相似查询中长期占据 top-2，A 即使正确也取不出来。AMIE 可抑制重复竞争者，提升 A 的相对曝光。但如果 B 实际上含有关键报错，盲目按频次压制它就会损失任务效用——这正是 count policy 的失效模式。

Experiment Setup / Baselines / RQ

三组 benchmark：LoCoMo、GroupMem、MemBench；五种宿主：BM25、Mem0、MemoryOS、A-MEM、Memory-R2。比较 Host only、Trained AMIE、Frozen AMIE、Count-only；检索层使用宿主定义的 recall/ranking，最终层 LoCoMo 用 F1、其他任务用 accuracy。作者报告 15 组下游比较与 10 组可测 retrieval 的成对对照；只有部分对照提供成对置信区间，不能把 15/15 都理解成统计显著。

RQ1：不修改 memory content 能否提升下游回答？RQ2：效果来自语义选择还是仅来自检索流量的累积？RQ3：哪些宿主和 memory granularity 更容易被索引更新改善？RQ4：持久抑制是否会带来 stale/utility regression？

Results / Table & Figure Reading

Table 1（检索）：LoCoMo BM25 从 51.94 升到 trained 53.02（+1.08pp），简单 count 却到 53.41（+1.47pp）；LoCoMo Mem0 从 42.17 到 44.42（+2.25pp），count 到 45.03。MemBench BM25 从 83.94 到 85.62（+1.68pp），但 count 降至 81.82（-2.12pp）。LoCoMo Memory-R2 从 65.92 到 67.78（+1.86pp），count 反而到 65.03（-0.89pp）。这组“简单方法有时最好、有时伤害”的对照比单纯平均提升更值得关注。

Table 2（下游）：训练 AMIE 在 15/15 个宿主×数据集组合中提升 F1/accuracy，增幅 0.70–3.37 个百分点；10/10 个同时测 retrieval 的组合也都出现正向变化。LoCoMo Mem0 的下游指标从 9.98 到 12.44（+2.46pp），该配对给出 bootstrap 95% 区间 [+1.60,+3.24]。Figure 1 及后续深度分析表明，收益往往集中在检索结果前部，而非记忆总量变大。

Ablation / Claim vs Evidence

移除语义教师、仅积累检索流量，部分宿主仍获益，证明持久访问状态本身就是有效机制；但 Memory-R2、MemBench BM25 等场景出现负增益，说明“多次被检索”不等于“应该被惩罚”。论文还分析反复竞争、headroom、存储粒度和过期状态：没有可被重新排序的候选时，索引更新无法凭空创造证据。

Authors Claim：索引演化可作为独立且通用的适应层。Experiments Actually Show：多宿主正向结果与若干严格配对重放支持这个判断。What Is Not Yet Proven：检索增益是否在问题级因果中介下游收益、长达数千轮后是否稳定、遇到对抗性检索/记忆投毒是否可靠，以及不同宿主的索引更新成本是否完全可比。

Contribution / Limitation / Research Value

贡献类型：New Mechanism（持久访问状态与内容分离）、New Empirical Finding（流量计数有强基线价值但会反噬）、New Evaluation Protocol（同存储、同检索条件下控制访问变化）。它对 Agent 的意义是把 memory lifecycle 从“写/删”扩展到“谁能被看到”；对 RL 是提供 action-level retrieval policy 的可学习接口；对 Security 是让 memory poisoning 与 stale memory 的传播路径更可审计。

局限：依赖宿主可暴露检索候选、竞争与访问状态；对原始候选完全缺失的事实无能为力；持续压制可能引入长期偏差；对跨任务共享记忆、动态写入和大规模并发没有充分证明。Baseline Potential 很高，因为 count-only 与 trained 版容易拆解；Benchmark Value 在于 LoCoMo 等固定对照；Attack/Evaluation Value 可定义访问剥夺攻击；New Paper Potential 在于“记忆真正造成性能变化”的反事实 credit。

Migration / Minimum Experiment / Risk

五句话总结

一，记忆的存在与可访问性是两个变量。二，不修改内容也能通过索引更新改善回答。三，简单频次策略是必须打败的强基线。四，选择性抑制能减少错误压制，但不保证长期稳定。五，最有价值的后续是对 memory retrieval 的反事实贡献测量。

Further Mechanism & Evaluation Interpretation

在 AMIE 中，“当前 query 的正确答案”与“应该永久压制哪条 memory”并非同一件事。一次 query 的相关性可以瞬时变化，但 index state 是跨请求持续积累的。因此评估时应同时看 immediate retrieval、后续 query 的 carry-over，以及是否把短期噪声固化成长期优先级。论文的 bounded state 是重要设计选择：它使更新幅度受控，却也带来窗口长度、衰减系数和突发任务切换之间的权衡。

这也解释了为什么只用 count 的策略有时很强：它无需理解内容，已经能够打破长期占位的竞争关系；而为什么有时失败：高频记忆也可能是真正的关键事实。最值得复现的不是把所有宿主平均，而是按“竞争强度×可到达的 top-k 空间”分层分析，进一步验证改善是否来自更正确的答案证据。

Tier S 3. Triage: Skip, Skim, or Refine Attention Tiles in Video Diffusion Transformers

arXiv:2610.35706 · 2026-10-26 · arXiv preprint；未核验正式录用
Authors / Affiliation: Yeonjae Kim; Omin Kwon; Seong Hoon Seo; Jae W. Lee（Seoul National University）
Abstract / Metadata · Paper HTML · PDF · Code: 未核验 / Not Reported

人话版：这篇论文到底干了什么？

视频生成的瓶颈不只是 token 多，而是视频 DiT 的每个 attention tile 值得花多少计算。传统 sparse attention 统一跳过一部分块，量化 attention 统一降低精度，二者都无法处理“有的块可跳、有的块 FP4 就够、有的块必须精算”的差异。Triage 用低成本统计估计每块的近似误差，把块分成 skip、skim、refine 三档，并在 Blackwell FP4 Tensor Core 上用融合 kernel 一次执行。论文在 Wan2.2、HunyuanVideo、LTX-2.5 上测得最高 2.32× 端到端生成加速，同时与最接近的稀疏基线相比保持更高的 dense-output PSNR。这是有真实 wall-clock 数据的系统工作，值得与只报 FLOPs 的视频压缩论文区分。

Background & Research Gap

高分辨率视频生成会产生数万乃至十几万视觉 token；自注意力对每一步扩散反复计算，单纯把 denoising step 减少会改变生成模型，而直接稀疏/低精度 attention 又可能在关键帧、运动边界产生明显误差。举例：一个镜头里大面积静止天空的跨帧注意力块，与正在快速运动的人脸边缘的块，对误差的敏感度截然不同。对所有保留块使用同一精度，就把算力浪费在“不值得精算”的区域。

论文观察到误差既在不同行之间变化，也在同一行的 tile 之间变化；不同近似策略在不同 tile 上轮流胜出。研究缺口是把误差预算和计算成本联合分配到 tile，而不是先决定全局稀疏率再统一量化。

Core Insight & Method Deep Dive

Input → Video DiT 某层 Q/K/V → 低成本 tile-aligned clustering → 统计块内 key/value、估计各 tile 的 attention mass 和近似误差 → Router 为每个 tile 选择 skip / skim / refine → 单个 fused kernel 计算在线 softmax → 输出近似 attention → 扩散下一层/下一步。

Skip 不是直接丢弃：把整块 K/V 用均值构成 virtual tile，仍参加 softmax 归一化；这样保留粗粒度质量，减少硬删除造成的权重偏差。Skim 使用 NVFP4 执行低精度块乘。Refine 额外计算 NVFP4 残差修正，逼近 BF16 精度，却继续使用 FP4 Tensor Core。Query/Key 聚类树把相似 token 放到同一 tile，减少均值近似误差；树每五个稀疏步重建一次。

Tile 尺寸为 128×128，router 将每块的近似误差与相对成本比较。一个价格参数 π 决定算力–保真折中，避免手工设置三档独立比例。执行层用融合 kernel 和不均匀 query block 的调度减少 launch 与负载不均衡开销。该方法只替换 self-attention 后端，模型权重与 diffusion steps 不变，属于 training-free，但需要相应低精度硬件和定制 kernel。

Objective / Toy Example

Router 近似最小化 Σ_t [E_t(k_t)+π·c(k_t)]，k_t∈{skip,skim,refine}；E_t 是该 tile 单独采用近似造成的行输出误差估计，c(skip)=0、c(skim)=1、c(refine)>1。这里的误差可加性来自对 softmax 耦合项的一阶近似，不是严格独立定理。π 越大越偏向节省算力；π 越小越偏向保真。

Toy：假设一帧有 100 个 attention tile，其中 70 个是近乎静止背景，20 个是普通运动，10 个是关键人物细节。传统稀疏可能简单保留 30 个，或对 100 个全用低精度；Triage 可让 70 个 skip、20 个 skim、10 个 refine。实际分配由误差预测决定，不会真的使用固定 70/20/10 配额。

Experiment Setup / Baselines / RQ

四个 Video DiT、五种设置：RTX 5090 32GB 上的 Wan2.2-TI2V-5B 720p、HunyuanVideo 540p；RTX PRO 6000 96GB 上的 Wan2.2-T2V-A14B、HunyuanVideo 720p、LTX-2.5 I2V。大多数模型 50 denoising steps，Wan A14B 40 steps，LTX 两阶段 8+3 steps；每设置 50 prompts/pairs。环境 SGLang Diffusion 0.5.20、PyTorch 2.13、CUDA 13.0。Dense FlashAttention-2 是基准；比较 Sol-Attn、SVG-EAR、SageAttn3、SpargeAttn。指标包括 PSNR/SSIM/LPIPS（相对于 dense 生成）、VBench（生成质量）、E2E latency speedup、attention kernel speedup 与实际 tile density。

RQ1：逐 tile 分精度能否优于全局 sparse 或 low-bit？RQ2：kernel-level 节省有多少传递到端到端生成？RQ3：Router、聚类与 residual refine 各贡献多少？RQ4：质量下降是否与真实加速成比例？

Results / Table & Figure Reading

Table 1：Wan2.2-TI2V-5B 在 720p、121 帧、27K tokens 时，Triage(π=0.15) 的 VBench 0.826、dense 0.827，PSNR 29.35 dB，E2E 1.35×；Sol-Attn 1.33× 但 PSNR 25.33 dB，SVG-EAR 1.19× 且 PSNR 28.51 dB。这里 0.001 的 VBench 差异很小，但不能说质量绝对无损。

HunyuanVideo 540p 的一个设置在 π=0.3 时 E2E 2.32×、只计算 19% tiles（其中 5% refine），PSNR 34.46 dB；这是五种配置中的最高 E2E speedup，不是所有视频都能 2.32×。HunyuanVideo 720p 的一组设置达到 2.28×，VBench 0.834。LTX-2.5 在 1088p、721 帧、186K tokens 下达到 1.84×，VBench 0.844 与 dense 0.844 一致。

Figure 2/7 展示 PSNR–speedup Pareto 曲线：相近加速下，Triage 往往比纯稀疏和统一量化更接近 dense 输出。Table 3 单 attention kernel 相对 FlashAttention 的加速最高 8.6×，但 E2E 最高仅 2.32×；差距说明非 attention 的 DiT/文本处理、前后处理和 kernel 预处理占用总时间，不能把 kernel speedup 当生成 speedup。

Efficiency Breakdown / FLOPs vs Wall-clock

Baseline → Proposed：FlashAttention-2 dense → tile-wise Skip/Skim/Refine + NVFP4 fused kernel。Frames：相同（如 Wan 121f、LTX 721f）；Visual Tokens：输入 token 数相同（如 27K/186K），并未做 token pruning；Attention tiles：100% → 某配置 19% 实际计算、5% refine；FLOPs：Not Reported（不能将 tile density 直接换算为精确 FLOPs）；Latency：报告 E2E 1.35–2.32× speedup，绝对毫秒未在本次核验表中摘录；Throughput/FPS：Not Reported；GPU Memory：Not Reported；Accuracy/Quality：Wan VBench 0.827→0.826，LTX 0.844→0.844，PSNR 衡量相对 dense 的 fidelity。

理论节省与 wall-clock 并不一一对应：计算 19% tile 不等于 81% 端到端时延下降。该方法更适合 token 多、attention 占比高且硬件支持 FP4 的视频 DiT；若模型本身 attention 占比低、tile 分布不利于聚类、硬件缺少 FP4 Tensor Core，收益可能明显下降。

Ablation / Claim vs Evidence

Router 去掉 tile mass 相关统计，预测误差在测试设置中出现约 1.18× 的几何平均上升；去掉 head 权重也使误差上升约 1.07×，支持“估计误差再分配计算”优于仅用稀疏比例。Residual refine 与聚类树的消融用于检验高精度修正和相似块分组的作用。

Authors Claim：training-free 的 tile 级多档 attention 是更优的速度–保真折中。Experiments Actually Show：五种 Blackwell 视频生成设置上有真实端到端速度与 dense-reference fidelity 的共同优势。What Is Not Yet Proven：在 Ampere/Hopper 上的同等效果、长视频语义一致性的人类评价、跨视频理解 VLM 的直接迁移、显存峰值节省，以及比 FlashAttention 更新版本更稳健的性能。

Contribution / Limitation / Research Value

贡献类型：New Mechanism（tile-wise 三档误差预算）、New System/Engineering（NVFP4 fused attention kernel）、New Empirical Finding（kernel vs E2E 差距）。Baseline Potential 很高：对视频生成系统可直接做 attention backend 对照；System Value 是核心；Benchmark Value 在于五设置的速度–保真 Pareto；Attack/Evaluation Value 可测极端运动与小目标的误差集中；New Paper Potential 是把分档策略推广到视频 VLM 的视觉 KV/cache 和 query-aware attention。

局限：依赖 Blackwell FP4、tile 聚类/统计额外成本、输出 fidelity 主要相对 dense 而非所有下游任务。它不解决 frame selection，也没有证明对 Agent 视频理解同样有效。

Migration / Minimum Experiment / Risk

Original Problem：Video DiT attention 过度均匀计算 → Transferable Mechanism：按局部误差/收益选择多档计算 → New Research Question：Video VLM 能否按 query 与时间漂移把 token 分为 reuse、low precision、recompute？→ Method Modification：将 tile error 代理换成 query-conditioned feature drift 和答案敏感性，保留事件边界高精度 → Minimum Experiment：Video-MME/LongVideoBench 对 8/16/32 帧与固定 token budget 做三档策略 → Model：Qwen2.5-VL-7B 或 LLaVA-OneVision-7B → Dataset：Video-MME、LongVideoBench → Baseline：uniform sampling、VETO、VisionZip、固定精度/稀疏 → Metric：wall-clock、tokens、显存、QA accuracy、事件定位误差 → Expected Contribution：语义驱动的多档视频推理 → Risk：生成 attention tile 的误差代理与 VLM 答案敏感性不等价，跨硬件 kernel 工程成本高。

五句话总结

一，视频 attention 需要的是分配精度，不只是删除 token。二，skip/skim/refine 形成连续的计算预算。三，融合 FP4 kernel 让机制真正转化为 wall-clock 收益。四，8.6× kernel 加速最终只有最高 2.32× E2E，必须报告两者。五，最值得迁移的是基于误差的分档思想，而不是直接照搬生成模型 kernel。

Further System Analysis & Failure Modes

应把 Triage 的计算收益拆成三部分：第一，低成本聚类与 router 预测需要额外预处理；第二，少量真正精算的 tile 由 NVFP4 tensor core 完成，降低 attention 主体耗时；第三，非 attention 的模型层、文本编码、扩散调度与视频解码仍保持原有成本。即便 attention 本身最高达到 8.6×，整个模型也不可能同比例加速。真实部署时需要对 kernel launch、clustering refresh、显存搬运分别计时。

论文质量指标也应谨慎解释。PSNR/SSIM/LPIPS 是相对于同随机种子的 dense 生成，不等于视频内容真实度的绝对评价；VBench 只覆盖部分生成质量维度。高速运动、镜头切换、细粒度文字与小目标都可能是高误差 tile 聚集的压力测试。迁移到视频理解模型前，必须证明路由分数与问答答案敏感性有关，而不是仅对视觉重建误差有效。

Tier A 1. FOCUS: Active Critic Learning for Long-Horizon Language Model Agents

arXiv:2610.35801 · 2026-10-26 · arXiv preprint；未核验正式录用
Authors / Affiliation: Zhengping Jiang; William Jurayj; Liaoyaqi Wang; Chunsheng Zuo; Anqi Liu; Benjamin Van Durme（Johns Hopkins University）
Abstract / Metadata · Paper HTML · PDF · Code: 未核验 / Not Reported

人话版：这篇论文到底干了什么？

长链路 Agent 的最终奖励稀疏，GRPO 直接把最终成功/失败广播到全部步骤，难以区分“正确搜索”和“错误总结”。FOCUS 的关键不是无节制增加 rollout，而是把额外采样投到 critic 最不确定、最有可能降低价值估计误差的中间状态。它用选择性 continuation 分支校准 critic，再用 TD(λ) 给轨迹片段分配优势。Qwen3.5-9B 上，BrowseComp-Plus 的 held-out 准确率从最强对照 48.2% 提升到 55.4%；DeonticBench 从 52.4% 到 56.5%。这为 Agent RL 提供了一个可迁移的“在哪里花 rollout 预算”机制。

与平均分支相比，它把额外计算集中在可能改变训练决策的节点；这也意味着必须同时核算 critic 校准成本和真实 rollout 预算。

Background & Gap

长轨迹 Agent 的状态不是纯文本序列：它包括网页、搜索结果、压缩上下文与工具状态。直接对整条轨迹算一个 GRPO advantage，会把有用动作与错误动作混在一起。训练 critic 可以提供中间 value，但若所有状态都进行昂贵的 continuation rollout，计算成本不可接受。FOCUS 将 critic 的数据收集本身视为主动学习问题。

Core Insight / Method / RL Formulation

Input → 当前 Agent 轨迹及 compaction 分段边界 → Critic 估计各边界 value 与不确定性 → 挑选最值得分支的状态 → 额外 rollout 观察后续结果 → 更新 critic → 对相邻片段计算 TD(λ) advantage → 更新 actor。State 是包含工具历史的压缩上下文；Action 是搜索、工具调用与回答；Reward 主要来自最终任务成功；Policy 为 Qwen3.5-9B；Credit 在片段级而非统一广播；目标仍是提高最终 outcome。

关键与 VinePPO 的区别在于分支采样不是平均分配：主动分支给价值估计提供信息增益。与 outcome-only GRPO 的区别是引入可学习的 critic 并把计算集中在难以判断的节点。探索仍由 rollout policy 驱动；KL/entropy 具体设置应按附录复现，不能由摘要推断。

Experiment Setup / Results / Figures

评估包含 DeonticBench 法律/规范推理、BrowseComp-Plus 深度搜索、LocBench 代码定位；比较 GRPO、VinePPO 和未训练参考，在匹配的每步生成预算下测 held-out accuracy。BrowseComp-Plus：55.4 vs GRPO 48.2 vs VinePPO 46.6（+7.2pp 相对最强）；DeonticBench：56.5 vs 52.4 vs 49.4（+4.1pp）；LocBench File@1：72.4 vs 70.1 vs 67.8，File@5：81.6 vs 80.5 vs 79.3。

Table 1 也显示不是每个细分任务都赢：DeonticBench 某子集 FOCUS 52.0 vs GRPO 56.0（-4.0pp），另一子集 26.8 vs 28.2（-1.4pp），置信区间可跨零。Ablation 研究了不使用主动 refinement 与更换 compaction operator，说明收益不能简单归结为“有 critic”。应优先阅读 Method 2.2/2.3、Table 1 和 ablation。

Contribution / Limitation / Research Value

贡献：New Mechanism（active critic refinement）、New Objective Implementation（片段 TD(λ)）、New Empirical Finding（稀疏终局任务中选择性分支更值钱）。优点是与长链路上下文压缩自然结合；弱点是 critic 误差与真实信息增益未必同向，分支会增加推理与环境重放成本，且在不可恢复的真实环境中 continuation 可能难以复制。它与视频剪辑的过程奖励退火形成互补：一个决定在哪里采样，一个决定采样后的奖励如何使用。

Migration / Minimum Experiment / Worth Deep Reading

Reward, Exploration, Stability & Failure Propagation

FOCUS 的 reward 仍以最终可验证 outcome 为锚点，critic 的作用是给中间状态估值，并不创造一个可以任意刷分的过程奖励。其核心训练信号依赖 TD(λ) 的 bias–variance 折中：λ 越偏向长回报，越接近稀疏 outcome；越依赖 bootstrap，就越容易受到 critic 估计偏差影响。主动采样的目的正是减少最有害的估计误差，而不是单纯增加采样量。

对于长 Agent 任务，错误传播通常是“早期错误检索→错误上下文压缩→后续工具选择偏移→最终失败”。在 compaction boundary 分段有助于诊断这种传播，但若 compactor 丢失关键证据，critic 可能无法从压缩状态恢复真实原因。下一步可把“重放的真实收益”与 critic uncertainty 分开测量，避免主动学习只追逐高噪声状态。

Claim vs Evidence / Concrete Next Step

作者证明的是匹配每步生成预算时，主动选择 critic refinement 状态能够改善若干 held-out 任务；尚未证明所有复杂 Agent 都适用，也没有证明 critic 在极长 1000-step 任务中不会发生价值漂移。建议优先复现 BrowseComp-Plus 的 55.4/48.2 配对，并在同一总 GPU 小时下测单纯增加 rollout 的收益。若分支策略只在高不确定状态增加计算，却没有带来更低的 value calibration error，就应质疑主动采样的机制解释。

Tier A 2. S3AC: Stabilized, Selective, and Scalable Actor-Critic for LLM Reasoning

人话版：这篇论文到底干了什么？

长 CoT 推理中的 actor-critic 不是新想法，但 critic 往往训练不稳，尤其新 value head 的初始梯度和不同长度轨迹的覆盖问题会让训练劣于 GRPO。S3AC 先用覆盖不同长度与正确性状态的数据预训练 value，再处理梯度失衡；训练时以 token-level advantage 更新 actor，同时用 critic 估计的题目难度做 DAPS prompt selection，避免浪费 rollout 在太容易或太难的题目上。Intern-S2-397B 的五项评测平均从 GRPO-X 85.1 升至 87.3；但 critic 的预训练数据与算力成本不可忽略。

关键问题不只是平均成绩是否上升，而是训练 value model 所消耗的数十亿 token 能否在长期训练中摊销，以及选择性采样是否漏掉高难度题。

Background & Gap

GRPO 等 critic-free RLVR 算法避免了 value model 的训练成本，却常用组内相对分数作为整段回答的共同信号。长 CoT 里某个错误推导与最终猜对可能同时出现，组内平均无法识别 token 的真实贡献。旧式 actor-critic 虽可给 token-specific value，却在超长回答、价值头随机初始化和少量 rollout 下不稳定。

Core Insight / Method / RL Formulation

Input → 大量长短不一、正确性不同的轨迹 → 覆盖导向的 critic 预训练 → value-head 梯度稳定化与在线适配 → 预测 prompt 难度 → DAPS 选择值得生成的题目 → Actor rollout → token-specific advantage 与 policy 更新。State 是 CoT 前缀，Action 是下一 token，Reward 主要是可验证最终答案；critic 提供中间价值及 prompt baseline，解决 GRPO 均匀 credit 的限制。DAPS 在生成之前做筛选，与生成后过滤无效 group 不同。

这一设计是两层效率：第一层改善学习信号质量，第二层减少无效采样。Reward hacking 风险仍在：critic 可能把“看似正确的推导风格”误当真实可验证性。

Experiment Setup / Results / Figure

实验跨 1.5B–397B dense/MoE 模型，比较 GRPO-X 与其他 critic-free/actor-critic 对照；评估 GPQA-D、IMO-AnswerBench、MMMU-Pro、MathVision、HMMT26 等。Intern-S2-397B 的 Table 1：GRPO-X 五项平均 85.1，S3AC 87.3；GPQA-D 88.9→90.5、IMO-AnswerBench 81.4→84.2、MathVision 87.5→89.7。

1.5B 单 rollout 的一组结果：FlashREINFORCE 的前两项为 67.2、44.8，S3AC 达 71.4、57.3；但同表也存在单项小幅回退（如 38.0→29.8 的对应列），不能只看均值。附录显示 35B critic 预训练用 1.13M 条轨迹/6.24B response tokens，397B 用 1.85M/10.0B，提示“省 rollout”不等于整体训练便宜。

Contribution / Limitation / Research Value

贡献类型：New Training Recipe、New Sampling Policy、New Empirical Finding。强项是把 critic 训练覆盖率、稳定性和采样预算放在同一个框架；弱项是大规模 critic 预训练昂贵、不同模型尺度的实验预算不完全可交换，DAPS 可能过度偏向中等难度题，忽略罕见的困难样本。对 Agent RL 可以把题目难度换成“环境状态的可恢复性”或“工具风险”，对 Multi-Agent 可学习局部 value 但需要更强的反事实验证。

Migration / Minimum Experiment / Worth Deep Reading

最小实验用 Qwen3-1.5B 在 MATH-500/AMC23 复现 DAPS 与 critic 的 2×2 消融，严格报告 critic 预训练 token、rollout token、最终 pass@1、校准误差和总 GPU hours。迁移到 Agent 时把 value 定义为后续完成概率，比较“均匀采样 vs 难度采样 vs 信息增益采样”。Worth Deep Reading：YES；优先读 Section 3.3/3.4、Table 1/2 和 critic 预训练附录。

Ablation, Credit and Training Cost Audit

S3AC 的主要实验要拆成三个独立问题：第一，value head 是否因预训练覆盖多种长度和成功/失败轨迹而更稳定；第二，token-level advantage 是否比组内共享优势更准确；第三，DAPS 是否在相同总生成预算下减少无效题目。若只比较最终 pass@1，三种收益可能混在一起。合理的 2×2×2 消融应分别关掉 critic 预训练、token-specific advantage 和 prompt selection，并匹配 rollout token。

最重要的负面风险是训练预算的错觉：397B critic 的预训练本身包含 10.0B response tokens，只有当它能在多次 actor 更新或多个任务间复用，才可能抵消前置成本。另一个风险是难度估计偏差：critic 可能将罕见、分布外的高价值难题判为“不可学”，导致长期探索不足。应报告按题目难度分层的覆盖率和 OOD 性能，而不只是平均准确率。

Claim vs Evidence / Failure Case

作者的强证据是跨模型规模、不同 benchmark 的平均性能改善；但大模型预训练 critic 所需的数十亿 token 不属于免费训练。必须检查相同训练成本下，较小 critic + 更多 actor rollout 是否更划算。另一个尚未证明的点是奖励模型与验证器不一致时的稳定性：若最终 reward 错误，token-level value 可能精确地放大错误监督。把 reward noise、长 CoT 长度分布、critic 误差和训练崩溃率一起画图，才能分辨是 credit assignment 改善还是数据分布更容易。

Tier A 3. GUIFlow: Temporal Redundancy-Aware Incremental Inference for GUI Agents

人话版：这篇论文到底干了什么？

GUI Agent 连续操作桌面时，每一步新截图与上一步高度重合，历史工具轨迹也大多没变。传统 VLM 每次从头编码图像、重做 prefill、重新生成动作，造成重复计算。GUIFlow 把三段都改成增量：历史 KV 做位置对齐复用，当前视觉内容按变化信号选择性更新，上一动作作为 speculative draft 由目标模型验证。论文报告离线多图 benchmark 约 3.37–3.39×、在线 OSWorld 约 3.32–3.49× 的 FLOPs 比率改善。它为 Streaming Video Agent 提供了比单纯 token pruning 更完整的跨步状态复用方案。

需要特别警惕把 FLOPs ratio 直接写成 wall-clock speedup；真实部署还受到缓存维护、工具响应和动态页面变化的制约。

Background & Gap

GUI 与视频一样具有时间冗余，但还多了一个难点：一次点击可能改变按钮位置、历史上下文、动作参数。直接沿用旧 KV 可能使 Agent 对已经变化的界面作出错误操作；每步全量重算又让长任务成本随交互次数累积。已有方法常只优化视觉编码或视觉 token 数量，缺少从 encoder 到 decoder 的一致增量处理。

Core Insight / Method / Agent Architecture

Input → 历史截图和当前 GUI observation → position-aligned historical KV integration → 视觉编码器/语言模型按 change signal 做 selective refinement → 以上一步动作响应为 speculative draft → 目标模型验证并提交 action → 新界面状态回写缓存。Memory 是跨步计算状态与工具历史，非长期语义知识库；Tool 是 GUI 点击/输入；Environment 是 OSWorld 等界面。

方法 training-free、不需要独立 draft model、不改变 Agent 可见的动作接口。最值得关注的是“缓存的逻辑有效性”：位置对齐与变化检测必须同时成立，否则旧内容虽可复用，却可能在下一步产生错误。长链路错误可能经由缓存污染后续所有动作。

作者证明的是跨视觉编码、prefill、decoding 的可组合计算复用，而不是在所有 GUI 环境中保证相同成功率或时延。应对静态表单、动态网页、弹窗密集界面分别测速度和准确率，并记录 speculative draft 被拒绝的比例。若高速界面变化导致重算率接近 100%，缓存层可能反而增加开销；需要设定明确的自动 fallback 条件。

Tier A 4. TRIAGE: Efficient Vision-Language-Action Inference Needs Both Reuse and Pruning

Authors / Affiliation: Sooyoung Kwon; Carlee Joe-Wong; Kyunghan Lee（SNU / CMU）
Abstract / Metadata · Paper HTML · PDF · Code: 未核验 / Not Reported

人话版：这篇论文到底干了什么？

视觉动作模型的相邻控制步有大量重复 token，但“直接复用旧 KV”和“删除 token”并不总是同一种误差。TRIAGE 测量 token 浅层 value 的 drift：变化小时复用往往优于丢弃，变化太大时复用旧信息反而比 pruning 更糟。于是它把 token 分成 recompute、reuse、prune 三类，固定重算预算，按重要性与缓存有效性分配。Jetson AGX Orin 上预填充时延最多下降 48%，平均成功率距离 full recompute 不超过 3pp；在 7% token 重算预算下，LIBERO-Object 比最强对照高 24.4pp。

它的机制是缓存有效性判定而非简单删除视觉 token，因此值得和 GUIFlow 一起研究，但当前实验对象是机器人 VLA，不能直接外推到 Video QA。

Background & Gap

边缘机器人每个动作周期都要处理几百个视觉 token。只做 pruning 会损失稳定背景信息，只做 KV reuse 则可能把移动物体的旧位置带到下一动作。旧方法把两种选择当成二选一，忽略 token-level drift 与下游 action error 的关系。

Core Insight / Method / Agent Architecture

Input → 当前图像、上步 KV cache、动作状态 → 估计 token importance 与浅层 value drift → 用 drift 阈值和缓存年龄判定 valid → 在固定预算内优先 recompute 重要且失效的 token → 对剩余 valid token reuse → 其余 prune → VLA action。这里没有额外训练，阈值通过两个 backbone 的诊断校准。

核心发现：低于阈值的 token reuse 不比 prune 差；高于阈值时 reuse 的动作误差最多达到 pruning 的 4.4×。所以策略不是“缓存越多越好”，而是对每个 token 选最低风险的计算路径。Long-horizon 失效风险是早期 cache 污染持续影响动作；年龄门限是缓解但不是完全证明。

Experiment Setup / Results / Figures

LIBERO 与 SimplerEnv，包含 Jetson AGX Orin 与 RTX 3090；对照 full recomputation、prune-only、reuse-only 和已有加速器。Fig.5 的 success–prefill Pareto 前沿显示 TRIAGE 在测试设置中没有被其他基线同时以更低时延和更高成功率支配。Table I：Jetson prefill 最多降低 48%，成功率与 full recompute 相差不超过 3pp。LIBERO-Object 仅重算 7% visual tokens 时，相对最强 baseline +24.4pp；Table II 给出 SimplerEnv 跨 backbone 的对照。

这不是 Video LLM QA 结果，不能把 LIBERO 成功率当成 Video-MME accuracy。训练成本是零，但 drift 估计、缓存保存与调度仍有运行成本。

Efficiency Breakdown / Limitation

Baseline Full recompute → TRIAGE；Frames：连续控制观察不变；Visual Tokens：仅重算 7% 是一个测试预算，余下 token 被 reuse/prune；FLOPs：Not Reported（具体绝对量）；Latency：Jetson prefill 最多 ↓48%，不是完整机器人任务时延；Throughput/FPS：Not Reported；GPU Memory：Not Reported；Accuracy：平均成功率距 full recompute ≤3pp，特定 LIBERO-Object 对照 +24.4pp。理论节省可能被 cache 管理抵消，需补真实 end-to-end 控制频率。

主要限制是 token drift 与最终动作风险之间的校准依赖 backbone 和任务分布；当场景突然变化时，阈值可能失效。

贡献：New Mechanism（validity-aware reuse/prune 三分）、New Empirical Finding（过期缓存有时比删除更危险）。可迁移到 Streaming Video VLM 的跨帧 feature cache；最小实验在 Video-MME 上对静止、镜头切换、快速运动分别测重算比例、准确率、p95 latency 和显存，基线包括 full encode、prune-only、reuse-only。Worth Deep Reading：YES；重点 Section III-B、Fig.5、Table I/II。

Ablation, Cache Validity and Migration Risk

在 TRIAGE 的三分决策中，importance 和 validity 承担不同职责：importance 决定哪一条 token 值得花重算预算，validity 决定旧 KV 是否仍可信。把两者合成单一相似度阈值，会让高重要但过期的 token 被复用，或让低重要但稳定的背景被反复重算。关键消融应分别关闭 age gate、drift threshold、importance ranking，并比较同一重算预算下的 action error。

若迁移到视频问答，不能直接使用机器人 action error 校准阈值。视频 QA 的关键对象可能只在一帧短暂出现，之后几十帧静止背景都与缓存高度相似；若按局部 drift 选择缓存，事件证据仍可能消失。更稳妥的扩展是同时维护短期视觉 cache 与事件级摘要，在镜头切换和问题相关事件发生时触发强制重算。

Claim vs Evidence / Concrete Next Step

现有结果主要说明在测试 VLA 模型和机器人控制任务中，三路分配优于一刀切。并不能推出 Video-MME 或长视频问答会同样提升。下一步应先用离线相邻帧重放测 drift 分布，再按相同 p95 延迟预算对比复用和剪枝，尤其检查被剪掉的短暂事件是否造成不可恢复的后续推理错误。

Additional Audit / Next Experiment

额外的长期评估应关注缓存污染的恢复速度：当视觉状态突然变化时，系统需要多少控制步才能重新与 full recompute 对齐？可以把缓存有效性预测误差与任务失败率画成条件曲线，并测试不同 age threshold。若在极低重算预算下只保住平均成功率，却在危险状态出现少数严重失败，就不能只凭均值认定部署安全。

人话版：这篇论文到底干了什么？

少步自回归视频生成不只要让当前 chunk 看起来像真实视频，还要避免当前 chunk 的错误在后续片段被放大。传统 DMD 通过 teacher/student score 差构造训练方向，成本高；而 detached history 切断了未来片段对当前片段的信用分配。Leta 同时提出 ScoreDelta（直接估计修正场）与 FutureCredit（用未来 chunk 的教师残差信号训练跨 chunk 更新），把局部保真与未来一致性放进一个生成器更新。论文相对 DMD 的受控实验在 VBench 上提高 0.9 分、VideoAlign 提高 0.66 分；但不能据此声称推理 wall-clock 也提升同样比例。

Background & Gap

Video diffusion 的少步蒸馏常分初始化与分布匹配两个阶段，生成器被迫学习一个昂贵的 score 修正。更深层问题是 chunk 自回归：当前 chunk 的偏差会进入未来条件，但训练时如果对历史 stop-gradient，就无法把未来质量问题归因到先前生成。

Core Insight / Method

它把 RL 中“长轨迹信用分配”的思想迁移到可微视频生成轨迹，但这里不是标准 RL 的 policy gradient：FutureCredit 是跨 chunk 的梯度代理，不能称为 learned reward。

Experiment Setup / Results / Figures

在少步自回归视频生成的受控设置下比较 DMD 和 Leta，使用 VBench、VideoAlign 的质量/对齐指标，并分别消融 ScoreDelta、FutureCredit、生成器与估计器更新比。主结果相对 DMD：VBench +0.9、VideoAlign +0.66。Table 2 对 G:E=1:4 与 1:1 两种更新比进行消融；Fig.6 展示相同时间戳的视频对照，帮助判断未来片段的结构一致性。

Efficiency Breakdown / Limitations

贡献：New Mechanism（cross-chunk future credit）、New Objective/Training（直接 score-difference 摊销）。迁移 Idea：对 streaming video agent 的缓存决策，不只测当前帧答案误差，还测当前压缩对后续事件理解的影响；最小实验固定 video token budget，比较逐帧贪心压缩与 future-aware 压缩，报告 Video-MME QA、事件定位与真实 latency。Worth Deep Reading：MAYBE；优先 Section 4、Table 1/2 和 FutureCredit 消融。

作者报告的质量增益与 ScoreDelta/FutureCredit 机制一致，但还需要更强的跨时间消融来证明后续片段的提升确实来自早期 credit，而不是更大的估计器或更多 teacher 调用。建议固定 teacher 访问次数与总训练 FLOPs，在不同 chunk 长度下比较 DMD、仅 ScoreDelta、仅 FutureCredit、两者联合，额外报告长序列结构漂移和视频生成 p95 wall-clock。

Additional Audit / Next Experiment

对视频生成加速的进一步验证还应固定输出分辨率、帧数、采样步数和同一硬件，以防不同生成配置造成伪加速。特别需要比较首个 chunk 的生成时间、后续 chunk 的平均延迟、长时间 rollout 的质量漂移与显存峰值。若 FutureCredit 只能提高画质但增加训练成本，则应将其定位为质量–成本折中，而不是新的 inference accelerator。

Abstract / Metadata · Paper HTML · PDF · Project · Code: 未核验 / Not Reported

人话版：这篇论文到底干了什么？

Agent 的 skill 不是写得越详细越有用。同一份技能指令能显著帮助强模型，却可能使弱模型因工具、上下文或验证能力不足而表现下降。作者从七种模型、三个 benchmark 中找到 103 个典型 task–skill 配对：强执行器受益 31.1 分，弱执行器反而下降 8.8 分；86% 弱模型失败的要求其实已经写在技能里。论文把失败诊断提炼成 meta-skill，让技能重写适配执行器能力，并放入多轮 harness self-evolution。核心启发是 skill 的有效性必须以执行器能力为条件，而不能仅按文本质量评价。

如果后续研究 Agent Skill Learning，这篇论文提示我们必须同时记录技能文本、执行器能力、验证反馈和真实工具权限。

Background & Gap

传统 skill library 假设“正确的流程说明”可以跨模型迁移，实际上执行器是否能遵守、能否处理长上下文和复杂工具决定了技能的实际收益。比如一份写着“先运行脚本再检查 JSON schema”的技能，对强模型是指导，对缺乏文件操作能力的模型则可能增加失败路径。

Core Insight / Method / Agent Architecture

Input → 已有 skill、任务、执行器能力 → 收集工具调用/上下文管理/指令遵循/验证失败 → 形成四类诊断 → Meta-skill 引导强模型重写 skill 或执行器自改 → 验证改写后的执行表现 → 五轮 self-evolution 中持续迭代。状态包含任务、技能文本、轨迹与 verifier feedback；它不更新基础模型参数。

与普通 prompt rewrite 不同，meta-skill 不只追求简洁，而是把不可执行的步骤降解为能力范围内的可验证动作。它的目标是 executor–skill fit，而非在一个固定大模型上优化 benchmark。

Experiment Setup / Results / Figures

三个 benchmark、七个执行器、103 个精选 task–skill 配对；包括 SkillsBench、DocOps、Tessl。Table 1：三个弱模型的原始技能平均分为 0.294；用不同 rewriter 的 meta-skill 改写可到 0.335/0.343 等。Kimi-K3 在不看执行轨迹的情况下改写技能，使三个弱执行器相对原始技能提升 5.1–14.1 分。五轮自进化中 meta-skill 相对无 meta-skill 的相同循环最终 +2.0–5.1 分。

强弱模型之间 31.1 与 -8.8 分的差异并非对所有模型的总体平均，来自作者挑出的 103 个对照；不能把它当作总体部署收益。Figure/Case studies 中的表格处理、PDDL 任务揭示技能“文字上有要求”与“模型能落实”之间的差距。

Contribution / Limitation / Research Value

贡献：New Empirical Finding（skill 的能力依赖性）、New Mechanism（meta-skill 诊断改写）、New Evaluation（跨执行器 skill transfer）。弱点是精选样本可能放大负迁移、强模型 rewriter 的成本和安全性未充分比较；自进化可能过拟合已有 verifier。对于 Multi-Agent 系统，角色专长和模型能力不同，应该按 executor-specific skill version 管理，而不是共享同一段提示词。

Migration / Minimum Experiment / Worth Deep Reading

最小实验：选 20 个工具操作任务，分别给 3B/7B/更强模型运行同一技能；记录每条指令被执行/验证的概率，比较原技能、通用简化、能力条件化改写。进一步把能力条件加入 skill retrieval 的 reward，测跨模型迁移率、失败传播、token 成本。Worth Deep Reading：YES；重点 Section 3、Table 1/2 与 self-evolution 消融。

Skill Attribution, Failure Propagation & Baseline Design

技能文本中写了某个操作，并不意味着 Agent 有能力执行；反过来，执行器失败也不一定说明技能设计错误。评估时应该把“技能可理解性”“工具可达性”“验证能力”“上下文承载能力”拆开。一个低能力模型如果不会处理异常退出码，单纯加长技能解释可能让上下文更拥挤；能力条件化重写应该把失败恢复步骤改成更短、更可验证的局部操作。

对 Multi-Agent，技能版本应绑定执行器能力与工具权限：同一角色在不同模型上使用不同的 skill variant，并记录谁生成、谁修改、在哪个任务验证有效。最小反事实实验可在不改变模型和任务的条件下交换 skill 版本，估计每条技能改动的真实边际贡献。还需与 Self-HPO/RRSI 这类 harness self-evolution 工作做直接 Collision 对照。

Claim vs Evidence / Concrete Next Step

作者的实证最强之处是把“要求已经写在 skill 里”与“执行器仍失败”放到同一案例中，直接反驳了纯文本完整性等于可执行性的假设。但 meta-skill 本身由人工总结失败类型，跨工具生态和未知权限体系的泛化仍未充分证明。下一步应在完全未见过的 MCP 工具集上测试改写是否降低误调用率，并将重写 token、验证成本与任务收益一起计入。

Tier B 1. Improving Reasoning with Rollout Agreement for Group-Based Policy Optimization

arXiv:2610.34951 · 2026-10（具体提交日未单独核验） · arXiv preprint；未核验正式录用
Authors / Affiliation: Sohyun Son; Yerim Hong; Jaeyun Park; Mujeen Sung
Abstract / Metadata · Paper HTML · PDF · Code: 未核验 / Not Reported

人话版：这篇论文到底干了什么？

GRPO 通常只看最终答案对不对；但同一道题的多个正确答案轨迹，可能有的推理扎实、有的靠碰巧猜对。RoAR 从同一组 rollout 中计算推理一致性，只给经过答案验证的正确轨迹增加 agreement reward，不需要额外采样或独立 PRM。它提供了一个低额外成本的 reasoning reward 信号，也提醒我们不能把最终正确率等同于过程可信度。

这与视频剪辑的过程奖励退火互补：前者改善奖励的可靠性，后者控制奖励在训练后期的影响。需要额外警惕一致性导致的模式坍缩。

Background / Core Method

作者先盲评同题 126 对正确答案轨迹，发现低 agreement 轨迹的伪推理率 35%，高 agreement 为 22%。据此把词面重合和语义相似组合成 rollout agreement，并只对 verified-correct 的 rollout 加奖励；这是 group 内部的信息再利用，不是另训 verifier。

Experiment / Main Finding

DeepSeek-R1-Distill-Qwen-1.5B，约 7K 训练题，五项数学 benchmark 平均 pass@1 55.5%，比 GRPO 高 6.0pp、比 GRPO-CARE 高 5.5pp。独立 100 题盲评的 spurious reasoning 比率为 18%，GRPO 为 32%。只用词面或只用语义分别约 52.8%/52.0%，二者混合 55.5%。

Contribution / Limitation / Connection

贡献是 New Reward Signal 与 New Empirical Finding。限制：同题一致性也可能是共同错误或模式坍缩，少数正确解法可能被惩罚；数学可验证任务不等于开放式 Agent。可迁移到 Multi-Agent 的“证据一致性 vs 少数正确观点”研究，最低成本先测试不同 rollout diversity 下的准确率、正确解法覆盖率与 reward hacking。

Why It Matters / Further Evaluation

这个工作的重要性在于把“同样正确的答案”拆成推理质量不同的样本，直接对 outcome-only reward 的信息缺口做低成本补充。一个必须补做的实验是刻意加入多个互不相似但都正确的数学解法，检查 agreement reward 会不会错误地把少数新颖解法压低。还应在高温采样与低温采样下分别测 pass@k、unique-solution coverage 和 reward variance，判断提升来自真实推理改善还是输出同质化。

迁移到 Agent 时，一致性不应只比较文字，而应比较工具调用前提、引用证据和环境状态；否则不同 Agent 同时复制同一错误工具结果，也可能获得虚假的高 agreement。

Potential Use / Collision Check

如果把 RoAR 迁移到 Agent RL，可以把“推理一致性”换成“工具调用后的证据一致性”，但需要避免奖励多个 Agent 对同一错误来源的相互模仿。与过程奖励退火论文的关系是：RoAR 试图让 reward 更可信，退火试图限制 reward 长期主导训练。一个有价值的最小实验是对同一数学题构造多个正确但表达差异大的解法，测试 reward 是否错误地惩罚探索。

arXiv:2610.35303 · 2026-10（具体提交日未单独核验） · arXiv preprint；未核验正式录用
Authors / Affiliation: Yingbo Hao; Song Liu; Guanghua Yu; Zhaojing Zhou; Jianchen Zhu; Yi Zou
Abstract / Metadata · Paper HTML · PDF · Code: 未核验 / Not Reported

人话版：这篇论文到底干了什么？

Agent RL 的 rollout 往往需要量化来降低 KV cache 和生成成本，但量化执行器与高精度 learner 的策略并不完全一致。单步 importance ratio 只能校正当前 token，不能纠正前面一连串量化动作已经把环境带到不同状态的问题。InterQ-RL 把 correction 扩展到 state-reaching trajectory prefix，并按可用 support 分配校正预算。它关心的是多轮 Agent 的分布偏移，而不是传统单轮 LLM 量化精度。

它也提示：对 Agent 的量化压缩，不能只评估单 token 的 perplexity 或动作概率，还要测状态历史是否被持续带偏。

这让长链路校正与单步量化误差分析有了明确区别。

Background / Core Method

Input → quantized rollout policy 的完整多轮轨迹 → 对齐量化执行路径与 learner → 计算 trajectory-prefix likelihood correction → 按支持度而非仅按比值幅度分配校正 → 更新 RL policy。这里的 State 是环境交互历史，Action 是多轮工具行为，Reward 仍来自任务 outcome；校正不是新 reward，而是纠正 off-policy 执行偏差。

Experiment / Main Finding

论文在 ALFWorld、WebShop 和 ScienceWorld 上比较量化训练策略，Qwen3-4B 用于前两项，ScienceWorld 另有 8B/A3B 规模；Table 1 使用相同训练预算，并指出某量化对照 QuRL 在第 278 步崩溃，无法得到共同终点。可获取信息支持其稳定性和任务表现的研究方向，但本次未完整核验每项精确数值，故不杜撰百分比。

Contribution / Limitation / Connection

贡献：New Objective/Correction（历史依赖的分布校正）、New System Insight（量化 rollout 的长链路失配）。限制是长前缀 importance ratio 的方差、环境可重复性和支持度估计成本。可迁移到视频 Agent 的压缩观测：当早期帧被近似编码，后续状态偏差不应只由当前帧误差衡量。

Why It Matters / Further Evaluation

在闭环环境中，量化引起的早期动作偏移会改变后续可见状态：一个网页按钮点错后，后续 action 即便在当前状态下概率比率接近 1，也不代表它与高精度策略处于同一任务分布。InterQ-RL 对 state-reaching prefix 的关注正是这种历史依赖性。它提示 Agent RL 的 off-policy correction 应同时审计“当前动作”和“如何到达当前状态”。

最小可复现实验是固定同一组环境初态，对比 BF16 rollout、4-bit rollout、只校正当前 token、校正 trajectory prefix，记录状态分歧率、最终成功率、KL 漂移、训练不稳定次数与总推理成本。对长轨迹，还应分析 importance weight 的有效样本量随步数是否迅速下降。

Potential Use / Collision Check

对在线 Agent 训练，量化执行器节省的显存和 token 计算是明确动机，但如果前缀校正带来过大的方差，最终可能用更少 GPU 显存换来更差训练稳定性。应将 policy KL、有效样本量、长轨迹完成率和 rollout wall-clock 一起报告。该工作与 HARTS 的 prefix-sharing 关注点不同：前者修正分布偏移，后者复用共享前缀计算；二者可能组合，但需先排除校正后的重复计算。

人话版：这篇论文到底干了什么？

多数 Agent benchmark 把每道题当成一次独立考试，却很少测试 Agent 是否真的从上次任务学到可迁移的经验。Continual Learning Exam（CLE）把 120 个真实职业工作流设计成五级阶梯，共 600 个关卡，后续任务需要复用此前经验，且必须过关才能解锁下一层。它将 Agent Memory、Skill Evolution 与长期自改进的价值放到同一套递进任务中评估。

需要用记忆清空对照来验证这种学习。

Background / Core Method

Benchmark 涵盖 89 个职业角色、12 个领域，由 50 多位领域专家参与编写。每个 task 的五级难度并非简单换题，而是带有知识继承、工具使用和可验证反馈的连续过程；系统还包括有状态 mock service 与 block-based evaluation，能够比较不同 harness/feedback 对后续阶段的作用。

Experiment / Main Finding

最强受测系统仅通过 47.7% 的关卡，完整完成五级阶梯的任务比例只有 23.3%。这两个数字说明当前系统可能擅长单关解决，却难以持续把经验转化为后续能力。指标必须区分 level clearance 与完整 ladder completion，不能只报告单题成功率。

Contribution / Limitation / Connection

贡献：New Benchmark 与 New Evaluation Protocol。限制是职业任务的覆盖度、评估器偏差以及五级阶梯与真正 1000-step 自主学习的差距。可用于比较 AMIE、技能适配、RL memory policy 的长期收益，并引入“第 n 关性能相对第 1 关的净增益”作为研究指标。

Why It Matters / Further Evaluation

CLE 的价值不是把 600 个任务当成一套更大的静态测试集，而是明确要求同一 Agent 在连续阶段中积累并利用经验。因此评估应区分“模型先验知识已经足够完成下一关”和“前一关确实贡献了可迁移信息”。可以设置 memory reset、skill reset、只保留 raw transcript、只保留 distilled lessons 等对照，测相同 token 预算下的阶梯完成率。

还要关注错误经验的传播：某一关碰巧成功，Agent 写下不正确的 lesson，下一关是否因此退步？这与 Lessons from Luck 的注册实验直接相关。用 CLE 做新论文时，最好报告跨关性能曲线、累计成本和任务间迁移矩阵，而不是只报告总通过率。

Potential Use / Collision Check

将 CLE 用于科研 Agent 时，应加入“前一关经验是否必要”的反事实设置：同样任务只保留最终答案、只保留工具轨迹、只保留 lesson、完全清空 memory，比较下一关结果。这样才能把真实的 lifelong learning 与模型已有知识区分开。若五级任务存在固定顺序，Agent 也可能通过记住题目模式获得表面进步，必须使用新任务和新环境验证迁移。

Tier B 4. Memory Tax: Dissecting the Net Value of Agent Memory

arXiv:2610.34073 · 2026-10（具体提交日未单独核验） · arXiv preprint；未核验正式录用
Authors / Affiliation: Xuan He; Sining Zhoubian; Ruozhen Yang; Yuhao Wen; Zhineng Wang 等
Abstract / Metadata · Paper HTML · PDF · Code: 未核验 / Not Reported

人话版：这篇论文到底干了什么？

很多 Agent Memory 系统在自己的 benchmark 上展示提升，却没有回答最基本的问题：与直接在原始历史上做 RAG 相比，写摘要、建图谱和压缩真的有净收益吗？Memory Tax 将“记忆带来的收益”和“记忆处理造成的信息损失”分开，指出不少专门记忆系统甚至不如简单 RAG。它把记忆系统从比绝对 accuracy 推向比净增益、证据保真和可访问性。

因此新记忆方法必须和强 RAG 在相同上下文预算、写入成本与查询成本下比较，才能证明真实的系统价值。

Background / Core Method

论文把原始历史直接检索作为 reference，对照各种 memory construction 与 retrieval pipeline；分析维度包括 faithfulness（原始事实是否保留）、accessibility（存下的证据能否取到）、robustness（换 backbone 是否仍有效），并考察 benchmark headroom 对 memory tax 的影响。与 AMIE 只改变访问索引不同，本工作重点拆解整个记忆处理流程造成的损益。

Experiment / Main Finding

评估涉及 LongMemEval-s、PersonaMem-v2、MINT-Eval 以及不同 Qwen/GPT backbone。主要发现是若干 memory 系统在某些设置下低于 Naive RAG，说明“存储结构更复杂”不自动带来任务收益。论文主表包含多种配置的 judge accuracy；本次没有逐单元核验全部表格，因此不把未核实的数值写进结论。

Contribution / Limitation / Connection

贡献：New Evaluation Lens（Memory Benefit/Tax）、New Empirical Finding。限制是 RAG 强弱对实现和检索范围敏感，不能把所有 memory 系统一概判负。研究用途是给任何新 Agent Memory 方法强制加入 RAG baseline，并报告写入成本、检索成本、证据丢失率和跨模型稳定性；也可用作 AMIE 的 Collision/反事实评估起点。

Why It Matters / Further Evaluation

Memory Tax 对 Agent 系统的工程意义在于：任何额外记忆层都要证明它相对 raw-history RAG 的净收益，而不能只与“无记忆模型”比较。记忆构建消耗的模型调用、写入延迟、索引大小、检索开销，以及后续回答准确率应放在同一条成本–效用曲线上。若 RAG 已经取到正确证据，复杂摘要可能把时间、数量、否定条件压缩掉，产生更隐蔽的事实错误。

可以把 memory tax 拆成三类可操作指标：原始证据丢失率、检索可达性损失和跨模型 reader 不兼容率。它与 AMIE 的关系是互补而非替代：AMIE 改善 access，但无法恢复在内容构建阶段已经被删除的事实。

Potential Use / Collision Check

对任何声称改进 Agent Memory 的论文，建议建立统一审计表：raw-history RAG accuracy、memory-enhanced accuracy、写入 token、检索 token、证据保留率、时效冲突率、跨模型迁移率。只有净收益为正，才值得进一步比较复杂结构。若只是减少检索成本而损失少量准确率，也应明确标成成本–效用折中，而非笼统的性能提升。

Tier BBACKFILL 5. Intuition with Evidence: Adaptive Dual Memory for Multimodal Agents

arXiv:2610.33019 · 2026-10（具体提交日未单独核验） · arXiv preprint；未核验正式录用
Authors / Affiliation: Qiuhe Hong; Jingya Wang; Cuzhen Geng; Shenyao Peng; Munan Ning; Yuyang Liu; Yonghong Tian
Abstract / Metadata · Paper HTML · PDF · Official Code

人话版：这篇论文到底干了什么？

多模态 Agent 的记忆既需要“精确找到那一帧证据”，也需要“把分散片段整合成整体判断”。单纯 episodic retrieval 可能漏掉跨片段关联，单纯 latent memory 又可能缺乏事实锚定。这篇工作将可检索的 episodic memory 与模型内部 latent intuition 结合，并用基于 JSD 敏感度和置信度的 training-free router 决定查询时更依赖哪一边。总体相对 vanilla Episodic 提升 4.67%，是 memory routing 与多模态证据结合的可迁移基线。

但双记忆也引入新的冲突：当内部直觉与可检索的具体证据矛盾时，系统必须能说明为什么选择其中一方。

Background / Core Method

Input → query 与多模态历史 → 多索引 episodic memory 检索精确证据，同时从 latent memory 得到全局先验 → 计算两路预测的 JSD sensitivity/置信代理 → 自适应路由与联合对齐 → 输出答案。它不是简单拼接两份记忆，而是按任务对 evidence-localized 与 dispersed-information 两种需求做选择。

Experiment / Main Finding

论文在 Mem-Gallery、MemoryBench 等多模态长期记忆设置中比较单一 episodic、latent 和检索类 baseline；整体报告相对 vanilla Episodic +4.67%。论文还分析检索失败时 latent memory 的补偿作用。这个数字是论文汇总指标，不能解读为所有子任务都提高 4.67pp。官方代码链接已在论文正文给出。

Contribution / Limitation / Connection

贡献：New Mechanism（dual memory + query-adaptive routing）。限制是 latent memory 可能在缺乏证据时自信地补全错误事实，JSD 也不等于因果贡献。可迁移到 Streaming Video Agent：关键事件用 episodic evidence，长时语义用压缩 latent state；必须和 raw-video RAG、AMIE index adaptation 一起比较。

Why It Matters / Further Evaluation

Dual memory 的真正挑战是冲突处理。假设 latent memory 从多次观察中形成“人物通常向左走”的整体印象，但 episodic evidence 明确记录本次事件向右；router 必须知道何时以具体证据覆盖先验。JSD 只能测两路预测分歧，不能自动判断哪一路更正确。应把有证据冲突、证据缺失、时间过期和长距离依赖的查询分开评估，并报告错误归因。

迁移到视频 Agent 时，latent branch 可以压缩持续场景语义，episodic branch 保存关键事件和时间戳；需要与原始视频检索、均匀帧采样、AMIE 索引演化做成本匹配对照。若在相同视觉 token 预算下不能稳定超过简单 RAG，就不宜把双记忆结构复杂度视为天然优势。

Potential Use / Collision Check

对于长期视频记忆，可以设计“同一视频里先出现误导性常态，后出现关键反例”的测试。latent memory 如果保留常态先验，episodic branch 必须在关键反例被检索到时覆盖它。评价指标不仅是最终 QA accuracy，还应包括引用的时间戳是否正确、冲突证据是否被承认、缓存预算与推理时延。它与 AMIE 的区别是 memory representation 组合，而不是持续访问索引更新。

Idea 1 · Trajectory-Conditioned Cache Validity：面向 Streaming Video Agent 的未来影响感知缓存
