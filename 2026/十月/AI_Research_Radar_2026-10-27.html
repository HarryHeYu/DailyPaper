TIER S

Direction-Aware Token Credit Assignment with Reward-Model Gradients

2026-10-23 · RL / Reinforcement Learning · 未核验（预印本） · 代码链接未在核验页面确认；不要假定开源

Yikuan Hu 等 · 南京大学 / 新加坡国立大学 / 清华大学 / 南洋理工大学

Paper / Abstract · Full HTML · PDF · Project

人话版：这篇论文到底干了什么？

GRPO 在一次采样回答里，通常把整条回答的相对好坏当成每个 token 的同一学习信号。但一句回答里，真正决定奖励的可能只有一个否定词、一个关键事实或某个工具参数。DATC 不直接猜哪个词重要，而是把冻结 Reward Model 的梯度映射到策略模型的 logit 空间，检查“当前策略准备增强或压低这个 token 的方向”与“奖励实际希望变化的方向”是否一致。然后用带 KL 约束的 softmax 把整条回答的优势重新分配给各 token。

Qwen3-14B-Base 上 AlpacaEval 从 GRPO 的 37.39% 提至 49.57%，Arena-Hard 从 28.49% 提至 39.31%；但这是偏好对齐而不是数学推理或 Agent 长轨迹验证。

Background & Research Gap

现有 GRPO 对一条输出的所有位置赋予同一 response advantage。设模型回答“地球不是围绕太阳转”，如果评估器认为整句不好，统一负优势会惩罚所有词，包括正确的实体和语法；真正应修复的是“不”及相关推断。RED 用前缀奖励差做归因，P2T 用输入梯度近似替换 token 的影响，但“某 token 影响奖励”不等于“沿本轮策略梯度更新它会增加奖励”。

DATC 把这一缺口明确写成 update-direction-aware credit。它关注训练动作的边际效果，而非静态文本显著性。

Core Insight 与 Observation

把 token 概率向量看成可微空间，奖励模型在该空间的局部梯度 g_t 是“奖励增长方向”；被采样 token 的对数概率梯度 k_t 是“增加这个动作概率的方向”。二者内积 d_t=〈g_t,k_t〉刻画局部奖励变化。若整条回答的优势 A 为正，就优先加强 d_t 大的 token；A 为负则优先抑制 d_t 小的 token。作者不是假定所有梯度都可靠，而是只在一阶 surrogate 中给出收益保证。

尤其要记住：共享网络参数会让不同 token 之间交叉影响，这个理论保证并非真实非凸训练的全局单调性定理。

Method Deep Dive · Input → Output

Input：prompt、当前 actor 的采样回答、冻结 RM 的响应评分。Step 1：按 GRPO 在同一 prompt 的多条采样间计算 response-level advantage A。Step 2：通过 straight-through 近似，把离散采样 token 接到 RM 输入 embedding 的可微分支；RM 冻结，只回传输入梯度，避免训练另一个 critic。

Step 3：借助 actor 当前 token 分布与 embedding 矩阵，把 RM 的输入梯度变成 logit 空间奖励方向 g_t。Step 4：对每个采样 token 计算 k_t=∇log p_t(a_t)，形成 d_t=〈g_t,k_t〉，保留方向正负。Step 5：对 A d_t 做按回答归一化、温度调节及权重上界控制，得到非负 w_t，保证均值为 1。

Step 6：把 A_t=A·w_t 缓存为 GRPO clipped objective 的 token 系数，原有 reference KL 和 LoRA 更新保留。Output：每个 token 获得不同更新强度，但整条回答的总体优势尺度不被任意放大。它多了一次 RM 输入反向传播，因此不是零开销。

关键公式 / Objective / Toy Example

核心分配是 max_{w≥0,Σw=T} [ A/T·Σ(w_t d_t) − τ/T·Σ(w_t log w_t) ]。第一项最大化一阶预测奖励增长；第二项约束偏离均匀 GRPO 的程度，等价于在 token 份额分布上施加 KL。最优解 w_t=T·softmax(A d_t/τ)，最终 token advantage 为 A_t=A w_t。τ 越小越聚焦少数 token；作者使用最大权重 λ（主实验 λ=4）避免集中度过高。

Toy：三词回答 A=+1，方向增益 d=[0.7,0.1,-0.4]，普通 GRPO 三词等权；DATC 给第一个词更多份额，第三个更少。若 A=-1，方向相反，优先惩罚对奖励最不利的词。这里的 d 是局部模型预测，不是对反事实答案进行真实多次 RM 评估。

Experiment Setup / Research Questions / Baselines

模型：Qwen3-14B 与 Llama-3.1-8B，各含 Base 经轻量 SFT 与官方 Instruct 两种初始化。训练：UltraFeedback 选定 2,000 prompts；每次 8 prompts×8 responses，250 rollouts、每轮一次更新；LoRA rank 64、α128、KL β=0.03、clip ε=0.2；3 张 H200。

冻结 RM 分别为 Skywork-Reward-V2-Qwen3-8B 和 Skywork-Reward-Llama-3.1-8B-v0.2。评估：RM-Reward、AlpacaEval、Arena-Hard v2、MT-Bench。

RQ1：在固定采样预算下，token 定向分配是否优于 GRPO？RQ2：是“梯度大小”还是“方向对齐”重要？RQ3：位置对应关系是否必要？RQ4：额外 GPU 时间值不值得？Baselines：GRPO 为主；P2T、RED 是更直接的 token reward 归因对照；不能把原始 SFT 误当最强 baseline。

Results / Table & Figure Reading

Table 1：Qwen3-14B-Base 的 AlpacaEval 37.39→49.57（+12.18pp），Arena-Hard 28.49→39.31（+10.82pp），MT-Bench 7.70→7.99；Instruct 版的 AlpacaEval 72.80→73.66（仅 +0.86pp），说明强初始模型的边际收益明显缩小。

Llama-3.1-8B-Base 的 RM reward 4.55→11.80、Arena-Hard 2.83→5.10；Instruct 的 AlpacaEval 21.61→27.08。Figure 3：Llama Base 最后 25 轮平均 RM reward 为 14.14 vs 7.72，平均回复长度 497.9 vs 605.2 tokens，提示改进并非单纯增加输出长度。

Table 2：去掉方向对齐，Qwen Base AlpacaEval 暴跌至 1.53；把正确权重随机打乱位置，降至 32.62，显示“权重大小”和“权重落在哪个 token”都重要。Figure 4 通过实际样例显示某个事实词被增强或抑制，但示例本身不等于因果证明。额外 GPU 时间 5.7%–9.1%，需和推理性能增益一起看。

Ablation / Claim vs Evidence

Authors Claim：方向感知的 token credit 能提升对齐优化。Experiments Actually Show：在两种模型家族、四个偏好对齐设置中，平均指标均胜 GRPO；λ=4 比 2、8 更稳；删除方向项和乱序权重都会损害效果。

What Is Not Yet Proven：对 sparse rule-based reward、数学 RLVR、真实 tool-use trajectory、跨 token 的参数耦合是否同样有效。更需警惕 reward hacking：训练 RM 的梯度既可能指向人类偏好，也可能指向评分器的表面模式；外部 judge 的增益减轻但未消除这个问题。

Contribution / Limitation / Research Value

贡献 1 [New Mechanism]：把 credit 从“奖励归因”改写为“沿实际 policy update 的奖励变化归因”。贡献 2 [New Objective]：用 KL 正则推导 token 份额最优分配并保持 advantage 符号与均值。贡献 3 [Empirical Finding]：方向项和 token 位置对齐是必要条件。

限制：需要可微且 tokenizer 对齐的 RM；对外部黑盒 reward 不直接适用；理论基于 straight-through 与独立 logit 局部近似；仅偏好对齐验证；三张 H200 的实验成本并不等于可在 8GB GPU 直接复现。研究价值：可作为 credit-assignment baseline、解释 reward gradient 的攻击对象，以及将 RM 梯度转移到工具决策/多 Agent 通信的起点。

Migration · 最小实验 / 风险

Original Problem：单条回复内 token credit。Transferable Mechanism：奖励梯度与当前更新方向的内积。New Research Question：长轨迹中哪些 tool call / memory retrieval 的更新真正提高最终成功率？Method Modification：把 token 分配扩展为 turn 或 tool-action 分组，构造可微的局部 reward surrogate，保留 trajectory-level outcome 的符号。

Minimum Experiment：先在可重放的 3–10 步工具环境训练 Qwen3-4B/8B LoRA，比较 GRPO、均匀 turn credit、随机分配与方向分配；记录 success、训练稳定性、工具调用次数和 RM 梯度噪声。Dataset：可用可执行的 QA/工具任务，具体协议需先冻结。Expected Contribution：由 token credit 推广到结构化动作 credit 的机制验证。

Risk：环境不可微、reward 模型误差、跨步依赖使局部梯度失真；若只换权重而无真实 credit 对照，很容易撞题。

五句话总结

第一，DATC 解决的是更新方向上的 token credit，而非普通 saliency。第二，它在固定 GRPO 框架中改变每个位置的学习份额。第三，Qwen Base 的偏好指标改善很大，但 Instruct 收益有限。第四，额外计算与 RM 梯度偏差是实际代价。第五，最有价值的下一步是将 credit 从 token 推广到可验证的 trajectory decision。

TIER S

Lifelong Context Adaptation through Bidirectional Memory–Skill Learning

2026-10-23 · Agent / Multi-Agent · 未核验（预印本）

Tianyi Xu; Huazheng Wang · Oregon State University

Paper / Abstract · Full HTML · PDF · GitHub / Code

人话版：这篇论文到底干了什么？

长时间运行的 Agent 会积累大量交互：有些是“上次用户说过什么”的事实，有些是“遇到这类任务应该怎么做”的技能。只存 memory，下一次还得重新推导步骤；只存 skill，容易丢掉具体对象和约束。MemCryst 把 episode、typed fact、conditional skill 分开保存，又让它们相互促进：重复 episode 形成 skill，skill 指导的新行动再形成 episode；任务结果只更新“哪些记录以后更值得检索”，不直接改写事实内容。

它不更新 LLM 参数，Qwen3-8B 在 ALFWorld 上达到 63.17%，超过 memory-only 59.83% 和 skill-only 50.50%。真正值得研究的是“记忆被使用”和“记忆造成成功”之间仍存在因果缺口。

Background & Gap · 具体例子

设 Agent 上周在厨房任务里失败：它把脏杯子直接放进柜子。episode 记录“杯子未清洗导致失败”，skill 可总结“放入柜子前先清洗”；但下次任务还要记住杯子的位置、哪些柜子可用，这些是具体事实。纯 memory 会反复推导流程，纯 skill 无法定位对象。更复杂的是：一次成功时上下文可能同时出现 5 条事实和 2 个技能，不能因此认定它们都造成了成功。

MemCryst 将内容生成与使用权重更新分开，试图让系统在线适应，但其反馈依然是相关性，不是严格的 counterfactual attribution。

Core Insight / Architecture

外部状态 Ξ=(Episodes E, Facts F, Skills S, retrieval statistics ρ)，冻结策略 πθ0 不变，有效策略由输入任务和检索上下文共同决定。系统按“检索 → 行动 → 获得 outcome → 对本次实际曝光记录更新统计 → 写入新 episode/fact → 到 sleep boundary 时聚类合成或修订 skill”的时间顺序运行。

先 return 后 write 是关键：刚从本次任务写入的记录不能反过来领到本次成功奖励，避免信息泄漏。Skill 保存适用条件、参数化步骤、来源 episode IDs；事实保留来源与重复证据。检索同时考虑相关性、scope 和历史使用统计。

Method Deep Dive / Objective / Toy

Step 1：任务 q_t 到达，R_ρ 从 E/F/S 中按域、适用性和预算筛选记录，记录真实曝光集合 U_t。Step 2：冻结 Qwen3 根据 q_t 和上下文执行 τ_t，环境返回 r_t 和二元 success y_t。Step 3：对曝光事实更新次数 n_f 与成功数 h_f，得到 C_f=(h_f+1)/(n_f+2)；对曝光 skill 做 EMA：U_s←U_s+α_s·x_ts·(y_t−U_s)。

Step 4：从轨迹提取 episode 的证据、诊断和教训，抽取带 provenance 的 typed facts。Step 5：周期性对相似 episode 聚类，合成条件化 skill，独立 audit 其泛化、适用性与支持证据；若已有同 capability key，合并来源并审计后修订，保留原 skill 身份和使用统计。

Toy：某 skill 在十次使用中八次成功，EMA 提升其未来排序；但同时出现的“杯子在台面上”事实也可能被加分，即使成功真正依赖的是导航技能。该例揭示 outcome-return 的可用性与归因风险。

Experiment Setup / Baselines / RQ

主要冻结 backbone Qwen3-8B；ALFWorld 额外测试 Qwen3-1.7B 和 GPT-4o-mini。十个设置覆盖 ALFWorld、RULER、BABILong、LoCoMo、LongMemEval、名称替换 DialSim、MATH-hard、MBPP、CodeContests、LCB+。

比较 ReAct、ExpeL、MemP、SimpleMem、LightMem；评估使用 prequential 协议，即每次任务先评分再写入更新，包含冷启动错误，防止只报告训练后的漂亮成绩。RQ1：memory+skill 是否互补？RQ2：反馈通道是否有交互效应？RQ3：跨域共享状态会不会干扰？RQ4：冻结模型换规模后是否成立？RQ5：被检索内容真有用还是只是 token 更多？

Claim vs Evidence / Ablation

Authors Claim：联合 memory-skill 和 outcome return 构成可持续的上下文适应。Experiments Actually Show：在多个基准、不同 backbone 上有效；ALFWorld 2×2 消融显示事实和技能反馈不能简单相加。

What Is Not Yet Proven：记录的 individual causal contribution、1000-step 长期漂移、敏感事实的删除闭环、跨任务同一记忆的可迁移价值。论文明确承认：C_f 是曝光后任务成功的平滑统计，不是事实为真的概率；同一次成功分配给全部曝光记录并非因果 credit。这里正是最重要的 research gap，而非可以忽略的小瑕疵。

Contribution / Limitation / Research Value

贡献 [New Mechanism]：memory→skill→behavior→memory 的双向在线环；[New Evaluation]：prequential 冷启动与跨域交错；[Empirical Finding]：事实与技能联合反馈的交互效应。局限：技能为文本建议而非可执行能力；LLM 冻结但总结/审计仍有额外调用成本；错误事实可能因共同曝光被奖励；跨域共享不如 specialist；代码任务收益不稳定。

研究价值：作为长期 Agent memory baseline 很合适；更重要的是它提供可追踪曝光集合、来源 ID 和技能版本，可在此基础上做真正的 causal memory attribution、删除验证和 counterfactual replay。

Migration · 从相关性到因果贡献

Original Problem：多类外部记录的检索权重在线更新。Transferable Mechanism：曝光追踪 + 成功反馈 + 版本化技能。New Research Question：某条 memory/skill 究竟让成功率改变多少，而不只是与成功共现？Method Modification：对高价值或高风险记录做 paired replay（同状态、同随机种子，有/无该记录），用差值更新信用，并对重叠技能做 Shapley 近似或分组反事实。

Minimum Experiment：ALFWorld 或可重放工具任务，Qwen3-4B/8B，比较 MemCryst outcome return、均匀反馈、随机权重、paired counterfactual；指标 success、token/调用成本、错误记忆抑制、stale-memory 恢复、记录删除后的行为差异。Expected Contribution：从 usage statistics 升级到可验证的记忆因果归因。

Risk：配对重放成本高、非确定性环境与隐藏状态造成混杂，不能把模型输出差异直接等同真实因果。

五句话总结

第一，MemCryst 让 memory 和 skill 真正形成反馈循环。第二，它把内容改写与使用权重更新分离。第三，ALFWorld 与对话记忆证据较强，代码场景不总占优。第四，它自己承认曝光后的 success 不是因果贡献。第五，做 attribution、冲突/过期记忆与删除闭环，可能比再加一个 memory store 更有研究价值。

Video-MemComp: Taylor-Guided Sensitivity-Aware Memory Management for Streaming Video Understanding

2026-10-23 · Video / Multimodal Acceleration · ACM Multimedia 2026（论文标注已接收）

Yonghui Niu 等 · 南京大学 / 中国移动九天 / 中科院自动化所等

Paper / Abstract · Full HTML · PDF · Project · GitHub / Code

人话版：这篇论文到底干了什么？

流式视频不断进帧，Video VLM 的视觉 token 与 KV cache 会越积越多。只按相似度删 token，可能把关键动作删掉；只给每层一样多的 cache，又可能在敏感层造成大误差。Video-MemComp 把压缩误差拆成“局部近似损失”和“后续网络对该层误差的敏感性”：在 RoPE 之前聚合时空冗余 token，并用 attention logit bias 补偿融合数量；再结合离线梯度先验与在线注意力熵，为各层动态分配固定总 cache。

作者报告 Qwen2.5-VL-3B 综合准确率 62.3→64.1，KV 内存节省超过 90%；在 A6000 上相对 ReKV 峰值显存 22.95→16.74GB、TTFT 0.0846→0.0302 秒，但吞吐低于 ReKV，必须一起看。

Background & Gap

设一个 2 小时监控视频，前 20 分钟画面静止，下一秒有人打开门。均匀抽帧会浪费静止时段预算，粗暴按 token similarity 删除可能损失门把手的小动作；更糟糕的是，同样的压缩扰动在不同 Transformer 层会被不同程度放大。已有 KV eviction、时空 token merging、CPU offload 或固定预算方法往往分别优化局部冗余、历史保留或内存，但缺少把局部误差与跨层敏感性一起考虑的准则。

论文将这两项放在同一个可解释框架里。

Core Insight / Theoretical Objective

把模型输出写成各层 attention state 的函数 O=G(A⁰,…,Aᴸ⁻¹)。一阶 Taylor 给出压缩后输出变化的近似上界，按层分解为 S_l·E_l，其中 S_l 表示输出对第 l 层 attention state 的结构敏感性，E_l 表示该层压缩引入的局部近似误差。于是固定 cache 预算 B 下，目标是 min Σ_l S_l E_l(b_l)，约束 Σ_l b_l≤B。

直觉：同样节省 100 个 KV，应该优先从“误差小且不敏感”的层拿，而不是所有层等比例削减。这里是 surrogate 上界和近似分配，不代表实际任务准确率的严格最优性证明。

Method Deep Dive · 两级压缩

Input：连续视频帧的视觉特征、当前 KV cache、预先标定的各层敏感性。阶段一（frame/token）：比较当前帧与上一帧的 cosine similarity，保留发生变化的 token；对同帧冗余 token 做二分匹配与聚合，记录每个 survivor 代表多少原 token；在 pre-RoPE 区域完成融合，避免旋转位置编码破坏相似性；在 attention logit 加入代表数量的补偿，减少聚合后 attention mass 偏差。

阶段二（layer/cache）：用离线 calibration 数据求各层梯度范数先验 S_l；在线用 proxy query 估计 KV 重要性与 attention entropy，结合 value norm 得到动态可压缩性；再混合均匀预算、静态敏感性和动态信号，为每层求 b_l，保留最重要的 KV。Output：随时间有上界的 cache，而不是所有历史帧都保留。

注意 training-free 指不更新目标 VLM 权重，但离线敏感性标定仍需要数据与计算。

关键公式 / Toy Example

预算分配目标 min_{b_l} Σ S_l E_l(b_l)；实际使用 ρ*=λ_uρ_uniform+λ_sρ_static+λ_eρ_dynamic，再取 b_l=floor(B·ρ*_l)。Toy：两层各压缩 100 token，第一层敏感度 5、第二层 1，若两层的每个 token 删除误差近似相同，优先给第一层更多预算可降低总误差。若下一段视频突发复杂运动，在线 entropy 与 value norm 可能改变第二层的优先级。

这个例子是解释分配直觉，不是论文报告的数值实验。

任务包括离线 EgoSchema、MLVU、VideoMME 与在线 RVS-Ego、RVS-Movie；模型 Qwen2-VL-7B、Qwen2.5-VL-3B、LLaVA-OneVision-7B 等。比较完整 KV、InfiniPot-V、StreamMem、StreamingTOM、ReKV（区分 CPU offload 和 GPU-only）等。

Migration · Query-aware / Agent-aware Cache

MultiAgent-OPD: End-to-End Training of Hierarchical Multi-Agent Systems with On-Policy Distillation

2026-10-20 · RL / Reinforcement Learning · 未核验（预印本） · 近周更新；本日社区重新收录，不是 10/27 首次提交

Yuhan Sun 等 · 论文作者团队（详见原文）

Paper / Abstract · Full HTML · PDF · Project

人话版

一个 Leader 把问题拆给 Searcher，再由 Answerer 汇总；只用最终答对没答对训练所有角色，会让搜索者不知道哪条查询、哪段摘要真正有帮助。MultiAgent-OPD 先训练一个会搜索和总结的 teacher，再冻结它，让它对学生实际生成的 search/query/summary token 提供局部 process supervision；Leader 与 Answerer 则主要接收任务结果奖励。

最终共享参数团队在七个问答数据集上的 macro pass@1 为 38.68%，高于 Prompted Critic 约 4.06pp、C-MAS+RL 约 2.61pp。关键不是“多 Agent 就会更好”，而是不同角色需要不同粒度的信用信号。

Background & Gap / Core Insight

单体 RLVR 的 terminal reward 在短题上尚可，但多轮搜索任务存在延迟和稀疏反馈。把最终答案奖励直接给 Searcher，容易把它训练成不再积极搜索的保守策略；用通用 LLM judge 评分搜索质量，又可能与最终正确性错位。

作者将训练拆为两阶段：先用任务正确性培养 Searcher-Answerer teacher，再对当前学生的 on-policy 中间动作做 token-level teacher distillation。这样搜索者收到密集、与任务相关的过程信号，Leader 仍按最终任务目标学习，避免所有角色共享一个粗糙奖励。

Method / RL Formulation / Reward

Input：用户问题、Leader 的子任务、Searcher 的搜索工具反馈。Stage I：训练 Searcher-Answerer teacher，以答案正确性为监督来源；Stage II：共享 student 参数承载 Leader、Searcher、Answerer 角色，Leader 生成拆解与调度，Searcher 生成查询/摘要，Answerer 综合候选。

冻结 teacher 在 student 当前轨迹上打 token-level distillation 信号；Leader 使用团队 success advantage，Answerer 使用候选答案 correctness advantage。State 是问题、历史子任务和检索观察；Action 包括分配、搜索和回答；Trajectory 是多波搜索及最终回答；Reward 包含最终可验证结果与 teacher 的局部过程监督。

它不是严格的 counterfactual multi-agent credit：teacher 仍可能奖励“像正确搜索”但实际无用的动作。

Experiments / Results / Figure Reading

七数据集覆盖 NQ、TriviaQA、PopQA、HotpotQA、2Wiki、MuSiQue、Bamboogle，比较 C-MAS base/+RL、H-MAS base、Prompted Critic、Search-R1、DeSA、Tree-GRPO、MemSearcher 等。主要表格的 38.68 是 macro pass@1，不能误写成 pass@4；pass@4 在另一张子表中单独给出。

作者还分析 outcome-only Searcher RL 的 search collapse，teacher 是否针对任务训练，以及直接监督和推理资源使用。研究问题是：收益来自团队结构、teacher 专长，还是更细的 on-policy process credit？必须把结构基线与训练信号消融分开读。

Contribution / Limitation / Migration

贡献 [New Training Paradigm]：角色差异化的 end-to-end team training；[New Objective]：把 frozen teacher 的过程监督与 outcome RL 合用。限制：teacher 自身训练有成本；局部蒸馏不保证工具调用真实因果价值；搜索任务与多 Agent 通信拓扑仍较固定；更长 horizon 可能出现错误摘要的级联传播。

迁移：用工具成功率或反事实删除评估 Searcher 每次检索的真实边际贡献，比较 uniform team reward、teacher-only、OPD 与 counterfactual credit。最小实验可在多跳 QA 复用 4B/8B student，测 pass@1、search collapse、无效检索比例和训练 GPU 时长。Worth Deep Reading：YES。

Phronix: The Capability-Centric Learning Paradigm for Agents

2026-10-22 · Agent / Multi-Agent · 未核验（预印本） · 官方代码地址未在本次可核验正文确认

Hariharan Devarajan 等 · Lawrence Livermore National Laboratory / Illinois Institute of Technology / University of Tennessee

Paper / Abstract · Full HTML · PDF

人话版

很多 Agent 每次遇到类似的编译、分析或迁移任务，都重新试错一遍。Phronix 让 agent harness 从执行轨迹中抽取可复用 capability，并通过 predictor–validator–corrector 循环持续改进：固定、可验证的操作做成工具，需要上下文判断的策略保留为 skill。

作者在重复任务中报告首试成功率 93–95%，warm-start 每任务约 0.38–0.40M tokens，比单次 baseline 少约 3–4 倍。它特别适合研究“经验如何从日志变成可验证技能”，而不只是无限增长的记忆库。

Background & Gap / Insight

手工写 skill 的 Agent 依赖人的先验；自动摘要记忆又常把失败、环境条件和代码版本混在一起。Phronix 的核心划分是：可确定复用的动作应有输入输出契约并能在执行时验证，语义上需判断的步骤应留在可编辑 skill。论文用性能工程场景说明：缺失的链接 flag 可以固化为工具；选择哪些函数值得 I/O 标注，则必须依据具体程序分析。它尝试把经验转为“有类型、可校验、可复用”的 capability，而非仅存文本教训。

无标签 test-time RL 常把“采样出现次数多的答案”当作更可信，但多解题目恰恰需要保留罕见而正确的答案。MS-TTRL 指出 frequency 同时被拿来做正确性估计和多样性控制，会产生冲突：高频答案可能是流行错误，低频答案可能是有效新解。

方法将两种用途分开，用 outcome-level self-verification 估计正确性，用三态 cache 记住验证状态，再用 confidence-gated inverse probability scaling 加强被可靠验证的稀有答案。作者报告相对最强无标签 baseline 的 Recovery Rate 平均提高 19.13 个百分点。

Background & Gap / Core Insight

数学、工程和科学题可能存在多个等价或非等价正确解。若用频率当 correctness，policy 会不断强化最常见的候选，最终模式坍缩；若简单对稀有候选加权，又会奖励随机噪声。核心 insight 是 correctness 与 diversity 不能由同一个频率统计承担。先做独立的 self-verification，再只对“罕见且有把握正确”的结果增加优化权重，才能同时保护探索和稳定性。

Method / RL Formulation / Reward

State 是当前题目、候选结果集合与验证缓存；Action 是生成一条候选解；Trajectory 为 test-time 多次采样与自验证；Reward 来自 outcome-level self-verification 而非完整人工标签；Objective 将验证后的正确性与罕见结果的 inverse probability scaling 结合。

Three-State Outcome Cache 区分可信、待确认和否定状态，Candidate State 缓冲模糊情况，避免一次不确定判定永久抛弃候选。Confidence Gate 限制错误稀有解被放大。风险是 verifier 自身与生成器共享偏差，伪验证可能被模型利用；这并非严格外部 ground truth。

Experiments / Results / RQ

作者在两个 benchmark、四种多解任务、三个 backbone 上分别使用五个随机种子，报告 Recovery Rate 相对最强 label-free baseline 平均 +19.13pp，并接近 supervised IPS-GRPO。

研究问题：拆开 frequency 两种角色是否减少 mode collapse？缓存复用是否改善样本效率？罕见解加权是否会放大错误？应重点读论文 Section 3 的 Frequency Conflict、Section 4 的三态 cache、Section 5 的 ablation 和 rare valid outcome 分析。当前核验到的公开摘要未提供各任务完整数字，因此不虚构具体模型、训练 token 或 GPU 时长。

Contribution / Limitation / Migration

贡献 [New Objective]：正确性与多样性统计解耦；[New Mechanism]：带置信门控的稀有结果强化。局限：依赖自验证可靠性；多解集合边界不总可判定；test-time RL 的在线训练成本未从摘要直接确认。迁移到 Agent RL：把 trajectory outcome 去重，避免把频繁但无效的工具路径当成功经验；用可执行环境 verifier 再对稀有成功轨迹增加采样。

Zhiyong Cao 等 · 机构见原文

Paper / Abstract · Full HTML · PDF

人话版

一个 Agent 完成了任务，不代表它的 harness 没有越权、恢复错误或工具记录缺失。TraceTrial-Bench 将模型任务能力和 harness 可靠性分开评估，用轨迹追踪、环境证据采集和机制链归因定位失败。

作者构造 95 个机制导向任务，覆盖 4 个 harness、9 个模型，总计 3,420 次运行；harness 综合分为 59.8%–72.0%，有 31.1% 的运行虽然任务成功，却至少违反一项 harness 可靠性标准。

Background / Method

传统 Agent benchmark 主要看最终答案，难以发现 checkpoint 恢复、权限边界、工具调用一致性与观察链路的缺陷。论文把可靠性分为 context、execution、governance、lifecycle、observability、tools、verification 七个方面；TT 记录执行轨迹，MEA 收集 agent/context/environment 多来源证据，FA 输出机制链。

其关键设计是“可观察到的证据”与“可以作出的结论”保持边界。

Experiment / Main Finding

95 个任务采用可执行或状态型 ground truth，强调跨 harness 的语义等价比较。3420 次运行揭示任务成功与 harness 安全并不等价；59.8–72.0% 的综合得分提示底层运行器仍有大缺口。最值得读的是 harness taxonomy 与 Failure Attribution 的证据协议，而非单纯排行榜。该论文不是提高模型准确率的新训练算法。

Contribution / Limitation / Connection

贡献 [New Benchmark]：将 harness 作为独立系统对象；[New Evaluation]：机制链归因。限制：覆盖的 harness 与任务有限，评价器仍可能有证据盲点；真实云工具的不可逆副作用难完全复现。连接：可以作为 memory/skill agent 的长期运行测试框架，尤其适合验证错误恢复、共享状态和工具 provenance。

潜在实验：对同一 Agent 的 memory update 插入故障，比较任务 success 与 harness reliability 的分离程度。

On-Policy Self-Training: Data-Free Self-Improvement in Large Language Models

2026-10-23 · Other / Reasoning & Systems · 未核验（预印本）

Leon Sick 等 · Google 等（详见论文）

Paper / Abstract · Full HTML · PDF

人话版

模型能否在没有人工题目和标准答案的情况下自己变强？OPST 从很粗的 topic seed 出发，让模型自己生成问题、答案和 privileged reasoning，再用伪验证筛选可信样本，进行 on-policy self-distillation。作者还扩展到视觉问答。这个方向与 Agent 自我改进有交叉，但不应误称为普通 RLVR：它的核心训练信号来自自生成课程与蒸馏，而不是外部环境的可验证 reward。

Background / Method

传统自蒸馏往往仍依赖人工任务集或外部 teacher。OPST 的 Topic-Seeded Curriculum 生成多样问题和高信息量推理；Pseudo-Verification 在新上下文和改写问题下检查答案能否重现；Consensus Gate 筛除不一致候选；再以 EMA teacher 和 divergence objective 更新 student，迭代刷新数据。视觉版将课程与验证扩展到图像相关输入。

Experiment / Main Finding

论文声称在语言与多模态 benchmark 上有持续提升，且混合领域训练时保留其他领域能力；但本次核验的摘要没有给可安全引用的逐数据集数字，因此不伪造“提升 X%”。应优先核对 Section 3 的验证门、Section 4 的训练配置与 out-of-domain retention 表，判断改进是否只是生成数据分布向模型已有强项收缩。

Contribution / Limitation / Connection

贡献 [New Training Paradigm]：从 topic seed 形成自生成数据闭环。限制：自验证会形成 self-confirmation bias，错误答案也可能稳定复现；生成成本与验证成本不可忽略。Connection：可迁移到 Agent curriculum / tool-skill 数据生成，但必须加执行环境验证或独立 verifier，否则只是在强化模型已有偏见。

TileShare: Training-Free Acceleration of Overlapping Tiled ViT Decoding

2026-10-23 · Other / Reasoning & Systems · 未核验（预印本） · 视觉加速相邻技术；不计入 Video 主方向正式数

Xiangzhong Ye 等 · 机构见原文

Paper / Abstract · Full HTML · PDF

人话版

处理高分辨率视觉输入时，模型常把画面切成相互重叠的 tile，再分别做 ViT 计算。重叠区域被重复编码，浪费大量算力。TileShare 研究在保留 tile 语义边界的前提下共享重叠 token 的计算，而不是简单把所有 tile 拼成一张图。它不是专门的 Video LLM 加速方法，但“跨窗口共享重复特征”很容易启发跨帧 feature cache。

Background / Method

Tiled decoding 近似一个隐式 ensemble：同一位置在不同 tile 上会看到不同上下文。若无条件共享所有层，可能破坏 tile-specific attention。作者区分共享 token 的可精确部分与需要近似的 attention 影响，并讨论为什么早期层、融合方式和 tile 边界更关键。方法以 training-free 加速为主，另讨论经过训练的全层共享。

Experiment / Main Finding

论文在 MiniMax-H3 及另外两个 decoder 上评估，包含相对替代方法和不同 tile 条件的比较；本次可核验的页面目录没有提供足够明确的 FLOPs、延迟、质量数字，因此这里不写加速倍数。建议读 Section 3 的 exact vs approximate、Section 4 的误差位置、Section 5 的硬件 latency 表。

Contribution / Limitation / Connection

贡献 [New System/Mechanism]：把空间重叠计算共享与 tile 上下文保留分离。限制：共享计算的 cache 与调度开销可能抵消理论 FLOPs，tile 间语义不一致也可能引入误差。迁移：对 Video VLM 相邻帧重叠 patch 建立 feature reuse，在同一 GPU 上测 encoder ms/frame、峰值显存、Video QA 与动作边界误差；避免把静态图像收益直接外推到视频。

Understanding Communication Failures in Multi-Agent LLM Systems

2026-10-22 · Agent / Multi-Agent · 未核验（预印本）

Priya Pitre 等 · 机构见原文

Paper / Abstract · Full HTML · PDF

人话版

多个 Agent 讨论不一定更准确：它们可能过早一致、忽略少数正确意见、延续错误前提，或者把不确定说成确定。本文从 3,211 条失败的多轮轨迹出发，建立通信失败分类法，并分析错误如何随轮次传播。它不提出一个“又多聊一轮”的新框架，而是为 multi-agent communication 提供可操作的故障模式与诊断维度。

Background / Method

多 Agent 系统常只报告最终准确率，难判断错误是独立推理失败还是信息交换导致。作者收集医疗 QA、代码、金融、多跳推理、伦理和具身文本任务的失败轨迹，进行分类、人工标注和对照集构建；分析多数意见转移、少数信号压制、错误恢复难度与实时触发模型。重点是 round-level error dynamics，而不是只看平均对话长度。

Experiment / Main Finding

已核验 3,211 条失败轨迹的样本规模；论文进一步分析不同系统设计与任务的失败分布，但本次摘要未给可直接确认的细分百分比，故不编造。应读 Section 4 taxonomy 和 Section 5 temporal cascades、recovery hardness，特别留意“最终失败的轨迹样本”是否足以推断所有多 Agent 交互的总体失败概率。

Contribution / Limitation / Connection

贡献 [New Evaluation/Empirical Finding]：把通信错误从结果层拆到传播链。局限：以失败轨迹为主的采样可能产生选择偏差，LLM 标注与人类一致性也需审计。连接到 MultiAgent-OPD：局部 Searcher credit 如果奖励“与 Leader 一致”，可能加剧错误共识；未来可对不同 agent 的信息来源、独立证据和 dissent preservation 建立显式 credit。

11 · Idea Mining · 值得真正实验的交叉点

以下是研究假设，不是已经证明的新贡献。Novelty、Feasibility 与 Compute Cost 为本次初步主观评估，5 星 Compute Cost 表示更贵。

Video Acceleration × Streaming Agent

I-1 · 目标条件化流视频记忆：事件证据约束的双层缓存预算

Novelty ★★★★☆ · Feasibility ★★★★☆ · Compute Cost ★★★☆☆

Inspiration：Video-MemComp 的 layer-sensitive KV budget、DirCast 的主动视角选择与 VETO 的时空 token 聚合。Research Gap：现有压缩多依据相似度、proxy query 或注意力统计，未直接保证“未来决策所需事件证据”仍可被恢复。

Hypothesis：将事件变化概率、用户当前 goal 与 layer sensitivity 联合纳入预算，比仅按相似度或注意力压缩更能在固定显存下保留关键动作。

Proposed Method：先低成本检测 frame/event boundary，为每个事件保留 provenance 与可回访索引；再按任务 query 的可回答性预测给 token/帧分配保留预算；KV 层预算沿用 Video-MemComp 的 S_l·E_l surrogate，增加事件遗漏风险项。若下一步 Agent 决策置信度低，触发局部高分辨率 revisit，而不是扩大所有历史 KV。

Minimum Viable Experiment：Qwen2.5-VL-3B + VideoMME/MLVU 中事件定位与时序 QA 子集；对照 uniform sampling、VETO、Video-MemComp、Video-MemComp+random revisit。

固定 6K KV 预算，报告 QA accuracy、event recall、frames/tokens、FLOPs（若可测）、TTFT、end-to-end GPU latency、tok/s、peak memory。Expected Contribution：在相同内存预算下，以可验证事件证据约束的 query-aware streaming compression。

Risk：未来 query 不可见、检测器漏事件、revisit I/O 反而变慢。Collision Risk：HIGH，和 Video-MemComp、VETO、DirCast 在组件上重合；差异化必须是“事件证据可恢复约束 + 真实端到端效率”而非再加一个 token scorer。Best Venue：CVPR / ICCV / ACM MM。

RL × Agent Memory × Credit Assignment

I-2 · Counterfactual Memory Credit：记录被用到不等于记录有用

Novelty ★★★★☆ · Feasibility ★★★★☆ · Compute Cost ★★★☆☆

Inspiration：MemCryst 对曝光记录统一回传成功统计，但明确承认这不是因果归因；DATC 强调更新方向的 credit；Phronix 为 capability 提供可执行验证。Research Gap：memory/skill 检索后的 outcome 只能说明共现，无法区分必要、冗余、误导性信息。

Hypothesis：对关键记录进行低成本反事实 replay，可更准确地估计净贡献，减少 stale memory 与错误技能的长期强化。

Proposed Method：为每次执行保存 state、检索记录 ID、工具快照与随机种子；对高不确定/高频记录进行有/无该记录的 paired replay；估计 Δsuccess、Δtool cost 与安全风险，更新 record-level utility；普通任务用便宜的代理预测，定期以可执行 counterfactual 校准。

Minimum Viable Experiment：Qwen3-4B/8B + ALFWorld 或可重放的工具 QA，比较 MemCryst outcome return、frequency-only、random、paired replay；指标 online success、反事实归因一致率、错误记忆恢复时间、token/call 开销、跨域性能。

Expected Contribution：从关联性 usage feedback 走向可审计的 memory causal credit。Risk：重放不完全可复现、组合爆炸、成本过高。Collision Risk：HIGH；与 Live-Evo、MemCryst、memory attribution 方向存在重合，差异化须靠严格 paired design 与成本-收益曲线。Best Venue：ICLR / NeurIPS。

Multi-Agent RL × Information Flow

I-3 · Dissent-Preserving Multi-Agent Credit：保护少数正确证据

Novelty ★★★★☆ · Feasibility ★★★☆☆ · Compute Cost ★★★★☆

Inspiration：MultiAgent-OPD 用角色专属 process signal 训练团队，Communication Failures 揭示少数正确意见被压制，DATC 则强调“沿更新方向”而非静态重要性。Research Gap：团队最终成功奖励可能鼓励早期一致，导致独立证据被多数意见淹没。Hypothesis：若对每条跨 Agent 信息记录来源、独立性和最终贡献，可在不无限增加通信轮数的前提下改善少数正确意见的保留。

Proposed Method：建立 message provenance graph；对关键 dissent 消息执行 remove/replay 或 role swap，估计其对最终答案的边际影响；对 Leader 的聚合动作施加 evidence coverage reward，对 Searcher 保留 task-trained teacher 监督。仅在 verifier 支持的任务上计算昂贵的反事实信用。

Minimum Viable Experiment：4B/8B 三角色多跳 QA，比较 majority vote、Prompted Critic、MultiAgent-OPD、provenance credit；指标 pass@1、正确少数意见召回、通信 token、错误传播轮数、训练稳定性。Expected Contribution：明确的 message-level causal credit 与反共识坍缩评估。

Risk：角色重放成本高、证据独立性难定义、reward hacking。Collision Risk：MEDIUM-HIGH；与 MARL counterfactual credit 和 communication attribution 已有交叉。Best Venue：NeurIPS / ACL。

Agent Evolution × Security × Evaluation

I-4 · Capability Regression Gate：Agent 自进化中的技能退化与权限回归

Novelty ★★★☆☆ · Feasibility ★★★★★ · Compute Cost ★★☆☆☆

Inspiration：Phronix 自动固化工具与技能，RSIHub 提供版本化候选与评测 lineage，TraceTrial-Bench 区分任务成功与 harness 可靠性。Research Gap：能力进化常只奖励 pass@1，新增 skill 可能使旧任务退化或扩大工具权限，却仍被评估器接受。

Hypothesis：将旧任务回归、权限约束和副作用一致性纳入候选准入门，可显著降低 Agent self-improvement 的长期退化。

Proposed Method：每个 capability 保留 provenance、测试集、最小权限与副作用声明；候选合并前运行分层 gate：新任务成功、旧任务 regression、权限 diff、checkpoint/retry 一致性；只有通过 gate 才更新 skill catalog。失败样例进入可重放 regression bank。

Minimum Viable Experiment：30–50 个重复软件工程任务、2 个 Agent backbone，对照 Phronix-style capability builder、RSIHub evolution、加 regression gate 的方法；指标 pass@1、旧任务退化率、越权率、恢复一致性、每次进化成本。

Expected Contribution：将安全与回归测试变成 agent evolution 的可复现目标。Risk：测试覆盖不足、过严 gate 限制探索。Collision Risk：MEDIUM；主要是系统/benchmark 创新，需设计真实且非平凡的回归分布。Best Venue：ICSE / NeurIPS Datasets & Benchmarks。
