人话版：这篇论文到底干了什么？

为什么小模型做 Agent RL 时，碰到难题常常越训越没有信号？因为一组 rollout 可能全失败，GRPO 得到的组内相对优势近乎为零。RTI 不直接让更强教师替代学生，而是在 rollout 当下，用“Validator→Corrector→Verifier”修正会让任务失败的关键一步；随后用困惑度门控排除离原策略太远的修正，再对真正改变推理方向的 token 加权。Qwen3-8B 在 Navigation 的 pass@1 从 GRPO 的 35.33% 到 57.33%，在 Claw-Eval-Hard20 从 22.50% 到 50.00%。它的重要性在于把“失败轨迹的局部可修复性”变成 RL 的探索来源，同时明确讨论 off-policy 偏移和信息泄漏。

Background & Research Gap

常规 GRPO 从当前策略采样 G 条轨迹，以同组 reward 的均值与标准差构造 advantage。假如某个工具任务 8 次都失败，所有 reward 都是 0，组内差异消失；即使模型实际上知道 90% 的操作，也没有哪一条轨迹告诉它“第一步工具权限理解错了”。OPD、LUFFY 用强教师或离线成功轨迹补信号，但教师能力与行为分布又成为限制。RTI 的观察是许多失败并非整体知识缺失，而是一个早期局部决策让后续工具调用陷入死循环。例子：Telecom 场景里需要用户自行执行的工具，被 Agent 错当成自己可调用的工具。纠正这一点后，后续步骤仍可由原策略完成。

Core Insight & Observation

RTI 不是把失败任务直接交给更强模型“给答案”，而是识别“最小纠错”能否把当前策略引向成功。这改变了训练样本的生成机制：原先只观察策略自然采样出的成功，现在主动在失败组上制造可学习的成功。但制造出来的轨迹并非严格 on-policy，所以作者将“修正质量”“策略分布距离”“梯度应该聚焦哪里”分成三个独立控制问题。它最值得迁移的是局部因果转折点，而不是多 Agent 提示词本身。

Method Deep Dive

完整流程：输入任务 x 和当前策略 πθ → 采样 G 条工具交互轨迹 → 用任务评估器给每条二值 reward → 若整组失败则触发干预 → Validator 检查当前步骤是否已偏离可完成任务的路径 → Corrector 保留原行为风格和工具 schema，只修改关键错误步骤 → Verifier 同时检查任务目标一致性、无特权信息泄露、与原策略行为合理接近 → 用原策略重新计算修正片段的 PPL → 超过阈值 δ 的修正被过滤 → 通过的修正轨迹替换组内一条失败轨迹 → 用 reasoning-shift token 权重优化策略。注意三个 Agent 角色默认都可由策略模型本身承担，并不要求外部超强教师。Validator 能看到 reward-side rubric，但 Corrector 只能得到经过限制的纠错方向；Verifier 是防止把答案偷偷带入轨迹的关键安全边界。

Objective / RL Formulation

状态 s 是任务描述、可见历史、工具观察；动作 a 是推理 token、工具选择和参数；策略 πθ 生成交互轨迹 τ；环境与评估规则给二值终局奖励 r(x,τ)。GRPO 的 A_i=(r_i−mean(r))/(std(r)+ε)，并用 PPO 风格 clip 比率与 KL 正则优化。RTI 对修正步骤计算 PPL_roll=exp(−平均 log π_roll(token|原始可见历史))，仅接受 PPL≤δ；作者实验默认 δ=5。再比较校正分布与原策略对各 token 的概率，强调导致策略转向的 token。这里不是标准意义上的无偏 on-policy 梯度；分布门控是工程上控制 off-policy 风险的替代约束。reward 是稀疏的、基于可验证结果/规则，不是人工逐 token 打分；潜在 reward hacking 来自 rubric 泄漏或修正器投机。

Toy Example

假设一个订票 Agent 已找到正确航班，却在第三步把“需要用户确认”误解为“自己可以执行支付”。原始 8 条轨迹全失败，GRPO 只看见 8 个 0。RTI 在第三步将动作改成请求用户确认，并让 Agent 从该历史继续；若最终完成，产生一条成功轨迹。若修正器突然写出一串从未在当前策略出现的神奇 API，PPL 门控会把它拒绝。训练时最应该加权的是“先征求确认”的关键转折，而不是已正确的航班搜索 token。这个例子是解释性构造，不是论文额外报告的实验。

Experiment Setup & Research Questions

作者使用 Qwen3-8B 和 Qwen3.5-9B，覆盖 Navigation、τ²-Telecom、τ²-Retail、τ²-Airline、Claw-Eval-Hard20 五组任务，比较原模型、GRPO、GSPO、AEPO、OPD、LUFFY，以及更强闭源/开源模型作参照。报告 pass@1、平均 pass@k 和 pass^k，后者反映多次重复均成功的可靠性。RQ1：能否越过原策略成功率上限？RQ2：改进是否只来自更强教师？RQ3：Verifier、PPL、token reweight 各自解决哪种失败？RQ4：门控阈值如何影响训练稳定性？论文的主实验训练 token、rollout 总量、GPU 小时没有在本报告核实为可比口径，因此不填写推测数字。

Results & Baseline Comparison

Table 1（Qwen3-8B）：Navigation pass@1，GRPO 35.33%、OPD 37.33%、LUFFY 36.00%、RTI 57.33%；τ²-Telecom 依次为 36.84%、55.26%、49.12%、61.40%；Claw-Eval-Hard20 为 22.50%、26.25%、30.00%、50.00%。Navigation 的 RTI 相比 strongest competing OPD 高 20.00 个百分点；Claw-Eval 相比 strongest competing LUFFY 高 20.00 个百分点。Table 2（Qwen3.5-9B）：Claw-Eval-Hard20 中 GRPO 52.50%、LUFFY 61.25%、RTI 85.00%，提升 23.75 个百分点；τ²-Telecom 则已接近饱和，RTI 96.49%，相较其他方法优势有限。强结果集中在原策略难以探索的任务，弱结果出现在天花板已很高的任务；不能简单宣传“所有 benchmark 提升几十点”。

Figure / Table Reading & Ablation

Figure 1 展示普通 rollout 失败与局部干预成功的因果直觉；Figure 2 展示 Validator–Corrector–Verifier、PPL gating 与 reweight 三段管线。Table 3 的消融尤其重要：Navigation 完整 RTI 57.33%，去掉 Verifier 变成 26.00%，甚至低于 GRPO 的 35.33%；去掉 PPL gating 为 50.00%；去掉 reweight 为 55.33%。Telecom 完整 61.40%，去 Verifier 38.60%，去 PPL 54.39%，去 reweight 60.53%。说明“修正必须可学习且无泄漏”比额外权重更关键。Figure 3 扫描 δ∈{0,3,5,20,∞}，δ=5 的最终表现最好；太小没有干预，太大引入高方差 off-policy 更新。Figure 4 的训练曲线显示干预前后 rollout 成功率的差距，解释了为何早期能获得新的训练信号。

Claim vs Evidence

Authors Claim：通过 rollout-time intervention，Agent RL 能跨过当前策略探索边界。Experiments Actually Show：在两种 Qwen 骨干、五类任务和与 GRPO/教师方法对比中，RTI 对难题显著有效；消融支持 Verifier 与 PPL 是必要机制。What Is Not Yet Proven：是否在完全未知的 reward rubric、真实不可逆外部工具、不同评估器噪声下仍成立；训练计算与额外多角色推理开销是否优于用同预算增加 rollout；以及长期 memory/skill 的跨任务保留效果。

Contribution / Limitation / Research Value

Contribution 1 [New Mechanism]：只在全失败组触发的局部轨迹纠错，改善探索覆盖；2 [New Objective/Training]：PPL gating 与关键 token 加权约束 off-policy 学习；3 [New Empirical Finding]：校验器缺失时，修正数据反而会伤害策略。作者限制可从需要 reward-side evidence 与可验证任务推断：没有可靠成功判据时干预目标可能失真。额外限制是三角色多轮推理成本、校验器漏检和对抗性工具输出污染。Baseline Potential：可作为 GRPO 与 Agent RL 的插件；System Value：可将失败定位与修正审计结构化；Benchmark Value：可设计不可逆工具动作与延迟奖励场景；Attack/Evaluation Value：专测 rubric 泄漏；New Paper Potential：研究修正步骤的反事实贡献归因。

Migration & Minimum Experiment

Original Problem：失败组无梯度 → Transferable Mechanism：关键步骤局部反事实修正 + off-policy 过滤 → New RQ：在 Multi-Agent handoff 中，哪个上游消息导致团队失败，修正该消息能否提高后续团队成功率？→ Modification：对单条 handoff 做 minimal edit，不修改其余 agent 轨迹 → Minimum Experiment：固定 100 个失败任务，对 handoff 进行随机替换、最小修正、全重写三组比较 → Model：Qwen3-8B 级开源 agent → Dataset：τ²-Bench 的可分解工具任务或公开 coding-agent trajectories → Baseline：GRPO、随机修正、teacher full rewrite → Metric：终局 success、修正成功率、PPL、额外 token/GPU 成本、跨任务泛化 → Expected Contribution：基于反事实纠错的 multi-agent credit assignment → Risk：reward 泄漏、handoff 非因果、纠正器成为隐藏教师。训练效率必须同时计入三角色干预调用。

五句话总结

第一，难任务的瓶颈可能是成功样本太少而非完全不会做。第二，RTI 把失败轨迹中局部可修复步骤转成学习信号。第三，Verifier 与 PPL gating 是防止干预污染训练的关键。第四，最强证据来自 Claw-Eval 与 Navigation 的大幅提升及严格消融。第五，下一步最值得研究的是跨 Agent 的局部错误归因和单位训练算力收益。

人话版：这篇论文到底干了什么？

面对上亿 token 的文件库，Agent 真正困难的不是能否再检索一次，而是检索到的证据是否仍然有效、结论有没有被新证据及时修正。LongHarness 把 EvidenceBank 和 Conclusion State 变成显式、持久的运行状态，让“当前结论缺什么”决定下一步搜什么，并让新证据反过来更新结论。OfficeQA Pro V1 上 GLM-5.3-Flash 的 exact match 从直接推理 15.8% 提到 60.2%，V2 从 4.4% 提到 61.1%。对 Agent Memory、长期任务管理和跨会话工作交接，它提出的是可操作的证据生命周期，而不只是“把历史摘要写进记忆”。这类设计尤其适合需要不断纠正中间判断的真实长程工作流。

Background & Research Gap

传统长上下文 Agent 将搜索结果、推理、工具日志放进不断增长的对话历史。上下文长度越大，越容易出现两个相互促进的失败：Unbounded Exploration（继续搜却不知道还缺哪条关键证据），Evidence-State Drift（先前引用已被更正但最终答案还在使用旧结论）。例如一个财政数据问题，需要从不同年份的 Treasury 文档提取分母、分子并计算比例；如果后续发现早先数据年份错了，普通对话笔记不一定知道哪些中间结论必须重算。长窗口或普通 RAG 增加可见文本，并不自动解决结论依赖与证据失效。

Core Insight

作者把 Agent 推理重写成双向循环：结论的未解决部分指导证据搜索；新证据又修正结论。证据不是一次性检索片段，而有 active、superseded、retracted 等生命周期；结论不是最终回答时才生成，而是中间持久状态。关键机制是 Evidence–Conclusion Coevolution + Evidence Lifecycle Management，前者控制搜索方向，后者保证引用可追踪。其设计与 Agent 的 episodic/semantic memory 有交集，但更接近“带来源的工作状态机”。

Method Deep Dive

输入问题与可检索的大规模语料 → 初始化 Conclusion State（已有结论、待验证子命题、未解决信息缺口）和 EvidenceBank（原始来源、摘录、有效性状态）→ Agent 使用 Search 找候选段落 → Read 获取正文并登记来源引用 → upsert 将证据写入 EvidenceBank，revise 可纠正或撤回旧证据 → 观察工具结果后更新受影响的结论与缺口 → Compute 对需要的数值计算并校验引用是否仍 active → 再次 Search 只针对剩余缺口 → Final 提交结论与可解析引用。重要细节：EvidenceBank 被 supersede 后不会自动改写依赖它的结论，模型仍需主动修正；控制器验证引用有效性而不是替代语义事实核查。这一责任划分直接决定了系统的可审计性与剩余风险。

Formalization / State / Toy Example

可将系统视为状态 S_t=(E_t,C_t,H_t,B_t)：E_t 为带来源与状态的证据集合，C_t 为结论及待验证缺口，H_t 为交互历史，B_t 为剩余搜索与阅读预算。每次动作 a_t∈{Search,Read,Upsert,Revise,Compute,Final} 引发状态转移；不是通过额外梯度训练模型，而是 harness 在推理时强制显式管理状态。Toy Example：结论“2025年收入同比增长 8%”引用证据 e1；后来 Read 发现 e1 是合并口径，正确数据为 e2。系统把 e1 标为失效，C_t 必须重新计算增长率，并在 Final 阶段拒绝引用 e1 的输出。这个演示是解释性例子，不代表论文的具体样本。

Experiment Setup & Research Questions

评估 OfficeQA Pro V1（697 份 Treasury 文档、约 100M tokens）、V2（1,435 份文档且组合统计问题更难）、AA-LCR（100 个问题）及 LongBench v2 Long subset。骨干模型为 GLM-5.3-Flash 与 Qwen3.8-Flash；比较 direct reasoning、Claude Code、Codex、RLM。OfficeQA 直接推理用 BM25 把候选片段放进 256K 上下文；所有 harness 获得同样的问题和语料，不能读 gold 文档标注。LongHarness 预算为 200 步、累计阅读 1,000,000 tokens、最多 60 次 Search；Codex/Claude Code 最多 200 turns 与 200 tool calls。RQ1：持久状态是否优于不断增长的历史？RQ2：结论驱动搜索是否能提升正确率？RQ3：EvidenceBank 的生命周期约束有多重要？RQ4：换骨干是否成立？主表每设置只有一次 run，作者在附录另报三次运行以检查波动。

Results & Baseline Comparison

Claim vs Evidence

Authors Claim：显式的证据—结论共演使百兆 token 语料推理更可靠。Experiments Actually Show：OfficeQA 与其他长上下文任务显著改善；去状态、去共演的消融导致明显退化。What Is Not Yet Proven：状态增长到几千个长期任务后能否保持稳定，跨会话迁移与多人协作的并发一致性，证据真实度的自动验证，真实企业文档权限/更新，以及成本—正确率帕累托边界。这里“100M tokens”指可访问语料规模，不是模型一次装入 100M token 上下文。

Contribution / Limitation / Research Value

Contribution 1 [New System]：把证据与结论提升为运行时一等状态；2 [New Mechanism]：由结论缺口驱动检索、由新证据修正结论的双向循环；3 [New Empirical Finding]：naive evidence accumulation 与 generic notes 在复杂组合问题上明显弱于结构化状态。限制：仍由 Agent 负责判断证据是否真正支持结论，控制器主要检查引用结构；一次运行主表对随机性敏感；检索预算、提示词设计与工程复杂度可能影响比较。Research Value：可作 Agent Memory、长程任务、工作日志追踪 baseline；对多 Agent 的 shared state、handoff provenance、冲突消解和 stale-memory evaluation 有直接系统价值。

Migration & Minimum Experiment

五句话总结

第一，长上下文不等于正确管理长期证据。第二，LongHarness 的核心是 EvidenceBank 与 Conclusion State 的双向更新。第三，主表和消融都支持“显式状态优于自由笔记”。第四，当前证据还不能证明跨月、多 Agent 的稳定性。第五，最值得迁移的是有来源、有失效语义的工作状态机。

Failure Propagation & Engineering Detail

一个实际的失败传播链是：Search 返回候选来源 → Agent 把错误年份的数值写入 EvidenceBank → Conclusion State 引用该条证据形成中间比率 → 后续 Read 更正年份，但旧结论未更新 → Compute 继续使用过期数值 → Final 引用无效证据。LongHarness 的控制器能发现“引用已失效”，却不能自动保证“新证据在语义上正确”。因此评估时至少应区分 source-invalid、source-valid-but-wrong 和 missing-evidence 三类失败。长期系统还需要研究并发写入与冲突合并；这些是本报告的扩展研究问题，而非论文已解决的功能。

人话版：这篇论文到底干了什么？

传统扩散视频压缩有两个极端：双向注意力能看完整片段、画质好，却不适合实时流式播放；自回归解码能边到边播，却因为只能利用过去信息而牺牲质量。UniGVC 让两种解码器共享同一比特流与层次潜变量条件，离线高质量回放用 BI-DiT，实时播放用窗口化 AR-DiT，并将 AR 分支蒸馏为单步、替换沉重的 3D VAE decoder。论文报告 1080p 的 AR 解码 36.85 FPS，相比同系统 BI 模式快 250 倍以上，最低演示 0.0005 bpp。最值得学的是“共享表示 + 双工作模式 + 分阶段去除真正瓶颈”，但这不是 Video VLM 推理直接加速的实验证据。

Background & Research Gap

视频压缩与生成结合后，解码器需要从很少的比特恢复高保真帧。BI diffusion 用全序列双向上下文，适合完整视频文件回放，但未来帧未到达时无法做低延迟解码；AR diffusion 每次只依赖历史，可流式输出，却容易累积误差。两条分支若使用不同码流，实际部署需要维护两套编码资产。例子：同一直播既要实时观看，也要回放时高画质；如果必须重新编码，存储、分发与延迟成本都会增加。UniGVC 将问题改成“同一条件码流能否支撑两种生成路径”。

Core Insight

与纯视频生成不同，视频压缩的扩散模型可以看到由比特流重建的、时间对齐的 codec condition。这个条件携带稳定的几何与颜色信息，可作为 AR 的外部锚点，而不必完全依赖上一帧的生成像素。作者先让 BI/AR 共用分层 latent codec，再利用 BI 分支作条件教师，对 AR 进行 one-step distribution matching。接下来识别出新的瓶颈：当 DiT 已经单步后，原始 3D VAE decoder 的计算反而占主导，于是再换成 tiny causal decoder。这种逐阶段瓶颈迁移是系统论文最重要的工程经验。

Method Deep Dive

输入原始视频 → 视频 VAE latent → recurrent hierarchical entropy codec 对 latent 进行压缩，构造共享码流与每帧条件 c_t → 分支一：BI-DiT 读取完整条件序列，用双向注意力与多步 denoising 输出高质量视频 → 分支二：AR-DiT 用局部窗口因果注意力、KV cache、历史条件进行低延迟生成 → 训练 Stage 1 联合适配共享 codec 与两个 DiT 的 LoRA → Stage 2 合并 LoRA 并以 BI 为教师，使用 DMD 条件 score difference 与 latent GAN 监督把 AR 蒸馏为一步 → Stage 3 使用像素空间 perceptual、GAN、warp loss 细调，并用带上一帧缓存的 2D causal tiny decoder 取代 3D decoder。推理时同一码流按播放需求选择 BI 或 AR。AR 的 one-step 并不意味着整个 codec pipeline 完全只有一次运算。

Objective / Formalization / Toy Example

Stage 2 的 DMD 梯度由“fake-score − real-score”加权并乘以生成器对参数的导数，鼓励学生生成分布靠近 BI 条件教师；附加 latent GAN loss 防止教师自身分布缺陷被完整继承。Stage 3 组合 MSE、LPIPS/DISTS 感知项、pixel GAN 与 RAFT 光流 warping 项；权重 λ 决定像素精度、观感与时间一致性的平衡。Toy Example：10 秒直播视频的编码端只发送一份低比特码流，手机端选 one-step AR 路径以 30+ FPS 播放，服务器回放端等整段到齐再走 BI 路径获取更好纹理；这是系统使用情景，不是论文另做的用户研究。

Experiment Setup & Research Questions

训练语料：MLIC-100K 的 100K 图像、Koala-36M 中采样 1M 个 720p 片段、UltraVideo 的 11K 个 1080p 片段；测试取 HEVC-B、UVG、MCL-JCV 的 1080p 序列前 96 帧。比较 VTM-17.0 (VVC LD/RA)、DCVC-FM、DCVC-RT、GLC-Video、GLVC、GNVC-VD、GVC1D、Free-GVC、S2VC 等。训练分多个阶段，BF16；不属于 training-free。RQ1：同一码流是否可同时服务流式与离线高画质？RQ2：窗口大小如何改变 FPS/BD-rate？RQ3：one-step distillation 和 tiny decoder 各消除了多少延迟？RQ4：极低码率下时间一致性与主观观感是否仍稳定？必须分清 bitrate–quality 曲线与同码率的绝对帧速比较。

Results & Baseline Comparison

论文摘要报告 UniGVC-AR 在 1080p 达到 36.85 FPS，较 UniGVC-BI 快超过 250×；UniGVC-BI 可在低至 0.0005 bpp 的条件下恢复较稳定的视频。Table 1 的 DiT 注意力消融：双向 attention 7.09 FPS，普通 causal 24.45 FPS，causal window=5 为 44.92 FPS，window=3 为 62.18 FPS，window=2 为 66.37 FPS，window=1 为 68.23 FPS。以 causal 为 BD-rate 基准，w=3 在 LPIPS 与 DISTS 的 BD-rate 分别恶化 +4.96%、+5.35%；w=1 则恶化 +40.11%、+42.63%，所以作者选 w=3。注意 Table 1 的 62.18 FPS 是 DiT 子模块测试，而摘要的 36.85 FPS 是端到端解码；绝不能把两者写成同一个速度。BI 画质更强但速度最慢，是明确的 quality–latency trade-off。

加速对象：生成式视频编解码的解码端，不是 Video QA 的视觉 token prefill。节省项：双向全序列注意力改因果窗口、扩散步数减少至 1、3D decoder 改轻量 2D cached decoder；不是简单减少输入帧。理论 FLOPs 与 GPU memory 的统一端到端表在本次可核实段落中未给出，不能由 FPS 倒推 FLOPs。真实端到端：AR 36.85 FPS，BI <约 0.1474 FPS（按论文“>250×”关系推得上界，不视为作者直接报告的精确测量）；子模块 w=3 为 62.18 FPS，显示系统仍有其他瓶颈。训练开销巨大且需特定 codec condition，不是 drop-in 的通用视频 LLM 优化。

Abstract / metadataFull HTMLPDF

Video 方向是可迁移的视觉 token 压缩；并非已验证 Video LLM 加速。

人话版：这篇论文到底干了什么？

视觉 token 减少通常要在丢信息和计算代价之间二选一：Top-k 直接丢 token，匹配式 merge 又可能在长序列上代价很高。LapMerge 把有序 token 序列看作可学习质量分布，划分成恰好 N 个等质量区间，用线性扫描合并为固定预算输出，理论前后向均为 O(M+N)。在冻结 Qwen2.5-VL-7B 的 POPE 评估上，10% 视觉 token 预算时 F1 为 81.31，超过 VisionSelector 的 79.73；30% 预算时为 85.50 vs 85.05。其“固定预算 + 保留局部信息 + 可微”非常适合探索长视频 token 压缩，但论文并未证明在 Video VLM 上获得同样加速。真正的视频端到端收益仍需新的实验检验。

Background & Gap

视觉编码器产生数千乃至更多 patch token，进入语言模型后带来显著 prefill 与注意力成本。Top-k selection 只留高分 token，容易丢掉相邻 patch 的上下文；ToMe 等 pairwise merging 保留更多信息但存在匹配成本；TokenLearner 类方法还可能涉及输入到输出的 M×N 交互。对于视频，时间上连续的帧往往存在大量局部冗余，但“保留恰好多少 token”与“如何不损伤动作线索”需要同时考虑。LapMerge 针对有序序列给出可微且预算精确的算子，重要前提是顺序代表空间或时间局部性。

Core Insight & Method

输入 M 个有序 token 及目标预算 N。网络学习每个 token 的非负 mass；按 mass 的累积积分把序列划为 N 个等质量区间，再用 Laplace kernel 的局部加权读出与 prefix/suffix scans 聚合区间信息。相比直接选择 N 个位置，输出是局部片段的融合；相比自由 token-to-output attention，不构造稠密 M×N 关联矩阵。算子参数不随 N 改变，部署时可以调整预算；mass 同时提供哪些位置被分配更多容量的可解释性。对于冻结 VLM 的 drop-in 测试，论文重用 VisionSelector 的 score，替换最后的 token selection 为 score-routed merging，不重新训练主模型。

迁移到 Agent RL 时，难度不能只用最终成功率：任务可能因为工具不可用而失败，或因步骤太长而偶然失败，并非模型推理能力不足。应增加失败原因分解：知识不足、工具权限、格式错误、长程依赖、环境随机性。还要按每种失败类型统计 group reward variance、KL 漂移、有效 advantage 比例及学习后的回访成功率。否则 curriculum 可能把不可学习的工具故障当成“最难样本”，错误地将预算推向 B5 式无效区间。

Additional Research Audit

Background & Method

单看最终文件 diff 容易忽略中间工具操作与隐藏的失败恢复；普通 LLM judge 也可能因轨迹太长而误判。SWE-Critix 将任务描述与执行轨迹输入训练后的 verifier，让它预测是否成功并给出理由。训练采用 SFT+RL 的后训练管线；分类准确率的提升与理由的忠实度是不同问题，需要单独验证后者。

Experiment / Contribution / Limitation

人话版：这篇论文到底干了什么？

可探索视频世界模型在镜头回到旧场景时，必须找回之前看到的内容。传统 feature warping 会把错误深度与姿态转成重影；GLIMPSE 不直接搬运特征值，而是移动历史 patch 的“地址”，并按几何置信度降低不可靠位置频率，结合局部 patch memory 与全局 recurrent memory。论文报告相机平均旋转误差 0.77°，优于 UCM 的 0.88°；但平移 NRMSE 为 0.102，差于 UCM 的 0.059，FVD 863.838 也不及 ReWorld 的 854.19。它是长视频记忆的结构设计，而非已证实的推理加速论文。它适合探索长程记忆的可信读取而非直接加速结论。

Background & Method

固定记忆预算下，模型既需要局部细节，又需要长程全局场景一致性。GLIMPSE 用 footprint-guided retrieval 挑选历史 patch，再以多精度 spectral coordinates 表示投影位置，投影不确定时抑制高频坐标信息，减少错误几何带来的错位。与简单帧缓存相比，它把“位置可信度”显式用于记忆读取。

Experiment / Contribution / Limitation

评估 81、241、721 帧的可探索镜头轨迹及相机控制/视频质量。Table 1 中平均旋转误差 0.77°、CLIP-T 30.445、FVD 863.838，结果并非所有指标最佳；不能因 6/9 个 WorldScore 维度领先就声称全面超越。没有在本次可核实信息中发现端到端 FPS、GPU memory 或 FLOPs 的可比加速表，因此 Video Acceleration 证据不足。可迁移的最小实验是将置信度条件下的历史 patch 读取用于 streaming video QA，与最近帧缓存和 keyframe retrieval 比较准确率、缓存预算与 latency。

Memory Trust and Long-Horizon Evaluation

GLIMPSE 的 spectral attenuation 可理解为：投影位置不可靠时，不让高频精细位置编码过度主导读取。这个思路可迁移到视频 Agent 的缓存置信度，但 world-model 的几何重建与 QA 的事实判断不是同一任务。要做跨任务实验，需固定缓存大小，记录 10、100、1000 帧之后的错误累计，并把错误分成错位、遗漏和生成幻觉。只有在相同延迟预算下提升事件问答或稳定性，才有理由称其为 Video AI 效率研究。

Additional Research Audit

其另一个研究启发是把记忆的“位置误差”转化为“读取置信度”。对于 Streaming Agent，可以给每条缓存事件附上时间、来源帧和可信区间；遇到冲突时请求重看原始片段，而不是直接用低置信度缓存回答。这是机制迁移建议，论文并未报告视频问答性能或相关系统实现。

Tier B Other DP-MIND: Differentially private memory-guided Long context Inference

Authors: Zhihao Liu, Yitian Cheng, Shuang Liu 等 · Affiliation: 见论文正文

Abstract / metadataFull HTMLPDF

仅根据 Abstract / 可获取信息总结；没有虚构 DP ε 或准确率。

人话版：这篇论文到底干了什么？

当用户把百万 token 的敏感文档交给云端 LLM，直接上传可能泄漏隐私，逐 token 差分隐私扰动又会严重伤害长上下文推理。DP-MIND 在本地对输入分块扰动，用紧凑 memory 跨块传递任务相关信息，并用 RL 在受扰输入上学习 memory construction policy，最后以本地去噪模块修复被扰乱的答案片段。它把 memory selection、privacy budget 与 long-context utility 连接起来，但本次可核实摘要没有足够实验数值，不能声称其在某个隐私预算下已实现无损。必须核实隐私预算和长期组合损失。

Background & Method

传统 DP inference 在短上下文相对容易控制，但百万 token 下噪声会在长链推理中累积，远程模型还可能因上下文窗口不足而失效。DP-MIND 的路径是本地分块→DP perturbation→紧凑跨块记忆→云端推理→本地答案去噪。RL 的 state 可理解为当前扰动块与 memory，action 为记忆更新，reward 结合最终答案正确性与 memory consistency；但需要正文核实具体策略目标与隐私会计。

Experiment / Contribution / Limitation

新意是让 memory policy 在带 DP 噪声的数据分布上优化，而不是先在干净文本训练再加噪声。最重要的验证应同时报告 ε/δ、答案准确率、远程 token 数、端到端时延及本地计算成本。局限是本地 denoising 模块可能需要访问敏感原文，系统威胁模型必须清晰；memory 若可逆或保留敏感细节，隐私收益不能仅由最终噪声大小推断。可迁移到隐私敏感 Agent memory 的按预算写入与查询。

Threat Model and DP Accounting

差分隐私不是“加了随机噪声就安全”。必须明确相邻数据集定义、隐私预算 ε/δ、分块组合的隐私损失、是否把本地记忆传给云端，以及本地去噪模块能访问哪些敏感原文。如果 memory policy 的训练使用原始私密语料，其训练过程本身也需要单独威胁模型。对 Agent 系统而言，跨轮共享 memory 可能累积泄漏，即使单次请求满足某种 DP 保证，也不能自动推出无限次查询同样安全。

Additional Research Audit

在实验上，还需要把性能下降拆分为三部分：DP 噪声导致的信息丢失、分块压缩导致的长期依赖损失、外部 LLM 推理错误。只有分别与无噪声分块、加噪声无记忆、完整上下文上界比较，才能说明 RL memory policy 真正解决了哪一种瓶颈。单纯报告最终准确率无法隔离隐私与记忆的贡献。
