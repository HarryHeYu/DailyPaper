一句话定位

它解决的是：Agent 的 trajectory 长到塞不进 context 时，如何让“压缩过去”本身成为 RL policy 的一部分，并把最终任务奖励正确传回压缩前的行为和 summary。

人话版

普通 Agent 一直把 tool call、环境返回、计划和错误堆进 prompt，长任务迟早爆 context。最直接的办法是让模型中途写摘要、开一个新窗口继续，但如果摘要只在 inference 时临时做，训练时模型并没有学过“什么信息必须留下”。CompactionRL 把 summary token 也当作 policy 输出，用最终任务成败一起训练；同时解决 segmented trajectory 带来的两个优化偏差：不同 segment 长度造成 loss 权重不公平，以及 reward 跨 summary 边界传播时的 credit 距离失真。结果在两个 coding-agent benchmark、两个 GLM backbone 上都稳定优于 inference-only compaction，并且摘要更少、tool call 更少，说明收益不只是“跑得更久”。

Background & Research Gap

长程 Agent 的核心矛盾不是单纯 context window 不够大，而是 trajectory 中信息价值极不均匀。一次 SWE-bench 修复可能经历：读 issue → grep → 打开 5 个文件 → 改错位置 → 测试失败 → 找到真正 root cause → 修复 → regression test。若把所有 terminal output 永久保留，token 成本不断累积；若简单摘要，最危险的是把“失败证据”压掉。例如摘要只写“修改 parser 并运行测试”，却漏掉“test_x 在 Windows 路径分隔符上失败”，下一段 policy 就失去了真正关键的 state。

ReSum / SUPO 等已经把 summarization 引入长程 rollout，但本文 gap 更具体：summary 是影响未来 action 的中间决策，因此它需要 end-to-end credit；同时 segment 化不能破坏 PPO/GAE 的统计意义。 这使问题从 prompt engineering 变成 sequential decision learning。

Core Insight

核心观察有两层。第一，摘要质量不能靠“像不像好摘要”判断，而应看它是否提高后续 task return，因此 summary 应与 execution 共用最终 reward。第二，compaction 会把一条 trajectory 切成长度不同的 segments；若每段独立平均 loss 或独立算 GAE，就会人为改变 token 的权重和 reward 的时间距离。本文属于优化机制 + 工程发现：不是证明 summary 的充分统计性，而是让训练目标更接近原始未切断 trajectory 的 credit geometry。

Method Deep Dive

Input task → Agent execution/tool observations → Context 剩余量触阈值 → Policy 生成 summary → summary + 最近两轮 verbatim tail 重启窗口 → 继续 execution → 最终环境 reward → token-normalized PPO + cross-segment GAE → updated policy

Step 1 — rollout：assistant action 与对应 observation 被视为不可拆 step，避免 compaction 把 tool call 与返回结果切开。Step 2 — trigger：剩余 context 少于 10,240 tokens 时触发压缩；不同 backbone 总预算为 64k/80k，最多三次 compaction。Step 3 — summary action：policy 被要求保留目标、已完成工作、关键 observation、未解决错误、当前状态与 next steps；不是外部 summarizer。Step 4 — continuation：新窗口由 summary 加最近两轮原文构成，后者是防止摘要刚刚丢掉局部精确信息的 safety tail。Step 5 — optimization：execution token 和 summary token 都进入 PPO loss。Step 6 — cross-segment credit：用后续 segment 的 token 距离修正 local GAE，让早期动作离 terminal reward 的“真实距离”不会因为切段而被重置。

核心公式与数学直觉

C_(t+1) = S_t ⊕ H_t^(k)

S_t 是压缩摘要，H 是保留的最近 k 轮原文。关键不是拼接本身，而是 S_t 由同一个 trainable policy 产生，因此 summary 的错误可以通过最终 reward 被惩罚。

L_policy = (1 / N_tokens) Σ_i ℓ_i^PPO

分母是所有优化 token，而不是 segment 数。若按 segment 平均，一个 500-token 段和 5000-token 段可能得到相同总权重，训练目标会因“切了几段”而变化。token normalization 让基本统计单位回到生成 token。

Â_(s,i) = (γλ)^(N_>s) · A_(s,i)^loc ,   N_>s = Σ_(j>s) n_j

local GAE 只知道本段内部距离；乘上后续 optimized-token 数对应的折扣，把 terminal reward 对早段 token 的影响继续衰减。γλ 越小，远端 summary/动作得到的 credit 越弱；过小会让早期关键信息无法学到，过大则增加高方差 credit。与 SUPO/GRPO 相比，本文最关键差异是 critic-driven token-level credit，而不是 group-relative reward。

Toy Example

假设 coding agent 要修一个跨平台 bug。Segment 1 发现 Linux 测试通过、Windows 的 Path.resolve() 行为异常，并定位到 loader.py。上下文快满时，policy 生成 summary：“目标：Windows path bug；已排除 parser；loader.py:88 对绝对路径做了错误 join；下一步改 normalize 并跑 test_windows_path。”新窗口保留这段 summary + 最近两轮测试输出。Segment 2 修改代码并测试成功，最终 reward=1。若 summary 漏掉 Windows 条件，后续可能重新调查几十轮并失败；由于 summary token 参与 PPO 且跨段 advantage 传播，模型能逐渐学到“错误条件 + 文件位置 + 未完成 next step”比冗余 shell 输出更值得保存。

Research Question 1：训练 compaction 是否优于只在 inference 加 compaction？

RQ3：收益来自更有效的信息压缩，还是只是更长 trajectory？

Metrics 教学式解释

Pass@1：一次 rollout 成功概率，高更好；适合 agent task，但看不到多次尝试的 coverage。Compaction count / tool calls：不是能力指标，而是行为效率 proxy；少不一定好，但在成功率同时提高时说明 trajectory 更紧凑。Summary judge score：1–5 的 LLM judge 主观质量，越高越好，但可能与真正 causal usefulness 不一致，因此只能辅助 Pass@1。

Results Deep Dive

  1. GLM-4.7-Flash SWE-bench：50.5→56.0，+5.5pp；支持 end-to-end compaction 有效。
  2. 同模型 Terminal-Bench：13.5→20.2，+6.7pp，是相对增幅很大的结果。
  3. GLM-4.5-Air SWE-bench：59.8→66.4，+6.6pp；说明不是小模型特例。
  4. 同模型 Terminal-Bench：21.3→26.2，+4.9pp；方向一致但绝对能力仍低，暴露 benchmark 难度。
  5. 普通 PPO + inference compaction 在 4.7-Flash 上仅 48.2 / 12.4，甚至低于 base 50.5 / 13.5：strong evidence 表明“会做任务”不等于“会在压缩后继续做”。
  6. 去 token normalization：Air 降到 60.0 / 21.3；SWE-bench -6.4pp，说明 weighting 不是小细节。
  7. 去 cross-segment GAE：63.0 / 22.5；分别 -3.4/-3.7pp，credit geometry 确实重要。
  8. mask summary loss：compaction 0.58 vs 0.36、tool calls 90.8 vs 60.7；且触发 compaction 的 SWE 子集 42.4 vs 47.7。Strongest result：跨两模型四 setting 全胜。Weakest evidence：summary judge 3.52 vs 3.30，差距小且依赖 LLM judge。

Ablation / Mechanistic Analysis

去 token normalization → 最大退化，说明 variable segment length 的 weighting bias 很实；去 cross-segment GAE → 中等退化，说明跨段 credit 重要；mask summary loss → summary 次数和 tool calls 上升且成功率降，最接近“summary causal usefulness”的证据。但这些仍不是严格因果分解：组件同时改变训练 dynamics，且 summary judge 不是环境 oracle。

Claim vs Evidence

Authors Claim：可通过 RL 联合学习 execution 与 compaction，并改善长程 agent。
Actually Show：在两 GLM、两个 coding benchmark、指定 compaction policy 下稳定提升。
Not Proven：对 web/embodied/research agents 泛化；summary 是否形成近似 sufficient state；超过三次 compaction 后是否累积信息损失；单窗口 inference 的普遍收益。

Contribution

1. New Objective/Mechanism：summary 与 action 共享 task reward；是真机制创新。 2. New Optimization：token normalization + cross-segment GAE；组件本身源自 PPO/GAE，但组合针对 segmented agent trajectory。 3. New Empirical Finding：普通 RL 不自动获得 compaction robustness。 4. System/Engineering：可用于 GLM-5.2 RL pipeline，工程价值高。

Limitation & Failure Modes

Authors：coding-only、SWE 子集、cross-segment GAE 是近似、summary quality 用 LLM judge、收益不稳定迁移到 single-window inference。
Additional：三次以上反复压缩可能产生“telephone-game”漂移；summary poisoning 一旦写入会跨窗口持续；固定 trigger 10,240 不是 learned budget；64 H800 的训练门槛高；没有把 token/latency saving 与成功率做完整 Pareto；没有 adversarially 测试摘要遗漏、错误记忆和 recovery。

Reproduction View

最小复现先不要上 106B：选 7B/30B coding model + 可验证 terminal task，实现四模块：context-budget trigger、summary prompt、segment recorder、token-indexed GAE。第一组实验只跑 Base+Compaction / PPO+Compaction / CompactionRL / Mask-Summary 四组；记录 Pass@1、触发压缩子集准确率、tool calls、summary tokens。最敏感参数预计是 trigger threshold、保留 tail 长度、γλ 和最大 compaction 次数。最能验证 claim 的不是总 Pass@1，而是只在发生 compaction 的 trajectory 上的 success delta。

Research Value

Baseline：长程 Agent memory/compaction 很强 baseline。Migration：可直接迁移到多 Agent shared memory、video-agent episodic state。Systems：可把 compaction trigger 与 KV/token budget 联合优化。Attack：摘要是新的 persistent attack surface。Evaluation：可定义 compaction survival / state-retention 指标。Benchmark：构造必须跨 2–5 次 compaction 才能完成的任务。New Paper：最有价值的是“可验证状态保真 + learned compaction budget”。

Attack / Verification Lens

可形成 Compaction Poisoning Attack：在早段植入一个“看似次要但后续关键”的错误事实，测试它是否被 summary 固化；black-box probe 可只观察多次压缩前后行为一致性；新 metric 可定义 Compaction Retention Curve：关键状态在第 1/2/3 次压缩后的可恢复率。Recovery test 则在 summary 丢失后重新提供原 observation，测 agent 是否能 reacquire 正确状态。

一句话定位

它把“RL post-training 是否真的扩展能力”改写成一个可测问题：模型单次更稳之后，是否反而失去了通过更多 test-time samples 找到不同成功路径的能力？

人话版

很多 RL 后训练模型 pass@1 更高，于是我们直觉上说“能力变强了”。这篇论文提醒：可能只是概率分布变尖了。一个 base model 第一次常失败，但采样 128 次能探索出很多不同策略；post-trained model 第一次更靠谱，却反复走同一种路线，导致 pass@K 很快饱和。作者在 14 对 base/post-trained checkpoint、3 个 agent benchmark 上观察到这种现象，并提出 Sharpening Tax 衡量“后训练损失了多少 test-time scaling value”。进一步用 PTGS：根据每个 prompt 的估计难度自适应 temperature，困难题加热探索、简单题降温稳定，在 RL 中同时提高 pass@1 和 pass@128，并降低 tax。

Background & Research Gap

传统评估默认一次成功率代表能力，但 Agent 有天然的 test-time compute 维度：同一任务可以 retry、换 sampling seed、改变 temperature。若 base policy 对某任务成功概率是 0.1，128 次几乎一定能找到成功轨迹；若 post-training 把一部分任务推成 0.8、另一部分推成近 0，则平均 pass@1 可能上升，但“可探索到的任务集合”反而缩小。旧的 entropy 或 pass@1 指标都不能直接表达这种 coverage loss。

Core Insight

经验观察是 post-training 把 per-task success probability 向 0/1 两端推：always-solved 增多，同时 never-solved 也增多，sometimes-solved 大幅减少。这解释了为什么 reliability 上升而 retry scalability 下降。它不是“RL 一定不创造新能力”的理论定理，而是跨模型/benchmark 的强经验规律。

Method Deep Dive

Base/Post-trained pair → 每任务重复 rollout k=1…K → pass@k curve → per-task success histogram → calibrated scalability S(K) → Sharpening Tax = S_base−S_post → 用少量 rollout 估计 prompt difficulty → PTGS 自适应 temperature → PPO training

首先统一给 base 一个轻量 agent harness，让它能真正参与 tool interaction；然后对同一任务做大量 rollouts，观察曲线而不是一个点。接着把任务按 128 次观测分为 never/sometimes/always，定位 coverage 变化。Sharpening Tax 对 pass@K 相对 pass@1 的“额外收益面积”做归一化。PTGS 则维护 prompt 的 success/failure posterior：难题提高温度扩大探索，简单题降低温度减少无谓随机性。

核心公式与数学直觉

pass@k = P(至少 1 个成功 | k 次 rollout)

它同时受单次成功率和样本多样性影响；因此不能只用独立同分布的 1−(1−p)^k 心智模型解释真实 Agent，因为轨迹模式可能高度相关。

A(K): 对 k<K 的 [pass@K − pass@k] 累积； S(K): 再按 retry 数与 (1−pass@1) headroom 校准； Tax(K)=S_base(K)−S_post(K)

正 Tax 表示 base 从增加 test-time budget 得到更多相对收益。注意 Tax 不是“能力差值”：一个 post model 若很早就把所有能解的题解完，也会使后续曲线变平。因此必须与 pass@1/pass@K 联读。

Toy Example

有 10 个 web-agent tasks。Base 第一次只解 3 个，但剩下 7 个中有 5 个偶尔能通过不同搜索路径解决；Post model 第一次解 5 个，可它对另外 5 个几乎总走同一失败路径。于是 pass@1 是 30% vs 50%，看起来 post 大胜；到 64 次时 base 可能覆盖 80%，post 仍只有 60%。Sharpening Tax 就是在量化“后训练把一次命中率换成了多少探索空间”。PTGS 对那些连续失败但 posterior 仍不确定的 prompt 提高 temperature，尝试避免训练把它们压成 never-solved。

Strongest baseline：fixed-temperature PPO T=1.5，因为它与 PTGS 共享 RL 算法且温度上限一致，最能隔离 adaptive sampling 的价值。

Experiment Setup Deep Dive

14 个 base/post-trained pairs，来自 4 个 model families；3 个 agentic benchmarks：BFCL v4 multi-turn、WebShop、ACEBench，共 42 model-benchmark cases。WebShop 有 500 tasks，每 task 最多 128 rollouts。PTGS 关键实验使用 Qwen2.5-7B-Instruct + Sokoban，报告 5-run mean。RQ1：post-training 是否普遍降低 retry scalability？ RQ2：少量 rollouts 能否预测 tax？ RQ3：adaptive exploration 能否同时提高 first-shot 与 coverage？

Metrics 教学式解释

pass@1：可靠性；高好。pass@K：K 次预算下至少一次成功；高好，反映 reachable solution coverage。Sharpening Tax：base 相对 post 的 normalized retry value；越大表示 post-training 越损失 test-time scaling，但不是单独的“坏分”。Spearman ρ：排序相关；ρ=0.85 表示少 rollout 估计对 tax 排序很有预测性，但不代表绝对误差小。

Results Deep Dive

  1. Gemma-4-31B WebShop base：22.7 pass@1 → 87.6 pass@128；+64.9pp。
  2. 对应 post：39.5 → 56.0；只 +16.5pp；首轮更强但预算扩展弱得多。
  3. 128 rollout 后 sometimes-solved 87.6%→30.0%，下降 57.6pp。
  4. never-solved 12.4%→44.0%，+31.6pp，是最值得警惕的 failure。
  5. always-solved 0→26%，说明 sharpening 也带来真实 reliability 收益，而不是纯退化。
  6. 42 cases 中 36 个 Sharpening Tax 为正，现象具有广度。
  7. 8 rollouts 估计 tax 可预测 32-rollout tax，ρ=0.85，说明指标可能不必昂贵地跑到 128 才有用。

Ablation / Mechanistic Analysis

Claim vs Evidence

Contribution

1. New Metric/Protocol：Sharpening Tax，是真正值得复用的贡献。2. New Empirical Finding：agentic post-training 的 reliability–coverage trade-off。3. New Mechanism：PTGS prompt-wise adaptive temperature，思想简单但直接对应发现。4. Evaluation：倡议把 test-time scaling curve 纳入 post-training 报告。

Limitation & Failure Modes

6. Paper 3 — Rethinking at Fixed Points

基本信息

一句话定位

它把 looped LM 的“反复算同一 block”解释成趋向 fixed point 的迭代过程，并利用端点近似路径，统一降低 KV cache、prefill、training BPTT 和 RL replay 成本。

人话版

Looped LM 用同一组 block 重复计算 R 次，以更少参数换更多 test-time compute，但传统实现每一轮都要保存 KV、激活和反传路径，省参数却不一定省内存/延迟。本文抓住一个关键性质：很多 token 的 recurrent state 会逐渐稳定，接近 fixed point。一旦“后几轮已经几乎不变”，就没有必要永久保存每轮历史。作者据此做 terminal KV sharing、truncated BPTT、student prefill 和 RL fixed-point reuse，并进一步通过 learned depth prior + orthogonal input injection 主动把模型训练成更容易收敛的形态。1.6B 下共享 KV 可缩 3×；student prefill 最高 1.79×；RL scoring/backward 约 2×。

Background & Research Gap

普通 Transformer 加深通常同时增加参数和 KV cache；looped model 重复同一 block，可把参数量与计算量解耦，但如果每轮都保存独立 KV，decode memory 仍随 recurrence depth 增长。Huginn 已观察 terminal KV sharing 可行，但“为什么可行、什么训练会让它可行、能否进一步把 fixed point 用到训练和 RL”没有统一答案。本文 gap 是把 fixed-point convergence 从现象提升为系统设计原则。

Core Insight

若迭代 h_(r+1)=F(h_r,x) 是 contraction 并收敛到 h*，则越靠近 h*，“怎么走到这里”越不重要；prefix token 的 terminal KV 可代表中间 KV，梯度也可从 endpoint 用 implicit/Neumann 形式近似。经验上 95% tokens 到 loop 8 已稳定；理论上在 contraction 条件下 terminal sharing 与 full path 的差异受离收敛点距离控制。它兼具理论动机 + empirical systems finding。

Method Deep Dive

Input → shared recurrent block repeated R times → depth sampling 训练多深度 → learned depth prior 调整监督分布 → OrthoInj 稳定输入条件 → states 接近 fixed point → terminal KV sharing / student endpoint prefill / truncated BPTT / RL endpoint reuse → lower memory & latency

Depth sampling：短 depth 样本保留完整路径监督，深样本促使状态在不同深度都可用并形成稳定点。Learned prior：预测反馈把 probability mass 推向预测好的 depth，entropy 防止坍缩，budget term 固定平均 depth≈5。OrthoInj：每轮注入 input 时，先去掉 state 沿 input 方向的分量，避免已有 state 随机增强/抵消 input。Terminal KV：每个过去 token 只保留最后 loop 的 KV，当前 token 每轮都读 terminal bank。Student prefill：学生直接预测 teacher endpoint，再由 teacher 一轮生成 decoding 所需 KV。RL reuse：rollout 已无梯度地产生 endpoint state，更新时不重放全部 loops，而从保存 endpoint 做一次 block + Neumann backward。

核心公式与数学直觉

h_(r+1)=F_θ(h_r,x),   fixed point: h*=F_θ(h*,x)

如果 Jacobian 对 state 的谱半径小于 1，局部扰动会逐轮缩小，这就是“端点可以替代路径”的数学根。

dh*/dθ ≈ Σ_(k=0)^(K) J_h^k · ∂F/∂θ

这是 implicit fixed-point gradient 的 Neumann-series 直觉：每项影响几何衰减，因此不必保存完整 unrolled graph。最关键超参数是 backprop window b / Neumann truncation depth；太小且状态未收敛会 bias，太大则失去加速。

OrthoInj: h' = h − proj_x(h), 然后再注入 x

把 h 在 x 方向的分量移除，使每轮 input conditioning 的幅度不被旧 state 同方向分量放大或抵消。

Toy Example

一个 token 经过同一 4-block 模块循环 5 次，hidden state 变化量依次 0.30、0.12、0.04、0.01、0.003。传统 decode 为 prefix token 保存每轮 KV；terminal sharing 只保留最后一次。新 token 第 1 轮直接读 prefix 的 terminal KV，虽然与训练时“第1轮读第1轮 KV”有 mismatch，但若 prefix 已接近 fixed point，这些 KV 已非常接近。训练时用不同 R 抽样，逼模型适应“prefix 已经更成熟”的状态。RL 时 rollout 已保存最后 state，更新不再从 loop1 重算到 loop5，而从 endpoint 附近求梯度。

Experiment Setup Deep Dive

Metrics 教学式解释

PPL：next-token negative log-likelihood 的指数化，低好。Downstream avg：7 个 accuracy benchmark 平均，高好，但会掩盖单任务差异。KV banks：直接 memory proxy；4 vs 12≈3× reduction。Prefill speedup：真实 wall-clock 比理论 FLOPs 更重要。Pass@1：RL 后 GSM8K/MBPP+ 单次成功率，用来确认加速没有明显伤能力。

Results Deep Dive

  1. 95% tokens 到 loop 8 稳定：fixed-point 假设有直接 empirical support。
  2. R=5 terminal sharing 只留 4/12 KV banks，100M–1.6B PPL 增幅最多 0.85%；memory benefit 明确。
  3. 1.6B learned prior shared-cache downstream avg 60.0，fixed-depth full-cache 59.9：用 3× 小 cache 达到近同等平均分。
  4. fixed-depth 1.6B 的 GSM8K 从 full-cache 50.64 跌到 sharing 21.23，说明 sharing 不是 architecture 免费午餐，训练方式决定成败。
  5. learned-prior + sharing GSM8K 47.92，恢复大部分损失。
  6. student 在 1/4 teacher data 上训练，8K prompt prefill 最高 1.79× faster，同时保留 93% downstream score；这是明显 quality-speed trade-off。
  7. truncated BPTT 在 PLN-5 下 b≥4 后匹配 full backprop，表明 gradient path 可大幅截断。
  8. 1.6B RL scoring+backward 在 GSM8K/MBPP+ 约 2× faster，pass@1 在 run-to-run variation 内。Strongest：3× KV + 近等 downstream。Weakest：student 只保 93% teacher score，且规模止于1.6B。

  6. learned prior 用预测反馈、entropy 与 compute budget 更有效分配监督。
  7. OrthoInj 去掉 state 沿 input 的分量，稳定每轮 conditioning。
  8. student endpoint prefill 可到 1.79×，但只保留 93% teacher score。
  9. RL endpoint reuse 报告约 2× scoring/backward speedup。
  10. 最值得做的新方向是“在线检测是否收敛，再动态决定 shortcut”。

7. Cross-Paper Synthesis

三篇共同趋势非常清晰：AI 系统开始把“中间状态”当作一等研究对象。 CompactionRL 问哪些历史必须压进 summary；Sharpening Tax 问 post-training 如何改变 trajectory distribution；Fixed Points 问哪些 recurrent states 已经稳定到可以丢掉路径。它们都不满足于最终 accuracy。

可组合机制：CompactionRL 的 learned state compression + Sharpening Tax 的 coverage-aware evaluation + Fixed-Point 的 convergence gate，可以形成“Budgeted Long-Horizon Agent”：只有状态稳定时才压缩/复用；若 policy 开始 mode collapse，则提高 exploration；最终同时优化 task success、context/KV cost 和 trajectory coverage。

8. Combined Research Opportunities

Opportunity 1 — State Sufficiency under Compute Budgets

统一研究问题：Agent/VLM/looped LM 的中间状态什么时候已经“足够”支持未来决策？可以定义三类证据：行为 sufficiency（后续 success 不降）、表示 convergence（state/KV 变化小）、探索 sufficiency（pass@K coverage 不坍缩）。这可能形成一个跨 Agent memory 与 inference acceleration 的统一 benchmark。

Opportunity 2 — Adaptive Compression without Sharpening

Compaction 会把历史压成单一 summary，本身可能造成 trajectory mode collapse；因此直接把 Sharpening Tax 用到 compaction 前后，测“压缩是否让 Agent 未来策略变尖”。若是，可生成多个 diverse summaries 或保留 uncertainty slots，而不是单摘要。

9. Collision / Overlap

Strongest Collision：CompactionRL × Sharpening Tax。 CompactionRL 用单一 summary 把长历史映射成紧凑 state，目标是提高任务成功率；Sharpening Tax 则警告 post-training 可能通过集中行为分布提高 pass@1，却牺牲多样路径覆盖。因此 CompactionRL 的 +Pass@1 还不能回答“summary 是否把未来策略空间压窄”。最直接的新实验：对 compaction 前后同一 checkpoint 做 pass@K 与 trajectory-cluster coverage，检查是否存在 Compaction Sharpening Tax。

10. Reading / Reproduction Priority

#1 CompactionRL：最贴近 Agent 长程学习，且复现实验路径清楚；优先复现 trigger-compaction subset 与 summary-mask ablation。
#2 Sharpening Tax：最适合作为你以后所有 Agent/RL 工作的 evaluation augmentation；先做低成本 K=8/32 版本。
#3 Fixed Points：系统/理论潜力最大，但需要 looped architecture；适合作为 inference acceleration 新线的中期项目。
