一句话定位与人话版

定位： 把现代 Agent 中“压缩上下文、创建子 Agent、返回结果”等导致的多会话执行结构，真正纳入强化学习的信用分配单位，而不再假定一次任务只有一条连续上下文。

设想一个搜索 Agent 为回答问题查了几十个网页，临近上下文上限时把历史压缩为摘要，之后继续检索；或者把两个子问题派给不同 Agent，等它们返回再综合。真实执行是一棵带边界的会话树，训练时却常把任务最终答对或答错的同一个 reward 广播给每一段。这样，错误摘要、重复搜索和有用子任务都会被同样鼓励或惩罚。Mosaic 把训练信号拆成两层：先按任务成功与否、使用多少个 session 调整整条轨迹的 advantage；再用“一个 session 前后，模型对正确答案的对数概率提高了多少”估计局部贡献，按 session 类型归一化，修正各段训练信号。在 BrowseComp 上，压缩模式的准确率从 Broadcasting 的 35.31% 到 38.86%，平均会话数从 3.17 降到 2.35。关键价值不是数字本身，而是提出了可以在真实 Agent harness 上验证的 session-level learning 单元。

Background & Research Gap：单条轨迹不等于一个训练片段

传统 ReAct Agent 轮流执行“思考—工具调用—观察—继续”，在一个上下文里积累状态。GRPO 对同一个问题采样 G 条轨迹，按最终奖励的组内相对位置产生 advantage，再用同一标量训练轨迹中的动作 token。这对单会话比较自然：至少每条样本都有同一种上下文连续性。进入长程任务后，compaction 会把旧消息替换成一个短摘要，下一段的条件分布不是旧前缀的自然延续；forking 则产生多个分支，其状态甚至不是线性序列。把多段文本强行拼接成一个样本，会让模型在训练时看到实际执行中不存在的上下文。

具体例子：问题需要先查公司 A 的并购日期、再查交易所公告、最后对照监管文件。第一段检索得到正确日期；第二段 compaction 遗漏“交易已撤销”；第三段据错误摘要给出过期答案。广播负 reward 会同时压制第一段的正确搜索；如果最后恰巧答对，又会奖励错误摘要。Mosaic 要填的 gap 不是“是否能用 RL 训练 Agent”，而是如何给不同 session 分配方向正确、量级有区别的学习信号。它比仅增加 rollout 长度更关注状态交接是否有用。

Core Insight：成功时节制，失败时探索；局部进展单独计分

作者提出三个约束：同样成功的轨迹，session 越少越好；同样失败的轨迹，session 太少可能意味着探索不足，因此更长的失败尝试可得到相对不那么负面的 advantage；但成功必须始终压过失败。这里的 session 数只是“执行复杂度/探索”的代理变量，不是实测 token 成本，也不意味着多会话一定更好。第一层采用同结果子组内的 rank 而非原始数量，使极端长轨迹不能凭长度无限操纵训练信号。

第二个洞察是把一个 session 视作状态转换：它输入上下文，输出新的上下文或主 Agent 可用的证据。真正值得奖励的不是生成了多少文本，而是后续 Agent 对正确答案的可预测性是否提高。正常搜索、压缩摘要、子 Agent 返回在统计分布上不同，若混合标准化，压缩这种“删文本”的操作容易被系统性误判。因此按 session 类型分别归一化。前者是有明确排序性质的数学构造；后者是以模型 log-likelihood 为代理的经验性过程奖励，并未证明因果贡献。

Method Deep Dive：从任务到每段 advantage

任务 x → 同题采样 G 条多会话 rollout → 最终 R∈{0,1} → 组内 GRPO advantage → 按成功/失败分组的 session-count rank 调制 → 每段前后答案似然差 → 类型内归一化与安全门控 → session advantage → token 级 clipped policy update。

步骤 1：收集真实 session 边界。 正常 session 记录模型输出及工具返回；compaction 把原始历史序列化为只读记录，由同一策略生成摘要，再用摘要替换前缀，摘要本身是可训练片段；subagent 使用同步 fork-join，子任务的 search/visit 轨迹单独成为训练片段，主 Agent 负责汇总。训练时只对策略生成的 token 计算 loss，工具观察、角色分隔符均 mask。对 compaction，m 次成功压缩会产生 2m+1 个片段；forking 则是 1 个主 session 加 M 个子 session。

步骤 2：获得全局成功信号。 用同题 8 条 rollout 的最终二元奖励计算标准化 GRPO advantage。这个全局信号必须保留：即使某段带来高信息增益，只要最后失败，也不能把它直接等同于成功。对 mixed-outcome group，把轨迹按结果分成成功/失败两组，各自在组内将 session 数升序映射到 [-1,1] 的中心化 rank u。成功轨迹的正 advantage 在 u 小时放大；失败轨迹的负 advantage 在 u 大时绝对值减小。

步骤 3：处理所有样本同成同败。 传统 GRPO 遇到 8 条全对或全错时，组内 reward 方差为 0，advantage 接近 0。Mosaic 在全成功组用 −β₁u 奖励节制；全失败组用 β₀ min(u,0) 惩罚过早结束，但不把失败样本变成正 advantage。这是明确的 sample-efficiency 设计，而不是增加一个学习的 critic。

步骤 4：测局部信息增益。 对非终止 session，记录输入边界 h⁻ 与输出边界 h⁺；分别在同一个冻结的 rollout policy 上，用 teacher forcing 对 ground-truth 答案 y* 计算平均 token log-prob。两个值相减得 rΔ。注意只算答案 token，固定的 <answer> 包装不计入评分。Compaction 对比完整旧上下文与新摘要上下文；subagent 对比主 Agent fork 前后；终止 session 的局部 shaping 强制置零，避免最终正确答案泄漏进特征。

步骤 5：校准与防止反向奖励。 在同一 prompt group、同一种 session type 内，对 rΔ 做均值方差标准化。λr 控制局部信号占比。Appendix B 有两个 gate：全失败且 base advantage 近零时截断正 shaping；若局部项与全局项相反且幅度足以反转符号，则清零局部项。最后把 session advantage 广播到该段可训练 token，按整条轨迹的 token 总量归一化；这避免会话多的轨迹天然权重更大。

核心公式与数学直觉

Aᵢᴳᴿᴾᴼ = (Rᵢ − μᴳ) / (σᴳ + ε)　；　uᵢ = 2(rank(Nᵢ) − 1)/(|Gᴿ| − 1) − 1

R 是最终正确与否；μ、σ 是同题组统计；N 是 session 数；Gᴿ 是相同结果的子组。若子组只有一个样本或 session 数无差异，u=0。这里的 rank 只在同结果轨迹之间比较，避免用“失败但长”压过“成功但短”。

Aᵢˢᵃᵗ = (1 − ρuᵢ) Aᵢᴳᴿᴾᴼ　（混合成败组；0 ≤ ρ < 1）

ρ 控制 session 数调制幅度，论文设 0.2；乘子始终大于 0，所以成功 advantage 仍为正、失败仍为负。全成功组改为 −β₁u，全失败组改为 β₀min(u,0)，论文 β₁=0.2、β₀=0.1。若把 ρ 增得接近 1，成功样本间的 session 偏好更强，但也更容易把“困难任务需要额外 session”误认为低效率；若设为 0，则退化为无 session 调制的 outcome advantage。

Φ(y* | x,v) = (1/L) Σₗ log π̄(y*ₗ | x,v,y*<ₗ)　；　rΔᵢⱼ = stopgrad[Φ(v⁺) − Φ(v⁻)]

Φ 是答案在指定上下文中的平均 log-likelihood，值通常为负，变得不那么负就是进步。这不是信息论中严格的互信息，也不是反事实删除该 session 后的因果效果。stopgrad 意味着该分数只是构造 reward，不沿评分计算图反向传播。每段需要两次 forward-only 评分，额外计算不可忽略，但比每个工具 turn 都评分更节省。

这里 ratio 是新旧策略对同一生成 token 的概率比；clip 限制一次更新幅度；KL 抑制策略远离参考分布。论文训练配置：lower clip 0.2、upper clip 0.28、KL 系数 0.001、熵系数 0、λr=0.1。上式最后的 KL 是便于教学的概括写法，实际实现还受 token mask、trajectory aggregation 和 KL estimator 影响。与 Broadcasting 的本质区别：不再把同一个 Â 无条件复制给每段。

Toy Example：四条轨迹与两段信息增益

假设同一问题有四条 rollout：成功轨迹 S1 用 2 段、S2 用 5 段；失败 F1 用 1 段、F2 用 4 段。假设组内 outcome advantage 成功为 +1、失败为 −1；ρ=0.2。同结果组各有两条，session rank 对应 u=-1,+1。S1 得 +1.2，S2 得 +0.8；F1 得 −1.2，F2 得 −0.8。于是成功少开 session 更受奖励，失败多尝试也只是少受惩罚，没有让失败转正。

现在看 S1 的第一段搜索：正确答案平均 log-prob 从 −2.0 到 −1.1，rΔ=+0.9；第二段 compaction 从 −1.1 到 −1.4，rΔ=−0.3，意味着摘要后模型对答案更不确定。假设类型内标准化后分别为 +1 和 −1，λr=0.1，则两段的 advantage 为 +1.3、+1.1（如第二段是最终段，则依规则 r=0，保持 +1.2）。广播法则两段都 +1。这些数是教学构造，不是论文实验值。 真正实现要对每种 session 类型独立计算均值方差，并执行两个门控。

Experiment Setup 与 Metrics 教学

模型/数据/协议： Qwen3.5-4B，ReAct Agent 仅用 search（Serper）和 visit（Jina Reader）；REDSearcher_RL_1K 共 1000 道训练题，训练 1 epoch、63 个 rollout iteration，每次 16 prompts × 8 samples；BrowseComp 测试 1266 道困难网页检索题。答案由 deepseek-v4-flash judge 在 temperature=0 下判定，judge 不是人工标注真值。每段 context 上限 131072 tokens、预留 16384 tokens；compaction 最多 10 次；每次 fork 最多 3 个子 Agent、最多 10 次 fork；同步等待子 Agent。训练为 8 GPU、TP=2、CP=4、Adam、lr=1e−6，训练硬件具体型号与 wall-clock 总成本未在所核验表格中给出。数据切分：训练集 REDSearcher 与测试集 BrowseComp 不同来源，未见作者报告多 seed 方差或训练-测试污染审计。

研究问题： RQ1 同执行模式下 Mosaic 是否胜过 Broadcasting？RQ2 两级机制是否各自有效？RQ3 rank 与 type-normalization 是否按设计改变信号分布？RQ4 进步来自“更多 session”还是“更有用的 session”？这些问题层层递进，但 RQ3/RQ4 中一些度量直接用训练定义的 IG 构造，需警惕同义反复。

Accuracy 是最终题目回答被 judge 认为正确的比例，越高越好；依赖 judge 的一致性、答案等价性。Num. Session 是平均 session 数，越低通常越省 orchestration，但不是 token/美元成本，不能直接当“总延迟”。Positive-IG Rate 是 rΔ>0 的 session 比例，越高表示模型评分下的正进展越多；它可能被更短上下文或格式效应抬高。IG/Session 对每段取 max(rΔ,0) 后平均，越高表示每段“正向答案似然增量”更大，但不等于真实信息增益。两者应与 Accuracy、实际工具成本、错误率一起解释。

Ablation、Claim vs Evidence、贡献边界

去掉 session-aware rank：丢失“成功更节制/失败别太早停”的结构化信号，Figure 3 显示性能回落。去掉 session-level IG：所有 session 重新共享粗粒度反馈，无法区分压缩前后、fork 前后是否带来可预测性提升。两者叠加：compact 的联合收益明显；subagent 的联合收益较小，符合 DAG 中单段影响多后续节点的归因难题。论文没有把每个消融的精确数值写成可读表，因此不推断虚假的 pp 变化。

Authors Claim： 多会话 RL 可改善性能与 session allocation。Experiments Actually Show： 在一个模型、一个网页搜索 benchmark、两种执行模式、给定 judge 和训练预算下，Mosaic 相比 Broadcasting 取得更高准确率和更少平均 session。Not Proven： 真实跨任务泛化、session count 与实际美元成本的关系、IG 的因果忠实性、异步训练稳定性、对其他 harness 的鲁棒性，以及多次独立运行的显著性。

Contribution 1 / New Problem Formulation： 把 multi-session rollout 作为独立训练对象，值得认可。Contribution 2 / New Objective Combination： 有界 session rank + outcome-conditioned fallback + type-normalized local shaping，组合层面的创新强于单个数学原语；GRPO、rank、log-likelihood IG 并非从零发明。Contribution 3 / New Empirical Finding： session utility 与 allocation 比单纯 session 数更能解释当前结果，但这一发现依赖作者的 proxy 定义，证据等级中等。

Limitation / Failure Modes 与复现视角

作者在 §5 明确讨论公共多会话训练数据不足、异步 rollout 的 policy staleness、compaction/fork/merge 状态传递以及 black-box harness 的适配。我的额外质疑有四点：其一，session 数与 token 数、检索 API 费用不等价；其二，teacher-forced 正确答案似然可能受上下文长度、答案格式、提示模板影响，而非证据增量；其三，子 Agent fork-join 形成 DAG，简单局部增量不满足加和性；其四，judge 本身可能错判别名答案，且实验未给 bootstrap CI。

基本信息。 Hyunwook Choi、Seungryong Kim、Dongyoon Han、Sangdoo Yun；KAIST AI 与 NAVER AI Lab。2026-10-15 提交 arXiv v1，预印本，未核实会议接收。arXiv 正文 · 摘要/PDF · 项目页 · 官方 GitHub。代码状态必须区分： GitHub 仓库已公开，但 2026-10-17 读取 README 时声明代码仍在内部审核、稍后发布，仓库当前只有 README，不能声称已具备可运行的完整实现。正文 §3–4、Table 1–5、Appendix A–D 是下文证据来源。

一句话定位与人话版

定位： 在四步蒸馏的自回归视频扩散生成中，让不同视频 latent token 在“已经收敛”时提前退出去噪，而不是所有 token 无条件做完四步。

传统视频扩散生成每一块 latent 都跑相同去噪步数。可是一帧里有的背景几乎没变，第一步就与最终结果接近；有的新物体、快速运动区域还需要继续细化。如果对整帧统一缩减步数，复杂区域就会失真；如果统一保留四步，简单区域浪费计算。Speculative Forcing 把每一步输出的 clean latent 当成候选草稿，使用验证器估计它距离四步最终结果还有多远。足够接近的 token 直接固定，后续只更新未收敛 token；已经固定的 token 仍作为 KV 上下文被其他 token 访问。作者提供无需训练的相似度/稳定性验证器，以及只训练轻量 3D 卷积头的学习型验证器。在 LongLive 5 秒视频上，平均去噪深度 1.68 步、41.74 FPS，四步基线为 26.40 FPS，VBench 总分 83.21 对 83.08。它展示了减少 token-step 计算可以变成真实吞吐收益，但这不是包含 VAE 和整条产品链路的端到端 FPS。

Background & Research Gap：统一时间步浪费在哪里

自回归视频扩散模型把视频拆成按时间顺序生成的 chunk，每个 chunk 内是空间×时间 latent token。模型基于已生成的 clean history 和当前噪声状态，重复执行 denoising。蒸馏方法（如 Self Forcing、distribution matching）把几十步压到四步，但四步中的每一步仍对所有 token 做完整计算。视频有很强的时空冗余：静止背景、相似纹理、上一帧已出现的对象，往往早已接近最终 latent；刚进入视野的物体、镜头转向后的遮挡解除区域则更难。

举个例子：固定摄像机拍摄一名行人在广场上走过，天空和建筑占大部分 token，行人和其阴影占少部分。全四步在建筑上可能浪费；统一两步又可能导致行人边缘模糊。前人路线大致有缓存旧特征、稀疏重算注意力、按帧或 chunk 选步数等。它们常在一个区域或一个 chunk 上采用共同退出点，或要求被跳过的 token 最终仍参加后续完整更新。本文 gap 是在同一个 chunk 内按 token 独立判定是否可以“永久提交”，并保持后续活跃 token 的注意力上下文可用。

Core Insight：把中间 clean estimate 当可验证草稿

作者的 Figure 2 观察到 token 到四步输出的距离并不一致：一些背景区域第一、二步已经稳定，而新暴露区域变化大。这是通过完整四步 rollout 计算中间与最终 latent 差异得到的经验观察。进一步的关键是：已接受 token 不是“完全从注意力里删除”，而是冻结其当前层级 KV，让尚未接受的 token 仍能 attend 到它。整个 chunk 完成后，再用 clean pass 重建一致的历史 KV，供下一个 chunk 使用。否则混合不同去噪时间的 KV 会把误差长期传播。

这里的“Speculative”不同于 LLM lossless speculative decoding：LLM 有精确概率接受规则，目标可以保持原分布；本方法用近似收敛预测与容差 ε，不是严格无损采样。它真正可迁移的机制是“可提前提交的局部状态 + 低成本 verifier + 保留上下文依赖 + 统一刷新”。在世界模型里，镜头不断运动，新区域较多，能提前接受的 token 更少，这种数据依赖性是合理且应被重视的失败边界。

Method Deep Dive：逐 token 验证与提交

已有视频 clean history H + 当前 chunk 噪声 → 第 1 次去噪产生所有 token 的 clean drafts → verifier 预测剩余误差 → 空间/时间平滑 → 小于阈值的 token commit 并冻结 KV → 未接受 token 继续去噪 → 重复至第 4 步 → 拼合不同退出步的 chunk → clean pass 刷新 KV → 下一个 chunk。

步骤 1：生成候选。 对 K=4 的蒸馏模型，输入当前 noisy latent 与过去 chunk 的 KV，DiT 每次产生 clean estimate x̂₀^(k)。常规算法把中间估计重新加噪到下一时间步，直到 K=4。Speculative Forcing 在每一步后多一个判断；它不改变 backbone 的训练权重，也不改原始时间步表。被接受 token 的输出定为当前 clean estimate，未接受 token 才进入下一个去噪 forward。

步骤 2：无训练验证器。 第一去噪步只有一个 draft，没有“同一 token 上一步”可比，故把它与已生成历史及参考帧的 clean latent 比较，取最近邻距离 s_red；相似则推测已经收敛。第二步起，对尚活跃 token 比较连续两次 clean draft 的距离 s_stab。两个阈值 τ_red、τ_stab 需在 held-out calibration set 上校准，不能直接照搬到不同模型/分辨率。相似历史并不等于一定正确；两次几乎不变也可能是停滞在错误估计，所以它们只是 proxy。

步骤 3：学习型验证器。 冻结原视频生成器，先跑完整四步，收集每个 token 在每一步的 hidden state 与真实剩余 gap；用最后 Transformer block 的 hidden state 输入 LayerNorm + 3 层 3D Conv 头，预测 gap。作者使用通道 1536→96→48→1，前两层 3×3×3 + GELU，末层 1×1×1；约 4.11M 参数，Adam lr=1e−3、batch=4。训练数据 LongLive 用 1000 个 VidProM prompts，Lingbot 用 1000 个独立初始场景。这个 verifier 不是另一个视频生成器，而是一个廉价的“还需不需要继续算”预测器。

步骤 4：局部一致性与 KV 管理。 验证分数先经过时空平滑，避免相邻 token 的退出决策形成锯齿边界。论文实现的空间核是 9×9 Gaussian，时间方向也进行平滑；学习头输出还做 2×2×2 池化并插值。提交后的 token 保留对应层级 KV 供活跃 token 查询；未提交 token 更新 KV。最后对拼接好的 clean chunk 做一次 timestep=0 的 clean pass 统一刷新历史 KV，防止下一 chunk 读取跨时间步的混杂表示。作者还用共享索引、原地 KV 更新以及 clean pass 与下一个 chunk 首步合并来降低实际开销。

步骤 5：只在真正能节省计算时提交。 如果 verifier 错误接受了正在变化的物体，后续步无法修复该 token；如果过于保守，所有 token 都做到第 4 步，反而白付 verifier 的 overhead。ε 因而是部署的主控制旋钮：增大 ε 更激进，通常 FPS 上升但失真风险增加。作者的主要 operating point 在短视频用 ε=0.28、长视频和 world 用 ε=0.24。

核心公式、优化目标与数学直觉

p(c₁,…,cₜ) = ∏ₜ p(cₜ | c<ₜ)　；　cₜ(i) = x̂₀^(k*(i))(i)

cₜ 是第 t 个生成 chunk；i 是 chunk 内 token；k(i) 是该 token 被接受的去噪步。传统 k(i)=4 对所有 i 成立，本文允许 k*∈{1,2,3,4}。这是结构上的动态计算，而非减少生成帧数。若一个 token 早停，它仍占输出空间，并保留 KV 依赖，不是视觉 token pruning。

relₖ(i) = || x̂₀^(k)(i) − x̂₀^(K)(i) ||₂ / σₜ　；　commit ⇔ relₖ(i) ≤ ε

σₜ 是完整四步 chunk 的 token norm 中位数，防止 latent 整体尺度影响阈值；ε 是允许的相对误差。训练时能计算完整四步结果，因而知道 oracle gap；部署时如果还计算完整四步来决定是否接受，就没有加速意义，所以必须用代理 verifier 预测 gap。

L(φ) = [1/(N(K−1))] Σᵢ Σₖ<K SmoothL1( r̂ₖ(i), relₖ(i) )

φ 是 verifier 头参数；SmoothL1/Huber 在小误差区近似二次，大误差区近似线性，避免少量极端 token 主导训练。模型 backbone 完全冻结，训练成本集中在收集完整四步标签与训练小头。损失直接回归连续 gap，而非把所有 token 硬分类为接受/拒绝，因此一个头可以在不同 ε 下复用。

Denosing token-evals: baseline = K·N； proposed = Σᵢ k*(i) = N·k̄　；　reduction = 1 − k̄/K

5 秒 LongLive 的 k̄=1.68，相比 4 步节省约 58% 去噪 token-evaluations；不是 58% 总 FLOPs，也不是 2.38× 实测加速。因为仍有 clean pass、verifier、稀疏索引、KV 更新、非 DiT 部分。若只计去噪与一次 clean pass，理论 token-evals 由 5N 到 2.68N，降幅约 46.4%；这只是便于理解的简化计数，不等同实际 FLOPs。真实吞吐要看单 H100 测量值。

Toy Example：四步去噪中的六个 token

假设一个 chunk 只有 6 个 token，依次表示天空 A、建筑 B、地面 C、行人 D、阴影 E、新出现车辆 F。第 1 步生成 6 个 clean draft，verifier 判断 A、B 已足够接近四步输出，于是 A、B 在 k=1 提交。第 2 步只算 C、D、E、F；C 的连续 draft 已稳定，k=2。第 3 步只算 D、E、F；D、E 稳定，k=3。第 4 步仅 F 仍活跃，k=4。总去噪 token-evals 为 1+1+2+3+3+4=14，原四步是 24，节省 10/24≈41.7%。

被接受的 A、B 在后续三步中不再计算 Q/MLP，但其缓存的 K/V 仍可被 F 注意；整个 chunk 结束后所有 6 个 token 用统一 clean pass 刷新历史。若把 F 也在第一步提交，车辆形状可能明显错误，并在下一 chunk 被当成历史真值，导致误差传播。此例是手工教学示意，不是论文测量结果；真实模型里退出粒度受 token grid、head 平滑与内核实现约束。

Experiment Setup 与 Metrics 教学式解释

Models： LongLive 1.3B 与 Lingbot-World 2.0 Causal-Fast 1.3B，均 K=4。数据： LongLive 的 5 秒 VBench（每 prompt 5 seeds）和 30 秒 VBench-Long；Lingbot 用 200 个独立导航场景，每个 253 帧、5 段随机相机动作，初始图像由 Z-Image-Turbo 构造、文本场景由 Qwen2.5-7B-Instruct 构造。训练： 仅学习 verifier 时分别用 1000 个 prompts/场景，和评估场景分离；training-free 则用 held-out calibration 设置阈值。硬件： 单张 NVIDIA H100 测 throughput，论文明确排除 VAE 编码/解码，仅以生成帧数除以 DiT forward time；不是完整产品端到端 FPS。RQ1 能否保持质量并提升短视频 FPS？RQ2 30 秒 autoregressive rollout 是否引入更多漂移？RQ3 摄像机不断改变内容的世界模型还能否提前提交？RQ4 ε、verifier 信号、token/chunk 粒度分别起什么作用？

Mean Steps 是每个 latent token 的平均去噪前向次数，越低越省 DiT 去噪计算，但不包括 clean pass。Throughput/FPS 是论文定义的 DiT-only 帧吞吐，越高越好；它不能替代 TTFT、真实播放端到端 latency。VBench Total/Quality/Semantic 是按协议聚合的视觉质量和语义分数，越高越好，但分数细微差异不等于人类能辨别。Drift 是视频按 2 秒分段计算 imaging-quality 分数的标准差，越低表示画质随时间更稳定，但可能误把“变得不动”当稳定，所以还需 Dynamic Degree。RPE Trans/Rot 分别衡量相机轨迹相对平移/旋转误差，越低越好；依赖 Depth Anything 3 重建和每段 Sim3 对齐。AUROC 衡量 verifier 能否把“仍需继续去噪”token 排在前面，越接近 1 越好，但分类排序好不等于校准阈值后 FPS/画质一定好。

Ablation / Mechanistic Analysis：真正验证的机制

改 ε： 增大容差→更多 token 提前提交→FPS 升、超过阈值后质量和 Drift 恶化。说明该方法是有明确风险边界的近似推理，不是严格 lossless。换 verifier： Channel Variance 的 Drift 4.996、Temporal Difference 4.116，远差于 Head 的 2.839；运动变化混合了真实相机运动与噪声失真，不能直接当作“还需去噪”的证据。把 token 改为 chunk 接受： mean steps 2.61 vs Head 2.55 相近，Drift 3.214 vs 2.839，说明局部退出粒度确实重要。去掉时空平滑： Appendix Table B 的 Drift 从 2.839 升至 2.882，Imaging Quality 从 72.65 降至 72.54，收益小但方向一致。用 MLP 替代 3D Conv： Quality 82.67 与 Head 82.65 相近，说明复杂 3D 卷积不是唯一可行设计，实际创新更偏向 verifier 任务定义与 KV commitment 机制。

AUROC sanity check： Appendix Table A 在 ε=0.24、k=1，Head AUROC 0.934，Redundancy 0.828，Motion-based 0.701；k=2 时 Head 0.890、Stability 0.774。排序性能更好支持 head 的信息优势，但 AUROC 不是阈值校准，也不保证对分布外视频稳定。尤其世界模型在训练中没见过的相机速度和场景布局，可能使 gap predictor 低估错误。

Claim vs Evidence、Contribution 与 Limitation

Authors Claim： token-wise early commitment 在保持四步生成质量的同时明显加速。Experiments Actually Show： 两个 1.3B backbone、短视频/30 秒视频/253 帧世界模型、单 H100 DiT-only FPS 上，存在可选 ε 使质量指标接近四步，且去噪 token-evals 与实际 FPS 都改善。What Is Not Yet Proven： 任意视频生成器、不同 GPU/批大小/高分辨率下的收益；VAE-inclusive end-to-end 延迟、显存、能耗；人类偏好无差异；长于 30 秒或数小时的稳定性；对快速镜头切换、复杂交互的最坏情况保证。

Contribution 1 / New Mechanism： token-wise commit 并保留 KV，上下文不因 early exit 断裂；比统一缩步或 chunk-wise 退出更细。Contribution 2 / New Verifier： 两种收敛代理及 4.11M 参数 gap-regression head；网络结构本身是常见组件，创新主要是监督目标和推理用法。Contribution 3 / New Empirical Finding： 4-step AR video 中不同 token 的剩余收敛步数差异明显，且可以兑现为单卡 DiT 吞吐提升。Contribution 4 / Engineering： in-place KV 更新、clean-pass 合并和稀疏活跃索引是让理论节省兑现为 wall-clock 的关键实现。

作者局限： 适用于能产生中间 clean estimate 的 few-step 自回归视频模型；错误提前接受可能在后续 chunk 中传播；收敛判断依赖当前模型、数据和容差。额外局限： 训练型 verifier 需先付完整四步标签成本，分布偏移可能破坏校准；训练-free 的最近邻历史搜索在更长缓存窗口可能增加代价；不报告显存与真实用户侧延迟；固定 4 步下的 k̄ 收益不能直接外推到 8、16、40 步；动态稀疏 token kernel 的效率高度依赖硬件和 batch size。项目 GitHub 尚未放出实现，限制当前可复现性。

Reproduction View：最小实验怎么做

优先从 training-free 版本验证机制，而不是等待完整仓库。 选可运行的 LongLive 1.3B 或同类 four-step AR video backbone；固定种子、相同提示词和原始 timestep [1000,937.5,833.3,625]，首先完整运行四步并保存每一步 clean latent、最后输出、KV。对每个 token 计算 oracle relₖ，统计 k=1/2/3 的收敛比例及其在背景/运动区域的差异。第二阶段仅在离线保存的 latent 上模拟 ε=0.16/0.20/0.24/0.28/0.32 的早停分配，画 mean steps vs oracle mismatch，确认是否存在足够异质性。

实现难点不在一行 if，而在注意力的 token mask 与 KV 更新：已提交 token 不应继续算 Q/MLP，却仍提供 K/V；每个层的活跃索引必须一致；clean pass 必须刷新整块历史，且与下一 chunk 首步的合并不可违反因果顺序。对照必须让 uniform 1/2/3/4-step 使用同一原始采样 schedule 和同一 DiT kernel 优化。训练 learned head 时，先收集 1000 个与测试不重合的 prompts，使用最后 block hidden states 与 oracle relₖ，训练 LayerNorm+3DConv，记录 Huber loss、AUROC、校准曲线，再部署 ε sweep。最先验证 Table 1 的 FPS/Total 与 Table 5 的 token-vs-chunk ablation；若无法获得官方代码，应该明确写“独立近似复现”，不能称“官方结果复现”。

Research Value 与两个可执行迁移方向

Baseline Potential：中高。 论文提供细致指标，但正式实现尚未发布。Migration Potential：高。 任何存在逐 token/区域可验证收敛的迭代模型都可能适用。Systems Potential：高。 关键是动态稀疏执行、KV 一致性和内核调度。Attack Potential：中。 可以构造让 verifier 过度自信的分布外运动或重复纹理。Evaluation Potential：高。 有 oracle gap、AUROC、FPS、质量与 Drift 多维协议。Benchmark Potential：中高。 缺少对 worst-case 早停风险的压力测试。New Paper Potential：中高。 必须在新模型类别或更强校准/保证上突破，而非只换一个阈值。

Migration A — Risk-Calibrated Early Commit（Video × Robustness）。 Original Problem：ε 是静态容差，world 模型新区域多、错误代价高；Transferable Mechanism：按 token 预测 remaining gap；New Research Question：能否让不同场景动态控制“错误提前接受概率”？Method Modification：在 verifier head 输出 gap 的同时估计不确定性，采用保守分位数或 conformal calibration；对新显露区域提高置信阈值，对稳定背景放宽。Minimum Experiment：采集 200 个世界场景，训练/校准/测试按场景分离；按 camera action（stop/translation/yaw）分组计算 false-commit rate，固定同一 FPS 预算对比全局 ε、分组 ε、uncertainty-aware ε，输出 per-action Drift 与 RPE；Model：Lingbot-World 2.0 1.3B；Dataset：200-scene navigation protocol；Baseline：TF/Head/global ε；Metric：False Accept Rate、FPS、VBench、Drift、RPE、ECE；Expected Contribution：受控风险的 token-wise compute allocation；Risk：过保守导致无加速；Collision Risk：adaptive diffusion/uncertainty-aware scheduling 已有研究，需突出“commit 错误的跨 chunk 累积风险”。

Migration B — Query-Aware Video Evidence Budget（Video Understanding × Agent）。 Original Problem：长视频 VLM 为每帧每区域花近似固定视觉编码预算；Transferable Mechanism：只对“尚未足够确定”的局部 token 继续计算；New Research Question：能否用 query-conditioned evidence sufficiency 而不是视频生成的 latent convergence 判断提前退出？Method Modification：将 verifier 目标改成“多算一次视觉编码是否改变正确答案的 log-prob/判别”，保留已编码 token 的 KV/feature cache，未达阈值的区域进一步采样帧或提高分辨率。Minimum Experiment：从长视频 QA 取 300 条样本，固定 8/16/32 帧预算，先跑全帧高分辨率 teacher 记录每阶段答案分布；训练二分类 verifier 预测下一步能否改变答案，比较 uniform frames、keyframe selection、query-aware top-k、early-commit；Model：公开 Video VLM 7B 级模型；Dataset：LongVideoBench 或 Video-MME 的公开可用子集；Baseline：uniform sampling、query-aware frame selector、no-exit；Metric：QA accuracy、visual tokens、prefill latency、peak VRAM、wall-clock、calibration；Expected Contribution：面向任务的多模态推理计算预算；Risk：错误早停遗漏稀有关键帧；Collision Risk：已有 adaptive frame sampling 和 token pruning 很接近，必须强调“可验证信息充分性 + 跨帧缓存一致性”，并做真实 wall-clock 实验。

Attack / Verification Lens： 制作重复纹理但运动方向相反、镜头快速转向、遮挡后突然出现对象、长序列反复复用错误历史的 stress suite。把 verifier 的 false-accept 按空间区域和时间累计统计，检查错误是否在后续 chunk 被放大。可定义 Risk@Speedup（固定 1.3× 加速时的最坏质量下降）、Drift Accumulation Slope（分段画质方差随时长的变化）、OOD Gap Calibration。这些是建议中的指标，并非原论文已验证。对未发布代码状态应持续关注，避免把项目页的漂亮演示误认为开源可复现。

Cross-Paper Synthesis：两篇共同说明什么

统一趋势是 conditional computation / conditional credit。 Mosaic 不应让所有 session 无差别地共享成功奖励；Speculative Forcing 不应让所有 latent token 无差别地执行四步。两者都先保留一个全局约束：Mosaic 保留最终 outcome 的方向，Speculative 保留原模型的完整输出作为训练/校准参照；再用局部 proxy 决定“哪一段值得投入或奖励”。这种思路很有迁移性，但两者的 proxy 都有忠实性问题：正确答案 log-likelihood 增量不一定是因果贡献，token gap predictor 也可能对 OOD 内容过度自信。

机制互补： Mosaic 的 session boundary 是离散状态转移，Speculative 的 token commit 是局部计算终止；共同可以构成一个有层级预算的 Agent 系统：上层决定是否 fork/compact、下层决定视频证据还需不需要计算。假设冲突： Mosaic 的 session utility 用 ground-truth answer teacher forcing 评分，训练时能用答案但部署时不能；Speculative 训练时用四步 oracle gap，部署时由 verifier 预测。若直接照搬“用答案似然决定 Agent 在线动作”，会泄漏真值；必须把训练信号与推理策略分开。

最佳统一实验范式： 对每个边界同时保留 before_state、after_state、global_outcome、local_proxy、counterfactual/oracle_label、actual_cost；做三组对照：不做局部控制、按启发式局部控制、按校准模型局部控制。报告任务成功/质量、真实 wall-clock、最坏失效、proxy 与反事实/完整结果的一致性。这比“仅比较平均 token 数”更有科研说服力。

Combined Research Opportunities

Opportunity 1 — Verified Handoff Budget： 在多模态 Agent 中，让视频子 Agent 返回结构化证据与置信度，主 Agent 依据该证据对最终答案的边际贡献决定是否继续解码更多帧/再开新 session。关键不是拼接两个模型，而是构造跨层可观测的 marginal evidence gain / GPU-second，并对错误提前停止设置保守门控。最小验证：50–100 个视频 QA 多跳任务，固定 8/16/32 帧预算，测 accuracy、总 tokens、DiT/VLM wall-clock、handoff fidelity。

Opportunity 2 — Counterfactual Calibration Benchmark： 对 Agent 的摘要/子任务返回与 Video 的 early commit 分别做“保留、替换、重算”的受控干预，比较代理得分和真实最终任务变化。若代理对因果变化预测不佳，就应训练更强的 verifier 而不是继续微调 reward 权重。可以形成跨 Agent 与视频的统一实验协议，但两领域的 ground truth 不同，不应假称同一个网络能通用。

Opportunity 3 — Long-Horizon Error Propagation： Mosaic 的错误摘要会污染后续 session，Speculative 的错误 commit 会污染后续 chunk；共同研究对象是不可逆的状态压缩。建立 state fidelity、recovery cost、error amplification slope，让每次状态交接保留必要的 provenance 与可回滚 checkpoint。这更接近真实系统问题，也更有可能与已有只看平均分的工作拉开差异。

Collision / Overlap：不是零风险

Mosaic 与已有 GRPO + process reward、IGPO、CompactionRL、Agent handoff attribution 发生方法层面的邻近：它的独特点是 session 粒度、结果分组 rank、类型条件化局部信号，不能把“答案似然增量”独立宣称全新。Speculative Forcing 与 frame/chunk adaptive denoising、token caching、speculative decoding 有明显重叠；真正差异在 token-wise commit + 继续提供 KV + clean refresh，而非“动态步数”四个字。两篇之间目前没有直接研究命题冲突，因此 Strongest direct collision: NONE；对迁移想法而言存在上述近邻工作，正式投稿前必须系统检索。
