人话版：这篇论文到底干了什么？

一个搜索 Agent 可能先查到关键人物、再查事件时间，最后答对问题；也可能在第 3 步已经找齐事实却继续搜索，最后被噪声误导。过去 GRPO 只知道最终对错，很难判断哪一步真正提供了知识。KnowGPO 把每道题拆成可验证的原子知识条件，把轨迹投影为“已掌握哪些条件”的二值状态；同样知识进度的步骤放在一起比较，并把新获得的事实数作为过程奖励。它不是奖励搜索次数，而是奖励可验证的知识增量。Qwen3-8B 在 BrowseComp-ZH 达 38.8%，GAIA 达 40.2%，均高于对应 GRPO。它提供了将复杂轨迹转为可比较语义状态的可迁移方案。

Background & Research Gap

长程 Deep Search 的 reward 稀疏：成功/失败往往只在最终回答时揭晓。GRPO 把同一条轨迹的终局优势广播给所有动作，可能连冗余搜索一起鼓励。GiGPO 按可观测状态匹配，但两个 Agent 访问不同网页却掌握相同事实时被错误分开；IGPO 依赖正确答案的模型概率增量，容易受到检索噪声和模型过度自信干扰。具体例子：两条轨迹分别从百科与新闻页找到同一发布日期，页面文本不同而信息进度相同，按页面相似度聚类会丢失可比较性。

Core Insight 与 observation

对搜索策略而言，真正重要的状态不是网页字符串，而是“为回答问题所需的知识条件集合”。研究先以问题、参考答案和成功轨迹构建条件骨架，再由 verifier 检查每步新增事实。这样不同措辞和不同网页可映射到同一个知识状态。Figure 1 对比终局奖励、表面状态匹配与知识状态匹配；Figure 2 展示从条件构建到 group advantage 的全流程。核心风险也由此产生：条件拆解和 verifier 可能引入标签泄漏与伪知识奖励。

Method Deep Dive

Input：问题 Q、参考答案 y*、初始搜索策略与可用检索工具。Step 1：把答案所需证据拆成 K 个单跳原子条件，避免直接把完整答案当作状态。Step 2：对每条 rollout 的每次观察，用 DeepSeek-v3.2 verifier 判定新满足的条件；通过逐位 OR 形成累计状态 s_t。Step 3：把先前知识状态相同的非终止动作组成 group，只比较在相同知识起点上谁获得更多新事实。Step 4：计算增量知识 reward、组内标准化优势；同时保留最终回答对错的 episode advantage。Step 5：用 PPO-style clipping + KL 约束更新策略，得到能够动态决定继续搜索或停止的 Agent。Output：经 RL 后训练的深度搜索策略。

Toy Example

问：某获奖导演的第一部长片在哪一年上映？条件 k1=确认导演身份，k2=确认第一部长片，k3=确认上映年份。轨迹甲先得到 k1、k2，再得到 k3；轨迹乙访问三个近似新闻页面却只获得 k1。若两条轨迹在 k1 状态下比较下一步，甲获得两个新条件，乙获得零个，甲的下一步应获更高 advantage；若最终甲仍答错，终局项会纠偏，避免纯粹“刷知识条件”。

Baseline Comparison

同一 SFT 初始化与工具环境下比较 GRPO（终局奖励）、GiGPO（表面状态分组）和 IGPO（答案概率变化），这是最可比的三条 baseline。BrowseComp-ZH：GRPO 32.9、GiGPO 37.3、IGPO 32.2、KnowGPO 38.8；该数据集 strongest baseline 为 GiGPO。GAIA：35.0、35.0、37.9、40.2；strongest baseline 为 IGPO。与 32B 公开系统的横向比较并非同数据、同工具的严格控制实验，不能等同于纯算法胜利。

Experiment Setup 与 Research Questions

模型 Qwen3-8B，YaRN 扩展至 128K context，SFT 使用 LlamaFactory，RL 使用 verl；基准 Xbench-2505、Xbench-2510、BrowseComp-ZH、GAIA 文本子集；GPT-4o 判定最终回答，三次独立运行取均值。RQ1：相同模型/工具下能否稳定超过 GRPO、GiGPO、IGPO？RQ2：知识增量 reward 与知识状态分组是否分别必要？RQ3：状态抽象是否增加跨轨迹可比性？RQ4：额外 verifier 开销与搜索轮次是否值得？论文提供附录超参，但本摘要不将未逐项核验的训练 token/GPU 小时写成事实。

Ablation / Analysis

去掉知识增量 reward → BrowseComp-ZH 的完整 38.8 降至使用折扣回报的 32.8；说明后续随机性会污染局部 credit。只保留知识增量而不分组 → 34.6，说明语义起点匹配至关重要。ω 从 0.3 提到 0.5 → BrowseComp-ZH 38.8→36.3；局部过程监督过强会牺牲最终目标。观察分组 ESR 51.8% vs 知识分组 97.8%；这说明可比较的样本覆盖更好，不证明条件标签天然无偏。

Claim vs Evidence

Authors Claim：知识条件驱动的过程 reward 使深搜 Agent 的 credit assignment 更准确、更高效。Experiments Actually Show：四个 split 均优于 GRPO，主表及组件消融支持分组和局部增量共同有效。What Is Not Yet Proven：跨任务泛化、无参考答案场景的条件构造、verifier 被对抗性网页欺骗时的稳健性、与不同 tool latency 的真实成本最优性。

Contribution / Limitation

贡献 1【New Mechanism】：将多样化检索轨迹映射到原子知识状态。贡献 2【New Objective】：同知识状态下的增量 reward 与 episode reward 混合。贡献 3【New Empirical Finding】：语义分组显著减少 singleton 并提高搜索准确率。作者机制假设：已获得知识单调累积。额外局限：参考答案和成功轨迹辅助条件构造；验证器可误报；某些问题无法拆成稳定事实条件；终局正确性仍可能受 LLM judge 误判影响。

Research Value

Baseline Potential：可作为 Agent RL 的可解释 credit assignment 强基线。Research Migration：把“知识条件”替换成工具成功条件、记忆事实或跨 Agent 贡献。System Value：过程 reward 可帮助提前停止无用检索，但 verifier 成本需要测。Benchmark Value：可设计状态匹配质量与证据错误传播测评。Attack/Evaluation Value：恶意网页伪造满足条件，检验 verifier 脆弱性。New Paper Potential：从单调知识覆盖扩展到可撤销、可纠错的证据状态。

Migration：完整可实验路线

Original Problem：长程搜索动作难以分配 credit → Transferable Mechanism：把观察压缩为可验证事实状态并进行组内对照 → New Research Question：在 Agent Memory 中，某条记忆到底对未来任务有无因果贡献？→ Method Modification：将知识条件扩展为带 provenance 的 memory claims，并允许事实撤销；在相同记忆状态下做 leave-one-memory-out 反事实比较 → Minimum Experiment：选 100–200 个跨会话多跳任务，固定检索预算，比较原始记忆、随机压缩、只按检索频率筛选、知识增量选择、反事实选择 → Model：Qwen3-8B 级别 Agent → Dataset：BrowseComp-Plus 或 LongMemEval 适配任务 → Baseline：GRPO、频率/相似度选择、KnowGPO 风格覆盖奖励 → Metric：最终准确率、错误传播率、token/成功任务、memory precision → Expected Contribution：可归因的记忆选择与纠错机制 → Risk：verifier 伪阳性、评测泄漏和高 rollout 成本。

State=累计知识条件；Action=search/answer；Policy=Qwen3-8B；Reward=终局正确性 + 事实增量；Trajectory=多轮检索；Advantage=episode + knowledge-group；Objective=PPO-style clip + KL；Credit=同知识状态比较。奖励基于 verifier 而非纯人工标注，但 verifier 误判可能被 reward hack。训练成本：作者测得 rollout 2574s、policy update 583s、概率计算 310s，新增知识验证 356s、分组 0.03s；非统一 GPU-hour 统计。

人话版：这篇论文到底干了什么？

多数 RAG 系统收到问题才开始检索，跨文档整理要在每次问答时重复做。Librarian Agents 换了思路：先训练一个“图书管理员” Agent，主动把原始文档整理成层级文件、合并摘要和可追溯链接；后续答题 Agent 直接在这个工作空间里找证据。整理行为不靠人工规定的知识图谱模板，而是把文件操作当作强化学习动作，用未来问题的正确率训练构建策略。在 BrowseComp-Plus 上，冻结 Qwen3.5-4B 答题器时正确率达到 75%，高于检索/重排基线 42%/44%；迁移到 BRIGHT 三领域时平均 pass@1 为 52%。其研究价值是把 Agent Memory 的质量定义为未来可复用的实际任务收益。

Background & Research Gap

传统 RAG 在每个 query 到来后重新检索，知识图谱与层级摘要则用固定启发式预处理。若企业代码库中某个 bug 分散在 release note、Issue 与测试记录中，重复问“何时引入、影响谁、如何修复”会反复消耗推理。作者观察到 Agent 已经善于读取目录，却很少被训练去提前写出方便未来导航的目录。关键 gap 不是缺少记忆存储，而是没有把记忆组织结构本身作为可优化决策。

Core Insight

一个工作空间是否好，取决于未来使用它的 Agent 能否更准确、更低成本地完成任务，而非摘要是否看起来完整。把整理过程建模成 MDP 后，可以把多次编辑的长期效果归因到 Create/Merge/Delete/Stop 操作。保留 raw documents 和引用链接是重要的 safety valve：被摘要丢弃的细节仍可追溯。Figure 2 是结构与动作空间的核心图；Figure 3 是间隔 probe 的 reward shaping。

Method Deep Dive

Input：原始文档集合 D、隐藏的未来查询分布、Builder policy 与冻结的 answering policy。Step 1：Builder 查看文件树并决定创建聚合文件 CreateFile，合并主题文件 MergeFiles，删除冗余合成文件 Delete，或 Stop。Step 2：每个合成文件保留来源链接，原始文件不可删除。Step 3：在若干操作后对答题 Agent 做隐藏查询 probe，观察回答正确率的变化。Step 4：将阶段性正确率增量转为 reward，以多轮 GRPO 更新 Builder；答题器始终冻结。Step 5：推理时一次构建 workspace，未来多条 query 通过文件列表和读取操作导航。Output：可重复使用的分层语义工作空间与其 provenance。

视频生成通常每个 latent token 都跑完整的 4 次去噪，但并不是每个区域都需要四轮精修：静态背景可能第一轮就接近最终结果，新出现的物体却还需要多轮。Speculative Forcing 在中间步骤把每个 token 的预测视为“草稿”，用无需训练的稳定性判据或小型学习 verifier 决定是否提前接受。已接受 token 停止继续去噪，但保留 KV 供其他 token 注意力访问。LongLive 的 5 秒视频平均每 token 只需 1.68 步，吞吐从 26.40 提至 41.74 FPS，VBench 总分 83.08→83.21；在动态世界模型上提升较小。这提供了视频计算预算按 token 适应性分配的清晰机制。

Background & Research Gap

少步自回归视频模型虽可流式生成，却通常在每个 chunk 内让所有 token 执行同样的 K 次去噪。均匀减步会损害新物体边界、快速运动和相机转向时的细节。问题并不是“能否让整段视频少采样”，而是能否对每个 token 判断何时已经收敛。例子：室内静态墙面与刚进入镜头的行人不应消耗同样的去噪预算。

Method Deep Dive

Input：冻结的少步 autoregressive video generator、当前 chunk 的噪声 latent、历史 KV 与 verifier。Step 1：所有 token 执行第一个去噪步，得到 clean estimate 草稿。Step 2：训练自由版使用与已清洁内容的相似度和跨步稳定性；学习版使用冻结生成器中间特征，由 3 层 3D Conv 预测距完整输出的残差。Step 3：对评分做时空平滑，低于阈值 ε 的 token 提前 commit；这些 token 不再参与后续去噪计算。Step 4：缓存已提交 token 的 K/V，使尚未收敛 token 仍可利用上下文。Step 5：最终对完整 chunk 执行 clean pass 更新后续 chunk 的 KV。Output：不同 token 使用不同去噪步数的视频序列。

人话版

视频扩散生成的昂贵部分是每一步都运行大网络。传统缓存把“缓存是否过期”变成二选一：要么重新算，要么复用。SoftCache 发现离过期阈值还有多远（headroom）本身包含误差风险信息，因此在缓存很新时一次跨过多个采样节点，临近刷新时缩小步长，并重排剩余采样网格。它不重新训练，在 HunyuanVideo 与 Wan2.1 视频模型上展示多档 3.5–6.9× 真实 wall-clock 加速下的质量优势。核心不是更激进地跳过网络，而是把缓存可靠性转化为连续步长决策。

Background & Gap

50 步采样意味着大量重复的 Transformer 前向。TeaCache/SeaCache 以阈值决定刷新，DPCache 固定刷新日程，TaylorSeer 外推中间特征；这些策略没有充分利用“缓存还剩多少安全余量”。如果刚缓存后的残差变化很小，仍严格走固定采样网格，会错失跨越多个节点的机会。

Core Insight & Method

长程 Agent 经常在工具调用中偏离目标，且直接让强模型监督每一步太贵。本文引入 steering agent：低成本 fast path 先判断何时需要介入，高成本 slow path 再生成纠偏建议。作者用 pairwise ranking 和 GRPO 联合训练两条路径，在单 Agent 与多 Agent 的信息搜索任务中报告成功率和效率改善，且可迁移到未见执行器。其重点不是更强的 planner，而是让“何时纠偏”成为可学习、可控制的策略。

Background & Gap

传统反思式 Agent 常固定频率检查或失败后才重试。固定频率浪费 token，完全不监控则在早期错误后持续积累偏差。多 Agent 系统中某个角色理解错目标会通过消息传播，使错误成本被放大。需要区分漂移检测和干预生成的预算。

Core Insight & Method

Input：原始目标、执行历史、当前 Agent/团队状态。Step 1：fast path 读取状态并估计 goal drift 或介入价值；Step 2：必要时激活 slow path，形成纠偏指令；Step 3：将建议注入正在执行的 Agent/多 Agent 过程；Step 4：根据执行改善训练 fast/slow 策略。Pairwise ranking 学习干预优先次序，GRPO 学习策略；推理时可调 intervention frequency，无需重新训练。

Experiment Setup / Research Questions

实验为信息检索类单 Agent 与多 Agent 任务。RQ1：steering 是否减少目标漂移并提高效率？RQ2：fast path 是否足够便宜？RQ3：跨任务、跨 executor 是否能泛化？RQ4：干预频率调低时效果如何变化？摘要未给出明确成功率与成本数值，不能把定性改善转换为百分比。

LEASH 的弱强升级 + Learning to Steer 的双路径纠偏 + AgentPerturb 的受控扰动。

Research Gap
