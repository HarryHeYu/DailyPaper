1. 人话版（先读这一段）

想象一个需要连续搜索网页、打开文档、整理证据、最后提交答案的 Agent。任务成功才给 1 分，失败给 0 分；如果它在第 15 步犯错，却在第 60 步失败，直接把 0 分分摊到全部步骤，根本分不清哪一步坏了。一个思路是从中途状态反复重新执行后半段，看看这个状态究竟有多大机会成功；但每次续跑都很贵。FOCUS 的做法是训练一个预测“从当前状态最终成功概率”的 critic，观察其预测与已经采样到的结局是否矛盾，再把额外的 rollout 预算分配给预计能最大幅度减少价值估计误差的状态。新增证据既修正当前的逐段 advantage，也用来训练下一轮 critic。作者在 Qwen3.5-9B 上报告 BrowseComp-Plus 55.4%，GRPO 为 48.2%；DeonticBench 总分 56.5%，GRPO 为 52.4%。它真正值得关注的不是再发明一种 PPO，而是将采样位置、价值估计、credit assignment、上下文压缩边界组织成一个可迁移的训练控制器。

2. Background & Research Gap：为什么需要“主动修 critic”

现实问题。 Agent 的动作不是一段静态答案，而是“查资料—调用工具—观察反馈—再决定”。终局奖励只回答“最后是否成功”，却不回答“哪次工具调用导致成功”。比如代码定位任务，前 20 次 grep 可能找到正确模块，第 21 次错误地忽略测试，第 40 次提交错误文件；对全部 token 广播同一个失败 advantage 会惩罚前面的正确搜索。长程任务还经常需要 context compaction：把几万 token 的历史压成短笔记继续执行，原始上下文与环境状态必须能恢复，否则无法公平地从中途分叉。

旧范式一：GRPO。 对同一题采多条完整轨迹，按组内终局 reward 计算相对 advantage，再广播到各步。它省去 critic，训练简单，但中途“正确探索”和“过早提交”可能被同一轨迹分数捆绑。旧范式二：PPO+critic。 学一个 V(s)，对每步算 TD/GAE；代价是 critic 在稀疏奖励、分布不断变化时不准。旧范式三：VinePPO/树形 rollout。 从中间节点重新采样 suffix，近似局部成功率；然而每个节点都续跑 k 次，长 Agent 的工具开销会迅速膨胀。本文填的 gap 并不是“能不能分叉”，而是在有限预算下应该优先分叉哪里、如何把分叉收益写回一个可复用的 critic。

3. Core Insight：最值得采样的不是最不确定的节点

作者观察到：critic 的错误与续跑结局的随机性不同。某个节点预测成功率 0.9，实际多次续跑只有 0.1，它既存在系统性偏差又值得修正；另一个节点预测 0.5，结局一半成功一半失败，采样更多也许只能缓慢降低方差。只按熵、单次残差或平均分叉会把这两类混在一起。FOCUS 用 Beta 近似后验与一个 MSE 边际下降代理函数 g(s)，兼顾当前预测偏差、结局方差、已采样数量和先验强度。g 高才值得追加 rollout。这个观察是统计建模加工程经验，不是证明了对所有非平稳 RL 环境全局最优。论文在固定审计树、常数 critic 和随机 critic 上检验了优先级排序的效果，但这种离线诊断不等于在线训练每一步都满足独立同分布假设。

另一个关键观察是 compaction 边界天然适合做可恢复状态：一次压缩之前的动作可以合成一条 edge，压缩后是新的 node。它减少“每 token 分叉”的状态爆炸，但也意味着训练信号分辨率由 compaction 频率决定。作者强调分叉条件与压缩触发器在实现上可解耦，这点对于已有 Agent harness 很重要。

4. Method Deep Dive：从状态树到 Actor 更新

Input → 固定当前 actor/critic → 采种子轨迹并保存可恢复快照 → 为每个节点估计 V 与观察到的结局 → 计算 g(s) → 选最大 g 的节点追加 suffix → 更新统计并循环 → 自底向上备份价值 → 训练 critic → 按逐段 advantage 训练 actor → Output：下一轮策略与价值网络。

Step 1：建树。 每个问题 x 对应一棵 T_x；节点不是一句文本，而是可恢复的 (context, environment snapshot)。边是从一个分叉点到下一分叉点的一段工具交互，包含策略生成 token、工具结果、奖励、耗费的 task turns。节点可复现性是方法的先决条件：如果浏览器页面或外部 API 状态变化，续跑就不再是“同一个 s 的条件分布”。论文实验主要用固定检索语料和可控环境来缓解这一问题。

Step 2：采样并计数。 每个候选节点保存 critic 值 v、直接子节点数 n、完成的 suffix 结局数 N、结局均值 G_obs。n 和 N 不相同：从后代再次分叉不应反向给所有祖先虚增一个独立观测；作者在 Appendix E 特别区分它们。把两者混淆会让深层重复采样的证据被祖先重复计数。

Step 3：计算采样收益。 把 V_phi(s) 看成强度为 κ 的先验均值，观察到 N 个二元结局后更新后验均值 μ_obs；用估计的 squared critic error 与 Bernoulli 方差构造 g(s)。每轮选 g 最大且可恢复的状态，从这里续跑到终局。它不是选择“成功率最高”的状态，而是选择“多花一次预算预计最能改善估计”的状态。实现允许异步并发，单节点最多两个在途 continuation，并在排序时用 N_eff=N+pending 防止多个 worker 同时涌向一个节点。

Step 4：递归价值修正。 收集完后按树的逆拓扑顺序，把每条边的中间 reward 加上下一节点的折扣价值，得到直接子分支平均 backup G_bar。然后用 κ 与 n 混合旧 critic 和 backup 得到 V_tilde。为什么不直接平均所有后代的最终 reward？ 因为分叉位置是主动挑选的，后代样本并非从祖先状态按原始策略独立抽样；粗暴平均会产生由选择策略引入的偏差。单层 backup 并不自动消除所有偏差，但更清楚地隔离了直接子分支。

Step 5：critic 与 actor 联合学习。 critic 用 (V_phi-G_bar)^2 回归，actor 则将边级 TD residual 分配给该边中策略生成的任务 token 和 compaction token；工具返回文本与条件文本不反向更新。作者使用 PPO-style clipped ratio，限制单轮策略更新幅度。Critic 的当前迭代监督与下一迭代采样决策构成闭环：Memory/Context → Action/Tool → Outcome → Value Evidence → Credit → Policy Update。

5. 核心公式与数学直觉

Ḡ(s) = (1/n(s)) Σs′∈children(s) [ R(s→s′) + γd Ṽ(s′) ]
Ṽ(s) = [κ Vφ(s) + n(s) Ḡ(s)] / [κ+n(s)]

γ 是折扣率，d 是边内跨越的 task transitions，κ 是 critic 相当于多少条“伪观测”。κ 越大越信 critic；κ 越小越信续跑。n=0 时保留原 critic，终点价值为零。论文主要配置 γ=1, λ=0, κ=1，因此不是一般意义上大量 GAE(λ) 混合的实验。critic loss 是 Σ_s (Vφ(s)-Ḡ(s))²，注意回归目标是 Ḡ 而不是 Ṽ。

μ = (κv + N Ḡobs)/(κ+N)
ê² = (v−μ)² + μ(1−μ)/(κ+N+1)
g(s) = [2κ² ê² + (N−κ) μ(1−μ)]/(κ+N)³

这里 v=Vφ(s)，N 是该节点观察到的完整 suffix 数。分母是三次方，所以重复采样某节点后，其边际收益通常快速下降；但在某些小 N 或极端估计下 g 可不为正，算法只从 g>0 的可恢复节点挑选。重要限定： 这是二元终局 reward、Beta 近似、冻结 actor/critic 下的启发式 acquisition score，不能把它误写成严格的策略性能增益。它优化的是 critic MSE 代理，不是直接最大化最终任务成功率。

ρ=πθ(token|prefix)/πold(token|prefix)；正 advantage 增加该段生成概率，负 advantage 降低它；clip ε 防止一次更新把策略推得太远。Appendix 的实际优化配置有 PPO clip=0.2、KL coefficient=0.01、entropy bonus=0。KL 惩罚约束与参考策略的分布偏离，系数大可能保守、系数小可能不稳定；主文公式未展开全部实现项，复现必须参考配置而非仅抄 Eq.(5)。与 GRPO 最本质差别：GRPO 的 advantage 来源是同题终局 reward 的组内相对排序；FOCUS 用经过分叉证据修正的节点价值形成逐段 TD 信号。

6. Toy Example：一次失败如何分配采样

假设一个 Agent 查找漏洞根因，完成 3 个阶段：S0 读 issue，S1 查日志，S2 定位文件，终点提交。当前 critic 预测 V(S0)=0.55, V(S1)=0.85, V(S2)=0.40。已观察到 S1 的两次 suffix 都失败，而 S2 的两次 suffix 一成一败。取 κ=1，S1 的后验均值 (0.85+0+0)/3≈0.283，S2 的后验均值 (0.40+1+0)/3≈0.467。S1 的“预测与证据冲突”更大；按 g 计算时还会考虑两者方差，不能仅凭这个差值断言 S1 必然排第一。若分配器选 S1，再续跑得到失败，则它的 N 变 3，G_obs 仍为 0；下一轮 g 更新，可能转而采 S2。最终从各直接分支 backup，假设 Ṽ(S1)=0.30，Ṽ(S2)=0.65，且这两段即时 reward 都为 0，则 S1→S2 的 advantage +0.35，S0→S1 的 advantage −0.25。于是模型鼓励“正确定位”那段，抑制“错误日志判断”那段。数值是教学构造，不是论文实验数据；真实方法的树备份与选择 score 应按公式计算。

7. Baseline Deep Comparison（谁是 strongest）

Baseline 怎么做、为何合理 在此 setting 的不足 FOCUS 的机制差异
GRPO（整体最强、本文主要参照） 同题完整轨迹组内标准化终局 reward；不需 critic，成本结构清晰 早期正确动作与后期错误动作同分；训练后期出现 compaction 后过早提交 用分叉后的段级 TD，不再广播整条轨迹的同一信号
VinePPO（最直接的结构性对手） 从中间状态额外续跑，估计 suffix 的相对价值 固定采样位置和次数可能浪费预算，且无可持续学习的 critic 按 g 主动分配预算并训练 critic
PPO + learned critic Actor–critic 直接预测中间价值，经典且低采样开销 稀疏结局使 critic 容易偏，预测误差会污染 advantage 用实际续跑证据校正 critic

8. Experiment Setup 与 Metrics

Research Question A： 在相同每步生成预算下，主动 critic 是否提高长程任务成功率？作者用 Qwen3.5-9B 全参数训练比较三方法，三个 benchmark 都训练 1 epoch；另用 Qwen3.5-27B + LoRA 在 DeonticBench 检验规模迁移。DeonticBench 共 6232 道规则推理任务，论文选 Airline、SARA numeric/binary 子集并做等规模 train/held-out 分层划分；BrowseComp-Plus 固定检索语料的 830 题，分 498/83/249 训练/验证/held-out；LocBench 560 个真实 GitHub issue，按仓库与 issue 类别分层对半划分。三者分别考查规则应用、深度搜索、代码定位，不是同一类技能的三次重复。

Research Question B： critic 的价值估计是否更准？固定审计树，对常数或随机初始化 critic，比较 MSE 随额外 continuation 预算的下降；LocBench 以 8 条 trace、每节点 16 次额外续跑的估计作为参照，测 Spearman 排序相关。Research Question C： 增益是否仅来自 compaction 形式或额外计算？分别替换压缩机制、去掉 refinement rollout、使用结构化压缩笔记，观察 held-out 曲线。

预算与实现： BrowseComp-Plus 的 FOCUS 9B actor + 9B critic；B_seed=64 turns/prompt，每更新 6 题；actor lr=critic lr=1e−6，temperature=1，PPO clip=.2，KL=.01；compaction 在 prompt 14,336 tokens 或 18 次工具调用后触发，最大 80 turns，context 98,304 tokens。论文列出训练 2×H200、rollout 4–6×H100、critic refinement 1×H100；这说明有额外 critic 硬件，matched per-step generation budget 不等于 matched 总 GPU-hours。DeonticBench 9B 的 critic lr 是 5e−6，不要错误套用 BrowseComp 配置。27B 使用 LoRA (r=16, α=32, dropout=0)。

指标教学。 Held-out accuracy 是未训练样本的正确率，高好，但受 checkpoint 选择与样本分布影响；BrowseComp-Plus 的答案等价性由 Qwen3-32B 判断，存在 judge 偏差。LocBench File@1/@5 要求所有 gold 文件都在前 k 个中，高好，@5 高不代表实际补丁正确。Critic MSE 是估值与高采样参考的平方误差，低好，但“16 次续跑平均”也不是无噪声真值。Spearman ρ 衡量价值排序一致性，高好，不代表概率校准准确。平均工具调用数不是越少越好：过少可能意味着高效，也可能是“放弃任务”。KL 衡量策略偏离程度，过大可能导致能力漂移，过小也可能表示根本没学到。

  2. DeonticBench Overall：56.5 vs 52.4（+4.1 pp），CI [+0.59,+7.69]；对 VinePPO 49.4 则 +7.1。规则推理也受益，但 SARA-N 子集 FOCUS 52.0 低于 GRPO 56.0（−4.0），不能声称每个细分任务都更强。
  3. DeonticBench Airline：21.3 vs 14.0（+7.3 pp）；SARA-B：96.4 vs 92.8（+3.6 pp），Hard：26.8 vs 28.2（−1.4 pp）。这是同一总体分数下存在显著异质性的证据，hard 子集尤其需要检查错误类型。

11. Ablation / Mechanistic Analysis

去 refinement → 早期 BrowseComp 学习速度下降：说明 critic 单独给 TD 信号不够，实际 continuation evidence 承担纠偏职责。随机/残差优先级替代 g → 固定树 MSE 下降更慢：说明采样策略确实重要，但只在固定树、指定估计误差定义下成立。换 in-context compaction 为 in-memory workspace → DeonticBench 接近：说明采样控制器不绑死压缩实现。换结构化笔记 → LocBench 曲线更稳但峰值较低：提示记忆结构可能改变可恢复性和探索。严格说这些是干预组件后的性能变化，不能直接识别“哪一个具体 token 的影响”或证明价值估计误差是唯一中介变量。

12. Claim vs Evidence；Contribution

Authors Claim： 主动分配 suffix 预算可改善 critic 估计和长程 Agent RL。Experiments Actually Show： 9B 三类任务总体优于 GRPO/VinePPO；固定树估计误差更低；去 refinement 的性能下降；后期工具使用更稳定。What Is Not Yet Proven： 同等总 GPU-hours、跨动态外部网页环境、非二元奖励、超长轨迹、不同基础模型家族上的稳健优势；更不等于“所有 compaction 均可完美恢复”。

Contribution 1 [New Mechanism]： 用 critic MSE 边际收益驱动 rollout 分配；创新在预算控制准则，不在树搜索本身。Contribution 2 [New Objective / Training Integration]： 以递归备份监督 critic、以修正价值形成逐段 PPO advantage；属于已有 Actor–Critic、树备份、主动学习的有针对性组合。Contribution 3 [New System / Engineering]： compaction / fork / environment snapshot 与训练解耦，支持异步分叉。Contribution 4 [New Empirical Finding]： 轨迹级 GRPO 的工具调用坍缩与主动校准的稳定性差异，值得独立复验。

13. Limitations & Failure Modes

Authors' Limitation / Future Work： 论文明确提出更大模型、更长预算、更强不确定性估计、compaction 质量与稳定性的关联仍待研究。Additional Limitation： (i) 需要可复现 fork；在线网页、数据库写入、时效 API 会破坏条件分布；(ii) critic 本身可能过拟合，Beta–Bernoulli 对连续 reward 或多目标回报不自然；(iii) 追加 rollout 的真实成本按长度变化，g 只近似单位样本收益，长 suffix 可能“收益高但太贵”；(iv) 训练算力增加额外 critic GPU，不能直接声称总成本更低；(v) 某些子集负增益与 27B 缩小的收益说明可迁移性有限；(vi) 评测等价判断由 LLM 执行，可能带来判分误差；(vii) 早停 collapse 与 context compaction 的因果关系尚未隔离。失败传播路径： 错误压缩笔记 → fork 状态丢失证据 → critic 学到偏差 → g 继续采错位置 → actor 误奖励某段工具行为。

16. 方向专用：RL / Agent / Verification

RL Formulation： State = context+环境快照；Action = Agent 生成的工具调用/文本及 compaction；Policy = πθ；Trajectory = 树上的根到叶路径；Reward = 终局可验证 outcome（主要稀疏、二元）；Critic = Vφ；Advantage = 边级 TD；Objective = clipped PPO + 实际配置 KL；Entropy bonus=0；Credit assignment = segment。Reward 多为规则/任务答案检查，但 BrowseComp-Plus 使用模型等价判分，并非完全无主观性。Reward hacking 风险包括过早提交、格式钻空子、利用验证器等。Sample efficiency 不能只看每步 accuracy，要与 rollout token、GPU-hours 同时报告。

Agent Architecture： Input → Context/Compaction → Planner/Actor → Tool → Environment → Snapshot → Critic/Outcome → Rollout Controller → Policy Update。Memory 是可恢复压缩上下文，不是单独的长期知识库；trajectory 是树边；skill library 不是本文模块。Long horizon 成立的前提是 compaction 后仍能恢复关键事实。Attack / Verification Lens： 设计假高价值状态、伪造工具反馈或污染压缩笔记，测 critic calibration degradation、误采样预算、下游成功率；做 black-box probe 时可用成对任务重试频率近似节点价值，但无法直接观察内部 g。还可以测 recovery/reacquisition：错误笔记被修复后模型是否恢复正常探索。

17. 如果只记住这篇：9 句话

FOCUS 解决的是长程 Agent RL 的“续跑预算分给谁”。它保留 critic，但不盲信 critic。它把中间可恢复状态组成一棵树。它用 Beta 近似下的 MSE 边际收益 g 选择下一处分叉。它把续跑证据自底向上混入 critic 预测。它以段级 TD 而非整条轨迹同一 reward 更新 actor。BrowseComp-Plus 9B 从 48.2 提升到 55.4，是最有力的主结果。SARA-N、Hard 子集以及 27B 的较小增益提醒我们它不是全能方法。最值得迁移的是“带成本、可验证、可反事实干预的主动信用分配”。

1. 人话版（先读这一段）

视频扩散模型生成一段长视频时，每一步去噪都要让大量视觉 token 相互注意；几十万 token 的全注意力会非常昂贵。已有加速通常二选一：删掉部分 attention tile，或者把所有 tile 都用 4/8-bit 计算；混合方案也往往给所有留下的 tile 相同精度。Triage 发现这不划算：有些 tile 轻到用聚类均值代替即可，有些 tile 用 FP4 就够，少数重要 tile 即使 FP4 仍有较大误差，值得额外算残差。它先用块统计量预测每个 tile 的误差，再用一个“计算价格”决定升档，最后把三档执行融合进同一个 Blackwell FP4 kernel。作者在五个视频生成 setting 中报告端到端 1.38–2.32 倍的最快配置加速，并且某些更高保真配置同时比所有 baseline 更快、更接近 dense 输出。真正的研究价值是误差收益驱动的动态计算精度，而不是单纯“再稀疏一点”。

2. Background & Research Gap：为何光做 sparsity 不够

视频 DiT 的每次去噪迭代包含空间和时间上的视觉 token，3D full attention 使一个帧的 patch 可以关联其它帧。序列长度 N 增大时，QKᵀ 与 PV 的计算量随 N² 增长。以 119K token 的 HunyuanVideo 720p 为例，理论上全连接的 token pair 数量巨大，不能简单把单张图片的稀疏窗口照搬到视频：运动、物体一致性、远帧依赖会使某些跨时空连接非常重要。具体例子： 一只狗在床上叼拖鞋，背景帧之间大量重复；背景区域可近似，狗嘴与拖鞋交互区域的注意力却需要精确，否则会出现局部形变或闪烁。

Sparse Attention 选少数高 mass tile 用 BF16 计算，其余跳过；对“sharp row”（注意力集中少数块）很有效，但 diffuse row 会损失大量分散信息。Low-bit Attention 如 SageAttention3 把全部 tile 用 NVFP4 算，适合 diffuse row，却把算力花在很多不重要的块上，重要块还可能受到量化误差。Sparse+Low-bit 如 SpargeAttn 结合两者，但保留块的精度通常固定，仍不能区分“中等重要”和“必须高精度”。Research Gap： 能否在不重新训练 DiT、也不运行多个昂贵 kernel 的条件下，对每个 tile 同时决定是否算以及算多精确？

3. Core Insight：边际误差减少 / 边际算力

作者先在 Wan2.2-TI2V-5B 和 HunyuanVideo 的 dense Q/K/V 上分析不同近似。将三种方案都压到模型化的 BF16 成本 25% 后，发现注意力熵低的 row 更适合 sparsity、熵高的 row 更适合 low-bit、中间更适合混合。进一步，单独近似某 tile 的输出误差大致随 tile 的 attention mass 增大；NVFP4 误差约为均值替代误差的 1/5–1/4。这意味着只根据 mass 决定 keep/drop 不够：两个 mass 相同的 tile，内部 key/value 方差不同，均值近似误差也可能相差很大。

因此真正可迁移的准则是：对每个 tile，比较 skip→skim、skim→refine 的预期误差下降 / 额外计算，只在收益超过统一价格 π 时升级。这是有一阶近似推导的工程优化目标，不是对最终视频感知质量的严格最优性证明。其系统配套同样关键：如果升档要另起 BF16 kernel、重读 QKV、额外 merge，即使算术量少了也可能变慢。Triage 用 FP4 高低位残差分解把高精度路径也留在一个 kernel 中，减少启动与搬运开销。

4. Method Deep Dive：Planning 与 Execution 两阶段

Input：每个 DiT attention 层的 Q/K/V → Step 1 以主方向划分 query/key clusters → Step 2 统计 mean、variance、KV covariance、head energy → Step 3 估计 tile mass 与 skip error → Step 4 用 π 路由到 skip/skim/refine → Step 5 生成 virtual mean tiles 与 NVFP4 hi/lo operands → Step 6 fused online-softmax attention → Output：近似 attention output，继续后续 DiT 层与去噪步骤。

Step 1：Tile-aligned clustering。 普通 k-means 会得到大小不等的簇，GPU 需要 padding 或重新切块。作者使用 Principal Direction Divisive Partitioning：在每个节点估计主方向，按投影排序，并在 128 或 64 token 的倍数处二分，直到每个叶簇固定大小。query cluster=128 token，key cluster=64 token，两组 key cluster 组成一个 128-key tile；kernel 处理 128×128 tile。树每五个 sparse steps 重建一次，不是每步从零聚类。好处是簇内差异变小，均值更可信；代价是聚类和索引重排本身有开销。

Step 2：估计误差。 每个 tile 的 mass m_t 是该 query block 的注意力概率落在 tile 上的比例，行内各 tile mass 之和为 1。作者用两条近似路径估计：一条用平均 query 对所有 key 打分，补偿 query variance；另一条用所有 query 对平均 key 打分，再校正均值替代损失。两条平均得 m̃_t。用 key 协方差的 trace 估计均值替代后 softmax 权重丢失 J_t，用 key–value covariance 与 mean value 估计值向量偏移 R_t；上一轮 attention 的 head 输出能量提供 w_h。最终评分 Ẽ_t=m̃_t(J_t+R_t)√w_h，比单纯按 mass 排序多考虑了块内结构和 head 重要性。

Step 3：Tier router。 对每个 tile，skip 的成本记 0、skim 成本 1、refine 成本 3。skimming 的预测误差设为 skip 的 α=0.22 倍，refine 在路由代理中近似视为 0；π 是用户可以调整的计算价格。高 π 更节约算力，低 π 更保真。这里的“0 成本 skip”仅是相对 tile 主矩阵乘法的模型化成本；真实执行仍需统计、virtual tile 与 softmax 操作，不能理解为完全不消耗时间。

Step 4：Skip 的 virtual tiles。 直接丢掉 tile 会损失 softmax 分母，也会让被跳过区域完全没有信息。作者用两个 key cluster 的平均 key/value 代表整个 tile：每个均值相当于 n 个相同 key，所以在 softmax logit 上加 ln n，使它在分母中的总权重等价于 n 个重复均值。若真实 tile 已保留，对应 virtual tile 的 logit 设为负无穷，避免重复计数。它保留的是均值近似贡献，不是精确保留所有原始 token 信息。

Step 5：Skim 与 Refine。 Skim 用 NVFP4 进行 QKᵀ、PV；Refine 先把每个操作数拆成 FP4 的 high 与 residual low，再做 hi×hi + low×hi + hi×low 三项，省略二阶 low×low。这样仍在 Blackwell FP4 Tensor Core 上执行，精度接近 BF16，但没有 BF16 kernel 的低吞吐和多 pass merge。作者还复用了 smoothing correction，保留 FP32 累积与 online softmax。失败模式： 当低位残差很大或二阶项不可忽略时，refine 不等于精确 BF16；当聚类错误或路由评分失准时，重要 tile 可能被跳过。

Step 6：单 pass kernel 与调度。 CuTe DSL/CUTLASS 实现面向 sm_120；producer warp 通过 TMA 载入保留 tile，MMA warps 做矩阵乘，所有 tier 在同一 online softmax 中归并。不同 query row 的保留/精修块数不同，persistent kernel 采用近似按成本排序的 snake order 分配 CTA，避免部分 SM 提前空闲。系统意义在于减少多次 launch、QKV 反复搬运和额外输出合并，而不仅是减少理论乘法。

5. 公式：Router 的误差—计算优化

mt = (1/|I|) Σi∈I Σj∈Jₜ softmax(QKᵀ/√D)ij
min{kₜ} Σt [ Et(kt) + π · c(kt)/Ntiles ]

I 是 128-query block，J_t 是某 128-key tile，D 是 head dimension；E_t 是只近似该 tile 时的相对输出误差，c(skip,skim,refine)=(0,1,3)。除以 N_tiles 让 π 在不同长度下可比较。最小化目标时，如果多花一次算力能带来的误差下降大于价格 π，就值得升级；否则留在便宜档。这里没有模型重新训练，π 是 inference-time 控制变量。

Eskip,t ≈ mt(Jt+Rt)
Eskim,t ≈ αEskip,t，Erefine,t ≈ 0，α=0.22
Ẽt=m̃t(Jt+Rt)√wh

J_t 衡量用 mean key 替代后由于指数函数凸性造成的 softmax mass 损失；R_t 衡量 key 与 value 的相关变化使加权 value 偏离简单均值；w_h 是上一 attention 调用的 head 输出能量相对权重。Σ_K、Σ_KV 通过 block moments 计算，公式中包含协方差 trace 与 Frobenius norm；这不是显式计算完整 dense attention 再做路由，否则加速目的就消失。Appendix B 的推导依赖近似高斯分数、随机方向及一阶扰动，多 tile 共同近似时共享 softmax 分母，误差不严格可加。

refine if α Ntiles Ẽt /(3−1) ≥ π；
else skim if (1−α)NtilesẼt ≥ π；else skip

这两个阈值对应从 skim 到 refine、从 skip 到 skim 的边际收益。π↑ 会降低密度与精修比例，通常更快但 PSNR 下降；α↑ 代表低精度更不准，更多重要块需要 refine；c_refine↑ 会让 refine 更少。最强 baseline SpargeAttn 主要通过固定 top-k 稀疏 + INT8/FP8 降低计算；Triage 不是另一个固定 top-k，而是依据预测误差的边际收益在三档间选择。

X ≈ g(Xhi+Xlo)
QKᵀ ≈ gQgK[QhiKhiᵀ + QloKhiᵀ + QhiKloᵀ]

g 是 2 的整数幂共享缩放，hi 是 NVFP4 主分量，lo 是再量化残差；PV 同样展开三项。省略 lo×lo 是误差来源，也是节省计算的关键。硬件 FP4 峰值性能优势是实现该方案的前提，不可将“3 次 FP4 比 1 次 BF16 快”机械外推到所有 GPU。

6. Toy Example：8 个 tile 如何选三档

设某 query row 有 8 个 tile，估计 Ẽ=[0.40,0.20,0.12,0.08,0.06,0.05,0.04,0.05]（仅用于教学，未归一化的误差 score），α=.22、N_tiles=8、π=.30。skip→skim 的阈值是 (1−.22)×8×Ẽ ≥ .30，即 Ẽ ≥ .0481；skim→refine 的阈值是 .22×8×Ẽ/2 ≥ .30，即 Ẽ ≥ .3409。所以第 1 个 tile 进入 refine，第 2–6 和第 8 个进入 skim，第 7 个 skip。第 7 个不是真的“完全没有贡献”，它的两个 key clusters 由均值 virtual tile 代替；第 1 个用 3 次 FP4 乘积修复量化误差。若把 π 提高到 .60，更多 tile 会降档，速度可能增加但输出误差通常上升。这组数字是自造的公式演示，不是论文中任何 Table 的测量。

8. Experiment Setup 与 Metrics 教学

Research Question A： 三档 tile 精度能否带来真实视频生成加速，而非仅 FLOPs 下降？在单卡 RTX 5090 32GB 或 RTX PRO 6000 96GB 上测试 Wan2.2-TI2V-5B（720p、121 帧、27K tokens）、HunyuanVideo FP8（540p、129 帧、67K）、Wan2.2-T2V-A14B（720p、81 帧、76K）、HunyuanVideo BF16（720p、129 帧、119K）、LTX-2.5 I2V（1088p、721 帧、stage-2 186K tokens）。注意：32GB/96GB 是设备容量，不是论文测出的峰值 GPU memory usage。

Research Question B： 性能来自路由还是 kernel 技巧？固定 dense QKV 调用（Wan 160 次、Hunyuan 240 次）比较相同相对 L2 误差下的 attention speedup；消融 refine、clustering、score 三因子；对照“两 pass BF16 refine”。Research Question C： 质量与速度的 trade-off 是否稳定？同一模型对 50 条 prompt/图文输入固定 seed，比较 PSNR、SSIM、LPIPS、VBench 与 E2E 时间，并扫描 π。text-to-video 使用 Penguin Video Benchmark 50 prompts，LTX-2.5 使用 VBench 50 image–prompt pairs。Wan/Hunyuan 主要 50 denoising steps，Wan A14B 为 40，LTX 分 8 个 stage-1 + 3 个 stage-2 steps。全部在 SGLang Diffusion 0.5.20、PyTorch 2.13、CUDA 13.0、Ubuntu 24.04；仅替换视觉 self-attention。所有方法前 20% 步骤（LTX 为 stage 1）及首个 transformer block 使用 dense attention。

Metrics： PSNR=10log10(MAX²/MSE_pixels)，相对 dense 视频越高越接近原输出，但不是人类主观质量绝对分数；SSIM 评估结构相似度，高好；LPIPS 用感知网络特征距离，低好，可能受模型偏好影响；VBench 是多个视频质量维度的组合，论文平均 subject consistency、background consistency、motion smoothness、aesthetic quality、imaging quality 五项，高好，但小变化不等于所有场景无损；Relative L2 是 attention 输出相对误差，低好，不能直接推断生成视频语义一致性；E2E speedup=T_dense/T_method，大于 1 才是实际加速；Density 是实际计算的 tile 比例，refined 比例是所有 tile 中精修占比，不是保留块中的比例。论文未提供通用的 FLOPs、吞吐 FPS、GPU 峰值显存或能耗数据，必须标为 Not Reported。

12. Ablation / Mechanistic Analysis

去 refine → Wan 最低误差从 2.0% 退化到 9.6%，Hunyuan 从 1.3% 到 6.9%；说明少量重要 tile 的高精度修正不是装饰。去 clustering tree → 在无 refine 版本上 Wan 最低误差 9.6→12.9%，Hunyuan 6.9→7.3%，Hunyuan 同误差慢 1.2–1.3×；说明相似 token 分块提升均值代表性。去 J+R → 误差整体 +18%，95% 的 replay 调用更差；仅按 mass 排序不够。去 head weight → +7%，说明跨 head 分配误差预算有意义。去 mass correction → +3%，属于稳定但较小增益。改用两 pass BF16 refine → 近似同误差，kernel 慢 34–43%，支持“融合是 wall-clock 的必要条件”。这些干预支持组件有效，但没有证明每个 router 预测值是无偏的真实 output error；更没有证明视觉语义失败一定由 attention 层误差导致。

13. Claim vs Evidence；Contribution

Authors Claim： training-free、tile 级三档注意力可以更快且更保真。Experiments Actually Show： 五个特定 DiT setting、两张 Blackwell GPU、50 prompts/setting 的 E2E 和 attention replay Pareto 改善；router 与 refine 的消融确实解释了相当部分收益。What Is Not Yet Proven： 在 A100/H100、其它注意力布局、实时 streaming video、生成式世界模型长期 rollout、不同 seed 大规模分布、跨视频语义事件上的等效效果；VBench 接近也不意味着绝对无损。

Contribution 1 [New Mechanism]： 将 tile 的 sparsity 与 precision 统一成 error-per-compute 分档，真正新意是 router 选择目标。Contribution 2 [New System / Engineering]： virtual mean tile + FP4 residual refine + 单 kernel online softmax 的系统整合。Contribution 3 [New Empirical Finding]： row entropy、tile mass、近似误差的关系，解释为何固定精度无法覆盖所有分布。Contribution 4 [New Protocol]： 同时测 kernel replay、含预处理 attention、完整视频 E2E 与多指标质量的分层评测范式；这是一套扎实的评测组合，不等于作者新发明 PSNR/VBench。

14. Limitations & Failure Modes

Authors' scope / Limitation： 工作聚焦训练免改、3D full attention、Blackwell FP4 tensor core；不同模型仍需选择 π，长视频的 E2E 收益受其它层和 dense steps 限制。Additional Limitation： (i) 依赖 sm_120/CuTe DSL/TMA，硬件移植可能推翻 3×FP4 优于 BF16 的成本模型；(ii) PDDP 聚类每五步重建，场景突变、运动剧烈或跨帧信息重排时可能过时；(iii) router 采用高斯/一阶假设，异常大 logit、极端高 entropy、复杂 KV 相关性下误差估计会偏；(iv) VBench 平均可能掩盖物体身份漂移、罕见手部动作、文字渲染和细节闪烁；(v) 只测单卡，未展示多 GPU 通信、batch-size scaling；(vi) 未给峰值 GPU memory、功耗、吞吐与理论 FLOPs；(vii) 论文未核实作者代码，复现门槛高；(viii) 真实感知质量与 dense 一致性不是同一个目标，某些近似视频可能 PSNR 低但主观更好，反之亦然。

15. Reproduction View：从 Python 模拟到 CUDA

第一阶段，不写 CUDA 先验证 router。 在已有 Wan2.2 模型的 4 prompts×4 steps×10 layers 抽取 QKV，固定 BF16 dense 输出为 ground truth。将 token 按 128 query / 64 key cluster 分组，先用简单聚类替代 PDDP，再实现 J,R,m̃,w_h 计算，按 Eq.(6) 产生三档 map。用 PyTorch 模拟 skip 的 virtual means、skim 的低精度量化、refine 的 high/low 三乘积，扫 π=0.10/0.15/0.30/0.60，画相对 L2–模拟成本曲线。这一步验证算法，而不是 wall-clock 加速；不能把 PyTorch 模拟的 latency 当论文系统结果。

第二阶段，实现 kernel。 复用 CUTLASS CuTe DSL 的 FP4 attention 参考实现，增加 tier_map、virtual key/value、可选 residual load、FP32 online softmax、按工作量排序的 persistent CTA。关键测试是：skip=0、全部 skim、全部 refine 三种极端配置的数值正确性；对比 BF16 dense，单测 softmax normalizer 与 ln cluster_size 是否重复计数。先复现 Table 3 的 41.7/4.3/6.1ms 类型比较，再把 preprocessing 加回，最后测完整 SGLang Diffusion E2E。

最敏感超参： π、α=.22、refine 相对成本 3、clustering refresh 每 5 sparse steps、tile 128×128、key cluster 64、第一 20% dense steps、首 block dense。最容易踩坑： GPU 不支持 NVFP4、量化 scale 不一致、hi/lo 计算顺序错误、TMA 对齐、ragged cluster、virtual tile 与真实 tile 双计数、异步计时未同步、baseline 使用不同 seed/不同步数。应先复现 Wan 5B 27K token 的 replay，再上 119K/186K token；若无 Blackwell，只能复现 router 数学，不应宣称复现了系统 speedup。

16. Research Value 与迁移（两个可开工方向）

Baseline Potential：高，可对比 SpargeAttn、SVG-EAR、SageAttention3；Migration Potential：高，边际误差/算力原则适用于 VLM、video agent、KV cache；Systems Potential：极高，真实融合 kernel + E2E 证据；Attack Potential：中高，可寻找路由误判触发的语义失真；Evaluation Potential：高，PSNR–latency 不够，还应引入任务成功率；Benchmark Potential：高，可做 streaming、长时序、突发运动 stress test；New Paper Potential：中高，需要证明跨 workload 的新 router/新目标，而非复用三档阈值。

Migration A：Task-Utility-Aware Video Attention（Video Agent / VLM）

Original Problem → Triage 优化的是 DiT attention 数值误差，不直接优化 Video QA 的答案质量。Transferable Mechanism → 以 tile 的边际误差收益决定计算精度。New Research Question → 若把“注意力输出误差”替换为“下游答案错误风险”，能否更省计算地保留关键帧/跨帧关系？Method Modification → 给 video VLM 的视觉 token 关联 query-aware relevance、temporal event novelty 与验证器预测风险，按 ΔP(correct)/Δlatency 选择 keep/low-bit/refine；保留突发事件附近的跨帧连接。Minimum Experiment → 在 100 条短视频 + 100 条长视频上离线缓存视觉特征；构建 4 档 token budget（25/50/75/100%），对比随机帧、均匀帧、attention mass pruning、Triage-style proxy router；记录问题级 accuracy、关键事件召回、prefill latency、GPU memory、tokens。Model → Qwen2.5-VL-7B 或其它明确可用的开源 video VLM（选定后冻结 checkpoint）。Dataset → Video-MME 与 LongVideoBench 可访问子集。Baseline → uniform frame sampling、top-mass token pruning、dense VLM。Metric → QA accuracy、event recall、TTFT、prefill time、GPU peak memory。Expected Contribution → 面向任务效用而非像素保真的动态视频计算。Risk → query-aware router 计算自身可能抵消收益；压缩后无法恢复已丢帧。Collision Risk → 高：必须系统对比现有 query-aware frame selection 与 video token pruning。

Migration B：Temporal Router Stress Test（Video Generation / Robustness）

Original Problem → 均值统计量和五步复用的 clustering tree 可能跟不上快速运动。Transferable Mechanism → Triage 的路由评分与三档精度可被直接测量和干预。New Research Question → 是否存在“mass 很低但对时序身份极关键”的 tile，导致路由器高估可跳过性？Method Modification → 构造运动突变、快速遮挡、文字出现/消失、物体身份交换的 prompt；记录每层每步 m̃,J,R,w_h,tier，与 dense 对照得到真实 per-tile error，加入 temporal-consistency risk 项。Minimum Experiment → 先固定 Hunyuan 540p 的 20 个基础 prompt，各生成 5 个运动强度变体；每个固定 3 seeds；跑 dense、Triage π=.15/.3、always-refine-high-motion 三组；输出按时间的 LPIPS、subject consistency、局部光流偏差、E2E 时间。Model → HunyuanVideo，Blackwell GPU。Dataset → 自建 100 prompt 运动扰动集 + Penguin 视频提示子集。Baseline → Dense FlashAttention、SpargeAttn、Triage。Metric → temporal LPIPS、identity consistency、PSNR、per-step error、wall-clock。Expected Contribution → 视频加速算法的语义失效 benchmark 与鲁棒路由。Risk → motion 评测指标本身有噪声，稀有事件难覆盖。Collision Risk → 中高：与 temporal-aware sparse attention、motion-based frame selection 有重叠，需证明是新 failure mechanism。

17. 方向专用：Video / Inference / Attack

加速发生在何处？ 视频生成的 DiT self-attention（主要是 sparse denoising steps），不是 VAE decode、text encoder、模型权重量化或减少 diffusion steps。是否 retraining？ 不需要；但需要新的 CUDA kernel 和 Blackwell。是否 query-aware？ router 对当前 Q/K 的统计做动态选择，因此对输入状态敏感；它不是面向自然语言问题的 query-aware Video QA。long-video 是否有效？ LTX 186K tokens 和 Hunyuan 119K 显示长序列下仍可加速，但未证明无限长 streaming 或在线 agent workload。batch-size scaling？ Not Reported。KV cache / TTFT / TPOT？ 此处是 diffusion 生成，不是 autoregressive LLM decode；这些指标不直接适用，不能强行填造。FLOPs vs wall-clock？ 论文同时报告两层时间，且预处理开销明确计入，真实 E2E 最高 2.32×，而不是 kernel 的 9–13×。

Attack / Verification Lens： 可针对 router 的高斯近似构造 outlier key/value、跨帧低 mass 高语义影响 tile、聚类边界抖动等 stress test；black-box probe 可固定 seed 比较 dense/accelerated 的视频时序质量，但无法从外部准确识别哪个 tile 被 skip。可以定义 Quality Drop per Saved GPU-second、Critical Event Miss Rate、Worst-5%-Prompt Temporal Drift 等指标。若将它迁移到 Agent video workload，应验证模型对安全关键事件（红灯、行人突然出现）的漏检风险，而非只追求平均 PSNR。

18. 如果只记住这篇：9 句话

Triage 解决的是视频 DiT attention 的计算精度分配。它不删帧，也不缩短 diffusion steps。它将每个 attention tile 分成 skip、skim、refine 三档。路由器估计的是误差减少，而非只看 attention mass。skip 用均值 virtual tile 保留近似贡献。refine 用三次 NVFP4 乘积补偿量化残差。单个融合 kernel 是理论收益转化为真实速度的关键。五个 setting 的最佳 E2E 加速是 1.38–2.32×，但未报告 FLOPs、GPU 峰值显存和吞吐。最值得迁移的是“按下游任务效用而非代理数值误差购买计算预算”。

Cross-Paper Synthesis · 从“算得更多”转向“计算预算应该给谁”

1. 今天两篇共同说明的趋势

FOCUS 与 Triage 分别来自长程 Agent RL 和视频 DiT 推理，看似毫无关系，实际上共享一个优化范式：把昂贵操作拆成可选择的单元，先估计每单位额外计算的边际收益，再把预算分配给最值得处理的单元。 FOCUS 的单元是可恢复 Agent 状态，额外计算是一条 suffix rollout，收益代理是 critic MSE 的预期下降；Triage 的单元是 query–key attention tile，额外计算是从 skip 升到 skim/refine，收益代理是 attention output error 的预期下降。两者都不是“对所有样本平均加算力”，而是“让控制器选择”。

关键差异同样重要。FOCUS 的 reward 来自真实任务结果（尽管有 judge），但 critic 的 g 是间接代理；Triage 的 Ẽ 是更局部的数值误差代理，与视频质量之间隔着整个 DiT 去噪过程。这构成研究问题，不构成已经被证明的学术 Collision：代理误差改善是否一定带来下游任务效用改善？ FOCUS 的 SARA-N/Hard 子集负增益和 Triage 的 VBench 平均值几乎不变，都提醒我们不要把代理目标与最终能力画等号。

3. Combined Research Opportunities：优先做哪一个

Opportunity A（最优先）：Verified Marginal Utility Router。 从可控制的 Video QA 或 Computer-use Agent 开始，把 action/memory/frame 视为预算单元。训练一个轻量 surrogate 预测“再读取这个证据/再精修这个 tile/再做一次 rollout”会增加多少最终正确率，并用少量 verifier 调用校准它。目标是最大化 E[Δtask_success]/ΔGPU_second，与纯 entropy、纯 attention mass、FOCUS g、Triage Ẽ 对比。最低实验可用 100–300 个固定任务、四档预算、配对 seed、至少三种 proxy，报告 Accuracy–Latency Pareto、最坏 10% 样本和校准误差。新意必须落在下游效用验证与真实成本闭环，否则只是两种已有 heuristic 拼接。

Opportunity B：Proxy-Utility Misalignment Benchmark。 专门找“critic MSE 降了但任务成功率没升”“attention L2 降了但关键事件被漏掉”的反例。Agent 侧用污染记忆、过早提交、工具错误反馈；Video 侧用运动突变、物体遮挡、身份交换、文本细节。记录 proxy rank 与真实 outcome rank 的 Spearman、top-k 选择 regret、worst-case quality drop。它更适合作为 benchmark/attack/evaluation paper，计算门槛可能低于从零写 FP4 kernel。

Opportunity C：Cost-Aware Adaptive Fidelity for Streaming Agents。 将 Triage 的分档思想用在 Agent 感知：普通帧低精度/缓存复用，关键事件精修；同时让 FOCUS-style verifier 决定哪些状态值得重新感知。必须验证端到端任务成功率、TTFT/帧到决策延迟、显存峰值与工具错误传播。单纯降低视觉 tokens 不足以证明更好。

4. Collision / Overlap：需要提前规避什么

已有方向的重叠： FOCUS 本身明确讨论 TRACE、VinePPO、Tree-GRPO、PaTR、IGRPO 等预算与分叉方法；Triage 明确对比 SpargeAttn、SVG-EAR、SageAttention3、Sol-Attn。跨论文组合如果只把 FOCUS 的 g 换成 g/cost 或把 Triage 的 Ẽ 换成一个任务得分，创新风险很高。本日报识别的 strongest potential collision 是“proxy score vs downstream utility”：这是两篇共同暴露的潜在研究空缺，而非已有第三篇论文已被证实抢先。需要在立项前检索 task-aware sparsity、cost-aware rollout、calibrated adaptive compute 与 causal credit assignment。
