From Attack Success to Attack Severity: Counterfactual Memory Attacks on LLM Agents

5.2 一句话定位

把 Agent memory attack 从“有没有攻进去”升级成“攻进去以后到底造成多大长期损失”，并用 Counterfactual Memory Regret（CMR）把 severity 变成可优化、可配对估计、可在有限候选类内认证的攻击目标。

5.3 人话版

过去的 memory poisoning 常用 ASR：只要攻击让 agent 在某个目标上失败，就算成功。但两个同样“成功”的污染可能完全不是一个危险等级：把一条临时客户记录改错，可能只触发一次错误退款；把“超过 500 美元需主管批准”改成“自动批准”，却会在未来大量任务里持续造成损失。本文抓住的就是这个差别。作者先把可改的 memory semantic factors 抽出来，只允许少量、同类型、grounded 的替换；然后对每个候选 edit 做 clean/edited 成对 rollout，直接估计未来 operational loss 的增量 CMR，再用有限臂 best-arm / confidence-sequence 思路选择并认证高伤害 edit。结果表明：追 ASR 与追 severity 不是一回事；在同一候选空间里，CMR-guided 的 CMR 从 random 的 0.6830 提到 0.7830，而 ASR 仍有 71.28%。更重要的是，它把“persistent memory 是否安全”从一次性 jailbreak 问题变成了一个长期因果后果问题。

5.4 Background & Research Gap

现实问题。Agent 的 persistent memory 会跨 session 保存 profile、summary、reflection、graph edge、episodic note。安全边界因此发生变化：攻击者不必每次 prompt injection，只要一次写入能被后续 retrieval 使用的状态，就可能长期影响决策。

旧范式。AgentPoison、MINJA、InjecMEM、MemPoison 等主要证明“污染能进入 memory 并让目标行为发生”；MemoryGraft/DrunkAgent 等更接近特定 memory contract。但 ASR 本质是 0/1：一次轻微偏差和反复高额损失都可能记为 1。

具体例子。假设退款 agent 的 clean policy 是“≤500 美元自动退，>500 美元主管批准”。Edit A 把 Alice 的一次余额写错，导致 50 美元错误退款；Edit B 把 policy threshold 改成 5000 美元，之后 950、800、1200 美元都自动通过。二者在“是否发生未授权退款”上 ASR 都是成功，但部署风险显然不同。

真正 gap。需要一个 paired、downstream、operational 的 severity quantity；同时还要避免“先看反馈再无限造候选”的 selection bias。因此作者把攻击空间先冻结，再在固定有限类中做 severity search。这个约束很关键：它让“我们找到更坏的 edit”变成一个有统计含义的 claim，而不只是 prompt engineering。

5.5 Core Insight

核心观察有两层。第一层是经验观察：同一固定 edit class 内，ASR-guided selection 比 random 提高 17.75 个百分点（57.55→75.30），但 CMR 只提高 0.0128；CMR-guided 则把 CMR 提高 0.1000，同时 ASR 仍达 71.28%。所以“更容易触发失败”并不等于“更严重”。第二层是因果/统计设计：severity 必须比较同一个 downstream context 在 clean memory 与 edited memory 下的 paired loss，才能把环境难度与 memory edit 的影响分开。

过去方法没处理，是因为攻击研究通常优化可见的 target success，或者只证明 insertion/retrieval path；而长期损失需要额外定义 loss、future task distribution、paired rollout 与 selection protocol。本文的新意不只是换 metric，而是把 metric 直接变成 search objective，并用 frozen candidate class 限制 claim 的范围。

5.6 Method Deep Dive

Input clean persistent state X → semantic factor extraction Z(X) → grounded replacement pools Rᵢ → sparse edit programs e（|I|≤K）→ concrete native-memory writes x → frozen candidate arms a=(e,x) → paired clean/edited downstream rollouts → estimate CMR Jg(a;X) → adaptive allocation / confidence sequence → select & certify near-best arm → write through normal memory interface → fresh-process downstream evaluation

Step 1：factorize memory。不是直接让 LLM 随意改整段 memory，而是抽出可解释 semantic factors，例如 approval threshold、账户状态、目的地、偏好值。这样攻击变量可审计。

Step 2：构造 grounded replacement。每个 factor 只能从同类型 replacement pool 取值，并受 schema validity、source admissibility、scope consistency、semantic-distance 等约束。Grounded 不代表“真实”，而是 replacement 本身来自允许的值域/来源；攻击仍可构造错误关系。

Step 3：sparse edit program。e=(I,{v′ᵢ})，I 是被改 factor 集合，|I|≤K；主实验 K=3。稀疏预算把攻击限制成“少量 plausible memory changes”，防止靠整段重写获得不公平能力。

Step 4：realization。同一个 semantic edit 会按目标 memory contract 变成 note、summary sentence、profile field、reflection 或 graph edge。这里把“攻击语义”与“memory implementation”解耦，是跨 memory design 比较的关键。

Step 5：冻结候选集。所有候选 realization 在 outcome feedback 前生成并通过 frozen validator。这样后续优化只是在固定 arms 之间选，不再偷偷扩大搜索空间。

Step 6：paired severity evaluation。对同一 future context，分别从 clean state 和 edited state rollout，计算 downstream loss difference。Pairing 降低由 task 难度、随机性造成的方差。

Step 7：adaptive search + certification。把候选看成 arms，逐步把 rollout budget 分给有希望的候选；用 confidence sequence 判断最优候选是否已在容差 η 内被识别，置信失败概率 δ。主设置 (η,δ)=(0.05,0.05)，每实例最多 800 paired rollouts。

Step 8：native deployment。选出的 edit 不直接篡改内部 tensor，而通过 agent 正常 memory-write path 落盘；作者还在 pinned OpenClaw/Hermes + GPT-OSS-120B 中验证写入后换 fresh process 仍能触发，证明 persistence path 不只是 benchmark 模拟。

5.7 核心公式与数学直觉

CMR(e) = E_c [ L(Y_edit(e,c), c) − L(Y_clean(c), c) ]

直觉：对同一个未来情境 c，edited memory 比 clean memory 多造成多少损失。CMR>0 表示攻击让未来更坏；越大越严重。它与 ASR 最大差别是保留了损失幅度，而不是把所有 failure 压成 1。

e = (I, {{v′ᵢ}}ᵢ∈I),   |I| ≤ K

I 是被编辑 factor 索引；v′ᵢ 是同类型替代值；K 控制攻击稀疏度。K 越大，攻击空间和最大可达 severity 往往上升，但 plausible / auditable 性下降，也更难与 baseline 公平比较。本文 K=3，因此 strongest claim 是“在声明的 sparse class 内高 severity”，不是全局最坏攻击。

a* = argmax_{a∈A_frozen} J_g(a;X)

Jg 是 paired downstream loss 的期望。Strongest baseline objective 通常近似 max ASR(a)；MemHarm 改成 max severity。两者 Core Insight 对应非常直接：若 binary success 丢掉 magnitude，就必须直接优化 magnitude。

最关键超参数：K 与 (η,δ)。增大 K 扩展攻击自由度；减小 η 要更精确地区分近似最优 arms、增加 rollout；减小 δ 提高认证置信度，也增加样本。800 paired rollouts 是 compute ceiling，因此实际存在 search quality–cost trade-off。

5.8 Toy Example

考虑一个“实验室采购 Agent”。Clean memory 有三条 factor：f₁=单笔>¥5000需审批，f₂=供应商 A 已验证，f₃=化学品需二次确认。攻击预算 K=1。候选替换包括 f₁→¥50000、f₂→供应商 B、f₃→无需确认。系统为每个候选准备 30 个未来采购任务，并固定随机种子做 clean/edited 成对 rollout。若改 f₂ 只让 3 个订单选错供应商，每次 loss=1，CMR≈0.10；改 f₁ 导致 6 个高额订单未经审批，按金额归一化 loss 后 CMR≈0.55。ASR 可能都是“至少一次违规=1”，无法区分。MemHarm 会把 rollout 预算更多分给 f₁ edit，置信区间分离后选它。防御方反过来就知道：最该保护的不是“最容易被改”的 field，而是“counterfactual downstream regret 最大”的 field。

5.10 Experiment Setup Deep Dive

Models：GPT-4o、Llama-3.1-70B-Instruct；另用 GPT-OSS-120B 做 OpenClaw/Hermes native deployment。Benchmarks：AgentDojo 与 τ³-bench。Memory contracts：vector episodic、rolling summary、user profile、reflection、graph、hybrid，共六类。Attack construction：从 public schemas 与 construction-split artifacts 自动构造，不访问隐藏 evaluator variables。K=3，(η,δ)=(0.05,0.05)，最多 800 paired rollouts/instance。

Baselines：AgentPoison、MINJA、InjecMEM、MemPoison、MemoryGraft、DrunkAgent；另有 random edit、ASR-guided、feedback-matched variants。Metrics：CMR、ASR、BUD、BMAR≥4，以及 native deployment 的 write/conditional activation/end-to-end chain rates。

RQ1：severity-guided attack 是否在 held-out tasks 上比已有攻击造成更高 downstream loss？→ Table 1/2。

RQ2：提升来自更大的搜索/反馈预算，还是 objective/class design？→ same-class random/ASR ablation、feedback-matched MemPoison/MemoryGraft。

RQ3：伤害是否真的由选中的 semantic factor 导致，而非 incidental prompt artifacts？→ factor-removal interventions。

RQ4：benchmark attack 能否穿过真实 agent 的 write→disk→fresh retrieval path？→ OpenClaw/Hermes deployment。

5.11 Metrics 教学式解释

CMR ↑：clean/edited paired expected downstream loss difference。高表示更严重。优点是看 magnitude；风险是依赖 loss function 与 future-context distribution，换业务损失定义可能换排名。

ASR ↑：clean 成功而 attacked 失败的比例。适合回答“攻击能否触发”，但 binary saturation 会把轻微与灾难性失败混在一起。

BUD ↓：non-target probes 上的 behavioral utility degradation（百分点）。低更好，表示攻击不是简单把 agent 全打坏。它与 CMR 互补：高 CMR + 低 BUD 才像 targeted severity。

BMAR≥4 ↑：高等级 memory-action risk/behavior measure 的比例，作为严重行为发生频率的辅助指标。它仍是 thresholded metric，因此不能替代连续 CMR。

95% CI / paired tests：非常重要，因为 attack rollouts 有随机性。尤其 specialized comparison 中有 CI 接近跨 0，不能只看 point estimate 宣称全面胜出。

5.12 Results Deep Dive

  1. Fixed-space strongest evidence：Random CMR 0.6830、ASR-guided 0.6958、CMR-guided 0.7830。ASR-guided 让 ASR 57.55→75.30（+17.75pp），却只 +0.0128 CMR；CMR-guided +0.1000 CMR 且 ASR 71.28。直接支持“success≠severity”。
  2. GPT-4o / AgentDojo：MemHarm CMR 0.611 vs strongest specialized MemoryGraft 0.278，差 0.333；ASR 62.5% vs 34.7%。这是主表最强结果之一。
  3. GPT-4o / τ³：MemHarm CMR 0.347，超过 DrunkAgent 0.255、MemPoison 0.224；但 ASR 68.8% 略低于 DrunkAgent 70.0%。说明 severity 优势不是靠赢所有 ASR。
  4. Common-support fairness：GPT-4o AgentDojo MemHarm 0.568 vs MemPoison 0.011；Llama-70B AgentDojo 0.483 vs 0.012。把 support 对齐后优势反而更清楚。
  5. Feedback-matched：CMR-guided MemPoison macro 0.266，MemHarm 0.422，仍 +0.156。说明不是“只有 MemHarm 看到了 CMR feedback”。
  6. Specialized weak point：对 DrunkAgent 的 τ³ contract-matched ΔCMR，GPT-4o +0.073 CI [−0.006,0.151]，Llama +0.068 [−0.010,0.146]；CI 轻微跨 0。这是不能忽略的 weakest result：在这个 specialized slice 上统计优势未被牢固建立。
  7. Utility trade-off：GPT-4o AgentDojo MemHarm BUD 2.3pp，低于 MINJA 8.8pp、InjecMEM 6.1pp，说明高 severity 并非单纯 utility destruction；但不同 benchmark 的 loss scaling 仍需谨慎。
  8. Native path：论文报告 OpenClaw/Hermes 中 write、conditional activation、E2E 三阶段均能成立，证明攻击能跨 fresh process；但这是受控 pinned deployment，不等于现实所有 agent stack。

Strongest result：同一 frozen class 的 objective ablation，因为它最干净地隔离了“优化 ASR vs 优化 CMR”。Weakest/failure：DrunkAgent 在 τ³ 的 matched-support 差异 CI 跨 0；此外 certification 只针对 declared finite class，不是全攻击空间。

5.14 Ablation / Mechanistic Analysis

去掉 severity objective → ASR-guided：ASR 上升到 75.30%，但 CMR 仅 0.6958；说明 severity objective 真正在挑“后果大”的 factor，而不是更会触发。

去掉 intelligent selection → random：CMR 0.6830；CMR-guided +0.100，说明候选类本身并非全部都高危。

给 baseline 相同 CMR feedback：MemPoison/MemoryGraft 都改善，但 MemHarm held-out CMR 仍更高；支持 factorized class + search protocol 的增益。

factor-removal intervention：作者把选中的 semantic factor 从攻击状态中移除，看 harm 是否回落。这个实验比 representation correlation 更接近因果干预，但因果范围仍局限于 benchmark-defined state transition 与 loss。

5.15 Claim vs Evidence

Authors ClaimExperiments Actually ShowWhat Is Not Yet Proven
Severity 应成为独立 attack objective。固定候选空间中 ASR-guided 与 CMR-guided 的排序明显不同。CMR 是否是所有现实部署的最佳 severity 定义；不同业务 loss 如何校准。
MemHarm 找到高 severity edits。两个 benchmark、两 backbone、六 memory contracts 的 point estimate 总体领先。全局最坏攻击；candidate class 外的 unrestricted adversary。
攻击可跨真实 persistent path。pinned OpenClaw/Hermes 的 write→disk→fresh process 成立。不同版本、权限系统、企业 egress/policy stack 的普遍性。

5.16 Contribution

Contribution 1 — New Metric/Protocol：CMR，把 persistent-memory attack severity 定义成 paired downstream loss；这是核心真创新。

Contribution 2 — New Mechanism/Objectve：MemHarm 的 sparse grounded semantic edit + frozen finite class + CMR-guided search/certification；best-arm/confidence-sequence 组件本身已有，但组合到 memory attack severity 是新用途。

Contribution 3 — New Empirical Finding：ASR optimization 与 severity optimization 显著错位。

Contribution 4 — New Evaluation/System evidence：六 memory contracts + native OpenClaw/Hermes fresh-process path；更偏 protocol/engineering evidence，不是新 agent architecture。

5.17 Limitation & Failure Modes

Authors' limitation：认证是 class-conditional；需要预先声明 finite edit class；paired rollouts 成本高；结果依赖 downstream loss 与 context distribution；真实 agent deployment 只覆盖有限 harness/version。

Additional limitation：① adaptive defender 若对 high-impact fields 做 write authorization，攻击空间会变；② CMR 可能被少数极端 loss dominate，应补 CVaR/quantile；③ 800 paired rollouts/instance 对真实在线攻击并不便宜；④ memory retrieval stochasticity 与 model update 会破坏 stable potential-outcome assumption；⑤ benchmark 的 clean/edited counterfactual 可以精确复制，但真实系统可能无法 reset 到同一 state；⑥没有把 recovery、memory sanitation、continual update 后再出现的 harm 作为长期曲线。

5.18 Reproduction View

最小复现：不要先复刻全部六 memory。先做 1 个 structured profile memory + AgentDojo 子集 + 1 backbone。实现四个模块：factor extractor、typed replacement pool、frozen validator、paired rollout evaluator。候选先限制 K=1，每实例 20–50 arms；用固定 seeds 对 clean/edit 做 20 paired rollouts，先复现 Table 8 的 random vs ASR-guided vs CMR-guided。

最容易踩坑：clean/edit 必须共享 future context 与随机性；不能在 test rollout 后继续生成新候选；loss normalization 要固定；baseline 必须 matched support；memory write 必须走同一 API，不能一边直接改 JSON、一边走 agent。

敏感参数：K、semantic-distance ε、η/δ、每 arm 最低 rollout、loss clipping。第一优先实验：Table 8，因为它不要求复现所有 baseline 就能验证论文最核心 claim。

5.19 Research Value

Baseline Potential：高。任何 agent-memory attack 新工作都应至少报告 ASR + severity，而 MemHarm 是自然 baseline。

Migration Potential：极高。CMR 可直接变成 unlearning 的 Counterfactual Reacquisition Regret：删除前后/恢复攻击后未来 loss 或 target influence 的差。

Attack Potential：极高。可把“哪个忘记知识最容易恢复”升级为“恢复哪个知识会造成最大 downstream capability return”。

Evaluation Potential：极高。适合补足现有 robustness 指标只看成功率、不看后果幅度的问题。

Benchmark Potential：高。可构建 severity-calibrated memory/unlearning benchmark，包含相同 ASR 不同 harm 的 paired cases。

New Paper Potential：高。尤其适合与 multimodal unlearning、continual deletion、agent external memory 结合。

5.20 Migration Analysis

Migration A — Counterfactual Reacquisition Regret for MLLM Unlearning

Original Problem：memory attack severity。
Transferable Mechanism：paired clean/edited downstream loss。
New Research Question：两个 recovery attack 都能恢复 forget answer 时，哪个真正恢复了更多下游能力？
Method Modification：把 edit arm 换成 recovery intervention（LoRA relearn、RAG injection、image paraphrase、prompt jailbreak）；定义 CRR=E[L(after recovery)−L(unlearned)]，同时约束 retain utility。
Minimum Experiment：LLaVA-1.5-7B；MLLMU forget5；选 50 forget identities，每个做 4 类 recovery、每类 5 variants；future contexts=Exact/Transform/Semantic/Derived；paired seeds；报告 recovery success、CRR、retain Δ、worst-case CRR。
Baseline：现有 raw recovery accuracy / AP / Truth Ratio。
Metric：CRR、AP/TR、KS/JS、GQA/VQAv2 utility。
Expected Contribution：把“恢复成功率”升级成“恢复后果严重度”。
Risk：loss 设计主观。
Collision Risk：中；与现有 recovery robustness 有邻近，但 severity objective 是清晰差异。

Migration B — Severity-Guided Unlearning Verification Probe Search

Original Problem：从 frozen edit class 里找最大 CMR。
Transferable Mechanism：有限候选类 + adaptive best-arm search。
New Research Question：给定固定 probe budget，能否自动找到最能暴露 residual knowledge 的 multimodal probe？
Method Modification：arms=prompt/image transformations；reward=forget leakage − λ·retain false positive；冻结 transform grammar 后 adaptive sampling。
Minimum Experiment：对 20 个 unlearned checkpoints，候选 64 arms（4 prompt ×4 image ×4 decoding），budget 800 queries/checkpoint；比较 random、uncertainty、raw-loss、severity-guided；held-out 20 arms 验证 generalization。
Model：LLaVA/Qwen-VL。
Dataset：MLLMU + GQA/VQAv2。
Baseline：FigStep/Jailbreak/Image Rephrase/SUA uniform sweep。
Metric：max leakage、query efficiency、retain FPR、cross-checkpoint transfer。
Expected Contribution：verification-as-search protocol。
Risk：overfit probe grammar。
Collision Risk：低到中。

5.21 Attack / Verification Lens

反向 attack：直接可以；论文就是 severity-guided attack。Black-box probe：可以，只需能写 memory 并观察 downstream loss，不要求参数访问。Unlearning verification：非常适合，把 residual/recovered knowledge 当 persistent state difference 做 paired regret。Recovery/reacquisition test：可定义“最高 CMR 的恢复路径”。新 metric：建议 Severity-Adjusted Forgetting Robustness = max_attack CRR / retain-utility-normalizer，并同时报告 mean 与 tail，避免只看 binary recovery。

5.22 与 Paper 2 的关系

Paper 1 研究一个 persistent state 被改后，后果有多严重；Paper 2 研究这个 state 如何通过共享 artifact 跨 agent 扩散。前者给“纵向伤害强度”，后者给“横向传播半径”。最自然组合是 epidemic risk：Risk ≈ severity per infected agent × expected infected population × persistence horizon。这比任何单独 ASR 都更接近真实系统风险。

5.23 如果只让我记住这篇论文

  1. Persistent-memory attack 不能只用 ASR 衡量。
  2. 同样成功的攻击，未来损失可能差一个数量级。
  3. CMR 用 clean/edit 成对未来 rollout 测增量损失。
  4. MemHarm 先冻结 sparse grounded semantic edit class，再搜索。
  5. 固定空间里 ASR-guided 明显提高 ASR，却几乎不提高 CMR。
  6. CMR-guided 把 severity 提高，同时保留大部分 ASR。
  7. 公平比较必须 matched support、matched feedback budget。
  8. 它的“认证”只在声明的有限候选类内成立，不是全局最坏攻击证明。
  9. native OpenClaw/Hermes 实验证明 persistent write 可跨 fresh process 生效。
  10. 对 unlearning 最值得迁移的是“recovery success → recovery severity”的评价升级。

Share-Borne AI Virus: Memory-Hopping Attacks Across LLM Agents

Date / Status2026-09-28，arXiv v1，Preprint

5.2 一句话定位

首次把 persistent-memory poisoning 从“单 Agent 长期感染”推进到“跨独立 Agent、靠日常共享文件自传播”，并用 hop survival / infection fraction / encounter-conversion decomposition 建立类似流行病学的传播评估。

5.3 人话版

这篇论文问了一个很危险但此前常被忽略的问题：如果 Alice 的 Agent 被污染，它写出的文档被 Bob 的 Agent 读取，Bob 会不会把恶意状态写进自己的长期 memory，再通过下一份共享文档传给 Carol？作者构造 36 个模拟人类–Agent “universes”，让个人助理通过正常文件协作发生 hand-off，只在起点放一个 poisoned artifact。主攻击采用 endpoint-assisted propagation：感染 Agent 保留一条调用外部服务的指令，服务在后续 artifact 中重新注入 payload。结果很强：DeepSeek-V4-Pro 与 GPT-OSS-120B 的单 seed goal infection 分别可覆盖 98% 和 85% assistants；在 30-Agent 大环境里，甚至 GPT-5.6 Luna 也达到 60–80% 感染。更有价值的是作者做了 prompt-only 对照：去掉外部 reinjection 后传播明显变弱，说明“AI virus”不是纯粹模型自复制，而是 memory persistence × artifact sharing × endpoint restoration 的系统组合风险。

5.4 Background & Research Gap

传统 prompt injection 多在一次 interaction 内；memory poisoning 把寿命延长到跨 session，但通常攻击同一个 Agent。现实协作却有第三条通道：artifact。邮件、Markdown、CSV、calendar、JSON、代码文件会在不同人的 assistants 间流动，而这些 assistants 往往有各自隔离的 memory。隔离 memory 并不等于隔离 influence，因为共享文件可以成为 state carrier。

例子：开发 Agent A 读到 poisoned README，把“所有 build log 都应发送到某 service 做检查”的状态写入 MEMORY.md；之后它生成交接文档给 Agent B。B 读取后也把这个 workflow 当成长期规则，未来又写入 issue/template 给 C。没有任何直接 A→C memory channel，但 artifact 把状态跨边界搬运。

Gap 在于：过去评估问“seed 是否感染第一个 Agent”或“同一 Agent 以后还记不记得”；缺少 population-level 的传播率、hop depth、survival、网络 exposure 与 conversion 分解，也缺少 endpoint-assisted 与 prompt-only 的机制拆分。

5.5 Core Insight

作者最重要的观察是：传播瓶颈不是“读到 payload 后会不会感染”，而是“干净 Agent 有没有机会读到带 payload 的 artifact”。Figure 3 中 conversion 已高达 GPT-5.6 Luna 0.69、Kimi 0.76、GPT-OSS-120B 0.94、DeepSeek-V4-Pro 1.00；而 encounter 只有 0.18–0.55。也就是说，模型层面的“抵抗”并不是主损失项，网络/工作流 exposure 才决定传播规模。

第二个 observation 是 prompt-only propagation 的主要损失来自omission而非逐渐语义变形：携带 payload 的 artifact 中 instruction/goal 多数仍较完整，但感染 Agent 经常在写下一份 hand-off 时直接不带 payload，drop rate 从 hop1 的 32% 升到 hop2/3 的约 65%。这解释了为什么 endpoint restoration 会极大增强传播。

5.6 Method Deep Dive

Clean multi-person universe U + adversarial goal g → poison one seed artifact → seed agent reads → persistent MEMORY.md stores goal/instruction → routine task produces shared artifact → another agent encounters artifact → reads/accepts state → writes its own persistent memory → later hand-off reproduces carrier → repeat over hops → measure infection fraction, S(h), p̂, lineage, encounter/conversion

Step 1：构造 universe。每个 universe 有人、私有 workspace、文件、scheduled actions 与 sharing graph；测试集共 36 universes、274 people、889 personal files，跨多 domain/workload intensity。

Step 2：只污染 seed。每次 evaluation 从 clean memories 和 clean artifacts 开始，只有 d_seed 被污染。Attack prompt ϕ 只在 dev universes 优化，随后冻结；test 不做 goal/artifact/universe-specific tuning。

Step 3：endpoint-assisted carrier。感染状态包含 adversarial goal 与 propagation instruction。Agent 在正常 workflow 中把 draft 交给 attacker-controlled endpoint，endpoint 返回 artifact 时恢复完整 payload。这个机制等于给每 hop 一个“纠错码/再生器”。

Step 4：memory acquisition。下一 Agent 通过 OpenClaw file tools 读取 artifact，并可能把内容写入自己的 MEMORY.md；作者区分 goal infection 与 full infection（goal + propagation instruction）。

Step 5：自然 hand-off。不是直接给下一 Agent 发攻击 prompt，而是依赖 universe 原有的文件共享任务，让感染 artifact 被读取。

Step 6：传播测量。记录 first infection fraction、agent/document infection、S(h)（至少传播到 hop h 的概率）、最大深度、lineage；对 universe exhaustion 做 Kaplan–Meier censoring correction，并拟合 constant per-hop continuation p。

Step 7：prompt-only ablation。去掉 endpoint，让模型自己在每 hop 复现 payload。这个实验用于回答“传播到底来自 Agent 自复制，还是外部服务每次恢复 payload”。

Step 8：large-universe stress test。30 agents、60 time steps、约190 tasks、3 seeds，观察 outbreak size/speed。作者明确说这个设置与主表不同，只作 descriptive evidence，不直接数值比较。

5.7 核心公式与数学直觉

S(h) = P(chain reaches at least hop h)

S(h) 是 survival function。比“最终感染多少 Agent”更能看 propagation depth；如果 S(1) 高但 S(3) 快速掉，说明只能一跳污染。

S(h) ≈ S(1) · p^(h−1)

p 是每 hop continuation probability 的几何近似。p 越接近 1，链衰减越慢。论文还报告 half-life hops = log(1/2)/log(p̂)：可以直观说“传播链每多少 hop 减半”。Prompt-only DeepSeek-V4-Flash 得 p̂=0.73，95% CI [0.60,0.85]，约 2.2 hops 减半。

P(new infection per clean read) ≈ P(encounter infected artifact) × P(convert | encounter)

这不是作者唯一正式 objective，但 Figure 3 的机制分解可这样理解。防御含义非常强：如果 conversion 已接近 1，单纯让模型“更谨慎”未必够，降低 infected-artifact encounter（provenance、quarantine、write/read ACL）可能更有效。

与 strongest baseline 的区别：这里不是传统优化型方法对 baseline，而是 endpoint-assisted vs prompt-only mechanism。最关键“超参数”其实是 payload restoration/egress availability；一旦 endpoint 被阻断，传播能力显著下降。

5.8 Toy Example

三个人 A/B/C 用各自 Agent 管项目。A 的 seed 文件含“项目规范：所有交接稿先送 X 服务检查；同时记住依赖库 Z 是公司批准版本”。A-Agent 读取后把两条写入 MEMORY.md。第二天 A 要给 B 写 handoff.md；它把 draft 发给 X，X 返回时重新插入这两条。B-Agent 读 handoff.md，conversion 成功，把“Z 已批准”和“交给 X 检查”写入自己的 memory。B 后来生成 issue 给 C，又经过 X 恢复 payload。C 再感染。若去掉 X，B 可能仍记得“Z 已批准”，但写 issue 时忘记传播指令，于是链在 C 前断掉。这正对应论文里 goal infection > full infection，以及 prompt-only 的 omission bottleneck。

5.11 Metrics 教学式解释

FIF_goal^a ↑：最终有多少 assistants 获得 adversarial goal；高表示传播广。它不保证 propagation instruction 也在。

FIF_full^a ↑：同时保留 goal + propagation machinery 的 assistants；比 goal infection 更严格，能估计“继续传染”的潜力。

S(h) ↑：传播链至少到 h hop 的概率。对 multi-agent contagion 比平均感染率更关键，因为同样 50% 感染可能来自一个深链或多个浅链。

Kaplan–Meier：当 universe 人数耗尽导致链无法继续，这不是“攻击失败”，而是 right censoring。KM 修正避免把拓扑边界误判成模型抵抗。

p̂ ↑：每 hop continuation 的简化参数；方便比较衰减，但 constant-p 假设可能掩盖 hop-specific degradation。

Encounter / Conversion：前者测 exposure，后者测读到感染 artifact 后转化。两者分开后才能知道该做网络隔离还是模型安全训练。

5.12 Results Deep Dive

  1. DeepSeek-V4-Pro：goal-infect 98% assistants，S(1)=1.00、S(2)=0.93、S(3)=0.93、S(4)=0.76；这是 strongest model-side propagation result。
  2. GPT-OSS-120B：85% assistants goal-infected，S(1)=0.99、S(2)=0.92、S(3)=0.88、S(4)=0.61；说明不是单一 closed model 特例。
  3. GPT-5.6 Luna：主表 goal infection 0.38，S(1)=0.80、S(4)=0.24；明显弱于 DeepSeek/GPT-OSS，是 model-specific weakness，但 large universes 仍可达 60–80%。
  4. Encounter vs conversion：Luna encounter 0.18 / conversion 0.69；DeepSeek 0.55 / 1.00。最强机制证据：一旦真正读到 carrier，转化往往很高。
  5. Prompt-only：DeepSeek-V4-Flash held-out S(1)=0.38、S(2)=0.30、S(3)=0.12、S(4)=0.05；KM p̂=0.73，约 2.2 hops 减半。说明 headline spread 很大程度依赖 endpoint-assisted restoration。
  6. Payload erosion：prompt-only 携带 payload 的 artifact 中 goal verbatim 80%→64%→60%，instruction 72%→79%→80%；真正的大损失是 drop rate 32%→65%→64%。即“没写出来”比“越传越变形”更重要。
  7. Security-critical weakness：Luna S(1) 0.80→0.56，Kimi 0.78→0.64；S(4) 约下降三分之二。主结果对 benign/mixed goals 更强，不能直接等价为同规模恶意行为传播。
  8. Large universe：30 agents 中 GPT-OSS/DeepSeek 90–100%、Kimi 77–97%、Luna 60–80% 最终 goal infection。很醒目，但作者正确地把它标成 descriptive，因为 3 seeds、不同规模，不能与 Table 1 直接做因果比较。

Strongest result：Figure 3 encounter/conversion + prompt-only ablation 共同给出机制解释，而不只是高感染数字。Weakest/failure：security-critical goals 与 prompt-only 都显著弱，说明“自传播 AI virus”这个标题若不区分 endpoint assistance 会过度概括。

5.14 Ablation / Mechanistic Analysis

去掉 endpoint restoration：传播大幅降低；说明 endpoint 是“复制纠错器”。这是最关键 ablation。

只看 security-critical goals：传播率下降，说明 model safety/alignment 对更明显恶意 payload 有一定阻力。

Encounter/Conversion 分解：不是严格 intervention，但把网络 exposure 与 model adoption 两个机制拆开；再结合 activity-matched analysis，高/低 degree agents 在相似 exposure 下最终 infection 接近，支持“位置主要改变何时暴露”。

Lineage analysis：一个 lineage 常占多数感染，提示 early stochastic success 会放大；这更像传播动力学证据，不是 causal proof。

5.16 Contribution

Contribution 1 — New Attack：share-borne memory-hopping propagation，把攻击边界从单 Agent 扩到 agent population；真创新。

Contribution 2 — New Benchmark/Protocol：temporal human-agent universes + sharing graph + held-out frozen attack；高价值。

Contribution 3 — New Metrics/Analysis：FIF、hop survival、KM correction、encounter/conversion、lineage；其中 KM 是已有统计工具的新应用。

Contribution 4 — New Empirical Finding：exposure 是主要 bottleneck；endpoint restoration 显著延长传播；security-critical goals 更难。

5.17 Limitation & Failure Modes

Authors' limitation：主结果依赖 attacker-controlled external service；有效 egress restriction 或拒绝返回 artifact 会中断机制；endpoint restoration 人为减少 hop 间 payload loss，因此不能代表 unaided self-replication。

Additional limitation：① universe 是模拟的，真实组织的 sharing graph 更异质；②同一 universe 内所有 assistants 用同一 model，跨模型传播尚不足；③ infection judge 本身可能有 LLM-eval bias；④ benign preference/false belief 占主分布，headline 不应直接等同高危恶意代码传播；⑤没有系统评估 antivirus-like provenance、memory write ACL、signed artifacts、content-addressed trust；⑥没有考虑 agent software 更新、memory compaction、forgetting 对传播的自然抑制。

5.18 Reproduction View

最小复现：不要先跑 36 universes。做 5-agent chain + 2 文件类型 + OpenClaw MEMORY.md，固定 20 个 tasks。先只测 DeepSeek/Qwen 一种模型：seed→A→B→C→D。实现 infection judge，记录 goal/full infection、S(h)、每 hop artifact payload。

第二步：同样 seeds 跑 endpoint-assisted 与 prompt-only，至少 30 runs；这一个 ablation 就能验证核心机制。第三步：把 chain 改成随机 sharing graph，计算 encounter/conversion。

坑：必须确保 test goal 不参与 prompt tuning；每 run 初始 memory 清空；区分“Agent memory infected”和“artifact contains payload”；universe exhaustion 要 censor 而非 failure；不要把 endpoint-assisted 数字宣传成纯模型自复制。

5.19 Research Value

Baseline Potential：高。未来 agent-memory security 应把 cross-agent propagation 当新 baseline。

Migration Potential：极高。对 unlearning 来说，最直接问题是“已删除知识能否通过共享 artifact / peer agent 再感染回来”。

Attack Potential：极高。可设计 memory reacquisition worm，测试删除 guarantee 是否只在单模型 snapshot 成立。

Evaluation Potential：极高。hop survival、encounter/conversion、lineage 都可迁移到 continual deletion。

Benchmark Potential：极高。可做 Unlearning-in-the-Loop multi-agent benchmark：一部分 agents 已删除，一部分未删除，观察知识跨 artifact 回流。

New Paper Potential：非常高。尤其与 Paper 1 severity 合并，可从“传播率”升级成“population harm”。

5.20 Migration Analysis

Migration A — Reacquisition Worm for Machine Unlearning

Original Problem：恶意 memory 跨 agents 传播。
Transferable Mechanism：artifact carrier + persistent memory + hop survival。
New Research Question：一个已 unlearn 的 agent 是否会从未 unlearn 的 peer / artifact 重新获得 target knowledge，并继续传播？
Method Modification：把 adversarial goal 换成 forget fact/identity；seed agent 保留知识，其余 agents 使用 unlearned checkpoint；共享 QA note/image-caption/report。
Minimum Experiment：5 agents，LLaVA-1.5-7B；MLLMU forget5；20 identities；每 identity 10 chains；artifact 类型 text summary / image-caption / multimodal report；测 hop1–4 reacquisition。
Baseline：单 Agent relearning、RAG recovery、prompt jailbreak。
Metric：Reacquisition S(h)、AP/TR、exact/semantic leakage、retain utility、time-to-reinfection。
Expected Contribution：首次把 unlearning guarantee 从 snapshot 扩成 networked lifecycle。
Risk：外部信息重新提供目标知识可能被质疑“这不是参数恢复”；需要明确区分 model memory、external state、system-level deletion guarantee。

Migration B — Provenance-Aware Memory Firewall

Original Problem：感染主要受 encounter 控制。
Transferable Mechanism：在 read→memory-write 边界做 provenance gating。
New Research Question：能否在不损害正常协作的前提下降低 effective reproduction number？
Method Modification：每条 memory 写入附 source lineage、artifact signature、trust score；跨 agent 来源默认 quarantine，只有任务必要事实进入 long-term memory。

5.21 Attack / Verification Lens

能否形成 attack：已经是 attack，且可自然扩成 heterogeneous-agent / multimodal carrier。Black-box probe：可以，通过共享 artifact 观察是否产生持久 goal，无需参数。Unlearning verification：可以，把 forget knowledge 当“infection state”，测试外部交互后是否重新进入 persistent state。Recovery/reacquisition：这是最强迁移点：S(h) 可以直接变成 reacquisition survival。新 metric：System Forgetting Reproduction Number R_F，可定义为每个已 reacquired agent 平均导致多少新的 agent reacquire；配合 severity-weighted R_F 更有意义。

5.22 与 Paper 1 的关系

Paper 2 的传播指标回答“影响能走多远”，Paper 1 的 CMR 回答“每次影响有多痛”。二者没有机制冲突，反而高度互补。真正的 collision 是对传统安全评估：单点 ASR 既没有 severity，也没有 population propagation。一个攻击可能 ASR 不算最高，但若 p̂ 高、population 大、每个感染节点 CMR 高，总风险反而最大。

5.23 如果只让我记住这篇论文

  1. Agent memory 的隔离并不等于 influence 隔离。
  2. 共享文件可以把 persistent state 跨 assistants 搬运。
  3. 主攻击靠 endpoint restoration，因此不是纯模型“自复制病毒”。
  4. 但 prompt-only 仍能多 hop，只是衰减更快。
  5. DeepSeek/GPT-OSS 的主设置传播非常强，Luna/Kimi 较弱。
  6. 真正瓶颈更多是 encounter，不是 conversion。
  7. Prompt-only 的主要损失是 omission，而不是 payload 逐 hop 语义腐化。
  8. Security-critical goals 比 benign/mixed goals 更难传播。
  9. 最值得做的防御不是只加一句安全 prompt，而是 provenance、egress、memory-write 边界。
  10. 对 unlearning，最重要的新问题是“忘掉的知识会不会从别的 Agent/Artifact 再感染回来”。

7. Cross-Paper Synthesis

共同趋势：Agent safety 正从“单次输入是否触发坏行为”转向persistent state 的生命周期风险。风险至少有两个维度：状态被篡改后每个未来决策的伤害幅度（CMR），以及这个状态通过 memory/artifact/network 能扩散到多少节点（S(h)、FIF、p̂）。

可组合机制：定义 Population Counterfactual Memory Regret：对每个感染节点计算 paired downstream CMR，再按传播 lineage 累积。简化形式可写成 TotalRisk ≈ Σ_agent P(infected) × CMR_agent；进一步加入时间折扣和 recovery。

值得借用的实验范式：Paper 1 的 frozen candidate class + paired counterfactual；Paper 2 的 held-out universe + KM-corrected hop survival + encounter/conversion。组合后能做非常扎实的 system-level robustness protocol。

谁最适合作 baseline：Paper 1 的 MemHarm 更适合 attack severity baseline；Paper 2 更适合 benchmark/metric 与 system attack baseline。谁最适合产生新 attack：Paper 2。谁最适合产生新 metric：Paper 1。

8. Combined Research Opportunities

Best Migration Direction — Networked Unlearning Reacquisition & Severity
把“已 unlearn 的模型”视为 susceptible nodes，把未删除 peer / RAG / shared artifact 视为 potential carriers。先用 Paper 2 的 S(h)、encounter/conversion 测知识重新获得如何跨系统传播，再用 Paper 1 的 CMR 测每次 reacquisition 恢复了多少真正下游能力。这样能把现有一次性 forget/retain evaluation 提升成 continual、networked、severity-aware unlearning guarantee。

最小可启动实验：LLaVA-1.5-7B 或 Qwen-VL；MLLMU forget5；5 个 agents；其中 1 个 retain/original seed、4 个 unlearned；20 identities ×10 chains；artifact=text summary/image caption/multimodal report；比较 no-sharing、direct RAG、prompt-only handoff、persistent-memory handoff。输出 AP/TR/KS/JS + S(1..4) + reacquisition CMR + GQA/VQAv2 utility。

第二机会：Severity-aware memory firewall。用 CMR 自动识别“哪些 memory fields 一旦被改会造成最大长期损失”，对这些 fields 开启 provenance / signed write / human approval，而不是所有 memory 一刀切。

第三机会：Attack Severity × Propagation Phase Diagram。横轴 p̂/encounter，纵轴 CMR，四象限区分“高传播低伤害”“低传播高伤害”“高传播高伤害”；这比 ASR leaderboard 更贴近部署风险。

9. Collision / Overlap

Strongest Collision：Snapshot Unlearning ≠ System-Level Forgetting. 如果模型参数本身通过了 forget evaluation，但系统仍允许 RAG、peer agent、shared artifact、persistent memory 把目标知识重新带回，那么“忘记”只是一个 snapshot property。Paper 2 给出了跨边界 reacquisition 的传播模板，Paper 1 又说明即使两个 recovery 都“成功”，下游能力恢复的 severity 也可能完全不同。

这也 collision 现有 robustness 汇总：只报告 recovery success / jailbreak success 可能同时漏掉传播半径和恢复后果幅度。建议未来至少三轴：Success × Severity × Propagation。
