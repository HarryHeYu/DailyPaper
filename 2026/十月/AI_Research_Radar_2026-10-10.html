Today’s Most Important Paper

Recursive Self-Improvement through Multi-Agent Self-Supervision (MASS) — arXiv 2610.12176。今天最重要不在于榜单最高分，而在于它提出一个可迁移机制：优化信息交接契约，再把多 Agent 协作轨迹变成模型参数的监督。它同时给出强正证据（更高 token 监督效率、研究 benchmark 改进）和负证据（SWE-bench / Terminal-Bench 回落），便于判断研究边界。优先读：Section 3 Method、Figure 3 的跨角色/负面结果、Figure 6 的 token 效率。未来价值：Agent memory、RL credit assignment、错误传播与自动科研 workflow 的共同基础。

RL Highlights

SynCo 用独立 Synthesizer/Reasoner 的多 Agent GRPO 同时更新训练分布和推理能力：八数学任务平均 78.72，对照 Frozen Synth 75.85。关键机制是 task quality/answer reliability/teachability 与最终正确性共同反馈。ThunderSyncRL 则是另一条路线：GRPO 目标不变，把可分解的 score gradient 提前算，达到相同 SWE-bench Verified 目标用 121.3 而非 233.5 GPU-hours。前者是学习信号，后者是训练调度；两者不可把训练速度提升误说成 sample efficiency。另留意 MetaOPD 的 token weighting，但其公式和数字本轮尚未核实。

Agent / Multi-Agent Highlights

MASS 把交接契约和信息路由优化后蒸馏回共享模型，研究类 benchmark 单位输出 token 性能提高 1.2–1.6×，但 SWE-bench Verified 回落，提醒避免过度外推。VAMR 将多个视频问题共享一条工具轨迹，使用问题级 critic 和 round alignment；Hippocam 用 intent 层级和使用驱动的记忆再巩固减少长期上下文冗余。建议重点检查错误如何从共享 memory 传播到下游 Agent，而不只是平均成功率。

Video Acceleration Highlights

iCATS 是今天最扎实的视频生成系统证据：Hunyuan 1730→854 秒，SVG2 同速率下 PSNR 26.247→31.017；Wan T2V 则是 1889→1222 秒，不能只宣传最大 2×。VAMR 报告 LVBench 帧处理量 -61.4%、推理轮次 -85.9%，但尚未从本轮材料核实实际 GPU latency。FastBench 是值得追踪的高动态流式视频评估方向，具体实验数字待查。

Inference Acceleration Highlights

TokenRouter 主要优化 decode 的跨模型切换、异步调度与 batch admission；RaReCache 主要优化模型切换后的 prefill/TTFT，目标饱和负载下报告 p50/p99 TTFT 分别最多 5.0×/6.4×；VFold 通过离线对齐合并相邻层 Value，减少 25% 总 KV cache，却不能因此声称 25% latency 加速。系统设计上，三者可形成互补栈，但合并后必须实测内存、消息与重算开销。

Tier SRecursive Self-Improvement through Multi-Agent Self-SupervisionAgent / Multi-Agent2610.12176
arXiv 论文入口 · 正文来源等级：Method + Experiments 已核验

Basic Information. Hyunin Lee、Jinglue Xu、Jeffrey Seely、Donghyun Lee、Somayeh Sojoudi、Matei Zaharia、Yujin Tang；UC Berkeley / Sakana AI。2026-10-08 v1；arXiv preprint，未据此认定已被主会录用。Paper · HTML 全文（正文附官方代码链接）。

人话版：这篇论文到底干了什么？

传统自我改进让同一个模型做题、批改、再改进自己，但遇到开放式科研任务，单模型往往看不出自己犯的错。MASS 的办法不是先找更强教师，而是让同一个模型扮演多个分工明确的 Agent，自动进化“谁做什么、把什么结果交给谁”的工作流，再把成功的多 Agent 执行轨迹蒸馏回模型参数。两轮之后，研究类任务的单位输出 token 得分提高约 1.2–1.6 倍，测试任务胜率从第一轮 53.9% 升到第二轮 69.9%。最有价值的是：信息流设计本身可以成为可学习的监督信号，而不是把长链推理简单拼接起来。

Background & Gap

已有路线一是单 Agent 自反思与自训练：同一模型提出答案、评价答案并更新，容易把自身偏差循环强化。路线二是固定多 Agent workflow：能分工，但不同任务最优拓扑不同，固定角色和传递格式可能把有用信息丢掉。具体例子：量化研究需要数据处理、策略实现、回测验证。若数据 Agent 只把“收益不错”传给回测 Agent，而不传成本假设、时间切分与数据来源，后续步骤就会在错误基础上继续。论文把关键 Gap 定位在 workflow optimization 与 trajectory supervision 的联动：先发现更有效的交接，再把这种协作习惯学进权重。

Core Insight 与 Method Deep Dive

Pipeline：研究任务 → 生成 orchestrator–subagent 工作流 → 执行并产生 workspace → 同模型成对评价 → 修改工作流中的角色/调用顺序/输出契约 → 选出高质量多 Agent 轨迹 → SFT 更新共享模型 → 下一轮继续搜索。

  1. 工作流表示。 每个子 Agent 由角色 r、指令 u、输出契约 c 描述，另有调用顺序/信息路由 h。论文刻意把搜索重点放在 h 和 c，不是只换 persona 名称；因为后续 Agent 实际能看到什么，决定了任务是否可复用、可验证。
  2. 内循环进化。 固定当前模型权重，执行候选工作流，比较候选 workspace 与当前最优 workspace，由模型给出相对偏好与反馈，再修改工作流。保留最优候选的精英搜索不保证全局最优，且自评价可能偏差；作者用外部模型只做最终评估，避免训练过程直接泄漏外部评审信号。
  3. 外循环蒸馏。 每个训练任务独立执行 18 次候选轨迹，经 pairwise tournament 与 Bradley–Terry 排序，挑选优质轨迹；同时监督 orchestrator 的分派/整合动作与 subagent 的局部执行。训练目标是带 token mask 的 SFT 交叉熵：只对目标 assistant token 计算负对数似然，不把工具返回和上下文当作预测目标。其关键不是新的 RL reward，而是高质量协作轨迹的监督密度。
  4. 递归更新。 更新后的模型同时替换求解器、评估器、优化器；因此下一轮 workflow 搜索也会变化。两轮结果支持这一反馈闭环在选定任务上有效，但不能据此断言无限轮次持续增长。

Toy Example。 输入“分析一个新策略是否有真实超额收益”。初始单 Agent 可能写回测代码后直接报告 Sharpe。MASS 搜索出的流程可以是：Agent A 交付数据切分和缺失值日志 → Agent B 交付可执行策略及依赖 → Agent C 交付含交易成本与泄漏检查的回测报告 → Orchestrator 汇总并标注未验证假设。若 C 发现未来信息泄漏，评价器偏好保留证据链的版本；下一轮 c 便要求 B 交付特征可用时间。蒸馏时模型同时学习“何时委派”与“如何给出可验证产物”。这是解释性示例，不是论文原始案例的逐字复现。

Baseline Comparison 与 Setup

对照一：单 Agent 轨迹 SFT，合理但把所有局部与全局动作混在一个长序列中。对照二：固定多 Agent workflow，只能享受即时协作，无法把成功模式内化。对照三：同模型单轮 MASS，缺少第二轮递归收益。最重要的强对照是更大训练 token 预算的单 Agent SFT，因为它排除了“多 Agent 只是用了更多训练 token”这一简单解释。

基座 Qwen3.6-27B-FP8、执行器 qwen-code 0.20.0；12 个合成科研编程任务覆盖金融、机器人、药学，其中 9 个拟训练、3 个留作测试，最终 8 个进入 SFT。119 条 teacher trajectories → 2,435 windows → 17.2M supervised tokens；LoRA rank 64、alpha 128、dropout 0.05，峰值 LR 3e-5，1,624 optimizer steps。公开测试包括 ScienceAgentBench、MLR-Bench、DSBench、AstaBench、Terminal-Bench 2.0、SWE-bench Verified。外部评价用两个强模型，各 3 个随机种子，成对胜率去掉平票。RQ：训练得到的能力是否能跨求解、优化、评价三角色迁移？多 Agent 数据是否比单 Agent 更高效？

Results：数字 → 对照 → 意义

  • 测试任务胜率：第一轮相对初始模型 53.9%，第二轮相对初始模型 69.9%；第二轮相对第一轮仍有 60.8%。支持递归改进，但仅验证两轮。
  • 研究任务：MLR-Bench 从 1.58±0.38 → 2.40±0.28；ScienceAgentBench 从 28.8±1.5 → 31.7±2.0；四个研究 benchmark 的 score/output-token 约 1.2–1.6×。
  • 评估器：与外部评审的一致准确率 0.73 → 0.91 → 0.93；说明只训练执行轨迹，也可能改善评价能力，但外部评审不等于绝对真值。
  • 监督效率：多 Agent 学生用 28.82M processed supervised tokens 达到 68.3% 胜率，单 Agent 42M tokens 仅 64.0%，节省 31.4% 处理 token 且高 4.3pp；这是本文最强的机制证据之一。
  • 负面结果不能略过：Terminal-Bench 2.0 从 37.5±2.2 降到 35.2±1.7；SWE-bench Verified 从 62.6±1.4 降到 61.1±0.6。开放式研究提升没有自动转化为所有代码 Agent 能力提升。

Claim vs Evidence / Contribution / Limitation

Authors claim：多 Agent 信息流提供可递归改进的自监督。Experiments actually show：在有限合成科研任务和两轮更新下，外部偏好、训练效率及部分公开研究 benchmark 改善。Not proven：无限轮收敛、真正科学发现质量、跨领域普适性，以及在 SWE-bench 上的正迁移。

Contribution 1 [New Mechanism]：可进化的角色/输出契约/信息路由；Contribution 2 [New Objective/Training Recipe]：orchestrator 与 subagent 轨迹联合 SFT；Contribution 3 [New Empirical Finding]：多 Agent 数据在给定实验中提供更高监督效率。Authors' limitation / additional：自评误差、仅两轮、任务集小且部分私有、外部 LLM 评判偏好；长程记忆污染与错误级联缺少系统评估。

Research Value & Migration

Baseline Potential：高，可作为 multi-agent self-training 对照。Migration Potential：高，把 handoff contract 看成学习对象。Systems Value：中，多 Agent 执行更贵；Evaluation Potential：高，可设计信息流缺失与错误传播测试。New Paper Potential：中高，但需避开单纯 workflow search。

五句话总结

第一，MASS 把多 Agent 信息流变成自监督来源。第二，它通过工作流进化加 SFT 而非纯 RL 完成两轮递归改进。第三，多 Agent 轨迹的监督效率优于更大 token 预算的单 Agent 对照。第四，Terminal-Bench 和 SWE-bench 的回落提醒我们不要把研究 benchmark 改进外推到所有 Agent。第五，最值得迁移的是可验证的 handoff contract 与错误传播评估。

Tier SiCATS: Fast Video Generation via Interaction-Aware Sparse Attention and Timestep-Adaptive SparsityVideo Acceleration2610.11302
arXiv 论文入口 · 正文来源等级：Method + Experiments 已核验

Basic Information. Chengfeng Han、Baole Ai、Xianlu Bian、Jie Yao、Zilong Huang、Ang Wang、Dandan Ding。2026-10-08 v1；arXiv preprint，作者单位与代码发布状态未在本轮核实。Paper · HTML 全文。

人话版：这篇论文到底干了什么？

视频扩散模型一次生成视频要反复做注意力计算。已有稀疏注意力会跳过很多不重要的 token 对，但常见做法是先分别聚类 Query 和 Key，再猜哪些区域该计算；猜错就影响画面。iCATS 改为根据 Query–Key 的相互作用来聚类，按照去噪阶段的信噪比动态分配稀疏预算，最后把 GPU 上填不满的尾块合并。它不需要重新训练模型。HunyuanVideo-T2V-13B 的端到端生成从 1730 秒降到 854 秒，约 2.03 倍；同速率下 PSNR 从强基线 SVG2 的 26.247 提升到 31.017 dB。亮点不是单纯削 FLOPs，而是同时改进选择正确性、时间预算与硬件执行。

Background & Gap

DiT 视频生成含大量跨帧 token；密集 attention 复杂度与 token 数平方相关。SVG 等方法利用预设时空稀疏模式，SVG2 用聚类动态估计稀疏块，优点是训练自由、能直接部署，缺点有三：独立聚类不一定保持真正重要的 Q–K 交互；固定 top-p 无法适应不同去噪时刻；不规则 cluster 映射到 GPU block 后产生 padding 和 kernel 空转。具体例子：两个 Query 特征在欧氏空间很近，却分别关注运动物体和背景；若按 Query 自身相似性合并，就可能漏掉对运动边界关键的 Key 区域。

Core Insight 与 Method Deep Dive

Pipeline：预先获得噪声调度 → 按 Q–K 交互构造聚类与重要性估计 → 每个 timestep 根据 logSNR 选择 top-p → 生成稀疏注意力 mask → 合并不规则 query 尾块 → 专用 GPU kernel 计算 sparse attention → DiT 继续去噪。

  1. Interaction-aware clustering。 传统分别对 Q/K 做 k-means，优化的是各自几何距离；iCATS 改为让聚类更忠实于 QK 内积结构。论文把交互目标改写为可低成本求解的二次型，避免真的构建完整 QK 注意力矩阵，否则“为选择稀疏区域先做一次 dense attention”会得不偿失。
  2. SNR-guided schedule。 去噪初、中、末阶段对近似误差容忍度不同。令 ℓ_t = logSNR(t)，x_t = ℓ_t − ℓ_pivot，p_min 为最小保留比例，则 top-p_t = p_min + (1-p_min)[1 − sigmoid(k x_t)]（适用稀疏阶段）。pivot 从 logSNR 相邻变化最小位置自动确定，k 由初始保留阈值 τ 决定；top-p 离线算好，不引入显著在线控制开销。注意这里 top-p 是保留注意力质量的预算控制，不等于直接“保留 p% 的 token”。
  3. Tail merging。 同一 head 中若两个 query cluster 访问完全相同的 key-cluster 集，可无损合并。对于 block size 无法整除的剩余 cluster，再根据 key-mask 的 Hamming 距离寻找兼容目标，合并尾块以减少 padding；这种合并可能稍微增加理论稀疏计算，却减少真实 GPU 空转。

Toy Example。 一段 5 秒视频含 1000 个关键候选块。初期噪声大时需要较密集的全局交互，中间阶段可以只计算运动主体相关区域，末期细节又需要较高保留比例。若两组 Query 都访问同一组 Key，原本两个各占半个 GPU block 的工作可合并成一个满块。这样同时减少错误跳过与空块执行；具体数字仅为解释性示例。

人话版：这篇论文到底干了什么？

为了省推理成本，模型可以让小 LLM 生成容易的 token，遇到困难 token 才转给大 LLM。但真正部署时，一个请求可能每几个 token 就切换一次模型，传统 serving 系统每次都重新调度、匹配前缀，导致 GPU 等待与小 batch。TokenRouter 把“单请求如何选择模型”的编程逻辑和“每个模型如何批量执行”的运行时解耦：每个模型有自己的子服务器、KV 缓存和调度器，请求异步转移，等待合适时机再凑 batch。论文在多种 routing 算法与工作负载上报告相对较强服务基线 2.01–64.15× decoding throughput 提升，但这个大范围强烈依赖基线实现；更有意义的是给出具体 TTFT、吞吐和端到端延迟，证明算法上的 token 级路由，必须配套系统层面的异步调度。

Background & Gap

Query-level routing 在整个请求开始时选模型，易服务；token-level routing 可把难 token 升级到大模型，算法上更细，但模型间控制权频繁交换，造成两类开销。第一，step desynchronization：两个模型执行进度不一致，某模型等待另一模型给回 token。第二，batch admission delay：到达某模型的请求零散，立即执行导致 batch 太小；盲目等更多请求又增加等待时间。举例：4 个数学题请求同时在小模型跑，只有 1 个触发高熵转发，大模型立即处理这 1 个请求，其他 3 个稍后到达又重新启动，吞吐会非常差。

Core Insight 与 Method Deep Dive

Pipeline：请求进入 entry model → 本地 decode → route(result) 判断是否切换 → send(req) 只传对方未见过的 token suffix 与位置锚点 → 目标模型 receive(peer_req) 恢复请求 → 子服务器独立排队、异步执行与 delayed batching → 回传或继续 decode。

  1. Request-centric programming。 开发者只需实现 route / send / receive 三个操作。route 可根据 entropy、置信度或路由器输出选择 peer；send 维护请求 ID、未见 suffix 和位置锚点，避免每次重传完整上下文；receive 把 peer message 还原为本地可继续解码的状态。这是 API 抽象，不是新的 token-level routing 策略。
  2. Model-centric execution。 每个模型由独立 subserver 管理自己的 scheduler、runner 和 KV pool。请求跨模型移动，但某模型内仍可以做连续 batching 与 prefix caching。论文基于 SGLang 构建，额外优化 CUDA graph 与 handoff-resume。
  3. Delayed batching。 对小 batch 不一定马上启动 decode；调度器等待更多本地请求进入。过早执行造成低利用率，等待过久又让队列饥饿。论文使用离散时间马尔可夫链，根据并发数 N、模型间转移概率 P、各模型单步延迟 L_i，估计吞吐 Throughput(B) 并选择最大化吞吐的阈值 B*。核心超参不是随便拍的“等 5ms”，而是与路由分布及负载有关。
  4. 边界。 它优化的是跨模型 token-routing 的 decode serving，不是直接让单个 Transformer 的 attention FLOPs 减少，也不是普遍提高模型本身的正确率。质量取决于底层 routing 算法；系统主要改变调度与状态传递。

Toy Example。 4 个 Agent 请求使用 0.6B/32B 两模型。A、B 只需要小模型，C 的第 30 个 token 置信度不足，D 的第 33 个 token 也需升级。传统服务 C 一到就启动大模型，D 随后到又启动一次；TokenRouter 允许两个 peer 请求在大模型的同一批次执行，并保留各自位置锚点。返回后小模型只处理自己尚未看到的 suffix。注意真实收益取决于路由频率和并发，单请求低并发下 delayed batching 可能不划算。

Background / Method

KV Cache 使 autoregressive decode 避免重复计算历史 token，但 context×batch 增大时 HBM 占用严重。MiniCache 直接合并跨层 cache 可能损伤质量；低秩跨层方法又引入在线重构开销。VFold 首先对相邻层 Value 做 CCA 对齐，并通过 Hungarian matching 解决 KV heads 的排列问题。对于 attention head 输出 (A·V)·W_O，插入任意可逆 T 后 (A·V·T)·(T⁻¹·W_O) 数学上等价；因此可以离线把 T 融入 W_V，把 T⁻¹ 融入 W_O，不需要模型重新训练。随后对齐后的相邻层 V 做平均，只存一份共享缓存。Key 不能同样随意合并：它影响 softmax 选择，且 RoPE 限制等价变换。

Bottleneck：长上下文 Decode 的 KV 显存容量，间接影响 batch size；主要不是 prefill 算力。训练：无需微调；离线校准 CCA。Model-specific：需要访问/修改 attention 权重，GQA 有额外 head 映射。硬件：本轮未核实特定 GPU 对真实延迟的影响。

人话版：这篇论文到底干了什么？

人话版：这篇论文到底干了什么？

流式视频 VLM 往往在静态或低变化率视频上测试，看起来能实时处理，却不一定能应对高速运动、短时事件和快速切换场景。FastBench 的标题 Can Streaming VLMs Perceive High-Dynamic Real-World Streams? 直接质疑现有流式 VLM 在高动态真实世界中的感知能力。它值得关注的不是又做一个平均准确率排行榜，而是能否暴露帧选择、流式记忆更新、视觉编码延迟三者的耦合失败：跳过某一帧可能省时，却让关键事件永久丢失。

Background / Core Method

Video VLM 加速方法常把低冗余假设当作默认条件，但高动态场景的变化频率与问答证据出现时间可能高度不均匀。FastBench 从题名看是评价/benchmark 工作，而不是已证明的推理加速算法。已核实：论文在 2026-10-09 的 cs.CV recent 列表，标题与作者列表可查。未核实：benchmark 的具体构造、数据规模、模型数量、指标与结果数字；因此此处不编造数据集或所谓性能下降幅度。

Experiment / Main Finding

具体 benchmark protocols 与分数 Not Verified。建议精读时重点检查：实时流是否严格遵守因果可见性、是否允许未来帧泄漏、是否同时报告事件检测延迟与正确率、输入 FPS 与输出 token/s 如何匹配。对 Video Acceleration 而言，只有 frames/FLOPs 下降而没有实时 latency/accuracy 证据，不能说明系统真正更快更好。

Contribution（待验证）：面向高动态流的 evaluation gap。Limitation：场景采集和标注偏差可能影响泛化；高动态并不总意味着语义信息密度高。Connection：iCATS 关注生成侧 attention，VAMR 关注理解侧多问题共享；FastBench 可作为视频理解加速的压力测试。Potential Use：在固定延迟预算下比较均匀采帧、运动强度采帧、query-aware 采帧，绘制 accuracy—latency—FPS 曲线。阅读等级：SAVE，等全文核验后决定是否升级。

Idea 1 — Provenance-Grounded Credit Assignment for Multi-Agent Handoffs

RL × Agent × Memory × Failure Attribution

Inspiration：MASS 证明 workflow 的信息交接影响自监督质量；VAMR 用问题级 critic 将 advantage 对齐到实际服务问题的回合；Error-Propagation Modeling 提醒最终失败可能来自上游消息。

Gap：现有多 Agent 优化经常把最终任务成功率平均归因给所有子 Agent 或所有 handoff，难以区分“错误产生”“错误传播”“错误被修复”。Hypothesis：如果对 handoff 中每条证据维护 provenance，并用局部反事实干预估计其对最终成功的贡献，信用分配会比均匀 step reward 更准确，减少 reward hacking 和错误级联。

Proposed Method：把消息/工具输出/记忆写入表示成带时间戳的 evidence DAG；在可执行任务中随机屏蔽、替换或修复少量节点，估计 downstream value delta；训练一个轻量 handoff critic，为共享策略提供只对因果相关节点生效的 advantage；把 uncertainty 写入输出契约。

Minimum Viable Experiment：3 个角色（Planner / Executor / Verifier）完成 100–300 个可执行工具任务，在 10%/20% 回合注入可追踪错误，比较 final-only GRPO、uniform step reward、MASS 风格 workflow、provenance credit。Model：Qwen3-4B/8B；Dataset：SWE-smith 子集或自建可执行工具环境；Baseline：final reward、per-step judge、无 provenance、固定拓扑；Metric：task success、source attribution F1、error propagation depth、recovery rate、token/GPU-hour；Expected Contribution：新 credit assignment 机制 + 可控错误传播评估。

Novelty：★★★★☆　Feasibility：★★★☆☆　Compute Cost：★★★☆☆（越高越贵）。Risk：反事实重跑成本大、judge 不稳定、因果图含循环；Collision Risk：高（MASS、VAMR、Error-Propagation），必须把“有干预 ground truth 的 credit”作为差异点；Best Venue：ICLR / NeurIPS（机制+强实验）或 ACL/EMNLP（Agent 轨迹）。

Idea 2 — Quality-Gated Cross-Model KV Handoff for Long-Horizon Agents

Inference Acceleration × Agent × KV Cache

Inspiration：TokenRouter 解决 decode 时多模型间的高频 handoff；RaReCache 让小模型预填缓存供大模型使用并选择性重算；VFold 用无额外在线投影的跨层 Value 合并压缩容量。

Gap：这些工作分别解决路由调度、跨模型缓存误差和单模型层冗余，缺少针对多轮工具 Agent 反复升级/降级模型的统一状态一致性与质量门控。Hypothesis：只有在预计 TTFT 收益大于映射/校验开销、且关键工具状态被可靠保留时才复用缓存，能改善端到端任务成本而不显著损伤工具行为。

Proposed Method：在模型切换前对上下文标注 tool-state critical spans，估计 RaReCache 风格的 rank disagreement；按预计收益选择 full prefill、partial recompute 或不切换；TokenRouter 式 runtime 保持请求 ID、位置锚点与 KV 生命周期；必要时结合 VFold 节省目标模型缓存容量。

Minimum Viable Experiment：Qwen3 0.6B→14B 的 4K/16K/32K 多轮 Agent 轨迹，设置 1/4/16 并发，比较 full prefill、纯线性映射、RaReCache、TokenRouter 式异步调度、quality-gated 组合。Model：Qwen3 系列；Dataset：SWE-Smith 工具轨迹及自建跨模型升级任务；Baseline：TokenRouter、RaReCache、full target；Metric：TTFT p50/p99、TPOT、tokens/s、peak KV HBM、任务成功率、状态一致性；Expected Contribution：端到端 quality-constrained Agent handoff scheduler。

Novelty：★★★☆☆　Feasibility：★★★★☆　Compute Cost：★★★★☆。Risk：跨模型 KV 对齐脆弱，显存/通信开销可能吞掉收益；Collision Risk：很高（TokenRouter + RaReCache 已分别覆盖核心组件），仅做拼接不构成论文；Best Venue：MLSys / OSDI / ASPLOS（若系统贡献扎实）。

Idea 3 — Wall-Clock-Aware Evidence Budgeting for Streaming Video Agents

Video Acceleration × RL × Agent × Dynamic Inference

Inspiration：iCATS 显示更高理论 sparsity 未必更快，GPU tail merging 可以在 sparsity 下降时提升真实速度；VAMR 将多个问题的视觉探索合并；FastBench 指向高动态流的证据遗漏风险。

Gap：Video Agent 常用固定帧数、固定 token 预算或仅优化 QA accuracy，缺少对实际 GPU 延迟负责的跨问题、跨时间、跨视觉 token 的联合预算策略。Hypothesis：使用“预计证据增益/真实边际毫秒”的动作价值，并根据视频动态与问题不确定性更新预算，能在同等 wall-clock 下取得更高正确率。

Proposed Method：把帧选择、视觉 token 保留、工具 seek 和继续推理视为统一动作；cost predictor 由真实 GPU profiling 学习，而不是仅用 FLOPs 近似；使用问题级 advantage 或 bandit feedback 选择动作，保存可验证的 evidence provenance；对高动态区域设置不可忽略的覆盖下限。

Minimum Viable Experiment：在一款开源 Video VLM 上比较 uniform sampling、motion-aware、query-aware、VAMR-style multi-question、cost-aware policy，先用 100–300 条视频建立 profiling 表，再在 holdout 上测。Model：开源 7B 级 Video VLM；Dataset：LongVideoBench/LVBench 子集及高动态视频压力样本；Baseline：均匀采帧、固定 top-k token、VAMR；Metric：accuracy、frames、visual tokens、真实 TTFT、GPU memory、FPS、evidence recall；Expected Contribution：以 wall-clock 为目标的可验证视频 Agent 预算优化。

Novelty：★★★★☆　Feasibility：★★★★☆　Compute Cost：★★★☆☆。Risk：profiling 难迁移硬件，错误漏帧不可恢复，奖励可能偏好过短路径；Collision Risk：中高（iCATS/VAMR/已有 query-aware pruning），必须强调系统实测 + 多问题 + 动态流；Best Venue：CVPR / ICCV / NeurIPS（机制）或 MLSys（系统）。

Collision Detection · ⚠️ 4 组重叠风险

⚠️ Collision Warning 1 — 多 Agent 信息流与信用分配

Collision Paper：MASS、VAMR、Error-Propagation Modeling。已解决：MASS 优化 handoff contract 并蒸馏，VAMR 将问题 advantage 对齐到相关轮次，Error-Propagation 的题名已覆盖失败归因主题。与新 Idea 重合：都在“哪些消息/回合对最终结果重要”上发力。剩余 Gap：有真实故障注入标签的因果证据归因，以及跨 Agent 错误修复 credit。如何差异化：不要只做另一种 message importance score，必须有可控 intervention、source attribution ground truth、long-horizon recovery。是否继续：YES，条件是先做小规模归因可行性实验。证据等级：**前两篇正文已读；第三篇机制与数字待核实。

⚠️ Collision Warning 2 — 跨模型 KV 与路由系统

Collision Paper：TokenRouter、RaReCache、VFold。已解决：decode handoff 调度、跨模型部分重算、跨层 V cache 合并分别已有独立方案。与新 Idea 重合：quality-gated handoff 直接调用已有组件。剩余 Gap：工具状态一致性、Agent 级 SLO、跨多次切换的累积误差、真实 end-to-end Pareto。如何差异化：明确新调度策略及理论/实验，做三种组件交叉消融，必须证明组合优于分别使用。是否继续：MAYBE，先测 baseline 是否已接近上限。

⚠️ Collision Warning 3 — Video 动态预算与系统速度

Collision Paper：iCATS、VAMR、V-CoLA。已解决：生成侧 timestep 稀疏、理解侧多问题共享、视觉 token 压缩已有对应研究。与新 Idea 重合：动态保留 token/帧和多问题证据复用。剩余 Gap：直接优化真实 GPU latency 的跨层预算与高动态流证据覆盖。如何差异化：测量 wall-clock、p99、错误漏帧，并报告 FLOPs 不等于 latency 的失败案例。是否继续：YES，优先做无训练的 profiling + budget baseline。

⚠️ Collision Warning 4 — 零陈旧 Agent RL 流水线

Collision Paper：ThunderSyncRL。已解决：对 GRPO/OPD 的部分梯度提前计算、保留同步更新。剩余 Gap：跨 Agent 联合 reward 依赖图是否存在可安全提前计算的 sufficient statistics。如何差异化：需要新 objective decomposition 或真实多 Agent dependency-aware scheduler，不能只把已有实现部署到另一个 benchmark。**是否继续：仅在可证明多 Agent reward 可分解时继续。
