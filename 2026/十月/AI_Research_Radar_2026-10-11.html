人话版：这篇论文到底干了什么？

这篇工作研究一个非常实际的 Agent 难题：模型在陌生环境里不断试错，却很难把试错变成真正可执行、可纠错的世界知识。作者没有继续微调大模型，而是让固定参数的 LLM 维护一份可修改的自然语言“规则书”，再把规则编译成能模拟动作后果的代码。每次实际操作后，系统都用新观察去检查旧规则、修订程序，并把能完整重放历史的版本留下来。它在 ARC-AGI-3 的 25 个公开游戏中完成全部关卡，报告平均 RHAE 达到 100、实际动作数为人类参考动作数的 44%。关键不是某次任务答对，而是把经验变成下一轮可检验的行动模型。

Background & Gap：为什么传统 Agent Memory 不够

传统 episodic memory 记录“我做过什么”，procedural memory 记录“这类任务怎么做”，但二者未必回答“世界为什么会这样变化”。例如在游戏中，Agent 观察到一个箱子在第 7 列停下，可能归纳成“碰到墙停止”，也可能错误归纳成“到第 7 列就停止”。两种解释都能重放已见历史，却对未来新地图给出完全不同的预测。只靠向量检索历史轨迹无法主动区分这两种假设。Memento 3 的核心 Gap 是：历史一致性 ≠ 未见状态的规则正确性，因此 memory 需要可执行的预测、反例与修订闭环。

Core Insight：把记忆变成“可证伪的外部世界模型”

其核心 observation 是：自然语言适合表达抽象规则、假设与不确定部分，代码适合严格执行转移和做规划。两者必须绑定，否则会出现“规则写得对、实现写错”或“代码能复现历史、规则其实过拟合”的情况。作者将持续学习状态定义为 Z_t=(H_t, ψ_t, θ_t)：H 为真实交互历史，ψ 为语义规则书，θ 为可执行转移模型；底层 LLM 参数 φ 保持不变。学习发生在外部状态，而不是梯度更新。

Method Deep Dive：完整 Pipeline

观察 o_t → 更新真实轨迹 H_t → 对照可执行模型预测 → 反思规则 ψ_t → 编译/修复程序 θ_t → 规则忠实性检查 + 历史逐步精确重放 → 采用合格模型 → 模型内规划/探索 → 执行下一动作。

Step 1，记录可追溯证据。 对每个真实动作保存动作前后的观测及完成反馈；历史不是摘要，而是用于以后重新验证模型的不可替代证据。模型用内部状态模拟环境，允许隐藏变量不直接出现在单帧观测中。

Step 2，明确假设边界。 规则书写对象、动作语义、状态变化、目标条件；未知部分允许保持未定义，而不是强行补完。LLM 可修订规则或仅修复实现，避免把编程 bug 误当世界规律。

Step 3，编译为执行模型。 θ 包括状态初始化、转移函数、观测函数与目标判定。规划器在模拟状态上搜索动作序列，减少真实环境试错；这相当于“用代码做预测”，而非让语言模型每步想象一次。

Step 4，双重验证。 只有代码忠实实现规则书，并且对每条记录的真实转移逐步重放得到完全一致的观测，才接受新版本。重放检验保证训练历史一致性，却不能保证未见状态正确性；作者明确承认这个差别。

Step 5，闭环探索与多假设。 若当前模型不能找到计划，Agent 执行探索动作获取新证据；扩展版维护多个规则书/程序候选，共享真实历史，用不同行为预测鼓励探索，避免所有候选只是语法不同的同一个程序。

关键公式与直觉

H_t=(o_0,a_0,o_1,...,a_{t-1},o_t) 是真实证据；Z_t=(H_t,ψ_t,θ_t) 是外部学习状态；φ_{t+1}=φ_t 强调没有参数学习。验收条件是对所有已记录转移 预测观测 θ(H_i,a_i)=真实观测 o_{i+1}，并要求 θ 属于 ψ 允许的实现集合。任务优化是预算 B 内到达目标的概率 p_B，同等成功概率下再降低条件动作成本 c_B。它不是 PPO/GRPO，也没有 token-level advantage 或 learned reward model；把它称为“模型驱动的自改进”比“参数强化学习”更准确。

Toy Example：一条错误规则怎样被修正

初次看到门禁徽章，Agent 写入规则“镜面反射会改变徽章颜色”，编译出转移代码。它执行一次镜面操作，发现实际图案顺时针旋转而颜色不变。新观测与程序预测冲突，反思模块修订规则为“镜面触发图案旋转”，重新编译，重放旧轨迹与新轨迹，只有都一致才采纳。随后规划器基于新规则搜索“旋转图案 → 取得补给 → 匹配门禁”的路线。这个例子说明错误不会只被存进 memory，而会触发结构化模型修复。

Baseline Comparison 与 strongest baseline

Claude Opus 5 + ARC Prize Standard harness：强通用模型及标准交互接口，合理地代表“靠模型推理+工具执行”的强基线；缺点是未必显式维护可编译的长期世界模型。论文报告 Memento 3 的平均 RHAE 高出 59.3 个百分点。仅历史轨迹/反思的 Agent：可利用经验，却难对未见状态执行精确模拟。不带规则书的代码世界模型：能拟合轨迹，但缺少规则级语义修订与可读的假设边界。多候选模型版本：比单模型保留更多行为解释，但增加管理/调用成本。可核实的最强公开数值对照是 Claude Opus 5 标准 harness；其它比较的具体表格数字不在本次逐项核实范围，不虚构。

Experiment Setup / Research Questions

RQ1：外部世界模型能否提高陌生环境交互效率？ ARC-AGI-3 的 25 个公开游戏，以 level clearance、Relative Human Action Efficiency（RHAE）与动作数衡量；公开游戏不等于未知隐藏分布。RQ2：规则书与多候选有什么贡献？ 正文包含 rulebook/population ablation，应对照是否取消语义规则、是否只维护一个假设。RQ3：学到的模型能否脱离 LLM 实时调用执行？ Atari Pong 控制案例。底层 LLM 固定参数；具体模型调用成本、token 消耗和不同种子方差未在本次已核对段落完整取得，不能视为零。

Results：数字 / 现象 → 对照 → 意义

结果 1（strongest）：25/25 个公开游戏全部完成、平均 RHAE=100.0；证明该设置下的规则—程序循环具备高任务完成度，不是未知环境的普适保证。

结果 2（动作效率）：使用人类参考动作数的 44%；说明真实环境交互成本较低，但不能把 LLM 反思/编译调用成本也算作下降 56%。

结果 3（强基线）：比 Claude Opus 5 标准 harness 平均 RHAE +59.3pp；比较需注意 harness、预算、允许的外部代码执行能力是否严格一致。

结果 4（迁移案例）：Atari Pong 三次不同开局测试均以 21:0 获胜，执行控制阶段无额外 LLM 调用；展示“学一次规则，之后廉价执行”的潜力，样本量仅三局。

结果 5（weakest / failure）：历史完全重放仍可能同时接受多个互相矛盾的未见状态假设；这是方法明确承认的不可识别性，而非已被实验彻底消除。多模型候选缓解而非解决此问题。

Claim vs Evidence

Authors Claim：通过持续学习外部规则/可执行模型实现递归自改进。Actually Show：固定 LLM 在 25 个公开 ARC 游戏中通过规则修订取得高交互效率，并在少量 Pong 实验中产生可脱离 LLM 的控制器。Not Yet Proven：跨任意开放世界、长时间非平稳任务、多 Agent 信息冲突与不可观测随机环境的可靠性；“recursive self-improvement”也不能等同于底层模型能力不断提高。

Contribution / Limitation / Research Value

Contribution 1 — New Mechanism：双表示世界模型 rulebook + executable。Contribution 2 — New System/Engineering：以 replay consistency 作为记忆更新准入门槛。Contribution 3 — New Empirical Finding：外部模型学习可在公开交互游戏与小规模控制任务中显著降低真实动作数。作者自身局限是未见状态的假设歧义；额外局限包括确定性/离散环境假设、LLM 调用成本未统一计入、验证器自身可能失误、历史增长导致重放开销、跨 Agent 共享时的错误传播。

人话版：这篇论文到底干了什么？

很多大模型剪枝论文宣称“权重少了一半，所以推理更快”，但真实生成时往往没那么简单：一方面剪枝时用的是完整真实文本，部署时模型却在读自己刚刚生成的词；另一方面 GPU 的稀疏矩阵乘法库主要优化 prefill 的矩阵乘矩阵，未必能加速逐 token decode 的矩阵乘向量。SparseDecoding 同时修这两个缺口：先用原模型真实自回归生成过程收集校准激活，再为 N:M 稀疏权重设计专用 SpMV kernel。论文在 A100 上报告最高 1.48× 实测 decoding 加速，同时比固定文本校准显著保留更多长文本与代码生成能力。真正重要的是“算法压缩必须与运行时算子和数据分布对齐”。

Background & Gap：为什么传统剪枝速度和质量都可能翻车

SparseGPT/Wanda 等 post-training pruning 通过少量文本估计哪些权重可删。典型校准方式是 teacher forcing：所有输入 token 都是真实语料；但部署中前一步输出会改变后一步输入，尤其长文本生成时激活分布可能漂移。论文 Figure 1(a) 显示模型与剪枝模型的激活差异在前 12 个 decoding step 内就达到平台值的 90%。同时 Figure 1(b) 说明 cuSPARSELt 风格 2:4 Tensor Core 路径在 prefill 获得 1.31–1.46×，在 decoding 反而仅有密集执行速度的 0.85–0.87×。所以只报告 FLOPs 或权重稀疏率会严重误导部署判断。

Core Insight 与公式

核心 insight 分两层：统计对齐，校准样本应该来自实际自回归 decode 轨迹；硬件对齐，decode 常是低 batch 的 GEMV/SpMV，应该为其设计紧凑索引和固定工作量。层级剪枝目标为 min_{W~} ||(W-W~) X||_F²，其中 W 是原权重、W~ 是剪枝权重、X 是校准激活矩阵；与 SparseGPT 的区别不是换优化器，而是把 X_teacher-forcing 换成 X_autoregressive-decode。由 H=2XXᵀ 构造二阶近似，改变权重重要性与补偿更新。保留每 M 个权重中的 N 个（如 2:4），是硬件可执行的稀疏约束。

Method Deep Dive：完整 Pipeline

任务校准 prompt → 原始 dense LLM 自回归生成 → 按层记录激活 → 丢弃 prefill 激活，仅保留 decode → 计算 decode-aware Hessian/重建目标 → SparseGPT 类 OBS 剪枝 → 2:4 / 8:16 稀疏权重 → bitmask + fixed-step SpMV kernel → 逐 token 生成。

Step 1：真实 rollout 校准。 对 K 个任务 prompt 让 dense 模型采样后续 token，得到每层每个 decode step 的激活向量。保留所有生成步、丢弃 prompt prefill 的激活，是因为优化目标明确指向 decode 阶段。

Step 2：用这些激活决定删什么。 仍求最小化层输出重建误差，保留已有剪枝求解器，因此是 post-training、无重新训练的部署方案。代价是需要先跑 dense 模型采集校准轨迹，属于离线准备开销。

Step 3：压缩索引。 对 50% N:M 模式，以 bitmask 记录非零位置，每个非零权重的索引元数据约 2 bits；论文对照 int32 索引 32 bits、uint8 offset 8 bits，元数据分别下降 16× / 4×。这不等于整个模型显存下降 16×，只是索引元数据。

Step 4：固定步遍历。 当 M≤32 且稀疏率为 50%，对齐的 32-bit mask 恰有 16 个 set bit，GPU 线程可用相同步数做位扫描，避免行长不同造成的线程分歧。此设计针对 batch=1 或小 batch 的 SpMV，不可无条件推广到大 batch GEMM。

Toy Example：为什么生成数据更适合剪枝

给模型一个“写 2000 字教程”的 prompt。传统校准从 C4 文本中读连续真实 token，计算激活并剪枝；但模型实际生成到第 100 步时已经根据自己写的标题、列表和例子形成新上下文。若某一层对“自己刚刚输出的代码块结束符”敏感，C4 校准可能低估它。SparseDecoding 先让 dense 模型生成完整教程，从这些真实后续 token 收集激活再剪枝，降低这种分布错配。执行时一个 token 一个 token 解码，专用 bitmask SpMV 才把稀疏权重转成 wall-clock 收益。

Baseline Comparison / strongest baseline

Dense checkpoint 是质量上界/速度参照，不是稀疏对照。C4 teacher-forced calibration + 同一剪枝 backend 是最关键 strongest controlled baseline，因为模型、稀疏率、solver 都相同，唯一变化是校准分布。SparseGPT/OBS 是通用剪枝求解器；本文复用它，创新在数据收集和 kernel。cuSPARSELt 2:4 是强 prefill 系统基线，但在小 batch decode 不匹配。论文同时检查 50% unstructured、2:4、8:16；不可把不同稀疏结构的质量直接混为算法效果。

Experiment Setup / Research Questions

RQ1：生成式校准是否提升长文本质量？ WritingBench：1000 prompts / 100 子领域 / 6 大领域，用 DeepSeek-V4-Flash 评审 1–10 分；采样温度 0.7、top-k 20、top-p 0.8，最长 16000 tokens。RQ2：是否迁移到代码？ ClassEval：100 个 Python 类任务 / 410 个方法，指标 class-level Pass@1。RQ3：是否真实加速？ NVIDIA A100 80GB，四个模型：Llama-3.1-8B、Llama-3.3-70B、Qwen3-14B/32B；检查 decode wall-clock 而非仅 FLOPs。50% 剪枝含 unstructured、2:4、8:16 配置。

Results：至少五个具体对照

结果 1（WritingBench）：Llama-3.1-8B 50% unstructured 下 C4 2.25 → SparseDecoding 2.54（+0.29）；dense 3.70。质量有改善，但仍明显低于原模型。

结果 5（ClassEval，32B）：2:4 下 C4 9% → 24%；dense 34%。这是强烈的校准分布证据，但需要不同 prompt/任务迁移验证。

部署前必须回答的两个系统问题

首先，TPOT 可能由权重访存、KV 读取、kernel launch 和 batch packing 共同决定。本文压缩权重并优化 SpMV，但随着 context 增长、batch 增大，瓶颈可能从权重转向 KV 或 GEMM；这时同一个 2:4 mask 的收益可能改变。其次，校准轨迹来自 dense model，部署时稀疏模型的自回归分布仍可能继续偏移，因此还应比较长输出后半段的错误积累，而不是只报告前几百 token 的平均分。推荐额外报告不同生成长度下的质量退化曲线、batch-size scaling 与实际 GPU HBM 带宽利用率，这能判断 1.48× 是否来自预期的内存流量下降。

人话版：这篇论文到底干了什么？

不少人把“把过去的动作和奖励塞进 prompt，模型下一轮做得更好”称为 in-context reinforcement learning。作者做了一个很有杀伤力的控制实验：把历史中的 reward 翻转、随机化甚至直接删掉，观察能力提升曲线是否变化。结果在 6 个模型、4 个 benchmark 上，提升几乎照旧；甚至把轨迹打乱或损坏，也能出现类似改进。这说明模型可能主要利用“有历史示例”这一 ICL 效应，而不是像真正 RL 那样根据奖励更新策略。它直接挑战 Agent memory + reward 的许多轻率叙事。

Background & Gap / Core Insight

过去的直接 ICRL 往往将 (trajectory, reward) 拼接到上下文，后续任务表现提升便解释为“Agent 在上下文中学习了奖励”。但没有做 reward shuffle/flip/remove 的反事实控制，就无法判断究竟是 reward 语义、轨迹样本分布、上下文长度还是示例格式造成变化。本文将 reward 是否具有因果增量信息作为可证伪问题，而非只看 performance 曲线。

Method / Experiment Setup

多轮任务 → 记录轨迹与奖励 → 构造真实 reward / 反转 reward / 随机 reward / 无 reward / 损坏轨迹等控制组 → 固定模型和 prompt 结构 → 比较随轮次变化的任务表现。实验覆盖 四个 benchmark、六个模型，还测试显式要求 explore/exploit/reason about rewards 的 meta-prompt。Research Question：当轨迹与提示长度大体相同，reward 的数值或方向是否会系统性改变后续决策？另一个问题是轨迹语义是否必要。

结果与证据强度

现象 1：翻转 reward 后改进曲线变化很小，挑战“模型沿奖励梯度学习”的解释。现象 2：随机化或移除 reward 也基本不改变曲线，说明 reward 通道未必被用于有效的策略更新。现象 3：轨迹打乱或损坏后仍有类似改进，提示示例分布/上下文结构可能更关键。现象 4：显式 meta-prompt 不能可靠扭转这些结果。论文摘要未给出具体 accuracy 数值或置信区间；此处不伪造提升百分点，完整定量复核列入后续 Deep Dive。

RL Formulation / Reward Analysis

这里没有参数更新，不应把它写成 PPO 或 GRPO。State 是当前任务与上下文；Action 是 LLM 输出；Trajectory 是历史交互；Reward 是附在历史后的外部评分；Policy 是由当前 prompt 条件化的冻结 LLM；Advantage、KL 正则、熵项、策略梯度均不适用或未报告。论文的关键恰是证明 reward 在这种设置下并未表现出应有的 credit-assignment 作用。Reward 是否 sparse/dense、learned/rule-based 随具体任务变化；不能统一臆测。Reward hacking 风险不仅是“追分”，也包括模型完全忽略 reward 却被误认作学会奖励。

Contribution / Limitation / Research Value

New Empirical Finding：直接 ICRL 的能力曲线可能主要来自 ICL，而不是奖励驱动学习。New Evaluation Protocol：奖励反事实置换是 Agent memory 论文的必要控制。局限：结果针对直接把 raw trajectory-reward 放入上下文的方案，不能否定有明确梯度更新、显式值函数或外部 policy optimizer 的 RL；也不能证明所有 memory architecture 都不使用 reward。对 Agent 的价值是把“有历史所以变好”拆成 reward、trajectory semantics、格式和数据分布四种效应。

进一步审稿视角：什么才算“真的在上下文里 RL”？

一个最低要求是同一批轨迹在奖励语义被系统改变时，后续动作分布应朝与奖励一致的方向变化。仅凭任务准确率随轮次上升，无法排除 few-shot prompting、任务分布适应或上下文格式熟悉化。更强实验可构造同一初始状态下的成对轨迹，仅交换成功/失败标签，比较 Agent 是否真正改变工具选择；再用 unseen task 检验奖励学到的是通用策略还是题目模式。这里也要区分“模型读到了 reward token”和“reward 作为因果学习信号起作用”：前者不代表后者。若某方法包含外部 bandit 选择器或真实参数更新，应另立实验，不能拿本文结论一概否定。

训练效率、稳定性与失败边界

该设置不进行梯度训练，所以 rollout GPU compute、优化收敛和 KL 稳定性不能照搬标准 RL 口径；但仍需统计每次交互新增的上下文 token、输入长度增长、成功率是否饱和，以及 reward 标签扰动下的方差。若奖励确实无效，那么花成本设计复杂 reward model 可能没有收益；反过来，若某个任务的 reward flip 明显改变决策，就需要追查它依赖的是奖励的排序、符号还是具体数值。这个反事实审计可直接成为多 Agent memory 论文的评测门槛。

人话版：这篇论文到底干了什么？

GRPO 训练 reasoning 模型时，一个常见问题是策略逐渐变得过于确定，rollout 多样性下降，探索停滞。常规做法是调 KL、熵奖励或 token 权重；这篇论文提出一个更便宜的干预点：不改变采样预算，只改变哪些 rollout 被拿去更新模型。它在更新前剔除少量“概率已经很高且优势为正”的样本，再对剩余优势重新中心化。直觉是，模型已经非常确信且成功的轨迹继续被强化，可能加速熵塌缩；少用这部分梯度反而能保留探索。摘要报告优于原始 GRPO 的准确率、更高的 actor entropy 与更少的更新样本。

Background & Gap / Core Insight

传统 GRPO 对同题多个 rollout 的 reward 做组内归一化，成功轨迹获得正优势。但当高概率成功样本长期主导更新时，概率质量可能继续集中，导致未来采样缺少新解。现有 KL/entropy 方案改变 objective，token reweighting 改变局部梯度；本文提出 rollout-level selection，将探索保护前移到样本准入层。关键是高概率、正优势同时成立才是候选，不能粗暴删除所有正确答案。

Method / Experiment

同题生成 G 个 rollout → 规则或 verifier 产生 reward → 组内估计 advantage → 找出高概率且 advantage>0 的部分 rollout → 按阈值少量丢弃 → 对剩余优势重新中心化 → 标准 GRPO 更新。论文提出 rollout-level 理论分析用于解释阈值选择。已核实摘要确认在相同采样预算下，训练只使用部分 rollout；但具体模型、任务、阈值、训练 token、GPU-hour 和主表数字未在本次逐项取得，均标 Not Reported in verified excerpt，不虚构。

RL Formulation / Reward Analysis

State 是 prompt 与已生成 token；Action 是下一个 token；Policy 是 LLM；Trajectory 是整条 response；Reward 是最终任务/verifier 给出的标量（具体规则依任务，未核实）；Advantage 是组相对估计并在删除后重新中心化；Objective 仍是 GRPO 风格 surrogate；KL/entropy 是对照干预手段，不代表本文必须增加新的 KL 项。Credit assignment 仍偏序列级奖励分配给 token，创新点是序列选择而非细粒度因果归因。Reward hacking 风险在于偏好容易通过 verifier 的短答案或格式获益；删除高概率样本不直接修复 reward model 错误。

Results / Contribution / Limitation

Method / Setup

假设整个请求耗时中只有 30% 花在可替换的 sparse attention kernel，即使 kernel 提速 1.70×，其余 70% 不变，理论端到端上限也只有约 1/(0.7+0.3/1.7)≈1.14×。这只是解释 Amdahl 定律的示例，不是本文实验配置。论文报告的整模型 prefill 提升 7.88–14.36% 与这一逻辑相容：调度、embedding、MLP、通信、分组准备都仍需时间。反过来，若 Agent 长上下文在重复 prefix 上有很高 cache hit，prefill 的可优化份额又会变小。

建议将 8K、32K、64K 视为不同工作负载，而不是一条连续速度曲线：短上下文 regrouping 开销可能主导，长上下文 page reuse 才值得；H200 与 B300 的 native kernel 能力不同，也不能混算平均值。对于多模态输入，视觉 token 的局部聚簇可能改变 query-page overlap，但是否增加重组收益必须实测。PageWeaver 的强点正是把负面结果公开出来，适合作为系统论文的评测范式。

关键对照与失败情形

这里的 strongest baseline 不是“密集 attention”这种容易击败的对象，而是实测的 FlashInfer path 与硬件上的 native sparse kernel。PageWeaver 的创新主要发生在执行计划而非模型注意力语义：每个 query 的 page support 保持不变，因此不应把它写成更聪明的 token pruning。若原 sparse selector 已经错误丢弃关键信息，PageWeaver 不会自动修复精度。另一方面，GPU 上构建 page-affinity 分组需要读取索引、排序/搜索并安排线程块；在短上下文时，这些准备成本可能超过减少的 KV 访问。B300 的对照恰好说明系统优化不是一次性“发明一个 kernel”就永久成立，而要随硬件演进重新测量。

目标主要是 prefill，非已证实的 decode 提速；减少的是冗余 KV page 访问与执行碎片，不直接减少模型参数；理论复杂度没有在已核实片段中给出统一降阶；真实加速必须区分 kernel 与 whole-model；无需模型重训；依赖 FP8 KV 与具体 GPU kernel；不主动改变原 sparse support；长上下文收益比 8K 更有希望但非单调；VLM/Video/Agent 迁移仍是待验证假设。这九项判断比只报“1.70×”更能指导复现。

数学推理实验与消融支持设计，但摘要未提供具体 accuracy、entropy 或 KL 数值，不能臆测提升百分点。可核实的机制结论是作者明确枚举七种 failure modes；是否在不同模型和 batch 上都成立仍需全文复核。对 RL 的价值是提醒 credit assignment、序列长度与 KL 标度耦合，不能只扫一个 β 就认为调参充分。

Contribution / Limitation / Connection

New Objective：Zero-Sum Calibrated Policy Optimization；New Analysis：KL 与组相对 reward 的多种失配机制。局限：目前可核实的证据主要是数学推理任务，尚未确认 Agent 长轨迹、异步 rollout、工具调用奖励的稳定性。Potential Use：Agent GRPO 训练中分离 token KL、tool-step KL 与 terminal reward，比较不同长度轨迹的梯度贡献、entropy collapse 和任务成功率。

七种失败模式为什么值得拆开看

例如组内 reward 全相同，原本没有可区分的正负优势，若 KL 项仍推动策略向参考分布靠拢，训练就可能产生与任务表现无关的更新。又如长回答比短回答积累更多 KL，即便两条轨迹最终 reward 相同，惩罚权重也可能不成比例。少数 token 集中贡献 KL 则可能让模型在标点、格式等局部位置过度保守。这里的关键不是把 KL 系数一律设为零，而是区分“保护参考策略”与“制造不必要的优化方向”。

可执行检查

训练日志应按 response length、reward variance、positive/negative advantage、tool-call token 占比拆解 KL 与 policy-gradient 范数；分别记录零优势组中的更新量。最小实验只需固定同一模型、相同 rollout 与更新预算，比较原 GRPO、去 KL、ZCPO，先验证梯度分解再讨论任务准确率，避免把调参收益误认成新理论。

人话版：这篇论文到底干了什么？

知识蒸馏通常让小模型模仿教师对每个样本的输出或特征，却忽略“这个样本和历史上哪些动态模式相似”。TAM 给冻结教师配一个有界可检索的历史 memory，存储 latent feature、预测变化或 flow residual，并按任务挑选历史参照，让学生学习相似性分布或残差原型。重要的是：教师、记忆和辅助适配器只在训练时存在，学生推理结构不变。四组配对实验中，六个视频数据集的 SSIM 均有改善；若干 MSE 改进幅度较小但稳定。

Background / Core Method

传统 KD 只做 sample-wise imitation；TAM 则加入跨样本动态结构。冻结 teacher → 写入 bounded task-aware memory → 按当前任务检索历史参照 → 学生对齐 teacher 相似性分布/残差 prototype → 训练后移除 memory/teacher。因此它是训练阶段知识迁移，不是运行时的 cache reuse 加速。

Experiment / Main Finding

论文覆盖视频预测、天气与交通流，四次 paired runs。结果 1：六个视频数据集 SSIM 都改善。结果 2：KittiCaltech 平均 paired MSE 降低 1.86%。结果 3：WeatherBench（gSTA teacher）MSE 降低 1.93%。结果 4：TaxiBJ MSE 降低 1.01%。这些是相对对应 KD baseline 的改进，不是相对无蒸馏训练。

Contribution / Limitation / Connection

New Mechanism：任务感知的历史关系蒸馏。局限：训练时增加 memory 检索开销；跨任务分布变化下 memory 可能失效；并未报告新的推理 FPS/latency 加速比。Why It Matters：能把长期动态结构转移到更小的学生。Potential Use：用视频历史关系蒸馏训练 streaming VLM 的轻量视觉前端，验证部署端实际 FPS、GPU memory 与长程事件召回，而非只看 SSIM。

与 Video Acceleration 的关系需要分清

TAM 训练时多用了 teacher、memory 检索与辅助损失，但部署时学生的参数量和前向结构没有因 TAM 进一步改变。因此“推理没有额外开销”不等于“相对原学生推理更快”；其效率收益来自学生本来就比教师小。正确实验应分别比较 teacher、普通 KD student、TAM student 的 FPS、显存和预测误差，在相同学生架构下验证 TAM 是否提供更好的质量—效率 Pareto 点。

潜在失败案例与最小验证

当视频从平稳驾驶突然切到拥堵路口，历史 memory 中相似外观可能对应不同未来运动，错误检索会误导学生。可在 KittiCaltech 与含突发事件的短视频集合中对比随机 memory、任务无关 memory、任务感知 memory，并报告 SSIM/MSE、分布外误差和训练额外 GPU-hour。若检索本身不稳定，建议加置信度门控而不是无条件使用历史原型。

Idea 1 · Counterfactual Provenance Admission（反事实来源约束的多 Agent 世界模型准入）

Novelty ★★★★☆Feasibility ★★★★☆Compute Cost ★★☆☆☆

Inspiration：Memento 3 的规则书+精确重放；OnTrack 的在线依赖结构；前日 MASS 的多 Agent 自监督。

Gap：共享历史可以验证“发生过”，却不能区分多个与历史一致但在未见状态冲突的规则；错误规则一旦跨 Agent handoff，会被重复引用放大。

Hypothesis：对每条共享规则同时记录来源、支持/反驳轨迹、可执行反事实测试，可减少错误传播而不过度牺牲探索效率。

Proposed Method：将 rulebook 拆成可追踪规则节点；新 Agent 接收规则前执行 replay + 反事实分歧测试，只有 evidence-supported rule 进入全局库，冲突规则进入 quarantine；用后续任务收益回写规则可靠度。

Minimum Viable Experiment：在 MiniGrid/ALFWorld 构造 2–4 Agent 顺序探索，随机植入 10% 规则错误；比较无门控、仅 replay、provenance+counterfactual。

Model：同一固定 7B/8B LLM

Dataset：MiniGrid、ALFWorld + 可控规则变更集

Baseline：Memento 3、共享摘要记忆、OnTrack 异常检测

Metric：Success、误规则接纳率、传播深度、修复步数、环境动作数、LLM tokens、wall-clock

Expected Contribution：New mechanism + new evaluation：带因果证据的跨 Agent memory admission

Risk：反事实生成可能昂贵；未知环境不能轻易获得 ground truth

Collision Risk：HIGH：Memento 3 已做 replay；必须以跨 Agent 规则归因与未见状态测试差异化

Best Venue：ICLR / NeurIPS / AAMAS

Idea 2 · Phase-Conditioned Sparse Agent Inference（分阶段稀疏推理）

Novelty ★★★☆☆Feasibility ★★★★☆Compute Cost ★★★☆☆

Inspiration：SparseDecoding 的 decode-only calibration 与 PageWeaver 的 page affinity 系统测量。

Gap：Agent prompt 包含 tool result、计划、长 CoT、最终答案；统一校准可能让稀疏模型对少数高风险工具决策失真。

Hypothesis：按 tool/planning/final-answer 阶段构造 activation 校准集，能在相同 2:4 sparsity 下提高 Agent success，同时维持实际 TPOT 收益。

Proposed Method：给轨迹分阶段标签，构造加权 Hessian 校准，保留关键 tool-call 层/模块；部署同一 N:M kernel，不增加每 token 动态路由。

Minimum Viable Experiment：8B LLM 的 2:4 剪枝，比较 C4、普通 AR、阶段均匀 AR、风险加权 AR；测 batch=1/4/16。

Model：Llama-3.1-8B

Dataset：SWE-bench Lite 工具轨迹、WebShop、长 CoT

Baseline：SparseGPT-C4、SparseDecoding、dense

Metric：任务成功率、tool syntax error、TTFT、TPOT、tokens/s、HBM、P95 latency

Expected Contribution：New empirical finding：Agent 阶段分布对剪枝质量的因果影响

Risk：校准集泄漏；不同任务的激活分布不一致

Collision Risk：MEDIUM：SparseDecoding 已做 AR calibration；必须证明 phase-aware 优于仅换数据源

Best Venue：MLSys / NeurIPS Datasets & Benchmarks

Idea 3 · Evidence-Preserving Video Cache with Failure-Triggered Rehydration

Novelty ★★★☆☆Feasibility ★★★☆☆Compute Cost ★★★★☆

Inspiration：Memory Forcing 的 archive/working KV 与 Streaming-Aware Diffusion 的跨步复用。

Gap：视频系统常优化平均 FPS 或 VBench，但事件消失再出现时，缓存中哪些证据不可丢失仍缺少在线可检验机制。

Hypothesis：对高不确定或即将复现的事件保留稀疏 keyframe evidence，并在 cache 不一致时触发少量重新编码，比固定 window 更好地平衡延迟与事件召回。

Model：小型 streaming VLM + 1.3B video generator 作为独立扩展

Dataset：长视频事件召回构造集 + CMBench (BACKFILL)

Baseline：sliding window、Memory Forcing、固定 keyframe、DeCoPrune

Metric：事件召回、FID/FVD（生成分支）、FPS、TTFT、P95 wall-clock、KV GB、GPU HBM

Expected Contribution：New mechanism：failure-triggered evidence recovery under fixed cache budget

Risk：在线错误检测自身消耗时间；跨生成/理解两任务目标不同

Collision Risk：HIGH：Memory Forcing / DeCoPrune 已保留长程信息；必须聚焦可测的失效触发与真实延迟

Best Venue：CVPR / ICCV / MLSys
