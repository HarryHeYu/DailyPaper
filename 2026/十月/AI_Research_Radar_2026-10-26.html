05 · RL Highlights

核心观察：今天最强的 RL 相关线索并非又一个 GRPO loss，而是两种不同层次的 reward/credit 设计：PKTP 在测试时把多轨迹的相关失败纳入集合效用；Memory-Aware Reward 从真实用户偏好学习“何时使用记忆”才有价值。前者不更新策略，后者尚未做 RLHF，两者都不应伪装成完整 RL 训练论文。

近期值得继续追的真实 Agent RL 基线：Twin-World Credit Assignment（共享随机性下的反事实 credit，10/24 Tier S 冷却）、Self-Credit（组内长程 credit，10/23 Tier S 冷却）、Self-Assessment RL（搜索状态 reward）。后续要核对 rollout 数、token、KL/entropy、训练稳定性，而不是只引用 success rate。

06 · Agent / Multi-Agent Highlights

Agent Memory 从存储问题变成决策问题：Memory-Aware Reward 研究用户是否喜欢被引用的记忆；APA 研究哪些未知偏好值得主动问；AMV-Guard（冷却期）研究执行不可逆动作前哪些记忆必须核验。三者分别覆盖“用不用、问不问、信不信”，可组成有成本的 Agent memory policy。

Multi-Agent：DuoCook 的视觉双角色协调完成率低，且共享 notebook 对不同模型正负不一；CMAS 则把多 Agent 架构更新加入 shadow replay、canary 与 rollback。需要进一步研究“共享状态如何导致错误传播”与“谁真正对协作成功负责”。

07 · Video Acceleration Highlights

三条路线：Attn-Forcing 用 attention proxy 保存被驱逐历史对当前 query 的作用，质量更高但相对 LongLive 约慢 13%；Online Textual Memory 把长视频转为可检索 caption，揭示 temporal recall 不是 QA accuracy 的充分条件；LFC 用 77K 参数补偿跳帧输入，报告 2.05–2.55× 吞吐增益。三者优化对象分别是生成历史 attention、视频问答检索上下文和实时分割 backbone 调用，不能把它们的 speedup 混为同一种。

ParaLin++ 的图像扩散实测为 solver 时间步并行化提供重要思路，但没有足够证据声称在 Video DiT 上复现同等加速。对于真正的视频系统，需要统一采集 Frames / Tokens / FLOPs / Latency / GPU Memory / FPS / Accuracy，并固定模型、硬件、分辨率和输入长度。

Tier S

Direct Pass@k Optimization for Thought Pruning: Balancing Quality and Diversity in Test-Time Reasoning

arXiv:2610.31667 · 2026-10-22 · RL / Reasoning / Test-time selection · 预印本；Venue 未核验

Authors: Mahdi Salmani; Adel Javanmard; Devansh Gupta; Meisam Razaviyayn
Affiliation / Status: 论文正文未单独核验机构，Venue 未核验；arXiv preprint
Links: Paper · HTML Full Text · PDF
Project / Code: 未核实（Not Verified），不据此声称开源
Read: §3 Method、Figure 3–7、Table 1

人话版：这篇论文到底干了什么？

推理模型可以为同一道题生成一百多条思考路径，但把它们全部算到答案非常贵。传统“质量优先”剪枝会把看起来最靠谱、却可能一起犯错的路径留下；“多样性优先”又容易选择奇怪但错误的离群路径。PKTP 不分别调质量和多样性的权重，而是直接估计“保留的 k 条路径中至少一条最终答对”的概率，利用部分轨迹表示建模共同失败，再贪心挑选子集。八个开源推理模型的实验表明，在中等保留预算下通常优于质量探针和纯多样性剪枝。真正重要的不是又一种排序分数，而是把候选之间的相关性显式写进选择目标。

Background & Research Gap · 一个反例

设有 128 条数学推理前缀，只能继续运行其中 4 条。质量探针选出同一错误假设的四个近邻，四条都错；多样性算法选出四个罕见的离群轨迹，也可能全错。我们想最大化的不是四条平均质量，而是“至少一条成功”的集合概率。作者 Figure 4 展示 Qwen3-8B 在 AMO-Bench 上探针选择的 16 条前缀全错，随机抽样的 16 条反而有 7 条正确；Figure 5 则展示 RepExp 四个离群候选全错，随机四个有一个正确。这两种失败指向同一个遗漏：候选结果不独立。

本工作是 test-time selection，不是新 RL 算法，也没有声称优化训练策略的 GRPO/PPO 更新。它与 RL 的关系是探索—利用及多轨迹预算分配，不能把 pass@k 提升误写成 policy-training improvement。

Core Insight 与 Method Deep Dive

Input → 为每个问题生成 N 条 rollout → 在 T token 处截断 → 从隐状态构造 EMA 表示 hᵢ → 学习单条质量 qᵢ 与跨条相关性 → 近似计算子集全部失败概率 → 贪心选 k 条 → 仅继续生成被选前缀 → 验证最终答案。

关键的概率模型把每条路径的潜在成功得分拆成质量项 qᵢ、共享高斯扰动 hᵢᵀf 和路径独立噪声 mᵢ。两条路径表示越对齐，共享项导致它们成功或失败越相关；这解释了“看起来都是高分”并不等于覆盖更多正确解。作者用带正确/错误标签的训练题拟合 qᵢ，再对不可积的高斯期望做二阶近似。

目标可写为 max₍|S|=k₎ P(∪ᵢ∈S{Cᵢ=1}) = 1 − P(∀i∈S,Cᵢ=0)。作者证明精确集合目标以及近似目标具有单调次模性，因此可使用贪心边际增益。实现不是每次重算整个协方差矩阵，而是 rank-one 更新；文中给出选择时间 O(k(Nd+d²))、空间 O(Nd+d²)。若把相关项关掉，退化为质量探针；若质量分数相同、相关项主导，趋向 RepExp 风格的残余方差选择。

关键变量：N 是候选总数，k 是保留数，T 是前缀截断长度，hᵢ 是 EMA 隐表示，qᵢ 是预测质量，f 是共享随机因素。模型学习的是 rollout correctness 的联合代理，而不是环境奖励函数；其训练依赖已完成轨迹的正确性标签。

Toy Example / RL Formulation / Reward Analysis

四条候选 A/B/C/D 的单条成功概率分别可设为 0.8/0.78/0.55/0.50。若 A 与 B 依赖同一错误前提、几乎总是一起成败，选 A+B 的“至少一条成功”概率可能只略高于 0.8；A+C 若失败模式独立，即使 C 单条更弱，集合成功概率也可能更高。这里数字纯属教学假设，绝非论文实验结果。

State 是当前问题与 N 条前缀；Action 是选择大小为 k 的子集；Reward 是最终是否至少一条正确；Trajectory 是被继续生成的解题路径；Credit 通过集合边际成功概率归因给每个候选。论文没有对生成 policy 施加 KL、entropy 正则，也没有给出 PPO/GRPO advantage。可能的 reward hacking 是代理 qᵢ 学到数据集特有的正确性线索，而非可迁移的求解能力。

Experiment Setup / Research Questions / Baselines

模型覆盖 Qwen3-0.6B/1.7B/8B、OpenMath-Nemotron-1.5B/7B、DeepSeek-R1-Distill-Qwen-1.5B/7B 与 Skywork-OR1-Math-7B。题目包括 AIME 2024–2026、HMMT 2024–2026、RIMO-N，以及不同难度的 BeyondAIME、OlymMATH、Omni-MATH、AMO-Bench；每个模型约 600 道题，排除 128 次采样全部正确或全部错误的题。采样 temperature=0.8、top-p=0.95、最大 32768 tokens；主要设置 N=128、T=4000、k∈{1,2,4,8,16}。

采用按 benchmark 分层的 8-fold 交叉验证，20 次随机重复；最终正确性从 boxed answer 提取并用 Qwen3-32B 判断等价性。比较 Random、Linear Probe、RepExp；Random 是无剪枝基准，Linear Probe 是质量强基线，RepExp 是多样性强基线。RQ1：联合优化是否优于两个极端？RQ2：截断位置 T 如何影响质量信号？RQ3：候选池 N 增大后，相关性建模是否更有价值？

Results / Table & Figure Reading / Ablation

Figure 3：DeepSeek-R1-Distill-Qwen-1.5B 在 k=4 时，PKTP 比 Linear Probe 高 3.0 个百分点、比 RepExp 高 3.2 个百分点；DeepSeek-R1-Distill-Qwen-7B 在 k=4 时比 Linear Probe 高 3.3 点。Qwen3-0.6B 在所有 k≥2 的设置中对两个对照都领先超过 2 点。这些是同模型同预算的 pass@k 差值，不能与跨模型绝对准确率混淆。

Figure 4：最强质量候选聚集成“共同失败簇”；Figure 5：纯多样性偏爱离群错误解；Figure 6：Qwen3-1.7B 的 PKTP pass@4 从 T=2000 时的 63.5% 增至 T=8000 时的 65.9%，7B DeepSeek 从 57.4% 到 61.7%。这说明前缀太短时联合预测仍不可靠。Figure 7：池越大，单独质量探针有时反而下降，提示共同失败相关性会随候选池增大变得重要。

最强结果：中等 k 的稳定领先。弱结果：k 很大时与 RepExp 差距缩小；T 很小时优势不稳。代价：需要事先生成 N 条长前缀、训练质量预测器和保留表示，论文报告的 pass@k 不等于等预算 wall-clock 最优；验证器对描述性数学答案也可能误判。

Claim vs Evidence / Contribution / Limitation

Authors Claim：直接优化至少一条成功概率，自然统一质量与多样性。Experiments Actually Show：在八个数学推理模型、既定 N/T/k 和已过滤的题目上，PKTP 优于两种代表性剪枝。Not Yet Proven：对 Web Agent、开放式工具任务、不同 verifier、同算力约束和真实在线延迟的收益。

Contribution：New Objective（集合 pass@k）、New Mechanism（潜在相关性 + 次模贪心）、New Empirical Finding（质量集中失败与多样性离群失败）。作者指出前缀隐表示的质量信号可能很弱；这恰是将其迁移到长程 Agent 的最大风险。

Research Value / Migration · 机制迁移链

Original Problem 数学前缀选择 → Transferable Mechanism 对共同失败进行相关性建模 → New RQ 相同环境初始状态下，选取多条“互补”的 Agent trajectory 能否提升每单位 rollout 的成功率与 credit 信号？→ Modification 用工具调用事件图、状态变更、环境反馈构造 hᵢ，而不是仅用 token EMA；把失败相关性分解为环境噪声与策略动作相似性。

Minimum Experiment：在 WebArena 或 AppWorld 的固定任务子集，每题生成 16–32 条候选执行前缀，预算只延续 4 条；对比 random、top-score、diversity、PKTP-style、相同 token 预算 GRPO 采样。Model：可复现实验的开源 7B/8B Agent；Metric：task success@budget、token、wall-clock、trajectory diversity、reward correlation、错误传播。Expected Contribution：Agent rollout allocation objective；Risk：非平稳工具状态令“同一前缀表示”的相关性不可校准，且轨迹采样成本可能吃掉节省。

Research Priority：可做 baseline / attack-evaluation / 新目标三种用途；最值得先验证的是同一环境快照下的相关失败矩阵是否可预测。

五句话总结

它把“保留最优路径”改为“保留最可能至少有一条成功的路径”。它通过共享潜变量刻画多条候选一起失败的风险。中等预算的数学推理实验支持机制有效。它没有证明 RL 训练或真实 Agent 长程部署的收益。最值得迁移的是集合成功目标与环境可控的相关性 credit。

BeNice! Closing Looping’s Inference-Memory Gap via KV-Sharing

arXiv:2610.31633 · 2026-10-22 · Other / Efficient Inference / KV Cache · 预印本；Venue 未核验

Authors: Hayden Prairie; Jacob M. Ryan; Taylor Berg-Kirkpatrick; Daniel Y. Fu
Affiliation / Status: UC San Diego; Together AI；arXiv preprint，Venue 未核验
Links: Paper · HTML Full Text · PDF
Project / Code: 未核实（Not Verified），不据此声称开源
Read: §3–5、Table 1/4/5/10、Figure 8–10

人话版：这篇论文到底干了什么？

Looped Transformer 反复运行同一组层，可以用较少参数增加有效计算深度，但每次循环都会生成自己的 KV cache，内存随循环次数增加。直接把不同循环的 KV 共用，看似简单，却可能严重损坏语言质量。BeNice! 发现关键不是“缓存能否复用”本身，而是共享与不共享缓存时，隐藏状态是否收敛到相容的固定点。作者先用 stochastic depth 促进收缩动力学，再用专门的后训练损失校正第一次循环的残差，使最终循环的缓存可以供早期循环使用。在内存受限模拟负载中，它显著降低显存、提升吞吐并减少高分位首 token 延迟。

Background & Research Gap / 具体例子

假设一个 1.3B looped 模型每 token 运行 8 次。参数并未变成 8 倍，但若每次都存一份 KV，长上下文服务仍可能被显存限制。简单把第 8 次的 KV 借给第 1 次，第一轮 residual 与原来不兼容，后续误差沿循环累积。论文 Table 1：Parcae 1.3B 在 unshared 下 Lambada BPB 为 0.601，直接 shared 恶化到 2.281；Core-Extended 从 16.73 掉到 13.48。与此同时某些小模型和 Huginn 3.5B 能自然共享，说明可共享性不是架构必然属性。

现有 KV quantization、MLA、KDA 解决的是单份 cache 的大小；looping 产生的是跨 recurrence 的重复 cache。两个维度可叠加，但需要先确保缓存语义兼容。

Core Insight / Method Deep Dive

Input → 同一 token 的循环隐状态 → stochastic-depth 预训练促成 residual dynamics 的 contraction → 测量 shared/unshared 固定点差异 → 构造“第 1 次循环 query/residual + 最后一次循环 KV”的 hybrid predictor → BeNice! 辅助 CE 微调 → 推理时复用最后一次循环 cache → 压低 HBM 并扩大 prefix cache 容量。

作者分析发现，失败并非仅仅来自局部注意力误差，而与不同缓存协议下的固定点偏移有关。收缩动力学使多次循环逐渐逼近稳定表示，但 stochastic depth 并不能保证两种 cache 协议收敛到同一个固定点；因此第二阶段专门校正首次循环的 token-independent basis shift。

关键目标为 L = CE(y,pθ(T)) + γ·CE(y,pθ(1←T))。第一项维持完整多次循环的语言建模质量，第二项要求“第一轮用最终轮 KV”也能预测正确 token；γ 是两者的权重。训练时循环深度仍按预训练分布采样，而不是只适配一个固定 T。该设计是 需要训练 的方法，不是 training-free cache hack。

Toy Example / Baselines

想象连续四轮循环对同一词逐步修正语义表示：轮 1 还在猜实体，轮 4 已形成稳定语义。直接给轮 1 看轮 4 的 KV 可能坐标系不一致；BeNice! 用 hybrid 预测让轮 1 的 query/residual 适应轮 4 的“词典”，使复用变得合法。该例为机制类比，非论文数据。

比较包括原始 Parcae、无共享缓存、直接共享、Standard Finetuning、BeNice!；在兼容性实验中还测试 MHA、MLA、KDA 与 fp8/mxfp8/nvfp4 KV 量化。Strongest baseline 是 unshared + Standard FT 的质量，而不是原始直接共享的较弱设置。

Experiment Setup / RQs / Table Reading

新训练 Parcae 140M、370M、770M、1.3B，在超过 100B climbix tokens 上预训练；公开 770M/1.3B checkpoint 做后训练比较，包含 fineweb-edu validation、Core 与 Core-Extended（46 个下游任务）。对 memory-bound serving 的延迟与吞吐使用模拟长上下文负载及 Mooncake traces，服务负载和 batch/context 设置必须与指标一起看。

额外技术审计：为何这是系统级机制而非简单 KV 剪枝

从工程上看，looped architecture 的 KV 内存开销与循环次数有关，但计算开销并未因为共享缓存而同步消失。模型仍执行多次 recurrence；共享主要让缓存占用与循环深度脱钩。因此评价时应同时记录“每 token 计算时间”“可同时容纳的 prefix token 数”“缓存驱逐后的重新 prefill 成本”，不能把显存减少 66.2% 直接换算成每个请求延迟减少 66.2%。论文中低负载不明显、高负载大幅改善的结果恰好说明瓶颈转移。

更细地看，作者的共享策略利用最后一轮生成的 cache 服务早期轮次，要求缓存内容与当前 query/residual 的坐标系统一。若只是直接把最后轮 cache 复制到前几轮而不做 BeNice!，表格里的 PPL 暴涨就是严重的表示错配证据。BeNice! 的第二项 CE 不是常规蒸馏教师的输出 logits，而是直接约束一个混合缓存协议下的预测器，这一点使其目标具有明确的系统语义。

研究迁移的负对照与部署约束

如果要把机制迁移到 Video VLM，应先做三个负对照：仅共享但不训练；训练相同 token 数的普通 adapter；只做 cache quantization 而不共享。否则即使新方法有效，也无法确认收益来自“跨帧相容性”而非额外训练。其次，镜头切换、物体出现消失和运动突变会破坏帧间同态关系；最好让缓存复用策略显式输出不确定度，并在高风险片段触发重新编码。最后，评测应在单请求、并发饱和、不同视频长度三个区间分别报告 TTFT 和 peak VRAM，避免只挑高负载展示最大收益。

人话版：这篇论文到底干了什么？

流式视频生成要持续生成下一段画面。若每次都对历史全部帧做注意力，成本和显存会随时间增长；若只保留有限窗口，前面的人物、物体和动作关系又容易被忘掉。Attn-Forcing 的想法是保留一个固定规模、可更新的 attention proxy，让它替代被驱逐的历史 KV 对当前 query 的贡献；训练时不仅监督最终画面，还直接用完整历史 attention 的输出监督代理。它在 30 秒和 60 秒生成的 VBench 指标上优于若干同规模自回归视频基线，但相对 LongLive 的实际推理时间约增加 13%。因此这是固定内存条件下的质量—成本折中，不能误写成对 LongLive 的 wall-clock 加速。

Background & Gap / Toy Example

想象生成一分钟街头视频：人物在第 2 秒拿起红伞，到第 40 秒再次出现。固定 8 帧窗口早已丢掉“红伞属于谁”的历史证据；全量 attention 虽可保留却随视频长度变贵。单纯均值池化历史会损失 query 相关性，普通 token 压缩也未必保留“历史对当前 query 的注意力响应”。

本文聚焦 streaming autoregressive video generation 的跨段长期一致性，而不是 Video QA 的 token pruning；“减少历史 attention 的理论增长”不等于实际速度更快。它需要额外训练 proxy 更新模块，且多一次 DiT forward。

Core Insight / Method Deep Dive

Input → 历史视频 latent 与当前生成段 → 把过旧 KV 从有限窗口驱逐 → Proxy Update Module 吸收历史视觉 latent → 用少量 learnable visual latents 形成原生 KV 代理 → 当前 DiT query 同时访问窗口内 KV 和 proxy → 输出下一段视频 → 持续更新 proxy。

作者认为真正需要保留的不是每一帧像素，而是历史 key/value 对未来 query 的“注意力作用”。代理并非把所有旧 token 拼接成越来越长的缓存，而是学习固定规模的 latent 表示。为了避免代理只在图像质量损失上碰巧奏效，加入 Attention Matching Loss：把 proxy 产生的 attention response 与完整历史 KV 的 attention response 对齐。

关键监督构造来自历史 attention 的在线统计与随机特征近似，从而不必在每一步真实存储全部历史 KV 做训练目标；推理时代理通过标准 DiT 路径产生 native KV，避免直接在推理阶段用近似随机特征造成误差积累。训练包括 causal initialization、DMD 和 streaming long tuning。

Objective（概念化，不冒充原文等式）：生成质量目标 + λ × 历史注意力响应匹配误差。这里 λ 仅为解释权衡的示意变量；论文实际联合目标见正文 Eq.(17)。核心变量是历史 query、proxy KV、全历史 KV、proxy 数量与历史近似随机特征数 M。

骨干为 Wan2.1-T2V-1.3B，832×480；从 Self-Forcing 的 causal init 出发并进行 DMD，再按 LongLive 方式做 60 秒序列训练。5 秒/30 秒使用 946 个 VBench prompts、每个 5 个种子，60 秒使用 128 个 MovieGen prompts。对照包括 Self-Forcing、Causal-Forcing、LongLive，短视频还对照 LTX-Video 和 Wan2.1。

额外技术审计：代理记忆究竟保存了什么

这里需要区分“保存视觉外观”和“保存对未来 query 的响应”。传统帧压缩可以在重建误差上很小，却可能丢失一个后来才被询问的细节。Attn-Forcing 把监督直接施加在 attention response 上，使压缩目标与下游 DiT 的读取操作耦合。它更像学习一个可以被未来注意力查询访问的隐式索引，而非通用的视频摘要。代价是代理只对训练时出现的 query 分布有保证；若未来 query 突然要求一个历史中极少被关注的对象，压缩后的代理仍可能无法恢复。

值得关注的另一个机制细节是代理的更新与生成耦合。生成时模型自己产生的画面会进入后续上下文，早期错误可能通过 proxy 被固化为“历史事实”。因此长视频评估不能只看单帧清晰度，还应构造事件反转、人物交换物品、长时间遮挡后重新出现等定向测试，观察错误是否在后续几十秒被持续放大。

系统预算与负面证据

与 LongLive 相比，30 秒总分只高 0.70，却要付出额外 proxy update 和一次 DiT 前向；60 秒时总分收益变成 3.11，表明方法更适合长历史场景。若产品只生成 5 秒短片，13% 的额外推理成本可能不值得；若产品要连续生成一分钟且运动连续性是关键，收益则更有意义。这是长度依赖的质量—成本曲线，而不是单点 SOTA。

从未来论文角度，真正可发表的切入点不是简单把代理 token 数从 128 调到 64，而是提出按事件不确定度自适应增减代理容量，并在固定峰值显存与相同 wall-clock 预算下比较质量。必须同时给出同长度、同硬件、同采样步数的对照，才能区分更好训练与更高推理开销的贡献。

人话版：这篇论文到底干了什么？

很多长期 Agent 以为“用上用户记忆”就等于“更懂用户”，但用户未必喜欢这种个性化。作者让 87 位参与者使用自己的查询和记忆，评价带记忆与不带记忆的回答，得到约一千组偏好判断。结果发现记忆回答并不稳定获胜，现成 LLM judge 反而显著偏向记忆回答。作者于是让 judge 先对多个可解释 rubric 打分，再从真实用户偏好中学习各项权重，达到 72.8% 的偏好预测准确率。这不是已完成的 RLHF 训练，而是为未来 memory policy / reward design 提供了更贴近真实用户的监督信号。

Background & Research Gap

Memory retrieval 的 Hit@K、长期对话事实记忆率不等于用户效用：假设用户问“今天吃什么”，模型因记得用户上月想减脂就反复说教，虽然记忆准确却可能令人反感。论文把“记忆正确”和“是否应该使用记忆”拆开。

作者还发现人类偏好本身有噪声：10 位参与者三天后重复判断 75 对回答，总体方向一致率 68.0%；强偏好 73.9%，弱偏好 58.6%。因此模型评测只选更清晰的 much better 对比，这会提高信号纯度，但也限制对模糊偏好的外推。

Core Insight / Method / RL Reward Analysis

Input → 用户 query + 个人 memory + 两份候选回答 → 自动 rubric evaluator 分别评估 memory relevance、assumption proportionality、unwarranted personal assumptions 以及表达属性 → 线性加权 reward Rw=wᵀφ → 用用户 pairwise choice 拟合权重 → 输出哪份回答更符合用户偏好。

核心概率模型是 Bradley–Terry：P(yₐ≻yᵦ|q)=σ(R(q,yₐ)−R(q,yᵦ))。State 为 query+memory，Action 是回答是否引用记忆及其呈现方式，Reward 是人类成对偏好；它是 learned preference reward，尚未用于在线 RL。风险包括对长度、标题等格式偏好的过拟合，以及 reward hacking：只让回答更长而不让记忆更有用。

Experiments / Results / Table Reading

RQ1：用户到底是否更喜欢记忆回答？普通提示下记忆版获偏好 38.7%、无记忆版 41.9%；保守个性化的记忆偏好 43.3%，激进个性化降到 34.6%，且后者无记忆回答获偏好 49.3%。这说明“更多 personalization”不是单调增益。

RQ2：自动 judge 能否代替用户？Table 3：多数类基线 55.0%、直接 GPT-5.2 judge 58.1%、Skywork with-memory 52.9%、本文 72.8%。自动评估选择记忆版的比例 67.2% / 81.1%，真实用户约 45.0%，存在系统性偏差。

RQ3：记忆特征是否有独立价值？response-only 67.0%、memory-only 62.5%、combined 72.8%；在 25% 最高置信覆盖率下准确率 88.8%。Table 4 的标题数、长度系数较大，提示模型可能同时学到表现形式偏好。

长期 Web Agent 会反复替同一个用户订票、购物和安排行程，但有些偏好用户从未主动说过。当前任务不值得打扰用户去问的问题，可能在未来十次任务中反复有用。APA 把“现在问一次，未来能复用多少次”变成 Prospective Personalization Value：预期跨任务效用增益减去提问成本与信息披露风险，再在预算内挑要问的偏好。作者用可计算真实效用的模拟长期任务验证，20 任务 horizon 下，它能捕获大部分必须靠长期摊销才划算的偏好。

Background / Core Insight / Agent Architecture

传统被动 memory 只能记住用户说过的东西，current-task VOI 只关心当下收益。比如用户首次订票时，“靠窗/靠过道”不值得打断；若未来 20 次出行都受其影响，一次询问可能有很高累计价值。

Input → 当前 user profile + 任务 → 发现缺失偏好 → 预测未来任务 family 及复用频率 → 在公开 task prototypes 上反事实评估“知道/不知道偏好”对 agent solver 的效用 → 扣除询问 effort 与 disclosure-risk → budgeted question selection → 更新 profile → 后续任务复用。

Agent state 包括 profile、task-family 统计、历史交互与提问预算；错误传播风险是错误地认为某个偏好稳定，从而在未来大量任务中反复误用。论文没有给出多 Agent 共享 profile 下的隐私传播证明。

Experiments / Results / RQ

ActiveWebPref 是带隐藏但可询问 user profile、精确任务效用的受控 longitudinal benchmark；作者比较当前任务 VOI 和四种 heuristic acquisition policy，按询问成本预算做匹配。

在 horizon=20 时，预算可行且有价值的缺失偏好中 34.4% 必须靠未来复用才能摊销；APA 发现其中 80.3%，current-task VOI 只有 5.1%。APA 仅用全部询问策略 27.6% 的问题数，获得其 84.2% 的效用增益。

RQ1：跨任务预期价值是否胜过只看当前？RQ2：问得越多是否越好？在论文成本设置中，问完所有未知偏好反而比完全不问净效用更差，说明提问本身是资源与隐私成本。

Contribution / Limitation / Research Value

New Objective：PPV 的长期摊销；New Benchmark：ActiveWebPref；New Mechanism：反事实任务原型 + budgeted acquisition。限制：用户是模拟的、未来任务分布可能估错、单一 backbone 与 benchmark 的外推性有限，偏好漂移会让“长期复用”失效。

对 Agent Memory 的迁移价值：memory 写入不只是“记录观察”，也可以主动采集高复用偏好；若与 human-preference reward 联合训练，可形成 Ask / Remember / Ignore 的完整决策环。

Migration / MVE / Worth Deep Reading

Worth Deep Reading: YES；优先 §3–6 的 PPV 定义、Table/ablation 和负结果。

额外机制分析：PPV 与普通 VOI 的根本区别

普通 VOI 估计当前这次询问能否改变马上要执行的动作；PPV 关心这条偏好在未来任务中会被复用多少次。两者并不互斥：在同一时刻，一个问题可能对当前任务毫无帮助，却能长期降低错误选择；反过来，一个只在今天有效的偏好即使当前收益很大，也不应被永久写成高置信记忆。

作者的长期价值估计依赖未来任务 family 的概率与模拟 solver 的反事实效用，这为长期 Agent 提供可操作目标，但也带来模型误设：如果未来任务分布突变，过去估计的复用价值会失效。因此需要加入偏好有效期、主动过期机制和用户撤销后的删除闭包，并检验是否会因为过度预测未来收益而频繁打扰用户。

可验证的新实验方向

与 Memory-Aware Reward 结合时，不能只看模拟器的 exact utility。应引入真实用户小样本偏好、提问频率上限、敏感信息惩罚，以及“不问”的拒绝选项。最有价值的负结果可能是：预测未来越自信，真实用户越容易觉得 Agent 越界；这会直接挑战单纯最大化长期任务成功率的目标。

人话版：这篇论文到底干了什么？

Speculative decoding 的小 drafter 在长输入、长输出时也会被 KV cache 限制。只按 prefill 重要性保留 KV，生成越久就越容易忽视新 token，这种现象被作者称为 decode staleness。RIFT 通过滑窗与动态重选缓存平衡旧输入和新生成内容，再用稀疏 attention mask 训练更适合压缩的 drafter。关键价值是把“缓存该留谁”从一次性预处理改成随生成过程更新的策略。 如果不区分草稿模型的接受长度和整个系统的速度，缓存压缩收益就很容易被夸大。它特别适合研究长输出时缓存信息如何逐渐过时。

Background / Method / Main Finding

Input → 32K prompt + draft tokens → prefill cache selection → 动态或自适应 refresh → 保留近期 decode token + 关键 prefill token → 稀疏 mask compressibility training → draft acceptance。刷新频繁会提高质量也增加计算，因此必须测 acceptance length 和 wall-clock。

在 Qwen3.5-4B 为 Qwen3.5-122B 草拟、32K 输入、4K 输出、8K KV 预算时，结合压缩训练后保持 full-cache acceptance length 的 98% 以上。这是 acceptance length 比例，不是 98% 任务准确率或 98% speedup。

Contribution / Limitation / Connection

New Mechanism：decode staleness-aware cache refresh；New Training：稀疏掩码的压缩适应。弱点：refresh 评分本身有延迟，cache hit 与 speculative acceptance 不保证端到端吞吐提升。与 BeNice! 的互补在于一个解决随时间的 cache 选择，一个解决跨循环的 cache 兼容。

Potential Use：长输出 coding agent / streaming agent 的 KV 生命周期。最小验证应记录 acceptance length、draft tokens/s、target calls、p95 TTFT 与显存，而非只看 KV 数量。

细节补充：训练与推理为什么要联动

如果 drafter 训练时总能看到完整 KV，部署时突然压缩到 8K token，就会产生训练—推理分布差异。RIFT 不只在推理时调整哪些 token 保留，还在训练时用稀疏 attention mask 让模型习惯压缩后的可见历史。这与“先训练满上下文，再临时裁剪”的方案有机制区别。

重要的系统权衡是 refresh 太少会使新生成内容被忽视，refresh 太频繁又会增加每步评分开销。应比较静态缓存、固定间隔 refresh、adaptive refresh 三种策略的 acceptance length、draft latency、target-model 调用次数和最终 tokens/s。论文报告 98% full-cache acceptance length 是强证据，但不是整个 speculative decoding 系统 98% 的速度保持率。

研究连接

它与视频跨帧 cache 的共同问题是“缓存选择随新观测变旧”。但文本 decode 与视频帧变化的时间尺度不同；迁移时需要定义 scene-change-aware staleness，而不是简单把 token 位置当作时间。

人话版：这篇论文到底干了什么？

很多自动设计 Agent 架构的论文在静态任务集上不断尝试角色数量和工具拓扑，选到高分配置就部署，却忽视切换成本、环境漂移和一次错误架构更新可能造成的连锁损失。CMAS 把系统结构搜索变成“保守替换当前已运行架构”的序贯决策：从历史结构提议类型化图编辑，配对影子重放做对照，再通过风险校准的 promotion gate、canary 与 rollback 决定是否上线。 该方法强调一次架构更新可能带来长期连锁影响，因此必须把搜索成本、切换成本和回滚风险一起纳入评估，而非只看某次任务的高分。

Background / Method / Results

Input → 当前 incumbent graph + 历史 archive + 任务流 → typed edits → common-random-number paired replay → interventional component credit → variance-penalized promotion score → simulated canary / rollback。实验用作者构建的 MetaInvest-Bench，包含 regime shift、负对照与可计算的 surrogate oracle。

96 条模拟 stream 上，相对最强 adaptive baseline，归一化 surrogate dynamic-oracle regret 0.116→0.104，held-out utility 0.44→0.48；部署推理成本约低 6%，但含搜索的 token 总成本最高。错误 promotion 率 3.4%，封闭复测 4.8%，并非长期安全保证。

Contribution / Limitation / Connection

New Objective：带切换成本与风险约束的架构替换；New Benchmark：MetaInvest-Bench；New Mechanism：paired shadow replay + interventional credit。弱点是作者自建金融模拟器、模型/任务分布受限，负对照不能代替真实系统部署。

Potential Use：Agent memory/skill policy 的安全更新和多 Agent 动态 topology；最小实验是在软件工程 Agent 上用真实任务回放测 promotion false-positive、rollback cost 和长期 task success。

额外方法审计：反事实 credit 与保守上线

CMAS 使用 common random numbers 做配对 replay 的意义，是尽可能让候选架构和当前架构面对相同外部扰动，减少把“运气更好”误判为“结构更好”。interventional component credit 则进一步问：移除或替换一个 worker 后，系统最终效用究竟变化多少。这个思路与 Agent memory/skill attribution 非常接近。

但论文的风险控制是对更新级统计量做经验校准，不能保证连续上线几十次后累计失败概率仍然小于名义阈值。3.4% 与 4.8% 的 false-promotion 率是在其受控模拟条件下观测的结果，不应解释为真实生产系统的安全保证。

系统部署与碰撞

若要迁移到 coding agent，必须把搜索阶段 token 计入总成本：论文虽然报告部署推理约节省 6%，但搜索包含的 token 开销最高。应绘制“部署多少次后才能摊销搜索成本”的 break-even 曲线，并加入失败回滚的人力成本。与 RoleFlow 的撞题点是结构自适应；差异化空间在风险校准、真实 canary 与长期非平稳更新。
