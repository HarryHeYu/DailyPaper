Title: Self-Credit: Credit Assignment for Long-Horizon Agentic RL via Intra-group Rescaling · Authors: Fangcong Yin et al. · Affiliation: Meta / Duke University / New York University · Date: 2026-10-20 · Venue/Status: arXiv preprint；正式 Venue 未核实 · Paper: arXiv · Full text: HTML 正文 · Code: 未在已核验页面确认公开代码

人话版：这篇论文到底干了什么？

长链路搜索 Agent 可能连续检索十几次，最后才知道答对没有。传统 GRPO 把同一个成功或失败奖励广播给整条轨迹，结果连无用的搜索动作也被鼓励。Self-Credit 让 Agent 在压缩上下文时顺便引用“哪些历史轮次提供了关键证据”，再把同一道题多条成功、失败轨迹放在一起比较：只有成功轨迹反复引用的动作才应加奖，失败轨迹反复引用的动作应加重惩罚。最后将这些权重乘到 token advantage 上。它在 BrowseComp-Plus 的 8B 模型上达到 40.6%，强基线为 32.1%，核心价值是把“轨迹中的证据归因”变成可用于 RL 的密集训练信号。

Background & Research Gap

RLVR 的终局奖励通常只有答对或答错，无法知道究竟哪次搜索、打开网页或提炼证据改变了答案。例如 Agent 先搜索错误关键词，后来偶然打开正确网页，最终答对；统一正 advantage 会强化两种行为。GiGPO 借助组内轨迹重加权，ECHO 倾向从成功轨迹选关键轮次，SUPO 处理长上下文摘要，但三者没有同时把“自我引用、正反轨迹对照、turn-level advantage”连成闭环。作者观察到摘要中的引用天然表达 Agent 对证据重要性的判断，但这种判断可能自我合理化，因此必须用不同 rollout 的 outcome 校正。

Core Insight 与完整 Method Deep Dive

Input → 同一问题采样 G 条搜索轨迹 → 触发 self-compaction 并生成带 turn index 的摘要 → 匹配组内相似动作 → 按成功/失败共现重缩放引用权重 → 形成 turn-level advantage → clipped policy optimization → 更新 Agent。

第一步是引用式压缩。Agent 的历史越来越长时，自己写摘要并标出关键历史轮次；摘要同时作为下一段推理的上下文，而引用索引成为 credit 候选。它不是让外部更强模型标注关键步，节约了监督成本。第二步是组内匹配。对同一 prompt 的成功与失败 rollout，比较可匹配的工具动作；成功与失败都出现的动作不应被强力正奖，因为它不足以区分 outcome。仅在多条成功轨迹重复出现的动作给予更大正权重；仅在多条失败轨迹重复出现的动作放大负 advantage。无法匹配的动作保留基础权重，summary 与 final-answer turn 不参与组内匹配，避免错误扣分。第三步按 turn 将权重广播到本轮模型 token，再进行带 clip 的策略优化。重复失败的惩罚权重采用 annealing：训练初期重罚低质量检索，后期放松以免抑制探索。

Baseline、实验设置与 Research Questions

主实验采用 Qwen3-8B、Qwen3-32B 和 Gemma4-E4B（thinking mode），BrowseComp-Plus 按 747 train / 83 test 划分；深度研究训练用 OpenResearcher 的 1K QA，评测 GAIA 文本子集与 xBench-DeepSearch。对照 Zero-shot、GRPO、GiGPO、SUPO、ECHO；其中 BrowseComp-Plus 最强常规基线为 ECHO（32B 41.4，8B ECHO 与 SUPO 同为 32.1），深度研究任务则随 benchmark 变化。研究问题包括：RQ1 终局奖励能否被拆成有效 turn-level 信号？RQ2 组内正负对照是否优于只看成功轨迹？RQ3 更高正确率是否靠无节制增加搜索轮数换来？RQ4 自引用是否真的指向关键证据？

RL Formulation / Reward / Training Efficiency

State 是当前 query、历史摘要与检索环境状态；Action 是搜索、打开文档、继续推理及回答；Policy 是带工具接口的 LLM；Trajectory 是跨多个 compaction segment 的动作与 token 序列；Reward 是终局正确性驱动的稀疏 outcome；Advantage 来自 group-relative reward，再被引用权重局部修正。没有证明引用具有真实因果效应，存在“Agent 学会引用看似重要的步骤来刷梯度”的 reward/credit hacking 风险。组内匹配需要多条 rollout，训练开销不可视为零；公开摘要和所读正文没有足以安全转述的完整 GPU-hours 数字，因此不填造 rollout 成本。KL/entropy 等正则以论文具体训练配置为准，不把常见 GRPO 默认值当成本文实测。

Claim vs Evidence

Authors Claim：自生成引用配合正反轨迹比较，能为长链路 Agent 提供更准确的 credit。Experiments Actually Show：三项 QA/search benchmark 上成功率更高，证据搜索/打开与引用质量改善，工具轮数并非单调增加。What Is Not Yet Proven：引用是否等价于干预意义的因果贡献、遇到对抗网页时引用是否可靠、跨多 Agent 与真实数百步任务是否同样成立。

Contribution、Limitation 与 Research Value

贡献类型：New Mechanism（引用式自监督 credit）、New Objective / Training Signal（turn advantage 重加权）、New Empirical Finding（失败轨迹能纠正成功轨迹的伪 credit）。作者机制的弱点是动作匹配依赖语义近似、组内对照可能把“经常共同出现”的关键前置步骤误判为非关键；不同 prompt 的长期经验价值也尚未衡量。作为 Baseline Potential，最适合与 GRPO/ECHO/GiGPO 做直接复现；System Value 在于把日志中已有的摘要/引用变成监督；Benchmark Value 在于引用 F1 与 Gold Opened 的细粒度评估；Attack/Evaluation Value 是检查 citation spoofing；New Paper Potential 在于将信用分配扩展到 memory、skill 与跨 Agent 信息传递。

Research Migration：RL × Memory × Multi-Agent

Original Problem → 单 Agent 搜索轨迹中的动作 credit。Transferable Mechanism → 自引用与成功/失败对照。New Research Question → 哪一条历史 memory 或哪一个 Agent 的消息真正促成下一轮任务成功？Method Modification → 在 trajectory 中为 retrieved memory、tool result、agent message 记录可验证来源 ID，对成功/失败 rollout 做 leave-one-out 反事实替换，再用反事实 outcome 校准引用权重。Minimum Experiment → 在固定模型和相同任务预算下，对照均匀 GRPO、Self-Credit、只按引用加权、引用+反事实。Model → Qwen3-8B；Dataset → BrowseComp-Plus / ALFWorld 的可重放任务；Baseline → GRPO / ECHO / Self-Credit；Metric → success、credit precision、rollout cost、memory reuse utility；Expected Contribution → 从自述重要性迈向可干预的 memory credit；Risk → 环境随机性、反事实重放成本、动作不可交换。可先用 100–200 条轨迹检验方向，再决定是否上大规模训练。

五句话总结

这篇工作的核心不是新 reward model，而是把稀疏奖励按证据引用分给历史动作。成功与失败 rollout 的对照比单看成功轨迹更可信。8B 上 40.6 对 32.1 的提升足以值得复现。Evidence Recall 的反例提示不要过度宣传“所有证据指标都更好”。最值得延伸的是 Memory / Tool / Agent message 的反事实信用分配。

Title: Cache Locally, Recompute Selectively for Streaming Video Understanding · Authors: Junhyeok Lee, Sangyoon Lee, Jaeho Lee · Affiliation: POSTECH · Date: 2026-10-21 · Venue/Status: arXiv preprint · Paper: arXiv · Full text: HTML 正文 · Code: 未在已核验页面确认公开代码

人话版：这篇论文到底干了什么？

直播视频理解模型常在用户提问前就把视频帧预计算成 KV cache，问题是当时不知道未来会问什么：缓存上下文太短，重要场景联系会丢；太长，又耗时耗显存。FrameBlend 采用“平时短窗口缓存、提问后只重新算相关 token”的分工。它利用现有检索框架的跨层 token 选择结果，找出最可能影响答案的 token，重新 prefill 并替换缓存中的 KV，不训练模型。在 RVS-Ego 上，ReKV 总处理延迟从 90.6 秒降到 37.4 秒，准确率从 59.3 升到 62.4；但提问后的 TTFT 从 0.17 秒增至 0.93 秒。它真正有价值的不是“缓存越多越好”，而是把计算分配给知道 query 之后最有用的部分。

Background & Gap：为什么传统 KV Reuse 不够？

Streaming Video Understanding（SVU）有两个不同的时钟：视频流持续到来时的 idle-time prefill 与用户提问后的 query-time decoding。ReKV、LiveVLM 通过预先缓存 KV 降低查询时延，HERMES 使用压缩；但未来 query 不可知，早期 KV 的上下文化容易吸收不相关内容，同时长窗口每帧重复注意力成本高。想象一小时摄像头视频，用户最后问“钥匙被放在哪里”；预缓存时无法知道钥匙相关的 40 帧最重要，统一扩大历史窗口既浪费，又可能把无关人物、背景编码进 token。作者的观察是：既然查询时检索框架已找到相关 KV，那么可以只为这些 KV 支付一次重计算成本，并因此把此前每帧的窗口缩短。

Core Insight / Method Deep Dive

视频流 → 视觉 token → 短窗口 idle prefill → 持久 KV cache → query 到达 → backbone 检索候选 KV → QTS 选重算 token → 联合 re-prefill → 用新 KV 替换旧 KV → 解码答案。

第一阶段保持视频流处理接口不变，只把 prefill attention window 缩短；旧 KV 可以迁移到 CPU memory。第二阶段查询到来，ReKV/LiveVLM 等原框架根据 query 选出各层要加载的 KV。FrameBlend 的 QTS 不另训一个 selector，而是统计每个 token 在多少层被原框架选中：跨层一致性越高，越值得重算。第三阶段将选中的 token 按时间顺序联合通过 LLM 各层，用 query 相关的上下文重新得到 KV，再替换原缓存的对应位置。对于 HERMES 这种不做相同查询检索的框架，QTS 使用额外相似度选择，因此开销与适配细节不同。方法不减少视频采样帧率，而是降低每帧注意力计算并选择性更新 token 的上下文化表示。

公式、变量与 Toy Example

φ(xᵢ)=Σₗ 1[cᵢˡ∈Sˡ]，P=TopKₓ φ(x)。xᵢ 是第 i 个视觉 token，Sˡ 是 backbone 第 l 层原本选择的缓存 KV 集合，φ 表示它跨层被选中的次数，P 是需要重新 prefill 的 token 集。作者设 K=7,840 视频 token，对 LLaVA-OV-7B 大约对应 40 帧。一个例子：查询“红杯子何时被移走”，token A 在 28 层检索中出现 25 次，背景 token B 只出现 2 次；优先重算 A，可让答案看到与杯子相关的历史，而不是对全流重新编码。此选择依赖 backbone 的检索质量，若跨层一致地选错，FrameBlend 也会重算错对象。

模型为 LLaVA-OneVision-7B、Qwen2.5-VL-7B；SVU 框架为 ReKV、LiveVLM、HERMES。Streaming：OVO-Bench、RVS-Ego、RVS-Movie；offline：MLVU、Video-MME（无字幕）、EgoSchema。采样统一 0.5 FPS，效率测试在单张 A100 80GB 上进行。RQ1 同一 backbone 下准确率是否提高？RQ2 平时省下的 FLOPs 是否覆盖查询时重算？RQ3 额外 TTFT 是否在可接受范围？RQ4 缩窗口和重算单独使用能否产生同样效果？RQ5 是否适配不同缓存架构？必须注意：论文给的是固定采样 FPS 下的推理改进，不是视频解码器 FPS 加速。

额外的部署诊断：为什么不能只看 speedup

FrameBlend 体现了三个不同的优化目标。单帧 prefill 决定长期视频持续运行的算力账单；查询 TTFT 决定用户交互体验；端到端总延迟 决定离线评测的累计处理时间。若用户一分钟只提一次问，节省的数百帧 prefill 足以覆盖一次 0.76 秒重算；若每秒问一次，重算成本可能反过来主导。论文 Table 3 是按 RVS-Ego 的查询分布计算，不代表任意查询到达率。复现时应固定同一视频流，改变每分钟查询次数并画出 TTFT p95、GPU busy time 与准确率曲线。

还有一个经常被忽略的指标是 cache correctness：跨层频次 φ 可能偏好被重复检索的背景 token，而不是短暂出现但决定答案的异常事件。可将输入按静态镜头、快速切镜头、稀有事件、长时间重复动作分组；比较 TopK 命中关键证据的 recall 与重算后的 answer confidence。真正强的系统论文应报告不同事件密度下的收益边界，而不是仅用平均视频长度描述效率。

五句话总结

FrameBlend 把一部分计算从“提问前”推迟到“提问后”。它用现有检索结果做跨层 token 重要性统计，避免再训练 selector。ReKV 的总时延从 90.6 秒降到 37.4 秒，但 TTFT 从 0.17 增至 0.93 秒。准确率大体提升，却有个别指标小幅下降。最值得做的下一步是 Query-aware / Reward-aware 动态 KV 重算预算。

人话版：这篇论文到底干了什么？

多 Agent 协作时，真正难的不是自己会不会推理，而是猜测队友“知道什么、想做什么、下一步会怎么行动”。传统做法让 LLM 用文字猜队友想法，容易过早锁定单一解释。ToM2Vec 让 Agent 在隐空间生成固定数量的连续 ToM tokens：训练时通过 self-play 获取伙伴真实思考轨迹，并学习预测其压缩后的隐表示；推理时不需要看到伙伴真实思维链，就能用这些 tokens 调节自己的决策。Overcooked 三布局平均得分由 94.7 升到 106.7，多方谈判达成率从 62% 到 71%。这篇论文的重要性在于把跨 Agent 的“伙伴状态建模”从文本提示变成可训练、可迁移的表示机制。

Background & Research Gap

一个厨房协作例子：Agent A 看到队友 B 在拿盘子，却不知道 B 是准备送餐还是清理桌面；A 若错误判断，可能两人都去拿盘子，造成资源冲突。Prompted ToM、SimToM、Adaptive ToM 通过文字猜测对方信念，但自然语言通常输出一个确定故事，难以容纳多个可能意图；且多轮对话消耗 token。作者的 observation 是：伙伴真实 reasoning trace 在训练时可采集，没必要把这种知识硬压成离散文字。一个固定预算的隐空间可以学到更灵活的伙伴状态摘要，供自己后续生成条件化。

Core Insight / Method Deep Dive

Agent 自身局部观察 cₜ → 生成 K 个 latent ToM tokens ẑₜ → 将 ẑₜ 作为后续思考与动作条件 → 执行与交互。 训练时另有：self-play 采集伙伴 CoT → 将伙伴 CoT 压缩成 latent teacher targets → 训练主 Agent 预测 targets → 在任务轨迹中继续训练与评估。

第一步定义部分可观测的多 Agent 环境。每个 Agent 只能看到自己的历史、任务角色与局部状态，不能假设知道队友所有私有信息。第二步采用类似 Coconut 的 latent recurrence：模型每步不将隐藏状态解码成文本 token，而是把上一隐藏状态作为下一步输入 embedding，重复 K 次生成连续 ToM token。第三步利用伙伴的真实 CoT 构造监督：不是预测队友下一句话，而是学习一个能代表其潜在意图的隐空间。第四步在推理阶段将预测的 ToM tokens 作为生成自身思考/动作的条件，不需要获取伙伴私有 CoT。这里并非 MARL 的显式共享奖励分解，也不是不需要训练的 prompt trick；其训练监督来自伙伴思维链，目标与任务 outcome 的关系需要单独检验。

关键公式与 Toy Example

论文形式化为 ẑₜ = Latent_K(Bθ; cₜᴹ)，cₜᴹ 是主 Agent 的局部上下文，Bθ 是可训练模型，K 是固定 latent steps，ẑₜ 是 K 个连续向量。直觉是“把对队友的多种可能猜测藏在向量中，而不是用一段文字宣布队友一定想做 X”。若队友刚拿起洋葱，文字推理可能写“他要切菜”；latent 表示则可保留“切菜/交给我/送去锅边”等不确定性线索，再根据后续观察修正。重要区分：论文证明 latent 条件化有用，并未数学证明向量等价于完整贝叶斯信念分布。

额外分析：隐空间表示究竟学到了什么？

Table 7 的三种 probing 很重要：它把“协作得分提高”拆成伙伴 belief、desire、action 的可检验预测，避免仅凭总分推断模型一定学会心智推理。不过 probing 的 ground truth 来自伙伴继续生成的自述或下一动作，仍可能与伙伴真实的长期目标有差距；尤其 belief 是二阶问题（我猜队友认为我想做什么），更容易出现自述不一致。Table 8 通过替换布局和恶意意图检验向量是否敏感，但 PPL 区分也可能来自表面上下文特征。进一步的强实验应让不同伙伴在表面行动相同、私有目标不同的条件下行动，再检查 ToM2Vec 是否能预测分叉点。

Title: Memory-Centric Continual Learning for AI Agents · Authors: Dongfang Li et al. · Affiliation: 详见论文正文 · Date: 2026-10-21 · Venue/Status: arXiv preprint · Paper: arXiv · Full text: HTML 正文 · Code: 未核实

人话版：这篇论文到底干了什么？

很多 Agent Memory 论文只测“是否能从历史对话里找到事实”，却没有回答记忆是否真的让 Agent 下一次行动更好。Memory-Centric Continual Learning（MCCL）提出一个研究框架：用 substrate（存在哪里）、asset（存什么）、policy（怎么管）三轴描述记忆，并把更新 memory state 的内循环与优化 memory management policy 的外循环分开。它进一步提出在干扰、环境变化、任务迁移下测试真实行为收益，并讨论经验量、存储容量和计算预算的 scaling 关系。其价值是改变评估标准，而不是推出一个已被实验证明全面领先的新模型。

Background / Core Method

Passive retrieval cache 的“召回准确率”容易被长上下文堆叠取巧：把所有历史放进 prompt，答对事实题，不等于能持续学会新的工具策略。MCCL 的流程是 交互 → 提取 memory assets → 通过 policy 管理存储/检索/更新 → 执行后续任务 → 观察行为收益 → 外循环优化管理策略。它区分 memory capacity、经验增长和 compute budget，以免将更多 token 误判为更聪明。

Experiment / Main Finding

这是框架与评估协议导向的工作，所读摘要没有可核验的单一模型胜率或消融数字，不填造“提升 X%”。其 Research Questions 更重要：在干扰下是否保持旧技能？新事实冲突时是否适应？旧经验是否改善新任务？更大 memory 是真正持续学习还是单纯更长 prompt？后续应查正文具体 benchmark 与 protocol 的可执行性。

Contribution / Limitation / Connection

贡献为 New Taxonomy / Evaluation Protocol / Scaling Framework，不是已经证明的 SOTA training algorithm。限制是理论框架宽、具体可重复实验与因果归因仍待社区落实。它与 D-Skill、PreCoMem、Self-Credit 形成研究闭环：写什么、保留什么、哪条经验促成后续成功。作为 Agent Memory 的实验设计参考很有价值，但因缺少本轮可核验的强定量证据放 Tier B。

Potential Use

最小实验：固定模型与总 token 预算，对比 append-only memory、检索压缩、行为收益筛选与带反事实 credit 的 memory policy；在 100 个连续任务上画 future success vs memory size vs inference cost 的三维曲线，并增加版本变化与恶意记忆干扰。重点报告行为收益，不只报告 recall。

最低实验要求

如果要把 MCCL 用作研究基线，至少需要固定模型、数据顺序、历史长度上限与工具预算，分别测 retention、adaptation、transfer 三种不同性质。建议对 memory store 做版本化快照，并保存每次写入和检索的来源，使未来的任务增益可以回溯到具体经验。只有在相同 token 与执行成本下改善未来行动，才能称为真正的 continual learning。
