02 · Today’s Most Important Paper

SPROUT — Long-Horizon Coding Agent 的状态恢复与 RL 数据效率

**为什么今天最重要：**在 Agent RL 中，失败轨迹的最大浪费常常不是缺少 reward 设计，而是重复执行昂贵的有效前缀。SPROUT 给出了可操作的系统闭环：环境与上下文成对快照、verifier 指导局部回退、成功分支训练、共享前缀去重。其价值可以迁移到长期 Coding Agent 和多 Agent 任务交接，并且论文同时报告成功率、token 与训练每步 wall-clock。

**READ NOW：**先读 §3.3 Restorable Execution States、§3.4 Verifier-guided Backtracking、§3.5 Policy Optimization，再看 Figure 3、Table 2/3、Table 4。核心审稿问题是：有多少收益来自更多可尝试分支，有多少来自真正的策略更新？系统假设（同步 shell、无后台进程）能否推广？

本日最值得借鉴的机制：把不可用的失败轨迹变成可恢复、可验证、可归因的局部学习样本。

05 · RL Highlights

今天 RL 的主轴是 sparse reward 下的可用 credit 与 rollout 成本。 SPROUT 用执行状态分支提高可验证成功样本密度；VH-GPO 通过最早可独立完成的 teacher handoff 提供恢复监督；LVRL 用 frozen LLM value critic 提供 step credit；LEAF 将失败反馈作为同题探索记忆；CoCA 将 rubric criterion 的 outcome 转为 token credit。它们回答的是不同层次的问题：采样从哪里开始、谁帮助修复、哪一步贡献了结果、哪些反馈可以复用。

**必须避免的混淆：**SPROUT 的 pass@search 提升不等于训练后单次成功率；LVRL 的 critic 推理成本不等于零；VH-GPO 的 Teacher 生成占比不等于全流程 FLOPs；CoCA 的 4.2% 不能擅自改写成 4.2pp。

06 · Agent / Multi-Agent Highlights

今天 Agent 的主轴是 communication、reflection、skill 与 memory lifecycle。 PACO 证明优化发送/接收的共同协议优于只做消息改写；Agent-Reflex 让反思成为可训练的恢复行为；EvoSpatial 把空间经验绑定到可执行技能和工具；MemForm 说明相同经验的保存顺序都可能改变未来行为。

**最值得追问的问题：**某条交接消息是否真正导致后续成功？某个 memory/skill 是正贡献还是污染？一条错误工具观察在 10/100/1000 步后怎样传播？现有论文对后两种长程问题的实验证据仍不充分。

07 · Video Acceleration Highlights

今天 Video 的主轴是三种不同“省计算”对象。 FoveaTree 减少 Video LLM 的视觉 token，报告 30% 保留率时 TFLOPs −53.2% 但 latency 只 −19.2%；TGuide 减少视频生成中昂贵的去噪 backbone 计算，在 333 帧 Self Forcing 上 32.93s→17.46s；FrameFold 以 attention response 保真约束固定 KV 预算，但不能从质量提升推断实际 FPS 加速。Open-o3-Video-v2 更像按需视觉证据获取，不应冒称 inference acceleration。

**研究机会：**统一比较 Frames / Tokens / TFLOPs / Latency / GPU Memory / Accuracy，并将 query-aware pruning 与 agentic seek 的证据收益纳入同一真实系统协议。

Date：2026-10-09　Venue/Status：arXiv preprint（未从所核对正文确认正式会议则不推断）　Paper：arXiv:2610.14405　HTML：Full text　Code：Not verified / Not Reported

人话版：这篇论文到底干了什么？

长期 Coding Agent 的失败经常发生在执行数十步之后：前面已经查完仓库、安装好依赖、定位到错误，但最后一个补丁没通过测试。传统 RL 为了找到成功轨迹，只能从头再跑，既浪费 token，也可能因为整组失败而拿不到梯度。SPROUT 把Agent 对话上下文和完整执行文件系统成对保存，失败后由同一模型阅读测试反馈，选择一个可恢复节点并尝试新的后续操作；成功分支再成为训练信号。它把“重试”变成“从真实中间状态继续探索”，在多个长程编码基准上提升通过率，同时降低训练耗时。对长期 Agent、可恢复环境和 RL 数据采集都很有启发。

Background & Research Gap

以修复仓库依赖冲突为例，Agent 花 40 个工具调用找到根因，第 41 步改错配置导致测试失败。重新采样四条轨迹会重复前 40 步；仅恢复聊天记录而不恢复文件、依赖和编译产物，又会让工具观察与模型记忆不一致。GRPO 依赖同一任务不同 rollout 的奖励差异，若全部最终失败，组内 advantage 退化为零。现有 TreeRL/CBPO 侧重对话树；Shepherd 主要恢复工作区，BPO 只在少量位置做容器快照；完整 VM 内存快照又过重。SPROUT 试图同时解决状态一致、任意轮可恢复、低增量存储、由 verifier 指导回退四个问题。

Core Insight 与 Method Deep Dive

Input → 执行 Agent → 每轮持久化联合状态 → verifier 诊断 → 选择失败前的可恢复边界 → 新 VM 恢复 → 分支继续 → 收集成功/失败树 → 训练。

  1. 状态定义：每轮状态不是纯文本历史，而是 s_t=(e_t,h_t)，其中 e_t 是工具执行后环境，h_t 是模型可见上下文。只有整轮工具执行结束、上下文与文件系统同时可恢复的边界才可分支。
  2. Restorable Execution：每个尝试运行在独立 microVM；工具为同步 shell，协议禁止后台常驻进程，因此跨轮持久状态可以由磁盘表示。每轮用 OverlayBD 增量块快照保存整盘改动，分支以 copy-on-write 层隔离，避免重跑前缀，也不需要每次复制内存。
  3. Verifier-guided Backtracking：失败后，同一 Actor 以 analyst/reviewer 角色读测试诊断、执行树与已尝试方向，提出父轨迹、回退轮次和替代首步动作。恢复相应快照后，新分支从这一首步开始执行，其余步骤仍由 Actor 自主生成。不是引入一个更强的外部 Teacher。
  4. 训练组构造：每题两条 root，各保留三个 child，共八个尝试。两条 root 均失败的 FF 组，成功 child 取得正优势；其他组使用组内归一化结果。共享前缀通过 token mask 去重，防止多个成功 sibling 重复奖励同一段旧操作。
  5. Review 信息隔离：用于搜索的失败分析、纠正提示不直接进入 Actor 的常规输入；训练将搜索得到的有益行动蒸馏到正常上下文下的策略。论文明确承认这种 guided branch 训练是带剪切的 surrogate，不应被说成完全无偏 on-policy RL。

RL Formulation / Objective

状态是仓库、文件系统、安装环境和 Agent 上下文；动作是自然语言决策与工具调用；策略是待训练的编码 LLM；轨迹由多轮动作/工具观察组成；终局奖励是 verifier 测试通过的二元 R∈{0,1}，属于稀疏、规则验证。在 FF 组，child 优势定义为 A(τ)=R(τ)；非 FF 组为 (R−mean(R))/std(R)（方差零时置零）。使用剪切 policy-ratio surrogate 和 token mask 学习；已共享的历史前缀只在合适的成功分支计入损失。与 GRPO 最大差别不是换一种 reward，而是改变能获得正例的状态分布与计算成本。Reward hacking 风险主要来自测试覆盖不足：通过有限测试不代表补丁正确或安全。

Toy Example

Agent 已完成 pip install、构建与问题定位，最后把一个路径变量写错，单测报 ModuleNotFoundError。SPROUT 不是重新 clone 并分析仓库，而是恢复改错之前的 (文件系统,对话)，读取 verifier 的失败类别，尝试改路径并继续测试。若第二个分支成功，它继承先前有效的定位过程，但不会为多个成功分支重复放大那段前缀的梯度。这与简单“把失败日志贴回对话”有本质区别。

Baselines、实验设置与 Research Questions

RQ1： 相同探索预算，恢复中间状态是否比独立 Pass@4 更划算？对比 Pass@1、Pass@4、Entropy-based branching、Shepherd；在 DeepSWE、Terminal-Bench 2.1、SWE-bench Pro v2 Hard 测试多种模型。RQ2： 分支 rollout 能否提高 RL 而非只提高测试时搜索？在 SWE-bench Rebench v2 子集训练 Qwen3.8-27B，与 Basic GRPO 对比，外测三套基准。RQ3： verifier 选点与环境快照带来多少收益？检查 Table 1 的恢复能力矩阵、Figure 3 的完整工作流与消融。训练细节、组大小与分支协议应以论文 Appendix A/B 为准，不把未核对的优化超参数补造出来。

关键 Results（数字 → 对照 → 含义）

  • DeepSWE 上 Qwen3.8-27B：Pass@1 37.2%，独立 Pass@4 71.7%，SPROUT 78.6%；在额外尝试中真正提高了可恢复覆盖，而非只增加抽样数。
  • 在 DeepSWE 的 GPT 5.6 Luna 设置中，单次 42.5% → SPROUT 85.8%；Claude Sonnet 5 为 46.9% → 82.3%；这些是搜索期通过率，不应冒充模型参数训练后的性能。
  • 训练后 SWE-bench Pro v2 Hard：Base 62.7%，Basic GRPO 74.5%，SPROUT 84.3%，较 GRPO +9.8pp。
  • 训练后 DeepSWE：Basic GRPO 33.6%，SPROUT 40.7%；Terminal-Bench 2.1：39.3% → 64.0%。不同基准收益幅度差别很大，后者改善更明显。

Authors Claim vs Evidence vs Not Proven

Authors Claim：可恢复的分支采样提高长程 Agent RL 的效率与效果。Experiments Actually Show：在列出的编码环境、模型和预算下，搜索通过率、RL 后成功率与每步训练耗时均有明确收益。What Is Not Yet Proven：在 GUI/浏览器、有后台守护进程、网络外部副作用或不可逆 API 调用环境中能否精确恢复；跨任务通用最优分支策略；更长（数千轮）运行的存储与一致性上界。

五句话总结

SPROUT 把恢复点当作探索的基本单位。它的关键不是更复杂的奖励，而是让原本全失败的轨迹产生可用分支。系统层的磁盘/上下文一致性是方法成立的前提。真实 wall-clock 与成功率同时改善，证据较强。最值得迁移的是“失败定位—精确恢复—局部重试—去重 credit”链条。

人话版：这篇论文到底干了什么？

多 Agent 系统经常不是某个 Agent 不聪明，而是上游传的信息和下游理解信息的方式不匹配：上游给出一个正确结论，却没给证据、约束或歧义，下游把它用错。PACO 将优化单位从 Agent 节点改为通信边，每条边同时修改“发送方该怎么写”“接收方该怎么读”和共同消息约定。它不改变模型权重、角色和拓扑，利用真实任务执行反馈迭代优化通信协议。HotpotQA 的 Joint F1 从 30.00 升至 61.26，略胜强提示优化器 GEPA，并能迁移到 DROP、MuSiQue。它为多 Agent information flow 和交接可靠性提供了可实验的机制。

Background & Gap

假设 Agent A 看到了两个数 10、10，正确汇总均值 10；Agent B 手里还有 100，要计算三个数的总体均值。A 只传“均值=10”但不传样本数，B 无法正确加权。即使 A、B 的独立推理完全正确，信息流仍会失败。类似地，Research Agent 传“该论文证明方法有效”但不带数据集、baseline、可信度，后续 Writer 可能夸大结论。既有方法倾向优化全局提示、单端消息改写或压缩，而不是把一条边的发送与接收协议联合优化。PACO 认为 communication edge 才是信息损失与语义错配的最小可控单位。

Core Insight / Agent Architecture

Input → 固定 DAG 多 Agent 工作流 → 选择一条通信边 → 联合修订发送指令/接收指令/协议 → 小批量运行 → end-to-end 评分 → bandit 更新 → 冻结协议部署。

形式上 DAG G=(V,E) 固定，每个 Agent 保持原模型、角色、工具权限与输入访问范围。消息 m_(u→v) 组成接收方上下文 C_v；只优化通信配置 Θ，目标是 J(Θ)=E[q(F_G(x;Θ),y)]，即最终任务质量，而非消息格式相似度。由于模型黑盒、提示离散，无法直接反向传播，于是采用执行驱动搜索。

阶段一：边选择。 为每个配置—边维护历史收益，使用折扣统计的 UCB 风格指标：历史估计增益 + 探索奖励。折扣 λ 减弱过时观测，α 控制探索；论文说明这是一种启发式优先级，不是严格校准的置信上界。阶段二：两轮联合修订。 第一轮 proposer 修改所选边的两端指令及共同约定，在 pilot batch 执行；第二轮读取执行反馈进一步修正；两轮候选都和原父配置比较。阶段三：分级评估。 小样本筛选后，在独立保留集选择配置，冻结后跨数据集测试。部署时新约定直接并入已有 prompt，不增加新的模型调用。

关键公式与参数

Θ*=argmax_Θ E_(x,y,ξ)[q(F_G(x;Θ,ξ),y)]，其中 ξ 是执行随机性，q 为最终评分。边选择分数 I_(Θ,e)=折扣历史增益 + α×探索项；λ 决定旧反馈的衰减，ρ 负责稀疏统计平滑，pilot/promotion batch 大小影响估计噪声。与 RL 的关系：它是带 bandit 的黑盒通信配置优化，而不是对 LLM 权重做 PPO/GRPO；不能把其搜索奖励等同于 token-level policy reward。

Toy Example / Failure Propagation

进一步的因果解释与评价协议审计

通信边优化后的收益，不能直接解释为“每条边都传输了更多正确事实”。因为最终 Joint F1 同时依赖证据检索、局部推理、上下游格式与终端判分；一条边的修改也会改变后续 Agent 的输入分布。更严格的机制验证应该保存相同问题、相同 evidence shards、相同 seed，对比仅替换一条边的成对执行，分别测事实保留率、关系方向正确率、引用可追溯率、接收方误解率。这也解释为什么论文的 Case Study 很重要：原系统并非完全没有证据，而是把正确交易方向解释反了。它证明“语义契约”可能比“压缩更多上下文”更关键。

还要注意训练/测试的成本核算：25M tokens 是优化搜索预算，不是部署成本；5.21M 是整个 HotpotQA 评测的部署 token，而不是单题 5.21M。对真实系统应再报告每题均值、p95 latency、失败重试开销与跨模型兼容性。PACO 使用固定四节点链，无法直接证明在带循环反馈、并行汇合或共享数据库的多 Agent 系统中也能收敛。可进一步引入消息协议的版本管理、回滚与兼容性测试，避免一次优化使历史 Agent 无法解析新格式。

Date：2026-10-12　Venue/Status：arXiv preprint（未从所核对正文确认正式会议则不推断）　Paper：arXiv:2610.16744　HTML：Full text　Code：Not verified / Not Reported

人话版：这篇论文到底干了什么？

Video LLM 每帧可能有数百视觉 token。直接按相似度合并，会误删局部文字、计数目标；只按 LLM 注意力删 token，又会受到位置偏置与 attention sink 干扰。FoveaTree 用两阶段、无需训练的树结构方法：先衡量每个图像区域合并后会丢失多少特征信息，构建四叉树并压缩；再利用问题相关注意力，在 LLM 中间层按树剪枝，保留空间连续的证据。在 InternVL3.5-8B 上仅保留 30% 视觉 token，综合相对性能仍达 100.62%，TFLOPs 降 53.2%，但真实延迟仅快 1.24 倍。它非常适合研究“质量、FLOPs 与真实加速为何不成比例”。

Background & Gap（具体例子）

长视频问“画面左下角店牌写的是什么”，一段大面积天空和墙面可以被合并，但小店牌上的每个笔画不能简单丢弃。纯 token similarity 可能只保留整体显著区域，OCR/计数/局部定位明显退化；纯 text-to-vision attention 的 Top-K 则可能偏向序列早期位置、边界或 attention sink。作者称这两个失败为 Hierarchy-blind Pruning 和 Attention Drift。以前的 ToMe、VisionZip、FrameFusion、STTM、FlashVID、LearnPruner 都可作为强基线；在强低预算压缩下，保留空间结构和问题相关性比单独优化其中一项更重要。

Core Insight / Method Deep Dive

Input 视频帧+Query → 视觉编码 → MGDE 四叉树区域密度估计 → 丢弃/合并/保留 → 进入 LLM → ATP 中间层注意力树传播 → 预算内选子树 → Answer。

  1. MGDE：用视觉编码器浅层特征 z_(t,p) 估计区域合并的特征失真，而不是单看相邻 token 的余弦相似度。构建每帧四叉树；若大块区域可以低失真合并，说明可压缩性高；边缘、文字、小物体需要细粒度保留。得到区域密度图与携带空间祖先关系的 token 单元。
  2. 预填充前压缩：在把视觉 token 输入语言解码器前，按区域密度进行 drop/merge/keep，减少第一阶段前缀长度。每个合并单元保留它覆盖的空间支持集和树节点身份，而非丢掉坐标。
  3. ATP：在 LLM 中间层读取文本到视觉的注意力，将子节点分数向父节点传播，再按预算自顶向下选择保留的区域粒度；相关区域既能保留细节，也尽量保留必要上下文，减轻平坦 Top-K 的碎片化。
  4. RoPE 与 Cache：合并后的 token 需要决定位置锚点，作者采用注意力最高的组成 token 的原位置；前层缓存不回写，后续层用压缩前缀建立新缓存。方法本身不微调 backbone，因此属于 training-free，但并非完全没有运行时计算开销。

Objective / 关键变量 / Toy Example

设视频 T 帧，每帧视觉网格 H×W，原始 token 数 N=THW；保留率 η，每帧名义预算 B=ceil(ηHW)。这里并非重新训练一个 loss，而是在预算约束下尽量保留区域表示和问题相关证据。Toy example：一帧 16×16 token 的路口视频，背景路面用较大四叉树节点表示；问“红灯旁数字几”时，红灯与数字区域保留更细 token，LLM 中间层再淘汰无关背景。这样比把红灯和背景一同平均合并更合理，但若视觉浅层本来没编码出文字差异，密度估计也可能失败。

更细的系统剖析：为什么 70% token 减少不等于 70% 加速

视觉 token 被删掉之前，视觉编码器已经产生了一部分特征；MGDE 构造区域树需要额外特征计算与树操作，ATP 在中间层还要读取注意力并决定新的区域粒度。因而被缩短的是部分 LLM 前缀计算与后续 KV 存储，不是完整 Video Pipeline 的所有算子。对 30% 预算，322.0→150.8 TFLOPs 的差额主要反映被统计的计算范围；但 2.484→2.006 秒说明剩余固定成本、kernel launch、内存传输、动态形状和剪枝逻辑仍影响真实时间。应使用 profiler 将 vision encoder / MGDE / projector / decoder prefill / ATP / decode 分开计时，确认算法成本归属。

额外的公平性与失败模式检查

相同“保留率”不一定等于相同空间信息量：区域合并保留了上下文，而纯丢弃只保留原 patch，二者实际每个 token 的语义容量不同。必须在相同模型、相同帧数、相同输入分辨率、相同生成长度下比较。更重要的是，平均相对性能 100.62% 并不意味着每个子任务都超越全量模型；例如细粒度 OCR、计数和时间顺序任务可能表现不同。建议单列长视频中被删掉的关键短事件、镜头切换、密集字幕、快速运动四类 stress test。若未来将其作为 Streaming Agent 的视觉前端，还需要记录错误删除后能否二次取回原帧，因为在线压缩造成的证据损失可能不可逆。

Input task → G 条 student rollouts → 检测全部失败且优势为零 → 从 student-reached anchor 调用冻结 teacher → 环境验证 teacher recovery → 有界搜索可交还控制的最早 state → 独立复验 student success → 组合 relay → 更新 student。State 是环境观测+历史，Action 是工具操作，Policy 是学生 LLM，Reward 为环境终局成功（稀疏、规则验证）；Teacher 仅在训练使用。选择 j*=min{j: 从 s_j 独立验证学生可成功}，要求 j*<L。总目标 L=L_GRPO+ηL_KL+λ_pair L_pair+λ_bridge L_bridge+λ_resume L_resume；原 GRPO 保留，辅助项仅由有效 relay 提供。KL 控制策略偏移，桥接项监督困难局部动作，resume 项巩固学生自己的成功后缀。错误风险在于 teacher 的成功被 verifier 错误认可，或早交接验证偶然成功。

进一步拆解三路监督为什么互补

Action preference 的作用是比较同一状态下可取的动作，避免只把教师完整回答当成标签；Bridge loss 专门学习跨过学生能力缺口的几步；Resume loss 则让学生在修复后的状态继续把任务做完。三者分别对应局部选择、错误修复、独立完成。消融中 Bridge 去掉损失最大，提示 all-failure 的主要瓶颈不是学生不会最后一步，而是没有足够监督穿越失败状态。随机 handoff 仍有成功但明显弱于最早验证点，说明“让学生多做一些”必须建立在可成功的环境证据上。

更严格的复现与风险核对

早交接搜索需要从候选状态重复采样，成功的确认概率取决于采样次数与随机性；若每个候选只试极少次，所谓“学生可独立完成”可能只是偶然成功。建议报告每个 anchor 的重试次数、成功置信区间、Teacher bridge 平均长度与真实计算成本。还应比较强 Teacher、同规模 Teacher 和受限 Teacher，观察是否只是借助更强模型的能力。对 1000-step 的长程任务，候选交接点数随轨迹增长，必须采用自适应搜索预算，否则验证本身会成为瓶颈。

研究可迁移性的边界

在 Multi-Agent 场景，handoff 可能跨越不同工具权限和记忆可见范围，不能直接把教师动作插入学生轨迹。合理设计是：仅允许 repair agent 修改它有权限的共享工件，并在交接后用原 Agent 的真实权限复验。否则“修复成功”可能依赖部署时不可用的特权信息，造成虚假的独立性。

长程 Agent 只有终局成败，GRPO 会把整条成功轨迹里的所有动作一视同仁，PPO 则需要训练额外 critic。LVRL 让一个冻结的强 LLM 直接根据状态、同组轨迹和起终点已知回报估计中间状态价值，用相邻价值差形成 step-level credit；还把价值下降的位置用于选择性教师蒸馏。它的亮点不是提出新 reward，而是利用现成 LLM 的知识充当不训练参数的 value critic。AppWorld、BabyAI、SWE-bench Verified 都报告超过 GRPO/PPO 的结果，但强 critic 的推理成本不能忽略。

Background & Gap / Insight

假设工具调用链为“查文档→错误编辑→运行测试→修复→通过”。单一终局 reward=1 会奖励错误编辑，甚至奖励无意义的中间步骤；训练单独 value network 又可能需要大量样本。作者观察强语言模型可以读懂局部动作与任务进展，于是把 frozen LLM 当作政策相关的值函数估计器，并利用已知起点/终点值校准，避免模型只给主观“好/坏”分数。与独立 Judge 对最终回答打分不同，它关注某一步后成功概率究竟变化多少。

Method / RL Formulation

Trajectory → group context → frozen LLM value estimate V(s_t) → terminal/initial calibration → ΔV_t credit → policy update。State 包含历史与环境状态；Action 是 Agent 工具调用；Policy 为 Qwen3-4B/8B/32B；Reward 是环境终局回报；Advantage 从相邻值估计的变化得到细粒度信号，KL/熵项以原文具体训练设置为准，不能从摘要推断系数。对于 OPD，LVOPD 将 Teacher 监督集中到 value 下降的步骤。强 critic 可看作 learned value estimator，但它并没有用 RL 在当前任务上训练 critic；这也意味着外部模型的潜在先验和偏见会进入 credit。

Credit 的因果性问题

值差 V(s_{t+1})−V(s_t) 直观上像某个动作的贡献，但它并不自动等于因果效应：后续状态同时受环境随机性、隐藏工具结果和未来策略影响。若冻结 critic 看到了整个 group 的更多信息，某个动作被评为有益，可能只是与成功轨迹共现。真正的 attribution 检验应从同一个状态执行多种候选动作，并用 Monte Carlo 后续成功率估计 Q(s,a)，再比较 critic 的值差排序。论文提供 Monte Carlo 分析，是比只报告最终 benchmark 更有价值的部分。

Critic 成本与部署权衡

LVRL 的一个关键优势是省去单独训练 value network，但冻结强 LLM 每步调用仍然昂贵。对于长达 100 次工具调用的任务，若每步都需要一次强模型评分，token 与网络延迟可能超过采样节约。训练时离线批处理 critic、缓存相同前缀、仅在高不确定步骤调用、或蒸馏一个小 critic，都是可测量的替代方案。应分别报告 Actor rollout tokens、Critic tokens、最终每步 wall-clock、策略提升；只看 policy 成功率无法判断训练是否更高效。

适合研究的失败案例

当任务需要探索未知 API 时，强 LLM 的先验可能误判某个看似荒谬但正确的操作；当工具返回不可信文本时，critic 也可能受 prompt injection 影响。可设计“环境真实值与语言先验冲突”的实验，检验价值估计是否仍能识别关键恢复步骤。若在 Multi-Agent 系统使用，应让 critic 区分发送者错误、接收者误解、工具返回污染三种因果路径，而非把所有下降都归因给最后执行动作。

Background & Research Gap

传统 reflection 通常只在失败后做一段语言总结，既不区分工具噪声、用户纠正和策略错误，也难以确保总结能改变下一次动作。作者认为应从真实成功—失败对中归纳可复用的技能，并让策略在在线交互中学会触发这些技能。例如工具返回“订单不存在”，究竟应换搜索条件、核验 ID 还是直接终止？正确的恢复方式取决于环境状态，而不是固定反思模板。

Method / Agent Architecture

Environment perturbation → diverse LLM trajectories → success/failure pair mining → Reflection Skill Discovery → Reflective SFT → ORPO on-policy training → robust Agent。RSD 将噪声与成功/失败轨迹联系起来，提取技能库；ReSFT 监督自我反思、技能恢复和用户纠正三类行为；ORPO 在带噪交互中结合 Agent RL 与 reflection-guided on-policy distillation。Agent State 包括工具历史、错误反馈、已抽取的 meta-skill 和当前任务状态。Reward 来自环境任务结果与训练中的反思指导，具体各项权重需要查正文公式，不能用最终分数倒推 reward 结构。注意它不是简单增加“思考 token”，而是通过训练改变失败后的行动策略。

Reflection Skill 与普通 Prompt Reflection 的差别

一个真正的 skill 至少要说明触发条件、需要读取的证据、允许的恢复动作以及停止条件。例如“工具返回字段缺失”与“工具返回字段被恶意篡改”看似都需要重试，但前者可能是 schema mismatch，后者需要隔离不可信来源。若只学习一句“重新检查结果”，在训练集可能有益，却很难在分布外环境中复用。RSD 的价值在于用匹配成功—失败对构造较具体的元技能；ReSFT 负责让模型学会表达并执行，ORPO 再在真实交互中调整行为。

应补充的实验问题

第一，移除 RSD 但保留 ReSFT，性能下降多少？第二，只做离线反思而不做 on-policy 训练，能否处理新的工具噪声？第三，反思调用是否提高每题 token/latency，是否在高成功率任务上产生过度反思？第四，用户纠正与工具返回矛盾时如何选择可信来源？这些问题直接关系到 skill 的可迁移性和 reward hacking 风险。建议把成功率之外的 recovery precision、false intervention rate、reflection trigger calibration、token overhead 纳入评测。

长程状态与传播

把“多找到一些线索”当 reward 很容易造成过度检索：模型可能不断请求相似帧，或者把重复对象当成新证据。理想的 credit 应区分新增的独立证据与重复视觉 token，并把工具调用耗时显式计入预算。Open-o3-v2 的 clue coverage 与 step-wise gain 是重要进展，但仍需观察它们是否与最终 grounded answer 的因果改善一致。可以固定同一问题，对某次 seek 的结果做遮挡或替换，测最终答案与定位指标的变化，从而评估真正的 evidence value。

为什么它与 Video Acceleration 有联系又不等价

如果初始只编码 8 帧，Agent 后续主动检索 16 帧，准确率提高并不代表计算减少。只有在相同总帧预算或相同 wall-clock 下，比均匀采样获得更高正确率，才能称为效率提升。需要同时统计初始编码帧数、后续检索帧数、重复帧率、vision encoder 时间、LLM prefill 时间、工具往返延迟与最终正确率。未来与 FoveaTree 联合时，应把 query-aware token pruning 的开销和额外 seek 的收益共同计入，而不是只报告单模块加速。

Long-horizon 与失败传播

对于多跳视频问题，早期错误的对象框会导致后续时间定位偏离；如果这些错误证据被写入 trajectory，模型可能在后续推理中反复引用。建议设计证据冲突场景，要求 Agent 对旧证据执行撤销或更新，测是否能够在 10/100 次 seek 后保持引用正确。现有 4B 模型的 benchmark 提升不能直接说明千步长程记忆可靠。

进一步的证据质量审计：应记录检索命中的片段是否包含独立可核验的对象与时间证据，而不只看模型输出的解释是否流畅；如果检索结果与初始帧冲突，Agent 是否能够显式撤销旧结论，是比增加推理长度更重要的鲁棒性指标。

Background / Gap / Core Insight

Method / Efficiency Mechanism

当前 chunk 当前步输入 → Anchor-Transport-Correct (ATC) → 当前 chunk 前一步特征 + 历史 chunk 同 timestep 特征 → 空间检索 → 自适应修正 → 近似速度/特征预测 → 下一去噪状态。ATC 是轻量 predictor；训练时用自己的 autoregressive rollout 形成输入分布，减轻预测误差积累；可选 confidence-aware scheduler 调整何时使用近似计算。它需要训练预测器，不是 training-free。节省的是部分去噪 backbone 计算，而非视频理解中的 frame/token pruning。

ATC 的机制边界

“上一 chunk 同 timestep 特征”之所以有用，是因为视频相邻 chunk 的背景、主体、运动状态具有连续性，而去噪网络在同一 timestep 面临相似噪声尺度。但遇到硬切镜头、主体突然出现或摄像机快速运动时，这种相关性可能下降；预测器若仍大量复用历史特征，容易出现鬼影或身份漂移。一个有说服力的消融应分别移除当前 chunk 的前一步 anchor、上一 chunk 的同 timestep reference、空间检索与 correction，观察 VBench、LPIPS、PSNR 和 latency 变化。这样才能确认收益来自跨 chunk 信息，而非简单增加一个轻量网络。

训练开销与在线成本

TGuide 需要对自身生成轨迹进行训练，减少的是推理期重复 backbone 调用；这部分训练算力不能从部署 latency 中直接扣除。对于长期视频生成服务，训练一次可被大量推理摊销；对于只生成少量视频的场景，可能不值得。可建立总成本模型：Total Cost = Predictor Training + N×Inference Cost，计算在多少次生成后比四步原模型更划算。还应分别记录 predictor 的 FLOPs、GPU Memory 与 kernel time，避免“1.89×”被误解为整个视频系统端到端吞吐都提升 1.89 倍。

与长视频理解的迁移警告

视频生成中的同 timestep 是扩散去噪阶段，Video VLM 没有同样的时间轴；不能直接复制 ATC。可迁移的是条件相近时跨时间复用特征这一抽象机制。Video Agent 的对应条件可能是同一事件、相同视角或相同 query，而不是扩散时间。迁移研究首先应验证跨帧特征在相同语义事件中的预测误差，再决定是否构造缓存或轻量校正器。

稀疏注意力虽然只处理少数重要 key，但“找出哪些 key 重要”的索引器本身仍可能需要对全部 key 完整打分。DoSA 发现 Top-K 选择不一定要知道每个候选的精确分数，只需要有足够严格的上界证明某些候选不可能入选。它用初始种子给出获胜阈值下界，再以非负投影、正负贡献界与激活统计构造排除证书，只有未能被排除的候选才完整计算。该方法强调保持原 Top-K 选择不变，却让索引器最高加速 2.74×，部分模型的 TTFT 最高加速 1.94×。这是通用高效推理机制，不是 Video 专用算法。

Gap / Method / Correctness

传统稀疏注意力的总体耗时是“查找 Top-K + 对 Top-K 做注意力”，前者在长上下文中不一定便宜。DoSA 不改变目标 attention 的排名规则，而通过可证上界跳过不可能胜出的 key：seed threshold → 每候选乐观分数上界 → 上界低于当前阈值则排除 → 剩余完整评分 → 精确 Top-K。关键是上界必须保守，否则所谓 lossless 只是在 benchmark 上“碰巧没掉分”。它的创新在于 conditional exact scoring，而非更激进地牺牲 token。

New Mechanism：以可验证候选淘汰代替全量精确评分；New System Optimization：GPU indexer 实现。限制是收益依赖选择 margin、分数几何结构和稀疏分布；证书构造也要付计算代价，弱分离场景可能几乎没有加速。迁移到 Video Token Pruning：对 query-aware token 排序建立可证上界，只在必要时做昂贵的跨模态 attention 计算。MVE：同一 Video VLM 上比较普通 attention scoring、近似筛选、DoSA 风格精确证书，测 Top-K 一致率、准确率、TTFT、GPU kernel time。Worth Deep Reading：MAYBE，对系统工程有价值，但不应直接宣称能迁移到视频。

更具体的算法直觉与 Toy Example

设当前 query 要从 10 万个 key 中选 Top-128。传统 indexer 可能为所有 key 计算完整的多头分数，即使大部分候选明显不可能进入前 128。DoSA 先从少量 seed 得到当前第 128 名分数的下界，例如 0.72；某候选即便把尚未计算的所有正贡献都按最乐观上界加上、再扣除保守的负贡献下界，最高也只能达到 0.31，那么它不可能超过阈值，可以直接跳过完整计算。只有上界仍高于 0.72 的候选才继续精确评分。只要证书合法，最终 Top-K 与全量打分一致。

实验可迁移性与失败条件

这种证书的收益高度依赖分数分离程度。若所有候选分数都在 0.69–0.73 之间，上界难以排除候选，索引器可能几乎全量计算；如果大部分分数远低于 Top-K 阈值，则很容易加速。要检查证书是否引入 GPU 分支发散、动态内存访问和额外 kernel launch，并在 batch size、context length、Top-K 比例变化时测收益。TTFT 的最高加速和 indexer 的最高加速是不同层次的指标，不可直接相乘。

与 Video 的关系

Video VLM 的视觉 token 评分也常需从大量帧中挑选少量相关区域。DoSA 可启发“可证据保留”的候选排除：先用廉价局部视觉分数建立上界，只对可能影响 query 的区域计算昂贵跨模态相关性。然而视觉 token pruning 的目标可能并非精确 Top-K，而是保留空间连贯的证据集合；这时 DoSA 的逐 token 精确性未必等于任务最优性。一个新论文需要同时证明选择正确、空间结构保留与真实 GPU 加速，不能只套用证书名词。

关键对照：对相同 Top-K 和相同上下文长度，应同时测 indexer 单独耗时与端到端 TTFT，并检查证书在低分离 margin 下的退化。只要候选上界过于松散，精确选择虽然正确，但速度优势可能消失。

传统 RLVR 对同一道题独立采样多条答案，后续 rollout 并不知道前面哪些解法已失败，探索会重复浪费。LEAF 在每次 rollout 前临时注入问题专属的“上一条答案、reward 和环境反馈”记忆，让下一次尝试有方向地避开错误；训练时又把这种带记忆的成功探索蒸馏回不带记忆输入的策略。这样推理时无需一直附加历史，却能继承探索中学到的知识。

Background / Method

Experiment / Findings

在 四个 benchmark、两个开源模型上，作者报告相对随机采样基线探索速度约 4×；在未见测试集上，较最强 baseline 分别提升 1.59pp 和 1.83pp，同时计算消耗低于被比较的 RL baseline。强点是采样效率，弱点是最终准确率绝对增益并不巨大；不能把“探索 4×”说成“最终推理吞吐 4×”。

Contribution / Limitation / Connection

New Exploration Mechanism：将 verifier feedback 转成 rollout 条件记忆；New Training Separation：有记忆探索、无记忆蒸馏。潜在风险是历史错误诱导模型过早排除正确路径，或模型仅复述最近反馈。迁移到 Agent：每次失败交接形成局部经验，在下一条分支里复用，但最终学成不依赖外部记忆的恢复策略。可与 SPROUT 比较：一个重用文字反馈，一个重用可执行状态。

更严格的奖励与探索分析

LEAF 的记忆中同时有先前答案、reward 与环境反馈，模型可能学会排除已经被证伪的路径，也可能被前一次失败“锚定”，忽略不同解法。需要比较只保留失败答案、只保留 reward、保留完整反馈、随机打乱反馈、错误反馈注入五组设置。训练阶段的 self-distillation 也值得单独消融：如果带记忆 rollout 的成功率提高，但去掉记忆后模型不再提升，那就只是 inference-time search，而非策略能力真正增强。其 4× exploration speedup 应核对达到同一正确解覆盖率所需样本数，而不是把它解释成单次生成更快。

Date：2026-10（见论文页）　Venue/Status：arXiv preprint（未从所核对正文确认正式会议则不推断）　Paper：arXiv:2610.16679　HTML：Full text　Code：Not verified / Not Reported

人话版

视觉空间 Agent 不仅要看懂图片，还要调用测量、几何计算等工具，并知道什么时候不该相信自己的计算。EvoSpatial 将过去成功和失败的轨迹转成可复用的技能与工具库：任务中检索适合的技能、调用已有函数，必要时生成新计算函数；任务结束后根据监督反馈修改技能、合并工具。它把“经验”从模糊的自然语言总结变成与计算过程绑定的可执行程序知识。

Background / Method

Visual question → skill retrieval → perception/measurement tools → geometric reasoning → outcome feedback → skill refinement + tool consolidation。核心 Insight 是：成功与失败轨迹不仅告诉 Agent 如何计算，还告诉它什么条件下计算结果可信。与单纯积累 RAG 文档相比，这里 procedural knowledge 与实际函数实现关联；对同类任务的跨任务迁移更直接。

Experiment / Findings

论文报告 20 个空间推理 benchmark，总体平均超过所比较空间 Agent，其中比 SpatialClaw 高 4.0pp。另外观察到跨 benchmark 迁移，并在评测时不提供外部技能的 skill-guided distillation 下仍有收益。这个 4.0pp 是平均指标，不代表每个子任务都提高。值得进一步核对技能库增长、错误工具污染、调用成本和长期遗忘消融。

Contribution / Limitation / Connection

New Agent Skill System：关联技能、工具与信任条件的演化机制。局限是反馈主要来自任务结束后的监督结果，未证明长期 1000-step 技能稳定性，也没有充分因果分解哪条经验导致提升。与 RL 交叉可做 skill credit assignment：每次技能调用记录版本、上下文与后续成功率，通过可控替换估计其边际贡献。潜在应用包括 coding tool library、视频几何分析 Agent。

Skill Attribution 的未解决问题

技能库不断增长后，Agent 可能同时检索多个相似技能，最终成功究竟由哪一个引起并不清楚。仅记录“某技能在成功轨迹中被调用”会有严重选择偏差：困难任务可能更频繁调用技能，却更容易失败。可在相同任务、相同工具与随机种子下做 skill ablation，比较删去、替换或降级某技能后的成功率；同时记录工具执行正确率、几何假设验证与 token 成本。对于视频 Agent，空间技能还应注明适用的帧率、摄像机坐标系和时间范围，避免把静态图像经验错误迁移到运动场景。

Tier BAgentMemForm: Benchmarking Memory Formation Poisoning in LLM Agents
Authors：Haowen Pan 等　Affiliation：作者单位见原文
Date：2026-10（见论文页）　Venue/Status：arXiv preprint（未从所核对正文确认正式会议则不推断）　Paper：arXiv:2610.14431　HTML：Full text　Code：Not verified / Not Reported

人话版

Agent Memory 的风险不只在“检索到恶意文本”，更早发生在经验写入记忆时：哪些内容被保存、什么证据被当作支持、适用范围如何定义、哪些候选被选中、多个经验按什么顺序合并。MemForm 将这五个入口系统化为 Content、Evidence、Scope、Selection、Path Poisoning。它表明即使原始经历是真实的、结果也成功，改变选择或整合顺序仍可能让后续 Agent 产生错误行为。这是研究 memory provenance 与长期稳定性的高价值安全评测。

Background / Method

Clean/Poisoned experiences → memory formation interface intervention → memory write/consolidation → future agent task → attack success measurement。特别新颖的是 Selection/Path 两种干预：不必改写经验正文，只调整哪条经验被留下、或者相同经验的合并顺序，就可能影响后续决策。论文比较六个 LLM 和两种输出格式，区分模型本身能力与记忆系统形成策略的脆弱性。

Experiment / Findings

在 multiple-choice 条件下，Table 1 的平均攻击成功率：GLM-5.2 71.7%、GPT-5.6-Luna 67.3%、Claude-Sonnet-5 35.2%、Gemini-3.7-Flash 84.0%；这些数值属于论文规定的攻击协议，不可推广为模型的通用安全评分。论文还发现相同保留经验，仅改变 consolidation order 就可能改变行为，且对 updater 实现敏感。各接口防御效果不均衡。

Contribution / Limitation / Connection

New Benchmark/Attack Taxonomy：从输入内容层扩展到记忆形成接口；New Empirical Finding：写入顺序与保留决策本身是攻击面。限制是结果受记忆架构、更新器、测试格式影响，不能直接说明现实系统攻击概率。可迁移到 Agent RL 的 experience replay：记录每条经验的来源、验证状态、写入版本与顺序；比较“有无该经验”对后续任务的反事实贡献，兼顾效用与污染检测。

对 Agent Memory 实验的直接启发

MemForm 最值得重视的不是哪个模型 ASR 更高，而是攻击面发生在记忆形成前后。当 Agent 把成功经历压缩成一句经验时，可能丢失原始证据、适用范围和反例；之后另一个 Agent 只看到“已验证的规则”，很难恢复其来源。防御不应只在 retrieval 阶段扫描文本，还应在 write/consolidate 时记录来源签名、scope、验证器结果、更新顺序和回滚点。建议评测 clean utility、poison ASR 与 memory growth 三者的权衡，而不是单纯降低攻击成功率导致 Agent 什么都不记。

最小复现实验：固定模型与经验集合，仅交换 consolidation 顺序，记录写入后 memory 差异和下游输出变化。再恢复原顺序检验攻击是否可逆，区分一次性提示偏差与真正的持久记忆污染。

Tier BRLCoCA: Criterion-Aware Credit Assignment for Rubric-Based Reinforcement Learning
Authors：Guangcheng Zhu 等　Affiliation：作者单位见原文
Date：2026-10（见论文页）　Venue/Status：arXiv preprint（未从所核对正文确认正式会议则不推断）　Paper：arXiv:2610.17733　HTML：Full text　Code：Not verified / Not Reported

人话版

开放式任务很难用“最终答案对不对”打分，通常会把多个 rubric criterion（如事实性、完整性、格式）压成一个总 reward，再把同一个 advantage 分给所有 token。CoCA 认为这样丢掉了 criterion 的结构信息：不同 token 对不同评价维度的贡献不一样。它用每条 rubric 的组内相对结果构造 criterion-level credit，再根据 rubric 对 token 分布的影响将 credit 分配到细粒度位置；避免把 rubric 直接变成模仿目标而导致 reward 退化。

Background / Method

Response rollouts → criterion-level judge outcomes → group-relative credit per criterion → criterion-induced distribution shift → token allocation → policy optimization。与一般 GRPO 的同一序列优势不同，CoCA 试图把“哪个评价标准得分变化”映射到“哪些 token 该获得更多/更少梯度”。与有 privileged rubric 的 self-distillation 不同，它强调 credit 必须由实际 outcome grounding 支撑，不能只凭教师对词的偏好。

Experiment / Findings

作者在医学与科学开放式任务上报告，相较标准 rubric-based RL 平均提升 4.2%（论文原文使用百分号，未在摘要中明示是相对百分比还是百分点，故不自行改写成 pp）。重要 RQ 是 reward 是否真的改善、细粒度 credit 是否比统一优势更稳定，以及是否存在 rubric 漏洞被模型利用。当前核对信息没有足够的逐任务绝对数字，保留为 Tier B，不凭空补出模型规模与超参。

Contribution / Limitation / Connection

New Objective/Credit Assignment：criterion-grounded token credit。局限是 criterion 可能相互重叠、judge 噪声会误导 token attribution，仍缺少真实因果验证。可迁移到多 Agent：将 rubric 维度换成 evidence preservation、tool correctness、handoff completeness，再测每条消息/动作对最终 outcome 的贡献。最小实验用四 Agent QA 链，比较统一 reward、criterion scalar reward、criterion-aware token/edge credit，测准确率和 credit fidelity。

Rubric Credit 的边界与检验方法

当一个 token 同时影响事实性与流畅性时，criterion-level credit 可能发生重复计分；若 judge 的各项标准高度相关，所谓细粒度 credit 也可能只是重新缩放同一个总奖励。更强的验证应针对特定 criterion 构造可控反事实编辑，例如只改变事实引用、只改变格式、只改变论证完整性，观察对应 token 的 credit 是否局部变化。对于多 Agent 交接，可把 rubric 分为“证据完整、权限正确、任务完成、消息简洁”，再检验某条边的错误是否得到正确定位。若最终收益只在同一套 judge 下成立，还需要跨 judge 测试 reward hacking。

复现优先级：先检查 criterion 标签的一致性与评分器间相关性，再测 token credit 的局部性。若标准间高度共线，即使最终分数提高，也不能直接说明每个 token 的因果贡献已被正确识别。

11 · Idea Mining — 可检验研究提案

以下均为本报告提出的 研究假设，不是论文已证实的实验结果；星级是初步主观判断，Compute Cost 五星表示更昂贵。

I1 · Verifier-Grounded Handoff Credit: 从交接边定位长程 Agent 失败

RL × Multi-Agent × Agent Memory

Inspiration：PACO 的边级优化、SPROUT 的状态回滚、LVRL 的逐步 value、MemForm 的记忆写入风险。Research Gap：通信协议优化并未告诉我们哪条 handoff 在因果上造成最终失败；价值估计也可能把相关性当因果性。Hypothesis：对交接前后的可重放状态进行反事实替换，能构造比统一终局 reward 更可信的 edge-level credit。

Proposed Method：每次 Agent handoff 保存 source evidence / message / receiver state / tool side effects / memory version，终局失败后由 verifier 生成错误假设，固定其余边，仅替换候选消息或恢复到边前节点重跑，计算 ΔSuccess 与 ΔCost；用这些 credit 更新发送/接收协议和 memory admission policy。MVE：先用 4-Agent HotpotQA + 20 个可执行 coding 任务，每题 2–4 个交接，执行 3–5 次配对重放；再扩大到 7B/8B 开源 Agent。

Model：Qwen3-8B / Qwen3-Coder 级模型。Dataset：HotpotQA、MuSiQue、SWE-bench Verified 子集。Baseline：Vanilla、GEPA、PACO、uniform outcome credit、LLM value critic、random edge replay。Metric：task success、causal edge localization AUROC、handoff evidence fidelity、tokens、wall-clock、false blame rate。Expected Contribution：可验证的 multi-agent communication credit/evidence provenance benchmark + recovery policy。Novelty ★★★★☆；Feasibility ★★★★☆；Compute Cost ★★★☆☆（五星=昂贵）；Risk：环境副作用难完全重放，替换消息可能构造分布外状态。Collision Risk：高，PACO/GraphGPO/VH-GPO/SPROUT 已覆盖部分机制；差异化应锁定“边级反事实真值与记忆版本”而非泛化的优化框架。Best Venue：ICLR / NeurIPS / ACL。

I2 · Evidence-Constrained Streaming Video Budget Controller

Video Acceleration × Agent RL

Inspiration：FoveaTree 的区域密度树、Open-o3-Video-v2 的主动证据采集、SPARE 的历史检索、FrameFold 的响应保持缓存。Gap：现有剪枝多在固定查询下优化 token 质量；主动找证据则可能增加工具调用和 latency，缺少统一的“额外视觉计算是否值得”的优化目标。Hypothesis：根据每次 seek 的真实证据增益自适应选择 frame/token/cache 预算，可在相同 wall-clock 下提高证据覆盖与答案可靠性。

Proposed Method：Streaming Agent 在每轮估计缺失证据的价值 V_evidence，选择 skip / retrieve / fine-grain encode / re-use cache，奖励为 answer gain + verified grounding gain − λ·latency − μ·memory；加入可逆检索日志，避免重复取相同片段。MVE：先做无需训练的预算策略 + 小规模 bandit；在 Qwen3-VL-8B 上测 1–5min VideoQA，统一 GPU/帧率/批量，真实计时。

Model：Qwen3-VL-8B。Dataset：VideoMME、NExT-QA、StreamingBench。Baseline：uniform frame、FrameFusion、FoveaTree、Open-o3-v2、固定 query-aware retrieval。Metric：Accuracy、Evidence Recall、Frames、Tokens、TFLOPs、TTFT、Latency、VRAM、Cache Hit。Expected Contribution：面向流式 Agent 的计算—证据联合预算策略与评价协议。Novelty ★★★★☆；Feasibility ★★★★☆；Compute Cost ★★★☆☆；Risk：检索成本抵消剪枝收益、训练时证据奖励不可靠。Collision Risk：高，与 VideoZoomer、SPARE、Open-o3-v2、FoveaTree 重叠；必须提供端到端真实延迟与未见事件证据恢复实验。Best Venue：CVPR / ICCV / NeurIPS。

I3 · Functional Cache Preservation for Video Agent Memory

Video Cache × Long-Horizon Agent

Inspiration：FrameFold 用注意力响应而非原始向量相似度判断可合并性；TGuide 用同去噪阶段的历史轨迹跨 chunk 复用；CineMem 用 query-level 检索。Gap：Video Agent 的缓存压缩多按最近/相似程度决定，但未来 Agent 查询所需证据与当前注意力分布可能不同。Hypothesis：维护少量多样化的 query probes，最小化合并前后的任务响应偏差，比只做 cosine KV merging 更能保留长程信息。

Proposed Method：构造“近期 query + 潜在未来任务 query”的小探针集，对候选 cache merge 计算 Δattention response 与 token 成本；使用可分解的分层事件缓存，给难预测的关键帧设置保护阈值。MVE：先在离线 1–3 分钟视频上只改 KV/feature cache，不训练 backbone，报告合并误差与任务准确率；再转在线 streaming。

Model：8B Video VLM。Dataset：VideoMME、StreamingBench、VideoOdyssey 子集。Baseline：LRU、similarity merging、FrameFold 风格单探针、query-aware pruning。Metric：answer accuracy、long-range evidence recall、cache MB、TTFT、latency、error accumulation。Expected Contribution：可测量的 functional cache preservation 准则。Novelty ★★★☆☆；Feasibility ★★★★☆；Compute Cost ★★☆☆☆；Risk：probe 集偏差，压缩判别开销大于收益。Collision Risk：很高，FrameFold/CineMem 已做部分核心思路；差异化需明确是 Video Understanding Agent、未来查询分布和可证据化的失败模式。Best Venue：CVPR / ECCV / MLSys。

I4 · Robust Memory Admission via Counterfactual Experience Utility

Agent Memory × Security × RL

Inspiration：MemForm 发现 Selection/Path Poisoning、EvoSpatial 强调可执行经验与信任条件、LEAF 区分探索记忆与部署策略。Gap：Memory Writer 常依据摘要质量或语义相似度保存经验，无法知道这条经验是否真的提升未来成功率，甚至可能把被操纵的“成功经验”永久固化。Hypothesis：将 memory admission 与未来任务的反事实 utility 绑定，可以同时降低无用记忆和污染传播。

Proposed Method：每条候选 memory 存储来源、scope、验证证据、形成路径；在小规模任务 replay 上比较“写入/不写入”对成功率、token、错误传播的影响，用 conservative bandit 更新 admission/forget policy，并对不同写入顺序做鲁棒测试。MVE：使用 100–300 条受控 Agent 经验，在 MemForm 五种接口扰动下训练/评估 admission controller。

Model：7B/8B Agent。Dataset：MemForm + ALFWorld / WebShop 经验流。Baseline：append-all、recency、semantic memory、MemCon、scope filter。Metric：future task success、poison ASR、memory size、token cost、causal utility correlation。Expected Contribution：面向记忆形成的效用与安全联合评估。Novelty ★★★★☆；Feasibility ★★★☆☆；Compute Cost ★★★☆☆；Risk：反事实 replay 不稳定，经验 utility 随策略更新而变化。Collision Risk：中高，MemForm/MemCon 已涉及安全或管理，但 utility-grounded causal admission 仍可细化。Best Venue：ACL / ICLR / NeurIPS。
