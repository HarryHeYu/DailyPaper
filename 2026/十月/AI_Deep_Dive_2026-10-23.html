一句话定位： 它不是再造一个 reward，而是修正离策略自回归 RL 中“用哪个分布上的概率比率来约束策略更新”这一基础问题。

2.2 人话版（先建立直觉）

想象你让一个数学推理模型写 10,000 个 token。它写到第 8000 个 token 时，当前策略和采样时的旧策略可能已经在前 7999 个 token 上累积了很大的分歧。传统 PPO / GRPO 往往只看第 8000 个 token 的条件概率比率；GSPO 则把整条答案压成一个比率。前者看不见前文漂移，后者可能因为后半段不可靠而把前半段有价值的学习信号一并抑制。EPIC 的做法是：每走一步，就计算截至这一步的累计 prefix ratio；再依据一个与 reverse KL 精确关联的凸函数，为这个 prefix 设置自适应裁剪区间。 为避免长序列数值爆炸，它把累计比率转换成几何平均，并用 straight-through 让梯度仍只从当前 token 回传。作者在 Qwen3-30B-A3B-Base 上做数学 RL，四基准均值达到 39.34%，超过最强非 replay baseline DAPO 的 35.45%。它重要的地方不只是多出几分，而是提供了可迁移到 Agent action trajectory 的“前缀级离策略纠偏”思路。

2.3 Background & Research Gap：旧方法究竟错位在哪里？

RLVR（Reinforcement Learning with Verifiable Rewards）常用题目最终答案是否正确来给 0/1 reward，再以一组 rollout 的相对奖励估计 advantage，优化 token 生成概率。状态不是抽象的“第 t 步”，而是 s_t=(prompt, y_<t)；动作是当前 token。状态本身由前面的动作生成。因此策略更新改变了前缀的概率，也改变了后续 token 所处状态的访问频率。只校正当前条件概率并不能自动校正“走到这里”的概率。

具体例子：一条旧轨迹有 8 个决策，每步当前策略相对旧策略的比率都是 1.1。每个 token 的比率 1.1 看起来温和，但整条 prefix 的比率已是 1.1⁸≈2.14；旧策略中常见的整条路径在新策略下可能变得超过两倍常见。GRPO 的 token clipping 可能每步都放行。GSPO 用整个 response 的归一化比率处理所有位置，则可能因为最后几个 token 的异常，把早期合理步骤也压掉。离策略训练时 rollout 由滞后的策略产生，MoE 专家路由还可能在 rollout 和训练端不同，放大分布错配。

历史基线解决的是不同子问题：PPO/GRPO 提供廉价的一阶裁剪，DAPO 改进训练稳定性与采样，GSPO 改用 sequence ratio，CTPO/RIPO 关注累计或位置相关比率，R2/R3 通过重放专家路由减少 MoE 不一致。EPIC 要补的是prefix distribution 作为统计对象：不能只用 token-level 局部比率，也不应只在完整答案结束后才做全局判决。

2.4 Core Insight：从 performance-difference identity 推导，而非拍脑袋换 loss

观察性质：理论恒等式 + 工程观察。 在有限 horizon 自回归 MDP 中，旧策略 μ 的精确 advantage 满足望远镜求和：沿新策略 π 的轨迹，所有 step advantage 之和的期望，等于新旧策略的期望回报差。把期望从 π 的 prefix 分布换成 μ 的 prefix 分布时，严格的 Radon–Nikodym 权重正是 π(y₁:ₜ|x)/μ(y₁:ₜ|x)，而不是仅当前 token 的 ratio，也不需要额外乘未来 suffix 的 ratio。

第二个洞见是 KL 不必近似成局部二次函数。定义 φ(r)=r−1−log r，在 μ 的 prefix 分布下取期望，利用 Eμ[r]=1，可得到精确的 D_KL(μ_prefix∥π_prefix)。这允许以真实的非对称 KL 几何来求两侧裁剪边界。第三个是实现层面的折中：直接乘长 prefix 的 ratio 容易出现长度依赖与梯度尖峰，于是采用几何平均作为 forward weight，并保留 current-token-only 的梯度路径。请注意：理论恒等式与实际 surrogate 并非同一个对象；作者的 clipping、近似 advantage 和 stop-gradient 是实用设计，不继承无条件单调提升保证。

2.5 Method Deep Dive：Input → Output

Prompt + old policy μ → G 条 rollout → rule-based reward / group advantage → 每个 token 的 logπ−logμ → prefix cumsum → exact-KL coordinate 的两侧 root → 几何平均区间 + straight-through → sign-aware clipping → 优化 πθ → 下一轮 rollout

Step 1 · 收集行为轨迹。 对一个 prompt 采样 G=8 条答案，记录每个 token 在行为策略 μ 下的 log-probability。训练端的当前策略 πθ 在后续多次更新中不断变化，但 μ 是这批样本的生成分布。若把“当前训练模型输出的 logp”错当成旧 logp，prefix correction 立即失去意义。

Step 2 · 计算稀疏 reward 与组相对 advantage。 用规则验证器检查归一化最终答案，正确为 1、错误为 0；同题八条答案形成相对好坏。优势 Âᵢ 在该响应内按 token 共享。这里没有 step-level verifier，因此不能声称 EPIC 解决了真实过程奖励的 credit assignment；它只是重新分配离策略样本在每个 prefix 的梯度权重。

Step 3 · 从局部差异累计到 prefix。 令 Δₖ=logπθ(yₖ|x,y<ₖ)−logμ(yₖ|x,y<ₖ)，则 log r_pre,t=Σₖ≤t Δₖ。代码使用 masked cumsum，复杂度 O(T)，无需增加模型 forward。EOS / padding 的 mask 必须正确，否则末尾虚假 token 会污染累计比率。

Step 4 · 构造 KL 预算。 对每个样本 prefix，计算旧策略 prefix 概率的几何平均 p̄_old,t=exp[(Σ logμ)/t]；设置 κ⁻=tδ⁻/p̄，κ⁺=tδ⁺/p̄，再分别解 φ(ℓ)=κ⁻、φ(u)=κ⁺，得到 ℓ≤1≤u。因为 φ 在 1 两侧单调方向相反，数值求根必须分别处理上下支；不能拿一侧根复制到另一侧。

Step 5 · 归一化与局部梯度。 令 g=(r_pre,t)^(1/t)，裁剪区间相应为 [ℓ^(1/t),u^(1/t)]。直接对 g 求导会使第 t 个 loss 对前 t 个 token 全部回传。作者采用 straight-through：前向仍是 g，反向只通过当前 token logp。这是稳定性和工程可用性折中，不是对原始精确目标的严格梯度。

Step 6 · sign-aware clipping 并更新。 对正 advantage，限制向上增长的收益；对负 advantage，限制权重两侧并额外做上侧保护。每条回答先平均有效 token，再平均同组响应，避免长答案凭 token 数量主导 batch loss。参数更新后，重复新的 rollout。典型失败包括：logp 溢出、root 不收敛、mask 错误、policy lag 过大、奖励验证器错误、MoE routing 引入额外分布差。

2.6 核心公式与数学直觉

Eq. (8)/(10) · Prefix importance weight
rₜᵖʳᵉ = π(y₁:ₜ | x) / μ(y₁:ₜ | x) = ∏ₖ₌₁ᵗ π(yₖ | x,y<ₖ) / μ(yₖ | x,y<ₖ)
Jₓ(π) − Jₓ(μ) = Eᵧ~μ [ Σₜ rₜᵖʳᵉ Aᵘ(sₜ,aₜ) ]

π 是待训练策略，μ 是产生 rollout 的旧策略，Aᵘ 是“在 μ 下继续执行”的优势。最大化加权优势，理论上推动新策略回报超过旧策略；但实际估计优势不精确，且样本有限。这里的 r_pre 负责校正到达当前 prefix + 选择当前动作的联合概率，不能用单个 token ratio 代替。若动作改为 Agent tool call，完全相同的概率乘积形式可在离散动作 MDP 中成立，但 tool 反馈改变环境动态时必须重新验证假设。

Eq. (17) · Exact reverse-KL coordinate
φ(r)=r−1−log r； Eμ[φ(rₜᵖʳᵉ)] = D_KL( μ(y₁:ₜ|x) ∥ π(y₁:ₜ|x) )
φ′(r)=1−1/r；φ″(r)=1/r²>0

φ 的最小值在 r=1，两侧严格凸；r→0 或 r→∞ 都会产生大惩罚。相比常见的 (log r)²/2，φ 是全局精确坐标，保留上下方向的非对称性。注意“精确”修饰分布期望等式，不代表对一个 sampled prefix 的 φ 就等于全分布 KL，也不意味着按样本裁剪就严格满足总体 KL 约束。

Eq. (18)–(22) · Calibrated clipping
κₜ⁻ = tδ⁻ / μ(y₁:ₜ|x)^(1/t)；κₜ⁺ = tδ⁺ / μ(y₁:ₜ|x)^(1/t)
φ(ℓₜ)=κₜ⁻，φ(uₜ)=κₜ⁺；gₜ=(rₜᵖʳᵉ)^(1/t)
maximize J_EPIC = E[ (1/G) Σᵢ (1/Tᵢ) Σₜ C(g̃ᵢₜ, Âᵢ; ℓᵢₜ^(1/t),uᵢₜ^(1/t)) ]

δ⁻、δ⁺ 越大，允许的下/上侧偏离越大，裁剪越松，潜在学习速度与不稳定风险都增加。论文默认 δ⁻=5×10⁻⁴、δ⁺=2×10⁻³，上侧预算较大，反映非对称容忍。C 为符号敏感裁剪：A≥0 时 A·min(g̃,u)，A<0 时 A·clip(g̃,ℓ,u)。实用训练最小化的是 −J_EPIC。KL loss coefficient 10⁻³ 是额外训练配置，不可与 φ 的两侧预算混为一谈。

2.9 Experiment Setup：每组实验想回答什么？

2.10 Metrics 教学式解释

mean@8：对每题独立采样 8 条响应，统计八条中正确的比例，再对题目求平均；越高越好。它不是“8 条里至少一条对”的 pass@8，不能互换。Four-benchmark Average：先各自计算 mean@8，再四套题等权平均，尽管题量 30/30/40/30 不等；它衡量跨 benchmark 的平均能力，却会掩盖单个困难集合的极端退化。Clip Fraction：有多少位置触发裁剪；过低可能约束失效，过高可能学习被抑制，不能简单认为越大越好。Position-wise CV：各位置裁剪率的标准差/均值，越低表示位置更均衡，但不表示裁剪强度合理。Entropy：输出分布不确定性，过低可能模式塌缩，过高可能乱采样。Train–rollout logp gap：训练引擎与 rollout 引擎的对数概率差；越小通常越一致，但不等于最终泛化。CPU RSS：驱动进程常驻内存，越低越省内存，不等于 GPU memory 或集群总内存。

2.13 Ablation / Mechanistic Analysis

去掉几何平均的旧概率校准 → raw prefix probability 随长度指数衰减，后期位置裁剪近乎失活 → AIME24 末次约 27.1、梯度尖峰约 3.98，说明校准主要承担位置均衡与数值稳定。保留校准但把优化权重改为原始累计 ratio → 末次 AIME24 约 31.3、梯度峰值约 2.00 → 表明 weight normalization 仍有独立贡献。完整 EPIC → 约 33.3、梯度峰值约 1.73。上述实验是消融相关性证据；要严格分离 φ 精确性与 ST 近似的因果贡献，还应在同预算下加上 quadratic-coordinate、full-prefix-gradient 等受控版本。

2.14 Claim vs Evidence

Authors Claim： Prefix ratio 是正确的逐步 change-of-measure 权重；φ 的行为策略期望是精确 reverse KL；实际 clipping 可以稳定离策略 MoE RL，并减少 replay 额外内存。Experiments Actually Show： 在 Qwen3-30B-A3B-Base + 17,917 数学训练样本 + 130 测试题的统一协议下，EPIC 三 seed 平均优于五个 clipping baseline；消融展示位置校准与梯度控制；对 R2/R3 driver RSS 显著更低。What Is Not Yet Proven： 实际训练 loss 的全程单调提升；对 dense LLM、Agent、VLM、不同 verifier 的泛化；在等 wall-clock / 等 GPU-hour 下仍占优；更大训练数据或更严格独立测试集上的统计显著性。

2.15 Contribution（创新类型与已有组件）

C1 [New Mechanism / Theoretical Finding] 将自回归 performance difference 明确写成 prefix 分布上的精确重要性权重；数学恒等式依赖已有重要性采样与 MDP 工具，创新是针对 LLM prefix trust-region 的系统化构造。C2 [New Objective] 用 φ(r)=r−1−log r 反解非对称边界，并把 per-prefix trust region 落地到 PPO-style loss；φ/KL 关系不是新发现，新的部分是组合与校准。C3 [New Engineering] 几何平均与 current-token-only ST、无 replay 集成；这些算子本身非首创，但在该问题上有有效消融。C4 [New Empirical Finding] 在强 off-policy MoE 数学 RL 下，prefix 校准比 token / sequence 粒度更稳，并减少 replay 进程内存；不是新 benchmark。

2.16 Limitation & Failure Modes

Authors' limitation / 论文证据边界： 实验集中在一个稀疏 MoE 模型、四个数学基准；单调性命题假设 exact advantage、共同支持集、精确优化，实践使用 group advantage、clipped surrogate 与 ST。理论层面的“精确”不可误解为实证保证。Additional limitation： (1) 三 seed 仍不足以刻画稀有崩溃；(2) 130 prompt 选点与报告共用；(3) 0/1 最终奖励可能被格式技巧利用，不能保证 reasoning faithfulness；(4) 对极长 horizon，prefix logp cumsum 的尾部数值和梯度路径敏感；(5) 对 tool-use RL，动作可能不是单 token，环境观测与工具副作用改变 state distribution；(6) routing replay 比较使用特定版本/索引 dtype，不能直接外推所有系统；(7) 训练 reward 变高不等于 reward hacking 被消除；(8) 没有报告等质量所需 rollout、GPU-hour 或端到端训练吞吐提升。

2.17 Reproduction View：可执行的最小复现路线

关键模块： 先做一个独立 PyTorch loss 函数，输入形状 [B,T] 的 logp, old_logp, advantage, mask；先实现 cumsum(logp-old_logp)、几何平均、φ 两侧 root（在 log-space 做 Newton / 分支近似）、ST、sign-aware clipping；再接 verl 的 policy loss 插件。先在 CPU 上用 3-token toy 验证数值，再在 1–2 张卡的小模型跑 smoke test，最后才考虑 32×A100 的原文规模。

先跑哪项？ 先做“固定 rollout buffer、同一 batch 的 GRPO vs EPIC 更新”测试：记录每位置 clip fraction、CV、grad norm、logp gap，验证 loss 没有 NaN、mask 位置梯度为零、ST 只让当前 token 的 logp 接受梯度。之后在 Qwen 1.5B/3B 级别的小数学训练集跑 200–500 step 的迁移性预实验，不是论文复现；最终要对齐 Qwen3-30B-A3B-Base、DAPO-Math-17K、八采样、四基准、三 seed、300 step 才能称主结果复现。

最敏感超参： δ⁻/δ⁺、policy lag、update depth、每题 rollout G、response length、KL loss、reward verifier。优先网格 δ 取默认的 0.5×/1×/2×，固定 seed 与采样预算；记录所有训练/验证 prompt hash，避免泄漏。首个最能证伪 Claim 的实验： 在相同采样轨迹上，若 EPIC 无法比 GRPO/GSPO 更均衡地控制后段 clipping，或准确率收益仅在选点集合存在，则核心论证需重新审视。官方代码链接已给出，实际 commit / 环境可用性仍需复现时核验。

2.19 Migration Analysis：两条可以开始写脚本的方向

Migration A — Agent RL 的 Action-Prefix Trust Region（优先）。 Original Problem： token prefix 的离策略漂移。Transferable Mechanism： 累计行为概率比率 + exact-KL coordinate + 分步裁剪。New Research Question： 在工具反馈随机、行为策略滞后 0/2/4 轮时，按 tool action prefix 而非 token 裁剪，能否改善长时程成功率并减少崩溃？Method Modification： 将每次工具调用（工具名+参数）定义为高层动作，保存行为策略的 action logp；工具返回值只作为 state observation，不纳入 action probability；对每个高层动作累计 ratio，奖励按任务成功或可验证子目标赋值；同 token 版本与 action 版本都做。Minimum Experiment： 使用 WebShop 与 ALFWorld 各抽 200 train/100 test episodes，固定环境种子；Qwen3-4B（可换同级开源 instruct），LoRA r=16，batch 16 episodes、每任务 4 rollout、最长 20 tool steps、3 seed；lag ∈{0,2,4}，δ 比例 ∈{0.5,1,2}，记录每 step logp 与 tool outcome，先跑 100 update smoke，再 1000 update 主实验。Model： Qwen3-4B；Dataset： WebShop/ALFWorld；Baseline： action-level PPO/GRPO、token-level EPIC、GSPO。Metric： success rate、action prefix KL、clip CV、reward hacking incidents、GPU-hour、rollout count。Expected Contribution： 将序列分布纠偏从 token 推到 agent action，提供长时程实证。Risk： action 参数的 logp 定义与工具返回随机性、不同 action 长度造成偏差。Collision Risk： 与已有 trajectory-level IS / off-policy agent RL 接近；须明确“prefix calibrated trust region + tool-state dynamics”的新意。

Migration B — 低成本视频问答中的 Query-Conditioned Frame Policy RL。 Original Problem： 长序列采样策略改变使后续决策分布漂移。Transferable Mechanism： 对逐帧选择 policy 的 prefix trajectory 进行 importance correction。New Research Question： 以固定视觉 token 预算选择关键帧时，是否能比 REINFORCE / PPO 更稳定地学到 query-aware selection？Method Modification： 每个时间步的动作是 select/skip，状态包含问题、已选帧摘要、剩余预算；reward=答案正确 − λ·已用帧数，保留离策略旧选择概率；prefix ratio 用于 clip，加入“必须保留答案证据帧”的反事实评估。Minimum Experiment： 在 NExT-QA 和 EgoSchema 各抽 500 个训练视频、200 个验证视频（若许可/划分允许，按官方 split 替换），每视频统一采样 32 帧，预算 B∈{4,8,16}；视觉编码器冻结，Qwen2.5-VL-7B 做回答；策略先用两层 MLP 读取帧特征，batch 16、3 seed、1000 updates；比较 Uniform、CLIP similarity、PPO、EPIC-style。Model/Dataset： Qwen2.5-VL-7B + NExT-QA/EgoSchema。Metric： accuracy、frames、visual tokens、prefill wall-clock latency、FPS、峰值显存、每步 clip CV。Expected Contribution： quality–budget–stability 三维 Pareto 与 frame-policy prefix correction。Risk： 视频解码与视觉编码耗时可能吞掉减少 token 的收益。Collision Risk： 与既有 adaptive frame selection / RL video sampling 交叠，必须突出 off-policy stability 与真实系统延迟。

2.20 RL 专用分析：Formulation / Reward / Training Efficiency

State： (x, y<t)，即 prompt 与已生成 prefix；Action： 下一个 token；Policy： πθ(yₜ|x,y<t)；Trajectory： 整条生成答案；Reward： 最终规则核验的 0/1 correctness，稀疏 outcome reward；Advantage： 同题八条回答的 group-relative estimator，非训练好的 PRM；Objective： 最大化经 prefix correction 和 sign-aware clipping 的 surrogate；KL： φ 对应的 prefix reverse-KL 几何 + 配置中的额外 KL loss；Entropy： entropy bonus=0，仍监控熵变化；Credit Assignment： 同一答案优势传播到 token，prefix ratio 调整权重，未产生真正 dense process credit。

Reward hacking 风险： 验证器只检查标准化答案是否匹配，模型可能学到格式与答案猜测，而非可验证的每步推理。可加入步骤扰动、答案替换、过程一致性检测；若正确率上升而轨迹因果性下降，则属于能力代理指标错配。训练效率： 8 rollout/题、512 responses/rollout batch、300 global steps、32×A100 是论文报告的主要计算设置；没有足够证据得出“sample efficiency 提升 X%”或“wall-clock 加速 Y×”。不需要额外模型 forward 是实现优点，不等于完整训练成本下降。

2.21 Attack / Verification Lens

Black-box probe： 对同一道题生成长度分层（短、中、长）的题目与固定答案，比较不同 policy lag 下正确率与答案自洽率；Robustness： 对早期推理 token 注入局部替换，测试后续 prefix drift 是否导致脆弱性；Efficiency stress： 将输出上限从 2k→4k→8k→16k，记录 wall-clock、GPU memory 与 clip CV；Recovery： 中断训练、切换行为策略快照后继续更新，测恢复步数；New metric： Prefix Drift–Accuracy Curve (PDAC)：以 E[|log r_pre,t|] 分位数为横轴、正确率为纵轴，按长度分桶，防止只看平均 reward。以上均是本报告的研究建议，不是论文已验证的结果。

2.22 如果只记住 EPIC（九句话）

  1. 自回归 RL 的“状态”就是生成前缀，旧策略和新策略到达同一状态的概率会变。
  2. 单 token ratio 无法校正 prefix 访问概率，完整 response ratio 又可能裁掉有价值的早期信号。
  3. 精确逐步 change-of-measure 权重是截至当前 token 的累计 prefix ratio。
  4. φ(r)=r−1−log r 的旧策略期望等于 prefix reverse KL，保留非对称几何。
  5. EPIC 对每个 prefix 解上下裁剪界，按几何平均归一化长序列。
  6. Straight-through 让前向利用 prefix，反向仍只通过当前 token，这是一项工程折中。
  7. Qwen3-30B-A3B-Base 四数学基准均值 39.34%，最强非 replay 基线 DAPO 35.45%。
  8. 论文没有证明实用 clipped loss 必然单调提升，也没有证明训练 wall-clock 更快。
  9. 最值得迁移的是 Agent 的 action-prefix off-policy RL，并用真正的任务成功率验证。

3.2 人话版（250–400 字）

假设你用一个购物 Agent 连续几周看同一款背包：第一天看到黑色款 120 元有货，第二天在另一家店看到外观相似的背包 99 元但缺货，第三天你又问“之前那款更便宜而且有货吗？拉链到底是什么颜色？”普通文本记忆可能只留下“买过背包”，丢失拉链图像细节；普通多模态 RAG 虽然保留照片，却不知道不同页面是不是同一款，也未必知道价格与库存如何变化。MHG-Mem 把原始事实、每次出现的实体、跨时间变化的状态拆成三层节点，用三类超边记录“同一个对象”“状态怎样演化”“这项结论来自哪张图/哪段话”。检索时，Agent 可以先找实体、再沿状态历史走、最后回看原图验证，而不是只向量召回一次。论文在 MemEye、Mem-Gallery、WorldMemArena-S 上用三种 backbone 测试，平均 Judge 指标比各自最强 baseline 高 8.20、9.89、9.98 个百分点；但代价是约两倍 token 消耗。其研究价值是：长期记忆的可靠性不仅由压缩质量决定，还取决于身份一致性、时间版本与可验证来源能否一起保留。

3.3 Background & Research Gap：为何“存图片”仍不够？

传统 Agent memory 常做两件事：把历史交互总结成文本摘要，或者把对话/图片存入向量库。前者省 token，能高效回答“用户喜欢什么”，但当问题是“那款背包主拉链是斜的还是直的”时，摘要可能没记录细节；后者保留像素，可检索“相似背包”，但两张不同角度照片、不同网页布局与跨会话的别名会让系统难以确定是否是同一物体。即使正确找到两张图，系统还必须知道“99 元”的库存状态属于哪一天，而不是把不同时间的价格和库存错误拼接。

旧范式的 gap 有三层。Identity gap： 多次观察的同一实体没有稳定 referent；Evolution gap： “变成什么”常被简单最新摘要覆盖，失去过去版本；Provenance gap： 推导出的状态没有可追溯到原始观察的证据。MHG-Mem 将这三者视为互相依赖：如果 identity 错了，后续时间序列就会混入别的物体；如果状态合成没有 source ID，即使结论正确也不能被核查；如果检索不按问题类型选择入口，再好的记忆图也可能检索不到。

与文字型 A-Mem、MemoryOS、SimpleMem 相比，它强调原始视觉证据；与多模态 SRAG、UniversalRAG 相比，它强调跨会话身份和状态历史；与已有 HyperMem 相比，创新不在“第一次使用超图”，而在类型化多模态 occurrence/evolution/evidence 关系的联动及查询驱动的源证据检查。它不是端到端可训练的记忆神经网络，而是以现有 VLM/LLM、embedding 和工具调用构建的系统。

3.4 Core Insight：将“记忆内容”与“记忆为何可信”一起存储

观察性质：系统设计假设 + benchmark 经验验证。 作者发现两类方法各缺一半：文本抽象能表达变化但遗失图像细节，像素保存能回看细节却不自带跨会话身份绑定。于是设计三个可独立访问的层次：FactNode 保留原子事实及来源，EntityNode 保留每次具体提及及图像区域，EvolutionNode 表示某个属性跨时间的状态变化。三个层次不是简单父子树：一次事件可以涉及多个实体和多个事实，所以使用能同时连接多个节点的 n-ary hyperedge。

Occurrence hyperedge 连接同一 referent 的多次出现与事实；Evolutionary hyperedge 连接状态变化与主体、共同参与者；Evidential hyperedge 把状态变化连接回用于推导的事实。这样，“最近库存缺货”是一个可读状态，“库存从有货变成缺货”是一条演化，“这个结论来自第 2 天商品页面”是一条证据链。更关键的是 Agent 不被迫每次读全部层：细节问题直接找原图，时间问题先找 evolution，再沿证据边回溯。这一 insight 的实证支持来自三基准与消融；没有证明超图结构本身在所有场景优于等价的关系数据库 schema。

3.5 Method Deep Dive：从历史到证据链

多轮 (文本 + 图像 + 日期) → Fact extraction → Entity mentions → Occurrence linking (UPDATE/ADD/SKIP) → Evolution synthesis → Evidential hyperedges → 分层索引 → Query-aware agentic search → Source inspection → Evidence assembly → QA answer

Step 1 · 保存每轮原始观察并抽取原子事实。 输入 dₜ=(xₜ, Iₜ, δₜ)，包含文本、图片和记录日期。VLM 从当前轮与同会话最多前三轮上下文抽取独立事实，例如“背包 A 在店铺 X 的标价 120 元”。每个 FactNode 绑定图像 ID、会话轮次、来源与时间，原始图片不因抽象而删除。风险是 VLM 把图上看不清的库存标记误识别为“有货”，之后所有结构化推导都会继承错误。

Step 2 · 抽取 EntityNode 与 identity linking。 VLM 提取文字/视觉实体 mention，视觉 mention 可绑定图像区域。候选同一 referent 的 occurrence hyperedge 通过文本 cosine 与视觉 cosine 各取最大相似度，加权排序，默认 w_text=w_image=0.5、top-K=3。模型选择 UPDATE（并入已有 referent）、ADD（新 referent）或 SKIP（无效提及）。保留每个 mention 独立节点，不能为了省空间把不同会话的证据覆盖成一个实体摘要。若误 UPDATE，会把两只相似背包合并；误 ADD 会让同一背包的历史断裂。

Step 3 · 将事实附着到实体组。 论文用 mention-name 的词法匹配，把事实关联到对应 occurrence hyperedge。这一步实现简单，但“黑色背包 / 型号 ZX-3 / 那个包”别名、同名不同物、OCR 错误都可能导致关联遗漏或误连；这也是最值得改进的可迁移模块之一。单靠更强的视觉 embedding 不一定解决实体同一性，需要时间与上下文约束。

Step 4 · 合成 EvolutionNode。 对某个 referent 关联的事实按观察顺序排序，让 LLM 找到同一属性/关系的不同取值，生成 evolution summary、更新类型（replacement/update/addition）与一串 (value, fact_id) 配对。默认仅保留至少两个事实、来自至少两个 session 的变化。比如 price: 120→99，stock: in→out。注意这是“观测顺序”，不总等于真实事件发生时间；迟到的消息或回填数据可能产生错误演化。系统还把共同参与的实体放入 evolutionary hyperedge，支持“是谁把物体移动了”的跨实体问题。

Step 5 · 保存 evidential hyperedge。 每个 evolution 与实际支撑它的 FactNode 建立边，并在状态序列中保留 value→fact 的逐项映射。之后若事实被更新，系统可按来源重建演化，不必直接信任一个不可追溯的摘要。这里的形式化命题是可恢复已记录来源，而不是证明原始观察为真或摘要没有幻觉。

Step 6 · 运行查询驱动 Agent 搜索。 给定问题 q，LLM controller 逐步选择工具：resolve_facts、resolve_entity、resolve_evolution、search_image、get_raw_verbatim、submit_evidence。默认最多 16 次工具步、最多向模型展示 10 张不同图片；实体检索最多 3 组、演化最多 3 个方面、事实最多 30 条。搜索动作改变 Agent 的当前检索历史 hₖ；后续动作依赖之前看到的候选与原始证据。

Step 7 · 组装与回答。 检索 Agent 将 fact ID、image ID 与可选说明提交为证据链 E_q；系统验证引用的标识符确实已检索且图片属于对应来源轮次，然后交给 QA backbone 生成答案。重要细节：引用 ID 的合法性检查不验证文本总结的语义真伪；一个引用格式正确的错误结论仍可能通过。失败传播链为：错误抽取→错误身份链接→错误演化→检索到错误证据→答案错误。若缺少原始图片，Source Inspection 无法弥补前端遗漏。

3.6 核心公式、超图与概率直觉

Eq. (1)/(2) · Query conditioned retrieval + typed hypergraph
E_q = S(q, M_T)， ŷ ~ pθ(· | q,E_q)
H=(V,E,ι,τV,τE)；V=F ⊔ U ⊔ Z；E=E_occ ⊔ E_evo ⊔ E_evd；ι(e)⊆V

M_T 是从历史构建的持久记忆，S 是搜索器；F/U/Z 分别是 Fact/Entity/Evolution，⊔ 表示互不混淆的类型化集合，ι(e) 返回超边所连接的节点集合。普通图一条边连接两个节点，超图可将“这次商品页面出现的背包 mention、价格事实、库存事实”作为一个关系组。它并没有优化可微 loss，优化目标是通过结构与检索策略提高回答正确率；超图是数据模型，不是神经网络注意力矩阵。

Eq. (4)/(5) · Occurrence linking
s(u,e_occ,r)=w_T · maxᵥ∈Uᵣ cos(text(u),text(v)) + w_I · maxᵥ∈Uᵣ,visual cos(img(u),img(v))
F_r ← F_r ∪ { f : A(f,e_occ,r)=1 }

u 是当前 mention，r 是候选实体组；两个 max 分别选最相似的历史文字 mention 与视觉 mention，默认 w_T=w_I=0.5。高分表示更像同一实体，不保证身份相同。第二式 A 是词法命中指示器，容易受别名影响。提高 top-K 会扩大候选覆盖，但增加 VLM 判别成本和误匹配风险；论文 K=1→3 的均值从 71.65→73.28，K=5 为 73.33，收益明显递减。

Eq. (6)/(7) · Evolution as grounded state sequence
Ẑ_r = LLM_evo( Order(F_r) )
S_z = ((v₁,f₁),...,(v_m,f_m))，F_z={f_j}⊆F_r；保留至少两个不同状态值

这里 v_j 是属性取值、f_j 是支持它的事实。不同于只存一个最新摘要，S_z 保留可回溯的变化序列。EvolutionNode 可能有多个 coactor；如果事实排序错或“两个值”其实是同一天不同店铺报价，模型可能误判为状态变化。应当把 event-time 与 observation-time 分开并显式记录来源冲突。

Eq. (8)–(11) · Agentic search + cross-layer traversal
a_k ~ πθ(·|q,h_k)；o_k = Execute(a_k,M_T)
s_F=λ_T s_text-text + λ_TI s_text-image + λ_II s_image-image
Traverse(v,E′,V′)=⋃_{e∈E′, v∈ι(e)} (ι(e)∩V′)

controller πθ 不是本论文训练的 RL policy；此处仅表示 LLM 按当前检索历史选择工具。s_F 三项是跨模态检索的线性加权相似度；图像缺失时相关项记零而不重归一化，可能对纯文本 query 造成系统性分数差。Traverse 是“从某个节点沿指定类型超边扩展到目标层”的集合运算，若 occurrence 误连，扩展会把错误事实一次性引入证据集合。

Appendix Proposition 1 · Source recoverability ≠ Truth
z → e_evd → f_j → ρ(f_j) → original observation
Src(z) = {ρ(f_j)}；合法更新后来源集合仍可恢复

ρ(f) 是事实的来源标识符，原始归档必须仍可访问。该命题证明的是记录链条不会因为规范化的插入/替换操作而丢失引用，不证明 f_j 的内容正确，也不证明 LLM_evo 生成的 summary 合理。这是全文最需要区分的“形式化保证”和“语义可信度”。

3.7 Toy Example：从三次购物观察到可验证答案

Input： Session 1：用户看见“ZX-3 背包，黑色，¥120，现货”，保存页面图 img01，抽取 f1=price(120)、f2=stock(in)、f3=zipper(black)。Session 2：另一网页“ZX-3，¥99，缺货”，img02，抽取 f4=price(99)、f5=stock(out)。Session 3：侧面图 img03，mention 叫“这只包”，实体抽取与 img01 视觉特征相近。这里假设它们确实是同款；如果不同款，应当 ADD 而不是 UPDATE。

Graph construction： u1/u2/u3 三个 mention 经 UPDATE 并入 referent r_ZX3；Occurrence hyperedge 包含 u1,u2,u3 与 f1…f5。LLM_evo 生成 z_price 的状态序列 [(120,f1),(99,f4)]，z_stock=[(in,f2),(out,f5)]；两条 evidential hyperedge 分别连回对应事实及 img01/img02。原图 img03 仍可用于核对拉链，不因为“背包价格”摘要而删除。

Query： “以前有没有比 120 元更便宜而且有货的报价？拉链颜色是什么？” Controller 先 resolve_entity(ZX-3)，再 resolve_evolution(price) 和 resolve_evolution(stock)，发现 99 元与 out 同源 Session 2，因此不能把 99 元和 Session 1 的 in 拼成一个虚假好价；随后 get_raw_verbatim(img01) 核查拉链。Output： “记录中没有同时满足低于 120 元且有货的报价；第一天图片显示拉链为黑色”，并附对应事实与图片来源。若图片无法辨色，可靠系统应回答“无法确认”，而不是根据背包主体颜色猜测。该例是本报告构造的可执行演示，非论文原始数据。

3.9 Experiment Setup：实验究竟在测什么？

RQ1：身份、演化、来源三者结合能否提高跨会话问答？ 三个 benchmark：MemEye 8 个生活场景、371 个问题（配选择题与开放题）；Mem-Gallery 20 场景、240 sessions、3962 对话轮、1490 张图、1711 个开放问题；WorldMemArena-S 为发布的 150-sample 子集，含 7906 个问题，覆盖 GUI/embodied/personal/project 历史中的 11 类能力。后者不是完整 WorldMemArena，泛化时不能省略 “-S”。系统按 QA checkpoint 的可见历史构建 memory，避免读到未来会话。

RQ2：提升是否跨 backbone 成立？ Qwen3-VL-8B、GPT-4.1-mini、Qwen3.8-27B 三种 backbone；作者用同一 backbone 做 memory construction、agentic retrieval 与回答。Qwen3-VL-8B / Qwen3.8-27B 通过 vLLM 部署于 4×NVIDIA A800，GPT-4.1-mini 用官方 API；max tokens 65,536、temperature 0，三次运行取平均。文本 embedding 是 all-MiniLM-L6-v2，视觉/跨模态是 SigLIP2 base patch16 384。Judge 使用 GPT-5.4-mini；这一独立评判器也引入闭源依赖与主观评分风险。

RQ3：哪类结构或工具真正有用？ Table 2 从 fact-only 逐步增加 Entity、Occurrence、Evolution、Evidence；Table 3 分别去掉 Agentic Search、Inspection、Cross-layer Traversal、Visual Tool。RQ4：成本与预算如何折中？ Figure 6 记录构建+检索+QA 的总 token；Table 6 改 top-K、tool step budget 与 image budget。RQ5：真的能找回来源吗？ Figure 4 的家庭装修示例和附录 Figure 9/10 逐步展示工具与原图证据。

数据与推理设置： 构建时最多看同 session 前三轮、当前轮最多 8 张图；实体链接 top-K=3、文字/图像权重各 0.5；演化需至少两个事实和两个 session；检索最多 16 tool steps、10 张图，实体最多 3 组、演化 3 条、事实 30 条。Training： 本文不报告训练一个新的 backbone，核心是固定模型上的 memory construction / search 系统；不存在与 RL 论文相同意义的训练 epoch 或 loss。

3.10 Metrics 教学式解释

EM (Exact Match)：MemEye 选择题正确率，选项轮换后取均值；越高越好，易受猜测与选项格式影响。Token F1：把开放回答分词并归一化，precision 与 recall 的调和均值；越高越好，可能把语义等价但用词不同的正确回答判低。BLEU-1：一元词匹配精度加长度惩罚；越高越好，尤其不擅长衡量复杂语义与视觉证据真实性。Judge：MemEye/Mem-Gallery 参考答案打 0、0.5、1 分；WorldMemArena-S 使用 QA-C，统计被评为正确的有效问题比例；越高越好，但三基准的 Judge 规则并不完全一致，取简单均值需谨慎。Avg. J.：三基准 Judge 等权平均，不按问题数加权。Memory Recall：重要性加权的 gold memory point 覆盖率；高好，但不保证内容无误。Memory Correctness：已存条目中被判断正确的比例；高好，但可通过少存东西虚高，因此需结合 recall。Retrieval Coverage：检索证据覆盖 gold evidence 的程度；高好，但不保证最终答案正确。Update Handling：最新/同时保留新旧/仍过期分别按 1/0.5/0 计分；高好。Token Cost：包含构建、检索、QA 的输入输出 token 与视觉 token；低成本好，但不是 wall-clock latency 或真实费用的同义词。

去掉 Occurrence linking： Fact+Entity 仅 63.57，加入 occurrence 到 68.35，+4.78 pp，说明把跨会话 mention 合并到稳定 referent 是核心模块。去掉 Evolution： 从含 occurrence 的 68.35 到完整 evolution 的 71.72，+3.37 pp，支持时间状态摘要的作用。去掉 Evidence hyperedge： 71.72→73.28，+1.56 pp，来源链接在总体上有增益但小于 identity；并不意味着来源不重要，因为它承担可审计性。去掉 Inspection Tool： 73.28→69.84，−3.44 pp，说明仅有结构化事实不足以替代原始图片/对话。去掉 Cross-layer Traversal： −3.09 pp；去掉 Visual Tool： −1.37 pp；去掉 Agentic Search： −5.10 pp。这些都是模块去除的性能差异，不是证明“超图语义结构对最终答案具有严格因果性”的随机干预；组件间交互与不同 token 预算仍可能混淆。

3.14 Claim vs Evidence：作者说的与真正证明的

Authors Claim： 三层超图统一身份、演化与来源，Agentic Search 能根据问题找到正确证据，三 benchmark / 三 backbone 上明显优于既有 memory。Experiments Actually Show： 在论文规定的三数据集、三模型、相同运行环境下，Judge 均值领先 8.20–9.98 pp；结构和工具消融显示 identity / evolution / inspection 有可分辨的贡献；附录有成本、预算与失败子任务。What Is Not Yet Proven： 原始事实抽取在真实开放世界长期稳定；跨数千次更新的身份误合并率；语义证据的真实性；同质量下的端到端 wall-clock/美元成本优势；超图优于实现相同 schema 的关系数据库；在 streaming video 实时限制下仍可部署。形式化 Source Recoverability 只保证“找回记录的来源”，不保证来源正确。

3.15 Contribution：真创新还是组件组合？

C1 [New System / Engineering] 三层多模态 typed hypergraph：Fact、Entity、Evolution 及 occurrence/evolution/evidence 超边联合表示；超图和 provenance link 早已存在，创新是围绕跨会话状态的具体 schema 与集成。C2 [New Mechanism] 结合文本与视觉的 identity linking、按属性的 state evolution、证据逐项绑定；不是全新 embedding 或 LLM objective。C3 [New Evaluation Protocol / Empirical Finding] 在 MemEye/Mem-Gallery/WMA-S 上用多 backbone、分层 ablation、成本与检索预算系统验证；数据集不是作者新建。C4 [New Formal Property] 证明合规更新下 source reference 可恢复；命题是数据结构不变量，不是语义正确性定理。C5 [Agent Tool System] 六工具 query-adaptive search，把 retrieval policy 显式暴露为可优化的行为链；这给 RL 与 cost-aware agent 提供了可迁移接口。

3.16 Limitation & Failure Modes：从错误传播看风险

Authors' limitation / 实验承认的弱点： 约两倍 token 消耗；低预算下 forced submit 率高；部分 factual recall 不如 strongest baseline；GPT-4.1-mini 上 Mem-Gallery temporal reasoning 低 6 pp。Additional limitation： (1) 词法匹配附着事实容易漏别名、OCR 变体与跨语言名词；(2) entity UPDATE 错误会污染多个 session，后续 Evolution 看似自洽但全错；(3) 当前视觉输入上限 8 张图/轮，视频帧流必须另行设计；(4) 原始图片长期存储有隐私、合规与存储成本；(5) 时间顺序使用 observation order，迟到事件、纠错与时间戳冲突处理不足；(6) Judge 是闭源模型，存在 LLM-as-judge bias；(7) 16 次工具步可能使在线延迟过高；(8) 仅三 benchmark，开放网页、代码仓库、实时视觉与多 Agent 并发修改缺少直接实验；(9) 代码状态未报告，复现需要重新实现 schema 与工具；(10) 如果检索的原始来源本身被 prompt injection 污染，provenance 只让攻击内容“有出处”，不自动变安全。

3.17 Reproduction View：先复现结构贡献，再复现昂贵 Agent 搜索

最小代码结构： archive.py 保存原始轮次与图片哈希；fact_extractor.py 抽取事实与 source IDs；entity_linker.py 使用 MiniLM+SigLIP2 top-K 与 UPDATE/ADD/SKIP；evolution.py 生成 (value,fact_id) 序列并验证至少两会话；hypergraph_store.py 管理 F/U/Z 与三类超边（最初可用 SQLite 三表+incidence 表，不必上专门图库）；tools.py 实现六个工具；eval.py 计算 EM/F1/Judge 与 token cost。

第一轮最小复现： 先在 30 个手工标注的多轮“物体颜色/价格/位置变化”样例上固定事实抽取，测试 identity linking 的 pairwise precision/recall、状态序列正确率、Source Recoverability 100%（结构性）。再在 MemEye 的公开样本上用 Qwen3-VL-8B、top-K=3、temperature=0 对比 Fact-only、Fact+Occurrence、Full without agentic、Full。确认各阶段有稳定增益后，再加入 16-step Agentic Search，记录每个工具调用、引用 ID、耗费 token 与真实延迟。

最终对齐： 按官方 benchmark checkpoint 控制可见历史，避免未来信息泄漏；模型 4×A800 的硬件只是原文部署，不是最小复现必需；重做三次运行并使用一致 judge。最敏感超参： top-K、w_text/w_image、图像 crop 粒度、事实提取 prompt、最大 tool steps、image budget、演化最少支持事实数。先证伪什么？ 在 identity label 错误率高于某阈值时，Full 是否反而劣于 SRAG？若会，就说明这套系统对链接误差敏感，需要 confidence-aware split/merge 与可逆更新。官方未提供可核验代码仓库，复现属于独立实现，不应假装运行了原作者代码。

3.19 Migration Analysis：两条可写脚本的研究方案

Migration A — Agent Memory 的 Provenance-Aware Recovery & Poisoning Benchmark。 Original Problem： 跨会话多模态实体和状态来源丢失。Transferable Mechanism： Fact–Entity–Evolution typed hypergraph + source recoverability。New Research Question： 当攻击者仅能污染一轮工具输出或伪造一张图时，错误 identity merge 会如何沿记忆演化传播？系统能否追溯并撤销污染？Method Modification： 每个 fact 加 source_hash、trust_score、version；occurrence linking 增加置信阈值与可逆 merge log；evolution 每个状态存完整 evidence set 与 conflicting evidence；设计回滚工具 retract_source。Minimum Experiment： 以 MemEye 371 问题与自建 100 条三会话实体序列为基础，注入 0/1/2 条同名不同物、错误库存或错误图像描述；四种策略：Text RAG、SRAG、MHG-Mem-like、MHG+confidence+rollback；每条样例执行构建→注入→问答→撤销→再问答，3 seed；记录 source ID、引用链、错误传播范围。Model： Qwen3-VL-8B；Dataset： MemEye + 合成跨会话扰动集（明确合成）。Baseline： SRAG、Fact-only、MHG-no-rollback。Metric： QA EM、entity pairwise F1、poisoning success、source precision、rollback recovery rate、token cost。Expected Contribution： 由单一 QA 准确率扩展到“来源污染—错误传播—可恢复性”协议。Risk： 合成污染不代表真实攻击；LLM 判断链接可能不稳定。Collision Risk： 与 memory poisoning / RAG attribution 工作接近，需以跨会话 state-evolution 可逆性形成差异。

Migration B — Streaming Video Agent 的 Evidence-Preserving Temporal Memory。 Original Problem： 历史视频帧既要压缩，又要回答“物体何时变化、证据在哪一帧”。Transferable Mechanism： occurrence identity + aspect evolution + evidential frame links。New Research Question： 在固定 frame/token budget 下，保留事件状态与 source frame 的图结构，能否比 uniform sampling 或纯向量视频 RAG 更准确回答时序变化？Method Modification： 每 2 秒采样候选帧，轻量视觉跟踪形成 object track ID，按视觉变化阈值触发 fact/evolution 更新；每个状态绑定 frame timestamp、crop ID；query 时先检索 evolution，再仅解码证据帧，支持预算控制。Minimum Experiment： 从 NExT-QA 选 300 个含时序问答的视频（按官方划分，人工标 50 个关键证据时间戳）；每视频候选 32 帧、回答预算 B∈{4,8,16}；冻结 Qwen2.5-VL-7B 与 SigLIP2；比较 Uniform、CLIP top-B、video RAG、MHG-style evidence memory，重复 3 seed；用 torch.cuda.Event + wall-clock 计时，包含解码、检索、prefill、decode。Model： Qwen2.5-VL-7B。Dataset： NExT-QA + 50 个人工证据标注。Baseline： Uniform、CLIP、plain video RAG。Metric： QA accuracy、temporal evidence recall@B、frames、visual tokens、FLOPs estimate、end-to-end latency、GPU peak memory。Expected Contribution： quality–latency–provenance Pareto 与时间证据保真机制。Risk： 视觉跟踪错误与图构建耗时可能抵消推理节省；Collision Risk： 与 query-aware video frame pruning / temporal graph RAG 重叠，必须用来源可追溯和真实延迟构成独特贡献。

3.20 Agent 专用分析：Memory → Planning → Tool → Environment → Feedback → Learning

Architecture： User Query → Search Controller → typed Memory (F/U/Z) → resolve/inspect 工具 → 原始观察归档 → Evidence Assembly → QA model。与经典 Agent 的闭环相比，本文主要研究的是 Memory→Tool→Evidence→Answer；没有通过在线 RL 或梯度更新把 feedback 写回模型参数，所谓“Learning”主要是新会话到来时的结构化记忆更新。Agent State： 包含已保存事实、实体 referent、evolution、source archive、当前检索历史 hₖ、工具预算；trajectory 是一次搜索的工具调用序列。Long Horizon： 跨多 session 的状态更新被测试，但“持续运行几个月/上百万事件”及增量索引成本没有充分量化。Failure Propagation： 一次误 merge 可能同时污染价格、位置、库存等多个 evolution；随后 resolve_evolution 会反复检索错误状态，甚至以合法 source ID 包装错误回答。Multi-Agent 延伸： 如果多个 Agent 并发写同一 referent，必须引入写入者身份、版本冲突、时间戳、可回滚日志与一致性规则；论文未解决分布式一致性。

3.21 Attack / Verification Lens

Attack： 制作两张高度相似却不同款的商品图，诱导 UPDATE 合并；或让网页工具返回带伪造时间戳的旧库存。Black-box probe： 只观察最终回答与引用来源，不看内部图，检测是否出现“不同会话的属性拼接”。Robustness： 同义实体名、遮挡 crop、图像噪声、乱序 session、重复/冲突事实。Recovery： 删除污染来源后，要求旧状态不再被引用并保留未污染历史；评估撤销正确率。Efficiency stress： 随 session 数 10→100→1000、图片数 100→1000→10000，测构建耗时、检索延迟、总 token 与峰值存储。新 Metric： Evidence-Correct Answer Rate (ECAR) = 正确回答且引用包含有效支持证据的比例；与普通 Judge 并列报告。上述攻击与指标是本报告提出的验证路线，不是原论文结果。

3.22 如果只记住 MHG-Mem（九句话）

  1. 多模态长期记忆不能只压成文字，也不能只把图片放进向量库。
  2. 真正难的是跨会话同一实体、状态随时间变化、以及每个状态的原始证据三者同时保留。
  3. MHG-Mem 使用 Fact、Entity、Evolution 三类节点与三类类型化超边。
  4. Occurrence hyperedge 将不同观察中的同一实体关联起来，是重要增益来源。
  5. EvolutionNode 记录 (value,fact_id) 序列，Evidential hyperedge 让状态能回溯到原图。
  6. Agentic Search 根据问题选择事实、实体、演化、图片与原始来源工具。
  7. 三 backbone 的平均 Judge 领先 8.20、9.89、9.98 个百分点，但约耗费两倍 token。
  8. Source Recoverability 证明的是来源可找回，不是事实必然正确；错误身份合并仍是重大风险。
  9. 最值得迁移的是 Agent memory poisoning/recovery benchmark 与证据保留的视频时序记忆。

04 · Cross-Paper Synthesis：两篇共同说明什么？

共同趋势：模型性能越来越依赖“历史的分布与证据结构”，而非仅当前一步的局部打分。 EPIC 告诉我们，当前 token 看似合理不代表到达该 token 的 prefix 分布仍可信；MHG-Mem 告诉我们，当前检索的图片看似相关不代表它属于同一个实体或正确时间版本。二者都反对把历史压缩成一个无上下文的标量：EPIC 不满足于单 token ratio 或整句统一 ratio，MHG-Mem 不满足于单次 embedding similarity 或最新摘要。

机制互补： EPIC 提供“策略分布偏离”的数学约束，MHG-Mem 提供“记忆事实与证据的谱系”的结构约束。把二者放在 Agent 中，一个解决训练更新时行为策略与当前策略的偏差，另一个解决检索行动所见的历史事实是否正确。可以构建 state=(query, retrieved-evidence, tool-history)、action=memory/tool call、reward=correct answer with valid citation − tool cost 的任务；对 action prefix 做 trust-region 校准，对 evidence source 做一致性校验。

假设冲突： EPIC 的精确 performance difference 要求可定义行为策略 μ 对动作轨迹的概率、共同支持集和固定的环境动态；MHG-Mem 的搜索动作会改变后续检索历史，而外部记忆可能在两次调用之间被其他 Agent 更新。若 memory store 不固定，环境转移核 P(s'|s,a) 也会变，直接照搬 EPIC 的保证不成立。研究必须显式记录 memory snapshot/version，将 source update 纳入状态或做环境漂移校正。

可组合的实验范式： 从 EPIC 借用固定 rollout buffer、prefix log-ratio、clip fraction by position、policy lag sweep；从 MHG-Mem 借用 Fact-only→Identity→Evolution→Evidence 的模块递增消融、source inspection 去除实验、token cost 和工具预算扫描。联合报告至少应有：任务成功率、证据正确率、工具调用数、总 token、TTFT/TPOT、wall-clock、prefix drift、source-recovery rate。只报单一准确率或 FLOPs 无法证明“更智能且更高效”。

跨方向位置： EPIC 更适合做 RL baseline；MHG-Mem 更适合做 Agent memory baseline、可审计检索系统和新的 benchmark。视频加速方面，最直接的组合是“事件驱动的 evidence frame memory + 预算约束的选择策略”，而不是把视频帧当纯文本 token 硬套。推理加速方面，源证据复用可借鉴 prefix cache/feature cache，但 Agent semantic memory ≠ Transformer KV cache：前者持久且语义可审计，后者是特定模型、特定位置编码与上下文的运行时状态，不可随意跨模型复用。

06 · Collision / Overlap：最强交汇与风险

Strongest Collision：Action-Prefix Trust Region × Provenance-Aware Agent Memory。 两篇在“历史不应该被无条件当作正确当前上下文”这一点相遇：EPIC 用累计概率比率衡量历史生成分布偏离，MHG-Mem 用 source lineage 衡量历史事实可追溯性。潜在统一框架可以同时给每个 Agent action 附加 (behavior logp, memory snapshot ID, source provenance)，在训练时用 prefix clipping，在执行时用 evidence validation。这是一条由本报告提出的跨论文研究交汇，不是作者之间已公开的直接冲突或已验证的统一方法。

现有工作重叠风险： EPIC 与 PPO/TRPO/sequence-level IS、CTPO/RIPO 的差别必须落实到精确 KL 几何、前缀裁剪和 ST 设计；MHG-Mem 与 HyperMem/M2A/UniversalRAG 的差别必须落实到“多模态实体身份 + 演化 + 来源 + 查询工具”的联合消融。若新工作只把两个已有模块串起来，容易被认为是 engineering assembly；必须有一个新的可检验机制或 benchmark，例如“在固定成本下，prefix trust region 是否显著减少来源污染后的错误放大”。

不应强行形成 Collision 的地方： EPIC 的 KL 是策略分布上的信息几何，不等于 MHG-Mem 的视觉 cosine；MHG-Mem 的 source recoverability 不是因果 attribution；prefix KV cache 的节省也不是 MHG-Mem 的 token cost 减少。术语相似不能替代严格问题定义。要证明新方法优于独立使用两篇方法，需要 2×2 factorial ablation：无 prefix/无 provenance、仅 prefix、仅 provenance、两者都用，并在相同模型、相同工具预算、相同数据和多 seed 下比较。
