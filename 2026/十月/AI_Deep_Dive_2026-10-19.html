Learning Self-Orchestration in Decentralized Agent Swarms

Market-based Post-Training · 2026-10-15 · arXiv:2610.22322

1. 基本信息与一句话定位

Title：Learning Self-Orchestration in Decentralized Agent Swarms。Authors：Guowei Xu、Zhenting Qi（共同一作）、Amani Kiruga、Himabindu Lakkaraju、Yilun Du；Affiliation：Harvard University。Date：2026-10-15，arXiv:2610.22322v1；Venue：尚未确认正式会议接收，当前为预印本。Paper：arXiv 正文 / PDF；Project：项目主页；Code：Embodied-Minds-Lab/MPT，仓库提供训练、评测脚本和权重链接。主题：Multi-Agent RL、动态协作、credit assignment。

一句话定位：把“谁应该在当前状态执行动作”从固定编排规则变成可学习策略，并让这个选择同时决定延迟奖励怎样向之前的参与者传递。

2. 人话版（先抓住问题）

想象三个 Minecraft 智能体：Logger 只会采木头，Miner 只会挖矿，Smith 只会合成。做铁镐需要三者接力，但固定轮流执行会在需要挖矿时浪费采木者的回合。让一个中央规划器挑人也不一定可靠：它可能不清楚各专家当前真正擅长什么。MPT 让每个专家根据当前状态出价，最高价者获得执行权；出价又是承诺把自己后续收益的一部分返还给前一位行动者。这样，末尾做成铁镐的收益可以沿动作链向前传递。更关键的是，作者通过“恢复同一状态、换个人行动、比较后续结果”的反事实 rollout 教智能体什么时候应该争取执行权。实验显示，在保留相同已训练动作策略时，竞价编排在铁镐任务上获得 41.5 平均奖励，而最强的其他编排策略 GoA 为 25.4。它的价值不只是让 Agent 分工，而是把分工决策、动作学习和信用分配耦合为一个可训练闭环。

3. Background & Research Gap：固定拓扑为什么不够

传统多 Agent 框架通常先写死一个流程：Planner 分配任务、Coder 写代码、Reviewer 检查，或者 Round-robin 每人轮一次。这种做法适合角色边界稳定、任务阶段可预测的场景；但在长轨迹中，最需要的能力会随状态切换。Minecraft 起步时应砍木头，制作木镐后应挖石头，收集材料后又应交给合成者。即便拥有正确的专家，如果调度错误，也会把稀缺的交互预算耗在无效动作上。

更深的 gap 是训练与调度彼此影响：某个 Agent 不被选中，就没有该状态下的训练样本；它的能力不提高，调度器又更不愿选它。这形成“参与机会—经验分布—能力—下一次参与机会”的反馈环。单体 REINFORCE 把所有动作交给一个模型，难以发挥专家化；静态专家切换不能随学习进展变化；只在推理时优化图结构的方法，没有直接通过参数更新改变专家行动能力。MPT 针对的不是一般意义的消息通信，而是同一环境控制权的竞争性分配。

4. Core Insight：出价同时是一种信用传输契约

作者的关键观察是：Agent 对“我现在能否推进任务”的估计，可以作为竞价信号；而竞价又能承担一个不同但相关的功能——把下游回报向上游转移。假设 Miner 要挖铁矿，但前面 Logger 先造出了木镐，Miner 之后的成功并非完全来自自己。若 Miner 出价较高，它就让出较多后续价值给上一位行动者。这样不必显式训练一个中心化 value critic，也能把部分延迟奖励送回早期关键动作。

这里有两个不同性质的论据。机制层面：回传公式保证了后续奖励按出价乘积衰减传递，这是明确的数学定义。经验层面：学出的竞价比例随任务阶段改变，并在消融中优于随机 credit，说明这种学习信号在所测环境有用。但“出价代表真实因果贡献”不是定理；Agent 可能为了赢得回合报高价，也可能因为高价会让渡奖励而策略性压价。MPT 需要反事实比较约束这种博弈。

5. Method Deep Dive：一条轨迹如何被训练

Input → 多个角色受限的 Agent、当前环境状态、可验证 reward → Step 1 所有 Agent 生成 bid → Step 2 最高 bid 者行动 → Step 3 环境更新并产生奖励 → Step 4 逆序传播 credit → Step 5 对获胜者 action 做 REINFORCE → Step 6 在争议回合做 counterfactual rollout → Step 7 用偏好损失训练 bid → Output 更好的专家动作策略与动态执行权分配。

Step 1：角色限制与局部竞价。 每个 Agent 有独立参数与受限动作集合，例如 Logger 只能发出采集类指令。每轮所有 Agent 看状态并给出 bid，最高者执行；相同出价随机打破平局，全零则跳过。这是无中央“挑选者”的分布式仲裁，但并非无协调成本：每轮要让多个模型推理竞价。

Step 2：执行和记录。 只允许获胜 Agent 发出真实环境动作。训练日志必须同时保存所有人的 bid、胜者身份、获胜动作、奖励、完整环境快照及可恢复的 Agent 状态。否则后续反事实实验无法公平复原。

Step 3：信用回传。 从 episode 最后一步向前计算累积价值 v；当前胜者只保留其中的 (1−bid) 部分，其余作为对上一个行动者的价值转移。最终每个 Agent 仅对自己实际执行的 action token 更新参数，而不是拿其他人的文本做监督。每个 Agent 用自己样本的平均 credit 作 baseline 减少梯度方差。

Step 4：竞价学习。 在第二名也有非零 bid 的 contested turn，恢复完全相同的环境和智能体状态。对原胜者重新采样竞价，最多三次，直到让第二名获胜；沿新的执行分支跑到结束，比较两个分支从分叉点以后的真实回报。较好分支的竞价文本是 preferred response，较差的是 rejected response；平局丢弃。训练时四次 action update 配一次 bid preference update。注意“换人执行”不是简单把当前动作替换掉，后续所有状态、动作和奖励都可能随之变化。

Step 5：共同演化。 竞价和动作更新同一个 Agent 内的参数，因此优化 action 可能改变竞价生成分布，反过来也一样。此处没有证明一定收敛到稳定分工；方法依赖多轮训练的经验稳定性。

6. 核心公式与数学直觉

价值回传（论文式 1）：

v_t = r̂_t + b_(t+1) · v_(t+1); c_t = (1 − b_t) · v_t; v_(T+1)=0

r̂_t 是第 t 轮环境奖励（终局奖励并入最后一步），b_t 是该轮胜者竞价，v_t 是累计价值，c_t 是分给该轮胜者的训练 credit。第 t+k 步的奖励影响第 t 步的权重是中间竞价的连乘；因此 bid 越小，远距离信用越容易消失。第一个行动者向更早时刻转出的份额被丢弃，这不是严格的全回报守恒机制。

动作目标（论文式 2）：E[(c_t − mean_credit_i) · ∇ log π_i(action_t | history_i,t)]。正 advantage 提高已执行动作概率，负 advantage 降低；这是 REINFORCE，不是 PPO 或 GRPO，论文该式没有显式 KL penalty。baseline 是每个 Agent 在 batch 中的平均 credit，能降低方差但无法解决所有稀疏奖励问题。

竞价目标（论文式 3）：L_bid = −log σ(log π_i(y_win|h) − log π_i(y_lose|h))。它增加更好竞价文本相对较差文本的对数似然差，属于 Bradley–Terry 型 pairwise preference learning。和标准 DPO 的常见写法相比，这里没有显式 reference-policy 比值项；不能直接把它等同于带参考模型约束的 DPO。它优化的是“让哪个竞价结果更可能出现”，而非直接回归一个数值型最佳 bid。

超参数敏感性：bid 允许的取值范围和离散档位会影响探索；反事实采样最多三次会造成可替代竞价样本的选择偏差；action/bid 的 4:1 更新比决定两种能力共同演化速度。把高 bid 直接解释为高置信度并不严谨，因为它还包含让渡收益的经济代价。

7. Toy Example：三步把一份奖励分回去

假设三轮分别是 Logger、Miner、Smith，环境奖励为 0、0、10，获胜 bid 依次为 0.2、0.5、0.8。由后往前：v3=10, c3=(1−0.8)×10=2；v2=0+0.8×10=8, c2=(1−0.5)×8=4；v1=0+0.5×8=4, c1=(1−0.2)×4=3.2。三人的 credit 合计 9.2，剩余 0.8 是首轮向不存在的上一位参与者让出的部分。这揭示一个容易忽略的事实：MPT credit 不是 Shapley value，也不等于把总 reward 完全分完。

若在第二轮将 Miner 的 bid 降低，使 Smith 提前行动，后续只得 3 分，那么该替代竞价是 loser；如果替代分支得 15 分，原竞价反而是 loser。训练不是奖励“永远出高价”，而是奖励在当前状态能改善未来结果的执行权分配。

10. Metrics 教学式解释

Mean Episode Reward：环境每个 episode 的累计分数，越高越好；Minecraft 上限 140，但高奖励不等于真的做出铁镐——中间里程碑也能得分，必须配合终局成功率。Deep Research Accuracy：参考答案经 LLM judge 判定正确的比例，越高越好；可能受 judge 偏差和答案格式影响。Robot Navigation Reward：距离缩短与成功停靠奖励之和，可出现超过 1 的值，不是 0–1 成功率。pass@3：同一测试 seed 进行三次尝试，至少一次达到指定里程碑的比例；对随机采样有利，不能替代单次成功率。Training FLOPs：训练总计算量的估计，用来比较训练效率，但不等于真实 GPU-hours。SE：跨测试实例的均值标准误，不是单次运行的标准差，样本仅 32/88/50 时仍有显著不确定性。

11. Results Deep Dive：数字、差异与证据边界

  1. Held-out Crafting：41.5±5.9 vs 20.3±4.1，绝对高 21.2，约 2.04 倍。支持 MPT 在此环境整体更强；但不能单凭该实验归因于竞价，因为模型专家化也不同。
  2. Held-out Navigation：1.23±0.18 vs 0.52±0.14，高 0.71，约 2.37 倍。说明机制跨到视觉导航；指标是复合奖励，不能误写成导航成功率翻倍。
  3. Held-out Deep Research：21.0±4.1% vs 9.0±2.1%，高 12.0 个百分点。这里 reward 来自 LLM judge，说明跨工具有效，但也可能受判分器误差影响。
  4. 固定动作权重：MPT 41.5 vs GoA 25.4，高 16.1，相对 +63.4%，是最能隔离调度机制的结果；仍未对齐不同编排的 token/latency 成本。
  5. 双模块协同：41.5 vs 27.2（只训动作）vs 21.5（只训 bid）vs 15.4（都未训）。两个模块都有贡献；从四格结果看存在交互增益，但不应声称严格因果分解。
  6. 随机信用消融：约 42 vs 31，差约 11；Round-robin 约 15，三者取自 Figure 7 的约 5×10^18 FLOPs 位置，是图上近似读数，非精确表格。
  7. 参与比例：第 120 决策 Logger 约 80%→45%，Miner 约 10%→40%，支持角色切换随训练改变；但不是证明所有状态下竞价最优。
  8. 推理时扩群：木镐 pass@3 约 78%→97%，石镐 69%→94%，熔炉 66%→91%（3→12 Agent）。扩群是复制已训练 Agent，不是训练出 12 种新技能；多副本可提高采样多样性和冗余。
  9. p=0.9 dropout：12-Agent 约 33 分 vs 3-Agent 约 19 分。极端掉线下更稳健，但更多 Agent 也意味着更高竞价开销。

Strongest result：固定 action 权重仍有 +63.4% 编排收益。Weakest evidence：研究任务 accuracy 绝对仅 21%，且受 LLM judge 影响；真正复杂开放网页交互的泛化尚未证明。Trade-off：每轮 N 个 Agent 竞价 + 反事实 rollout 换取调度和学习收益。

13. Ablation / Mechanistic Analysis

去掉竞价改轮流：约 42→15，说明执行权分配与相应学习链很关键，但该 ablation 同时改变探索轨迹。保留竞价、随机化 credit：约 42→31，更干净地说明学得竞价不仅用于调度，还包含可利用的回报传输信息。冻结 action、切换 bid checkpoint：27.2→41.5，验证 bid policy 本身有价值。冻结 bid、切换 action checkpoint：21.5→41.5，验证专家能力不可缺。角色参与可视化说明分工演化，但没有对竞价信号做因果 intervention 的单独验证；反事实 rollout 才是训练时的干预，而非可视化。

14. Claim vs Evidence

Authors Claim：Agent 群可以自组织、共同学会何时行动，并在任务迁移、人数增加和掉线时保持收益。Experiments Actually Show：在三种受限角色与可验证环境、特定模型规模和训练预算下，MPT 对单体更好；在 Minecraft 中固定 action 权重后竞价优于三种替代编排；对特定新任务与副本扩群有效。What Is Not Yet Proven：任意开放任务的自组织、竞价的最优因果贡献分配、异构模型成本最优、真实不可回滚环境的可训练性，以及随 Agent 数量持续增长的计算效率。

15. Contribution：新意在哪里

Contribution 1 [New Mechanism]：把执行权分配与下游奖励返还绑定到同一个 bid，形成训练闭环。借用了既有经济竞价思想，真正新增的是与参数更新联合训练的具体系统。

Contribution 2 [New Objective / Training Protocol]：反事实替代胜者 + pairwise bid preference update；偏好损失本身不是全新数学形式，但将其用于“竞价是否应让位”有机制价值。

Contribution 3 [New Empirical Finding]：固定 action 权重仍有调度收益；复制人数和 Agent dropout 的鲁棒性实验提供可借用的评测范式。不是新 benchmark，也没有新 metric 的独立定义。

16. Limitation & Failure Modes

Authors' Limitation：依赖外部可靠 reward；bid 学习需要从同一状态重放反事实，现实不可逆交互不适用；未训练单体超过 10B 的更大 Agent 群。Additional Limitation：所有专家有硬性动作空间分割，这降低调度难度但可能高估角色专门化收益；大量竞价会增加推理 token 和墙钟延迟；反事实环境复原不完全时因果对比失效；终局 reward 稀疏时有大量平局被丢弃；多副本扩群可能仅是多次采样的收益；研究任务 judge 可被答案模板或错误引用误导；高 bid 引起的信用传递与实际贡献并非天然一致。

19. Migration A：Agent 记忆与跨会话归因

Original Problem：长期 Agent 的前一段 memory / handoff 对后续成功有贡献，却得不到明确训练信号。Transferable Mechanism：bid 作为“愿意承担执行权 + 返还上游价值”的信号；对同状态替代方案做反事实。New Research Question：一条记忆是否真正提高后续任务成功，而不是仅被检索到？Method Modification：把 Agent bid 改为 memory/skill 的 relevance bid；每次选择记忆时记录 provenance，后续成功奖励沿使用图回传；在可回放沙箱中删除/替换该记忆比较结局。Minimum Experiment：固定 200 条多会话代码修复轨迹，每条有 2–5 个候选记忆；三组 no-memory / embedding-top1 / bid-credit；对 50 条做“删除记忆后重跑”，设置 seed=42、temperature=0，最大 12 次工具调用，输出 success, calls, token_cost, causal_delta CSV；先做不训练的排序器，后做小 LoRA preference update。Model：Qwen3-8B-Instruct 或同级开源模型。Dataset：SWE-bench Lite 任务子集加人工构造跨会话记忆。Baseline：BM25、向量 top-k、固定最近记忆。Metric：任务成功率、干预后成功率差、每次成功 token、memory precision。Expected Contribution：因果使用度而非相似度驱动的记忆学习。Risk：回放非确定性、训练数据泄漏。Collision Risk：与既有 Agent memory attribution / causal retrieval 工作可能重合，投稿前必须检索。

20. Migration B：无环境回滚的信用近似

Original Problem：MPT 依赖昂贵且可回滚的反事实 rollout。Transferable Mechanism：比较“当前 Agent 赢”和“次优 Agent 赢”的后续价值。New Research Question：能否用低成本 world model 或 learned verifier 近似换人执行的结果，并保持调度收益？Method Modification：训练小型 outcome predictor 输入 (state, winner, action, runner-up) 预测未来 reward 差，仅在高不确定性时执行真实 counterfactual rollout。Minimum Experiment：在 Minecraft 采 5,000 个 contested states，每个采 2 条分支，按 world seed 80/20 分割；拟合轻量 reward-delta regressor；对照 full-counterfactual、随机 20% counterfactual、uncertainty-top20% counterfactual；固定总训练 FLOPs，画 regret 与真实分支数曲线。Model：原 MPT 3×Qwen3-VL-4B，预测器用小 MLP 或 0.5B LM。Dataset：MineStudio 轨迹和验证 seeds。Baseline：原 MPT、无 bid update、均匀抽样。Metric：reward、pairwise sign accuracy、counterfactual GPU-seconds、FLOPs。Expected Contribution：可部署的低成本近似因果竞价训练。Risk：预测器偏差被 Agent 利用、分布漂移。Collision Risk：与 model-based MARL、offline counterfactual evaluation 直接相关。

21. RL / Agent 专项与 Attack / Verification Lens

RL Formulation：state 为环境观察与共享历史；action 包括 bid 文本与获胜者的实际工具/环境动作；policy 是各自独立的 LLM；trajectory 是单个环境的多 Agent 接力；reward 在 crafting/nav 为过程奖励、research 为终局 judge；advantage 是 local_credit − per-agent mean；objective 为 REINFORCE 与 bid preference 交替；未显式使用 PPO clip 或 KL；credit assignment 是 bid 加权逆向回传。Reward Hacking：Agent 可能为了拿局部 credit 偏好易得的技术树中间分数，而非真正完成铁镐；研究任务可能学会迎合 judge。Training Efficiency：训练 FLOPs 对齐，但反事实分支、每轮全员竞价和多模型服务会造成明显 wall-clock 开销，论文没有给出跨硬件的统一 GPU-hours。

Agent Architecture：Observation → all bids → winner → action → environment → reward → credit → action/bid update；state 里包含近期历史、工具输出与当前资源，角色分工由动作约束确定。Long-horizon：Minecraft 120 回合、其他最多 64 回合，尚不足以说明无限会话下稳定。Failure Propagation：一次错误竞价会让错误 Agent 操作环境，污染后续 state；如果它仍得到正向 credit，错误策略可能被强化。Attack Lens：恶意 Agent 可以操纵 bid 或伪造 tool feedback；用固定 checkpoint 注入竞价扰动，测试成功率、错误 credit 占比、后续参与集中度，构成黑盒 probe 和鲁棒性 benchmark。

HyCo: Hybrid Drafting for Cost-Efficient Mobile–Cloud Speculative Decoding

Split MTP Head + One-pass SLM · 2026-10-15 · arXiv:2610.21436

1. 基本信息与一句话定位

Title：HyCo: Hybrid Drafting for Cost-Efficient Mobile-Cloud Speculative Decoding。Authors：Hanbin Bae、Heejin Choi、Joohyung Lee、Byoung Jin Choi、Sangjun Park、Hoon-Young Cho；Affiliation：Samsung Research, Seoul。Date：2026-10-15，arXiv:2610.21436v1；Status：ACL Rolling Review（2026 年 10 月轮次）在审，不能写成 ACL 已接收。Paper：HTML 全文 / PDF；Project / Code：正文未提供可核验的官方公开实现链接，状态记为 Not Reported / Not Verified，不推测已开源。主题：Speculative Decoding、Mobile NPU、Device–Cloud Split Inference、MTP。

一句话定位：把大模型原生 MTP draft head 搬到手机，与一次小模型前向组合出宽而深的草稿树，从而减少云端 GPU 工作量，同时控制移动端串行草稿开销。

2. 人话版（250–400 字）

推测解码像“先让小模型猜接下来的词，再让大模型一口气批改”。传统云端方案把大模型和它自带的 MTP 草稿头都留在服务器；传统端云方案让手机上的小模型负责猜词，但想生成一棵很深的候选树，就要在手机 NPU 上反复执行小模型，结果手机慢、网络来回也慢。HyCo 的思路是重新分工：服务器把大模型刚算出的隐藏状态、输入嵌入和少量 KV 信息发给手机，手机运行这个大模型的轻量 MTP head，快速构造一条四层主干；再让手机小模型只执行一次，给主干各节点补候选分支。服务器一次验证整棵树。实验在 Galaxy S26 Ultra + RTX PRO 6000、LTE/5G 下进行：相对云端 MTP 自推测，服务器 GPU 每输出 token 的时间在 Spec-Bench 降低 38.6%，手机端用户交付速度为 35.0 tokens/s。但默认的 ε 接受规则是有损的，作者明确承认它会改变原大模型采样分布。最值得学的是谁承担串行深度、谁提供并行宽度的系统分工，而不是单看 38.6%。

3. Background & Research Gap

自回归 LLM 每生成一个 token 通常都需要大模型执行一次 decode。Speculative Decoding 先用便宜的 drafter 产生多个候选，再让昂贵 verifier 并行检查，目的是用一次大模型调用提交多个 token。两条常见路线：Cloud+MTP 直接用大模型自带多 token 预测头生成一条链，省去外部小模型但仍在服务器串行执行 head；SpecEdge-style 把小模型放手机上，通过多轮小模型推理构造树，云端只负责验证，但树越深移动端越慢。

具体例子：用户让手机助手生成长段文字。若小模型为了四层草稿树要连续跑四次 NPU，哪怕服务器每轮可以多接受几个词，手机仍可能成为瓶颈。反过来，如果服务器承担四次 MTP head 推理，就省不了这部分 GPU 时间。HyCo 试图将“深度”与“分支宽度”拆开：MTP head 用少量状态串行延长主链，小模型用一次批处理给多个节点同时提供分支。它还必须解决跨设备 state handoff、移动端整数计算图、词表大小和 KV 窗口问题。

4. Core Insight：不同模型擅长不同草稿结构

MTP head 已经受过与目标大模型相关的训练，对主链的下一个 token 往往更可信，适合提供 depth；独立 SLM 可以一次在多个前缀位置上产生 top-k 候选，适合提供 width。关键不是把两种预测简单投票，而是把不同计算依赖映射到不同硬件：服务器只做昂贵的树验证；手机运行小 MTP head 的顺序步骤，以及一次可并行的小模型前向。

这个洞察来自作者对每轮耗时和 MAT 的测量，是工程机制发现，而不是复杂度下界。移动端获得服务器隐藏状态的代价不为零：每轮需传 5.6KB 固定信息和每个已提交 token 约 6.1KB 的 KV，首次长上下文最多额外约 6.3MB。作者在实验中证明此分工能降低服务器 GPU-busy 时间，但没有证明多客户端高负载吞吐必然提升，也没有证明在弱网络上总能更快。

5. Method Deep Dive：一轮端云协作发生什么

Input → 服务器已提交前缀和目标模型状态 → Step 1 传 MTP 所需状态到手机 → Step 2 手机 MTP head 生成深度 K=4 的链与候补 sibling → Step 3 手机 SLM 单次批量前向补树枝 → Step 4 对候选节点评分并裁剪为 B=32 → Step 5 服务器一次树注意力验证 → Step 6 exact 或 ε-rule 选择最长合法路径 → Step 7 提交路径、更新双方 KV → Output 多个已确认 token 与下一轮 handoff。

Step 1：服务器状态切片。 服务器不把完整大模型复制给手机，只把 MTP head 需要的输入嵌入 e(x_{t+1})、上一 token 的 hidden state h_t，以及两层的 KV 条目发送过去。手机维护 1,024 token 环形窗口；服务器仍处理完整 prompt。这样手机无须执行大模型的前面所有层，但要付出网络带宽和对中间激活的访问权限。

Step 2：MTP 主链。 量化后的原生 MTP head 生成连续四个 top-1 候选，在前两层还保留第二名 token 作为 sibling。深度从 head 的自回归预测得到，而非要求独立 SLM 每层都跑一次。链节点的 score 按 ln(0.66) 累加，0.66 来自验证集观察到的逐层链接受率，故深层节点分数逐步降低。

Step 3：SLM 横向扩展。 让 Gemma 4 E2B 的手机 drafter 对 root 与已种下的节点一次并行前向，针对每个位置提出 top-32 候选。候选分数结合其 log probability 和深度惩罚。只保留全树分数最高的 32 个节点并保证祖先闭包，避免出现“保留孙节点却丢失父节点”的非法树。手机发送 token ID 与 parent index，树本身每轮约 2.2KB。

Step 4：服务器验证。 在 33 行（root + 32 节点）树 attention mask 下，一次目标模型前向计算各候选位置的分布。Exact 模式只允许匹配目标模型采样的边；默认 ε 模式还允许目标采样分布中概率不低于 ε 的候选。服务器选择可接受的最深路径，优先更多真正采样命中的边，再用概率乘积打破平局；路径末尾加一个 bonus token。

Step 5：缓存维护与下一轮。 仅把被接受路径对应的 KV 位置提交到持久前缀，丢弃其他树枝的临时 KV。手机也要搬移 SLM KV 行并维护位置编码，否则下轮草稿可能基于错误前缀。Failure mode：任何一端对树父子索引、RoPE 绝对位置、采样规则或 bonus token 的理解不一致，都可能导致 silent mismatch，最终生成错误文本。

6. 核心公式与数学直觉

成本目标：g = (GPU prefill time + Σ GPU verification time) / # output tokens。越低越好。它不是 TPOT，也不是用户看到的 wall-clock latency；网络、手机等待与排队可能完全不计入 g。若一次验证耗时 25ms、平均提交 MAT=4，纯 decode 部分约 6.25ms/token；如果提高 MAT 却让手机每轮多耗 30ms，用户未必更快。

节点排序：MTP 链深度 d 的分数 s_chain(d)=d·ln λ，λ=0.66；SLM 分支节点 s(child)=s(parent)+ln q(child|parent)+ln λ。q 是手机小模型概率。对数求和相当于比较路径概率乘积并惩罚深度；λ 越小越偏向浅层分支，越大越偏向深链。λ 是经验校准值，不是理论最优常数。

接受规则：ok(c)= [c = sampled_token(parent)] OR [p̃(c|parent) ≥ ε]。p̃ 是服务器经过 temperature=1、top-k=64、top-p=0.95 后的实际采样分布，不是 raw softmax。默认 ε=0.005；ε=1 恢复 exact。ε 下降意味着更多候选能被提交、MAT 提高，但也更可能偏离 verifier 原本的采样分布；即便候选在目标分布支持集内，也不意味着保持概率权重不变。

量化校准 KL：作者用 BF16 MTP head 作 teacher，最小化量化 head 的 token 分布与 teacher 的 KL 差异，100 步 QAT。KL 小代表两分布接近，却不能保证逐 token top-1 完全相同；实际 top-1 agreement 从 87.4% 提高到 91.0%。这是一种训练辅助，不等于重新训练整套大模型。Strongest baseline objective 差异：Cloud+MTP 的目标是服务器内原生 head 自推测；HyCo 改变执行位置和树结构，而非提出一个全新的语言建模 loss。

7. Toy Example：从一条主链长出树

设服务器当前前缀为“今天的天气”，MTP head 猜出四个 token：很 → 好 → ， → 适合；第二名在第一层是“不错”，第二层是“晴朗”。手机 SLM 一次并行前向给 root、“很”、“好”等节点增加候选，例如 root 下还有“晴”、 “有”，在“很”之后有“热”。假设经 score 排序保留 32 个节点。服务器并行计算各节点概率，第一层真正抽到“很”，第二层真正抽到“热”，第三层没有匹配候选。Exact 模式只提交“很、热”加一个 bonus token。

如果第三层某候选“。”虽不是实际抽样 token，但目标分布概率为 0.008，那么 ε=0.005 模式允许它成为路径的一部分，可能一次提交更多 token。问题是：这改变了输出概率；不能因为目标模型也觉得“。”有 0.8% 概率，就认为默认系统仍是无损。再设四次 SLM 串行前向共 60ms，单次并行前向只需 18ms；如果手机 MTP head 耗 20ms，则混合方案移动端 38ms，小于纯 SLM 的 60ms。这些玩具耗时只是解释机制的假设数，不是论文测量。

9. Experiment Setup Deep Dive

Verifier：Gemma 4 26B-A4B，4-bit AWQ，在一张 RTX PRO 6000 云 GPU 上运行；采样 temperature 1、top-k 64、top-p 0.95。Device：Galaxy S26 Ultra，SM8850、Hexagon Tensor Processor v81，真实商用 LTE/5G；一台手机连接一台服务器，非多用户负载。Drafters：服务器原生 MTP head 经 W4 QAT 后移到手机；手机 SLM 为 Gemma 4 E2B QAT checkpoint，经整数 graph surgery 转换。量化与结构：MTP head 100 步 KL QAT，两个 drafter 使用 16-bit fixed-point activations；输出 keep set 86,089 tokens；手机窗口 1,024；K=4、D=2、B=32、λ=0.66、ε=0.005。

训练/验证数据：UltraChat 200k 训练 split 中 60 prompts 用于 QAT/校准，另有 UC-val 60 prompts 用于超参筛选；词频来自 UC-tr 20,000 对话。正式测评：Spec-Bench 全部 480 问题（含 MT-Bench 两轮），最大输出 1,024 token；质量评估非 QA 的首轮完整可评分样本 398 或三次重复共同的 396 条。长文本用 ∞Bench Sum 前 50 篇英文小说，截断 32K token，最大输出 1,200。判分：GPT-5.4 作为问题条件 judge，另用 GSM8K、RAG、CNN/DailyMail、WMT14、HELMET 指标交叉检查。不确定性：HyCo 与 SpecEdge-ε 在 SB 各跑三次；大多数其他配置只跑一次，CI 用问题级 bootstrap，不能把单次 judge 波动当成已控制。

RQ1：混合树在相同接受规则下是否减少云端成本并提升手机交付？RQ2：exact 模式是否仍有收益？RQ3：多跑一次 SLM、预先草稿或把 head 留服务器是否值得？RQ4：性能提升是否伴随可检测的质量下降？RQ5：长上下文的 prefill、首次 handoff 和手机内存是否成为新瓶颈？

10. Metrics 教学式解释

GPU time/output token（g）：服务器忙碌 GPU 时间除以生成 token，越低越好；包含 prefill，但不代表用户等待。MAT（mean accepted tokens per verification round）：每轮平均提交 token，越高越好；过高可能来自有损接受。Delivery speed（tokens/s）：手机从请求开始到最后 token 的总体交付速率，越高越好；与纯 decode tokens/s 不同。TTFT：请求开始到第一个 token 到达的时间，越低越好；首轮大上下文 prefill 会让它升高。ROUGE-L-Sum：与参考摘要最长公共子序列相关的重合度，越高通常越好，但容易奖励字面重合而非事实性。HELMET F1 / precision / recall：基于参考要点的覆盖与准确程度，越高越好，但对小说中未标注信息无法全面验证。Judge score：LLM 给出的 0–100 主观质量分；置信区间包含 0 不等于严格等价。Server throughput / GPU memory / energy：本论文未给多用户 loaded throughput、整体 GPU memory 曲线与能耗结果，不能从 g 推断。

11. Results Deep Dive：最重要的 10 个证据点

  1. Spec-Bench server saving：HyCo −38.6±0.2% vs Cloud+MTP 0%，对比基准 g=7.81ms/token；大约对应 4.80ms/token（按百分比计算），但此数字混有 ε 放宽的贡献。
  2. 同 ε 对比：HyCo −38.6% vs SpecEdge-ε −29.6%，多节省 9.0 个百分点；这是比直接对 Cloud+MTP 更干净的结构对比。
  3. 手机交付：35.0±0.7 vs 18.9±0.1 tokens/s，比 SpecEdge-ε 约 1.85×；同时 MAT 4.71 vs 4.13，且 SLM passes 为 1 vs 4。
  4. 32K 总结：HyCo −29.2% vs SpecEdge-ε −15.7%，多节省 13.5 个百分点；手机 21.0 vs 12.4 tokens/s，约 1.69×。此任务含长 prefill，因此 server saving 比短输入更难提高。
  5. Exact 消融：SB −27.7% vs SpecEdge exact −20.6%；32K −11.9% vs −2.9%。即便不改变目标采样分布，混合结构也有收益，是最有力的机制证据。
  6. HyCo-2P：SB server saving −44.7%，优于默认 −38.6%，但 delivery 29.0 vs 35.0 tokens/s；“更省云端”不等于“用户更快”。
  7. 移动 head 搬迁：服务器单轮中位时间 26.8→21.7ms，约省 5.1ms，但手机每轮多约 20ms；典型的异构资源交换。
  8. 质量总体：HyCo vs Cloud+MTP judge 差 +0.2（95% CI −0.9 至 +1.3）。不能说严格无损或已证明等价；只说明在所测非 QA 任务没有检出稳定总体下降。
  9. 弱项：翻译 HyCo 比 SpecEdge-ε 低 2.6 分（95% CI −5.2 至 −0.2）；而 32K ROUGE-L-Sum 37.5 vs 38.5，低 1.0。是明确的任务特异性 trade-off。
  10. 首 token：SB 846ms，32K 4.60s；证明平均 delivery speed 高仍可能有明显 TTFT。另手机 SLM 单独生成 26.4 tok/s，HyCo 35.0，约快 32.6%。

Strongest result：exact 模式与同 ε 模式双重对照均胜，较可信地隔离结构价值。Weakest result：翻译与部分摘要质量存在下降，且没有 loaded-service throughput 或 energy。Failure cases：480 问题中三次 HyCo 运行分别有 2、1、0 个不节省 server g 的问题，主要是仅约 40 token 的短 RAG 输出；人工查看被筛出的 13 个大幅降分案例发现 6 个实质错误，不能据此估算总体错误率。

13. Ablation / Mechanistic Analysis

去掉 ε 放宽：HyCo SB saving 38.6→27.7%，MAT 4.71→3.84；说明默认报告的最大节省部分来自改变分布，不能全记在 hybrid tree 账上。增加第二次 SLM pass：MAT 4.71→5.27、saving 38.6→44.7%，但交付 35.0→29.0；说明设备串行时间比额外接受的 token 更昂贵。head 留服务器：该变体 36.1 tok/s，但 server saving 只有 14.6%，且同时改了 sibling 等配置，不能称为完全纯净的 placement-only ablation。Proactive drafting：SpecEdge-style server saving 20.6→23.9%，交付 16.1→12.1；在此网络/实现下并行预取反而拖慢。量化 QAT：top-1 agreement 87.4→91.0%，有利于提升草稿接受，但并不单独证明最终质量不变。限制词表：全词表手机轮耗时 77.9ms vs 限制后 52.9ms；但 UC-val 中 3.0% 的 bonus token 在 keep set 外，可能伤害长尾语言。

14. Claim vs Evidence

Authors Claim：混合 drafter 在端云分工下减少 server GPU 时间、提高移动端交付速度，且整体质量下降有限。Experiments Actually Show：在指定 Gemma 家族、Galaxy S26 Ultra、RTX PRO 6000、LTE/5G、单客户端和特定 benchmark 下，精确与放宽接受规则均可实现成本收益；默认 ε 在整体 judge 上没有检出显著差异，但翻译等子任务下降。What Is Not Yet Proven：多用户吞吐和实际云成本下降、低带宽/高 RTT 稳定性、其他芯片与闭源 API 的可移植性、严格的语义质量等价、数据隐私安全、图像/视频多模态推理收益。

15. Contribution：创新还是组合

Contribution 1 [New System / Engineering]：把目标模型原生 MTP head 从服务器迁到手机，利用可传输的中间状态完成 split inference；是主要系统新意。Contribution 2 [New Mechanism / Engineering]：MTP chain 提供 depth、一次 SLM 提供 width，混合树按路径分数裁剪；组合方式有价值，但 tree speculative decoding 和 MTP 都不是本文首次提出。Contribution 3 [New Empirical Finding]：通过 exact/same-ε 双对照揭示结构收益，并报告 server GPU time 与用户 delivery 的相反变化；有利于后续研究设计更公平的效率 benchmark。Not New：KL、QAT、restricted vocabulary、Bradley–Terry 等不是本文的新理论；ε-rule 也有既有采样阈值思想来源。

16. Limitation & Failure Modes

Authors' Limitation：只有一台手机、一种网络、一类云 GPU、一类 verifier，单客户端；不测真实负载 capacity、货币成本、手机/无线电能耗；默认有损接受改变目标分布；judge 不能充分验证事实；头部与隐藏状态必须可访问，闭源 API 通常不支持；MTP 图与 SLM 图占内存，首次长 prompt 可能传 6.3MB；仅评文本，不含图像和音频；激活传输可能泄漏敏感信息。

Additional Limitation：高 RTT 下每轮同步可能压过服务器省下的 5ms；不同 tokenizer 需要 token bridge；分布外专业词汇不在 86K keep set 中时 MAT 下降；在更高 batch size 下服务器 MTP head 原本可能更有效率，迁移收益变化；网络断连后手机与服务器 KV 状态可能不一致；固定 K/B/ε 无法适应不同问题难度。尤其要警惕把 g 下降直接写成“推理速度提升 38.6%”：一个是服务器计算成本，另一个才是用户端速度。

17. Reproduction View：先复现哪个实验

官方公开代码未核验，因此完整原系统复现难度高。最小实验应先在单机 GPU 模拟端云两端：选带 MTP head 的开源目标模型，取 head 的 hidden/KV 输入，在独立进程运行 head；另以小模型对多个树节点做一次 batch forward，构造 K=4、B=32 的候选树。服务器进程用 tree mask 验证；在 exact 模式下首先做 1,000 个相同 seed 的分布一致性单元测试，再做 ε=0.005 模式的质量与 MAT 对照。

建议优先复现同 ε 下 hybrid tree vs SLM-only tree，因为它最能检验分工思想且不必一开始就实现移动 NPU 量化。随后增加网络模拟（RTT=10/40/100ms、带宽=10/50/200Mbps）、1K KV window、W4 head 与词表限制。输出每轮 draft_ms, verify_ms, transfer_bytes, accepted_tokens, TTFT, TPOT, tokens_per_s, quality。关键坑：目标模型中间层定义、RoPE 位置、父子树 attention mask、bonus token KV、top-k/top-p 后概率阈值、首轮 prefill 状态同步。若不能确保 exact 分布一致，所有速度数字都没有可比性。

Baseline Potential：中高，论文设置详细但公开代码未核验；可做 split speculative baseline。Migration Potential：高，将 depth/width 分工迁移到 Video VLM、长上下文 Agent 或异构推理。Systems Potential：高，调度、网络、显存、量化与模型结构交叉。Attack Potential：中高，手机可访问目标 hidden/KV，存在激活泄漏与篡改可能。Evaluation Potential：高，强调 g、TTFT、TPOT、delivery、quality 同时报告。Benchmark Potential：高，可定义网络波动和分布外词汇压力测试。New Paper Potential：中高，但简单“换设备运行 head”已被本文占据，需加入自适应调度、可靠性或跨模态机制。

19. Migration A：面向 Agent 的动态端云草稿预算

Original Problem：Agent 在连续工具调用时，每次输出长度与难度变化大，固定 K=4、B=32 不一定合适。Transferable Mechanism：MTP 提供串行 depth、SLM 提供并行 width，服务器根据接受率节省 GPU 工作。New Research Question：能否根据工具类型、网络 RTT 和前几轮接受率动态选择 K/B/ε，并优化真实任务完成时间而不是单纯 tokens/s？Method Modification：加入 contextual bandit，状态为 (RTT, MAT_recent, prompt_len, tool_type, NPU_load)，动作从 K∈{2,4,6}、B∈{8,16,32}、ε∈{1,0.005} 选择，奖励为 −wall_clock_ms − λ·quality_regression。Minimum Experiment：在单机两进程模拟端云，用 100 个可验证工具调用任务、seed=42、每种 RTT 重复 3 次；固定 K4-B32、仅动态 K、仅动态 B、完整控制器四组；保存逐轮日志与 Pareto 曲线。Model：Gemma 4 或其他公开带 MTP head 模型。Dataset：ToolBench 可执行子集或自建 Python 工具任务。Baseline：Cloud+MTP、HyCo 固定配置、SpecEdge-style。Metric：task success、TTFT、end-to-end task latency、g、MAT、NPU energy（能测时）。Expected Contribution：面向真实 Agent workload 的质量约束动态预算。Risk：reward hacking（通过少输出掩盖慢速）、训练和部署分布不同。Collision Risk：与 adaptive speculative decoding、network-aware scheduling 存在明显交集。

20. Migration B：Video VLM 的跨帧混合草稿与缓存

Original Problem：长视频 VLM 的 frame tokens 和 text decode 都贵，跨帧重复特征常被重算。Transferable Mechanism：把“串行深度由轻量历史状态预测、并行宽度由另一模块提出候选”的思想迁移到视觉 token 选择。New Research Question：能否用历史帧特征预测下一帧需要保留的关键 token，并用 query-aware 分支候选减少视觉编码与后续 LLM prefill？Method Modification：以小型 temporal predictor 输出连续帧关键 token 主链，再由 query-aware selector 一次提出补充候选，统一预算 B 下用教师模型验证视觉回答变化。这里是研究构想，不是 HyCo 已证明的视觉方法。Minimum Experiment：抽取 200 条短/中/长视频 QA，固定 8/32/128 帧三档，视觉 token budget 25/50/100%，对照均匀采样、attention-topk、temporal-only、hybrid；同一 GPU 测 encode、prefill、decode wall-clock，记录答案准确率与峰值显存。Model：Qwen2.5-VL-7B 或同等开源 Video VLM。Dataset：Video-MME 子集、MVBench。Baseline：uniform frames、query-aware frame selection、token pruning。Metric：frames、visual tokens、FLOPs、wall-clock、VRAM、QA accuracy。Expected Contribution：把草稿结构分工转化为视频推理动态计算预算。Risk：跨模态的“验证”成本过高，可能省不了真实时间。Collision Risk：与 Video Token Pruning / Adaptive Frame Sampling 高度重叠，需重点检查最新论文。

21. Inference 专项：真正少算了什么

Bottleneck：云端 MTP 自推测的顺序 head 前向占用服务器 GPU；纯移动端 SLM 造深树需要多次 NPU 前向；网络 RTT 又限制每轮确认速度。Acceleration Mechanism：不是减少目标模型单次 verifier 的参数量，而是把顺序 MTP head 前向移到手机，并减少 SLM 前向次数；云端每轮验证更多候选，以更少 GPU 时间输出同样数量的 token。需要训练吗：不需要重新训练 verifier；MTP head 需要 100 步 W4 QAT，SLM 做整数 graph surgery 和校准。硬件相关性：强依赖可访问原生 head、移动 NPU 整数图和链路质量。Long-context：32K 已测，但手机只看 1K 窗口，且 prefill 占比上升，不能直接推到 128K。Batch-size scaling：仅单客户端，没有证据。理论 vs wall-clock：作者给了真实手机交付速度 35.0 tok/s，因而有 wall-clock 证据；但 g 节省 38.6% 不能直接解释为端到端 1.63×，实际对 SpecEdge-ε 的 delivery 约 1.85×。

22. Attack / Verification Lens

攻击面一：中间状态暴露。手机持有部分 embedding、hidden state 和 KV；若客户端被控制，可能尝试推断 prompt 信息或篡改后续草稿。最小测试是仅在授权、公开合成数据上做 hidden-state membership / prompt-attribute probe，比较原始状态与噪声/量化后的可识别性。攻击面二：有损接受。构造低概率但 ε 可接受的候选路径，测试安全拒答、指令遵循和跨语言翻译的偏移；这是效率压力测试与安全评估，不是论文已证明存在可利用攻击。新 metric：Verified Quality per Cloud GPU-second 与 Quality-constrained End-to-End Latency，再附 network bytes/output token，避免仅以服务器 g 优化产生虚假收益。

23. 如果只记住这篇论文（9 句话）

  1. HyCo 研究的是手机与云端协同的推测解码。2. 原生 MTP head 负责候选链的深度。3. 小模型单次并行前向负责树的宽度。4. 云端传中间状态给手机，再一次验证整棵树。5. 默认 K=4、B=32、1K KV window、ε=0.005。6. SB 服务器 GPU time/token 相对 Cloud+MTP 降低 38.6%。7. 与同 ε 的 SLM-only 对手相比，手机交付约 1.85 倍。8. 默认 ε 接受改变目标采样分布，翻译存在下降，不能叫严格无损。9. 未来真正值得做的是质量约束的动态计算与网络调度，而不是照搬固定草稿树。
CROSS-PAPER SYNTHESIS

1. Cross-Paper Synthesis：今天共同揭示什么

两篇论文属于不同层次，但共享一个强机制：把固定分配变成依状态而变化的资源配置。MPT 分配“哪个专家获得下一次环境行动”，HyCo 分配“哪种 drafter 在什么硬件上承担串行深度或并行宽度”。二者都反对简单平均：MPT 不让所有 Agent 轮流浪费回合，HyCo 不让 SLM 为所有草稿深度重复前向。另一个共同点是成本与收益不能只看局部：MPT 增加竞价/反事实计算换取任务 reward；HyCo 增加手机 NPU/网络负担换取云端 GPU 时间。若把系统优化目标只写成局部 reward 或局部 GPU time，可能出现“局部好、整体差”。

2. Combined Research Opportunities

机会 A：Cost-Aware Agent Bidding。 让 Agent 报价不仅代表执行意愿，也报告执行时间、预期 token、工具费用。目标从最大化任务 reward 变成 task_success − α·GPU_seconds − β·wall_clock；用 MPT 的反事实替换和 HyCo 的设备成本计量共同学习动态调度。最小实验：固定 3-Agent 工具任务 100 条，记录每个 Agent 的 reward、响应时间、工具费用；对照固定轮流、只优化 reward 的竞价、成本感知竞价，报告成功率与 Pareto 前沿。核心挑战是不同 Agent 的报价可能不可信，须用实际测量校准。

机会 B：Selective Counterfactual Compute。 MPT 的每次反事实重跑很贵；HyCo 告诉我们不同候选分支值得不同计算预算。训练一个 uncertainty predictor，只对高争议/高后续影响的 contested turn 启动真实环境回滚，其余用轻量 reward delta 估计。对比完整反事实、随机 20% 反事实、置信度前 20% 反事实，在相同总 FLOPs 下测任务 reward。创新必须落在可验证的 credit bias–cost 曲线，而不是把两篇模块拼接成框图。

机会 C：Causal Resource Attribution Benchmark。 同一条 Agent 轨迹同时记录：谁被调度、为什么被调度、消耗多少 GPU/网络资源、删掉这次执行后结局如何。定义 causal gain per GPU-second、counterfactual regret 和 replay stability，为动态 Agent 和推理加速建立统一评价协议。这是评测构想，不是已存在的统一 benchmark。

3. Collision / Overlap：哪些是重合、哪些不是

直接 Collision：NONE。 MPT 的主要贡献是多 Agent 竞价和信用分配；HyCo 的主要贡献是原生 MTP head 端云迁移与混合草稿树。两者没有相同的模型目标、数据集或直接复现关系。概念重叠：都在做选择性分配与延迟收益评估，但“参与机会”不是“候选 token”，不能据此声称方法相同。MPT 与经典 counterfactual MARL、AgentNet/GoA 有真实研究邻域；HyCo 与 SpecEdge、Cloud+MTP、Medusa、adaptive speculative decoding 有真实研究邻域。迁移选题应先检索这两组邻域，防止重新发明已有调度器。

4. Reading / Reproduction Priority

第一优先：MPT（科研机制）。先看式 1 的 credit 回传、式 3 的反事实竞价偏好，再看 Table 2 与 Figure 7。代码和 checkpoint 已公开，适合在可回放环境做严格复现与扩展。尤其适合研究 Agent memory/trajectory 的因果归因和跨会话技能选择。

第二优先：HyCo（系统工程）。先看 Figure 2 的深宽分工、Table 2 的同 ε / exact 双对照、附录 Algorithm 1–4 的 KV 和 tree mask。公开实现未核验，完整手机 NPU 复现成本高，建议先做单机双进程模拟验证算法正确性，再研究真实网络与移动硬件。

Baseline 选择：Agent 动态协作选 MPT；端云推测解码选 HyCo/SpecEdge。Systems / acceleration idea：HyCo 更直接。Benchmark / metric：优先建立跨硬件端到端质量-成本评测，补足 HyCo 只测单客户端的缺口。Attack / evaluation：MPT 的恶意竞价与错误信用传播最易构造受控实验；HyCo 的中间状态泄露和 ε-rule 质量偏移需要严格授权与安全边界。
