Paper 1｜MoEZip：把“路由稳定性”纳入 KV 缓存压缩

基本信息　MoEZip: Routing-Aware KV Cache Compression for Sparse Mixture-of-Experts LLMs；Minsang Kim、Seungjun Baek；Korea University / SK Telecom；arXiv v1 2026-10-21；作者标注 NeurIPS 2026 Accepted；本期标记 BACKFILL（距本次运行约四天，超出严格 72 小时）。 论文 HTML · PDF · 官方仓库 · OpenReview。代码核验：官方 GitHub 页面目前只列 README.md 与 LICENSE，README 的 run_example.sh 不在可见文件列表，故“仓库存在”不等于“可直接运行的完整代码已公开”。

一句话定位：传统 KV eviction 保护“被注意到的信息”，MoEZip 进一步保护“删掉后会改变 MoE 专家选择的信息”，把缓存压缩从 attention preservation 推进到 computation-path preservation。

1. 人话版：为什么这篇值得读

长上下文模型需要存储每层每个注意力头过去 token 的 Key、Value；上下文越长，显存越吃紧。通常我们看哪些旧 token 获得的 attention 高，就保留哪些，剩下丢弃。对普通稠密 Transformer，丢掉一个 token 主要改变注意力聚合值；对 MoE 模型，改变注意力输出还会改变路由器选择哪几个 expert，相当于“本来让数学专家处理，结果换成了另一个专家”。MoEZip 抓住这个放大效应：先在当前 instruction token 上读取路由分布，利用 Fisher information trace 估计哪些位置处在“路由容易被扰动”的状态，再沿 attention 把脆弱性映射回历史上下文位置，优先保留一批 anchor，剩余预算仍交给 KVZip/SnapKV 等已有压缩器。它不需要重新训练 MoE 权重，保留 KV 数量也不增加。Qwen3-30B-A3B 上，在只保留 10% KV 时，12 项 LongBench 宏平均由 KVZip 的 19.51 提高到 44.89；但论文没有证明真实端到端 tokens/s 必然提高，且压缩选择本身有额外时间。其最大价值是揭示：缓存重要性不只由信息内容决定，还取决于它会把后续计算送到哪里。

2. Background & Research Gap：旧方法为何不够

以一个 16K token 的工具调用历史为例，模型接到“找出客户取消订单的唯一证据”时，历史中有一句罕见的例外规则。SnapKV 观察最近查询对历史 token 的注意力；PyramidKV 根据层间注意力集中程度分配预算；KVZip 通过上下文重建评估 token 的重要性，以便一份压缩缓存复用于多个查询。这些思路都合理，因为 attention 常常对应信息读取需求。但 MoE 的前馈部分不是固定的一个 FFN，而是 router → top-k experts → combine：缓存删除造成微小隐藏状态变化，就可能让两个得分接近的专家名次互换，后续整条解码路径发生离散改变。即便保留下来的文字片段看似足够，计算路径仍可能不稳定。

这不是“MoE 的 KV 比 dense 更大”的论断：KV 大小主要由注意力架构、层数、KV heads 和精度决定；本文真正指出的是同样比例的 KV 删除在 MoE 可能额外触发专家翻转。作者用同一串 instruction 与 teacher-forced reference answer，在完整 KV 和压缩 KV 条件下比较每个 MoE 层的专家分配，避免自由生成不同答案带来的 token 对齐混淆。Figure 1 展示压缩越激进，路由翻转越多、任务质量越差；但仅有相关性不能排除“attention 信息丢失”和“专家变化”共同由 KV 删除引起，所以后面设计固定缓存的路由干预实验。这条从 observation 到 intervention 的证据链，是论文比普通“新打分函数”更值得读的原因。

3. Core Insight：平均方向上的路由脆弱性

观察 A（经验）： instruction 位置的 expert flip rate 与随后 answer 位置的 flip rate 同步变化。未来答案尚未生成，无法直接计算未来路由风险；但当前 instruction 已知，可以用作可部署的代理。观察 B（局部数学）：当 router logits 有小扰动时，两个路由概率分布之间的 KL 散度的二阶项由 Fisher 信息矩阵控制。其迹 trace 衡量在各向同性扰动假设下，对所有扰动方向平均的敏感程度。观察 C（系统设计）：一个历史位置即使没有最高的通用 saliency，只要被“脆弱路由状态”的 instruction 强烈读取，就可能值得保护。故使用 Fisher × attention 评分，先占用有限 anchor 预算，再让通用 scorer 补齐。

关键边界：trace(F) 不是实际删除某个 KV 后的精确影响；真实扰动方向不是各向同性，而且 expert top-k 的硬切换与平滑概率分布 KL 也不等价。论文的 Fisher 是便宜、可计算的风险代理，而不是“理论证明任何高分 token 都会导致 expert flip”。它之所以可信，主要靠后面的 correlation、ablation 和 oracle intervention 共同支撑。

4. Method Deep Dive：从输入到输出

长上下文 C + 下游指令 I + 预训练 MoE → 读取 instruction attention / router logits → 计算 Fisher trace → 反向归因到历史位置 r(i) → 自适应决定 anchor 数量 → anchor + base scorer 补足预算 → 构建压缩 KV → 原模型正常 decode

Step 1｜获得预压缩观测。在可访问 router 与 attention 的白盒 MoE 上，以完整历史和当前指令运行前向，取得每个 MoE 层、每个 instruction token 的专家门控分布 g_{t,l}，以及 instruction 对历史第 i 个位置的 attention α_{t,l,h,i}。输入对象是 KV、router logits 与 attention；输出是两个统计张量。风险是 flash attention 或 serving runtime 不暴露完整 attention matrix，提取统计可能破坏原本高效的 kernel 路径。

Step 2｜量化“脆弱”而非“注意力大”。 softmax router 的 Fisher trace 为 1−Σg_e²；分布接近均匀时更大，接近 one-hot 时更小。sigmoid 独立门控对应 Σg_e(1−g_e)。它表示对小 logit 扰动的概率分布敏感性，而不是 expert 实际已经翻转。输出是每个 instruction token × MoE 层一个标量 f_{t,l}；若路由高度饱和，该值会小，但一个极接近 top-k 决策边界的稀疏路由仍可能产生不同于 Fisher 的风险，属于代理失配。

Step 3｜将风险映射回历史 token。先对 head 做 max_h α，而非 mean，保留某个头特别依赖某位置的尖峰；再对 instruction token 与 MoE 层累加 attention × Fisher，得到每个历史位置的 r(i)。它不是梯度归因、也不是对每个 KV 做反事实删除，而是基于前向统计的启发式 attribution。一个位置只有在“被脆弱状态读取”时才高分；高 Fisher 但没有读到它，不会自动进入 anchor。

Step 4｜决定多少位置需要特殊保护。作者对 Fisher 值按理论上限的 85% 设置阈值，计算超过阈值的状态比例 Γ；将 Γ 映射到 anchor 占预算比例 ρ_min + (ρ_max−ρ_min)Γ。默认 ρ_min=0.05、ρ_max=0.25，同时用 B_min=32、B_max=128 对 anchor 数量裁剪。若 B 很小，最小 anchor 数还需受总预算约束，实际实现必须防止 B_f>B。此处决定“多少位置由路由评分保护”，不是“总共保留多少 KV”。

Step 5｜预算内拼接。先按 r(i) 取 top-B_f anchor，再把剩余 B−B_f 交给 KVZip（默认）或 SnapKV，去重后填满。每个 layer/head 的总 KV budget 与 baseline 相同，区别只是组成。这个组合有助于防止过度追求路由稳定而忘记普通内容检索。随后照常 autoregressive decode，不修改模型参数、expert 结构或生成目标。MoEZip-Recon 用 KVZip 原有的固定重建 query 替代真实下游指令，因此压缩缓存可跨请求复用；代价是少了 query-aware 信号。

5. 核心公式与数学直觉

αt,ℓ,h,i = softmaxi(qt,ℓ,h · kℓ,h,i / √d)
zt,ℓ = Rℓ ut,ℓ　→　g = softmax(z) 或 sigmoid(z)

其中 u 是 attention 聚合后的隐藏状态，R 是 router 线性映射。删除第 i 个 KV 不只是让 α 重归一化，还会改变 u、z 和 expert assignment；这就是缓存压缩与 MoE 路由之间的因果链候选。

DKL(p(z) ∥ p(z+δz)) ≈ ½ δzᵀF(z)δz
Eδz∼(0,σ²I)[DKL] ≈ (σ²/2) tr F(z)

KL 衡量两个路由分布差异，越大说明 logit 小扰动导致概率变化越大。F 是 Fisher 信息矩阵；其特征值刻画不同方向的敏感程度，迹是特征值之和。对于 softmax，F=diag(g)−ggᵀ，故 tr F=1−Σg_e²；对于独立 sigmoid，F 对角元素是 g_e(1−g_e)。这一推导只在小扰动与所设协方差下成立；它不包含真实删除位置引起的 δz 方向，也不能把高 trace 直接解释成“路由必翻转”。

r(i) = Σℓ∈MoE Σt∈Instruction [ maxh αt,ℓ,h,i · tr F(zt,ℓ) ]
Γ = mean 1[ft,ℓ > τ]；Bf = clip(⌊B·ρ(Γ)⌋,32,128)

这不是一个需要梯度下降的 objective，而是受 KV 预算约束的贪心排序/选择规则。最重要的超参数不是学习率，而是 keep ratio、τ、ρ_min/max、anchor clip 和 query-conditioned/reconstruction 两种模式。增加 ρ 会多保护路由位置，但减少 base scorer 的普通内容位；减少 ρ 反之。strongest baseline KVZip 的目标是重建上下文重要性，MoEZip 在相同预算下额外显式加入“计算路径是否会变化”。

6. Toy Example：4 个历史位置如何决定保留谁

设一个 MoE 层、两个 instruction token、四个历史位置 A=客户名、B=例外规则、C=订单金额、D=日志尾部。只保留 B=2 个位置。两个 instruction 状态的 Fisher trace 分别为 0.48 与 0.08。为了演示，设其 max-head attention 对 A/B/C/D 分别为 [0.1,0.7,0.1,0.1] 和 [0.1,0.1,0.7,0.1]。于是 r(A)=0.056、r(B)=0.344、r(C)=0.104、r(D)=0.056。如果 routing anchor 占 1 个位置，选 B；另一个位置由 KVZip 选，例如 C。得到 {B,C}。纯 KVZip 可能选 {A,C}，漏掉“例外规则”。当 B 被删除时，instruction 隐藏状态改变、router top-2 expert 可能变成另一组；保留 B 不保证答案正确，但更有机会保持原来的计算路径。这里的数字完全是教学构造，不是论文实验数据；实际默认 anchor 最小数量为 32，toy 中将预算规则缩放演示。

9. Metrics 教学式解释：读数前先弄懂量尺

Keep ratio = 保留历史 KV 数 / 原始历史 KV 数；越低越省缓存，通常质量风险越大；10% 不等于整个模型显存减少 90%，因为模型权重、当前 token、运行时缓存仍在。LongBench macro 是对不同任务官方指标求宏平均：QA 用 F1，摘要用 ROUGE-L，分类/少样本用 accuracy，代码用 edit similarity。越高越好，但跨任务量尺混合，平均 +24 不等于“24% 真实用户任务提升”。RULER score 是 13 项长上下文任务平均，越高越好；合成检索强，不等于真实代理稳定。NIAH ROUGE-L F1 测输出与针目标文本的最长公共子序列重合，越高越好；它测文本抽取而不是因果推理。

Expert flip rate = 在相同 token 序列、相同层位置下，压缩与完整 KV 选择专家不一致的比例，越低越接近原路由，但“接近”不保证正确。NLL = reference answer 的平均负对数似然，越低越好；是 teacher forcing 指标，可能与自由生成任务分数不完全一致。Spearman ρ 衡量排序相关，越接近 +1 越单调一致；相关并不证明原因。Jaccard = 两组 anchors 交集 / 并集，越高说明选择更一致，但高一致性本身不是任务质量。Selection overhead 需要加在真实 prefill/decoding 之外，不能把缓存节省直接当作端到端加速。

13. Claim vs Evidence 与 Contribution

Authors Claim：MoE KV 删除引入特有的 routing instability；Fisher-aware anchors 能在固定 KV 预算下显著提升保留质量；适用于不同 router 和更大规模模型。Experiments Actually Show：在 Qwen3-30B/235B 与 GLM-4.7-Flash、LongBench/RULER/NIAH 等给定 setting，性能显著改善；固定 KV 的 oracle routing correction 明确表明专家分配本身对输出有贡献；INT8 实验显示六任务 macro 从 BF16 26.4 降到 25.8，方法相对 KVZip 的优势大体保留。What Is Not Yet Proven：通用 online serving 的 TTFT/TPOT 降低、所有 MoE router 类型的稳定性、黑盒适用性、真实 agent 多轮 KV 复用下的收益、Fisher 比所有更便宜 margin 指标都更好。

Contribution 1｜New Empirical Finding：压缩引发 MoE routing flip，并与生成质量损失相关；有干预加强因果解释，属实质机制发现。Contribution 2｜New Metric/Mechanism：用 router Fisher trace 量化局部 fragility，再 attention 传播为 KV 重要性，属于有数学动机的组合创新，不是首次提出 Fisher 或 attention。Contribution 3｜New System/Engineering：自适应 anchor 与已有 KVZip/SnapKV 组合，且不增保留预算；实用性依赖系统能低成本导出统计。Contribution 4｜New Evaluation Protocol：固定 retained KV 的 routing oracle 和渐进纠正值得复用；其原创性是针对该问题的实验范式，而非通用 causal inference 的发明。

14. Limitation & Failure Modes

Authors' Limitation：需白盒 router outputs 与 instruction-to-context attention；黑盒 API 不适用。Additional Limitation 1｜selection cost：每次 query 都重选 anchors 可能吞掉 decode 省时，尤其短输出、短上下文。2｜路由 proxy：各向同性 Fisher trace 对真实 KV 删除的定向扰动不一定准确；hard top-k 边界与 softmax 平滑敏感性不完全一致。3｜语义丢失：保护 expert assignment 不能恢复丢失的具体证据，Table 2 oracle correction 后仍远逊 full KV。4｜评估：LongBench 宏平均跨任务异质；需要 AgentBench、tool-use、长会话和并发 serving。5｜规模：235B 仍属 Qwen 同一家族，不能等同跨架构充分验证。6｜开源：截至本次检查，公开仓库可见 README/LICENSE，无实际代码文件；论文宣称的可复现性尚不能按 README 直接验证。7｜显存与性能：只保留 10% prefix KV 不是 10% 总 GPU memory，也不是 10× speedup。

Paper 2｜CAVC：视频生成的“可恢复性”决定缓存哪条分支

基本信息　CAVC: Convergence-Adaptive Audio-Visual Cache for Modality-Asymmetric Diffusion Generation；Lifan Jiang、Yibo Zhao、Senlin Cheng、Bolei Xu、Xiaobo Li、Can Ye、Dehai Zhao、Deng Cai、Boxi Wu；Zhejiang University（State Key Lab of CAD&CG）/ Ant Group；arXiv v1 2026-10-22；PREPRINT，未核实正式录用 venue；论文 HTML · PDF。Code：正文提及匿名 code artifact 和 manifest，但未在可核验的 arXiv 页面提供公开 GitHub 仓库地址，标记 Not Publicly Verified，不能把“论文写了 artifact”说成“代码已开源”。

一句话定位：联合音视频扩散推理不必每步同等计算所有模态；CAVC 通过“哪些误差能在最后几步修回来”决定中途缓存音频、保留视频计算，以较小但真实测得的 wall-clock speedup 换取较稳的生成质量。

1. 人话版：这篇真正讲了什么

一个模型同时生成画面和声音，比如“院子里猫扑球，碰撞时发出清脆声音”。传统联合扩散模型每一步都要更新视频 latent、音频 latent，还要让两条分支通过 cross-attention 交换信息。即使画面动作需要不断精修，声音分支可能已进入一个阶段：暂时复用它刚算出的去噪预测，最后再做几次完整的音视频联合去噪，也能恢复不少声音语义和同步。作者不是说“音频永远比视频先收敛”，而是提出更谨慎的 modality-asymmetric recoverability：音频缓存导致的偏差较容易通过尾部 joint refinement 修复，视频中途冻结导致的动作损失却不容易补回来。CAVC 因此先完整联合预热，观察音频预测变化连续变小后，缓存音频 denoiser 的输出、跳过中段音频网络和跨模态注意力，视频网络仍逐步完整计算；最后 3 步恢复 joint denoising。基于 LTX-2.3-22B-dev、单张 H20 96GB，三个 benchmark 报告 1.10–1.35× 实测端到端加速。这是系统机制工作，而非只在 FLOPs 纸面上画漂亮曲线；但提升幅度有限，部分音画同步和自然度指标确实下降。

2. Background & Research Gap：为什么普通 cache 不够

联合 audio-video diffusion 可以抽象成两个状态 v_t（视频）和 a_t（音频），每个去噪步同时调用 f_v(v_t,a_t,c,σ_t) 与 f_a(v_t,a_t,c,σ_t)，其中 c 是文字 prompt，A2V/V2A cross-attention 让“看到球碰撞”和“听到碰撞声”对齐。以 30 个 denoising step 为例，如果每一步都执行两个大分支与跨模态 attention，成本很高。减少总 step 数、蒸馏少步模型可以加速，但往往需要训练或损伤时序细节；DeepCache、TeaCache、Cache-DiT 一类方法复用旧层/旧 step 的结果，但直接用于双模态模型时，不知道哪个分支的误差更致命。

想象把画面生成的第 8–22 步全部冻结：球的运动轨迹没有持续被修正，最后 3 步很难凭空补出自然的运动连续性。反过来，若中途音频分支只沿 scheduler 更新 latent、复用一个稳定的 audio prediction，最后恢复 3 次联合处理，碰撞声的语义和节奏有机会回来。作者通过branch freezing和terminal recovery实验证实这两种干预不对称。这里的 gap 不是“从未有人缓存 diffusion 特征”，而是缓存策略忽略了不同分支的误差可恢复性、误差修复成本和跨模态耦合阶段。

3. Core Insight：缓存应按“未来能否修复”分配

经验观察 1：音频输出预测在某个阶段的逐步变化变小，可作为进入 cache-tolerant regime 的在线信号；注意它并不等价于“音频比视频数值收敛更快”。经验观察 2：如果缓存音频分支，中间的偏差可由少量 terminal joint steps 大幅缩小；如果缓存视频，动作动态的损伤很难靠尾部重算恢复。工程推论：把可近似计算集中到 audio branch，把“必须持续迭代”的视频 branch 留下来。进一步推论：中段跳过跨模态 attention 不一定只有坏处，它可能减弱已经稳定的音频特征对视频动态的过度约束，因此某些视频 motion 指标反而提高。

证据类型要分清：上述 recoverability 是特定 LTX 双流模型与 benchmark 的经验现象；论文理论部分给出在局部 Lipschitz 和有界误差条件下的输出偏差上界，不能证明“最后 3 步必然恢复质量”。如果把方法迁移到 speech-dominant talking-head、实时音乐或多事件视频，音频可能是不可牺牲的一侧，策略需要重新测量。

4. Method Deep Dive：三段式“夹心”调度

文本 prompt c + 初始噪声 (vT,aT) → Phase A 联合预热 → 连续 W 步音频变化小于 θ → Phase B 缓存 audio prediction / 跳过 AV attention / 视频照常细化 → Phase C 恢复 3 步联合去噪 → 视频帧 + 同步音频

Step 1｜Phase A，完整预热。从大噪声到较低噪声的初始步骤，照常执行音频、视频及双向 cross-attention。其作用是建立画面场景、声音类别、文字条件和粗粒度同步。不能一开始就 cache：如果猫扑球与音效还没有建立语义绑定，最后短短 3 步未必能补上。输入是 v_t,a_t,c,σ_t，输出是两路 denoiser prediction 和 scheduler 更新后的 latent。

Step 2｜Trigger，在线检测。每步计算相邻两次音频 denoiser 输出的平均绝对差 Δ_a^t=mean|ŷ_a^t−ŷ_a^{t+1}|，而不是比较两次音频 latent 是否相同。当 Δ_a^t<θ 连续 W 步成立，触发缓存，存下当前音频预测 ŷ_a*。默认 θ=0.30、W=3。阈值越严格，通常触发越晚、质量更稳但加速少；窗口越短越早触发、容易把偶然小变化误判成可缓存。此处的 τ 是倒数的 diffusion timestep，论文另用正向递增执行序号 k 描述触发时间；混淆二者会导致复现时把“早触发”理解反。

Step 3｜Phase B，真正省计算。触发后不再运行音频 denoiser，而是在每个剩余中段 timestep 使用同一个 ŷ_a* 输入原来的 audio scheduler，得到新的 a_{t−1}。这与冻结音频 latent不同：音频状态仍沿噪声时间表演化，只是更新方向来自缓存预测。视频分支继续完整计算 spatial/temporal self-attention 与 text conditioning，但 A2V/V2A cross-attention 以 residual skip 方式旁路。这里省的是音频网络前向 + 跨模态 attention，并非整个 DiT 前向、并非帧数/视频 tokens 的删除。可能失败：多次新声音事件出现时，复用旧音频预测无法及时适配，声音与画面脱节。

Step 4｜Phase C，尾部恢复。最后 t_ref=3 步恢复音频网络、视频网络和 cross-attention，重新让两种 latent 互相修正，再 decode 输出。这三步主要修补声音语义、音画同步偏移与跨模态 drift，而不是重建被中途跳过的视频细节——所以作者从一开始就没有跳过视频 refinement。注意论文 Table 4 显示恢复步数 1、3、5 并非所有指标单调上升，更多联合步骤可能改变某项评估器的判断。

Step 5｜部署层面。必须改推理 loop：在 Phase B 使用 cached audio prediction，保证 scheduler 每步仍运行，确保 cross-attention 的 bypass 不错误删除视频 self-attention、文本条件或 residual scale。原模型权重冻结，不做额外训练；但需要访问模型内部双流分支和采样 scheduler，不是任何闭源视频 API 都能即插即用。

5. 核心公式：缓存的是预测，预算节省来自分支

ŷvt=fv(vt,at,c,σt)；ŷat=fa(vt,at,c,σt)
vt−1=Stv(vt,ŷvt)；at−1=Sta(at,ŷat)

f 是去噪预测网络，S 是扩散/flow scheduler，σ_t 是噪声级别。CAVC 在 Phase B 把音频 f_a 替换成常量输出 ŷ_a*，但 S_t^a 仍依赖当前音频 latent 和时间步，因此不能简单说“声音被静止”。视频改为 g_v(v_t,c,σ_t)，即无跨模态 attention 的视频 denoiser，保留视频自己的时间建模。

Δat = mean(|ŷat−ŷat+1|)；连续 W 次 Δ < θ ⇒ cache
ãt−1=Sta(ãt,ŷa*)；ṽt−1=Stv(ṽt,gv(ṽt,c,σt))

理论偏差：设音频缓存预测误差上界为 ε_a，删除 AV attention 后的视频预测残差上界为 ε_v；scheduler 对 latent、prediction 的局部 Lipschitz 系数分别为 α_t,β_t。论文推导 e_a^{t−1}≤α_t e_a^t+β_t ε_a，视频则是 e_v^{t−1}≤(α_t+β_t L_g)e_v^t+β_t ε_v。连续展开得到多步误差的加权和；尾部联合处理再乘一组局部 Lipschitz 系数的积 K_C，得到输出标量质量函数的条件性偏差上界。直觉：缓存越久、单步残差越大、传播因子越大，最终偏差风险越大。不能推出：K_C<1、误差必收缩、或者任意主观视频质量都满足这个上界；作者明确把它当 perturbation characterization 而非无条件保证。

系统成本模型：Full AV 的每步成本约为 C_v+C_a+C_av；CAVC 的中段仅支付 C_v，触发检测还要支付 C_d，最后 joint steps 与 decode/I/O 都保留。若视频计算占大头，最多也只能节省音频和跨模态部分，因此端到端 speedup 远小于“被跳过的音频前向次数”所暗示的倍数。相较 TeaCache/Cache-DiT 的通用特征重用，CAVC 的关键 objective 不是直接最小化 FLOPs，而是在视频动作质量可接受的前提下，最小化不可恢复的分支近似误差与总 wall-clock cost；这一表述是对设计原则的归纳，非作者实际训练的损失函数。

6. Toy Example：30 步“猫扑球”如何加速

构造一个教学示例（非论文逐步 trace）：原本 30 步均执行音频 A、视频 V、跨模态 X，每步成本假设 A=2、V=5、X=1 单位，总 240 单位。前 6 步完整计算，音频预测变化依次从 0.7、0.5、0.28、0.20、0.18 下降；在阈值 θ=0.30、连续 W=3 的假设下，第 6 步触发缓存。随后第 7–27 步音频沿 scheduler 用第 6 步的 ŷ_a* 更新，视频照常计算但跳过 X；最后 28–30 步重新执行 A+V+X。总成本约 9×8 + 21×5 =177，理论示意 speedup 240/177≈1.36×，实际还需加触发检测、kernel 调度、CPU offload、decode 和 I/O，真实速度会更低。若中途发生第二次突然碰撞，缓存的旧音频方向可能不适用；这时应延迟触发或考虑重启联合计算。此例解释“省掉哪些运算”，不应误当论文报告的 1.35× 所对应的真实 profiling。

9. Metrics 教学式解释：不要把 FPS、Dynamic Degree、Sync 混淆

Speedup = Full AV 的实际生成时间 / 当前方法实际生成时间，越大越快；小于 1 说明变慢。Latency 是生成一个样本所花的 wall-clock 秒数，越低越好；24 FPS 是生成视频的播放帧率，不等于模型每秒生成 24 帧。Dynamic Degree 基于 RAFT 光流统计达到运动阈值的视频比例，越高表示更容易出现运动，但不能保证物理合理性。Subject/Background Consistency 使用 DINO/CLIP 特征比较帧间语义稳定，越高越好，但画面静止也可能高。Motion Smoothness 使用插帧模型 AMT-S 判断相邻运动是否平滑，越高越好，不能替代人工运动质量判断。

Flicker 是帧均值亮度变化的二阶差分统计，越低越好；可能把有意的闪光误判为缺陷。Naturalness 是像素亮度/梯度峰度接近参考统计的程度，越高越好，可能和主观真实感不一致。DNSMOS 是无参考语音/音频质量预测，越高越好，不等于声音语义正确。CLAP = 音频 embedding 与音频文本提示的余弦相似度，越高越符合文字，但可能无法精确测同步。AV-F1 将视频变化峰与音频谱通量峰在 ±3 视频帧内配对，算 precision/recall 的 F1；越高越好，但同步“出现一个声响”与“声响来自正确物体”不同。AV Sync 将 SyncFormer 预测的绝对时间偏移 |offset| 转为 max(0,1−|offset|/0.5s)，越高越好；超过 0.5s 的偏移都压成 0。Qwen2.5-Omni-7B 的 Audio/Visual Reality、Expressiveness 是 1–5 的模型评审分，可能有评审偏差。Lo-Phy/VideoPhy2 测局部物理合理性，越高越好；不等于全局物理一致。

13. Ablation / Mechanistic Analysis：去掉模块会怎样

缓存视频而非音频：2.84× 或 3.01× 的更大速度数字看似诱人，但动态度仅 0.460/0.440；这说明省算的位置比省算的总量重要。改成固定触发：Fixed 20% 只有 1.09×、Fixed 80% 只有 1.01×，dynamic 为 1.19×；说明 prompt-specific cacheability 有实用价值。只保留 Phase B，不做 Phase C：论文 Table 3(c) Stage 1 的 Dyn 从 0.540→0.580，加入 full stages 后到 0.620；说明尾部 joint refinement 在实验中贡献额外收益，但它也可能通过其他未隔离的状态变化提升质量，不能把每个差值都解释成单纯“同步修复”。

改变 θ 与 W：θ=0.15 更保守，触发晚，1.13×；θ=0.30,W=3 是默认，约 1.18×；θ=0.80,W=1 约 1.20×，更快但论文并未给出所有 prompt 的置信区间来证明质量无损。改变 terminal step 数：音频 CLAP 从无修复的 −0.005 到 1/3/5 步的 0.220/0.235/0.247；视频缓存的 Dyn 在 0.320–0.360 徘徊。这个不对称恢复曲线支持核心机制，而不是某个任意缓存阈值碰巧有效。仍需做“相同被跳过 FLOPs 的公平对照”和“不同 prompt 类别的置信区间”，否则不能断言最优调度策略已找到。

14. Claim vs Evidence 与 Contribution

Authors Claim：联合音视频扩散存在模态不对称可恢复性；在线音频缓存加末端 joint refinement 能训练自由加速并保持/改善若干质量指标。Experiments Actually Show：在 LTX-2.3-22B-dev + 官方 distilled LoRA、H20、batch1、CPU offload 条件下，三 benchmark 1.10–1.35× wall-clock；branch freezing 与 terminal step 消融显示 audio/visual 的恢复曲线明显不同；部分动态度和同步诊断改善。What Is Not Yet Proven：所有双流扩散模型都有相同恢复方向、所有音画同步指标都无损、不同硬件与高并发下同样加速、跨模态 attention 在中段对语义永远多余、理论上界能预测主观质量。

Contribution 1｜New Empirical Finding：通过 branch-specific perturbation 与 recovery 曲线提出“按模态可恢复性分配计算”，机制观察比单纯发现重复特征更有价值。Contribution 2｜New System/Engineering：三阶段 warm-up/cache/recouple 与 audio-only cache，属训练自由系统调度创新；cache、threshold、residual bypass 单独并非新发明。Contribution 3｜New Metric/Protocol：用 CLAP gap closure 和 Dynamics gap closure 对比不同模态恢复程度，提供可迁移的“recoverability curve”实验范式。Contribution 4｜New Theory/Analysis：局部 Lipschitz 误差传播界有解释作用，但属于条件性上界，不是强收敛保证。没有新训练 objective，也没有声称新数据集作为核心创新。

15. Limitation & Failure Modes

Authors' Limitation：保留完整视频分支导致速度上限被视频计算绑定；声音事件持续变化会推迟 trigger、速度趋近 Full AV；快速多事件可能仍有同步偏差，需要增加 Phase C 步数。Additional 1｜泛化：只在一个 LTX 双流主模型和单 H20 评估，迁移到别的 DiT、不同音视频比例、音频更重要的任务需重新验证。2｜质量指标冲突：Naturalness、Flicker、AV Sync 在部分数据集下降，不能以 Dynamic Degree 单指标替代感知质量。3｜评估器偏差：Qwen2.5-Omni 评分可能偏向更活跃的画面；AV-F1 的 ±3 帧阈值可能容忍肉眼明显错位。4｜硬件：CPU offload + batch1 可能让缓存收益受到传输、内存带宽和调度开销主导。5｜未报告：峰值显存、每步分支 FLOPs、真实生成吞吐、batch scaling、不同分辨率长视频的系统曲线。6｜复现：未核验到公开代码仓库，匿名 artifact 的可获得性需要独立确认。7｜理论：有界残差/Lipschitz 假设不保证 terminal refinement 是收缩映射，不能证明对所有质量函数有效。

16. Reproduction View：从最小 ablation 开始

关键模块：av_denoise_loop.py、audio_delta_monitor.py、cache_audio_prediction.py、skip_av_attention.py、terminal_recouple.py、profile_steps.py、eval_avsync.py。数据预处理：先固定 General-80 中 8–16 个公开/自拟 prompt（猫扑球、关门、拍手、打鼓、流水、多人说话），同一 seed 100、同一音视频长度与分辨率；视频质量和声音质量评估需保证生成与评估所用 FPS/音频采样率一致。

最小实验：如果拿不到 H20/22B，先在可公开运行的双流音视频扩散模型上做机制验证，不声称数值可与论文直接比较。保持 30 步（若模型原生 step 不同则固定它的官方配置），实现 Full、Audio-cache、Video-cache、Audio-cache+3-step recovery、Fixed-20%、Dynamic(θ=.30,W=3) 六组。每个 prompt 至少 3 个种子；记录每步 Δ_a、cache 命中次数、audio/video/AV attention CUDA event 时间、总 latency、peak allocated VRAM、CLAP、AV-F1、Dynamic Degree 和主观 A/B 评分。最先跑的实验：同一视频只改“缓存 audio vs 缓存 video”，观察终端 0/1/3/5 步对 CLAP/Dyn 的 gap closure；这比一开始追求 1.35× 更能验证论文机制。

容易踩坑：把 cache 的 ŷ_a* 当成 audio latent、没有运行 scheduler；跳过 cross-attention 时连视频 text conditioning 一起误删；t 与 k 索引相反；开启 CPU offload 后 profiler 只统计 GPU kernel 不统计 H2D/D2H；不同 prompt 使用不同分辨率却直接平均 latency；只报视频 Dynamic Degree 忽略 Naturalness/AV Sync。最敏感超参数：θ、W、terminal steps、audio/visual CFG、分辨率、是否使用 distilled LoRA、CPU offload。最关键 Claim 的判据：在相同跳过步骤数下 audio-cache 经 terminal recovery 的质量恢复显著高于 video-cache，且 wall-clock 确实小于 Full AV。

维度 判断与理由
Baseline Potential 中高：双流音视频 diffusion 的训练自由缓存基线；需要公开可运行实现才能高效复现
Migration Potential 高：将“可恢复性”从音频/视频分支迁移到时间段、token 组、工具观察、推理阶段
Systems Potential 高：直接减少 denoiser 与 cross-attention 调用，且有 wall-clock 证据；需补 profiling/并发/显存
Attack Potential 中：构造多声源突变 prompt，使 Δ 小但未来事件复杂，诱发过早 cache 与错位
Evaluation Potential 高：不同 branch 的 recovery curve 比单一 final score 更能区分误差可修复性
Benchmark Potential 中高：AV-hard 按音频事件密度、视频运动强度、可恢复性分桶很自然
New Paper Potential 中高：若能做可预测的 recoverability-aware compute allocator，并在多模型/硬件证明 Pareto 优势

18. Migration A：长视频理解的“可恢复信息”驱动 token pruning

Original Problem →联合音视频生成的各模态对缓存误差的可恢复性不同。Transferable Mechanism →不是直接按注意力/冗余删 token，而是估计删除后下游能否从保留信息中恢复关键证据。New Research Question →长视频 QA 中，哪些帧信息可以靠相邻帧或模型记忆重建，哪些动作转折一旦丢失就不可恢复？Method Modification →为每个 frame segment 构造轻量 reconstruction probe：屏蔽该 segment 后，用相邻帧特征/短期记忆预测事件标签；低恢复率的片段保留，高恢复率片段合并/压缩。再用 query-aware temporal saliency 对转折事件加权。

Minimum Experiment →build_segments.py --fps 1 --segments 16 --seed 42；对 NExT-QA temporal 100 个问题、MVBench 100 个视频各抽最多 32 帧；在 8/16 帧预算下比较 uniform、CLIP similarity、motion-based、recoverability-aware；以 32 帧结果作 teacher，遮掉每个 2-frame segment 计算事件答案变化和 feature reconstruction error。先不训练新模型，只实现 score 与选择；eval.py 记录 QA accuracy、temporal question accuracy、frames、visual tokens、prefill ms、peak VRAM。Model →Qwen2.5-VL-7B / 可运行 Video VLM；Dataset →NExT-QA、MVBench；Baseline →uniform、query-aware、motion；Metric →QA、token/latency、critical-event recall；Expected Contribution →可恢复性约束的视频 token 预算分配；Risk →“feature 可重建”不等于“因果事件可回答”；Collision Risk →与 adaptive frame selection、video token pruning、temporal memory 方法重合，必须加入可验证的反事实删除-恢复曲线和真实 wall-clock 才能形成新贡献。

19. Migration B：多模态 Agent 的阶段性缓存与错误恢复

Original Problem →音视频 joint denoising 的中段计算存在可省的分支。Transferable Mechanism →根据状态变化和恢复成本，把高频执行拆成完整预热→安全复用→关键时刻重新同步。New Research Question →Agent 在连续 GUI/视频观察中，能否缓存变化缓慢的环境表征，而对不可恢复的关键动作/状态转换保留全量感知？Method Modification →以视觉 embedding 变化率与 tool-state diff 共同触发缓存；连续 W 次变化小则重用 observation summary /视觉特征，但对 click、submit、error、navigation、new speaker 等事件强制重新观测；每 N 步或任务结束前执行 full refresh。相当于将 Phase C 改成“关键决策前恢复完整感知”。

Minimum Experiment →在固定的 BrowserGym/WebArena-like 本地任务环境录制 100 条轨迹，每步保存 screenshot、DOM、tool action、reward；实现 agent_cache.py --theta 0.1 --window 3 --refresh_before submit,click_navigation --seed 42。对 Full observation、fixed-interval refresh、embedding-threshold cache、event-aware cache 四组离线回放/在线重跑；对每条轨迹记录观察调用次数、视觉 token 数、工具选择一致率、任务成功率、错误累积长度、TTFT 和 end-to-end latency。Model →Qwen2.5-VL-7B / 可用 GUI Agent；Dataset →BrowserGym mini tasks、可复现的本地 GUI 流程；Baseline →no cache、every-3-step、cosine-threshold；Metric →success、wall-clock、stale-state action rate、recovery latency；Expected Contribution →带风险约束的 agent perceptual cache；Risk →细小按钮状态变化在 embedding 空间不可见，导致灾难性误点击；Collision Risk →agent observation compression、screen differencing、memory refresh 已有研究，需要证明 recoverability-conditioned refresh 优于普通阈值并可跨任务泛化。

20. Attack / Verification Lens

Attack：构造“前 5 步声音变化小、第 6 步突然爆发多事件”的 prompt 或音频轨迹，使阈值提前触发，测音画错位、CLAP/AV Sync 降幅；这是 robustness stress test，不是系统安全漏洞声明。Black-box probe：闭源生成器若支持可控 seed 与缓存开关，可做同 prompt paired outputs；无法访问分支时不能宣称测得内部 cacheability。Robustness：事件密度、声音类型、视频速度、分辨率、生成长度、seed 逐轴扫描。Efficiency stress：CPU offload on/off、H20 vs A100/4090、batch1/4、不同分辨率、不同末端 steps。Recovery：用 Recovery(m,k)=(Quality(cache+m steps)−Quality(cache+0))/(Quality(full)−Quality(cache+0)) 测恢复比例，注意分母接近零时需排除/单独报告。Metric：Recoverability-Adjusted Compute Saving（节省 wall-clock × 质量恢复比例），同时报最差 10% prompt 的 AV Sync。Benchmark：按可恢复性标签构建音画双流缓存压力测试，而非只平均 80 个 prompt。

21. 如果只记住这篇：九句话

  1. CAVC 的目标是音视频联合生成加速，不是视频理解 token pruning。2. 它的关键发现是音频缓存误差较容易由末端 joint denoising 修复，而视频动作损失难以补救。3. 这种结论是特定模型上的经验发现，不能泛化成“音频天生比视频先收敛”。4. 方法分成联合预热、音频缓存/视频独立精修、末端重新联合三阶段。5. 缓存的是 audio denoiser prediction，不是直接冻结 audio latent。6. 中段真正少算的是音频分支和 AV cross-attention，视频 branch 仍完整运行。7. 单 H20、batch1 的三个 benchmark 有 1.10–1.35× wall-clock speedup，说明是实测而非 FLOPs 猜测。8. General-80 Naturalness 与部分 AV Sync/Flicker 指标下降，不能宣称无损。9. 最值得迁移的是“先测错误可恢复性，再决定省掉哪段计算”，而不是机械复用 audio-only 规则。

Cross-Paper Synthesis｜同一个 Cache 问题，两种互补视角

两篇论文恰好从“删掉/跳过某些计算之后会发生什么”切入，但优化对象不同：MoEZip 在 LLM prefill 后保留哪些历史 KV，保护的是后续 MoE expert routing；CAVC 在视频生成的迭代去噪过程中哪些分支可以不重复执行，保护的是不可轻易恢复的视频时序细节。前者研究的是压缩诱发的计算路径脆弱性，后者研究的是近似误差的末端可恢复性。它们都说明：只看 attention mass、特征相似度或理论 FLOPs 不够，必须知道近似如何沿未来计算传播，以及它是否能被纠正。

Combined Research Opportunities｜可以形成什么新研究

机会 A｜Recoverability-Conditioned Cache Budgeting（最值得先试）。将 MoEZip 的“受扰动敏感性”与 CAVC 的“未来能否修复”结合，对每个 cache 单元 j 定义三个可观测量：S_j = 删除/跳算引起的下游任务或路由变化；R_j = 允许有限额外计算后恢复的质量比例；C_j = 保留该单元的 wall-clock 成本。一个可探索的新启发式（不是两篇论文现成公式）是 priority_j = S_j · (1−R_j) / (C_j+ε)：影响大、难恢复、成本相对低的单元优先保留；容易恢复的单元允许更大胆缓存。若 S 或 R 难测，可用 offline perturbation lookup table 训练轻量 predictor，再在在线推理用 predictor 选预算。

最小实验配置：在同一 MoE 模型、Qasper/HotpotQA 各 50 条、keep 10%/20%，以 32-token 为 cache block 做逐块反事实删除；先测 answer NLL / expert flip 作为 S，删除后允许追加 0/1/2 个“恢复”操作（例如 retrieval refresh 或局部重读）测 R，记录每次额外 ms 为 C。比较 KVZip、MoEZip、仅 S、仅 R、S×(1−R)/C；先离线验证“高 priority block 被删除时伤害更大”，再做在线预算器。关键风险：恢复操作本身可能读取原文，产生额外成本或违反固定 KV budget；因此要同时报告 total bytes read 与 total latency，避免作弊式恢复。

机会 B｜视频 Agent 的可恢复事件记忆。长视频/GUI Agent 有两类状态：缓慢变化、可以从附近帧重建的背景；瞬间变化、错过就无法恢复的按钮点击结果、遮挡事件、声源切换。先在视频 QA 或 BrowserGym 轨迹上做 masked-segment recovery，测删掉某帧后最终 action / QA 是否改变，再根据 event irreversibility 选择高分辨率帧或重新调用视觉工具。它借用 CAVC 的恢复曲线和 MoEZip 的决策路径敏感性，但不能把没有 MoE router 的模型硬说成路由压缩；应把路径变化定义为 tool/action flip。

机会 C｜Efficiency Failure Benchmark。建立统一表格：压缩比例、被跳过的实际 kernel 时间、selection/trigger overhead、peak VRAM、quality、最差 10% 样本、恢复所需额外 compute、是否出现路由/动作翻转。对比只看平均分和只看 FLOPs 的旧评估。这个 benchmark 在 Agent + Video + Inference 三条主线之间有自然的迁移价值。

Collision / Overlap｜哪些是“相撞”，哪些只是类比

最强的机制交叉（不是已有论文间已证实的同题竞争）：Routing Fragility × Error Recoverability。MoEZip 说“某些 token 删除会使路由变化，所以要保护”；CAVC 说“某些分支即使近似了也能在最后修复，所以可以省”。统一问题是：在给定计算/显存预算下，怎样保护对未来行为影响大且不可恢复的状态？它们没有在同一模型、同一任务上比较，不能宣称一篇直接推翻另一篇。最需要警惕的真实文献重合是已有的 KV importance/attention eviction、query-aware frame pruning、dynamic diffusion caching、agent memory attribution；新工作要靠反事实干预、跨模型泛化和真实 wall-clock 形成差异。
