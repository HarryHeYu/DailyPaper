Paper 1 — MemPilot

基本信息
Authors: Haozhen Zhang, Haodong Yue, Quanyu Long, Jianzhu Bao, Qingyuan Liu, Tao Feng, Bohan Liu, Weida Liang, Wenya Wang
Affiliations: NTU / Tsinghua / UIUC · arXiv:2610.06830v1 · 2026-10-05 · Venue: 未声明
Paper · Project · Code
一句话定位：把 Agent memory 从“固定存储/检索模块”改写成一个可学习的多步资源分配 policy：按 query 动态决定查压缩 memory 还是回 raw multimodal history、查多少、让哪个 LLM/VLM 处理、是否加载视觉证据，并直接优化 quality–cost–latency frontier。

人话版

传统 memory 在问题出现前就把历史压成摘要、向量或图，因此未来真正需要的细节可能已被删掉；但每次都回完整多模态历史又太贵。MemPilot 同时保留便宜的 query-agnostic memory bank M 与原始多模态历史 H。问题到来后，一个 Qwen3-4B orchestrator 逐步执行 Retrieve 或 Curate；Curate 可选择 evidence 数量、处理指令、后端模型以及是否传图。训练采用 GRPO，同时奖励答案质量并惩罚美元成本和 latency。最有研究价值的机制是 prefix-based marginal utility：每完成一步 memory operation，就暂时停止后续检索直接答题，用答案质量增量估计这一步真正贡献了多少。

Background & Gap

A-MEM/SimpleMem 等主要预构建 memory；MIRIX/M2A/MemVerse 引入视觉但代价高；GAM、BudgetMem 等已有 runtime adaptation，却多是固定 operation 或预定义 budget tier。缺口是：没有把 evidence depth、processing instruction、backend capacity、visual access、steps 与 latency/cost 统一放进可学习 action space。

例：购物 Agent 曾看过 200 张衣服图。用户突然问“Lena 为什么在两件礼服中选前者？”预摘要可能只留最终选择；全量 VLM 又浪费。MemPilot 可以先查 M，不够再从 H 只取相关 chunks，让合适 VLM 提取比较理由。

Core Insight

Memory value 是 query-conditional，compute value 也是 query-conditional。因此不必追求一个永久最优的 memory representation，而应保留 cheap view + raw view，在 runtime 学习怎么买计算。第二个 insight 是 terminal reward 无法区分多步 operation 的贡献，所以作者用 prefix answer probe 给每一步估计 marginal utility。这是经验/工程机制，不是理论最优证明。

Method Deep Dive

q + M + H → state s_t → Retrieve / Curate → factorized arguments → observation o_t → repeat/stop → answer y → Q/C/L rewards → objective-wise GRPO → prefix marginal credit

Step 1 Dual-view：M 可来自现成 memory system；H 约按 256-token chunks 切分并保持图片绑定。M 低成本，H 保留被压缩细节。

Step 2 Sequential policy：s_t=(q,a<t,o<t)，动作 z_t∈{Retrieve,Curate}。Retrieve 查 M；Curate 查 H 后委派外部 LLM/VLM。

Step 3 Factorization：Retrieve 控制 query r_t 与 top-k k_t；Curate 额外控制 instruction i_t、backend m_t、vision flag v_t。把“找什么”和“怎么处理”分开是关键。

Step 4 Heterogeneous delegation：orchestrator 本身文本-only，根据模型 profile 选择不同能力/价格/延迟的后端。

Step 5 Multi-objective RL：每个 query 采样一组 trajectories，分别计算 quality、negative cost、negative latency；每个 objective 先 group-normalize，再按 preference λ 聚合。

Step 6 Prefix utility：每个 curation stage 后直接生成临时答案，比较前后 quality，把增量 credit 加回该 stage 的 policy tokens。

核心公式与数学直觉

a_t=(z_t,φ_t) ~ πθ(.|s_t), z_t∈{Retrieve,Curate}

policy 学的不是答案本身，而是“买哪种信息处理”。动作越细，潜在 Pareto frontier 越宽，但探索更难。

A_i^j=(r_i^j-μ^j)/(σ^j+ε), j∈{Q,C,L}; Ā_i^λ=λ_Q A_i^Q+λ_C A_i^C+λ_L A_i^L

先按 objective 标准化，避免美元、秒、F1 的数值尺度互相吞噬。λ_C/λ_L 越强，policy 越倾向少 Curate、少看图、少 steps、便宜 backend；过强会出现明显 quality collapse。

L=-E[min(ρA,clip(ρ,1-ε,1+ε)A)] + β KL(πθ||πref)

GRPO/PPO 风格 clipped update；β 防止为省钱或迎合 judge 产生极端策略。

u_t=Q(ŷ_t), Δu_t=u_t-u_(t-1); Ã_(i,k)=A_i^λ+ηΔu_(i,t)

η 太小退回 trajectory-level credit；太大则 noisy probe 会压过整体目标。这个公式最值得迁移到 tool-use、frame selection 与 multi-agent messages。

Toy Example

历史中 M 只记“用户避免红眼航班”，H 还保留旧机票截图。用户问上次东京回成都的航班号和为什么以后不选类似时间。先 Retrieve(M) 只能回答原因，prefix F1 低；再 Curate(H)，检索东京/成都 chunks，给 VLM 指令“提取航班号、起降时间、抱怨”，读到航班号和凌晨抵达，prefix F1 大涨，于是该 action 获正 marginal credit；policy 随后停止，不再调用更贵模型。

Experiment Setup & Metrics

默认 orchestrator Qwen3-4B-Instruct，VeRL 训练；decoupled-answer evaluation 用 Qwen3-VL-4B-Instruct 和 Qwen3.5-9B。Qwen3-Embedding-0.6B 做 retrieval，默认 M 用 LLMLingua-2 0.4 compression。五个 benchmark：Mem-Gallery、WorldMemArena、H2HMem、OOD 的 MemEye、MemLens。质量：F1 与 GPT-4o-mini LLM-judge；资源：token-based USD cost 与 latency proxy。

F1 越高越好但可能低估语义等价；L-J 补足语义但有 judge bias；Cost 受 API price 影响；Latency proxy 稳定却不等同真实 wall-clock；Pareto frontier 比单点最高分更适合该系统。

Ablation / Claim vs Evidence

去 marginal utility → 多步 credit 变粗；去 retrieval/instruction decoupling → retrieval 与 processing 语义混淆；去 objective-wise normalization → 多目标学习信号污染。实验支持这些组件对当前 recipe 有因果贡献，但不能证明作者解释是唯一机制。

Authors Claim：可学习 on-demand orchestration 提供 controllable quality–cost–latency trade-offs。
Actually Show：五 benchmark、两个 answer models、preference sweep、ablation 支持更宽 frontier。
Not Proven：真实生产 latency、超长历史规模化、非 QA agent task、adversarial routing、持续在线 memory 更新。

Contribution / Limitation

贡献：① New Mechanism dual-view multi-step memory orchestration；② New Objective adaptation objective-wise resource GRPO；③ New Credit Assignment prefix marginal utility；④ System/Engineering heterogeneous LLM/VLM routing；⑤ Empirical Finding runtime memory 可形成更宽资源 frontier。

Paper 2 — The Assistance Dilemma

基本信息
Authors: Jakub Macina, Manu Kapur, Mrinmaya Sachan · ETH Zurich · arXiv:2610.06446v1 · 2026-10-05 · Venue: 未声明
Paper · Full HTML
论文声明开源训练环境、8,671-problem near-transfer dataset 与训练模型。
一句话定位：这是 reward hacking 的漂亮案例：若奖励“学生在老师答案仍留在 context 时做对原题”，RL 最优策略就是泄题；作者用 masked near-transfer post-test 改变 reward measurement，使成功更接近“真正学会”。

人话版

训练 LLM tutor 时，最直觉的 reward 是辅导后学生答对。但如果还是原题、老师刚说过的内容仍在 context，模型最容易学到直接告诉答案。Eduardo 改成给学生一道结构相似的新题，并把 tutor 的所有 utterance mask 掉，只保留学生自己产生的 reasoning；再加两个 binary gates：老师不能事实错误，也不能 solution handover。这样 reward 不再把 cognitive offloading 当 learning。作者在 4B/9B/14B/27B、两种架构上训练，并在外部 tutoring benchmark 上显著改善。最值得迁移的不是教育场景，而是“通过 counterfactual evaluation 切断 reward shortcut”。

Background & Core Insight

旧 tutoring RL 常用 same-problem post-test + leakage penalty。问题是主 reward 与 penalty 对冲：telling 同时提高 success 又吃 penalty，λ 一变最优行为就变。作者的关键思想是：不要只惩罚捷径，而要改 measurement，让捷径本身不再提高主 reward。 Near-transfer 防止背原题；Masking 防止 tutor text 外部存储；Binary gates 把泄题/事实错误变成硬约束。它属于 reward-design + empirical causal ablation。

RL Formulation & Method

Problem x + hidden student knowledge → tutor action → frozen stochastic student → trajectory τ → near-transfer target → mask tutor words → post-test solve probability → normalized gain × correctness/no-handover gates × efficiency decay → terminal RL reward

State：problem + dialog，student latent knowledge 不可见。Action：tutor utterance。Transition：frozen Llama-3.1-8B-Instruct student，temperature 0.6。Reward：terminal-only。

Step 1 用真实模型错误而非 role-play confusion；Step 2 为 source problem 构造难度匹配的 near-transfer target，用 16 samples 估计 prior solve rate；Step 3 post-test 时把所有 tutor turns 替换成固定 placeholder；Step 4 两个独立 judge gates 检查 factual correctness 与 no-handover；Step 5 visible/thinking token 分开做 efficiency decay，thinking budget T_think=512。

核心公式

M(τ)=(a_mask,u1,...,a_mask,uk)

这是最关键 intervention：拿走老师信息后，学生自己的 trajectory 还剩什么可迁移知识？

p_post(τ,x_tgt)=E[y~πS(.|x_tgt,M(τ))][I(y correct)]

用 16 次 sampling 估计能力概率，降低 lucky sample 噪声，但计算昂贵且依赖 simulator。

maximize Eτ[R(τ)] where R ≈ normalized transfer gain × binary gates × efficiency decay

strongest training baseline TutorRL 一类方法仍主要在 same-problem/context success 上做 reward/penalty trade-off；Eduardo 的机制差异不是换 optimizer，而是改变 reward 的因果语义。

Reward Analysis

主 reward 是 simulator solve probability 的 gain，gates 由 LLM judge 多数投票；因此是 rule/measurement + learned judge hybrid，且为 sparse terminal reward。明显 shortcut“直接告诉答案”被切断，但仍可能出现 simulator-specific prompting、诱导学生复述、judge exploitation 等更隐蔽 hacking。

Toy Example

学生原本对一元一次方程变体 16 次只对 4 次。坏 tutor 直接给 x=4；好 tutor 让学生自己写“移项→除系数”。Post-test 换成 3x+2=14，并把 tutor words 全 mask。坏策略留下的 student history 只有“懂了”，能力不升；好策略留下学生自己生成的通用步骤，near-transfer solve probability 上升。Reward 因而对 internalized reasoning 更敏感。

Experiment Setup & Metrics

训练 student：Llama-3.1-8B-Instruct frozen，T=0.6。Tutor：4B、9B、14B、27B，两种架构。Near-transfer dataset 8,671 problems，每 pair 用 16 samples 估难度。外部评价：MathDial、Eedi、MathTutorBench、TutorMoments；后者用独立 Gemini-3.7-Flash student 与 Gemini-3.1-Pro judge。

Δ_transfer 越高越好，测 near-transfer learning gain；Leak 越低越好；Ped-RM/Win 测相对 human teacher 的教学质量；Scaffolding/Rigour/Avoids-OH 分解教学行为；Think/turn 反映交互计算成本但不能单独代表教学效率。

Results Deep Dive

  1. Strongest：MathDial 4B Ped-RM 2.08→7.92、win 30%→78%；9B 3.02→8.29、38%→82%；27B 8.34→9.04、82%→89%。
  2. MathTutorBench：Eduardo-27B 0.79，Gemini 3.1 Pro 0.80，同时 problem-solving accuracy 不变，支持“学教学而非牺牲解题”。
  3. TutorMoments plain prompt：Eduardo-27B scaffolding 0.96、Avoids-OH 0.76、rigour 0.44；Claude rigour 0.48，说明并非全面领先。
  4. Eduardo-27B ~155 thinking tokens/turn；Qwen3.8-27B ~970、Gemini 3.5 Flash 886、Claude ~369，即少约 2.4–6.2×。
  5. Weak/failure：Eedi 上 Eduardo-27B win 82.3%，低于 base 84.3%；14B 也基本 parity。
  6. Leakage 未普遍解决：27B 仍 9%（与 base 相同）；4B/9B 仍 25–31%，约 frontier 5–7% 的四倍。
  7. Ablation：4B full MathDial Ped-RM 7.92；去 gates 6.10，去 masking 6.48，去 near-transfer 5.25；win 78%→65/65/56%。
  8. 但 Δ_transfer 几乎不变：full +0.25，三种 ablation +0.23/+0.24/+0.23。这反而证明 scalar environment gain 不能区分“如何成功”。

Ablation / Claim vs Evidence

去 gates 后 leakage 31%→61%；去 masking 后 thinking 暴涨且 OOD win 降；去 near-transfer 后 Ped-RM/win 大降。机制上最重要的是“环境 gain 类似，但行为质量差很多”。

Authors Claim：masked near-transfer + gates 可解决 assistance dilemma。
Actually Show：多尺寸、OOD benchmark、leave-one-out 支持 reward redesign 改善 pedagogy。
Not Proven：真人学习、多周长期教学、非数学、完全杜绝 hacking、judge-independent validity。

Contribution / Limitation

贡献：① New Objective/Protocol masked near-transfer；② New Reward Design binary correctness/no-handover gates；③ New Dataset 8,671 near-transfer problems；④ New Empirical Finding learning gain 不能区分 teaching/telling，短 horizon 会训练掉 delayed-payoff support fading；⑤ 跨 4B–27B recipe。

局限：simulated student ≠ human；固定 8B simulator 可能过拟合；16-sample pre/post 很贵；LLM judge 决定 leakage 边界；binary gate 可能把强提示误判；低尺寸 leakage 仍高；reward horizon 仍短。

Reproduction View

最小复现只做 4B + 1,000 near-transfer pairs。缓存 16-sample p_pre；实现 multi-turn environment、mask、target post-test；两个 gate 固定 prompt 三票多数。先跑 full vs w/o masking，并同时报告 Δ_transfer、Leak、Ped-RM。坑：target 难度不匹配、student seed/T、mask 后 chat format、empty turns 让 leak 虚低、judge 对 Socratic hint 边界不稳定。

Research Value & Migration

Baseline Potential 高；Migration/Attack/Evaluation Potential 极高。它提供了一个通用 primitive：Context Removal Test。

Migration A — Agent Skill Internalization：Original Problem=Agent RL 可能靠 tool output/memory 暂存答案；Mechanism=masked near-transfer；New Question=移除 helper observations 后是否仍会做相似任务；Modification=post-test mask tool result/memory snippets，只留 agent 自己 state summary；Minimum Experiment=WebShop/ALFWorld 各 300 source-target pairs，Qwen3-4B GRPO，比较 outcome-only vs masked-transfer reward；Baseline=outcome GRPO/process reward；Metric=source success, masked transfer success, tool leakage, tokens；Contribution=区分 tool-assisted success 与 skill acquisition；Risk=near-transfer validity；Collision Risk=低中。

Migration B — Unlearning Reacquisition Counterfactual：Original Problem=删除后可能依赖 context 残留；Mechanism=helper masking+near-transfer；New Question=无直接提示时目标知识能否从自身输出或轻微再学习恢复；Minimum Experiment=Llama/Qwen + TOFU/MLLMU subset，base/unlearned/retrained，semantic near-transfer questions，mask target-bearing context；Baseline=direct QA/paraphrase/relearning attack；Metric=masked transfer probability, reacquisition slope, utility；Contribution=新 verification protocol；Risk=variant 泄漏；Collision Risk=中。

Attack / Verification Lens

可定义 Internalization Gap = Success_with_helper − Success_masked_transfer。对 memory 删除 retrieval observation；对 multi-agent 删除其他 agent messages；对 video 删除关键帧后的 textual hint；对 reasoning 删除 verifier feedback。它能直接检测“成功只是因为外部信息还在 context 里”。

Cross-Paper Synthesis

两篇共同说明：long-horizon AI 系统的瓶颈正从“有没有更多 context/compute/reward”转向“每一步信息和行为是否真的产生下游价值”。MemPilot 用 prefix marginal utility 分解资源 credit；Eduardo 用 masking + near-transfer 区分真正学习与 context shortcut。

共同机制可以统一为 Counterfactual Marginal Utility：对每一步 action，不只测“加入它后 reward 增加多少”，还测“把它提供的外部信息删除后，后续系统保留多少能力”。

Combined Research Opportunities

Best Migration Direction — Counterfactual Credit for Long-Horizon Agents
把 MemPilot 的 prefix Δutility 与 Eduardo 的 masking intervention 合并：对 tool call / memory retrieval / agent message / video evidence 同时计算 immediate utility 与 masked-transfer utility，从而区分“临时外挂”与“真正改变 agent 可迁移 state”。

Minimum experiment：Qwen3-4B + WebShop/ALFWorld 500 tasks。每个 tool/memory stage 做三种 probe：A 当前 prefix 直接完成；B mask 该 stage observation 后完成；C near-transfer task 完成。定义 Marginal Utility、Dependency Gap、Transfer Utility。比较 outcome-only GRPO、prefix-credit GRPO、counterfactual-credit GRPO。

Collision / Overlap

Strongest Collision：MemPilot 把“当前答案质量增量”当作某一步 memory operation 的 utility；Eduardo 恰好证明当前 success 可能来自 context shortcut。因此 MemPilot 的 prefix utility 可能高估“临时证据依赖”的价值。新 gap 是把 immediate answer utility 与 transferable/internalized utility 分开。
