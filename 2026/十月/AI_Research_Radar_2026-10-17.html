Mosaic: Multi-Session Agentic Reinforcement Learning

arXiv:2610.22174 · 15 Oct 2026 v1 · 研究正文约 2059 中文字 · 预印本（未核实会议录用）

Authors：Yilong Xu, Minrui Xu, Xinyu Zhou, Xiang Long, Haochen Tan, Zhijiang Guo
Affiliation：LARK / HKUST(GZ); Huawei Foundation Model Lab; City University of Hong Kong
Paper：arXiv Abstract / PDF / HTML · Project Page · Code: Not Verified

人话版：这篇论文到底干了什么？

现有 Agent RL 常把一次任务视作单一连续上下文，但真实搜索代理会压缩上下文、分叉子代理：一个任务因此跨多个 session。直接把最终成败的同一 advantage 广播到每个 session，无法区分真正贡献与冗余执行。Mosaic 同时按成功与否调整 session 数量的全局优势，并用正确答案对数似然的变化估计每段局部信息增益。Qwen3.5-4B 在 BrowseComp 的压缩模式中从 Broadcasting 的 35.31% 提升到 38.86%，平均 session 数从 3.17 降到 2.35。它的重要性是把“跨会话执行”正式变成可训练的 RL 单元。

Background & Research Gap

想象一个搜索代理先搜集证据，随后因上下文过长压缩历史，再委托子代理核实最后一个线索。最终答对了，但三段工作贡献不相同：一次无效搜索不应与关键证据回传获得完全相同的训练奖励。单 session GRPO 对整个 rollout 的一组奖励标准化，再把优势给所有 token；在 context compaction 后训练片段已分裂，fork 还会出现分支依赖。简单 Broadcasting 虽可训练，却不能判断应该多开 session 还是少开，更不能对错误压缩作负反馈。作者把“执行结构”视为 RL 的组成部分，而非外部 harness 的无关细节。

Core Insight / 观察证据

关键观察有两个：成功任务里过多 session 往往是执行成本，失败任务里极少 session 可能表示探索不足；而一段 session 是否有用，可以用它使模型更容易生成正确答案的程度近似。前者提供有边界的全局成本信号，后者提供局部信息增益。作者同时指出不同 session 类型的增益分布不同，不能把普通搜索、压缩和子代理的 raw gain 混在同一均值方差里。注意：答案似然上升不等价于因果贡献，这是本工作的核心可延伸缺口。

Method：Input → Steps → Output

Input：带标准答案的深搜任务 x 与多条在线 rollout。Step 1：每条 trajectory 拆成 normal、compaction、subagent 等 session；保留其前后可见上下文状态。Step 2：对同题多条 rollout 的终局二值 reward 做 GRPO 标准化。Step 3：按成功/失败分别给 session 数排序，得到 [-1,1] 的中心化 rank u；用 (1−ρu) 调节全局 advantage，确保成功/失败的主排序不被 session 数颠覆。全成功/全失败组启用保守 fallback，避免优势全为零。Step 4：在每个 session 前后，用冻结的 rollout policy 计算正确答案 y* 的平均 token log-probability Φ；两者差 ΔΦ 作为局部 reward。Step 5：按 session type 在同一 prompt group 内标准化 ΔΦ；最后一段因直接输出答案而被置零以防泄漏。Step 6：A_session=A_global+λ·normalized(ΔΦ)，再分配给该段可训练 token，用裁剪的 GRPO 更新策略。Output：更会分配 session、且会区别训练不同片段的搜索 Agent。

Toy Example：把方法放到一个具体场景

问题“哪位研究者在两所机构先后工作并发表某篇论文？”Session A 找到论文作者，B 压缩记录，C 子代理验证履历。若 B 丢掉作者消歧证据，最终失败；Mosaic 可能因 B 后答案似然降低而惩罚 B，但若 C 独立找回证据，B 的真实边际影响会被补偿。这个例子说明局部势函数与全局反事实之间的差别。

Objective / 公式直觉 / 关键超参数

State=每个 session 的可见上下文与任务状态；Action=search/visit/compact/fork 中可训练的语言与工具选择；Policy=Qwen3.5-4B；Reward=最终答案经 judge 验证的二值结果+ΔΦ shaping；Trajectory=含 N 个 session 的 rollout；Advantage=同题组归一化结果、session-count rank 调制、type-wise ΔΦ；Objective=裁剪 GRPO+KL；Entropy 系数为 0；Credit Assignment=全局与局部两级。奖励为终局 sparse + 局部近似 dense，不是人类逐步打分。训练样本数每轮 16×8=128、63 轮；GPU 小时/实际训练 token 未见明确总量，不作推断。

Experiment Setup / Research Questions

模型 Qwen3.5-4B；训练 REDSearcher_RL_1k 的 1,000 个深搜任务；评估 BrowseComp 共 1,266 题，采用 ReAct 风格 search/visit。两种推理/训练循环分别为 context compaction 与非嵌套 subagent forking。基线：未训练 Qwen、单会话 GRPO、IGPO、多会话 Broadcasting。每批 16 prompts、每题 8 rollouts，63 轮迭代；学习率 1e−6，KL 0.001，ρ=0.2，β0=0.1，β1=0.2，λ=0.1。RQ1：多会话训练是否优于只在推理期加 harness？RQ2：全局 session 调节与局部 shaping 各自有效吗？RQ3：增益和 session 分配是否按预期改变？RQ4：不同类型 session 的信息收益是否可区分？论文没有在其他大规模 backbone 或真实生产工具链做广泛复现。

Results：数字、强基线与弱结果

Table 1：compact 模式原模型 24.80、单 session GRPO 34.68、Broadcasting 35.31、Mosaic 38.86；相对 Broadcasting +3.55 个百分点，session 3.17→2.35（减少约 25.9%）。subagent 模式 31.44→32.46（+1.02 点），session 4.43→3.77。Table 2：compact 正信息增益 session 比例 47.74%→59.92%；subagent 41.15%→51.04%。IGPO 在 compact 只有 31.36%，说明单纯 turn 级 IG 与 session 级训练并不等价。最弱之处是 subagent 收益较小，尤其分叉图的局部 ΔΦ 未必覆盖下游分支影响。

Table / Figure Reading

Figure 1 对比连续轨迹与压缩/分叉产生的多 session 轨迹，确立问题定义。Figure 2 把全局 rank 修正与 session ΔΦ 两条信号汇合成优势。Table 1 是必须优先读的主结果：除了 accuracy，还必须看平均 session 数；否则容易把更多调用造成的收益误认成训练收益。Figure 3(c,d) 的消融显示两模块分别贡献性能，但 subagent 中联合增益有限。Figure 5 比较 session 数与 advantage 的排序及不同类型增益分布，支撑 type-conditioned normalization 的动机。Table 2 的 Positive-IG 比例是中间机制指标，不是独立任务成功率。

Ablation / Analysis

作者移除 session-aware advantage 或移除 session-level shaping，性能均退化；两者叠加在 compact 模式更明显，在 subagent 模式提升有限。全成功/全失败时的 fallback 使同奖组仍有可学习排序。不同 session 类型独立标准化可避免压缩片段因平均增益偏低被系统性惩罚。消融主要是作者给出的趋势图而非完整置信区间；报告不把图上未明确标注的点数伪装成精确数值。

Authors Claim vs Evidence vs Not Proven

Authors Claim：multi-session Agent RL 应成为通用设置，分层 critic-free 优势能改善效果与效率。Experiments Actually Show：在 Qwen3.5-4B、BrowseComp、两种特定 harness 中，准确率与平均 session 数同时改善，局部信息增益比例提高。What Is Not Yet Proven：Δlog P(y*) 是否是无偏因果贡献；复杂 DAG、多代理共享 memory、长时间跨任务复用、非二值 reward 及不同 backbone 的泛化均未充分证明。

Contribution / Research Value

Baseline Potential ★★★★★：很适合检验跨 Agent handoff 的 credit assignment；Research Migration ★★★★★：把 session 看作可训练轨迹节点。System Value ★★★★☆：真实 harness 会频繁 compact/fork；Benchmark Value ★★★☆☆：可构建跨 session 因果贡献测试；Attack/Evaluation ★★★★☆：可测试伪证据污染导致的似然误判；New Paper Potential ★★★★☆：在 DAG 结构上设计 counterfactual credit 与证据可验证性。应避免简单把 ΔΦ 改成另一个相似度分数，那会与本工作高度重合。

Limitation / Failure Propagation

作者讨论公开多会话训练数据和可复现实验环境不足，异步训练与黑盒 harness RL 尚待探索。额外局限：计算正确答案似然依赖 gold answer；压缩前后状态包含的信息可能由提示长度与格式变化影响；session count 不等于 token、时延或费用；fork 的 DAG 存在共享祖先与间接效应，直接差分难正确归因。还有 reward hacking 风险：模型可能学习制造看似提高答案似然的中间文本而非可靠证据。

Agent Architecture / State / Long-Horizon / Failure Propagation

Architecture：任务→ReAct 规划/工具→普通 session→可选 compaction 或 fork→search/visit→answer verifier→session advantage 更新。State 包含当前上下文、工具历史、压缩摘要与子代理回传；没有证明持久化跨任务 memory 的长期收益。10/100/1000-step 逐级生存曲线未报告；不应把 128K context 限额等同 1000 步有效性。失败传播：错误压缩可删去关键证据，子代理的错误摘要会成为主代理的可信输入，再污染最终答案与后续训练。

Research Migration / Minimum Experiment

Original：跨 session 深搜 RL → Mechanism：全局结果与局部信息增益分层归因 → RQ：子代理 handoff 中，移除某段证据是否真正改变最终正确率？ → Modification：在固定下游随机种子下对 session 摘要做 evidence-preserving ablation，估计反事实边际贡献，再用 verifier 校验引用 → Minimum Experiment：100–300 个多跳任务、每题 4–8 轨迹、对关键 handoff 重放 → Model：Qwen3.5-4B 或同级开源 Agent → Dataset：BrowseComp 可复现子集 / HotpotQA 多跳子集 → Baseline：Broadcasting、Mosaic、random credit、ΔΦ-only → Metric：成功率、credit 与删段性能变化的相关性、token/cost、false attribution → Contribution：更因果且可审计的 handoff credit → Risk：重放开销和工具非确定性。

补充机制与证据审计

Contribution 1（New Setting）：将 multi-session trajectory 正式纳入 RL 的可训练对象，session 不再只是运行时压缩技巧。Contribution 2（New Objective）：将成功率、session 数和局部答案信息增益合成分层 advantage；其中全局项始终保持成功/失败的符号约束。Contribution 3（New Empirical Finding）：compact 与 fork 的收益并不对称，说明 DAG 结构会使局部差分归因变难。注意，本文没有引入全新通用 benchmark，不能把 BrowseComp 误标为作者原创。

五句话总结 / Worth Deep Reading

① 把 multi-session 从工程技巧提升为 RL 训练单位。② 成功率和 session 成本必须一起看。③ ΔΦ 让局部训练信号可算但并非因果真值。④ fork DAG 是比线性 compaction 更难的归因问题。⑤ 最值得迁移的是“结果约束下的结构化局部 credit”，而不是照搬超参数。

KnowGPO: Knowledge-Grouped Policy Optimization for Search Agents

arXiv:2610.22331 · 15 Oct 2026 v1 · 研究正文约 2000 中文字 · 预印本（未核实会议录用）

Authors：Siqi Chen et al. (13 authors)
Affiliation：Zhejiang University; Tencent
Paper：arXiv Abstract / PDF / HTML · Code: Not Verified

人话版：这篇论文到底干了什么？

深度搜索 Agent 的终局 reward 很稀疏，同一问题的多条搜索轨迹虽然网页与查询完全不同，却可能已经获得相同的关键知识。KnowGPO 先把问题拆成可核验的原子知识条件，再用已满足条件的集合表示搜索状态；从同一知识状态出发的动作在组内比较“新增了多少条件”，生成 step-level advantage，并与最终答题 reward 混合。Qwen3-8B 在 BrowseComp-ZH、GAIA 与 Xbench 的四个评估切分均超过 GRPO。它将 credit assignment 的对齐对象从表面 observation 改成知识进展，是面向 Agent memory 和工具归因的高迁移价值机制。

Background & Research Gap

搜索代理常在几十轮中反复打开不同网页。假设两条轨迹分别搜索论文作者的姓名和机构，网页链接、摘要措辞完全不同，但都已经确定“作者是 A、机构是 B”。以网页文本或内部 hidden state 对齐，无法可靠认定它们处于同一进度。GRPO 仅按最终对错给整条轨迹同一优势；GiGPO 依赖状态匹配，IGPO 使用信息增益但容易受模型置信度和上下文噪声影响。KnowGPO 试图用“完成了哪些可验证事实”建立更稳定的可比状态。

Core Insight / 观察证据

作者把复杂问题的必要知识拆成原子条件 K(Q)，例如“论文发表于哪年”“作者当时在哪个机构”。每次工具观察经过 LLM verifier 标成已获得哪些事实，累积为二进制 knowledge state。这样不同网页/不同搜索策略只要满足同一条件集合就进入同一个 group，比较下一步获得的新增知识数量。其核心是“先构建语义等价类，再做 group-relative credit”，而非单纯把最终 reward 变稠密。

Method：Input → Steps → Output

Input：问题 Q、参考答案 y*、成功参考轨迹以及在线搜索轨迹。Step 1：两阶段构造知识条件：先抽象问题推理骨架及实体占位符，再利用标准答案和成功轨迹填充，使条件尽可能原子、完整且实体一致。Step 2：每轮工具返回 observation，LLM verifier 判定新增可验证条件 Δs_t；累计 s_t=s_(t−1) OR Δs_t，形成单调知识状态。Step 3：同题采样 N 条轨迹，对终局 binary reward 标准化得到 A_episode。Step 4：把不同轨迹中“行动前具有相同知识状态”的非终止步骤归入同组。Step 5：每步新增知识 r_t=||s_t||₁−||s_(t−1)||₁；在对应知识组内标准化得到 A_step。Step 6：用权重 ω 将全局与局部优势混合，广播给该动作 token，按策略梯度更新。Output：倾向于在同等已知信息下采取更有效下一步的搜索 Agent。

Toy Example：把方法放到一个具体场景

问题要求找“2020 年后某获奖项目的联合负责人”。搜索 A 打开新闻，B 打开项目官网，均得到负责人姓名；两个网页字符串完全不同，但知识状态都从 {获奖项目} 变为 {获奖项目,负责人}。从此状态继续搜索获奖年份，A 找到正式名单而 B 重复打开新闻；组内比较就能奖励 A 的新增条件。若新闻是假信息，单调状态仍可能被错误置位，这是需要 provenance 的原因。

Objective / 公式直觉 / 关键超参数

State=累计已满足知识条件的集合；Action=查询、访问网页及后续搜索决策；Policy=Qwen3-8B；Reward=终局是否答对的二值稀疏信号+新增知识条件数量的密集过程信号；Trajectory=多轮工具交互；Advantage=A_episode 与 A_step 按 ω 融合；Objective=group-relative policy optimization；Credit Assignment=从相同知识状态出发的步骤组内比较。ω=0.3 是主实验配置。探索奖励并非“网页越多越好”，而是知识状态真正变化；验证器错误与 reward hacking 是主要风险。训练 GPU/总 token/wall-clock 若未明确给出则 Not Reported。

人话版：这篇论文到底干了什么？

少步自回归视频生成每个 chunk 只需几次去噪，但传统推理仍让所有视觉 token 做完相同次数的 denoising。作者发现同一 chunk 中不少 token 早已接近最终输出，只有局部复杂区域需要继续细化。Speculative Forcing 把中间 clean estimate 当作草稿，由 training-free 或轻量 learned verifier 判断是否提前“提交”该 token；已提交 token 不再计算后续去噪，但保留 KV 供未完成 token 参考。LongLive 四步基线在 5 秒视频上 26.40 FPS，方法约 41.74–43.61 FPS 且 VBench 分数相当；长视频和世界模型也有加速。关键是从整帧/整步预算转为 token 级自适应计算。

Background & Research Gap

传统 few-step video diffusion 已把几十步压到 4 步左右，但每一步仍对所有时空 token 重算。设想一个镜头里背景墙几乎不变、只有人物手臂快速移动：背景 token 可能第 1 步已稳定，手臂区域第 4 步才收敛。固定 4 步浪费背景计算；固定 2 步又可能损伤手臂细节。已有缓存或 motion-based 跳步通常按整帧、chunk 或时间点决策，无法细致区分同帧不同区域的收敛速度。

Core Insight / 观察证据

作者比较中间 clean latent estimate 与原本 4 步最终 latent 的距离，观察到不同 token 收敛不一致。由此提出“局部早停+保留上下文”：接受 token 后不再更新它，但仍将它的 K/V 留给活跃 token。Verifier 不必真正计算未知的最终输出：training-free 版本用与已有 clean 内容的冗余性、相邻草稿稳定性作代理；learned 版本用冻结生成器中间特征预测剩余 gap。两者都不改原生成器权重。

Method：Input → Steps → Output

Input：预训练少步自回归视频/世界生成器、当前 chunk 的噪声 latent 与历史 KV。Step 1：所有 token 先做第一个 denoising step，形成 clean estimate 草稿。Step 2：对活跃 token 运行 verifier：training-free 先看与历史 clean 内容的相似性，后续步看相邻草稿变化；learned head 则从中间特征估计与 full-step 输出的相对 gap。Step 3：若 gap 低于容忍阈值 ε，则 commit 此 token 并冻结其值；未通过者按原采样过程继续。Step 4：commit token 不再参与后续 denoising 的 query 更新，但其 KV 保留，供仍活跃的 token 使用。Step 5：直到所有 token commit 或到最大 K 步；将不同 step 接受的 token 组合为 chunk。Step 6：原生成器的 clean pass 刷新下一 chunk 的 KV。Output：接近原 K-step 质量、但平均每 token 计算步数更少的流式视频。

Toy Example：把方法放到一个具体场景

四步视频去噪中，静态背景 token 在第 1 步已与最终结果接近，运动人物 token 需第 4 步。若 70% token 第 1 步 commit、30% token 第 4 步 commit，平均步数为 0.7×1+0.3×4=1.9，理论 denoising token evaluations 从 4N 降至 1.9N；但 KV 更新、clean pass 和 verifier 仍有成本，真实 FPS 不会严格按 4/1.9 增长。

Objective / 公式直觉 / 关键超参数

对 video token i 定义收敛间隙 rel_k(i)=||draft_k(i)−full_K(i)||₂/σ；在阈值 ε 下提前提交，平均去噪步数 k̄=Σ_i k*(i)/N。ε 越大越快但可能损伤质量。full_K 仅用于离线监督/校准，推理时 verifier 不能偷看最终输出。

Experiment Setup / Research Questions

两个生成器：LongLive（5 秒与 30 秒视频）和 Lingbot-World 2.0（带相机运动的世界模型）；评估 VBench、VBench-Long、Drift、RPE 与实际 FPS。主基线为相同生成器固定 1/2/3/4 步，验证器比较包括 training-free、learned head、motion-based 等。5 秒 LongLive 的 FPS 在单张 H100 上报告。RQ1：能否在维持 4-step 质量时减少平均 token steps？RQ2：长视频误差会不会累积？RQ3：相机运动世界模型是否仍可早停？RQ4：阈值与验证器类型如何影响速度质量边界？论文不直接声称可以无修改迁移到 Video VLM 的理解任务。

提高容忍 ε 会提前 commit 更多 token，FPS 增加，但过高阈值引入未充分去噪的形变。Table B 在 Lingbot 相近平均 2.5 步时：per-token MLP 24.8 FPS、Drift 2.899；带时空平滑 head 24.5 FPS、Drift 2.839，显示邻域一致性有助于稳定。motion-based 信号可能把真实相机运动误判为未收敛，说明“运动小”不等于“预测已稳定”。作者还比较训练时采用 on-policy 截断轨迹，未发现优于标准 head 的明确优势。

Authors Claim：token-wise speculative commitment 在视频生成与世界模型中减少计算且保留质量。Experiments Actually Show：在 LongLive/Lingbot 的已测设置下，平均 denoising steps 下降，实测 FPS 提高，VBench/Drift 近似维持。What Is Not Yet Proven：任意视频模型的通用性、所有动态场景的视觉无损性、长期交互上千 chunk 的稳定性、显存下降量以及训练 verifier 的整体投入回报。

Method：Input → Steps → Output

Input：冻结 base model、Text-to-SQL 问题与可执行验证器。先采样 SQL 候选，用 correctness 与策略特征构建 quality-diversity archive；RL 期间采样新轨迹做 GRPO；同时对 archive 中 elite solutions 加 replay loss，抑制训练把这些策略概率压到极低。最终在准确率、策略覆盖与 base 策略保留率上共同评估。区别于普通 replay：档案不是 IID 随机抽样，而强调 distinct correct strategies。

将观察方式、工具执行方式和部分 harness state control 交给模型选择，使已有代码能力直接作用于桌面任务。评估时应同时报告模型、工具权限与 harness 配置，否则跨系统分数不可比。

Method：Input → Steps → Output

输入用户电脑任务。模型在视觉/程序化接口之间选择；执行脚本或 GUI 操作，读取结果后继续规划；harness 将部分固定决策开放给模型。输出完整可执行工作流。需要核对安全沙箱与权限控制，不能假设代码执行天然安全。

Experiment Setup / Research Questions

OSWorld-v2、八种模型配置，比较 full OpenGCUA 与 batched GUI-only。RQ：程序化接口与 harness-to-model 决策转移是否改善效率与质量？主要指标 partial score、steps/task。

Results：数字、强基线与弱结果

平均 partial score +19.6 点；reported steps/task 平均下降 53.0%。这些是跨八模型的平均值，不能声称某个具体模型一定获得相同改善。步骤下降不直接等于 wall-clock、费用或风险下降。

Contribution / Research Value

适合复现 Agent tool-use 的 harness effect，研究 action-space choice 与 policy training 的耦合；也可作为多 Agent 系统的可控底座。

Limitation / Failure Propagation

执行脚本扩大攻击面；模型选择接口可能受环境权限影响；partial score 与完全任务成功率不是同一个指标。

Research Migration / Minimum Experiment

在相同电脑任务中固定模型、切换 GUI-only / code-only / mixed policy，统计成功率、工具调用、总时间、错误恢复；风险是权限差异造成不公平。

补充机制与证据审计

混合工具接口引入了新的安全变量：脚本执行权限、文件修改范围和 GUI 可观察性必须固定。研究报告应区分 partial score 与完整成功率。 对照需固定工具权限。 尤其注意成本。

FilterFusion: Prior-Guided Adaptive Filter Fusion for Efficient Video Denoising

Authors：Wenlong Yang et al. (6 authors)
Affiliation：Tsinghua University; Microsoft
Paper：arXiv Abstract / PDF / HTML · Code: Not Verified

人话版：这篇论文到底干了什么？

实时视频去噪同时遇到传感器噪声、压缩伪影与运动不一致。深度 CNN 可以高质量但太慢，传统滤波快却难适应局部情况。FilterFusion 用低分辨率控制器预测混合权重，再在原分辨率融合一组规则滤波分支，把学习能力集中在“如何选择滤波器”而不是让大网络处理每个像素。仅 109K 参数、0.18 GFLOPs（network-only），在 CRVD 上达到 PSNR 34.72 dB、SSIM 0.9330；1080p 单 CPU 线程 C 实现合成路径 17.9ms/帧（55.9 FPS）。这是系统可部署性与质量权衡的典型案例。

Background & Research Gap

视频去噪的混合噪声具有时空不均匀性。逐像素深度重建成本高，而固定 Gaussian/median 滤波器无法根据局部噪声和运动自动调节。

Core Insight / 观察证据

学习低成本控制信号，再由高分辨率规则滤波库完成合成；把大部分高分辨率计算交给规则、易编译的算子。

Method：Input → Steps → Output

输入多帧视频和空间/时间方差先验。低分辨率控制网络输出权重图；高分辨率分支计算 Gaussian、median 等滤波结果；按权重融合，得到去噪帧。训练目标兼顾重建质量；推理阶段可用 C 实现规则合成。

Experiment Setup / Research Questions

CRVD 真实噪声；指标 PSNR、SSIM、network-only GFLOPs、1080p CPU 单线程合成路径 FPS。与 lightweight CNN 和传统滤波比较。RQ：质量是否超过传统滤波、CPU 实测是否满足实时？

Results：数字、强基线与弱结果

PSNR 34.72 dB、SSIM 0.9330、0.18 GFLOPs、109K 参数；17.9ms/帧即 55.9 FPS，较论文所选 lightweight CNN baselines 快 122–252×。必须注意 17.9ms 是 synthesis path 的 CPU 实测，不可误写为所有输入预处理和控制网络都包含的整机端到端延迟。

Contribution / Research Value

迁移启发是“低分辨率学习控制、高分辨率规则执行”，可用于 Video Agent 的低成本预处理或 adaptive resolution，但需要重新验证 QA 质量。

Limitation / Failure Propagation

网络 FLOPs 不含所有规则滤波操作；合成路径速度不等于完整视频流水线。研究对象是去噪，不是 Video LLM token acceleration。

Where, How, and When: Query-Guided Grounding for Video Understanding

Authors：Yogesh Kumar
Affiliation：请以原文为准
Paper：arXiv Abstract / PDF / HTML · Code: Not Verified

人话版：这篇论文到底干了什么？

这份视频理解方向的论文/学位论文把“视频中发生什么”拆成三个互补问题：where（目标在哪里）、how（实体如何交互）、when（事件发生在哪段时间）。作者分别介绍 query-guided 目标定位 QDETRv、跨帧高置信特征传播的 TOViT、关系查询下的结构化推断，以及用于 moment retrieval 的 MATR。它不是直接的 Video Acceleration 工作，但其中的 query-conditioned grounding 与时序记忆可作为高效视频理解的基础：先明确用户要找的证据，再决定哪些帧和区域值得高成本处理。

Background & Research Gap

常规视频编码可能均匀处理所有帧，却未明确用户询问的是物体、关系还是时间片段。不同粒度的 grounding 需要不同证据；统一池化可能丢掉细粒度定位。

Core Insight / 观察证据

把查询拆成对象、关系、时刻三种约束，分别采用 temporal memory、关系图和动态对齐。此工作提供问题结构化视角，不应被包装成已证明的计算加速算法。

Method：Input → Steps → Output

对象层：QDETRv 将查询与上下文融合并做目标定位，TOViT 传播高置信对象特征；关系层：针对主语-谓语-宾语查询，用图结构与 message passing 推断；时间层：MATR 结合动态时间规整与边界预测，定位相应片段。

Experiment Setup / Research Questions

涉及视频目标检测、关系定位、video-to-video 和 text-to-video moment retrieval 等任务。当前已核对的摘要没有给出统一 FPS、FLOPs 或内存比较，因此不能归入高等级 Video Acceleration。

Results：数字、强基线与弱结果

作者报告部分任务达到与 SOTA 可比或更好的表现，但本次可核验信息没有具体数值；按要求标注 Not Reported，不虚构性能提升百分比。

Contribution / Research Value

用于设计 Video VLM 的 query-aware token/frame selection 研究问题：先定位证据，再动态分配视觉计算。

Limitation / Failure Propagation

多个子工作组合而非单一统一机制；查询类型的划分可能无法覆盖开放式复杂视频推理；未证明减少编码帧数后质量不降。

Research Migration / Minimum Experiment

把 object/relation/moment query 作为路由条件，在 Video-MME/长视频片段检索中测试 query-aware frame budget；基线 uniform sampling；指标 QA、temporal IoU、latency、漏检率。

补充机制与证据审计

若迁移到高效 Video QA，应先证明 where/how/when 的证据类型能够预测必要帧和 token，而不是只把已有定位模型接到剪枝模块后宣称创新。 它适合作为方法迁移背景，而不是当天最重要加速成果。

Idea 1 · Evidence-Counterfactual Credit for Multi-Session Agents

Novelty ★★★★☆ · Feasibility ★★★☆☆ · Compute Cost ★★★☆☆（越高表示越昂贵）

Inspiration：Mosaic 用 ΔlogP(answer) 为 session 评分，KnowGPO 用知识条件增量，HTN-Orchestrate 用任务依赖传递证据；三者都需要回答“这段证据是否真正改变了最终结果”。

Research Gap：势函数与知识条件都是 proxy：错误网页可能提高答案似然，子代理证据还可能被后续分支重复找到。没有对“删除某段 handoff 后是否改变结果”的直接可复现检验。

Hypothesis：在预算受限下，只对高争议 handoff 做 paired counterfactual replay，可比 ΔΦ-only 更准确识别关键证据，改善多 session RL 的训练效率。

Proposed Method：先对 handoff 做可引用证据提取与 hash；用 ΔΦ、knowledge-gain 预筛高不确定片段；固定后续工具快照与随机种子，分别在保留/移除该片段的状态下重放下游；以 outcome 差异和证据 verifier 形成 credit，并对共享祖先做 DAG 去重。

Minimum Viable Experiment：100–200 个 BrowseComp/HotpotQA 多跳任务；每题 4 条 rollout；抽 2 个 handoff 做 paired replay。先只评价 attribution accuracy，不急于 RL 训练。

Model：Qwen3.5-4B；verifier 使用可核验引用或独立小模型

Dataset：BrowseComp 子集、HotpotQA 多跳子集

Baseline：Broadcasting、Mosaic、KnowGPO proxy、随机删除、oracle evidence

Metric：credit 与删段后成功率变化 Spearman；成功率；错误证据采纳率；replay cost；token

Expected Contribution：可审计的 DAG session counterfactual credit benchmark 与低预算近似方法。

Risk：工具环境非确定性、重放计算开销、不同 handoff 之间交互项不可加。

Collision Risk：⚠️ 与 Mosaic session ΔΦ、KnowGPO knowledge gain、HTN evidence carryover 高度相邻；差异必须落在受控反事实重放和 DAG 去重，不可仅换奖励函数。

Best Venue（投稿方向建议）：ICLR / ICML / NeurIPS（目标建议，非已录用）

Proposed Method：先用低分辨率/稀疏帧提取事件草图；对每个时空区域估计 query relevance、uncertainty 与运动新颖性；满足证据阈值的区域冻结或缓存，不确定区域继续高分辨率编码；遇到异常事件强制回退 dense。

Idea 3 · Diversity-Preserving Agent Skill RL

Risk：与 EliteReplay 在机制上接近；如果只把 SQL 换成 Agent 会缺乏新颖性。
