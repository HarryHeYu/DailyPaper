Tier SRLNEW · 10/18Trackable Skill Library Lifecycle Management for Agentic Reinforcement Learning

Xi Zhu; Yuanlin Duan; Changyi Yang; Kai Mei; Riyang Bao; Shichao Zhu; Dimitris N. Metaxas · 2026-10-18 v1 · arXiv preprint

arXiv / PDF metadata · 论文 HTML 全文 · Official GitHub

阅读定位：最值得读 §2.1 Eq.(5)–(9)、Table 1/2 与 Figure 3；它直接挑战“命中=贡献”的 Agent Memory 评价方式。

人话版：这篇论文到底干了什么？

Agent 训练时会把失败经验总结成技能，存入可检索的 skill library。但一个技能“被检索到”和“真的帮助成功”完全不是一回事：它可能搭了其他技能的便车，也可能早已被模型学会，继续塞进上下文反而有害。TrackRL 的核心是把同一问题的 GRPO 多条 rollout 当成小型随机对照试验：随机注入或屏蔽每条技能，估计技能对成功率的边际贡献，再追踪不使用该技能时模型能否独立完成任务。最终把技能从生成、孵化、保留到退休、移除做成有证据门槛的状态机，而不是凭相似度和使用频率粗暴清理。

Background & Research Gap：为什么旧方法不够

传统 SkillRL/D2Skill 类系统能生成和检索技能，却常将多个技能一起放入提示词；最终成功后无法判断究竟哪个起作用。假设“打开抽屉”和“先检查钥匙”同时被调用，成功并不说明两条建议都有效。更棘手的是策略会随 RL 更新：昨天必要的提示今天可能已内化，若永远保留，会遮蔽模型的真实独立能力。作者把 free-riding、任务难度混杂、缺少 counterfactual 三个问题合并为“可识别的技能效用”问题。

Core Insight 与 Observation

GRPO 本来就针对同一任务采样多条 episode，因此天然有同题、同阶段策略的比较基础。作者不是额外训练 reward model，而是在已有 rollout 中独立随机化每条技能的出现与否；不同技能的 treatment/control 交错形成近似因果对照。再用 skill-free control-arm 成功率测 mastery，便可区分“技能无用”与“模型已经掌握”。关键在于效用和掌握度是两条不同坐标，不能互相替代。

Method Deep Dive：Input → Output

Input：任务、当前策略 π、两级技能库。Step 1：按任务描述检索 task-level 技能，按当前 observation 检索 step-level 技能，结合语义相关性、历史效用与探索奖励重排。Step 2：在每个 GRPO group 内，独立对各技能抽 Bernoulli 注入开关，保留 skill-free rollout。Step 3：完成交互，得到终局成功与非法动作惩罚，照常优化策略。Step 4：按技能比较同题有/无注入的成功率，更新效用均值与标准误。Step 5：用未注入技能时的成功估计模型 mastery。Step 6：基于置信界和证据数执行孵化、退休、永久移除或保留。Output：更新后的策略与随策略演化的技能库。

关键公式 / Objective 与 RL Formulation

技能 s 在 group g 的效用对比为 d(s,g)=成功率(注入)-成功率(屏蔽)，可靠性权重 w=n+·n-/(n++n-)；跨组按 γ=0.98 折扣聚合得到 u(s) 及 SE(u)。mastery 用 control-arm 的 Beta(成功数+1,失败数+1) 后验均值估计。状态包含任务、环境观察、已调用工具与技能记录；动作是文本或 API 操作；策略为 Qwen3-4B；reward 主要是任务成败并含非法动作惩罚，组内归一化 advantage 更新。注意 skill utility 是额外统计量，不等于训练 reward。探索项鼓励尚未充分试验的技能获得曝光。

Toy Example：同一任务的四次试验

假设 8 次同题 rollout 中，某技能注入组 4 次成功 3 次，未注入组 4 次成功 1 次，则本组 d=0.75-0.25=+0.50；但这不是永久真实因果效应，只是当前策略和任务分布下的噪声估计。若若干轮后未注入组也达到 90% 成功，mastery 上升而 u 接近零，系统倾向退休而非删除；若 u 的置信上界仍小于零，才认定有害并移除。

Baseline / Setup / Research Questions

实验使用 ALFWorld（seen/unseen、最多 50 turn、Success Rate）和 AppWorld（normal/challenge、最多 40 turn、Task/Scenario Goal Completion）；同一 Qwen3-4B-Instruct-2507 策略从 base 或 SFT 初始化，比较 GRPO、SkillRL、D2Skill 与原始模型；反思模型使用 GPT-5.6-Luna 或 Gemini-2.5-Flash。RQ1：技能库是否提升带技能成功率？RQ2：不调用技能时策略本身是否提升？RQ3：不同初始化、环境和反思模型下结论是否稳健？RQ4：追踪与生命周期管理各自有多大贡献？

Results：数字 → Baseline → 差异

ALFWorld 冷启动、Luna 反思：带技能 seen 78.1%，SkillRL 62.1%，差 +16.0 点；unseen 71.9% 对 58.2%，差 +13.7 点。无技能 seen 72.7%，GRPO 58.6%，差 +14.1 点；unseen 64.1% 对 53.0%，差 +11.1 点。SFT 初始化下带技能 seen/unseen 为 98.4%/97.7%，D2Skill 为 96.9%/96.1%。AppWorld 冷启动 TGC-N 无技能 22.6%，GRPO 15.5%；SFT 后 TGC-N 无技能 34.5%，D2Skill 25.6%。最弱处是 AppWorld challenge 的绝对成功率仍偏低，不能把相对增益误解为复杂工具环境已解决。

Table / Figure Reading

Table 1 要分别看 skill-assisted 和 skill-free：如果只看前者，可能只是更会使用外部提示；两列一起提高才支持策略内化。Table 2 的 AppWorld TGC 与 SGC 区分“完成单任务”和“同一场景三个变体全部完成”，后者更严。Figure 3 消融：去 tracking 后 seen 带技能 SR 由 78.1% 降至 61.7%；去 management 后无技能 SR 从 72.7% 掉至 53.1%。Figure 4/5 展示技能规模与 utility–mastery 平面随训练变化，提示生命周期决策是动态的。

Ablation / Training Efficiency

去追踪导致联合注入的搭便车问题复现；去管理使技能依赖性增强，尤其伤害 skill-free 指标。每个训练 step 收集 128 episodes，ALFWorld 每个最多 50 turn，理论最多 6400 次策略生成调用；耗时主要在 rollout，非统计更新。作者说明随机 treatment/control 利用原有 GRPO rollout，不额外增加 episode，但 reflection 调用与验证仍有成本。论文未给出可跨硬件复现的总 GPU-hour 预算，不能宣称零额外成本。

Claim vs Evidence

Authors Claim：随机对照式技能归因可驱动技能库全生命周期，并促进策略内化。Experiments Actually Show：在两种环境、两类初始化和两种反思模型中，多项带技能与无技能指标优于所选 baseline；消融支持 tracking 和 management 的必要性。What Is Not Yet Proven：独立 Bernoulli 注入在技能强交互时估计的是平均边际效应，未识别所有高阶协同；模型长期非平稳会改变估计目标；没有 1000-step、跨 Agent 共享技能或敌意技能注入的安全性证据。

Contribution / Limitation

Contribution 1 [New Mechanism]：把 GRPO 同题 group 变为在线随机技能对照；Contribution 2 [New Metric]：分离 skill utility 与 model mastery；Contribution 3 [New System]：以置信区间、孵化和软容量治理技能库。Authors’ Limitation 可从实验范围观察：只验证两个 agent benchmark。Additional Limitation：低频技能难积累足够 treatment/control；检索候选本身可能引入选择偏差；模型更新和技能交互使因果解释需要额外随机化或分层分析。

Research Value / Migration

Baseline Potential：TrackRL 适合作为 agent skill/memory attribution 的强基线；System Value：可以落地技能退休、版本管理与回滚；Benchmark Value：可定义注入干预下的因果效用稳定性；Attack/Evaluation：测试恶意技能在何种证据阈值下被误留。Original Problem（单 Agent 技能）→ Transferable Mechanism（同题随机注入 + 双轴效用/掌握度）→ New Research Question（跨 Agent 共享记忆是谁真正贡献的？）→ Method Modification（对 memory/tool/skill 节点做分层随机屏蔽，估计交互效应）→ Minimum Experiment（同一任务 4–8 次复跑）→ Model（Qwen3-4B）→ Dataset（ALFWorld/AppWorld）→ Baseline（TrackRL、leave-one-out、无记忆）→ Metric（success、marginal lift、估计方差、额外 tokens）→ Expected Contribution（跨组件因果 credit benchmark）→ Risk（干预破坏轨迹分布、调用成本和伦理）。

五句话总结

一，技能库不能仅按相似度和命中率维护。二，同题多 rollout 的随机注入为边际效用提供了可操作证据。三，效用下降与模型能力内化不是同一个事件。四，最强结果是无技能成功率也提升，而不只是上下文提示更有效。五，迁移到多 Agent 前必须处理交互效应和非平稳偏差。

更严格的因果解释与失败边界

随机注入识别的是“当前候选技能被提供”对该策略在该任务上的平均边际效应，而非技能语义的永恒价值。若技能 A 只有与技能 B 同时出现才有效，独立随机化得到的 A 效用会随 B 的注入概率改变；因此必须报告交互项或至少做 p 敏感性分析。若检索器从来不给某技能曝光，它无法被评估，构成 positivity 问题。策略参数更新又让历史 treatment effect 失效，γ 折扣只是一种启发式补救。

推荐复现实验的判别标准

最小可信复现不仅报告 success rate，还应报告每个技能 treatment/control 数量、效用置信区间宽度、被退休技能的再激活率、任务难度分层结果，以及有/无技能模式的同 checkpoint 对照。建议额外设置“错误技能但高语义相似度”组，测试检索相关性与真实效用是否脱钩；再设置两个互补技能，检查单独注入无效但联合注入有效时的误删率。这两项更能检验归因机制，而非重复主表成功率。

Tier SRLNEW · 10/18EG-GRPO: Evidence-Guided Step-level Credit Assignment for Deep Search Agents

Sijia Luo; Mengjie Gao; Yuxiao He; Mengshu Sun; Cuiping Li; Hong Chen; Jing Zhang · 2026-10-18 v1 · arXiv preprint

arXiv / PDF metadata · 论文 HTML 全文 · Code: 未核验

阅读定位：重点读 §3.1 first-exposure、§3.3 fallback、Table 2、Figure 3；适合与 TrackRL 的因果技能效用形成机制对照。

人话版：这篇论文到底干了什么？

深度搜索 Agent 往往要连续搜索十几轮，最后才得到答对或答错的单个 reward。这样一来，找到关键网页的动作和无效重复搜索可能得到同样 advantage。EG-GRPO 利用合成多跳问答数据里本来就有的“必须找到哪些证据”标注，把每条事实第一次被检索到的时刻转成局部 reward，再按 Agent 已掌握的证据集合给不同 trajectory 的同状态步骤分组比较。它把终局正确性与中途证据进展合并训练，改善早停和无效搜索，并在五个深搜 benchmark 上超过普通 GRPO。

Background & Research Gap

普通 GRPO 把最终回答的 0/1 reward 广播到整个 trajectory，无法区分哪一步搜索真正推进问题。比如题目要求找出 A→B→C 的两条证据：第一步找到 A→B，第二步重复同页，第三步找到 B→C，终局正确并不意味着第二步有贡献。旧的实体覆盖奖励或 rubric 可能仍停留在 trajectory 级别；GiGPO 以状态分组，但搜索文本历史很难可靠匹配。论文指出合成数据生成阶段已产生原子事实链，训练时常被丢弃。

Core Insight / Observation

作者先观察到成功轨迹的 evidence coverage 更高，而且在搜索早期就与失败轨迹分叉；这提示“何时获得必要证据”比“最终检索了多少页面”更适合做 process signal。把已发现的原子 claim 集合视为 knowledge state，可跨不同表面措辞、不同网页路径对齐搜索进度。重要前提是训练集拥有可核验 claim；没有这一先验的真实开放任务不能直接照搬。

Method Deep Dive：完整 Pipeline

Input：合成问题 q、所需证据 claims C(q)、可搜索网页环境。Step 1：Agent 用 ReAct 循环调用 search/visit，收集带编号引用块。Step 2：LLM judge 逐 claim 寻找第一次明确支持该事实的 citation，映射回 originating turn。Step 3：首次发现的 claim 数除以 K 作为该 turn reward；重复发现不给分。Step 4：以之前已知 claim 集 S(i,t) 表示 knowledge state，计算未来折扣证据回报。Step 5：优先在完全相同的 (q,S) 中归一化 advantage；样本不足时退化到 (q,|S|)，再退化到同 q 的全部步骤。Step 6：把 step advantage 与普通 outcome GRPO advantage 加权相加，裁剪后更新 decision tokens，mask 掉工具返回原文。Output：更能持续获取证据的搜索策略。

公式 / RL Formulation

令 φ_i(c) 为 claim c 首次被支持的 turn，则 Δ(i,t)={c:φ_i(c)=t}，r(i,t)=|Δ(i,t)|/K；知识状态 S(i,t)={c:φ_i(c)<t}。折扣回报 G(i,t)=Σ_{k≥t}γ^(k-t)r(i,k)。归一化后 A(i,t)=A_outcome(i)+w·clip(A_step(i,t),−C,C)，用 GRPO/PPO-style clipped surrogate 更新。State 是问题与已获证据、搜索历史；Action 是检索、访问和作答；Reward 同时含 final outcome 与证据增量；Credit 是 state-conditioned step advantage；KL/entropy 的具体控制需看附录配置，不能假定额外 PRM。judge 是 learned LLM，不是严格规则 verifier，可能把幻觉证据误判为支持。

Toy Example

设问题需 4 条 claim，第一轮找到 c1/c2 得 0.5，第二轮重访同页得 0，第三轮找到 c3 得 0.25，第四轮找到 c4 得 0.25。若另条轨迹在第一轮只找到 c1，那么两条轨迹第二轮虽然都是“搜索”，其知识状态不同，直接同组归一化会不公平。精确状态组太稀时，用已知 claim 数退化分组是一种偏差与方差折中：它更稳，但不能保证两个同数量状态具有同等难度。

Baseline / Experiment Setup / Research Questions

两种策略骨干：Qwen3-4B-Thinking-2507 与 Qwen3-30B-A3B-Thinking-2507。先用 OpenSeeker 1000 条高质量轨迹 SFT，再对 2316 个合成 prompt 做 RL；Serper 搜索、Jina 页面访问，Qwen-Flash 既用于证据判断也用于答案判断；128k context。五个 benchmark：BrowseComp、BrowseComp-ZH、GAIA 文本验证子集、xBenchDS-2505/2510。Baseline：GRPO、C-GRPO、GiGPO、STAMP；跨系统大模型数字只是参考，不构成同预算强对照。RQ1：证据级 reward 是否胜过纯 outcome？RQ2：不同规模是否一致？RQ3：分组与权重如何影响早停、覆盖率与准确率？

Ablation / Training Efficiency

Step 权重 w 从 0、0.25、0.5、0.75、1.0 扫描，w=0.5 最佳；过大权重可能鼓励只追求证据覆盖而忽略最终答案。三层 fallback 的目的在于缓解 exact-state 样本稀疏，消融说明 state grouping 对稳定性重要。论文列出训练 prompt 数和模型规模，但本次未核实可跨硬件比较的总 rollout tokens、GPU-hours 和 judge 开销；这些必须在复现时记录。训练中搜索服务的网页漂移也是重要复现实验变量。

Claim vs Evidence / Contribution

Authors Claim：合成证据标注可转化为可靠的 step-level credit，改善长程搜索。Experiments Actually Show：五项 benchmark 大多优于同骨干 GRPO 和所选 step-level baseline；工具调用和证据覆盖曲线与“避免早停”解释一致。What Is Not Yet Proven：judge 的 first citation 归因是否等价于因果贡献、缺失 claim 时能否工作、开放网络分布变化下是否稳定。Contribution 1 [New Reward]：首次证据增量；Contribution 2 [New Mechanism]：knowledge-state fallback advantage；Contribution 3 [New Empirical Finding]：正确轨迹更早积累证据。

Limitations / Research Value / Migration

作者方法依赖合成数据中的 claim 标注，真实 research agent 可能没有 gold evidence；LLM judge 的引用判定可能被伪造页面污染；对“先探索后发现证据”的间接动作奖励仍不充分。Baseline Potential：可做 Search-RL credit baseline；Benchmark Value：首次证据到达时间、重复检索率；Attack Value：伪证据 reward hacking；System Value：优化搜索成本。Original Problem（深搜 claim）→ Transferable Mechanism（首次可验证信息增量）→ New Research Question（多 Agent 之间谁提供了独有证据？）→ Method Modification（给 evidence 标 provenance agent/turn，并用干预校验）→ Minimum Experiment（2-agent multi-hop QA）→ Model（Qwen3-4B）→ Dataset（HotpotQA/自构多跳证据）→ Baseline（GRPO、EG-GRPO、共享 reward）→ Metric（accuracy、first-evidence latency、attribution precision、tool calls）→ Expected Contribution（跨 Agent evidence credit）→ Risk（judge 漏判和因果误归因）。

五句话总结

一，终局 reward 不足以指导每一次搜索。二，首次出现的可核验证据是比页面数量更有意义的过程信号。三，knowledge state 可以跨不同轨迹对齐。四，当前收益在 GAIA 较大，但部分 xBench 改进有限。五，把 evidence provenance 扩展到跨 Agent 是可实验方向，但需避免将相关性当因果。

Reward Hacking 与证据来源的可验证性

first-exposure reward 只在 judge 认为 citation 明确支持 claim 时触发，但检索网页可能包含复制粘贴、伪造引用或片段截断。若模型学会搜索“看起来像答案”的网页，就可能提高 coverage 而不提高真实性。需要把证据可用性拆成 source validity、claim entailment、temporal freshness 三个层次，分别检查是否能被伪证据操纵。尤其不能把一次被引用等同于可独立复核的事实。

为什么这不是完全解决 credit assignment

第一次找到某 claim 的动作并非必然唯一关键：之前两轮失败搜索可能提供了改写 query 的启发；某次找到线索却没直接命中 claim 的动作可能对最终答案至关重要。作者使用折扣回报把未来证据收益向前传播，部分缓解 delayed credit，但 discount γ 不能真正识别反事实必要性。对于跨 Agent 场景，先搜索到的 agent 与最终解释证据的 agent 也可能不同，必须区分 evidence production、transmission 与 consumption。

复现时应新增的评价切片

建议按问题 hop 数、答案稀有度、网页噪声、证据出现顺序和工具调用预算分层。除 accuracy 外，记录 claim 首次到达 turn、重复搜索占比、答案前的有效证据数、judge 与人工验证一致率、同预算的 cost per solved query。对失败案例逐步复盘：是 claim 标注不全、judge 误判、搜索早停，还是 evidence 已足但 reasoning 失败？只有区分这些来源，才能知道提升来自 reward 设计还是更长的探索。

人话版：这篇论文到底干了什么？

Video DiT 生成一段视频时，跨时空 token 的全注意力非常昂贵。过去的 sparse attention 往往每个去噪步使用固定稀疏度，或者为了重新找重要 attention block 付出很高搜索开销。GSRS 观察到：随着 denoising 进行，注意力越来越集中，且早期重要 block 的候选集合对后续仍有很高覆盖率。于是它早期算得多、后期算得少，第一次全面搜索后只在早期候选集内更新 mask，并在 FlashAttention 内精确统计 block 权重。无需训练，在 Wan2.1 与 HunyuanVideo 上实现 1.55×/1.68× 端到端加速，视频质量指标接近全注意力。

Background & Research Gap

生成 720p 视频时 token 数量会随帧数与分辨率增长，full attention 的 O(N²) 是主要瓶颈。作者给出的背景例子：HunyuanVideo 125 帧 720p 的一次生成可涉及超过 115K tokens，单 A800 耗时约 38 分钟，注意力占约 80% latency。固定稀疏率忽略“早期噪声大、后期结构更确定”的计算需求变化；每步全局重新搜索关键块则可能抵消稀疏计算节省的时间。GSRS 同时优化保留计算量和寻找重要计算的位置。

Core Insight / Observation

Figure 3 的 attention entropy 与 mean attention distance 随去噪步下降，支持后期 attention 质量更集中；另一组观测显示第一次搜索保留的候选 block 对后续仍有较高 recall。由此推出两件事：Top-p 的累计注意力阈值应逐步降低；后续 search 不必再扫描完整 block 空间。关键不是“缓存上一轮所有结果”，而是固定第一轮候选全集，允许被上一轮 mask 排除的 block 重新进入，避免不可逆的贪心丢失。

Method Deep Dive：Input → Output

Input：预训练 Wan2.1/HunyuanVideo DiT、视频 latent tokens、去噪时间步。Step 1：前 20% 去噪步使用 full attention warmup，获得可靠统计。Step 2：第一次搜索在全 block 空间估计重要性，形成候选集合 S1。Step 3：按 p={0.95,0.90,0.85,0.80} 的递减 schedule，在步骤 10/20/30/40 更新稀疏 mask；后续搜索只在 S1 中评估，不只看上一步 mask。Step 4：非搜索步复用最新 mask，跳过不重要 block 的 QK/AV 计算。Step 5：FlashAttention kernel 内积累局部 block log-sum-exp，kernel 完成后用真实 row-wise LSE 校正成精确权重，供 Top-p 排序。Output：保持生成步数和模型参数不变的稀疏注意力推理。

关键公式与 Toy Example

标准 attention 权重 w_ij=exp(q_i·k_j/√d−LSE_i)。对 query block u 和 key block v，重要性 W_uv=(1/B)Σ_{i∈u}Σ_{j∈v}w_ij；按 W_uv 从大到小选块，累计权重达到 p 即停止。假设某 query 的 block 权重为 [0.55,0.30,0.10,0.05]，早期 p=0.95 需前三块，后期 p=0.80 只需前两块。与固定 top-k 相比，它对注意力分布平坦和尖锐的输入自适应。注意：后期可用块必须属于第一次候选集 S1，若重要性发生大幅迁移仍可能遗漏。

Experiment Setup / Research Questions

Wan2.1-T2V-14B 与 HunyuanVideo-T2V-13B，均 720p、50 denoising steps；latent 中分别 21/32 帧、每帧 3600 tokens；VBench prompts，单 NVIDIA A800、CUDA 12.8、block size 128、TileLang 和 block-sparse CUDA kernels。比较 Full Attention、SpargeAttention、SVG、SVG2、SVOO；指标 PSNR/SSIM/LPIPS、VBench-Q、attention density、end-to-end latency。RQ1：质量与加速是否同时成立？RQ2：递减 p 是否优于固定 p？RQ3：Reduced Search 是否真正节约 wall-clock？RQ4：精确 LSE 重要性是否必要？

五句话总结

一，Video DiT 的计算分配应随去噪进度变化。二，重要 block 的早期候选集可重用，但不能完全锁死上一轮 mask。三，精确权重估计比缓存旧 LSE 更可靠。四，attention density 约 25% 不意味着端到端加速 4×，实测 A800 为 1.68×。五，迁移到 Video VLM 前必须重新验证注意力统计规律。

Efficiency Breakdown 的正确读法

论文在两个模型上均保持 50 个去噪步骤，没有减少 diffusion steps；latent frame 数和每帧 token 数也未因方法而改变。节约对象主要是每个去噪步中 attention 的 key–query block 乘加，而不是视频编码器或 VAE 的输入。报告的 density 是参与 attention 的计算比例，理论上可作为局部 FLOPs proxy，却不包含搜索 mask、数据重排、kernel launch、非 attention 模块。端到端节省比例应按 (baseline latency−proposed latency)/baseline latency 计算，不能直接把 1−density 当总算力节省。

为什么初始候选集不是简单 KV Cache

GSRS 重用的是 attention block 的候选位置和选择 mask，不是直接复用旧时刻的 K/V 向量或 hidden states。新 denoising step 仍重新计算需要保留的 attention 数值；因此与 MagCache/FasterCache 那类跨步 feature reuse 的收益机制不同。若将其迁移到 streaming Video VLM，必须区分三层缓存：视觉 encoder features、LLM visual KV、attention support mask。它们的有效期和一致性条件完全不同，混为一谈会产生错误的加速估计。

极端输入与硬件敏感性

对镜头快速切换、多个高速运动物体、长时遮挡后重现的目标，早期候选集可能不再覆盖后期重要 block；此时提高 p 或重新全局搜索能降低质量风险，但会牺牲加速。建议按运动强度、视频时长、场景变化率分桶，报告每桶 attention recall、VBench-Q 与 latency，而不是只给全数据平均。硬件方面，A800 与 H800 的速度收益不同，表明 memory bandwidth、kernel occupancy、block layout 也在决定最终性能；在消费级 GPU 上应重新基准测试。

更细的可复现系统实验

最小复现应固定模型 checkpoint、resolution、frames、seed、denoising scheduler、精度与 batch size。分别计时 full attention、第一次 full search、后续 reduced search、非搜索步 sparse kernel、VAE 解码、其他 transformer blocks；同时用 GPU profiler 记录 FLOPs、HBM traffic、peak allocated/reserved memory。用同一 prompt 比较 PSNR/LPIPS 只能说明与 full attention 的相似性，VBench 与人工偏好才更接近生成质量；两类指标都不能替代对稀有动态事件的失真检查。

对比 strongest baseline 的真正增量

主表中 GSRS 的速度并非对所有稀疏方法都有巨大优势：Wan2.1 上 SVG2 已达 1.50×，GSRS 1.55×；Hunyuan 上多个 baseline 约 1.55×，GSRS 1.68×。因此研究贡献更应表述为“在较高保真度下改善效率前沿”，而不是“首次使视频生成变快”。强 baseline 比较还需统一 VBench prompt、精度、kernel 实现和 warmup。若把 quality 作为约束，GSRS 的准确 block importance 可能比单纯追求最高 speedup 更有意义。

新研究的可证伪假设

把 GSRS 迁移到 Video VLM 时，先提出可证伪假设：相邻帧的 attention support 在静态片段中稳定，在事件边界处显著漂移。如果该统计规律不成立，就不应继续做 support-mask reuse。验证可在同一 Video VLM 中记录每帧 top attention block 的 Jaccard overlap、对 query 的敏感度和关键事件 recall，再把缓存策略接入真实 CUDA profiler。只有同时提升 accuracy–latency Pareto，才称得上新的视频加速机制。

多 Agent 可以互相分享经验，但通常仍由人手写“如何总结经验、如何汇总、如何修改工具和 prompt”的固定流程。FoH 让中心 server 不仅进化各个 client 的 harness，还进化自己负责汇总反思的 harness。每个 client 在不同环境运行任务、上传 reflection；server 读这些反思后同时更新共享知识、工具和执行流程，再下发给下一轮 client。它不使用额外的 ground-truth 验证集选择版本，实验报告相对固定单 Agent harness 与单 Agent harness 自进化分别提升 53.57% 和 29.76%。

Background & Gap

FoT 之类系统主要共享文本 insight，FederatedSkill 共享技能库；RHO 等 harness 自进化方法往往聚焦单 Agent，或者固定外层优化算法。真实分布式 Agent 还面临环境异构：不同机器、工具、目录、API 不能简单复制原始轨迹。FoH 的创新不是又加一个 memory，而是将“收集反思→聚合→更新 client 运行逻辑”本身变成可演化对象。与 RL 的差异：这是基于 reflection 的外部程序优化，不是显式 policy gradient。

Core Insight / Method

Input：各 client 的任务与运行环境、当前 client/server harness。Step 1：中心 server 按 guide 初始化可执行 harness。Step 2：并行 client 拉取版本、执行任务，上传 reflection 而非完整隐私轨迹。Step 3：server 通过自身 harness 汇总跨 client 共性，维护 insight library，并生成下一版 server harness。Step 4：新 server harness 再修改 client 的 prompts、tools、execution flow。Step 5：重复，形成双层演化闭环。关键变量是 client harness Hc(t) 与 server harness Hs(t)，二者相互影响；失误可能从 server 广播到所有 client。

一个答案可能“格式完整”得高分，却在“证据真实性”上持续失败；简单把所有 criterion 求平均，会使已学会的能力继续主导训练，弱项长期缺乏梯度。另一极端是只优化最低分 rubric，可能损害整体输出质量。作者希望让 reward 结构直接决定探索与 credit routing，而不是仅作为评估表格。

Method / RL Formulation

Input：问题 q、rubric criteria、当前模型的多条候选回答。Step 1：将 criterion 聚合到可解释的 capability channels。Step 2：根据本批回答证据和历史 domain 估计各 channel 的表现；以 h=max(0,(τ−S)/τ) 定义缺口。Step 3：选最大缺口能力，引导生成补足该能力的候选，并校正 proposal bias。Step 4：基于 rubric 分数计算 baseline advantage，构造针对目标能力的 residual routing。Step 5：用 guard 限制修改必须与目标方向一致、保持共享排序、幅度有界；不满足则退回原 advantage。Reward 来自 rubric evaluator；属于过程结构化但未必可机检，存在 evaluator bias/reward hacking 风险。

Experiment / Results / Analysis

实验比较普通 rubric RL、非结构化奖励、去 guided exploration、去 residual routing 等配置。摘要的两项最大提升为 +7.43（对初始策略）和 +7.60（对非结构化 RL）；这是不同对照，不能相加。消融 Figure 2 的四项指标中 full RSRL 均领先移除组件的变体，支持探索和 credit routing 的互补作用。由于本次只核对主文部分图表而未逐项记录完整 benchmark 的逐表数字，其他未核实的具体数据一律不补。训练 tokens、rollout 次数和 GPU-hours 未在本次记录中得到可比数值。

Contribution / Limitation / Research Value

Reward Analysis / Credit Assignment 的关键歧义

rubric 条目既可以是客观条件（是否引用来源），也可以是主观判断（是否清晰）。若一个 channel 的评分器对表达风格有偏好，RL 可能学会迎合风格而不是提高真实能力。RSRL 的 residual routing 通过 guard 保持共享排序，但并不能证明 rubric score 与真实任务成功完全一致。应在训练 reward 外增加独立人工或程序化指标，观察某一能力得分提高时是否伤害其他能力。

迁移到 Agent 的最小闭环

把 Agent trajectory 拆成规划、工具选择、证据核对、错误恢复四个 capability channel；每个 channel 用可验证事件与 rubric 结合打分。先做 reward-only 评估，确认每个 channel 对终局 success 的预测价值，再用 RSRL-style weak-channel exploration 更新策略。与单一 outcome GRPO、简单 rubric sum、独立 PRM 做对照，重点报告各 channel 的真实失败率与 reward hacking，而不是只报告 rubric 总分。

成本与稳定性边界

额外的 rubric 解析、能力诊断、引导生成和评分调用都会消耗 token；若训练 token 数不匹配，不能把总分优势完全归因于 credit routing。不同 rubric 映射成相同 capability 可能使 channel 过粗；映射过细则每组数据太稀，advantage 方差增大。应报告 capability 数、每个 channel 的有效样本量、探索覆盖率、训练稳定性与最终输出长度变化。

与 EG-GRPO 的差异化

EG-GRPO 将“首次证据获得”定义为任务进度，RSRL 则把 rubric 条目视为能力分解。前者的 state 是已知证据集合，后者的 state 是能力表现估计；前者适合可枚举 claim 的搜索，后者适合没有唯一标准答案的开放生成。若将二者合并，必须先证明两种信号互补，否则只是 reward 项相加。

人话版：这篇论文到底干了什么？

推测解码会根据实时负载改变 batch size 和 draft length，导致 GPU kernel 的实际工作形状一直变。CUDA Graph 却通常要求固定捕获的 launch 结构，传统系统要么为很多 shape 预先建 graph，要么在运行时捕获，要么填充到最大尺寸浪费计算。PolyGraph 在 GPU 上写一个很小的 plan buffer，graph 始终以最大 grid 捕获，kernel 内根据实际 shape 跳过无效 tile。它在单 H800 的 trace-driven prototype 中，用一个 graph 代替 64 个 shape graph，把预服务构图时间从 3915ms 降到 93ms，同时维持约 17.7ms 的中位 step latency。

Background & Gap

adaptive speculative decoding 的 verification width M=B×d 会动态变化。即使 token 数减少，GPU graph 的捕获和 shape dispatch 也可能变成新瓶颈；max-padding 虽然省掉重建，却在小 batch/短 draft 时做无用工作。该论文属于服务系统层的“固定图结构、动态工作负载”，可迁移到 Video VLM 动态帧预算，但并未直接测视频模型。

Core Method / Objective

Input：当前 batch B、draft length d、预捕获最大 grid 的 CUDA Graph。Step 1：host 将 active shape 写到 device plan buffer（28 bytes）。Step 2：重放固定 graph，所有 Triton kernel 使用同一 launch topology。Step 3：每个 tile 在执行前读取 plan，超出 active shape 的 tile 直接返回；指针、内存布局和 graph 节点不变。Step 4：输出仅包含有效 verification 区域。这里没有 RL reward；优化目标是减少 graph capture 与 padding waste，而非改变语言模型采样算法。

GPU 计算机理与误解排查

CUDA Graph 的价值在于减少 CPU launch 开销和固定调度拓扑，但 speculative decoding 的 B 和 d 会随请求变化。预捕获 64 个图会增加初始化与管理成本；只捕获最大图再 padding 又会执行无效 tile。plan buffer 将 active shape 放在 device memory，使每个 kernel 在 GPU 内决定是否处理该 tile，既保持 graph 可重放，也避免最大形状的全部计算。28-byte plan update 是元数据传输，不等于整次请求只需传 28 bytes。

最强与最弱结果如何同时成立

构图时间从 3915ms 到 93ms 是部署准备阶段的显著收益；P50 17.8ms 到 17.7ms 则说明正常稳定工作负载下运行时几乎没有变快。P99 18.7% 的改善只在极高 padding waste 条件下出现，不能当作典型流量的平均收益。最强证据是消除了 shape-specific graph explosion；最弱证据是未证明线上复杂 serving 的吞吐提升。论文也明确称它是 trace-driven prototype，需避免产品级推断。

Video VLM 迁移的技术风险

视频帧数、patch 数和每个请求的 query-aware token budget 会改变 prefill 形状，确实可能触发相同 graph 管理问题。但视觉 encoder 的动态裁剪、跨帧缓存、LLM 的 prefill/decoding 是不同 kernel 路径；只有能够修改 kernel 并确保 shape guard 不破坏数值语义，才适合 plan-buffer 方案。最小系统测试要包括冷启动与稳态两个阶段，分别报告 graph capture time、显存、P99、batch throughput 和模型准确率。

实际部署中的性能预算

生产 serving 的关键指标不是一次 trace 的 P50，而是不同请求到达率、batch size 分布、draft 接受率、上下文长度和并发负载下的吞吐–延迟曲线。应加入 graph capture amortization：若服务长期运行，3915ms 的构图成本会被大量请求摊薄；若模型频繁切换或服务弹性扩缩容，这个初始化收益就很重要。把 workload 分为短会话、长会话与突发请求，才能判断 PolyGraph 的实际价值。

与 Video Acceleration 的交叉点

Video VLM 动态帧采样往往导致每个请求进入 LLM 的视觉 token 数不同。算法层若只优化帧数，却触发 CUDA Graph shape explosion，可能抵消理论收益。PolyGraph 提供一个系统层补丁，但要求每个核心 kernel 遵守 plan-buffer 契约。一个有价值的跨领域实验是同时优化帧选择策略和图执行策略，检验两者收益是否可叠加，以及长尾时延是否比平均 FLOPs 更敏感。

[New Empirical Finding] 在严控数据和调参后，RL 的收益并不完全来自 rejection data；[New Evaluation] 把难度混合、截断和预算匹配作为必查变量。限制：只有程序化 counting task，结论未覆盖长程 tool-use agent；部分预算匹配是 post hoc；LoRA 与 full FT 的优化动态不同。对 Agent RL 的价值在于构建强 RFT baseline，避免新 reward 方法仅靠弱对照获得虚高提升。

Potential Use

在 AppWorld 或 ALFWorld 复现 GRPO vs RFT：固定任务、环境反馈、成功轨迹池、模型和总 rollout tokens；测 success、样本效率、失败恢复与梯度稳定性。若 RL 优势仅在可多步纠错环境出现，才值得研究 credit assignment 与 exploration 的独立贡献。本条基于 arXiv new-listing 可获取摘要，未完整核验正文表格。

为什么这个对照值得保留

许多 RL 论文对 SFT/RFT 的对照不够认真：若 SFT 只用一份随机数据、RL 却能反复在线采样，胜利可能来自数据量和数据分布。该论文把 prompt、verifier 和 token cap 对齐，并允许 RFT 做更多调参，提供更公平的判别方式。迁移到 Agent 训练时还应控制环境交互次数、工具成本、成功轨迹重复率与模型初始能力。

复现注意事项

建议额外记录每个实验臂的有效正确样本数与被截断比例。RFT 的正样本数量若随训练变化，所谓“相同 prompt pool”仍可能对应不同监督量；GRPO 的 group 内全错或全对样本也会影响有效梯度。报告这些细节能减少将数据效应误归因于优化算法的风险。
