Tier S · 深度精读

Tier S EnvSched: Environment-Aware Scheduling for Rollout-Efficient Agent Reinforcement LearningRL
日期 2026-10-27 · arXiv 2610.37609 · 作者 Sihan Yang, Weichen Bai, Ruichuan An, et al. · 机构 PKU / XJTU / THU / Samsung Research / CASIA / CUHK（论文所列机构） · Venue/Status arXiv 预印本；未核实正式接收 · Code 官方 GitHub

人话版：这篇论文到底干了什么？

Agent RL 的算力浪费不只来自模型训练，也来自抽到了“所有 rollout 都失败”或“所有 rollout 都成功”的任务：这种组内奖励没有差异，GRPO 难以从中得到有效相对优势。EnvSched 不改模型结构，也不另训 reward model，而是把“环境＋任务”视为训练调度单元，利用同环境与跨环境的执行结构相似性，从历史 rollout 预测下一批哪些任务最可能产生有效奖励差异；同时强制覆盖此前见得少的环境。Qwen3-8B 在 40 步达到三项工具基准平均 48.81，超过随机抽样训练至 120 步的最高水平。价值在于把 Agent RL 的优化对象从 policy 扩展到了环境数据调度。

Background & Research Gap

在可执行环境中，Agent 不只回答问题，还会读取数据库、调用工具、改变状态，再由终局 verifier 判断成功。例子：安排预约与调换病床看似不同业务，但都涉及查询对象、检查约束、修改关系、确认后继状态。只按 prompt 文本相似度或任务难度抽样，可能把这两类可迁移的执行结构割裂，也可能连续抽到无法产生梯度的任务。旧方法 Random、DPS、LEEPS 主要在任务层选样；EnvSched 的 gap 是环境工具、状态与 verifier 结构尚未进入调度。

Core Insight & Observation

GRPO 依赖同一任务 K 次 rollout 的奖励差异：当奖励全为 0 或全为 1 时，组相对优势趋于无信息。因此作者把组内 reward variance 当作“训练信息量”的可操作代理，而非把高成功率等同于高训练价值。另一个观察是：只选高方差任务容易反复集中于少数环境，造成工具与状态分布覆盖不足。二者必须共同优化。

Method Deep Dive

Input：EnvScaler 中的可执行环境、任务、工具描述、初始状态、verifier 与已有 rollout 日志。Step 1：LLM 抽取每个任务的操作、先决条件、依赖与奖励检查；构建六种具体 TF–IDF 特征以及去实体名的抽象执行特征。Step 2：在同环境连接具体相似任务，在不同环境连接执行拓扑相似任务，形成 dual-relation graph。Step 3：每个节点维护 reward mean、variance、dispersion 与被抽次数；按时间衰减聚合邻居统计，结合本节点历史估计未来 reward variance。Step 4：每批 64 个任务对分为 32 个 coverage 与 32 个 exploitation；前者优先低覆盖环境，后者优先高预测方差，并用相似度惩罚、环境配额与重复曝光折扣限制扎堆。Step 5：对每个任务做 8 次 rollout，用 GRPO 更新模型，再回写统计。Output：更有信息量且分布更广的训练批次与更新后的 Agent policy。

Objective / RL Formulation

State：当前策略及环境—任务的历史奖励统计；Action：调度器选中的环境—任务批次（而非 Agent 的 token）；Policy：被 GRPO 更新的 Qwen3 Agent。Agent reward 来自可执行环境终局 verifier，是稀疏 outcome reward；调度器本身用预测组内方差作为选择效用，不是把它加入 Agent reward。核心式为 vᵢ=Var(rᵢ,₁,…,rᵢ,₈)，以及调度选择 argmaxᵢ[priorityᵢ−λsim·maxⱼ∈batch Sim(i,j)]。历史估计和同／跨环境邻居的先验通过加权融合，ρ=0.5 决定覆盖比例。Advantage 仍由组相对奖励给出；KL、entropy 等 GRPO 细节沿统一训练配置，论文此处的主要变量是 batch selection。风险：高方差可能由 verifier 噪声而非有价值的探索引起。

Toy Example

假设 3 个任务各 rollout 8 次：A 成功 0/8、B 成功 4/8、C 成功 8/8。若 reward 为二元，A、C 的组内方差为 0，B 为 0.25。纯 exploitation 会反复选 B；EnvSched 还会从少见的“审批—修改—验证”环境抽取 D，避免模型只学会 B 的工具族。这个数值是解释机制的自造例子，不是论文实验。

Baseline & Experiment Setup

Model：Qwen3-Thinking 1.7B、4B、8B、30B-A3B；训练池 51 个环境、2,550 个任务；每步 64 task pairs × 8 rollouts＝512 trajectories。训练采用统一 GRPO；测试 BFCL-v3 Multi-Turn、τ-Bench 与 ACEBench-Agent。Baseline：Random、DPS、LEEPS；强基线因模型／子集而变，不能简单宣称某一个始终最强。RQ1：同 rollout budget 能否提升工具基准？RQ2：提升来自组内奖励差异还是环境覆盖？RQ3：调度额外 wall-clock 是否值得？

Results & Table / Figure Reading

Table 1：Qwen3-4B 训练 200 步时，BFCL-v3 overall 从 Random 的 28.83 到 31.88（+3.05），τ-Bench 从 37.78 到 41.01（+3.23），ACEBench-Agent 从 56.00 到 58.00（+2.00）；该规模上 LEEPS 的 τ-Bench 38.79 是一个更强的对照。Qwen3-8B 在 40 步得到 48.81 的三基准平均分，超过 Random 至 120 步的最好结果，说明并非必须等量训练才能追上。Figure 1 展示训练效率曲线，但它不是“GPU 训练总时长节省 3 倍”的直接证据。Table 2：4B 平均组内方差 0.03208→0.04290（约 +34%），每批环境覆盖 36.53→45.96（约 +26%），工具覆盖 413.41→478.39（约 +16%）。Figure 4 显示上述趋势在训练阶段大体持续。Table 3：coverage-only 虽覆盖 51 环境却方差降到 0.0357；exploitation-only 方差升至 0.0442 却只覆盖 33.95 环境，二者单用均损害综合分数。

Ablation, Weakest Result & Cost

去掉 coverage：样本变“更可学”但覆盖不足；去掉 exploitation：覆盖最大但奖励差异不够；去掉其中一种 graph relation：历史迁移能力下降（论文报告的定性消融，未在此抄录未经逐项核对的数值）。弱点是小模型 1.7B 在部分子集的改善仅持平于强基线，且 8B 的 τ-Bench 在 200 步为 50.30，略低于其 40 步的 50.71，收益并非随训练步数单调。在线调度实测约 34.93 秒／步，对比 4B H100 约 25 分钟／步，约占 2.3%，但离线建图和 LLM 特征抽取仍需另计。

Claim vs Evidence

Authors Claim：环境感知调度提升 Agent RL 的 rollout 效率。Experiments Actually Show：在指定 EnvScaler 环境池与 Qwen3 模型上，固定每步 rollout 数的下游工具任务表现改善，且方差与覆盖的统计代理同步改善。What Is Not Yet Proven：对完全不同 verifier 质量、真实用户动态环境、非 GRPO 算法和更大规模在线环境是否同样成立；预测方差与真实梯度价值是否具有因果等价关系。

Contribution / Limitation / Research Value

贡献类型：New Training Data Scheduling、New Environment-level Representation、New Empirical Finding。作者方法的优势是可作为既有 GRPO 外围的调度插件，基线价值强；工程价值在无需额外 pilot rollout。限制：图结构来自 LLM 抽取和静态相似性，可能受错误抽象与领域偏差影响；方差奖励会偏爱随机 verifier；环境覆盖是代理目标，未必等于长期泛化。可迁移至 Agent Memory 选择：把记忆片段视作训练资源，优先回放既有成功与失败差异最大、同时覆盖新任务类型的经验。

Migration / Minimum Experiment

Original Problem：环境任务抽样 → Transferable Mechanism：reward-variance prediction × coverage → New Question：能否按“记忆片段对未来成功率的差异”选择 replay？Method Modification：把 graph 节点换为 (experience, task family)，以相似轨迹为边，保留随机对照。Minimum Experiment：Qwen3-4B 在 ALFWorld 或 τ-Bench 上固定 rollout/token budget，比 Random Replay、Difficulty Replay、EnvSched-like Replay；Metric：success@1、跨任务泛化、每单位 rollout 收益、memory 读取 tokens；Expected Contribution：Memory-aware RL 数据调度；Risk：任务方差与记忆因果贡献不等价。新论文潜力中高，先验证统计代理。

五句话总结

EnvSched 不改 GRPO 的梯度公式，而改它每天“看见什么训练任务”。高组内奖励方差给出可学性信号，跨环境覆盖避免局部过拟合。实验同时给出训练步数、工具基准、方差和调度耗时。它仍未证明高方差就是高因果学习价值。最值得迁移的是环境／经验级的主动调度，而不是照搬图的相似度特征。

Tier S Does Your Generalist Skill Optimizer Really Incentivize Agentic Tasks? Rethinking Skill Optimization via Bipartite AttributionAgent
日期 2026-10-27 · arXiv 2610.37201 · 作者 Jiawei Zhou, Bo Peng, Yuxuan Huang, et al. · 机构 Shanghai AI Laboratory 等（论文所列机构） · Venue/Status arXiv 预印本；未核实正式接收 · Code 未核实具体 URL

人话版：这篇论文到底干了什么？

很多 Agent Skill Optimizer 会反复让模型改写一份自然语言技能说明，然后在十几或几十个开发任务上挑“成功率最高”的版本。BiPA 发现这种提升可能只是挑中了随机波动：三种优化器、两种模型、三个长任务基准上，16 份学到的技能在测试集上平均只比手写种子高 0.1 个百分点，却平均多消耗约 16% 输入 token。论文不仅指出过拟合，还把 Agent 轨迹拆成“每轮调用”和“每轮读到的上下文”的二部图，解释为何增加一句“每次检查”会引起额外工具轮次与历史反复传输。它是对 Agent 自改进评估方法的一次有力审计。

Background & Gap

Agent skill 是放在上下文中的可执行流程建议，例如“修复文件后重新运行测试，再核对结果”。GEPA、SkillOpt、SkillAdam 都会根据运行反馈改写 skill，并在小 dev set 上保留更高分版本。难点一：单次任务成功率随机性很大，“best of many”天然偏高；难点二：更长的 skill 不仅占几百个 token，还可能让 Agent 多执行十轮检查，每轮重新发送全部对话历史。传统论文只报告成功率与 skill 字数，无法说明到底哪个行为导致成本。

Core Insight

作者把两个容易混淆的问题拆开：选出一个分数更高的 skill，是否真正改变了任务能力？新增 skill 规则是否真的减少总成本？前者需要把优化器的 accept/reject 机制在“候选根本没改”时重放，建立纯选择偏差基线；后者需要追踪 skill、工具输出、历史内容在每轮上下文中的重复读取，而不能只看最终 prompt 长度。

Method Deep Dive

Input：种子 skill、每个优化器提出／保留的文本版本、训练和 dev 选择记录、测试轨迹。Step 1 Selection Replay：固定种子内容，模拟候选采样与验收规则，估计“没有真正改进也能在 dev 上涨多少”。Step 2 Bipartite Attribution：将每个 episode 表为左侧 Agent turns、右侧 context components（skill、历史、工具结果等）的二部图，边记录某轮读取了哪些内容。Step 3 统计 X（累计输入 tokens）、R（turn 数）、F（固定前缀）、h（每轮新增历史）。Step 4 计算 turn elasticity 与四项成本分解：更多 action、把动作拆成更多 turn、每轮历史内容、skill 文本本身。Step 5 对每个 skill 的 test success、成本、跨模型迁移做对照。Output：选择偏差估计与成本来源审计，而不是一个新的在线技能优化器。

Key Formula / Toy Example

近似公式 Δlog X≈e_R Δlog N−e_R Δlog m+s_H Δlog h+s_F Δlog F，其中 N 是工具调用数、m 是每轮平均调用数、s_H/s_F 是历史／前缀在输入中的份额。e_R=1+s_H·R/(R−1)，在完整历史重传且长轨迹下趋近 2。直觉：若原本 10 轮、每轮重读不断增长的上下文，新增一条“每次调用后单独复查”规则把轮数提高到 12，成本增加可能显著大于 skill 字面增加的几个 token。这里的 10→12 是解释例子，不是论文观测。

Experiment Setup & Baselines

Optimizer：GEPA、SkillOpt、SkillAdam；Model：DeepSeek-V4.1-Flash、GPT-6-Luna；Harness：OpenCode（不压缩历史）；Benchmark：Terminal-Bench 2.1、τ³-bench、AutomationBench。测试集分别 18、75、120 个任务，dev 不超过 30 个；使用统一种子与训练 episode。Baseline：原始 seed、no-skill、三种优化器、selection replay。最强基线在平均总体层面就是手写 seed；单独任务上优化器偶尔胜出。RQ1：学到的 skill 是否真的增加 test success？RQ2：额外 tokens 来自 skill 字数还是行为变化？RQ3：dev 提升能否排除纯选择偏差？RQ4：技能能否跨模型／基准迁移？

Results / Tables / Figures

Table 1：DeepSeek 在 TB2 上 seed 75.9%，GEPA 74.1%、SkillOpt 64.8%、SkillAdam 68.5%，即多个“优化”结果低于原始技能。DeepSeek 在 τ³-bench 上 SkillOpt 79.1% 对 seed 76.4%，说明不是每项都失败。GPT-6-Luna 在 AutoBench 上 SkillAdam 43.6% 对 seed 37.2%，出现局部 +6.4 点，但整体 16 个 learned skills 仅平均 +0.1 点。成本汇总：平均 input tokens 约 ×1.16；91/97 次被评分的编辑延长技能文本。Figure 2 解释 turn—context 二部图；Figure 1 的成本拆解说明“多轮重读历史”比“技能文本变长”更关键。选择重放的结果说明 dev 选择收益在无效候选中也会出现，不能直接当作训练效果。

Ablation & Weak Cases

作者没有把 BiPA 设计成训练算法，因此它的主要“消融”是测量机制分解：去掉 selection replay 就无法剥离 winner’s curse；只统计 skill 长度就会漏掉额外轮次；用 compacted-history 计费会改变 turn elasticity，说明结论对 harness 的历史策略敏感。弱点：对单条规则的成功贡献仍没有可观测 value function；四项分解是 token accounting，不是任务成功的因果分解。跨模型迁移普遍不稳定，且高成功率不等于成本最优。

Claim vs Evidence

Authors Claim：通用 skill optimizer 在所测长任务上缺乏稳定增益，反而增加成本。Experiments Actually Show：固定 seed、两个模型、三类 benchmark 与相同 harness 下，test 平均几乎无提升且 token 开销增加；dev 优势可由无效候选选择重现。What Is Not Yet Proven：所有技能优化器都无效；在长上下文缓存、摘要压缩或规则级干预下是否仍然如此；哪些具体 skill 语句导致任务成功／失败的因果链。

Contribution / Research Value

贡献类型：New Evaluation Instrument、New Cost Attribution、New Empirical Finding。它是很好的“自进化 Agent”基线审计工具，也直接影响研究论文的显著性要求：要比较 test 的置信区间、selection-only baseline 与相同总 token budget。工程上，优化器应支持删除／合并规则、批量工具调用和成本感知接受准则。与跨 Agent sessionflow/memory 的交叉点是：一条被保留下来的“经验”可能改变未来交互轮次，真实效用必须由后续行为与结果联合衡量。

Migration / Minimum Experiment

Original Problem：技能编辑接受偏差 → Mechanism：selection replay + turn-context graph → Question：能否对每条 memory/skill 估计净因果效用？Method：随机插入、移除、替换单条规则，在同任务多 seed 轨迹上做 paired counterfactual；对 cost 使用 BiPA，对 success 使用受控重跑差异。Model：Qwen3-8B 或现成 Agent API；Dataset：Terminal-Bench 2.1 / AppWorld；Baseline：GEPA、SkillOpt、固定种子、随机编辑；Metric：success Δ、95% CI、token cost、工具轮数、跨任务转移。Expected Contribution：Causal Skill Credit / Budget-aware Skill Evolution；Risk：API 随机性和环境不可复现造成高样本成本。

五句话总结

优化器报告的 dev gain 可能只是选择噪声。Skill 变长还会通过更多 turn 放大上下文成本。BiPA 给出可复用的偏差对照与 token 归因工具。它不能证明每条规则对成功的因果作用。真正值得做的下一步是把 success attribution 和 cost attribution 合并为可实验的净效用准则。

人话版：这篇论文到底干了什么？

4K 视频抠像要求每帧每个像素都有准确 alpha 值，但基于时序记忆的模型要将当前高分辨率位置与历史记忆做大规模匹配，显存和延迟迅速膨胀。MatAnyone-E 的策略是“低分辨率先探路，高分辨率只修最不确定的地方”：先做便宜的粗匹配，再同时剪掉不需要精算的 query 位置和无关历史 memory，最后用蒸馏得到的轻量 decoder 还原完整高分辨率结果。论文报告 4K A800 上相对 MatAnyone 2 的约 7.4× 估计加速与 13.1× 峰值显存下降；H200 编译版本达到 28.62 FPS。它不是 Video LLM 论文，但提供了非常清晰的跨帧缓存与动态算力分配机制。

Background & Research Gap

视频抠像（matting）要恢复头发、透明边缘等细节，并避免连续帧抖动。MatAnyone 2 等方法通过与前几帧 memory 匹配来维护时序一致性；分辨率从 1080p 提高到 4K，查询位置与历史位置成倍增长。简单降低所有帧分辨率会损失细节；对所有位置做高分辨率匹配又难以满足实时系统。核心 gap 是：应在进行昂贵的历史匹配之前就知道“哪些地方值得算”。

Core Insight

作者观察到时序融合中某些区域高度依赖上一帧已传播的结果，而另一些区域（细发丝、边界变化、新遮挡）需要重新从 memory 找证据。原模型的 uncertainty gate 可以反映这种差异，但它在昂贵的 memory retrieval 后才出现。新方法先在低分辨率近似求出该信号，再将其用于高分辨率 query 与 memory 的双重筛选。这是“把判断计算需求的动作前移”的系统设计。

Method Deep Dive

Input：当前视频帧特征、历史 memory keys/values、上一帧传播状态。Step 1：下采样 query 和 memory，做一次低分辨率传播，获得粗 readout、attention affinity 与 uncertainty。Step 2 Query Pruning：保留不确定性高的少量空间位置作为高分辨率 query；低风险区域直接复用粗结果。Step 3 Memory Pruning：依据这些 query 对历史 memory 的 affinity 选择相关位置，而非遍历整个历史。Step 4：仅在选中的 query–memory 对上做高分辨率匹配，覆盖粗 readout 的对应位置。Step 5：其余位置由上采样粗 readout 填充，保证输出仍是完整的 alpha matte。Step 6：以 MatAnyone 2 原 decoder 为 teacher，训练按阶段 profiling 设计的轻量 decoder；部署时只用 student。4K 附录采用 4→2→1 的逐级细化路径。

Objective / Toy Example

主要是推理时稀疏化与 decoder 蒸馏，不是 RL。可以将计算预算理解为：min Latency(Q_high,M_high)+λ·MattingError，其中 Q_high、M_high 由粗阶段的 uncertainty/affinity 决定；此式是便于理解的抽象目标，不是论文原式。Toy：一帧 100 个粗区域，只有 7 个区域发生头发移动；模型只对这 7 个区域重新做高分辨率历史匹配，剩余 93 个沿用粗传播结果；再只查询与这 7 个区域相关的 15% memory。7/100 与 15% 是机制示意，论文具体 ablation 的高分辨率 query 比例为 6.99%。

Baseline & Experiment Setup

主要 baseline：MatAnyone 2（同架构前身，最重要比较）、VideoMaMa、SAM2Matting，以及均匀 query 选择和 alpha 边界 query 选择。Dataset：VideoMatte HR、YouTubeMatte HR、CRGNN；Metric：MAD、MSE、Grad、dtSSD，越低越好。系统：A800-SXM4-80GB 的非编译性能，以及 H200 NVL 编译性能，必须分开看。RQ1：能否在 4K 保持质量同时降低显存？RQ2：uncertainty 是否比均匀/边界选择更值得精算？RQ3：轻量 decoder 与稀疏 memory 各承担什么成本？

Results & Figure Reading

Ablation / Failure

移除 query 筛选会让更多位置走高分辨率路径；移除 memory 筛选会让每个被保留 query 仍需搜索过多历史；移除轻量 decoder 会恢复高分辨率解码瓶颈。公开可读材料给出 uncertainty vs uniform/boundary 的数值消融，但未提供所有组件逐项的完整数表，故不虚构贡献比例。失败场景可能包括快速镜头切换、低分辨率漏检的细小新物体、长时遮挡后的错误 memory 选择；这些是研究风险假设，不是论文已证实的 failure case。

Contribution / Research Value

贡献类型：New Sparse Memory Retrieval、New System Engineering、New Efficiency Trade-off。对 Video LLM 的可迁移价值在“低分辨率 evidence gate → 仅在必要时高精度编码 → 选择性历史 KV 检索”，而不是直接复用 matting 网络。对 Streaming Agent 也有启发：连续观察时，不必对每帧的全部区域重算，只要给新证据和状态变化保留预算。系统论文价值高，但跨任务 transfer 需要全新实证。

Migration / Minimum Experiment

五句话总结

真正的瓶颈是跨帧 memory matching，不只是图像编码。低分辨率 uncertainty 把精算决策提前。A800 4K 实测 8.1 FPS、6.08 GB，而相对旧模型的 7.4× 为估计值。抠像质量有轻微损失，不能写成完全无损。最值得研究的是把 query-aware 稀疏历史检索迁移到 Video Agent。
