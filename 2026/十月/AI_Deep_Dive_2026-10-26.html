Paper 1 · When to Follow the Teacher: Advantage-Based On-Policy Distillation

RL / ReasoningNew Objective + Theory2026-10-22 UTC · 最新论文代码已核验

1.1 基本信息与一句话定位

作者：Mahdi Sabbaghi、George Pappas、Hamed Hassani、Adel Javanmard。机构：University of Pennsylvania、University of Southern California。日期：2026-10-22（arXiv v1）；Venue / Status：arXiv 预印本，未核实正式会议接收。正文：arXiv HTML · PDF · 官方代码：AOPD GitHub。无单独项目主页的已核实证据。

一句话定位：它把 On-Policy Distillation 的学习目标从“尽量像教师”改成“只强化对当前学生完成任务真正有帮助的教师动作”，并用现成学生 rollout 的终局 reward 构造无需反事实 rollout 的估计器。

1.2 人话版（问题、方法、结果、意义）

假设老师能解一道难题，学生只能解简单题。老师推荐“先引入一个复杂定理”，老师自己接下来能把证明做完，但学生采用这个开头后很可能卡住。传统知识蒸馏只看“老师认为哪个 token 好”，于是强迫学生走老师的路；哪怕学生原来有一条笨但能走通的路线，也可能被压制。AOPD 反过来问：假设学生在这里采用老师建议的动作，随后仍由学生自己完成，最终成功率究竟增加还是减少？ 它用学生自己的终局成败、教师与学生的 token 概率比，以及一个减去基线的校正项，估计这种“对学生有用”的优势信号。论文在数学、代码、生物与医疗问答上比较 GRPO、常规蒸馏和自蒸馏；例如 Qwen3-8B 自蒸馏的 AIME24 为 52.1%，常规 OPSD 为 41.7%。关键价值不是简单再加一个 reward，而是指出教师偏好与学生可实现的成功并非同一目标，并给出一个理论上可分析、训练上可实现的修正。

1.3 Background & Research Gap：旧范式为什么会失效

SFT 用固定教师答案训练，训练输入与学生真实推理时访问的历史不同，容易产生 exposure bias。On-Policy Distillation（OPD） 让学生先自己采样，再请教师在学生实际走到的历史上给出 token 分布；这修复了“状态分布不匹配”，却没有修复“目标不匹配”。GRPO 直接用终局 reward 训练学生，但当正确答案很少出现时，奖励稀疏、组内方差小，训练信号弱。KDRL 把 OPD 与 RL 项相加，看似兼得教师知识与任务奖励，然而两个梯度仍可能互相冲突。

一个具体例子：学生在证明题中有 80% 概率沿初等路线走到正确答案；老师有能力走抽象代数路线，因而在分叉处强烈推荐抽象路线。老师的完整策略比学生更强，不代表“老师第一步 + 学生后续”更强。常规 OPD 提升老师首选 token 的概率，可能降低学生的成功率。论文填补的 gap 正是以学生当前 continuation 能力定义教师指导价值，而不是用教师概率、熵或局部相似度充当价值。

这也解释了为什么只把训练数据换成 on-policy 不够：训练数据分布对齐是“在哪些状态学习”的问题，优势加权是“这些状态下应该学习哪些动作”的问题。二者正交。论文的贡献依赖可计算终局 reward 与教师 log-prob，并不声称在完全不可验证的开放式任务中也同样有效。

1.4 Core Insight：把教师动作视为一次干预

作者的核心观察来自两个层次。机制层：教师在历史 h 上认为动作 a 概率高，只说明教师愿意这样做；若把 a 插入学生轨迹，学生后续完成任务的概率可能降低。实证层：512 条数学学生轨迹的单 token 干预中，在教师/学生 KL 最大的位置替换成教师最可能 token，9.6% 的案例从失败变成功，9.8% 却从成功变失败；这不是“教师总有帮助”的分布。这个观察是干预实验的经验事实，而不是直接证明所有训练步都有负作用。

由此定义 student-relative advantage：A^S(h,a)=Q^S(h,a)−V^S(h)。其中 Q 是“强制采取动作 a，后续交还给当前学生”的期望终局 reward；V 是学生照常行动的期望 reward。正优势意味着老师的动作有益，负优势意味着老师的动作对当前学生有害。优势随学生能力改变：学生学会后续步骤之后，同一个复杂动作可能从负变正。这是一种动态、学生条件化的教师筛选，不是固定教师质量评分。

困难在于直接算 Q 需要每个 token、每个教师备选动作都生成多条后续轨迹，成本爆炸。作者用重要性采样恒等式把“教师动作的期望”改写为“学生已采样动作的期望”，再用 baseline 校正去掉 V。它是有明确推导的估计器；在满足 support、独立 baseline 和未截断条件下，对目标函数及其梯度无偏。注意“无额外 rollout”不等于“无额外算力”：仍需教师在学生历史上计算分布，并做全词表或近似的监督计算。

1.5 Method Deep Dive：从输入到参数更新

Prompt / 可验证任务 → 冻结当前学生 S → 每题采样 G 条学生轨迹 → 计算终局 reward → 教师评估每个访问过的历史 → importance ratio + leave-one-out baseline → 构造 AOPD loss → LoRA 更新 Sθ → 下一批重新采样

Step 1｜输入与轨迹。 输入是 prompt x、学生策略 S、教师策略 T 和可执行 reward R(x,y)。在一次训练迭代开始时冻结 rollout 策略 S，生成 y=(a₀,…,aH−1)。历史 h_t=(x,a₀,…,a_{t−1}) 来自学生而非教师，避免教师生成历史与学生部署历史脱节。若学生从未采样到某类必要动作，后续重要性估计会变得高方差；因此 support 与探索分布很重要。

Step 2｜任务结果。 数学按最终答案是否正确给二值 reward；代码按 5 个测试用例的通过情况给部分 reward。组内 G 条响应共享题目但结局不同，计算 b_i=mean(R_j, j≠i)，得到 R_i−b_i。Leave-one-out 避免 baseline 依赖当前被评分轨迹，从而保持论文证明需要的条件。全错组的中心化 reward 为零，会出现学习停滞，官方代码还提供 mu 机制补救，属于工程细节，不能与纯理论目标混为一谈。

Step 3｜教师打分。 在学生每个历史 h_t 上获得教师的 T(a|h_t)，并读取冻结学生的 S(a|h_t)。关键比值 w_t=T(a_t|h_t)/S(a_t|h_t)：当学生偶尔采到教师很看好的动作时，这个样本可以代表更大的教师概率质量；若 S(a) 接近零则方差可能极大。AOPD 关闭 top-k/top-p 截断，使用温度 0.8 来保证理论所需的动作 support。

Step 4｜双项校正。 第一项让带有 reward 的学生采样动作按教师比值加权；第二项对教师完整分布的 log-prob 做校正，相当于减去该历史的 student value。只保留第一项就不再是 student advantage，而更接近带权终局 reward；两项同时存在是本方法区别于普通重要性加权模仿的关键。

Step 5｜截断与优化。 令 w̃=min(w,c)，论文使用 c=4，并对第二项中的教师质量同样采用 T̃(a)=min(T(a),cS(a))。它降低高比值方差，但严格来说截断后优化的是截断目标，不再是原始未截断目标的无偏估计。优化时只对 Sθ 求梯度，S 与 T 停止梯度。官方实现还有对截断残余概率质量的 sigmoid 修正，以及可选的全错组 KL；复现必须记录这些开关，否则“论文公式”和“开源代码”可能不是同一实验条件。

Step 6｜迭代反馈。 更新后的学生重新生成下一批轨迹；随着学生 continuation 变强，Q、V、A 的含义发生变化，原先不值得模仿的教师动作可能变得有益。潜在失败点包括 teacher/student tokenizer 不兼容、teacher logits 不完整、reward 噪声、importance ratio 尖峰、组内奖励全同、教师动作没有 student support。

1.6 核心公式与数学直觉

价值与优势 · Eq. (3.4)
QS(h,a) = Estudent continuation[R | h,a]
VS(h) = Ea∼S[QS(h,a)]
AS(h,a) = QS(h,a) − VS(h)

Q 不是老师做完整道题的成功率，而是“学生执行老师给出的这一步，学生自己完成剩余部分”的成功率。V 是学生自己从该历史出发的平均水平，A 是超额收益。A 大于 0 才有强化的依据。由于这里是 token-level action，信用分配的基本单位是 token；它不自动解决工具调用等长跨度动作的 credit assignment。

FKL 与 AOPD · Eq. (3.3)/(3.5)
JFKL = Eh∼S,a∼T[log Sθ(a|h)]
JAOPD = Eh∼S,a∼T[AS(h,a) · log Sθ(a|h)]

两式均最大化；FKL 对所有教师动作施加同向模仿压力，AOPD 则按优势的正负改变梯度方向。它与 GRPO 的差异也很明确：GRPO 用同组终局 reward 直接加权学生采样 token，AOPD 进一步用教师分布对“该信号是否值得模仿”进行过滤与校正。Strongest baseline 不是固定唯一的：外部教师数学 AIME24 上 OPD-RKL 最强（32.6），代码 pass@10 上 GRPO 最强（87.9）；自蒸馏 Qwen3-8B AIME24 上 OPSD 是最强模仿基线（41.7）。

无需反事实 rollout 的估计 · Eq. (3.6)
Ĵ = (R−b)/H · Σt{ [T(at|ht)/S(at|ht)] log Sθ(at|ht) − Ea∼T[log Sθ(a|ht)] }

证明要点：对学生采样动作求期望，S(a)·T(a)/S(a) 消去 S，第一项产生 T(a)(Q(a)−b)；第二项产生 T(a)(V−b)；相减恰为 T(a)(Q−V)。因此不是神奇地“知道”反事实，而是用随机样本的期望恒等式估计它。代价是方差；clipping c 从 4 增大时偏差趋小但不稳定风险上升，c 过小时可能过度抑制教师支持动作。

局部保证 · Eq. (5.3)
Ea∼S⁺[AS(h,a)] = η Ea∼T[AS(h,a)²] / (1 + η Ea∼T[AS(h,a)]) ≥ 0

分子是平方优势，所以非负；在足够小的 KL-proximal 步长 η 下可推出单次理想化策略更新的期望 reward 不下降。这里 KL 是 KL(S||π)，约束更新不能离原学生太远；它并不保证实际有限 batch、LoRA、SGD、近似 logits 和 noisy reward 的每一步都单调提升。论文还给出二步反例：即使教师完整策略更强，FKL+RL 的混合梯度仍可能让学生退步。这是该论文最重要的理论边界与亮点。

1.7 Toy Example：教师强，但教师的第一步不适合学生

设题目有“稳妥路线 safe”与“困难路线 difficult”。学生 S(safe)=0.8, S(difficult)=0.2；学生继续完成时 Q^S(safe)=0.9, Q^S(difficult)=0.3。于是 V^S=0.8×0.9+0.2×0.3=0.78，A^S(safe)=+0.12，A^S(difficult)=−0.48。教师却更喜欢困难路线：T(safe)=0.3, T(difficult)=0.7。若教师亲自继续，两条路线成功率可为 0.95/0.98，教师完整策略成功率 0.3×0.95+0.7×0.98=0.971，确实强于学生。

传统 FKL 会把学生的 difficult 概率往 0.7 推；AOPD 的教师加权贡献则是 safe 的 0.3×(+0.12)=+0.036、difficult 的 0.7×(−0.48)=−0.336，抑制困难路线。实际训练并不直接获得上述 Q。若某条学生采样轨迹走 safe 且成功、同组 leave-one-out baseline 为 0.5，则 R−b=+0.5、w=T(safe)/S(safe)=0.375；它把这条成功轨迹和教师全分布送入 Eq. (3.6)，在多次采样的期望中恢复优势方向。这个 toy 是解释公式的自造案例，不是论文数据。

1.9 Experiment Setup & Metrics 教学式解释

Research Question A（外部教师）：教师更大时，AOPD 是否比 OPD、GRPO 更好？学生 Qwen3-1.7B；数学教师 Qwen3-4B-Instruct-2507，代码教师 Qwen3-8B。Open-Thoughts 数学训练 450 steps，TACO verified 代码训练 350 steps。Research Question B（自蒸馏）：同一模型在获得 ground-truth privileged context 后充当教师，是否仍有负迁移？数学用 Qwen3-1.7B/8B 400 steps；医学 300 steps；生物和代码 400 steps。医学训练 MedMCQA、评估 MedQA 与 held-out MedMCQA；生物训练 SciKnowEval、评估其 held-out 与 MMLU-Pro；代码评估 HumanEval+ 与 MultiPL-E。

训练控制：论文在各组比较中固定 batch=32、LoRA r=64/α=128；AOPD G=4，GRPO/KDRL G=8；数学训练最长 8192 tokens，评估可达 16192；Qwen3 为 non-thinking mode。AOPD 采样 temperature 0.8、top-p=1、top-k 关闭，数学与代码学习率 2e−5；其他任务与方法有各自配置。Compute：官方脚本默认 8 GPU、BF16；论文没有给可跨硬件比较的总 GPU-hours / 训练成本，不应编造。外部代码 reward 需要可执行测试环境，仓库提供 SandboxFusion 配置。不同方法 G 与 sampling 不完全相同，故实验更接近“各方法合理调参”而非完全相同采样预算。

pass@1：每题一次生成成功的比例，越高越好；最贴近单次部署成功率，但受 decoding 与题目难度影响。pass@10：10 次生成至少一次通过的估计概率，越高越好；衡量候选多样性和搜索潜力，可能与 pass@1 排名相反。HumanEval / HumanEval+：代码执行测试正确率，HE+ 的额外测试更严格；并不等价于真实软件工程能力。MultiPL-E：跨七种语言的代码生成平均表现；可揭示 Python 训练迁移不足。AIME24/AMC/HMMT：不同难度的数学竞赛评估，都是 pass@1，但小测试集会放大波动。SciKnowEval/MMLU-Pro/MedQA/MedMCQA：领域 QA accuracy，越高越好；医学答案正确不等于临床可靠性。Training reward：训练集/验证集上的 reward 曲线，不能代替跨 benchmark 泛化。KL(T‖S)：教师相对学生的分布差异，越大只说明分歧越大，不说明哪方更正确。

1.10 Results Deep Dive：9 个具体结果与反证

  1. 外部教师数学主结果：Open-Thoughts pass@1，AOPD 78.4 对 OPD-FKL 73.2，+5.2 pp；GRPO 为 71.8。说明 dense teacher signal 与 outcome 结合有效，但不是证明更长推理任务都受益。
  2. AIME24：35.0 对最强 OPD-RKL 32.6，+2.4 pp；比 GRPO 22.3 高 12.7 pp。支持数学迁移，不过样本量较小，单次成绩需谨慎解读。
  3. AMC：65.1 对 OPD-FKL 61.8，+3.3 pp；相对 GRPO 51.4 更高 13.7 pp。跨题型一致性比单独 AIME 更有说服力。
  4. HMMT 反例：AOPD 15.8，OPD-FKL 16.0，−0.2 pp；并非所有数学 benchmark 最好。高难度任务上可能仍受 rollout 成功稀缺限制。
  5. 代码 pass@1 与 pass@10 分离：HumanEval AOPD 74.4，GRPO 71.8，+2.6 pp；但 HumanEval pass@10 为 86.5，GRPO 87.9，−1.4 pp。提高单次成功可能牺牲候选覆盖。

  8. 生物模型依赖的明显失败：Qwen2.5-7B SciKnowEval AOPD 54.0、GRPO 42.0，+12.0 pp；但 Qwen3-4B 同指标 AOPD 32.0、OPSD 44.0，−12.0 pp。这是不能用“跨域全面领先”掩盖的模型特异弱点。

Strongest result 可选 Qwen3-8B 自蒸馏 AIME24 的 +10.4 pp（相对 OPSD）及 Qwen2.5-7B 生物 +12.0 pp（相对 GRPO），前者机制对应更直接。Weakest result 是 Qwen3-4B 生物 −12.0 pp，且 HumanEval pass@10、MultiPL-E 都没有全面领先。Trade-off：更密集教师评估、全词表概率计算和可能的探索分布差异，换取更好的 outcome alignment；论文没有给吞吐或 GPU-hours，不能宣称训练绝对更省算力。

1.12 Ablation / Mechanistic Analysis

去掉 advantage、只做 OPSD/OPD：Table 2 的 Qwen3-8B AIME24 从 AOPD 52.1 降至 OPSD 41.7，表明结果条件化的监督确有作用；但两方法的 loss、采样温度和其他训练细节也不同，不能把 10.4 pp 全部归因于某一行公式。不做 clipping：Appendix Figure 5 报告更大的训练波动；论文没有提供该图的精确纵轴表格值，因此不能捏造具体下降幅度。改变组大小 G：Appendix Figure 4 显示增大 G 对 AOPD reward 改善很小，且不一定转化为 benchmark 增益；这是 sample efficiency 的积极信号，但没有逐 GPU-hour 的成本比较。

最高 KL 分歧位置的教师替换：Table 4 中改善 9.6% 与损害 9.8% 几乎相当，说明“教师/学生不一致”不是充分的监督门控规则。它是局部干预证据，不等于训练中的 advantage 估计无偏性已被实验验证。理论机制：Theorem 5.1 的平方优势非负与二步反例一起说明“按 student advantage 加权”为什么比“RL loss + imitation loss”更有针对性；证明在理想 policy-space proximal 更新上成立，不自动推广到有限参数神经网络训练。

1.13 Claim vs Evidence

Authors Claim：教师指导应按对学生任务结果的优势筛选；可不额外 rollout 估计；理想化 AOPD 更新具 reward-improvement 保证；跨数学、代码与 QA 提升。

Experiments Actually Show：在给定 Qwen 模型、LoRA、数据与可验证 reward 下，多数 benchmark AOPD 比主要对照更好；干预实验确实出现教师有害动作；开源代码能落地该训练流程。理论证明的是满足 support 与精确 proximal 条件的局部策略更新，不是实测每步 monotonicity。

What Is Not Yet Proven：在完全开放式 Agent 工具链、没有正确答案的长程任务、噪声 judge reward、闭源教师仅返回文本、tokenizer 不同、跨 70B+ 模型的效果；是否在相同训练 FLOPs/teacher compute 下仍领先；是否在所有领域都优于 OPSD（生物 Qwen3-4B 已反例）。

1.14 Contribution、Limitation & Failure Modes

Contribution 1 — New Objective / New Mechanism：定义 teacher action 的 student-relative advantage 并嵌入 on-policy 蒸馏，是主要概念创新。Contribution 2 — New Estimator：用已有 student rollouts 的 reward 和重要性比估计该目标，避免为每个教师动作做反事实续写；重要性采样本身是已有工具，新的在于双项抵消后对应的目标。Contribution 3 — New Theory：给出 KL-proximal 单步改善与 FKL+RL 反例，属于明确理论贡献。Contribution 4 — New Empirical Finding：单 token 干预中教师帮助与损害并存；不是新 benchmark。代码在已有 TRL/vLLM/LoRA 组件上构建，属于可复用工程组合。

Authors' Limitation（论文可见范围）：方法需要教师 token 概率和可验证 reward；采样分布需要足够 support；实验聚焦 Qwen、数学/代码/QA。Additional Limitation：极低学生概率造成权重爆炸，clip 引入目标改变；全错组的 advantage 近零；偏好 reward 或 LLM-as-judge 可能产生 reward hacking；对长工具轨迹使用 token 级优势会误把偶然终局成败归因于早期动作；教师与学生 tokenizer 不同会破坏比值；代码 mu 和 residual correction 使“纯 AOPD”复现边界复杂。数据污染、测试集泄漏、不同方法 temperature/G 与训练 compute 差异也需独立审计。

1.17 Migration Analysis：两个可以开工的实验

Migration A · Agent Tool-Choice Advantage Distillation

Original Problem：教师的 token 建议未必提高学生终局成功。Transferable Mechanism：student-relative advantage + on-policy importance correction。New Research Question：教师建议某工具时，学生后续工具链是否真的更可能成功？Method Modification：把 token action 换成离散工具 ID；工具调用历史为 h，教师在 top-20 候选工具上输出归一化概率，学生在同一候选集采样，使用终局任务 reward 的 AOPD 两项估计；可额外引入错误工具调用惩罚，但必须与原始 reward 单独消融。

Minimum Experiment：先构造 200 条可重放、确定性工具链任务，每条需要 2–5 次工具选择；工具库含 30 个函数（查找、计算、文件查询、数据库模拟），每个状态提供 10 个候选；80/20 训练测试划分。学生 Qwen3-1.7B LoRA r16、教师 Qwen3-8B，G=4, batch=16, lr=2e−5, steps=200, temp=0.8, clip=4, seed=[42,43,44]。每条轨迹记录 state, candidates, action, logp_student, logp_teacher, reward, next_state，训练 AOPD/OPD-FKL/GRPO/纯规则。Model：Qwen3-1.7B / Qwen3-8B。Dataset：先合成可验证工具任务，再用 ToolBench 子集做外推。Baseline：SFT、OPD-FKL、GRPO、无教师 RL。Metric：end-to-end task success、tool recall@k、平均调用次数、teacher-query tokens、help/harm intervention rate。Expected Contribution：把 outcome-aligned distillation 扩展到工具级 credit assignment。Risk：teacher/student 工具 action support、环境非确定性、reward 稀疏。Collision Risk：与 tool-use RL、trajectory-level teacher validation、counterfactual tool planning 现有研究高度相关；创新必须是无额外 rollout 的可验证工具级优势估计。

Migration B · Outcome-Aligned Video Frame Policy

Original Problem：教师认为重要的帧不一定是当前 Video VLM 真能用来回答问题的帧。Transferable Mechanism：student-relative advantage 对教师帧选择建议做筛选。New Research Question：在固定视觉 token 预算下，是否能用 QA 成败而非视觉相似度训练 query-aware 帧选择器？Method Modification：把帧选择视作多步离散 policy；teacher 是全帧 VLM 的帧重要性分布，student 是仅能看 8 帧的轻量选择器；终局 reward 为 QA correctness，额外记录 latency 但初版不混进 reward，防止优化目标不清。

Minimum Experiment：LongVideoBench 先抽 500 个有标准答案的样本；每视频统一解码 1 fps、最多 128 候选帧；选择器按 8 次 action 不放回选帧；冻结 Qwen2-VL-7B 答题模型，训练小选择器（Qwen3-1.7B LoRA 或 2-layer MLP over CLIP features），G=4, 3 seeds, 200 updates, clip=4。Model：Qwen2-VL-7B + 轻量选择器。Dataset：LongVideoBench 500 样本开发，另留 200 独立测试。Baseline：Uniform-8、CLIP-query top8、teacher top8、GRPO、OPD。Metric：QA accuracy、帧数、visual tokens、TTFT、总延迟、跨视频长度泛化。Expected Contribution：把帧选择从 proxy score 转向 student downstream value。Risk：高成本全帧 teacher、选择动作依赖、视频 benchmark 答案偏差。Collision Risk：与 query-aware frame selection / RL frame sampling 已有工作碰撞，必须突出优势估计与零额外反事实 rollout。

1.18 Attack / Verification Lens

可做 black-box teacher-harm probe：从学生正确轨迹选一处替换为教师推荐动作，再测最终是否失败，定义 Harm@1 与 Net Intervention Gain=Help−Harm；可进一步按 KL、teacher confidence、trajectory depth 分桶。Robustness：把 reward verifier 故意注入 5–10% 错标，观察 AOPD 是否比 GRPO 更易 reward hacking；Recovery：学生掌握复杂后续后，同一 teacher action 的优势是否从负转正；Efficiency stress：增大词表、group size、序列长度记录 teacher forward FLOPs 与 tokens/s。注意上述均为研究建议，非论文已有结果。

AOPD 用 Q^S−V^S 定义 teacher action 的学生相对优势。 4. 它把优势乘进教师蒸馏目标，而不是额外拼一个 RL loss。 5. 重要性比值与减去教师期望项，使现成学生 rollout 的终局 reward 足以无偏估计未截断目标。 6. Clip=4 控制方差，但改变原目标；理论保证针对精确 KL-proximal 更新。 7. 2.1 基本信息与一句话定位

作者：Bin Hu、Yingbo Xiao。机构：Tsinghua University、The Chinese University of Hong Kong, Shenzhen。日期：2026-10-22（arXiv v1）；Venue / Status：arXiv 预印本，未核实正式会议接收。正文：arXiv HTML · PDF。代码：论文 Appendix M 写明“Code, logs and registration files will be released”，截至本次检索没有核验到已公开的官方仓库；不得把未来承诺写成 Code Available。

一句话定位：它把多模态 KV cache 的更新拆成两个问题——用 attention drift 决定何时/何处更新，用每样本速率控制决定更新多少次——修复一次性视觉 KV 选择在长文本生成中的证据过时问题。

2.2 人话版（250–400 字）

让视觉语言模型看一张复杂照片并写几百字描述，开头它可能关注人物，中间关注滑板坡道，后面才描述角落垃圾桶。为了省显存，常见方法在 Prefill 时选出少数“重要视觉 token”，其余丢掉或放在 CPU。问题是重要性会随生成内容移动：开头不重要的垃圾桶，写到后面可能正是关键证据。RCR 不再指望一次选择永远正确，而是保留完整前缀 KV 的可恢复副本，让 GPU 上的小 cache 按需替换。作者发现，直接设固定“漂移超过 0.03 就更新”仍会饿死某些样本，因为不同图像的漂移数值不可比较。RCR 让每个样本维护一个自适应阈值，使大约 40% 的层-步执行刷新，同时用 8 维低秩探测器和候选重排控制数据搬运。六组图像任务中，它有五组显著优于 InfiniGen；但最重要的警告是：论文只测了模拟卸载的流量，没有证明端到端 wall-clock 加速，而且在视频上相对固定阈值的优势消失。

2.3 Background & Research Gap：省什么、为什么旧方法不够

Transformer 解码时，每个历史 token 的 Key/Value 需要缓存，以免每生成一个新 token 都重新计算前缀。多模态输入的视觉前缀可能包含数百到数千 token；论文的图像任务前缀约 640–2300 tokens，视频任务 32 帧、约 2205–2342 tokens。One-shot eviction（SnapKV、PyramidKV、BACON）在 Prefill 后选择 c 个重要 prefix token，GPU 只保留小集合；它省 GPU KV memory，但一旦被删掉的证据无法再读，后续生成会遗漏细节。

Per-step retrieval（Quest、ArkVale、InfiniGen）把完整 KV 放在可访问的外存/CPU，解码每一步从中取当前需要的 token；它改善证据新鲜度，但每一步都搬运数据，且近似选取会错。Periodic refresh 每 T 步重新选一次，省决策复杂度却不看语义转折；fixed drift threshold 只在被丢弃 token 的 attention mass 大时刷新，已经比固定周期更聪明，但其阈值在不同图像/模型/生成位置间不校准。

具体例子：同一图片，模型先说“一个人站在滑板旁”，再说“坡道上方的标识”，最后说“远处垃圾桶”。如果 Prefill 只留下人和滑板相关的 token，第三段就缺乏视觉依据。作者甚至用完整答案的 attention 作为离线 oracle 去做一次性选取，在 DetailCaps 上 ROUGE-L fidelity 也只有 0.44–0.52；这是“更聪明的一次选择”解决不了的结构性问题。注意这个 oracle 是用于诊断的非部署基线，不能实际在线使用。

2.4 Core Insight：重要性分数与预算不是一回事

作者的第一个 observation 是 attention evidence shifts：相邻生成步最受关注的前缀位置保持不变的比例，在不同模型上只有 41%–80%；某些新关注区域远离旧区域。第二个 observation 更有价值：drift 绝对值不能跨样本比较。固定阈值在 Qwen2-VL DetailCaps 的高漂移样本中刷新 35% 的层-步，已接近精确每步重选；低漂移样本却只刷新 1%，而这些样本恰好从 BACON 0.462 到 exact 0.763，有高达 30.1 个百分点的潜在 fidelity 收益。直觉上“漂移小”似乎不需要更新，实则小的 attention mass 也可能对应极重要的视觉细节。

第三个 observation 是时间漂移：随着生成文本变长，新文本 token 分走 attention，视觉前缀上被丢弃部分的绝对 mass 会自然下降。固定阈值于是前期频繁刷新、后期几乎停止。RCR 的关键并非另造一个更准的静态分数，而是用漂移排序决定局部时机，用反馈控制器调节每个样本的触发率。这属于“经验诊断 + 控制工程 + 低秩近似”的组合：漂移和 SVD 都不是新概念，创新在于将 score calibration 与 budget allocation 解耦并以实验证实其必要性。

2.5 Method Deep Dive：完整数据流

图像/视频 + 文本 prompt → Prefill 得到完整 prefix KV → BACON 选 GPU 小 cache → SVD 生成低秩检测器 → 每个 decode layer-step 估计 evicted attention drift → per-sample 阈值反馈控制 → 触发时粗选 4c 候选、精排 c → 掩码更新 GPU KV → 继续生成

Step 1｜两层 cache 布局。 每层、每 KV head 有完整视觉前缀 K,V，前缀长度 Np。GPU 实际用于 attention 的 cache 布局是 [c 个被选 prefix KV | W 个窗口 KV | 已生成文本 KV]。论文主设置总预算 64 prefix entries/head，c=32, W=32。完整前缀在部署设想中留在 CPU，以便被“重新召回”；但论文实验为了模拟卸载，把完整前缀仍放在 GPU。因此论文的 memory/latency 结果必须按“模拟系统”解释，而不是已上线 CPU-offload 系统。

Step 2｜Prefill 与初选。 先用 BACON 根据 Prefill 的 attention 选出首批 token。它是强 one-shot baseline，也是所有动态方法共同起点。选错并非致命，只要完整 KV 副本还在，后续可以恢复；但副本占用 CPU 内存，不能把方法描述成“完整 KV 被永久删除”。

Step 3｜构造廉价 drift detector。 对每层、每 KV head 的前缀 key 矩阵 K∈R^(Np×128) 做 SVD，取前 R=8 个右奇异向量组成 P_R∈R^(128×8)，在 GPU 保留 K P_R。当前 query q 也投影为 qP_R；两者点积近似原 qKᵀ，能估计被逐出 token的 attention mass 和粗略 token 排序。对仍在 cache 的 token 使用精确 logits。8 维并非理论保证足够，只是论文选定的速度/精度折中；当重要信息位于低能量子空间时，探测器可能漏报。

Step 4｜计算 drift。 对每个 KV head h，求估计 attention 分布落在未保留 prefix token 上的总质量 d̂_{l,h}(t)，再对该层所有 KV heads 求均值。超过当前样本阈值 τ 则触发该层刷新。漂移是触发信号，不是直接的任务 reward，也不是语义重要性真值；其失真会导致误触发或漏触发。

Step 5｜每样本 rate controller。 每张图像/视频单独维护一个 τ，初始化 0.03；每完成一次 layer-step 检查，令 m=1 表示刷新、m=0 表示不刷新，执行 τ←τ·exp(η(m−ρ))，论文 η=0.05, ρ=0.4。若刷新太频繁，阈值自动升高；若刷新太少，阈值自动下降。一个样本的低 drift 不会永远得不到刷新；不同层共享阈值，层间相对 drift 高低仍能影响哪个层更常刷新。

Step 6｜候选粗选与精排。 一旦触发，先用 8 维 detector 选 top 4c 候选（c=32 时是 128 个）；从完整 KV 取这些候选的原始 key，用当前 query 做精确打分，再选 top c，取对应的 value。每次刷新理论上读 4c 个 key + c 个 value，共 5c 个 128 维向量；相比扫描全部 Np prefix 大幅减少搬运。失败模式是 detector 把真正重要 token 排除在 top 4c 外，后续精排也无法挽回。

Step 7｜GPU-side decision。 朴素 Python if 需要把 GPU 上的触发标量传到 CPU，每层每步同步会严重阻塞。作者改成始终在 GPU 计算候选，再用 torch.where / mask 决定写入新旧 cache；非触发层保持旧值。它在当前 GPU 模拟实现中可避免 host sync；但真正 CPU offload 还需要 GPU 掩码条件化 host read，否则每步都取 5c 就失去节流意义。这一尚未实现的系统环节，是论文从算法到真实加速的最大缺口。

2.6 核心公式、SVD 与系统成本

Evicted attention drift · Eq. (1)
dl,h(t)=Σj∉Sl,h at,j
dl(t)=(1/Hkv) Σh dl,h(t)

S_{l,h} 是当前缓存的 c 个 prefix token 下标；a_{t,j} 是当前生成步 t 对前缀 token j 的 attention 权重（对 GQA 共享 KV head 的多个 query heads 做平均，并按完整上下文归一化）。d=0.02 不代表只有 2% 的任务价值丢失，只代表注意力概率质量约 2%。一旦小质量对应决定性对象，质量损失仍可能很大。故 drift 的相对排序比绝对数值可靠。

Rate controller · Eq. (2)
τnext = τ · exp[η(m−ρ)]
log τnext − log τ = η(m−ρ)

这是对目标刷新率 ρ 的反馈：若 m=1 且 ρ=.4，logτ 增加 0.03；若 m=0，减少 0.02。它近似追踪 drift 的 (1−ρ) 分位点，避免手工为每个模型调 τ。η 大会更快适应突变但阈值振荡更强；η 小更稳却追不上长输出中的分布变化；ρ 大改善 fidelity 但增加搬运与候选计算。对短输出（12–29 步）控制器尚未收敛，实际刷新率 41–48% 高于目标 40%。

Low-rank detector · Section 5
K ∈ RNp×128, PR ∈ R128×8
ApproxLogit(q,k) = (qPR)(kPR)ᵀ
ExactLogit(q,k) = qkᵀ

SVD 选择最大能量方向，低秩投影减少探测器的存储与每步点积。8 个通道相对于 InfiniGen 的 32 通道使 GPU-resident detector 约小 4 倍；但这里的 4× 是探测器体积，不是整机显存减少 4 倍。论文对每次刷新候选精排用完整 key，避免把 8 维近似直接当最终 attention。SVD 还会带来 Prefill 末端的一次性开销，论文未提供端到端 TTFT 测量。

Data movement model · Section 5
RCR ≈ 5cρ = 5×32×0.4 = 64 vectors / step / KV head
InfiniGen ≈ 2c = 64 vectors / step / KV head
Fixed full scan ≈ ρ(Np+2c) vectors / step / KV head

它优化的主要是期望 CPU→GPU 数据搬运与 cache 质量，而非声称 Transformer FLOPs 全面降低。RCR 检测器还要每步扫描低秩 prefix、触发时计算候选、做 SVD；是否更快取决于 PCIe、host memory、GPU kernel、batching 与同步。论文估算 Qwen2-VL fp16 约 1.8 MB/token 的条件搬运，在 25 GB/s 理想带宽下约 75 μs；这只是数据传输下界的量级估算，不能当真实 TPOT。

2.7 Toy Example：8 个视觉 token 如何被重新召回

假设图片前缀有 8 个 token：[人物1,人物2,滑板1,滑板2,坡道1,坡道2,垃圾桶1,垃圾桶2]，GPU 只保留 c=2 个被选 token（为演示忽略窗口）。初选保留人物1与滑板1；完整 8 个 KV 在 CPU 可恢复。生成第一句“一个人拿着滑板”时，低秩估计未保留 token 的 attention mass 为 0.01，小于 τ=0.03，因此 m=0，更新阈值 0.03·exp(0.05×(0−0.4))≈0.02941，不刷新。

写到“他走上坡道”时，未保留 token 的估计 drift 变成 0.07，大于 0.02941，触发刷新，m=1，阈值变为 0.02941·exp(0.05×0.6)≈0.03030。探测器粗选候选，再用完整 128 维 key 精排，GPU 两个 prefix 槽换成坡道1、坡道2。继续写“角落有垃圾桶”时，若 drift 再升高，垃圾桶 token 可被重新召回。这个例子说明保留可恢复副本是必要条件；如果原 token 真被永久丢弃，控制器再聪明也不能重建证据。

实际论文用 c=32、候选 4c=128、检测器 R=8、ρ=.4；这里 c=2 仅用于手算。若 c=2，平均数据搬运 5×2×.4=4 向量/步，恰好等于每步取 2c=4 的方案；但按 drift 选时机可能在相同平均搬运下更忠实。这个 toy 不是论文测量结果。

2.9 Experiment Setup & Metrics：评估到底测了什么

Research Question A：一次性选择是不是结构性失败？ 用 Qwen2-VL-7B、LLaVA-NeXT-7B、Qwen3-VL-8B 在 DetailCaps 做 one-shot oracle 与动态重选对比。Research Question B：动态触发比固定频率好多少？ 控制候选检测器、预算与刷新率，只替换 random/periodic/drift trigger。Research Question C：跨模型、跨任务能否同一组参数？ 三模型 × DetailCaps/TextCaps 六个 setting，主参数固定 ρ=.4, η=.05, τ0=.03, R=8, c=W=32, candidates=4c。Research Question D：诊断是否可迁移到视频？ 在 300 个 ActivityNet VideoDetailCaption 视频（每段 32 帧）比较 Qwen2-VL/Qwen3-VL；不为了视频重新调 RCR。

数据与协议：DetailCaps 从 4870 图像中均匀取 300 个测试样本；TextCaps 取前 500 张验证图像；Qwen2-VL DetailCaps 的 100 张开发图像与 300 张测试图像有 2 张重合，不是绝对零重合。作者在开发集比较 14 个变体，再在六个设置下按预先登记的决策规则确认，另有 post-hoc ρ/budget 扫描。DetailCaps 最多生成 512 tokens，TextCaps 输出较短；视频也是最多 512 tokens、greedy decoding。Qwen2-VL 与 LLaVA 用 fp16，Qwen3-VL 用 bf16。所有动态 baseline 都在同一套 Transformers attention patch 模拟环境中实现，不是逐个官方系统原样部署。

Fidelity / ROUGE-L to full output：把压缩方法输出与同模型未压缩输出比较最长公共子序列相似度，越高代表更像 full-cache 输出；但 full-cache 可能幻觉，fidelity 高不等于事实更正确。Reference ROUGE-L/CIDEr：与人工参考描述比较，越高通常越好，但详细描述的表达多样性大，可能无法区分方法；论文发现动态方法之间差异很小。CAPTURE：通过 scene graph 解析对象/属性/关系，与人工参考比较，越高越好；依赖自动解析器，会误判同义词或遗漏。Object Precision/Recall/F1：把方法输出中的对象与 full-cache 输出中的对象比对，precision 高表示额外编造的对象少，recall 高表示漏掉的对象少，F1 是调和平均；它仍以 full-cache 输出为参照，不能证明真实物体存在。Refresh Rate：触发更新的 layer-step 比例，越低搬运通常越少，但质量可能差。Traffic：每步每 KV head 读多少 128 维向量，是成本模型，不是实测延迟。95% bootstrap CI：对配对差异重采样得到不确定区间，若包含 0 就不应声称显著领先；作者也指出多重比较未完全校正。

2.12 Ablation / Mechanistic Analysis

去掉 rate controller：改成固定 τ，低 drift 样本和长输出后期被饿死；Qwen2-VL DetailCaps Table 2 的 fixed 0.551（25%） vs RCR 0.598（40%），但刷新率不同，不能直接归因；应优先看 Figure 2 的分组诊断和相近 rate 扫描。去掉 drift 触发、换随机：Table 4 同 40% rate 下 0.598→0.548，下降 5.0 pp，是更干净的因果消融。去掉 low-rank detector、改 page-mean：开发集相近 rate 的比较提示低秩更好，但有 rate 混杂；关键价值是可做 token-level 排名与 top-4c 候选。

去掉 candidate-restricted re-selection：每次刷新要扫描全部 Np prefix，成本从 5c 上升到 Np+2c，在 Np≈1000–2300 时昂贵；它主要承担工程可行性，不是决定刷新时机的核心理论。去掉 GPU-side decision：Qwen3-VL 模拟环境每样本约 137 秒→40 秒（约 3.4×），但该数字来自 14 个评估进程/4 核主机的模拟同步瓶颈，绝对不能写成端到端模型推理 3.4×。ρ 扫描：Qwen2-VL DetailCaps ρ=.1/.2/.4/.6 的 fidelity 为 .538/.560/.598/.606，说明前期加预算收益更大、后期边际收益下降。视频反证：视频 drift CV 0.14–0.18，图像 Qwen CV 0.71–0.78；当样本间分数分布更同质，rate control 的独特收益不再显著。这是作者对自身机制假设较诚实的边界检验。

2.14 Claim vs Evidence

Authors Claim：一次性视觉 KV 选择对长描述有结构性不足；固定 drift 阈值跨样本不校准；按样本速率控制 + 低秩检测 + 候选精排在相近估算流量下提高 fidelity；视频漂移更同质时该优势会减弱。

Experiments Actually Show：图像六设置中五组 RCR 相比 InfiniGen 的 paired CI 不含 0；控制 trigger 的实验在同 rate 下支持“刷新时机重要”；低 drift 三分组和时间轨迹支持固定阈值饿死样本的诊断；视频上的 fixed threshold 反例与诊断相符。What Is Not Yet Proven：真实 CPU-offload 系统的 TTFT/TPOT/throughput/energy；在不同 batch size、长 streaming、多图/多轮 Agent 场景仍有优势；fidelity 的提升一定带来人类感知的事实正确率提升；RCR 与未实现的 DSTP 等触发策略相比的优势。

2.15 Contribution、Limitation & Failure Modes

Contribution 1 — New Empirical Finding：one-shot oracle 在长描述仍严重失真，揭示证据时变性；这一诊断比小幅榜单提升更可迁移。Contribution 2 — New Mechanism / Engineering：将漂移排名与每样本 rate control 分离，控制器实现自适应分位点。Contribution 3 — New System / Engineering：8 维 SVD detector + top-4c coarse-to-fine + GPU-side mask；均借用成熟数值/系统组件，创新主要在组合与适配。Contribution 4 — New Evaluation Protocol：开发-确认分离、paired bootstrap、对象级质量、视频异质性反证；并非新数据集。

Authors' Limitation：只评估三款 7–8B 模型的图像 caption、两款模型的视频 caption，budget 64 为主；budget 256 的提升不显著；视频不优于匹配 rate 的 fixed threshold；参考指标差异小；没有人类评测；开发/测试存在 2 张重合；对比均为统一模拟重实现；未测真实 offload latency。Additional Limitation：CPU 副本可恢复性与带宽容量依赖；SVD 初始化可能拖慢 TTFT；GPU-side mask 仍可能执行无效候选计算；低秩 detector 遗漏低能量但关键的细节；自动 scene-graph parser 的错误；当压缩诱发幻觉时“接近 full output”不等于正确；动态缓存跨 batch/跨请求的调度复杂度、cache consistency、并发 offload 尚未验证。

2.18 Migration Analysis：两个不同研究方向

Migration A · Streaming Video 的可恢复时序记忆

Original Problem：长输出时图像证据发生漂移，固定阈值可能错过关键细节。Transferable Mechanism：drift-trigger + per-stream budget controller + recoverable KV。New Research Question：在连续流视频中，事件发生后若干秒才被问及，能否用低成本的动态证据回取降低遗忘和延迟？Method Modification：把视觉前缀按时间段 chunk；缓存每段压缩 token 的轻量索引，GPU 只留近端窗口与少数关键段；将 RCR 的样本级 τ 扩展成按事件突变与 query 变化自适应的双时间尺度控制器，允许“高风险事件临时借预算”，事后归还。

Minimum Experiment：先从 ActivityNet/VideoDetailCaption 取 200 个视频，统一 1 fps 生成 32/64/128 帧版本；冻结 Qwen2-VL-7B；GPU 视觉 KV 预算设 64/128 entries/head；每 8 帧设一 chunk，事件查询在视频末尾和延迟 30/60 秒触发。配置 rho=.2/.4, eta=.05, rank=8, candidates=4c, batch=1/4, seeds=3；同时保留原始全帧 baseline 和 fixed threshold。Model：Qwen2-VL-7B。Dataset：ActivityNet/VideoDetailCaption + 人工合成“早期对象晚期问答”子集。Baseline：Uniform frame sampling、BACON、InfiniGen、fixed τ、原 RCR。Metric：event QA accuracy、object recall、F1、TTFT/TPOT、FPS、PCIe bytes、峰值 GPU memory、长视频长度分桶。Expected Contribution：将证据可恢复性与流式时序预算结合。Risk：真实条件 offload 复杂、帧数增加导致视觉 encoder 成本主导。Collision Risk：与 streaming memory、adaptive frame selection、dynamic KV eviction 大量相近工作重合；新意必须是延迟事件回取的实测收益和机制分析。

Migration B · Agent Memory Rehydration with Outcome-Aware Rate Control

Original Problem：长生成中的视觉 KV 可能因注意力迁移而过时。Transferable Mechanism：低成本“是否需要恢复旧证据”检测 + 每 episode 自适应访问预算。New Research Question：Agent 在多轮工具调用后，何时应把旧 trajectory/skill/tool result 重新放回工作上下文？Method Modification：把 KV token 替换成语义记忆块；当前 plan/query 对已缓存摘要的相似度下降作为 drift proxy；每个任务维护 log-threshold controller，目标检索率 ρ；触发时在外部 memory index 中粗排 top 4c，再用小 reranker 精排 c 条；另测恢复某条记忆对任务成功的真实增益，避免把相似度误当 usefulness。

Minimum Experiment：用 100 个可重放的仓库问答/工具链任务，每题人为加入 20 条历史工具输出和 5 条关键依赖；把关键事实放在早期轮次，要求最后 2–4 步才能使用。冻结 Qwen3-4B-Instruct，记忆库 100–500 chunks；c=8, candidates=32, rho=.2/.4, eta=.05, 3 seeds；记录每轮是否检索、检索到的证据 ID、最终执行是否正确。Model：Qwen3-4B-Instruct + BM25/embedding retriever。Dataset：合成可验证 repository QA，随后迁移到 SWE-bench Lite 的可控子集。Baseline：always retrieve、never retrieve、periodic、fixed similarity threshold、top-k retrieval。Metric：task success、critical-evidence recall、memory tokens、检索调用数、p95 latency、token cost、错误传播长度。Expected Contribution：把 budgeted refresh 从 KV cache 推向可追踪的 Agent 语义记忆。Risk：embedding drift 不等于 causal usefulness，历史文本可能被恶意污染。Collision Risk：与 agent memory retrieval、context compression、cache management 研究交叉；需引入真正的 outcome-conditioned 检验而非只换术语。

2.19 Attack / Verification Lens

Black-box probe：构造“关键视觉对象只占少量 attention，但决定答案”的图片/视频，比较固定阈值与 rate controller 的漏检概率。Efficiency stress test：逐步增加帧数 32→128→512、batch 1→16，测真实 PCIe bytes、TTFT、TPOT、p95 latency；让视频在后段才出现新对象，观察 refresh 是否及时。Robustness：用视觉遮挡、相似对象、文字噪声、镜头切换改变 drift 分布，检查 rate 控制是否失稳。Recovery / reacquisition：定义 Recovery@k——某关键 token 被驱逐后 k 个生成步内是否被重新选回；并与最终对象 recall 对齐。新 metric：Starvation Rate = share(samples with refresh<5%)，加上 Critical Evidence Miss Rate。这些都是建议的验证方案，不是论文已经报告的 attack 结果。

2.20 如果只记住这篇论文（9 句话）

  1. 多模态 KV 压缩的关键问题不只是保留多少 token，还包括什么时候重新选择。 2. 长描述的关注对象会移动，一次性 Prefill Oracle 也只能达到约 0.44–0.52 fidelity。 3. Drift 是落在已驱逐视觉 token 上的 attention mass。 4. 固定 drift 阈值会饿死低 drift 样本，且生成后期会因视觉 attention mass 衰减而停止刷新。 5. RCR 用 drift 决定时机，用每样本 ρ=.4 的反馈控制决定刷新频率。 6. 8 维 SVD detector 和 4c 候选精排让刷新更省数据搬运。 7. 图像六设置有五组显著优于 InfiniGen，随机 40% timing 比 RCR 差 5.0 pp 是关键机制证据。 8. 视频上相对固定阈值的优势不再显著，预算增大后增益也缩小。 9. 没有真实 offload wall-clock speedup 是必须记住的系统限制，真正值得做的是 outcome-aware budget 与真实条件访存内核。

Cross-Paper Synthesis · 两篇论文放在一起看

共同趋势：从“分数高”转向“真正有用”

AOPD 说：教师在某个 token 上给高概率，不代表学生跟着做能成功。RCR 说：某些视觉 token 的 evicted attention mass 很小，不代表恢复它们对长描述不重要。前者研究 行为建议的结果价值，后者研究 信息恢复的预算价值；两者都警惕用局部 proxy score 代替最终 utility。这不是两篇论文互相引用或已完成的联合方法，而是我们从两篇工作抽象出的潜在研究交叉点。

共同方法论有三点。第一，必须定义真正的 downstream 目标：AOPD 用终局 reward，RCR 以 full-output fidelity 与 object F1 评估质量；但 RCR 的 full-output fidelity 本身仍是 proxy，尚未等于事实正确性。第二，必须做对照干预而非只看相关性：AOPD 的教师 token 替换有帮助/损害统计，RCR 的随机/周期/漂移触发同预算消融能隔离 timing 的作用。第三，必须有可调预算：AOPD 通过重要性比与 clipping 限制方差、group size 控制 rollout；RCR 用 ρ 直接限制刷新比例、候选粗精排限制搬运。

哪些机制可以组合，哪些假设冲突

互补机制：RCR 的 drift 是廉价、在线的“可能需要恢复”信号；AOPD 的 student-relative advantage 是昂贵但更接近结果的“恢复是否有益”目标。可以让一个轻量 selector 用 drift 产生候选，再用离线成功/失败轨迹训练 outcome-conditioned gate，并在运行时用 rate controller 限制重取预算。这样既避免每一步完整反事实评估，也避免仅凭 attention mass 判定价值。

关键冲突：AOPD 的理论无偏性依赖 action support、可评估 reward 和冻结 rollout；RCR 的缓存选择发生在高维、连续、强状态依赖的 decode 内部，token 选择的组合动作空间巨大。把 AOPD 公式直接套到每个 KV token 上，会遭遇动作支持集与 credit assignment 的严重困难。正确做法可能是chunk/segment 级离散动作，而不是对每个 KV entry 做 RL。

Collision / Overlap：两篇并非方法重复；与已有工作的实质重叠风险分别是 AOPD 对 selective teacher guidance、trajectory validation 的延伸，以及 RCR 对 dynamic KV retrieval、DSTP/fixed-threshold trigger 的延伸。新 Idea 必须在实验中证明“结果条件化价值”比相似度/attention proxy 更强，同时给出真实成本，否则容易变成已有方法简单拼接。

Combined Research Opportunities · 优先尝试的三个方向

Opportunity 1 — Outcome-Aware Budgeted Memory Refresh（优先级最高）

问题：Agent 在长任务里需要回取旧 tool output、skill、memory，但相似度检索会把“看起来相关”当成“能提高成功率”。统一机制：RCR 式每 episode 检索率控制 + AOPD 式 outcome-conditioned teacher gate。最小设计：在 200 个确定性多步工具任务上，每轮有 10 个可选 memory chunk，gate action 为 retrieve/skip/replace；学生 Qwen3-1.7B、教师 Qwen3-8B；终局成功 reward=1/0，先离线用 AOPD 学 gate，在线用 τ←τexp(η(m−ρ)) 控制检索比例；ρ=.2/.4。对照：always retrieve、fixed similarity threshold、rate-only、AOPD-only、joint。指标：success、critical-evidence recall、tokens/call、p95 latency、teacher-query cost、错误传播深度。新意门槛：联合方法必须在相同预算下改善 end-to-end success，并用 intervention 证明是恢复了关键证据，而不是仅增加了上下文。

Opportunity 2 — Video Evidence Reacquisition under Latency SLO

问题：长视频的关键帧可能被早期压缩丢掉，而问题在晚期才出现。统一机制：RCR 的可恢复 KV + AOPD 的结果优势校正，将 frame/chunk 回取动作按最终 VideoQA 正确性训练。最小设计：Qwen2-VL-7B、ActivityNet/LongVideoBench 子集 300 条，32/64/128 帧，固定视觉预算 64/128 KV entries/head；训练 2-action gate（refresh/skip）和 8-way chunk selector，三随机种子。对照：Uniform、BACON、InfiniGen、RCR、RL-only、AOPD-gate。指标：QA accuracy、event recall、TTFT、TPOT、PCIe bytes、显存与真实 wall-clock。新意门槛：必须实现条件 host fetch；如果只提升 fidelity 而没有实测 latency/throughput，仍只是算法层论文。

Opportunity 3 — Proxy–Outcome Mismatch Benchmark

问题：教师概率、KL、attention drift、retrieval similarity 是否会系统性误导资源分配？数据生成：对同一状态收集 proxy score 与有限预算的真实 intervention outcome；在 RL 记录 teacher-token help/harm，在视频记录 evicted chunk reacquisition 后的 QA/factuality 改善，在 Agent 记录 memory retrieval 的成功变化。Metric：proxy-outcome Spearman、top-k utility recall、Budgeted Intervention Gain、Starvation Rate、Outcome per 1k extra tokens。风险：反事实评估昂贵，环境随机性可能导致假因果；用同种子 replay、多次 rollout 置信区间、held-out 任务解决。这个 benchmark 比再造一个相似度评分器更容易构成清晰研究贡献。

P3：真正系统化 RCR 实现 mask-conditioned CPU KV fetch；batch=1/4/16 估算流量是否转化为真实 TPOT/throughput 改善 UVA/pinned memory、GPU kernel、异步调度
P4：联合 Agent memory gate 200 条可重放工具轨迹，2×2 ablation 结果价值 + 预算控制是否互补 长程 reward、工具动作 support、污染数据

最适合做 baseline：AOPD（官方代码与多任务表格较完整）。最适合形成 system / acceleration idea：RCR（但必须补真实 offload）。最适合做 benchmark/metric：两篇共同启发的 Proxy–Outcome Mismatch。最适合做 attack/evaluation：AOPD 的 teacher-harm intervention 与 RCR 的 low-drift-critical-evidence stress test。最有潜力的新论文缺口：在固定预算下证明“恢复旧信息的结果价值”优于仅按相似度或注意力更新。
