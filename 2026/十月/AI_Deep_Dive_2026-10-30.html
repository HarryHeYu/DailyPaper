Paper 1 — The Trinity §

1. 基本信息与一句话定位 §

标题：The Trinity: Capability-Driven Recursive Self-Improvement for Multimodal Agents。作者：Weidong Tang、Ruiheng Wang、Jingxuan Zhang、Hexin Wang 等；通信作者 Pengfei Zhou、Odin Zhang、Yang You。机构：InfRec、西安电子科技大学、同济大学、新加坡国立大学、加州大学伯克利分校、香港中文大学、香港科技大学、香港大学、上海创新研究院等。日期：arXiv v1 于 2026-10-26 UTC 提交。Venue/Status：arXiv 预印本，正文未声明已录用 venue。模型：冻结的 Claude Opus 5，优化 Harness 而非模型权重。论文：摘要 / 正文 / PDF。项目：官网。代码：官方仓库，2026-10-28 README 明确写着 Code: Coming Soon，当时只有报告与项目说明；不能称为已经开源可运行实现。

一句话定位：它试图解决“Agent 在一个任务上改进的经验如何变成可验证、可继承、可路由的跨任务能力”，而不是仅把一个任务的提示词反复改好。

2. 人话版（问题、方法、结果、意义） §

现有 Agent 的“自我进化”常常是：在某个游戏、编码任务或网页任务上失败，分析失败，改写 prompt / tool workflow，然后在同一个任务上再试。问题在于，不同任务表面上完全不同，却可能都需要“记住当前状态”“验证假设”“不要重复已失败动作”等共同能力；反过来，一份面向所有任务的统一提示词又会相互干扰。The Trinity 将系统分成 Creator（造可验证训练世界）、Explorer（执行并积累轨迹）、Evolver（从轨迹中归纳能力要求和改进模块）。它把任务归类为 capability tree，沿树继承和修改 Harness，并用 Router 在新任务上选择合适版本。冻结同一个大模型后，28 个训练 benchmark 的平均分由 39.06 升至 73.16，18 个 unseen benchmark 由 37.45 升至 63.61。值得重视的不是“自进化”口号，而是它把任务、轨迹、模块、版本、验证和路由连成了可检查的数据流；但它仍高度依赖强闭源模型和大量交互成本。

3. Background & Research Gap：为什么按任务进化不够 §

Agent 不是简单的 LLM 单轮回答。以迷宫任务为例，模型必须在每步接收 observation、更新地图、判断动作是否有效、执行、再根据反馈修正地图。若失败源于“走过的死路被遗忘”，修复的是状态追踪机制，而非“迷宫”这一主题。同样，视频 QA 的跨帧证据定位和游戏中的观测记账，都涉及证据维护；多 Agent 博弈的假设更新和科学实验中的假设证伪，也共享推理协议。按 benchmark 名称存一套 workflow 会重复学习相同修复；只用一个全局 Harness，又会在不同预算、不同可观测性和不同工具权限下产生冲突。

旧范式包括：Global Harness（所有训练环境共享一份模块）、Task-Domain（每任务或任务域单独训练）、Capability-Domain（能力平铺分类但无继承）、普通 task-specific recursive harness self-improvement，以及 agent–environment co-evolution。它们各有合理性：Global 能共享数据，Task-Domain 可避免冲突，环境生成可扩大训练覆盖；问题是没有同时解决“哪些能力可共享”“何处专门化”“生成环境是否真的训练原任务需要的能力”“新任务应调用哪一版 Harness”。

作者给出 ARC-AGI-3 与 Micromouse 的例子：一个是视觉网格游戏，一个是探索迷宫，表面任务不一样，但都依赖感知与状态跟踪。若把两者的失败轨迹抽象成“observation-to-state grounding”和“re-acquisition of out-of-window facts”，就可以复用同一 Memory/Perception 模块。这里的 research gap 是可迁移的执行协议，而非再训练一个更大的模型。

4. Core Insight：能力是跨模态任务的共同因子 §

核心观察属于经验性系统假设：任务外观、数据集名称与所需决策能力不是一一对应。作者通过规范化的任务说明和已验证轨迹，为每个任务建立能力集合 K_τ；再按预先固定顺序将能力集合变成 Trie 路径。共同前缀共享模块，分支保留专门化修复。它并非证明能力天然具有树形因果结构：作者明确说固定顺序不代表能力间的因果依赖。树只是共享与版本管理的工程结构。

第二个观察是训练世界可以保留决策难点，而无需复制原环境表面细节。例如把需要“行动前检查不可逆约束”的机器人/游戏任务变成小型、可验证的状态机；只要模型必须做相同类型的判断，模拟环境就可能提供更清洁的反馈。这里的风险是 simulator shortcut：模型可能只学会模拟世界的特征，迁移时失败。作者通过原 benchmark 与真实机器人评估，而不是仅在自造世界上评估，部分缓解这一风险。

第三个观察是不同 Harness 版本可以作为候选策略，由具备能力先验与执行历史的 Router 选择。选择时必须先提交版本和理由，后执行、后验证，避免使用真实结果作弊；这个设计和 Agent memory/provenance 研究非常接近。

5. Method Deep Dive：从任务到能力树、世界树、Harness 树 §

Input → 规范化 benchmark/task spec → Base Harness 轨迹 → 能力标签与 Trie → Creator 生成可验证世界 → Explorer 执行 → Evolver 修模块 → 选择性继承与版本冻结 → Router 选择 Harness → 原任务验证反馈 → Output。

Step 1｜定义可执行 Harness。 论文将 H_φ 定义为六类协议 (Perception, Memory, Inference, Planning, Orchestration, Loop)。Perception 把 observation 提取成事实；Memory 结合历史和 controller state 形成视图；Inference 维护候选假设；Planning 形成决策；Orchestration 判断固定工具集合中哪些可用；Loop 决定实际动作、commit 或等待。模块只读取允许的公开记录；只有 Memory 可显式携带状态。这里的重点是把提示词系统变成有类型接口的模块，而非一大段不可追踪的 prompt。

Step 2｜冻结任务与数据边界。 Evolver 先把任务描述整理为目标、观测、动作、反馈、完成条件和预算；划定 Train/Unseen。Explorer 使用同一 Base Harness 跑训练样本，记录 observation、action、结果和执行配置。系统用哈希链验证记录完整性；基础设施失败与任务失败分开。若这一步混入 unseen 的成功轨迹，后续所有“迁移”都可能是泄漏。

Step 3｜从缺陷到能力标签。 独立 agent 提议能力类别，judge 合并，reviewer 检查定义、证据和覆盖。附录给出六类能力：PST（感知/状态跟踪）、HCI（假设/对手推断）、CFR（约束/反馈修复）、GVT（目标/价值取舍）、VEA（视频证据获取）、VC（视频理解），并细分成 F01–F24、V01–V06 缺陷。能力可以多标签：同一任务同时需要记忆、约束检查和预算规划。

Step 4｜构造 Trie。 固定顺序 c,d,a,b,e,f，对每个任务的能力集合排序，路径的公共前缀合并。论文共构造 11 个 capability nodes，Explorer 的 Harness 树有 10 个非根候选配置。某任务在内部节点也可直接结束，不强制叶节点才是合法任务。注意：换一个排序可能改变共享结构；作者没有证明排序是全局最优。

Step 5｜Capability-Driven Real2Sim2Real。 Creator 不复制原 benchmark 的私有答案或布局，而是把节点要求转成简化训练 level。host verifier 检查环境绑定、状态转移、渲染和完成条件。筛选 Harness 在固定预算内试跑：太简单或太难都调整难度，只保留预设中间成功率带的世界。世界在一次本地训练内冻结，避免评估目标边训练边变化。可验证世界相当于为“具体能力”提供一个密集、低歧义的训练信号，但不是神经网络梯度 reward。

Step 6｜模块演化与选择性继承。 Explorer 比较成功/失败轨迹，提出对六协议模块的局部更新。每次更新必须记录 node、前驱版本、episode、可执行例子；host 检查 ownership、类型、接口和版本谱系。子节点先比较旧父模块与更新后父模块，在相同任务/预算/次数上严格更好才接受新的继承；本地模块可以覆盖父模块，但保留 lineage。一个细节：本地模块通过合法性审查即可保留，不要求当下分数提升，因此仍可能发生短期退化。

Step 7｜Creator 的下一轮更新。 Creator 仅在 verifier 检测失败时修改自己的世界构造模块；轮末合并各节点验证过的 proposal，去重并形成下一轮 Base Harness。Explorer 则沿固定树继续迭代。论文是 Harness RSI，不是对 Claude 权重执行 PPO、GRPO 或 DPO。

Step 8｜Capability-Aware Router。 给新任务公开目标、初始 observation、元数据与图片；Router 从固定版本池选择 h_n。它检索相似执行记录（cosine ≥ 0.5，最多 10 条，FIFO 20,000 条），结合能力卡片、历史成功与成本，先提交决策，再运行并验证终止 receipt，最后把 (task, chosen harness, feedback) 追加到 memory。Unseen 的能力真值标签不能进入决策；错误选择无 fallback。这样一条 trajectory 对未来行为的作用路径非常明确：证据 → 记忆检索 → Harness 选择 → 行为 → 终局验证 → 新证据。

6. 核心公式与数学直觉 §

Hφ = (Πer, M, I, P, F, L)； pτ = sort≺(Kτ)； T = Trie({pτ})

Kτ 是任务所需能力集合；≺ 是固定顺序；T 是前缀共享树。优化对象并非一个端到端可微 loss，而是经验证的任务成功率与执行成本。树构造使共享从“相似任务名称”变成“相同能力前缀”，但标签与顺序来自系统设计。

Hᵢ,v = Pᵢ,v ⊕ Lᵢ,v； (P ⊕ L)[m] = L[m]（若本地有 m），否则 P[m]

P 为继承模块 registry，L 为本地 registry，⊕ 是本地优先的合并，不是向量加法。它允许继承通用记忆协议，同时覆盖某类任务特有的动作验证。错误的覆盖可能破坏上游功能，因此必须有接口与 lineage 审查。

Zᵢ₊₁,v = Rollout(Pᵢ₊₁,v ⊕ Lᵢ,v, Dᵢ₊₁,v)； L̃ᵢ₊₁,v = Evolve(Lᵢ,v, Zᵢ₊₁,v, Fᵢ,v)

D 是节点训练世界，Z 是真实执行轨迹，F 是历史反馈。改变世界难度会改变反馈分布；若只在自造世界上比较分数，会产生 reward hacking 的环境版本。作者把原任务评价放在另一个阶段，这是设计上的关键防线。

hₙ = π(xₙ, C, R(xₙ, Mₙ), S(Mₙ))； Mₙ₊₁ = Append(Mₙ, (xₙ, hₙ, fₙ))

π 是 Router 策略，C 是版本池，R 是相似记忆，S 是已观测配置成本/成功统计，fₙ 是验证后的反馈。没有一个在文中训练出的 RL advantage 或 KL penalty；将其称为“RL 训练 Claude”会误读。

7. Toy Example：跨游戏与视频任务共享“证据确认” §

假设训练集中有一个三格迷宫 A 和一个视频事件定位 B。A 的 agent 看见红门，未确认钥匙就尝试开门，浪费动作；B 的 agent 看见一帧红色物体就断言“目标出现”，忽略前后帧。Evolver 不把两者按“游戏/视频”分开，而标注共同能力“evidence-gated commitment”，A 还需要 state tracking，B 还需要 video evidence acquisition。Creator 为共同能力造一个三状态环境：未知 → 收集第二证据 → 满足条件才 commit，验证器明确判断是否过早提交。Explorer 在 20 个合成回合中学得一个 pre_commit_check 模块（20 只是教学例子，非论文实验参数）。模块在父节点通过验证，A 分支继承后增加动作合法性检查，B 分支继承后增加跨帧时间一致性检查。新任务 C 到来，Router 根据公开输入选择包含这两个能力的 Harness；C 的终局成功/失败 receipt 再影响未来路由。若 B 的画面质量差导致验证器误标，错误就会从 world 进入 module，再进入后续任务；因此“验证器正确性”比提示词写得漂亮更关键。

9. Experiment Setup 与 Metrics 教学 §

RQ1：能力树是否比任务组织更好？Table 3 在同一冻结 Claude Opus 5 下比较 Global、Task-Domain、Capability-Domain、Tree Real、Tree Sim；其中 Tree Real vs Tree Sim 最接近只改训练世界的比较。RQ2：持续四轮 RSI 是否有效？Figure 5/6 与 Appendix Table 8 在固定 Train/Unseen 划分、拓扑、backbone 下观察增量。RQ3：Router 的能力标签与 memory 各贡献多少？Table 4 逐项增加 Cap、Mem。RQ4：模块相关性是否有行为作用？Figure 7 和 Table 5 做 relevant/irrelevant addition 及 removal。RQ5：能否跨到真实机器人？Table 6 的 SOON（Unitree G1）和 CaP-X（AlohaMini2）测试。

数据：28 Train、18 Unseen，涵盖规则发现、约束求解、感知控制、多 Agent、长时交互。论文部分 Train 使用少量固定实例、重复 episodes；Unseen 有官方全量或固定子集，例如 Video-MME-v2 取 400/800 视频、1600 问，PHYRE 50 个测试任务，SciGym 126/137 个小系统。Train/Unseen 不是随机同分布 QA 切分，而是 benchmark-level generalization。每个 benchmark–Harness 配对还先进行 5 次 skill preparation trials，汇总成固定 skills 后再正式测试；这些 trial 不计入正式成功率。

指标：每 benchmark 原生 success / win / solve / accuracy / progress / human rank percentile 等被放到 0–100，之后做 benchmark-equal mean（每个 benchmark 权重相同）。高分更好，但 10 次机器人试验和 1600 道视频问答在总体均值里权重相同；不同任务的 1 分未必有相同实际价值。Training Tokens (M) 统计进化阶段 token 总量，Inference Tokens (M) 为评估阶段 token 成本；低成本更好，但 token 不是美元、GPU 小时或真实延迟。Router 的 Oracle 是知道每实例最优配置的事后参考，不能视为真实在线算法。相关性系数 r∈[-1,1] 仅表示共变，不能证明模块导致能力。

1. 基本信息与一句话定位 §

标题：ResCom: Activation Residual Compensation for Large Language Model Quantization。作者：Ning Yang、Bohan Cui、Zhuowen Liu、Yuting Wang。机构：中国科学院自动化研究所、复旦大学、香港中文大学、中国科学院大学。日期：arXiv v1 于 2026-10-25 UTC 提交。Venue/Status：arXiv 预印本，未确认会议录用。论文：摘要 / HTML 正文 / PDF。项目/代码：论文与 arXiv 页面未提供可核实的作者官方代码仓库链接；Code Status: Not Verified，不能把论文内伪代码当成已开源实现。

一句话定位：它不是发明另一种 4-bit 量化器，而是利用量化时被丢弃的 activation residual，给已经量化好的模型附加一个闭式求解的低秩补偿器，在不重新训练主模型的前提下修复输出质量。

2. 人话版（问题、方法、结果、意义） §

把 LLM 权重和激活都压到 4 bit 可以降低存储和潜在计算成本，但每次把浮点 activation 四舍五入成少量离散值时，会把不同输入压成同一个数字。传统量化修复若只看已经舍入的 activation，就无法分辨这些原本不同的输入。ResCom 抓住一个简单但强的信号：舍入前的值减去舍入后的值，这正是被丢掉的信息。它不把所有信息都补回来，而是通过校准数据，找出哪些残差方向会显著影响 layer output，用 Cholesky、SVD 和低秩回归拟合一条很小的补偿支路。Llama-3-8B 的 W4A4 WikiText-2 perplexity 从 7.708 降到 7.147，MMLU 增加 2.89 点，GSM8K strict 从 23.96% 升到 36.16%。但必须看到，作者的 FP32 模拟推理并没有比 FP16 快，额外补偿还会增加 decode 延迟；这是“提高量化质量/显存效率”的论文，不是已证明的端到端推理加速方案。

3. Background & Research Gap：为什么量化后仍然需要补偿 §

考虑一个线性层 y = Wx + c。权重量化让 W 的表示变粗，激活量化让 x 也变粗。W4A4 意味着主路径的权重和激活主要采用 4-bit 表示。激活 outlier 会扩大动态范围，使相同 16 个等级之间的间距变大；因此常见方法先处理 outlier，再量化。SmoothQuant 用缩放把困难从 activation 侧转移到 weight 侧；QuaRot/SpinQuant 用旋转把异常维度混合；FlatQuant 用变换；PrefixQuant 处理特定 outlier；SERQ 用 selected-channel compensation 恢复一部分输出。这些方法能让舍入误差变小，却不能让舍入操作完全无损。

一个最小反例：量化器把 1.21 和 1.24 都映射为 1.2。如果后续补偿器只能读取 Q(x)=1.2，它对两者必然输出相同修正；但当线性层权重为 100 时，原输出分别是 121 与 124，理想修正差了 3。从舍入后的数字本身无法恢复这 3。这是一个信息不可辨识问题，而不是调大 LoRA rank 就能解决的问题。若保留 d=x−Q(x)，两个输入分别产生 0.01 与 0.04，差异立即可见。

旧的 QERA/LQER 对量化误差做低秩重建；ARHQ 也使用未舍入信息，但会在构造量化模型时拆分权重、重新量化主路径；SERQ 在既有主路径上补偿，但输入主要是 rounded activation。本文的 gap 更具体：量化器和已校准权重完全冻结后，如何利用主路径尚未使用的残差，以很小的附加计算修复层输出？

4. Core Insight：缺失信号比额外参数更重要 §

作者的第一层观察是量化桶内的信息丢失是不可逆的：相同 Q(x) 可以对应不同 x 和不同真实输出。第二层观察是量化残差与输出误差之间存在精确的线性关系，前提是参考输出与量化主路径使用同一冻结有效线性算子 W_s。于是误差目标不需要训练一个神经网络来猜，可以直接写成 e = W_s d。第三层观察是有限 rank 应按输出重要性分配，而不是按输入残差能量分配：一个大残差可能被权重压到几乎不影响输出，一个小残差可能被权重放大很多倍。

这三点分别是信息可辨识性事实、线性代数恒等式、以及输出感知校准的工程设计。论文给出 Proposition 1：对指定的 activation-rounding target，在相同 rank 预算下，以 residual 为输入的最优无正则线性修复不会比用 x 或 Q(x) 更差。定理只针对给定校准样本、指定层级误差与 rank 约束；它不证明端到端任务 accuracy 必然提升，也不保证跨模型、跨精度单调变好。

5. Method Deep Dive：每个量化层增加一条小支路 §

Input：已校准 W4A4 host + calibration tokens → 捕获量化前 x 和 Q(x) → 计算 d、目标 e → 流式累计 G/C 统计 → Cholesky whitening → truncated SVD → 生成 U/V/b → 所有层一次性挂载补偿支路 → Output：冻结主路径 + 低秩修复。

Step 1｜先确定“同一冻结算子”条件。 在 SERQ setting，W_s 是 dequantized main weight 与已存在的 selected-channel 线性补偿的合成有效映射。量化前输出 y_u = W_s x + c，量化后 ŷ = W_s Q(x) + c。只改变输入是否舍入，才能把两者差定义为纯 activation-rounding error。如果 host 还有独立输出量化、不同分支使用不同 quantizer，这个恒等式不再自动成立；论文附录 C 明确要求重新定义真实 reference/host 误差目标。

Step 2｜保留残差，不改变主路径。 在 input quantizer 处记录 d=x−Q(x)，主路径照常执行 W_s Q(x)；新支路计算 U(Vd)+b 并加回输出。V 先把 n 维残差投影到 r 维，U 再从 r 维映射到 m 维；rank 32 是论文主要默认值。每 token 额外约 r(n+m) 次乘加及 n 维减法，额外参数 r(n+m)+m。若 r 接近原维度，补偿效果可能更好，但计算与显存收益会丧失。

Step 3｜流式收集校准统计。 使用 T 个 token，收集每层 (d_t,e_t)；计算均值并中心化。G = Σ(d−d̄)(d−d̄)^T 是残差 Gram/协方差尺度矩阵，记录残差维度之间如何一起变化；C = Σ(e−ē)(d−d̄)^T 是输出误差与残差的 cross-covariance，记录哪种输入残差对应哪种输出损失。只保存 G、C 与均值，内存与 T 无关，但每层需 O(n²+mn) 统计空间；对大 hidden size 不可忽视。

Step 4｜解带 rank 约束的 ridge 回归。 目标是最小化 calibration 上的输出误差平方和，同时惩罚过大的补偿矩阵。先计算 G+λI=LLᵀ 的 Cholesky 分解。加 λ 是为了让校准样本有限或高度相关时矩阵稳定可逆；λ 太大时会把所有修复压小，太小时可能放大校准噪声。随后对 C L^(−T) 做 SVD，取前 r 个奇异方向，反变换得到 U、V，再计算 bias b=ē−UVd̄。不要显式求矩阵逆，实现时用三角求解更稳定。

Step 5｜一次性挂载所有层。 论文特别强调：所有层的 G/C 必须在未修复 host 上先收集完，再同时挂载新支路。如果先修第 1 层、再用修后的 activation 校准第 2 层，后者目标就不再属于同一个冻结参考分布。反过来，一次性挂载也会产生 layer interaction：前层修复改变后层输入，局部最优不保证全模型最优。这个矛盾是值得做后续研究的真实 limitation。

Step 6｜选择修复位置。 默认只在 attention 的 Q/K/V/O projection 上加 rank-32 分支，而不是所有 FFN 层。原因是成本—质量平衡：全线性层修复的 PPL 略低，但额外计算更大。校准样本为 128 个 WikiText-2 的 2048-token windows，λ = 0.01 tr(G)/n，这是主要复现超参数，不是理论必需的唯一选择。

6. 核心公式、SVD/Gram/Projection 逐项解释 §

d = x − Q(x)； e = Wₛx + c − [WₛQ(x)+c] = Wₛd

x 为量化前激活，Q(x) 为量化后反量化回同坐标系的激活，d 为舍入残差，W_s 为冻结有效线性映射，e 为因舍入而丢失的输出。这个等式说明 residual 是充分且直接的线性输入，而不是让补偿器从已经失真的值里猜原值。

min(rank(B) ≤ r, b) Σₜ ‖eₜ − B dₜ − b‖²₂ + λ ‖B‖²F； B = U V

B∈R^(m×n) 是补偿矩阵，rank(B)≤r 限制有效自由度，b 是输出均值偏移，λ 是 ridge 惩罚。第一项越小，层输出修复越准确；第二项越小，参数幅度越稳健。这里不是最小化语言模型 cross-entropy，而是最小化层级输出误差。与 strongest baseline SERQ 的区别是：SERQ 的已校准 selected-channel 补偿仍依赖 rounded activation；ResCom 在其后补充 d 的专门支路。

G = Σₜ d̃ₜ d̃ₜᵀ； C = Σₜ ẽₜ d̃ₜᵀ； G+λI = L Lᵀ； C L^(−T) = Φ Σ Ψᵀ

G 是输入残差的 Gram 统计，C 是残差—输出误差的关联统计；Cholesky 的 L 把不同尺度和相关性的输入方向标准化。SVD 把白化后对输出最重要的方向排在前面，取 Φ_r,Σ_r,Ψ_r 即保留前 r 个方向。U=Φ_rΣ_r、V=Ψ_rᵀL^(−1)、b=ē−UVd̄。这里的 projection 是把输出误差投影到主奇异子空间，而不是注意力权重投影；也不是 PCA 仅保留输入残差方差最大的方向。

Rᵣ(d) = Σ_{i>r} sᵢ² ≤ min{Rᵣ(x), Rᵣ(Q(x))}

s_i 是中心化目标误差矩阵的奇异值。Eckart–Young 型截断误差给出 rank-r 下的不可避免剩余；因为 e=W_s d，residual 输入能构造达到这一低秩下界的映射。x 和 Q(x) 在相同 rank 下不能保证做到。加 ridge 后，误差上界多一项 λ‖P_r W_s‖²F，其中 P_r 投影到目标误差前 r 个左奇异方向。边界：只对给定样本和局部 target；不能用它证明 W4A8、任务指标或真实推理速度必定改善。

7. Toy Example：两个 activation 落在同一量化桶 §

假设线性层 W_s=[100, 1]，bias 0，两个输入 x_A=[1.21, 2.02]、x_B=[1.24, 2.02]；简化量化器把第一维都变成 1.20、第二维变成 2.00。则 Q(x_A)=Q(x_B)=[1.20,2.00]，主路径输出都是 122.00。原始输出 A 是 123.02，B 是 126.02，理想补偿分别是 1.02 与 4.02。若只用 Q(x) 做任何确定性修复，A/B 修正必然相同，无法同时正确。

ResCom 捕获 d_A=[0.01,0.02]、d_B=[0.04,0.02]。若 rank=1 且校准数据表明第一维主导输出误差，取 V=[1,0]、U=[100]，补偿分别为 1 与 4，输出变成 123 与 126；剩余 0.02 来自第二维未修复残差。若 rank=2 并用真实 W_s，可完全恢复 123.02 和 126.02。这个数字例子是教学构造，非论文实验。它同时说明为什么单纯“多加参数”不够：必须把区分 A/B 的信号提供给支路；也说明为什么低 rank 需要按输出敏感性而不是残差绝对大小排序。

8. Baseline Deep Comparison：谁是真正的 strongest baseline §

Baseline 做法与合理性 本文 setting 的不足 ResCom 的区别
SERQ 已校准 W4A4 + selected-channel compensation；最严格的 strongest paired baseline 只能利用其现有补偿输入，量化桶内差异仍丢失 冻结 SERQ，新增 residual-conditioned rank-r 支路；直接配对比较，因果识别较清楚
SmoothQuant / g128 缩放 activation 与 weight 的难度，低开销且经典 W4A4 outlier 仍可使质量明显退化 ResCom 是 post-calibration 修复，不替代缩放
QuaRot / SpinQuant 旋转或学习旋转以缓和 outlier，适合低比特量化 旋转后仍会舍入；有额外旋转计算 从被舍入掉的残差恢复 output-relevant 信息，正交于变换本身
QERA / LQER 对量化输出误差做低秩重建，数学/工程上成熟 目标和分支输入不专门针对 activation-rounding residual 输出感知的残差条件化 + 闭式 reduced-rank regression

Strongest baseline 的两个含义：要证明“新分支有用”，最强的是同 checkpoint 的 SERQ；要证明“residual 是关键而不是 rank 增加”，最强的是同 rank、同 target、同预算的 unrounded-input branch（Table 5）。作者的 selected-channel budget-matched control 在 PPL 甚至略优于默认低秩实现，必须如实指出。

9. Experiment Setup 与 Metrics 教学 §

RQ1： 在已校准 W4A4 checkpoint 上，ResCom 是否跨模型规模和架构改善质量？测试 Llama-3/3.2 1B–8B、LLaMA-2 7B/13B/70B、Mistral-7B-v0.3、Gemma-3 1B/4B；以 SERQ 为主，另测试 PrefixQuant、FlatQuant。RQ2： 是 residual 信号还是新增容量导致改善？在相同 rank/参数/MAC 预算下，比较 rounded、unrounded、residual 三种支路输入。RQ3： 校准数据和修复位置敏感吗？做 rank 8–256、calibration windows 32/128/512、attention-only vs all-linear、重复抽样。RQ4： 质量修复能否转化为部署价值？在 B200 上分别测 FP32 模拟、compact-storage 与 native MXFP4。注意这些是三个不同执行协议，不能把某协议的 accuracy 和另一协议的 latency 拼成一个真实部署结果。

校准：WikiText-2 128×2048 windows；rank=32；λ=0.01 tr(G)/n；先全模型收集 moments 后挂载。评估：WikiText-2/C4 PPL、8 项 zero-shot accuracy、MMLU 57 subjects、GSM8K 5-shot（flexible/strict）、LongBench 的 QMSum/SAMSum/RepoBench-P。C4 为 WikiText-2 拟合之外的语料；长文本生成使用 7500 token 输入预算、对应任务的输出限制，具体见 Appendix F。硬件：B200，性能测量以 batch=1 为主；FP32 模拟关闭 TF32，native MXFP4 是功能性实现而非成熟 serving kernel。

PPL（Perplexity）：近似为 exp(平均负对数似然)，越低越好，反映对真实下一个 token 的预测能力；不等于人类偏好或任务正确率。MMLU：57 学科多选题 accuracy，越高越好，但对 prompt/评估 harness 敏感。GSM8K Strict：算术推理答案严格匹配，越高越好；Flexible 对格式更宽容，二者差异能揭示答案解析偏差。LongBench：QMSum/SAMSum 等任务各有自己的自动指标，越高通常越好，但自动摘要分数不等于事实忠实性。ρ_r：相对于校准层误差的正则化拟合减少比例，越高表示局部 fit 更好；不能等同下游准确率。Peak GiB：峰值分配显存，越低越好，依赖实现、prompt 长度与 KV cache。Prefill latency：一次处理输入 prompt 的耗时，越低越好；TPOT：生成阶段每个 token 的平均耗时，越低越好；TTFT 是首 token 出现时间，论文未提供独立完整报告。Nominal MAC overhead 是算术量估计，不等于真实 GPU latency。没有报告可推广的 batch-size scaling、energy 或多用户 throughput，统一记为 Not Reported。

10. Results Deep Dive：八个结果，包含最弱与负结果 §

  1. 最强质量结果之一：Llama-3-8B 的 WikiText-2 PPL 7.708 → 7.147，绝对降 0.561、相对降约 7.28%；同 checkpoint 的 MMLU 54.69 → 57.58（+2.89 点），8-task zero-shot 62.98 → 64.89（+1.91 点，Table 1）。支持修复有效，但仍未回到 FP16 的 PPL 6.13 / MMLU 62.13。
  2. 推理任务改善突出：Llama-3-8B GSM8K strict 23.96% → 36.16%，+12.20 点（Table 4），比 PPL 的相对改善大得多。可能说明量化误差在多步生成中累积；但这只是解释假设，论文未证明每个推理步骤的因果机制。
  3. 跨语料泛化：同一 WikiText-2 校准的 Llama-3-8B 在 C4 上 PPL 11.192 → 10.349，降 0.843；LLaMA-2 7B 的 C4 7.432 → 7.315，降 0.117（Table 2/3）。说明并非仅记住 WikiText-2 词分布，但跨领域的幅度差异明显。
  4. 跨模型收益不均：Mistral-7B PPL 5.663 → 5.617，仅降 0.046；zero-shot 67.10 → 67.13，仅 +0.03 点（Table 2）。这属于weakest result：同一机制可修，但未必有可观应用收益。
  5. 不同量化 host 的适用性：SERQ 7.708→7.147；PrefixQuant 7.860→7.605；FlatQuant 6.972→6.960（Table 3）。在本来更强的 FlatQuant 上仅降 0.012，显示方法不是通用大幅提升器。
  6. 严格信号消融：Llama-3-8B rank 32，rounded-input branch PPL 8.327，unrounded-input 7.242，residual-input 7.147（Table 5）。在相同容量下，rounded 甚至比未修复 SERQ 7.708 更差；这是支持“丢失信号本身重要”的最强机制证据。
  7. 明显负结果：Gemma-3-4B 的 SAMSum 16.73 → 8.17，近乎腰斩；Gemma-3-1B 的 GSM8K strict 1.36 → 0.99（Table 4）。更重要的是 W4A8 setting：Gemma-3-4B WikiText-2 PPL 10.753 → 11.128（变差），C4 14.901 → 15.326（Appendix Table 15）。这直接否定“残差补偿总是有益”。
  8. 系统代价不能回避：B200 FP32 模拟 4K prefill 1342.32 → 1372.46 ms（+2.25%），decode 76.79 → 86.11 ms/token（约 +12.14%）；同表 FP16 prefill 209.07 ms、decode 15.89 ms/token（Table 17）。因此在该实现上，ResCom 不是比 FP16 更快。compact-storage 14.233 GiB vs FP16 19.686 GiB（节省 27.7%），但 compact SERQ 14.130 GiB，新增支路 +0.103 GiB。native MXFP4 的 4096 prompt +32 token：BF16 0.788 s，MXFP4 7.302 s，MXFP4+ResCom 7.571 s；显存 20.686 / 11.097 / 11.200 GiB（Appendix Table 19）。这体现当前 wrapper 的 kernel/调度瓶颈，理论 MAC 少绝不代表真实 wall-clock 加速。

12. Ablation、Claim vs Evidence、Contribution §

Ablation：去掉 residual 改用 rounded input，rank-32 PPL 7.147→8.327；改用 unrounded input，7.147→7.242；减少 rank 32→8，7.147→7.203；增大 rank 32→256，7.147→7.085，但算力和参数同步增加；只修 bias，PPL 7.715；修全部线性层 7.070，略好但预算更高；32/128/512 校准 windows 分别 7.139/7.147/7.137，差异小。不同 calibration draws 的 ΔPPL 标准差在测试中低于 0.006，支持局部稳定性。不要把局部拟合改善当成端到端严格因果：前层修复改变后层输入，附录承认了这个局限。

Authors Claim：残差是低比特量化后有价值的额外信息，闭式低秩修复在多个模型/任务上改善质量且保留显存优势。Experiments Actually Show：W4A4 下配对 SERQ 的 PPL 普遍改善；rank-matched ablation 支持 residual 输入；一部分 reasoning/LongBench 改善；B200 上有真实 latency/VRAM 数据。What Is Not Yet Proven：推理速度提升、在更成熟低比特 kernel 下仍有同样性价比、W4A8 也改善、所有下游任务单调变好、batch>1 规模效应、超长上下文的 KV cache 影响、量化残差本身的隐私安全边界。

Contribution 1 — New Mechanism：用 activation rounding residual 作为后校准补偿输入，明确恢复主路径缺失的区别信息。Contribution 2 — New Objective / Mathematical Analysis：输出感知 reduced-rank ridge regression，Cholesky+SVD 闭式解，给出 residual alignment proposition；基础线性代数是成熟工具，创新在目标与输入的结合。Contribution 3 — New Empirical Finding：同 rank residual > unrounded > rounded 的强消融，跨 W4A4 host/模型/语料的配对验证。Contribution 4 — New System/Engineering：FP32、compact、MXFP4 的实现分析与 fused residual frontend；当前 native wrapper 仍明显未优化，不能称为生产级推理加速系统。

13. Limitations & Failure Modes §

Authors' Limitation（从正文/附录明确边界归纳）：局部闭式最优不保证修复后网络的 end-to-end 最优；不同 host 的真实 target 定义不一定等于 W_s d；native MXFP4 wrapper 尚非优化 serving kernel；效果取决于 backbone、task、quantization pipeline。Additional Limitation：W4A8 的负收益揭示信号强度不足时补偿可能过拟合；某些生成任务明显退化；多层并行修复会改变下游残差分布；长上下文推理中的 K/V activation 修复可能改变 KV cache 数值，需明确缓存与重用协议；rank 和 λ 的静态选择忽略层间差异；每层 O(n²+mn) 校准统计在大模型上昂贵；FP32 factor 精度与低比特主路径之间的类型转换可能增加 kernel launch 和带宽；batch 1 的 B200 测量不能外推到高并发；没有能耗、吞吐和质量-延迟 Pareto 的完整部署曲线；部分 baseline 采用文献数值而非完全相同代码栈重跑。

14. Inference Acceleration 专用：Bottleneck 与真实效率表 §

Bottleneck：W4A4 原始目标是减少权重/激活内存与算术负担；ResCom 实际解决的是低比特的质量瓶颈，额外分支引入 compute/memory movement。它没有减少 target transformer 的 token 数、KV cache 长度或 attention complexity。Acceleration Mechanism：理论上以 rank-r 的 U(Vd) 代替昂贵的 full-rank W_s d，少算的是“为了补偿而额外执行的高精度全矩阵乘法”，不是比无补偿 SERQ少算。对 SERQ 而言它是新增计算。

15. Reproduction View：先复现层级恒等式，再测系统 §

最关键代码模块：quantizer_hook（捕获 x/Q(x)）、frozen_host_adapter（构造正确的 y_ref 和 e）、moment_collector（流式 G/C）、cholesky_svd_solver、residual_branch、attach_all_at_once、ppl_eval、latency_benchmark。最容易踩坑：误把未缩放的 x 与旋转后 Q(x) 相减；在统计尚未收集完时先挂载分支；Cholesky 数值病态；使用错误的 SERQ selected-channel 有效映射；用不同 prompt 评估修复前后；把 FP32 模拟当 native INT4；测时没有 warmup、CUDA synchronize 或缓存状态一致性。

最小复现方案：先用一个 2 层、hidden=256 的 Transformer 或随机线性层，构造 W4A4 fake quant，验证逐 token e=W_s d 的最大误差应接近浮点数值误差；然后收集 8k–32k calibration tokens，求 rank=8/16/32、λ/trace(G)∈{0.001,0.01,0.1}，比较 rounded / unrounded / residual 三个相同容量输入，输出 held-out layer MSE 与 PPL。再在 Llama-3.2-1B 的现成 SERQ checkpoint（若可合法取得）上复现 rank-32 attention-only：先确认 host PPL 接近论文 12.461，再检验修复后是否接近 12.071；若 checkpoint 不可得，应明确改用自己的量化 host，不可直接要求复现相同绝对数字。性能实验固定 GPU、batch=1/8、prompt=128/2048/4096、generation=32/128，分别报告 prefill / decode / total / peak VRAM / PPL，所有模型执行相同 kernel path；第一优先验证的是 residual vs unrounded 的 matched-rank 消融，不是争取一个漂亮的 speedup。

16. Research Value 与两条迁移路线 §

Baseline Potential：高，SERQ + ResCom 可构成质量修复基线，尤其适合比较相同 W4A4 checkpoint。Migration Potential：中高，核心是“丢失信号的输出感知低秩修复”，不局限于文本。Systems Potential：中，当前 native 性能弱，但算子融合和动态 rank 有优化空间。Attack Potential：中，构造高输出敏感残差可形成量化脆弱性测试。Evaluation Potential：高，layer fit 与 downstream metric 的失配值得系统评测。Benchmark Potential：高，可建立跨模态、跨精度、跨长度的 quality–latency benchmark。New Paper Potential：中高，必须补齐部署收益与负结果机制，而非只再换一个 SVD 公式。

Migration A：VLM / Video 的模态条件化残差修复 §

Original Problem：文本 LLM W4A4 activation rounding 损失影响输出。Transferable Mechanism：d=x−Q(x) + 输出感知 reduced-rank regression。New Research Question：视觉 token 与文本 token 的量化残差方向是否不同，单一低秩支路是否在视觉理解/视频时序任务上产生负迁移？Method Modification：在 multimodal projector 与前四层 fusion attention 分别收集 G_visual, C_visual 和 G_text, C_text；拟合 shared rank-16、modality-specific rank-16、combined rank-32 三种支路，测试同预算。Minimum Experiment：用 Qwen3-VL-8B-Instruct 的可量化子模块或 LLaVA-1.5-7B（视 checkpoint/算子支持锁定），每模态各 16k calibration tokens，rank∈{0,8,16,32}、λ∈{0.001,0.01,0.1}×trace(G)/n；图像使用 MME/MMBench 固定评估集，视频使用 Video-MME 或 MVBench，保证视频级去重。训练仅拟合残差，不更新主模型；记录各模态 layer MSE、QA accuracy、temporal order accuracy、4K prefill、TPOT、峰值显存。Model：LLaVA-1.5-7B / Qwen3-VL-8B。Dataset：MMBench、MVBench、Video-MME。Baseline：W4A4 host、SERQ 类 selected-channel、unrounded-input rank branch、shared residual rank branch。Metric：accuracy、PPL（文本控制组）、视觉 token 敏感度、latency、VRAM。Expected Contribution：证明是否需要 modality-conditioned compensation，并给出负迁移边界。Risk：视觉投影结构和 host quantizer 不满足同一 W_s 条件；校准视频与测试泄漏。Collision Risk：QERA、视觉量化补偿及模态感知量化已有大量相近工作，真正新意应是严格的模态残差可辨识性与 matched-budget 负结果。

Migration B：KV Cache 量化后的误差感知稀疏修复 §

Original Problem：低比特 KV cache 节省内存却改变 attention 输出。Transferable Mechanism：保留/预测量化残差中对下游输出最敏感的方向，而不是按残差幅度或 token recency 保留。New Research Question：在固定 KV 字节预算下，能否只为少量高影响 token/head 存储残差低秩码，提高长上下文质量而不损失 decode throughput？Method Modification：针对每个 attention head 的 K/V 定义 d_K=K−Q(K)、d_V=V−Q(V)；用 query-conditioned output error 或校准期近似梯度选择 top-p head/token，额外保存 rank-8 residual code；注意 attention softmax 非线性，不能照搬 e=W_s d 恒等式，需要局部线性化或直接测真实 attention output error。Minimum Experiment：Llama-3.2-3B，长上下文 4k/16k/32k，KV 精度 2/3/4 bit，固定总 KV 字节预算；选 100 个 LongBench/Needle-in-a-Haystack 测例做校准，另 300 个不重叠样本评估；比较 uniform 2-bit / recent+sink / per-head mixed precision / residual top-k / query-aware residual；batch 1/8，测 PPL、retrieval accuracy、TPOT、TTFT、tokens/s、峰值 VRAM。Model：Llama-3.2-3B 或可用 32k 模型。Dataset：LongBench + synthetic needle probes。Baseline：uniform quant、recent/sink retention、现有 E8/向量量化方案（在相同 bit/硬件条件下）。Metric：quality per KV GiB、decode latency、quality–throughput Pareto。Expected Contribution：从“按 token 重要性保留”转向“按输出误差贡献修复”的 KV 质量—成本前沿。Risk：query-dependent 额外读写抵消节省、attention 非线性与动态 prefix 导致校准失效。Collision Risk：KV cache 量化与重要 token selection 极度拥挤，必须做同字节预算、同 kernel、长上下文的强比较。

17. Attack / Verification Lens 与“只记住这篇”的 9 句话 §

Attack：构造量化桶边界附近输入，使 d 很小但 W_s d 很大；检测某些 token/head 在 W4A4 下的输出翻转。Black-box probe：不需要读权重，比较 FP16 与 W4A4 在等义改写、长上下文位置变化、稀有 token 上的输出一致性，估计量化脆弱区域。Robustness test：W4A4/W4A8、不同 rank、不同校准分布与随机种子；特别跟踪 SAMSum 类负迁移。Efficiency stress test：batch 1→8→32、prefill 128→32k、decode 长度变化、kernel fusion on/off。New metric：Net Utility per Millisecond = (TaskGain − α·QualityRegression) / AddedLatency，α 必须事先规定；同时报告显存 Pareto，不用一个数字掩盖 trade-off。

  1. 量化后的相同数值可能来自不同真实激活。2. 只读 rounded activation 的补偿器无法区分这些输入。3. residual d=x−Q(x) 保存了被舍入掉的信息。4. 在线性同算子条件下，丢失的输出正好是 W_s d。5. rank-r 补偿应优先拟合输出敏感方向而非输入大方差方向。6. Cholesky + SVD 使后校准修复无需梯度训练。7. W4A4 的 PPL/GSM8K 改善有证据，但 W4A8 和部分 LongBench 指标出现负结果。8. 现有 FP32/native 测量没有证明端到端加速，甚至比 BF16 慢得多。9. 最值得研究的是残差信息、任务质量与真实系统成本之间的边际收益。

Cross-Paper Synthesis — 共同机制与分歧 §

这两篇分别处理两个不同层次的“信息损失”。The Trinity 关注 交互历史中哪些可验证经验应该进入下一次决策；ResCom 关注 低比特计算中哪些被舍弃的激活信息值得恢复。二者都不主张把所有历史/残差完整保留，而是让某种“下游效用”指导有限预算下的选择。但这只是概念互补，不是同一算法：Trinity 的模块选择是非可微的、含长期状态与 verifier；ResCom 的优化是冻结线性层上的闭式平方误差最小化。不能把后者的 Proposition 1 直接搬去证明 Agent memory 的最优性。

共同趋势：2026 年的系统论文越来越重视冻结 backbone 后的外围可控机制：Harness、router、校准补偿、证据 ledger、实际成本。可组合的机制：用 Trinity 的 capability router 判断任务需要什么精度/证据，再用 ResCom 的 output-aware residual budget 决定哪些层或视觉 token 值得额外修复。冲突假设：Trinity 默认任务能力标签足够预测最合适模块；ResCom 说明真正的误差贡献可能由底层连续数值方向决定。高层标签不一定预测数值误差；要做层级—数值联合路由，必须有实测校准。

Combined Research Opportunities：三个可执行想法 §

Idea 1｜Verified Marginal Utility Router（优先）。统一衡量“启用一个 Agent memory/module/visual token/quantization repair branch 后，最终任务效用改善多少、额外成本多少”。训练时采用 matched counterfactual pairs；部署时 Router 只用公开可用特征预测增益。最小实验：固定 200 个视频 QA，四种帧选择策略与三种残差修复 rank，记录 accuracy、wall-clock、VRAM；把 Router 的收益与 oracle 上界、uniform 预算比较。新意必须是可验证的因果边际效用，不是普通 mixture-of-experts。

Idea 2｜Capability-Conditioned Precision。将 Agent 的任务能力需求映射到不同精度配置：时序顺序/细粒度计数使用更高视觉 projector 精度，普通文本任务使用低比特。最小实验在一个 VLM 上为 text-only / image counting / temporal order 三类任务建立 per-layer residual sensitivity，按固定显存预算路由 rank 0/8/32；若 Router 额外开销超过节省，判定失败。

Idea 3｜Evidence & Residual Failure Benchmark。两种干预：给 Agent 注入错误但格式合法的记忆 receipt；给量化模型构造同桶不同输出的高敏感输入。共同报告 failure amplification、repair recovery 与 cost of verification。它们不是同一攻击，但可共享“信息被抹平后，系统如何恢复区别”的实验范式。

Collision / Overlap：已有工作与边界 §

Agent 侧 Collision：Recursive Harness Self-Improvement、ModularRSI、HarnessDev、EvoWeave、task-specific skill libraries、agent memory provenance 已覆盖“模块化改进/经验复用”的部分空间。The Trinity 的独特性更接近 capability Trie + 可验证世界 + 选择性继承 + Router 的联合闭环，而非首次提出 agent 自改进。

Inference 侧 Collision：QERA/LQER/ARHQ/SERQ、SmoothQuant、QuaRot、FlatQuant、KV cache vector quantization 已覆盖低秩修复、残差、量化重建的大量空间。ResCom 的区别是后校准冻结 host、用 activation rounding residual 拟合明确的层输出 target、带证明的 matched-rank 信号比较。跨论文的“Verified Marginal Utility Router”目前是研究假说，Strongest Collision = capability-aware routing × output-aware residual budgeting；尚未发现这两篇直接互相引用或构成同题竞争。
