Paper 1 · Humanize MLE Agents：为什么让两个原生 Agent 轮换，比持续堆叠上下文更有效？

基本信息：Humanize MLE Agents: Multi-Agent Session Alternation Beyond Single-Agent Limits；Changye Li、Zijian Zhang、Muheng Li、Yiduo Pang 等 15 位作者；清华大学、浙江大学、NVIDIA、MIT。arXiv:2610.13494v1，2026-10-09 提交，2026-10-12 进入近期列表；目前核实为预印本，未确认正式发表。 论文 · 完整 HTML · 官方代码。本篇属于 Agent / Multi-Agent，兼具层级 RL 的理论视角，但没有训练一个新 RL policy。

1. 一句话定位与人话版

定位：将多个原生编码 Agent 的跨会话交替，建模为保留共享工作成果、重置局部上下文的 semi-MDP，在固定实验与时间预算下研究“何时切换才真正增加可达的优质解”。

想象让一个编程 Agent 连续六小时参加 Kaggle：它一开始能快速试不同特征、模型与参数，后来往往重复尝试小改动，输出的思考内容也越来越短。给它塞更多经验 Markdown、技能文件和复杂 harness，不一定能救场；模型升级后，这些旧指令甚至可能拖后腿。HMA 不修改任何模型参数，而是让两个使用各自原生工具链的 Agent 轮流接管同一个工作目录。每个会话最多完成五次有效实验，就清空该 Agent 的临时对话上下文，把代码、预测文件、训练结果和历史候选留在磁盘；下一位 Agent 读共享成果继续探索。最后专门留出时间回顾并挑选候选。在 75 个 MLE-bench 任务上，最佳顺序达到 78.2% 的 any-medal，强于六小时最强单 Agent 的 72.4%，也高于此前公开系统的 70.2%。论文的重要性不是证明“两个人总比一个人强”，而是给跨 Agent 接续建立了可检验的状态、终止和预算理论。

2. Background & Research Gap：单 Agent 的长程瓶颈

任务本质不是回答一个问题，而是维护一条实验序列：读数据→写训练脚本→训练/验证→比较 leaderboard 指标→决定下一次实验→保存最佳提交。它同时要求连续性与新鲜探索。传统单 Agent 方案用越来越长的对话历史维持连续性，或依赖自定义 harness 注入 planning、skills、memory、反思模板。这里有两种失败：一是早期决定形成路径依赖，例如过早认定 XGBoost 已足够好，后面只调学习率；二是模型本身升级，旧 harness 仍强制重复模型已能自动完成的步骤。论文称前者为 long-horizon deceleration，后者为 harness staleness。

具体例子：某 Kaggle 回归任务，Agent A 已生成特征工程与五折验证脚本，并得到分数 0.80；它继续花两小时反复尝试 0.001 的学习率变化。Agent B 接管时，保留文件、验证结果与 checkpoint，但不继承 A 全部推理噪声；B 可能想到基于时间的验证泄漏检查，使分数到 0.84。之后 A 回来又能基于 B 的发现重新组合特征。真正有效的信息是可执行且可评估的工作产物，不一定是上一会话的完整语言上下文。

研究缺口：此前 MLE 系统多比较“哪个模型或 harness 单独更强”，较少在严格共享预算下研究两套原生 model–harness pair 的轮换。即使已经有 handoff 系统，也未必量化强弱模型的接入时间、每段实验数量、启动顺序和候选保留是否决定收益。HMA 把这些变成可测的控制变量。

3. Core Insight：观察与因果边界

观察一：六个单 Agent 配置在 0–2 小时与 3–5 小时比较，每次回复的平均输出 token 下降 29.8%–45.0%。这说明回复长度与持续改进同步下降，但“token 数=推理质量”并非定理：更精炼也可能代表更高效。因此这只是探索活跃度的代理，而非因果证明。

观察二：在 16 任务的 DeepSeek harness 比较中，弱 V4 上 ScienceFlow 25.0% 优于原生 harness 16.7%；强 V4.1 上原生 harness 77.1% 反而优于 ScienceFlow 68.8%、MLEvolve 50.0% 与 ML-Master 37.5%。这支持旧工程脚手架可能失效的经验判断，但模型、预算和系统实现仍会影响结论，不能推广为“所有自定义 harness 都无用”。

观察三：共享工作目录可把一次 Agent 运行视为一个完整 option，option 结束时清空私有上下文，仍保留能让下一 Agent 接着做的外部状态。只要 Agent A 能以非零概率制造 B 可利用、但单 Agent 不易到达的状态，就可能产生协同收益。这是作者理论建模的核心，属于有明确充分条件的数学命题，并非无条件的普适优势。

4. Method Deep Dive：从输入到最终候选

完整流程：Task + W₀ → 初始化 A/B 原生 Agent → Agent A 完成 ≤k 次实验 → 归档候选/工具结果 → 清空局部 context → Agent B 继续同一 workspace → 循环切换 → 最后 15 分钟交叉复核 → 选最终 Ê。

Step 1：把原生 Agent 当成不可拆的执行单元。 A、B 不是简单两个不同提示词，而是各自原生模型、CLI、工具、会话管理的组合。论文不要求将两个模型塞进统一 prompt，也不替换其内部 planner。这样更接近真实部署，但带来模型版本、API 计费、工具权限和实验执行速度不一致的混杂因素。

Step 2：定义共享状态。 工作空间 W 存代码、数据处理脚本、日志、模型权重、预测文件；保留结果 E 是目前认为最优的提交；c^(u) 是当前 Agent 的私有对话。x=(W,E,c^(u))。一次实验是能被计数的接受结果，不等于一次 token 生成或一个工具调用。应给每个实验不可变 ID、提交路径、指标、时间戳和作者，避免交接后覆盖文件造成候选失踪。

Step 3：按 option 执行与截断。 当前 Agent 持续做实验，直到自然结束、累计 k 个接受实验或预算用尽。论文默认 k=5。切换时不回滚 workspace，只清空上下文，再启动另一 Agent。它保留外部记忆却重置内部注意路径，既不同于把长上下文截断后继续同一模型，也不同于每轮从空目录重来。

Step 4：把所有候选记入 archive。 即使最新候选不如历史最好，也不直接删除。论文理论要求最优结果保留，实际系统靠候选归档与最终 review 近似满足；这里是从数学理想到工程实现的重要落差。若不归档，最后一个 Agent 可能误把失败版本当最佳。

Step 5：留出最终复核。 总六小时中最后 15 分钟给最后执行者之外的 Agent 检查 archive，选择最终候选；没有可用 review 则回退到最新有效结果。此步不提供隐藏 test score，只能依据允许访问的验证结果和产物质量判断。最后得到可提交文件 Ê。

潜在失败模式：实验耗时不均导致 k 次实验对应的真实时间悬殊；上下文重置可能丢失未写入文件的关键知识；两个 Agent 同时修改工作目录会有并发覆盖；某模型对另一个模型的命名约定不熟悉；最后 review 可能错误挑选。论文以顺序轮换降低并发风险，但并未解决所有跨 Agent provenance 问题。

5. 数学对象与公式：CR-SMDP 究竟证明了什么？

状态与策略：x=(W,E,c)，u∈{A,B} 表示活跃 Agent；每个会话是 option oᵢ=(Iᵢ,πᵢ,βᵢ)，分别是可启动状态集、内部策略和终止规则。工作流策略 μ 决定接下来选哪个 option。奖励定义为 rₙ₊₁=q(Eₙ₊₁)−q(Eₙ)，q∈[0,1] 是保留候选质量。这个增量 reward 与最终分数一致且可望远镜求和，但前提是 E 的质量定义一致且保留策略可靠。HMA 不是用这个 reward 对 GPT/Claude 反向传播；这是理论分析的量。

Bellman 关系：Q^μ(x,o)=r̄ᵒ(x)+Σₓ′Pᵒ(x,x′)V^μ(x′)，V^μ(x)=Σₒ μ(o|x)Q^μ(x,o)。Q 表示先让某 Agent 继续一个会话的预期总改进；V 表示允许调度器选择会话后的预期总改进。semi-MDP 与普通 MDP 的区别在于一个 option 可以执行多个实验，终止才发生上层调度。

上下文重置算子：f(W,E,c)=(W,E,∅)。它明确区分保留的外部事实与丢弃的语言上下文，能解释为何“会话连续性”和“上下文连续性”不是同一件事。若重要假设只写在 c 里而没进入 W，f 会造成信息损失；反过来若 W 里有污染性提示或错误脚本，重置也不会自动清理。

协同超越条件：设单 Agent 参考家族长期性能上限 U*，选择阈值 τ>U*；假设每个 A→B 周期中，A 至少以 α 的概率进入对 B 有帮助的中间状态，B 再至少以 β 的概率抵达超过阈值的状态。令 a=αβ、初始失败概率 F₀，则 Perf_μ(2km) ≥ τ[1−F₀(1−a)^m]。当 m 增长、a>0 且最优结果保留时，下界逼近 τ。关键限制：α、β 的正下界、参考不可达状态和保留性是强假设，论文实验没有逐任务直接估计 αβ，因此定理是充分条件而非对 78.2% 的经验因果解释。

预算公式：对目标成功概率 p₀，近似 N_suff≈(2k/a)·ln[1/(1−p₀)] 次实验。例：若 k=5、a=0.1、p₀=0.9，粗略需要 10/0.1×2.303≈230 次实验；这只是示例代入，不是论文实测成本。k 越大单周期花费越高，a 也可能随 k 改变，故不能只把 k 调小就声称预算必降。

截断是否有利：论文定义 interruption advantage 为重置切换后的价值减去继续当前 Agent 的价值。只有 Δ_NTA(N)+A_μk(N)>0 才能保证截断工作流超过参考上限。若 A 在当前方向正接近重大突破，强制切换会产生负 advantage；这与“频繁切换总更好”正好相反。

6. 完整 Toy Example：六次实验怎样传递信息？

设任务是房价回归，初始分数越大越好，六次实验的总预算只是演示。A 第一次用 LightGBM 得 0.70，第二次做目标编码得 0.75，第三次试深树过拟合退到 0.71；archive 保存 0.75。假设 k=3，调度器切到 B。B 不继承 A 的聊天，但在 workspace 看到训练脚本、五折指标和历史 CSV，检查发现 A 随机划分造成时间泄漏，改为时间切分后得到可泛化的 0.73；第二次加外部时序特征达 0.78。B 退出后 A 再接手，结合 A 的目标编码与 B 的时序特征，达到 0.81。最终 reviewer 从 0.75、0.78、0.81 等候选中选择合法且验证最稳的版本。

这个例子中，B 的 0.73 看似比 0.75 低，但提供了修正验证协议的知识，可能是之后 0.81 的必要中介；只按每次局部分数决定是否保留工作目录会误删关键知识。反过来，若 B 的“修正”实际破坏评价规则，后续所有候选会被污染。要真正归因，需要对照“只切模型不重置”“只重置不切模型”“不共享文件”“保留文件但不传指标”等条件，而非只看最终是否获奖。

8. Experiment Setup 与 Metrics 教学

研究问题 RQ1：轮换是否超过组成它的两个单 Agent？75 个 MLE-bench Kaggle 任务，难度 Lite=22、Medium=38、High=15。每次六小时、一块 NVIDIA A10、max reasoning effort；主要模型为 Claude Opus 5、GPT-5.6-sol、DeepSeek-V4.1-Flash、Kimi K3、GLM-5.3。使用官方原生 harness，k=5，最后 15 分钟 review。论文主表对单 Agent 提供重复运行均值与标准差；部分调度消融只跑一轮，应区分统计强度。

研究问题 RQ2：是否仅在某一强弱配对有用？论文比较五个不同模型对、六个起始顺序配置；把每个组合与两个 constituent 的平均表现比较，也检查是否超过较强 constituent。注意“相对均值 +8pp”与“相对最强成员 +5.8pp”分母不同。

研究问题 RQ3：收益是否来自重置、伙伴接入、最后选择？Figure 4 追踪 response tokens 与 medal 随时间；Appendix F 扫 k=1/3/5、起始顺序、自然退出与最终 review。附录单独统计原生会话启动/结束、工具时间与第二 Agent 实际参与，避免把“计划切换”误当“已实际接管”。

Any-medal rate：任务最终提交获 bronze/silver/gold 的比例，越高越好，体现“有多少任务达最低可接受性能”，但不代表每个任务提升幅度。Gold rate：获得金牌的任务比例，难度更高。Med+：超过人类排行榜中位数的比例；Mean Percentile：各任务 leaderboard 百分位的平均，反映连续排名而非阈值跳变。Response tokens/response：单次模型输出长度的代理，不能单独作为 reasoning quality。Historical retention：历史上至少有一个获奖候选的任务中，最终是否仍选到获奖版本；它测的是选优能力，不是搜索能力。所有指标需同时看任务数量、重复次数、预算与模型差异。

9. Results：至少八个数字背后的证据链

结果 1（主结果）：Opus→GPT 的 HMA 78.2%，对六小时 Opus 72.4% 为 +5.8pp，对 ScienceFlow 70.2% 为 +8.0pp。作者主张流程级协作可超越强单体，数据支持特定 MLE-bench 与模型组合；不能证明任意任务、任意模型均可超越。

结果 2（高难任务）：High 子集 HMA 62.2%，两个单体均值 46.7%，为 +15.5pp（表中四舍五入 +15.6）。高难度可能更需要互补探索，但样本仅 15 任务，误差会比总榜更大。

结果 3（弱伙伴也可能贡献）：GPT→Kimi HMA 70.7%，GPT 单独 68.0%，提升 2.7pp；相对两单体均值 61.1% 提升 9.6pp。若只比较均值会夸大相对最佳单体的价值，必须并列报告两种差值。

结果 4（最弱配对）：DeepSeek→Kimi 62.7%，高于较强单体 DeepSeek 的 61.3%，仅 +1.4pp；这说明协同存在边际较小的配置，且无法推断所有 pair 都大幅改善。

结果 5（token 轨迹）：HMA 后期回复长度保留 86.4%，匹配单 Agent 仅 60.7%，相差 25.7pp；它与更持续的分数增长同向，但并未排除会话长度、模型混合及 prompt 差异。

结果 6（prefix 与预算）：k=5 的前缀保留 97.83% 已观察收益，只执行约 73.77% 原 option 实验数。这是历史轨迹的 prefix 统计，不能直接等同“真实端到端速度提升 1/0.7377 倍”。

结果 7（重要反例）：GPT→Kimi 的 NTA 77.3%，强于 k=5 的 70.7%，而 k=1/3 仅 65.3%/66.7%。这明确反驳“固定截断在所有顺序都更好”；强模型占用更多预算时可能收益更大。

结果 8（交接确实提前）：GPT→Kimi 的 NTA 到 3 小时只有 17/75 任务出现第二 Agent 回复，HMA 为 55/75；中位首次接入从 5.97 小时提前到 1.89 小时。它证明了调度机制真的改变伙伴参与，而不是只改了任务名称。

结果 9（保留能力）：450 次任务运行中，330 次曾产生获奖候选；最终 review 使获奖保留由 311/330=94.2% 到 319/330=96.7%，恢复 8 个奖牌。说明 archive/review 有独立价值，但仍漏掉 11 个历史奖牌。

结果 10（非 MLE 外推）：单次 48 小时 kernel 优化达到 878 cycles，比社区榜首 864 cycles 多 14（差 1.62%）；分数越低越好，且采用不同判题种子，不应写成“正式获得第十名”或“验证了跨领域 SOTA”。

Paper 2 · Rollout-Time Intervention：让失败轨迹被“最小纠正”后真正学进模型

基本信息：Rollout-Time Intervention: Unlocking Agentic Reinforcement Learning Beyond Policy Limits；Xi Chen、Ruixue Ding、Zhigaoyuan Wang、Fanrui Zhang、Qiang Zhang 等 12 位作者；Alibaba Token Hub、HKUST (Guangzhou)、Amap。arXiv:2610.13438v1，2026-10-09 提交，2026-10-12 进入近期列表；目前核实为预印本。 论文 · 完整 HTML · 官方代码与训练脚本。方向：RL for Agents × Credit Assignment × Off-policy Correction。

1. 一句话定位与人话版

定位：在 on-policy Agent RL 几乎采不到成功轨迹时，RTI 通过训练时的任务规则辅助纠正、分布偏移过滤和 token 级权重，使原模型能从原本学不到的成功行动中更新，而部署时不需要纠错器。

一个工具 Agent 如果总把“需要用户自己操作的工具”误当成自己能调用的工具，可能八次 rollout 全错。GRPO 的组内奖励全是零，优势也就接近零，模型学不到任何东西。RTI 不直接把标准答案塞进 prompt，而是在训练 rollout 过程中，让同一模型扮演三个角色：Validator 用评分规则发现关键违规，Corrector 在不泄露答案的情况下最小幅度改写当前行动，Verifier 检查是否有越权信息或不可信推理。修正后的行动必须仍是原策略“有可能说出来”的内容：用原始 prompt 重新计算 perplexity，偏移太大就丢弃。成功的干预轨迹只替换失败组中的一个样本，关键纠正 token 再加适度权重。论文报告 Qwen3-8B 在 Navigation 上从 GRPO 的 35.33% 提高到 57.33%，在 Claw-Eval-Hard20 上从 22.50% 到 50.00%。真正的研究点是：突破探索边界的监督必须同时满足“能成功、无泄漏、可学习”。

2. Background & Research Gap：为什么纯 on-policy RL 会停住？

将 Agent 轨迹写成 τ=[reasoning z₁, action a₁, observation o₁, …, final y]。模型策略 πθ 给出下一段推理或工具调用，环境提供反馈，最终验证器给 0/1 reward。GRPO 对同一任务采 G 条轨迹，利用组内均值和方差形成相对优势。若某个任务对当前模型太难，G=8 条轨迹全错，r_i=0，则 A_i=(0−0)/(0+ε)=0；这批样本不会把模型引向正确策略。重复采样也可能始终被早期同一错误卡住。

具体失败例子：用户让客服协助修改运营商账户设置，其中某步只能由用户在手机端完成。Agent 错误地向后台 API 发送“用户端操作”请求，得到错误后仍反复重试。它其实知道工具规则，也会向用户解释步骤，只是早期把控制权归属判断错了。一个合规的“请用户点击设置页面”就能让剩余流程恢复正常。纯 RL 需要随机撞到这条策略；RTI 在训练时把关键错误转成可学习的成功样本。

旧方法的不足：SFT 用大量专家轨迹训练，但昂贵且与当前 policy 分布可能脱节；GRPO/GSPO/AEPO 改进 on-policy 优化或熵控制，却无法凭空制造未探索到的成功分支；OPD、LUFFY 引入较强教师或离线成功数据，能解决一部分覆盖问题，但老师自身有能力上限，而且分布差异会使重要性权重不稳定。RTI 关注“用当前 policy 纠错而非直接由大模型代做”，并把可学习性放进筛选门槛。

3. Core Insight：一次小纠正比整条重写更可学

作者观察：很多 Agent 失败不是每个推理步骤都错，而是某个关键工具动作、控制权判断或地名消歧错误，导致后续进入失败循环。只修正决定性一步，模型其余能力仍可发挥。这个观察来自 τ²-Telecom 与 Navigation 的失败轨迹及案例，属于经验观察，不能证明所有 hard task 都只需一步修复。

第二层 insight：干预后的轨迹并非从原 rollout prompt 下采样。若 Corrector 因为拿到了隐藏评分规则而写出当前 policy 极不可能产生的回答，强行拿它做 GRPO，既可能泄漏测试信息，也可能造成高方差梯度。因此作者同时要求 integrity gate（是否合规）与 PPL gate（是否在可学习的分布邻域）。这与“教师越强越好”的直觉不同：过强教师给出的优质行动可能离学生太远。

第三层 insight：不是纠正文本的每个 token 都同等关键。比如“请您”与“请调用 user-side tool”中，后者决定了控制权归属；RTI 比较 corrected prompt 与原 rollout prompt 对每个 token 的概率，增大那些真正受纠错信息影响的 token 的训练权重。注意这仍是相关性代理，不是真正的 causal token attribution；概率差大可能来自措辞变化，而非策略关键点。

4. Method Deep Dive：完整训练流水线

完整流程：Task x → G 条纯 on-policy rollout → 若至少一条成功则普通 GRPO → 若全部失败则启动 Validator → Corrector → Verifier → 原 prompt PPL gate → 继续 rollout 直至终局 → 成功则替换一个失败样本 → 计算组优势 + token reweight → clipped policy update → 新 πθ。

Step 1：先采一组纯 on-policy 轨迹。 每个训练 query 采 G=8 条，temperature 0.8；记录生成 token 的旧策略 logprob、工具调用、环境 observation、终局 reward。若有任何成功，完全不启动干预，直接按 GRPO 训练。这一点减少了在容易任务上引入 off-policy 噪声的机会，也让方法成本随失败率变化。

Step 2：失败组触发 Validator。 Validator 在训练时可读取评价规则或 rubric，用它判断当前动作是否明确违反硬约束。关键是诊断信息与执行 Agent 的可见历史必须分离。它可以知道“用户端工具不能由 Agent 调用”，但不能把隐藏账户值、最终坐标或标准答案直接写入接下来的动作。

Step 3：Corrector 最小改写。 输入可见历史、工具 schema、错误草稿和经过处理的诊断，输出修正行动。作者要求风格接近、逐步修复、禁止泄漏和最小干预；例如把错误的 API 调用改成面向用户的操作指导，而不是把整段对话改写成标准答案。这样纠正后的轨迹与当前 policy 仍共享大部分前缀。

Step 4：Verifier 双重审查。 检查修正是否满足任务约束、是否泄露了隐藏信息、是否凭空编造原上下文推不出的事实；失败就回退原行动。去掉这个模块后 Navigation Pass@1 反而低于 GRPO，说明“错误纠正器”可以制造比不干预更糟的训练样本。

Step 5：PPL gate 重新评分。 将 validator/corrector 的特权信息全部从 prompt 移除，在原始 rollout 条件下计算修正片段的平均 token 负 logprob，取指数得到 perplexity；高于阈值 δ 则拒绝。这里衡量的是原策略能否合理生成这段纠正，不是这段纠正的事实正确率；事实性由 Verifier 和终局 reward 负责。

Step 6：继续环境执行并只接纳成功轨迹。 被接受的修正进入环境，继续后续步骤；若最终 reward=1，则替换 G 条全错轨迹中的一个。若最终仍失败，不强制加入。替换一个而非整个 group 是为了在原始失败轨迹与成功干预轨迹之间保留相对对照，形成非零 group advantage。

Step 7：带校准权重的 GRPO。 对纯 on-policy token 权重为 1；对纠正 token 计算校准 prompt 与原 prompt 的概率比，并限制在 0.8–1.2。对环境 observation token 置 loss mask，不应让模型“学习输出工具返回的文本”。梯度更新后，下一轮仍从没有干预的原始策略开始采样，以检验真正学进模型，而不是让纠错器在部署时永远兜底。

5. 公式教学：Reward、Advantage、KL、PPL、重要性权重

GRPO 的组优势：Aᵢ=(rᵢ−μᵣ)/(σᵣ+ε)。rᵢ 是第 i 条轨迹的 0/1 成功值，μᵣ 和 σᵣ 是同组 G 条的均值与标准差，ε 避免除零。最大化优势加权 logprob 会增加成功样本的生成概率，降低失败样本概率。若全错，μ=σ=0，训练没有方向。RTI 的关键不在于发明新 reward，而是让困难任务组内出现一个可用的 r=1。

原始 clipped objective：对每个生成 token 的新旧策略比 ρ_grpo=πθ(token|history)/πold(token|history)，最大化 min(ρA, clip(ρ,1−ε_clip,1+ε_clip)A)；clip 防止单次更新过猛。原论文 Preliminaries 还写了 −β KL(πθ||πref) 的常见正则项，但其最终 RTI Eq.(7) 主要展示带权的 clipped surrogate，不能自动假设每个复现配置都用了同样 KL 系数。KL 惩罚与 clipping 都限制偏离，却不是同一数学对象：KL 约束整体策略分布，clip 只约束采样 token 的局部概率比。

PPL gate：PPL_roll(ũ)=exp{−(1/T) Σₜ log π_roll(ũₜ | visible_history,ũ_<t)}。T 是修正片段 token 数，数值越小表示模型越能自然说出该片段。PPL≤δ 才保留。若 δ 太小，正确但稍有新意的策略也被丢弃；δ 太大，离策略太远的修正可能导致不稳定。注意 PPL 是 token 平均概率的指数，不等于两个完整轨迹分布的 KL 距离，也不能保证有限方差。

Reasoning-shift weight：ρ_cal^t=exp[log π_cal(ũₜ|h,ũ_<t)−log π_roll(ũₜ|h,ũ_<t)]，再做 wₜ=clip(ρ_cal^t,1−ε_cal,1+ε_cal)。这里 π_cal 与 π_roll 可来自同一模型、不同条件 prompt；π_cal 带 validator 反馈，π_roll 只有可见历史。比值高的 token 更依赖纠错信息，权重略大；比值低的 token 略小。ε_cal=0.2 意味着权重 0.8–1.2，且 stop-gradient。与常规 off-policy importance sampling π_target/π_behavior 不同，它是用于突出干预 token 的校准系数，不应宣称给出了严格无偏估计。

最终目标：J_RTI=E[(1/G)Σᵢ (1/|τᵢ|)Σₜ wₜ·min(ρ_grpo Aᵢ,clip(ρ_grpo)Aᵢ)]。与最强 RL baseline 的区别在于样本分布和 token 权重，而非把 GRPO 完全换成另一种优化器。理论附录给出 O(1/√K) 的梯度平稳性上界，但假设 smoothness、梯度对齐和干预项二阶矩受控；它不证明实际非凸训练必收敛到更优策略，也不证明对任何 δ 都成立。

6. Toy Example：把“八条全错”变成有效学习信号

假设一个 Navigation 任务需要依次经过 A、B、C 三处景点。Agent 查询 B 时拿到两个同名地点，错误地选择离 A、C 都很远的坐标；接下来直接调用 direction，因坐标不匹配，八条 rollout 的 reward 都为 0。原始 GRPO 组优势全为 0。RTI 在第一个误选 B 的位置让 Validator 指出“该 POI 与已知路线区域不一致，需要补充 region 检索”，Corrector 将 direction(A,B_wrong,C) 改成 poi_search(B, region=附近城市)，Verifier 检查没有偷看真实 B 坐标。假设原策略对改写的 PPL=4.2，小于 δ=5，于是执行补查，得到正确 B，最终 direction 成功，reward=1。

现在组奖励是 [1,0,0,0,0,0,0,0]，均值 μ=0.125，标准差约 0.331，成功轨迹优势约 (1−0.125)/0.331=2.65，失败轨迹优势约 −0.125/0.331=−0.38。在成功轨迹里，region= 和 poi_search 可能得到较高校准比值，clip 后最多 1.2 倍权重；礼貌措辞可能仍接近 1。训练若真正有效，下一轮不用 Validator 的 Agent 就会主动检查地理一致性。这个小例子展示 reward 稀疏性如何被打破，但 PPL、坐标和优势数字除 G=8 外均为教学构造，不是论文的实验记录。

8. Experiment Setup：数据、模型、协议、成本

RQ1：弱模型在复杂工具交互中是否突破 on-policy 上限？ 两个骨干：Qwen3-8B 与 Qwen3.5-9B。五个测试 setting：Navigation、τ²-Telecom、τ²-Retail、τ²-Airline、Claw-Eval-Hard20。训练/测试数量分别是 Navigation 600/150、Telecom 1148/114、Retail 563/114、Airline 271/50、Claw 160/20。Navigation 使用高德真实 POI API、3–9 个途经点、最多六轮工具交互，按 origin/destination/waypoints 的精确参数匹配给 reward。

RQ2：提升是“模型自身学会”还是只靠纠错器？ 比较训练中干预前与干预后 rollout 成功率、训练外独立 evaluation Pass@k，以及干预片段的 PPL 随时间变化。若仅干预后成功率高而原模型无干预评估不涨，说明方法只是训练时外挂，不能宣称能力内化。

RQ3：三个组件各有什么作用？ 在 Qwen3-8B 的 Navigation 与 Telecom 上分别去掉 Post-Check、PPL gate、token reweight；扫描 δ=0/3/5/20/∞；另用 397B 大模型担任纠错者，与同模型 self-intervention 对比。

训练配置：Adam，lr=1e−6、weight decay=0.1、temperature=0.8、G=8、GRPO clip=0.2、calibration clip=0.2；环境 observation token 不计算 loss。作者报告 8×NVIDIA H20、tensor parallel=4 训练，教师基线额外服务在 16×PPU-ZW810E 上。训练总 GPU 小时、所有模型端到端美元成本与各方法相同成功轨迹数下的严格效率对照未见统一完整披露，不应推断 RTI “更省算力”。

重要实现核对：论文 §5.4 在 Navigation 上选 δ=5，并有“所有实验采用 δ=5”的表述；但 2026-10-14 查到的官方 qqr README 明确列出 Navigation δ=5，τ²/Claw δ=20。这可能是代码后续调整、实验配置差异或文字不一致；复现时必须锁定 Git commit、训练脚本实际参数，不能把两者混为同一配置。官方仓库包含 qqr/off_policy/rti/、qqr/examples/navigation/、scripts/navigation/、训练数据与 run 脚本；这比只声称“有代码”更可操作。

9. Metrics 教学：Pass@k 与 Pass^k 不是一回事

Pass@k：对每个任务独立尝试 k 次，只要至少一次成功就算该任务成功，最后对任务求平均。越高越好，反映覆盖面和“多试几次能否做对”。Pass^k：同一任务 k 次全部成功才算成功，越高越好，反映重复稳定性。若某任务单次成功概率 p 且各次独立，则理论上 Pass@k≈1−(1−p)^k，Pass^k≈p^k；实际存在任务难度异质性，不能简单由总体 p@1 推算其他 k。

p@1：作者四轮评测中 Pass@1 的平均。avg p@k：对 k=1..4 的 Pass@k 再平均。avg p^k：同理对 all-success 指标平均。三个指标不能混着报：一个模型可能偶尔成功、Pass@4 很高，却每次结果不稳定、Pass^4 很低。PPL_roll 越低表示纠正越接近原策略，但不保证更正确；训练 pre-intervention success 才更直接衡量能力是否内化。Claw-Eval task_score：safety × (0.8 completion + 0.2 robustness)，按阈值判 pass；它含 LLM judge 主观性，不如 Navigation 的精确工具参数完全可验证。

10. Results Deep Dive：十个关键数字与边界

结果 1（Navigation, Qwen3-8B）：RTI 57.33%，GRPO 35.33%，提升 22.00pp；对最强 OPD 37.33% 为 +20.00pp。这是清晰的工具纠错收益，但仅 150 测试任务、任务来自特定合成地图协议。

结果 2（Telecom, Qwen3-8B）：RTI 61.40%，GRPO 36.84%，+24.56pp；对最强 OPD 55.26% 为 +6.14pp。这个 setting 正对应用户侧/Agent 侧工具控制权混淆，机制解释比较可信。

结果 3（Retail, Qwen3-8B）：RTI 73.68%，最强 LUFFY 71.93%，只有 +1.75pp；说明并非每个领域都有大幅收益，原模型已较容易探索成功时 RTI 触发率下降。

结果 4（Airline, Qwen3-8B）：RTI 56.00%，AEPO 51.00%，+5.00pp；相比 Retail 增益大一些，但并非革命性。若只挑 Navigation、Claw 展示会高估平均效应。

结果 5（Claw-Hard20, Qwen3-8B）：RTI 50.00%，GRPO 22.50%，+27.50pp；LUFFY 30.00%，+20.00pp。20 个 hard task 的样本非常小，且专门挑了 base policy 罕见成功的任务，适合验证边界突破，不适合估计总体部署提升。

结果 6（Claw-Hard20, Qwen3.5-9B）：RTI 85.00%，基础模型 26.25%，+58.75pp；最强 LUFFY 61.25%，+23.75pp。这是最强相对结果，但训练数据专门针对这 20 个任务合成，不能等同严格跨任务 OOD 泛化。

结果 7（较强模型已饱和）：Qwen3.5-9B 在 Telecom 上 base 92.11%，RTI 96.49%，仅 +4.38pp；与 AEPO、OPD、LUFFY 的 96.49% 持平。这说明能力接近天花板时 RTI 优势缩小，不能把它说成所有设置均显著击败 strongest baseline。

结果 8（Verifier 是刚需）：Navigation 去掉 Post-Check 后 26.00%，比完整 RTI 57.33% 低 31.33pp，也低于 GRPO 35.33%；这不是“少一点提升”，而是干预数据可能伤害模型。

结果 9（PPL gate 的稳定性）：Telecom 去掉 PPL gate 后 Pass@1 61.40→54.39（-7.01pp），Pass^4 31.58→18.42（-13.16pp）。后者跌得更厉害，说明过滤分布偏移不仅影响能否偶尔成功，还影响重复可靠性。

结果 10（Token 权重贡献较小）：Navigation 去掉 reweight，Pass@1 57.33→55.33，仅 -2.00pp；Telecom 61.40→60.53，仅 -0.87pp。token 归因有帮助，但最大增益来自安全、近策略的成功轨迹本身；应防止把所有效果归因于一个新的 token objective。

Ablation 机制归纳：去 Verifier → 泄漏/幻觉污染，可能负迁移；去 PPL gate → 接纳离策略太远的行为，训练稳定性变差；去 reweight → 仍有成功纠正，但学习焦点分散；δ 过小 → 没有足够纠正样本；δ 过大 → 低概率行动增加梯度噪声。它们分别对应数据正确性、分布可学性、token 贡献权重三个不同问题。

12. Claim vs Evidence、Contribution 与局限

Authors Claim：RTI 能超越当前 policy 的探索能力边界，不依赖强外部教师，并能稳定学到新推理模式。Experiments Actually Show：在两种 Qwen 骨干、五类任务和特定训练配置下，独立无干预评估有提升；多个消融与训练曲线支持纠错/过滤的必要性。Not Yet Proven：在完全新任务分布中仍能维持同等增益；对隐藏 rubric 绝无信息泄漏；token 权重确实是因果 credit；相同 GPU/美元成本下仍优于所有方法；理论收敛上界足以解释经验优势。

Contribution 1 — New Mechanism：仅对全失败组执行 Validator–Corrector–Verifier，并把成功轨迹作为组内一个样本；核心新意是 rollout 阶段的可验证最小纠错。Contribution 2 — New Training Protocol：原 prompt PPL 过滤与校准 token 权重，把 off-policy 样本可学习性纳入数据入口；数学部件源于已知重要性比与 clipping，但组合有明确动机。Contribution 3 — New Empirical Finding：较强教师未必更好，Verifier 缺失会产生负迁移，且模型能逐渐在无干预条件下成功。Contribution 4 — New Benchmark/Protocol：Navigation 的空间锚定多途经点构造与精确参数匹配，便于研究真实工具行为，而非仅评价最终自然语言回答。

Authors' limitation（从实验边界可见）：训练依赖可访问的任务规则或 rubric；复杂环境必须有可靠终局评估；强模型对容易任务增益有限；离策略纠正有稳定性风险。Additional limitation：Verifier 本身由 LLM 扮演，可能误判泄漏；Claw 采用 LLM-as-judge 且样本只有 20；Navigation 数据由强模型合成并筛选，可能存在模板偏差；修正的 PPL 低不代表真实任务合理；额外的三角色推理会增加 rollout 成本；PPL gate 对低概率但真正新颖的策略存在保守偏见；训练/评估若共享任务模板可能高估泛化。

13. Reproduction View：最小实现与核验点

官方入口：qqr 中 qqr/off_policy/rti/ 是诊断、纠错、post-check 和 PPL 参考打分；qqr/off_policy/train_async 是两阶段采样训练入口；qqr/reward_models/utils.py 包含 token reweight；scripts/navigation/run-qwen3-8B.sh 是最明确的复现脚本。需要先匹配 qqr 与 slime 版本，再配置地图 API 与 inspector endpoint。敏感参数：G=8、temperature=0.8、δ、ε_cal=0.2、最大工具轮次、修正接受率、是否只替换一个失败样本。

最小复现版本：若没有 8×H20，可先不训练完整 Qwen，而是使用 100–200 个可确定判分的本地工具任务和小型开源模型，只验证 all-fail detection → correction → verifier → PPL gate → final success → group advantage 是否能产出合规样本；第二阶段再做 LoRA/小批量 GRPO 更新。最先跑的实验：固定 100 个全失败任务，统计 Validator 发现错误比例、Verifier 接受率、PPL 通过率、终局成功率、额外 token/GPU 秒，再比较四个组件组合。关键验收：在独立测试集上关闭全部纠错角色后，Pass@1 是否真正上升；若仅训练时成功，不能算能力提升。

Research Value：Baseline Potential 高——适合 hard-agent RL 采样策略对照；Migration Potential 高——可迁移到 coding agent 的失败工具调用和 video agent 的错误帧选择；Systems Potential 中高——需要训练期多角色调度和 PPL scoring 缓存；Attack Potential 高——恶意 rubric/validator 可把“纠错”变成后门；Evaluation Potential 高——可测 correction faithfulness、off-policy distance 与 internalization；Benchmark Potential 高——Navigation 精确工具调用易审计；New Paper Potential 中高——若把纠错可学性与因果 credit 区分并建立鲁棒协议，可形成新训练或评测方法。

14. 两条可执行 Migration：跨方向而不是换名复用

Migration A · Coding Agent 的因果错误点纠正 RL。Original Problem：代码 Agent 在长任务中一处工具/测试错误导致整条轨迹失败。Transferable Mechanism：失败组触发最小干预 + PPL gate + 无干预复测。New Research Question：针对 git checkout、单元测试失败、错误依赖安装的关键行动纠正，能否比整条专家轨迹 SFT 更省训练样本？Method Modification：Validator 使用可验证 test assertion 和工具调用约束，Corrector 只改一个 tool action，Verifier 禁止直接把 patch 的隐藏标准答案注入。Minimum Experiment：选择 200 个小型 SWE 任务，每任务采 8 条；记录首个可验证失败动作；纠错后续跑到单测通过；构建 GRPO / SFT-success / RTI-no-gate / RTI-full 四组，固定总生成 token；LoRA 训练 3 seeds。Model：Qwen3-8B 或同级开源 coding model。Dataset：可本地复现的 SWE-bench Lite 子集或自建单元测试仓库。Baseline：GRPO、成功轨迹 SFT、teacher distillation。Metric：独立 task resolved、token/$/success、纠错接受率、原始策略无干预成功率。Expected Contribution：验证“局部纠错比全轨迹替换更可学”。Risk：测试 oracle 不完整、长轨迹成本高。Collision Risk：与 process supervision、SWE trajectory repair 文献相近，必须用“只修一处且保留原策略分布”的因果对照区分。

Migration B · Video Agent 的视觉决策干预与可学性过滤。Original Problem：视频 Agent 在长视频中选错关键帧，后续 QA 轨迹无法恢复。Transferable Mechanism：只在失败轨迹的关键 frame selection 处插入经验证的替代行动，过滤与原策略相差过远的决策。New Research Question：纠正一两个 frame/token selection 决策能否改善 Video QA，而无需全量增加帧数？Method Modification：把行动定义为下一批要读取的帧索引，Validator 用训练集 temporal grounding 标注诊断遗漏证据，Corrector 从原候选窗口选邻近关键帧，Verifier 禁止直接泄露答案；用策略的帧选择 logprob 或可学习评分代替语言 token PPL。Minimum Experiment：取 500 个有时间定位标签的 Video QA 样例，统一每题最多 16 帧；比较 uniform、learned selector、selector+unfiltered correction、selector+gated correction；记录训练时被修正帧比例，测试时完全关闭 oracle。Model：开源 Video VLM + 轻量帧选择器。Dataset：有证据时间段标注的 Video QA 子集。Baseline：均匀抽帧、query-aware selection、无门控纠错。Metric：QA accuracy、evidence recall、frames、visual tokens、FLOPs、实际 latency、GPU memory。Expected Contribution：把 RL 的可学性约束引入视频信息预算决策。Risk：帧选择器概率不校准、视觉证据缺失无法靠小修正补救。Collision Risk：与 adaptive frame selection、temporal grounding、video agent reflection 有交叉，需证明训练后无 oracle 的效率—质量 Pareto 改善。

15. Attack / Verification Lens 与十句话记忆

Attack：篡改 Validator rubric 使 Corrector 偷看隐藏答案，测试模型是否学到捷径。Black-box probe：训练后只给原始任务，不提供纠错提示，检测是否重现关键行动。Robustness：将工具 schema 改名、注入误导性观察、打乱环境回馈顺序。Efficiency stress：让绝大多数任务失败，观察三角色干预开销和训练吞吐下降。Recovery：训练后再改变 rubric，检查是否只记住旧评分规则。New metric：Corrected-Trajectory Learnability = 干预后成功率与训练后原策略成功率之间的差距；差距越小才越可能真正内化。Benchmark：可验证工具动作错误点、隐藏规则隔离和跨分布修复。

  1. RTI 解决的是全失败 rollout 组缺乏正梯度的问题。2. 干预只在全组失败时触发。3. Validator 可用训练期 rubric，但不能把隐藏答案交给 Corrector。4. Verifier 缺失会让性能低于纯 GRPO。5. PPL gate 衡量修正对原策略是否“可说出来”，不是事实真伪。6. Token 权重是校准比值而非严格因果归因。7. 最强提升出现在困难 Claw-Hard20，但样本仅 20。8. 强教师未必比同模型纠错更可学习。9. 复现时要核对论文与官方仓库 δ 配置的差异。10. 最重要的下一步是证明纠错被模型真正内化，而不是训练时借了 oracle 的光。

2. 机制互补、冲突与可组合框架

互补一：HMA 的共享工作目录可以存 RTI 所需的失败轨迹、错误类型、工具 schema 和验证结果；不同 Agent 能互相生成候选修复。互补二：RTI 的“纠正必须可学习”原则可以反过来约束 HMA 的 handoff：交接摘要必须可验证、接手者能够从可见工作产物恢复，而不是只能靠特权提示才能继续。互补三：HMA 的 option 终止 advantage 可用于决定何时召唤额外 Agent 作为纠错者，避免每一步都付多 Agent 费用。

真实冲突一：HMA 鼓励切换不同强模型寻找互补性；RTI 的结果却提示过强教师产生的纠正可能离学生分布太远。这意味着“换更强 Agent 解决问题”与“让原 Agent 学会解决问题”不是同一优化目标。真实冲突二：HMA 依赖共享 workspace 充分保留有价值信息；RTI 刻意把训练期 privileged rubric 与原策略可见信息隔离。若把所有历史消息无差别写进共享记忆，就可能同时破坏可学性与评测有效性。

统一框架建议：Observable State → Failure/Progress Detector → {Continue Current Agent, Handoff to Peer, Minimal Correction} → Verifier → Provenance Ledger → Budget-aware Scheduler → [optional RL update]。训练时可以用可验证 reward 评估不同控制动作，部署时则只允许观察任务本身可访问的信号。框架应至少拆分三个目标：当前任务成功率、无外部帮助的能力内化率、总系统成本。

3. Combined Research Opportunities：三个不同层次的实验

机会 A：Adaptive Handoff vs Adaptive Intervention（最值得先做）。选择 100 个编码 Agent 任务，构建 always continue / fixed handoff / error-triggered handoff / error-triggered minimal correction / joint scheduler 五组；所有方法共享总 token 与 wall-clock 上限。将“最近验证增益”和“可验证错误位置”作为状态，研究哪类失败应该切换模型、哪类失败只需修正当前动作。关键评估是 task resolved、额外调用数、真实切换税和相同成本下的 Pareto 曲线。若联合策略没有超过最强单项，说明两种机制的互补性尚未得到证据支持。

机会 B：Provenance-Aware Intervention Benchmark（更适合评测论文）。在共享目录里引入三种受控污染：虚假的最佳分数、带泄漏答案的纠错日志、失效工具 schema。区分 visible task evidence、privileged training-only rubric、untrusted peer artifact 三个信息级别，统计污染传播、恢复、无泄漏成功率。与普通“最后能否完成任务”不同，它直接测哪些历史信息可以合法影响未来行动。

机会 C：Counterfactual Credit for Handoff（更偏机制论文）。对同一个中间 workspace 快照分别运行 A 继续、B 接手、A 重置、B 纠错四种反事实分支，测量条件增益 Δq 与时间成本。再拟合一个小模型预测最佳动作，比较基于固定 k、PPL 阈值和 learned scheduler 的校准误差。此实验不需要先训练大型 LLM，能够优先验证核心科学问题：观察到的收益究竟来自互补能力、重置、更多样本还是历史成果的正确选择。

4. Collision / Overlap：如何避免把已有组件重新包装成新论文

HMA 与传统 multi-agent handoff：仅提出“两个 Agent 轮流执行”没有足够创新；需要动态终止优势、同预算强对照、可追踪工作产物和跨模型泛化。论文自身的 NTA 77.3% > k=5 70.7% 是很好的反例，说明新的调度方法不能只宣称“更早切换”。

RTI 与 teacher distillation / trajectory repair：仅把失败行动交给更强模型修复也不新；必须严格分离 privileged rubric，展示 PPL 过滤和无干预能力内化，并比较相同成本下的有效成功轨迹数。论文中 self-intervention 优于大教师，是值得复现的边界，但不能把它写成“强教师永远无用”。

与昨天的 TreeHCA 的重叠提醒：若将 credit assignment 当成新 Idea，先核对是否已存在“基于后见信息为关键动作分配信用”的工作。RTI 目前的校准比值是 likelihood proxy，未提供真正的因果 credit；一个潜在新点是用反事实工具行动差值替代 token 概率比，且必须通过 action-level causal intervention 证明增益，而非只重命名 weighting。
