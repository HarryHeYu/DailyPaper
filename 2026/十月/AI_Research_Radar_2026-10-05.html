9–11. Tier S / A / B

Tier SRL / Reasoning VIMPO: Value-Implicit Policy Optimization for LLMs

Paper / Source

人话版：这篇论文到底干了什么？ GRPO 的优点是不训练 critic，工程简单；缺点是同一条推理轨迹里的 token 往往共享一个粗粒度的 trajectory advantage，谁真正促成了正确答案并不清楚。VIMPO 从 KL-regularized RL 的最优性条件反推出一个“policy 自己隐含的 value function”，用 policy/reference 的 log-ratio 和终点条件构造 value recurrence，于是不额外训练 critic，也能得到更细的 credit assignment。对今天的四条主线来说，它最值得看的是：如何把 outcome reward 变成 token/step-level learning signal，而不引入传统 actor-critic 的不稳定性。

Background & Gap

RLVR 通常只有最终答案是否正确这一类 sparse reward。GRPO 用组内相对回报估计 advantage，省掉 critic，但一条 200-token 推理链里“关键转折”和“无效绕路”容易得到近似相同的更新方向；PPO/actor-critic 可用 value 做更细估计，却要额外学习 value network。VIMPO 的 gap 正是：能否保留 critic-free 的工程简单性，同时恢复更细粒度 credit。

Core Insight & Method Deep Dive

Pipeline：prompt → policy rollout → terminal verifiable reward → 计算 policy/reference log-ratio → 由 KL-regularized optimality relation 递推 policy-implied value → 构造 value loss → 形成 critic-free actor advantage → PPO-style policy update。关键不是“再造一个 critic”，而是把当前 policy 相对 reference 的概率变化视为价值信息的载体，并用序列末端“未来 reward 为 0”作为边界条件。

RL Formulation：state 是当前 prompt+已生成 prefix；action 是下一个 token；policy 是待训练 LLM；trajectory 是完整 reasoning response；reward 主要来自最终可验证答案；KL 项限制 policy 偏离 reference。Credit assignment 的核心改动是把 outcome reward 通过 value recurrence 向前传播，而不是把同一 scalar advantage 平铺到所有 token。

Toy Example

假设数学题最终答对得 +1。GRPO 可能让“列出关键方程”“一次无效展开”“最后代入”都继承近似相同的轨迹优势。VIMPO 则利用每一步 policy/reference 的 log-ratio 与终端 reward 递推隐含 value：若某个 token 后续明显进入高价值分支，其 prefix value 应上升；无效绕路不再天然和关键步骤等价。

Baseline Comparison

GRPO：最强且最直接 baseline，critic-free、稳定但 credit 粗；PPO/actor-critic：value 更细，但 critic 带来额外参数、拟合误差与训练耦合；VIMPO 的创新是机制性的折中，而非单纯工程优化。

Experiment Setup & Results

公开摘要报告数学 RLVR 上比较 GRPO，覆盖 MATH-500、AIME 2024、AIME 2025、OlympiadBench；在这些 benchmark 上 VIMPO 均优于 GRPO，且 competition-style evaluation 增益更明显；在 noisy reward 下仍保持一致优势。当前可获取信息没有给出所有表格的逐项数值，因此本日报不编造数字。

Research Question 1：policy-implied value 是否能稳定超过 GRPO？摘要给出的跨四个数学 benchmark 的一致提升支持“有效”，但还不能证明对非数学 agent trajectory 同样成立。
RQ2：noisy reward 下是否更稳？作者报告仍持续领先 GRPO，这对真实 agent 环境尤其重要，因为 tool/environment reward 往往比数学 verifier 更脏。

Claim vs Evidence

Claim：critic-free 也能获得更细 credit assignment。Evidence：数学 RLVR 多 benchmark + noisy reward 对比。尚未证明：长时程 tool-use、多 reward source、部分可观测 agent 环境，以及 wall-clock/sample efficiency 是否优于成熟 GRPO stack。

Contribution / Limitation

Contribution 1【New Mechanism】：policy-implied value；2【New Objective】：value loss 与 PPO-style actor update 的 critic-free 分离；3【New Empirical Finding】：noisy reward 下仍优于 GRPO。限制是现有证据集中于数学 RLVR，尚缺 agentic long-horizon credit、工具失败传播、真实训练成本和大规模 stability 曲线。

Research Value & Migration

Original Problem 数学 RLVR 粗粒度 credit → Transferable Mechanism policy-implied value → New Question 能否对 Agent 每次 tool call / memory write 分配 credit？→ Minimum Experiment 在 WebArena/OSWorld 轨迹中把 action span 视作 macro-action，比较 GRPO vs VIMPO-style recurrence；Model 可从 7B/8B open model 起；Metric 用 task success、step efficiency、tool-error recovery、reward variance、training stability；风险是 token-level log-ratio 未必对应 tool-level causal contribution。

五句话总结

  1. VIMPO 试图同时拿到 GRPO 的简单和 actor-critic 的细 credit。
  2. 核心信号来自 policy/reference log-ratio，而不是额外 critic。
  3. 数学 RLVR 多 benchmark 均报告优于 GRPO。
  4. noisy reward 结果让它对 Agent RL 特别有迁移价值。
  5. 最值得做的下一步是 tool/trajectory-level credit assignment。
Tier SRL × Agent OpenForgeRL: Train Harness-native Agents in Any Environment

Paper / Source

人话版：很多 Agent 真正运行时依赖 Codex/OpenClaw 一类复杂 harness：多轮模型调用、工具、容器、GUI、状态都在 harness 里，但常见 RL 框架只会“模型输入→模型输出”。OpenForgeRL 用代理层截获 harness 的模型调用并记录成 RL 训练数据，再用 Kubernetes 给每个 rollout 独立环境，从而让 Agent 在真实部署 harness中端到端训练。它把“Agent RL 到底训谁”从裸 LLM 推到了完整运行系统。

Background & Gap

传统 RL stack 假定一次 rollout 的边界清楚，而 coding/computer-use agent 的状态散落在 shell、文件、浏览器、工具输出和 harness 控制逻辑中。若训练时使用简化 harness、部署时换真实 harness，会产生明显 train–serve mismatch。

Core Insight / Architecture

Environment → harness 执行 → lightweight proxy 接管模型调用 → 记录 observation/action → 标准 RL backend（如 veRL）更新模型；Kubernetes orchestrator 为 rollout 提供隔离容器。关键是解耦 inference orchestration 与 RL optimization：harness 不必重写成 RL 框架原生环境。

Agent State & Failure Propagation

state 不只是 prompt，而包含 trajectory、tool result、filesystem/browser state 与 harness 控制状态。一次错误 tool call 会污染后续 observation；若 agent 把错误结果写入 memory/文件，影响会跨 turn 延续。论文摘要特别指出 RL 提升 self-verification、tool coverage、multi-step completion，但 error recovery 仍弱——这正是长时程 credit 的硬骨头。

Experiment / Results

OpenForgeClaw：ClawEval 31.7 pass^3、55.9 pass@3，QwenClawBench 33.7；OpenForgeGUI：OSWorld-Verified 37.7、Online-Mind2Web 63.0、WebVoyager 72.3。作者称同规模 open baselines 上几乎全面领先，GUI 场景可匹配/超过大数倍模型。训练只用数百到数千任务，说明 harness-native RL 的 sample efficiency 值得继续追。

RL / Reward Analysis

公开摘要不足以完整核对每个环境 reward shaping、KL/entropy 和 rollout token budget，因此不猜。真正值得精读正文的是：环境 success signal 如何转为训练 reward、失败 trajectory 如何处理，以及不同 harness 对探索空间和 credit assignment 的改变。

Claim vs Evidence / Contribution

【New System/Engineering】通用 harness-native RL bridge；【New Empirical Finding】harness choice 显著影响可学习性；【New Evaluation】跨 claw、GUI/browser/computer-use。证据支持“真实 harness 可训练且 RL 改善可靠性”，但尚不能证明错误恢复、超长任务和不同 reward schema 已解决。

Migration

直接可做：在同一 base model 上固定任务与 reward，只切换 harness（minimal / Codex-like / memory-augmented），测 success、rollout length、tool entropy、recovery rate 和 reward variance；进一步接 VIMPO 做 tool-span credit。风险是 harness 改变 action space，导致公平对比困难。

五句话总结

  1. Agent RL 不应只训练“裸模型”。
  2. OpenForgeRL 把真实 harness 变成可被标准 RL stack 训练的环境。
  3. GUI/browser 多 benchmark 已给出明确结果。
  4. RL 改善自检和多步完成，但 error recovery 仍弱。
  5. 它和细粒度 credit assignment 的结合非常值得做。
Tier SVideo Acceleration JoyAI-Video-Edit: Real-Time Open-Ended Video Editing with Autoregressive Diffusion

Paper / Source

人话版：这项工作把 16B 视频编辑模型做到了单张 Nvidia B200 上约 30 FPS、720p 的端到端实时编辑。核心不是简单“少算几帧”，而是把视频编辑改造成 chunk-wise causal autoregressive diffusion，并通过 Source-Anchored Distribution Matching Distillation 与 Long-Horizon Autoregressive Distillation，把生成压到 two-step，同时抑制长视频自回归误差累积。

Background & Gap

离线视频扩散可以看未来帧，质量高但延迟大；流式编辑必须只看过去，并且每个 chunk 的小误差会成为下一 chunk 的条件，长期产生 drift。若只减少 diffusion steps，train–inference mismatch 与 source fidelity 又会恶化。

Method Deep Dive

Streaming input → chunk-wise autoregressive adaptation → SA-DMD 对齐两步生成与 teacher/source 分布 → Long-Horizon Autoregressive Distillation 显式暴露累计误差 → causal two-step generation → edited stream。SA-DMD 的直觉是“加速不能以忘掉原视频结构为代价”；long-horizon distillation 则不是只教单个 chunk，而是教模型在自己的历史输出条件下继续稳定生成。

Toy Example

把一分钟视频切成连续 chunk。普通两步学生第 1 个 chunk 只偏一点色调，第 20 个 chunk 条件已经来自连续偏差，人物身份可能漂移。长时程蒸馏训练时让学生看到这种自回归历史，从而学习把状态拉回稳定轨道。

关键判断：这里不是“FLOPs 看起来下降但速度没落地”的论文：作者明确给出端到端 720p≈30 FPS 的 wall-clock 系统结果。不过硬件是 B200，跨 A100/H100/消费卡的可迁移性不能从该数字直接推出。

Results / Evidence

最强结果是 16B + 720p + 单 B200 ≈30 FPS；自动和人工评测均称显著超过既有 streaming editors，并与强 offline systems 保持竞争力。最需要警惕的是“实时”高度依赖 B200；公开摘要没有给出 FLOPs、显存、各 baseline FPS，因此这些项应读正文表格后再做硬件归一化。

Contribution / Limitation / Migration

【New Mechanism】source-anchored distillation + long-horizon autoregressive distillation；【New System】real-time causal video editing；【New Empirical Finding】大模型两步生成可达到实时。限制：高端硬件依赖、长时漂移仍是核心风险、缺少这里可核验的跨硬件 latency 曲线。

迁移方向：把 long-horizon distillation 用到 Video Agent 的 streaming perception cache。Minimum Experiment：选 Video-MME/长视频 QA，缓存 chunk representation；训练学生在自己的压缩历史上继续预测，比较无 long-horizon training 的 drift、token 数、延迟、QA accuracy。

五句话总结

  1. 16B 视频编辑模型做到 720p≈30 FPS。
  2. 真正难点是 causal streaming 的长期误差累积。
  3. two-step 只是速度手段，SA-DMD 负责 fidelity。
  4. Long-Horizon Distillation 负责抑制自回归 drift。
  5. 这个机制很适合迁移到 streaming Video Agent memory/cache。
Tier AInference Acceleration × Agent The KV Cache Working Set: Online Capacity Planning for LLM Inference Systems

Paper / Source

人话版：KVSET 不直接发明新的 KV 压缩，而是回答生产系统更实际的问题：为了让 prefix cache 达到目标 hit rate，我到底需要多少显存/缓存容量？它用 Mattson stack algorithm 在线估计不同 cache capacity 下的命中率，尤其适合会反复携带增长中的 conversation/tool history 的 Agent workload。

Gap & Method

“把所有历史 KV 都留着”太贵，“拍脑袋给容量”又会让 hit rate 掉下去。KVSET 对每个 KV page 计算 LRU stack distance，一次性推断多个候选容量下是否命中，避免逐容量模拟。

Bottleneck / Acceleration Mechanism

瓶颈主要在 prefix cache capacity 与重复 prefill；它减少的是因 cache miss 造成的冗余 prefill，不是 decode FLOPs。理论价值是把容量规划从离线试错变成在线 working-set estimation。

Experiment

作者用生产 LLM workload traces 验证估计与真实 cache deployment 测量接近。摘要未给 TTFT/TPOT 的具体提升，因此不能把它说成直接 latency speedup 方法；它更像 serving observability/capacity-planning primitive。

Contribution / Limitation / Migration

【New System/Engineering】在线 KV working-set analyzer；【New Metric/Protocol】目标 hit-rate 对应最小容量。局限是 LRU working-set 模型不等于所有实际 eviction/prefix-sharing policy；估计准不代表 end-to-end SLO 自动最优。迁移：给 coding agent trace 做 session-aware KV working-set profiling，比较普通 chat 与 tool-heavy agent 的 cache reuse 曲线。Worth Deep Reading: YES，优先看算法复杂度和 production trace 实验。

Tier AAgent × RL ScienceBuddy: Recursive-in-Recursive Self-Improvement for Interactive Scientific Agents

Paper / Source

人话版：ScienceBuddy 把科研 Agent 的“自我改进”拆成两层递归：内层先固定模型、改 harness/工具/工作流；外层再在改好的 harness 中用交互产生的任务、反馈、execution evidence 做模型学习。它的价值不在单个 benchmark 分数，而在把 human-in-the-loop 的真实使用痕迹变成持续 curriculum。

Core Insight

Agent capability = model × harness。只训模型会被旧 harness 限制，只改 harness 又无法把经验沉淀进 policy；两者交替更新会产生新的训练分布。

Agent Architecture / State

Research request → harness/tools → execution evidence → feedback → task/rubric construction → inner harness evolution → outer model RL → new interaction。长期 state 包含任务、rubric、执行轨迹与 harness 版本；因此 provenance 很重要，否则很难判断能力提升来自 model 还是 scaffold。

Experiment / Evidence

作者展示 researcher interaction、harness refinement、model learning 的 case studies，覆盖四类 scientific tasks。公开页面没有提供足够统一的量化表格供本日报逐项比较，因此这里不编造“提升 X%”。

Contribution / Limitation / Migration

【New Mechanism】recursive-in-recursive self-improvement；【New System】科研 workspace；【New Empirical Finding】真实交互可转为持续学习材料。限制：case-study 证据较强但因果拆分困难；harness 与 model 同时演化后 attribution 变复杂。Minimum Experiment：固定 model，A/B 测 harness evolution；再固定 harness 做 RL；最后交替训练，比较三者在相同任务流上的增益与 regression。Worth Deep Reading: YES。

Tier AAgent Memory / Efficiency PRO-LONG: Programmatic Memory Enables Long-Horizon Reasoning

Paper / Source

人话版：PRO-LONG 的想法很朴素但很“Agent 原生”：不要把所有历史都塞进上下文，也不要用有损摘要把细节扔掉；把完整 interaction log 结构化保存，再让擅长写代码的 Agent 用程序化搜索去取需要的信息。它在 ARC-AGI-3 上平均提升 18.0 个百分点，最高 76.1% pass@1，同时用少 4.2–5.8× 的 token。

Method / Long-Horizon

Environment history → lossless structured log → programmatic query/search → relevant evidence → active context → action。它把“长上下文”问题改写成“外部存储 + 主动检索程序”问题。长期优势是历史不因 summary 被不可逆压缩。

Results

全 ARC-AGI-3 public game set：相对 base coding agent 平均 +18.0pp；可达到 76.1% pass@1；token 使用降低 4.2–5.8×；Fable 5 上报告 97.4% best@2，总成本 $1,750。这里最值得关注的是 capability 与 token efficiency 同时改善，而不是典型“更长 context 换更高分”。

Failure Propagation

风险从“摘要错误”转成“检索程序漏掉关键历史”。日志本身 lossless，但 query 仍可能错；因此下一步应测 retrieval recall、错误 action 后的 recovery，以及不同 history size 下 latency。

Contribution / Migration

【New Mechanism】programmatic memory；【New Empirical Finding】少 4.2–5.8× token 仍更强。可迁移到 coding/web agent：用完整 trajectory store + executable retrieval 替代 rolling summary，并和 KV prefix reuse 联动。Worth Deep Reading: YES。

Tier AInference Acceleration MetaKV: Adaptive KV Cache Compression for Constrained LLM Inference

Paper / Source

人话版：MetaKV 不押注一种 KV compression，而是针对每个 prompt 和用户给定的 latency/memory budget，在 KVQuant、H2O、RocketKV 等候选配置中动态选最合适的。它把 KV 压缩从“全局固定超参”变成 per-request decision。

Bottleneck / Mechanism

不同 prompt 对 KV 丢失的敏感度不同；固定压缩率要么浪费显存，要么损伤正确率。MetaKV 用轻量预测器估计每个配置的 end-to-end latency、peak memory 和 correct probability，再做受约束选择。

Results

10 种配置、3 类代表性压缩方法 + FP16，覆盖数学、科学、常识、阅读理解四类数据。Constrained Success Rate 平均提升约 0.07，最高 +0.135，相对最佳静态配置更好。

System Metrics

摘要明确优化 latency + peak memory + correctness，但未给统一 TTFT/TPOT/tokens/s 表，因此不虚构。它主要影响 KV memory 与由此产生的 attention/memory traffic；是否在大 batch 下保持收益需看正文。

Contribution / Limitation / Migration

【New System】prompt-adaptive KV policy；【New Evaluation】CSR 联合约束指标。局限是 predictor 本身有误差，候选空间受预定义 compressor 限制。Agent workload 可把“任务阶段/工具类型/历史长度”加入 selector feature，动态选择 KV policy。Worth Deep Reading: YES。

Tier BInference Acceleration SwiftCache: Efficient LLM Serving for Multi-turn Conversations with Heterogeneous KV Cache Sharing

Paper / Source

人话版：SwiftCache 让同一服务器上 KV 需求低的模型把闲置 GPU memory 借给高需求模型，通过 NVLink 共享 prefix cache，避免慢速 PCIe/CPU/SSD reload；同时只在本地保留当前 active layer 的 KV，换取更长 context。

Main Finding：真实 workload 上 P99 TTFT 最多下降 69%，最大 context length 最多扩展 3.98×，且对 colocated model 干扰很小。它主要加速 multi-turn prefill/cache reload，不是直接让 decode arithmetic 更快。

Contribution：【New System】heterogeneous cross-model KV sharing。Limitation：依赖同机 GPU/NVLink 拓扑，跨节点收益不能直接外推。Connection：Agent 的多轮工具历史正是 prefix cache 快速膨胀的 workload。Potential Use：Serving baseline / Agent inference system。

Tier BInference Acceleration / Long Context CompressKV: Semantic-Retrieval-Guided KV-Cache Compression

Paper / Source

人话版：CompressKV 发现并非所有 attention head 都适合决定“哪些 token 的 KV 可以删”。它先识别 Semantic Retrieval Heads，再用这些 head 选择应保留 token，并按层的 eviction error 分配预算。

Main Finding：LongBench QA 只保留 3% KV 仍保持超过 97% full-cache performance；Needle-in-a-Haystack 用 0.7% KV storage 达到 90% accuracy。这个结果说明极端 KV sparsity 并非必然毁掉 retrieval，但摘要没有给真实 end-to-end latency，所以不能把 memory reduction 等同于 wall-clock speedup。

Contribution：【New Mechanism】semantic-head-guided eviction + layer-wise budget。Limitation：GQA 模型与 long-context retrieval 场景为主。Potential Use：Agent memory/KV co-design baseline。

Tier BRL / Reasoning Metacognition as Reward: Reinforcing LLM Reasoning via Knowledge and Regulation Signals

Paper / Source

人话版：MaR 不只奖励“答案对不对”，还奖励模型是否识别了需要的知识、是否对推理过程进行了合理规划与调节。它把 metacognitive knowledge、metacognitive regulation 与 final correctness 组成 trajectory-level reward，试图解决纯 RLVR 过程监督太稀的问题。

Main Finding：22 个 benchmark 上，报告相对 base model 最高 +7.7%，相对 vanilla DAPO 最高 +11.0%；Qwen3.5-9B 的整体表现可超过 GPT-OSS-120B，且有 OOD generalization。分析还显示移除 knowledge/regulation reward 的损失可大于移除 correctness reward，提示 process reward 不是装饰。

Limitation：显式 metacognitive scaffold 可能让 reward 与格式遵循纠缠，且 trajectory-level reward 仍未完全解决 token-level causal credit。Potential Use：与 VIMPO 结合——MaR 提供 richer reward，VIMPO 负责更细 credit。

12. Idea Mining

Idea 1 — ToolVIM: Policy-Implied Credit for Long-Horizon Agent RL

Inspiration：VIMPO + OpenForgeRL。Gap：Agent RL 常用 episode success，把 credit 平铺到整条 tool trajectory。Hypothesis：把 token-level implied value 聚合到 tool-span，可识别真正推进任务的调用并减少错误工具强化。

Proposed Method：每次 tool call 作为 macro-action；在 call 前后计算 policy/reference log-ratio-derived value，terminal environment reward 作边界；对 memory-write、tool-use、final-answer 分头统计 advantage。

MVE：7B/8B open model + WebArena/OSWorld 小子集；GRPO vs VIMPO-token vs ToolVIM；100–500 tasks 即可先看趋势。Metrics：success、steps-to-success、tool error rate、recovery rate、reward variance、KL、wall-clock/sample efficiency。
Novelty：★★★★★　Feasibility：★★★★☆　Compute Cost：★★★☆☆　Risk：log-ratio 与 causal tool contribution 不完全一致。Collision Risk：中。Best Venue：ICLR/NeurIPS。

Idea 2 — Cache-as-Memory: Joint Agent Memory × KV Working-Set Control

Inspiration：KVSET + PRO-LONG + MetaKV。Gap：Agent memory 系统决定“语义上保存什么”，serving 系统决定“KV 物理上留什么”，两层目前彼此无知。Hypothesis：把 memory retrieval probability/provenance 作为 KV retention signal，可同时提高 prefix hit rate 与任务成功率。

MVE：收集 coding-agent 1000 条 multi-turn trace；对比 LRU、KVSET-only、semantic-memory-aware retention；测 TTFT、cache hit、HBM、task success、retrieval recall。
Novelty：★★★★★　Feasibility：★★★★☆　Compute：★★★☆☆　Risk：需要 serving trace instrumentation。Collision Risk：中低。Best Venue：MLSys/OSDI/NeurIPS Systems。

Idea 3 — Self-History Distillation for Streaming Video Agents

Inspiration：JoyAI-Video-Edit 的 Long-Horizon Autoregressive Distillation。Gap：Streaming Video VLM 的 compressed memory/cache 会积累表征 drift。Hypothesis：训练时让学生在“自己的压缩历史”上继续推理，可显著降低长视频后半段 accuracy decay。

MVE：选 Video-MME/LongVideoBench，固定 frame budget；baseline 为 rolling summary / token pruning / cache compression；加入 self-history distillation；按视频时间分桶报告 accuracy、visual tokens、latency、GPU memory。
Novelty：★★★★☆　Feasibility：★★★★☆　Compute：★★★★☆　Risk：teacher cost 高。Collision Risk：中。Best Venue：CVPR/ICCV/NeurIPS。

13. Collision Detection

⚠️ Collision Warning: YES

Tool-level credit assignment：VIMPO 已占据“critic-free finer credit”核心机制，因此新工作不能只把 VIMPO 换到 Agent benchmark。差异化必须落在 macro-action/tool/memory causal credit、异步 environment feedback 或 cross-agent credit。

Agent memory efficiency：PRO-LONG 已证明“完整日志 + programmatic retrieval”可以同时提升能力并减少 token；新 memory 论文若只是“把摘要换成数据库”很容易撞。更好的 gap 是 memory semantics 与 KV/serving physical cache 联合优化。

Streaming video：JoyAI-Video-Edit 已把 long-horizon autoregressive distillation 用于生成/编辑，因此迁移到 Video Understanding 时应强调 compressed perceptual state drift，而不是泛泛声称“long-horizon distillation”。
