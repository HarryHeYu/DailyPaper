SCARL: Sequence Confidence-Aligned Reinforcement Learning

Authors：Zhenghong Ke; Jingbo Zhou; Hua Wu · Affiliation：Baidu Frontier Research Department; Nanjing University · Venue / Status：arXiv preprint

Full HTML  ·  PDF  ·  Code：Official GitHub  ·  Project：未核实 / 未公布

人话版：这篇论文到底干了什么？

在 GRPO/DAPO 一类可验证奖励强化学习中，模型采样出八条解题路径后，通常只根据“做对/做错”计算优势值。问题是：一条模型几乎不会写出的正确推理，和一条已经十分熟练的正确推理，可能得到相同的正向更新；自信满满的错误也没有被额外纠正。SCARL 读取采样时已有的整条序列 log-probability，将其转成组内相对置信度，并按“置信度与正确性不一致的程度”重新分配同类样本的优势预算。它不改变奖励正负、不增加模型前向次数。Qwen3-4B 上平均 Pass@32 从 DAPO 的 67.1% 提升至 69.5%，同时缓解熵塌缩。价值在于把探索维持与 credit allocation 放到一个可插拔的 advantage 算子里。

Background & Research Gap

传统 RLVR 用规则验证器给最终答案 0/1，再以组内奖励中心化得到 advantage。设一道题八次 rollout 有两条成功，其中一条是模型偶然找到的全新解法，另一条是高度重复的熟悉套路。标准组相对 advantage 无法区别它们；若持续强化熟悉套路，单次正确率可能增加，但 Pass@32 对“还能解决多少不同题目”的覆盖率未必增长。已有 DAPO 调 clipping、GSPO 调 sequence ratio、SAPO 调连续 gate，却未直接回答“同样正奖励应优先更新哪条序列”。

Core Insight 与观察依据

作者把 sequence-confidence misalignment 视为缺失的监督维度：正确但低置信的成功应更强地巩固，错误但高置信的失败应更强地惩罚；正确且高置信、错误且低置信则少更新。重要的是保持正负 advantage 两类各自的总预算不变，否则容易让正奖励吞掉负奖励。Figure 1 的示意不是另造一个 reward，而是给已有 reward 的更新强度分配份额。

Method Deep Dive：从输入到优化

Input → 同题 G 条采样 → 规则 verifier → 基础 advantage → 序列置信度 → alignment gap → 类内归一化 → 替换 advantage → 原始 PPO/GRPO surrogate。

第一步，使用采样策略 π_old 对每条序列求 c_i = Σ_t log π_old(y_it | x,y_i,<t)；这是整条回答的 log-likelihood，非平均 token 置信度。第二步，以组内标准差和温度 τ 标准化 c，再 Softmax 得到相对份额 p_i。第三步，以 advantage 符号构造目标 t_i∈{0,1}，计算 gap_i = |t_i − p_i|。第四步，在正、负 advantage 各自的样本集合内除以该类 gap 均值，得到 w_i；最终 A'_it = w_i A_it。w_i > 0，不会把正确解当成错误惩罚，也不会改变正负类的平均更新质量。若某类只有一条样本，则回退 w=1；类内置信度一致时退化成原估计器。τ=5 是论文统一使用的主要超参数。

关键公式 / Objective 与 Toy Example

J_SCARL(θ) = J_base(θ; {w_i · A_it})，其中基础 J_base 可以是 GRPO、DAPO、GSPO 或 SAPO。p_i = softmax_i(c_i / (τ(std(c)+δ)))；w_i = gap_i / mean_{j:sign(A_j)=sign(A_i)} gap_j。这里 τ 调节组内置信度差异的锐度，正负类分别归一化是最重要的结构性约束。举例：八条答案里两条正确，若其中一条 p 很低，则其正类 gap 接近 1，获得更高权重；另一条已十分确定的正确答案 gap 较小，减少重复强化。若某条错误却具有异常高的 p，它在负类获得较大的惩罚份额。这个 toy 解释是公式推论，不是作者另行报告的实验数字。

Baseline Comparison 与 Experiment Setup

Research Question 1：在严格相同训练预算下是否比强 baseline 更好？ 主比较 Qwen3-4B-Base，训练 DAPO-Math-17K，verl 实现，150 steps、group size 8、batch size 512、learning rate 1e-6。基础算法含 GRPO、DAPO、GSPO、SAPO、Dr.GRPO；置信度方法含 EAS、SEED-GRPO、UCAS。最重要的同基线对照是 DAPO 67.1%，而非拿未训练模型 54.5% 当唯一参照。每五步评估，五个 benchmark 为 AMC23、AIME24、AIME25、Minerva Math、MATH-500，单题采样 32 次，报告 Avg@32 与 bootstrap Pass@32。

Research Question 2：机制能否跨算法与模型？ Qwen3-1.7B、Qwen3-4B、DeepSeek-R1-Distill-Qwen-1.5B、Hunyuan-1.8B，分别配四种基础估计器，固定 τ=5，构成 16 个组合。Research Question 3：提升是否来自 alignment，而不是单纯 confidence weighting？ 在 Qwen3-1.7B+GSPO 上消融类内归一化、目标符号、序列长度归一化与 τ。

Results：数字 → baseline → 差异 → 意义

Table 1：DAPO 67.1 → DAPO+SCARL 69.5，提升 +2.4pp Pass@32；AMC23 90.4→95.3，AIME25 45.0→50.1，MATH-500 95.5→95.6；Minerva 却从 DAPO 58.4 降到 57.4，且不及 Dr.GRPO 的 59.6，说明不是每个 benchmark 都赢。Figure 2：150 steps 中 30 个记录点，SCARL 在其中 20 个点的两个主要指标居首；末十点优势仍在，减少“挑单点 checkpoint”的担忧。

Table 2：16 个跨模型/估计器组合中 14/16 有正增益，两个例外都出现在 SAPO，均为 −0.2pp。Table 3：去掉类内归一化，GSPO 的 56.4 反而跌至 47.0；去掉 alignment 目标只到 56.6，远低于完整 57.1；改用每 token 平均置信度得到 55.3。Figure 3：DAPO 最后十步策略 entropy 从 0.50 提至 1.02，confidence-correctness 的 Cohen's d 从 0.65 提至 1.06。最弱现象是：对 GRPO 的硬 clipping，熵下降虽被减缓，仍无法完全阻止塌缩。

Ablation、Claim vs Evidence

Authors Claim： confidence 与结果的对齐能保护探索，并且兼容现有组相对 RL 算法。Experiments Actually Show： 数学验证器环境内，跨四骨干和四估计器多数成立，类内归一化确实关键；Pass@32 与 Avg@32 同时上升。What Is Not Yet Proven： 未验证多轮工具轨迹、稀疏且有噪声的 Agent reward、跨任务长期在线学习；不同长度回答的 log-likelihood 总和也可能把“简短”当作“高置信”，作者的消融仅说明当前数学协议下总和更好，不能证明不存在长度偏置。主要指标按各方法最佳 checkpoint 汇总，仍需要固定终点与多 seed 的进一步审计。

Contribution / Limitation / Research Value

New Objective / Mechanism： 将 advantage 更新预算分配给置信度—结果不匹配的轨迹，具有符号与类质量守恒性质。New Empirical Finding： 仅加 entropy bonus 未必有效，confidence calibration 与 coverage 可以同时改善。Baseline Potential： 极强，已有代码、额外计算 O(G)；适合先作为 RLVR baseline。System Value： 训练计算近乎零额外开销，但并不减少 rollout 本身。Benchmark Value： 建议加入 Pass@k、entropy、confidence separation 三联指标。Attack / Evaluation Value： 可以构造高置信错误和低置信正确的分层评测，识别 reward hacking。

Migration：完整研究迁移链

Original Problem 数学 RLVR 序列更新失配 → Transferable Mechanism 按置信度与可验证 outcome 的偏差分配同类 credit → New Research Question Agent 工具调用链中，哪些局部步骤值得额外巩固而不是简单奖励整条成功轨迹？ → Method Modification 将序列置信度替换为 tool-action / subtrajectory 条件置信度，对成功与失败片段分组守恒，并用过程 verifier 抑制伪高置信 → Minimum Experiment 在 100–300 条可重放工具任务上比较 outcome-only GRPO、过程 reward、SCARL 与 step-SCARL → Model Qwen3-4B → Dataset 可复现 GUI/工具环境小样本 → Baseline DAPO、SCARL、PivotRL 风格 pivot → Metric task success、Pass@8、tool cost、entropy、reward-hack rate → Expected Contribution 可解释的长轨迹 credit 算子 → Risk 局部置信度不可校准、不同轨迹长度不可比、过程 verifier 错误放大。

五句话总结

SCARL 不是新 reward，而是 advantage 的重新分账。类内归一化比直觉上的置信度加权更重要。+2.4pp 的价值来自强对照和跨设置稳定性，不是绝对涨幅惊人。它尚未证明能解决 Agent long-horizon credit。最值得读的是 Section 2.2–2.6、Table 3 和 Figure 3。

进一步审计：探索、reward hacking 与训练稳定性

SCARL 的 reward 是规则验证器给出的最终正确性，属于稀疏、非 learned reward；并没有人类逐步标注或 process reward。它降低的主要风险是训练内部的探索收缩，而不是外部 reward hacking：如果模型发现错误的答案格式也能骗过 verifier，SCARL 仍会强化这些被错误标成正类的轨迹，甚至更优先强化“低置信却被判成功”的投机行为。迁移 Agent 前必须引入 verifier 可信度或多证据一致性检查。论文报告的 wall-clock 额外开销可以忽略，因为所需 log-prob 已用于重要性采样；但 rollout 生成仍占主要成本，SCARL 不是减少 token 训练预算的方法。

更强的最小复现实验： 不只复现 Table 1 的 best checkpoint，还在 step 150 固定终点报告均值、标准差和不同 seed；对比总 log-prob 与长度归一化置信度在不同输出长度桶上的误差；把规则 verifier 的标签随机翻转 1%、5%、10%，观察 class-wise normalization 是否放大错误反馈。另一个关键审计是固定 Avg@32 后比较 Pass@32，排除只靠总体准确率变化解释 coverage 改善。若这些结果仍稳定，才能更有信心将其视为通用 credit operator。

SkillMem: Compact External Skill Memory for Latent Multi-Agent Reasoning

Authors：Yuxuan Zhu; Mohammad Mohammadi Amiri; Pin-Yu Chen; Keerthiram Murugesan · Affiliation：Rensselaer Polytechnic Institute; IBM Research · Venue / Status：arXiv preprint

Full HTML  ·  PDF  ·  Code：未核实 / 未公布  ·  Project：未核实 / 未公布

人话版：这篇论文到底干了什么？

多 Agent 系统常从成功/失败轨迹中提炼“技能”，但每次把长技能文本塞进 Planner、Critic、Refiner 的提示词会重复消耗 token；改存 KV 前缀或每技能 LoRA 又会导致库膨胀。SkillMem 把每个技能编译成仅 8×256 的外部潜向量，由一个跨技能共享、按角色条件化的 cross-attention reader 在中间层读入。训练时不是复述技能文字，而是匹配“加入技能文本后模型对同一答案 token 的概率变化”。Qwen3-4B 的 GPQA-Diamond 从 LatentMAS 17.97% 升至 35.63%，GSM8K 从 72.40% 升至 89.90%。每技能增量存储 9.6KB，但需另算 34.5MB 共享 reader；其速度优势主要相对文本多 Agent，而非无技能 LatentMAS。

Background & Research Gap（含具体例子）

假设四个 Agent 依次计划、检查、修正、回答数学题；上一批任务总结出“先核对边界条件再推导”的可复用经验。文本技能要在每个角色提示里重新 prefill，且角色对同一句规则的用途不同。KV Skill 可以缓存文本但随层数与技能数线性涨；LoRA Skill 则要维护每技能参数。LatentMAS 本来通过连续状态传递避免中间自然语言通信，文本技能把这部分成本又带回来了。更难的是：直接从成功轨迹抽取 latent direction 并不能稳定起效，附录报告 GPQA-D 上甚至出现重复输出崩溃。

Core Insight：从语义重构转为行为效果蒸馏

作者没有要求 8 个向量“讲清楚”一段技能，而是要求它们对模型输出分布产生与文本技能相似的影响。对同一 teacher response，在有文本技能、无技能、有 latent memory 三个条件下 teacher forcing，求每 token 的 log-probability 差。这样技能被定义为对行为的可重复干预，不是可读描述。不同角色共享技能向量，但通过角色编码和隐藏状态决定如何读，避免重复存储。

Method Deep Dive：Input → Output

成功/失败同题轨迹 → 比较得到程序性技能文本 → 生成技能索引 → 编译成 8 个 latent vectors → 角色条件 reader 注入 → Agent 间继续用 latent KV 通信 → 最终答案。

  1. Skill discovery： 对每个 benchmark 预留 20 个 calibration 例子，多次运行 Planner/Critic/Refiner/Judger，取同题成功和失败轨迹对；比较角色间差异提炼通用操作规则，删除实例特有数值与实体，再去重。2. Retrieval： 使用冻结 backbone 文本编码任务与技能，余弦相似度选一个技能；这一步仅按任务查询检索，尚不支持运行中多技能组合。3. Memory： 每技能 Z_s∈R^(8×256)，从外部库加载；不改变原 backbone。4. Role-conditioned reader： 角色 system instruction 生成固定角色向量，与当前 hidden state 拼接成 Query，技能 memory 投影为 Key/Value；cross-attention 读出后再经 sigmoid gate 残差加到隐藏状态。5. Distillation： 文本技能生成固定 teacher 回答，分别计算有技能、无技能、memory 条件的 token log-prob；只更新 Z_s 与共享 reader。

Objective 与 Toy Example

令 Δ_text = log p(y_t | skill_text) − log p(y_t | no_skill)，Δ_mem 同理；用 w_t = sigmoid(β·stopgrad(Δ_text)) 衡量文本技能是否真正支持该 token。目标含三项：L_token 提升技能支持 token 的概率，L_shift 用 SmoothL1 匹配 Δ_mem 与 Δ_text，L_safe 在低支持位置维持无技能行为。总损失为三项加权和，backbone 冻结。例子：技能“检验中间变量单位”对正确单位 token 提升 log-prob，但对标点符号几乎不影响；latent memory 应复制前者而不干扰后者。这解释了为何比直接训练技能文本重建更有针对性。

Baseline Comparison 与 Experiment Setup

更细的 Agent 状态、信息流与失败传播

人话版：这篇论文到底干了什么？

视觉大模型在看图或视频时，往往把几千个视觉 token 送进语言解码器。常见剪枝要么在 LLM 内部等 attention 出来才删，已经付过前几层计算；要么在进入 LLM 前靠图像 CLS attention 选 token，压得很狠时会留下背景、丢掉关键物体。ST-Pruner 在进入 LLM 前对视觉 patch 特征做低秩 SVD，找承载主要结构的 patch，再用一个反直觉的信号——取负的 patch–text cosine similarity——估计查询相关性，两者相乘选 Top-K。LLaVA-NeXT 在 2880→320 token 时，POPE F1 从 86.5 到 86.1，端到端 727.9ms→224.0ms，3.2×；Video-LLaVA 在 2048→136 token 下保留 95.4% 的平均性能。但 3.2× 是图像 LLaVA-NeXT 的 wall-clock，不是视频模型的实测速度。

Background & Research Gap

例如八帧视频里，一个人拿起杯子的动作只占很小区域；均匀 token 采样会保留大量静止墙面，CLS 注意力可能优先高对比背景，而 LLM 中后层确实更懂“谁拿起杯子”，但等中后层才剪，prefill 成本已经发生。FastV、SparseVLM 等 in-LLM pruning 在早期层仍处理长序列；VisionZip、DivPrune 等 pre-LLM 方法能更早省算力，却可能错过 query relevance。作者分析 Figure 1–2：CLS 极端预算下背景偏置明显，负局部 CLIP 相似度与中后层 query-aware token 选择重叠逐渐增加，K=32 时达到随机期望的 4.1×。这只是经验相关，尚非因果证明。

Core Insight 与 Method Deep Dive

Input 图像/视频帧 + query → 冻结 ViT 特征 Z → 随机低秩 SVD 得结构分数 → 冻结视觉-文本编码器算负相似度 → 两分数归一化相乘 → 每组 Top-K → 保持原位置顺序 → 完整 LLM 推理。

第一步取 ViT 的 pre-projector patch 特征 Z∈R^(N×d)。对 Z 做 rank-R 近似 SVD，得到每个 patch 在主成分上的参与程度 s̄_i = Σ_{k=1}^R sqrt(σ_k)·U_ik²，再 min-max 到 [0,1]。平方消除奇异向量符号歧义，sqrt 奇异值减弱头部成分过强支配。第二步，借助与 ViT 配对的冻结 CLIP text encoder 得 query 向量 q，视觉 patch 投影 v_i，计算 ρ_i = cosine(v_i,q)，却使用 r_i = normalize(−ρ_i)；作者认为全局 CLIP 对齐目标使局部 patch 正相似度不能直接代表 decoder 真正需要的 patch。第三步 g_i = s_i × r_i，按 g 选 K 个；乘法意味着任一信号很低的 token 被抑制，无额外可训练参数。最后按原顺序重排 surviving tokens，送入解码器，所有层都受益。

关键公式 / Complexity / Toy Example

Z≈U_R Σ_R V_Rᵀ，g_i = normalize(Σ sqrt(σ_k) U_ik²) × normalize(−cos(v_i,q))，S=TopK(g,K)。谱分支复杂度约 O(NdR)，文本分支额外一次冻结 text encoder 前向；并非零成本。若视频中有“杯子、人物、墙面”，结构分数保留人物/杯子等连贯区域，负相似度分支可能优先与后层选择一致的细节，两者交集避免只按视觉显著性保留整片背景。这个例子解释机制，不能把负相似度视作普适的语义定律；Qwen2.5-VL 缺配对 text encoder 时只能运行 spectral-only。

更细的效率核算与可复现边界

为什么 2880→320 token 理论 FLOPs 降到约 13%，端到端却只快 3.2×？一方面 ViT 视觉编码仍要运行，另一方面谱 SVD、CLIP 文本编码、排序和数据移动需要时间；GPU kernel 在短序列时也可能由访存和 launch overhead 主导。因此理论 attention complexity 下降不等于真实 wall-clock 等比例下降。对视频尤其如此：逐帧做谱分解会重复付费，若不做跨帧特征缓存，短视频可能看不到图像实验中的加速幅度。是否 training-free 的答案是是：剪枝器无需额外训练；是否需要重新训练 backbone 的答案是否；但需要能访问匹配的视觉 patch 特征和文本编码器。

失败场景设计： 低对比小物体、短暂手势、快速镜头切换、文本与视觉强语义相似但需要计数的区域，均可能让乘法融合误删关键 token。可设计“保留原图→剪枝→反事实恢复被删 patch”的对照，测每个被删 token 对答案的真实影响。若 query 在流视频后半段才到达，之前依据旧 query 剪掉的 token 不一定可恢复；必须保存原始帧或可回溯特征。这个系统问题正是 ST-Pruner 与 streaming video memory 的研究边界。

人话版：这篇论文到底干了什么？

合作式 MARL 的难点不是只训练多个策略，而是给团队设计中间奖励：只有终局成功太稀疏，手写 shaping 又容易鼓励错误行为。GARDEN 用一个 LLM 驱动的 reward 设计器先阅读环境 API，再通过可执行探针探索状态变量和事件，产生可运行的奖励代码，最后用真实训练反馈迭代。它并非把“奖励是什么”问一次 LLM 就结束，而是让设计器积累环境证据。作者在不同团队规模与地图布局上比较手工 reward 和自动设计器，报告四个 held-out 场景相对原生 reward 全部改善。值得注意：它节省人类 reward 工程，却不一定省训练或 LLM 调用成本。

Background & Gap / Core Insight

Turbo4DGen: Ultra-Fast Acceleration for 4D Generation

Authors：Yuanbin Man; Ying Huang; Zhile Ren; Miao Yin · Affiliation：机构见原文 · Venue / Status：arXiv v2 · 作者 Comments: ICML 2026

人话版：这篇论文到底干了什么？

4D 生成要在时间和多视角上保持同一物体一致，SV4D 的 Spatial–Camera–Motion（SCM）attention chain 计算量很高。Turbo4DGen 不只删 token，而是同时从三个尺度减少冗余：相邻去噪步复用 block attention 输出；用空间 cross-attention 识别物体相关 token，指导 camera/motion 分支剪枝，并从 cache 补回被剪位置；当跨步相似度足够高时，直接绕过中间 SCM chains。论文报告平均 9.7× wall-clock 加速，在 ObjaverseDy 的多个质量指标上优于 SV4D。它是 4D 新视角视频生成而非通用 text-to-video；并且实验包含微调，不能称为纯 training-free。

Background / Core Insight

直接把图像扩散模型的 DeepCache 移到 4D，可能缓存错误视角/运动信息；对 camera/motion attention 独立 Top-K 会破坏时空一致性。作者观察 SCM 各 block 的相邻 denoising step 输出相似，且越接近后期相似度越高。另一个观察是 spatial attention map 已经定位物体语义区域，可以为后续 camera/motion 的 token 保留提供跨 block 共享依据。于是把 cache、语义剪枝、动态 chain bypass 组合成一条可解释的加速流水线。

Method / Key Formula

输入单目视频 → SV4D 的多视角时空 latent → rolling attention cache → spatial attention Top-K 选择 → camera/motion 稀疏计算并用 cache refill → 计算 ASR 相似度 → 超阈值时跳过中间 SCM chains → 输出 4D 生成视频。 I_c = TopK(mean_view(Q_spatial))，I_m = TopK(mean_frame(Q_spatial))；ASR = Σ cos(cache_i^j, current_i^j)，超过阈值 α 时执行 chain bypass。默认 top-K 比例 0.2、α=0.9、20 denoising steps、576×576、5 frames×8 views。缓存不是简单“丢弃旧状态”：它负责在剪枝后填充缺失的 attention 输出，维持形状和一致性。

Experiment Setup / Results

RQ1：真实加速有多大？ ObjaverseDy 上比较 SV4D、DeepCache、AT-EDM 适配版，作者报告平均 9.7×；SV4D 与 DeepCache 在 30 frames×8 views 出现 OOM。RQ2：质量是否保持？ Table 1：SV4D→Turbo4DGen 的 LPIPS 0.122→0.113、PSNR 18.47→20.27、SSIM 0.884→0.891、FVD-F 754.23→626.36；这不是“仅维持”，而是在该测试集上有所改善。RQ3：三个机制分别做什么？ 论文消融指出 token pruning 主要保内存，cache 与 bypass 主要降延迟；激进 pruning 会损害 PSNR 和运动连续性。训练数据包含超过 11,000 个过滤的 4D objects；Consistent4D 做 zero-shot 测试，部分指标略逊于最优方法。

人话版：这篇论文到底干了什么？

科学编程 Agent 常在执行到具体错误时才需要某段历史经验，而只在任务开始时检索 memory 会错过时机。MUSE 将历史轨迹拆成全局经验 L0、方法级 L1 和实现细节 L2：开始时注入通用与任务匹配的知识，执行过程中按当前工具输出检索实现经验，再由 LLM gate 判断是否应注入“需要检查什么”的审查建议。它在 PDEAgent-Bench、KernelBenchX、KernelGenBench-MS 和 SWE-bench Science 上优于十种记忆基线。关键不是记忆越多越好，而是 何时、以什么粒度让记忆进入当前上下文。

Background / Core Method

例如 Agent 已经选择了正确的 PDE 求解方法，但在写 CUDA kernel 时出现了边界条件错误；任务初始阶段检索到的“选择数值方法”建议帮不上忙，只有运行到 kernel 输出异常时才应引入具体排查经验。MUSE 先从成功/失败尝试提取三层记忆，再建立 GlobalMemBank；运行时对最新交互做检索，gate 可拒绝无关候选，选中后生成针对当前操作的 review note，避免机械粘贴整段历史。Input → Global/L1 init → Tool execution → L2 retrieval → gate review → context update → continue。其方法属于 memory selection 和 timing，不是 RL 权重更新。

Experiment / Main Finding

四个 benchmark 的提取/测试数量分别是 PDE 194/451、KBX 53/122、KGB 63/140、SWE Science 35/84；统一使用 ZCode + GLM-5.3-flash。Table 3：PDE Pass 由最强 EvoScientist 87.8% 提升到 MUSE 92.2%；KBX Correct 从 ACE 66.4%→79.5%，Accel 从 36.9%→44.3%；SWE Science Pass 35.7%→40.5%。Table 4：PDE 仅 L0 82.7、L0+L1 89.4、全量 92.2，说明层级分工有实际作用。Table 6：去掉 gate，KBX correctness 从 79.5 降到 66.4，说明“拒绝错误经验”与“检索到经验”同样重要。

Contribution / Limitation / Connection / Potential Use

New Mechanism： 分层 memory 与选择性 runtime 注入。Limitation： 单一 agent/模型与科学代码场景，LLM gate 成本和误判会累积；历史经验可信度没有被严格因果验证。长任务中错误 L2 建议可能进入后续 context，形成 stale memory。与 SkillMem 的差别是 MUSE 侧重检索时机和文字审查，SkillMem 侧重技能的潜变量表示。值得将 MUSE 的 gate 作为 memory-credit 研究基线，再加入 leave-one-memory-out 和过期记忆污染实验，指标包括 task success、gate precision、latency、token cost、negative transfer。

研究连接补充

MUSE 与 SkillMem 可以组合，但不能把两者混成一个“更大的记忆库”：前者解决何时注入，后者解决技能怎样表示。若要研究 memory attribution，优先在 MUSE 的 gate 触发位置做有/无注入的配对重放，估计每条经验的真实贡献，并测试 gate 对错误记忆的拒绝率。

人话版：这篇论文到底干了什么？

如果模型做的是概率化分类决策，删除某类训练样本后，模型应该像 retain-only 重训模型那样输出概率。但这种“正确遗忘目标”还依赖推理时给出的候选标签和标签文字：候选从“转账失败”换成不透明代码，或者删除部分备选项，重训 oracle 本身的分布也会变。DecisionUnlearn-Bench 不是提出新 loss，而是系统检验决策 schema 改变时，遗忘是否仍逼近对应的 retraining oracle。它对 MLLM/Agent 的启发是：评估遗忘不应只固定一套 QA prompt 或候选集合。

Background / Core Method

作者把 schema 定义为 (候选集合 C, 标签文本渲染 ℓ)，对同一个输入比较 Full、Unlearned、Retain-only Oracle 的概率分布，并分 example、association、class 三种删除粒度。除 forget rows，还测未见过的同类泛化样本；指标包含 oracle distance、相对进展、retained utility、校准与 relearning。不同 schema 的 oracle 必须重新定义，而不是用固定参考答案衡量所有输出。

Experiments / Main Finding

New Benchmark / Empirical Finding： schema-specific oracle、删除粒度与重学的联合审计。Limitation： 研究的是监督分类决策接口，不等于从 foundation model 预训练中删除知识；类别选项变更也可能改变输出归一化几何。对视频/Agent unlearning 可迁移为“同一目标在不同候选、工具 schema、视觉证据下是否一致遗忘”，但当前研究优先级仍低于 RL/Agent/Video 的新机制。可用作 MLLMU-BENCH 的额外评估维度，不应把它当成新的 unlearning 优化算法。

Hierarchical Step Decomposition for Training-free Online Video Step Grounding

Authors：作者见论文首页 · Affiliation：机构见论文首页 · Venue / Status：arXiv preprint

Full HTML  ·  PDF  ·  Code：未核实 / 未公布  ·  Project：未核实 / 未公布

人话版：这篇论文到底干了什么？

在线视频步骤定位要在视频还没看完时识别“当前是哪一步”，固定长度窗口容易把完整动作切碎；一味细分步骤又会产生大量推理调用。HSD 先在线构建语义一致的 event segment，再根据当前步骤预测的不确定性，选择性地把父步骤拆成子步骤重新匹配。它不训练新的 VLM，而是在现有 InternVL、Qwen-VL 上组织推理流程。其价值是把时间分辨率和额外推理预算绑在一起：只有预测模糊时才细化，而不是对每段视频一视同仁地耗算力。

Background / Method

固定 10 秒窗口可能把“拿起杯子→倒水”分成不完整片段，使 LLM 难以判断步骤边界。HSD 的 Online Semantic Event Construction（OSEC）基于内容变化生成 event；Hierarchical Step Refinement（HSR）将不确定的父步骤分解为更细子步骤，聚合回父步骤预测。视频帧流 → 在线 event segmentation → 步骤打分 → entropy 触发 HSR → substep scoring → 父步骤聚合 → 时间区间输出。训练免费不等于推理免费：多轮细化会增加 VLM 调用。

Experiment / Main Finding

HT-Step、CrossTask、Ego4D Goal-Step 三个 benchmark，使用 Qwen2.5-VL-7B、Qwen3-VL-8B、InternVL2.5-8B。Table 2：Qwen2.5-VL-7B 的 HT-Step mAP@0.3 从固定窗口 18.10→仅 OSEC 23.65→OSEC+HSR 25.92；Ego4D R@1@0.3 从 8.08→17.48→19.51。Table 3：Entropy 触发 HT-Step 25.92，Always refinement 仅 23.58，Random 18.05；oracle 41.85 暗示“何时细化”仍是主要改进空间。与 BAGLM 同 backbone 对比，Qwen3-VL-8B 在 HT-Step mAP@0.3 为 16.70→26.45，但并未给完整 GPU wall-clock 加速对比。

Contribution / Limitation / Connection

New Mechanism： 在线事件级划分 + 不确定性驱动的分层细化。Limitation： entropy 不等于可纠正错误，遇到长时间缓慢动作或快速转场会误分段；高阶时间定位提升不代表更快。与 ST-Pruner 的连接是“先决定哪些时间段值得精看，再决定这些帧的哪些 token 值得保留”；最小实验比较固定帧/固定 token、HSD、ST-Pruner 和组合，在 HT-Step 上同时测 mAP、事件召回、token 数、实际 wall-clock、峰值显存。需要防止组合后重复计算导致净加速消失。

研究连接补充

HSD 训练免费但可能增加测试时 VLM 调用，因此应把它视作 adaptive test-time compute 而不是已证实的推理加速。若与 ST-Pruner 组合，必须同时量化 event 分段开销、token 减少和 HSR 额外调用，报告 wall-clock Pareto；否则 mAP 提高却延迟翻倍仍可能不适合实时 Agent。

边界条件： 语义事件切分依赖在线可见帧，不能使用未来帧做定位；若对比 offline 方法必须标注其信息优势。对实时系统还要报告每段事件结束后多久输出步骤预测，而不仅是最终时间段的 mAP。
