RL Highlights

① MagicBeanStalk 证明零优势问题不是靠扩大 78K 题库自动解决的：按当前策略与 rollout 长度校准训练题的有效性更重要。② BSR 在 SWE 任务中把同为失败的轨迹重新排序，同时通过 a_fail+a_pass<1 保留真实 verifier 的优先权。③ CLEAT 用 paired rollout 估计澄清的 residual query value，直接把信息价值映射为任务收益。④ CToM 用用户响应预测帮助策略在真实问询前自我修订。

研究判断：这四项分别在 data、reward、action-value 和 interaction-model 四个层面改善反馈信号。不能把它们都称为“更好的 GRPO”；最有价值的共同问题是如何在长程 Agent 中把稀疏 outcome 精确归因到可复用的子技能或记忆。

Agent / Multi-Agent Highlights

① ReTRAIL 将可恢复环境状态与不可回退的经验分离，能从相同状态比较多个分支。② EvoBelief 不直接相信一次反思，而将世界规则写成可证伪、可缩小适用范围的假设。③ SpireBench 发现“会记录 memory”并不等于“会用 memory 变强”，长期战略风险管理是现有 Agent 的显著短板。④ VEPA 用确定性验证器和证据门槛保护运行时安全规则的演化。

跨 Agent 重点：信息如何从失败轨迹中提取、如何验证、什么时候共享、共享后能否真的提高其他 Agent 的成功率。今日 Reward Hacking as a Transmissible Strategy 和 Provenance-Aware Belief Updating 也值得列入高优先 Watchlist，因为它们直接检验“错误知识如何沿共享计划传播”。

Video Acceleration Highlights

① CORAL-KV：视频生成 KV 压缩的内存—质量前沿；HY-WorldPlay 相对 QVG-4 存储 −48.4%，但不是整体生成提速 48.4%。② ForcingBooster：去噪 patch NFE −50.19%，端到端 11.15→8.56 秒（1.30×），VBench Total 82.08→81.55。③ Codec-guided compression：保护 token 的特征比较最多 −96.6%，但未报告真实 TTFT。④ GeoGR：LLM prefill 6.8×，完整 TTFT 2.4×，证明系统固定开销不可忽略。

MagicBeanStalk: Escaping the RLVR Zero Advantage Trap with Recursive Data Synthesis

人话版：这篇论文到底干了什么？

这篇论文指出，RLVR 训练并不缺“题目数量”，真正缺的是对当前策略与输出预算有梯度信号的题。一个题目如果采样八次全部答对或全部答错，组内优势几乎为零；把这种题继续堆入训练集无法带来有效更新。MagicBeanStalk 反而从全部失败的难题出发，提取它们需要的推理操作，先向下分解，再从子问题向上组合出结构相似但内容真正新颖的题，最后用当前策略筛出“有时成功、有时失败且能在预算内解完”的题。它把数据合成从题面改写变成了针对能力边界的课程构造。

Background / Gap

普通 RLVR 用可验证的最终答案给每条推理轨迹打 0/1 分，再以同一题的组内奖励差更新模型。常见做法是收集更多数学题、让强模型改写题目或对已有题过滤。问题在于题目难度不是固定属性：同一题在不同策略、16K/64K 的生成预算下，可能从“全错”变成“可解”。如果只保留当前混合成功率的题，虽然训练信号变密，却把暴露能力缺口的真正难题丢弃了。

具体例子：一道必须先发现不变量、再完成递推的竞赛题，当前模型八次都失败；让教师把数字换掉通常只是同一个模板。论文的目标是拆出“不变量识别”和“递推闭合”两个必要子能力，再组合成新题，同时让模型有概率真正完成。

Core Insight 与公式

给题目 p、策略 π、最大输出长度 L，采样 N 条轨迹；奖励 rᵢ∈{0,1}，组均值 r̄=(Σrᵢ)/N，优势 Âᵢ=rᵢ−r̄。若 r̄=0 或 1，所有优势为零；只有 0<r̄<1 的 Goldilocks 区间能直接提供组相对学习信号。论文进一步要求至少存在一条在 L 内正常结束的正确轨迹，避免“偶然被截断”造成虚假的难度分类。

这不是新优化器，而是“数据—策略—预算”三元组的联合数据选择标准。原始 78K 数学题在 gpt-oss-120b、32K、每题八次采样下约 88% 落在零优势区，只有 12.2% 进入 Goldilocks 区；改变模型会使 32.3% 的题重新分类。

Method Deep Dive：Input → Output

输入是带标准答案的难题与可访问的强教师模型。① 通过多个教师的拒绝采样获得可核验的解题轨迹；未通过验证的根题直接丢弃。② 自顶向下把根题拆成最多三个更易的子题，继续递归；对候选拆解做“有效性测试”：把子题与解法作为例子给学生后，原题成功率是否真的提高。只有有效的分解保留。③ 对叶子要求生成更难且不同的变体，而非同义改写；再沿原有树形依赖自底向上重组父题。④ 逐级验证正确性、限制弱学生成功率，最后用目标策略进行八次 rollout，筛选混合成败并至少一条预算内完成的根题。输出是可直接用于 GRPO 的新题集合。

关键设置：分支 K≤3、深度 D=3、分解失败最多重试三次；叶子成功率阈值 0.8、父节点 0.625。金融任务另外从新文档抽取证据段，再把合成题重新锚定到文档实体，防止题目虽“可验证”却脱离资料。这里的关键不是教师答案，而是验证“子问题确实教会了原问题所需能力”。

Toy Example

假设种子题要求先从运动轨迹估计速度，再推导制动距离。直接合成可能只是更换车速数字；MBS 会拆成“估计速度”“带摩擦系数计算停止距离”，对两项分别创造不同场景，再合成为新任务。最终如果当前模型八次尝试中三次成功、五次失败，并且至少一条在长度限制内完整完成，它才被纳入训练。此例用于解释机制，不是论文报告的实际数据。

Experiments / Research Questions

RQ1：大数据集是否一定带来更强 RLVR？作者比较完整 78K 来源、Goldilocks 子集、Golden Goose、直接种子合成和 MBS。RQ2：新题是否保留困难种子的推理蓝图、而非只换皮？作者对 300 对数学题及 100 对金融题做评审，并统计合格后代与种子转化。RQ3：换策略与输出预算后还有效吗？同一合成集训练 gpt-oss-120b 与 DeepSeek v4 Flash，并测试 16K/24K/32K。RQ4：是否迁移到低资源金融问答？用 340 道专家题、17 份信贷协议生成约 14.2K Goldilocks 题。

训练细节：gpt-oss-120b 用 16×H100、LoRA rank 32、GRPO、学习率 4e-5、每步 32 prompts×16 responses；DeepSeek v4 Flash 用 80×H100 全参数 GRPO、8 responses、学习率 1e-6。数学测 AIME 2024/25、AMC、HMMT-F/N、Minerva、Olympiad、Omega-500 的 pass@1；金融测 SecQue 与 FinanceBench。可验证奖励主要来自答案等价判定，不是逐 token dense reward。

Ablation / Claim vs Evidence

去掉树状分解、改为直接合成时，合格种子转化率从 74.7% 降到 43.8%；对相同种子训练，MBS 69.2、直接合成 63.9、种子本身 65.3，说明“结构性新问题”比表面变体更有用。更严格的预算内完成过滤使筛选更保守，但能排除截断假象。

Authors Claim：可以从模型尚不会的题生成有效 RLVR 训练数据。Experiments Actually Show：在两个数学策略与一个金融设置中，模型平均分和难种子恢复均改善。Not Yet Proven：合成成本最优、其他推理域泛化、教师判定无偏、长期持续训练是否会引入重复/污染。作者也承认 API 教师版本变化影响复现，合成数据将待论文接收后发布。

Contribution / Limitation / Research Value

贡献分类：New Empirical Finding（零优势陷阱的规模与预算依赖）；New Mechanism（top-down decomposition + bottom-up composition）；New Evaluation Protocol（policy-budget-calibrated qualified yield）。它不是新 reward loss，也不是“无限数据即可解决 RL”的证据。局限包括合成验证昂贵、金融答案评审仍依赖模型判断、任务主要是可验证推理、未完整量化每增加一单位 GPU/教师调用的收益。

作者：Ziang Ye et al.　｜　版本：arXiv v1: 2026-10-09；10-12 新刊列表　｜　机构：参见原文（未逐项核实）　｜　状态：Preprint（未核实正式 venue）

人话版：这篇论文到底干了什么？

长任务的难点不只是“想错”，而是早期操作会把环境推进到死胡同。ReTRAIL 给 Agent 一个真正的环境级 rewind：保留已经完成的有效前缀，丢弃错误分支的环境变化，但不丢弃从错误分支学到的经验。它再用两个强化学习信号训练同一策略：从相同状态出发的多条 continuation 谁走得更好，以及回退后是否真的比被丢弃的分支取得更大进展。这样，失败探索不再只是日志，而成为能改善后续动作的经验。

Background / Gap

ReAct/Reflexion 可以在上下文里检讨失败，但无法撤销已经对文件、网页、棋盘或机器人状态造成的修改。Rollback 类方法虽能回退，却经常只是启发式地选择回退点和写反思，没有训练“何时回退”“反思是否有效”的统一学习信号。长程任务更严重：第 5 步的坏选择可能让第 40 步无解，最终成功率无法说明哪段历史有价值。

例如 Sokoban 推箱子时把关键箱子推入墙角，继续尝试会消耗 token 且无法修复；真正有效的系统应回到错误推箱前，同时记住“那个方向会封死通道”。

Core Insight 与状态

把状态拆为可回滚的环境 s、执行历史 h，以及跨分支保留的经验 E。回退前轨迹 τ₀:k = retained prefix τ₀:j ⊕ abandoned suffix β；从 β 提取反思 e 后，状态变为 (sⱼ,hⱼ,E⊕e)。这让环境时间后退，而知识时间前进。它与只把完整失败轨迹塞进 prompt 不同，经验是有选择的压缩与保留。

State/Action/Policy：状态包含任务描述、当前环境、工具反馈、经验库；动作包括环境操作、触发 rewind、选 checkpoint 和生成 reflection；同一个 πθ 同时承担执行与反思。Reward 是可验证任务完成、进度分数与分支进展差，既包含稀疏终局信号，也有相对密集的中间进展。

Method Deep Dive：Input → Output

① Agent 从初始任务执行工具动作，并记录可恢复 checkpoint。② 发现无效路径时选择早期状态 j；把历史分成有效前缀和废弃后缀。③ 在废弃后缀中提炼约束、错误原因与下一次应避开的动作，形成紧凑 reflection。④ 恢复环境 checkpoint，裁剪执行上下文，但将 reflection 合并入持久经验。⑤ 从相同状态重新展开多个 continuation，按 task-level progress 与 state-relative return 训练执行策略。⑥ 将“新分支比旧分支多推进多少”作为反思奖励，联合更新。输出是能主动回退且利用经验的策略。

这是一种有状态的探索，而不是简单 Best-of-N：多次尝试共享合法进度与错误知识，且 60 次模型调用预算同时计入执行和反思。Checkpoint 可用性是方法前提；不可逆现实世界动作需要替代恢复机制。

Objective / Credit Assignment

对从同一状态/历史出发的 continuation ξ，优势 A_cont = Norm_task(Sξ)+λ_state·Norm_same-state(Gξ)。第一项确保总体任务进展，第二项在可比较的起点内评价哪条续走更好；没有可比较分支时第二项归零。对 reflection m，核心奖励取恢复后进度与废弃分支进度之差 r_ref = v⁺−v⁻。联合目标 J=J_GRPO_exec+λ_ref·J_GRPO_ref。

自回归视频生成要不断保存旧帧的注意力 KV cache，视频越长显存越吃紧。常见压缩只利用同一层 KV 向量相似性做聚类和量化，早期的小误差却会在后续帧不断传播。CORAL-KV 观察到不同 Transformer 层的 KV 有强相关性：上一层已经重建的 KV 能预测下一层的大部分内容，因此只需要存储“预测残差”。它用块对角加低秩预测器代替昂贵的全连接预测，再做低比特残差编码，在两种视频生成架构上同时改善缓存体积与重建保真度。

Background / Gap

视频生成的 KV 缓存随帧数、分辨率和网络层数增长。BF16 保存全部历史最保真，却占用巨大存储；QVG-1/QVG-4/QVG-Pro 用层内聚类与残差量化压缩，容量较小，但误差在长期 autoregressive 生成里会跨时间积累。AQUA-KV 在语言模型中利用跨层预测，不过直接在视频模型里用 dense linear predictor，参数矩阵按 C² 增长，还会带来高额推理开销。

具体例子：一个场景中人物的脸在前后几十帧持续出现；每层、每帧都重新存高精度 KV 浪费空间，而早期某个错误压缩的身份特征还可能让后续脸部逐渐漂移。CORAL-KV 不做帧语义识别，而是利用相邻层表示的线性可预测性。

Core Insight / Method Deep Dive

输入是已填满的 KV cache block。① 第 0 层保留量化锚点；② 对第 ℓ 层，先用重建的上一层 K 预测当前 K，再加当前 K 的量化残差；③ 用当前重建 K 与上一层重建 V 联合预测当前 V，再加 V 残差；④ 逐层恢复供后续注意力使用。预测器 P(x)=Dx+A(Bx)，其中 D 是每个 attention head 内的块对角映射，AB 是跨 head 的 rank-r 低秩项。

拟合时交替优化块对角项与低秩项以减小 Frobenius 残差；压缩时只保存量化 residual、尺度、必要 metadata 和共享预测器。Reusable 模式离线校准并在多个视频共享预测器；video-adapted 模式固定低秩项但对每个视频块重拟合块对角项，保真更好、耗时更高。它压缩的是存储状态，而非直接删除帧或 token。

关键公式 / Toy Example

形式化写作 K̂ℓ=Pᴷℓ(K̂ℓ−1)+Q(Kℓ−Pᴷℓ(K̂ℓ−1))；V̂ℓ=Pⱽℓ([K̂ℓ,V̂ℓ−1])+Q(Vℓ−Pⱽℓ([K̂ℓ,V̂ℓ−1]))。Q 表示低比特残差量化。若第 5 层的一个 KV 通道能从第 4 层预测到 0.95，而真实值是 1.00，系统只需要保存约 0.05 的残差，而不重复存 1.00 的全部精度。此数值仅为理解机制的示例。

区别于普通 delta coding：它不是只做相邻帧差分，而是跨 Transformer 层预测；区别于 dense AQUA：block-DPLR 控制预测器自身的存储与计算成本。

Background / Insight

简单的“缺字段就提问”规则会造成无谓对话；完全不问又会误解用户意图。尤其当任务策略升级后，同样的问题可能已经不值得问，固定问答策略会过时。核心不是 information gain 本身，而是 answer 对当前 policy 的真实增量效用。

Method / RL Formulation

在 history h 与澄清目标 z 下，定义 gπ(h,z)=Qπ(h,z)−Vπ(h)：前者是先问 z 再执行的期望回报，后者是直接交给现有策略继续的回报，后者本身仍可以自行提问。训练时对同一个 h 进行配对 rollout 估计差分；控制器据此选择哪些缺口值得问，并将这些信息反馈到后续采样。任务策略用共享任务回报学习如何在用户回复后行动，控制器的监督也随策略更新。

State 是交互历史与已知约束；Action 是 pass 或 query(z)，之后是任务动作；Reward 是任务完成质量并考虑交互成本；Trajectory 是用户答复、工具操作和终局。这里的 credit assignment 用配对续走把“问这一句”的增量效果与普通策略的基础能力区分开，而不是按信息量给奖励。

RQV 与普通 information gain 的区别可以用一个反例理解：用户提供正确预算信息，弱策略却不会用这个预算过滤酒店，那么询问本身的信息量很高，但实际任务收益仍可能接近零；当策略学会预算约束后，同一句问题的价值才会上升。反过来，策略如果已能从上下文可靠推断日期，重复询问反而可能降低交互效用。

把同一三维场景的多个视角直接拼给 VLM，会同时产生两种浪费：多个视角反复看见同一物体；LLM 每一层又都对所有视觉 token 计算。GeoGR 先把跨视角视觉证据压成带空间覆盖约束的 3D voxel token，再按层分组让低相关视觉 token 暂时跳过部分 Transformer 层，必要时重新加入。它不是简单一次性删掉 token，而是把“保留空间信息”和“分配深度计算”分开处理。在两种 7B 3D VLM 上，报告 6.8×/6.1× 的 LLM prefill 加速，但完整 TTFT 只有 2.4×/2.3×。

Gap / Core Method

纯 token pruning 容易丢失小物体、遮挡视角的关键信息；纯 late-entry/early-exit 又忽略跨视角重复。GeoGR 的 GeoSemZip 把多视角对应的空间区域映射到 3D voxel，按语义显著性与几何覆盖选择 token，未选中的特征聚合成 context anchors；GroupRoute 根据 query 相关性将视觉 token 分组，选择进入与退出 LLM 计算的层区间，跳过时保留隐藏状态以便后续层恢复。

与静态剪枝不同，token 在一个 layer group 低相关，不意味着永远无用；保留重入机制更适合长程空间推理。方法需要 compression-aware post-training，并非 training-free。

Ablation / Limitation

应区分 LLM prefill 与整个 TTFT：token 层计算大幅下降，但 projector 处理变慢，其他固定开销使真实加速缩水。与 SeGPruner 相比，GeoGR 牺牲部分极限 prefill 速度以换取更高任务保留；DTC 的 projector 代价更高，TTFT 可能反而变差。只在特定 3D VLM 和室内场景任务上验证，不可直接宣称通用 Video VLM 都能达到 6×。

Systems Bottleneck / Layer Routing Audit

GeoGR 同时在两个层级动刀：projector 前后减少跨视角冗余，以及 Transformer 层内部动态跳过低相关 token。Table 3 的一个关键细节是 projector 处理时间从 53.3ms 增至 99.0ms，这个额外开销吞掉了一部分 LLM prefill 节省。因此只展示 6.8× prefill 不足以评价部署收益，必须同时报告完整 TTFT 605.0ms 对 1426.7ms。

与不可逆 pruning 相比，GroupRoute 让 token 在后续 anchor layers 重新参与计算，降低早期误判造成永久信息丢失的风险；但保留隐藏状态也有内存代价，且查询变化可能改变哪些 token 重要。需要在复杂空间问答里测试被跳过的小物体、计数、方位关系是否更容易出错。

3D voxel 对齐依赖多视角几何信息；如果迁移到普通网络视频，摄像机运动估计误差会影响空间聚合。一个更可行的低成本试验是先把 voxel 改成局部 temporal tracklet 或事件片段，保持层路由不变，检验时空抽象本身的贡献。

Ablation Design and Transfer Boundary

GeoGR 的空间聚合与层路由是两个不同来源的收益。复现时至少应分别关闭 GeoSemZip、GroupRoute，再关闭可恢复 group skipping，报告 accuracy、KV cache 和 TTFT；否则无法判断系统主要靠前端 token 减少还是靠深层路由加速。

此外，性能保留率 95.2% 与绝对准确率不是同一指标。若 dense 模型在某项任务本身准确率不高，95.2% retention 也不表示结果已经可靠；应额外看小物体定位、长距离空间关系和跨视角遮挡等困难切片。

Additional Practical Metric

未来实验还应记录 3D 输入视角数、voxel 数、有效 token 数和每层实际活跃 token 比例，检查模型是否仅在简单视角组合下高效；对复杂遮挡场景应把空间定位错误率单列，避免平均分掩盖失败。

许多自进化 Agent 只更新执行经验、工具技能或反思文本，却没有显式维护“环境如何运作”的可证伪知识。EvoBelief 把世界模型写成带证据的假设：意外结果触发提出新规则，后续观测与受控实验验证后才允许进入规划；反例会缩小规则适用范围或将其退役。模型权重冻结，更新的是有来源、有适用范围的环境知识。相比直接累积未经验证的经验，这更接近科学实验的知识管理。

Method / Evidence

Input 是环境交互轨迹与当前规则库。Agent 先检测预测失败或决策相关的未知条件，生成可测试的假设；通过后续交互验证，保存支持证据、适用条件和受影响决策；遇到反例时修订或废弃。它把 memory provenance、confidence 与更新机制联结起来，防止“同一句经验被反复转述”后被误认为真理。

作者在 ALFWorld、MiniGrid、DiscoveryWorld 等四类设置测试静态动力学、隐藏漂移与科学发现。在不提供 actor-side transition memory 的 ALFWorld 条件下，分别相对 matched Frozen World Model 提高 23.9%（Claude Haiku 4.5）与 31.3%（GPT-5.4）；DiscoveryWorld Reactor Lab 完成 Normal 83.3%、Challenge 58.3%，所比较基线为 0%。这些是特定协议下的结果，不能外推到所有任务。

Contribution / Limits / Connection

New Mechanism：证伪驱动的规则生命周期；New Evaluation：环境漂移下的知识修复。它的优势不是“写更多 memory”，而是要求规则与独立证据和作用范围绑定。局限：实验反馈是否真正独立、错误规则会否影响后续采样、开放世界中验证成本是否可承受，都需要进一步测。

潜在应用：为跨 Agent 的共享 memory 建立证据链和冲突消解；与 ReTRAIL 的 branch advancement 配合，可给反思生成的规则赋予可证伪的后续检验。优先阅读假设验证机制与 ALFWorld/DiscoveryWorld 对照；在自己的 Agent 系统中先做“未经验证规则不可全局传播”的最小实验。

Minimum Experiment / Evidence Boundary

最小可迁移实验：让 Agent 在两个相似但物理规则不同的环境中执行任务，先写入一条错误的通用规则，再引入一条可验证反例；比较直接追加新 memory、覆盖旧 memory 与带 provenance 的 rule revision。除成功率外，记录错误规则存活轮次、误用次数与验证成本。

这类系统的难点不是能否生成“假设”，而是验证是否真正独立，以及规则何时被允许影响行动。论文的实验显示特定环境收益，但不等于开放世界中的事实验证已解决。

Agent 的安全规则通常有两难：纯 LLM guardrail 能适应新场景，却可能同一输入做出不一致判断；静态形式化规则可审计且确定，却无法跟上部署中新出现的攻击。VEPA 用可执行的 typed event 规则表达 allow/deny 决策，再让 LLM 根据反馈提出小规模 policy patch，由确定性验证器检查结构与冲突，最后还要过证据充分性门槛才真正激活。它把“持续学习”和“可验证执行”分层。

Method / Experiment

输入是 Agent 即将执行的动作、当前形式化策略与部署反馈。LLM 负责提出修补候选，deterministic verifier 负责检查一致性与冲突，evidence-aware authority 层决定何时启用。这样即使模型错误建议了某条安全规则，也不一定能直接改变运行时决策。

作者在 ASSEBench-Safety、ASSEBench-Security、ATBench 上比较自适应与形式化 guardrail，并测试混合流、受污染反馈和更长时间跨度。公开摘要明确报告优于基线，但当前收录未摘录足够可复核的逐表数字，因此不把“显著提升”虚构为具体百分点。

Contribution / Limitations / Connection

New System / Engineering：受验证器约束的策略演化；New Mechanism：把证据门槛放在正式激活之前。局限：符号事件抽象可能漏掉自然语言的语义攻击，反馈污染可能绕过证据来源验证，冲突检查不等于对安全性质的完备证明。

潜在应用：跨 Agent 的工具调用授权、memory 写入权限和不可逆操作门控。可与 EvoBelief 形成“事实证据更新”和“安全政策更新”两个互不混淆的生命周期；最低成本实验是记录每次 policy patch 的来源、冲突检查与回滚路径。

Threat Model / Minimum Experiment

VEPA 的重要边界是验证器只对已形式化的规则与 typed event 做确定性检查。如果自然语言工具输出被错误解析为安全事件，形式化系统仍可能对错误的事件做出“正确”决策。因此应同时测 event extraction 错误率、policy conflict rate 和真实攻击成功率。

最小实验是在支持回放的 coding sandbox 中逐步引入新的工具风险，记录每个 patch 的提案来源、验证结果、激活证据与回滚路径；与直接 LLM guardrail、静态规则库比较误拦截与漏拦截。

Long-Horizon Guardrail Failure Propagation

在 100 次以上的 Agent 工具调用里，一条错误的新 policy patch 可能长期影响后续动作；因此应记录规则从提出、验证、激活到退役的整个生命周期。若两个规则在语法上不冲突，但在真实任务中共同导致错误拒绝，单纯的结构检查无法发现。

这提示需要把静态形式验证与部署时的任务级回放结合：每次规则升级前在保留的 benign/attack 轨迹上重跑，检查是否出现新的安全回归或 utility regression。

多轮协作 Agent 经常在没弄清用户要求前就直接行动，或者收到反馈后仍重复原来的假设。CToM 在回复用户之前先预测用户可能怎样回应，再利用这个预测在内部修改当前答复；训练时把真实用户后续回复当作预测目标，和 GRPO 的任务奖励一起优化。它不是简单生成多个候选答案，而是把“用户会怎么反应”作为可训练的辅助模型能力。

Method / Results

输入为当前对话历史与初步答案。先生成草稿，再预测用户反馈，再自我修订后输出；训练目标包含用户下一轮回复的负对数似然与 group-relative policy optimization。它可以理解为一种内生的交互世界模型：Agent 不必每次都真的问用户，就先模拟一次潜在反应。

在协作数学推理任务中，相比 naive GRPO 的最终准确率 74.1%，CToM 达到 79.6%。在同等奖励设置下，加入用户响应预测监督使 coding 所需用户回复减少 8%、writing 减少 17%，同时提升任务表现。实验还发现预测更准确与修订收益更大相关，但相关不等于严格因果。

Contribution / Limitation / Connection

New Objective：用户反应预测辅助监督；New Mechanism：预测—修订的内循环。局限：模型可能只学到数据中的典型用户风格，不能准确预测特殊偏好；过度“代替用户思考”可能减少必要的澄清。

与 CLEAT 的差异很清楚：CLEAT 用 paired rollout 学什么时候应当真的问，CToM 学不问时如何模拟可能反馈。两者可组合成成本感知的协作策略：只有预测不确定或预测后的修订不足时，才触发真实用户询问。最小实验可以测同等任务成功率下真实交互次数与错误假设率。

Mechanism vs Causality / Minimum Experiment

CToM 里的预测用户反馈是一个训练时的辅助任务，不能保证推理时生成的预测一定等于真实用户意图。预测准确率与最终任务提升相关，也可能由共同的底层模型能力驱动。需要做固定策略下的预测替换、随机反馈、真实用户回复三个对照，区分“预测本身有用”与“额外训练数据使模型更强”。

一个实际可用的指标是每完成一个任务平均需要多少次真实用户往返，而不是只看单轮准确率。将它与 CLEAT 的真实询问价值控制器结合，是值得验证但尚未被论文证明的交叉想法。

这篇论文的“遗忘”不是删除基础模型的参数知识，而是修复 Agent 外部长期记忆被投毒后的功能影响。DREAM 借鉴弱再激活可能导致记忆衰减的思想，先通过扰动诱导隐式 reactivation，诊断异常的激活与拓扑模式，再选择性抑制可疑记忆并强化良性记忆。目标是避免每次查询都依赖重型外部审计模块，尽可能用训练自由的记忆修复减轻污染。

Method / Experiment

Input 是包含良性与潜在恶意条目的 Agent memory。① 对记忆执行扰动式激活，观察哪些关联在微小变化下不稳定；② 汇总多维激活信号，定位可疑结构；③ 动态调整记忆影响权重，弱化有害条目并保留正常检索。输出不是“模型忘掉事实”的证明，而是指定攻击条件下的攻击成功率与任务效用变化。

论文针对 AgentPoison 类攻击，在 EHRAgent 的 eICU/MIMIC-III 与 ReAct 的 StrategyQA 设置中评价，模型包含 GPT-5.4-mini 与 Claude-Haiku-4.5，指标包括攻击成功率 ASR-r/ASR-a/ASR-t 与 benign ACC。本文已访问正文和 Table 1 说明，但这里不转录未完整核验的逐项数值；不能将“训练自由”理解为无任何运行开销。

Contribution / Limitation / Connection

New Mechanism：按记忆再激活脆弱性做选择性修复；New Evaluation：同时考虑攻击抑制与正常准确率。与参数级 unlearning 的 forgetting/retain trade-off 类似，但删除对象与威胁模型不同。主要风险是 benign memory 被误删、投毒内容通过语义改写绕过异常诊断、长期多轮交互中被重新写入。

潜在应用：Agent memory poisoning defense；与 EvoBelief 的 provenance verification 结合，在写入前验证证据、写入后用异常检测修复。值得后续读全文，但今天不因题目出现“forgetting”而自动抬高 Tier。

Deletion Closure / Minimum Experiment

针对 Agent memory 的“忘记成功”至少应有三层评价：恶意记忆是否不再被检索、即使被间接引用是否仍影响决策、在后续重新学习与跨 Agent 传播后是否会恢复。单次攻击成功率下降不足以证明 deletion closure；良性 ACC 也要同时监测，防止把所有记忆都抑制导致虚假安全。

最小实验可以固定同一批被投毒的记忆条目，比较静态过滤、DREAM 式动态修复和带来源验证的规则更新，并记录检索次数、正常任务准确率与每轮额外延迟。

Collision Detection — YES

⚠️ Collision Warning 1 — Zero-advantage learning: MagicBeanStalk ↔ BSR ↔ AdaC-GRPO

已解决什么：MagicBeanStalk 从数据生成恢复混合成功题；BSR 给同结果轨迹补局部排序奖励；AdaC-GRPO 用在线难度调度。

重合在哪里：共同目标是从稀疏/全同奖励恢复学习信号，但操作层分别是 data、reward、curriculum。

剩余 Gap：剩余 Gap：Agent 交互环境里三者成本—收益与 reward hacking 的系统比较。

如何差异化：差异化：固定模型、rollout、验证器和总算力，做 3×3 因子消融；不把简单组合包装为新算法。

是否继续：值得做系统评测，不宜仅拼接三者投稿。

⚠️ Collision Warning 2 — Video efficiency: Codec-guided ↔ GeoGR ↔ ForcingBooster

已解决什么：Codec 方法降低压缩决策的特征比较；GeoGR 减少 3D VLM token 与层计算；ForcingBooster 分配视频生成去噪次数。

重合在哪里：共同点是预算自适应，但三者优化的系统瓶颈不同；不可直接把 96.6% 比较减少等同 TTFT。

剩余 Gap：剩余 Gap：query-conditioned 视频事件预算与跨压缩器的真实 wall-clock 评价。

如何差异化：差异化：在同一 Video QA 系统统一评估 encoder、compressor、LLM prefill、KV memory、TTFT。

是否继续：值得继续，前提是拿出端到端收益。

⚠️ Collision Warning 3 — Agent experience: ReTRAIL ↔ EvoBelief ↔ VEPA ↔ Provenance-Aware Belief Updating

已解决什么：ReTRAIL 学回退后经验价值；EvoBelief 验证世界规则；VEPA 验证安全策略补丁；LQET 处理证据重复。

重合在哪里：共享经验的形成、验证、更新与传播已被多条路线分别覆盖。

剩余 Gap：剩余 Gap：跨 Agent 交接中具体 memory item 对最终任务收益的可重复归因。

如何差异化：差异化：相同 checkpoint 的 memory ablation + 来源 DAG + 延迟成功指标。

是否继续：有研究潜力，但必须正面比较四种机制。
