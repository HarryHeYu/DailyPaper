Hy-Memory-30B-A3B: Attributed Reinforcement Learning for Long-Term Memory Writing

Authors：Tianxiang Fei; Jiazheng Kang; Mao Zheng; Xingyan He; Xiang Yu
Affiliation：Tencent Hunyuan
First arXiv version：2026-10-15 · Status：arXiv 预印本；未核实正式会议录用

人话版：这篇论文到底干了什么？

长期记忆系统的关键不只是“把历史存下来”，而是每次新对话到来时，写入器要决定哪些事实值得保存、旧事实如何更新、哪些话不该记。普通大模型充当写入器往往既贵又不稳定；只按最终问答对错训练，又无法知道究竟哪一次写入出了问题。Hy-Memory 把每段对话写入当作一次改变外部数据库的动作：先让小模型学会真实 Memory Harness 的操作协议，再以局部事实召回、跨段证据归因、过度存储惩罚联合构造奖励，用 chunk-level GRPO 更新写入策略。它在四个记忆系统配置的抽样评估中达到 55.49% 宏平均，略高于对照 Opus 5 的 54.62%。最有价值的不是这 0.87 个百分点，而是“外部记忆写入—未来证据—局部信用分配”的可训练接口。

Background & Research Gap

旧方案通常把长对话按固定长度总结，或让通用 LLM 遵循框架专属 prompt 产生增删改操作。它们有两个根本问题：其一，写入质量由未来检索和回答才能验证；其二，最终回答错误不能定位是写漏、写错、过时信息未替换、检索失败还是 reader 误判。举例：用户先说项目依赖 v1.2，几天后改为 v1.4。只记新版本会损失时间线；只记旧版本会污染当前查询；全部复制则会增加检索噪声。真正的优化对象是随时间演化的外部 memory bank，而不是单条摘要的文本相似度。

Core Insight 与 observation

作者把一次写入的后果拆成可观察的局部事实与跨时间证据。局部 probe 测试精确姓名、版本、否定、更新、应当不存的闲聊；跨 chunk 问题测试多个事实能否被组合恢复。奖励只通过“已写 memory → 固定 retriever/answerer → 固定 judge”计算，不把答案泄漏给写入器。作者明确承认这种归因是 evidence-based，而非严格反事实因果贡献；这一点恰好暴露了下一步研究缺口。

Method Deep Dive

Input → 按 session 切 chunk → OPD 学协议 → RL rollout 写独立 bank → 检索/回答/裁判 → chunk 奖励 → GRPO 更新 → 胜出 bank 传到下一窗口。

第一步，按时间顺序把每个 session 切成约十轮的 chunk；最多五个 chunk 组成窗口，跨窗口沿用之前策略真正写出的 bank。第二步，Memory On-Policy Distillation 在学生访问过的状态上，让冻结教师给出 top-50 分布，最小化近似 reverse-KL；这一步主要修复格式错误、操作名错误和多阶段协议失效。第三步，从同一 parent bank 拷贝八份沙箱，各 rollout 独立执行完整窗口的写入；不能让不同候选共享状态，否则会污染信用分配。第四步，冻结 answer model 和 judge：检索器读取候选 bank，answer model 作答，judge 依据带权 rubric 评估证据恢复。第五步，针对每个 chunk 而非整个窗口，比较八条 rollout 的奖励，形成独立 advantage；同一 chunk 若触发多次 LLM 调用，它们共享一次 advantage，不能重复投票。第六步，按窗口总分挑选最终 bank 传给下一窗口，模拟部署时必须面对自己的历史错误。

关键公式 / Objective

作者的总分可以写成 s[t] = w_prm·PRM[t] + w_orm·ORM[t] − w_pen·Penalty[t]（原文还含未来 PRM 折扣项，但本实验 γ=0）。权重分别为 1、2、0.3。PRM 是当前 chunk 正向事实 probe 与“不要存”陷阱的平均得分；ORM 按 gold fact 来源将跨 chunk 问答得分分摊回证据 chunk；Penalty 由 bank token 增长率构造。然后 A[i,t]=(s[i,t]−mean_t)/(std_t+ε)，按同一位置的八个候选写入比较。与传统轨迹级 GRPO 的差别是：成功答案不会无差别奖励所有历史写入，且不让多次工具调用扭曲统计权重。训练效率中已核实八条 rollout、两阶段训练、OPD step 375 初始化；完整 GPU 小时和 token 总消耗不应猜测。

Toy Example

设三个 chunk 依次记录“模型 A 使用版本 1.2”“项目切换到版本 1.4”“用户问现在使用哪个版本”。写入策略 X 只保留 1.2，策略 Y 保留 1.4 且标记旧版本已过期，策略 Z 全量存储无关聊天。局部 probe 让 X 因更新失败失分，让 Z 因 trap 与 bank 增长失分；跨 chunk 问答把 Y 的正确答案部分归因于第二段写入。这个玩具例子说明为什么最终答对/答错一个 bit 不能替代逐段信用，但并不证明严格因果性。

Baseline Comparison / strongest baseline

比较 Hy3-A3B 原始写入器、DeepSeek V4.1 Flash、Claude Opus 5，以及跨 Mem0、MemOS、Hy-Memory、未见过的 EverMemOS 框架。按论文汇总，Opus 5 是最强的总体对照：54.62% vs 方法 55.49%；DeepSeek V4.1 Flash 为 53.64%，Hy3-A3B 为 47.66%。不能把 0.01–0.02 的单框架优势解释为显著性胜利。

Experiment Setup 与 Research Questions

训练采用 Mem0、MemOS 和 Hy-Memory 的 Chat/Working/Coding 五种 harness 配置；评估包含未参加训练的 EverMemOS。实验用固定的 20% benchmark subsamples，并对多类长期记忆能力汇总。RQ1：训练过的写入策略是否优于强通用模型？RQ2：跨 harness 的技能能否泛化到未见协议？RQ3：分解奖励是否能让局部写入获得比最终 QA 更细的信号？其中 RQ3 的严格消融尚未充分完成，不能将机制设计等同于因果验证。

Results：强结果、弱结果与 trade-off

作者报告四框架宏平均 55.49%，比 Opus 5 高 0.87 点、比原始 Hy3-A3B 高 7.83 点；在 held-out EverMemOS 上为 56.89，对照 Opus 5 的 54.04，差 2.85 点（论文按未四舍五入值写 +2.86）。然而在 MemOS 和 Hy-Memory 的差距仅 0.01–0.02 点，不能排除评估噪声。奖励数据工件包含 164,576 个正向 probe、8,599 个 trap、约 60.8k 个跨 chunk 问题；规模证明工程投入，并不自动证明 judge 无偏。代价是训练时多次独立 bank rollout、冻结 reader/judge 调用及奖励生成成本。

Ablation / Analysis

作者明确列出尚未完成的关键消融：chunk-GRPO vs window-GRPO、gold-fact attribution vs 广播、是否使用 trap、bank-growth penalty、OPD vs 普通 SFT、单框架 vs 混合框架。缺这些对照，不能断言每一组件分别带来多少点增益。作者还发现 silent failures：bank 未跨窗口持久化、教师 top-k 为空、chunk 映射缺失等均可能产生“看似正常”的日志，因此需要强制 invariant 检查。

Claim vs Evidence

Authors Claim：记忆写入可作为跨框架迁移的独立模型能力训练。Experiments Actually Show：固定抽样协议下，多框架平均和一个 OOD 框架表现较好。What Is Not Yet Proven：严格反事实 credit、跨多个 OOD 框架泛化、不同随机种子的显著性、真实线上持续删除/撤销以及独立 judge 的人类一致性。

Contribution / Limitation

【New Objective】chunk-level PRM+ORM+增长惩罚；【New Mechanism】按 gold-fact evidence 做写入归因、跨窗口保留策略写出的状态；【New System】真实 memory harness 的隔离 rollout 与故障 invariant；【New Empirical Finding】小规模活跃参数的专用 writer 在特定测试上可与强通用模型竞争。作者局限：非因果 attribution、评估抽样、缺 ablation 与 judge audit。额外局限：在长程共享记忆中，早期错误被多个 agent 继承后，当前窗口的局部奖励可能无法逆向追责。

Research Value / Migration

Baseline Potential：高，因为 Mem0/MemOS 与 chunk-level reward 接口具体；System Value：高，能复用到可回滚的多 agent 工作区；Benchmark Value：中高，trap 与 stale-state 分桶可扩展；Attack/Evaluation：高，可对照 memory poisoning、删除闭包；New Paper Potential：高但撞题严重，必须证明比 gold-fact attribution 更强的因果识别。

Original Problem（memory 写入） → Transferable Mechanism（按 chunk 可观测后果分配 reward） → New Research Question（删去某条写入是否真的改变未来任务？） → Method Modification（counterfactual bank fork + delayed replay） → Minimum Experiment（200 条多会话轨迹，每条构造保留/撤销分支） → Model（Qwen3.5-4B 或可复现的轻量 writer） → Dataset（LoCoMo/LongMemEval 可核对 split） → Baseline（Hy-Memory chunk credit、均匀 reward、只按 retrieval 次数打分） → Metric（future QA delta、credit precision、回滚成功率、额外 token） → Expected Contribution（可验证的因果 memory credit） → Risk（fork 成本、轨迹分布偏移、答案 judge 噪声）。

五句话总结

这不是普通记忆摘要模型，而是把写入动作变成 RL 决策。最重要的机制是局部 probe 与跨段证据归因。最可靠的数字是宏平均 55.49% 和 OOD EverMemOS 56.89。最薄弱的证据是缺少关键组件消融与反事实因果验证。下一步值得做的是带撤销与延迟结果的 memory credit benchmark。

RL Formulation / Reward / Training Efficiency

State=当前 chunk、外部 bank、harness 类型；Action=写入/更新/跳过的结构化操作；Policy=Hy3-30B-A3B writer；Reward=PRM+ORM−Penalty；Trajectory=一个窗口内多个 chunk；Advantage=chunk-group GRPO；Objective=提升可回答性与选择性；KL=OPD 阶段 reverse KL，RL 正则细节以论文配置为准；Credit=gold-fact 证据而非反事实。Reward hacking 主要来自“存下所有东西”和对 judge rubric 过拟合，trap 与增长惩罚缓解前者但未彻底解决后者。长期稳定性需测试 10/100/1000-step 分桶。

人话版：这篇论文到底干了什么？

一个长程搜索 Agent 可能最初目标明确，查了几页后却沿着错误线索越走越远；多 Agent 协作时，一个角色的偏差还会通过交接传播。本文不直接重训执行者，而是训练一个专门的“纠偏 Agent”。它有两条路径：fast path 判断当前是否值得介入，slow path 在需要时生成具体的纠偏动作；训练时把排序学习和 GRPO 结合。这样，纠偏的时机与内容都能优化，而不必每一步都用昂贵的强模型审查。论文在七个信息检索问答 benchmark 上验证单 Agent 场景，也研究跨执行器、跨任务和多 Agent 迁移。最重要的研究价值是把监督者本身变成具有成本约束的策略。

Background & Research Gap

旧的 Reflection、Planning、Verification 通常是固定时机或固定形式的额外调用。若 Agent 在第 3 步错误理解了目标，第 20 步才回顾，可能已经产生大量无效搜索；反过来，若每一步都请强模型审核，成本会高得不可接受。多 Agent 中“任务分解—子 Agent 返回—主 Agent 汇总”进一步产生信息漂移：局部角色觉得自己完成了子任务，却可能偏离全局目标。需要一个能判断什么时候介入、怎样介入、介入是否值回成本的训练框架。

Core Insight 与 observation

作者区分检测与干预：识别“当前轨迹是否存在 goal drift”通常比生成完整修复策略便宜。把二者耦合为一次强模型调用会让监控成本居高不下；拆成快慢路径后，可以通过排序信号学习 fast path 的相对优先级，再让 slow path 从真实干预后的任务结果中优化建议。这里最值得迁移的是“监督动作本身也有预算”，而非某个具体搜索 prompt。

Method Deep Dive

Input（目标、执行上下文、团队消息）→ Fast-path 风险评估 → 选择介入时机 → Slow-path 生成 steering → Executor 继续执行 → 任务反馈 → 联合训练。

第一步，执行者按原来的搜索/工具循环工作；监督者只读取必要的上下文，不取代主策略。第二步，fast path 对当前执行状态给出是否介入的判断，训练目标为 pairwise ranking：让更需要纠偏的状态相对排在前面。第三步，触发时 slow path 生成可注入执行循环的建议或修正，目标不是重做整条任务，而是尽量把轨迹拉回原始目标。第四步，使用 group-relative policy optimization，根据干预后的结果更新 slow path；作者给出的联合损失形式为 L = L_GRPO + L_rank。第五步，推理时调节 fast path 的阈值/频率，实现同一训练策略下不同预算的干预方案。多 Agent 扩展时，监督者必须理解角色之间的信息传递，而不只是单个模型的最后一句话。

关键公式 / Objective

L_total = L_GRPO + L_rank，其中 GRPO 部分用组内相对优势优化生成干预，ranking 部分学习快路径对介入价值的排序。与只做 RL 的 planner 不同，这个 objective 同时控制触发决策和干预内容。从系统视角，可写成期望效用 E[task score − λ·intervention cost] 作为迁移时的研究目标，但这条式子是本报告提出的扩展，不是声称论文原文使用了该形式。奖励来自干预后可验证任务表现，具有稀疏和归因不清的风险：成功可能本来就会发生，失败也可能来自执行器而非 steering。

Toy Example

原任务是“找到一篇论文的正式版本与对应代码”，执行者先找到同名博客，随后开始验证博客作者而忘了寻找代码。fast path 根据目标与最近动作不一致提高介入概率；slow path 发出“先核实 arXiv ID，再检索论文代码链接”的建议。成功完成任务可给干预正反馈，但为了排除“本来就会成功”的假象，需要对同一中间状态做 intervention / no-intervention 两个分支。

Baseline Comparison / strongest baseline

论文将 No Intervention、Planning、Verification、Steering 及各自 RL 变体纳入对照。Table 1 已核对的平均 F1：无干预 42.70；Planning 43.74、其 RL 版 45.91；Verification 41.57、其 RL 版 44.87；未训练 Steering 44.54。需要特别注意：45.91 是 Planning w/RL，而不是本文最终 Steering w/RL 的结果。本文最终完整行应以原文 Table 1 核对，不在此凭印象填造；因此这里的 strongest baseline 是已核实子集中的 Planning w/RL。

Experiment Setup 与 Research Questions

Executor 使用 Qwen2.5-7B-Instruct，Steering backbone 为 Qwen3-8B；训练任务来自 ASearcher-Base-35k，评估覆盖 2Wiki、Hotpot、Bamboogle、MuSiQue、Natural Questions、TriviaQA、PopQA 七类检索问答。RQ1：额外 steering 是否提高 F1，且 RL 是否有效？RQ2：能否泛化到不同任务和未见执行器？RQ3：能否在多 Agent 合作中抑制目标漂移？RQ4：改变干预频率时性能与成本怎样变化？论文报告干预次数和 executor turns，因此应把成功率与额外动作成本同时读。

Results：数字 / 现象 → baseline → 意义

No Intervention 平均 F1=42.70；未训练 Planning 43.74（+1.04），训练后 45.91（+3.21）；未训练 Verification 41.57（−1.13），训练后 44.87（+2.17）；未训练 Steering 44.54（+1.84）。这些数字证明“多加一次监督”并不天然有效，甚至可能更差。成本方面，No Intervention 平均 6.4 executor turns，Planning w/RL 为 8.8 turns；所以提升 F1 不意味着执行步骤更少。作者还展示跨任务、跨执行器与多 Agent 的定性或表格结果，但本轮未对其全部数值逐项核验，不将摘要措辞转换为百分比。

Ablation / Analysis

可明确识别的消融维度是 ranking fast path、GRPO slow path、无训练的 Planning/Verification/Steering 与干预频率。已核实 Table 1 中 Verification 从 41.57 到 44.87，说明 RL 可改变监督策略的有效性；但不能把这个差额当作 fast-path ranking 的独立贡献。下一步需要“仅训练快路径”“仅训练慢路径”“两者都训练”“随机同预算介入”四组消融，比较每次介入净收益。

Claim vs Evidence

Authors Claim：学习到的 steering 可改善单 Agent、多 Agent 的表现和效率，并具有跨执行器迁移性。Experiments Actually Show：在检索问答及作者选定执行器上，干预策略有可测的 F1/动作成本差异。What Is Not Yet Proven：在 1000-step 长程任务、恶意工具输出、共享记忆污染、真实异步多 Agent 环境中仍能稳定识别 drift；干预收益的反事实归因也未被完全隔离。

Contribution / Limitation

【New Mechanism】快路径判定与慢路径纠偏解耦；【New Objective】ranking+GRPO 联合训练；【New System】可控制介入频率的外部监督者；【New Empirical Finding】错误监督可能不如无监督，训练机制重要。局限：监督者也可能犯错；对执行器模型、任务领域和上下文可见性的依赖尚需分桶分析。额外局限：跨 Agent 共享记忆里的陈旧结论可能在干预之后再次被检索，造成复发性 drift。

Baseline Potential：高，适合做 Agent 长程稳健性对照；System Value：高，可插在现有 Agent Harness 外围；Benchmark Value：中高，可构造有明确漂移点的轨迹；Attack/Evaluation Value：高，可与受控扰动结合；New Paper Potential：中高，需要从“触发纠偏”推进到“可归因的干预效用”。

SoftCache: Adaptive Step Size Caching for Diffusion Transformers

Authors：Shimon Malnick; Nadav Orenstein; Ohad Fried; Shai Avidan
Affiliation：Tel Aviv University; Reichman University
First arXiv version：2026-10-15 · Status：arXiv 预印本；未核实正式会议录用

人话版：这篇论文到底干了什么？

扩散式视频生成要重复运行昂贵的 Transformer。现有缓存方法常用一个阈值判断“当前缓存是否还可用”，却依然按固定的时间步走完采样网格。SoftCache 注意到缓存信号距离失效阈值还有多远，本身就反映近似误差的安全余量：缓存很新时可以跨过多个时间节点，接近失效时缩小步长，并对剩余节点重新排布。它不训练新模型，而是改变“何时刷新、每次前进多远”。在 FLUX、HunyuanVideo 和 Wan2.1 上，作者报告多个实际 wall-clock 加速档的保真度优势。对视频研究最重要的是它把离散 cache hit/miss 升级成连续的计算预算控制。

Background & Research Gap

视频扩散模型每生成一个样本需要数十次网络前向，即使相邻时间步的中间特征很接近，也常被重复计算。TeaCache、SeaCache 等方法依据残差变化决定是否复用，DPCache 更偏固定刷新日程，TaylorSeer 用特征预测。它们解决了“这一刻要不要重算”，却没有充分利用“缓存还可安全复用多长时间”。例如在变化很平缓的时间段，缓存的 staleness 信号离阈值很远，逐节点推进相当于在已经知道安全的区域内慢慢走；但直接粗暴跳步又可能跨过高曲率阶段导致结构崩坏。

Core Insight 与 observation

作者观察到 headroom（阈值与当前 staleness 的距离） 与缓存误差具有可预测关系。它不只是二值决策的中间产物，还能指导自适应步长。把缓存策略和积分网格联动，就能在低误差区域跳得远、在不确定区域走得细；而且不要求对每个 backbone 单独训练一个控制器。真正的迁移价值是“已有的低成本误差代理可以同时控制刷新和计算粒度”。

Method Deep Dive

Input（扩散状态、50 步 Euler 网格、缓存 residual、廉价 staleness probe）→ 计算 headroom → 判断 fresh/cache → 选择连续跳跃步长 → 预测 residual 并更新状态 → 重排剩余网格 → 最终视频。

第一步，建立正常 sampler 的时间节点与最新一次 fresh network evaluation 的缓存。第二步，使用动态 probe 累积近似过时程度；超过阈值时真实刷新，否则复用。第三步，SoftCache 不再强制“复用也只走一个固定步长”，而是按 headroom 伸长缓存步：余量大则跨过多个节点，余量小则回到细步。第四步，因跳跃可能落在原始网格之间，需要对缓存 residual 做线性外推，避免把旧节点的向量场机械搬到新时间。第五步，将尚未走完的尾部时间节点重新等距排布，使未来刷新点能与当前状态一致。第六步，最终输出同帧数的视频，与原始未缓存采样结果比较 fidelity。

关键公式 / Objective

论文的更新式可概括为 x_(i+1)=x_i + Δ̄_i · O(s_i + r̂_i, e_i)：Δ̄_i 是由 headroom 决定的实际步长，r̂_i 是缓存残差估计，O 是采样更新算子，e_i 表示对应时间/误差上下文。与固定网格硬缓存的关键差异是 Δ̄_i 不必等于原计划 Δ_i。统一参数 β 在低于 4× 速度档取 1，更高速度取 0.5；它不是给每个视频模型单独调出来的特殊常数。这里的目标不是新训练 loss，而是无训练推理控制策略，不能将 wall-clock 加速误写成训练效率。

Toy Example

假设原始采样在时间 1.0、0.9、0.8、0.7、0.6 各执行一步。刚刷新后 probe 显示 headroom 很大，SoftCache 可以从 1.0 直接跨到约 0.7，并重新安排后续节点；当画面出现快速运动，probe 接近阈值，就恢复小步并触发 fresh 评估。这个示例只解释机制，具体跨越位置由论文公式决定，不是论文给出的实际轨迹。

Baseline Comparison / strongest baseline

作者与 TeaCache、TaylorSeer、SeaCache、DPCache 比较。FLUX 的中速档 SeaCache 与 DPCache 是较强保真基线；在视频上作者主要对照 SeaCache 和 DPCache。比较时按相近的实际 wall-clock speed band匹配，而不是强行让各方法刷新次数完全相同。若某方法速度更慢、画质更好，就不能算同预算胜出；本文设计特别强调这一点。

Experiment Setup 与 Research Questions

FLUX.1-dev：200 个 DrawBench 提示、1024×1024；HunyuanVideo：946 个 VBench 提示、65 帧、640×480；Wan2.1-T2V-1.3B：100 个 VBench 提示、81 帧、832×480。每个 backbone 使用 50 Euler steps，并尽可能共享 prompt、seed、硬件。RQ1：相同加速档下，谁更接近未缓存输出？RQ2：动态跳步与网格重排是否真的贡献质量？RQ3：跨图像和视频模型能否共用机制？RQ4：FLOPs、延迟与保真度是否一致变化？主要 fidelity 指标为 PSNR、SSIM、LPIPS、DreamSim；视频额外看 VBench。

Results：真实 wall-clock 与质量

HunyuanVideo 的约 3.5× 档，SoftCache PSNR=26.48，SeaCache=23.63、DPCache=23.70；LPIPS 分别约 0.141、0.203、0.182。约 5.4× 档，SoftCache PSNR=22.36，SeaCache=21.82、DPCache=20.34；LPIPS 约 0.246 vs 0.292/0.293。约 6× 档 SoftCache PSNR=22.27、LPIPS=0.267。FLUX DrawBench 的 3.79× 档 SoftCache PSNR=23.20、SSIM=0.847，而 SeaCache 在相近 3.25× 档为 22.41、0.830；这些速度并非完全相等，须读原表的匹配策略。论文摘要汇总实际加速约 3.5–6.9×，但不同 backbone/档位的 speedup 不能拼成一条统一的延迟曲线。

Table / Figure Reading

Table 1（FLUX）用四个 fidelity 指标对照多个 speed band，说明更高 speedup 不能靠牺牲大量结构细节换取。视频实验表要优先看 HunyuanVideo 的 PSNR 与 LPIPS：这比仅报告 VBench 总分更敏感于缓存造成的细微输出偏差。Figure 3 展示不同方法的采样节点：固定刷新、动态刷新但固定步长、以及 SoftCache 的动态步长差异。Figure 4 的图像细节标注提醒：PSNR/LPIPS 与人类感知仍不完全等价。

Ablation / Analysis

关键消融是去掉 adaptive jump、只保留缓存判定、改变 β、改变重排几何。作者的高速度档分析表明，去掉 jump 会损害保真度；因此收益不是单纯把阈值调得更激进。另一个风险是 probe 本身低估误差，导致跨越关键运动变化；应按 camera motion、object motion、scene cut 分桶观察失败，而不是只报平均 PSNR。

Claim vs Evidence

Authors Claim：training-free、跨 backbone 的动态缓存与步长控制能在高加速下保持更高 fidelity。Experiments Actually Show：特定三种 backbone、固定采样器、多个 wall-clock 档位下的 PSNR/SSIM/LPIPS/DreamSim 对照。What Is Not Yet Proven：所有 GPU、不同并发/分布式 serving、不同视频长度与运动强度下都同样有效；与真实用户偏好、峰值显存和吞吐的关系仍需补充。

Contribution / Limitation

【New Mechanism】把缓存 headroom 连续映射为采样步长；【New System】允许偏离固定网格并重排尾部节点；【New Empirical Finding】匹配 wall-clock 下，缓存可靠性与步长联动能改善 fidelity。局限：probe 的误差估计可能在复杂动态场景失效；主实验主要对照未缓存输出的相似性，而不是全面的人类偏好或下游视频理解；对显存与能耗的报告仍需逐项核对。

Research Value / Migration

Baseline Potential：高，尤其适合 Wan2.1 复现；System Value：高，不需要重新训练 backbone；Benchmark Value：高，可按相同延迟预算评价；Attack/Evaluation Value：中，可研究误差代理失准的对抗场景；New Paper Potential：高但存在机制撞题，要证明与 token-wise speculative exit 的互补性。

五句话总结

SoftCache 不是简单多缓存一点，而是让缓存决定走多大一步。它的优势有真实 wall-clock 速度档支持。PSNR 与 LPIPS 让质量损失可被细粒度观察。尚不能把 FLOPs 减少自动换算为系统加速。最值得试的是与 token-wise early commitment 的联合预算。

人话版：这篇论文到底干了什么？

LLM 用可验证奖励做 RL 后训练，可能把模型推向一种最容易得分的解法，导致 pass@1 提高但其他同样正确的解题路线逐渐消失。EliteReplay 试图让模型同时保留“正确”和“多样”。它先让冻结的 base model 对每道题探索多种候选，用 quality-diversity 搜索保存互不等价的正确策略，构成 elite archive；再把 archive replay loss 与 GRPO 结合，使优化当前正确率时不轻易遗忘其他可行路线。论文在 text-to-SQL 和歧义查询任务中观察到更好的高 k 覆盖：正确策略类型相对强基线最多增加 77%，并报告更好的 pass@128。它对 Agent RL 的启示是，成功轨迹的多样性可以是可保护的训练资产，而不只是采样时的随机性。

Background & Gap / Core Insight

只看一次采样的最终准确率会忽略策略坍缩。SQL 任务可能同时存在连接顺序、子查询和聚合等不同正确实现；Agent 工具使用更有搜索路线、工具组合、失败回退等不同成功轨迹。单纯增加 entropy 并不能保证模型保留的是“正确而不同”的方案。EliteReplay 的核心机制是先在训练前用可验证环境建立高质量多样化 archive，再在 RL 更新时施加 replay 约束，保留已有的可行策略分布。

Method：从 Input 到 Output

人话版：这篇论文到底干了什么？

交互式视频世界模型要一边生成新画面，一边记住此前看过的空间。直接保留所有历史 KV 会使后续 chunk 的注意力越来越慢；只按时间丢弃旧帧，又会在相机转回旧区域时丢掉关键记忆。Velox 利用相机位姿与深度估计，把历史 token block 变成空间视锥片段，用几何重叠为当前 query block 选择更相关的历史块；当几何覆盖不足时，退回模型本身的注意力重要性。它是 training-free 的 sparse attention router，并通过布局和异步几何计算减少运行时开销。作者在第 48 个 chunk 报告 attention 4.36×、denoising 2.43× 的加速，同时 WBench 导航平均分接近 dense 对照。

Background & Gap / Core Insight

Dense KV 的历史成本随视频长度增长；滑动窗口虽快，却无法保证空间重访时的历史一致性。视频的冗余不仅是“相邻帧相似”，还包含“同一物体在不同时间、不同视角再次出现”。Velox 的 observation 是，当前相机视锥与历史几何块的交叠可作为历史信息是否值得访问的先验。与直接删历史不同，保留可用记忆但限制每个 query 可访问的块数，计算量就可能不再随完整历史线性增长。

Method：从 Input 到 Output

历史视频 KV + camera pose + depth → frustum slabs → 当前 query 的多次 warp 深度 → overlap score → 软融合模型重要性 → bounded block routing → sparse attention。历史块先映射到相机视锥与深度区间；当前块通过 recency-priority multiwarp 估计深度。几何覆盖可靠时，空间重叠度修正原模型的 block importance；不可靠时不强加几何偏置。再加入局部邻居和可选 reference-frame block 作为安全边界，最终用 block-sparse attention 只访问选中的 KV。全局 Gilbert token 顺序改善邻近块布局与访问局部性，但它本身不等同于算法正确性的保证。

Experiment Setup / Research Questions

作者在 LingBot-Fast-Cam 类交互式世界模型上，使用 WBench navigation 的 158 个案例评估，特别报告第 48 个 chunk 的 H200 加速。RQ1：历史增长后，固定路由预算能否压住 attention 成本？RQ2：空间选择是否比纯 recency 更能保留场景一致性？RQ3：几何计算是否可以异步隐藏？RQ4：注意力加速能否兑现为整段 denoising 加速？

Results / Table & Figure Reading

作者报告 chunk 48 attention 4.36×，而 denoising 只有 2.43×，说明非 attention 计算、路由和同步开销不可忽略。WBench 的 158-case 导航分桶中，API-free 平均评分与 dense 对照差异不超过 0.15 分。论文 Table 1 包含多项场景一致性、物理一致性和导航指标，应看是否某个弱项被平均分掩盖。注意“第 48 个 chunk 的加速”不是整个视频从第 1 帧开始的平均 FPS。

人话版：这篇论文到底干了什么？

长视频模型通常把过去的帧或摘要保存在上下文、检索库、KV cache 里，视频越长越需要在记忆容量、准确率和实时性之间取舍。Memory as Weights 提出另一条路：把长期历史编码成不断更新的轻量模型参数。它用 recurrent HyperNetwork 读取新的视频观察与先前状态，生成 LoRA 形式的参数化记忆，使当前时刻不必把全部历史 token 重新喂给主模型。作者构造 MaLoW-Instruct（56K 视频、381K 问答对），在 OVO-Bench backward split 上相对既有记忆方法提升 3.9%–11.8%，并报告 Simpler WidowX 上动作成功率提高 9.3%。这不是已经证明“推理更快”的论文，而是为固定容量视频记忆提供了新机制。

Background & Gap / Core Insight

显式 memory 的好处是可检索、可追溯、可删除，坏处是长视频的 token 与缓存会竞争上下文预算。把记忆写进参数能让历史存储量与帧数脱钩，但参数更新会引入灾难性干扰，也难以直接定位哪一帧导致当前预测。作者的核心思想是把“视频随时间变化的历史”与“当前帧实时输入”分离：前者用轻量权重承载，后者仍走正常视觉输入。相较于传统 online fine-tuning，HyperNetwork 生成低秩适配器使状态更新更结构化。

Method：从 Input 到 Output

当前视频片段 → 视觉编码 → recurrent HyperNetwork（接收前一状态）→ 更新 LoRA memory → 当前 query/动作与最新观察共同推理 → 下一片段继续更新。关键不在缓存所有视觉 token，而在固定大小的参数状态随时间滚动。若旧事件被新事件覆盖，未来 query 可能无法恢复；因此它天然需要“写入价值”和“可恢复性”的长期测评。这里的 LoRA 是在线记忆状态，不等于常规离线 PEFT 的单次训练权重。

Experiment Setup / Research Questions

作者报告 MaLoW-Instruct 的 56K videos 与 381K QA pairs；评估涉及 OVO-Bench、StreamingBench、StreamArena 与 Simpler WidowX。RQ1：历史写进参数是否比重放视频 token 更准确？RQ2：长时间流式输入下，memory 体积是否真正固定？RQ3：参数记忆能否迁移到视觉语言动作控制？RQ4：是否产生记忆覆盖、冲突或错误累积？不同 backbone 的逐项绝对分数、GPU latency 与 peak memory 本轮未核对，明确记为 Not Reported。

Background / Core Method
