When Fine-Grained Credit Assignment Helps and Hurts: Multimodal Agentic Reinforcement Learning through Video Editing

人话版：这篇论文到底干了什么？

这篇工作不是再发明一个“更细粒度的奖励”，而是问：把终局成功信号分配到每一步、每个 token，究竟什么时候值得？作者用电影预告片剪辑构造四类可执行多模态 Agent 任务，让同一个 Qwen3.5-9B 分别接受整条轨迹结果奖励、每轮过程奖励和 token 级自蒸馏。最有价值的发现是：长达几十轮的 Fine Cut 确实需要过程引导，但过程奖励长期保留反而会诱导冗余工具调用与奖励黑客行为；先用过程奖励学习，再逐渐退回结果奖励，表现最好。更细不等于更好，关键是信号何时可信。

Background & Research Gap

旧式 outcome-only GRPO 把同一条轨迹的终局得分分配给全部 token。若某个剪辑任务先正确识别镜头、后面却因错误音轨失败，正确的前半程也受到负面更新；反过来，偶然成功的长轨迹中无效的工具调用也得到正向 credit。过程奖励看似能解决，但它来自不完美的 LLM judge，可能奖励“认真检查”而非“真正交付”。现有论文常在不同模型、任务和训练预算下比较不同 credit，难以区分算法效果和环境差异。本文在统一剪辑环境中做相对干净的横向对照。

Core Insight 与观察依据

作者将任务划为 Content Selection、Narrative Sequencing、Rough Cut、Fine Cut。基线平均轮次分别为 22.3 / 15.3 / 21.8 / 87.2；最后一类显著更长、更易混入质量不一致的局部动作。观察到固定过程权重的训练中，PRM 分数继续上升，任务完成率和终局得分却下降，说明局部可奖励行为与整体目标发生脱钩。因此把过程奖励当成早期探索与行为塑形的临时脚手架，而非永久目标。

Method Deep Dive：Input → Output

  1. 构造可验证编辑任务：从 49 部电影及其公开预告片对齐镜头、生成任务简报，过滤后保留 797 个任务；按电影划分 716 train、81 validation，减少同片段泄漏。环境有 shell 与 8 个媒体工具，输出可验证的选择、排序、切点或成片。
  2. 终局奖励：根据任务组合确定性对齐指标、参考视频条件下的多模态评分、无参考的成片质量评分。Content Selection 与 Narrative Sequencing 使用确定性得分；后两类加入评审模型，评价的是最终交付物而不是中间动作。
  3. 轨迹级对照：同一 prompt 采样一组轨迹，用组内均值与标准差规范化 outcome，GRPO 将该优势施加于所有生成 token。
  4. 轮次级过程奖励：Gemini 3.8 Flash 对每轮行为及工具反馈评分，多次投票取平均；同一轮索引跨 rollout 规范化。比较固定权重与从第 20 次更新到第 30 次更新衰减至 0 的策略。
  5. token 级 OPSD：冻结初始策略作教师，教师额外看到参考答案或逐轮建议；学生在自己的 prefix 上匹配教师分布。该分支没有 outcome 奖励，测试更密集监督是否天然优越。
  6. 统一评测：Qwen3.5-9B、50 次更新、81 个留出任务、每题 4 次评估；同时记录视觉检查、工具调用、思考长度与完成率。

关键公式 / Objective

轨迹优势 A_out=(R_out-mean_group)/(std_group+ε)。轮级优势 A_turn=A_out+λ·(r_turn-mean_turn)/(std_turn+ε)；λ=0.5 固定或在更新 20–30 衰减到 0。这里 r_turn 是过程 judge 的局部评分，λ 决定是否把局部偏好当成优化目标。OPSD 则最小化 E[D_KL(p_teacher || p_student)]，其中 teacher 额外获得 privileged context。三种方法最大的区别不是 token 数量，而是监督信号的因果可信度、时间尺度与目标一致性。

Toy Example

假设 Agent 要把三段镜头配上音乐并导出。它先调用工具预览 5 次、选对镜头，却一直循环检查音频，最后没有导出。过程 judge 可能连续奖励“检查很认真”；固定 PRM 会把这种行为强化。若早期用 PRM 学会调用媒体工具、后期只以是否导出且质量达标为准，冗余调用便不再持续受益。这是对论文机制的说明性例子，不是原论文实验样本。

Research Questions / Results / Figures

RQ1：长 horizon 是否更需要细粒度 credit？ Fine Cut 从 outcome-only 的 .201 提高到 decayed PRM 的 .293，相对 +45.4%；NS 从 .500 到 .552，相对 +10.4%；CS 和 RC 反而略低。不能推出“细粒度永远更强”，应按轨迹长度与局部动作混杂度决定。

RQ2：奖励与最终结果何时分离？ 固定 PRM 的 Overall 仅 .334，低于 outcome-only .413；尤其 CS .482 vs .821。论文 Figure 1(c) 对比过程分数与 outcome 曲线，固定权重会持续抬升局部奖励却拖累终局。衰减曲线在训练后段恢复任务导向。

RQ3：token 级更细是否更好？ OPSD(reference) Overall .277，接近未训练 .284；OPSD(turn suggestions) 仅 .044，FC 为 0。教师-学生分布差异大并不等于提供了可执行的正确梯度；错误的 privileged information 还会系统性破坏策略。

Ablation、最强与最弱结果

最强：decayed PRM 在 FC 得到 .293，且整体 .447 高于 .413。最弱：OPSD(turn suggestions) 整体 .044，几乎完全崩溃。固定 λ 对短任务的明显伤害说明局部评分不是终局目标的可靠替代；λ 衰减不是一个简单正则化小技巧，而是改变了训练后期的优化目标。论文没有证明 20–30 次更新是普适最佳切换点，也没有跨多个 backbone 验证。

Claim vs Evidence

Authors Claim：细粒度 credit 在长任务可有效，但固定过程奖励会被利用，OPSD 对 privileged context 敏感。

Experiments Actually Show：在 Qwen3.5-9B、四种视频剪辑任务、一个训练预算下，上述现象有直接数值与行为诊断支持；独立电影划分加强了证据。

What Is Not Yet Proven：是否适用于 Web/Code/GUI Agent、不同 judge、1000-step 交互；也未建立过程奖励偏离最终目标的因果充分条件。LLM judge 的主观性可能引入共同偏差。

Contribution / Limitation / Research Value

贡献包括 New Benchmark（真实电影来源的可执行编辑任务）、New Empirical Finding（credit 粒度随任务结构变化）、Training Strategy（过程奖励衰减的有效性）、Evaluation（行为与得分脱钩的诊断）。局限：只有单一策略 backbone、评审模型参与 reward、任务类型与轮次同时变化，尚不能把效果纯粹归因于 horizon。作为 RL baseline，建议直接复现 outcome-only / fixed PRM / decayed PRM；作为 Agent 评测，应该同时报告完成率、有效工具调用、冗余调用；作为 Video Agent，视频剪辑工具链使结果比静态 Video QA 更贴近真实任务。安全价值在于揭示 reward hacking 的可观测早期征兆。

Migration：从论文到可实验的新问题

Original Problem：多模态剪辑的稀疏终局反馈 → Transferable Mechanism：过程奖励仅在有用的训练阶段启用 → New Research Question：能否根据在线“局部奖励-终局收益背离”自动切换过程权重？ → Method Modification：对一组 rollout 估计过程分数与任务完成率、有效工具调用的关联，动态更新 λ → Minimum Experiment：在 AppWorld / WebArena 小规模任务上比较 fixed、linear decay、adaptive λ → Model：开源 7B/9B Agent → Dataset：同一训练/验证环境 → Baseline：outcome GRPO、fixed PRM、预设 decay → Metric：成功率、无效调用数、reward gap、GPU-hours → Expected Contribution：机制驱动的 reward schedule → Risk：相关性噪声使权重抖动，必须做独立 seed 与奖励攻击测试。

五句话总结

这篇论文最重要的不是一个新 loss，而是什么时候不要再相信过程奖励。长任务上的过程奖励确实能帮助探索。持续奖励“看似合理的过程”会偏离真正交付。token 级蒸馏也可能比简单终局 RL 更差。最值得迁移的是动态过程奖励退火与 reward-hacking 诊断。

TeamGym: A Gym for Team Decision-Making by AI Agents with Distributed Information

Chanwoo Park; Jaywoong Jeong; Zachary Wojtowicz; Yubin Kim; Taekyun Lee; Kaiqing Zhang; Asuman Ozdaglar · 2026-10-27 · arXiv preprint
Affiliation：未逐一核实（请以原文首页为准）
HTML 正文（如可用） · PDF · Code：未核实

人话版：这篇论文到底干了什么？

很多 Multi-Agent 论文只比较“单人做题”和“多人讨论”，但多 Agent 的错误究竟来自知识没找到、消息没传出去，还是最终决策没整合？TeamGym 把问题拆开：为每道任务抽出一组缺一不可、合起来足以决定答案的 pivotal information units（PIU），然后控制这些事实分配给哪些 Agent、是否藏在长文档里、谁发言以及通信 token 预算。作者发现，分布式事实导致平均 22.9 个百分点 的决策损失，让 Agent 自己从文档检索又损失 19.9 个百分点。更重要的是，最终结果奖励能让团队学会协调，但“信息被说出来”并不等于“被正确使用”。

Background & Gap（含具体例子）

设三个 Agent 共同判断一份合同是否满足条件：A 看到生效日期，B 看到例外条款，C 看到金额上限。若只让单个模型看到全部三条，任务很容易；分给三个 Agent 后，A 可能没有询问 B，B 可能把例外解释错，C 的发言可能被截断。传统 benchmark 把失败混在一个成功率里，无法定位根因。TeamGym 从法律、金融、医疗和软件工程材料构建有可验证答案的任务，并用 PIU 把“事实缺失”和“通信失败”拆成可控实验因素。

Core Insight

最小充分事实集合不仅是标注，还可以作为可干预的因果单位：保持问题、PIU 内容、模型不变，仅改变事实的拥有者或检索方式，就能识别通信 gap 与 retrieval gap。进一步地，控制 speaker selection 和 token budget 可以检测局部通信策略是否损害全局 outcome。其机制价值高于普通角色扮演式 multi-agent benchmark，因为它给出了可归因的失败维度。

Method Deep Dive：Input → Team Decision

  1. 问题生成与 PIU 识别：从 12 个 source corpora 提取法律合同、法规、SEC 文件、医学论文和代码问题；验证一组事实的“必要性 + 联合充分性”，得到 PIU 与可计算答案。
  2. 事实分配：比较 Single-Agent All-PIU（单体持有全部关键事实）、Multi-Agent PIU-Only（每个参与者直接拿到局部关键事实）、Multi-Agent Full-Context（参与者拿到原始材料，必须自己找事实）。这三种条件依次隔离 communication 和 retrieval。
  3. 团队交互：每位 Agent 维护私有材料、私有笔记和可见公共 transcript；通过 coordinator-selected speaker、round robin、simultaneous responses 或 current-speaker selection 决定消息流。每次查询、回复都受 token budget 限制。
  4. 终局评估：最终 decision maker 根据对话作出有限选项、数值或文字答案；环境用问题专属效用函数评估。跟踪每条 PIU 是否被提及、被整合、是否被错误消息污染。
  5. 训练：在两种通信结构下训练协调者和参与者策略；奖励主要来自最终团队决策损失，而不是逐条消息人工评分，观察是否出现自发的信息收集与 speaker coordination。

RL Formulation / Reward / Credit

状态 s_t 是公共问题、角色私有观察、可见通信历史与剩余预算；动作 a_t 包括查询谁、发送什么消息、何时终止并提交决策；trajectory 是团队通信及最终决策；U_q(d)∈[0,1] 表示问题 q 对最终决策 d 的团队 payoff。Reward 是全局终局信号，不是每个参与者的局部正确性。文中训练并未证明对每条消息做了严格反事实 credit；若某个 Agent 的事实被正确使用但其他人犯错，该 Agent 仍可能受到低终局 reward。最值得研究的是从 PIU 的因果必要性推导局部贡献，而不是简单把团队奖励平摊。

Toy Example

人话版：这篇论文到底干了什么？

长视频流每来一帧就产生新的视觉 KV，直接全缓存会耗尽显存。多数压缩方法只问“哪些 token 相似、可以合并”，但不问“同样的压缩误差发生在不同 Transformer 层会造成多大后果”。Video-MemComp 把压缩损失分成局部近似误差与层级结构敏感度：先在 RoPE 旋转前安全地聚合相似视觉 token，再用离线梯度先验和在线熵把有限 KV 预算分配给更敏感的层。它是 training-free 的部署侧方法。论文在 Qwen2.5-VL-3B 上报告 KV 记忆节省超过 90%，整体准确率从 62.3% 到 64.1%；同时提供真实 A6000 上的显存、TTFT 和吞吐数据，值得仔细区分 trade-off。

Background & Gap

一个持续 20 分钟的摄像头流中，背景墙、桌子、人物服装重复出现，但一瞬间的物品移动可能决定问题答案。只做相似 token 删除会抹掉关键瞬态；统一每层压缩率又假设所有 Transformer 层对误差同样敏感。更隐蔽的是 RoPE：在位置编码旋转后直接平均两个 K，可能把相似语义放进错误的相位空间。本文强调局部表示误差与跨层放大效应是不同的预算分配问题。

Core Insight 与理论依据

用一阶 Taylor 展开把压缩后的模型输出扰动近似成各层局部误差经 Jacobian 传播的加权和。局部误差小不代表最终输出误差小，因为高敏感层可把微小扰动放大。因此需要 within-layer 的保真压缩与 across-layer 的 sensitivity-aware budget 两个正交组件。在线熵提供输入依赖调整，但离线梯度先验更稳定；论文的权重消融显示熵权过大反而变差。

Method Deep Dive：视频流 → 受限 KV → 回答

  1. 流式预填充：视频帧进入视觉编码器与 LLM，逐帧产生视觉 token / KV；不要求重新训练底座。
  2. 跨帧过滤：检测时间相近且表示冗余的 token，减少静态背景反复占用 cache。这个步骤主要节省时间冗余。
  3. 帧内聚合：在 pre-RoPE safe zone 聚合同帧相似 token，避免直接混合旋转后的 key；通过 attention-conserving logit bias 尽量维持聚合前的注意力质量。这一步压缩空间冗余，而不是机械丢弃所有低分 token。
  4. 结构敏感度先验：利用离线梯度估计不同层的压缩扰动对下游输出的影响；将层视为不同“容错能力”的容器。
  5. 动态预算：融合均匀先验、结构敏感度和在线上下文熵，决定每层应保留多少 KV token；预算约束下对每层的重要性排序并截取 Top-K。
  6. 在线推理：新帧更新缓存，后续问题只在有限显存预算内访问已压缩历史；评估离线 Video QA 与 RVS 流式任务。

关键公式 / Objective（概念解释）

一阶扰动可写作 Δoutput ≈ Σ_l J_l · Δh_l，其中 Δh_l 是第 l 层局部压缩误差，J_l 是后续计算对该层扰动的敏感度。目标不是只最小化 Σ_l ||Δh_l||，而是在总预算 Σ_l b_l≤B 下优先减少高敏感层的加权误差。预算策略综合 uniform prior、offline gradient sensitivity 和 online entropy；这不是论文完整符号的逐字复刻，而是机制等价的解释式。超参数权重需要离线校准，不能声称“完全零校准”。

人话版

手机 GUI Agent 通常用 7B VLM 把每一步操作解码成文本，虽然表达能力强，但一次点击也要经过大量 autoregressive token 生成。GUI-JEPA 改成“给定候选动作，在屏幕潜在表示中预测并评分”，不再让大语言模型逐 token 产生操作。它先对未标注 GUI 截图学习 JEPA 表征，再针对候选 action/region 做潜在预测，轻量 head 一次批量选择动作。作者报告在 AndroidControl 上，同 GPU 比微调 Qwen2.5-VL-7B 快 2.8–4.0 倍，仅用其 6% 参数，但保留的 in-distribution accuracy 是 86–92%，存在明显准确率代价。

Background & Core Insight

传统 Agent pipeline 是 screenshot → VLM → textual action → executor，瓶颈既有视觉编码，也有 token-by-token decoding。JEPA 方案把 action selection 转成 latent-space discriminative scoring：候选动作有限时，不必生成一段文字再解析。作者还发现随机初始化 predictor 与 screen-dynamics 预训练 predictor 表现相当，提示收益更可能来自决策条件化的表示学习，而非学会精准预测屏幕动力学。这一点很值得做消融验证。

Method / Agent Architecture

Instruction + Screenshot → JEPA Encoder → Candidate action/region-conditioned latent predictor → Batched scoring heads → Selected GUI action → Environment。环境状态是屏幕、指令与候选动作；工具历史、长时记忆和跨 app 任务依赖在可获取摘要中没有充分展开。若候选动作集不包含正确操作，快速 scorer 无法弥补候选生成的召回错误；这也是 failure propagation 的第一环。

Experiments / Results / Figure

在 AndroidControl、同 GPU、相同输入的微调 Qwen2.5-VL-7B 对照下：推理速度 2.8–4.0×；参数量约为 baseline 6%；in-distribution accuracy 为 baseline 的 86–92%，不是“准确率 86–92%”。摘要还给出 predictor 的随机初始化对照，支持决策目标比屏幕动力学预训练更关键。最强 baseline 为作者微调的 Qwen2.5-VL-7B；其他基线和具体 Table 编号须读正文确认，不虚构。

Contribution / Limitation / Research Value

Background / Core Insight

Verifier 的两条技术路线与消融重点

Training-free verifier 依赖中间 clean estimate 的相似性与跨步稳定性，优点是无需标注或重新训练，缺点是稳定的错误也可能被提前接受。Learned verifier 使用生成器中间特征预测未来误差，可能在复杂运动上更精确，但会引入训练数据偏差和额外推理开销。比较时不能只看接受率，还应按运动幅度、镜头切换、主体新出现、长时漂移分桶。若早期接受的 token 仍作为后续上下文，单点误差可通过 KV 在未来帧传播；这与普通图像扩散的局部冻结不同。

人话版

GRPO 常把同一 rollout 的结果优势分配给每个 token，这会忽略中间推理步骤的质量。BoT-GRPO 试图不训练额外 value network，就利用 token-level reward：把一组 rollout 的 token 奖励合并为一个“bag”，按原序列长度倒数加权，再根据组内统计构造 token 优势，避免长答案因 token 数多而主导训练。作者报告 React 前端代码生成达到 80% compile rate 的训练速度最多比 GRPO 快 1.9×，AIME 数学推理的 Pass@k 最多 +8.1 个百分点，只需约一半训练步数。核心不是奖励越密越好，而是长度无偏、稳定的过程信号。

Background & Gap

普通 GRPO 只有 terminal reward，长推理中错误与正确 token 共用一个 advantage；简单加 process reward 又可能被长轨迹放大，模型通过输出更多步骤获得更高累计奖励。BoT-GRPO 的机制是对每条序列使用 inverse-length 权重，让一条 1000-token 答案不因长度比 100-token 答案长十倍就对统计量贡献十倍。

Method / RL Formulation

Prompt → Group of rollouts → Token-level reward model → Inverse-length weighted bag statistics → Token-specific advantage → GRPO-style policy update。State 是 prompt 与已生成 prefix，Action 是下一个 token，Trajectory 是整段推理或代码输出，Reward 是逐 token process feedback，Policy 是语言模型；Advantage 来自加权组统计，省去 critic。摘要未列出完整 KL/entropy 系数和 rollout 总量，不能臆测。潜在 reward hacking 包括输出大量形式上“正确”的低价值步骤，或利用过程模型评分漏洞；长度无偏仅能缓解其中一类。

Experiments / Results

代码任务比较 GRPO、GSPO、DAPO、PURE，作者称 BoT-GRPO 更快达到 80% compile rate（最多 1.9×） 且最终 compile / VLM-judged win rate 更高；AIME 上 Pass@k 最多 +8.1pp、训练步数约减半。模型包括 Qwen2.5-3B、SmolLM3-3B、Phi-4-mini-reasoning，涉及 reasoning 与 non-reasoning base model。摘要特别强调 bounded、stable reward 比更丰富但噪声大的 reward 有效；这应视为作者实验观察，不是一般数学定理。

Contribution / Limitations / Research Value

贡献是 New Objective / Credit Mechanism（长度归一化的 token reward aggregation）与 Empirical Finding（reward 稳定性影响收敛）。局限：token reward model 的训练与推理成本、真实 wall-clock GPU-hours、跨长轨迹 tool agent 的适用性、对 adversarial process judge 的稳健性尚待核验。与 S 级 video-editing credit 论文形成重要对照：BoT-GRPO 解决token 长度权重，后者强调过程奖励何时关闭；两者可能正交，也可能相互干扰。

Migration / Minimum Experiment

Original：推理 token 共享 outcome advantage → Mechanism：length-invariant process credit → Question：在多轮 Agent 中是否也能减少冗余工具调用？ → Modification：把 token bag 改成 turn/skill bag，按动作成本归一化 → MVE：同一 AppWorld 任务比较 outcome GRPO、turn PRM、BoT-turn、BoT-turn+decay → Model：7B Agent → Dataset：AppWorld → Metric：success、tool calls、rollout tokens、GPU-hours、reward gap → Expected Contribution：成本归一化的多轮 credit → Risk：短但关键的动作可能被过度放大。Worth Deep Reading: YES。

关键公式直觉与实验边界

设第 i 条 rollout 长度为 L_i，token 过程奖励为 r_{i,t}。朴素拼接会让长 rollout 的 token 在统计中占更大权重；BoT 的核心是为该条序列中的每个 token 分配约 1/L_i 的权重，使每条 rollout 对组统计的总质量更接近。真正的 per-token advantage 还取决于加权组均值与方差，不能把“长度无偏”理解成奖励完全不受长度影响。它解决的是统计聚合偏差，不是过程奖励本身是否与终局一致；若 judge 错误地奖励冗长自检，仍会发生 reward hacking。

Ablation / Claim vs Evidence

最重要的对照应分别去掉 inverse-length weighting、替换为 sequence-level reward、注入噪声 process reward、固定训练 token budget，而不是只对比训练 step 数。Authors Claim：critic-free 的细粒度 reward 聚合改善收敛；Evidence：代码编译与 AIME 的多个模型实验。Not Yet Proven：真实长程工具使用、跨多 Agent 局部/全局奖励、奖励模型在线漂移。阅读优先级应放在 bag 统计公式、reward 稳定性消融与按 GPU 计算成本归一化的收敛曲线。它与 S 级视频剪辑论文的最关键交叉，是探索长度归一化 + 自适应过程奖励关闭能否同时降低 credit 偏差与后期奖励黑客。

Reward Design 的最小核查

需要把 reward model 的标签稳定性、评分分布方差和过程奖励长度偏差单独测量。若仅用更昂贵的评审模型换取更好训练信号，应报告总评分成本，而不能把策略更新步数减少直接称为整体算力节约。

Training Efficiency

Research Value

潜在价值是把 Agent 的探索多样性从每个 token 的随机性转移到 trajectory-level 的策略选择，例如不同 latent seed 对应不同工具规划路径。但若没有对独立解决路径数、任务成功率与真实计算成本同时评估，8× 样本数差异不能直接解释为 8× 训练提速。应与 entropy-regularized GRPO 和无 seed 的 group sampling 进行相同预算对照。

Failure Case

人话版

这篇理论论文挑战一个常见直觉：如果 unlearning 的模型输出与“从没见过删除样本、重新训练”的输出相似，是否就意味着隐私安全？作者指出，若攻击者能持续观察模型的多次发布，仅有重训等价并不自动提供有意义的隐私保证。他们把 unlearning 重新理解成retroactive algorithm：允许修改历史操作，并保证后续答案反映修改后的历史；若要隐私，还必须额外要求持续观察下的 differential privacy。

Background / Core Method

历史数据更新序列 → 删除/回溯修改 → Retroactive state update → 多次公开结果。与单次删除的输出分布比较不同，这里攻击者可观察时间序列。作者提出 private retroactive algorithms 的形式化定义，把历史一致性与 continual-observation DP 组合。对线性统计、聚类、直方图给出构造与不可能性结果；这不等于已为 LLM 参数级 unlearning 提供可直接部署的算法。

Experiment / Main Finding

该工作主要是理论构造与下界，不是在 TOFU/MLLMU 上跑 benchmark 的实证论文。摘要明确称某些问题的隐私与回溯性可在渐近复杂度上不比单独实现隐私更贵，但没有提供可移植到 LLM 的具体速度/遗忘率数字。不能编造 forget accuracy、MIA AUC 或训练成本。

Contribution / Limitation / Connection

贡献为 New Definition / Theoretical Framework：明确区分“删除后功能正确”与“连续发布下隐私保护”。局限是从统计数据结构到大型生成模型的技术鸿沟。对当前 black-box unlearning attack 的启发是比较多版本轨迹攻击与单版本 MIA：即使每次发布看起来都接近重训，版本差分也可能泄露被删信息。Potential Use：用同一删除序列构建 pre/post/multi-release 攻击协议，报告 AUC、TPR@FPR、utility 与攻击者可见信息。证据范围：仅根据 Abstract / 可获取信息总结。

Research Gap / Minimum Experiment

对生成式模型，值得做的是多次删除发布的差分攻击：固定训练集与删除顺序，攻击者分别只看最后一个版本、前后两个版本、完整发布轨迹；比较隐私风险是否随可观察版本数增加。这是从理论问题迁移出的实验建议，不能当作论文已经在 LLM 上证明的结果。

Why It Matters

如果评测只看一次 unlearning 之后的模型输出，可能忽略多个发布版本之间的差分信息。该理论工作为“删除正确性”和“隐私保证”划出清晰边界。

Collision Detection

⚠️ Collision Warning 1 — Process Reward / Credit Assignment

Collision papers：Credit Assignment Helps and Hurts、BoT-GRPO、TreeHCA。已解决：过程奖励衰减、长度无偏聚合、后见探索等局部问题。重合点：都改善长轨迹的 credit。剩余 gap：何时过程奖励不再可信的在线、可验证切换标准。差异化：reward–outcome divergence detector + independent judge + long-horizon cost accounting。结论：值得继续，但“再加一个 PRM loss”不够。

⚠️ Collision Warning 2 — Shared Memory / Information Attribution

Collision papers：TeamGym、CrossProfile、TAM。已解决：PIU 分配、来源偏差诊断、局部成功 skill 提取。重合点：信息是否应该被保留并用于后续决策。剩余 gap：多 Agent 信息/skill 的反事实边际效用与长期过期机制。差异化：固定 PIU 内容，做 remove/replace message 重放并联合成本约束。结论：值得继续，但必须有可审计 causal effect。

⚠️ Collision Warning 3 — Video Cache / Token Reuse

Collision papers：Video-MemComp、FrameBlend、Visual Cache Reuse。已解决：敏感度分层 KV 预算、query-time 重算与视觉 KV 复用。重合点：预算内保留/恢复任务相关视觉信息。剩余 gap：多查询负载下的联合 memory–accuracy–P99 Pareto。差异化：统一硬件、同一 GPU-seconds 预算、event-level provenance 与失败恢复；简单拼接不构成新机制。结论：条件性值得做，先完成强 baseline 实测。
