VETTA: Coordinating Turn- and Token-Level Credit Assignment for Multi-Turn LLM Agents

arXiv:2610.08402 · RL / Agent · 2026-10-06 UTC · Tier S

Paper / Abstract · Full text (if available) · Authors: Jiaju Chen, Min Yang, Jinghua Piao, Xiaochong Lan, Xu Xia, Xiangnan He, Yong Li. Affiliations: USTC / Zhongguancun Academy / Shandong University / Tsinghua University / Southeast University (作者对应关系见正文). Status: arXiv v1; venue 未标注. Code: https://github.com/Jiaju-Chen/VETTA-official

人话版：这篇论文到底干了什么？

训练能连续调用工具的 Agent，往往只在任务结束时知道成功还是失败。传统 PPO 很难判断到底哪一轮行动值得奖励，更难判断该轮生成的哪些 token 导致结果。VETTA 用一个共享的轻量 critic 同时给“整轮动作”和“动作内部 token”打价值分，前者确定该轮总体功劳，后者只调整该轮内部的相对功劳。Qwen2.5-1.5B 在 ALFWorld 与 WebShop 的成功率分别达到 91.9% 和 73.8%，相对普通 PPO 的 54.4% 和 51.5% 提升 37.5 与 22.3 个百分点。它重要的不只是精度，还在于 critic 只保留前两层 Transformer，显著降低 RL 的价值评估开销。

Background & Gap

一个 WebShop Agent 可能先搜索、再打开商品、筛选规格、最后购买。只有最后购物成功时，直接把奖励均分给每个生成 token，会把“点错页面但后来纠正”的行为也奖励；只给整个动作一个分数，又无法区分“正确工具参数”和冗长无效解释。GRPO/RLOO 等 critic-free 方法用多条 rollout 的相对收益做基线，GiGPO 进一步对同状态的动作比较；Turn-PPO 为每轮估值，PPO* 则跨轮给 token 做 GAE。两者都缺少另一种粒度的显式建模。VETTA 试图把不同时间尺度的价值信号正交化，而不是把它们直接相加。

Core Insight & RL Formulation

State 是任务指令、当前观察与历史组成的 H_k；Action 是一轮生成的 token 序列 a_k；Policy πθ 逐 token 采样；Trajectory 是 K 轮 action-observation；Reward r_k 来自环境任务反馈，可能很稀疏，WebShop 另有任务评分与无效动作惩罚。Turn value Vturn(H_k) 估计整轮动作之前的未来回报；token value Vtok(H_k,y_<j) 估计生成第 j 个 token 之前的未来回报。两条 GAE 轨迹各自用 γ、λ 计算 advantage，token 轨迹跳过环境 observation token。Reward 是环境反馈，不是训练一个 learned reward model；critic 学的是 value 而非 reward。Reward hacking 风险在于优化 WebShop 评分而非真正正确购买，因此同时看 task score 和 success。

Method Deep Dive & 核心公式

Pipeline：Actor 采集多轮交互 → 将同一轨迹表示成 turn 与 token 两条决策链 → 共享两层 critic、两个线性 value head → 分别做 GAE → token advantage 在每轮内部去均值 → 与 turn advantage 融合 → PPO clipped actor update 与双头 value regression。关键公式 A(k,j)=Aturn(k)+α·[Atok(k,j)−mean_j Atok(k,j)]。α 控制同一轮内部 token 信号的强度；去均值使这一轮所有 token 的平均优势仍等于 Aturn，防止 token 分支重新改变轮级奖励。与简单加法相比，这是一种保持轮级总量的残差分配。PPO 损失为 −E[min(ρA,clip(ρ,1−ε,1+ε)A)]，ρ 是新旧 policy 对当前 token 的概率比；clip 限制策略一步变化，KL 正则系数 0.01 单独施加，防止偏离初始策略过远。Turn γ/λ=0.95/0.95，Token γ/λ=1/1；ALFWorld α=1，WebShop α=3。Critic 取预训练 actor 的 embedding、前两层与 RMSNorm，删除后 26 层，两个 head 分开监督，降低价值网络训练开销。

Toy Example

假设购物任务有两轮：第一轮检索商品，第二轮选规格并提交。第一轮 Aturn=+0.6，三枚关键 token 的 Atok=[0.1,0.7,0.4]，均值 0.4；α=1 后融合优势=[0.3,0.9,0.6]，平均仍为 0.6。第二轮 Aturn=−0.2，Atok=[0.8,0.2]，中心化为 [+0.3,−0.3]，融合为 [+0.1,−0.5]。这意味着即便某一轮总体失败，也能在该轮内部区别有帮助与有害的决策；具体数值是教学构造，不是论文实验结果。

Baseline Deep Comparison

PPO：每轮最后 token 接收奖励，GAE 不充分跨轮传播，1.5B ALFWorld 54.4%；PPO*：token 级跨轮传播，ALFWorld 64.8%、WebShop 56.6%；Turn-PPO：整轮 action 优势，ALFWorld 76.4%，但 WebShop 52.2%；GiGPO：critic-free 状态分组相对信用，1.5B ALFWorld 86.1%、WebShop 67.4%，是两任务最强外部 baseline。VETTA 91.9%、73.8%，比 GiGPO +5.8/+6.4 pp。机制改进是粒度融合，engineering 改进是缩小 critic；二者应分别验证。

Experiment Setup & Research Questions

模型 Qwen2.5-1.5B-Instruct 与 7B-Instruct。ALFWorld 是文本具身家务六类任务，固定 seen=140、unseen=134；正文主表使用 valid_seen 140 任务的三个 decoding seed；WebShop 固定 500 任务。训练每更新 128 tasks×1 rollout，最多 50/15 turns，150 updates；actor LR 1e−6，critic LR 1e−5，PPO minibatch 256/64。RQ1：和 prompt、critic-free、critic-based RL 谁更强？RQ2：融合/中心化是否必要？RQ3：共享 backbone 与分头是否有效？RQ4：critic 深度对成功率与计算成本的影响？注意 GiGPO 等带 † 的行取自原论文，协议未必完全同源。

Results & Table/Figure Reading

Table 1：1.5B 的 VETTA 在 ALFWorld 91.9±1.1%，WebShop success 73.8±1.1%，WebShop task score 83.9；GiGPO 分别 86.1±4.7%、67.4±4.5%、83.5。7B VETTA ALFWorld 95.5±0.4%、WebShop 76.0±0.6%，而 GiGPO 是 90.2±2.3% 和 75.2±3.8%；7B WebShop 的优势只有 0.8 pp，属相对较弱增益。Table 1 的分项任务中，7B 的 Pick 类 Turn-PPO 达 100%，VETTA 93.6%，说明不是所有类别都优于最强 baseline。Figure 1 对比纯 token、纯 turn、混合 credit 以及 critic 深度，支持组合信号；Figure 2 是双头 critic 与中心化融合的关键架构图；Figure 3 的单次运行显示共享双头 93.6/72.8%，独立 critic 89.3/58.4%，共享单头 91.4/65.0%；Figure 4 对比 28 层和 2 层，ALFWorld critic 计时中位数 152.0→19.7 秒，WebShop 92.2→7.9 秒，节省约 87%/91%。注意这是 critic 子系统耗时，绝不是完整 RL 训练 wall-clock 下降 87%。

Ablation / Claim vs Evidence

去掉 response 内中心化改直接相加，会把 token 优势的整体偏置叠加到轮级信用，破坏设计目的；只用一个 value head 或独立两个 critic 的单次实验成功率均较低，支持共享双头，但参数量与优化方式也不同，不能单独归因于表示共享。两层 critic 比 28 层更快且成功率更高，支持价值估计不必等同 actor 深度；尚未证明对 30B+、多工具真实浏览器、非平稳奖励或极长任务同样成立。论文作者声称双粒度与低开销兼得，实验确实支持两个模拟 benchmark；没有证明在线生产安全、跨域鲁棒或无 reward hacking。

Contribution / Limitation / Research Value

Contribution 1 [New Objective/Mechanism]：轮级优势与 token 中心化残差的组合；2 [New Engineering]：共享浅层 critic 双头；3 [New Empirical Finding]：双尺度信号互补且小 critic 够用。作者限制与额外限制：ALFWorld/WebShop 场景较窄；critic-free baseline 协议可能不同；对更稀疏、多 Agent 团队、不可逆动作、偏好奖励没有充分测试；value 学习可能被短期代理 reward 误导。研究价值：可作 Agent RL 信用分配强 baseline，也能为 memory write、tool-call 参数、跨 Agent message 提供分层信用，适合引入因果干预检验是否真的奖励关键决策。

Migration / Minimum Experiment

Original Problem：多轮 Agent 稀疏任务反馈 → Transferable Mechanism：层级优势+轮内守恒残差 → New RQ：对 memory write / retrieval / tool use 进行独立信用分配，能否提升长任务成功率并减少无效上下文？Method Modification：保留 VETTA turn/token head，新增 memory-event head，把写入/读取动作映射为第三个事件序列；每轮对 event residual 中心化，并设置预算惩罚。Minimum Experiment：Qwen2.5-1.5B，ALFWorld 与 WebShop，各训练 3 seeds×150 updates；Baseline PPO、Turn-PPO、VETTA、event-only、VETTA+event；Metric success、tool calls、memory token budget、wall time、seed 方差；再对最有信用的 memory 做 delete/replay 干预验证因果性。Expected Contribution：可解释的 Agent 行为与记忆信用。Risk：critic 头增多导致 value 不稳定；Collision：VETTA、HiPER 与已有 action-to-token credit-conserving 工作，需证明 memory-event 层的新增价值。

Reward / Stability / Replication Audit

奖励来源需要进一步拆解：ALFWorld 的主要评价是任务是否完成，WebShop 同时给 task score 和严格 success；前者更稀疏，后者存在“评分高但没买对商品”的优化错位。VETTA 并没有把一个新 reward model 放进训练闭环，而是通过 value critic 预测未来环境奖励。因此不能把 value head 的改进解释为 reward 更准确。跨轮 credit 的真正作用，是让最后才观察到的成功通过 GAE 传播回早期选择；轮内中心化则避免将整轮奖励重复叠加。训练稳定性上，γ/λ 与 α 决定长距离信用的方差和衰减：γturn 降低会弱化远期动作；α 太大会让 noisy token critic 主导更新。论文附录专门有 token-residual scale 敏感性分析，复现时应首先重做该曲线，而不是直接移植 α=3 到其他任务。还要区分训练步数与环境交互量：150 updates×128 rollout 是更新批次预算，不等于每条 rollout 都跑满 50/15 turns，真实 environment steps 与 training tokens 应从日志统计。对长时 Agent，错误参数可能通过工具执行改变环境，随后写入 memory、影响下一轮状态，单纯 final success 无法定位是哪一轮引入错误。建议加工具调用合法率、无效动作惩罚、rollout length、reward variance 和重放后成功率等诊断，并用相同随机种子比较。

Open Questions / Strongest vs Weakest

最强证据是两个模型规模、两个任务都给出明确成功率，并对 critic depth 做时间分解；最弱证据是 7B WebShop 对 GiGPO 仅 0.8 pp，且部分 baseline 的评估协议沿用旧论文。一个严谨后续研究应重新在同一训练预算、同一 seed、同一解码温度下跑 GiGPO、Turn-PPO 与 VETTA，附置信区间和训练稳定性曲线。还需测试在同一总 GPU-hours 下，浅 critic 节省的计算是否能换取更多 rollout，最终是否优于直接增加采样预算。

如果只记住五句话

第一，成功奖励不应无差别撒给每轮和每个 token。第二，VETTA 用 turn advantage 定总体功劳，用中心化 token residual 定内部差异。第三，1.5B 对最强 GiGPO 在两个任务分别提升 5.8 和 6.4 pp。第四，critic 时间减少 87–91% 不等于全系统训练加速同等幅度。第五，最值得迁移的是把 memory/tool/communication 也做成可检验的层级信用。

S · SquidAgent: Parallelize Wisely, Coordinate Efficiently Agent / Multi-Agent

SquidAgent: Parallelize Wisely, Coordinate Efficiently

arXiv:2610.08647 · Agent / Multi-Agent · 2026-10-06 UTC · Tier S

Paper / Abstract · Full text (if available) · Authors: Yexiong Lin, Shanshan Ye, Yu Yao, Zhen Fang, Bo Han, Tongliang Liu. Affiliation: 未逐作者核验；请以正文首页为准. Venue: NeurIPS 2026（arXiv Comments 已标注 Accepted）. Project: https://yexionglin.github.io/SquidAgent_Demo ; Code: 未核验公开仓库

人话版：这篇论文到底干了什么？

很多 Multi-Agent 框架默认任务越能拆就越应该并行，但现实里 worker 往往需要重新理解上下文、统一文件接口、修正相互矛盾的结果，最后反而比单 Agent 慢。SquidAgent 不再盲目开并行，而是让 orchestrator 一次性生成任务 DAG 和各子任务的预计输出 token，再计算每一层串行与并行的成本，只有预计收益足够大才并行。并行 worker 直接继承 orchestrator 会话，提前写共享约定以减少返工。九项生成任务平均交付吞吐从 Claude Code 的 17.2 提高到 38.1 words/s，相对最强 Multi-Agent baseline AgentConductor 提高约 2.0 倍，质量评分仍达 98.2%。这是 Agent 系统真正重视 wall-clock 和协调成本的代表工作。

Background & Research Gap

假设要开发电商网站，后台支付、前端商品页、数据库模型可以分工，但如果每个 worker 独立猜测 API schema，最终整合可能花的时间比开发更久。串行 Agent 会自然继承上文约定；多 Agent 并行失去这份隐式共享状态，产生 re-exploration 与 alignment 两类隐藏成本。以往 MetaGPT 强调角色，AFlow 搜工作流，MacNet 强调拓扑，AgentConductor 自适应协调，却未把这两类开销纳入明确的逐层执行判据。论文的关键是把“并行还是串行”当成有阈值的成本优化，而非固定系统设计。

Core Insight / Method Deep Dive

Input：用户任务 R → orchestrator 生成 DAG G、每个任务的预计输出 token τ_i、每层对齐 token 预算 C_align → 拓扑分层 → 计算每层 ρ → 高于安全阈值才 fork workers → 在并行层提前声明统一接口、命名、格式 → 合并交付物。公式：T_serial(L)=Σ_i τ_i；T_parallel(L)=max_i τ_i+C_explore(L)+C_align(L)。Session fork 使 C_explore 近似为 0，预先约定把事后对齐转为有界 Ĉ_align，故 ρ̂=Στ_i/[max τ_i+Ĉ_align]。仅当 ρ̂>α 才并行，α=1.9。分子是所有任务串行 token 量，分母是最慢 worker 的 token 量加协调成本。α>1 是不确定性安全边际；过大错过可并行机会，过小把高耦合任务错误并行。这里的 token 是 wall-time 的 proxy，不是推理模型的 KV token 压缩。

Toy Example / Baseline Deep Comparison

该方法解决的是不同 edge cut 的层深错位，因此系统实验必须固定网络带宽、edge 算力、模型大小、并发和 KV 放置。吞吐 +275% 的解释是同样时间处理的请求数约为 FIFO 的 3.75 倍；如果系统同时减少 per-session latency，需要核对是否只是把等待移到 edge 侧。尤其要分开 TTFT（首 token 前的 edge prefill、通信和 cloud 接续）与 TPOT（稳定 decode 每 token 时间）。DSB 可能对平均并发 8 有优势，但 batch=1 时不存在跨请求合并收益；batch 很大时 GPU memory 和 KV 容量可能反过来限制吞吐。Depth-synchronized 也不能减少每个请求必须执行的全部模型层计算，它主要让已有算力更连续、更批量地执行。向 Agent 推理迁移时，请求的输入 prefix、tool-return 长度和多轮突发性高度异构，适合研究 cache-aware DSB；但模型深度同步与 prefix cache 命中是两种不同的对齐维度，不能直接视为同一机制。

这里的“训练效率”来自 rollout-policy 同步等待时间下降，而不是 PPO/GRPO objective、advantage 或探索策略改变。典型链路是 trainer 完成一次更新，refit 传新权重，rollout worker 才能按最新 policy 采样；如果同步耗时 87.5 分钟，增加 GPU 并不能弥补屏障。Bit-exact 之所以重要，是因为对 BF16 的浮点增量做数值重建可能出现不同舍入，进而造成训练端和 rollout 端策略不一致，影响重要性比率与训练可复现性。XOR payload 保存的是位差，overwrite 直接写新位模式；joint commit 让多 worker 不会一部分用新版本、一部分仍以旧版本计算下一轮 delta。工程故障测试必须模拟网络中断、重复上传、对象存储部分可见和重试，并逐 tensor 校验 hash。跨区域 1T 的 150 秒数据很强，但真实端到端 Agent RL 的 speedup 取决于 refit 占总周期的比例：若 rollout 已占 90% 时间，refit 即使快 35×，总吞吐也不会快 35×。建议使用 Amdahl 定律解释加速上限。

refit 时间由 delta 生成、压缩、上传、网络传输、下载、解码、native loader 写入和版本提交组成。论文摘要的 12–40× 是对 transport-only full-checkpoint reference，不是对包含所有优化的最强生产系统，复现时要明确分母。若每轮参数变化率从 1% 上升到 20%，delta 的元数据和随机写开销可能吞掉优势；如果参数分布被量化重编码，stored-value change 的统计也会变化。应画出 change rate 1/3/5/10/20% 对 refit time 的曲线，并分别标记训练端 CPU、网络、rollout 端 GPU 是否成为瓶颈。

Reliability and Research Value

这种 refit 系统还与模型 provenance 直接相关：每个 rollout 应标记实际加载的 policy version、delta base version 和参数校验 hash，否则训练日志可能把旧策略样本当成新策略样本。对 PPO 等 on-policy 方法，这类版本错配会使 importance ratio 和 advantage 估计失真。研究层面最有价值的后续是“bit-exact + low latency + fault-tolerant”的组合评估，而非只把压缩率做高。生产环境需要报告故障后恢复到一致状态的时间和错误率。

Theory Boundary / Practical Experiment

minimax-optimal 是在论文定义的层级 reward 函数类、查询预算和 KL 约束下的最优速率，不代表所有 RL for LLM 任务都达到全局最优。与固定 reference 采样的理论分离说明探索分布能够逐步聚焦奖励区域，但如果 verifier 有系统性偏差，on-policy 也可能更快集中到 reward hacking 区域。实际验证应把训练 reward 和独立 correctness verifier 分开；对每道题记录解题步骤、候选多样性、KL 和最终准确率，避免只比较训练奖励。多 Agent 情况还需研究 exploration 如何跨 Agent 共享：共享轨迹可能提高样本效率，也可能让错误策略在多个 worker 中同时强化。

Reasoning Reward Caveat

理论上逐层显现的 reward 可以理解为先学会基础步骤、再触及更深层解法；但真实数学题奖励常只有最终答案对错，层级结构未必可直接观察。要把理论变成方法，可能需要 verifier、过程奖励或自动课程构造。若训练集只覆盖一种题型，on-policy 聚焦还可能造成探索坍缩，因此应同时报告题型多样性和 held-out 泛化。

12. Idea Mining

Idea 1 · Event-Boundary Evidence Budgeting for Video Agents

Inspiration：CtrlCache 的控制变化刷新、DIPrune 的迟到关键 token、Readiness 的证据充足信号。

Research Gap：现有视频加速常只优化时间采样、token 裁剪或缓存之一，缺少统一的“事件边界+语义演化+证据是否充分”预算机制。

Hypothesis：在控制变化或 query 证据尚不足时提高 frame/token 预算，稳定且证据已足时压缩；同等延迟下提升 QA/决策可靠性。

Proposed Method：构建 event score（控制/场景变化）与 token evolution score，先在帧级分配预算，再对保留帧做跨层 token pruning；readiness probe 决定继续观察还是回答。

Minimum Viable Experiment / Model / Dataset：Qwen-VL 视频版本或 Video-LLaVA；Video-MME、LongVideoBench。先用 200 条带事件标注视频，固定 3 种预算（例如 25/50/75% token），测真实 prefill latency、TPOT、GPU peak、答案准确率与 evidence recall；3 seeds，禁用额外大模型判别器。

Baseline：Baselines: uniform frame, query-aware frame, FastV/DIPrune, CtrlCache-style event-only.

Metric：Accuracy@latency、evidence recall、visual tokens、TTFT/TPOT、VRAM、wall-clock speedup。

Expected Contribution：New Mechanism：证据风险约束的跨帧/跨层预算，而不是单纯 token 剪枝。

Novelty：★★★★☆

Feasibility：★★★★☆

Compute Cost（星越多成本越高）：★★★☆☆

Risk：事件检测成本可能抵消加速；readiness 标签标注昂贵。

Collision Risk：HIGH：CtrlCache、DIPrune、Readiness 分别覆盖组件，必须用联合优化与因果/系统证据差异化。

Best Venue：CVPR / ICCV / NeurIPS

Idea 2 · Hierarchical Memory-Action Credit for Long-Horizon RL Agents

Inspiration：VETTA 的轮/词优势分解与 Agent memory 写入/读取的长期影响。

Research Gap：memory write 的即时 token reward 与未来任务价值脱节，工具调用成功不等于该记忆长期有效。

Hypothesis：在 turn/token 信用之外新增 memory-event advantage，可减少无效记忆并提升长期任务成功率。

Proposed Method：构建 memory-write/read 事件链及独立 critic head，event residual 以每轮中心化，增加存储预算和错误记忆惩罚；做 memory intervention 检验 credit 因果性。

Minimum Viable Experiment / Model / Dataset：Qwen2.5-1.5B；ALFWorld+MemoryAgentBench 子集；固定 150 updates，比较 VETTA、VETTA+memory head、reward-only memory penalty，三随机种子。

Baseline：PPO、Turn-PPO、VETTA、event-only。

Metric：Success、token-memory cost、错误记忆写入率、replay/recovery、time-to-solve、KL。

Expected Contribution：New Objective：memory event 的跨时 credit 与因果可验证性。

Novelty：★★★☆☆

Feasibility：★★★☆☆

Compute Cost（星越多成本越高）：★★★★☆

Risk：长期 reward 太稀疏，critic 方差增大；数据收集成本高。

Collision Risk：VERY HIGH：VETTA、HiPER、action-to-token allocation、MemPilot，必须证明独立 memory-event credit 的增量。

Best Venue：NeurIPS / ICLR

Idea 3 · Cache- and Tool-Aware Parallel Agent Scheduling

Inspiration：SquidAgent 的 token cost criterion、DySCo 的 batch-depth scheduling 与 Agent 会话复用。

Research Gap：SquidAgent 用 output tokens 代理耗时，但真实 Agent workload 的 prefill、cache miss、工具 IO 和环境副作用可能占主导。

Hypothesis：用实测 TTFT/TPOT、cache hit 与工具耗时替代纯 token 估计，在混合负载上减少错并行与重复 prefill。

Proposed Method：为 DAG 每层维护在线 latency predictor，fork 只共享权限允许的 context；scheduler 用预计关键路径+上下文 hydration+对齐+工具延迟做门槛。

Minimum Viable Experiment / Model / Dataset：30 个多文件 coding/web Agent 任务；固定模型/工具；比较 Always Serial/Parallel、Squid threshold、latency-aware、latency+cache-aware；每任务三次。

Baseline：SquidAgent、Claude Code、AgentConductor、fixed DAG parallel。

Metric：End-to-end wall time、TTFT、TPOT、tokens/s、cache hit、tool idle、质量、provenance violation。

Expected Contribution：New System：面向 Agent 推理链路的联合 context-cache-scheduling。

Novelty：★★★☆☆

Feasibility：★★★★★

Compute Cost（星越多成本越高）：★★☆☆☆

Risk：系统复杂、工具时间噪声大；需要真实日志与权限隔离。

Collision Risk：HIGH：SquidAgent 直接覆盖基础调度，必须强调真实系统指标与缓存/工具联合。

Best Venue：MLSys / OSDI / NeurIPS Systems
