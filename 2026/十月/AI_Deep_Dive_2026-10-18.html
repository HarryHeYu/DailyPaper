PAPER 01 · AGENT / MULTI-AGENT

ARIA · Runtime Inspection and Amendment

1. 基本信息与研究定位

题名：ARIA: Runtime Inspection and Amendment for Multi-Agent Systems。作者：Bolin Shen、Yushun Dong；机构：Florida State University。版本：arXiv:2610.20780v1，页面标注 2026-10-14，出现在 10 月 16 日 cs.AI 新稿列表；BACKFILL（比严格 72 小时窗口略早，但机制价值高）；目前按预印本处理，Venue：未报告。论文：arXiv 正文 / PDF；代码：LabRAI/ARIA，仓库包含 src/aria、src/repair、src/inference、configs 和评测脚本，已公开，不等于所有模型权重与原始轨迹都完整开放。

一句话定位：把多 Agent 执行中的“事后发现哪里错了”推进为“运行到错误边界时，低成本识别、定位并替换下一条可执行消息”，通过执行验证的历史修复轨迹训练一个跨框架的干预策略。

1.1 人话版（先理解问题）

假设一个编程 Agent 把需求交给规划 Agent，后者误把“不能删除用户文件”理解成“允许清空临时目录”，接着执行 Agent 根据错误计划发出危险指令。等最终测试失败才回看日志，虽然能找到原因，却已浪费工具调用，甚至可能改坏环境。ARIA 的想法是：先离线收集大量真实失败轨迹，在失败发生的位置切断旧轨迹，提出新的消息或步骤，真正恢复执行并用任务评测器确认成功；然后把“错误是什么、该在哪一步截断、用什么替换、是否值得干预”作为训练目标。作者汇集超过 2.4 万条轨迹，筛出 3953 对经过执行验证的修复样本；再用结构化监督、偏好学习和执行反馈优化，让较小的修复模型在其他 Agent 继续运行之前做检查。其意义不是宣称可以任意回滚多 Agent 系统，而是把验证成本从每次在线搜索移到离线数据建设，并把修复收益与误干预风险放进同一决策问题。

2. Background、Gap 与核心观察

传统 MAS（Multi-Agent System）靠角色分工提升任务覆盖：MetaGPT 是相对固定的角色流水线，OpenManus 偏工具调用与委派，Magentic-One 通过 ledger 协调，AG2 使用群聊式消息路由。系统的难点不止单模型幻觉，而是错误沿依赖边传播：一个 Agent 的未经核验陈述成为下游 Agent 的前提；后续工具执行会把错误固化成外部状态。此时“发现错误”与“能修复错误”不是一回事。

已有 Who&When 偏向定位责任 Agent 和步骤；AgentRx 从约束与工具规范追踪故障；ErrorProbe 结合回溯与执行验证形成诊断；DoVer 能尝试消息或计划编辑并重放，因而在“验证具体补丁”上更接近 ARIA。然而这些方法若在每次新故障出现时反复试错，在线成本会高，而且定位标签未必告诉模型如何输出一个能被执行器接受的替代事件。ARIA 的 gap 是把事后验证过的干预变成可迁移的运行时预测能力。

核心洞察一：采集数据时不能只找“最容易失败”的 Agent，也不能只找“最容易修复”的 Agent；要找失败概率与条件修复率乘积最大的配置。核心洞察二：训练数据必须包含未修复执行仍失败、修复执行确实成功的成对证据，而不是语言模型给补丁打高分。核心洞察三：在线干预要控制 false positive——原本会成功的运行被改坏，与恢复一个失败同样重要。这三项分别属于统计产出率原则、执行层实证构造和成本敏感控制设计，尚不能自动推导出普遍的因果定位正确性。

3. Method Deep Dive：从离线轨迹到在线修复

流程：配置候选 MAS×Benchmark×Host → 收集成功/失败轨迹 → 定位首个坏事件与归因 → 在切点替换后缀并成对重放 → 留存执行验证样本 → SFT → DPO/诊断迁移 → GRPO/门控优化 → 运行时检查待交付消息 → 合法时替换并继续。

3.1 数据源选择：repair-optimality

一个 source cell 为 c=(A,B,M)，分别固定多 Agent 框架、任务分布和 host 模型。设 a(c) 为源运行通过概率，r(c) 为在源运行失败的条件下补丁经评测通过的概率，则每次源运行得到有效修复样本的期望率为：

S(c) = [1 − a(c)] · r(c)；N 次有效源执行的预期验证修复数 = N·S(c)

例子：系统甲失败率 80%，失败后仅 10% 能修复，S=0.08；系统乙失败率 40%，失败后 50% 能修复，S=0.20。即便甲更“脆弱”，乙每 100 次运行预期提供 20 条有效训练样本，而甲只有 8 条。这是产出率计算，不是新型 RL objective。必须把基础设施故障、评测器无结果与真正认知失败分开，否则 1-a 会被无关错误污染。

3.2 事件归一化、定位与修复证据

把原生 MAS 消息、工具事件、工作区工件统一成有稳定 event ID 的可观察序列 τ=(e₁,…,e_T)；每条含角色、类型、内容及工具字段。长日志默认最多保留 64 个事件（最初 4 个和最后 60 个），所以“最早错误”只能相对于可见片段确定。定位模块先输出错误事件、证据、置信度；归因模块将其归入 6 组 26 类 repair attribution，并给出修复操作；补丁模块生成 diagnosis + cut-event ID + replacement events。合法补丁需遵守 ID、角色和顺序约束，不能凭空伪造工具结果，最多八个替代事件。

τ′ = (e₁,…,e_k) ∥ (ê₁,…,ê_L)；保留 e_k，删除其后旧后缀，再接替代事件。

关键是paired execution：同一任务、同一切点下，原控制轨迹仍失败，修改后通过官方 evaluator 才算 verified pair。单纯 JSON 合法、LLM 说“看起来修好了”都不够。这个设计增强了可操作证据，但环境随机性与多条可行修复并存意味着它不是唯一因果解释的证明。

3.3 三阶段训练，实际细分五个训练相位

Stage 1 / Structured SFT：把结构化输出分解为诊断 d、切点 k、替代事件 e，分别条件建模，并用部分前缀训练 inspection gate gθ(τ≤t)。反馈 dropout 让模型既能读完整失败及 evaluator feedback 做 post-hoc，也能在没有最终答案的 runtime 使用。损失可以理解为三项负对数似然相加：

L_SFT = −E[log pθ(d|x̃) + log pθ(k|x̃,d) + log pθ(e|x̃,d,k)]

最重要的 failure mode 是级联错误：诊断错会让切点与补丁都错；门控把成功轨迹误判为失败，会制造新故障。附录把首个坏事件索引 b 对应的门控目标设为 1[t≥b]，正文采用相应切点之后的判别写法；复现时应以项目的数据投影规则核对 off-by-one，而不是混用两种事件索引。

Stage 2 / Outcome-anchored DPO + Diagnosis Transfer：对同一可见前缀，成功补丁 a⁺ 优于失败旧后缀或失败补丁 a⁻；用 SFT 检查点作为参考分布，增加成功补丁的相对对数几率：

L_DPO = −E log σ{ β[(log πθ(a⁺|h)−log πref(a⁺|h)) − (log πθ(a⁻|h)−log πref(a⁻|h))] }

β 调节偏好强度相对参考策略的约束。诊断文字本身没有执行结果，作者使用“给相似事件提供诊断后，正确补丁的对数似然提升”作为迁移 proxy；这一步不是直接证明诊断因果正确，只证明对预测修复有帮助。

Stage 3 / Execution-grounded GRPO + Gate GRPO：从当前策略采样修复，实际恢复执行，奖励包含任务是否通过、是否有害、执行开销：

r(y|x)=1[evaluator accepts] − λ_h·1[harmful] − λ_c·b(y)

对诊断 d 的奖励混合源事件及不同 source cell 的 sibling repair 结果：V(d)=(1−α)·平均源奖励 + α·平均跨 cell 奖励；α 越高越重视跨框架迁移，但可能牺牲本 cell 最优修复。诊断 token 与补丁 token 分别做组内优势归一化，近似 GRPO；随后门控在相同随机种子的原始与干预运行之间优化：

r_gate = Success_intervened − Success_baseline − λ_c·ΔExecutionBudget

这里 state 是可见事件前缀，action 是“不改”或“定位+替代消息”，policy 是门控与修复模型，trajectory 是整个 MAS 运行，reward 是官方执行反馈，credit 分配到诊断、补丁和触发决策。它并非环境每一步都有 dense reward：大部分任务结果仍是稀疏二值信号，且 GRPO 需要额外 rollout；reward hacking 风险包括针对公开评测器过拟合、通过选择简单可修复样本获得虚高收益。附录特别指出当前 reference trainer 单次 inner update 的概率比为 1，不应把配置了 clipping 就宣传为多轮 PPO。

3.4 运行时可实施的边界

作者的四个原生接入点都位于模型回答交付前。门控看当前待交付回答与历史，触发时产出建议，宿主验证合法性后决定是否替换。现有实现每次运行最多替换一条待发出的纯文本消息；不能直接修改 tool-call 结构化结果、回滚已经发生的工具动作或执行多事件重放。论文里训练补丁可描述更长的 continuation，但当前 live adapter 不等于具备完整回滚能力。运行时 EB=1 只表示没有再次执行整套 MAS，不表示 inspection 模型调用和 token 开销为零。

4. Toy Example：一条错误如何被拦住

设三个 Agent：Planner、Coder、Reviewer。任务是“计算订单金额，但退款记录应排除”。Planner 事件 e₁ 给出字段；Coder 待发事件 e₂ 写成 SUM(amount)，漏掉 status != refunded；Reviewer 后续会执行 SQL 并交付错误总额。历史失败轨迹为 [e₁,e₂,e₃,e₄]。ARIA 在 e₂ 即将交付时读到“退款记录也被计入”的约束冲突，门控触发；定位 k=1，归因为过滤条件遗漏，建议将 e₂ 改为 SELECT SUM(amount) FROM orders WHERE status != 'refunded'，保持 Planner 已确认的上文不变。宿主校验这只是合法纯文本替换后交付，后续 Reviewer 重新检查结果。

离线构造样本时，还要把替换前的运行与替换后的运行送到同一测试用例执行，证实前者失败、后者成功。运行时不能偷看答案，也不能凭“Reviewer 可能会修正”预先声称成功。若 Planner 已经删除数据库，则文本替换也无法恢复：这是当前接口的不可逆动作边界。再若 Coder 原本 SQL 正确，误触发反而会引入损害，因此 gate 的代价必须与修复能力共同优化。

6. Experiment Setup 与 Metrics 教学

RQ1：给定失败轨迹，能否以近似同样的重执行预算完成更多修复？RQ2：换一个未见过的 MAS，修复策略能否迁移？RQ3：SFT、偏好学习、执行优化各自起什么作用？源轨迹覆盖 MetaGPT、OpenManus、Magentic-One、AG2 四框架；GSM-PLUS、MMLU、HumanEval、OlympiadBench、GAIA、SWE-bench-Lite 六 benchmark；源 host 含 Llama-3.1-70B、Qwen3-8B/32B、GPT-5.5 不同 reasoning tier、Claude-Sonnet-4-6 与 Claude-Opus-4.8。被训练的 repair backbone 是 Qwen2.5-Instruct 1.5B/3B/7B/14B 及 Llama-3.1-8B，不应把 host 模型与修复模型混淆。

数据按任务 ID 做 nominal 60/20/20 训练/验证/测试，避免同一任务不同轨迹跨 split；未见系统测试将相应框架全部从训练、校准与选 checkpoint 中排除。SWE-bench-Lite 通过官方 Docker harness 验证，HumanEval 运行测试，GAIA 使用公开 quasi-exact answer matching；无法解析评测输出不等于失败。Reference recipe：Qwen2.5-7B、seed42、1 epoch、AdamW、LR 2e−4、LoRA rank16、BF16、梯度累积8、最大 4096 token、prompt 1024 token、feedback dropout0.25、DPO β0.1。配置值不是所有 release checkpoint 的实测训练账单；实际 GPU-hours、完整训练 tokens Not Reported。

SR（Success Rate）：通过任务数/该测试池任务数，越高越好；post-hoc 分母是确认失败的任务，runtime 分母是所有任务，因此两种 SR 不能互换。HIR（Harmful Intervention Rate）：结构错误、违反任务约束或实际替换造成评分下降的任务数/全测试池，越低越好；不是“在所有触发里有害的比例”。EB（Execution Budget）：平均每题完整 MAS 执行次数，越低越省重跑；但忽略局部模型推理、检查延迟与 token，需同时报告 wall-clock 和调用费用。报告中只给了 EB 作为主要成本指标，不可将 EB=1 解读为实时零开销。

PAPER 02 · VIDEO ACCELERATION

GSRS · Growing Sparsity and Reduced Search

1. 基本信息与一句话定位

题名：Sparse Attention for Video Generation Acceleration via Growing Sparsity and Reduced Search；方法简称：GSRS。作者：Yun Dai、Yuyun Chen、Jiarui Wen、Huiping Zhuang、Cen Chen、Ziqian Zeng；机构：South China University of Technology。版本：arXiv:2610.21129v1，2026-10-15，10 月 16 日列入 cs.CV 新稿；Venue：未报告，按预印本处理。正文：arXiv HTML；PDF：原文 PDF。代码状态：截至本次核查，正文没有提供 GSRS 专属官方仓库链接；文中给出 TileLang、Block Sparse Attention 的实现依赖，但不应把依赖库链接当作本方法已开源。

一句话定位：不是在每一步都固定保留 25% attention，而是依据视频扩散过程“越到后期越集中”的实测规律，让稀疏程度随去噪进程增长，并用早期候选集降低后续搜索成本。

1.1 人话版（250–400 字）

视频生成模型通常不是一次画出整段视频，而是在几十轮去噪中不断修改视频潜变量。每一轮的 DiT 都要让海量时空 token 彼此做 attention；长视频、高分辨率下，这个过程非常贵。以往稀疏 attention 虽然能跳过部分 token 对，但常常全程使用相同稀疏率，还要花不少时间判断哪些块值得保留。GSRS 首先观察到：去噪早期注意力分布较散，后期逐渐集中在少量且较近的块上；而早期找到的重要块往往在后期仍有用。于是它在最初完整计算一段时间，随后每隔若干步重新选块，但每次保留的累计注意力概率门槛逐步降低；并且第二次起只在第一次确定的候选集内搜索。为了避免使用上一轮 softmax 归一化因子造成误选，它把精确块权重统计融合进 FlashAttention。论文在两种 720p 视频 DiT 上报告 A800 端到端 1.55×/1.68× 加速，在 H800 附录最高 2.21×；质量与完整 attention 接近。它的价值在于把动态计算预算、候选复用、准确统计和真实 wall-clock连成闭环，而不只是报告 FLOPs 下降。

2. Background、Research Gap 与核心机制

标准 self-attention 先算 Z=QKᵀ/√d，再对每个 query 行 softmax，最后乘 V。当序列长度 L 随视频帧数与空间 patch 数一起增加时，QKᵀ 规模为 L×L；复杂度近似 O(L²d)，中间显存也可能成为问题。FlashAttention 通过分块与在线 softmax 降低 HBM 读写，但它不会自动把所有无用 query-key 配对消掉。块稀疏 attention 则只计算重要的 (query block, key block) 组合，必须支付“找出重要块”的搜索成本。

旧范式有两类：静态窗口或预设稀疏形状，部署简单但容易漏掉跨帧长程关系；动态搜索按输入计算重要块，适应性更好却可能花掉大量额外时间。进一步地，如果一整段去噪过程都用同一稀疏率，就等于假定早期结构建立与后期细节修补的 attention 需求相同。GSRS 正是填补这个跨 denoising timestep 的预算分配缺口。例如 50 步去噪中，第 10 步还在决定整体运动，若仅保留极少块可能丢掉关键远程依赖；第 40 步可能主要修复局部纹理，仍然全局密集计算则浪费。

Observation 1：论文 Figure 1 在 Wan2.1 与 HunyuanVideo 上观察到 attention entropy 与 mean attention distance 随去噪步数总体下降，表示权重更集中、依赖更局部。Observation 2：Figure 2/3 显示早期高权重块在后期保留相当高的 attention recall。它们是跨模型、提示词、head 的经验趋势，不是对每个 query/head/提示词都成立的数学定理；突发运动、场景切换可能违反。由此得到两个机制：Growing Sparsity（后期提高稀疏率）和 Reduced Search（后续只在早期大候选集里找）。第三个关键工程观察是旧步的 LSE 可能漂移，导致块重要性估计失准。

3. Method Deep Dive：逐步走过整个 pipeline

流程：Video prompt/latent → 3D token Hilbert/Gilbert 重排 → 前 20% 去噪步 Full Attention warmup → 首次全空间块重要性统计 → Top-p 建立基准候选集 S₁ → 非搜索步复用当前 mask → 后续搜索步只在 S₁ 内重算块权重 → 递减 p 更新 mask → sparse attention → 最终生成视频。

3.1 空间-时间 token 重排与 warmup

将 3D 视频张量直接按行优先展开，可能让真实空间邻近的 token 落在不同块中，导致块稀疏结构不符合运动连续性。作者使用 Generalized Hilbert/Gilbert curve 将时空邻近位置映射到更相近的一维顺序，提升块内局部性。实验块大小 B=128。这不是 GSRS 独有的新理论，但决定了“邻近 attention”能否变成真实块级跳过。

50 步去噪的前 20%（默认十步）先走 full attention。第 10 步第一次在全空间做块权重统计，形成 S₁。早期 warmup 让结构建立阶段避免激进剪枝；其代价是最初若干步不省计算。注意它是推理时 warmup，不需要微调 DiT 权重；论文并未证明可以完全取消 warmup。后续搜索步是 20、30、40，非搜索步沿用最近一次 mask。

3.2 Growing Sparsity：Top-p 与时间表

对某个 head、某个 query block，按 key block 重要性从大到小排序，选最小集合，使累计归一化权重 ≥ p。与固定 Top-k 的本质差异：若某 head 的前 5 块已覆盖 95% 注意力，则 p=.95 只需 5 块；若另一个 head 很分散，可能要 20 块。相同 p 自动产生不同稀疏率，避免给所有 head 同一计算预算。

默认在 {10,20,30,40} 四个搜索步使用 {0.95,0.90,0.85,0.80}。越往后门槛越低，意味着可以跳过更多块，但这里不是“保证每步恰好少算 5%”；Top-p 的保留数量由每个 head 的实际分布决定。失败模式：如果后期某段运动突然要求远距离依赖，固定下降 schedule 可能删掉新重要的远程块。最自然的改进是基于当前不确定性自适应调整 p，而不是盲目下降。

3.3 Reduced Search：为什么始终回到 S₁，而非上一轮 mask

第一次搜索在全空间找出较宽松的 S₁，此后在每个搜索步都对 S₁ 内的块重新打分，生成新的 S_k。这里容易误解为 S₄⊂S₃⊂S₂⊂S₁ 的永久单调删减；实际上 S₂、S₃ 可以彼此不包含，只需都属于 S₁。某块在第 20 步没入选，仍可能在第 30 步被重新选中。相比“上一轮 mask 搜索”，它允许候选集内部的回归；相比“每次全空间搜索”，它节省大量块重要性计算。

例如 S₁={A,B,C,D,E}，第二次选 {A,C,D}，第三次若 C 变弱、B 变强，可以选 {A,B,E}。只查上一轮 {A,C,D} 会永远丢掉 B；GSRS 的 S₁ 限制保留了这种恢复能力。不过最初不在 S₁ 的 F 从此不可见，因此它仍有早期候选偏置，不能说“所有未来重要块都能恢复”。

3.4 关键公式：为什么旧 LSE 不够精确

记 query token i 对 key token j 的 score 为 z_ij=q_iᵀk_j/√d，当前行的 log-sum-exp 为 L_i=log Σ_j exp(z_ij)。对于 query block u 与 key block v，块重要性定义为行均值：

W_uv = (1/B) Σ_(i∈u) Σ_(j∈v) exp(z_ij − L_i)，且在同一候选归一化空间 Σ_v W_uv = 1。

问题是 FlashAttention 逐个读 key block 时，完整 L_i 要到最后一个块处理完才知道。若拿上一去噪步 L_i^old 代替当前值，则每个 query 行被乘上 exp(L_i^new−L_i^old)；不同 query 行乘数不同，聚合后不仅 Top-p 总和不再为 1，连两个块的相对排名都可能翻转。这正是论文区别于单纯 cached-LSE 近似的机制重点。

作者在每个 key block 内计算数值稳定的块 log-sum-exp：

m_iv = max_(j∈v) z_ij；G_iv = m_iv + log Σ_(j∈v) exp(z_ij − m_iv)

等整行当前 L_i 可用后，再恢复：

W_uv = (1/B) Σ_(i∈u) exp(G_iv − L_i)

这两相设计只存每个 query 行与 key block 的一个标量，不必保存完整 L×L 权重矩阵。精确性限定：在后续 search step，它是对当前候选 S₁ 中 key 集合的归一化精确权重，不是对早已排除的全空间块重新恢复；这一区分决定了所谓 exact importance 的适用边界。数值稳定的 max-subtraction 也不能防止候选集本身遗漏关键块。

3.5 Toy Example：从注意力权重到 mask

假设某 query block 对五个 key block 的当前归一化权重为 [0.40,0.30,0.15,0.10,0.05]，按重要性排序即 A、B、C、D、E。第 10 步 p=.95，累计 A+B+C+D=0.95，得到 S₁={A,B,C,D}；E 从后续搜索空间剔除。第 20 步，在 S₁ 内重新归一化后权重假设为 [0.55,0.25,0.12,0.08]，p=.90，选 A+B+C=0.92。第 30 步 B 变弱、D 变强，候选权重变为 [0.60,0.05,0.10,0.25]，p=.85，选 A+D=0.85；D 可以“重新出现”，尽管上一步未入选。第 40 步 p=.80 时再选最少覆盖 80% 的块。非搜索步直接沿用上次选择，无需重新全量打分。

若错误地使用上一轮 LSE，使某行块权重总和从 1 放大为 1.2，那么 p=.90 可能只需选择前两块就“虚假达标”，导致漏算。这个小例子说明为何“候选复用”和“当前 LSE 统计”必须共同实现；若只把 p 调小而不处理估计误差，很难区分真实可稀疏与测量偏差。

7. Ablation、Claim vs Evidence 与局限

逐项看“去掉什么→指标怎么变→机制含义”：把当前 LSE 换成缓存 LSE，PSNR 31.96→25.32，说明权重归一化偏差可能导致错误 Top-p；去掉 Reduced Search，latency 1825→1990s，说明限制候选确实省成本；把候选改为上一轮 mask，PSNR 31.96→30.87，说明允许候选集内部重新进入有帮助；固定 p=.90，PSNR 30.28 低于递减策略 31.96，说明跨步预算合理。注意这些是组件消融的性能因果证据，不是严格证明“entropy 下降导致质量不变”的数学因果链。

Authors Claim：GSRS 无需训练，利用注意力动态减少无用计算，并在两种视频 DiT 上取得 1.55–2.21× 速度提升。Experiments Actually Show：指定模型、分辨率、50步、VBench 提示词和 A800/H800 条件下，attention density 显著下降，实际延迟下降且聚合质量近似维持。What Is Not Yet Proven：视频任意长度与场景切换下稳定；极端 prompt 的最坏质量；不同显存带宽和 batch size 下的加速；与 KV/feature cache、量化、distillation 组合是否互不干扰；对 streaming video VLM 是否可直接套用。

Contribution 分类：① New Empirical Finding：跨 denoising step 的 entropy/distance 下降及早期块 recall；② New Mechanism：递减 Top-p + 基准候选集反复搜索；③ New System/Engineering：fused 当前 LSE 块权重统计；④ New Objective：并无新训练目标，主要是推理调度与算子实现；⑤ New Benchmark：没有新数据集。作者明确局限：至少需要初始 full-attention warmup，研究范围限定视频 DiT。额外局限：主表未提供同配置峰值显存，但附录 Table 6 提供另一 125 帧配置的显存；能耗、总 FLOPs 和大 batch serving 未报告；块重排可能改变 cache layout；早期遗漏的块无法再进入；Top-p 的统计与排序本身有成本；单 GPU 的 end-to-end 数字不能直接推断多卡吞吐。

8. Reproduction View：从简化版到真实内核

若无官方 GSRS 仓库，先做算法级最小实现：用 PyTorch 生成一个小型多 head attention 张量，按 B=16/32 分块，计算全量 softmax 的真实块权重 W_uv，实现 Top-p 排序、S₁ 候选集、递减 p 与 mask 复用。先写单元测试：Σ_v W_uv≈1、缓存 LSE 漂移会导致错误累计、mask 可以在 S₁ 内重新进入、不同 head 的保留块数不同。然后接入可跑的公开 Wan2.1 小规模推理或论文相同的 14B 模型；在单 GPU 先固定 seed、prompt、latent shape 和 50 步，用 hook 保存每层每头每步 entropy、distance、候选 recall 与 wall-clock。

完整系统复现要遵循：CUDA12.8、TileLang fused search、Block Sparse Attention 非搜索步 kernel、Generalized Hilbert 重排、B=128、10/20/30/40 搜索、p=.95/.90/.85/.80、前十步 full attention。要分别测 kernel-only、search-step、non-search-step、whole-video latency，报告 GPU 型号、驱动、dtype、batch、峰值显存。首跑实验建议固定 20 个 VBench prompts 做 Full vs GSRS 的 paired-seed 视频生成，复现 Hunyuan 3057→1825s 的方向与 VBench-Q 接近；若硬件不足，先做缩短帧数的趋势验证，不宣称复现了论文主表。

最容易踩坑的是：把 p 当成保留比例；把候选内的 exact LSE 误当全空间 exact；只比较 attention FLOPs 不计 search/重排；使用不同随机种子计算 PSNR；误把 H800 2.21× 写成 A800；或直接把单步内核加速当作整段视频加速。每次报告都必须注明测的是 kernel、denoising step 还是 end-to-end。

9. Research Value 与两条研究迁移

Baseline Potential：适合作为训练自由的 DiT attention 稀疏基线。Migration Potential：跨时间动态预算分配可以迁移到视频理解、长上下文推理与流式感知。Systems Potential：精确块权重统计与可复用候选集可成为通用 GPU attention primitive。Attack Potential：构造低频出现、但决定视频内容的远程块，攻击早期候选稳定性假设。Evaluation Potential：增加 worst-case attention recall、quality tail-risk 和 latency P99。Benchmark Potential：镜头切换/高速运动/长视频场景的稀疏失效测试。New Paper Potential：用动态风险预算取代固定 p schedule，但须与 AdaSpa、LiteAttention、GSRS 及近期动态 token pruning 做明确 collision 检索。

Migration A：Query-Aware Dynamic Sparsity for Long-Video VLM

Original Problem：GSRS 依据去噪步分配注意力预算。Transferable Mechanism：按信息集中度调预算、早期候选集重用、精确归一化块权重。New Research Question：视频理解中，query 不同、帧间变化不同，能否自适应保留关键时间块并减少 VLM prefill？Method Modification：把 denoising step 改成视频时间窗口或层深；候选集由初始粗采样帧与 query cross-attention 形成，按窗口 entropy 与运动变化调 p；允许镜头切换触发全空间刷新。Minimum Experiment：固定 200 个 Video-MME/LongVideoBench QA，采样 32/64/128 帧；比较无压缩、固定 token budget、静态 Top-k、动态 p+候选刷新；每题同 seed、同模型，记录 frame recall、visual token 数、TTFT、GPU 峰值与 QA accuracy。Model：Qwen3-VL-8B 或可用的 LLaVA-OneVision-7B；Dataset：Video-MME 与 LongVideoBench；Baseline：uniform frame sampling、FastV、VisionZip/VETO（按可用实现）；Metric：QA accuracy、TTFT、prefill tokens/s、P99 latency、attention recall；Expected Contribution：以 query-conditioned risk 控制视频 token 预算；Risk：VLM attention 不一定呈现 DiT 的去噪单调规律，候选生成开销可能抵消收益；Collision Risk：与 VETO、TTF、CaCoVID 等视频 token 压缩高度相邻，需把“风险触发的候选刷新”做成核心差异。

Migration B：Worst-Case Sparse Attention Audit for Video DiT

Original Problem：GSRS 的早期 S₁ 限制可能漏掉后期突然重要的块。Transferable Mechanism：以候选 attention recall 与质量损失为验证信号。New Research Question：哪些运动/镜头模式导致 early-candidate 假设失效，能否在质量损失前检测并重建候选集？Method Modification：定义每步 full-attention shadow recall R_t=Σ_{v∈S₁}W_uv，使用少量随机 head/probe 估计 R_t；低于阈值时执行一次 full refresh，并对 p 做局部回退。Minimum Experiment：选 50 个 VBench prompt 加 50 个程序化“快速移动/突变场景”prompt；同 seed 生成 Full、GSRS、GSRS+Refresh，记录每层/head 最低 recall、PSNR P10、VBench-Q、latency、refresh 次数，扫阈值 0.8/0.9/0.95。Model：Wan2.1-T2V-14B（算力不足先用缩小模型作机制验证）；Dataset：VBench + 自建 stress prompts；Baseline：Full、GSRS、固定 p、定时全刷新；Metric：tail PSNR、VBench-Q、P99 latency、worst-head recall；Expected Contribution：稀疏注意力最坏情况评测与自恢复策略；Risk：shadow probe 的计算开销、质量损失与 recall 不完全对应；Collision Risk：与动态稀疏搜索及异常刷新方法可能重合，须展示“最坏风险可控”而非仅均值加速。

跨论文综合、研究机会与 Collision

1. Cross-Paper Synthesis：两篇共同说明什么

今天两篇看似分别研究 Agent reliability 和 Video DiT acceleration，实则都在回答一个系统问题：何时应当花费额外计算或修改执行路径，何时应当保留原路径？ ARIA 让检查器只在预期修复收益大于误干预风险时改变待发消息；GSRS 让 attention 在当前概率质量足够集中时减少块计算，并在需要时重新搜索。前者的错误代价是“把本来正确的运行改坏”，后者的错误代价是“跳过本来重要的注意力块”。两者都需要可验证反馈、选择性执行和明确成本，但优化目标并不相同，不能强行说它们提出同一方法。

ARIA 通过同 seed 的 baseline/intervention paired execution 估计真实任务收益；GSRS 通过 full attention 对照、精确 LSE 权重统计、质量指标和 wall-clock 验证稀疏决策。值得迁移的是先定义可测的干预风险，再决定预算，而不是简单把 Agent 的 GRPO 套到 DiT 或把 GSRS 的 Top-p 直接搬到 Agent memory。两者也暴露相同的“早期决策锁死未来空间”风险：ARIA 只看截断的 64 个事件，早期被裁掉的根因可能不可见；GSRS 把未来搜索限制在最初的 S₁，候选外的后来重要块无法回来。它们都值得加入周期性 refresh、置信度不足时回退与长程失效监测。

2. Combined Research Opportunities

Opportunity A — Risk-Calibrated Selective Intervention：将系统的每次干预统一表述为 Expected Benefit − Harm Probability×Harm Cost − Compute Cost。在 Agent 上 benefit 是任务恢复概率，harm 是破坏原本正确的执行；在 Video 上 benefit 是减少 attention latency，harm 是输出质量的尾部下降。最小验证不要求联合训练两种模型：先在 ARIA 记录 gate 的置信度分桶与实际 harm rate；在 GSRS 记录每步 entropy、candidate recall、PSNR P10；分别做风险校准曲线，再看是否能用同一个预算控制框架解释两种系统。

Opportunity B — Counterfactual State/Attention Audit：为每次“保留还是跳过”保留 shadow 证据。Agent 保存原消息与替代消息并做 paired run；Video 对少量 sampled heads 周期性执行 full-attention probe，与 sparse 输出比较。统一记录 (state_id, action, estimated_risk, observed_outcome, compute_cost)。研究价值在于提出一个通用的 intervention ledger，而不是仅以最终成功率或 FLOPs 评判策略。

Opportunity C — Long-Horizon Recovery Benchmark：故意让 Agent 的错误摘要跨多次 handoff 传播，同时让视频模型的关键运动块在后半段才出现。观察系统是否有能力“重新打开被排除的候选”，并分别统计修复时延和质量尾部风险。这里的共享概念是候选空间随时间收缩带来的不可恢复性；但两个任务的因果机制不同，应分别设计基准，最后再比较抽象规律。

3. Collision / Overlap：哪些已经有人做

直接论文 Collision：NONE。ARIA 的主题是执行验证的 MAS 在线修复，GSRS 是视频扩散注意力调度，研究对象与实验协议不相同。方法级重叠：明显存在：ARIA 与 DoVer、Who&When、AgentRx、ErrorProbe 在诊断/修复任务上相邻；GSRS 与 AdaSpa、LiteAttention、SVOO、SVG2 在稀疏选择上相邻。研究迁移时要避免“再做一个 gate”或“再把 p 设成动态值”这种薄创新。潜在新意必须落在可证伪的新设置：如不可逆动作下的可实施性证明、最坏 head recall 下的质量保障、跨会话状态 provenance、实时计算成本的校准。

两篇还有证据类型差异：ARIA 的 SR/HIR 是任务结果与有害干预率，能比较任务级影响，却不能直接给出毫秒级系统效率；GSRS 的 latency 是真实端到端时间，质量评测仍是 VBench 与 full-attention 相似度，不能保证所有主观视频质量。对任意“更安全且更快”的新论文，应同时要求可验证任务结果、真实 wall-clock 和 worst-case failure，而不是只选一种好看的指标。
