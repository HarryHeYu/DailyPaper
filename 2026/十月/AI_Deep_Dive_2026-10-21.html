Paper 1 · WeAct: Dynamic Weight Switching as Agent Actions

定位：把“使用哪一组模型权重”从部署时固定的配置变成 Agent 在一条轨迹中可调用、可验证的内部动作；同时以能力对齐的独立 LoRA 避免不同阶段训练互相覆盖。

1. 人话版（先建立直觉）

一个研究型 Agent 可能先拆解问题，再搜索网页、核验证据，最后写报告。常规训练把这三种本领揉进同一套参数：搜索能力增强时可能冲掉写作能力；即使分别训练三个 LoRA，简单相加或静态合并也会让它们在推理时互相干扰。WeAct 的处理不是训练一个复杂的专家门控网络，而是让 Agent 像调用搜索工具一样调用 load_lora 和 offload_lora：需要规划就启用规划权重，需要搜索就切换搜索权重，最后启用写作权重。上下文历史继续保留，改变的是下一步生成所用的参数。Qwen3-32B 的八个深度研究基准上，强制阶段切换版本平均准确率 45.47%，高于 Full SFT 的 42.80%，也高于最佳静态合并的 35.66%。但它并不是免费午餐：切换权重需要重建 KV cache，动态路由不如强制流程稳定，模块内部的持续学习遗忘仍然存在。

2. Background & Research Gap：为什么原方案不够

现实场景：用户问“某项政策如何影响三个地区的能源市场，并给出证据”。Agent 先列约束，再发多个搜索查询，检查来源，最后写一篇带引用的回答。规划要求任务分解，搜索要求外部事实对齐，写作要求长文组织；三者不仅目标不同，梯度方向还可能冲突。一个统一的 Full SFT 模型会更新同一套大参数，后续训练可能使先前能力退化。一个 Single LoRA 仍在同一低秩子空间里承载多个任务。若改为三个独立 LoRA 但先做 TIES / DARE-TIES 合并，则上线后仍是一组固定权重，搜索时写作更新也在参与每一层运算。

旧方法各有合理性：Full SFT 的容量最大；Single LoRA 省参数；TIES 消除符号冲突；MoLE 等门控混合专家能按输入动态组合；ManuSearch 可以交给多个独立 Agent。然而它们没有同时解决“训练更新相互隔离”和“同一执行轨迹里随阶段改变有效权重”两个问题。WeAct 的 gap 是把能力边界、监督 mask、运行时权重选择、工具状态机串成闭环。要注意这不是把 LoRA 发明一遍，也不是首个路由器；贡献更接近 Agent harness 层的可操作组合机制。

3. Core Insight：两种干扰必须分开

观察 A：学习干扰。共享参数上，对能力 k 做梯度下降会改变能力 j 的损失；一阶项由两种梯度内积决定。作者用六种训练顺序、同样数据和更新数对比 rank-32、rank-96 共享 LoRA、按能力分区 LoRA、随机分区 LoRA。即使把共享 rank 提到与三模块总量接近，仍不能消除能力损失；随机分区也不行。这意味着“只是参数不够”不足以解释遗忘，模块与真实能力的语义对齐很重要。

观察 B：执行干扰。把三个专家的低秩更新相加，虽然每个专家参数没有丢失，前向计算却会把别人的更新作用在本阶段的隐藏状态上。作者比较 Full Additive、TIES、DARE-TIES、TSPA 的局部激活残差和目标 token NLL，发现所有测试合并都出现平均退化。这里证据属于受控的经验诊断，不等于证明所有可能的 merge 都必然失败。两个观察共同支持：训练时分开，执行时按需激活原样专家。

4. Method Deep Dive：从数据到权重动作

历史 Agent 轨迹 → 能力阶段标注 → 保留前序上下文 / 仅监督本阶段 token → 独立训练 Plan/Search/Write LoRA → 注册 MCP 内部工具 → Agent 选择 / 卸载 LoRA → 继续同一历史中的外部工具操作 → 输出答案

Step 1：划分能力，而不是机械按消息切片。 作者把深度研究轨迹划为 Plan、Search、Writing：Plan 决定目标与后续动作，Search 包含证据获取、过滤和验证，Writing 负责整合。附录提到把检索和验证继续细分会造成边界标注不稳定；把检索并进规划又让规划吞下证据操作。能力定义因此是工程假设，不是自然定律。若你的任务存在“规划—检索—再规划”循环，三段线性流程未必合适。

Step 2：保留执行上下文，只对当前阶段算损失。 一条训练样本是前序历史 p、加载动作与返回 u、当前阶段内容 c、退出动作 v 的拼接。前序 assistant 消息、工具输出和加载结果只作为条件，不承担当前 LoRA 的 loss；本阶段 assistant 的推理、工具调用、退出调用才参与交叉熵。如此训练的 Search LoRA 不会像孤立的 QA 模型那样以为任务从零开始；它能看到 Plan 已做的工作，并学会在适当时刻交还控制。

Step 3：独立更新。 冻结 Qwen3-32B 主干，分别训练 Plan rank32、Search rank64、Write rank32。Search 更大不是任意美化：作者报告 rank32 试验出现重复推理、工具调用和卸载不可靠。主要适配注意力 q/k/v/o、FFN gate/up/down 和 lm_head，输入 embedding 不适配；每个模块具有独立优化参数，刷新 Writing 不会写坏 Search 的权重。

Step 4：把切换实现为可观察的工具状态机。 load_lora(lora_name) 只能从无激活状态装载；offload_lora(lora_name) 只能卸载当前别名；从 A 到 B 需先 offload A 再 load B。非法别名、失败、重复调用不改变状态。每次调用及结果进入同一历史，后续模型知道当前启用的是哪个专家。这一点对审计尤其关键：日志可以回答“这一步的答案由哪个权重状态生成”。

Step 5：两种控制策略。 WeAct-hard 规定 Plan→Search→Write，满足退出条件才切换，属于更可靠但不够灵活的流程；WeAct-soft 让基础模型及当前专家根据历史决定何时加载、退出、重访，附带覆盖与终止限制。二者没有额外训练的路由器。切换后 LoRA 常驻 GPU，减少权重搬运；但因为不同权重对相同历史计算出的 K/V 不兼容，必须重算历史 KV cache，这一隐藏成本不能从“LoRA 很小”推出为零。

5. 核心公式与数学直觉

(1) Wₖ,ℓ = W₀,ℓ + (αₖ / rₖ) Bₖ,ℓ Aₖ,ℓ；A∈ℝʳˣᵈⁱⁿ，B∈ℝᵈᵒᵘᵗˣʳ。

这里 W₀ 是冻结主干，k 是能力索引，ℓ 是被适配的线性层，r 是低秩维数，α 是缩放。不同 k 拥有互不共享的 A/B；与静态 merge 把多个 ΔW 加在一起不同，WeAct 在某一时刻只使用一个 ΔWₖ。rank 越大表达力通常更强，但训练显存与参数量增加；它不是自动提升路由准确率的万能旋钮。

(2) aₜ ∼ π₍θ₀₊Δθ_zₜ₎( · | hₜ )，zₜ∈{∅, Plan, Search, Write}。

hₜ 是共享历史，zₜ 是当前内部状态，aₜ 可以是普通文本、外部工具调用或内部权重动作。关键在于 policy 本身随 zₜ 变化，而不是仅把专家标签写进 prompt。它不是 RL objective：主论文的能力训练是 masked SFT，内部动作的选择没有单独的 policy-gradient 奖励训练。

(3) Lⱼ(ω−ηgₖ) − Lⱼ(ω) = −η gⱼᵀgₖ + O(η²)。

若两能力梯度内积为负，更新 k 可能增加 j 的损失；若为正则可能有正迁移。这只是局部泰勒展开，不能把一次负内积直接当作长期遗忘的因果证明。独立 LoRA 的跨模块梯度为零，解决的是参数写入冲突；共同主干的能力依赖、错误路由和同模块内部漂移仍未解决。

(4) Lₖ = − Eₛ∼Dₖ Σₙ mₖ,ₙ log πₖ(xₙ | x<ₙ)，m=1 仅覆盖本阶段 assistant 目标。

m 的作用比普通交叉熵更重要：若错误地让工具输出也参与 loss，模型可能学习复述网页而非选择工具；若把前序 Plan 的输出也作为 Search 目标，则又回到多能力共享监督。作者使用终止动作作为目标，让“什么时候退出”成为被学习的行为。

6. Toy Example：一次可复演的 Agent 轨迹

假设问题是“对比 A、B 两篇论文的真实 wall-clock 加速与质量退化”。初始状态 z=∅，历史只有问题。基础模型调用 load_lora(plan)，Plan 列出需要查原文 Table、硬件、batch、baseline、quality 指标，然后 offload_lora(plan)。Harness 验证状态从 Plan→∅。接着 load_lora(search)，Search 连续调用网页读取，提取“论文 A 3.5×/质量 80.9；论文 B 3.2×/质量 80.4”，为两条事实记录来源和设备，再卸载。最后 load_lora(write)，Writing 看到此前完整历史，指出若硬件不同就不能直接断言 A 更快，写成有条件的比较。若 Search 错把 3.5× 写成 5.3×，Writing 可能放大错误；WeAct 保留历史，不自动验证历史真实性。若 Search 忘记卸载，hard 模式可以在预算或无工具阈值触发强制阶段推进，soft 则可能长时间停留搜索。这个例子是解释性构造，不是论文报告的样本。

9. Metrics 教学式解释

Accuracy：正确任务数 / 总任务数，越高越好；但混合不同判分方式、重试预算会改变数值，且八数据集等权平均不代表真实任务频率。Nominal SE：按二项近似 √[p(1−p)/n]，表示任务抽样不确定性，不包含训练 seed、judge 偏差和系统时间波动。Target-token NLL：教师强制条件下目标 token 的平均负对数似然，越低越好；可检验合并后专家是否还能拟合原输出，但不能替代自由生成成功率。Query Utilization（QU）：实际发出的查询中能沿证据路径支持答案的比例，越高越好；可能因少发查询而虚高。Constraint Coverage（Cov）：问题约束中被答案相关查询覆盖的比例，越高越好；依赖约束抽取质量。PK→answer：被证据图归因为无检索支撑的先验知识答案比例，越低越好；并不等于错误率。Answer-ready latency：从启动到可用答案的实际时长，越低越好；需与累计 model-path time、含评审的 logged wall time 分开。EFLOPs 是估算训练浮点操作量，不是 H200 实测耗时或电费。

10. Results Deep Dive：八个带对照的结果

① 主结果：WeAct-hard 45.47 vs Full SFT 42.80，+2.67 个百分点、相对 +6.24%；支持多能力组合有效，但 hard 的预设顺序可能贡献部分优势，不能把增益全部归因于“自主路由”。

② 静态组合反例：hard 45.47 vs TIES 35.66，+9.81 点、相对 +27.51%；而 Single LoRA 38.73 也优于 TIES。说明在这组库和压缩 rank 下静态合并不可靠，不能推广为所有融合方法失败。

12. Ablation / Mechanistic Analysis

去掉能力对齐改随机分区，仍损失 1.12%：模块边界承担的是语义职责隔离，而非仅仅多一份参数。把共享 rank 从 32 提高到 96，遗忘仍未消失：容量不是充分条件。去掉运行时切换改静态融合，目标 NLL 与任务准确率下降：匹配激活的保真度重要。把 hard 换 soft，平均准确率 45.47→43.21，但 GAIA 提升，说明灵活调度在某些任务更合适。将 Search rank 降到 32 的 pilot 出现退出失败：终止控制本身是能力的一部分。刷新 Writing 不 replay 历史数据，旧 Writing NLL 变差：参数隔离与行为保留是两回事。以上是多组相关证据和局部干预，尚缺一个完全等训练、等切换次数的析因实验来精确估计各组件因果效应。

13. Claim vs Evidence

Authors Claim：能力对齐的独立 LoRA + 内部权重动作可提高长程研究 Agent 性能，减轻灾难性遗忘，并支持模块化持续扩展。Experiments Actually Show：在 Qwen3-32B、三种核心能力、八项深度研究基准及所给训练 recipe 下，准确率高于主要对照；局部融合诊断有正 NLL gap；新增第四模块时原三模块参数不变且已测任务未下降。What Is Not Yet Proven：几十或几百个模块的可靠路由、跨骨干与跨语言泛化、真实长期在线增量训练、极端工具错误的传播控制、同一模块的完全无遗忘、低并发高吞吐服务性能。作者也明确指出能力边界不清、库扩展和更长内部动作序列仍待研究。

14. Contribution / Innovation Audit

Contribution 1 [New Mechanism / System]：将 adapter 激活与卸载暴露为原生工具调用，并记录到 Agent history；创新在执行接口与状态管理，不是 LoRA 本身。Contribution 2 [New Training Protocol]：能力阶段标注、保留上下文、只监督本阶段和退出动作；各组件常见，但组合使专家可接手已有轨迹。Contribution 3 [New Empirical Finding]：容量匹配与随机分区无法消除干扰、无 rank 压缩的 Full Additive 仍改变匹配激活。Contribution 4 [New Evaluation]：端到端准确率、SearchAtlas 证据图、延迟与模块刷新共同测量；不是新 benchmark 的首发。

Authors' Limitation：能力库扩大后的路由可辨性未知；长期频繁内部动作是否稳定未知；能力边界交叠，泛化推理能力难分割。Additional Limitation：切换后的 KV 重算随历史长度增长，长上下文、多轮频繁切换可能吞掉收益；adapter 常驻显存随模块数线性增长；hard 固定流程在交错任务可能错误强制切换；soft 容易忘记 offload 或重复调用；训练数据标注依赖人工定义；LLM-as-judge 以及 SearchAtlas 自动归因带来评估偏差；不同 recipe 的训练预算不完全等价；Code 插入只测试 K=3→4，不能说明百模块规模。更隐蔽的是权重状态本身成为可攻击的控制面：若工具别名、阶段描述被污染，Agent 可能加载不适合当前任务的专家。

Paper 2 · SpecKCast: Spectral Kalman Forecasting for Diffusion Acceleration

定位：针对图像与视频 DiT 多次去噪的重复 Transformer 计算，把“跳过下一次网络前向”从统一特征缓存变成按空间频带预测 + 噪声进度对齐 + 不确定性触发重算的闭环系统。

基本信息：Javad Rajabi、Hakki Can Karaimer、David B. Lindell、Babak Taati、Michael S. Brown；University of Toronto、Vector Institute、Samsung AI Center–Toronto。arXiv:2610.26837v1，2026-10-19 17:58 UTC 首次提交；截至本次核查是预印本，正式 Venue 未核实。论文 arXiv · 完整 HTML · PDF。官方项目 / 代码链接未从论文或官方记录核实；不要把其他缓存仓库误认为 SpecKCast 官方实现。

1. 人话版

生成一段视频时，Diffusion Transformer 往往要反复运行几十次，把随机噪声一步步变成画面。最笨的加速是直接减少步数，结果可能模糊或变形；更聪明的办法是缓存前一步的特征，甚至预测下一步特征，但通常把整个特征图当成同一种时间信号。SpecKCast 观察到：图像的大轮廓等低频信息在去噪早期变化大，纹理等高频信息往往在后期才剧烈变化；同样相隔两步，对不同频带并不等于同样难预测。于是它先用二维 DCT 把网络输出分频，为每个频率系数用轻量 Kalman 滤波跟踪“当前值和变化速度”，再把噪声调度器转换成各频带自己的有效时间轴。当预测风险过高才真正调用 DiT，其他步用反变换后的预测输出推进采样。论文在 FLUX、Qwen-Image、Wan2.1-14B、HunyuanVideo 上报告最高 6× 真实延迟加速，额外显存很小；但它仍会损失部分质量，而且不是每个指标、每个设置都全面领先。

2. Background & Research Gap

现实瓶颈：一个 50-step 文生视频采样过程，最贵的操作往往不是最后把 latent 解码为帧，而是每个去噪 step 都运行一次巨大 DiT。若每次前向花 7 秒，50 次就需要数百秒。减少为 8–14 次 NFE 能省掉绝大部分前向，但直接用 8 步 Euler/Flow 更新会偏离原来 50 步轨迹，导致主体换脸、纹理漂移或物体数量变化。

旧范式：FORA/TeaCache/HiCache/SeaCache 通过缓存和复用中间特征跳过昂贵计算，假设邻近时间的表示足够相似；TaylorSeer 用局部 Taylor 外推，Spectrum 用 Chebyshev 对历史轨迹拟合，比“原样复用”能容忍更大时间跨度。但它们常用统一时间步或对整个特征应用同类外推，忽略空间频率分量的不同演化节律。举例：画面中一栋建筑的轮廓在早期就定型，后期主要改变窗户边缘和文字；如果对全部频率统一外推，早期对高频可能过度更新，后期对高频又可能预测不足。

研究缺口不是再提出一个更复杂的 DiT，而是在不训练新网络、不改扩散 sampler 目标的条件下，选择更适合预测的表示和时间坐标，再让系统依据可量化的预测不确定性分配有限 NFE。核心区别是 少算某些完整 DiT 前向，而不是压缩单次注意力的 FLOPs；因此理论 NFE 降低必须用真实 wall-clock latency 证明。

3. Core Insight：频带的“有效时间”不相同

作者在 Figure 2 中对 50 次 FLUX 速度场输出做 DCT、分成径向频带，再对每个频带的轨迹做 PCA 可视化。低频 B0 的点主要在前几个去噪步大幅移动，中频 B3 跨更长区间变化，高频 B6 在第 40 步以后移动显著。附录 G 又在 FLUX/Qwen-Image 不同 prompt 上补充类似观察。这是经验观察：图中的 PCA 轴按面板分别归一化，不能拿不同频带图上绝对距离直接比大小；更不能从可视化直接推出 Kalman 模型严格正确。

第二个观察来自噪声调度器：raw step index 的等间距不代表 log-SNR 的等间距。低频能量通常较大，较早从噪声中显现；高频能量小，需更低噪声才显现。作者据此为每个频带定义自己的 SNR 时间 warp。第三个工程洞见是 Kalman 滤波的协方差不仅能帮助修正预测，还可以充当“是否值得花一次昂贵 DiT 前向”的调度信号。三者组合：频带分解解决预测对象，时间 warp 解决预测坐标，Kalman + risk threshold 解决何时重新观察。

4. Method Deep Dive：真正少算了什么

Prompt + noise + 50-step schedule → 前 3 步真实 DiT 输出 → 每步 DCT 与 7 个径向频带 → 每频带 warped log-SNR 时间 → 每系数 Kalman 值/斜率预测 → 聚合协方差风险 → 风险低：IDCT 预测速度场推进 sampler / 风险高：真实 DiT 前向并校正 → 最后一步强制真实计算 → 视频或图像

Step 1：确定被预测的对象。 模型输出速度场 Y_j（对某些扩散参数化可视作 denoiser output），shape 是 C×H×W。每次真实调用后对每通道做正交 2D DCT，得到 Z_j。二维频率平面分为 L=7 个不重叠径向 band。每个系数独立保存估计值 m 和导数 ν，但一个 band 内的时间坐标和协方差可以共享，避免为海量系数分别存完整 2×2 协方差。DCT 是线性可逆变换，理论上没有压缩丢信息；加速来自跳过网络，而不是 DCT 本身。

Step 2：计算 band-specific time。 根据噪声标准差 σ_j 算全局 log-SNR，再加上该频带的信号功率 log p_l，经过 sigmoid 与线性 rescale。功率 p_l 通过 12 条 calibration prompts 的 50 步轨迹估计，选最后 25 步的 clean-latent 近似计算 DCT 能量。它不需要训练参数，但需要离线校准计算，不是完全零准备成本。高频功率低，其有效时间在更晚的物理 step 迅速变化；低频则更早。时间 warp 保持 step 的先后顺序，不是给不同频带真的执行不同的扩散过程。

Step 3：预测每个系数的值与趋势。 状态 h=(m,ν)，m 是当前频率系数，ν 是相对有效时间的变化率。推进一个有效时间增量 Δ 时，用 m_new=m+Δν；导数按 exp(−Δ/τ) 衰减，避免长跳跃时把旧趋势无限外推。若这一步实际运行 DiT，就得到观测 Z_j，按 Kalman gain 用残差修正 m/ν；若不运行，则只保留预测。每个 band 的过程噪声反映轨迹难预测程度，协方差随跳步增长。

Step 4：风险决定何时调用模型。 用每个 band 的值预测方差 P11 乘以系数数目 d_l，求和并乘晚期衰减因子，得到 R(j)。当 R(j)>ε，重新执行完整 DiT，取得真实输出并更新滤波器；否则把预测的频域 Z 经 IDCT 得到 Y_hat，直接喂给 sampler 更新 latent。ε 越大，通常调用越少但误差越大。论文不是完全无保护地跳步：前 3 步和最后 1 步强制真实计算，最多连续跳 10 步。目标 NFE 在校准集上按平均次数调 ε，因此单条生成的 NFE 可以浮动。

Step 5：处理 CFG。 对使用 classifier-free guidance 的模型，真实计算步需要条件/无条件两次前向，先合成 guided velocity，再用一个滤波器预测它；跳过步两次前向都不做。这样 50 步 CFG 的 100 次 transformer passes 可以缩到 n 步的 2n 次。它不需要重新训练 DiT，也不需要访问每层 hidden state；但需要修改 sampler loop 并正确匹配速度场参数化，不能把输出误当 x0 或 ε。

5. 核心公式与数学直觉

(1) xⱼ₊₁ = xⱼ + (σⱼ₊₁ − σⱼ) Yⱼ；Yⱼ = vθ(xⱼ,σⱼ,c)。

这里 x 是当前噪声 latent，σ 是噪声水平，c 是文本条件，Y 是昂贵 DiT 输出。普通采样每个 j 都计算 Y；SpecKCast 在跳过步用 Ŷ 代替，节省一次完整前向。若预测偏差 e=Ŷ−Y，单步 latent 误差近似 (σ_{j+1}−σ_j)e，后续又会改变模型输入，因此误差可能累积放大。

(2) Zⱼ = DCT₂D(Yⱼ)，Ŷⱼ = IDCT₂D(Ẑⱼ)。

DCT 系数按空间频率排列。低频对应大尺度亮度与形状，高频更敏感于边缘与细节；在 latent / velocity 空间解释不应机械等同于像素语义。对 C 通道分别变换，L=7 只是频带数量，不是只保留 7 个系数，所有系数仍被预测。

(3) λⱼ = 2 log[(1−σⱼ)/σⱼ]；sₗ(j)=rescale₍₋₁,₁₎ sigmoid[(λⱼ+log pₗ)/Tᵥ]。

p_l 是该频带 clean signal 的平均功率。由 SNR_l ≈ (1−σ)²p_l/σ² 得 logSNR_l=λ+log p_l；当 SNR≈1 时 sigmoid 变化最快。T_w=2 控制活跃窗口宽度，太小会让时间变化集中在很少几步，太大则退化为接近普通 log-SNR。因为每个 band 的 p 不同，等一个物理 step 对应不同 Δ_l。端点 σ 接近 0/1 时需 clamp，防止 log 无穷大。

(4) [mⱼ,νⱼ]ᵀ = [[1,Δ],[0,exp(−Δ/τ)]] [mⱼ₋₁,νⱼ₋₁]ᵀ；P̄=A P Aᵀ+Q。

A 负责预测均值，τ=0.1 决定趋势遗忘速度，Q 表示未建模的变化。Q 的主要形式是 q·[[Δ³/3, Δ²/2],[Δ²/2,Δ]]：跳跃越长，值的不确定性按三次项增长。真实观测到来时 K=P̄Hᵀ(HP̄Hᵀ+R_obs)⁻¹，h←h̄+K(z−Hh̄)。Kalman gain 大代表更信新观测，gain 小代表更信预测。作者采用带衰减的 A 和近似不带衰减的 Q，附录说明该选择对边缘方差偏保守，并非严格的连续阻尼系统精确离散化。

(5) Risk(j)=exp[−β j/(N−1)] Σₗ dₗ P₁₁⁽ˡ⁾(j)；若 Risk(j)>ε，则运行 DiT。

β=0.6 抑制后期风险权重，d_l 是 band 的系数数量。这里调度用的 covariance sidecar 还按 band/时间窗口校准预测误差，不能简单把每个系数的理论 Kalman P 直接求和就声称完全复现。ε 是最敏感的速度—质量旋钮，必须在独立 calibration prompts 上标定平均 NFE；若在测试集上调参会造成泄漏。

6. Toy Example：用 4 个频率系数预测两次跳步

考虑一个玩具 2×2 速度场，其 DCT 产生低频系数 z_L=10 与高频 z_H=2（其余系数暂略）。在真实计算的 step 5，滤波器估计低频 m_L=10, ν_L=1，高频 m_H=2, ν_H=−0.5。到 step 6，warp 给出低频 Δ_L=0.10、高频 Δ_H=0.02；设 τ=0.1，则先预测 m_L=10.10, ν_L≈0.368，m_H=1.99, ν_H≈−0.409。如果聚合 risk=0.04 小于阈值 ε=0.08，就不调用 DiT，把这些预测系数 IDCT 后用于更新 latent。到 step 7，低频 Δ_L=0.08、高频 Δ_H=0.04，预测值进一步变化；假设累计 risk=0.11 超过 ε，则运行一次真正的 DiT。若观测低频为 10.22 而预测 10.13，且 Kalman gain=0.6，则校正后低频约 10.184，误差被吸收。真实系统会同时跟踪所有 C×H×W 系数，风险与 gain 由协方差计算而不是随意指定；上述数字是教学示例，不是论文实验值。

9. Metrics 教学式解释

NFE：真正执行 denoiser 的步数，越少通常越快，但不同模型的 CFG 与算子成本不同。Latency（秒）：端到端采样计时，越低越好；这是 wall-clock，不等于 FLOPs。Speedup：50-step reference latency / 当前 latency，越高越好；只说明相对该 reference，不能跨模型直接比倍数。PSNR（dB）：由参考与加速输出像素均方误差计算，越高越接近同 seed reference；图像语义正确但局部平移也可能被严重惩罚。SSIM：亮度、对比度、结构相似性，越高越好；对细节语义不敏感。LPIPS：深度感知特征距离，越低越好；依赖特征网络的归纳偏差。ImageReward：学习的人类偏好评分，越高越好；可能偏向某些审美分布。CLIP Score：文本与图像嵌入相似性，越高越好；高分不保证文字拼写、物理一致性。VBench Quality：聚合时间一致性、运动平滑、单帧美感等质量维度，越高越好；可能掩盖特定对象错位。Mem Δ（GiB）：比同 NFE Base 的峰值 GPU 分配多出的显存，越低越好；不是全模型峰值显存，也不是训练显存。对 video generation，本文未系统报告 FPS、throughput、FLOPs 与多并发 scaling，应标为 Not Reported。

10. Results Deep Dive：八个可核对的定量事实

① 图像 FLUX 14 NFE：SpecKCast 3.45 s / 3.38× / PSNR 24.28 / LPIPS 0.146；Spectrum 3.49 s / 3.36× / 23.60 / 0.165。速度相近，PSNR +0.68 dB，LPIPS −0.019，支持频带预测提升同预算 fidelity；但 CLIP 27.32 低于 Spectrum 27.33，不能称所有指标最优。

② Qwen-Image 14 NFE：SpecKCast 15.01 s / 3.48× / PSNR 24.16，Spectrum 15.72 s / 3.32× / 23.66；PSNR +0.50 dB，真实时间减少 0.71 秒；同等 50-step reference 52.22 秒。Quality 上 ImageReward 1.22 vs Spectrum 1.21，差距小。

③ Qwen-Image 8 NFE：SpecKCast 8.70 s / 6.00× / PSNR 20.44 / LPIPS 0.267，Spectrum 10.23 s / 5.48× / 16.91 / 0.527；PSNR +3.53 dB、LPIPS 约减半，是极端跳步下最强证据。但 VLM/文本一致性并未因此得到普遍保证。

④ FLUX 8 NFE 的 trade-off：SpecKCast 2.11 s / 5.54× / PSNR 19.81；50-step reference 11.68 秒。虽然加速显著，PSNR 相比 14 NFE 的 24.28 降 4.47 dB，不能把 5.54× 解读成无损。

⑤ Wan2.1-14B 14 NFE：SpecKCast 105.2 s / 3.52× / PSNR 24.47 / SSIM 0.813 / VBench 80.86；Spectrum 110.3 s / 3.35× / PSNR 22.93 / VBench 80.76。50-step VBench 81.11，SpecKCast 仍低 0.25；说明接近而非严格等质。

⑥ HunyuanVideo 14 NFE：SpecKCast 55.0 s / 3.33× / PSNR 29.72 / LPIPS 0.107，SeaCache 71.3 s / 2.57× / PSNR 27.59 / LPIPS 0.121；快 16.3 秒、PSNR +2.13 dB。但 VBench 79.68 低于 50-step 的 80.26，也低于 TaylorSeer 的 79.98，质量维度存在明显弱项。

⑦ Wan2.1 8 NFE：SpecKCast 65.3 s / 5.67× / PSNR 19.94 / VBench 79.20，Spectrum 66.0 s / 5.61× / PSNR 17.81 / VBench 78.74；更快且更接近参考，但相对原始 VBench 81.11 下降 1.91，这是高速代价。

⑧ Ablation 与内存：FLUX 14 NFE 完整方法 PSNR 24.28；固定调度 Kalman 22.09（−2.19），raw logSNR 21.03（−3.25），uniform step 19.54（−4.74），去掉频率分解 21.19（−3.09）。完整方法额外内存在 FLUX 14 NFE 仅 0.005 GiB，而 Spectrum 1.15 GiB；但该数字不代表整体 GPU footprint 小到 5 MiB。

12. Ablation / Mechanistic Analysis

去掉频率分解：PSNR 24.28→21.19，表明一个统一频域/空间模型难以同时描述不同频率节律。改为原始 log-SNR：24.28→21.03，说明单一全局去噪进度仍不足；改为均匀 step index：24.28→19.54，说明不均匀时间推进是主要误差源之一。去掉自适应调度：24.28→22.09，说明同样平均 NFE 重新分配到高风险步骤有价值。把 Kalman 换成 Taylor：固定 schedule 下 22.09 vs 21.90，差距仅 0.19 dB；因此不要把所有收益归功于 Kalman 这个名字。Chebyshev 固定预测：21.10 dB、3.97 s，质量和开销均弱于固定 Kalman。机制可视化支持相关性，Table 3 的组件干预提供更强证据，但尚缺直接测量 risk calibration（预测方差与实际误差是否匹配）的可靠性曲线。

与 LLM KV 压缩不同，SpecKCast 的缓存对象是去噪步之间的速度场频率状态，而非 autoregressive sequence 的 K/V。它的 hardware dependence 主要在 H100 上的 DCT 实现、DiT forward 占比和 kernel launch 开销；小模型、batch 很大或移动 GPU 可能因 sidecar 相对开销变大而收益缩水。训练权重不变，适合现有 DiT sampler 集成；迁移到 VLM/LLM 需要重新证明连续状态的可预测性，不能直接把 log-SNR 套到文本生成。

15. Claim vs Evidence

Authors Claim：频带 Kalman 预测能以很低显存实现更好的速度—保真度折中，最高 6×。Experiments Actually Show：四个具体图像/视频模型、H100、同 prompt/seed 的 50-step reference 下，多个 NFE budget 有更低延迟和更高 PSNR/SSIM；消融支持 band/time/scheduler 的贡献；额外显存为 0.005–0.05 GiB 等量级。What Is Not Yet Proven：对所有视频类型的感知质量无损、超长连续生成无漂移、多 GPU 与高并发吞吐、校准分布外可靠性、其他 scheduler / prediction parameterization 的即插即用性、能耗收益、严格的方差/显著性结论。摘要的“up to 6×”是最佳 setting 的最大值，不能当作通用速度保证。

16. Contribution / Innovation Audit

Contribution 1 [New Mechanism]：DCT 频带分解 + band-specific SNR 时间坐标，是最核心的机制组合；DCT、sigmoid 和 log-SNR 本身均非新发明。Contribution 2 [New System / Engineering]：用在线 Kalman 状态与低维协方差 sidecar 驱动真实前向调用，形成可调 NFE 的闭环。Contribution 3 [New Empirical Finding]：不同频带在不同 denoising 阶段活跃，统一时间外推显著较差。Contribution 4 [New Evaluation Protocol 的应用]：把同 seed fidelity、VBench、wall-clock latency、额外显存放在同表比较；使用已有 metric，并未提出新公开 benchmark。

17. Limitation & Failure Modes

Authors' Limitation（从正文与附录可确认的约束）：需要针对模型估计频带功率与阈值；固定 NFE 版本不能根据样本难度调度，自适应版的每条样本计算次数不固定；极端跳步时误差仍增加。论文没有单列系统性的 Limitations 章节，因此不应虚构作者承认的额外实验结论。Additional Limitation：不同噪声 schedule 下 p_l 和 warp 可能不稳；频带按半径划分忽略方向性运动、纹理与局部对象边界；协方差共享可能掩盖某个局部危险高频系数；DCT 是全局空间变换，对大幅运动与 scene cut 不一定友好；风险阈值只校准平均 NFE，单样本尾部延迟未知；只在 H100 上报告，设备迁移需重测；VBench Quality 可能漏掉物理合理性与 prompt 复杂约束；校准 prompts 与评测 prompts 分布不一致可能导致过度自信；视频逐帧对象一致性未必与 PSNR 同步。最强的失败模式是：预测方差低但模型存在系统性偏差，调度器会自信地跳过本该重新观察的一步。

18. Reproduction View：先做最小闭环

第一阶段不必从 14B 视频开始。先用可运行的 FLUX.1-dev 或较小公开 DiT 实现 50-step reference，固定 12 条校准 prompt 和独立 30–100 条测试 prompt。记录每一步 (σ, x, guided_velocity, seed)，对 velocity 逐通道做 torch.fft 不可直接替代 DCT，须实现正交 DCT/IDCT 或验证等价变换；按二维半径分 7 band。校准 p_l 用末 25 步 clean-latent 估计，防止用测试输出校准。每系数保存 m, ν，每 band 保存 2×2 协方差，实施前 3 步 + 最后一步强制计算、最多连续跳 10 步、ε 二分校准目标 NFE。对照 Base、last-output cache、Taylor predictor、Kalman fixed、Kalman adaptive、去 band warp。最先看 FLUX 14 NFE 的 PSNR/SSIM 与 latency，目标是确认“band+warp+adaptive 比统一 step 有明显 fidelity 提升”，而非盲目追求 6×。复现易错点：σ 的方向（高→低）、CFG 组合顺序、DCT 归一化、warp 端点 clamp、Kalman 观测噪声、sidecar 的相对单位、CUDA 同步计时、GPU warmup、seed 对齐。论文没有核实的官方代码，所有伪代码均为复现路线建议。

19. Research Value：七个角度

Baseline Potential：高，同 NFE/同 seed 的缓存与预测对照很清楚。Migration Potential：高，band-wise 不确定性调度可推广到视频流、视觉 token 复用与连续世界模型。Systems Potential：高，低额外显存、真实 wall-clock 已测，下一步需批处理与吞吐。Attack Potential：中高，可构造高频突变/scene cut 使 risk 低估。Evaluation Potential：高，把模型调用节省与 quality fidelity、尾延迟联合量化。Benchmark Potential：中高，缺少对场景突变、长时视频、校准 OOD 的 stress benchmark。New Paper Potential：中高，若证明风险估计的可校准性并改善长时视频的 failure mode，会比仅换滤波器更有贡献。

20. Migration A：Streaming Video / World Model 的风险触发计算

Original Problem：离线扩散多步重复前向。Transferable Mechanism：频带分解、可预测状态、风险触发重算。New Research Question：长视频流中是否能只在运动突变/场景切换时重新运行重型视觉编码器，而保持时序问答准确率？Method Modification：把 log-SNR warp 替换为视频时间与 optical-flow/feature-change 驱动的 band activity 坐标，预测跨帧视觉特征并在 risk 超阈值时执行 encoder；缓存来源帧与时戳。Minimum Experiment：选 200 段 30–120 秒视频，固定 1 FPS、4 FPS 两档采样；比较每帧全编码、均匀隔帧、cosine feature reuse、band-Kalman adaptive；注入 20% 人工 scene cuts，记录 cut 前后前 5 帧 QA 错误。Model：Qwen2.5-VL-7B 或兼容视频 VLM + 冻结视觉编码器。Dataset：Video-MME / MVBench 可用子集。Baseline：uniform sampling、keyframe selection、feature cache。Metric：QA accuracy、encoder calls、visual tokens、P50/P95 latency、GPU memory、scene-cut miss rate。Expected Contribution：面向 streaming VLM 的校准风险—质量 Pareto。Risk：视频特征随内容而非噪声日程演化，原 band 假设不成立。Collision Risk：与动态帧选择、视频 KV cache 和自适应视觉 token 剪枝强重叠；需突出预测不确定性而非简单帧抽样。

21. Migration B：Diffusion 加速的黑盒压力测试与自校准

Original Problem：预测跳步存在未被平均指标揭示的结构漂移。Transferable Mechanism：风险 sidecar 与实际预测误差之间的校准关系。New Research Question：能否设计无权重访问的 prompt/seed stress test，系统性找到“低预测风险却高视觉错误”的失败区域？Method Modification：对不同频率纹理、快速物体移动、文字、镜头切换构造 prompt 家族；把实际误差按 band 与 step 记录为 oracle，测 risk 的可靠性；新增 conformal threshold 或高频保守触发。Minimum Experiment：100 基础 prompt×4 类扰动×3 seeds，50-step reference 与 8/14-NFE 方法一一配对；按 prompt 家族留一类作 OOD，校准阈值仅用其余类别；输出 risk decile vs empirical PSNR drop、worst-10% VBench、实际 NFE 与时延。Model：先 FLUX.1-dev，再 Wan2.1-14B。Dataset：DrawBench + 自建可复现 stress prompts、VBench。Baseline：Base、TeaCache、Spectrum、原 SpecKCast。Metric：ECE-like risk calibration error、worst-group LPIPS、PSNR、VBench、speedup、memory。Expected Contribution：不确定性驱动加速的可验证稳健性 benchmark 与阈值修正。Risk：黑盒时未必能读到内部 Kalman risk；需通过 sampler wrapper 记录，严格区分模型黑盒与系统白盒。Collision Risk：与 EigenCache、风险自适应调度研究可能碰撞；必须强调跨 prompt 分布 shift 的外部验证。

22. Attack / Verification Lens

即使目标不是攻击，仍可把极端高频纹理、闪烁字幕、物体快速进入画面、镜头切换作为 efficiency stress test。对同 seed 生成记录每个 step 的真实模型输出与预测输出（离线 shadow run），计算每个频带的 squared residual、risk percentile、误判跳步率。定义 False-Safe Skip Rate：risk≤ε 但实际误差超过质量阈值的跳步比例；定义 Quality@Latency Budget：在固定 wall-clock 上限内满足 LPIPS/VBench 门槛的比例；定义 Recovery Cost：一次严重预测偏差后需要多少真实 DiT 前向才能恢复。这里“恢复”是生成轨迹误差纠正，不是 Machine Unlearning 的知识恢复。要避免把自建 prompt 过拟合成调度器专用 benchmark。

23. 如果只记住这篇（9 句话）

  1. SpecKCast 预测的是去噪网络输出，不是语言模型 KV cache。2. DCT 把速度场分成空间频带。3. 低频通常早期活跃，高频通常后期活跃。4. 每个频带用自己的 log-SNR warp 定义有效时间。5. 每个系数的 Kalman 状态包含当前值与变化率。6. 协方差 risk 决定何时重新调用完整 DiT。7. 论文在 H100 上实测最高约 6× wall-clock speedup，而非只报告 FLOPs。8. 8 NFE 高速设置仍有质量退化，VBench 也不是全部最优。9. 最值得研究的是长视频 OOD、风险校准与 streaming 场景的失效检测。

Cross-Paper Synthesis · 今天两篇共同说明什么

两篇来自完全不同领域：WeAct 研究长程 Agent 的能力状态选择，SpecKCast 研究 DiT 的昂贵前向计算选择。它们的共同抽象不是“用了缓存”或“用了 LoRA”，而是把过去默认固定的系统决策变成随轨迹状态变化的显式控制动作。WeAct 依据历史决定加载哪个参数子空间；SpecKCast 依据预测协方差决定是否重新计算真实速度场。二者都把可观察的运行状态（当前 adapter、当前频带风险）放进 harness/sampler，给未来的安全审计和系统优化提供了入口。

机制互补：Agent 可把视频生成/理解工具作为一个外部工具，而视频工具内部运行 SpecKCast 这样的 risk-aware scheduler；上层 WeAct 的能力选择决定调用哪类工具，下层 scheduler 决定一次工具调用的算力预算。统一的执行状态可以写成 (task stage, active adapter, tool state, compute risk, budget)，并在每次 action 后更新。假设冲突：WeAct 的模块边界是离散且依赖人工标注的，SpecKCast 的频带时间变化是连续且依赖统计校准的；直接把离散状态机搬到频率预测会损失连续性，直接把 Kalman 方差当成 Agent 选择的置信度也没有理论依据。必须分别标定。

可组合实验范式：WeAct 的 capacity-matched 与 random-partition 控制可以迁移到视觉 token 分组（同样 token budget 下比较语义分组 vs 随机分组）；SpecKCast 的同 seed 50-step oracle 与风险—误差校准可以迁移到 Agent 的“预计下一步能成功”置信度测试（相同任务和工具返回，记录预估风险与真实失败）。二者都提醒我们：只看最终任务成功率，会漏掉路由错误、证据替换、预测误差、尾延迟。

Combined Research Opportunities · 可以开始做的交叉项目

Opportunity A · Budget-Aware Video Research Agent

构建一个需要读长视频、检索外部证据并回答复杂问题的 Agent：上层使用 WeAct 风格 plan / video-inspect / search / write 权重动作，下层视频工具使用频带变化/风险调度选择需要重新编码的帧。核心假设：不必给每个阶段相同的模型参数，也不必给每个视频时刻相同的视觉算力。最小实验：200 条 Video-MME 长视频任务，4 个路由策略（固定/强制/动态/动态+校验）×3 个帧预算（8/16/32），固定总 GPU 时间，测 QA、证据覆盖、frame misses、P95 latency、显存。与普通 adaptive frame sampling 的区别必须是联合内部能力状态与外部视觉预算，而不是简单叠加两种已有模块。

Opportunity B · Uncertainty-Calibrated Internal Actions

让 Agent 不仅记录 load_lora，还预测本次切换会改善哪种能力、可能引入何种风险；以小型 probe 或历史结果校准风险，风险高时执行一次低成本“专家验证”。这对应 SpecKCast 的 risk-triggered full forward，但 Agent 里“full forward”可以是额外检索、工具回放或第二专家审阅。最小实验：在 2Wiki/MuSiQue 200 题上注入 0/1/2 个阶段误导指令，对照无验证、固定每次验证、风险触发验证，报告 success@cost、错误路由率、证据完整性、每题额外 token、P95。只有证明相同额外成本下风险调度优于固定验证，才有独立研究价值。

Opportunity C · Failure-Propagation Benchmark

同时收集 Agent 的 adapter 状态错误和视频 sampler 的预测错误，构造统一的“局部错误→后续放大→何时恢复”协议。记录第 t 步的错误注入、下游状态差异、最后质量与恢复成本。它可以用于系统评估和安全研究，不必强行归类为 Unlearning。首批基准用可控工具环境 + 生成模型 shadow trajectories；要防止 benchmark 只奖励某一种 harness 的特定日志格式。

Collision / Overlap · 哪些方向容易撞车

WeAct 侧：它与 LoRAHub、MoLE、TIES、Adaptive Minds、Macaron-V1 共享“专家组合/调用”问题；若只把已有工具路由改成另一个 prompt 或换 LoRA rank，创新不足。真正空缺在可审计的权重动作、跨长历史 KV 重建、模块扩张时路由可靠性。SpecKCast 侧：它与 TeaCache、TaylorSeer、Spectrum、EigenCache 等共享“跳步/预测/调度”空间；若只把 Kalman 换成另一种滤波器，可能属于 incremental。值得做的是校准 OOD 风险、真实多并发吞吐、场景切换恢复与 streaming 长时稳定性。

Strongest Collision：风险触发计算 vs 风险触发 Agent 验证。 二者机制形式相似，但目前只是潜在可迁移重合，不是论文间直接优先权冲突：一篇的风险是频域数值预测方差，另一篇并没有提出概率路由风险模型。要形成新论文，必须给出跨系统的校准方法和受控实验，而不是画一张统一框图。

Reading / Reproduction Priority

先读 WeAct：若重点是 Agent / Multi-Agent、持续学习、内部动作、权重切换，优先看 Eq.3–6、Table 1、Figure 13/14、Table 12；建议先复现三专家静态 merge vs runtime switching，再加 KV cache 计时。再读 SpecKCast：若重点是视频/推理加速，优先看 Figure 2、Eq.8–12、Table 2/3、Appendix B/D；先复现 FLUX 14 NFE 的消融，再做 Wan2.1 的 wall-clock。最适合作为 baseline：WeAct（Agent 侧）；最适合 system/acceleration idea：SpecKCast；最适合 benchmark/metric：WeAct 的路由 provenance 与 SpecKCast 的 risk calibration；最适合 attack/evaluation：两者的错误传播 stress test。优先级建议是：① 小规模 WeAct 复现；② SpecKCast 频带/时间 warp 消融；③ 联合研究前先排查已有 adaptive compute / agent routing 工作，防止概念撞车。
